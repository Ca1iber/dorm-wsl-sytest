# Using the GIO library API from a C/C++ test application

If a test applications written in C or C++ shall make use of GIO library functions, it will have to be linked to the GIO library.

## About this task

After [Installing the GIO library API from the command line](<02.13.03_Installing_the_GIO_library_API_from_the_command_line.md>), the functionality of the GIO library can be used by a test application. This application can be a SmarTest program, but as well another test program outside SmarTest.

The header file of the GIO library API is compatible to C. The GIO library API functions are written in C++.

The GIO shared library is located at

/opt/hp93000rt/el7/x86_64/gio/lib/libhw_cor_gio.so

and the related header file is located at

/opt/hp93000rt/el7/x86_64/gio/include/xoc/hw/cor/gio/gio.h.

This topic considers test applications written in C or C++.

If your test application is already existing and based on SICL, you will have to port it the GIO library API. Consider [Porting SICL-based applications to GIO](<02.13.06_Porting_SICL-based_applications_to_GIO.md>) for details.

The procedure will be explained along an example of the fictitious external instrument "Fuchsia" with following settings:

- `johndoe` as the user
- fuchsiaDriver.c as the test application using the GIO library API functions
- fuchsiaTest as the runnable test application linked to the shared library
- The user is working in the directory /home/johndoe/fuchsia

This topic describes the rpath way of linking the shared library to the test application. There is as well the alternative option to use the environment variable `LD_LIBRARY_PATH` which is not described here. Reference to the public gcc documentation is made for details, and the pros and cons of the different approaches.

The steps below refer to a manual production of a runnable. It is possible as well to define a makefile and to let make do the job to produce an executable test application.

## Before you begin

Install the .rpm package of the GIO library API on the V93000 system controller according to [Installing the GIO library API](<02.13.03_Installing_the_GIO_library_API_from_the_command_line.md>).

## Procedure

-  Add the header file gio.h to the fuchsiaDriver.c program.

`#include <stdio.h>`

`#include <xoc/hw/cor/gio/gio.h>`

-  Compile the instrument driver and link it with the shared library.

gcc -L/opt/hp93000rt/el7/x86_64/gio/lib -Wall -I/opt/hp93000rt/el7/x86_64/gio/include -o fuchsiaTest fuchsiaDriver.c -lhw_cor_gio

The result is the runnable fuchsiaTest.

The compiler options have got the following meanings:

  - -L/opt/hp93000rt/el7/x86_64/gio/lib instructs the linker where to find the shared library .so
  - -Wall is the standard option to enable all warnings
  - -I/opt/hp93000rt/el7/x86_64/gio/include to add this directory to the list of directories being searched for header files
  - -o fuchsiaTest to produce the runnable as output file
  - fuchsiaDriver.c as the source file to be compiled
  - -lhw_cor_gio to search the library libhw_cor_gio when linking

-  Run the test application.

Enter ./fuchsiaTest

## Results

The user application implements connectivity to external instruments using the GIO library API.
