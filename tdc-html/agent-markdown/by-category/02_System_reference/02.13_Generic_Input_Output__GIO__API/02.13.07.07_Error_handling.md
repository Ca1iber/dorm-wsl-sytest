 | typedef void(* gio_error_handler_t) ( IDID id, [GIO_ERROR](<02.13.07.07_Error_handling.md#ga307753a7be5d06f3eaf383ca94efd15a>) error) |

Type of error handler functions.

An error handler is called when a GIO function encounters an error. The first argument to the handler is the IDID of the session which was passed to the failing operation (if any); the second argument is the error code.

There is only a single, global error handler.

If an error handler returns to its caller, the client application will be notified of the error via a returned error code (which is identical to `error`).

 AttentionThe `id` may be zero in some situations (e.g., when `[gio_open()](<02.13.07.01_Opening_and_closing_connections.md#gaddc8671fd089529c77794f0d38603fca>)` or `[gio_resume_events()](<02.13.07.05_Asynchronous_events.md#ga234c3d95dcd5a7864a17b0c6fc58707d>)` encounter errors).

 | enum [GIO_ERROR](<02.13.07.07_Error_handling.md#ga307753a7be5d06f3eaf383ca94efd15a>) |

Error codes.

Almost all functions in GIO return an error code of this type. All of them, when they encounter an error, set an internal error state which can be queried using the `[gio_get_errno()](<02.13.07.07_Error_handling.md#ga26d80faf8db0efc372f8ccf254e321f8>)` function.

 AttentionClient applications should normally not check for specific error codes, because not all access methods will return the same set of errors. Exceptions to this rule are codes like `GIO_ERR_NO_ERROR` (i.e., success) and `GIO_ERR_IO_TIMEOUT`.

Inquire error code of last GIO function called.

If the last GIO function called encountered an error, `[gio_get_errno()](<02.13.07.07_Error_handling.md#ga26d80faf8db0efc372f8ccf254e321f8>)` returns the corresponding error code. If the function was completed successfully, the return value of `[gio_get_errno()](<02.13.07.07_Error_handling.md#ga26d80faf8db0efc372f8ccf254e321f8>)` is undefined(!).
