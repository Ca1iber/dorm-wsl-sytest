Set lock waiting flag.

The state of the lock waiting flag affects the behavior of sessions which have been locked using `[gio_lock()](<02.13.07.02_Operations_applicable_to_diverse_interface_or_device_types.md#ga281f1e0664bd2ea69456e1f38bc93b61>)`. When `flag` is true, operations which encounter a locked session will wait for the lock to be released (or for a timeout); when `flag` is false, these operations will return an error (`GIO_ERR_DEVICE_LOCKED`) instead.

Set termination character.

If `termChar` is non-negative, it becomes the termination character for the session `id`. The termination character is used to signal the end of data for `[gio_read()](<02.13.07.02_Operations_applicable_to_diverse_interface_or_device_types.md#gac927c44b656660a6150cd7564b98f13c>)`.

If `termChar` is -1, subsequent `[gio_read()](<02.13.07.02_Operations_applicable_to_diverse_interface_or_device_types.md#gac927c44b656660a6150cd7564b98f13c>)` operations will not look for a termination character.

Set timeout.

`[gio_set_timeout()](<02.13.07.06_Session_parameters.md#gac2f86ca1b6ed305e0e70ebe821e7f422>)` sets the I/O timeout for the session `id` to `milliSeconds`. After this call, operations which don't complete within `milliSeconds` milliseconds will be aborted and will return `GIO_ERR_IO_TIMEOUT`.

If `milliSeconds` is zero, timeouts are disabled (i.e., the timeout interval becomes infinite).

 AttentionThere is no guarantee that any operation will time out after exactly `milliSeconds` milliseconds. Scheduling delays and timer granularities (which depend on the operating system and/or the system configuration) affect the timeout calculation. It is however guaranteed that a timeout will occur after at least the given interval. ReturnsGIO_ERROR  Return values
