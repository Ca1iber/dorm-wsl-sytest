# DPS_TASK

#### Subtopics

- [DPS_PIN_TASK](<02.07.04.01.50.01_DPS_PIN_TASK.md>)

The DPS_TASK API enables you to set up and execute measurements and to retrieve the measured value for DPS channels or DC Scale cards in DPS operating mode.

Supported tasks:

- Define measurement conditions for each DPS
- Execute, in parallel, the measurements defined with this class
- Retrieve measurement results
- Support triggered and un-triggered DPS measurement

This class can be added to [TASK_LIST](<02.07.04.01.240_TASK_LIST.md>), so all kinds of DC measurement (using PPMU, DPS and DC Scale pins) can be seamlessly executed.

## Constructor

```
DPS_TASK()
```

This constructs an object of the DPS_TASK class that allows the user to define different measurement conditions for each DPS, to execute all the measurements in parallel, and to retrieve the results.

Note Do not create static objects of the class in the test method and do not create test method member variables from this class.

## Member functions

 pin()

```
DPS_PIN_TASK & pin(const STRING & pinlist);
```

This function returns the reference to the [DPS_PIN_TASK](<02.07.04.01.50.01_DPS_PIN_TASK.md>) class object that represents the measurement conditions for specified DPSs.

 Note A call to this function must be followed by calls to member functions of [DPS_PIN_TASK](<02.07.04.01.50.01_DPS_PIN_TASK.md>) class. You cannot call another `DPS_TASK` member function after calling `pin()`.

Parameter
 | pinlist  | Target pin name for which the user wants to define measurement conditions.

You can specify multiple pins by separating pin entries with a comma.

  |   execMode()

```
DPS_TASK & execMode(const TM::DCTEST_MODE mode);
DPS_TASK & execMode(const STRING & mode);
```

This member function selects the execution mode.

Parameter
 | mode |

The measurement mode defined as TM::DCTEST_MODE or as string. The following types are available:

 |
 |

TM::GPF

"GPF"

 |

This mode executes a global pass/fail measurement. The test will pass if all of the measurements pass. The test result can be retrieved with the getPassFail() member function.

This is the default value.

 |
 |

TM:PPF

"PPF"

   | This mode executes a per-pin pass/fail measurement. The pass/fail result for each measured pin can be retrieved with the `getPassFail(const STRING & pinlist)` member function. In this mode, you can also retrieve the global pass/fail result with the getPassFail() member function. |
 |

TM::PVAL

"PVAL"

   | This mode executes a per-pin value measurement. The result value for each measured pin can be retrieved with the getValue(const STRING & pin) member function. In this mode, you can also retrieve the global pass/fail result and the per-pin pass/fail result by using the getPassFail() and getPassFail(const STRING & pinlist) member function, respectively. |
 |

TM::DCTEST_AUTO

"DCTEST_AUTO"

   | This mode executes the DC test according to the test suite flags.

If the flag ["Pass value"](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_value_on_pass>) or ["Fail value"](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_value_on_fail>) is on, the DC test will execute in the same way as in the TM::PVAL mode.

If the flags "Pass value" and "Fail value" are off and the flag ["Per pin on pass"](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_per_pin_on_pass>) or ["Per pin on fail"](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_per_pin_on_fail>) is on, the DC test will execute in the same way as in the TM::PPF mode.

If the flags "Pass value" and "Fail value" are off and the flag "Per pin on pass" and "Per pin on fail" are off, the DC test will execute in the same way as in the TM::GPF mode.

  |   execute()

```
void execute();
```

This function calls the setup() member function if the measurement conditions have not downloaded to the firmware layer yet. It then executes a DC parametric test based on the measurement conditions defined in DPS_TASK and DPS_PIN_TASK. If this class is added to TASK_LIST, the execute() member function of the TASK_LIST class calls this member function.

When executing the test method, the primaries will be applied.

 Note The current range defined by the DPS_PIN_TASK minimum and maximum values remains after the DPS_TASK execute() member function is called. The regulation performance of the DPS is negatively affected by the current sense resistor and therefore the current measurement range should be restored to the highest possible range after a low current measurement. To reset the current range to the highest possible range, you must program the DPS_PIN_TASK minimum and maximum values accordingly and then call the DPS_TASK execute() member function again.

Using the offline result emulation function:

The `execute()` method of the `DPS_TASK` class takes a measurement name as additional parameter. The name is required to refer to the corresponding offline measurement result specified in the setup file.

```
virtual void execute(FwStream* = NULL)
```

This function is the existing measurement execution method of `DPS_TASK`.

```
virtual void execute(const string& measurementName)
```

Parameter

 |

measurementName

 |

Associate the measurement with offline data.

 |

For more details, see [Parametric offline result emulation](<02.07.12.06.02_Parametric_offline_result_emulation.md>) in [Offline Result Emulation](<02.07.12_Offline_Result_Emulation.md>).

  measRangeMode()

```
DPS_TASK & measRangeMode(const TM::DPS_MEAS_RANGE_MODE& rangeMode);
```

This member function selects the measurement range mode. It is no longer supported and silently ignored.

 Note The regulation performance of the DPS is negatively affected by the current sense resistor. So after a low current measurement, use this function to restore the current measurement range to the highest possible range.

Parameter
 | rangemode  | Measurement mode. The following types are available:

- TM::KEEP_RANGE: This mode keeps the measurement range of the last measurement (default).
- TM::RESTORE_RANGE: This mode restores the measurement range after the measurement to the highest possible range: 1,5A.

The default value is TM::KEEP_RANGE.

For DPS128 and XPS256, the function is silently ignored and the measurement range is restored to the force or clamp range.

  |   preAction()

```
DPS_TASK & preAction(const STRING & action);
```

This member function defines the action to be performed prior to the DC measurement.

Parameter
 | action  | Action type to be performed prior to the DC measurement. The following types are available:

- "NONE": In the internal trigger measurement mode, this option defines no pre-action. However, the digital primaries specified in the Testsuite dialog are activated prior to the DC measurement.

Note: In the external trigger measurement mode, a functional test is forcibly executed prior to the DC measurement by activating the digital primaries specified in the Testsuite dialog. "NONE" is the same as "FTST" in the external trigger measurement mode.

To activate the primaries specified with the PRIMARY_STATUS API or primary analog set, put the FLUSH API prior to this statement.

- "FTST": Performs a functional test prior to the DC measurement by activating the digital primaries specified in the Testsuite dialog. This option is used to perform a DC measurement with applying a break vector defined in the primary set. To activate the primaries specified with the PRIMARY_STATUS API or primary analog set, put the FLUSH API prior to this statement.

You can retrieve the result of the functional test with the getFunctionalResult() member function of this API.

- "FTST_NO_RESULT": Performs a functional test prior to the DC measurement without uploading the test result. This option is used when you need to run a preconditioning pattern just to put the device in a desired state and Do not care about the test result. This option can help save time and optimize the performance.

The default value is "NONE".

  |   primaryActivation()

```
void DPS_TASK::primaryActivation(Boolean primaryActivation);
```

This function allows the user to specify whether he wants to have the primaries activated primaryActivation(true) or not primaryActivation(false) for a DPS measurement.

Parameter
 | primaryActivation  | Specifies whether to have the primaries activated (true) or not (false).  |   samples()

```
DPS_TASK & samples(size_t samples);
```

This function specifies the number of measurements. An external DPS measurement triggers the pattern for every measurement. After the measurements, the average of the measured values will be calculated.

Parameter
 | samples  | The number of measurements to be averaged. This must be a positive integer.

The default value is 1.

 |

The real sample number of the measurement may not be the specified samples. See details below.

- For DPS128-HC / DPS64-HC the real sample number of the measurement is:

 | Measurement type  | Range  | Number of samples |
 | Voltage measurement  | 7V  | The maximum between 4 and the specified samples. |
 | Current Measurement  | 12.5碌A - 250碌A   | The maximum between 64 and the specified samples. |
 | 1.25mA - 200mA  | The maximum between 16 and the specified samples. |
 | 1A  | The maximum between 8 and the specified samples. |
- For UHC4T, the real sample number of the measurement is:

 | Measurement type  | Range  | Number of samples |
 | Voltage measurement  | 4V  | The maximum between 8 and the specified samples. |
 | Current Measurement  | 2mA  | The maximum between 256 and the specified samples. |
 | Range larger than or equal to 50mA  | The maximum between 64 and the specified samples. |
- For XPS256 the real sample number of the measurement is the specified samples.

Maximum number of samples:

- For DPS128 / DPS64 the maximum number of samples is 8192.
- For UHC4T the maximum number of samples is 16384.
- For XPS256 the maximum number of samples is 262144.

Real sample number:

- For DPS128 / DPS64 and UHC4T, if the real sample number of the measurement is not power of 2, it will be rounded to the next power of 2.
- For XPS256 any sample number between 1 and the maximum value can be set.
 setup()

```
void setup();
```

This function downloads the measurement conditions defined in DPS_TASK and DPS_PIN_TASK into the firmware layer, but they will not be applied to the test card hardware until the execute() member is called. If this class is added to TASK_LIST, the setup() member function of the TASK_LIST class calls this member function.

  trigMode()

```
DPS_TASK & trigMode(TM::TrigMode trig_mode);
```

This member function defines the trigger mode.

Parameter
 | trig_mode  | Trigger mode. The following modes are available:

- TM::INTERNAL: This mode executes an internal trigger DPS measurement.
- TM::EXTERNAL: This mode executes an external trigger DPS measurement. In this mode, the measurement continues as long as a trigger is sent to the DPS.

This option forcibly executes a functional test prior to the DC measurement, with activation of the curren digital primaries specified in the Testsuite dialog.

To activate the primaries specified with the PRIMARY_STATUS API or primary analog set, put the FLUSH API prior to this statement.

You can retrieve the results of this functional test with the getFunctionalResult() member function of the DPS_TASK API. This mode can define multiple limits of the current and voltage values for target pins by use of the MULTI_LIMITS API.

 |
 | The default value is TM::INTERNAL.  |   wait()

```
DPS_TASK & wait(DOUBLE waitTime_s);
```

Specifies a wait time (in seconds) which is applied right before the measurement (after any necessary range-switching and/or unganging of channels). For static DPS measurement, internal settling time exists. But additional settling time may be needed because of load board design or large capacitor used. For dynamic DPS measurement, no internal settling time exists because it runs together with digital channels. You need to take care of the settling time within the pattern.

Parameter
 | waitTime_s  | The wait time in seconds.  |   getFunctionalResult()

```
Boolean getFunctionalResult() const;
```

This function returns a global Pass/Fail result for all the measured pins if the functional pre-test ("FTST" or external trigger measurement) was executed. If not, an error occurs.

```

```

This function returns a Pass/Fail result for the specified pin if the functional pre-test ("FTST" or external trigger measurement) was executed. If not, an error occurs.

Users can specify multiple pins by separating pin entries with a comma and obtain Pass/Fail results for each specified pin.

Parameter
 | pinlist  | Pin names for which the pass/fail result is to be retrieved.  |   getNumberOfUsedChannelsFromLastMeasurement()

Parameter

Parameter

Parameter

## Examples

### DPS per-pin value measurement

```
DPS_TASK dpsTask;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Setup the measurement
    //
    CONNECT();

    dpsTask.pin("Vcc").min(0 A).max(0.1 A);
    dpsTask.pin("Vee").min(0 A).max(0.2 A);
    dpsTask.wait(5 ms); //available in SW6.3.3
    dpsTask.execMode(TM::PVAL);
    dpsTask.trigMode(TM::INTERNAL);

    //
    // Execute the measurement
    //
    FUNCTIONAL_TEST();

    dpsTask.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and datalog
//
double IMeas1, IMeas2;

IMeas1 = dpsTask.getValue("Vcc");
IMeas2 = dpsTask.getValue("Vee");

TEST("Vcc,Vee", "Idd_Test", dpsTask.getPassFail()?TM::Pass:TM::Fail, true);
```

In this example, a DPS per-pin value measurement is performed on the pin "Vcc" and "Vee". The measured current values are retrieved. The pass/fail result is judged and logged.

### DPS measurement with different settings for different sites

```
DPS_TASK dpsTask;

ON_FIRST_INVOCATION_BEGIN();

    CONNECT();

    //
    // Dummy initialization of a testflow variable
    //
    FOR_EACH_SITE_BEGIN();

        SET_USER_FLAG("DPS_DUMMY_VAR", CURRENT_SITE_NUMBER());

    FOR_EACH_SITE_END();

    dpsTask.pin("Vcc").min(0 A).max(0.1 A);

    dpsTask.execMode(TM::GPF);

    dpsTask.trigMode(TM::INTERNAL);

    //
    // The task will be changed.
    //
    dpsTask.setup();

    FOR_EACH_SITE_BEGIN();

        INT current;

        GET_USER_FLAG("DPS_DUMMY_VAR",&current);

        dpsTask.pin("Vcc").max(current A);

    FOR_EACH_SITE_END();

    dpsTask.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and datalog
//
TEST( "Vcc", "multiDeltaDps", dpsTask.getPassFail()?TM::Pass:TM::Fail, true);
```

In this example, different settings are defined for different sites through the user flag "DPS_DUMMY_VAR". Then a global pass/fail measurement is performed on all the sites in parallel. The measurement result is retrieved and logged.

### DPS measurement with external trigger

```
DPS_TASK     dpsTask;
ARRAY_D      valueArrayVcc, valueArrayVdd;
INT          i;
static       LIMIT limit;
MULTI_LIMITS templ;

ON_FIRST_INVOCATION_BEGIN();

    CONNECT();

    //
    // Create a Limit for each measurement
    //
    limit.unit("A");
    limit.low(TM::GE, -4 uA);
    limit.high(TM::LE, 175 uA);
    templ.add(limit,8);

    //
    // Make sure that your pattern issues 8 triggers,
    // otherwise you will get an error message
    //
    dpsTask.pin("Vcc").limits(templ);
    dpsTask.trigMode(TM::EXTERNAL).execMode(TM::PVAL);

    //
    // Execute the primary pattern
    //
    dpsTask.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and datalog
//
valueArrayVcc = dpsTask.getWaveform("Vcc");

for ( i = 0 ; i < valueArrayVdd.size(); i++ )
{
    TEST("Vcc", "extTrigDps", limit, valueArrayVcc[i], TRUE);
}
```

In this example, a DPS per-pin value test is performed on the pin "Vcc". The test is triggered by an external digital pin. Eight times of measurements are performed. Each measurement result is retrieved, judged and logged.
