# Digital offline result emulation

#### Subtopics

- [Processing a setup file for (digital) offline result emulation](<02.07.12.06.01.01_Processing_a_setup_file_for__digital__offline_result_emulation.md>)

For the digital offline result emulation the following rules apply:

## Mandatory settings

- Failures are linked to patterns and to pins or pin groups by their name, therefore, you must provide a pattern and pin or pin group name.

  - `<pattern name="[pattern name]">`
  - `<pin name="[pin name]">` or `<pin name="[pin group name]">`

- If a pattern is called multiple times from a burst, the failures are the same for each call.
- Failures are assigned to dedicated cycles, ranges of cycles or to all cycles.

  - `<fail xmode_cycle="0"/>`
  - `<fail xmode_cycle="4" to="7"/>`
  - `<failAll/>`Note Specified X-cycles require wavetables with statemap information or appropriate device cycle names (see [Processing the digital error injection file](<02.07.12.06.01.01_Processing_a_setup_file_for__digital__offline_result_emulation.md>), section Example).

- ORE supports different x-modes per port.
- Match loops will always pass.

## Optional setting

You can link failures to sites by their number. To restrict the pattern cycle fails to a dedicated site, provide the site number.

`<site number="[site number]">`

If the settings shall effect every execution of the pattern for any site, omit the corresponding element, `<site>`.

## Example

### XML setup file

```
<offlineResultEmulation>

   <pattern name="myPattern1">

```

```
     <pin name="Q1">
       <fail xmode_cycle="256771"/>
       <fail xmode_cycle="9"/>
     </pin>
     <pin name="S0">
       <failAll/>
     </pin>
   </pattern>

</offlineResultEmulation>
```
