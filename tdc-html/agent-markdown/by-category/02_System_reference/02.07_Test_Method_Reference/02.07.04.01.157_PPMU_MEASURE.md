# PPMU_MEASURE

#### Subtopics

- [PPMU_PIN_MEASURE](<02.07.04.01.157.01_PPMU_PIN_MEASURE.md>)

The PPMU_MEASURE class is a data container holding the contents of the task for setting up measurement operations of pin PMUs.

This class can be used to call the [PPMU_PIN_MEASURE](<02.07.04.01.157.01_PPMU_PIN_MEASURE.md>) class that is a subsidiary data container to set up per pin measurement mode for pin PMUs. This class also contains the member functions to retrieve test results.

For releases up to 6.5.3 and of the 7.0 stream, to execute tasks defined with this class, you had to use the execute member function of the [TASK_LIST](<02.07.04.01.240_TASK_LIST.md>) class. With the releases 6.5.4, 7.1.0 and later, tasks defined with this class can also be executed directly.

For static DC measurements, it can be executed via [TASK_LIST](<02.07.04.01.240_TASK_LIST.md>) API or executed directly. For dynamic DC measurements, it can be executed via [PATTERN_CONTROLLER](<02.07.04.01.142_PATTERN_CONTROLLER.md>) API.

The TASK_LIST API creates a DC set that can contain up to 10 tasks. Therefore, one DC set is spent per 10 tasks for a task list.

Note

The typical time required for a BADC or PPMU measurement can be calculated as follows:

 |   | twait = (25 渭s + N * 4 渭s) |
 |   | where:  | 25 渭s is a one-time overhead |
 |   |   | "N" is the number of samples |

After the measurement is performed, SmarTest needs an additional time (typical) of 20 渭s * N, where N is the number of samples, to fetch the results. For this additional duration of time, the BADC cannot be used to perform a new measurement.

In additional, an extra wait time of, at least, 60 渭s must be added for the first BADC measurement after switching the measurement mode on one channel for EXA Scale digital cards or Smart Scale digital cards in Exa Scale compatibility mode.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PpmuMeasure.h.  Constructor

```
PPMU_MEASURE();
```

This constructor defines a task that holds measurement modes, compare modes and measurement results.

```
object.pin("pinlist").member_func;
```

## Member functions

Parameter
 | pinlist  | Target pin name or pin group name of this class. You can specify multiple pins and pin groups by separating with a comma or using "@" which means the all PPMU pins. "@" includes the digital pins that is wired to an analog module on the DUT board for a trigger source.   |  wait()

Parameter


This function sets the waiting time for the sequencers before the execution of the measurement.

Parameter
 | time  | The time to wait. Default unit is [s]. The time usually needs to be set as the value euqaling to `period*250`.  |  getPassFail()

```
Boolean getPassFail();

```

This function returns a pass/fail judgment for all pins or a specified pin.

Parameter
 | pin  | Pin name for which pass/fail judgment is to be retrieved. If this parameter is not set, this function returns true if all pins are passed, or false if any pins failed. |

 getValue()

```
DOUBLE getValue(const STRING& pin);
```

This function returns a measured voltage value in [V] or current value in [A] for the specified pin. If more than one sample has been taken the retrieved value is the average of all samples.

## Examples

### Example 1: Generic example

```
PPMU_SETTING   ppmuSetting;
PPMU_RELAY     ppmuRelay_on, ppmuRelay_off;
PPMU_MEASURE   ppmuMeasure;
PPMU_CLAMP     ppmuClamp_on, ppmuClamp_off;
TASK_LIST      taskList_1;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Setups for PPMU
    //
    ppmuSetting.pin("S0").iRange(1 mA).min(0 V).max(4.3 V).iForce(10 uA);
    ppmuSetting.pin("S1").iRange(10 mA).min(-10 uA).max(30 uA).vForce(3.3 V);

    //
    // Relay setups
    //
    ppmuRelay_on.pin("S0,S1").status("PPMU_ON");
    ppmuRelay_on.wait(1.3 ms);
    ppmuRelay_off.pin("S0,S1").status("AC_ON");

    //
    // Measurement setups
    //
    ppmuMeasure.pin("S0,S1").execMode(TM::PVAL);

    //
    // Hardware specific programming to avoid hot switching on the current force setup
    //
    ppmuClamp_on.pin("S0").status("CLAMP_ON").low(2.6 V).high(2.9 V);
    ppmuClamp_off.pin("S0").status("CLAMP_OFF");

    //
    // Build and execute the task list
    //
    taskList_1.add(ppmuSetting)
              .add(ppmuClamp_on)
              .add(ppmuRelay_on)
              .add(ppmuClamp_off)
              .add(ppmuMeasure)
              .add(ppmuRelay_off);

    taskList_1.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and Datalog
//
double VMeas, IMeas;

VMeas = ppmuMeasure.getValue("S0");
IMeas = ppmuMeasure.getValue("S1");

TEST("DC_Test",ppmuMeasure, true);
```

In this example, a PPMU IFVM test on the pin `S0` and a PPMU VFIM test on the pin `S1` are performed in parallel. The execution mode is set as per-pin value measurement with PPMU_MEASURE. The measured voltage of pin `S0` and the measured current of pin `S1` are retrieved with PPMU_MEASURE.

### Example 2: Direct execution without TASK_LIST

```
PPMU_MEASURE ppmuMeasure1;

ON_FIRST_INVOCATION_BEGIN();

    ppmuMeasure1.pin("I/O1").execMode(TM::PVAL);
    ppmuMeasure1.execute("I/O1");

ON_FIRST_INVOCATION_END();
```

In this example, ppmuMeasure1 is defined and directly executed, without using a TASK_LIST.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.0.1: New member function syncWait()
- SmarTest 6.5.4: PPMU_MEASURE tasks can be executed directly without TASK_LIST. Also supported in 7.1.0 and later, not supported in 7.0.n releases.
- SmarTest 7.0.4: New member function wait().
- SmarTest 7.1.3: Offline result emulation introduced
