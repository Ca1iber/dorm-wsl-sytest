# Testing flow and Test Method API

The main task of the test method program is to execute AC or DC tests. To this end, you need to develop a program that has a certain number of steps. The typical testing flow in a test method program consists of five steps: Changing the existing setup data (or setting up new setup data), executing a test, retrieving the raw measurement data, performing computation, and judging the result. See the figure below.

  ![Test method program and related APIs](<../../../../raw/20837.png>)

The steps are as follows:

Changing existing setup data (or setting up new setup data)

Almost all tests use the setup data of the primaries specified in the testsuite dialog of the Test Flow Editor. In this case, you can skip this step.

Sometimes multiple measurements must be performed by switching different conditions in a test method program. The first measurement should use the primaries that were set in the Testsuite dialog window of the Testflow Editor. Then from the second measurement, each measurement should use the setup data that was set in the test method program. Often, the conditions of the current primaries must be changed using the data obtained in the previous tests.

For some tests such as a DC test using PMUs, you need to set up the measurement conditions in the test method program.

APIs for setting up the measurement conditions are called Setup APIs.

Executing test

After conditioning the setup data, you can start test execution by using one of Execution APIs, which correspond to the types of tests.

Retrieving raw measurement data

After measurement, you can retrieve the raw measurement data (for example, analog waveform data, single value, and so on). APIs for retrieving measurement data are called Result APIs.

Computing data

You can compute the measurement data to obtain the desired parameters. APIs for computing data are called Computation APIs. They support dozens of computation functions.

Judging result to pass or fail

You have to judge whether the obtained result has passed or failed in order to determine the pass/fail of the testsuite. APIs for judging the result are called Judgment APIs. In addition to judgment, these APIs can be used for data logging. Details are discussed [Logging Data](<02.07.03.03.07_Logging_Data.md>).

- In addition, the SmarTest software supports APIs for the following features:
- For controlling the test sequence or the flow of the test method program such as follows:

  - Controlling the sequencer or monitoring the status
  - Waiting the program execution
  - Accessing the flags and variables

- For setting up multi-site test.
- For achieving a multi-port test.
- For controlling GPIB instruments connected to GPIB interface for users (not for system).
- For executing firmware commands from the test method program.
