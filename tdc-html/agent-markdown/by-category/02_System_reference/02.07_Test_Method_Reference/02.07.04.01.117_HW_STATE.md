# HW_STATE

This class is used to query the correct hardware status in FW. Currently, it can be used for DPS, PPMU and VI-source.

  Note

In offline mode, the API cannot always return the correct settings of the hardware. This is especially true when hardware settings depend on pattern‑based conditional jumps and match loops.

If SmarTest determines that the state of the hardware cannot be evaluated correctly, "WARNING: ... - reported last DC state ... may not reflect online state." is issued in the ui_report window.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/HwState.h.

  Constructor

```
HW_STATE();
```

This constructor creates an object of HW_STATE class. It contains the hardware setting status. You can retrieve the settings with the member functions of [HW_PIN_STATE](<02.07.04.01.117.01_HW_PIN_STATE.md>).

## Member functions

  getStatus()

```
void getStatus(const STRING &pinlist);
```

This function queries the status of specified pins for the site in focus. You need to call this method every time the settings of the hardware are changed. The read data are stored in HW_STATE object.

The member function must be called outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block or within a [FOR_EACH_SITE...WITH_QUERY](<02.07.04.01.71_FOR_EACH_SITE_BEGIN_WITH_QUERY.md>) block.

The data read from the hardware and stored in the HW_STATE object can be retrieved per pin and property by the [pin()](<02.07.04.01.117_HW_STATE.md#_105633__dle_pin>) function followed by a member function of the subsidiary [HW_PIN_STATE](<02.07.04.01.117.01_HW_PIN_STATE.md>) class.

  Parameter

 | pinList |

A comma‑separated list of the pins to be queried.

If the pinList is empty or an invalid pin is specified, an error message will be thrown out and the query will not be executed.

   |  Return value There is no return value.   pin()

```
HW_PIN_STATE& pin(const STRING &pinName);
```

This function returns the hardware settings for the specified pin. These settings are the settings of the hardware at the time you call the [getStatus()](<02.07.04.01.117_HW_STATE.md#_105633__dle_getStatus>) member function. The requested setting needs to be defined by a member function of the subsidiary [HW_PIN_STATE](<02.07.04.01.117.01_HW_PIN_STATE.md>) class.

  Parameter

 | pinName |

The pin that will be queried.

If the pinName is empty or is not in the pinList of [getStatus()](<02.07.04.01.117_HW_STATE.md#_105633__dle_getStatus>), an error message will be thrown out and no setting will be returned.

   |  Return value A reference to the subsidiary [HW_PIN_STATE](<02.07.04.01.117.01_HW_PIN_STATE.md>) class.   checkKelvinStatus()

```
bool checkKelvinStatus(...);
```

For the syntax and more information refer to [HW_STATE.checkGangConnectionParallel()](<02.07.04.01.117.05_HW_STATE.checkGangConnectionParallel.md>). readMaxAbsVdropsParallel

```
void readMaxAbsVdropsParallel(const STRING &pinlist, const Boolean reset);
```

This member function reads the latched maximum absolute voltage drop values from the hardware. The values are read for the given list of pins for all active sites and are stored in the test method cache. As long as the test method is loaded, the stored values in the test method cache are valid and can be retrieved with the [getMaxAbsVdrops](<02.07.04.01.117_HW_STATE.md#_105633__dle_getMaxAbsVdrops>) function.

The reset parameter defines whether the latched values are then cleared.

The function should be called in the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block and is supported only with the [DC Scale XPS256 card](<../02.05_Test_Head_Cards/02.05.05.03_DC_Scale_XPS256_card.md>) card.

  Parameter

 | pinList |

A comma‑separated list of the pins to be queried.

If the pinList is empty or an invalid pin is specified, an error message will be thrown out and the query will not be executed.

 |
 | reset  | Options are:

- true (default): Reset after readout.
- false: Do not reset after readout.
  |  Return value There is no return value.   getMaxAbsVdrops

```
void getMaxAbsVdrops(const STRING &pin, DOUBLE maxAbsForceDrop, DOUBLE maxAbsReturnDrop);
```

This function queries the maximum absolute force and return voltage drop values for the defined pin on the site in focus.

The [readMaxAbsVdropsParallel](<02.07.04.01.117_HW_STATE.md#_105633__dle_readMaxAbsVdropsParallel>) member function must be called upfront for reading the flags from the hardware into the test method cache.

The function should be called in a [FOR_EACH_SITE...WITH_QUERY](<02.07.04.01.71_FOR_EACH_SITE_BEGIN_WITH_QUERY.md>) block or outside the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block and is supported only with the [DC Scale XPS256 card](<../02.05_Test_Head_Cards/02.05.05.03_DC_Scale_XPS256_card.md>) card.

  Parameter

 | pin |

The pin that will be queried.

If the pinName is empty or is not in the pinList of getStatus(), an error message will be thrown out and no setting will be returned.

 |
 | maxAbsForceDrop  | The maximum absolute force voltage drop in volts (V) for the queried pin and the site in focus. |
 | maxAbsReturnDrop  | The maximum absolute return voltage drop in volts (V) for the queried pin and the site in focus.  |   Return value There is no return value.

## Examples

### Example 1: Query the status outside the ON_FIRST_INVOVATION block

The status is read from the hardware, stored in the HW_STATE object, and finally retrieved from the HW_STATE object for the site in focus outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block.

```
HW_STATE    hwState;
DOUBLE      forcedVoltage;
DOUBLE      clampCurrent;

ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...
}
ON_FIRST_INVOCATION_END();

hwState.getStatus ("PMU_pin_1, DPS_pin_1");

forcedVoltage = hwState.pin ("DPS_pin_1").getVoltageForce();
clampCurrent  = hwState.pin ("DPS_pin_1").getCurrentClampSource();

cout << "Current site: " << CURRENT_SITE_NUMBER() << ", pin \"DPS_pin_1\"" << endl;

cout << "\tForced voltage:       " << forcedVoltage << endl;
cout << "\tCurrent clamp source: " << clampCurrent  << endl;
```

### Example 2: Query the status in a FOR_EACH_SITE...WITH_QUERY block

The status is read from the hardware, stored in the HW_STATE object, and finally retrieved from the HW_STATE object for the site in focus within a FOR_EACH_SITE block in the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block. The [FOR_EACH_SITE_BEGIN_WITH_QUERY](<02.07.04.01.71_FOR_EACH_SITE_BEGIN_WITH_QUERY.md>) API must be used to set the query focus within the FOR_EACH_SITE block.

```
HW_STATE    hwState;
DOUBLE      forcedVoltage;
DOUBLE      clampCurrent;

ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...

    FOR_EACH_SITE_BEGIN_WITH_QUERY();
    {
        hwState.getStatus ("PMU_pin_1, DPS_pin_1");

        forcedVoltage = hwState.pin ("PMU_pin_1").getVoltageForce();
        clampCurrent  = hwState.pin ("PMU_pin_1").getCurrentClampSource();

        cout << "Current site: " << CURRENT_SITE_NUMBER() << ", pin \"PMU_pin_1\"" << endl;

        cout << "\tForced voltage:       " << forcedVoltage << endl;
        cout << "\tCurrent clamp source: " << clampCurrent  << endl;
    }
    FOR_EACH_SITE_END();
}
ON_FIRST_INVOCATION_END();
```
