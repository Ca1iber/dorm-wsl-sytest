# ON_FIRST_INVOCATION_BEGIN

This API declares the beginning of the block that enables you to execute setup and test for all sites in parallel, when the program is run for the first tested site.

ON_FIRST_INVOCATION_BEGIN and [ON_FIRST_INVOCATION_END](<02.07.04.01.139_ON_FIRST_INVOCATION_END.md>) must be used as a pair. The area enclosed by this pair is called "first-invocation block".

## Application note

- This API is meaningful for multisite testing. For single-site testing, this API is ignored.
- You can describe the Setup and Execute APIs within the first-invocation block, in order to achieve them for all active sites in parallel. In addition to the Setup and Execute APIs, you can describe any other function. However, these functions work for the currently-tested site (for example, Result APIs), or regardless of site information (for example, Computation APIs).
- All statements in the first-invocation block are executed once only when the program is run for the first tested site.
- You can describe the FW_TASK API enclosed by the BEGIN_EXTENSION API with the site parameter and END_EXTENSION API in the first-invocation block for multi-site testing. Note that you should not describe it enclosed by the BEGIN_EXTENSION API with no parameter and END_EXTENSION API.
- Do not make the first-invocation block conditional or make sure to put a dummy first-invocation block in the else branch.CAUTION The [TEST()](<02.07.04.01.241_TEST.md>) and [LIMIT()](<02.07.04.01.126_LIMIT.md>) statements as well as all of the "judgeAndLog_***" statements described in [TESTSET](<02.07.04.01.244_TESTSET.md>) must never be used inside a first-invocation block. Using any of these statements carries a high risk of defective devices being declared OK by the test.

## Syntax

```
ON_FIRST_INVOCATION_BEGIN();
```

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/MapiUtil.h.

  List of parameters There are no parameters. Return value There is no return value.

## Examples

### Example 1: Minimum code

The following example shows the minimum code for a "first-invocation block". The ellipses ("...") are to be replaced with your code.

```
ON_FIRST_INVOCATION_BEGIN();
    ...
    ...
ON_FIRST_INVOCATION_END();
```

### Example 2: Optional curly brackets

The example utilizes an optional pair of curly brackets "{" and "}". These optional curly brackets are used for simplifying the correct indentation with assistance of the related Eclipse tool.

```
ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...
}
ON_FIRST_INVOCATION_END();
```

### Example 3

```
//
// Parallel Execution for All Sites - BEGIN
//
ON_FIRST_INVOCATION_BEGIN();

    //
    // Setup and Test Execution
    //
    Routing.pin("Aout").connect(TM::SINGLE);
    Analog.DGT("Aout").enable();
    EXECUTE_TEST(0.1 sec);

    //
    // Retrieve measured analog waveform
    //
    ARRAY_D AnaWave = Analog.DGT("Aout").getWaveform();
    Routing.pin("Aout").disconnect();
    Analog.DGT("Aout").disable();

    FLUSH();

//
// Parallel Execution for All Sites - END
//
ON_FIRST_INVOCATION_END();
...
...
```

ON_FIRST_INVOCATION_BEGIN and ON_FIRST_INVOCATION_END declare the first-invocation block. All APIs in this block are executed for all sites in parallel once only when the program is run for the first tested site. Hence, the analog modules on the all connected site, specified by the "Aout" pin, are enabled and then the measurements are done on all connected sites.
