# Changing the default pin status with SmartRDI

#### Subtopics

- [clearPinStatus()](<02.07.13.08.02.01_clearPinStatus.md>)
- [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>)

Introduces the ways to change the default status of pin(s) in the generated pattern.

 Note In all patterns generated by RDI, the default waveform index is f, which means keeping the current status of the pin. So you need to define the waveform index f in the [wavetable](<../02.08_Setup_and_Result_Tools/02.08.04.16.04.05_Wavetables.md>) as follows.

```
PINS pinA
0 "XXXX" X
1 "XXXX" X
...
f  " " .
```

If the index f is occupied by other meaningful actions or the pin needs a changing waveform as the default index, you can change the default index in the generated pattern with the [RDI_configure file](<02.07.13.04_RDI_Configure_file.md>) or the [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>) and [clearPinStatus()](<02.07.13.08.02.01_clearPinStatus.md>) functions.

## Set the pin status in all generated patterns

Specify the pin and the waveform index in the [RDI_configure file](<02.07.13.04_RDI_Configure_file.md>) with the DEFAULT_STATUS_PIN and DEFAULT_STATUS_INDEX keywords as below:

```
DEFAULT_STATUS_PIN="pinA,pinB"
DEFAULT_STATUS_INDEX="3,5"
```

The waveform index of the pinA and pinB in all the generated patterns will be 3 and 5.

## Set the pin status in one generated pattern

Specify the pin and the waveform index with the function [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>) like below. You can have more flexible default index in the burst pattern. You can also reset the default waveform index with the function [clearPinStatus()](<02.07.13.08.02.01_clearPinStatus.md>).

```
rdi.setPinStatus("pinA",3);
```

All the indexes in the generated pattern for this pin will be the specified status. The pin name and pin status will be added to the name of the generated pattern.

 Note If you specify the status for the pin(s) with both the [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>) and the [RDI_configure file](<02.07.13.04_RDI_Configure_file.md>), the status specified in [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>) will overwrite the status specified by the keywords in the [RDI_configure file](<02.07.13.04_RDI_Configure_file.md>). Note The pin status setting is valid only for the current test suite. This means that even without calling [clearPinStatus()](<02.07.13.08.02.01_clearPinStatus.md>), the following test suite will use the [default pin status](<02.07.13.08.02_Changing_the_default_pin_status_with_SmartRDI.md>).

## Examples

### Example 1

```
RDI_BEGIN();
  rdi.setPinStatus("pinA",3);
  rdi.digCap("mcsame1_DATA1_0").pin("DATA2").samples(30).execute();
  rdi.clearPinStatus("pinA");
RDI_END();
```

### Example 2

Do not use [setPinStatus()](<02.07.13.08.02.02_setPinStatus.md>) and [clearPinStatus()](<02.07.13.08.02.01_clearPinStatus.md>) in the [burstLabel](<02.07.13.24.03_burstLabel.md>) block of [smartVec](<02.07.13.24_SmartRDI__Vector_and_protocol_programming.md>).

Wrong position:

```
RDI_BEGIN();
  rdi.smartVec().burstLabel("labelName").begin();
    ...
    rdi.setPinStatus("A",1); // This is not allowed.
    ...
  rdi.smartVec().burstLabel().end();
RDI_END();
```

  Correct position:

```
RDI_BEGIN();
  rdi.setPinStatus("A",1); // This is correct.
  rdi.smartVec().burstLabel("labelName").begin();
    ...
    ...
  rdi.smartVec().burstLabel().end();
RDI_END();
```
