# Using C/C++ functions from external libraries in universal test methods

#### Subtopics

- [Enabling modern C++ support for SmarTest 7](<02.07.02.11.01_Enabling_modern_C___support_for_SmarTest_7.md>)

This topic shows how to use your C/C++ functions from external libraries in the test method programming.

## About this task

This topic is not dealing with test method libraries. To find the related information about test method libraries, refer to [Universal test method concept](<02.07.02.01_Universal_test_method_concept.md>) and [Managing the universal test method libraries](<02.07.02.03_Managing_the_universal_test_method_libraries.md>).

You call the C/C++ functions from external libraries in the run() method of a test method.

The external libraries can be loaded before the test method library with the preload mechanism. These libraries must be named like libxxx.so, where xxx is a combination of letters, numbers or "_". In this mechanism, the external test method libraries need to be put in the directory device/testmethod/sh_lib-EL7-64bit/preload, /var/opt/hp93000/soc/testmethod/preload or /var/opt/hp93000/soc_common/testmethod/preload.

- The libraries in the directory device/testmethod/sh_lib-EL7-64bit/preload will be loaded earlier than the libraries in the directory device/testmethod/sh_lib-EL7-64bit/.
- The libraries in the directory /var/opt/hp93000/soc/testmethod/preload will be loaded earlier than the libraries in the directory /var/opt/hp93000/soc/testmethod.
- The libraries in the directory /var/opt/hp93000/soc_common/testmethod/preload will be loaded earlier than the libraries in the directory /var/opt/hp93000/soc_common/testmethod.

The libraries in the preload directories will be loaded with `RTLD_GLOBAL` flag enabled. (For the above three directories, the flag is enabled by default.) As a result, all the symbols defined in the libraries under preload sub-directories will be made available for symbol resolution of subsequently loaded libraries. (For details of `RTLD_GLOBAL`, see the `dlopen()` function of Linux.)

The preload mechanism supports multi-layers of dependencies among the shared libraries. In the above preload directories, the libraries in the current directory are loaded earlier than the libraries in its sub-directories. So you need to put the libraries in the appropriate directories. (See the example below.)

  Note

Most modern libraries require at least the c++11 or later c++ standard. SmarTest uses the Red Hat Developer Toolset to support modern C++. For Red Hat documentation, see:

[User Guide - Red Hat Developer Toolset](<https://access.redhat.com/documentation/en-us/red_hat_developer_toolset/9/html/user_guide/index>).

Starting SmarTest without enabling the developer toolset, uses the older GCC 4.8 compiler, which does not support C++11. To use C++11, use GCC 9. However, the GCC 9 devtoolset compiler is stricter. It returns more warnings and errors about valid code. For further information about compatibility of different GCC versions and modes, see:

[Red Hat Developer Toolset - GNU C++ Compiler - C++ Compatibility](<https://access.redhat.com/documentation/en-us/red_hat_developer_toolset/9/html/user_guide/chap-GCC#sect-GCC-CPP-Compatibility>)

To use the more modern GCC 9 (that uses C++14 by default), start SmarTest with the command:

scl enable devtoolset-9 /opt/hp93000/soc/prod_env/bin/HPSmarTest

For more information, see [Enabling modern C++ support for SmarTest 7](<02.07.02.11.01_Enabling_modern_C___support_for_SmarTest_7.md>).

## Before you begin

Make sure you are using SmarTest 6.3 or later. Your external C/C++ libraries must be ready to use. The test method project and the test method class must already be created.

## Procedure

-  Add the related code to the test method source file:

  -  Open the test method source file.
  -  Include the C/C++ project header file in the test method like below.

```
#include "Algorithm"
```

  -  Type in your code to call the C/C++ functions like below.

```
Algorithm algo;
if(mType == "FFT")
{
  algo.doFFT();
}
else if(mType == "ARMA")
{
  algo.doARMA();
}
else if(mType == "LINFIT")
{
  algo.doLinearFit();
}
else
{
  cout <<"error: Do not support this type." <<endl;
}
```

-  Include the header file path in the C/C++ compiler.

  -  In the C/C++ perspective, right-click the test method project and select Properties menu. The project Properties window is displayed.
  -  In the Properties window, click the C/C++ Build > Settings on the left side.
  -  In the Tool Settings tab, click the GCC C++ Compiler > Directories.
  -  Add the external C/C++ project path to the Include paths list and click OK.  ![Add the Include paths](<../../../../raw/100443.png>)  Note The Restore Defaults button will un-check the Shared setting of GCC C++ Linker > Shared Library Settings. This will make the compilation of the test method fail. So if you use the Restore Default button, you need to check the setting Shared of GCC C++ Linker > Shared Library Settings manually. Note You can also directly copy the headers files to be included in the UTM project directory. Then it is unnecessary to add the paths of the header files in the project Properties.

-  To load the external libraries before the loading the test method library, put the external libraries in the directory device/testmethod/sh_lib-EL7-64bit/preload, /var/opt/hp93000/soc/testmethod/preload or /var/opt/hp93000/soc_common/testmethod/preload.
-  To build the test method project, click Project > Build All.

## Results

Your C/C++ functions from external libraries are successfully used in the universal test method.

## Example

If UTM library libABB.so depends on libDeviceGeneral.so and libDeviceGeneral.so depends on libd2s.so, they need to be placed in the directories as below:

Device/testmethod/sh_lib-EL7-64bit/libABB.so

Device/testmethod/sh_lib-EL7-64bit/preload/libd2s.so

Device/testmethod/sh_lib-EL7-64bit/preload/generalLib/libGeneralDevice.so

- SmarTest 6.5.3: Preload mechanism supports multi-layers of dependencies among libraries.
