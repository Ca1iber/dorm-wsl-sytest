# FW_TASK

This API allows direct access from the test method to the system hardware at firmware level.

## Application note

- Sometimes several [firmware commands](<../02.06_Command_Reference/02.06_Command_Reference.md>) must be used in the test method program. If so, this API provides the environment where you can execute one or more firmware commands when necessary.
- [BEGIN_EXTENSION](<02.07.04.01.10_BEGIN_EXTENSION.md>) and [END_EXTENSION](<02.07.04.01.59_END_EXTENSION.md>) APIs are always used together with the FW_TASK function.
- Beside the firmware command, you can also execute the functions that you have originally created between [BEGIN_EXTENSION](<02.07.04.01.10_BEGIN_EXTENSION.md>) and [END_EXTENSION](<02.07.04.01.59_END_EXTENSION.md>) APIs.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Extension.h.

## Syntax

For setting:

```
FWTASK_STATUS FW_TASK(const STRING& command);
```

For query:

```
FWTASK_STATUS FW_TASK(const STRING& command, STRING& answer);
```

To retrieve binary data:

```
FWTASK_STATUS FW_TASK(const STRING& command, FW_ResultData & resultdata);
```

  Parameters

 | I/O  | Parameter  | Description |
 | I  | command |

Command string with one or more commands. Each string can be limited by a newline (\n) or a semicolon.

Multiple FW commands, delimited with a newline (\n) or a semicolon, can be combined in the command string.

 |
 | O  | answer  | Answer string as the response to the firmware command. Its maximum length is 1 MB. If the answer string exceeds the limit of the length, a system error will occur. |
 | O  | resultdata |

A reference to an existing object of type FW_ResultData. The function fills this object with the retrieved data.

The FW_ResultData object provides the following parameters:

 | Parameter  | Type  | Description |
 | Answer  | String  | The FW answer string without the binary data part |
 | BinaryDataLength  | unsigned int  | The data length |
 | BinaryData  | char*  | The data string |

See also [Example 3: Retrieve DPS current measurement results](<02.07.04.01.77_FW_TASK.md#_29362__ex_retrive_binary_data>) below.

   |  Return value The following enumerators of type FWTASK_STATUS are returned:

- FW_PASSED: The firmware commands are successfully executed.
- FW_WARNING: A warning has been generated from execution of the firmware commands. The [Message Concentrator and Distributor (MCD)](<../02.06_Command_Reference/02.06.01.01_V93000_Firmware_Overview.md#_10402__p_MCD>) generates the warning and it is output to the report window. You may have to confirm the contents of the warning and modify the test method program.
- FW_BREAK: If the break has occurred during the firmware execution, this is returned. When you press the Break button in the SmarTest Main Menu, the break signal is sent to the MCD and the digital sequencer is changed to the BRK state. The system hardware operation stops and the digital channels continue to output the break vectors. Then, control returns to the test method and program execution will be continued. If the firmware execution fails for reasons not mentioned above, an error will occur. For details, see the [Command Reference](<../02.06_Command_Reference/02.06_Command_Reference.md>) Manual. When an error occurs, the test method execution aborts. In other words, program execution terminates at this point. Note that two kinds of error message are output to the report window. One is the error message generated from the test method if error messages have been activated by the [ENABLE_ERROR_MESSAGE](<02.07.04.01.58_ENABLE_ERROR_MESSAGE.md>) API. The other is the message generated from the MCD.

## Examples

### Example 1: Execute setting command

```
FW_TASK("UTOT 1, 65535, 12345\n");
```

This API sets output lines URW15, 14, UW13 to 7 and URW06 to 00, to 53190 (inverted value of 12345) at the firmware level. Note that you need to terminate the command string with "\n" (newline) or ";"(semicolon) even if the only single command string is used.

### Example 2: Execute querying command

```
STRING answer;

if (FW_TASK("DFPS?(@)\n", answer) == FW_PASSED)
{
// continue the processing ....
}
```

If the firmware command DFPS? is executed successfully and the FW_TASK returns FW_PASSED, the statements in the "if" block are executed.

### Example 3: Retrieve DPS current measurement results

```
FW_ResultData data;

FW_TASK("DPSE 1,(dps1),#150,1,2");
FW_TASK("PSST ON");
FW_TASK("PSEE 1,,,(dps1)");
FW_TASK("PSER? 1,pval", data);

cout << "Answer: " << data.Answer << endl;
cout << "BinaryData: " << endl;

for ( unsigned int i = 0; i < data.BinaryDataLength; i++ )
{
cout << data.BinaryData[i];
}
```

To retrieve the binary data, the API executes the DPSE, PSST, and PSEE commands followed by the PSER? query. The result contains the properties of the retrieved data.

### Example 4: Enable the trace function / MCDLog

The following code enables and disables the [trace function](<../02.06_Command_Reference/02.06.01.03.05_Using_the_Trace_Function.md>) using the [DIAG](<../02.06_Command_Reference/02.06.02.02.74_DIAG_-__DIAGnostics.md>) command and writes some annotations to the MCDLog file using the [NOOP](<../02.06_Command_Reference/02.06.02.02.169_NOOP__NOOP__-__NO_OPeration.md>) command.

```
string testSuiteName;

GET_TESTSUITE_NAME(testSuiteName);

//
// Open the MCDLog, write the first annotation
//
FW_TASK("DIAG 2");

FW_TASK("NOOP \"##########\",\"" + testSuiteName + "\",\"Start\",");

//
// Execute tests and write some annotations
//
...
...
FW_TASK("NOOP \"##########\",\"" + testSuiteName + "\",\"Step\",1");
...
...
FW_TASK("NOOP \"##########\",\"" + testSuiteName + "\",\"Step\",2");
...
...
//
// Close the MCDLog
//
FW_TASK("DIAG -2");
```

Note: You must use a backslash "\" as escape character to insert strings that are enclosed in quotation marks into the command string.
