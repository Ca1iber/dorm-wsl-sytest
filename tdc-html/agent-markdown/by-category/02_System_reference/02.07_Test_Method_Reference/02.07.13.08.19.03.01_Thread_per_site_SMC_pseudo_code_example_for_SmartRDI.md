# Thread per site SMC pseudo code example for SmartRDI

Background threads using SmartCalc (SMC) in SmartRDI can be implemented as "thread per site" or as "common thread" (also known as "single thread"). The following example shows the pseudo code for implementing a "thread per site".

The "thread per site" is defined by calling [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) or a variant of this function outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block. This creates a separate thread for each active site.

The site to be processed within the background process is defined by the site that was active when the thread has been armed in the run() function of the test suite outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block.

For more information, refer to [SmartCalc "Thread per site" and "Common thread"](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>).

## Example

### Thread per site pseudo code example

The pseudo code below shows the typical code structure of hidden upload using a thread per site:

```
ON_FIRST_INVOCATION_BEGIN();
{
    rdi.hiddenUpload(TA::ALL)

    RDI_BEGIN();
    {
        ...
        rdi.dc("Result_ID").pin("..."). 鈥?.execute();
        ...
    }
    RDI_END();
}
ON_FIRST_INVOCATION_END();

SMC_ARM();
...
```

Background process of the same test suite:

```
public:

void SMC_backgroundProcessing()
{
    double result;

    result = rdi.id("Result_ID").getValue();
    ...
    ...
}
```

For a compilable, none-SmartRDI example, see [SmartCalc thread per site example](<02.07.10.02.01.01_SmartCalc_thread_per_site_example.md>).
