# SPECIFICATION

The SPECIFICATION API accesses the data container holding the contents of an existing specification, which is used in the timing setup of the multi-port testing.

This API is for multi-port testing only. For details of multi-port testing, see [How to use Multiport for specific Applications](<../../03_Use_cases_and_application_papers/03.03_How_to_use_Multiport_for_specific_Applications/03.03_How_to_use_Multiport_for_specific_Applications.md>).

To define a specification as the primary, execute the [PRIMARY_STATUS](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md>) API member function [timing()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_timing>) for the corresponding SPECIFICATION API's class object.

To change the definition of a spec value (or per-port spec value) in the specification that is currently defined as the primary, use the PRIMARY_STATUS API member function [getSpecification()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_getSpecification>) to return the corresponding SPECIFICATION API's class object (which represents the specification currently defined as the primary), and execute the SPECIFICATION API [change()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_change>) member function for that returned class object.

The changes of the definitions specified by this API are actually reflected to the hardware when any of the following APIs is executed.

- EXECUTE_TEST
- START_TEST
- DIGITAL_CAPTURE_TEST
- NB_DIGITAL_CAPTURE_START
- FUNCTIONAL_TEST
- FLUSH then SPEC_SEARCH (execute() member function)
- FLUSH then SEQUENCER_STATUS (run() member function)
- FLUSH then PMU_IFVM (execute() member function)
- FLUSH then PMU_VFIM (execute() member function)
- FLUSH then TASK_LIST (execute() member function)
- FLUSH then DPS_VFIM (execute() member function)

The changes of the definitions specified by this API can be also reflected to the MCD when the FLUSH API is executed. This is an option to reflect the changes on the user interface such as the Test Program Explorer and the Spec Tool.

For retrieving data, the specification name of the specified class object can be obtained using the getName member function.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Specification.h.

 Constructor

```
SPECIFICATION(const STRING& specif);
```

This constructor creates the SPECIFICATION API's class object that represents the contents of the specified specification name.

Parameter
 | specif  | Name of an existing specification.  |   Member functions

- [getName()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_getName>)
- [getSpecValue()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_getSpecValue>)
- [change()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_change>)
- [restore()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_restore>)

## Member functions

  getName()

```
const STRING& getName() const;
```

This member function returns the specification name.

There are no parameters in this member function.

 getSpecValue()

```
DOUBLE getSpecValue(const STRING& spec);
```

This member function queries the value of the specified spec (or per-port spec).

Parameter
 | spec |

Name of the spec whose value will be queried.

To specify a per-port spec, specify the port name after the spec name and "@" such as "spec1@port3". The port name must be specified unless the spec has been defined as global in all ports. A spec that is global in all ports can be specified with the spec name only or by adding any port name.

   |  change()

```
void change(const STRING& spec, DOUBLE value);
```

This member function changes the value of the specified spec (or per-port spec). If the change is made at the end of a test method without any following test execution, it will be lost. To keep the change in the following testflow execution, use FLUSH() right after it.

Parameters
 | spec |

Name of the spec whose value will be changed.

To specify a per-port spec, specify the port name after the spec name and "@" such as "spec1@port3". The port name must be specified unless the spec has been defined as global in all ports. A spec that is global in all ports can be specified with the spec name only or by adding any port name.

 |
 | value |

Value applied to the specification defined by parameter spec.

The value must be within the range between the minimum and maximum values specified in the specification (on the Spec Tool window).

   |  restore()

```
void restore();
```

This member function resets the values of all specs to the ones when the test method program in the current test suite is started.

There are no parameters in this member function.

## Important points

- In this API, only one member function can be specified in a statement.
- When you query a spec value in the specification that is currently defined as the primary, you can specify the corresponding SPECIFICATION API's class object in either of the following ways:

  - Obtaining the object by executing the getSpecification member function of the PRIMARY_STATUS API:

For example, to query the value of the spec "T", execute as follows:

`Primary.getSpecification().getSpecValue("T");`

If the specification "specif2" is currently defined as the primary, "Primary.getSpecification()" returns the "SPECIFICATION("specif2")" object, and "getSpecValue" return a spec value in that object.

  - Specifying the object name directly:

For example, if the currently defined primary specification name is"specif2", specify as follows to query the spec value.

`SPECIFICATION("specif2").getSpecValue("T");`

Both the statements which are shown in the above two ways execute the same thing if "specif2" is currently defined as the primary specification.

- When you change a spec value in the specification that is currently defined as the primary, you can specify the corresponding SPECIFICATION API's class object in either of the following ways:

  - Obtaining the object by executing the getSpecification member function of the PRIMARY_STATUS API:

For example, to change the value of the spec "T", execute as follows:

`Primary.getSpecification().change("T", 10);`

If the specification "specif2" is currently defined as the primary, "Primary.getSpecification()" returns the "SPECIFICATION("specif2")" object, and "change" changes a spec value in that object.

  - Specifying the object name directly:

For example, if the currently defined primary specification name is "specif2", specify as follows to change the spec value.

`SPECIFICATION("specif2").change("T", 10);`

Both the statements which are shown in the above two ways execute the same thing if "specif2" is currently defined as the primary specification.

- When the change of the primary specification is specified in the PRIMARY_STATUS API, the spec value-changes specified in the SPECIFICATION API's class objects are cleared if the FLUSH API has not been executed for them yet.

If you need to reflect these changes (into the MCD), execute FLUSH once before specifying another primary specification name in the PRIMARY_STATUS API. In the following example, FLUSH is not executed before the change to "specif3" is specified. Therefore, the changes specified for "T" and "T2" are ignored (not executed).

```
Primary.timing(SPECIFICATION("specif2"));
FUNCTIONAL_TEST();
TEST(TM::CONTINNUE);
Primary.getSpecification().change("T", 10);
Primary.getSpecification().change("T2", 20);
Primary.timing(SPECIFICATION("specif3"));
FLUSH();
```

- After the FLUSH API is executed to change the spec values in a testsuite, the changes are used in the subsequent testsuites (unless you load a timing setup file during debugging). If you want to use the original spec values in the next testsuite, execute the "restore" member function and FLUSH API in the test method program of the testsuite where you changed the spec values. "restore" returns the values of specs to the ones when the test method program of the current testsuite is started.
- The "change" member function and FLUSH API change a spec value, but the Test Program Explorer does not indicate the timing is changed. In this case, if you need to reload the current timing setup file during debugging, first change a spec value in the Spec Tool window to cause the Test Program Explorer to indicate the timing is changed.

## Examples

### Example 1: Change primary timing spec set

```
Primary.timing(SPECIFICATION("specif2"));
Primary.timing(1, "Port2");
FUNCTIONAL_TEST();
```

The PRIMARY_STATUS API timing member functions define the specification specif2 as the primary, and define the timing set 1 for the port Port2 as the primary. The specification name must be specified using the corresponding object name (SPECIFICATION("specif2")). The FUNCTIONAL_TEST API reflects these changes to the hardware then executes a functional test.

### Example 2: Retrieve primary spec values

```
Primary.getSpecification().getSpecValue("Tp@port1");
Primary.getSpecification().getSpecValue("Ed1@port2");
Primary.getSpecification().getSpecValue("Ed1@port3");
FUNCTIONAL_TEST();
```

The first line queries the timing spec Tp of port1 in the currently defined primary specification. The second line and the third line query the per-port spec Ed1 of port2 and port3. The Primary.getSpecification statement returns the SPECIFICATION API's class object that represents the specification that is currently defined as the primary.

```
SPECIFICATION& s_obj = Primary.getSpecification();
s_obj.getSpecValue("Tp@port1");
s_obj.getSpecValue("Ed1@port2");
s_obj.getSpecValue("Ed1@port3");
FUNCTIONAL_TEST();
```

These do the same thing as the previous example by creating the object explicitly once. By the ampersand (&) in the first statement, s_obj is created as a reference to the object returned by Primary.getSpecification (without copying the contents of the object).

```
Primary.getSpecification().getSpecValue("Ta");
Primary.getSpecification().getSpecValue("Pt");
FUNCTIONAL_TEST();
```

These query the (global) specs Ta and Pt (which have common values in all ports) in the specification currently defined as the primary.

### Example 3: Change primary spec values

```
Primary.getSpecification().change("Tp@port1", 10);
Primary.getSpecification().change("Ed1@port2", 30);
Primary.getSpecification().change("Ed1@port3", 60);
FUNCTIONAL_TEST();
```

The first line changes the timing spec Tp of port1 in the currently defined primary specification to 10 ns. The second line and third line change the per-port spec Ed1 of port2 and port3. The Primary.getSpecification statement returns the SPECIFICATION API's class object that represents the specification that is currently defined as the primary.

```
SPECIFICATION& s_obj = Primary.getSpecification();
s_obj.change("Tp@port1", 10);
s_obj.change("Ed1@port2", 30);
s_obj.change("Ed1@port3", 60);
FUNCTIONAL_TEST();
```

These do the same thing as the previous example by creating the object explicitly once. By the ampersand (&) in the first statement, s_obj is created as a reference to the object returned by Primary.getSpecification (without copying the contents of the object).

```
Primary.getSpecification().change("Ta", 50);
Primary.getSpecification().change("Pt", 10);
FUNCTIONAL_TEST();
```

These change the (global) specs Ta and Pt (which have common values in all ports) in the specification currently defined as the primary.

### Example 4: Retrieve primary specification name

```
STRING s_name;
 s_name = Primary.getSpecification().getName();
```

The [getName()](<02.07.04.01.232_SPECIFICATION.md#_29771__dle_getName>) member function returns the specification name currently defined as the primary.
