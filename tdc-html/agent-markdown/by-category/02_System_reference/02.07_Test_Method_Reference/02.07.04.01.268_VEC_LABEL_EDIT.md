# VEC_LABEL_EDIT

This API enables modifying label vectors at runtime on the specified digital pins of a certain site, while remaining pins continue executing the original vectors. The editing operation will overwrite the drive/receive actions in the specified label with a user defined action. The vector data will be overwritten directly in the corresponding memory.

The VEC_LABEL_EDIT() API supports the following features:

- Edit arbitrary vectors in a label. Any label of type "Main" or "SVEC" is supported except the labels containing subroutines.

For multi-port setups, the multi-port labels can be edited but the multi-port burst label cannot be edited.

- Set the specified pins of a certain site to a static mode. Once a pin is set to a constant action, it will only be able to generate that action independently of what the vector label contains. Once the pin is released from constant action, it will resume its normal operation.
- Store some vector data of the label to be edited. If needed, the stored vectors will be restored. After the restore operation, the original vector data of the label will be used for later test.
- Hidden download: To save test time you can download data, while the sequencer is running.

This API can be used when different test sites must undergo different programming due to prior pattern pass/fail conditions. It can also be used to do vector update of a specific site.

Which site this API will apply on depends on the scope of the call.

- Any call outside the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block:

If an upload (store) operation is called it will only store data for the site in focus.

If a download operation is called, the data will be downloaded only to the current site being executed.

- Any call inside the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block:

This will address all sites. The upload and download operation will be done on all sites. If a store operation is called, the vector data will be read for each site and stored.

- Any call inside [FOR_EACH_SITE](<02.07.04.01.70_FOR_EACH_SITE_BEGIN.md>) loop:

The operation will only be executed on the current site in the loop. Store operation will store the data of the current site in the loop.

Note See the related API [GET_PHY_WVF_IDX](<02.07.04.01.93_GET_PHY_WVF_IDX.md>).

## Class definition

  Constructor

```
VEC_LABEL_EDIT(const STRING& labelName, const STRING& pinList);
```

 Data type VECTOR_DATA and array of VECTOR_DATA The data type VECTOR_DATA holds a pair of vector number and a physical waveform index:

```
typedef struct
{
    int vectorNum;
    int phyWvfIndex;

} VECTOR_DATA;
```

Vector data for the VEC_LABEL_EDIT() API are to be defined defined as array of VECTOR_DATA. The end of an array of VECTOR_DATA must be marked by appending the predefined element VEC_LABEL_EDIT::VEC_END or by setting the last element to {-1,-1}.

## Constructor

```
VEC_LABEL_EDIT(const STRING& labelName, const STRING& pinList);
```

This constructor creates a class object of this API. It initializes the class object and fills it with all the required data related to the given label. It also creates a cache container for each site. The cache is empty at this point and can be used to store vector data.

This class can also be used to set a pin to only generate one specific waveform. If you only need this functionality, the first parameter labelName can be left empty(recommended for performance). This way you cannot use any label editing functions of the API.

  Parameters

 | labelName  | The label to be modified. If only the constant mode functionality is used, it's highly recommended to leave this parameter empty. |
 | pinList  | The pins for which the vector data will be modified. Only a single pin name or pin list is valid. Group names and port names are not allowed.   |  Constructor example

```
VEC_LABEL_EDIT myVectorLabelEdit("myLabelName", "myPin");

myVectorLabelEdit.<member_func>;
```

or

```
VEC_LABEL_EDIT("myLabelName", "myPin").member_function;
```

In which:

 |   | member_function:  | Member functions of the `VEC_LABEL_EDIT` API. |
 |   | myLabelName:  | The label of which the vector to be edited. |
 |   | myPin:  | The pin on which the vector to be edited. |

## Member functions

  downloadUserVectors()

```
VEC_LABEL_EDIT& downloadUserVectors(VECTOR_DATA vectorDATA[], INT numOfVectors);
```

This member function overwrites one or more of the vector data in the specified label of the specified pins or pin lists. The function will operate only on the first pin that has been defined by the [constructor](<02.07.04.01.268_VEC_LABEL_EDIT.md#_95305__rs_Constructor>).

Parameters
 | vectorDATA  | An array of [VECTOR_DATA](<02.07.04.01.268_VEC_LABEL_EDIT.md#_95305__dle_VECTOR_DATA>) that defines the new vector data. |
 | numOfVectors  | The number of vector entries stored in the array vectorDATA. |

```
VEC_LABEL_EDIT& downloadUserVectors(const char* pinListCstr, ...);
```

This member function overwrites one or more of the vector data in the specified label. The function operates on the pin list defined by pinListCstr. The function uses a variable list of arguments to handle different vector data on the defined pins.

Parameters
 | pinListCstr  | The pins or pin lists to overwrite. |
 | ...  | The input vector data as variable list of arguments. The expected arguments are arrays of type [VECTOR_DATA](<02.07.04.01.268_VEC_LABEL_EDIT.md#_95305__dle_VECTOR_DATA>). The order of the arguments must be same with the order of the input pin list pinListCstr.

If the number of input arguments is less than the pin number, use the variable VEC_LABEL_EDIT::PARA_END to mark the end of the vector data list. The following pins will use the last argument as input data.

If the number of VECTOR_DATA is more than the pin number, the redundant VECTOR_DATA will be ignored.

  |  downloadUserVectorRange()

```
VEC_LABEL_EDIT& downloadUserVectorRange(INT startVector, INT numOfVectors, INT physWfIndex);
VEC_LABEL_EDIT& downloadUserVectorRange(INT startVector, INT numOfVectors, INT physWfIndex, const char* pinListCstr);
```

This member function downloads the specified physical waveform to the specified range of vectors of the specified pins. If no pins are specified, the physical waveform will be downloaded to all the pins. All vectors in the range will be programmed to the same waveform.

Parameters
 | startVector  | The first vector in the vector range to be overwritten. This is the logical vector number. |
 | numOfVectors  | The number of vectors to be overwritten starting from startVector. |
 | physWfIndex  | The index of the physical waveform to be written to the specified vector range. |
 | pinListCstr  | The pin or pin list to change.  |  storeVectorData()

```
VEC_LABEL_EDIT& storeVectorData();
VEC_LABEL_EDIT& storeVectorData(const char* pinListCstr);

VEC_LABEL_EDIT& storeVectorData(INT startVector, INT numOfVectors);
VEC_LABEL_EDIT& storeVectorData(INT startVector, INT numOfVectors, const char* pinListCstr);
```

This member function reads vector data from the label and stores it internally in the class object:

- If no parameter is specified, the whole label data for all pins will be stored. This is not recommended as it might be time consuming for large labels.
- If the parameter pinListCstr is specified, the vector data for the specified pins will be stores.
- If startVector and numOfVectors are specified, the vector data from startVector to startVector + numOfVectors -1 will be stored.

The stored data will be the source for any later [restore](<02.07.04.01.268_VEC_LABEL_EDIT.md#_95305__dle_restoreVectorData>) operation. If the vector data has already been stored and is still up-to-date, the operation will be skipped.

Parameters
 | pinListCstr  | The pin or pin list for which the vectors will be stored. |
 | startVector  | The logical number of the first vector in the label that will be stored. Initialized to 0 if not used. |
 | numOfVectors  | The number of vectors to be stored (starting from startVector). Initialized to the size of the label if not used.  |  restoreVectorData()

```
VEC_LABEL_EDIT& restoreVectorData();
VEC_LABEL_EDIT& restoreVectorData(const char* pinListCstr);
```

This member function restores the vector data in the vector label to the state stored internally in the VEC_LABEL_EDIT object. Only the vectors stored by [storeVectorData()](<02.07.04.01.268_VEC_LABEL_EDIT.md#_95305__dle_storeVectorData>) will be restored.

Parameter
 | pinListCstr  | The pin or pin list for which the vectors will be restored.  |  setPinToConstantAction()

```
VEC_LABEL_EDIT& setPinToConstantAction(INT phyWvfIndex);
VEC_LABEL_EDIT& setPinToConstantAction(INT phyWvfIndex, const char* pinListCstr);

VEC_LABEL_EDIT& setPinToConstantAction(const STRING& wvfString);
VEC_LABEL_EDIT& setPinToConstantAction(const STRING& wvfString, const char* pinListCstr);
```

This member function sets the specified pins of the site in focus to a constant action (waveform) mode. The pin in this mode can only generate the given waveform or the break waveform. The given waveform can be a defined waveform (phyWvfIndex) or a completely new one (wvfString). This function will automatically detect the primary timing specset and it will alter the wavetable that is used in that specset.

Since a wavetable can be shared between several specsets, all the specsets using the same wavetable will be affected. So it is important to release a pin from constant mode whenever it is no longer used.

Parameters
 | pinListCstr  | The pin or pin list to set. |
 | phyWvfIndex  | The physical waveform that will be applied to the pin while it is in constant mode. |
 | wvfString   | A new waveform that will be applied to the pin while it is in constant action mode. It should be defined in the standard waveform string index "d1:F10 d2:F00" or "d1:1 d2:0".  |  releasePinFromConstantAction()

```
VEC_LABEL_EDIT& releasePinFromConstantAction();
VEC_LABEL_EDIT& releasePinFromConstantAction(const char* pinListCstr);
```

This member function releases the specified pins from constant action mode. The pins will resume its normal behavior (using vectors from the vector label). If the pins were not set to constant action mode using setPinToConstantAction(), nothing will happen.

Parameter
 | pinListCstr  | The pin or pin list to release.  |  isPinInConstantAction()

```
Boolean isPinInConstantAction()
Boolean isPinInConstantAction(const char* pinListCstr);
```

This function returns whether the specified pins are in constant action mode or not.

Parameter
 | pinListCstr  | The pin or pin list to query. |

## Examples

### Example 1

```
VEC_LABEL_EDIT myLabel("myLabelName", "myPin");

VECTOR_DATA myVectorData[3] = {{10, 0}, {12, 5}, {15, 3}};

myLabel.storeVectorData(10, 6);

myLabel.downloadUserVectors(myVectorData, 3);
...
...
myLabel.restoreVectorData();
```

The first line creates a class object of VEC_LABEL_EDIT and defines the label and pin to be edited.

 The second line defines the vectors that will be changed and their corresponding new values: Switch

- vector 10 to action 0,
- vector 12 to action 5 and
- vector 15 to action 3.
In the third line, the vector data from vector 10 to 15 is stored.

The data defined in myVectorData is downloaded to "myLabel" in the fourth line.

After testing with the modified vectors, the last line restores the vector data to the original one.

### Example 2

```
VEC_LABEL_EDIT("","myPin").setPinToConstantAction(1);
...
...
VEC_LABEL_EDIT("","myPin").releasePinFromConstantAction();
```

This example sets "myPin" to the constant action 1. Then in the following test "myPin" will only generate waveform 1 or break waveform. The last line releases "myPin" from constant mode. This pin will generate the waveforms defined in the vector label.

### Example 3

```
VEC_LABEL_EDIT myLabel("myLabelName", "myPin1, myPin2, myPin3");

VECTOR_DATA myVectorData1[] = { {10, 0}, {12, 5}, {15, 3}, VEC_LABEL_EDIT::VEC_END};
VECTOR_DATA myVectorData2[] = {  {2, 1},  {5, 3},  {8, 5}, {10, 1}, {-1, -1}};

myLabel.storeVectorData(10,6, "myPin1, myPin2");

myLabel.downloadUserVectors("myPin1, myPin2", myVectorData1, myVectorData2);
...
...
myLabel.downloadUserVectors(VEC_LABEL_EDIT::ALL_PINS, myVectorData1,
                                                     VEC_LABEL_EDIT::PARA_END);
...
...
myLabel.restoreVectorData("myPin1, myPin2");
```

This example firstly create an instance of VEC_LABEL_EDIT and defines the vector data to use. Then it stores the vector data from 10 to 15 for pins "myPin1" and "myPin2". Next it downloads myVectorData1 to "myPin1" and myVectorData2 to "myPin2".

After some other action, it downloads myVectorData1 to all three pins: The variable list of arguments is closed by VEC_LABEL_EDIT::PARA_END after the first array has been defined.

At last, the stored vector data for "myPin1" and "myPin2" is restored.

### Example 4

```
VEC_LABEL_EDIT myLabel("myLabelName", "myPin");

START_TEST();

for (int startVector = 0; startVector < 500; startVector++)
{
    myLabel.downloadUserVectorRange(startVector, 1, 0);
}

WAIT_TEST_DONE();

TEST();
```

This example downloads vector data while the sequencer is running.
