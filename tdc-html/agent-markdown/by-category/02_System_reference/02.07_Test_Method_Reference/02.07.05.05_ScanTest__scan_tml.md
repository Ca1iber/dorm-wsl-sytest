# ScanTest (scan_tml)

Performs a functional test using the specified primaries, retrieves the fail cycles on the scanPins from the error map and sends them to the EDL stream for logging in STDF-V4/2007 format. Additionally, it dumps the retrieved fail cycles to the report window and(or) to a text file if the output parameter is set to do so.

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

pin(s) or pin group(s) to collect the failing cycles. It is usually a pin group holding all the scan outputs.

maxFailsPerPin

 |

the maximum number of failing cycles of a pin to be logged

perLabelBasedMaxFails

 |

string

 |

if set to true, considers maxFailsPerPin as the upper limit of failing cycles to be logged for each label (rather than the whole burst), when a burst label is used.

Default is false, which means this parameter is disabled and maxFailsPerPin is still regarded as the upper limit of failing cycles to be logged across the whole burst.

As a sub-parameter of cycleNumberPerLabel, it is only visible if `cycleNumberPerLabel == true` AND `maxFailsPerPin > 0`.

 |
 |

extraFailureFlag

 |

string

 |

this flag lets user know whether there are extra failing cycles discarded by datalog because the total failing cycles count exceeds the maxFailsPerPin limit.

If set to true, adds a flag in datalog which marks whether there are more failing cycles than the logged ones.

- When extra failing cycles exist, the FAIL_MAP field in the STR record reports 1.
- When extra failing cycles do not exist, the FAIL_MAP field in the STR record reports 0.

Default is false, which means not to add this flag into datalog.

As a sub-parameter of maxFailsPerPin, it is only visible if maxFailsPerPin > 0.

 |
 |

stopAtSameCycle

 |

string

 |

if set to true, compares the first failing cycles reaching the maxFailsPerPin limit throughout all scan pins, to find out the lowest failing cycle and stops logging failures when this failing cycle is reached for each pin.

Default is false, which means this parameter is disabled and datalog stops logging failing cycles when the total failures count exceeds maxFailsPerPin for each pin.

As a sub-parameter of maxFailsPerPin, it is only visible if maxFailsPerPin > 0.

 |

output

 |

string

 |

specifies if the collected failing cycles are output to the report window and(or) a text file in addation to being sent to the datalog stream.

 It can be:

- none : Do not output to thereport window or a text file, only send the failing cycles to the EDL stream
- File: In addation to sending the failing cycles to the EDL stream, output the failing cycles to a text file. The file is named as <test suite name>_<pattern name>_Site<sitenr>_<timestamp> and located in the report sub-directory of the current device directory.
- ReportUI: In addation to sending the failing cycles to the EDL stream, output the failing cycles to the report window.

For the details of the output, refer to the example section below.

The output of the failing cycles are currently only available for cycle-based format (cycleBased = 1).

## Examples

### Scan test output

The example shows the content of the scan test output. In the output, the pattern name, the number of total failing cycles, the failed site(s), and the details of each failure are shown. For each failure happened, its cycle number, the failed pin name, the expected result (1 for H and 0 for L) and the received result (1 for H and 0 for L) are listed. The failures are listed according to the order of the cycle number.

```
Pattern: spec_search
Total fails: 9
Site: 1
fail nr |    cycle number |        pin name | E | R
----------------------------------------------------
      1 |               8 |            I/O1 | 1 | 0
      2 |               8 |            I/O2 | 0 | 1
      3 |               9 |            I/O2 | 1 | 0
      4 |               9 |            I/O3 | 0 | 1
      5 |              10 |            I/O2 | 1 | 0
      6 |              10 |            I/O4 | 0 | 1
      7 |              11 |            I/O3 | 1 | 0
      8 |              11 |            I/O5 | 0 | 1
      9 |              12 |            I/O3 | 1 | 0
```

### Example of using the maxFailsPerPin parameter

 Assume a scan test failed in the following burst. maxFailsPerPin is set to 5.

 | Burst  | Cycle range  | Failing cycles of pin 1  | Failing cycles of pin 2 |
 | label 1  | 1-10  | 5-10  | 1-3, 6-8 |
 | label 2  | 11-20  | 11  | 11-15 |
 | label 3  | 21-30  | 21-26  | 29 |

If both perLabelBasedMaxFails and stopAtSameCycle are set to false, failing cycles are logged as follows.

 | Burst  | Failing cycles logged for pin 1  | Failing cycles logged for pin 2 |
 | label 1  | 5-9 *  | 1-3, 6-7 * |
 | label 2  | **  | ** |
 | label 3  | **  | ** |
 |

*: Only the first 5 failing cycles are logged. All failing cycles that come after them are discarded. If extraFailureFlag is set to true, the FAIL_MAP field of the STR record reports 1 - extra failing cycles happened.

**: No data are logged for labels 2 and 3 because the burst reaches the maxFailsPerPin limit on label 1. |

If perLabelBasedMaxFails is set to true, and stopAtSameCycle is set to false, failing cycles are logged as follows.

 | Burst  | Failing cycles logged for pin 1  | Failing cycles logged for pin 2 |
 | label 1  | 5-9 *  | 1-3, 6-7 * |
 | label 2  | 11  | 11-15 |
 | label 3  | 21-25 *  | 29 |
 | *: Only the first 5 failing cycles are logged. All failing cycles that come after them are discarded. If extraFailureFlag is set to true, the FAIL_MAP field of the STR record reports 1 - extra failing cycles happened. |

If both perLabelBasedMaxFails and stopAtSameCycle are set to true, failing cycles are logged as follows.

 | Burst  | Failing cycles logged for pin 1  | Failing cycles logged for pin 2 |
 | label 1  | 5-7 **  | 1-3, 6-7 * |
 | label 2  | 11  | 11-15 |
 | label 3  | 21-25 *  | *** |
 | *: Only the first 5 failing cycles are logged. All failing cycles that come after them are discarded. If extraFailureFlag is set to true, the FAIL_MAP field of the STR record reports 1 - extra failing cycles happened.

**: Pin 1 stops at the same cycle as pin 2 (failing cycle 7, the 1st lowest cycle that reaches the maxFailsPerPin limit). All failing cycles larger than 7 are discarded.

***: Pin 2 stops at the same cycle as pin 1 (failing cycle 25, the 1st lowest cycle that reaches the maxFailsPerPin limit). All failing cycles larger than 25 are discarded so no data is logged for pin 2.

## Functional changes

- Introduced in SmarTest 6.5.0
- SmarTest 7.0.3: New parameter testName.
- SmarTest 7.0.3: Test table is supported.
- SmarTest 7.1.1: Mixed usage of test table and testflow limits in one testflow is supported in TML 2.1.1.
- SmarTest 7.2.1: New parameter output.
- SmarTest 7.4.4: New parameters "perLabelBasedMaxFails", "extraFailureFlag" and "stopAtSameCycle" to make the parameter "maxFailsPerPin" work for each label and log the extra failures when number of failures exceeds the "maxFailsPerPin" upper limit.
