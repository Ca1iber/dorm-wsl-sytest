# Executing a Transition Search

#### Subtopics

- [Parallel Search and Search Set Management](<02.07.03.03.08.01_Parallel_Search_and_Search_Set_Management.md>)
- [Using embedded timing and level search on a Smart Scale system](<02.07.03.03.08.02_Using_embedded_timing_and_level_search_on_a_Smart_Scale_system.md>)

Transition searches repeat a functional test in a loop. With each test execution, one and the same parameter is systematically modified within a certain range. The goal of such a search is to identify that value of the parameter where the test result changes from PASS to FAIL or vice versa. The parameter that is modified can be a spec variable or a resource parameter. Currently, the resource must be a (drive or receive) edge.

There are two main types of transition search.

- Spec search (SPEC_SEARCH API).

This type varies the value of a spec variable for all pins or a subset of the pins (the setup pins) within a certain range. You can also restrict the output pins whose results decide on the test result (the result pins), to a subset of the configured pins.

- Parallel search (SEARCH_FUNC_TASK API).

This search type is much more powerful. It allows you to execute different searches in parallel. The granularity is per pin and site, that is, the search conditions can be different for different setup pins on the same site, and also for the same setup pin on different sites. Of course, this enhances the throughput considerably.

Furthermore, you can change not only spec variables, but also modify edge positions directly.
