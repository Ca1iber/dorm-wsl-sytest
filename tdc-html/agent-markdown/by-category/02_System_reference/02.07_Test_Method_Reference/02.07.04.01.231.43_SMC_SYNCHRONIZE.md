# SMC_SYNCHRONIZE()

Waits for the end of the execution of all threads which have been started using [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>). After all threads have finished their upload and calculation task the queued [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) statements will be executed to perform the data logging and binning.

If [Hidden data logging](<02.07.10.04.09_Hidden_data_logging.md>) is used, binning is not handled in SMC_SYNCHRONIZE(), but in your [SMC_backgroundProcessing()](<02.07.10.04.03_Four-step_SmartCalc_implementation.md>)[ method](<02.07.10.04.03_Four-step_SmartCalc_implementation.md>). For details on binning rules, see [Use of bins with multisite tests](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.02.06.08_Use_of_bins_with_multisite_tests.md>) and [Use of multibins](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.02.06.07_Use_of_multibins.md>).

SMC_SYNCRONIZE() has to be called per site and thus outside of an [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block.

To properly synchronize a test flow with the ["thread per site" or the "common thread"](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>) implementation and also a mixture of both, refer to [Synchronize a test flow with any use model](<02.07.10.05_SmartCalc_recommendations.md#_119876__s_Synchronize_a_test_flow_with_any_use_model>) in [SmartCalc recommendations](<02.07.10.05_SmartCalc_recommendations.md>).

## Syntax

```
Boolean SMC_SYNCHRONIZE(DOUBLE timeout = 0);
Boolean SMC_SYNCHRONIZE(DOUBLE timeout, Boolean forceErrorExitOnFail);
Boolean SMC_SYNCHRONIZE(INT *noOfSMCExecutedTests, DOUBLE timeout = 0);
Boolean SMC_SYNCHRONIZE(INT *noOfSMCExecutedTests, DOUBLE timeout, Boolean forceErrorExitOnFail);
```

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.

  Parameters

 | Parameter  | Description/Range |
 | timeout |

The time in seconds after which a thread should be canceled and SMC_SYNCHRONIZE() should not wait for its completion.

Resolution: 1 µs

The accuracy of this parameter is influenced by the overhead time of the operating system.

The default value is 0.0 seconds which means that no timeout is set.

 |
 | noOfSMCExecutedTests  | References a pointer to store the number of [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) statements which have been executed during this synchronize operation per site. Note

When using the class SMC_ARM_FOR_SITES() or SMC_ARM_OTHER_TS_FOR_SITES(), SMC_SYNCHRONIZE() does not not return a test count. As a result, noOfSMCExecutedTests is not incremented and does not count the number of calls to SMC_TEST().

 |
 | forceErrorExitOnFail |

Enables a forced exit on an error. If set to

-

true - it causes an exception in case a calculation routine had to be aborted.

-

false - it causes SMC_SYCHRONIZE() to return false in case a calculation routine had to be aborted.

   |  Return value

Returns false in case threads had to be terminated or an invocation error occurred, else true is returned.

If the noOfSMCExecutedTests parameter is used, the number of [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) statements which have been executed during this synchronize operation per site will be stored in the integer variable referenced by the pointer.

## Example

Waits for all calculations to be finished within 100 ms. After the timeout of 100 ms all other still running calculation threads will be terminated!

```
SMC_SYNCHRONIZE(100 ms);
```

Waits for all calculations to be finished within 10 ms. After the timeout of 10 ms all other still running calculation threads will be terminated! In case a calculation had to terminated, SMC_SYNCRONIZE() throws an exception.

```
SMC_SYNCHRONIZE(10 ms, true);
```
