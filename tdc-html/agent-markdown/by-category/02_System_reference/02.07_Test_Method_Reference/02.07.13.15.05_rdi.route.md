Creates a "routeGroup" object for controlling setups of the Routing Tools.

This class handles all states that have been defined by the [Routing Tools editors](<02.07.13.15.01_Routing_Tools_editors.md>). The class translates the state setup table of the [State Setup editor](<02.07.13.15.01.04_Routing_Tools_-_State_Setup_editor.md>) into executable pattern and provides functions for downloading the MUX cards states to the setup memory of the cards. The class additionally provides functions for applying or activating the states, clearing all connections and modifying PMUX switches.

The created routeGroup object can only be accessed via the rdi() class.

 Note In SmartRDI, utility lines may be controlled by the rdi.util() class or by the rdi.route() class of the [Routing Tools](<02.07.13.15_SmartRDI__DUT_board_connections_control_by_Routing_Tools.md>). In addition, the utility lines may be controlled by test method APIs, firmware commands or the "Routing Setup Tool".

This may lead to conflicts if the same utility line is controlled by more than one API or tool.

For SmartRDI we therefore strongly recommend, controlling utility lines either by the rdi.route() class or by the rdi.util() class. The mixed use of the two APIs or other test method APIs and tools is not recommended. This recommendation applies to code鈥慴ased programming and to pattern鈥慴ased programming.

Code鈥慴ased programming for the rdi.route() means that the utility lines are set to "static" in the "Control table" of the [Utility Lines Control editor](<02.07.13.15.01.02_Routing_Tools_-_Utility_Lines_Control_editor.md>). Pattern鈥慴ased programming for the rdi.route() means that the utility lines are set to "dynamic" in the "Utility Lines Control editor".
