# SMC_PIN_ERROR_MAP.getFirstFailingXmodeCycles()

Retrieves the failing tester cycles that occur after the specified start tester cycle. This records failing tester cycles in the specified x-mode.

The parameter cycleXmodeMapping is a std::vector with a [CYCLE_XMODE_MAPPING](<02.07.04.01.231.27.02_SMC_PIN_ERROR_MAP.getFirstFailingXmodeCycles.md#_149669__dle_CYCLE_XMODE_MAPPING_struct>) struct that defines the x-mode used for the tester cycles. This is used to map the failing edge information to x-mode cycles.

The CYCLE_XMODE_MAPPING struct describes an x-mode area of the pattern. The x-mode area is specified by the xMode and the startTesterCycle variables.

If the pattern uses multiple x-modes, you must specify multiple CYCLE_XMODE_MAPPING structs.

For example, if a burst contains two main labels, one in x4 and one in x2-mode, you must specify two CYCLE_XMODE_MAPPING structs, each specifying the startTesterCycle of the corresponding x-mode.

If you want to specify a specific x-mode for the entire pattern, you only need to define one CYCLE_XMODE_MAPPING struct specifying 0 as startTesterCycle.

## Syntax

```
LONG getFirstFailingXmodeCycles(const LONG_LONG                         startXmodeCycle,
                                const LONG_LONG                         maxNumberOfFailingCycles,
                                const std::vector<CYCLE_XMODE_MAPPING> &cycleXmodeMapping,
                                ARRAY_LL                               &failingXmodeCycles,
                                bool                                   &fewerFailsReturnedDueToEmapFull);
```

  CYCLE_XMODE_MAPPING struct

```
typedef struct
{
    long long startTesterCycle;
    int       xMode;

} CYCLE_XMODE_MAPPING;
```

 Parameters

 | Parameter  | Description |
 | startXmodeCycle |

The first xmode cycle after which the reporting of failing xmode cycles starts.

0 represents the first xmode cycle.

 |
 | maxNumberOfFailCycles  | The number of failing xmode cycles to report. |
 | cycleXmodeMapping  | The x-mode mapping struct of type [CYCLE_XMODE_MAPPING](<02.07.04.01.231.27.02_SMC_PIN_ERROR_MAP.getFirstFailingXmodeCycles.md#_149669__dle_CYCLE_XMODE_MAPPING_struct>). |
 | failingXmodeCycles  | Container where the failing cycles are reported to. |
 | fewerFailsReturnedDueToEmapFull |

A flag that indicates that the error map is full and thus not all failing tester cycles were reported.

true = error map is full, less failing tester cycles reported than requested.

false = error map is not full, the requested failing tester cycles are reported.

Note: If less failing tester cycles occurred in the test than requested and the error map is not full, this flag will be false.

   |  Return value

Returns the number of failing tester cycles that are copied to the referenced failingXmodeCycles array.

If the error map runs full and less failing tester cycles can be reported than requested, the referenced fewerFailsReturnedDueToEmapFull parameter returns true.

## Examples

### Example 1: Specify two different x-modes

This example shows how to specify two different x-modes for a busted pattern that has 1000 tester cycles in x4-mode and 1000 tester cycles in x2-mode.

```
//
// Declare the vector "cycleXmodeMapping" that holds the list of x-mode areas
//
std::vector<CYCLE_XMODE_MAPPING> cycleXmodeMapping;

//
// Declare the xModeMapping type to be of CYCLE_XMODE_MAPPING type,
// specify x4-mode for the first tester cycles
// and append the definition to the list of x-mode areas
//
CYCLE_XMODE_MAPPING xModeMapping;

xModeMapping.startTesterCycle = 0;
xModeMapping.xMode            = 4;

cycleXmodeMapping.push_back(xModeMapping);

//
// Specify x2-mode for the remaining tester cycles
// and append the definition to the list of x-mode areas
//
xModeMapping.startTesterCycle = 1000;
xModeMapping.xMode            = 2;

cycleXmodeMapping.push_back(xModeMapping);
```

### Example 2: Specify the CYCLE_XMODE_MAPPING to be used with the getFirstFailingXmodeCycles()

This example shows how to specify the CYCLE_XMODE_MAPPING to be used with the getFirstFailingXmodeCycles API and how to use the SMC_PIN_ERROR_MAP_ACCESSOR with multiple pins and a result area.

```
protected:

    virtual void initialize()
    {
    }

    virtual void run()
    {
        ON_FIRST_INVOCATION_BEGIN();
        {
            //
            // Configure error map modes before test execution
            //
            ERROR_MAP_TEST emap(TM::XMODE_CYCLES);

            //
            // Results must be in RAM for the SMC_PIN_ERROR_MAP API
            //
            emap.pin("@").setLocation(TM::RAM)
                         .setRecordingMode(TM::PF);

            //
            // Optionally: configure a result area
            //
            RESULT_AREA_CONFIG_SET resConfig("resultAreaName");

            resConfig.pin("@").setErrorMapResultAreaSize(100000);
            resConfig.setAsPrimary();

            SMC_FUNCTIONAL_TEST();

            resConfig.deselectGlobally();
        }
        ON_FIRST_INVOCATION_END();

        //
        // Add the pins that are passed to SMC_PIN_ERROR_MAP_ACCESSOR.
        // This enables you to access the error maps of multiple pins
        //
        std::vector<STRING> pins;

        pins.push_back("DATA1");
        pins.push_back("DATA2");
        pins.push_back("DATA3");
        pins.push_back("DATA4");

        //
        // The amount of data to upload
        //
        const int maxFailsPerPin = 16;

        //
        // Arm a background process per site
        //
        SMC_ARM(pins, maxFailsPerPin);

        return;

    } // virtual void run()

public:

    void SMC_backgroundProcessing(std::vector<STRING> pins, int maxFailsPerPin)
    {
        ARRAY_LL    failCycles;
        int         site        = SMC_SITE_NUMBER();

        //
        // You can use an empty string "" if you do not use a result area
        //
        SMC_PIN_ERROR_MAP_ACCESSOR errorMaps(site, pins, "resultAreaName", maxFailsPerPin);

        SMC_PIN_ERROR_MAP &errorMapsResults(errorMaps.getSmcPinErrorMap("DATA4"));

        //
        // Define how the edge results are mapped to x-mode cycles
        // here the entire pattern is specified to be x4-mode
        //
        CYCLE_XMODE_MAPPING                 xModeMapping;
        std::vector<CYCLE_XMODE_MAPPING>    cycleXmodeMapping;

        xModeMapping.startTesterCycle = 0;
        xModeMapping.xMode            = 4;

        cycleXmodeMapping.push_back(xModeMapping);

        //
        // Retrieve the first 16 failing cycles
        //
        const LONG_LONG startCycle      = 0;
        const LONG_LONG maxFailCycles   = 16;

        bool fewerFailsReturnedDueToEmapFull;

        errorMapsResults.getFirstFailingXmodeCycles(startCycle, maxFailCycles, cycleXmodeMapping, failCycles, fewerFailsReturnedDueToEmapFull);

        cout << "Site " << site << ": " << failCycles << endl;

    } // SMC_backgroundProcessing(std::vector<STRING> pins, int maxFailsPerPin)
```

 Note

The example above contains a call of cout in function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to [Thread safety](<02.07.10.02.02_Thread_safety.md>).
