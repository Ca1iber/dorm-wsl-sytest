SmartRDI provides alarm checking commands to specify alarm sets, enable or disable alarm checking on pins, and set limit values.

 These commands are described in other individual topics. For detailed information, click the command name in the Function column to go to its specific topic.

Overview of alarm handling functions - Table I
 | Function  | Description  | Mode |
 | [rdi.alarm().applySet()](<02.07.13.09.02.01_rdi.alarm__.applySet.md>)  | Specify an alarm set.  | P, C |
 | [rdi.alarm().check().execute()](<02.07.13.09.02.02_rdi.alarm__.check__.execute.md>)  | Add an alarm checking event in any position inside an RDI_BEGIN-RDI_END block.

This command is the only alarm handling command that requires the usage of port in case of multiport setups.

The rule is: all commands that are completed by .execute() require .port() for multiport setups.

  | P |
 | [rdi.alarm().enable()](<02.07.13.09.02.03_rdi.alarm__.enable.md>)  | Enable or disable alarm checking on all pins  | P, C |
 | [rdi.alarm().pin().enable()](<02.07.13.09.02.05_rdi.alarm__.pin__.enable.md>)  | Enable or disable alarm checking on specified pins.  | P, C |
 | [rdi.id().getAlarmPassFail()](<02.07.13.09.02.07_rdi.id__.getAlarmPassFail.md>)  | Retrieves the alarm pass or fail result on a pin or the general alarm pass or fail result on all pins.  | |
 | [rdi.id().getAlarmBurstValue()](<02.07.13.09.02.06_rdi.id__.getAlarmBurstValue.md>)  | Gets alarm DC results on specified pins in burst.  | |

 | [rdi.id().getAlarmValue()](<02.07.13.09.02.09_rdi.id__.getAlarmValue.md>)  | Gets alarm DC results on specified pins per id.  | |

In the Mode column: C = Code-based, P = Pattern-based.

In the Mode column: C = Code-based, P = Pattern-based.

## Result retrieval

 SmartRDI provides rdi.id().getAlarmPassFail() for retrieving the alarm pass or fail result. For how to retrieve the alarm pass or fail result, see [rdi.id().getAlarmPassFail()](<02.07.13.09.02.07_rdi.id__.getAlarmPassFail.md>).Note An alarm fail can impact the burst pass/fail result. If an alarm check fails, the burst result fails too.

## Examples

```
rdi.alarm().applySet("abc"); // Use an alarm handing set "abc"

RDI_BEGIN();
  rdi.class(id)... // Each measurement with "id" triggers an alarm compare event after it
  ...
  rdi.alarm().check().execute(); // Add an alarm check point
RDI_END();

rdi.id("id").getAlarmPassFail("pinA"); // Alarm result of pinA, and any result "id" in burst
rdi.id("id").getAlarmPassFail();       // Alarm result for all alarm pins.
```

   Each of these commands takes effect in its test suite and subsequently keeps valid no matter where it is located, inside or outside an RDI_BEGIN-RDI_END block in the test suite.

```
RDI_BEGIN();
  rdi.alarm().globalLimitRelForcePercent(0.1);
...
RDI_END();

RDI_BEGIN();
... // the globalLimitRelForcePercent also takes effect.
RDI_END();
```
