# SET_USER_STRING

This API sets the specified user-defined testflow variable to a particular value, which can have been stored at a defined site. The variable must have been previously declared as type STRING, and the site must have been previously declared as type INT.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TestControl.h.

## Syntax

```
SET_USER_STRING(const STRING& name, const STRING& value);
SET_USER_STRING(const STRING& name, INT site, const STRING& value);
```

Parameters
 |

I/O

 |

Parameter

 |

Description / Range

 |
 |

I

 |

flag

 |

The user-defined user variable name.

 |
 |

I

 |

site

 |

Site number, must be in the range [1 ... MAX_SITES], where MAX_SITES is the maximum number of sites allowed by SmarTest.

 Note This is not the number of enabled or active sites. |
 |

I

 |

value

 |

A string value to be set for the specified variable.

   | Note @[string] is not supported as value: All string types of test method parameters do not regard and evaluate @[string] as a testflow variable.

## Examples

### For the current site only

The `SET_USER_STRING` API sets the variable specified by the parameter OperatorName to OperatorName_var of the current site (first example) or of site 2 (second example).

```
STRING OperatorName_var;
    :
SET_USER_STRING("OperatorName", OperatorName_var);
```

### For a particularly set site

You can get the variable in a later called test method even if you executed the initialization test method for different sites:

```
...
STRING factory_name = getFactoryName(); // returns the name of the factory
SET_USER_STRING("factory", 1, factory_name); // site-independent value is stored at site 1
...
```

Get the variable:

```
...
STRING factory_name;
GET_USER_STRING("factory", 1, factory_name);
report_stream << "Factory Name: " << factory_name << endl;
...
```
