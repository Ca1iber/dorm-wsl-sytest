# Timing of DC events - DPS128 / DPS64

The settling time and data processing time of the front end and a minimum number of vectors between DC events or at the end of a pattern has to be respected when using DC event based programming of the [DC Scale DPS128/DPS64 cards](<../02.05_Test_Head_Cards/02.05.05.01_DC_Scale_DPS128_DPS64_cards.md>).

The following table shows the execution time that consists of the settling time for the front end and the minimum number of vectors that are required:

- Vectors: The table shows the minimum number of vectors that are required between DC events or between the last DC event in a pattern and the end of the pattern in light blue, and the number of vectors automatically added by SmartRDI in dark blue.
- Time: The table shows the mandatory execution time and typical values of settling time in light blue. The real settling time values depend on the DUT board and the DUT. The dark blue column shows the wait time automatically added by SmartRDI.

For common information regarding the timing of DC events refer to [Timing of DC events](<02.07.04.01.63.01.01_Timing_of_DC_events.md>).

## Note on wait time

 Note Note that in some use cases you must program additional wait time, as the SmartRDI settling time is shorter than the hardware requirement.

## Wait times defined for DPS128 measurement ranging

 The following wait times are to be considered when changing the DPS128 measurement range:

- Range settling time: The required wait time to achieve the specified accuracy of the target range.
- Auto-range execution time: The required wait time to allow the auto-range algorithm to finish.

## Non-measurement events (data transfer time)

All non-measurement events should be followed by 8 user vectors to ensure the event is properly transferred and executed, for all DPS products. This is automatically taken care of by the SmartRDI. These additional vectors are needed when the subsequent vectors are break vectors or when the event is placed at the end of a pattern. Break vectors are generated for example by [CTIM](<../02.06_Command_Reference/02.06.07.01.08.03.01_Changing_the_timing_set__CTIM.md>), [CLEV](<../02.06_Command_Reference/02.06.07.01.08.03.02_Changing_the_level_set__CLEV.md>), XACT/ MEAS.
