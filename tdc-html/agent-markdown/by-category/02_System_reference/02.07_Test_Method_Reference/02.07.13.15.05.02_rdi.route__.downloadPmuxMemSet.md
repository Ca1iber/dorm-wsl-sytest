# rdi.route().downloadPmuxMemSet()

Loads the setup file and downloads the PMUX switch states to the PMUX memory.

The download switch states must already be defined by the [State Setup editor](<02.07.13.15.01.04_Routing_Tools_-_State_Setup_editor.md>) of the [Routing Tools editors](<02.07.13.15.01_Routing_Tools_editors.md>).

 Usage of the function:

- The function is to be called in the code‑based mode. For more information, refer to [Execution mode](<02.07.13_SmartRDI.md#_142069__s_Execution_mode>) in topic [SmartRDI](<02.07.13_SmartRDI.md>).
- The function must be called at least once in the test program flow.
- The first run can take several milliseconds due to time required for download.
To optimize the execution time, subsequent runs only check for changes. No new download is performed if no changes are detected. Important recommendations for optimizing the memory consumption:

- The function should be called in a test suite with a tester frequency 2x the desired PMUX speed (if PMUX is set to 1 MHz, the tester frequency needs to be 2 MHz). The idea is to avoid having any type of padding or RPTV vectors either of which can lead to excessive memory usage.
- The function should be called in a separate port. Memory consumption is high if the default port (@) is used as memory of non-PMUX control pins is also reserved.

Best practice: Create a port exclusively for PMUX (and utility line) control pins. This recommendation applies only to this function. Ordinary [rdi.route()](<02.07.13.15.05_rdi.route.md>) class calls within the program can but Do not necessarily have to use a separate port.

 Note The function does not only download the PMUX switch states but also reads the setup file that has been defined in the [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>) using keyword [ROUTING_SETUP_FILE](<02.07.13.04_RDI_Configure_file.md#_146692__row_ROUTING_SETUP_FILE>). The function must therefore be called at least once in the test program flow even if only utility lines are controlled by the Routing Tools.The function re-reads the setup file only if the time-stamp has changed.  Note The function can work with port() and the generated burst pattern is based on the specified port. See Example 2.

## Usage of downloadPmuxMemSet().xMode()

 This downloadPmuxMemSet() can work together with [xMode()](<02.07.13.24.42_xMode.md>) to reduce vector memory consumption.

```
rdi.route().downloadPmuxMemSet().xMode().execute();
```

Here, the xMode() function can be set to xMode(2) or xMode(4) only. Approximately, xMode(2) would save half (½) the vector memory consumption; xMode(4) would save three fourths (¾) of the vector memory consumption.

For SCL and SDA pins, downloadPmuxMemSet().xMode() requires more complex wavetable definitions as shown in the following examples:

xMode(2) wavetables DVC for SCL pins:

```
PINS SCL
0    "d1:0 d2:0"    00
1    "d1:0 d2:1"    01
2    "d1:1 d2:0"    10
3    "d1:1 d2:1"    11
f    ""             ..
brk  "d1:Z"
```

xMode(2) wavetables DVC for SDA pins:

```
PINS SDA
0    "d1:0"         0
1    "d1:1"         1
2    "d1:Z r1:L"    L
3    "d1:Z r1:H"    H
f    ""             .
brk  "d1:Z"
```

xMode(4) wavetable DVC for SCL pin:

```
PINS SCL
0    "d1:0 d2:1 d3:0 d4:1"    0101
1    "d1:1 d2:1 d3:1 d4:1"    1111
2    "d1:0 d2:1 d3:1 d4:1"    0111
3    "d1:1 d2:1 d3:0 d4:0"    1100
f    ""                       ....
brk  "d1:Z"
```

xMode(4) wavetable DVC for SDA pin:

```
PINS SDA
0    "d1:0 d2:0"         00
1    "d1:0 d2:1"         01
2    "d1:1 d2:0"         10
3    "d1:1 d2:1"         11
4    "d1:Z r1:L d2:0"    L0
5    "d1:Z r1:L d2:1"    L1
6    "d1:1 r1:X r2:L"    1L
7    "d1:0 r1:X r2:L"    0L
8    "d1:Z r1:L r2:L"    LL
9    "d1:1 r1:X r2:H"    1H
f    ""                  ..
brk  "d1:Z"
```

When you use xMode() with downloadPmuxMemSet() together to reduce the vector memory consumption, you must set a timing period slower than when xMode() is not used.

- For xMode(2), the test period (time) must be two times longer.
- For xMode(4), the test period (time) must be four times longer.

## Syntax

```
routeGroup& downloadPmuxMemSet(bool forceDownload = false);
```

  List of parameters

 | Parameter  | Description |
 | forceDownload  | The optional bool parameter enables you enforcing the download:

- true: The switch states are downloaded even if no changes are detected.
- false: The switch states are downloaded only of changes are detected.
Default value: false  |  Return value A reference to the [routeGroup](<02.07.13.15.05_rdi.route.md>) object.

## Examples

### Example 1

```
RDI_INIT();
...
...
ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...
    rdi.route().downloadPmuxMemSet().execute();
    ...
    ...
    RDI_BEGIN();
    {
        ...
        ...
    }
    RDI_END();
    ...
    ...
}
ON_FIRST_INVOCATION_END();
...
...
```

### Example 2

```
rdi.port("pmuxCtrlPort").route().downloadPmuxMemSet().execute();  // The port "pmuxCtrlPort" includes pmux digital control SDA and SCL pins.
```
