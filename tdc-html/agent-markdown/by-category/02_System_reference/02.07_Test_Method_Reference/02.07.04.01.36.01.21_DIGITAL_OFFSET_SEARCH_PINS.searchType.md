# DIGITAL_OFFSET_SEARCH_PINS.searchType()

Sets the search type for timing/level offset searches.

The search type determines whether the offset for the left or right boundary, or the middle of the pass area will be stored as the offset value. To use these stored values as offsets, [disable the restore flag](<02.07.04.01.36.01.19_DIGITAL_OFFSET_SEARCH_PINS.restoreFlag.md>).

Note that the left and right boundaries of the pass area are the first and last passing values of the pass area, representing the fail-to-pass and pass-to-fail transitions.

Note A boundary is the transition from fail to pass or from pass to fail. The algorithm of the search function works strictly from the left to the right to find the selected boundary of the passing area. So the left boundary is a transition from fail to pass and the right boundary is the transition from pass to fail.

1: Level resources: LB means the lower boundary (the fail to pass transition) of the pass area. RB means the upper boundary (the pass to fail transition) of the pass area.

To learn these search resources, see [DIGITAL_OFFSET_SEARCH_PINS.resourceType()](<02.07.04.01.36.01.18_DIGITAL_OFFSET_SEARCH_PINS.resourceType.md>).

For level resources, most of them can only search for one transition, either LB or RB. The EYE search only applies for moving two level resources to the same direction, such as VTH, VIOFFSET, and VOOFFSET.
