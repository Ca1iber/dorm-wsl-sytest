This class defines the functions used to access the TMU result cache on the system controller workstation. Thus the TMU_RESULTS members are only usable after upload of the TMU results. They all relate to the uploaded result.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TMUResultCache.h.

## Syntax

```
TMU_RESULTS();
```

This creates an object of TMU_RESULTS with the default factory key "<testsuite_name>". You can access the data in the result cache with the defined member functions.

```
TMU_RESULTS(const STRING& keyname);
TMU_RESULTS(const char* keyname);
```

This creates an object of TMU_RESULTS with the factory key "<testsuite_name>_<keyname>". You can access the data in the result cache with the defined member functions. When defining more than one TMU_RESULTS objects in a test suite, you must specify a value for the parameter.

Note The created TMU_RESULTS objects are persistent until the next testflow run. One object cannot be assigned to other objects. But one object can reference other objects.

Parameter
 |

I

 |

keyName

 |

The string to be appended to the default factory key. It is needed when more than one TMU_RESULTS object is defined in a test suite.

 |

## Example

The following example shows how to get and print out the pins that have not finished.

```
TMU_RESULTS siteResults;
STRING_VECTOR errpinvec;
STRING errstr;
UINT32 numpins = siteResults.getPinsNotFinished(errpinvec,errstr);
cout << "these pins have not finished: " <<  errstr << endl;
for ( UINT32 i = 0; i < numpins;i++)
{
     cout << "the pin  "  << errpinvec[i]  << " has not finished"   < endl;
}
```

Refer to [TMU_TASK](<02.07.04.01.252_TMU_TASK.md>) for more examples.
