# Parameter reconstruction

At this stage the decoded fields are still represented as state character sequences. They must be mapped back to transaction parameters which can be read from the test method. This is called parameter reconstruction.

Additional allowed parameters are:

- The state character sequence reconstructed for a specific field of a pin role (@<pin_role>.<field>)
- Protocol Constants (<constant>)

The following errors may occur:

- Specified pin role is not defined
- Specified field is not defined for the pin role given

## Specifics of IN parameters

For parameter reconstruction one has to distinguish between pattern generated by protocol test APIs and vector streams from simulation.

Pattern generated with protocol test specific API:

- If no decode function is given, the IN parameter value itself will be used for decoding.
- If a decode function is available, it has to be used.
- Inconsistency can occur if the decode function is not specified exactly inverse to the encode function.

This means, that the provided IN parameter value and the value determined after encoding it to a field and decoding it back to a parameter value does not match.

By applying the decode function the user gets an indication for the mismatch in the Pattern Debug Tool display.

Pattern from simulation:

- If a stream of vectors from simulation should be interpreted as protocol transactions, the decode function must be used.
- If no decode function is provided, the Pattern Debug Tool display will show ‘' for the parameters that cannot be decoded.
