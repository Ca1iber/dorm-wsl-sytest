# PPMU_PIN_RELAY

The PPMU_PIN_RELAY class is a data container holding the object reflecting the pin PMU's relay setup data. The target pin PMU can be specified via the [PPMU_RELAY](<02.07.04.01.158_PPMU_RELAY.md>) class because the PPMU_PIN_RELAY class can be called as a subsidiary data container of the [PPMU_RELAY](<02.07.04.01.158_PPMU_RELAY.md>) class.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PpmuPinRelay.h.

## Class definition

Member Functions:

```
PPMU_PIN_RELAY & status(const STRING& relay_stat);
status(const STRING& rlynames, TM::RELAY_STATE onoff);
```

## Member functions

### PPMU_PIN_RELAY & status()

```
PPMU_PIN_RELAY & status(const STRING& relay_stat);
```

This function sets the specified relay to be opened or closed when the task is executed.

- To program a typical DC test, close only the PPMU relays with the status option "PPMU_ON".
- To use the board ADC to measure voltage or current on pins during a pattern running (dynamic DC tests) in a functional test, employ the "MUX_PPMU_BADC_ON" and "MUX_VM_HIZ_ON" options. (Available on PS1600.)

"MUX_PPMU_BADC_ON"

(Available only on PS1600)

 |

Supports using board ADC to measure voltage/current on pins during a pattern running in a functional test.

This option controls the multiplexer before a board ADC to select the signal coming from the measured pin and inputs this signal to the board ADC for value measurement.

As the signal reaches the multiplexer by its pin PPMU, you need to connect the pin to its PPMU with the "PPMU_ON" option. The other setups for this measurement are configuring the PPMU, board ADC, and setting up measurement points in the pattern. See the example 3.

When measuring multiple pins,

- If the pins are on the same logical board, create different `PPMU_RELAY.pin().status("MUX_PPMU_BADC_ON")` objects for different pins, for they share the board ADC through the multiplexer (one logical board has 16 pins and one board ADC) and the ADC measures them sequentially.
- If the pins are on different logical boards, these pins can reside in the same `PPMU_RELAY.pin().status("MUX_PPMU_BADC_ON")` function, for they are using different board ADCs.
 |
 |

"MUX_VM_HIZ_ON"

(Available only on PS1600)

 |

Supports using board ADC to measure high impedance or high voltage on pins during a pattern running in a functional test.

This option controls the multiplexer before a board ADC to select the voltage signal coming from the measured pin that has been connected to a DC Line and inputs it to the board ADC for value measurement.

To connect the pin to the DC Line, use the "DC_ON" option. The other setups for this measurement are configuring the board ADC and setting up measurement points in the pattern. See the example 4.

When measuring multiple pins,

- If the pins are on the same logical board, create different `PPMU_RELAY.pin().status("MUX_VM_HIZ_ON")` objects for different pins, for they share the board ADC through the multiplexer (One logical board has are16 pins and one board ADC) and the measurements must be serialized with multiple [BADC_MEASURE](<02.07.04.01.08_BADC_MEASURE.md>) objects.
- If the pins are on different logical boards, these pins can reside in the same `PPMU_RELAY.pin().status("MUX_VM_HIZ_ON")` function, for they are using different board ADCs.
 |

### status()

```
PPMU_PIN_RELAY & status(const STRING& rlynames, TM::RELAY_STATE onoff);
```

This function opens or closes single relays when the task is executed.

Parameters
 |

rlynames

 |

Comma separated list of relays to be switched. ( AC, PPMU, or DC).

 |
 |

onoff

 |

State to be switched to ( TM::RELAY_ON or

TM::RELAY_OFF)

## Examples

### Example 1

```
    :
PPMU_RELAY relay1;
relay1.pin("p1, p2").status("PPMU_ON");
    :
```

This example defines a task to close the PMU relay of "p1" and "p2".

### Example 2

```
PPMU_RELAY relay1;
relay1.pin("p1").status("DC",TM::RELAY_ON);
```

The DC relay of pin "p1" is switched on at task execute.

```
relay1.pin("p1").status("AC,DC",TM::RELAY_ON);
```

The AC and DC relays of pin "p1" are switched on at task execute.

```
relay1.pin("p1,p2").status("PPMU,DC",TM::RELAY_OFF);
```

The PPMU and DC relays of pins "p1" and "p2" are switched off at task execute.

Please note the difference to the above status function:

```
relay1.pin("p1").status("AC_ON")
```

switches the AC relay ON and the DC and PPMU relay OFF, while

```
relay1.pin("p1").status("AC",TM::RELAY_ON);
```

switches only the AC relay to ON. The other relays remain unchanged.

### Example 3

Use the board ADC to measure the current of the "PinMeasure1" pin when a pattern is running.

```
void measureCurrent()
  {
    string meaPin1 = "pinMeasure1";
    string allMeaPins = "pinMeasure1";

    PPMU_RELAY   measRelay;
    PPMU_RELAY   adcConnectPmu1;
    PATTERN_CONTROLLER pattern1;

    // use PPMU_SETTING to configure measurement thresholds etc.
    // measure through DUT - PPMU - MUX - BADC Path
    // when MUX is set to connect BADC with PPMU, the thresholds of PPMU_SETTING are relevant for P/F result.

    PPMU_SETTING measPmuSet;
    BADC_MEASURE badcMeasPin1;

    ON_FIRST_INVOCATION_BEGIN();
    measPmuSet.pin(allMeaPins).vForce(100 mV).iRange(100 uA).min(0 uA).max(100 uA);
    measPmuSet.wait(1 ms);

    // forcePin and measPin1 are cross Connected
    measRelay.pin(meaPin1).status("PPMU_ON");
    measRelay.wait(1.3 ms);

    // MUX_PPMU_BADC_ON one object per pin of the board
    adcConnectPmu1.pin(meaPin1).status("MUX_PPMU_BADC_ON");
    adcConnectPmu1.wait(1.3 ms);

    //meas current
    badcMeasPin1.pin(meaPin1).numberOfSamples(16);
    badcMeasPin1.wait(1 ms);
    pattern1.label("badcMeasSub","meaPort").add(measPmuSet).add(measRelay).add(adcConnectPmu1)
                                           .add(badcMeasPin1);

    pattern1.setup();

    ON_FIRST_INVOCATION_END();

  }
```

### Example 4

Use the board ADC to measure HIZ on the pin "PinMeasure1" when a pattern is running.

```
void measure()
  {
    string meaPin1 = "pinMeasure1";

    PPMU_RELAY   measRelay,adcConnectHIZ;
    PATTERN_CONTROLLER pattern1;

    // use BADC_SETTING to configure measurement thresholds etc.
    // measure with BADC - DC Line Path, for HIZ Measurement no PPMU_XXX objects are required, only BADC is used
    // for HIZ measurement (DUT -- DC-Line -- MUX -- BADC)

    BADC_SETTING badcSet1V;
    BADC_MEASURE badcMeasPin1;

    ON_FIRST_INVOCATION_BEGIN();

    // forcePin and measPin1 are cross Connected
    measRelay.pin(meaPin1).status("DC_ON");
    measRelay.wait(1.3 ms);

    adcConnectHIZ.pin(meaPin1).status("MUX_VM_HIZ_ON");
    adcConnectHIZ.wait(1.3 ms);

    //meas voltage
    badcSet1V.pin(meaPin1).min(0.4 V).max(0.6 V);
    badcMeasPin1.pin(meaPin1).numberOfSamples(16);
    badcMeasPin1.wait(1 ms);

    pattern1.label("badcMeasSub","meaPort").add(badcSet1V).add(measRelay).add(adcConnectHIZ)
                                           .add(badcMeasPin1);
    pattern1.setup();

    ON_FIRST_INVOCATION_END();
  }
```
