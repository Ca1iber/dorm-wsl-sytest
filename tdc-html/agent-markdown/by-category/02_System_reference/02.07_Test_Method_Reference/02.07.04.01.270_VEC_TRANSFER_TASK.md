# VEC_TRANSFER_TASK

#### Subtopics

- [VEC_TRANSFER_PIN_TASK](<02.07.04.01.270.01_VEC_TRANSFER_PIN_TASK.md>)

The VECTOR_TRANSFER_TASK class is a data container that holds the contents of the task for setting up vector data modification of a label.

This class is used to call the VEC_TRANSFER_PIN_TASK class, which is a subsidiary data container, to update vectors per site very efficiently by using the [Fast Transfer Buffer](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_fast_transfer_buffer_size>). Objects of the class VEC_TRANSFER_TASK can be added to a [TASK_LIST](<02.07.04.01.240_TASK_LIST.md>) container.

Note Modifying vector data by the VECTOR_TRANSFER_TASK class requires that memory type SM has been selected for the pattern. For more information refer to [Selecting the memory type](<../02.06_Command_Reference/02.06.07.01.04.01_Selecting_the_memory_type.md>).Note This API can only be used with SmartScale test head cards.

## Constructor

```
VEC_TRANSFER_TASK();
```

This constructor creates an object of the VECTOR_TRANSFER_TASK class, which allows the user to modify pattern for different pins or different sites in parallel. The VECTOR_TRANSFER_TASK API can be used in protected mode to encrypt test program.

  blockSize(...)

```
VEC_TRANSFER_TASK & blockSize(INT blockSize);
```

Specifies the size of the vector block whose data will be modified. The maximum size of the block is restricted by parameter [fast_transfer_buffer_size](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_fast_transfer_buffer_size>) of the [.technology file](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>).

 Note

-

For SmarTest ≥7.4.3.0:

fast_transfer_buffer_size ≤ blockSize * (number of digital pins specified in VEC_TRANSFER_TASK() * number of configured sites)

The value of the fast_transfer_buffer_size must greater than the largest used VTT (transfer) size multiplied by the number of configured (DPS and digital) channels.

For example, if the largest vector update operation is 128 bytes, and a device is configured with 100 digital and DPS channels for each of 16 sites (a total of 1600 channels), the fast_transfer_buffer_size must be at least 128 x 1600 = 204800 bytes.

To avoid problems when increasing the site count (for example, going from single or dual site to octal or higher production testing), it is recommended to calculate the buffer size assuming a minimum of 2000 channels (If the actual channel count is higher, the actual higher count should be used as a minimum).

-

For SmarTest < 7.4.3.0:

fast_transfer_buffer_size 鈮? blockSize * (number of configured digital and DPS/DC channels across all sites)

-

For SmarTest 鈮?7.4.1.0:

The specified fast_transfer_buffer_size must be a multiple of 8192 bytes for SmarTest 7.4.1.0 and older versions.

An error message will be issued if the rule that is defined above is violated. You can then either increase the block size or split the vector data transfer into smaller blocks.

## Example

The following example shows how to modify the vector label patVecTransfer using the VEC_TRANSFER_TASK class.

```
virtual void run()
{
    static INT MAX_TRANSFER_BITS    = 8;
    static INT MAX_SITES            = 128;

    VEC_TRANSFER_TASK   vTask;
    ARRAY_I             waveIdxData[MAX_SITES];

    ON_FIRST_INVOCATION_BEGIN();
    {
        for ( int i = 0; i < MAX_SITES; i++)
        {
            //
            // For each of 128 sites create the new data for each of 8 vectors
            //
            waveIdxData[i].resize(MAX_TRANSFER_BITS);
            waveIdxData[i].init(0);

            if ( i == 0 )
            {
                waveIdxData[i][0] = 1; // Site 1: 10000000
            }
            else
            {
                waveIdxData[i][1] = 1;
                waveIdxData[i][2] = 1; // Site 2: 01100000
            }
        }

        vTask.label("patVecTransfer").vecNumber(0).blockSize(MAX_TRANSFER_BITS);

        FOR_EACH_SITE_BEGIN();
        {
            vTask.pin(mPinlist).data(waveIdxData[CURRENT_SITE_NUMBER()-1]);
        }
        FOR_EACH_SITE_END();

        vTask.execute();
    }
    ON_FIRST_INVOCATION_END();

    return;
}
```
