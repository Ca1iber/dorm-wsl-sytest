# How to handle ARRAY_x data type

The ARRAY_x data type includes:

ARRAY_BOOL: array of BOOL type of data

ARRAY_CHAR: array of CHAR type of data

ARRAY_COMPLEX: array of COMPLEX type of data

ARRAY_D: array of DOUBLE type of data

ARRAY_I: array of INT type of data

ARRAY_LL: array of LONG_LONG type of data

 Note The "x" is a placeholder only for this documentation and is to be replaced by valid types as shown above.

## Defining an array

To define an array, do as follows:

```
ARRAY_x array(size);
```

or

```
ARRAY_x array;
```

where

 |

 |

x

 |

BOOL, CHAR, COMPLEX, D, I, or LL

 |
 |

 |

array

 |

Array name

 |
 |

 |

size

 |

Array size

 |

If you omit "(size)", the system does not allocate memory area to the buffer initially. If you specify "(size)" with parameter size set to a value larger than zero, the size of the array is fixed and you cannot change the size later.

Some examples:

```
//
// Define an array with the initial size of zero.
// The array can be resized afterwards
//
ARRAY_I a_i1;

//
// Define an array with the initial size of 1024.
// The size of the array is fixed and cannot be changed.
//
ARRAY_I a_i2(1024);
```

## Defining an array by copying another array

To define an array by copying another array, do as follows.

For defining an array with fixed size:

```
ARRAY_x array2(array1);
```

or

```
ARRAY_x array2=array1;
```

For defining a resizable array (execute two statements):

```
//
// 1: Define a resizable array.
//
ARRAY_x array2();

//
// Copy the first resizable array to the 2nd resizable array
//
array2=array1;
```

where

 |

 |

`x`

 |

BOOL, CHAR, COMPLEX, D, I, or LL

 |
 |

 |

`array1`

 |

Original array

 |
 |

 |

`array2`

 |

New array defined by copying array

 |

## Defining an array by sharing / copying a part of on an existing array

You can define an array by sharing / copying part of another array. The array defined in this way is not resizable. To define the array in this method, do as follows:

For sharing:

```
ARRAY_x array2(array1, size, offset);
```

or

```
ARRAY_x array2 =ARRAY_x(array1, size, offset);
```

If you omit size and offset, array2 is created by copying the complete array1.

For copying:

```
ARRAY_x array3;
array3 = ARRAY_x(array1, size, offset);
```

where

 |

 |

`x`

 |

BOOL, CHAR, COMPLEX, D, I, or LL

 |
 |

 |

`array1`

 |

Original array

 |
 |

 |

`array2`

 |

Array newly created by sharing part of array1. array2 uses the same data as array1. However, if you omit size and offset, array2 is created by copying.

 |
 |

 |

`array3`

 |

Array newly created by copying part of array1. array3 uses a different buffer from array1.

 |
 |

 |

`size`

 |

Size of new array.

 |
 |

 |

`offset`

 |

Starting point in original array buffer where sharing begins with new array. This parameter can be omitted.

 |

The following are examples for creating an array by sharing a part of another array buffer.

```
ARRAY_I a_i1;
ARRAY_I a_i2 (a_i1, 200, 30);
```

a_i2 is created by sharing a_i1[30] to a_i1[229]. a_i2 uses the same buffer as a_i1.

You can use the same syntax for extracting part of an array, for example, for calculating FFT as follows.

```
ARRAY_COMPLEX rslt_ary;
DSP_FFT(ARRAY_I(a_i1,256,30), rslt_ary, RECT);
```

For calculating FFT, a_i1[30] to a_i1[285] is extracted and used as the source array.

## Initializing an array

You can fill the array elements with the specified value by doing as follows:

```
array.init(value);
```

where

 |

 |

`array`

 |

Array name

 |
 |

 |

`value`

 |

Value which fills the array elements

 |

The following is an example.

```
a_i1.init(10);
```

All the array elements are set to 10.

## Reading the size of an array

You can read the array size by the following:

```
array.size();
```

where

 |

 |

`array`

 |

Array name

 |

The following is an example.

```
current_size = a_i.size();
```

`a_i.size()` returns the size of array `a_i` to the variable `current_size`.

## Changing the size of an array

You can change the size of an array if the array is resizable, by using the following:

```
array.resize(size);
```

where

 |

 |

array

 |

Array name

 |
 |

 |

size

 |

New buffer size

 |

The following is an example.

```
ARRAY_I a_i;
if(a_i.resize(2048)==2048)
cout << "Can expand array a_i to 2048." << endl;
```

If the size of array a_i can be expanded to 2048 elements, the program displays

```
Can expand array a_i to 2048.
```

## Array size when using assignment operators

If the array on the left of the assignment operator (=) is resizable, the array size is reduced or enlarged to be the same size as the array on the right of the assignment operator. Then, all the elements are copied. If the array on the left is not resizable, as many elements of the array as possible on the right are copied to the array on the left.

## Accessing array elements

An array element is accessed by indexing the array using the number of the element. In C++, all arrays begin at "0". This means that if you want to access the first element in an array, use 0 for the index. To index an array, specify the index of the desired element inside square brackets.

If an array name is "source", for instance, the (i+1)-th element of the "source" array is "source[i]" in C++ notation, where "i" begins at "0".

For accessing the real and imaginary part of ARRAY_COMPLEX type data, use real() and imag(), the same as for COMPLEX. The following are examples.

```
ARRAY_COMPLEX a_d;
...
...
//
// Read real part of 100-th element
//
real_val = a_d[99].real();

//
//Read imag part of 100-th element
//
imag_val = a_d[99].imag();
```

## Using the array name as pointer

If you specify only an array name (without index), which is defined by an ARRAY_x data type, you can use it as a pointer in the same manner as the C++ standard array.

The following is an example.

```
const INT* p;
ARRAY_I a_i(100);
...
...
//
//Pointer p specifies array a_i
//
p = a_i;

//
// The 20th element is accessed by p as array
//
int val_20th = p[19];

//
// The 50th element is accessed by a_i as pointer.
//
int val_50th = *(a_i +49);
```

## Printing an array

To print an ARRAY_x data type, use the `<<` operator. The data is printed in the following form:

```
{1st_elem, 2nd_elem, ..., last_elem}
```

where

 |

 |

`1st_elem`

 |

1st element

 |
 |

 |

`2nd_elem`

 |

2nd element

 |
 |

 |

`last_elem`

 |

last element

 |

The following is an example.

```
ARRAY_I a_i(5);

for (INT j=0; j < 5; j++)
{
    a_i[j]=j;
}

cout << a_i; // Output is {0,1,2,3,4}
```

## Retrieving real / imaginary arrays from a complex array

You can retrieve arrays of the real and imaginary parts from a complex array by the following:

```
ARRAY_D real_array= complex_array.getReal();
ARRAY_D imag_array = complex_array.getImag();
```

where

 |

 |

`complex_array`

 |

Complex array name

 |

The following is an example.

```
ARRAY_COMPLEX CmpWave;
...
...
ARRAY_D real_array = CmpWave.getReal();
ARRAY_D imag_array = CmpWave.getImag();
```

CmpWave.getReal() returns the real part of the cmpWave array to an array real_array. CmpWave.getImag() returns the imaginary part of the cmpWave array to an array imag_array.

## Using ARRAY_x (x = I, D, or COMPLEX) data type in DSP programming

ARRAY_x data types are flexible-size arrays. Hence, you can declare ARRAY_x variables with or without size-specification. If you declare a specified-size array, it is not resizable and the size must be constant. If you declare an unspecified-size array, the size of the array will be determined by assignment statement, `[Analog.]DGT().getWaveform()`, `[Analog.]DGT().getComplexWaveform()`, or the computation API.

```
ARRAY_D wfm, spec;

wfm = DGT("Aout").getWaveform(1); // The size of "wfm" is determined at run-time

DSP_SPECTRUM (wfm, spec, VOLT, 1, HANNING, 0);
```

In the above example, the size of the wfm array is determined when DGT().getWaveform() is executed. Since the size of the output array in the DSP_SPECTRUM API is always half the size of the input array, it is not necessary to declare the output array with the size.

To define the data size for ARRAY_x data types, use ( ) (round brackets) as follows:

```
INT idx;
ARRAY_D wfm, spec, filter(256);

wfm = DGT("Aout").getWaveform(1);

for(idx = 0; idx < 128; idx++)
{
    filter[idx] = 1.0; // pass band
}

for(idx = 128; idx < 256; idx++)
{
    filter[idx] = 0.0; // stop band
}

DSP_SPECTRUM(wfm, spec, VOLT, 1, HANNING, filter);
```

Note The array boundary is checked when the DSP routines run on the system controller. Hence, run your DSP routines on the system controller at least once for checking this in the debugging stage.

The following operations for the ARRAY_x data type are supported in the DSP routines of the post-process function.

- Defining array

```
ARRAY_I a_i1;
ARRAY_I a_i2(1024);
```

- Reading array size

```
current_size = a_i.size();
```

- Accessing array element

```
ARRAY_COMPLEX a_d;
...
...
real_val = a_d[99].real();
imag_val = a_d[99].imag();
```

Limitations: The following operations are prohibited in the DSP routines of the post-process function.

- Initializing array

```
a_i1.init(10); //Error!
```

- Defining array by copying another array

```
ARRAY_D a;
a = DGT("Aout").getWaveform(1);
ARRAY_D c(a);  // Error!
```

- Copying array

```
ARRAY_D a,b;
a = DGT("Aout").getWaveform(1);
b = a; // Error!
```

- Sharing or copying part of buffer of another array

```
ARRAY_I a_i1(512);
...
...
ARRAY_I a_i4();
a_i4 = = ARRAY_I (a_i1, 200, 30); //Error!
```

- Defining array by sharing or copying part of buffer of another array

```
ARRAY_I a_i1(512);
...
...
ARRAY_I a_i2 (a_i1, 200, 30); //Error!
ARRAY_I a_i3 = ARRAY_I (a_i1, 200, 30); //Error!
```

- Changing array size

```
ARRAY_I a_i1(1024);
if(a_i.resize(2048)==2048) { ... } //Error!
```

- Auto-fitting array size when using assignment operators

```
ARRAY_D a_d1(), a_d2(1024);
...
...
a_d1 = a_d2; //Error!
```

- Using array name as pointer

```
const INT* p;
ARRAY_I a_i(100);
...
...
p = a_i; //Error!
```

- Printing array data

```
ARRAY_I a_i(5);

for (INT j=0; j < 5, j++)
{
    a_i[i]=j;
}

cout << a_i; //Error!
```

- Retrieving real/imaginary arrays from complex array

```
ARRAY_COMPLEX CmpWave;
...
...
ARRAY_D real_array = CmpWave.getReal(); //Error!
ARRAY_D imag_array = CmpWave.getImag(); //Error!
```

- Reusing an array that stored a waveform once

```
ARRAY_D wfm;
wfm = DGT(pin).getWaveform(1);
...
...
wfm = DGT(pin).getWaveform(2); // Error!
```

## Using the variables of ARRAY_x type as function parameters

The variables should be handled as a reference or pointer from the function such as below. This is because if you do not handle the variables as a reference or pointer, the variable data will be copied to the parameter of the function. Most such data is very large size. Therefore, copying bulky data slows down the test throughput.

```
DOUBLE  dSamplePeriod;
STRING  DGT_PinName;
ARRAY_D DGT_Data;

void dist_calc(ARRAY_D& signal, DOUBLE SamplePeriod, STRING& pinName)
{
    ...
    ...
    //
    // Code for distortion calculation
    //
    ...
    ...
}
...
...
virtual void run()
{
    ...
    ...
    DGT_Data = Analog.DGT(DiGiTizer).getWaveform();
    dSamplePeriod = Analog.DGT(DiGiTizer).getConvClock();
    dist_calc(DGT_Data, dSamplePeriod, DGT_PinName);
    ...
    ...
}
```
