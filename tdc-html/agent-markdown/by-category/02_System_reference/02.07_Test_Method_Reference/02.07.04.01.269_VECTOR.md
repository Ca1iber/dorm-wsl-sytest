# VECTOR

The VECTOR API accesses a data container holding the settings of a vector variable. The class functions are used to either get, or set, vector variable data which will indirectly retrieve or change vector memory.

One typical use is copying digital capture data into an array for later test method processing. Another use is to define the source data to download to a vector variable; in this case the VECTOR API takes the multi-site setup focus into account.

You can create a class object of this API explicitly using the constructor function.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Vector.h.

```
VECTOR(const STRING& name);
```

The constructor function creates a class object of this API. Specifying the following parameter explicitly creates the particular object.

## Member functions

  format()

```
VECTOR& format(const STRING& f);
```

This member function sets the format of the DUT output or input codes. Code formats specified by member functions format() and inputMode() modify how [getVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_getVectors>) and [setVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_setVectors>) manipulate vector data when converting from vector data to integer data, and from integer data to vector data.

Parameter
 | f |

The basic format of DUT output code. The possible formats are:

- BIN: Binary
- COMP1: One's complement
- COMP2: Two's complement
- MOD_COMP1: Modified ones complement
- SYMM: Symmetry
- MOD_SYMM: Modified symmetry
- GRAY: Gray code
- BCD: BCD
- ALAW: A-law code
- MOD_ALAW: Modified A-law code
- MSB: Reversed bit order

The default is BIN.

For details, see [Code Format Tables](<02.07.04.04_Code_Format_Tables.md>).

   |  inputMode()

```
VECTOR& inputMode(INPUT_MODE imode);
```

This member function sets the input mode of the DUT output or input codes. Code formats specified by member functions format() and inputMode() modify how [getVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_getVectors>) and [setVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_setVectors>) manipulate vector data when converting from vector data to integer data, and from integer data to vector data.

Parameter
 | imode |

The possible modes are:

- NORM (normal) and
- COMP (complementary).

The default is NORM.

For details, see [Code Format Tables](<02.07.04.04_Code_Format_Tables.md>).

   |  byteOrder()

```
VECTOR& byteOrder(SOC_VECTOR_BYTE_ORDER order);
```

This member function sets the order of the bytes of the code to be retrieved for the member function [getVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_getVectors>).

The parameters to this member function are ignored by the member function [setVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_setVectors>).

Parameter
 | order |

The order of the bytes. The possible options are

- SOC_VECTOR_BIG_ENDIAN (high-order byte most significant) and
- SOC_VECTOR_LITTLE_ENDIAN (low-order byte most significant).

The default is SOC_VECTOR_BIG_ENDIAN.

   |  bits()

```
VECTOR& bits(INT b);
```

This member function sets the bit width of the code to be retrieved by the member function getVectors.

This member function sets the bit width of the code to be stored by the member function setVectors.

Parameter
 | b  | The bit width  |  offset()

```
VECTOR& offset(INT off);
```

This member function sets the start location offset for retrieving data through the [getVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_getVectors>) member function.

This member function should either not be called or only called with a zero value prior to calling the member function [setVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_setVectors>). This is because the download will always occur at the offset defined in the vector variable configuration.

Parameter
 | off  | The offset to the start location.  |  comment()

```
VECTOR& comment(const STRING& c);
```

This member function queues the comment for storage into the vector variable. The vector variable comment is not actually changed until setVectors() is called.

Parameter
 | c  | The comment for storage into the vector variable.  |  setVectors()

```
VECTOR& setVectors(const ARRAY_I& src);
```

This member function will download data to a vector label. All elements in array will be downloaded. Translations and conversions will be done during the download process as defined by the vector variable configuration and the download conditions specified by the following settings:

- [format()](<02.07.04.01.269_VECTOR.md#_29830__dle_format>)
- [inputMode()](<02.07.04.01.269_VECTOR.md#_29830__dle_inputMode>)
- [bits()](<02.07.04.01.269_VECTOR.md#_29830__dle_bits>)

Settings made to the member function[byteOrder()](<02.07.04.01.269_VECTOR.md#_29830__dle_byteOrder>) are ignored as the array source has a native byte order association. The vector variable configuration may be changed by the user to position bits within the vector frame, to align integer values to DUT code input vector data values.

The member function [offset()](<02.07.04.01.269_VECTOR.md#_29830__dle_offset>) should either not be called or only called with a zero value. This is because the download will always occur at the offset as defined in the vector variable configuration.

Parameter
 | src |

An array containing integer data to be downloaded to the vector variable identified in the constructor. The array elements correspond to the instances of the vector variable in the frames.

 |

Error cases

The following cases could cause the software to display an error:

- The vector variable does not exist.
- There is not enough physical memory to download the data.
- There are inconsistencies between the MAPPING rules defined in the vector variable configuration and the timing waveform table.
- The vector variable does not have a valid waveform.
- The vector variable is not "DIGDATA" type as defined in the vector variable configuration.
- The number of elements in variable src is larger than the memory allocated for the label. This memory allocation is done when the vector variable is assigned a usage towards this label.

 getVectors()

```
const ARRAY_I& getVectors (INT size = 0);
```

This member function returns the captured data on the vector memory located by the vector variable to an array, or data previously stored in the vector memory by setVectors member function. At this time, this member function uses the conditions specified by the following member functions:

- [format()](<02.07.04.01.269_VECTOR.md#_29830__dle_format>)
- [inputMode()](<02.07.04.01.269_VECTOR.md#_29830__dle_inputMode>)
- [byteOrder()](<02.07.04.01.269_VECTOR.md#_29830__dle_byteOrder>)
- [bits()](<02.07.04.01.269_VECTOR.md#_29830__dle_bits>)
- [offset()](<02.07.04.01.269_VECTOR.md#_29830__dle_offset>)

```
const ARRAY_I & getVectors(const ARRAY_I& sites, const INT size = 0);
const ARRAY_I & getVectors(const STRING& sites, const INT size = 0);
```

These two functions update the internal cache for the specified sites with the captured data. Then you can use the member function `getVectors(INT size = 0)` in FOR_EACH_SITE() loop to retrieve the data for each site. (See the example "Read the data for all the active sites" below.) The usage can improve the performance of retrieving data.

Parameter
 | sites  | The data of which sites to be retrieved. |
 | size  | The number of data items to be retrieved.  |  getImmediateVectors()

```
ARRAY_I getImmediateVectors(const INT offset);
INT     getImmediateVectors(const INT offset, ARRAY_I &resultVectorData);
```

These two functions provide the functionality of immediately uploading already available data of a started and still running capture test. Data processing like incremental calculations or protocol deframing may be immediately applied to the already retrieved data. The member function minimizes therefore not only the test time required for the upload but also offers the possibility optimizing the time overhead for processing the captured data.

The "Immediate upload" is supported by [Pin Scale 1600 digital card](<../02.05_Test_Head_Cards/02.05.04.01_Pin_Scale_1600_digital_card__Smart_Scale.md>).

The results are read for the site in focus and are written into an existing [ARRAY_I](<02.07.04.02.01_ARRAY_I.md>).

The second syntax returns the size of the uploaded data as INT value.

Parameters
 | offset |

The offset that is be set separately for each site and for each new upload.

-

First syntax:

Parameter offset defines the start position of the data to be read. The array is filled from the begin.

-

Second syntax:

Parameter offset defines the start position of the data to be read and the start position in the given ARRAY_I.

 |
 | resultVectorData |

Existing array of the type ARRAY_I to be filled incrementally with the captured data. Data are written into the array starting at the array element defined by parameter offset.

An array of the type ARRAY_I with fixed size must be defined for this parameter. The size of the array must be minimum the expected size of the capture data.

 |

For an example see [Example 10: Capture test using the immediate upload of already captured data](<02.07.04.01.269_VECTOR.md#_29830__e_Capture_test_using_the_immediate_upload>) below.

## Examples

### Example 1: Set input mode

```
VECTOR("VarLbl_A").inputMode(VECTOR::COMP);
```

The [inputMode()](<02.07.04.01.269_VECTOR.md#_29830__dle_inputMode>) member function sets the input mode to COMP.

### Example 2: Retrieve the offset

```
INT offset_var;
...
offset_var = VECTOR("VarLbl_A").getOffset();
```

The [getOffset()](<02.07.04.01.269_VECTOR.md#_29830__dle_getOffset>) member function obtains the offset to the start location and stores it to the variable offset_var.

### Example 3: Change the input mode

```
VECTOR::INPUT_MODE mode;
...
mode = VECTOR("VarLbl_A").getInputMode();

if (mode == VECTOR::NORM)
{
    VECTOR("VarLbl_A").inputMode(VECTOR::COMP);
}
```

If the input mode is NORM, the [inputMode()](<02.07.04.01.269_VECTOR.md#_29830__dle_inputMode>) member function sets the input mode to COMP.

### Example 4: Read the digital captured data

```
ARRAY_I digital_cap;
...
digital_cap = VECTOR("VarLbl_A").getVectors(1024);
```

The [getVectors()](<02.07.04.01.269_VECTOR.md#_29830__dle_getVectors>) member function reads the digital captured data, then stores it to the array digital_cap.

```
Wave<INT> CaptWave;

VECTOR ("VVar_capt").getWaveform (CaptWave, 4096);
```

This example reads 4096 digital captured data and stores it in CaptWave.

### Example 5: Reading the data for all the active sites

  Note For efficient upload of small amounts of digital capture results for high multisite count testing, use the [upload()](<02.07.04.01.269_VECTOR.md#_29830__dle_upload>) function as described in [Example 6: Read the data efficiently for all the active sites using the upload() function](<02.07.04.01.269_VECTOR.md#_29830__e_Read_the_data_efficiently>) below.

This example updates the internal cache with the data of "vector_variable_64k" for the active sites. Then it retrieves the data for each active site from cache.

```
ON_FIRST_INVOCATION_BEGIN();
    ...
    ARRAY_I sites;

    GET_ACTIVE_SITES(sites);

    VECTOR v("vector_variable_64k");

    // Update cache for all active sites:
    v.getVectors(sites);

    FOR_EACH_SITE_BEGIN();

        // Load from cache for each site
        ARRAY_I i = VECTOR("vector_variable_64k").getVectors();

    FOR_EACH_SITE_END();

ON_FIRST_INVOCATION_END();
```

### Example 6: Read the data efficiently for all the active sites using the upload() function

The [upload()](<02.07.04.01.269_VECTOR.md#_29830__dle_upload>) function is optimized for efficient upload of small amounts of digital capture results for high multisite count. The data is stored in a caller provided MULTISITE_VECTORS container which allows for efficient post processing and retrieval of the digital capture results. The data for each site as an ARRAY_I can be retrieved from this container using the getVectorsForSite() member function of the MULTISITE_VECTORS container as in the following:

 Note This function should only be used for small vector variables. In particular, less than 1000 samples.

```
MULTISITE_VECTORS msVectors;
{
    ON_FIRST_INVOCATION_BEGIN();

        //PREPARATION: capture setup is part of the pattern

        //EXECUTION
        CONNECT();
        DIGITAL_CAPTURE_TEST();

        //UPLOAD in parallel for all sites
        VECTOR vector("captureVariable");
        vector.upload(msVectors); //MULTISITE_VECTORS msVectors;

    ON_FIRST_INVOCATION_END();

    // RESULT PROCESSING
    // Site INDIVIDUAL; read form cache for each site
    ARRAY_I capData = msVectors.getVectorsForSite(CURRENT_SITE_NUMBER());

    // Do processing
    // ...

    return;
}
```

### Example 7: Download a sine wave to a vector

```
const INT    nSamples = 1024;
ARRAY_I      sine(nSamples);
const INT    nBits = 10;
const DOUBLE maxAmplitude = (1 << (nBits-1)) - 1;

for (INT i=0; i<nSamples; i++)
{
   sine[i] = round(sin(i * 2 * M_PI / nSamples) * maxAmplitude);
}

VECTOR("Sine").bits(nBits)
              .format("COMP2")
              .comment("Generated sine wave")
              .setVectors(sine);
```

The above example creates a sine wave in variable sine of type ARRAY_I. The sine waveform consists of 1024 samples with a ten bit resolution. The waveform is downloaded to the vector variable called "Sine". The sample points are converted from a signed integer to a two's complement bit pattern during the download. The comment "Generated sine wave" is also stored.

### Example 8: Create a vector variable with firmware command

```
FW_TASK("DVVA \"VarLbl_A\",DIGCAPT,\"port_A\",SERI,,,,0,1024,16,0,1,0,(pin1)\n");

VECTOR digCap("VarLbl_A");

int codeWidth = digCap.getVectorNumberPerSample();
int transferMode = digCap.getVariableTransferType();
STRING_VECTOR pinList = digCap.getVariablePinList();
```

In the first line, FW command [DVVA, DVVA? - (Define Vector VAriable)](<../02.06_Command_Reference/02.06.02.02.94_DVVA__DVVA__-__Define_Vector_VAriable.md>) defines a vector variable VarLbl_A. The last three lines return the vector variable information and store them in the variables.

### Example 9: Filling the DSM

This example fills the digital source memory with VECTOR API.

```
ARRAY_I ramp;
int     n,m,k;

ramp.resize( 256);

//
// Make ramp data 8 samples same value
//
for (n=0, k=0; n < 256 ; n=n+8,k++ )
{
    for ( m=0 ; m< 8 ; m++ )
    {
        ramp[n+m]=k;
    }
}

VECTOR ( "vv_d0_d7" ).bits(8).format("BIN").comment("C1").setVectors( ramp );

cout << "DAC_DigitalSourceMem_Fill : data downloaded " << endl;

FW_TASK("UPTD VEC, 1\n");
```

### Example 10: Capture test using the immediate upload of already captured data

The following example shows how to upload the already captured data while the capture pattern is still running. The test requires a digital capture setup named "cap". For more information refer to [Setting up a Vector Variable](<../02.08_Setup_and_Result_Tools/02.08.01.02.07.02.05_Setting_up_a_Vector_Variable.md>).

```
INT         offlineMode;
STRING      testSuiteName;
ARRAY_I     sites;
INT         configuredSites;
ARRAY_I     uploadDataOffset;

//
// Get offline mode, the name of the test suite and the number of configured sites
//
GET_SYSTEM_FLAG     ("offline", &offlineMode);
GET_TESTSUITE_NAME  (testSuiteName);

configuredSites = GET_CONFIGURED_SITES(sites);

//
// Capture test for the first invocation
//
ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Connect and enable the run once mechanism
    //
    CONNECT();

    setStopSiteLoop(true);

    //
    // Configure a user defined result area
    //
    INT rawDataSize         = 5242882;
    INT expectedDataSize    = 4 * rawDataSize;

    RESULT_AREA_CONFIG_SET resultArea(testSuiteName);

    resultArea.pin("sd0").setErrorMapResultAreaSize(expectedDataSize);
    resultArea.setAsPrimary();

    //
    // Define a VECTOR object
    //
    VECTOR vector("cap");

    //
    // Define a non-blocking test which contains digital capturing
    //
    NB_DIGITAL_CAPTURE_START();
    {
        //
        // Initialize an array that holds the upload offset per site
        //
        uploadDataOffset.resize(configuredSites);

        uploadDataOffset.init();

        //
        // Initialize the ADC histogram data for each site
        //
        ...
        ...

        //
        // Upload and evaluate the data while the capture pattern is running
        //
        bool dataIsRemaining = true;

        while ( dataIsRemaining )
        {
            dataIsRemaining = false;

            FOR_EACH_SITE_BEGIN();
            {
                //
                // Upload and evaluate data for the current site
                //
                int siteIndex = CURRENT_SITE_NUMBER() - 1;

                cout << "Site: " << siteIndex + 1 << ": Uploading data, offset = "
                     << uploadDataOffset[siteIndex] << endl;

                if (uploadDataOffset[siteIndex] < expectedDataSize - 1)
                {
                    //
                    // Upload the available data
                    //
                    ARRAY_I resultChunk = vector.getImmediateVectors (uploadDataOffset[siteIndex]);

                    //
                    // Set the read offset for the next upload
                    //
                    uploadDataOffset[siteIndex] += resultChunk.size();

                    //
                    // Add the available data to the ADC histogram data
                    //
                    ...
                    ...

                    //
                    // Set the exit flag for the loop
                    //
                    // Note:    The loop can be left if all expected data have been
                    //          captured, read and processed for all active sites.
                    //
                    if (offlineMode != 1)
                    {
                        dataIsRemaining = true;
                    }

                } // if (uploadDataOffset[iSiteIndex] < expectedDataSize - 1)
            }
            FOR_EACH_SITE_END();

        } // while ( dataIsRemaining )
    }
    NB_DIGITAL_CAPTURE_END(TM::WAIT_DIGITAL);

    resultArea.deselectGlobally();
}
ON_FIRST_INVOCATION_END();
```
