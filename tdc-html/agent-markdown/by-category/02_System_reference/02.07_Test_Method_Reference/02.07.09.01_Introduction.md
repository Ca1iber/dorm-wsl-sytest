# Introduction

Today's SOCs and SiPs require internal register programming to set up the appropriate test/operating modes before any RF, Analog, or DC test can be performed.

Most of the time, the necessary labels cannot be simulated and the test engineer then faces two major challenges:

- Creating a large set of labels necessary for the engineering development / characterization phase

This can be tackled by dynamic vector editing techniques performed on a known working template label obtained from simulation of one single register write, or manually generated, based on the device's known protocol. This may help decrease time-to-market (TTM), as labels can be derived from the template and the tests can be more quickly set up and debugged. This technique is also very convenient for changing device settings back and forth, like in debug and characterization, during test program development, or when bringing up a new device. It only takes a quick change applied to the template label to modify a register setting and take another measurement. The methodology is extremely flexible, but it is generally slower than executing a static label as the test system must first modify the template label and then execute it. During development this is not an issue, as throughput is not as critical, but it may then cause several hundred milliseconds overhead in production, depending on the application.

- Delivering a production-worthy, fast test program where the device pre-conditioning is achieved in the most test-time-efficient way possible

This is normally the execution of static labels. Dynamic techniques impact time-to-volume (TTV) because of the reduced throughput, however, converting dynamic to static might not be trivial, especially if there are hundreds of setup labels, one for each register address/value combination that need to be created.

The dynamic-to-static framework (d2s-framework) addresses both of these aspects without the necessity of changing the source code when switching from one mode to the other. It provides the ability of dynamically creating setup labels for engineering (shorter TTM) and easily converting them into static labels once the test program is mature for production (shorter TTV).

In addition, in case multiple register settings must be issued altogether before a measurement, the framework will create all the individual static example labels and burst them together to achieve faster execution.
