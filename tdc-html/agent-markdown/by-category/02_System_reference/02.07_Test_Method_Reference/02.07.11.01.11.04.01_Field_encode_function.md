# Field encode function

The field encode function generates a state character sequence for each field in a frame.

The resulting field value can be used with other functions of that transaction.

A protocol specific wavetable can be defined that maps the single state characters to vectors.

The user can define state characters almost freely. Exceptions apply to specific characters, such as R, H, L, 1 and 0. The following recommendation for preferred characters ensures best functionality:

- direction IN: [10Z]*
- direction OUT: [LHX]*Note The system automatically sets the state character R, in case that a value shall be determined for an OUT parameter. Thus R cannot be customized at all.

Additional allowed parameters are:

- Protocol Constants (<constant>)
- Transaction specific parameters (<parameter>)
- Field symbols of current field (<symbolName>)
- Other fields within the same transaction (@<field>)Note Beware of cyclic dependencies.
- Other fields within the same transaction but a different pin role (@<pinRole>.@<field>)

All references to other fields must be deterministic at pattern generation time, i.e. before the test is executed. As a consequence no content function may refer to any field with direction OUT.

Possible field encoding errors:

- Missing encode function of a field.
- Missing length specification of a field.
- Field generates illegal state character.
- Content function depends on field, which itself is defined via an OUT parameter.
- Reference to unknown field / pin role.
- Cyclic dependency between fields.
- SCS length resulting from encode function is longer as field length specified with protocol definition.

## Example

Examples for allowed syntax:

@data[0..4]

@data[0..1] + @data2[1..0] + @data[2..4]

@data[0,2,4,5]
