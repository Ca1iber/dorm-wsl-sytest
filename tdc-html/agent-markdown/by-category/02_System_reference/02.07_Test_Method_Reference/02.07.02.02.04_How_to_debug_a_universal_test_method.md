# How to debug a universal test method

- [Setting up Flags for Debugging](<02.07.02.02.04.02_Setting_up_Flags_for_Debugging.md>)

This topic shows how to debug a universal test method in SmarTest.

## About this task

The debugging of universal test methods is done in the Debug perspective of SmarTest.

## Before you begin

Make sure you are using SmarTest 6.3 or later, and the universal test method has been successfully built. A testflow using the test method must be ready for execution.

## Procedure

-  To set breakpoints in the source code, double-click in front of the lines .  ![Set breakpoints in the source file](<../../../../raw/113202.png>)
-  In the C/C++ perspective, click the button Start Test Method Debug ![Start Test Method Debug](<../../../../raw/113592.png>). The test method debugger will be opened. Note Only one SOC Test Method debug session can be run at a time. A default debug configuration is created when the test method debugger is started. If the source files of your different projects have the same name, it may happen that the wrong source file is shown in the debugger. You can solve this problem by checking the Search for duplicate source files on the path option in the Source page of the default test method debugger. This option is checked by default. The default test method debugger can be accessed through Run > Open Debug Dialog > SOC Test Method > test method debugger default.
-  Switch to the testflow editor and execute the test suite using the test method. The test method will be executed and stop at the first breakpoint you set. Note A process is started when you start executing a test method. The process will not be stopped after the execution. If the process is stopped exceptionally, it will be started next time when you execute a test method. You need to pay more attention to the testflow variables when you start executing a test method from exceptional termination. Otherwise you may get wrong test result. (See [Working with variables](<../02.08_Setup_and_Result_Tools/02.08.04.32.02.01.12_Working_with_variables.md>))
-  Debug the test method step by step with the debug icons.  ![Debug buttons](<../../../../raw/99323.png>)

When you step into a line, the debugger may hang up for several seconds and then pop up the error "Target request failed: Target is not responding (time out)." To avoid this, set a break point at the line where the error occurred and close the variables view before stepping into this line.

 Note When you are pausing at a breakpoint, you can also execute another UTM-based test suite.
-  To execute the test method to a special line after the current line and stop there, right-click the line and select Run to Line from the pop-up menu.
-  To execute the test method to a breakpoint ahead of the current line, right-click the line and select Resume At Line.
-  In the Console view, you can change and query the variable value and test method execution status with the C/C++ functions and test method APIs. For example, p variable1 prints the value of variable1 and p testmethod_api executes the testmethod_api`` and prints the execution returned value. To get more information of the commands that can be used in Console view, type in help.

If the test method debugger console is hidden by another console, click the screen button ![Display Selected Console button](<../../../../raw/116279.png>) and select the test method debugger from the shortcut menu.

  ![Debug with Console view](<../../../../raw/114579.png>)
-  To stop the test method debug, click the icon ![Start Test Method Debug](<../../../../raw/113592.png>) again. Note To terminate the execution of a universal test method outside of Debug perspective, you can choose Run > Terminate TestMethod Execution in the main menu of the SmarTest Work Center.

## Results

Your test method is bug free and ready to use.

## What to do next

Install the test method library for the use of other users or other devices.
