# TIMING_SPEC

The TIMING_SPEC API accesses the data container holding the contents of an existing timing equation and spec set.

To define a spec set of an equation set as the primary, execute the [PRIMARY_STATUS](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md>) API member function [timing()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_timing>) for the corresponding TIMING_SPEC API's class object.

To change the definition of a spec value in the spec set that is currently defined as the primary, use the PRIMARY_STATUS API member function [getTimingSpec()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_getTimingSpec>) to return the corresponding TIMING_SPEC API's class object, and execute the TIMING_SPEC API [change()](<02.07.04.01.249_TIMING_SPEC.md#_29809__dle_change>) member function for that returned class object.

The changes of the definitions specified by this API are actually reflected to the hardware when any of the following APIs is executed.

- EXECUTE_TEST
- START_TEST
- DIGITAL_CAPTURE_TEST
- NB_DIGITAL_CAPTURE_START
- FUNCTIONAL_TEST
- FLUSH then SPEC_SEARCH.execute() member function)
- FLUSH then SEQUENCER_STATUS.run() member function)
- FLUSH then PMU_IFVM.execute() member function)
- FLUSH then PMU_VFIM.execute() member function)
- FLUSH then TASK_LIST.execute() member function)
- FLUSH then DPS_VFIM.execute() member function)

The changes of the definitions specified by this API can be also reflected to the MCD when the [FLUSH](<02.07.04.01.69_FLUSH.md>) API is executed. This is an option to reflect the changes on the user interface such as the Test Program Explorer and the Spec Tool.

Using the member functions that retrieve data, the equation set and spec set numbers of the specified class object can be obtained.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TimingSpec.h.

## Important points

- In this API, only one member function can be specified per statement.
- Currently, you can change the primary timing specification or the value of a spec variable in the current specification only if you explicitly define an object of the TIMING_SPEC API class and then refer to this object, for example:

```
TIMING_SPEC spec1(1, 2);
Primary.timing(spec1);
```

- When you query a spec value in the spec set that is currently defined as the primary, you can specify the corresponding TIMING_SPEC API class object in either of the following ways:

  - Obtaining the object by executing the [getTimingSpec()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_getTimingSpec>) member function of the [PRIMARY_STATUS - (Primary)](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md>) API:

For example, to query the value of the spec variable "T", execute as follows:

`DOUBLE t_spec = Primary.getTimingSpec().getSpecValue("T");`

Primary.getTimingSpec() returns the object of the current primary specification and getSpecValue() returns the current value of the "T" spec variable in that object.

  - Specifying the object name directly:

For example, if spec1 defines the current primary specification, specify as follows to get the spec value of "T".

`spec1.getSpecValue("T");`

- When you change a spec value in the spec set that is currently defined as the primary, you can specify the corresponding TIMING_SPEC API's class object in either of the following ways:

  - Obtaining the object by executing the [getTimingSpec()](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md#_29640__dle_getTimingSpec>) member function of the [PRIMARY_STATUS - (Primary)](<02.07.04.01.167_PRIMARY_STATUS_-__Primary.md>) API:

For example, to change the value of the spec "T", execute as follows:

`Primary.getTimingSpec().change("T", 10);`

Primary.getTimingSpec() returns the object of the current primary specification and change() changes the spec value in that object.

  - Specifying the object name directly:

For example, if spec1 defines the current primary specification, specify as follows to change the spec value.

`spec1.change("T", 10);`

Both statements shown above produce the same result if spec1 defines the current primary timing specification.

- When the change of the primary spec set or primary equation set is specified in the PRIMARY_STATUS API, the spec value changes specified in the TIMING_SPEC API's class objects are cleared if the FLUSH API has not been executed for them yet.

If you need to reflect these changes (into the MCD), execute `FLUSH(TM::APRM)` once before specifying another primary spec set or primary equation set in the PRIMARY_STATUS API. In the following example, FLUSH is not executed before the change to the spec set "3" is specified. Therefore, the changes specified for "T" and "T2" are ignored (not executed).

```
TIMING_SPEC spec1(1, 2);
TIMING_SPEC spec2(1, 3);
Primary.timing(spec1);
FUNCTIONAL_TEST();
TEST(TM::CONTINNUE);
Primary.getSpecification().change("T", 10);
Primary.getSpecification().change("T2", 20);
Primary.timing(spec2);
FLUSH;
```

- After the [FLUSH](<02.07.04.01.69_FLUSH.md>) API is executed to change the spec values in a testsuite, the changes are used in the subsequent testsuites (unless you load a timing setup file during debugging). If you want to use the original spec values in the next testsuite, execute the [restore()](<02.07.04.01.249_TIMING_SPEC.md#_29809__dle_restore>) member function and FLUSH API in the test method program of the testsuite where you changed the spec values. restore() resets the values of specs to the ones when the test method program of the current testsuite is started.
- The [change()](<02.07.04.01.249_TIMING_SPEC.md#_29809__dle_change>) member function and FLUSH API change a spec value, but the Test Program Explorer does not indicate that the timing is changed. In this case, if you need to reload the current timing setup file during debugging, first change a spec value in the Spec Tool window to cause the Test Program Explorer to indicate that the timing is changed.

## Examples

### Example 1: Change primary timing set

```
TIMING_SPEC spec1(1, 2);
Primary.timing(spec1);
Primary.timing(1);
```

spec1 is an object of the TIMING_SPEC class. The timing() member function of the PRIMARY_STATUS API sets timing equation set "1" and spec set "2" as the primary timing specification. The timing equation and spec set numbers must be specified using the corresponding object name spec1.

The second timing() member function defines the timing set "1" as the primary.

### Example 2: Change a primary timing spec value

```
TIMING_SPEC spec1(1, 2);
Primary.getTimingSpec().change("Tp", 10);
```

The change() member function changes the value of spec variable "Tp" to 10 nanoseconds. The Primary.getTimingSpec() statement returns the TIMING_SPEC API's class object, namely spec1, that defines the current primary timing specification.

```
TIMING_SPEC& ts_obj= Primary.getTimingSpec();
ts_obj.change("Tp", 10);
```

The change() member function changes the spec variable "Tp" to10 nanoseconds. By the ampersand (&) in the first statement, ts_obj is created as a reference to the class object returned by Primary.getTimingSpec() without copying the contents object.

```
TIMING_SPEC spec1(1, 2);
Primary.getTimingSpec().change("Tp", 10 ns);
```

In this example, with "ns" in the second parameter of the change() member function, the spec variable "Tp" is changed into 10-9 seconds. This is more convenient when you want your timing in nanoseconds be represented in seconds basis.

### Example 3: Retrieve a primary timing spec value

```
DOUBLE specValue = Primary.getTimingSpec().getSpecValue("Tp");
```

The getSpecValue() member function returns the value of the "Tp" spec variable in the currently defined primary specification. The Primary.getTimingSpec() statement returns the TIMING_SPEC API's class object that represents the spec set and equation set that are currently defined as the primary.

### Example 4: Retrieve a primary timing spec value for a multiport specification

```
DOUBLE specValue = Primary.timing(SPECIFICATION("spec")).getSpecification().getSpecValue("specValue@port");
```

The [getSpecValue()](<02.07.04.01.249_TIMING_SPEC.md#_29809__dle_getSpecValue>) member function returns a spec value for a single port of a multiport timing specification. The spec value and the port are defined by `"specValue@port"`. The multiport timing specification is selected by the [SPECIFICATION](<02.07.04.01.232_SPECIFICATION.md>) API.

### Example 5: Retrieve the timing equation set

```
INT tmg_eq;
    :
tmg_eq = Primary.getTimingSpec().getEquation();
```

The getEquation() member function returns the timing equation set number currently defined as the primary.
