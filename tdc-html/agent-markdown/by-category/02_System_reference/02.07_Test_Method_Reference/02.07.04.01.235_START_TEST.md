# START_TEST()

Starts the digital sequencer at the specified start label, then changes the state of the digital sequencer from "BRK" to "RUN". Program execution goes to the next statement.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Execute.h.

## Syntax

```
START_TEST();
START_TEST(const STRING & exec_context);
```

 |

exec_context

Name of an execution context. The ports of the context must be included in the current start label (which must be a multiport burst). For more information on execution contexts see [Using execution contexts](<../02.06_Command_Reference/02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>) .

## Important points

- In order for this API (or an API that internally executes the [FLUSH](<02.07.04.01.69_FLUSH.md>) API) to reflect the changes that are specified by ROUTING_STATUS/ANALOG_STATUS to an analog module hardware, the sequencers in all analog modules must be halted. For more information, see the [FLUSH](<02.07.04.01.69_FLUSH.md>) API.
- The START_TEST API performs almost the same role as the [EXECUTE_TEST](<02.07.04.01.65_EXECUTE_TEST.md>) API. However, it does not wait for the test completion but goes to the next statement in your program.
- Instead of the START_TEST API, use the [DIGITAL_CAPTURE_TEST](<02.07.04.01.35_DIGITAL_CAPTURE_TEST.md>), or [NB_DIGITAL_CAPTURE_START](<02.07.04.01.135_NB_DIGITAL_CAPTURE_START.md>) APIs when executing the test which contains the digital capturing. If you attempt to execute the test containing the digital capturing with the normal START_TEST API, the test cannot be done. For details, see the [DIGITAL_CAPTURE_TEST](<02.07.04.01.35_DIGITAL_CAPTURE_TEST.md>) and [NB_DIGITAL_CAPTURE_START](<02.07.04.01.135_NB_DIGITAL_CAPTURE_START.md>).
- The START_TEST API has to be used in conjunction with the [WAIT_TEST_DONE](<02.07.04.01.271_WAIT_TEST_DONE.md>) API. You can perform another job (for example, data calculation in parallel) between the START_TEST and [WAIT_TEST_DONE](<02.07.04.01.271_WAIT_TEST_DONE.md>) APIs while the tester hardware is running.
- The [WAIT_TEST_DONE](<02.07.04.01.271_WAIT_TEST_DONE.md>) API does not wait until the AWG finishes the output. If an infinitely loop sequence, LOOPI or RPTI, is used for AWG, you can use the ABORT_TEST API to stop the infinitely loop of the AWG.

  - After starting the test execution, the START_TEST API executes the [FLUSH](<02.07.04.01.69_FLUSH.md>) API internally for reflecting the changes of the setting data by the following APIs to the setup data or hardware:
  - ANALOG
  - ANALOG_STATUS
  - PRIMARY_STATUS
  - TIMING_SPEC / LEVEL_SPEC / SPECIFICATION
  - ROUTING_STATUS

## Example

This example executes two test executions; the first is by the EXECUTE_TEST API and the second is by the START_TEST API. During the second test execution, the DSP_SND API calculates the SND in parallel from the first test's result between the START_TEST and [WAIT_TEST_DONE](<02.07.04.01.271_WAIT_TEST_DONE.md>) APIs.

```
  INT timeout_flag;
  ARRAY_D AnaWave1, AnaWave2;
  double snr_result, spower, n_power;
    :
 //Execute a test with primary analog set
  EXECUTE_TEST(0.1 sec);

  //Retrieve first measurement result
  AnaWave1 = Analog.DGT("Aout").getWaveform();

  //Change primary analog set to #2
  Analog.primary(2);

  //Execute a test with primary analog set #2
  START_TEST();

  //Calculate SND from first
  //measurement result
  DSP_SND(AnaWave1, &snr_result, &spower, &n_power,
          1, 0.0, 0);

  //Wait to complete a test and calculation
  WAIT_TEST_DONE(0.1 sec, &timeout_flag);

  //Retrieve second measurement result
  AnaWave2 = Analog.DGT("Aout").getWaveform();
```

For an example of START_TEST() with [WAIT_TIME()](<02.07.04.01.272_WAIT_TIME.md>), see the Example section of [SEQUENCER_CONTEXT](<02.07.04.01.201_SEQUENCER_CONTEXT.md>).
