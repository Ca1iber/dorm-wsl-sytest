# ORE file format

#### Subtopics

- [Test name elements](<02.07.13.08.20.03.01_Test_name_elements.md>)

An ORE file, as an XML file, follows common XML rules while has its own XML structure.

The example below demonstrates the ORE file structure.

```
<offlineResultEmulation>
 <testSuite name = "MytestSuite">
  <id name = "id1">
   <site num = "1,3">
    <pin name = "DATA1">
     <dc value= "3.0"/>
    </pin>
   </site>
   <site num = "4" to = "10">
    <pin name = "DATA1"/>
     <dc value= "4.0"/>
    </pin>
   </site>
  </id>
 </testSuite>
</offlineResultEmulation>
```

As shown above, an ORE file consists of some major elements as listed in the following table:

Elements in an ORE file
 |

Elements

 |

Description

 |
 |  <offlineResultEmulation>   | Root element of the ORE file. |
 |  <testSuite> |

The test suite that contains the result retrieval command.

Optional.

Skipping this element means "any" test suite.

 |
 | <id> |

The SmartRDI result ID.

Mandatory.

It supports string and integer IDs.

-

string id example: `<id name = "id1">`

- integer id example: `<id name = "__1__">`
 |
 | <pin> |

The measuring pin.

Mandatory in most cases.

Comma separated pin lists are supported; pin groups must be expanded to pin lists.

For special cases like per-label Pass/Fail results, `<pin>` is inapplicable.

 |
 | <site> |

Supports different results on different sites.

Optional.

Skipping this element means all sites are selected.

A syntax pattern is provided to select a range of sites. Below is an example:

```
<site num = "4" to = "10">
```

 |
 | Test name elements (such as <dc>) |

The node where the test result values are stored.

Mandatory.

See [Test name elements](<02.07.13.08.20.03.01_Test_name_elements.md>) for details.

  |  Check the [ORE file template](<02.07.13.08.20.02.01_Template_file_from_the_first_run.md>) to see a full list of elements. You can adapt this template file to your own requirements by commenting unwanted code blocks. To comment a code line or block, simply use the XML comment format. Below is an example.

```
<offlineResultEmulation>
 <testSuite name = "MytestSuite">
  <id name = "id1">
   <site num = "1,3">
    <pin name = "DATA1">
     <dc value= "3.0"/>
    </pin>
   </site>
   <!- My comments: The following code lines are commented to skip site 4-10 -->
   <!- site num = "4" to = "10">
    <pin name = "DATA1"/>
     <dc value= "4.0"/>
    </pin>
   </site -->
  </id>
 </testSuite>
</offlineResultEmulation>
```
