# Converting a classic testflow to a UTM-based testflow

#### Subtopics

- [How to convert a classic testflow to universal-test-method-based testflow](<02.07.02.06.01_How_to_convert_a_classic_testflow_to_universal-test-method-based_testflo.md>)

A conversion tool convertTestflow is provided to convert the classic-test-method-based test suite and test-function-based test suite to a UTM-based test suite. It is located in the directory /opt/hp93000/soc/prod_pws/migration/UTM_conversion/bin.

The conversion tool is only available in the 32-bit SmarTest.

The following four testflow types can be handled by the conversion tool:

- test-function-based testflow
- classic-test-method-based testflow
- testflow using both test functions and classic test methods
- testflow using both test functions and universal test methods.

Before converting a classic-test-method based test suite to a UTM-based test suite, you must have converted the classic test method to universal test method. Then in the testflow conversion, the classic-test-method-based test suite will be converted to a UTM-based test suite using the converted universal test method.

To convert a CTM-based testflow on RH3 to UTM-based testflow on RH5,

- you can convert CTM to UTM and convert the CTM-based testflow to UTM-based testflow on RH3. Then you can build the universal test method and load the UTM-based testflow on RH5.
- you can also firstly convert classic test method from RH3 to RH5. Then you can convert CTM to UTM and convert CTM-based testflow to UTM-based testflow on RH5. (This is only for SmarTest version supporting CTM on both RH3 and RH5.)
- or you can compile and register the CTM libraries on RH5 in the command line. Then you can convert CTM to UTM and convert CTM-based testflow to UTM-based testflow on RH5.

The conversion from a test-function-based test suite to a UTM-based test suite is done by replacing the test function with the equivalent test method available in the predefined test method libraries (in the directory /opt/hp93000/soc/testmethod/sh_lib).

 Note In SmarTest 6.5.4, to convert the test functions to TML 2.1.0, use the conversion tool included in the independent TML 2.1.0 package.

If the test function has no equivalent test method, it will be mapped to the most proper test method during the conversion. The related test function parameters will be dumped to a log file. At the end of the conversion, a warning message will be issued telling that you need to do manual conversion to the test function.

In the conversion of a test-function-based test suite, remember the following limitations:

- PPMU auto-ranging is not supported in test methods. You need to manually set proper limit ranges with the test method API.
- DPS sampling is done in test methods. You need to set proper limit ranges and samples for operating/standby current measurement.

As for the conversion of test functions with no equivalent test method libraries:

- To convert the Global Search ,Hold Time, Setup Time, Input Voltage Sensitivity, Output Voltage Sensitivity, Propagation Delay and Output Data Hold Time to test method library, you can use the `parametricFunctionalTest` test method. You need to adjust the parameters of `parametricFunctionalTest` to implement different tests. (See [AC test function conversion](<02.07.02.06.01.01_AC_test_function_conversion.md>).)
- To convert the Jitter test function to test method library, you can use the `JitterHistogram` test method. But a different test methodology is used in the measurement.
- To convert Mixed signal test, you can use the [test method snippets provided by SmarTest](<02.07.06_Test_method_snippets_provided_with_SmarTest.md>) to create your own test method.
- To convert the shmoo_2d test function, you can add specs in the level/timing setup and use `ac_tml.AcTest.Shmoo` to do the test.
- To convert the set_spec_value, header and comment test function, you need to create the test method code by yourself.
- To convert the golden_device test function, you can use the pattern debug tool. (Refer to [Replacing failed state characters for golden device](<../02.08_Setup_and_Result_Tools/02.08.04.16.02.06.06_Replacing_failed_state_characters_for_golden_device.md>).)
- To convert the memory_analysis and redundancy_repair test function, you can use the [Memory testing test method](<../02.12_Memory_Test_Plus_7.10.2/02.12.02.05.06.01_Memory_testing_test_method.md>) of MTP on SOC.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.5.2: Test-function-based test suite can now be converted to UTM-based test suite.
- SmarTest 6.5.4: Test functions which have no equivalent test methods will be mapped to the most proper test methods.
- SmarTest 7.1.0: The location of the conversion tool is changed.
