# SMC_WAIT_TEST_DONE()

Waits for the test to complete and allows hidden upload of data controlled by SmartCalc. It has to be used in conjunction with [START_TEST](<02.07.04.01.235_START_TEST.md>).

It is able to detect whether digitizers and samplers have received multiple trigger inputs during the execution. For further details, refer to [Error Handling on Missing Trigger Input](<02.07.03.16.03_Error_Handling_on_Missing_Trigger_Input.md>). This API cannot detect AWG timeouts.

The test time is compared to a timeout value. This value can be defined with the timeout parameter. If this parameter is omitted, the default or the value that was last set is used. If the timeout_info parameter is omitted and the test exceeds the timeout value, the test will be aborted and the testsuite will be judged as FAILED. If the timeout_info parameter is set, WAIT_TEST_DONE() will return timeout information, and the test will continue with the next statement.

In a multi-site test, the reply of the timeout_info parameter depends on whether it is used in combination with the trigger_info parameter. If it is used alone, it will return global timeout information, that is, it will return 1 if a timeout occurred on any site, and 0 otherwise. If both parameters are specified, it will return site specific timeout information.

`SMC_WAIT_TEST_DONE()` can also be used with [SMC_DIGITAL_CAPTURE_TEST()](<02.07.04.01.231.08_SMC_DIGITAL_CAPTURE_TEST.md>), [SMC_FUNCTIONAL_TEST()](<02.07.04.01.231.13_SMC_FUNCTIONAL_TEST.md>), [SEQUENCER_STATUS - (Sequencer)](<02.07.04.01.204_SEQUENCER_STATUS_-__Sequencer.md>) and [SPEC_SEARCH](<02.07.04.01.233_SPEC_SEARCH.md>). In this case, it starts to count the timeout from the end of the execution of the corresponding API used.

Another task (for example, data calculation in parallel) can be performed between [START_TEST](<02.07.04.01.235_START_TEST.md>)and `SMC_WAIT_TEST_DONE()` while the tester hardware is running.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.

## Syntax

```
void SMC_WAIT_TEST_DONE(DOUBLE timeout = 360000, const STRING& context = "",const STRING& pins = "");
void SMC_WAIT_TEST_DONE(DOUBLE timeout, INT *timeout_info, const STRING& context = "", const STRING& pins = "");
void SMC_WAIT_TEST_DONE(DOUBLE timeout, INT *timeout_info, INT *trigger_info, const STRING& context = "", const STRING& pins = "");
void SMC_WAIT_TEST_DONE(const TM::WAIT_ACTION& wait_action, const STRING& context = "", const STRING& pins = "");
void SMC_WAIT_TEST_DONE(DOUBLE timeout, const TM::WAIT_ACTION& wait_action, const STRING& context = "", const STRING& pins = "");
void SMC_WAIT_TEST_DONE(DOUBLE timeout, INT *timeout_info, const TM::WAIT_ACTION& wait_action, const STRING& context = "", const STRING& pins = "");
void SMC_WAIT_TEST_DONE(DOUBLE timeout, INT *timeout_info, INT *trigger_info, const TM::WAIT_ACTION& wait_action, const STRING& context = "", const STRING& pins = "");
```

Parameters
 |

I/O

 |

Parameter

 |

Description / Range

 |
 |

I

 |

timeout

 |

Timeout time of the measurement (test) in sec.

This cannot detect a timeout for the AWGs. Operations when timeout occurs depend on whether the timeout_info parameter is set or omitted.

 |
 |

O

 |

timeout_info

 |

This parameter returns timeout information. It can only be used in combination with the timeout parameter.

The reply of timeout_info depends on whether it is used with or without the trigger_info parameter.

If trigger_info is not specified, timeout_info returns global timeout information. Possible return values are:

0: No timeout occurred on any site.

1: A timeout occurred on one site at least.

If trigger_info is also specified, timeout_info returns site specific timeout information.

In this case, the returned integer must be converted into binary format. Every bit returns the timeout status of one site. Site 1 is represented by the LSB.

For example, if 13 is returned to this parameter, this corresponds to binary number 1101. This indicates timeout occurred on the site 1, site 3 and site 4.

 |
 |

I

 |

wait_action

 |

Selects the sequencer the API shall wait for completion. Options can be combined by using '|' (bitwise OR).

Default: TM::WAIT_DIGITAL `| ` TM::WAIT_DGT `| ` TM::WAIT_TIA

Refer to the list of available options of the wait_action parameter below.

 |
 |

I

 |

context

 |

Name of an execution context. The ports of the context must be included in the current start label (which must be a multiport burst). For more information on execution contexts see [Using execution contexts](<../02.06_Command_Reference/02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>) .

The context must have been defined on the firmware level (with the SQEC command), or as a SEQUENCER_CONTEXT_ITEM object. In the latter case this object must have been included in a SEQUENCER_CONTEXT object, and must also have been activated on the firmware level with the apply() function of this SEQUENCER_CONTEXT object. If the context has been defined as a SEQUENCER_CONTEXT_ITEM object, you must use the name specified for its name parameter.

 |
 |

I

 |

pins

 |

If WAIT_TMU is included in the wait_action parameter, WAIT_TEST_DONE will by default wait until the TMU measurement has been completed on all pins of the active TMU set. With the pins parameter, this behavior can be restricted to the specified pins.
