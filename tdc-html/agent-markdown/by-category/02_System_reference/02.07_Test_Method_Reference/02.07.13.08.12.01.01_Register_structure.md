# Register structure

Register structure is based on a CMSIS-SVD XML hierarchy. A CMSIS-SVD XML file normally contains the structure description of a single device. The file must be converted to a C++ structure before the register structure can be used in test methods.

  Here is a typical CMSIS-SVD XML Hierarchy: ![CMSIS-SVD XML Hierarchy](<../../../../raw/351644.png>)

According to [CMSIS-SVD](<https://www.keil.com/pack/doc/CMSIS/SVD/html/index.html>) , an SVD file usually describes the structure of a device. A device is formed of a processor and at least one peripheral. Each peripheral has at least one register. A register can have one or more fields. The range of values for a field can be further described with enumerated values.

 Peripheral level, register level, and field level are the main levels handled in [register operations](<02.07.13.08.12.03_Usage_of_register_operations_in_test_method.md>). They are described by [CMSIS-SVD](<https://www.keil.com/pack/doc/CMSIS/SVD/html/index.html>) as follows. Peripheral level A peripheral is a named collection of registers. A peripheral is mapped to a defined base address within the device's address space. A peripheral allocates one or more exclusive address blocks relative to its base address, such that all described registers fit into the allocated address blocks. Allocated addresses without an associated register description are automatically considered reserved. The peripheral can be assigned to a group of peripherals and may be associated with one or more interrupts.   Register level A register is a named, programmable resource that belongs to a peripheral. Registers are mapped to a defined address in the address space of the device. An address is specified relative to the peripheral base address. The description of a register documents the purpose and function of the resource. A debugger requires information about the permitted access to a resource as well as side effects triggered by read and write accesses respectively.   Field level Registers may be partitioned into chunks of bits of distinct functionality. A chunk is referred to as field. The field names within a single register must be unique. Only architecturally defined fields shall be described. Any bits not being explicitly described are treated as reserved. They are not displayed in the System Viewer and are padded in the bit fields of the device header file. The case-insensitive field named "reserved" is treated as a keyword and each field with this name is ignored.

For more detailed information about the CMSIS-SVD XML Hierarchy, refer to [SVD Description (*.svd) Format](<https://www.keil.com/pack/doc/CMSIS/SVD/html/svd_Format_pg.html>) on the [CMSIS-SVD](<https://www.keil.com/pack/doc/CMSIS/SVD/html/index.html>) website.

## Example

### An SVD file example

```
<?xml version="1.0" encoding="UTF-8" standalone="no"?>
<device xmlns:xs="http://www.w3.org/2001/XMLSchema-instance" schemaVersion="1.1" xs:noNamespaceSchemaLocation="CMSIS-SVD.xsd">
  <name>RegisterAccessExample</name>           <!-- name of part-->
  <addressUnitBits>8</addressUnitBits>         <!-- byte addressable memory -->
  <width>16</width><access>read-write</access> <!-- bus width is 16 bits -->
  <size>16</size>                              <!-- the default size (number of bits) of all peripherals and register that do not define "size" themselves -->

  <resetValue>0x00000000</resetValue>          <!-- by default all bits of the registers are initialized to 0 on reset -->
  <resetMask>0xFFFFFFFF</resetMask>            <!-- by default all 32 bits of the registers are used -->
  <peripherals>
    <peripheral>
      <name>RegisterGroup1</name>
      <baseAddress>0x0000</baseAddress>
      <size>16</size>
      <access>read-write</access>
      <registers>
        <register>
          <name>Register1</name>
          <addressOffset>0x0</addressOffset>
          <size>16</size>
          <resetValue>0x4800</resetValue>
          <fields>
            <field>
              <name>field1</name>
              <description>Description of field1</description>
              <bitRange>[15:13]</bitRange>
              <access>read-only</access>
            </field>

            <field>
              <name>field2</name>
              <description>Description of field2</description>
              <bitRange>[12:10]</bitRange>
              <access>read-only</access>
            </field>

            <field>

            </field>

              <name>field4</name>
              <description>Description of field4</description>
              <bitRange>[4:0]</bitRange>
              <access>read-only</access>
            </field>
          </fields>
        </register>

        <register>
          <name>Register2</name>
          <addressOffset>0x2</addressOffset>
          <size>16</size>
          <resetValue>0x0CC0</resetValue>
          <fields>

      </registers>
    </peripheral>
    <peripheral>

      <name>RegisterGroup2</name>
      <baseAddress>0x0080</baseAddress>
      <size>16</size>
      <access>read-write</access>
      <registers>
        <register>
          <name>Register1</name>
          <addressOffset>0x0</addressOffset>
          <size>16</size>
          <resetValue>0x0000</resetValue>
          <fields>
            <field>
              <name>field1</name>
```
