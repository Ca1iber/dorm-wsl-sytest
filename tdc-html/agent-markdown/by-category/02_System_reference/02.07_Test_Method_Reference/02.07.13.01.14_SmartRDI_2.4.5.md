# SmartRDI 2.4.5

This section summarizes the changes and new features in SmartRDI 2.4.5.

Changes and new features
 |

Category

 |

Description

 |
 |

General

 |

General features:

- Non-blocking execution

See the new parameter TA::NON_BLOCKING in [RDI_END()](<02.07.13.08.01.05_RDI_END.md>).

- Default Emap location set in the RDI_Configure file

See the new keyword DEFAULT_EMAP_LOCATION in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

- Support dumping RDI executed code information

See Level 3 in [RDI_INFO_LEVEL](<02.07.13.06_RDI_INFO_LEVEL.md>).

- Put RDI_INFO_LEVEL message to a log file

See the new keyword ENABLE_RDI_INFO_LOG_FILE in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

General Improvements:

- SmartVec upload speed improvement

  - Before SmartRDI 2.4.5, the DIGCAP read mode uploads data at a speed of 1 bit per word; SmartRDI 2.4.5 improves this speed to 32 bit per word.
  - In SmartRDI 2.4.5, the Emap read mode's upload speed is accelerated by [changing the default error map location](<02.07.13.16.02_emapLocation.md>). This improvement takes effect only if [the Emap location is set to RAM (default)](<02.07.13.04_RDI_Configure_file.md>).

- TMU upload speed improvement

In SmartRDI 2.4.5, the result upload of TMU pins with the same setup is combined. Because data upload for multiple TMU pins with the same parameters in one `RDI_BEGIN()/RDI_END()` block is combined, the upload speed is improved.

- 1st run speed improvement for non-MD5 bursts (SmarTest 7.4.2)

See BURST_NAME_MD5 in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

- Label content checking with customized label name (SmarTest 7.4.2)

See the new keyword USER_NAMED_LABEL_CONTENT_CHECK in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

 |

SMC

 |

- Common thread SMC for error map result

Since SmartRDI 2.4.5, the error map result supports common thread SMC. See [Using SmartCalc (SMC) with SmartRDI](<02.07.13.08.19_Using_SmartCalc__SMC__with_SmartRDI.md>) and [rdi.site()](<02.07.13.08.19.02.04_rdi.site.md>).

- Non-SMC execution for short bursts

See the new keyword DISABLE_SMC_EXEC_SHORT_BURST in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

- Flexible control of the SMC execution (global ON/OFF)

By default all `RDI_BEGIN()/RDI_END()` blocks run in the "SMC execution" mode, which can trigger result hidden upload of the previous tests, and take a longer time (extra 50-100 us) to complete compared to the normal execution. SmartRDI 2.4.5 provides two options to disable the default "SMC execution" mode.

  - A RDI_Configure option as a global setting of the mode. See the new keyword DISABLE_SMC_EXEC_GLOBAL in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).
  - A pair of commands to set the execution mode for the following `RDI_BEGIN()/RDI_END()` blocks in code. See the new topics [rdi.disableSmcExec()](<02.07.13.08.19.02.01_rdi.disableSmcExec.md>) and [rdi.enableSmcExec()](<02.07.13.08.19.02.02_rdi.enableSmcExec.md>).

- Improved code structure for SMC

  - In SmartRDI 2.4.5, `rdi.site().id().getXXX()` can be called anywhere inside a test method's `run()` function. See [rdi.site()](<02.07.13.08.19.02.04_rdi.site.md>).
  - In SmartRDI 2.4.5, `SMC_DISABLE(true)` can be combined with `rdi.hiddenUpload(TA::ALL)`. See [rdi.hiddenUpload()](<02.07.13.08.19.02.03_rdi.hiddenUpload.md>).

TMU

 |

- Timeout behavior improvement

Before SmartRDI 2.4.5, the TMU time out is set to 50 ms, which means that if the digital TMU does not get all results, it will wait for 50 ms after the pattern is finished. In SmartRDI 2.4.5, the timeout of the digital TMU is set to 0 ms, which means that the TMU stops working after the pattern is finished. To keep the same timeout behavior as SmarTest 2.4.4, a flag is implemented in the RDI_Configure file.

See the new keyword TMU_TIMEOUT_50ms in [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).
