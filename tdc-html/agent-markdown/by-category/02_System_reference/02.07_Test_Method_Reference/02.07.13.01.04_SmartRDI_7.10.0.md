# SmartRDI 7.10.0

This section summarizes software changes including new features and enhancements in SmartRDI 7.10.0.

Changes and new features
 | Category  | Description |
 | General  | Two functions are added for changing the value specified by the testflow flag variable [RDI_INFO_LEVEL](<02.07.13.06_RDI_INFO_LEVEL.md>):

- [rdi.setInfoLevel()](<02.07.13.06.02_rdi.setInfoLevel.md>): Set a new debug information level for a block or test suite.
- [rdi.getInfoLevel()](<02.07.13.06.01_rdi.getInfoLevel.md>): Retrieve the level result value.
 |
 | [Cogo](<02.07.13.19.02_Sequencer-controlled_searching_with_cogo.md>) |

- The results of binary, linear, and hysteresis linear searches can be retrieved without [pathPin()](<02.07.13.19.02.02_pathPin.md>).
 |
 | [DC](<02.07.13.12.02_Setting_up_DC_Scale_pins_with_SmartRDI.md>) |

- [perSiteVal()](<02.07.13.11.01.03_perSiteVal.md>) specifies a value per site.
- Both [vMeasReturnDrop()](<02.07.13.12.02.46_vMeasReturnDrop.md>) and [vMeasForceDrop()](<02.07.13.12.02.44_vMeasForceDrop.md>) support [UHC4T card](<../02.05_Test_Head_Cards/02.05.05.02.03_UHC4T_functionality_and_features.md>).
- [Parallel DC actions on multiple pins](<02.07.13.11.07.03_Forcing_waveform_and_sampling_in_parallel_on_multiple_pins.md>).
- [Parallel pulse actions with measurement and sampling](<02.07.13.11.08_Parallel_pulse_actions_with_measurement_and_sampling.md>).
- [DC waveforms per site](<02.07.13.11.03_DC_waveforms_per_site.md>).
 |
 | [Func](<02.07.13.17_Functional_test_setup.md>) |

- [rdi.func().burst()](<02.07.13.17.01.01_rdi.func__.burst.md>) supports multiport burst labels in the [pattern‑based mode](<02.07.13_SmartRDI.md#_142069__dle_Pattern-based_mode>).
- [rdi.port(TA::MULTI_PORT).func()](<02.07.13.17.01.20_rdi.port_TA__MULTI_PORT_.func.md>) supports inserting multiport bursts into a new label.
 |
 | [ORE](<02.07.13.08.20_Using_Offline_Result_Emulation_in_SmartRDI.md>) |

- [ORE_TEMPLATE_DATA_FILE_SIZE_THRESHOLD](<02.07.13.04_RDI_Configure_file.md#_146692__row_ORE_TEMPLATE_DATA_FILE_SIZE_THRESHOLD>) can be used to set a threshold for the result size of your ORE template.
- An ORE template file can be generated with real test results of all sites. See [Test results of all sites to the template file](<02.07.13.08.20.02.03_Template_file_from_online_test_results.md#_348899__ORE_all_sites_results_to_template>).
- An ORE template file can be generated for each execution. See [Generating an ORE template file for each execution](<02.07.13.08.20.02.02_Template_file_based_on_user_code.md#_346615__ORE_multi_templatefile_for_oneExecution>).
- [Alarm handling ORE results](<02.07.13.08.20.03.01.01_The__alarm__element.md>) can be retrieved and an alarm handling ORE result template file can be generated.
- [rdi.startNextOreTemp()](<02.07.13.08.20.01.03_rdi.startNextOreTemp.md>) can be used to set a separate point between executions so a template file for each execution can be generated.
 |
 | [smartVec](<02.07.13.24_SmartRDI__Vector_and_protocol_programming.md>) |

- The default value of [SMV_DIGCAP_AUTO_BURSTUPLOAD](<02.07.13.04_RDI_Configure_file.md#_146692__row_SMV_DIGCAP_AUTO_BURSTUPLOAD>) is changed from FALSE to TRUE.
 |

## Supported SmarTest versions

SmartRDI 7.10.0 supports SmarTest 7.10.0.
