# FOR_EACH_SITE_BEGIN

This API declares the beginning of the block that allows you to execute setup sequentially for all sites before the parallel test. If you want to sequentially setup and query, use [FOR_EACH_SITE_BEGIN_WITH_QUERY](<02.07.04.01.71_FOR_EACH_SITE_BEGIN_WITH_QUERY.md>).

## Application note

- FOR_EACH_SITE_BEGIN and [FOR_EACH_SITE_END](<02.07.04.01.72_FOR_EACH_SITE_END.md>) must be used as a pair. The area enclosed by this pair is called "each site loop block".
- This API is meaningful for multi-site testing. For single-site testing, this API is ignored.
- The each site loop block enables site-specific setup (different setup conditions for each site) before parallel test execution. The each site loop block must be placed

  - in the first-invocation block declared by [ON_FIRST_INVOCATION_BEGIN](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) and [ON_FIRST_INVOCATION_END](<02.07.04.01.139_ON_FIRST_INVOCATION_END.md>) or
  - in the last-invocation block declared by [ON_LAST_INVOCATION_BEGIN](<02.07.04.01.140_ON_LAST_INVOCATION_BEGIN.md>) and [ON_LAST_INVOCATION_END](<02.07.04.01.141_ON_LAST_INVOCATION_END.md>).

- All statements in the each site loop block are executed serially for all active sites when the program is run for the first tested site.
- For the APIs that set up conditions for the setup-focus state sites only and the APIs that always set up conditions for all sites, see [API Behavior on Multi-Site Testing](<02.07.03.13.07_API_Behavior_on_Multisite_Testing.md>).
- To query setup and result information for the active sites, use [FOR_EACH_SITE_BEGIN_WITH_QUERY](<02.07.04.01.71_FOR_EACH_SITE_BEGIN_WITH_QUERY.md>).

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/MapiUtil.h.

## Syntax

```
FOR_EACH_SITE_BEGIN();
```

List of parameters

There are no parameters.

Return value

There is no return value.

## Examples

### Example 1: Minimum code

The following example shows the minimum code for a "each site loop block". The ellipses ("...") are to be replaced with your code.

```
ON_FIRST_INVOCATION_BEGIN();
    ...
    ...
    FOR_EACH_SITE_BEGIN();
        ...
        ...
    FOR_EACH_SITE_END();
    ...
    ...
ON_FIRST_INVOCATION_END();
```

### Example 2: Optional curly brackets

The example utilizes optional pairs of curly brackets "{" and "}". These optional curly brackets are used for simplifying the correct indentation with assistance of the related Eclipse tool.

```
ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...
    FOR_EACH_SITE_BEGIN();
    {
        ...
        ...
    }
    FOR_EACH_SITE_END();
    ...
    ...
}
ON_FIRST_INVOCATION_END();
```

### Example 3

```
ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Pre-measurement
    //
    PMU_IFVM pmuIfvm("Aout_trig");
    ...
    ...

    //
    // Serial execution for all Sites - BEGIN
    //
    FOR_EACH_SITE_BEGIN();
    {
        //
        // Get pre-measurement result for each site
        //
        DOUBLE V_off = pmuIfvm.getValue("Aout_trig");

        //
        // Set pre-measurement result for each site
        // as site-specific setup condition
        //
        DGT("Aout").vOffset(V_off);

        //Serial Execution for All Sites - END
    }
    FOR_EACH_SITE_END();

    //
    // Setup and test Execution on all active sites
    //
    EXECUTE_TEST(0.1 sec);
    ...
    ...
}
ON_FIRST_INVOCATION_END();
```

FOR_EACH_SITE_BEGIN() and FOR_EACH_SITE_END() declare the each site loop block in the first-invocation block. All APIs in each site loop block are executed serially for all sites when the program is run for the first tested site.
