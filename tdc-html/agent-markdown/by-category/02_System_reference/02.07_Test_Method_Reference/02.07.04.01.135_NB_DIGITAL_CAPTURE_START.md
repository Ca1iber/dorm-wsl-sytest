# NB_DIGITAL_CAPTURE_START

This API declares the beginning of a non-blocking test which contains digital capturing.

The non-blocking function is designed to execute functional tests that include digital capture (for example, ADC). This functionality allows the user to continue to execute firmware commands on analog instrumentation while the digital capture test is running.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Execute.h.

## Syntax

```
NB_DIGITAL_CAPTURE_START();
NB_DIGITAL_CAPTURE_START(const STRING & resultAreaId);
NB_DIGITAL_CAPTURE_START(const STRING & resultAreaId, const STRING & exec_context);
```

Parameters
 |

resultAreaId

 |

The name of a result retention area for background processing. See [RESULT_AREA_CONFIG](<02.07.04.01.189_RESULT_AREA_CONFIG.md>) API.

 |
 |

exec_context

 |

Name of an execution context. The ports of the context must be included in the current start label (which must be a multiport burst). For more information on execution contexts see [Using execution contexts](<../02.06_Command_Reference/02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>) .

The context must have been defined on the firmware level (with the SQEC command), or as a SEQUENCER_CONTEXT_ITEM object. In the latter case this object must have been included in a SEQUENCER_CONTEXT object, and must also have been activated on the firmware level with the apply() function of this SEQUENCER_CONTEXT object. If the context has been defined as a SEQUENCER_CONTEXT_ITEM object, you must use the name specified for its name parameter.

 |

## Important points

- In order for this API (or an API that internally executes the FLUSH API) to reflect the changes that are specified by ROUTING_STATUS/ANALOG_STATUS to an analog module hardware, the sequencers in all analog modules must be halted. For more information, see the [FLUSH](<02.07.04.01.69_FLUSH.md>) API.
- NB_DIGITAL_CAPTURE_START and NB_DIGITAL_CAPTURE_END must be used as a pair.
- Non-blocking allows communication with analog instrumentation during a digital capture test.
- Used where test time is the most important consideration.
- May introduce digital noise that could interfere with sensitive digital tests.
- Before starting test execution, this API executes the FLUSH API internally to reflect the changes specified by the following APIs to the hardware of setup data:

  - ANALOG
  - ANALOG_STATUS
  - PRIMARY_STATUS
  - TIMING_SPEC / LEVEL_SPEC / SPECIFICATION
  - ROUTING_STATUS

- This API does not wait until the Digitizers/Samplers and TIAs finish the measurement. If you want to wait, use the WAIT_TEST_DONE API after this API as shown below:

```
...
...
NB_DIGITAL_CAPTURE_START();
...
...
NB_DIGITAL_CAPTURE_END(timeout);
...
...
WAIT_TEST_DONE(timeout);
```

## Example

The NB_DIGITAL_CAPTURE_START() API starts the test containing digital capture.

The following example utilizes optional pairs of curly brackets "{" and "}" for the "first-invocation block" and for the block enclosed by NB_DIGITAL_CAPTURE_START() `and `NB_DIGITAL_CAPTURE_END()`.` These optional curly brackets are used for simplifying the correct indentation with assistance of the related Eclipse tool.

```
ON_FIRST_INVOCATION_BEGIN();
{
    ...
    ...
    NB_DIGITAL_CAPTURE_START();
    {
        ...
        ...
    }
    NB_DIGITAL_CAPTURE_END(TM::WAIT_DIGITAL);
    ...
    ...
}
ON_FIRST_INVOCATION_END();
```
