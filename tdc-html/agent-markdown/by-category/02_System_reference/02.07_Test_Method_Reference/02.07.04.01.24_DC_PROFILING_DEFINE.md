# DC_PROFILING_DEFINE

The DC_PROFILING_DEFINE() API defines a DC profiling setup. The setup can be enabled later with DC_PROFILE_ENABLE().

On DC Scale DPS128/64 and UHC4T cards, profiling for multiport setups does not stop when the DPS part is finished. On these cards, profiling stops when the longest running port is finished. This gives the capability to profile the supply voltages/currents during the complete execution. In case you want to reduce memory consumption, you could put DPS pins into an empty port.

For the [DC Scale DPS128/DPS64 cards](<../02.05_Test_Head_Cards/02.05.05.01_DC_Scale_DPS128_DPS64_cards.md>), changing the current measurement range for profiling is not supported. That is, the measureRange parameter of the API is ignored when parameter measureType is set to TM::CURRENT. The profiling measurements are performed in the selected clamp current range.

 For [DC Scale XPS256 card](<../02.05_Test_Head_Cards/02.05.05.03_DC_Scale_XPS256_card.md>), changing the voltage range or the current range during profiling is supported, and the currently active range is also taken into account for profiling. The measureRange parameter is therefore not required for profiling and ignored, but still has to be set to a valid XPS256 range.

## Syntax

```
void DC_PROFILING_DEFINE( const STRING& pins,
    const TM::PHYSICAL_VALUE& measureType,
    DOUBLE measureRange,
    DOUBLE samplingInterval,
    INT oversampling = 1,
    const TM::DPS_MEAS_RANGE_MODE& keep_restore = TM::RESTORE_RANGE,
    const TM::MEASURE_RESOURCE& mea_res = TM::PMU );
```

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/DcProfiling.h.

  Parameters

These parameters are used by the current or voltage profiling measurement after the measurement, or to restore to the previously set range.

 | Parameter  | Description |
 | pins  | The STRING parameter specifies the pin names. Both pin lists and pin groups are supported. |
 | measureType  | The parameter of type TM::PHYSICAL_VALUE defines the measurement type. Possible values:

- TM::VOLTAGE
- TM::CURRENT
 |
 | measureRange  | The DOUBLE parameter defines the expected measurement value and the measurement range. The unit is either [V] or [A]. |
 | samplingInterval  | The DOUBLE parameter defines the sampling period in [s]. The minimum interval differs depending on the power supply card and number of channels:

 | DC Scale card  | Condition  | Max. rate  | Min. period |
 | DPS128  | 1  |   | channels per test processor[1)](<#_125001__d2708e223>) |

100 ksps

   | 0.010 ms |
 | 2 ... 8  | 50 ksps  | 0.020 ms |
 | UHC4T  | 1  |   | channels par card  | 100 ksps  | 0.010 ms |
 | 2 ... 4  | 50 ksps  | 0.020 ms |
 | XPS256  |    | 1 Msps  | 0.001 ms  | |
 | oversampling |

The optional integer number of measurements per sample.

- The number of measurements is internally corrected to a power of 2 number (2^n).
- For a sampling interval of 50渭s, to avoid skipped samples the max. number of measurements per sample is 4.

The default value is 1.

 |
 | keep_restore  | The optional parameter of type TM::DPS_MEAS_RANGE_MODE defines to keep or restore the measurement range. Possible values:

- TM::KEEP_RANGE
- TM::RESTORE_RANGE (default)
 |
 | mea_res  | The optional parameter of type TM::MEASURE_RESOURCE defines the measurement resource. Possible values:

- TM::PMU (default)
  |   Return value There is no return value.

## Examples

### Description

The examples below illustrate the use of the DC_PROFILING_... APIs.

### Example 1:

```
DC_PROFILING_ON("pin1", TM::CURRENT,100 uA, 100 ms, 16, TM::RESTORE_RANGE);
```

Defines and activates a current profiling setup for pin 1.

```
...
```

Execute test.

```
...
DC_PROFILING_OFF("pin1");
```

Disables the defined current profiling.

```
DC_RESULT_ACCESSOR resultAccessor;

resultAccessor.uploadResult("pin1", TM::RESULT_INDEX);

ARRAY_D results = resultAccessor.getValues("pin1");
```

Obtains the measured values.

### Example 2:

```
DC_PROFILING_DEFINE("pin1", TM::CURRENT,100 uA, 100 ms, 16, TM::RESTORE_RANGE);
```

Defines a current profiling setup for pin 1.

```
...
DC_PROFILING_ENABLE("pin1")
```

Enables the defined setup.

```
...
```

Execute test.

```
...
DC_PROFILING_OFF("pin1");
```

Disables the defined current profiling.

```
...
ARRAY_D values = GET_VALUE_RESULT("pin1"); ...
```

Obtains the measured values.

### Example 3:

This example shows how to use a DC_PROFILING_... API together with a functional test.

```
ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Define and activate the current profiling feature on dpsPin1
    //
    // NOTE:   No other measurement must be executed on dpsPin1
    //         as long the current profiling is activated
    //
    DC_PROFILING_ON("dpsPin1", TM::CURRENT,100 uA, 1 ms, 16, TM::RESTORE_RANGE);

    //
    // Execute a functional test on the digital pins
    //
    FUNCTIONAL_TEST();

    //
    // Deactivate the current profiling on dpsPIn1
    //
    DC_PROFILING_OFF("dpsPin1");
}
ON_FIRST_INVOCATION_END();

//
// Access the current profiling data
//
DC_RESULT_ACCESSOR resultAccessor;

resultAccessor.uploadResult("dpsPin1", TM::RESULT_INDEX);

ARRAY_D currentProfile = resultAccessor.getValues("dpsPin1");

std::cout << "Current profiling values on pin dpsPin1 : " << currentProfile << std::endl;

//
// Access the functional test result
//
Boolean result;

result = GET_FUNCTIONAL_RESULT("digitalPin1");

std::cout << "Result of the functional test on digitalPin1 : " << ( result ? "pass" : "fail" ) << std::endl;

//
// Datalog
//
TEST();
```
