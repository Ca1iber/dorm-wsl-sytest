# Code-based and pattern-based programming

Even if almost everything in a test method is programmed using the test method APIs, there are two fundamental differences in programming. With code鈥慴ased programming, the hardware is controlled directly from the workstation. With pattern鈥慴ased programming, the hardware is controlled by the pattern鈥憇equencer, which leads to stable timing.

Code鈥慴ased programming means that the programmed hardware is directly controlled by the workstation. This also applies if a test鈥憄rocessor is available.

Pattern鈥慴ased programming means that the programmed hardware is controlled by a pattern鈥憇equencer.

DC events can be defined by the [EVENT...](<02.07.04.01.63_EVENT_...__DC_events_API_reference.md>) test method APIs and inserted into an existing pattern using the [PATTERN_CONTROLLER](<02.07.04.01.142_PATTERN_CONTROLLER.md>) test method API or the [Pattern Editor](<../../03_Use_cases_and_application_papers/03.05_How_to_set_up_a_dynamic_DC_test/03.05.01.06_Defining_events_and_test_points_for_a_dynamic_DC_test.md>).
