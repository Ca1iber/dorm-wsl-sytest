# DC Test Methods, DC Sets, and Measurement Sets

#### Subtopics

- [DC set management](<02.07.03.02.06.01_DC_set_management.md>)
- [Using DC Sets Economically: DC Sets and Measurement Sets](<02.07.03.02.06.02_Using_DC_Sets_Economically__DC_Sets_and_Measurement_Sets.md>)
- [Managing DC Tests with Variable Parameters](<02.07.03.02.06.03_Managing_DC_Tests_with_Variable_Parameters.md>)
- [Note on cache management](<02.07.03.02.06.04_Note_on_cache_management.md>)

A DC test comprises two main parts,

- definition of the measurement parameters, and
- test execution with subsequent retrieval of the results.

Now suppose that a number of devices of the same type are tested with the same testflow in a loop, and that the testflow contains DC tests. If the testflow is not optimized, the measurement parameters of these tests will be defined anew for every repetition of the loop although they do not change and their definition and download is rather time consuming. This is remedied by the optimization, which ensures that the measurement parameters are defined only once, at the first execution of the testflow, and are then reused for the following loop repetitions.

Parallel result retrieval in a multi-site setting is also automatically implemented for DC test methods, but only for global PASS/FAIL results. Note that parallel setup and measurement for multi-site testing must be programmed by the user with the ON_FIRST_INVOCATION_BEGIN() and ON_FIRST_INVOCATION_END() API's.

As indicated, reuse of setup data is automated for DC test methods to a large extent. But there are limits to the reuse, and certain PPMU API's manage this reuse more economically than others. Therefore, the user must know the basics of the DC set management, and also understand the difference between DC sets and measurement sets. This will be explained in the following subsections.
