# SpecSearch

The Spec Search test method shifts specs defined in the equation-based test setup. These specs can be related to level or timing resources.

## Test method execution

In the execution of the test method, a spec is varied within a defined interval according to the specified search algorithm (linear, linear/binary or binary). After each variation of the spec a functional test is executed. This is repeated until a transition (pass/fail transition or fail/pass transition) has been detected. The last pass (fail) and first fail (pass) spec value is given back for the pass/fail (fail/pass) transition.

To shift the spec only for a subset of pins, the setupPinlist can be defined. The resultPinlist can also be defined so that only a subset of pins contributes to the pass/fail result of functional tests.

## Multi-site parallel test support

The test method allows shifting specs defined for DPS pins. It supports multi-site parallel test on Pin Scale test systems. But it does not support multi-site parallel spec search for specs related to period in binary/linbin search mode. (Switch off the allow parallel test suite flag when the spec search is for specs related to period in binary/linbin search mode.)

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

 |

Type

 |

Description

specName

 |

SpecVariable

 |

the spec to be shifted

For UTM, it is in the format of "type.equation_set_number.spec_name[unit]". For example, it can be "LEV.1.fooSpec[mV]" or "TIM.3.barSpec@port1[A]".

 |
 |

setupPinlist

 |

PinString

 |

(optional) The list of pins/pin groups the spec is shifted for. The pin type can be I, O, IO or DPS. If you omit an entry, the spec is shifted for all applicable pins.

 |
 |

method

 |

string

 |

the search method

It can be:

linear - linear search

lin/bin - linear/binary search

binary - binary search.

 |
 |

min

 |

double

 |

(optional) Start value of the spec to be shifted. If you omit an entry, the default minimum value defined in the spec set is used.

 |
 |

max

 |

double

 |

(optional) Stop value of the spec to be shifted. If you omit an entry, the default maximum value defined in the spec set is used.

 |
 |

step

 |

string

 |

(Optional) The step width of number or steps from min to max. This parameter is only needed for linear search and lin/bin search. Specify the number of steps in the format:

 # Number_Of_Steps

and the stepwidth in the format:

 Stepwidth

 |
 |

resolution

 |

string

 |

The resolution of the binary search. This entry is needed for binary search and lin/bin search. If you omit this entry the maximum resolution of the test system hardware is used.

 |
 |

resultPinlist

 |

PinString

 |

The list of pins/pin groups that contribute to the pass/fail result. The pin type can be IO or O.

 |
 |

output

 |

string

 |

Print out message or not. (ReportUI for debug mode or None for production mode)

 |
 |

testName

 |

string

 |

The test names to be used as limits. Default is SpecSearch_Test.

## Limit

 |

SpecSearch_Test

 |

It is only used to enter the test number input.

   | Note If you migrate this test method from previous TML versions to this version and test table is used in the device, you need to add the limit(s) in the test table manually to avoid the execution error. When the mix usage of test table limit and testflow limit in one testflow is supported, the manual adaption will not be needed.

## Implementation pseudo code

```
IF not already connected THEN
  connect DUT
ENDIF
clear the sequencer status with FW
set up search values
execute search with SEARCH_FUNC_TASK
retrieve and datalog the test result
```

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.5.0: Change the parameter type of specName to specVariable in UTM librabry.
- SmarTest 6.5.0: Change the parameter type of setupPinlist and resultPinlist to PinString in UTM library.
- SmarTest 7.0.3: Classic test method library is removed.
- SmarTest 7.0.3: New parameter testName.
- SmarTest 7.0.3: Parameter type of max and min is changed to DOUBLE.
- SmarTest 7.0.3: Test table is supported.
- SmarTest 7.1.1: Mixed usage of test table and testflow limits in one testflow is supported in TML 2.1.1.
