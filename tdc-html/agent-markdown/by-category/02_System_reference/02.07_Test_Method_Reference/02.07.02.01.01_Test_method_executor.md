# Test method executor

In universal test method, there are two test method executors (processes) that run the test method API based test method.

The first executor is used in testflow execution of production mode. It can also be used in test method debugging. The UTM Debugger always attaches and debugs the first UTM executor. When you execute a UTM-based testflow, the first UTM executor is started if it is not running yet. The executor will not be terminated after the testflow execution. As a result, if there are any global or static variables used in UTM programming, they will not be re-initialized next time you run the testflow. To update those global variables at the beginning of running a testflow every time, you can insert an initialize or a download special test suite to the testflow. In the special test suite, you can use a test method to re-initialize or update those global variables or objects accordingly.

The second executor is used for test engineering purposes. When a testflow execution is blocked by UTM debugger which runs to a certain breakpoint, if you want to execute a single test suite or run the Shmoo Tool, the second test method executor needs be used. If the test method executed in the second executor uses global or static variables impacted by the test methods executed in the first executor, you need to pay attention to the variables or objects which will not get auto-synchronized. You can re-run certain dependent test suites to update them again in the second executor, or choose to use shared memory. Using shared memory is time consuming but more robust and can even get recovered when the executor crashes unexpectedly. In Window > Preferences > Advantest V93000 > Testflow Tool, there is an option Execute selected UTM Test Method as separate process (to avoid blocking). (See [Testflow Tool preference page](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.14.30_Testflow_Tool_preference_page.md>).) To use the second executor, check this option. Otherwise, the first executor is used by default.

To terminate a test method executor, in SmarTest Eclipse Workcenter you can click Run > Terminate Test Method Execution or you can click Project > Build All. You can also terminate both executors from command line with `$ /opt/hp93000/soc/testmethod/bin/tmm_console -e stopAll`.

## Functional changes

- Introduced in SmarTest 6.5.0
- SmarTest 6.5.3: Default executor for single execution is changed to the first executor.
- SmarTest 6.5.3: Option to select the UTM executor is changed to Execute selected UTM Test Method as separate process (to avoid blocking).
