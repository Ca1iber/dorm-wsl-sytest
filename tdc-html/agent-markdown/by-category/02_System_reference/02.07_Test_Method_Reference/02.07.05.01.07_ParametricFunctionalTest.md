# ParametricFunctionalTest

The parametric functional test is a combination of two test methods:

- a functional test that can be customized
- a spec search

Both tests can be executed separately or together in a combined test.

## Customized functional test

To execute only a customized functional test, omit all entries for spec search. The functional test can be customized in three respects:

- You can stop at a specified vector (or cycle) before the end of the pattern.

This can be used to reduce the test time. If the same pattern must be executed several times up to different vectors or cycles to drive the DUT into different states, this can be done with the same pattern. No copies of this pattern need to be generated. This saves vector memory and simplifies tracking of changes needed in the pattern.

- You can exclude a start or end segment of the pattern from contributing to the overall test result.
- You can mask selected pins so that they do not contribute to the overall test result.

By combining all three options you can investigate the behavior of a subset of the pins in a certain vector (cycle) region, as illustrated in the following figure:

 ![Analyzing a part of the pattern](<../../../../raw/93681.png>)

In this example only the results in the marked rectangle contribute to the test result. The first five vectors are masked, vectors 9 and 10 are masked, the test is stopped at vector 10. Vectors 6 through 8 are only evaluated for 4 of the 12 pins.

## Spec search

To execute only a spec search, omit all entries for the functional test.This is identical with [SpecSearch](<02.07.05.01.10_SpecSearch.md>).

## Combined test

If executed together, the spec search shifts the specs and then run a customized functional test. This way you can gather characterization data for a specific section of the pattern in a spec search.

In contrast to the test function, the test method allows shifting specs defined for DPS pins. It supports multi-site parallel test on Pin Scale test systems. But it does not support multi-site parallel spec search for specs related to period and using binary/linbin search mode. (Switch off the allow parallel test suite flag when the spec search is for specs related to period and using binary/linbin search mode.)

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

## Implementation pseudo code

```
IF not already connected THEN
 connect DUT
ENDIF
clear sequencer status
IF pure functional test THEN
 store mask status
 set mask status with specified values
 execute functional test
ELSE
 store mask status
 set mask status with specified values
 customize search settings with specified values
 IF PinScale test system THEN
 execute spec search with SEARCH_FUNC_TASK
 ELSE
 execute spec search with SPEC_SEARCH
 ENDIF
 retrieve test result
 restore original mask status
ENDIF
datalog test results
IF pure functional test and mask mode is set THEN
 restore original mask status
ENDIF
```

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.5.0: Change the parameter type of setupPinlist and resultPinlist to PinString in UTM library.
- SmarTest 7.0.3: Classic test method library is removed.
- SmarTest 7.0.3: New parameter testName
- SmarTest 7.0.3: Parameter type of start, stop, passMin and passMax is changed to DOUBLE.
- SmarTest 7.0.3: Test table is supported.
- SmarTest 7.1.1: Mixed usage of test table and testflow limits in one testflow is supported in TML 2.1.1.
