# TRANSITION_TEST_SET

#### Subtopics

- [TRANSITION_TEST_PINS](<02.07.04.01.257.01_TRANSITION_TEST_PINS.md>)

The `TRANSITION_TEST_SET` class is a container representing a transition set. A transition set contains the settings of one or multiple transition test features. The associated target pins for transition test features will be specified via this class.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TransitionTestSet.h.

## Class definition

### Constructor

```
TRANSITION_TEST_SET(const STRING & setName,TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
TRANSITION_TEST_SET(const STRING & setName,const STRING& modeContext);
TRANSITION_TEST_SET (TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
```

### Member functions

```
TRANSITION_TEST_PINS& pin(const STRING& pinList);
void setAsPrimary();
void remove();
```

### Class functions

```
static void & setDefaultAsPrimary();
static const STRING& getPrimarySet();
static void getListofSets(STRING_VECTOR & setNames);
```

### Constructor

```
TRANSITION_TEST_SET(const STRING & setName,TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
TRANSITION_TEST_SET(const STRING & setName,const STRING& modeContext);
TRANSITION_TEST_SET (TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
```

It constructs an object of `TRANSITION_TEST_SET` with the specified transition test set and the specified context. If the specified transition set does not exist, it will be automatically created. If the specified set exists, but the context is different, the specified set will be created again. The number of sets is limited by hardware. If the transition set cannot be created, an exception will be issued.

Parameters
 |

setName

 |

The transition set name. If not specified, the DEFAULT transition test set is used.

 |
 |

modeContext

 |

The name of the [context](<../02.06_Command_Reference/02.06.03.01.03.01_Mode_contexts.md>) name for which the set will be created.

 |
 |

ctxt

 |

The [context](<../02.06_Command_Reference/02.06.03.01.03.01_Mode_contexts.md>) for which the set will be created. It can be:

- TESTMETHOD_API::TMAPI_DEFAULT: The default context
- TESTMETHOD_API::TMAPI_CURR: The context of the current primary sets (default)
- TESTMETHOD_API::TMAPI_PRM: Synonymous with TMAPI_CURR.
 |

## Member functions

The member functions are executed from an object of the TRANSITION_TEST_SET API.

### pin()

```
TRANSITION_TEST_PINS& pin(const STRING& pinList);
```

This function returns a reference to a `TRANSITION_TEST_PINS` object which represents the transition test features. It defines the pins for which the respective transition test settings will be done by calling the member functions of `TRANSITION_TEST_PINS`.

Parameter
 |

pinList

 |

The pins to work with.

 |

### setAsPrimary()

```
void setAsPrimary();
```

This function defines the current transition test set as primary. The primary transition set will be activated before the next start sequencer. This function calls the [TTPR](<../02.06_Command_Reference/02.06.02.02.290_TTPR__TTPR__-__Transition_Test_PRimary_set.md>) firmware command. See also [How to set up and execute a protocol engine test](<../02.06_Command_Reference/02.06.15.02_How_to_set_up_and_execute_a_protocol_engine_test.md>).

### remove()

```
void remove();
```

This function removes a transition test set from the firmware. The method calls the [TTUD](<../02.06_Command_Reference/02.06.02.02.293_TTUD_-__Transition_Test_UnDefine.md>) firmware command. It makes transition test set invalid and calling other functions after it will cause an exception.

## Class functions

The following three functions are class functions. They Do not relate to a specific object of a transition test set. You can use them without a TRANSITION_TEST_SET object.

### setDefaultAsPrimary()

```
static void & setDefaultAsPrimary();
```

This function sets the predefined transition set DEFAULT as the primary set. The configuration of the DEFAULT set cannot be changed but it can be queried with the firmware query [TTCF?](<../02.06_Command_Reference/02.06.02.02.286_TTCF__TTCF__-__Transition_Test_ConFiguration.md>).

### getPrimarySet()

```
static const STRING& getPrimarySet();
```

This function returns the name of the current primary transition test set. If the default set is primary, it will return an empty string.

### getListofSets()

```
static void getListofSets(STRING_VECTOR & setNames);
```

This function returns the list of the defined transition test sets by executing a [TTDF?](<../02.06_Command_Reference/02.06.02.02.288_TTDF__TTDF__-__Transition_Test_set_DeFinition.md>) query.

## Example

```
TRANSITION_TEST_SET myTTSet("TTSetExample");

myTTSet.pin("I/O0,I/O1,I/O2")
       .tokenSize(10)
       .firstInitialSyncMode(true).trackingMode(TRANSITION_TEST::FREEZE_ALWAYS);

myTTSet.setAsPrimary();    // set this set as primary

// execute first functional test (tracker is freezed)
START_TEST();
WAIT_TEST_DONE();
TEST();

//query transition status
TRANSITION_TEST_STATUS ttStatusObj= TRANSITION_TEST_STATUS("I/O0");
unsigned int statusBits;
unsigned int interuptStatusBits;
ttStatusObj.getStatus(statusBits,interuptStatusBits);
if (statusBits)
{
  cerr<<  "transitionError occurred";
}

// modify TT parameters , activate tracker
myTTSet.pin("I/O0,I/O1,I/O2").trackingMode(TRANSITION_TEST::ACTIVE);
 ...
// execute second functional test
START_TEST();
WAIT_TEST_DONE();
TEST();

// set Default setting as primary
TRANSITION_TEST_SET::setDefaultAsPrimary();
// query some configuration data
try
{
  INT tokenSize=myTTSet.pin("I/O1,I/O2").getTokenSize();
}
catch(TESTMETHOD_API::AmbiguityException e)
{
  // .. query the tokenSize on a per pin base
  INT tokenSize2=myTTSet.pin("I/O1").getTokenSize();
  INT tokenSize3=myTTSet.pin("I/O2").getTokenSize();
}

// set default values (for pin1)
myTTSet.pin("I/O0").setToDefault();

// dump configuration of set to stream
cout << myTTSet;

START_TEST();
WAIT_TEST_DONE();
TEST();

// remove this set from SW
myTTSet.remove();
```
