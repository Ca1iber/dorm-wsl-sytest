# Parallel Search and Search Set Management

#### Subtopics

- [Reusing Search Conditions](<02.07.03.03.08.01.01_Reusing_Search_Conditions.md>)
- [Managing Search Conditions with Variables](<02.07.03.03.08.01.02_Managing_Search_Conditions_with_Variables.md>)
- [Note on cache management](<02.07.03.03.08.01.03_Note_on_cache_management.md>)

The SEARCH_FUNC_TASK and the SEARCH_FUNC_PIN_TASK API serve to execute different spec variable or edge searches in parallel. The conditions for one parallel search are stored in a so-called search set. A search set can contain only one search condition for any combination of pin and site.

The SEARCH_FUNC_TASK API contains a mechanism that avoids repeated downloading of the same conditions for consecutive executions of a parallel search within a testflow loop (see [Reusing Search Conditions](<02.07.03.03.08.01.01_Reusing_Search_Conditions.md>)). A basic knowledge of this mechanism is required for effective coding of search conditions that use variables (see [Managing Search Conditions with Variables](<02.07.03.03.08.01.02_Managing_Search_Conditions_with_Variables.md>)).

The management of search sets is similar to the DC set management in optimized test flows.
