# Sharing Channels Between Several Sites

The standard application of the FOR_EACH_SITE block is to create a different setup for different sites within an ON_FIRST_INVOCATION block. The actual measurements are performed in parallel after closing the FOR_EACH_SITE block.

This is not possible if you associate a pin with the same channel on more than one site. For in this case the setup data for the different sites are stored at the same location in the same measurement sets, so that the settings for the subsequent site will overwrite those of the previous one. Therefore the measurements must be executed immediately after downloading the setup data. Accordingly, if the setups of the sites that share a channel are different, and if you still want to execute the measurement inside an ON_FIRST_INVOCATION block, then not only the download of the settings, but also the measurements based on these settings must be executed within the FOR_EACH_SITE block.

## Example

The following code fragment gives an example:

```
PPMU_MEASURE m1;

ON_FIRST_INVOCATION_BEGIN();
{
    PPMU_SETTING s1;
    PPMU_RELAY r1;
    TASK_LIST t1;

    s1.pin("IN1").iRange("100uA");
    s1.pin("IN1").iForce(100 uA).min(50 mV).max(100 mV);

    r1.pin("IN1").status("PPMU_ON");

    m1.pin("IN1").execMode("GPF");

    t1.add(s1).add(r1).add(m1);
    t1.setup();

    FOR_EACH_SITE_BEGIN();
    {
        DOUBLE var = rand() % 6;

        s1.pin("IN1").min(var/1000 V).max((var+1)/1000 V);

        t1.execute(); // Execute measurements within the FOR_EACH_SITE block
    }
    FOR_EACH_SITE_END();
}
ON_FIRST_INVOCATION_END();

Boolean pf = m1.getPassFail();
```

In this example, pin IN1 is supposed to be associated with the same channel on all sites. The example uses the rand() function to assign different values to the variable var in offline mode for every repetition of the FOR_EACH_SITE loop. In practice, the value of the variable will usually be determined by a previous measurement.
