# PPMU_RELAY

#### Subtopics

- [PPMU_PIN_RELAY](<02.07.04.01.158.01_PPMU_PIN_RELAY.md>)

The PPMU_RELAY class is a data container holding the contents of the task for setting up relay connections of pin PMUs. This class can be used to call the [PPMU_PIN_RELAY](<02.07.04.01.158.01_PPMU_PIN_RELAY.md>) class that is a subsidiary data container to specify the target relay type of the pin.

For releases up to 6.5.3 and of the 7.0 stream, to execute tasks defined with this class, you had to use the execute member function of the [TASK_LIST](<02.07.04.01.240_TASK_LIST.md>) class. With the releases 6.5.4, 7.1.0 and later, tasks defined with this class can also be executed directly.

PPMU_RELAY does not support pins in HV mode.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PpmuRelay.h.

## Class definition

Constructor:

```
PPMU_RELAY();
```

Member Functions:

```
PPMU_PIN_RELAY & pin(const STRING& pinlist);
wait(const DOUBLE time);
void syncWait(DOUBLE time);
```

## Syntax

For creating an object:

```
PPMU_RELAY <object>;
```

Note Do not create static objects of the class in the test method and do not create test method member variables from this class.

For setting up relay connections:

```
<object>.pin("pinlist").<member_func>;
```

For setting a wait time from when the execution of the task defined with the PPMU_RELAY is started:

```
<object>.wait(time);
```

 |

<object>

 |

Object name to be defined

 |
 |

pinlist

 |

Target pin name or pin group name of this class. You can specify multiple pins and pin groups by separating with a comma or using "@" which means the all PPMU pins. "@" includes the digital pins that is wired to an analog module on the DUT board for a trigger source.

 |
 |

<member_func>

 |

Member functions of the PPMU_PIN_RELAY class to control the relay

 |
 |

time

 |

Waiting time

 |

The next task execution will be started after the wait time.

## Constructor

### PPMU_RELAY

PPMU_RELAY();

This constructor defines a task that is a set of relay operations.

Parameters

There are no parameters associated with this function.

## Member functions

### pin()

```
PPMU_PIN_RELAY & pin(const STRING& pinlist);
```

This function returns the reference to the [PPMU_PIN_RELAY](<02.07.04.01.158.01_PPMU_PIN_RELAY.md>) class object that represents the relay operations for the specified pin. To add an action to the task, use the member functions of the [PPMU_PIN_RELAY](<02.07.04.01.158.01_PPMU_PIN_RELAY.md>) class.

Parameter
 |

pinlist

 |

Target pin name or pin group name of this class. You can specify multiple pins and pin groups by separating with a comma or using "@" which means the all PPMU pins. "@" includes the digital pins that is wired to an analog module on the DUT board for a trigger source.

 |

### wait()

```
void wait(const DOUBLE time);
```

For setting a wait time from when the execution of the task defined with the PPMU_RELAY is started.

Parameter
 |

time

 |

Wait time for the task. The default unit is [s].

   | Note It takes 0.3 ms to open or close relays. Further, it takes 1 ms as a settling time of PMUs after closing relays. Therefore, you must set at least 1.3 ms (for closing relays) or 0.3 ms (for opening relays) with the wait member function.

### syncWait()

```
void syncWait(DOUBLE time);
```

This function sets the waiting time for the sequencers before the execution of the measurement.

Parameter
 |

time

 |

The time to wait. Default unit is [s]. The time usually needs to be set as the value euqaling to `period*250`.

 |

## Examples

### Generic example

```
PPMU_SETTING   ppmuSetting;
PPMU_RELAY     ppmuRelay_on, ppmuRelay_off;
PPMU_MEASURE   ppmuMeasure;
PPMU_CLAMP     ppmuClamp_on, ppmuClamp_off;
TASK_LIST      taskList_1;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Setups for PPMU
    //
    ppmuSetting.pin("S0").iRange(1 mA).min(0 V).max(4.3 V).iForce(10 uA);
    ppmuSetting.pin("S1").iRange(10 mA).min(-10 uA).max(30 uA).vForce(3.3 V);

    //
    // Relay setups
    //
    ppmuRelay_on.pin("S0,S1").status("PPMU_ON");
    ppmuRelay_on.wait(1.3 ms);
    ppmuRelay_off.pin("S0,S1").status("AC_ON");

    //
    // Measurement setups
    //
    ppmuMeasure.pin("S0,S1").execMode(TM::PVAL);

    //
    // Hardware specific programming to avoid hot switching on the current force setup
    //
    ppmuClamp_on.pin("S0").status("CLAMP_ON").low(2.6 V).high(2.9 V);
    ppmuClamp_off.pin("S0").status("CLAMP_OFF");

    //
    // Build and execute the task list
    //
    taskList_1.add(ppmuSetting)
              .add(ppmuClamp_on)
              .add(ppmuRelay_on)
              .add(ppmuClamp_off)
              .add(ppmuMeasure)
              .add(ppmuRelay_off);

    taskList_1.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and Datalog
//
double VMeas, IMeas;

VMeas = ppmuMeasure.getValue("S0");
IMeas = ppmuMeasure.getValue("S1");

TEST("DC_Test",ppmuMeasure, true);
```

In this example, an PPMU IFVM test on pin `S0` and a PPMU VFIM test on pin `S1` are performed in parallel. Before the measurement, the PPMU relays of these two pins are switched on and the AC relays are switched off. 1.3 ms is waited before other settings are done. After the measurement, the PPMU relays are switched off and the AC relays are switched on.

### Direct execution without TASK_LIST

```
PPMU_RELAY relay;

ON_FIRST_INVOCATION_BEGIN();
   relay.pin("Q0").status("PPMU_ON");
   relay.execute();
ON_FIRST_INVOCATION_END();
```

This switches the relay permanently to PPMU_ON. The `setting` is defined and directly executed, without using a TASK_LIST.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.0.1: New member function syncWait()
- SmarTest 6.5.4: PPMU_RELAY tasks can be executed directly without TASK_LIST. Also supported in 7.1.0 and later, not supported in 7.0.n releases.
