# DIGITAL_OFFSET_SEARCH_PINS.uploadOffset()

Executes the [TORS?](<../02.06_Command_Reference/02.06.02.02.265_TORS__-__Timing_level_Offset_ReSult.md>) firmware command to upload the offset for the middle of the pass area from the tester to the system controller.

Later on, you can read out this offset value with [DIGITAL_OFFSET_SEARCH_PINS.getOffset()](<02.07.04.01.36.01.08_DIGITAL_OFFSET_SEARCH_PINS.getOffset.md>).

If you retrieve the offset on multiple pins and those pins have different settings, the exception TESTMETHOD_API::AmbiguityException will be issued.

## Syntax

```
void uploadOffset(SetSelector &selector, RESOURCE_TYPE resource) throws TMExcption;
```

Parameters
 |

Parameter

 |

Description

 |
 |

selector

 |

It can be:

- A TimingSetSelector object defined with the [TimingSetSelector](<02.07.04.02.17_TimingSetSelector.md>) class, to select timing sets. Or,
- A LevelSetSelector object defined with the [LevelSetSelector](<02.07.04.01.123_LevelSetSelector.md>) class, to select level sets.
 |
 |

resource

 |

It can be a timing resource or a level resource whose offset you want to upload. Choose a timing or level resource for the timing or level selector accordingly. Otherwise, an exception will be thrown.

For the resource types, see the following table.

## Example

```
STRING strpins("pcie_rx1n");
DIGITAL_OFFSET_SEARCH_TASK dos;

dos.pin(strpins)
        .resourceType(DIGITAL_OFFSET_SEARCH::VIH)
        .searchType(DIGITAL_OFFSET_SEARCH::EYE)
        .start(15 mV)
        .numSteps(120)
        .stepWidth(15 mV)
        .restoreFlag(DIGITAL_OFFSET_SEARCH::NO);

dos.execute();

DIGITAL_OFFSET_SEARCH::LevelSetSelector dest(DIGITAL_OFFSET_SEARCH::ALL);

dos.pin(strpins).uploadOffset(dest, DIGITAL_OFFSET_SEARCH::VIH);
```
