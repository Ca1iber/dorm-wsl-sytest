# rdi.hiddenUpload()

Enables or disables the hidden upload for the specified type of measurement in the following RDI blocks.

## Syntax

```
void hiddenUpload(TA::MEAS_TYPE type);
```

  Parameters

 | Parameter  | Description |
 | type  | The type of measurement. |

List of available options of parameter: TA::MEAS_TYPE type
 | Option  | Description |
 | TA::ALL  | Enables the hidden upload for all the supported measurements. |
 | TA::NO  | Disables the hidden upload. |
 | TA::ANA  | Enables the hidden upload for the RF measurement and the measurement with digitizer. |
 | TA::DIGCAP  | Enables the hidden upload for the digital capture test. |
 | TA::DC  | Enables the hidden upload for the DC (DC Scale and digital DC) measurement. |
 | TA::EMAP  | Enables the hidden upload for the error map. |
 | TA::TMU  | Enables the hidden upload for the TMU measurement.  |  Note Do NOT change the measurement type for hidden upload in each execution, for example,

```
static int runtime = 0;
                                       if(runtime%2)
                                       {
                                           rdi.hiddenUpload(TA::ALL);
                                       }
                                       else

                                           rdi.hiddenUpload(TA::NO); // This is not allowed.
                                       }
                                       runtime++;
```

  Return value There is no return value. Using the API The API can be accessed only from the SmartRDI base class:

```
rdi.hiddenUpload(type);
```

The mandatory parameter type must be defined as enum of the type [TA::MEAS_TYPE](<02.07.13.08.19.02.03_rdi.hiddenUpload.md#_144748__t_TA_MEAS_TYPE>).

Some more rules:

- Use function hiddenUpload() before the first [RDI block](<02.07.13.05_Code_structure_with_SmartRDI.md#_142604__dle_RDI_block>) that should uses hidden uploads.
- hiddenUpload() cannot be used within an RDI block.
- A single call of hiddenUpload() applies to all following RDI blocks within the run() function of a test suite.
- Additional calls of the function are supported if multiple RDI blocks are defined within the run() function. In this case, the selected type of measurement can be changed between the individual RDI blocks.

## Application notes

  Combination of SMC_DISABLE() & rdi.hiddenUpload() (SmartRDI version 2.4.4. or lower)

With SmartRDI 2.4.4 or lower versions, the combination of `SMC_DISABLE(true);` and `rdi.hiddenUpload(TA:ALL);` is not supported and will cause an error.

From SmartRDI 2.4.5, `SMC_DISABLE(true)` can be combined with `rdi.hiddenUpload(TA::ALL)`. This helps to simplify the test method code. To execute all processes at the foreground, only `SMC_DISABLE()` needs to be managed. Multibins must be specified (SmarTest versions below 7.3.4.1 and 7.4.1.0) You must specify multibins if you use SMC. This constraint only applies to SmarTest versions below 7.3.4.1 and 7.4.1.0.

## Examples

### Example 1: Hidden upload as thread per site

The following example shows how to implement a hidden upload for a TMU[1)](<#_144748__fn1>) measurement. For SmartRDI, the code for uploading the result in the background is the same as for a test without hidden upload except that one or more background processes are armed and the results are retrieved in the background.

The example is implemented as [thread per site](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>). This means, that [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) is started outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block and arms an independent background process for each active site.

The site that is processed in each of the created [background process](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) is defined by the site that was active when SMC_ARM() has armed the background process.

```
virtual void run()
{
    RDI_INIT();

    ON_FIRST_INVOCATION_BEGIN();

        rdi.hiddenUpload(TA::ALL);

        RDI_BEGIN();

            rdi.tmu("id").pin("AVI64")
                .measMode(TA::RISE_TIME)
                .vth(1,1.5)
                .samples(20)
                .execute();

        RDI_END();

    ON_FIRST_INVOCATION_END();

    SMC_ARM();

    return;
}

public:

void SMC_backgroundProcessing()
{
    ARRAY_D timStamps = rdi.id("id").getStamp();
}
```

### Example 2: Hidden upload as common thread

The following example shows how to implement a hidden upload for a TMU[1)](<#_144748__fn1>) measurement. For SmartRDI, the code for uploading the result in the background is the same as for a test without hidden upload except that one or more background processes are armed and the results are retrieved in the background.

The example is implemented as [common thread](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>). This means, that [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) is started intside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block and arms only one background process for the current test suite.

The sites to be processed in the background process must explicitly be defined. This is done by creating the integer array sites that holds the numbers of active sites only. A copy of this array is transferred to the [background process](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>). The background process must parse this array and process only the defined sites.

```
virtual void run()
{
    ARRAY_I sites;

    RDI_INIT();

    GET_ACTIVE_SITES(sites);

    ON_FIRST_INVOCATION_BEGIN();

        rdi.hiddenUpload(TA::ALL);

        RDI_BEGIN();

            rdi.tmu("id2").pin("AVI64")
                .measMode(TA::RISE_TIME)
                .vth(1,1.5)
                .samples(20)
                .execute();

        RDI_END();

        SMC_ARM(sites);

    ON_FIRST_INVOCATION_END();

    return;
}

public:

void SMC_backgroundProcessing(ARRAY_I sites)
{
    for(int i = 0; i < sites.size(); i++)
    {
        ARRAY_D timeStamps = rdi.site(sites[i]).id("id2").getStamp();
    }
}
```

## Functional changes

- Introduced in SmartRDI 2.1.0
- SmartRDI 2.3.1: A new option TA::TMU for digital TMU measurements.
- SmartRDI 2.4.2: A new option TA::EMAP for error map hidden upload.
- SmartRDI 2.4.4: Supports the new API for PVI8/AVI64 hidden upload (SMT 7.4.1); supports the new API for common thread upload of TMU results (SMT 7.4.1).
- SmartRDI 2.4.5: Combined use of SMC_DISABLE(true) with rdi.hiddenUpload(TA::ALL) no more reports an error.
[1)](<>) Hidden upload of TMU results for AVI64 and PVI8 is supported with SmarTest 7.4.1 / SmartRDI 2.4.4 and higher.
