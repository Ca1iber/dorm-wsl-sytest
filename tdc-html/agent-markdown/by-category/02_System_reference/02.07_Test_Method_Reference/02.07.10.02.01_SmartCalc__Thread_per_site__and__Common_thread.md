# SmartCalc "Thread per site" and "Common thread"

#### Subtopics

- [SmartCalc thread per site example](<02.07.10.02.01.01_SmartCalc_thread_per_site_example.md>)
- [SmartCalc common thread example](<02.07.10.02.01.02_SmartCalc_common_thread_example.md>)

SmartCalc (SMC) uses multi thread capabilities of the system controller for minimizing the test time. Setting up multi threading is supported as separate thread per site or as common thread for all sites that is also known as single thread.

 Each call of function [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) and the similar functions [SMC_ARM_OTHER_TS()](<02.07.04.01.231.03_SMC_ARM_OTHER_TS.md>), [SMC_ARM_FOR_SITES()](<02.07.04.01.231.02_SMC_ARM_FOR_SITES.md>) and [SMC_ARM_OTHER_TS_FOR_SITES()](<02.07.04.01.231.04_SMC_ARM_OTHER_TS_FOR_SITES.md>) creates a new thread. The performed actions of this thread is to be defined by function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) of the related test method.

Multi-core CPUs are able to perform several of these threads in parallel. This feature will minimize the test time as long as the overhead for calling functions and the handling of threads does not exceed the time gained by the parallel execution: Each function call and each thread creates some time overhead for preparation and cleanup. The overhead depends also on the ratio of function calls and threads and the number of available CPU cores. The overhead will significantly increase for a thread per site configuration on high-site-count applications with low number of available CPU cores.

The SmartCalc framwork allows therefore defining the background processes in two different ways:

- The "Thread per site" is armed outside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block.
- The "Common thread" (or "single thread") is armed inside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block.
