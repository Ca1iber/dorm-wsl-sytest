# SMC_DISABLE()

Disables the whole SmartCalc feature so that neither hidden upload nor background calculation take place. This is used for debugging purposes to execute parts of a test program without the SMC framework without the need of changing the existing functions calls.

This status will be active until `SMC_DISABLE()`will be set to false.

SmarTest still evaluates [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) statements during [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) with synchImmediately set to false. Thus, [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) must be called even if SmartCalc is disabled.

With synchImmediately set to true, [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) can be omitted. However you need to make sure that [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) calls are outside the `ON_FIRST_INVOCATION` block, because no data log statements can be executed inside that block.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.

## Syntax

```
void SMC_DISABLE(Boolean value);
void SMC_DISABLE(Boolean value, Boolean synchImmediately);
```

Parameters
 |

Parameter

 |

Description/Range

 |
 |

value

 |

true: SmartCalc is disabled.

false: SmartCalc is enabled.

 |
 |

synchImmediately

 |

true: SmartCalc immediately executes the [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) statements at the end of your SMC_backgroundProcessing() method without waiting for the next [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) call.

 Note [TESTSET().judgeAndLog_ParametricTest()](<02.07.04.01.244.10_TESTSET__.judgeAndLog_ParametricTest.md>) uses [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) internally if [Hidden data logging](<02.07.10.04.09_Hidden_data_logging.md>) is disabled. |

Return value

There is no return value.
