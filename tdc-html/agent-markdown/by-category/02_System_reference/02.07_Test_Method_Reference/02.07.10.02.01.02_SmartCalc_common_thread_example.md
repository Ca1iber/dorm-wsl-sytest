# SmartCalc common thread example

A common SMC thread requires the implementation of SMC_ARM() inside of the ON_FIRST_INVOCATION block. The thread is created once for all sites. Site handling within the thread requires the transfer of an array that holds all active sites.

The following example shows how a common thread is created: Function [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) is called inside of the [ON_FIRST_INVOCATION](<02.07.04.01.138_ON_FIRST_INVOCATION_BEGIN.md>) block. Function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) is therefore started only once in a separate thread.

 Some items to consider for the example:

- Data are transferred to the SMC_backgroundProcessing() function by member variables mTestData and mActiveSitesArray. This is the recommend solution for large amount of data to minimize the test time. If only a few data are to be transferred, you can transfer the data as parameter of SMC_ARM() as shown in the [SmartCalc thread per site example](<02.07.10.02.01.01_SmartCalc_thread_per_site_example.md>). You can also implement a combination of both methods.
- The example shows only how to create common thread and contains therefore no real test code.
- Some dummy data are created using the std::rand() function. These data are for demonstration only and need not to be created or processed in a real test method.
- There are also some dummy wait times created using the std::rand() function. These wait times should emulate the time for processing data, are for demonstration only and need not to be implemented in a real test method.

```
#include "testmethod.hpp"
#include "mapi.hpp"

using namespace std;

class commonThread: public testmethod::TestMethod {

protected:

    ARRAY_D mTestData;
    ARRAY_I mActiveSitesArray;

    virtual void initialize()
    {
    }

    virtual void run()
    {
        ON_FIRST_INVOCATION_BEGIN();
        {
            //
            // Initialize an array of dummy data
            //
            ARRAY_I configuredSitesArray;

            mTestData.resize    (GET_CONFIGURED_SITES(configuredSitesArray));
            mTestData.init      (-1.0);

            //
            // Start your test in on all active sites
            //
            // ...
            // ...

            //
            // Set the dummy data to be transferred to the background process
            //
            FOR_EACH_SITE_BEGIN()
            {
                mTestData[CURRENT_SITE_NUMBER()-1] =  1.0 * std::rand()/RAND_MAX;
            }
            FOR_EACH_SITE_END();

            //
            // Show the dummy data
            //
            cout << "Testsuite: run() - Data array:";

            for (int index = 0; index < mTestData.size(); index++)
            {
                cout << "  " << mTestData[index];
            }

            cout << endl;

            //
            // Get and show active sites
            //
            GET_ACTIVE_SITES(mActiveSitesArray);

            cout << "Testsuite: run() - Active sites:";

            for (int index = 0; index < mActiveSitesArray.size(); index++)
            {
                cout << " " << mActiveSitesArray[index];
            }

            cout << endl;

            //
            // Arm the SMC_backgroundProcessing() method
            //
            // Note: Data are transferred by member variables mTestData[] and mActiveSitesArray[].
            //
            SMC_ARM();
        }
        ON_FIRST_INVOCATION_END();

        return;

    } // virtual void run()

public:

    void SMC_backgroundProcessing()
    {
        //
        // Process the test data array for all active sites
        //
        for (int index = 0; index < mActiveSitesArray.size(); index++)
        {
            //
            // Wait time emulates time for processing
            //
            WAIT_TIME (50.0 ms * std::rand()/RAND_MAX);

            //
            // Show processed site and data
            //
            double result = mTestData[mActiveSitesArray[index] - 1];

            cout << setw(45) << "" << "Common thread, site " << mActiveSitesArray[index] << " - Result = " << result << endl;
        }

    } // void SMC_backgroundProcessing ...

}; // class commonThread

REGISTER_TESTMETHOD("commonThread", commonThread);
```

 Note

The example above contains a call of cout in function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to [Thread safety](<02.07.10.02.02_Thread_safety.md>).

 For a test program with eight configured sites and site 4 and 7 disabled, the code above results in an output in the ui_report window similar to the following text:

```
Testsuite: run() - Data array:  0.619596  0.281059  0.786002  -1  0.307458  0.447034  -1  0.226107
Testsuite: run() - Active sites: 1 2 3 5 6 8
Testsuite: Common_thread PASSED on site 1
                                             Common thread, site 1 - Result = 0.619596
Testsuite: Common_thread PASSED on site 2
Testsuite: Common_thread PASSED on site 3
Testsuite: Common_thread PASSED on site 5
                                             Common thread, site 2 - Result = 0.281059
Testsuite: Common_thread PASSED on site 6
Testsuite: Common_thread PASSED on site 8
                                             Common thread, site 3 - Result = 0.786002
                                             Common thread, site 5 - Result = 0.307458
                                             Common thread, site 6 - Result = 0.447034
                                             Common thread, site 8 - Result = 0.226107
```

The output in the ui_report shows the following behavior of the example code:

- The result array is defined for all configured sites with the values of currently deactivated sites set to -1. The transferred array of active sites enables the SMC_backgroundProcessing() function of the common thread to process only the active sites: Only valid dummy data (> 0.0) are processed and shown in the thread.
- The common thread runs independently from the further execution of the run() function: Due to the (emulated and variable) time for processing, sites 1 and 2 are processed while run() is invoked for site 1 …5. The remaining sites are processed after the test method already has been finished.
- The thread may need some more time for processing after the test method as been finished. This demonstrates the principle of saving test time by SmartCalc but requires also some more actions: [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) or [SMC_SYNCHRONIZE_WITHOUT_BINNING()](<02.07.04.01.231.44_SMC_SYNCHRONIZE_WITHOUT_BINNING.md>) are to be called in a subsequent test suite to wait for the end of the execution of all threads.
