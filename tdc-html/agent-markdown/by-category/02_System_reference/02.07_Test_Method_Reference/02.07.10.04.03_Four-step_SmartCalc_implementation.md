# Four-step SmartCalc implementation

There are four key steps to implement SmartCalc to your test program.

- Structure your test program for parallel execution.

```
//
// UTM class/test method code for RF Power Measurement
//
virtual void run()
{
    ON_FIRST_INVOCATION_BEGIN();
    {
        //
        // Parallel device setup and test execution
        //
        FOR_EACH_SITE_BEGIN();
        {
            //
            // Get "measParams", digitizer pin name and result handle.
            // Calculation will happen in your SMC_backgroundProcessing() method
            //
            SMC_ARM(measParams, mDgtPin, resultHandle);
        }
        FOR_EACH_SITE_END();
    }
    ON_FIRST_INVOCATION_END();
}
```

- Encapsulate upload, calculation and test statement into your [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) method.

You have to write your own public method, that must match exactly the name SMC_backgroundProcessing() for SmartCalc to recognize it. The signature must be identical to the signature of the corresponding [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>).

In case different SMC_backgroundProcessing() methods become necessary, they need different signatures.

```
public:

void SMC_backgroundProcessing(ARRAY_D& measParams, sting mDgtPin, string resultHandle)
{
    DOUBLE resPower;
    INT    site = SMC_SITE_NUMBER();

    //
    // Hidden upload
    //
    const ARRAY_COMPLEX& cData = SMC_GET_COMPLEX_WAVEFORM(mDgtPin, resultHandle, 1);

    DSP_RF_MOD_POWER(cData,measParams,DBM,site,&resPower);

    SMC_TEST("port","testName",tmLimits,resPower,true);
}
```

Note Use multibin to allow [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) to bin each thread correctly.
- Synchronizing calculations, performing binning and data logging.

```
virtual void run()
{
    //
    // Automatically synchronize all the calculation tasks,
    // print data log and do binning
    //
    SMC_SYNCHRONIZE();
}
```

To properly synchronize a test flow with the ["thread per site" or the "common thread"](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>) implementation and also a mixture of both, refer to [Synchronize a test flow with any use model](<02.07.10.05_SmartCalc_recommendations.md#_119876__s_Synchronize_a_test_flow_with_any_use_model>) in [SmartCalc recommendations](<02.07.10.05_SmartCalc_recommendations.md>).

- Using SmartCalc APIs for hidden uploads

Hidden uploads are implicitly triggered by SMC APIs listed in the section [Wrapper APIs to control hidden upload in threads](<02.07.10.04.02_SmartCalc_API_overview.md#_118901__s_Wrapper_APIs>) of [SmartCalc API overview](<02.07.10.04.02_SmartCalc_API_overview.md>).

However, hidden uploads can also be triggered explicitly by using [SMC_BACKGROUND_ENABLE()](<02.07.04.01.231.06_SMC_BACKGROUND_ENABLE.md>) and [SMC_BACKGROUND_DISABLE()](<02.07.04.01.231.05_SMC_BACKGROUND_DISABLE.md>).

These SMC APIs will make sure that uploads are carried out whenever they do not effect the throughput of the test program.

Note Result areas for the digital capture memory have to be set up when using hidden upload.
