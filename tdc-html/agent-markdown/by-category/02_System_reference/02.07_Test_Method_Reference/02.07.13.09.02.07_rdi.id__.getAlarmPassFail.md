# rdi.id().getAlarmPassFail()

Retrieves the alarm pass or fail result on a pin or the general alarm pass or fail result on all pins.

## Syntax

```
rdi.id(string id).getAlarmPassFail();
```

```
rdi.id(string id).getAlarmPassFail(string pin);
```

```
rdi.id(int id).getAlarmPassFail();
```

```
rdi.id(int id).getAlarmPassFail(string pin);
```

## Return value

The pass or fail result is returned:

- 1 is returned for pass.
- 0 is returned for fail.
- -1 is for "not enabled."

To retrieve the alarm pass or fail result on a pin in the current RDI_BEGIN-RDI_END block, use rdi.id(string id).getAlarmPassFail(string pin);. The result ID can be any result ID in this RDI_BEGIN-RDI_END block.

  Note If any of alarm checking events on a pin fails in the burst, the result is fail on this pin only.

To retrieve the general alarm pass or fail result in the current RDI_BEGIN-RDI_END block, use rdi.id(string id).getAlarmPassFail();. The result ID can be any result ID in this RDI_BEGIN-RDI_END block.

  Note The general alarm result is a combination of the results from all valid alarm pins. As long as any one of the alarm pins fails, the general alarm result fails. Note If an alarm checking fails in a burst, the general burst Pass/Fail result will fail too. The reason is that the alarm pin's fail contributes to the general burst fail result. Note If the burst comprises a match loop and the match loop fails on any site, the alarm results of that site will be reported as fail, even if none of the alarm checks itself fails. Note If an alarm pin has a user-defined measurement, all value results including alarm measurement values will get uploaded. [getValue()](<02.07.13.12.01.01.23_getValue.md>) and [getMultiValue()](<02.07.13.12.02.50_getMultiValue.md>) will not be impacted. But [getBurstValue()](<02.07.13.12.01.01.21_getBurstValue.md>) will include voltage measurement values and results of alarm events.

Also see the example in [Commands](<02.07.13.09.02_Alarm_handling_commands.md>).

## Example

 When -1 is returned:

```
rdi.alarm().enable(false);

RDI_BEGIN();
  // after all measurements with "id", alarm compare events are available.
  rdi.class("id")....
...
  rdi.alarm().check().execute();  // Add alarm check point.
...
RDI_END();
rdi.id("id").getAlarmPassFail();  // -1 is returned because alarm is disabled before RDI_BEGIN().
```

```
rdi.alarm().pin(A).enable(false);

RDI_BEGIN();...
  // after all measurements with "id", alarm compare events are available.
  rdi.class("id")....
...
  rdi.alarm().check().execute();  // Add alarm check point.
...
RDI_END();
rdi.id("id").getAlarmPassFail(A);  // -1 is returned because the pin A's alarm is disabled before RDI_BEGIN().
```

## Functional changes

- Introduced in SmartRDI 7.5.0
