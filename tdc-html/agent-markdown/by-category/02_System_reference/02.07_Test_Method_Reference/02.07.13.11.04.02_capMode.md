# capMode()

Specifies the way to capture the waveform when the PPMU or BADC is used as digitizer.

## Syntax

```
capMode(TA::DC_CAP_MODE capMode);
```

List of parameters
 |

Parameter

 |

Description

 |
 |

capMode

 |

The way to capture the waveform.

 |

List of available options of parameter: capMode
 |

Option

 |

Description

 |
 |

TA::TRIG

 |

[Trigger-based measurement](<../02.05_Test_Head_Cards/02.05.04.01.07.06.02_How_to_use_the_BADC_as_digitizer.md>). It only works for BADC (pure BADC or through PPMU) and is limited to the sharing of one BADC among 16 pins. It provides the sampling frequency up to 250 KHz.

This mode is only supported on SmarTest 7.2.1 or above.

 |
 |

TA::VEC (default)

 |

[Sequencer based measurement](<../02.05_Test_Head_Cards/02.05.04.01.07.06.02_How_to_use_the_BADC_as_digitizer.md>). It works for both BADC and successive approximation. The highest sampling frequency supported is 50 KHz for BADC and 3 KHz for the successive approximation.

 |

For the TRIG mode, when all DC digitizer measurements have been done, the results are read from the FPGA memory and then transferred into the channel memory. This reading and transferring process takes about 20 to 25 µs per sample. This means if you measure 1,024 samples, you have to wait about 1,024*25 µs after the measurements for further actions.

 Note About the sampling by samples() on DC Scale, PPMU, and BADC:

The samples() 鈥?execute() command can have two different execution behaviors: blocking execution and non-blocking execution.

For example,

```
RDI_BEGIN();
   rdi.dc().pin(A).....samples().FS().execute();// Command 1
   rdi.func().label().....execute(); // Command 2
RDI_END();
```

In this example,

- If Command 1 runs in the non-blocking execution, pin(A) will keep sampling while Command 2 is running the pattern till the block end.
- If Command 1 runs in the blocking execution, Command 2 will run the pattern after the pin(A) sampling has been done.
 Points to remember:

- For DC Scale, all the sampling executions with samples() are blocking execution. The pattern will be run after the sampling is done.
- For PPMU and BADC, the sampling mode depends on the parameter specified by capMode():

  - For capMode(TA::VEC), the sampling is blocking execution.
  - For capMode(TA:TRIG), the sampling is non-blocking execution. The operations of pattern and sampling are running in parallel till the end of the code block.

Example for samples() with capMode(TA::VEC):

```
RDI_BEGIN( );
  rdi.port("pt").dc().pin("pin").samples(1024).capMode(TA::VEC)...execute();
  rdi.port("pt").func().label(B).execute(); // Pattern running after sampling.
RDI_END();
```

Example for samples() with capMode(TA::TRIG):

```
RDI_BEGIN( );
  rdi.port("pt").dc().pin("pin").samples(1024).capMode(TA::TRIG)...execute();
  rdi.port("pt").label(A).execute();  // Pattern running while sampling.
  rdi.port("pt").wait(TA::WAIT_DCDGT);
  rdi.port("pt").func().label(B).execute(); // Pattern running after sampling.
RDI_END();
```

## Example

```
rdi.port("ptPin1").dc().pin("DATA1",TA::BADC).samples(1024)
                       .capMode(TA::TRIG).FS(10 KHz).execute();
rdi.dc().pin("DATA1").vForce(1 V).iMeas().samples(1024)
                     .capMode(TA::VEC).valueMode(TA::BADC).FS(10 KHz).execute();
```
