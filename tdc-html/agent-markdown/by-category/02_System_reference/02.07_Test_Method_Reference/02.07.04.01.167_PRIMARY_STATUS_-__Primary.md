# PRIMARY_STATUS - (Primary)

The PRIMARY_STATUS API accesses the data container holding the current definitions of digital primaries (timing-related primaries, level-related primaries, and start label). These definitions can be changed using the member functions.

This API can also be used to call the subsidiary data containers: The [TIMING_SPEC](<02.07.04.01.249_TIMING_SPEC.md>) and [LEVEL_SPEC](<02.07.04.01.124_LEVEL_SPEC.md>). API's class objects. Call these objects to change the definitions of the primary timing equation/spec sets and primary level equation/spec sets, and to change the definitions of the spec values. For multi-port testing, another subsidiary data container, the [SPECIFICATION](<02.07.04.01.232_SPECIFICATION.md>) API's class object is available.

The changes of the definitions specified by this API are actually reflected to the hardware when any of the following APIs is executed.

- EXECUTE_TEST
- START_TEST
- DIGITAL_CAPTURE_TEST
- NB_DIGITAL_CAPTURE_START
- FUNCTIONAL_TEST
- FLUSH then SPEC_SEARCH.execute() member function
- FLUSH then SEQUENCER_STATUS.run() member function
- FLUSH then PMU_IFVM.execute() member function
- FLUSH then PMU_VFIM.execute() member function
- FLUSH then TASK_LIST.execute() member function
- FLUSH then DPS_VFIM.execute() member function

The changes of the definitions specified by this API can be also reflected to the MCD when the [FLUSH](<02.07.04.01.69_FLUSH.md>) API is executed. This is an option to reflect the changes on the user interface such as the Test Program Explorer and the Spec Tool.

For retrieving the definitions, the current activated definitions are returned. Note that even if the timing set (or level set) is changed from the primary one to another one by the [CTIM](<../02.08_Setup_and_Result_Tools/02.08.04.16.02.06.10.02_Sequencer_instructions.md#_99880__row_CTIM>) (or [CLEV](<../02.08_Setup_and_Result_Tools/02.08.04.16.02.06.10.02_Sequencer_instructions.md#_99880__row_CLEV>)) sequencer instruction during the vector generation of the start label, the CTIM (or CLEV) sequencer instruction does not change the definition of primary timing set (or primary level set).

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PrimaryStat.h.

  Constructor

There is no constructor available for this class.

To use the PRIMARY_STATUS API, you must always use the system-prepared class object Primary which represents the current definitions of the digital primaries or represents the digital primaries to be defined. You cannot create any object of this API.

## Member functions

  timing()

```
PRIMARY_STATUS& timing(INT tset);

PRIMARY_STATUS& timing(INT tset, const STRING& port);
```

The timing member function specifies the timing-related primaries (except the waveform set). Which primary you specify is determined by the data type of the specified parameter.

 |

 isTimingPortBased()

```
Boolean isTimingPortBased();
```

For multi-port testing (however, executable even for non-multi-port). This member function returns TRUE if any specification of the timing setup is currently defined as the primary (that is, TRUE if the current timing setup is port-based). Otherwise (that is, a non-multi-port spec set or waveform set is used), this member function returns FALSE.

Note Do not mix the usage of the firmware command with the test method API to query or change the hardware status. The test method API uses an internal cache which is not known and not accessible to the firmware command. The hardware status change made with the firmware command is not recorded in the cache and the subsequent hardware status querying with the test method API may return an incorrect result. To query the hardware status with the test method API, you need to change the hardware status with the test method API. To query the hardware status with the firmware command, you need to change the hardware status with the firmware command. isLabelPortBased()

```
Boolean isLabelPortBased();
```

For multi-port testing (however, executable even for non-multi-port). This member function returns TRUE if any multi-port burst label is currently activated as the start label (that is, TRUE if the current vector setup is port-based). Otherwise, this member function returns FALSE.

There are no parameters in this member function.

 assignLabelToCurrentSite()

```
PRIMARY_STATUS & assignLabelToCurrentSite(const STRING & label);
```

This member function assigns a site specific start label to the current site. It can only be used within a FOR_EACH_SITE block. Note that this function requires the parallel enable flag of the respective testsuite to be set. See also [How to execute separate patterns per site](<02.07.03.13.10_How_to_execute_separate_patterns_per_site__Label_per_site.md>).

Parameter
 |

label

 |

The label that is to be defined as the start label of the current site.

   |  getAssignedLabelForCurrentSite()

```
const STRING & getAssignedLabelForCurrentSite();
```

This member function returns the start label for the current site. It can only be used within a FOR_EACH_SITE block. The function has no parameters.

 assignPinToCurrentSite()

```
PRIMARY_STATUS & assignPinToCurrentSite(const STRING & pin = "");
```

This member function controls which label is to be executed on a channel that is shared for a pin by sites with different start labels. The operation mode of this function depends on whether it is used within or outside a FOR_EACH_SITE block. In the first case, it must be called with a pin which is associated on the current site with a channel also used by other sites. This call will have the effect that the start label of the current site will be executed on this channel. If the function is used outside a FOR_EACH_SITE block, it must be called with an empty parameter. This has the effect that all previously defined associations of channel sharing pins with a specific site are revoked. Note that this function requires the parallel enable flag of the respective testsuite to be set. See also [How to execute separate patterns per site](<02.07.03.13.10_How_to_execute_separate_patterns_per_site__Label_per_site.md>).

Parameter
 |

pin

 |

Name of a pin that is mapped to the same channel on several sites.

   |  getAssignedPinForCurrentSite()

```
const STRING & getAssignedPinForCurrentSite();
```

This member function returns the channel sharing pins whose channel is associated with the current site. It can only be used within a FOR_EACH_SITE block. The function has no parameters.

```
bool getModeContextName(STRING& sModeContextName);
```

## Important points

- To use the PRIMARY_STATUS API, you must always use the system-prepared class object Primary, which is the single object of the PRIMARY_STATUS API. The constructor function is not available in the PRIMARY_STATUS API (you cannot create or destroy any object of this API).
- When a test is started by any of the [FUNCTIONAL_TEST()](<02.07.04.01.75_FUNCTIONAL_TEST.md>), [START_TEST()](<02.07.04.01.235_START_TEST.md>), [EXECUTE_TEST](<02.07.04.01.65_EXECUTE_TEST.md>), [DIGITAL_CAPTURE_TEST](<02.07.04.01.35_DIGITAL_CAPTURE_TEST.md>), or [NB_DIGITAL_CAPTURE_START](<02.07.04.01.135_NB_DIGITAL_CAPTURE_START.md>) API, the digital primaries (the timing/level-related primaries and start label) that are specified by this API are automatically defined as the new settings (in the MCD) and are activated into the hardware. Therefore, you do not have to execute the [FLUSH](<02.07.04.01.69_FLUSH.md>) API if one of these APIs is used. However, FUNCTIONAL_TEST does nothing for the analog set and routing set (execute FLUSH before FUNCTIONAL_TEST if you execute a functional test that involves an analog module).

If you need to generate vectors in a DC test API ([PMU_VFIM](<02.07.04.01.152_PMU_VFIM.md>), [PMU_IFVM](<02.07.04.01.151_PMU_IFVM.md>), or [DPS_VFIM](<02.07.04.01.51_DPS_VFIM.md>)) after you specify the change of digital primaries using the PRIMARY_STATUS API, execute the FLUSH API beforehand to reflect the changes.

```
timing(const SPECIFICATION& specif)
```

## Examples

### Change the primary timing set

```
Primary.timing(3);

FUNCTIONAL_TEST();
```

The timing member function specifies timing set 3 as the primary timing set to be defined, and FUNCTIONAL_TEST reflects it to the hardware then executes a functional test.

### Retrieve the primary DPS set

```
INT dps_setNum;
...
dps_setNum = Primary.getDps();
```

The getDps member function returns the DPS set number that is currently defined as the primary into the variable dps_setNum.
