# Issues to affect the test method debugger

The following issues can cause abnormal behavior of the test method debugger, such as not functioning, or omitting breakpoints:

- The .cpp file to be debugged has not been built.

The debugger debugs only test method codes that have been built successfully.

- The build configuration is wrong: The correct configuration is Debug [Active].

Actions:

  - In the C/C++ perspective, right-click the debugged test method project and select Properties.
  - On the C/C++ Build page, select Debug [Active] from the Configuration combo box.

If Debug [Active] dose not appear, set it up by clicking the Manage Configuration... button.

- The test method libraries (.so files) for the debugged test method and for the device are different.

To compare the two files, you click each .so file to view its properties in the Properties view of the Setup perspective.

  - The .so file of the device resides in <device>/testmethod/.
  - The .so file of the debugged test method resides in <the debugged test method project>/Binaries/.

To make the two files identical:

  - In the C/C++ perspective, right-click the device and select Clean Project to delete all the .so files located in <device>/testmethod/.
  - Rebuild the debugged test method project.
  - Rebuild the device project.

- The breakpoints are not enabled.

Action: In the Breakpoints view, select the desired breakpoints. If the desired breakpoints are not available, set them up in the code.

- The .hpp file cannot be debugged: You cannot debug a .hpp file if you have not set any breakpoints in the corresponding .cpp file.

Action: First, set a breakpoint in the corresponding .cpp file. Second, set the desired breakpoints in the .hpp file. Then, after the debugger finishes debugging the .hpp file, you can remove the breakpoint in the .cpp file without exiting the debugger.
