# Test method parameters

Besides the parameters you defined with addParameter(), the following test method parameters are provided in the concurrent test method template.

- CCF_ContextType

The parameter controls whether this test suite will be executed on the synchronous sequencer or on the independent sequencer by the concurrent test framework. For details, refer to [CCF-ISR mode and CCF-Burst mode](<02.07.08_Concurrent_test_framework.md>). Its value can be:

Synchronized: running on the synchronous sequencer, which means the test suite is a synchronized test suite

Independent: running on the independent sequencer, which means the test suite is an independent test suite

- CCF_FocusedPins

The focused pins of the test suite. Its value can be pin name(s), pin group name(s), port name(s) of digital pins, DPS pin names.

The parameter will control how the timing, level and pattern are merged. (For details, refer to [Merging the setups](<02.07.08.02_Merging_the_setups.md>).)

CCF will create the sequence context according to the specified port name(s) for the CCF-ISR mode. (For details, refer to [Using execution contexts](<../02.06_Command_Reference/02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>).)

For the `ccf_tml.CCExecution` and `ccf_tml.CCExecutionMultiGroup` test method, the following parameters are provided by CCF.

- CCF_LevelEqnNum

When CCF_DevelopMode is set to 1, CCF will create a new level equation by merging the level information from the levels of the native test suites. This parameter specifies the new level equation number for the merged level equation set.

Its value can be:

  - No merge (default): Do not merge the level settings in the CCF block.
  - [equation_number]: Create a new level equation with the specified level equation number. If the equation set number is already used, a warning message will be issued to indicate that the specified equation number was occupied and will be overwritten.
  - Auto: CTF finds an unused equation number, creates an equation with this number, and merges all level data to this new equation. If all equation numbers (max is 256) are assigned, an error is displayed:

`The CCF_LevelEqnNum for test suite xxx is set to AUTO, but all equation numbers have been used by other test suites.`

Limitation - Selecting Auto and running a CTF block test flow, results in the assignment of an unused level equation number. However, an error message is displayed reporting that the first test method of next test suite cannot be found. Error messages similar to the following examples can be seen in the console:

`ERROR: Exception happened: UTM creation testMethodType "Inco3_CTF3p0_tml.MPSync_ctf_Simplify.MPSync_FUNCTION_TEST_CTF" does not exist!`

`ERROR: During execution, testSuite "TC2_sh1_func_test" fails, due to testmethod "Inco3_CTF3p0_tml.MPSync_ctf_Simplify.MPSync_FUNCTION_TEST_CTF" object creation failure!`

`Rerun the` CTF block test flow. The test flow should complete without error messages.

- CCF_TimingSpecSetName

When CCF_DevelopMode is set to 1, CCF will create a new multiport timing spec by merging the timing spec from the native test suites. This parameter specifies the new multiport spec set name.

- CCF_LabelName

When CCF_DevelopMode is set to 1, CCF will create a new multiport burst by merging the multiport burst from the native test suites. This parameter specifies the name for the new multiport burst.

This is the primary label name executed in the concurrent mode (CCF_Concurrent=1).

- CCF_ParallelISR

The name of the parameter used to specify whether to run an independent test suites in parallel with a synchronized test suite (CCF_ContextType = Synchronized).

The CCF_ParallelISR parameter has two options:

  - SERIAL _ISR - Independent test suites in the associated CTF block run serially while the synchronized test suite is running.
  - PARALLEL_ISR - Independent test suites in the associated CTF block run in parallel while the synchronized test suite is running.

## Functional changes

- Introduced in SmarTest 6.5.4
- SmarTest 7.1.3: New parameter CCF_TimingSpecSetName.
- SmarTest 7.1.4: Supports analog sets defined in the analog setup file in TML 2.1.6
- SmarTest 7.2.0: Supports accessing the variable mAnalogRfSetName defined for CCF_AnalogRFSetName in TML 2.2.0
- SmarTest 7.2.1: in the patch 2, added the test method ccf_tml.CCExecutionMultiGroup in TML 2.2.0.
- SmarTest 7.3.2: CCF_ParallelISR parameter introduced to enable parallel testing of independent test suites.
