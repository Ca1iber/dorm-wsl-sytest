# Setting up Routing Connections

If analog module connection or utility line control is required in the AC test, you must set up them in the test method program using the ROUTING_STATUS API. There are two ways to set up analog module connections and utility line control.

- If routing set is not prepared

You can set up each required analog module connection as shown below:

```
Routing.pin(pin_name).func;
FLUSH();
```

Where, Routing is a system-prepared class object name of the ROUTING_STATUS API, pin_name is a pin name, and func is a member function of the PIN_I class that is used as a subsidiary data container of the ROUTING_STATUS API.

To execute a particular task, you can specify any of the following member functions of the PIN_I class. For details, see [PIN_I](<02.07.04.01.195.01_PIN_I.md>).

 |

The task to be executed...

 |

Use this member function...

 |
 |

Connect the analog pin to the analog core

 |

`connect(params)`

 |
 |

Disconnect the analog pin to the analog core

 |

`disconnect()`

 |
 |

Connect the analog pin to the other input/output pin

 |

`fwd(params)`

 |
 |

Connect the analog pin to the trigger input pin

 |

`trigger()`

   |  Note params in the above table means the parameters to be specified. Note The FLUSH API is necessary to download the routing settings specified by the ROUTING_STATUS API into the hardware. However, if the EXECUTE_TEST, START_TEST, DIGITAL_CAPTURE_TEST, or NB_DIGITAL_CAPTURE_START API is executed, you can omit the FLUSH API because the FLUSH API is automatically called in these APIs.

With the member function util, you can change the utility line settings. Utility line controls a user relay on the DUT board or logic device.

```
Routing.util(util_name).func;
FLUSH();
```

where, util_name is the name of a utility line and func is a member function of the UTIL_I class that is used as a subsidiary data container of the ROUTING_STATUS API.

To execute a particular task, specify any of the following member functions of the UTIL_I class. For details, see [UTIL_I](<02.07.04.01.195.02_UTIL_I.md>).

 |

The task to be executed...

 |

Use this member function...

 |
 |

Turns the utility line on

 |

`on()`

 |
 |

Turns the utility line off

 |

off()

 |

In addition, there is the member function uti_purpose for setting up multiple utility lines once by using the utility purpose. For details, see [UTI_PURPOSE_I](<02.07.04.01.195.03_UTI_PURPOSE_I.md>).

- If routing set is prepared

You can activate the existing routing set using the ROUTING_STATUS API as shown below:

```
Routing.primary(set);
FLUSH();
```

where, Routing is a system-prepared class object of the ROUTING_STATUS API, and set is the routing set number. The FLUSH API is necessary to download the settings defined in the routing set to the hardware. However, if the EXECUTE_TEST, START_TEST, DIGITAL_CAPTURE_TEST, or NB_DIGITAL_CAPTURE_START API is executed, you can omit the FLUSH API because the FLUSH API is automatically called in these APIs.
