# Controlling sequencer status

In the test method programming, you can control the sequencer status explicitly with the test method API [SEQUENCER_STATUS-(Sequencer)](<02.07.04.01.204_SEQUENCER_STATUS_-__Sequencer.md>) or with the firmware command [SQGB, SQGB? - (SeQuencer GloBal)](<../02.06_Command_Reference/02.06.02.02.232_SQGB__SQGB__-__SeQuencer_GloBal.md>).

For example, you can reset the sequencer status with

```
Sequencer.reset();
```

or

`FW_TASK("SQGB ACQF,0;")`

## DC test programming

In the DC test method library, the sequencer is not cleared after the measurement. This is because clearing the sequencer status will impact the result tools and the result firmware commands. So the settings of the sequencer will apply to the test method executed after it.

In your own DC test method programming, you may stop the sequencer at a specific cycle or vector to measure a current/voltage. If you want to run other patterns after it, you need to reset the sequencer explicitly.

## AC test programming

In the AC test method library, the sequencer status is cleared with `Sequencer.reset()` or `FW_TASK("SQGB ACQF,0;")` before a measurement.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.5.3: Clear the sequencer status before measurement in AC test method library.
