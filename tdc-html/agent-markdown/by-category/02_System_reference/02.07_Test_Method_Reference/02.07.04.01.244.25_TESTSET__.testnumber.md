# TESTSET().testnumber()

The function has three forms, which allow you to get a test number based on different information provided:

- Name of a test result: `testnumber(&name, logname)`
- Integer: `testnumber(number)`
- [TESTNUMBER](<02.07.04.01.242_TESTNUMBER.md>) object: `testnumber(&testnumber)`

Instead of using this member function you can assign a number in the [test table](<../02.10_Data_Logging/02.10.01.08.01.01.01_Test_table_editor.md>).

## Syntax

```
TESTSET & testnumber(const STRING &name, bool logname = false);
```

This form of the function assigns a test number to a test result from the test number values entered in the [Properties view](<../02.08_Setup_and_Result_Tools/02.08.04.32.03.04_Testflow_Properties_view.md>) for the specified test name, and the number of calls for the [TEST](<02.07.04.01.241_TEST.md>) member function with that test name. You can use this member function to assign a test number to a test result that does not have a test name, such as the result of a functional test. In this case, you must enter a test name in the Properties view, even if you have selected a functional test.

If you wish to log the specified test name, set the logname parameter to TRUE. The name is stored into the EDL as a [TestNameAttr](<../02.10_Data_Logging/02.10.01.06.05.61_TestNameAttrType.md>). The values of the test number offset and test number increment named "name" are searched from the test number table whose values are input through the Properties view. If "name" and the corresponding values are found, when one of the `TEST()` methods is called, these values are used to generate a subtest test number. The subtest test number return value is stored into the EDL as a TestId attribute.

```
TESTSET & testnumber(int number);
```

If the [test_number_enable](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_test_number_enable>) testflow flag is enabled, this form of the function stores the number integer value in the EDL as a TestId attribute.

```
TESTSET & testnumber(int number, const bool forceSTDFTestName);
```

If the [test_number_enable](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_test_number_enable>) testflow flag is enabled, this form of the function stores the number integer value in the EDL as a TestId attribute.

If forceSTDFTestName is true, the data formatter writes the name value of the test directly into the TEST_NAM field of the [TSR record](<../02.10_Data_Logging/02.10.03.05.26_Test_Synopsis_Record__TSR.md>), instead of calculating it from the test suite name, test name, and pin name. If this parameter is false, it results in the same behavior as using `TESTSET & testnumber(int number)`.

```
TESTSET & testnumber(TESTNUMBER &testnumber);
```

This form of the function assigns a test number for a test result from the offset and increment values defined by the [TESTNUMBER](<02.07.04.01.242_TESTNUMBER.md>) API. When the [test_number_enable](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_test_number_enable>) testflow flag is enabled and one of the [TEST()](<02.07.04.01.241_TEST.md>) methods is called, the integer value returned by `testnumber.applyTestNumber()` is stored in the EDL as a TestId attribute.

```
TESTSET & testnumber(TESTNUMBER &testnumber, const bool forceSTDFTestName);
```

This form of the function has the same effect as `TESTSET & testnumber(TESTNUMBER &testnumber)`, above. In addition, it lets you specify that the name of the test is put into the TEST_NAM field of the [TSR record](<../02.10_Data_Logging/02.10.03.05.26_Test_Synopsis_Record__TSR.md>) (as described for `TESTSET & testnumber(int number, const bool forceSTDFTestName)`, above).

Note The TEST() methods have to be called within the scope of the testnumber variable after this method is called. If one of the TEST() methods is called outside of the testnumber variable scope, an error occurs and the test method stops running. After you set the testnumber variable, one of the other testnumber() methods must be called before exiting the scope of the variable.

## Examples

### Example 1

This example assigns the test number defined in `limit1` to the current test. The specified test name is logged to EDL stream.

```
TestSet.testnumber("limit1",true);
```

### Example 2

This example assigns `100` as the test number to the current test.

```
TestSet.testnumber(100);
```

### Example 3

This example assigns the test number in `tm1` to the current test.

```
TESTNUMBER tm1;
...
TestSet.testnumber(tm1);
```
