# DpsStatus

This test method allows you to check the status of the DPS channels after executing a functional test. It checks for various DPS states, and returns a pass/fail result.

It supports DC Scale (DCS) cards.

You can choose which states will cause a failure from the following list:

- Constant Current
- Unregulated
- Overvoltage
- Overtemperature
- Overpower

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

## Dependencies

- Some states force the DPS channels to High-Z. To return to normal DPS operation, disconnect and then connect the DUT.
- In the overvoltage state, the DPS channels are disconnected and not initialized. Before continuing, you must disconnect and then connect the DUT.
- If a Power-On, a programming, or an overtemperature error occurs, you must disconnect and then connect the DPSs before continuing.
- If the DPS status becomes unregulated, any testflow currently being executed stops

Parameters
 |

dpsPins

 |

PinString

 |

DPS pins or DC Scale pins to be tested, separated by comma. Default is @.

 |
 |

constantCurrent

 |

string

 |

Checks whether DPS is in the constant current state. Its value can be:

ON: check

OFF: Do not check

 |
 |

unregulated

 |

string

 |

Checks whether DPS is in the unregulated state. Its value can be:

ON: check

OFF: Do not check

 |
 |

overVoltage

 |

string

 |

Checks whether DPS is in the overvoltage state. Its value can be:

ON: check

OFF: Do not check

 |
 |

overPowerTemp

 |

string

 |

Check whether DPS is in the overpower/overtemperature state. Its value can be:

ON: check

OFF: Do not check

 |
 |

protect

 |

string

 |

UHC4T only!

Checks whether UHC4T is in the protect state. It can be:

ON - check

OFF - Do not check

 |
 |

testName

 |

string

 |

The test names to be used as limit. You can:

- Use the test names defined in the test table or testflow limits. Type in the test names manually. Make sure these test names are in the Test name column of the test table (Refer to [Structure of a TMLimits CSV file](<../02.10_Data_Logging/02.10.01.08.01.01.03.01_Structure_of_a_TMLimits_CSV_file.md>)) or in Test Name column of Tests page of Flow Data Editor.
- Define new test names. After that you need to add the defined test names (limits) to the test suite. (Refer to [Adding a limit in the Properties view](<../02.08_Setup_and_Result_Tools/02.08.04.32.02.01.08_Adding_a_limit_in_the_Properties_view.md>) and [Adding a limit on the Tests page](<../02.08_Setup_and_Result_Tools/02.08.04.32.02.01.07_Adding_a_limit_on_the_Tests_page.md>).)

To specify different settings for different pins or pin groups, separate them with commas.

 |
 |

output

 |

string

 |

Controls how to output the per pin test result. It can be:

- None: Do not output the per pin result.
- ReportUI: Output all the per pin result to the report window.

ShowFailOnly: Only outputs the failed pin result to the report window.

 |

## Implementation pseudo code

```
IF not already connected THEN
 connect DUT
ENDIF
check DPS status with specified requirement
datalog test results
```

## Functional changes

- Introduced in SmarTest 6.5.4
- SmarTest 7.1.1: Mixed usage of test table and testflow limits in one testflow is supported in TML 2.1.1.
- SmarTest 7.2.1: New option ShowFailOnly for the parameter output in TML 2.2.0.
- SmarTest 7.3.2: DCS-UHC4T protection mode.
