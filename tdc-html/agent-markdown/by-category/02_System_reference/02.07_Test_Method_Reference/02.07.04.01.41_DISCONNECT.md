# DISCONNECT

The DISCONNECT API disconnects the test system resources from the DUT and sets the tester to the "disconnect" state unless they are already disconnected. If the test resources are already disconnected, this API performs no action. This API works the same as the disconnect testmethod or Disconnect item of the main menu, and performs the following sequences:

- Sets the sequencer to off state.
- Disconnects the analog modules from the pogo pins.
- Powers down the device power supplies.
- Disconnects the digital channels from the pogo pins.Note For multi-site testing, the DISCONNECT API must be used in the first-invocation block except the "each site" loop block. The DISCONNECT API cannot work correctly in the "each site" loop block. Note Do not mix the global `CONNECT()`/`DISCONNECT()` with individual relay switching. Manually switching relays (see for example [SmartRDI: Digital channel relay control](<02.07.13.14_SmartRDI__Digital_channel_relay_control.md>) and [PPMU_RELAY](<02.07.04.01.158_PPMU_RELAY.md>)) will not change the global connect state, and so `CONNECT()/DISCONNECT()` will see no action to perform. The relays which initially have been switched manually, must again be individually and manually switched to change their state.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TestControl.h.

See the test control method [Disconnect](<02.07.05.04.02_Disconnect.md>) for more information about the DISCONNECT.

## Syntax

```
void DISCONNECT();
```

List of parameters

There are no parameters.

Return value

There is no return value.

## Example

```
DISCONNECT();
...
...
PMU_IFVM("PIN1,PIN2").iForce(100 uA).settling(5 ms).mode("BP");

PMU_IFVM("PIN1,PIN2").limits("limit1").execute();
...
...
```

To use the [PMU_IFVM](<02.07.04.01.151_PMU_IFVM.md>) API for a continuity test (SP or BP mode), you must disconnect the tester resources from the DUT. This example disconnects the tester resources from the DUT before the continuity test.
