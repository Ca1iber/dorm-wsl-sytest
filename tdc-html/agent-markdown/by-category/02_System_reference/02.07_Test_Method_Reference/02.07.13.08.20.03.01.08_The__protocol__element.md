# The <protocol> element

This element stores results of a protocol test performed using the SmartRDI's `protocol()` class.

The <protocol> element stores protocol test results in its data and dataStream attributes. The data attribute saves protocol test results returned by a `getData()` function, while the dataStream attribute saves results by a `getDataStream()` function.

 | Get Result Function in SmartRDI |

ORE File Syntax Example

 |
 |

long long getData();

 |

<protocol data="27" />

 |
 |

ARRAY_LL& getDataStream();

 |

<protocol dataStream="46,47,48,49" />

<protocol dataStream="./ORE/waveform.txt" />

 |

## Example

Below is an example of the <protocol> element and its corresponding SmartRDI code block.

An ORE file containing <protocol> elements:

```
<offlineResultEmulation>
  <id name = "id1">
    <protocol data="27" />
  </id>
  <id name = "id2">
     <protocol dataStream="23,24,25" />
  </id>
</offlineResultEmulation>

```

 The corresponding SmartRDI code block that can generate this ORE file:

```
RDI_BEGIN();
rdi.protocol("id1").pname("i2c")
   .read(0x01).execute();
rdi.protocol("id2").pname("i2c_p")
   .read(0x21).regNum(3).execute();
...
RDI_END();
...
rdi.id("id1").getData(0x01); //27
rdi.id("id2").getDataStream(0x21);
//{23,24,25}
...
```

<pin> is inapplicable for the protocol results, because the protocol results is not pin-based.
