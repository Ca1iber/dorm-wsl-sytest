# Hidden data logging

Hidden data logging is a feature of the [SMC framework](<02.07.10_SmartCalc_framework.md>) that enables event-based data logging in the background.

Results of tests that are executed in the [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) function of the test method class are usually logged by calling [SMC_SYNCHRONIZE()](<02.07.04.01.231.43_SMC_SYNCHRONIZE.md>). Typically, SMC_SYNCHRONIZE() is called in one of the last test suites causing delays at the end of the testflow's execution.

In order to optimize event-based data logging with SmartCalc, the [TestEventType](<../02.10_Data_Logging/02.10.01.06.03.12_TestEventType.md>) event type includes two attributes which let you assign a test event to the correct context (test suite and site). This way, the event stream server is able to reconstruct the order of events according to the order of the testflow.

SmarTest handles hidden data logging automatically, once it is enabled by the [hidden_datalog_mode](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_hidden_datalog_mode>) testflow flag.

Hidden_datalog_mode options
 |

Value

 |

Description

 |
 |

0

 |

Default.

Turns hidden data logging off.

 |
 |

1

 |

Turns hidden data logging in compatibility mode on.

In this mode, the limits are used that are defined in the `SMC_SYNCHRONIZE()` test suite.

 |
 |

2

 |

Turns full hidden data logging on, including [LIMIT](<02.07.04.01.126_LIMIT.md>) support.

In this mode, the limits are used that are defined by the calling test suite.

This is the recommended mode.

   |  Note Activating the hidden mode (value 1 or 2) may cause missing or unexpected data log entries when you interactively execute test suites based on the SMC framework. We do not recommend to activate hidden data logging for interactive execution.

## Difference between mode 1 and 2

Note This differentiation is important only if you use test suite limits.

Mode 1 allows you to stay compatible using test suite [limits](<02.07.04.01.126_LIMIT.md>) defined in the `SMC_SYNCHRONIZE()` test suite.

This is because limits (opposed to [TMLimits](<02.07.04.01.250_TMLimits.md>)) are fetched from the test suite. Any [SMC_TEST()](<02.07.04.01.231.45_SMC_TEST.md>) that refers to test suite limits will be executed within SMC_SYNCHRONIZE(), retrieving its respective limit from that test suite. Thus running mode 1 with test suite limits will not hide data logging.

However, SMC_TEST() calls referencing a [LIMIT](<02.07.04.01.126_LIMIT.md>) object or using [TMLimits](<02.07.04.01.250_TMLimits.md>) are executed immediately ('hidden'), since they Do not rely on test suite limits.

Mode 2 immediately executes SMC_TEST() calls including those using test suite limits. However, this requires those limits to be defined within the test suite where they are called!

Note If you use tests with test suite limits in mode 1 and have other tests with [TMLimits](<02.07.04.01.250_TMLimits.md>) or [LIMIT](<02.07.04.01.126_LIMIT.md>) in the same test suite performing multisite tests, the appearance of the data log is not predictable. Therefore it is recommended to use mode 2.

## TMLimits within the SMC framework

If you use TMLimits within the SMC framework together with background processing (as described in [Four-step SmartCalc implementation](<02.07.10.04.03_Four-step_SmartCalc_implementation.md>)), the following rules must be observed:

- The functions [getLimit()](<02.07.04.01.250_TMLimits.md#_110432__dle_getLimit>), [getLimitRef()](<02.07.04.01.250_TMLimits.md#_110432__dle_getLimitRef>), and [getLimitObj()](<02.07.04.01.250_TMLimits.md#_110432__dle_getLimitObj>) for retrieving data from the TMLimits table are threadsafe.
- Ensure that the TMLimits table is loaded into the memory before calling [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>), for example:

```
tmLimits.load("tmuVerify_limits.csv");
SMC_ARM(XXX);
```

- Ensure that all required settings are done before an SMC background process is armed.
 CAUTION You must not change or reload a TMLimits table while an SMC background process is armed or running. Violating this rule may result in invalid data or the crash of the test method.

## Restrictions with hidden data logging enabled

If you enable the testflow flag [hidden_datalog_mode](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_hidden_datalog_mode>), you cannot use the following APIs

- SMC_SET_TESTSUITE_NAME()Note If you need to use the functionality of the following APIs with hidden data logging, use the corresponding functions of [TESTSET](<02.07.04.01.244_TESTSET.md>).
- SMC_TEST_TEXT(), use [TESTSET.testtext()](<02.07.04.01.244.30_TESTSET__.testtext.md>) instead.
- SMC_SET_HLM_FORMAT(), use [TESTSET().hlmFmt()](<02.07.04.01.244.05_TESTSET__.hlmFmt.md>) instead.
- SMC_SET_LLM_FORMAT(), use [TESTSET().llmFmt()](<02.07.04.01.244.18_TESTSET__.llmFmt.md>) instead.
- SMC_SET_RES_FORMAT(), use [TESTSET().resFmt()](<02.07.04.01.244.21_TESTSET__.resFmt.md>) instead.

As noted above, Advantest recommends not to execute SMC-based test suites interactively.

## Restrictions with hidden data logging disabled

If hidden data logging is disabled (`hidden_datalog_mode=0`), some member functions of the TESTSET API are not supported:

- [TESTSET().combineMultiPortTests()](<02.07.04.01.244.02_TESTSET__.combineMultiPortTests.md>)
- [TESTSET().hlmFmt()](<02.07.04.01.244.05_TESTSET__.hlmFmt.md>)
- [TESTSET().llmFmt()](<02.07.04.01.244.18_TESTSET__.llmFmt.md>)
- [TESTSET().port()](<02.07.04.01.244.19_TESTSET__.port.md>)
- [TESTSET().resFmt()](<02.07.04.01.244.21_TESTSET__.resFmt.md>)
- [TESTSET().suppressTestNameLoopCount()](<02.07.04.01.244.22_TESTSET__.suppressTestNameLoopCount.md>)
- [TESTSET().testname()](<02.07.04.01.244.23_TESTSET__.testname.md>)
- [TESTSET().testname_default()](<02.07.04.01.244.24_TESTSET__.testname_default.md>)
- [TESTSET().testtype()](<02.07.04.01.244.32_TESTSET__.testtype.md>)
- [TESTSET().testtype_default()](<02.07.04.01.244.33_TESTSET__.testtype_default.md>)
