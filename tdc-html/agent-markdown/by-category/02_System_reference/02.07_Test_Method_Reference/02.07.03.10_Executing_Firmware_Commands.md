# Executing Firmware Commands

You can execute firmware command to control your hardware directly by using the FW_TASK, BEGIN_EXTENSION and END_EXTENSION APIs.

The FW_TASK API executes a firmware command, and receives the firmware output if the firmware command returns it. For details of firmware commands, see the [Command Reference](<../02.06_Command_Reference/02.06_Command_Reference.md>) manual. The BEGIN_EXTENSION and END_EXTENSION APIs declare a block where you can access the system hardware or MCD at the firmware level.

For details, see [FW_TASK](<02.07.04.01.77_FW_TASK.md>), [BEGIN_EXTENSION](<02.07.04.01.10_BEGIN_EXTENSION.md>), and [END_EXTENSION](<02.07.04.01.59_END_EXTENSION.md>).

```
STRING dfcm("DFCM 1,4000,50,-1.0,1.00,4000,5,NGNG,(CP)\n");
STRING ptstq("PTST? 1,NONE,CVAL\n");

BEGIN_EXTENSION();
  FW_TASK(dfcm);
  STRING answer;
  FW_TASK(ptstq, answer);
      :
      :
END_EXTENSION();
```

 Note For setup data, a conflict might occur between the test method API outside the extension block and firmware commands within the extension block. The following actions avoid such a conflict:

- The caching mechanism of the test method is temporarily turned off between the "extension block" explicitly declared by BEGIN_EXTENSION and END_EXTENSION. This is implicitly done by the system.
- You should execute the FLUSH API before entering the extension block. The setup data relating to the test method APIs such as ANALOG, ANALOG_STATUS, PRIMARY_STATUS, and ROUTING_STATUS will be stored in the caching mechanism. The FLUSH API downloads the setup data to the system hardware or the MCD.
