# PPMU fast transfer mode of SmartRDI

For setting site-specific PPMU voltage levels as runtime values, SmartRDI features a fast transfer mode that shortens the test time in high-site-count applications.

  The fast transfer mode is intended to be used for high-site-count applications. This mode can increase the test time for low-site-count applications:

- The minimum number of sites to take advantage of the fast transfer mode is >= 4 sites.
- The break-even point can be higher depending on the configuration of your application.

## Basic rules to consider

With fast transfer mode enabled, SmartRDI will automatically use the mode if the following rules are met. Otherwise, the normal transfer mode is used:

- The fast transfer mode can be used only with SmartScale test head cards.
- The fast transfer mode is only supported for site-specific PPMU voltage levels that are to be set as runtime values.
- Common runtime values and other PPMU settings are not supported.
- The fast transfer mode is not supported for resources shared between active sites. The following error message is issued if shared resources are used[1)](<#fntarg_1>):

```
ERROR: MTRA - mismatch between number of sites selected and number of values given
```

## Using the fast transfer mode

The fast transfer mode is to be enabled for the entire testflow using keyword [FAST_PPMU_LEVEL_TRANSFER](<02.07.13.04_RDI_Configure_file.md#_146692__row_FAST_PPMU_LEVEL_TRANSFER>) in the [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

The fast transfer mode requires that a minimum [fast transfer buffer size](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_fast_transfer_buffer_size>) of 131072 bytes is specified in the [Technology file for a device](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>). Otherwise the following error message is issued:

```
ERROR: MTRA - ... a minimum fast transfer buffer size of 131072 bytes ...
```

## Example

### Example 4: Fast download of PPMU force voltage values

The example downloads first a runtime value that is common for all sites to pin "PS1600_1". The related double commonRuntimeValue is named "rtv_common" when passing it to [runTimeVal()](<02.07.13.08.03.01_runTimeVal.md>).

An ARRAY_D that is named siteSpecificRuntimeValues holds site specific values for pin "PS1600_2". This array is passed to runTimeVal() as "rtv_site_specific". The fast transfer mode is used only for these site specific runtime values.

```
INT         numOfConfiguredSites;
ARRAY_I     configuredSitesArray;
double      commonRuntimeValue;
ARRAY_D     siteSpecificRuntimeValues;

numOfConfiguredSites = GET_CONFIGURED_SITES(configuredSitesArray);

siteSpecificRuntimeValues.resize(numOfConfiguredSites);
siteSpecificRuntimeValues.init(0.0);

RDI_INIT();

ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Define the common value
    //
    commonRuntimeValue = 5.0 V;

    //
    // Fill the array for all active sites with site specific data
    //
    FOR_EACH_SITE_BEGIN();
    {
        siteSpecificRuntimeValues[CURRENT_SITE_NUMBER()-1] = 3.0 V + CURRENT_SITE_NUMBER() * 0.1 V;
    }
    FOR_EACH_SITE_END();

    //
    // Announce the already defined runtime values
    //
    rdi.runTimeVal("rtv_common",        commonRuntimeValue);
    rdi.runTimeVal("rtv_site_specific", siteSpecificRuntimeValues);

    //
    // Apply site specific values
    //
    RDI_BEGIN();
    {
        rdi.dc().pin("PS1600_1")
                .vForce("rtv_common")
                .iRange(1 mA)
                .relay(TA::ppmuRly_onPPMU, TA::ppmuRly_NO)
                .execute();

        rdi.dc().pin("PS1600_2")
                .vForce("rtv_site_specific")
                .iRange(1 mA)
                .relay(TA::ppmuRly_onPPMU, TA::ppmuRly_NO)
                .execute();
    }
    RDI_END();
}
ON_FIRST_INVOCATION_END();
```

The fast transfer mode is to be enabled for the entire testflow using keyword [FAST_PPMU_LEVEL_TRANSFER](<02.07.13.04_RDI_Configure_file.md#_146692__row_FAST_PPMU_LEVEL_TRANSFER>) in the [RDI_Configure file](<02.07.13.04_RDI_Configure_file.md>).

The fast transfer mode requires that a minimum [fast transfer buffer size](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_fast_transfer_buffer_size>) of 131072 bytes is specified in the [Technology file for a device](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>).

## Functional changes

- Introduced in SmarTest 7.5.3
[1)](<#fnsrc_1>) The firmware command MTRA shows the error message only, if resources are shared between active sites. For example, in a 4-site configuration where one resource is shared by sites 1 and 3 and another resource is shared by sites 2 and 4, no error message is issued if only sites 1 and 2 are active. To verify that your configuration is supported, you must activate all configured sites.
