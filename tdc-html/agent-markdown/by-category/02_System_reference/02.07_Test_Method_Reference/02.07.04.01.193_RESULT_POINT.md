# RESULT_POINT

The RESULT_POINT class gives the position of the result of a sequencer based measurement in the memory. One RESULT_POINT object corresponds to one measurement result, that is, each result is specified by its associated result point.

A RESULT_POINT allows the user to iterate over uploaded results without caring about possibly missing results in a non-continuous result range. A non-continuous range could appear when only failed results are uploaded rather than all results. Most likely the result range will contain "holes" (=passes). The RESULT_POINT object's increment operator ("++") allows to jump to the next uploaded result, regardless whether it is a direct successor of the actual result or not. The only possible direction is forward, jumping backwards (decrement operator) is not supported.

RESULT_POINT objects cannot be constructed directly by the user. Valid RESULT_POINTs can be either obtained through API calls or by using RESULT_POINT operators (for example, the increment operator ++).

The lifetime of a RESULT_POINT is equal to the lifetime of the uploaded results. A subsequent result upload will invalidate all existing RESULT_POINTs. In order to access the new uploaded results the existing RESULT_POINTs must be updated (request new objects for the uploaded range) or new RESULT_POINTs must be created.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/ResultPoint.h.

## Member functions

### getIndex()

```
RESULT_POINT::IndexType getIndex() const;
```

Returns the index of the result this RESULT_POINT object points to. If the RESULT_POINT is not valid, the value RESULT_POINT::NoResult is returned (which is for sure less in comparison to any other valid index value).

## Operators

### operator+

```
RESULT_POINT operator+ (const RESULT_POINT::DistanceType offset) const;
```

Returns a RESULT_POINT which references the result at the position "offset" relative to the actual result position. As results are not always continuous (for example, only failed results uploaded), the offset parameter refers to the number of uploaded results.

Example: If all results were uploaded, a + 3 on a RESULT_POINT at index 2 would result in index 5. If only failed results were uploaded, having the sequence 1,3,4,6,7,9, a + 3 on a RESULT_POINT at index 3 would result in index 7.

The sum of "actual position + offset" must not exceed the number of uploaded results, otherwise an error will be generated.

### operator+=

```
RESULT_POINT& operator+= (const RESULT_POINT::DistanceType offset );
```

Allows modifying the actual object instead of returning a copy.

### operator++

```
RESULT_POINT& operator++();
RESULT_POINT& operator++(int);
```

Pre/post increment operators used to step to the next RESULT_POINT. These operators are context aware, i.e. they will always step forward to the next existing result, depending on the mode of the uploaded results (uploaded ALL or FAILS only results).

### Comparison operators

```
bool operator==(const RESULT_POINT& otherResPoint);
bool operator!=(const RESULT_POINT& otherResPoint);
bool operator< (const RESULT_POINT& otherResPoint);
bool operator<=(const RESULT_POINT& otherResPoint);
bool operator> (const RESULT_POINT& otherResPoint);
bool operator>=(const RESULT_POINT& otherResPoint);
```

Comparison operators. RESULT_POINT objects are compared according to their indexes.

## Example

```
virtual void run()
{
    // ...
    // Perform DC Dynamic measurement ....
    ON_FIRST_INVOCATION_BEGIN();

        // settings and relay switching ...
        FUNCTIONAL_TEST();

    ON_FIRST_INVOCATION_END();

    // ...

    STRING pin("dps1");

    // upload the results
    //
    // Define a result accessor object
    DC_RESULT_ACCESSOR allResults;

    // Upload all available results for the pin in RESULT_INDEX addressing scheme.
    // The variable "range" will contain the start index and the length of the uploaded
    // result range. For uploadResult() the length is equal to the number of uploaded
    // results but for uploadFailedResults() it is usually larger than the number of
    // failed results.
    // Before the result data can be accessed, they always first need to be uploaded from
    // hardware/firmware. Each uploadResult() will overwrite the last uploaded results.
    // (independent of the particular DC_RESULT_ACCESSOR object!).

    const TM::RESULT_RANGE range(allResults.uploadResult(pin, TM::RESULT_INDEX));
    if (range.length > 0)
    {
        // Use result accessor member functions getFirstResultPoint() and
        // getLastResultPoint() to obtain iterators (RESULT_POINT objects) to the
        // first and last uploaded results.

        const RESULT_POINT first(allResults.getFirstResultPoint(pin));
        const RESULT_POINT end  (allResults.getLastResultPoint(pin));

        // process the results

        // Loop over the uploaded results using the first and end iterators (RESULT_POINTs)
        // and the increment ("++") operator on an iterator (decrement is not supported).
        for ( RESULT_POINT p = first; p <= end; ++p )
        {
            const bool testPassed         = allResults.getPassFail(p);
            const TM::PHYSICAL_VALUE type = allResults.getMeasurementType(p);

            std::cout << "Test " << (testPassed ? " PASSED " : " FAILED ");
            std::cout << ", Measured value " << allResults.getValue(p);
            std::cout << ((type == TM::VOLTAGE) ? " V " : " A ");
            std::cout << " at point " << p.getIndex();
            std::cout << " at site "  << CURRENT_SITE_NUMBER() << endl;

            if (! testPassed)
            {
                // test has failed at this point
                // obtain the status info to examine the fail reason...
                const RESULT_FAIL_INFO failInfo = allResults.getFailInfo(p);

                // print out the status bits ...
                std::cout << " HighLimitFailed : " << failInfo.hasHighLimitFailed();

                // ...
            }
        }
    }

    // set the test result and send data to datalog ...
    TEST(allResults, TRUE);
}

```
