# GET_PHY_WVF_IDX

This API can translate an existing device cycle name (physical or logical) defined in a wavetable to a physical waveform index. This is useful when physical waveform DC/DC power units are needed, for example in the [VEC_LABEL_EDIT](<02.07.04.01.268_VEC_LABEL_EDIT.md>) API.

Depending on the definition of a device cycle, the device cycle name might not be enough to obtain the corresponding physical waveform index.

- If a device cycle uses data parameter (DD1, DD2, ED1 and ED2), this device cycle name will translate to several physical waveforms. So you need to specify the values of all data parameters that are used in the device cycle to get the unique physical waveform index.
- If a physical device cycle is used, it can be translated to the physical waveform index directly with no more parameters needed.

The device cycle name you want to translate should have been defined in the wavetable associated with the primary timing specification. If the name does not exist in the primary wavetable or primary specification is not equation-based or invalid, an error will be thrown.

Note See the related API [VEC_LABEL_EDIT](<02.07.04.01.268_VEC_LABEL_EDIT.md>).

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/VecLabelEdit.h.

## Syntax

```
INT GET_PHY_WVF_IDX(const STRING& pinName,
                    const STRING& devCycName,
                    const STRING& dataParameters = "");
```

Parameters
 |

pinName

 |

The pin for which you want to get the physical waveform index.

 |
 |

devCycName

 |

The device cycle name for which you want to get the physical waveform index.

 |
 |

dataParameters

 |

The values of drive (DD1 and DD2) and receive (ED1 and ED2) data parameters used in the device cycle. It should follow the syntax: DD1, DD2, ED1, ED2. If the device cycle does not use data parameters, this parameter can be left empty (" ") or use ",,,".

For DD1 and DD2, the values you can define are:

F0N drive 0

F1N drive 1

FN0 tri-state off

FNZ tri-state on

F00 drive 0, tri-state off

F0Z drive 0, tri-state on

F10 drive 1, tri-state off

F1Z drive 1, tri-state on

For ED1 and ED2, the values you can define are:

F0 compare to low

F1 compare to high

FI compare to intermediate

FX compare to mask

FU compare to unstable

C capture digital data

D do not capture digital data

 |

## Example

```
VEC_LABEL_EDIT myLabel("myLabelName", "myPin");
VECTOR_DATA myVectorData[3] = {{10,0}, {12, 0}, {15, 0}};

myVectorData[0].phyWvfIndex = GET_PHY_WVF_IDX("myPin","devCycl1","F00,F10,,");
myVectorData[1].phyWvfIndex = GET_PHY_WVF_IDX("myPin","devCycl1","F10,F00,,");
myVectorData[2].phyWvfIndex = GET_PHY_WVF_IDX("myPin","devCycl2",",,FX,F1");

myLabel.downloadUserVectors(myVectorData,3);
```

The first two lines define the label and pin to edit and the vectors that will be changed and their corresponding new values. The next three lines get the physical waveform index that will be used as the new values and fill in myVectorData. Then the last line downloads the values in myVectorData to vector 10, 12, 15 of the label.
