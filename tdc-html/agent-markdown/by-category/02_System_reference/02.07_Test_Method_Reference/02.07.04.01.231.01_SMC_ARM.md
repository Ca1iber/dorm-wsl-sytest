# SMC_ARM()

Arms the SMC_backgroundProcessing() method and passes the specified data to it.

## Important points to consider

  Passing data to the background process Data can be passed to the background process

- as member variable of the test method class,
- by up to eight optional parameters as value,
- by up to eight optional parameters as reference.
 Passing data as member variable The recommended way of passing data to the background process is using class member variables.

Member variables of the test method class that are used in a background process must not be changed while the background process is running.

This restriction also applies to test method parameters defined in the initialize() function of a test method class and assigned to member variables of the class: SmarTest initializes these parameters for each execution of the run() function to ensure that the conditions are the same for all sites.CAUTION Parallel access to member variables of a test method class through the run() function and a background process may result in invalid data or in a crash of the test method and is therefore not allowed. Passing data by optional parameter as value All data that are passed to the background process using the eight optional parameters are copied by the SmartCalc framework. The background process gets only a copy of the data.

Be careful with passing large data containers to the background process even though the parameters are only references to the data containers: These data containers are also copied by the framework. This might impact the performance of the test method.

 Passing data by optional parameter as reference

Alternatively you can pass data by the optional parameters as follows, so that only references are used:

- use `boost::cref()` - for constant references
- use `boost::ref()` - for non-constant references

For this kind of passing data to the background process, you have to be aware of

- memory leaks if the variable is not freed properly,
- issues of the lifetime of the variable, as the background process will last longer than the run() function where it has been armed, and
- issues regarding thread safety as two or more threads could access the content of the variable at the same time.
    Binning of sites while hidden uploads are running

The SmartCalc framework automatically synchronizes background threads before sites are binned. For optimized usage of hidden uploads, only background threads that process the sites to be binned should be synchronized.

- For the [thread per site](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>), the processed site is automatically defined by the site that was in focus when the background process has been armed by this API.
- For the [common thread](<02.07.10.02.01_SmartCalc__Thread_per_site__and__Common_thread.md>), the SmartCalc frame work will automatically assume that all active sites are processed in the background process. In case a background process utilizes a modified list of sites to process, you must use APIs [SMC_ARM_FOR_SITES()](<02.07.04.01.231.02_SMC_ARM_FOR_SITES.md>) or [SMC_ARM_OTHER_TS_FOR_SITES()](<02.07.04.01.231.04_SMC_ARM_OTHER_TS_FOR_SITES.md>) to make the modified list of sites accessible for the SmartCalc framework.
 Hidden upload and Mode_contexts

[Hidden uploads](<02.07.10.04.05_Hidden_upload.md>), controlled and started by [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md>) must be finished before a [Mode context](<../02.06_Command_Reference/02.06.03.01.03_Configuring_pin_type_and_operating_mode_for_a_context.md>) is changed.

For changes of the Mode context within a test suite, we recommend calling the API [SMC_SYNCHRONIZE_WITHOUT_BINNING()](<02.07.04.01.231.44_SMC_SYNCHRONIZE_WITHOUT_BINNING.md>) before the Mode context is changed.

For changes of the Mode context over several test suites, we recommend inserting a new test suite with no level-, timing-, or pattern-information defined and assigning the system-prepared test method smartCalc.SMC__SYNCHRONIZE.

## Syntax

```
void SMC_ARM(value1, value2, value3,.... value8);
```

 This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.Note With C++98 there is a compiler warning when using the compile option -Wpedantic in the header.  Parameters

 | Parameter  | Description/Range |
 | value1 ... value8 |

Up to eight optional parameters of any type to transfer data to [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>).

The parameters of SMC_ARM() and your SMC_backgroundProcessing() method have to be equal in both the number of parameters and the type of the parameter.  |   Return value There is no return value.

## SMC_backgroundProcessing()

```
void SMC_backgroundProcessing (type value1, type value2, ..., type value8);
```

This method must be defined as public method of your test method class. The call of this function is armed by [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_ARM>) in the run() function of the same test method class and controlled by the SmartCalc framework.

In case different SMC_backgroundProcessing() methods become necessary in your test method class, they need a different number of parameters to be distinguishable (different types is insufficient).

  Parameters

 | Parameter  | Description/Range |
 | type value1 ... type value8 |

Up to eight optional parameters of any type that are passed from [SMC_ARM()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_ARM>).

The parameters of SMC_ARM() and your SMC_backgroundProcessing() method have to be equal in both the number of parameters and the type of the parameter.

   |   Return value There is no return value.

## Examples

### Example 1: Passing data by member variables

The following code shows the recommended way of passing data to SMC_ARM() and the background process.

```
Class myTestMethod
{
protected:

    ARRAY_D data;

    virtual void run()
    {
        ON_FIRST_INVOCATION_BEGIN();

            //
            // Store the data in the member variable of the class
            //
            data = ...

            FOR_EACH_SITE_BEGIN();

                SMC_ARM();
                ...

            FOR_EACH_SITE_END();

        ON_FIRST_INVOCATION_END();
        ...
    }

public:

    void SMC_backgroundProcessing()
    {
        //
        // Do some processing in the background
        //
        cout << data[0] << endl;
    }

} // Class myTestMethod
```

Note

The example above contains a call of cout in function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to [Thread safety](<02.07.10.02.02_Thread_safety.md>).

### Example 2: Passing data by reference

The following code shows how to pass data by reference to SMC_ARM() and the background process.

```
Class myTestMethod
{
protected:

    virtual void run()
    {
        ...
        static ARRAY_D data;
        ...
        //
        // Pass the data to SMC_ARM() by reference
        // Note: no data will be copied due to boost::cref()
        //
        SMC_ARM(boost::cref(data));
        ...
    }

public:

    //
    // Your SMC_backgroundProcessing() method uses the reference to 'data'
    //
    void SMC_backgroundProcessing(const ARRAY_D& data)
    {
        //
        // Do some processing in the background
        ...
    }

} // Class myTestMethod
```
