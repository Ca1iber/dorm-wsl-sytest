# Synchronized protocol test

Patterns are typically fully simulation-based, which means that for testing the device, its communication is completely ported to cycle-based test vectors.

Synchronized protocol test is very close to this approach. However, the main difference is that the pins of the host interface port are treated differently because their content is specified in transactions.

The term 鈥榮ynchronized' points to a particular step that is done before executing such a pattern. There is a user-defined reference point on a simulation-based port, called marker, to identify at which cycle to start the specified transaction sequence within a vector pattern. This allows pre-compiling (or 鈥榩reparing') the transaction sequence, i.e. to unroll each transaction to a vector stream. As a result the host interface transactions are translated to vector patterns which are embedded in the whole pattern execution including the specified markers. In order to be able to pre-compile a synchronized test sequence, it has to contain static transactions only.

Some documents use 鈥榩repared test', which is a (deprecated) synonym for 鈥榮ynchronized protocol test'. 鈥楽ynchronized test' is a short form of this terminology.
