# Timing of DC events

A minimum execution time must be respected when using DC event based programming of DC Scale cards.

For forcing events, the execution time to be respected is influenced by the following factors:

- 32 vectors are required to transfer the data from the pattern memory to the front end. The 32 vectors must be respected as minimum distance between DC events.

Actions on the front end are normally triggered latest at the end of last of the 32 vectors.

- The front end needs some time for internal data processing.
- Some settling time is required for the outputs of the front end.

For measuring events, the execution time to be respected depends on the following factors:

- Some settling time is required for inputs of the front end.
- The ADC needs some time to digitizing the input signal. The required time is defined by the sampling frequency of the ADC and the number of averaged samples set for measurement. The number of averaged samples is defined for example by function averages() of [EVENT_VM](<02.07.04.01.63.26_EVENT_VM.md>).
- Some more time may be required for data processing in the front end.
- The transfer of the measured value from the front end to the back end requires a defined number of vectors after digitizing and data processing has been finished in the front end. Dummy vectors are to be inserted at the end of the pattern if no more functional vectors are required to control the front end. Violating this requirement results in loss of sampled data.
 Note [SmartRDI](<02.07.13_SmartRDI.md>) considers the well-defined settling times and vectors as defined in the topics of this section and therefore simplifies programming using DC Events. Just the settling time of the DUT and the signal settling time at the inputs of the front end must be considered by the user.
