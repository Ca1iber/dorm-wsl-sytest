# TESTNUMBER

The `TESTNUMBER` class is used for several purposes related to test numbering. `TESTNUMBER` is used to assign test numbers to test results in a test method. This involves assigning offset, increment, and number of call (iteration) values to tests. `TESTNUMBER` is also used to retrieve test number values with the [GET_TESTNUMBER()](<02.07.04.01.99_GET_TESTNUMBER.md>) API and to initiate iterations of test number results.

An important use of `TESTNUMBER` functions, in conjunction with the [TESTSET()](<02.07.04.01.244_TESTSET.md>) class, is to implement numbering procedures, such as assigning default values to a test numbering sequence.

Test numbers are affected by other factors in addition to those described in this topic and in [TESTSET()](<02.07.04.01.244_TESTSET.md>), and [GET_TESTNUMBER()](<02.07.04.01.99_GET_TESTNUMBER.md>). For example, you can enter loop iterations and global increment numbering parameters by using the [Testflow Tool](<../02.08_Setup_and_Result_Tools/02.08.04.32_Testflow_Tool.md>). This will result in modifying the test numbers that would be derived by using these APIs. For a detailed explanation of how you can modify numbering values using these features, see [Test Number Generator and TMLimits](<../02.10_Data_Logging/02.10.01.08.01_Test_Number_Generator_and_TMLimits.md>) in [Data Logging](<../02.10_Data_Logging/02.10_Data_Logging.md>).

For an explanation of other factors that can affect test numbering, see the [Managing Test Numbers](<../02.10_Data_Logging/02.10.01.08_Managing_Test_Numbers.md>) section of the event data logging documentation.

Note To enable test numbering in the [Testflow Tool](<../02.08_Setup_and_Result_Tools/02.08.04.32_Testflow_Tool.md>) the test_number_enable testflow flag must be set. See the [Managing Test Numbers](<../02.10_Data_Logging/02.10.01.08_Managing_Test_Numbers.md>) section of the event data logging documentation for an explanation of enabling both default and user-selected numbering parameters.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TestNumber_r.h.

## Syntax

In the case of TESTNUMBER, there is no use case to use a temporary object. You will assign your own object when using TESTNUMBER.

```
User object (TESTNUMBER obj(offset,increment));
obj.member_func();
```

Users can use obj as an argument of TESTSET.testnumber() member_func(); or call obj.method();

## Constructor

### TESTNUMBER()

```
TESTNUMBER(int offset, int increment);
```

The constructor `TESTNUMBER (int offset, int increment);` creates the class object that contains the specified test number offset and test number increment values. Note that numberofcalls is set to -1. For parameters, see the setOffset() and setIncrement() member functions in the Member Function below.

### Member functions

Some of the following TESTNUMBER member function descriptions use the term "subtest test number". This is a subtest number assigned to each test in a test suite (or a test method) that is passed to the Test Number Generator, and is based on the following calculation:

```
subtest test number = offset + increment * (number of calls)
```

The numbers assigned to a test result can be modified and are affected by default and user-selectable numbering parameters.

### applyTestNumber()

```
int applyTestNumber();
```

This member function increments the number of calls and returns the current value of the subtest test number.

```
(number of calls) = (number of calls) + 1
(subtest Test Number) = (offset) + (increment) * (number of calls)
```

Parameters none

### getTestNumber()

```
getTestNumber() const;
```

This member function returns the current value of the subtest Test Number, which is calculated according to the following formula:

```
(subtest Test Number) = (offset) + (increment) * (number of calls)
```

Parameters none

### getOffset ()

```
int getOffset() const;
```

This member function returns the current setting value of the offset.

Parameters none

### getIncrement ()

```
int getIncrement() const;
```

This member function returns the current setting value of the increment.

Parameters none

### getNumberOfCalls ()

int getNumberOfCalls() const;

## Example

The example below demonstrates how the TESTNUMBER class can be used with the TESTSET class, and specifically illustrates the use of the getOffset, getIncrement, setOffset, setIncrement, and applyTestNumber member functions.

The test name "SDC_6" is defined. Its offset is set to 3000 and increment is set to 50.

```
TESTNUMBER sdc6 = GET_TESTNUMBER("SDC_6");
if (sdc6.getOffset()<=0){
  sdc6.setOffset(1000);
}
if(sdc6.getIncrement()<=100{
  sdc6.setIncrement(250);
}
TestSet.testnumber(sdc6.applyTestNumber()).TEST();//3000+250*0=3000
TestSet.testnumber(sdc6.applyTestNumber()).TEST();//3000+250*1=3250
TestSet.testnumber(sdc6).TEST();//3000+250*2=3500
TestSet.TEST();//3000+250*3=3750
```

In this example, the getOffset and getIncrement commands retrieve the offset and increment values that have been assigned for SDC_6. The increment value of 250, implemented through the setIncrement command, is applied. The applyTestNumber member function initiates an iteration based on the number of calls, and returns the resulting test number value.

Note The TESTNUMBER() class can be used with the TESTSET() class to work as an API for executing test numbering procedures, such as assigning default values, assigning offset and increment values, and deactivating test numbering for a tes tsuite. See the [TESTSET()](<02.07.04.01.244_TESTSET.md>) examples section for a set of examples that show the use of TESTNUMBER member functions with [TESTSET()](<02.07.04.01.244_TESTSET.md>). You may also want to look at the [GET_TESTNUMBER()](<02.07.04.01.99_GET_TESTNUMBER.md>) API examples section to learn how GET_TESTNUMBER() can be used with the TESTNUMBER().
