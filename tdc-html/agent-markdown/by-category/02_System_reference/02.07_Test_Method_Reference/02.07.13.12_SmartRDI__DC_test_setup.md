# SmartRDI: DC test setup

#### Subtopics

- [DC test with digital channels](<02.07.13.12.01_DC_test_with_digital_channels.md>)
- [Setting up DC Scale pins with SmartRDI](<02.07.13.12.02_Setting_up_DC_Scale_pins_with_SmartRDI.md>)

SmartRDI supports DC tests with PPMU, BADC, and DC Scale on V93000.

To do static DC tests, use the code鈥慴ased mode. To do dynamic DC tests, use the pattern鈥慴ased mode.

- Pattern-based commands only trigger actions that you have specified. Although it is rare, there are some pattern鈥慴ased commands that do not follow this rule, for example, commands for TMU connections.
- Code-based commands can contain default settings if the related parameters have not been specified. The default settings are applied in each separate command (.execute()). For examples,

```
// For DPS128 pin
rdi.dc().pin("P1_DPS128").vForce(1 V).iForceRange(150 mA).execute(); // range=200mA, iClamp=150mA, min/max=150mA
rdi.dc().pin("P1_DPS128").disconnect();
rdi.dc().pin("P1_DPS128").vForce(1 V).execute(); // range=1000mA, iClamp=500mA, min/max=500mA

```

- Recommendations:

  - If you are not to use default values for parameters used for connecting pins, specify all the relevant parameters in code鈥慴ased commands.
  - Use code鈥慴ased commands only for connection or disconnection of pins and put all other commands inside an RDI_BEGIN/RDI_END block.
  - If you need to execute setups or measurements in code鈥慴ased commands, specify all relevant parameters in each .execute().
  - Set [RDI_INFO_LEVEL](<02.07.13.06_RDI_INFO_LEVEL.md>) = 1 or 3 and then verify the execution events of code鈥慴ased commands in the UI_Report log; or check the HW-Monitor.

  Note In a command as `rdi.dc().pin(A)...pin(B)...execute()`:

- If pin A and pin B are the same type, for example, both are DC Scale pin or digital channel, pin A and pin B will act in parallel.
- If pin A and pin B are not the same type, for example, pin A is a DC Scale pin and pin B is a digital channel pin, pin A and pin B will act in serial order.
