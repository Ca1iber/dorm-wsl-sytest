# TASK_LIST

The TASK_LIST class is a data container holding PPMU_SETTING, PPMU_RELAY, and PPMU_MEASURE tasks to be performed.

 Tasks to be performed with this class are defined with the [PPMU_SETTING](<02.07.04.01.160_PPMU_SETTING.md>), [PPMU_RELAY](<02.07.04.01.158_PPMU_RELAY.md>) and [PPMU_MEASURE](<02.07.04.01.157_PPMU_MEASURE.md>) class. Each task will be performed in order of the definition of the task list.

## Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TaskList.h.

  Constructor

```
TASK_LIST();
```

This constructor defines a task list that holds task names to be executed.

Parameters

There are no parameters associated with this function.

  Member functions:

- [add()](<02.07.04.01.240_TASK_LIST.md#_29792__dle_add>)
- [setup()](<02.07.04.01.240_TASK_LIST.md#_29792__dle_setup>)
- [execute()](<02.07.04.01.240_TASK_LIST.md#_29792__dle_execute>)

## Usage

For creating an object:

```
TASK_LIST <object>;
```

For setting up tasks to be performed:

```
<object>.add(task1).add(task2)...add(taskN);
```

For downloading the settings in tasks:

```
<object>.setup();
```

For downloading the settings in tasks and performing the tasks:

```
<object>.execute();
```

 |

<object>

 |

Object name to be defined

 |
 |

task1-N

 |

Object name of the PPMU_SETTING, PPMU_RELAY or PPMU_MEASURE class to specify a task to be performed. A task list can contain up to 10 tasks.

 |

## Member functions

  add()

```
TASK_LIST & add(const TASK& task);
```

This function adds the specified task to the task list. Added tasks are performed sequentially.

 Note If you define a TASK_LIST object as global, the object will not be destroyed when the test method is completed. This will have the effect that the list grows longer with every testflow repetition, so that the test time is increased with every repetition.

Parameter
 |

task

 |

Object name of the PPMU_SETTING, PPMU_RELAY or PPMU_MEASURE class to specify a task be performed.

 |

Using the offline result emulation function:

Measurements can be made by using [DPS_TASK](<02.07.04.01.50_DPS_TASK.md>), [SPMU_TASK](<02.07.04.01.234_SPMU_TASK.md>), and [PPMU_MEASURE](<02.07.04.01.157_PPMU_MEASURE.md>) objects directly (by calling their execute() member functions) or be put in a TASK_LIST object which queues up tasks to be executed (by calling the execute() method on the TASK_LIST object rather than on the task objects themselves). This requires an enhancement also on the TASK_LIST add() method which takes a measurement name as additional parameter.

```
TASK_LIST& add(const TASK& task)
```

This is the existing function which adds the specified task to the task list.

```
TASK_LIST& add(const TASK& task, const string& measurementName)
```

This function adds the specified task to the task list.

Parameter

 |

measurementName

 |

Associate the measurement that will be executed by calling `task_list.execute()` with offline data.

 |

For more details, see [Parametric offline result emulation](<02.07.12.06.02_Parametric_offline_result_emulation.md>) in [Offline Result Emulation](<02.07.12_Offline_Result_Emulation.md>).

  setup()

```
void setup();
```

This function downloads settings defined in the task list. The tasks of the task list are executed sequentially in the registered order. It is used when the input parameters of the task are changed during the test method execution. It can change the parameters of an exisiting MSET and reuse it to avoid running out of MSETs. (Refer to [FlexDC](<../../03_Use_cases_and_application_papers/03.01_Performance_Cookbook__How_to_reduce_test_times/03.01.05.02_FlexDC.md>) and [Managing DC Tests with Variable Parameters](<02.07.03.02.06.03_Managing_DC_Tests_with_Variable_Parameters.md>) for details.)

Parameters

There are no parameters associated with this function.

  execute()

```
void execute();
```

This function performs a test by executing the task list. The tasks of the task list are executed sequentially in the registered order.

Parameters

There are no parameters associated with this function.

 Note After the execute() function is performed, you cannot define any tasks for the digital pin that is not included to the performed task. For example, the following program defines and executes the "tasks" task list.

```
PPMU_SETTING setting1;
TASK_LIST    tasks;

tasks.add(setting1);

setting1.pin("pin1").vForce(2.1 mV);
setting1.pin("pin1").iRange("10uA");
setting1.pin("pin1").min(0.1 uA).max(5.0 uA);

tasks.execute();
```

After that, you can modify or define tasks for "pin1" as shown below:

```
setting1.pin("pin1").vForce(2.5 mV); // OK
```

However, error occurs if the following program is performed because tasks for "pin2" is not defined in the "tasks" task list.

```
setting1.pin("pin2").vForce(2.1 mV);  // error
```

## Example

In the following example, the task setting, precharge, relay_on, relay_off, ppmuMeasure, clamp_on and clamp_off are defined and added to the task list. Then a PPMU measurement is performed by executing the task list.

```
PPMU_SETTING   ppmuSetting;
PPMU_RELAY     ppmuRelay_on, ppmuRelay_off;
PPMU_MEASURE   ppmuMeasure;
PPMU_CLAMP     ppmuClamp_on, ppmuClamp_off;
TASK_LIST      taskList_1;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Setups for PPMU
    //
    ppmuSetting.pin("S0").iRange(1 mA).min(0 V).max(4.3 V).iForce(10 uA);
    ppmuSetting.pin("S1").iRange(10 mA).min(-10 uA).max(30 uA).vForce(3.3 V);

    //
    // Relay setups
    //
    ppmuRelay_on.pin("S0,S1").status("PPMU_ON");
    ppmuRelay_on.wait(1.3 ms);
    ppmuRelay_off.pin("S0,S1").status("AC_ON");

    //
    // Measurement setups
    //
    ppmuMeasure.pin("S0,S1").execMode(TM::PVAL);

    //
    // Hardware specific programming to avoid hot switching on the current force setup
    //
    ppmuClamp_on.pin("S0").status("CLAMP_ON").low(2.6 V).high(2.9 V);
    ppmuClamp_off.pin("S0").status("CLAMP_OFF");

    //
    // Build and execute the task list
    //
    taskList_1.add(ppmuSetting)
              .add(ppmuClamp_on)
              .add(ppmuRelay_on)
              .add(ppmuClamp_off)
              .add(ppmuMeasure)
              .add(ppmuRelay_off);

    taskList_1.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and Datalog
//
double VMeas, IMeas;

VMeas = ppmuMeasure.getValue("S0");
IMeas = ppmuMeasure.getValue("S1");

TEST("DC_Test",ppmuMeasure, true);
```

The following example shows how to measure a current on a device pin and then use it as a force value for a following measurement for multi-sites. The result value of the first measurement differs from site to site.

```
PPMU_MEASURE ppmuMeasure2;

ON_FIRST_INVOCATION_BEGIN();

    PPMU_MEASURE ppmuMeasure1;
    PPMU_SETTING ppmuSetting1,ppmuSetting2;
    PPMU_RELAY   ppmuRelayOn, acRelayOn;
    TASK_LIST multiDeltaFlexDc1, multiDeltaFlexDc2;

    // 1st measurement
    ppmuSetting1.pin("I/O1").vForce(0 V).iRange(1 uA).max(1 uA).min(-1 uA);
    ppmuRelayOn.pin("I/O1").status("PPMU_ON");
    ppmuRelayOn.wait(1.3 ms);
    ppmuMeasure1.pin("I/O1").execMode(TM::PVAL);
    acRelayOn.pin("I/O1").status("AC_ON");
    multiDeltaFlexDc1.add(ppmuSetting1).add(ppmuRelayOn).add(ppmuMeasure1);
    multiDeltaFlexDc1.execute();

    // dummy setting for avoiding DC set run out
    ppmuSetting2.pin("I/O1").iForce(0 uA).iRange(1 mA).max(0.5 V).min(-0.5 V);
    ppmuSetting2.wait(1 ms);
    ppmuMeasure2.pin("I/O1").execMode(TM::PVAL);
    multiDeltaFlexDc2.add(ppmuSetting2).add(ppmuMeasure2).add(acRelayOn);
    multiDeltaFlexDc2.setup();

    // 2nd measurement
    FOR_EACH_SITE_BEGIN();

        ppmuSetting2.pin("I/O1")
                .iForce(ppmuMeasure1.getValue("I/O1"))
                .iRange(ppmuMeasure1.getValue("I/O1"))
                .max(0.5 V)
                .min(-0.5 V);

    FOR_EACH_SITE_END();

    multiDeltaFlexDc2.execute();

ON_FIRST_INVOCATION_END();

TEST("I/O1",
     "multi_delta",
     ppmuMeasure2.getPassFail("I/O1")?TM::Pass:TM::Fail,
     ppmuMeasure2.getValue("I/O1"),
     true );
```
