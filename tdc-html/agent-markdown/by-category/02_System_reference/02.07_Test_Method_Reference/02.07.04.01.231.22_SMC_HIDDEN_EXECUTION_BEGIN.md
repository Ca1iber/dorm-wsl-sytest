# SMC_HIDDEN_EXECUTION_BEGIN()

The SMC_HIDDEN_EXECUTION block in the SMC_backgroundProcessing() function is defined by SMC_HIDDEN_EXECUTION_BEGIN() and SMC_HIDDEN_EXECUTION_END(). The block marks a section in a background process where non-SMC APIs can access the tester hardware. The execution of the code within the block is controlled by the SmartCalc framework and triggered by SMC APIs like SMC_FUNCTIONAL_TEST(), SMC_WAIT_TIME() or the SMC_BACKGROUND block in the run() function of a test method class.

SMC_HIDDEN_EXECUTION_BEGIN() and [SMC_HIDDEN_EXECUTION_END()](<02.07.04.01.231.23_SMC_HIDDEN_EXECUTION_END.md>) are intended to be used in the [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) function of a test method class and must always be implemented together.

## Principle of operation

Creating background processes by the [SmartCalc framework](<02.07.10_SmartCalc_framework.md>) may result in conflicts if both the run() function of a test method class and an [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) function access the tester hardware at the same time.

The SmartCalc framework can therefore perform hidden uploads only if the tester hardware is not accessed by another process. Identifying these time slots and using them in a background process is done automatically if only SMC APIs are used in the run() function and in the background process.

For non-SMC APIs, separate handling is required for test time consuming sections of the run() function and for hardware access in a background process:

-

The [SMC_BACKGROUND](<02.07.04.01.231.06_SMC_BACKGROUND_ENABLE.md>) block in the run() function encloses non-SMC APIs that do not access the tester hardware. This block allows hidden uploads while the code in the block is executed.

- An SMC_HIDDEN_EXECUTION block in the background process encloses non-SMC APIs that access the tester hardware. The SmartCalc framework executes the code in the block only while no other process accesses the tester hardware.

Access from a background process to the tester hardware using non-SMC APIs must therefore be restricted as follows:

- All non-SMC APIs that access the tester hardware must be enclosed by an SMC_HIDDEN_EXECUTION block.
- The execution of the code within the SMC_HIDDEN_EXECUTION block is delayed until access to the tester hardware has been granted by the SmartCalc framework.
- The access to the hardware is granted while the following APIs are executed in the run() function of a test method class:

  - [SMC_DIGITAL_CAPTURE_TEST()](<02.07.04.01.231.08_SMC_DIGITAL_CAPTURE_TEST.md>)
  - [SMC_EXECUTE_TEST()](<02.07.04.01.231.11_SMC_EXECUTE_TEST.md>)
  - [SMC_FUNCTIONAL_TEST()](<02.07.04.01.231.13_SMC_FUNCTIONAL_TEST.md>)
  - [SMC_WAIT_TEST_DONE()](<02.07.04.01.231.52_SMC_WAIT_TEST_DONE.md>)
  - [SMC_WAIT_TIME()](<02.07.04.01.231.53_SMC_WAIT_TIME.md>)
  - [SMC_BACKGROUND block](<02.07.04.01.231.06_SMC_BACKGROUND_ENABLE.md>)

- The access granting API or SMC_BACKGROUND block may be in the run() function of any test method class that is executed after the SMC_HIDDEN_EXECUTION block of the background process has been reached.
    Note The SmartCalc framework cannot upload data in the background if this upload is done within an SMC_HIDDEN_EXECUTION block and there is no access granting SMC API or SMC_BACKGROUND block in a run() function.

## Syntax

```
SMC_HIDDEN_EXECUTION_BEGIN();
```

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.

  List of parameters There are no parameters. Return value There is no return value.

## Example

### SMC_HIDDEN_EXECUTION example

The example consists of two test suites which have to be executed in succession:

- Test method class Test_1_SMC_HIDDEN_EXECUTION arms a thread per site using [Syntax](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_ARM>). The [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) function utilizes an SMC_HIDDEN_EXECUTION block. For a real test, the block will enclose non-SMC APIs that access the tester hardware. The example emulates the time for processing by a singe wait time of 2 ms.
- Test method class Test_2_SMC_HIDDEN_EXECUTION uses the SMC APIs [SMC_WAIT_TIME()](<02.07.04.01.231.53_SMC_WAIT_TIME.md>) and [SMC_FUNCTIONAL_TEST()](<02.07.04.01.231.13_SMC_FUNCTIONAL_TEST.md>) within the ON_FIRST_INVOCATION block and an [SMC_BACKGROUND block](<02.07.04.01.231.06_SMC_BACKGROUND_ENABLE.md>) that is executed for each active site. The APIs and the SMC_BACKGROUND block allow hidden uploads in the background as long as they do not need access to the tester hardware for their own purpose.
Some items to consider for the example:

- The example utilizes an optional pair of curly brackets "{" and "}" for the ON_FIRST_INVOCATION block, the SMC_HIDDEN_EXECUTION block and the SMC_BACKGROUND block. These optional curly brackets are used for simplifying the correct indentation with assistance of the related Eclipse tool.
- The example shows only how to use the SMC_HIDDEN_EXECUTION block and contains therefore no real test code.

Test method class for the first test suite:

```
#include "testmethod.hpp"
#include "mapi.hpp"

using namespace std;

class Test_1_SMC_HIDDEN_EXECUTION: public testmethod::TestMethod {

protected:

    virtual void initialize()
    {
    }

    virtual void run()
    {
        STRING testName;

        GET_TESTSUITE_NAME(testName);

        ON_FIRST_INVOCATION_BEGIN();
        {
            //
            // Your test
            //
            // ...
        }
        ON_FIRST_INVOCATION_END();

        cout << testName << " - run(): " << "Arming SMC thread for site " << CURRENT_SITE_NUMBER() << endl;

        SMC_ARM();

        return;

    } // virtual void run()

public:

    virtual void SMC_backgroundProcessing()
    {
        STRING testName;

        SMC_GET_TESTSUITE_NAME(testName);

        cout << setw(50) << "" << testName << ": Entering SMC thread for site " << SMC_SITE_NUMBER() << endl;

        SMC_HIDDEN_EXECUTION_BEGIN();
        {
            cout << setw(50) << "" << testName << ": Site " << SMC_SITE_NUMBER() << " Non-SMC APIs in SMC_HIDDEN_EXECUTION block" << endl;

            //
            // Wait time emulates time for processing
            //
            WAIT_TIME (2.0 ms);
        }
        SMC_HIDDEN_EXECUTION_END();

        cout << setw(50) << "" << testName << ": Leaving SMC thread for site " << SMC_SITE_NUMBER() << endl;

    } // virtual void SMC_backgroundProcessing(ARRAY_I& activeSites)
};

REGISTER_TESTMETHOD("Test_1_SMC_HIDDEN_EXECUTION", Test_1_SMC_HIDDEN_EXECUTION);

```

Test method class for the second test suite:

```
#include "testmethod.hpp"
#include "mapi.hpp"

using namespace std;

class Test_2_SMC_HIDDEN_EXECUTION: public testmethod::TestMethod {

protected:

    virtual void initialize()
    {
    }

    virtual void run()
    {
        STRING testName;

        GET_TESTSUITE_NAME(testName);

        ON_FIRST_INVOCATION_BEGIN();
        {
            cout << testName << " - run(): " << "SMC_WAIT_TIME - 5 ms settling time" << endl;

            SMC_WAIT_TIME(5.0 ms);

            cout << testName << " - run(): " << "SMC_FUNCTIONAL_TEST" << endl;

            SMC_FUNCTIONAL_TEST();
        }
        ON_FIRST_INVOCATION_END();

        cout << testName << " - run(): " << "SMC_BACKGROUND_ENABLE for site " << CURRENT_SITE_NUMBER() << endl;

        SMC_BACKGROUND_ENABLE();
        {
            //
            // Wait time emulates time required for calculations
            //
            // No access to tester hardware in this block!
            //
            WAIT_TIME(5 ms);
        }
        SMC_BACKGROUND_DISABLE();

        cout << testName << " - run(): " << "SMC_BACKGROUND_DISABLE" << endl;

        return;

    } // virtual void run()
};

REGISTER_TESTMETHOD("Test_2_SMC_HIDDEN_EXECUTION", Test_2_SMC_HIDDEN_EXECUTION);

```

Note

The example above contains several calls of cout in function [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to [Thread safety](<02.07.10.02.02_Thread_safety.md>).

 For a test program with four configured and enabled site, the code above results in an output in the ui_report window similar to the following text:

The output in the ui_report shows the following behavior of the example code:

- A thread for each active site is armed in the run() function of test suite Test_1.
- The background process of Test_1 processes the first two sites while the SMC_WAIT_TIME() is executed in Test_2.
- The SMC_HIDDEN_EXECUTION block of the next site is executed while a functional test, started by SMC_FUNCTIONAL_TEST() is running.
- The last site is processed while calculations are emulated in the SMC_BACKGROUND block of Test_2.
