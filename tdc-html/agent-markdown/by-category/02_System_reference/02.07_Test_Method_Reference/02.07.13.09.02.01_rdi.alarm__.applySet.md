# rdi.alarm().applySet()

Specifies an alarm set, which has been defined in your alarm setup file, to be applied in the current test suite.

## Syntax

```
rdi.alarm().applySet(string alarmSet);
```

If you do not use this command to specify an alarm set, the DEFAULT set defined in the alarm setup file is applied by default.

This command can be put either inside or outside of an RDI_BEGIN()/RDI_END() block. When you put this command inside an RDI_BEGIN()/RDI_END() block, you cannot add another pin that has not been initially applied for this RDI_BEGIN()/RDI_END() block.

The application scope of this command is just in this test suite. The next test suite will use the default limit settings again.

The execution order of applySet() and enable() in the code does impact on the result.

- If the applySet() command is executed after the enable() command, for example,

```
rdi.alarm().enable(false);
rdi.alarm().applySet(alarmSet); // Alarm set enabled and applied
```

The applySet() command overwrites the enable(false) command. So the alarm set is enabled and applied.

- If the applySet() command is executed before the enable() command, for example,

```
rdi.alarm().applySet(alarmSet); // Alarm set enabled and applied
rdi.alarm().enable(false); // Alarm checking disabled
```

The alarm checking is disabled by the enable(false) command.

See the example in [Alarm handling commands](<02.07.13.09.02_Alarm_handling_commands.md>).
