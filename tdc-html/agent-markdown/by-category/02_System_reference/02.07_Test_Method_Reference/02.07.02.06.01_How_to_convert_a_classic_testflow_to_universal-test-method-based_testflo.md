# How to convert a classic testflow to universal-test-method-based testflow

#### Subtopics

- [AC test function conversion](<02.07.02.06.01.01_AC_test_function_conversion.md>)

## Before you begin

The conversion tool is available with SmarTest 6.3 or later. Make sure that

- the original testflow is valid.
- the classic test methods used in the testflow are registered correctly.

## Procedure

- Change to the device testflow directory.
- In the command line, type the following command:

/opt/hp93000/soc/testmethod/bin/convertTestflow [-t type]

[-f rename_configure_ file1[...][,fileN]]

<classic_testflow_file>

<new_testflow_file>

[log_file]

[-t type]: (optional) The conversion type. It can be TM for only converting classic-test-method-based test suites and FULL for converting both test-function-based test suites and classic-test-method-based test suites. Default value is FULL.

[-f rename_configuration_ file1[,...][,fileN]]: (optional) Input configuration files for re-mapping of classic test methods in a classic testflow to universal test methods in a new testflow. This parameter is only effective for the conversion of classic-test-method-based test suites. The re-mapping includes test method project name, test method name and test method parameters. This re-mapping is necessary if you want to define new names which are different from the default testflow conversion naming. For example:

  - the universal test method project name is different from the classic test method project name;
  - or the universal test method name is different from the combination of the classic test method class name plus '_' and the classic test method name;
  - or the parameters of a universal test method are different from the parameters of a classic test method.

The syntax rule `if_match` is provided to convert the classic test methods that match the specified conditions to universal test method. The syntax rule `if_not_match` is provided to convert the classic test methods that do not match the specified conditions to universal test method.

To create a renaming configuration file, refer to the template file /opt/hp93000/soc/testmethod/include/testflow_conversion_config.template.

<classic_testflow_file>: file name of classic testflow.

<new_testflow_file>: file name of new format testflow

[log file]: (optional) The file to log the information of the test functions which have no equivalent test methods in the libraries. If not specified, the default file /tmp/convertTestflow.unconverted_tf_log_file will be used.

 Note Make sure that the mapping relation is unique in all the configuration files and that the mapping information exists in the test method project.

- (optional) Manually convert the test functions which have no equivalent test methods in the libraries according to the log file.
- (optional) If you linked some other libraries in your classic test method, you need to manually link these libraries in the converted universal test method. About how to link the libraries in UTM, see [Using C/C++ functions from external libraries in universal test methods](<02.07.02.11_Using_C_C___functions_from_external_libraries_in_universal_test_methods.md>).

## Results

If the conversion is completed successfully, you will get a converted testflow file as specified. The test method part in the new testflow file includes three parts: `testmethodparameters`, `testmethodlimits` and `testmethods`.

In the following cases, an information message will be sent out:

- The classic test method is not used by any test suite, and it is removed from the new testflow file.
- For the conversion of test-function-based test suites, if there is no equivalent predefined test method, the test function will be mapped to the most proper test method in the new testflow. The warning message will be issued telling that the test function is mapped to a test method and asking you to do manual conversion.

If the classic testflow is invalid, the re-mapping configuration file is incorrect, or the new testflow path is invalid, the conversion will stop with errors.

## Examples

### Classic-test-method-based test suite conversion

In the following example, the classic testflow /home/demo/devices/74HC299/testflow/myFlow using the classic test method project /home/demo/devices/74HC299/TestMethod/MyTMLib is converted to a universal-test-method-based testflow.

Enter the following command in the command line:

cd /home/demo/devices/74HC299/testflow/

/opt/hp93000/soc/testmethod/bin/convertTestflow -t -TM myflow myflow.utm

The test method part in the classic testflow and the universal-test-method-based testflow are listed below.

 |

 In classic testflow

 |

In universal-test-method-based testflow

 |
 |

`testmethods`

`tm_1:`

`testmethod_class = "MyTMLib.ClassDcTest";`

`testmethod_name = "myMethod(STRING, )";`

`testmethod_parameters = "@:";`

`testmethod_limits = ":test_number:DEFAULT FUNCTIONAL TEST;80;2:passCurrentLow;10;1;[;10;]40:passCurrentHigh;20;1;[;30 uA;]50 uA:extraLimit;200;2;[;5;];100:";`

`end`

 |

`testmethodparameters`

`tm_1:`

`"pinlist" = "@";`

`end`

`----------------------------------`

`testmethodlimits`

`tm_1:`

`"DEFAULT FUNCTIONAL TEST " = "":"":"":"":"80":"2";`

`"passCurrentLow" = "10":"GE":"40":"LE":"": "10":"1";`

`"passCurrentHigh" = "30":"GT":"50:"LE":"uA":"20":"1";`

`"extraLimit" = "5":"NA":"100":"LE":"":"200":"2" ;`

`end`

`----------------------------------`

`testmethods`

`testmethod_class = "MyTMLib.ClassDcTest.myMethod";`

`end`

In the following example, the classic testflow /home/demo/devices/74HC299/testflow/myFlow_tf using the test function leakage is converted to a universal-test-method-based testflow.

Enter the following command in the command line.

cd /home/demo/devices/74HC299/testflow/

/opt/hp93000/soc/testmethod/bin/convertTestflow myflow_tf myflow_tf.utm

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.5.2: Test-function-based test suite can now be conerted to UTM-based test suite.
- SmarTest 6.5.3: New syntax rule if_match and if_not_match of the renaming configuration file.
- SmarTest 6.5.4: New option [log file] to log the unconverted test function information.
