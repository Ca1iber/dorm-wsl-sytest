# Thread safety

SmartCalc only works properly, if the executed code is thread safe.

 A piece of code is thread safe, if it functions correctly during simultaneous execution by multiple threads.

In particular, it must satisfy the need for multiple threads to access the same shared data, and the need for a shared piece of data to be accessed by only one thread at a given time. One typical root cause for issues with multithreading happens if the code uses static variables. Each call may change the state of the local variables differently. If a function is not thread-safe, the calculations need to be executed serially. Since calculation threads can run hidden, the same test time savings can be achieved.

A subroutine is thread-safe, if

- it only uses variables from the stack only
- the execution only depends on the arguments passed in
- further subroutines called have the same properties only.
 Note Your [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) method can only contain thread safe APIs like SMC_... , DSP_..., TESTSET and Wave class APIs to ensure the SmartCalc framework is working properly.

Since the thread safety of the APIs depends sometimes on the used parameters and how the APIs are implemented in the [SMC_backgroundProcessing()](<02.07.04.01.231.01_SMC_ARM.md#_120107__s_SMC_backgroundProcessing>) method, we strongly recommend using always the [Automatic check for thread-safe APIs](<02.07.10.02.02_Thread_safety.md#_118825__s_Automatic_check_for_thread_safe_APIs>) as described in the next section.

## Automatic check for thread-safe APIs

SmarTest automatically checks at run-time whether only thread-safe APIs are used in SMC background threads.

 An error message is thrown in the ui_report window when calling an API that is not thread-safe:

```
Exception is caught on Site ...:
Error:
An illegal call from a SMC_backgroundProcessing() to a TM API has been detected.
API called: ...
A backtrace to identify the problematic API usage is provided below:
*********** Begin Stack Trace ***********
/opt/hp93000/soc/prod_com/...
...
...
************ End Stack Trace ************
The thread is terminated.

Warning: Performing an exception handler: ERROR_EXIT
```

 The automatic check for thread safe APIs can be enabled or disabled through environment variable SMC_CONCURRENCY_CHECKING. Supported values for the variable are

- "ErrorAndLog": An illegal call raises an exception resulting in an error as shown in the example above and logs the issue including the stack trace to a file named SmartCalcSafeChecker.log in the system log directory /opt/hp93000/system/log.
- "LogOnly": Log the issue but otherwise ignore it.
- "Off": Ignore all illegal calls.

The check is enabled by default in "ErrorAndLog" mode if the environment variable is not defined.

CAUTION

Using non-thread-safe APIs in a background process can result in loss off data, invalid data, or a crash of the test method.

Since the automatic check does not require any significant test time, we strongly recommend keeping the automatic check always enabled.
