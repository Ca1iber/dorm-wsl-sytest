# Transaction level function

The transaction level function generates the state character sequence for a single transaction.

It can be specified globally and/or per pin role. If both are defined, the pin role specific function is applied before the global function. Latter then reuses the result of the pin role specific function to modify the SCS.

If no transaction level function is defined the field contents simply will be concatenated in the order of the protocol definition.

Additional allowed parameters are:

- Protocol Constants (<constant>)
- Parameters within the transaction (<parameter>)
- Field symbols of parameters within the transaction (<parameterName>.<symbolName>)
- Other fields within the transaction in the same pin role (@<field>)
- Other fields within the transaction (@<pinRole>.@<field>)
- Concatenation of all encoded fields (@@) per pin role (this is the default function)
- It is explicitly allowed to reference fields of type READ, even though they contain nothing but state character "R"

Possible errors of transaction encoding:

- Transaction length does not match sum of field lengths.
- Reference to unknown field / pin role.

## Example

The following transaction level encode function will append the field `op`, `ta` and 16 bits of field `data` to the leading state characters "00":

"00" + @op + @ta + data[15..0]

The following example shows how the SCS is assembled if no transaction level encode function is used (default function):

@<field 1> + ... + @<field n>
