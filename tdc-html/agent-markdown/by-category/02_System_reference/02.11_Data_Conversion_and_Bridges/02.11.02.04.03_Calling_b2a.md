# Calling b2a

The binary to ASCII (b2a) tool is a command line tool that takes input files as command line arguments and generates ASCII files.

The b2a tool is installed at the following location: /opt/93000/aif/b2a.

The general format of the call is

b2a <options>

The following options can be used:

 |

b2a Option

 |

Description

 |
 |

-p pin_file

 |

Pin configuration file. This option overrides -i.

 |
 |

-c pin_list

 |

List of up to 10 pins. If this parameter is specified, conversion will be executed only for the specified pins.

 |
 |

-t tim_file

 |

SmarTest timing setup file. This option overrides -i.

 |
 |

-f tfl_file

 |

Testflow file. This option overrides -i.

 |
 |

-i input_files_base_name

 |

Specify name (without extension) for input files TIM, TFL, and PIN

 |
 |

-o output_files_base_name

 |

Specify name (without extension) for output files DVC, TMF, AIC, and LOG

 |
 |

-b bcf_file

 |

b2a configuration file. See [Interactive Mode](<02.11.02.04.02.02_Interactive_Mode.md>) and [B2A Configuration File (BCF)](<02.11.02.04.04_B2A_Configuration_File__BCF.md>).

 |
 |

-l log file

 |

Log file. Use this option to specify a name and location for the log file. If you Do not give this option, the log file will be created with the primary name given in -o.

 |
 |

-I (t|v)

 |

b2a interactive translation mode.

-It is b2a timing translation

-Iv is b2a vector translation.

If no -I is given, b2a translation mode is batch mode.

 |
 |

-h

 |

help

 |
 |

-v

 |

b2a tool version information

 |
 |

-F (d|s[n]|w|m|b|c|S|v[n])

 |

d: Process duplicate binary waveforms

 |
 |

 |

s[n]: Insert a space after every n state characters in the ASCII vector file

 |
 |

 |

w: Process every waveform of the wavetable. By default only those waveforms are processed that are included in the #USED WAVEFORMS lines of the respective timing set. This flag must be set if the timing was generated by the ASCII Interface, but additional waveforms were created manually.

 |
 |

 |

v[n]: This option has the following effects in the ASCII vector file:

- Insert CR after n pins in the FORMAT statement
- Add line numbers as comments after the ASCII vectors
- Insert a space after every n state characters in every vector line.
 |
 |

 |

m: Support mixed ASCII dvc's for x-mode factors > 1.

 |
 |

 |

b: This option tells b2a to recover the original ASCII device cycle names from the binary comments (BCMT command) in the binary vector file. aiv generates these comments by default, but they can be suppressed. In this case, b2a will issue an error message.

If both b and c are specified, b prevails.

 |
 |

 |

c: This option tells b2a to use the ASCII device cycle names and state characters of the timing map file, as specified in the configuration file (*.bcf), for the timing retranslation.

This is another option to recover the original ASCII names, and in addition also the original state characters.

If both b and c are specified, b prevails.

 |
 |

 |

S: This option tells b2a to use the selectors and state characters of the state mapping tables, as defined in the wavetable, for the timing retranslation. It is based on the fact that when ait creates state mapping tables, it takes the original ASCII device cycle names as the selectors of these tables, and also uses the state characters of the ASCII timing file for them.

This is a third option to recover the original ASCII names and state characters. Note that this option allows you to reconstruct ASCII dvc's that have been merged into one timing set by ait.

For more information on the state mapping tables see [Representing a pattern in device orientation](<../02.06_Command_Reference/02.06.06.01.03.05_Representing_a_pattern_in_device_orientation.md>) and [ait command line parameters](<02.11.02.02.08.01_ait_command_line_parameters.md>).

 |
 |

-d n

 |

Defines the debug level of b2a. n can take the values 1 through 5. These values have the following meanings:

1: Execution details on the macro level

2: Processing status of implicitly given files

3: Information on creation and update of internal database

4: Information about duplicate binary timing or vector data

5: Detailed messages about tool execution

 |
 |

-V

 |

Specifies a vector setup file. To be used only for pattern conversion with the STATEMAP section. See [STATEMAP section and pattern conversion](<02.11.02.04.01.01_STATEMAP_section_and_pattern_conversion.md>).

 |
 |

-P

 |

Selects a pattern in the vector setup file specified with -V. To be used only for pattern conversion with the STATEMAP section. See [STATEMAP section and pattern conversion](<02.11.02.04.01.01_STATEMAP_section_and_pattern_conversion.md>).

 |
 |

-w

 |

Selects a wavetable in the timing setup file specified with -t. To be used only for pattern conversion with the STATEMAP section. See [STATEMAP section and pattern conversion](<02.11.02.04.01.01_STATEMAP_section_and_pattern_conversion.md>).

 |

Most of the command line options can also be defined in the b2a configuration file or a testflow file. The order of priority is such that that command line options override the configuration file, and the configuration file in its turn overrides the testflow file. If, for example, a timing setup file is specified with the -t command line option, and a b2a configuration file is also specified with the -b option, then the timing setup file specified with -t will be processed, and not the one which is specified in the configuration file. Similarly, if the option -t is not used in the command line, the timing setup file given in the configuration file will be used, and not the one specified in the testflow file.

 Note An exact reconstruction of the original ASCII setup with the options -Fb, -Fc, or -FS is only possible if ait has not optimized the binary setup by the removal of duplicate waveforms. This optimization can be suppressed with the ait parameter -FG.
