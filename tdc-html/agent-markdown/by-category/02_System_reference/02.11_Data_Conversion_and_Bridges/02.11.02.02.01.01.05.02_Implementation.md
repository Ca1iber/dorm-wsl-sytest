# Implementation

Shots are realized by the ASCII interface as follows:

- Every state character definition that contains more than one compare action will be translated into multiple waveforms in the generated wavetable. The total number of these waveforms depends on the number of compare actions and on the number of shots.
- Every shot will have its own timing set.
- The timing map file (*.tmf) will contain different sections for these different timing sets. For any state character definition containing more than one compare action, each of these sections will map the state character in question to a different waveform index.
- In the PATTERNS section of the vector configuration file (see [The PATTERNS Section](<02.11.02.02.01.01_The_PATTERNS_Section.md>)), the one line from the PATTERNS section of the global configuration file will be replaced by n lines for n shots. All of these lines will point to the one ASCII vector file that was specified (explicitly or implicitly) for the pattern in the global configuration file. Every shot has its own pattern configuration file (see [The Pattern Configuration File (*.vbc)](<02.11.02.03.05_The_Pattern_Configuration_File___.vbc.md>)).
- Each of these pattern configuration files will connect the ASCII device cycle specified in the global configuration file to a different timing set.
- In the vector setup file, n patterns will be created. The vectors of these patterns only differ for pins whose state characters have a definition containing more than one compare action.
