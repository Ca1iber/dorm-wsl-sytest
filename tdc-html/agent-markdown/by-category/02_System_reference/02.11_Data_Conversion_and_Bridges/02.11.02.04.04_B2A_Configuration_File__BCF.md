# B2A Configuration File (BCF)

A BCF file can be used as input for batch-mode execution, interactive timing conversion, and interactive vector conversion. There are four constructs in the BCF file:

- B2A_DIR_FILE
- DEFAULT_TMF_FILE
- PATTERNS
- TESTFLOW_TIMINGS.

## B2A_DIR_FILE

The B2A_DIR_FILE section defines the directory paths and the file names for various source and target files as follows:

tmf_dir

specifies the directory path where the TMF files are stored during the interactive vector conversion process. The default value is the current working directory.

binary_dir

specifies the directory path where the binary vector files are stored during batch-mode and interactive vector conversion mode.

avc_dir

specifies the directory path where the ASCII files will be generated during batch-mode and interactive vector conversion mode. The default value is the current working directory.

pinconfig_file

specifies the pin configuration file name.

pin_control_file

specifies the name of the pin control file. This file serves to define the pins for which conversion is actually to be executed. The pins in this file must be a subset of the pins that are configured in the pin configuration file. The individual pin names must be separated by blanks.

pmfl_file

specifies the pattern-master file name.

timing_file

specifies the timing-setup file name.

tfl_file

specifies the testflow file name.

## DEFAULT_TMF_FILE

For the interactive vector conversion, the DEFAULT_TMF_FILE section defines the timing map file (TMF) that has to be used for the patterns that do not have a TMF file specified in the PATTERNS section.

## PATTERNS

The PATTERNS section defines the patterns/labels and the TMF files in the conversion as follows:

binary_file

specifies the binary vector file name. If binary_dir in the B2A_DIR_FILE is given, the binary vector file will be read from the directory binary_dir.

tmf_file

specifies the timing map file name. If tmf_dir in B2A_DIR_FILE is given, the timing map file will be read from the directory tmf_dir. If this is left blank the DEFAULT_TMF_FILE will be used for this particular pattern conversion.

## TESTFLOW_TIMINGS

The TESTFLOW_TIMINGS section is optional. It can be specified instead of a testflow file. It has the format of a table with the following columns:

name

specifies the name of a label that occurs in the binary vector files.

eqn_set

specifies the number of an equation set that occurs in the timing setup file.

timing_set

specifies the number of a timing set that occurs in the specified equation set.

spec_set

specifies the number of a specset that is defined for the specified equation set.

## BCF File Syntax

```
<configuration_file>    ::= [b2a_dir_file] [def_tmf_file] [patterns] [testflow_timings]
<b2a_dir_file>    ::= "B2A_DIR_FILE" <line_sep> ([<comment_line>*] <dir_file_def>)
<dir_file_def>    ::= <dir_file_keyword> <dir_file>
<dir_file_keyword>    ::= "tmf_dir" | "binary_dir" | "avc_dir" | "pinconfig_file" | "pmfl_file" | "timing_file" | "testflow_file"
<dir_file>        ::= Unix file or path (absolute or relative)
<def_tmf_file>    ::= "DEFAULT_TMF_FILE" | <timing_map_file>
<patterns_section>    ::= "PATTERNS" <format_line> <line_sep> <pattern_defs>
<format_line>    ::= ("binary_file" | "tmf_file") +
<pattern_defs>    ::= (<binl_name> | <timing_map_file>) +
<timing_map_file>    ::= valid Unix file name
<binl_file>        ::= valid Unix file name
<comment>        ::= "#" (<any_character_but_not_ linesep>)*
<line_sep>         ::= "\n"
<testflow_timings> ::= "TESTFLOW_TIMINGS" <tt_format_line> <line_sep> <tt_defs>
<tt_format_line> ::= ("name" | "eqn_set" | "timing_set" | "spec_set")
<tt_defs> ::= (<pattern_name> | <equation_set> | <timing_set> | <spec_set>) +
<pattern_name> ::= valid pattern name from <binl_file>
<equation_set> ::= valid equation set number from <dir_file>
<timing_set> ::= valid timing set number from <equation_set>
<spec_set> ::= valid spec set number for <equation_set> from <dir_file>
```

## Example

The following are examples of b2a configuration files. The first example shows a file which is used as input for batch mode execution:

```
B2A_DIR_FILE
timing_file            sample.tim
tfl_file                demo.tfl
```

In this example all input files except the timing setup file are determined by the testflow file demo.tfl. The second example is also intended as the input for batch execution:

```
B2A_DIR_FILE
timing_file            sample.tim
tfl_file                demo.tfl

PATTERNS
binary_file
DEF_ST2.binl.gz
```

In this example not only the timing, but also the global vector file (or pattern master file) specified in the testflow file is overridden, namely by the zipped file DEF_ST2.binl.gz which is specified in the PATTERNS section. Only labels that occur in this file will be retranslated. In particular, labels that are specified in a testsuite of demo.tfl, but do not occur in DEF_ST2.binl.gz, will not be retranslated. You can specify more than one vector file in the PATTERNS section.

The third example uses the TESTFLOW_TIMINGS section instead of a testflow file for batch execution:

```
B2A_DIR_FILE
pinconfig_file        sample.pin
timing_file            sample.tim
pmfl_file             sample.binl

TESTFLOW_TIMINGS
name        eqn_set    timing_set    spec_set
"DEF_ST2"  1         2           1
"DEF_ST3"  1         1           1
```

Here the global binary vector file is defined with the pmfl_file keyword. Note that in spite of its name, you can also specify a binary vector file with this keyword.

The last two examples show configuration files that are generated by the interactive timing retranslation:

```
#Generated by B2A timing translator
B2A_DIR_FILE
pinconfig_file        sample.pin
timing_file            sample.tim
tfl_file                demo.tfl
pmfl_file                sample.binl

PATTERNS
binary_file    tmf_file     # tmf_file or { label  tmf_file }
sample.binl    {
DEF_ST2    DEF_ST2.tmf
DEF_ST3    DEF_ST3.tmf
}
```

The two pairs of label and timing map file at the end of the file tell the vector retranslation which timing map file is to be applied to which label.

If no pmfl_file entry is specified for the interactive timing retranslation in this example, the output configuration file would look as follows:

```
#Generated by B2A timing translator
B2A_DIR_FILE
pinconfig_file        sample.pin
timing_file            sample.tim
tfl_file                demo.tfl

PATTERNS
binary_file    tmf_file     # tmf_file or { label  tmf_file }
DEF_ST2    DEF_ST2.tmf
DEF_ST3    DEF_ST3.tmf
```
