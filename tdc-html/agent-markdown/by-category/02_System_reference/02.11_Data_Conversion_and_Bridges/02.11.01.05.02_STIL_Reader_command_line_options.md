# STIL Reader command line options

The basic operation of the STIL Reader is controlled with command line options.

For more detailed control, a [setup file](<02.11.01.05.03_STIL_Reader_setup_file.md>) can be used. If you use both command line options and a setup file, both affect the conversion process. Where a command line options conflicts with a setting in the setup file, STIL Reader uses the command line option.

## Syntax

The syntax for calling STIL Reader is:

```
stilreader
  [-help]
  [-version]
  [-timestamp]
  [-licwait]
  [-progress]
  [-template]
  [-setup:"setup-file"]
  [-debug]
  [-logfile:"log-file"]
  [-target:"target_platform"]
  [-show_targets]
  [-workdir:"working-directory"]
  [-project_name:"project-name"]
  [-unify_periods]
  [-mask_failing_signals:"failure_log"]
  [-fix_failing_signals:"failure_log"]
  [-pattern_comment:"comment"]
  [-label_suffix:"suffix"]
  [-input_file_type:"file-type"]
  input-file
```

All of the parameters are optional (but see the description of the input file name, the last parameter):

  -help Displays online help. No conversion is performed and no file needs to be specified. -version The version of STIL Reader is output to STDOUT. No conversion is performed and no file needs to be specified. -timestamp A time stamp is added to each line that is output to STDOUT. -licwait If no license is currently available, STIL Reader waits until one becomes available.

If this option is not used, STIL Reader exits with an error message when no license is available.

 -progress A progress bar is displayed while the STIL file is converted. -template

A template for a [setup file](<02.11.01.05.03_STIL_Reader_setup_file.md>) is created. No conversion is performed and no file needs to be specified.

The template file is created in the current directory and is named stilreader_setup_template.setup. Its contents depends on the setting of the -target option (see below).

Note that a setup template that is compatible with SmarTest 8 is created only when `target="93000SMT8"` is specified.

  -setup

The setup file to use. You can specify the file using a relative or absolute path; relative paths are based on the current directory.

Command line parameters (-target, -workdir, -project_name and the specified input file) override conflicting settings in the setup file.

See [STIL Reader setup file](<02.11.01.05.03_STIL_Reader_setup_file.md>) for a description of setup files.

  -debug

A file with a copy of the STIL environment data (not including pattern objects) is generated.

This option is intended for debugging purposes.

  -logfile

The file to which STIL Reader writes any messages generated during the translation process. You can specify the file using a relative or absolute path; relative paths are based on the current directory.

If this parameter is not specified, STIL Reader does not create a log file.

  -target

The type of V93000 architecture for which the files are to be converted. This must always be "93000SMT8". (STIL Reader also supports the "93000SD", "93000DD", and "93000SS" options, but the resulting output files are compatible only with SmarTest versions before 8.0.)

If you call STIL Reader with a setup file (see -setup, above) which specifies the target architecture with the target parameter, you can omit this command line parameter. However, if that is not the case, you must specify -target on the command line because the output would otherwise be incompatible with SmarTest 8.

  -showtargets A list of available targets (valid values for the -target parameter described above) is output to STDOUT.  -workdir

The directory in which the output files are saved. You can specify the directory using a relative or absolute path; relative paths are based on the current directory.

By default, the working directory is the output subdirectory of the current directory. STIL Reader creates the working directory if it does not yet exist.

You can optimize the performance of STIL Reader by specifying an output directory on a different physical drive from where the input file is located.

  -project_name The base name for naming the generated program blocks. If no base name is specified, "project" is used. -unify_periods

V93000 test systems require that the same tester period length is used throughout a pattern, unless the CTIM command is used, which is not always desirable. If the input pattern contains multiple tester periods, specifying this option causes STIL Reader to find the largest common denominator of all occurring periods and to use that as the tester period for the created V93000 patterns.

We recommend not to use this setting for SmarTest 8.

  -mask_failing_signals

failure_log is the location of a failure log file, specified as an absolute or relative path.

If this option is specified, all compare operations for these signals are replaced with X (compare Do not care).

  -fix_failing_signals

failure_log is the location of a failure log file, specified as an absolute or relative path.

If this option is specified, all expected values for these signals are replaced with the actual measured values so that all comparisons pass.

  -pattern_comment comment is a string that is added as a comment to the first vector in each generated pattern file. -label_suffix

suffix is a string that is added as a suffix to the names of all pattern and burst labels generated by STIL Reader.

  -input_file_type  The type of the specified input file (see below). Supported file types include:

- STIL
- WGL
- TDL
- SVF
- AIF

This is an optional parameter. If it is not specified, STIL Reader determines the file type from the filename extension.

  input-file

The final parameter input-file is the file that is to be converted. The file must be in the STIL, ASCII Interface, WGL, or TDL formats. Its location can be specified as an absolute or relative path; relative paths are based on the current directory.

This parameter is mandatory if you want to actually transform a STIL file. It is ignored, however, if the -help or the -version option is used.

## Examples

### Example 1

This is a sample call to STIL Reader:

stilreader -timestamp -licwait -setup:"setup/mySetup.setup" -target:"93000SD" workdir:"Output" myStilFile.stil

### Example 2

Setting the -unify_periods creates periods of the same length throughout the STIL pattern. For example, a pattern may look like this before the periods are unified:

```
Timing {
  WaveformTable t1 {
    Period '100ns';
    Waveforms {
      clk { P { '0ns' D; '25ns' U; } }
      data { 01 { '50ns' D/U; } }
    }
  }
  WaveformTable t2 {
    Period '150ns';
    Waveforms {
      clk { P { '0ns' D; '75ns' U; } }
      data { 01 { '100ns' D/U; } }
    }
  }
}

Pattern P1 {
  W t1;
  V { clk = P; data = 0; }
  V { clk = P; data = 1; }
  W t2;
  V { clk = P; data = 0; }
  V { clk = P; data = 1; }
}
```

After unification of the periods, the STIL pattern looks like this:

```
Timing {
  WaveformTable "WFT" {
    Period '150ns/3';
    Waveforms {
      "clk" {
        P { '0ns' D; '25ns' U; }
        U { '0ns' U; }
        p { '0ns' D; }
        0 { '75ns-150ns/3' U; }
      }
      "data" {
        0 {}
        D { '50ns-150ns/3' D; }
        1 { '50ns-150ns/3' U; }
      }
    }
  }
}

Pattern "P1" {
  // <t1> div 2
  W "WFT";
  V { "clk"=P; "data"=0; }
  V { "clk"=U; "data"=D; }
  // <t1> div 2
  V { "clk"=P; "data"=0; }
  V { "clk"=U; "data"=1; }
  // <t2> div 3
  V { "clk"=p; "data"=0; }
  V { "clk"=0; }
  V { "clk"=U; "data"=D; }
  // <t2> div 3
  V { "clk"=p; "data"=0; }
  V { "clk"=0; }
  V { "clk"=U; "data"=1; }
}
```
