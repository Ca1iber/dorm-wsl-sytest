# Structure of a Timing Map File Block

The general format of a timing map file block is as follows:

[TIMINGSET <x>]

[STATE_WILDCARD <character_string>]

PINS <list_of_pins_or_pin_groups_1>

DDC <ASCII_dvc_1> <ASCII_dvc_2> ... <ASCII_dvc_M>

<ch_1_1><ch_2_1>...<ch_M_1> <idx_1_1><idx_2_1>...<idx_N_1>

<ch_1_2><ch_2_2>...<ch_M_2> <idx_1_2><idx_2_2>...<idx_N_2>

...

PINS <list_of_pins_or_pin_groups_2>

...

The function of the individual statements is as follows:

- [TIMINGSET <x>] (optional): This statement defines the timing set to which the blocks belongs. If no such statement occurs in the file, the whole file will be associated with timing set 1.
- [STATE_WILDCARD <character_string>] (optional): This statement defines characters that are to be used as wildcards in the mapping definitions. <character_string> stands for the string of those characters that are to be used as wildcards.

The STATE_WILDCARD statement is inserted automatically by the timing translation whenever it is needed, for example for setups with differential pins or with a continuous clock (see [Keeping the Clock Alive](<02.11.02.02.06_Keeping_the_Clock_Alive.md>)). In this case, the 鈥?strong>*' character is used as the wildcard character.

- PINS <list_of_pins_or_pin_groups_i> (mandatory): This line defines the pins for which the mappings are to be specified.
- DDC <ASCII_dvc_i> (mandatory): This line defines the length of the state character sequence and, for each position, the ASCII device cycle to which the character belongs. The same device cycle name can occur more than once; in fact, the most common case will be that the sequence is "homogeneous", that is, that the same device cycle name is specified for every <ASCII_dvc_i>.

 The ASCII device cycle sequence is associated with a time span which is calculated by adding the periods of its elements; thus in the homogeneous case, this time span is m times the period of the respective ASCII device cycle.

When you generate the timing map files with ait, you must pass an x-mode control file to ait if you want to create timing map file entries with state character sequences belonging to different ASCII device cycles. For details see [Creating Sequences from Several ASCII Device Cycles](<02.11.02.02.03.05_Creating_Sequences_from_Several_ASCII_Device_Cycles.md>).

- <ch_i_k> <idx_j_k> (mandatory): Each of these lines specifies a state character or sequence of state characters on the left, and a waveform index or sequence of waveform DC/DC power units on the right. The length of the state character sequence must equal the length of the ASCII device cycle sequence in the DDC statement, and its ith element must be defined for the ith element of the ASCII device cycle sequence.

The waveform DC/DC power units must be specified in hexadecimal notation. If one of the DC/DC power units comprises more than one digit, the sequence must be preceded by the + character, and the individual DC/DC power units must be separated by a blank.
