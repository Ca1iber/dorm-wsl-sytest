# Configuring x-modes using STIL Reader

X-modes are a way to compress vectors using the V93000's flexible device cycle definitions. Using x-modes, two or more vectors are packed into one vector, while the timing definition is updated to reflect vector compression. Each compressed device cycle contains a number of original cycles as indicated by the x-mode. (For example, in the x4 mode, each compressed cycle contains four original cycles.)

There are two ways to use the x-mode compression feature:

- In order to compress all vectors in a STIL file, set the xmode_factor variable to 2 or higher in the setup file:

```
xmode_factor = 2
```

In case of a multiport setup, the x-mode factor is applied to all ports.

Instead of setting the x-mode manually, you can also specify `xmode_factor = "auto"` to let STIL Reader automatically determine the optimal x-mode for the translated patterns and the target hardware.

-

In order to apply different x-mode factors to the various ports in a multiport setup, additional parameters are required in the ports' NameMaps definitions in the STIL file:

```
signal_name "port_name,sync_group,master_clock,x_factor,hx, specs_scope,keep_spec_variables,phase_sync"
```

 The individual elements have the following meanings:

  - port_name: The port name.
  - sync_group: This parameter is currently unused.
  - master_clock: This parameter is currently unused.
  - x_factor: The x-mode to use. This parameter overrides the xmode_factor setup parameter.
  - port_type: The high-speed channel handling. This parameter can be left empty, set to hx, or set to fast.
  - specs_scope: Can be set to global or to local, to create global (for all ports) or local (per-port) specs tables, respectively.
  - keep_spec_variables: Can be set to 0 or 1. If the parameter is set to 1, unused spec variables will be kept; if is set to 0, they are dropped. This parameter overrides the keep_spec_variables setup parameter.
  - phase_sync: Can be set to on or off to (respectively) enable or disable phase synchronization. The default is on.

Example signal specification:

```
Sig1 "Clock,SyncGroup1,1,1,,global,1,off";
```

Please note that timing is created only for the actual combinations of vectors in the STIL file. The x-mode compression may fail when insufficient tester resources are available (that is, when there are too many edges or waveforms to compress).

## Padding

When an x-mode is specified, STIL Reader always makes sure that the number of vectors in the converted pattern is an even multiple of the chosen mode. For example, with X6 mode, the number of vectors in the patterns will always be a multiple of 6.

If the number of vectors in the STIL patterns is not evenly divisible by the x-mode factor, STIL Reader automatically adds the required number of padding vectors at the end. By default these padding vectors contain no actions. If you would like instead to repeat the drive actions from the last vector of the source pattern, set the [pad_xmode_vectors](<02.11.01.05.03.03_Translation-related_STIL_Reader_setup_options.md>) parameter in the setup file to 1.
