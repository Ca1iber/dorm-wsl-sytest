Every row of the PATTERNS section in the global configuration file associates the respective pattern with one or more ASCII device cycles, and also (explicitly or implicitly) with an x-mode factor. If this factor is > 1, the waveforms for any combination of a pin with one of these ASCII device cycles will be created not from single state characters, but from state character sequences. The length of the sequences is determined by the x-mode factor; if, for example, the x-mode factor is 4, then the waveforms are generated from sequences of length 4. For details see [Using X-Modes: the xfact Column](<02.11.02.02.01.01.04_Using_X-Modes__the_xfact_Column.md>).

By default, the timing translation creates a waveform for every possible character sequence of the given length that can be generated from the state characters of one ASCII device cycle. Since the total number of different sequences of length m that can be generated from n state characters is n^m, this will usually result in more than the 32 waveforms that are allowed on the P/Ce systems already for m = 3 and n = 4. On the Pin Scale systems, where up to 256 waveforms can be defined per pin, n = 4 and m = 5 will exceed the available resources.

Now in many cases less than n^m waveforms will be required. First, it is possible that some state character sequences never occur in the ASCII vector file (so that no waveform needs to be generated for them), and secondly it may happen that different character sequences can be mapped to the same waveform.

The main purpose of the x-mode control file is to inform ait of exactly these situations. It specifies the state character sequences for which entries are to be generated in the timing map file, and also defines for which of these sequences waveforms are to be generated, and which of them are to be mapped to a waveform created from another sequence. Furthermore, it provides the possibility to create waveforms from state character sequences belonging to different ASCII device cycles.

 You can insert comments into the file. These are identified by the hash character (#); if this character occurs in a line, the rest of the line after the hash character will be considered as a comment.
