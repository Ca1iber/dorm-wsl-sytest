# The MULTI_PORT_TIMING Statement

The MULTI_PORT_TIMING statement is intended to define a multi-port timing for a setup where timing ports and vector ports are not identical. It has the same syntax as the MULTI_PORT_BURST statement. In particular, it also requires a CTIM row.

Furthermore, the patterns of the MULTI_PORT_TIMING statement must have been defined in the PATTERNS section. If you want to suppress them in the vector configuration file (*.aiv), you must assign the type MDMY to them in the type column of the PATTERNS section; this also prevents generation of a pattern configuration file (*.vbc) for the pattern in question.

If you use the MULTI_PORT_TIMING statement, you must manually edit the input files for the vector translation as follows:

- Modify the PATTERNS section of the vector configuration file:

If you have specified MDMY as the pattern type in the global configuration file, you must add pattern definitions with the appropriate ports and timing map file entries. If you have specified any other type, you must at least change the ports of some or all of the entries, and possibly also the associated timing map file.

- Add a MULTI_PORT_BURST statement in the vector configuration file:

This statement must be added for the vector ports.

- Merge timing map files:

The timing translation creates separate wavetables, and therefore also separate timing map files, for each of the timing ports. Therefore, whenever a vector port contains pins from more than one timing port, you must merge the timing map files of the respective timing ports for this vector port.

In the special case where a multi-port timing is combined with a single-port vector setup, you can use the ait option -MS to create only one wavetable, and therefore also only one timing map file.
