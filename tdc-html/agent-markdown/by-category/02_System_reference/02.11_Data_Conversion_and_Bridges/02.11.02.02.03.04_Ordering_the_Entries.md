# Ordering the Entries

It is possible that two different entries of one definition block apply to the same state character sequence. For example, both entries of the block

DDC dvc dvc dvc

PINS input

000

000->111

apply to the sequence 000. In such a case the timing translation processes only the first of these entries. Thus, it will create a waveform from 000 and ignore the following mapping statement in this example.

You can make use of this principle to define rules with exceptions. As an example, consider the following definition:

DDC dvc dvc dvc

PINS input

000

***->111

In this example, a waveform will be created from 000, but apart from this exception, all sequences will be mapped to the index of the waveform created from 111. In the timing map file this would be stated as follows:

```
STATE_WILDCARD *

PINS input
DDC dvc dvc dvc
1 * *0
*1*0
**10
0001
```

The initial STATE_WILDCARD * statement defines the asterisk as a wildcard for state characters (see [The Pattern Configuration File (*.vbc)](<02.11.02.03.05_The_Pattern_Configuration_File___.vbc.md>) ).

You can cause the timing translation to report all cases where more than one entry of a definition block applies to the same state character sequence by calling ait with -Fdq (see[ait command line parameters](<02.11.02.02.08.01_ait_command_line_parameters.md>)).
