# FAQ

## What is STIL?

Standard Test Interface Language (STIL) is a standard language that provides an interface between digital test generation tools and test equipment. STIL may be directly generated as an output language of many test generation tools, or it may be used as an intermediate format for subsequent processing. STIL is a representation of information needed to define digital test operations in manufacturing tests.

## Where can I find the STIL specifications?

IEEE Std 1450-1999 is available from the IEEE Standards Association. The standard can be found under the Test Technology Standards reference. In addition, a Representative BNF for IEEE Std 1450-1999 (PDF format) is available. This BNF was generated with the goal of providing a simplified introduction to STIL. As such, it is an incomplete representation of the language, and the Standard Document must be used to completely specify the language. Still, this serves to orient newcomers to the constructs of STIL. Also, the Clarifications for IEEE Std 1450-1999 (PDF format) is available on the following website:

http://grouper.ieee.org/groups/1450/index.html

## How do I know what extensions my STIL file is using?

You can see which extension you are using in the STIL statement of the STIL file:

```
STIL 1.0 {
    ( <extension_name><extension_version>; )
}
```

<extension_name> means:

- Design: Extension 1 is included
- DCLevels: Extension 2 is included

## What are STIL extensions?

A series of dotted extension projects have been created to address issues identified to be outside the scope of the initial project:

- 1450.0-1999: Standard Test Interface Language(STIL) for Digital Test Vectors
- 1450.1-2005: Extensions to STIL for Semiconductor Design Environments
- 1450.2-2002: Extensions to STIL for DC Level Specification
- P1450.3: Extensions to STIL for Tester Target Specification
- P1450.4: Extensions to STIL for Test Flow Specification
- P1450.5: Extensions to STIL for Semiconductor Test Method Specification
- 1450.6-2005: Extensions to STIL for Core Test Language
- P1450.7: Extensions to STIL for Analog and Mixed Signal
- P1450.8: Extensions to STIL for Design Information - path delay, physical layout, and more.

## What is a "2-state ambiguity" and how can it be fixed?

Assigning different waveform characters to the same signal in one vector creates an ambiguity. By default, STILReader uses the data from the last assignment. For example, the following STIL statement will cause ambiguity if the D0 signal is a member of both the pi and po signal groups:

```
V { "_pi"=\r12 0 ; "_po"=\r10 X ; }
```

This ambiguity will cause STIL Reader to generate a warning:

```
Warning: [line 183] Unable to resolve 2-states ambiguity ( _pi=>0,
_po=>X ) for signal D0.
 (  Using state 'X' )
```

There is only an initial warning and subsequent instances are suppressed.

In STIL 1450.1, the WFCMap construct was added in order to resolve such conflicts. If WFCMap is present in the STIL file, it is used to resolve the ambiguity, and no warning is generated.

For the example above,the WFC map would be:

```
D0 In {
  WFCMap {
    0X->0; // Resolve D0=0; D0=X; assignment to 0
  }
}
```

The order of appearance of WFCs in the WFCMap object is important; it must match the order of assignments in the STIL vector.

Such ambiguities can also be fixed be including mapping settings in the setup file using the stil_wfc_map parameter (see [Translation-related STIL Reader setup options](<02.11.01.05.03.03_Translation-related_STIL_Reader_setup_options.md>)).

## Where does STIL Reader get timing when it is in advanced mode ?

The advanced mode is intended for incremental generation of multiple patterns sharing the same timing.

After processing the first pattern in normal mode, STIL Reader generates a special file (.tmf) is generated in the working directory. The file contains a mapping of STIL timing to V93000 waveform index. Each pattern, processed in advanced mode, will use those mappings. Time definitions not found in the TMF file are not allowed and are recognized as an error condition.

## Why are there two files for configuring the tool, setup and settings files?

The setup file template is created by calling the tool using the -template parameter. The template is used to run the tool. It contains the path to the files required to run the tool and specifies the path to the output files.

The settings file is automatically created by STIL Reader in the working directory (output by default) and contains flags that define the operation modes of the tool.
