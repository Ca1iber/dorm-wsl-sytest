# General Overview of Multi-Port Testing (ASCII IF)

SmarTest provides the capability of running different patterns (sequencer programs) with different timings for different groups of pins simultaneously; this is based on the fact that every pin has its own sequencer. The pin groups are called ports, and the feature as a whole is called the multi-port capability of SmarTest.

The multi-port timing is defined in a multi-port timing specification. Such a specification is defined for a set of ports, which are called timing ports. The timing ports must not overlap, that is, no pin may be contained in more than one of these ports. The specification associates a wavetable and an equation set with each of the timing ports. It also contains values for the spec variables of the associated equation sets. Furthermore, it can specify how far test execution for the ports contained in the specification is to be synchronized (sequencing groups, phase synchronization).

The multi-port vector setup is defined in a multi-port burst. A multi-port burst consists of one or more ordinary bursts (that is, pattern sequences that are executed in one sequencer run) each of which is associated with a port. These ports are called  vector ports. Again, the vector ports must not overlap. The port specific bursts belonging to one and the same multi-port burst are connected to each other by all having the same name.

In the most simple case, the timing port set and the vector port set of one multi-port setup will be identical. This can be visualized as follows:

  ![Identical Timing Port and Vector Port Sets](<../../../../raw/54343.png>)

In principle, however, the ports of the timing specification and the ports of the multi-port burst are completely independent of each other. The set of the timing ports and the set of the vector ports are allowed to have no member in common. In addition, combinations of single-port vector setup and a multi-port timing setup are acceptable as well as pairing a single-port timing setup with a multi-port vector setup.

The following figure shows an example where two of the timing ports subdivide one of the vector ports:

![A Timing Port Set Subdividing the Vector Port Set](<../../../../raw/54344.png>)

In this constellation, all pins of vector_port_A will use the same sequencer program (which implies, for example, that CTIM instructions, if present, are executed at exactly the same places for all these pins), but the timing (for example the period length) can be different for the pins belonging to timing_port_A and those belonging to timing_port_B.

 WARNING You should avoid a setup where some pins are included in a port of the current (multi-port burst) start label, but not in any port of the primary multi-port timing specification. For details see [Incomplete multi-port setups](<../02.06_Command_Reference/02.06.07.01.08.05.03.02.02_Incomplete_multi-port_setups.md>).

If you want to create a multi-port setup with the ASCII interface, you must use the high-level tools ait and aiv. This is because the multi-port timing specification is generated by ait (not d2w), and the multi-port burst by aiv(not v2b). For handling differences between timing and vector ports in the ASCII interface, see [The MULTI_PORT_TIMING Statement](<02.11.02.02.05.02.02_The_MULTI_PORT_TIMING_Statement.md>).
