# X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding

#### Subtopics

- [Processing a Repeat Factor > 1](<02.11.02.03.02.05.01_Processing_a_Repeat_Factor___1.md>)
- [X-Mode ASCII Vector Padding](<02.11.02.03.02.05.02_X-Mode_ASCII_Vector_Padding.md>)

The term x-mode refers to the possibility to execute more than one DUT cycle (as defined in an ASCII device cycle) in one test system cycle (as defined in a timing set); for more details see [Using X-Modes: the xfact Column](<02.11.02.02.01.01.04_Using_X-Modes__the_xfact_Column.md>). The x-mode factor specifies how many DUT cycles are to be executed in one test system cycle. The x-mode factor can also be fractional, which means that m DUT cycles are executed in n test system cycles, and n is not divisible by m.

Normally, the vector translation is informed of the x-mode factor through the timing map file (see [Calculating the Lengths of the State Character and the Index Sequences](<02.11.02.03.04.02_Calculating_the_Lengths_of_the_State_Character_and_the_Index_Sequences.md>)). If the x-mode factor m of a pattern is > 1 (and the x-mode is not fractional), it will convert blocks of m ASCII vectors to one row of the index array. Two points require more detailed explanations, namely:

- How is a repeat factor > 1 processed when the x-mode factor is > 1?
- What happens when the total number of the ASCII vectors (taking also account of the repeat factors) is not a multiple of the x-mode factor?
