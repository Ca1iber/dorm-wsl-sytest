# Creating a Multi-Port Timing with ait

#### Subtopics

- [The MULTI_PORT_BURST Statement](<02.11.02.02.05.02.01_The_MULTI_PORT_BURST_Statement.md>)
- [The MULTI_PORT_TIMING Statement](<02.11.02.02.05.02.02_The_MULTI_PORT_TIMING_Statement.md>)
- [Generating the Specification and the Vector Configuration File](<02.11.02.02.05.02.03_Generating_the_Specification_and_the_Vector_Configuration_File.md>)

To generate a multi-port timing with the ASCII interface, you must define the ports in the pin configuration file and specify the input information for the multi-port timing specification in the global configuration file (*.aic). The ports must be defined with the firmware command DFPT. The input information for the specification must be specified in the GROUPS section of the global configuration file (for general information on the GROUPS section see [The GROUPS Section](<02.11.02.02.01.02_The_GROUPS_Section.md>)).

If your timing port set and vector port set are identical (as illustrated by Figure[ General Overview of Multi-Port Testing](<02.11.02.02.05.01_General_Overview_of_Multi-Port_Testing__ASCII_IF.md>)), you should use a group of type MULTI_PORT_BURST to define the multi-port timing specification. This ensures that ait, in addition to creating the specification, generates a MULTI_PORT_BURST statement in the vector configuration file (*.aiv), which will then be converted into a multi-port burst definition by the vector translation (see [Bursts and Multi-Port Bursts](<02.11.02.03.01.02_Bursts_and_Multi-Port_Bursts.md>)).

If timing port set and vector port set are different, you can use the MULTI_PORT_TIMING statement to define the timing specification.
