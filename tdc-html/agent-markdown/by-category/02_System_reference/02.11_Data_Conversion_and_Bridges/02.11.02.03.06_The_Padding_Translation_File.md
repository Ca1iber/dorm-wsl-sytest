# The Padding Translation File

If the total number of vectors in the ASCII vector file, or of the vectors between two sequencer instructions, is not a multiple of the x-mode factor, the vector translation can automatically insert ASCII padding vectors; see [X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding](<02.11.02.03.02.05_X-Modes__Processing_of_the_Repeat_Factor__and_ASCII_Vector_Padding.md>). There is a default as to how this padding vector is created from the last vector of the file, or the last vector before the sequencer instruction, but you can define your own rules be creating a padding translation file and passing it to aiv(in the v2b_options column of the vector configuration file) or to v2b with the -xpe, -xpi, and -xph parameters.

 Note You can pass only one padding translation file to v2b for one pattern. This file will be used for all three padding parameters.

The format of the padding translation file looks as follows:

[STATE_WILDCARD <wildcard_char>]

PINS <list_of_pins_or_pin_groups_1>|@

DDC <ASCII_dvc_1>|@ [<ASCII_dvc_2> ...]

<s_st_ch_1>|<wildcard_char> <t_st_ch_1>

<s_st_ch_2> <t_st_ch_2>

...

<s_st_ch_n> <t_st_ch_n>

PINS <list_of_pins_or_pin_groups_2>

...

The function of the individual statements is as follows:

- STATE_WILDCARD <wildcard_char> (optional): This line defines the wildcard character which serves as a place holder for any state character.
- PINS <list_of_pins_or_pin_groups_i>|@ (mandatory): This line defines the pins for which the mappings are to be specified. @ is a wildcard for all pins.
- DDC <ASCII_dvc_1>|@ [<ASCII_dvc_2> ...] (mandatory): This line defines the ASCII device cycles for which the mapping is defined. @ is a wildcard for all ASCII device cycles.
- <s_st_ch_i>|<wildcard_char> <t_st_ch_i> (mandatory): Each of these lines maps a source state character to a target state character of <ASCII_dvc>. The mapping says that <t_st_ch_i> is to be used as the padding character for the pins in question if <s_st_ch_i> is the last character that occurs in the ASCII vector file before the sequencer instruction or the pattern end.

<wildcard_char> is a wildcard for all state characters of the respective ASCII device cycle. It must be defined with the STATE_WILDCARD keyword in the first line of the file.

You can specify more than one definition for the same combination of pin, ASCII device cycle and state character. This can be used to define global mappings (using wildcards) at the start of the file, and then override these for certain source characters.

As an example, suppose that you want the padding vector of Figure [X-Mode ASCII Vector Padding](<02.11.02.03.02.05.02_X-Mode_ASCII_Vector_Padding.md>) to be always 00X. Then you would have to code the following padding translation file:

STATE_WILDCARD *

PINS CP D0

DDC std

*0

PINS Q0

DDC std

*X
