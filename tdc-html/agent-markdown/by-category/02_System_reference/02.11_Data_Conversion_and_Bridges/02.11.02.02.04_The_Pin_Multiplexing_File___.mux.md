# The Pin Multiplexing File (*.mux)

#### Subtopics

- [The Standard Format of the Pin Multiplexing File](<02.11.02.02.04.01_The_Standard_Format_of_the_Pin_Multiplexing_File.md>)
- [Mapping HXA Pins To Pin Scale Pins](<02.11.02.02.04.02_Mapping_HXA_Pins_To_Pin_Scale_Pins.md>)
- [Passing the Pin Multiplexing File to ait](<02.11.02.02.04.03_Passing_the_Pin_Multiplexing_File_to_ait.md>)

If you need more edges or waveforms for a DUT pin than the system supplies, one way to circumvent these restrictions is to attach more than one tester channel to one DUT pin, and to distribute the required resources among these channels. The ASCII interface is able to cope with this situation. It accepts the state character definitions for the DUT pin in the ASCII timing file, and creates timings for the different associated channels. You can choose between several distribution algorithms.

The information about the mapping must be passed to ait in a pin multiplexing file, which has the default extension *.mux. The distribution algorithm must also be specified in the pin multiplexing file.

The pin multiplexing file is also used to define the mapping of HXA pins to Pin Scale pins for the Pin Scale HX feature. In this case the format of the entries is slightly different.
