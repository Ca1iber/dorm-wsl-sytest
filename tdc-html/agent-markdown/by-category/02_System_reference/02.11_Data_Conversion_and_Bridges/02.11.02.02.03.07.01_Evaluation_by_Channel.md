# Evaluation by Channel

With this type of evaluation, the two channels are treated as independent of each other. This means:

- The odd state character occurrences of the whole entry are assigned to the positive channel, and the even state character occurrences to the negative channel.
- A state character sequence in the ASCII vector file is translatable if the odd positions of a control file entry A are applicable to the odd state character occurrences of the sequence, and the even positions of a control file entry B are applicable to its even character occurrences. A and B can, but need not be the same entry.
- If two entries are applicable to the same state characters at the odd positions, only the first such entry is processed for the positive channel. The same holds for the even positions with respect to the negative channel.

As an example, consider the following definition for the output channel pair O+ andO- (as in the wavetable, only the positive channel is specified in the x-mode control file):

DDC normalnormalnormalnormalnormalnormal

PINS O+

HLHLHL->XXXXXX

HHHLHL

XXXXXX

The first entry says that HHH is to be mapped to XXX for the positive channel O+, and LLL to XXX for the negative channel O-.

The wavetable generated from this definition block will look as follows:

PINS O+

0 "XXXXXX"

1 "XHXLXL"

Observe that only the combination XXX is supplied for the positive channel. The combination HHH is mapped to XXX by the first entry in the x-mode control file; the second of these entries is ignored because it agrees with the first entry at the odd positions (this illustrates the previous statement 3 ).

The timing map file will contain the following entries for O+ and O-:

PINS O+

DDC normal normal normal normal normal normal

H*H*H* 0

X*X*X* 0

PINS O-

DDC normal normal normal normal normal normal

*L*L*L 0

*H*L*L 1

*X*X*X 0

The entries for O+ contain the wildcard character * at the even positions, and those for O- contain it at the odd positions. This ensures that if, for example, the state character sequence XHXLXL occurs in the ASCII vector file, it can be translated although no entry occurs for this sequence in the x-mode control file (this illustrates the previous statement 2 ). Details on the vector translation for differential pins can be found in[Translating ASCII Vectors with Differential Pins](<02.11.02.03.02.03_Translating_ASCII_Vectors_with_Differential_Pins.md>).
