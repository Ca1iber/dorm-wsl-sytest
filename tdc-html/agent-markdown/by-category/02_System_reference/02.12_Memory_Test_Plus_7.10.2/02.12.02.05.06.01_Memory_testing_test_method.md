MTP comes with a ready-made test method for memory testing, the ExecutionEngine test method. In addition, you can create your own custom test method.

## ExecutionEngine

The ExecutionEngine test method lets you execute memory tests and retrieve the results.

The parameters of the test method are explained in [Parameters for Memtest execution test methods](<02.12.02.05.06.01.03.01_Parameters_for_the_ExecutionEngine_test_method.md>).

The test method, which can be called from a test suite, executes a high-speed memory test. This is not the only way to execute such a test; any memory test pattern can be executed normally using the "functional test" function. However, that test function only provides cycle-based information which is displayed in the SmarTest result windows, such as timing diagram, error map, and pattern debug tool. For debugging a test using those tools or gathering pass/fail data, the test function is sufficient. For gathering address-based data, additional capabilities are needed; the ExecutionEngine test method provides those capabilities.

The ExecutionEngine test method performs the test, save pass/fail information in a file that can be read by the Bit Fail Map Viewer (for details about the Bit Fail Map viewer see [Bit Fail Map Viewer](<02.12.04.04_Bit_Fail_Map_Viewer.md>)), saves cycle-based data in the event data log file, and reconstructs address-based data from that cycle-based data.

The ExecutionEngine test method passes the main label that is specified in the primary set (defined in the test suite window). By setting flags, you can configure the test method to provide the results you want.

While using the test method you can:

- Enable [data logging](<02.12.02.05.09_Saving_the_data_log_file.md>) by setting test flow flags in the test flow editor
- Activate the event formatter (see [Using the Event Formatter](<../02.10_Data_Logging/02.10.02_Event_Formatter.md>) for further information)

## Custom test methods

For creating custom memory test methods, two APIs are provided that allow you to create and access address-based results in your own test methods:

- The [MTP_MEMORY_TEST](<02.12.06.17_MTP_MEMORY_TEST.md>) class lets you set parameters for the test execution, run a memory test and save the results as but fail map files.
- For more detailed analysis of address-based results, you can use the [MTP_MEMORY_PATTERN](<02.12.06.15_MTP_MEMORY_PATTERN.md>) class that provides selective access to the results of tests run with MTP_MEMORY_TEST.

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 3.0.1: The Memtest test methods have been consolidated into the ExecutionEngine test method
- MTP 3.1.3: MTP_MEMORY_TEST and MTP_MEMORY_PATTERN APIs are introduced to develop a customized test method.
- MTP 3.2.2: Removes Result Server.
- MTP 3.3.1: The ExecutionEngine test method starts to support the Pin Scale SL digital card.
