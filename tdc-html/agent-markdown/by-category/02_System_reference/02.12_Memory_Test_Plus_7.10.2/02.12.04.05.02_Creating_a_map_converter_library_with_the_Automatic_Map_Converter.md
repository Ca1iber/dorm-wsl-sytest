# Creating a map converter library with the Automatic Map Converter

Creating a map converter library for use with the Bit Fail Map Viewer is a largely automatic process, once properly set up. It requires a valid APG pattern file and a property file that describes the device geometry.

## About this task

Create a map converter library to enable the Bit Fail Map Viewer to automatically map physical to geometrical addresses and vice versa.

The created library also creates a routine to convert physical to logical addresses. If that conversion is involutary, a routine for converting logical to physical addresses is also created. (Functions that return the original values when applied to their own results are called involutary. For example, multiplying by -1 or XOR are involutary functions.) If it is not involutary, a dummy routine is generated in the C source code that you can manually expand to a working routine for your device.

Converter libraries for redundancy analysis are generated if the device properties file contains a redundancy analysis element. The generated phys_to_layout function handles the regular structure of the device, as specified in the properties file, but not any local deviations from that structure. If your device includes such deviations, you may need to modify the function in the generated C source file before compiling it.

## Before you begin

Set up the APG pattern file as required and create a property file for the device. The syntax for this file is described in [Device property file](<02.12.04.05.03_Device_property_file.md>).

## Procedure

-  In a terminal window, set the working directory to /opt/93000mts/mts/utilities/bin/.
-  Run the converter by entering `mapConvWizard `<config_file> `-o `<output_file>[ `-l `<library_path>] `-batch `[ `-nolib`| `-debug `].

The parameters and options mean:

  - <config_file>: The path to the prepared [Device property file](<02.12.04.05.03_Device_property_file.md>). It can be an absolute path or a path relative to the current directory.
  - -o: The option for specifying the output file. <output_file> is the file name for the output file. You can include an absolute path or a path relative to the current directory.

If you provide just a file name but no path, the C source file is created in the same folder as the device property file specified in <config_file>.

If <config_file> contains a path but you want the output file created in the current directory, you must begin <output_file> with ./

  - -l: The option for specifying the output location of the compiled library. <library_path> is the path to the folder in which you want the library to be created. It can be an absolute path or a path relative to the current directory.

If this parameter is not specified, the library is created in the same folder as the output file.

  - -batch: This is a required option. However, it may be omitted if the -nolib or -debug options are used.
  - -nolib: If this option is specified, no library is compiled. That is, only the C source file is created.
  - -debug: If this option is specified, a debug version of the library is compiled.

## Results

The source file and, unless you specified the -nolib option, library are created in the specified output directory.

## What to do next

Copy the compiled library to the mts/bitmap/converters/bin/ directory of the device directory. (See [BFM Viewer-specific device folder structure](<02.12.04.04.02.01.01_BFM_Viewer-specific_device_folder_structure.md>) for details.)

If required, configure the Bit Fail Map Viewer to use the new library, as described in [Configuring the BFM Viewer](<02.12.04.04.02.02_Configuring_the_BFM_Viewer.md>).
