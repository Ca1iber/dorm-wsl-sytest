# Multiport operation

#### Subtopics

- [Multiport timing conventions](<02.12.03.04.14.01_Multiport_timing_conventions.md>)

Multiport operation allows you to test different parts of a DUT with independent timing sets or spec variables using a single memory test pattern.

## Procedure

-  Make sure that all required ports are defined in the [Pin configuration file](<02.12.03.03.09.01_Pin_configuration_file.md>).

Set up each port so that it groups pins with identical timing. Usually, this is done in SmarTest.

-  Declare the ports in the [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>) by means of the using port statement.
-  Specify the required pin ratios in the pin mapping file, either for the port's individual pins or for the port as a whole.
-  Set up levels, timing, and vectors for each port as usual.

There are certain conventions to be observed when specifying the timing for multiport operation, as described in [Multiport timing conventions](<02.12.03.04.14.01_Multiport_timing_conventions.md>).

## Results

The pattern is set up so that you can test different parts of the DUT simultaneously with different timing.

If the :testLabel: keyword is used in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>), the compiler creates a multiport burst label. If not all ports were declared in the [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>), the multiport burst label only covers the declared ports and break vectors are applied to all other ports.
