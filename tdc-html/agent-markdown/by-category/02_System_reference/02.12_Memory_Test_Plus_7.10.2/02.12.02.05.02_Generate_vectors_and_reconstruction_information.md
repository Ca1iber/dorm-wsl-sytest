# Generate vectors and reconstruction information

Once you have programmed the desired memory test patterns with MTL, use the MTL compiler to generate the memory test program (see [Creating Test Patterns](<02.12.03.02_Creating_Test_Patterns.md>) for more information).

When the -r1 or -r2 options are used, the MTL compiler creates the required per-pin subroutines and a corresponding reconstruction file with the name <pattern-name>-EL7.apg.rec.so. (Specifying -r0 causes a compiler error; specifying -r is considered the same as -r1.)

See [Reconstruction information](<02.12.03.04.11_Reconstruction_information.md>) for more information.

The reconstruction files of all patterns to be used must be stored in the same directory: <device_directory>/mts/recon_datalib.

The reconstruction information is defined by using the data macro on those pins that are configured with an output component (o or io) in the pin configuration settings of SmarTest. These pins are the only pins that can fail during execution of a memory test pattern. The user programs the data macro (in MTL) so that a relationship is specified between each cycle that is executed and the device address that is enabled in the device during a read operation that occurs in that cycle. This relationship information is stored at compile time, and used after the execution of the test to reconstruct cycle-based failures into address-based fail information. (For more information on the data macro see [Macros in device accesses](<02.12.03.03.04.02_Macros_and_functions_in_device_accesses.md>).)

Not all patterns require this relationship information. For instance, a pattern that initializes the memory device can be created in MTL, but it contains no relationship between the initialization cycles and an address. Initialization patterns and other patterns that are not intended for display as a fail map, may be compiled without reconstruction information. For these patterns a data macro is not needed and cannot be set up. Therefore, if the -r1 or -r2 options are used for patterns that do not contain a data macro; the apgc command will generate a warning and will not create a reconstruction file; and a vector file will still be generated.

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 2.4.2: New file name convention for binary files on Red Hat Linux 5
- MTP 3.0.1: Removed the -r0 option and support for non-binary reconstruction files (.apg.rec files)
