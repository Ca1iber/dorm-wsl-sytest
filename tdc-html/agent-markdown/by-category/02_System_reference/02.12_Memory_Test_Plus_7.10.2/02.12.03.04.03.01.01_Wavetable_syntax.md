# Wavetable syntax

The wavetable syntax in the SmarTest timing file is briefly introduced here.

## Common syntax

```
WAVETBL "<wavetable_name>"

PINS <dutPinName>
<waveform_specification>
...

...
```

These are the keywords and parameters in alphabetical order:

 |

Keyword

 |

Parameters and descriptions

 |
 |

PINS

 |

<dutPinName>: The pin or pin group to be defined with waveform, which must have been already defined in the SmarTest pin configuration file and mapped into the MTL [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>).

- Up to 256 DUT pin names can be after a PINS keyword, separated by spaces.

<waveform_specification>: The detailed description for the waveform.

- If maintenance operations are used, waveforms for non-interruptible sequences on pins in the VEC refresh mode must be applied with indexes between (hexadecimal) 80 and FF. (See [Maintenance operations](<02.12.03.04.12_Maintenance_operations.md>) for details.)
 |
 |

WAVETBL

 |

<wavetableName>: A wavetable name. The name can be any string complying with the [naming conventions](<02.12.03.02.03_Naming_rules_and_conventions.md>).

 |

## Compatible format

There are two ways to specify a waveform, standard and fast.

In both modes, a waveform is specified as:

```
<phyWfIndex><edgeActions><deviceCycleName>
```

- <phyWIndex>: A physical waveform index, integer from 0 to 255.

Note that the numbers do not need to be prefixed with 0x.

- <edgeAction>:

  - For the standard mode, each edge in this description is prefixed with the name of the edge (for example, "d1:0 d2:1").
  - For the fast mode, the description consists simply of the sequence of level (for example, "01").

- <deviceCycleName>: The name to be displayed in Pattern View.

## Example

### Compatible syntax

In the [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>):

```
...
using defaultxmode 3
...
```

In the wavetable file:

```
WAVETBL "Compatible"
PINS pin1    # fast-mode
0 "000" 000
1 "001" 001
2 "011" 011
...
PINS pin1    # std-mode
0 "d1:0 d2:0 d3:0" 000
1 "d1:0 d2:0 d3:1" 001
2 "d1:0 d2:1 d3:1" 011
...
```
