# Memory test data log event structure

Memory test that are logged all create a similar event structure.

The exact sequence of events depends, among others, on the test functions used and the number of sites tested:

- Each execution of a memory test suite begins with a [TestSuiteStartEvent](<../02.10_Data_Logging/02.10.01.06.03.20_TestSuiteStartEventType.md>) and ends with a [TestSuiteEndEvent](<../02.10_Data_Logging/02.10.01.06.03.19_TestSuiteEndEventType.md>).

Between these two events, there is one test function block for each tested site.

Note that this does not mean that sites are tested sequentially: Alls sites are tested in parallel; the results of sites other than the first are cached and the events are then generated from these cached results.

- A test function block begins with a [TestFunctionStartEvent](<../02.10_Data_Logging/02.10.01.06.03.16_TestFunctionStartEventType.md>) and ends with a [TestFunctionEndEvent](<../02.10_Data_Logging/02.10.01.06.03.15_TestFunctionEndEventType.md>).

Between these two events, there are the main label test result events, optionally followed by one or more subroutine test result events.

- Each main label test result consists of a pair of events:

  - First the functional pass/fail result, a [TestEvent](<../02.10_Data_Logging/02.10.01.06.03.12_TestEventType.md>) with TEST_TYPE_FUNCTIONAL as the value of the [ParametricOrFunctionalTestAttrType](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>) parameter.

This event always contains the [test name](<../02.10_Data_Logging/02.10.01.06.05.61_TestNameAttrType.md>), [test ID](<../02.10_Data_Logging/02.10.01.06.05.60_TestIdAttrType.md>), [test type](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>), and [pass/fail result](<../02.10_Data_Logging/02.10.01.06.05.28_PassFailResultAttrType.md>).

If the per-pin on pass or per-pin on fail test suite flags, respectively, were set, the event also contains the [list of passed and failed pins](<../02.10_Data_Logging/02.10.01.06.05.34_PinPFResultAttrType.md>).

  - Next the fail bit count (FBC) pass/fail results, a [TestEvent](<../02.10_Data_Logging/02.10.01.06.03.12_TestEventType.md>) with TEST_TYPE_MEMORY as the value of the [ParametricOrFunctionalTestAttrType](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>) parameter.

- Each subroutine test result consists of a pair of events:

  - First the functional pass/fail result, a [TestEvent](<../02.10_Data_Logging/02.10.01.06.03.12_TestEventType.md>) with TEST_TYPE_FUNCTIONAL as the value of the [ParametricOrFunctionalTestAttrType](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>) parameter.

This event always contains the [test name](<../02.10_Data_Logging/02.10.01.06.05.61_TestNameAttrType.md>), [test ID](<../02.10_Data_Logging/02.10.01.06.05.60_TestIdAttrType.md>), [test type](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>), and [pass/fail result](<../02.10_Data_Logging/02.10.01.06.05.28_PassFailResultAttrType.md>).

If the per-pin on pass or per-pin on fail test suite flags, respectively, were set, the event also contains the [list of passed and failed pins](<../02.10_Data_Logging/02.10.01.06.05.34_PinPFResultAttrType.md>).

  - Next the FBC and fail addresses results, a [TestEvent](<../02.10_Data_Logging/02.10.01.06.03.12_TestEventType.md>) with TEST_TYPE_MEMORY as the value of the [ParametricOrFunctionalTestAttrType](<../02.10_Data_Logging/02.10.01.06.05.27_ParametricOrFunctionalTestAttrType.md>) parameter.

## Syntax

This is the structure of the EDL events for memory test in pseudo-code:

```
TestSuiteStartEvent

  TestFunctionStartEvent (site 1)
    TestEvent (main label functional pass/fail results)
    TestEvent (main label FBC pass/fail results)
      optional TestEvent(subroutine 1 functional pass/fail results)
      optional TestEvent(subroutine 1 FBC and fail addresses results)
      ...
      optional TestEvent(subroutine n functional pass/fail results)
      optional TestEvent(subroutine n FBC and fail addresses results)
  TestFunctionEndEvent (site 1)

  TestFunctionStartEvent (site 2)
    ...
  TestFunctionEndEvent (site 2)

  ...

  TestFunctionStartEvent (site n)
    ...
  TestFunctionEndEvent (site n)

TestSuiteEndEvent
```

These conditions apply:

- Events for passed tests are only created if the output on pass test suite flag is set; events for failed test are generated only if the output on fail flag is set.
- Subroutine events are only generated if subroutines exist.
- No events are generated for patterns based on parallel vectors.
- No memory test events are generated for patterns with no reconstruction data. Functional test events are still generated for such patterns.
- Events for FBC results are generated only if the [fail_count_enabling](<02.12.02.05.06.01.03.01_Parameters_for_the_ExecutionEngine_test_method.md>)[ parameter](<02.12.02.05.06.01.03.01_Parameters_for_the_ExecutionEngine_test_method.md>) is set to YES.

## Functional changes

- SmarTest 7.0.4: Logging memory tests events is available only in MTP on HSM.
- MTP 3.1.4: Logging memory tests events is available both in MTP on HSM and MTP on SOC.
