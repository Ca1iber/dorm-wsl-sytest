# DC event file syntax

The syntax of the DC event file follows the conventions of the [MTL compiler syntax](<02.12.03.02.02_MTL_compiler_syntax.md>).

Specifically, a DC event file looks like this:

```
:dcTest:
{
    :dcSet:
    {
        :name: <setName>
        :table:
        {
            :format:
            {:dcEvent:    :pinList:                :dcSetup:              :type:    }
            {<eventName><pinName>,...,<pinName><namespace>,<dataID>  DCScale    }
            {............     }
        }
[ :dcSequence:
        {
          :name:       <sequenceName>
          :interface:  {[<parameterName>...]}
          :period:     <periodLength>
          :table:
          {
            :format:
            { :dcEvent:      :offset:      }
            { <dcEventName><offsetValue> }
...
          }
        } ]
    }
...
}
```

The order of keywords shown above is typical, but not required; you can rearrange the keywords within a set of curly braces as desired.

Italic text indicates meta-syntax, as described in [Syntax conventions](<02.12.03.01.02_Syntax_conventions.md>).

## Keywords and parameters

These are the keywords and their parameters in alphabetical order:

 |

Keyword

 |

Parameters and descriptions

 |
 |

:dcEvent:

 |

<eventName>: The name of a DC event.

You can give the event any desired name, as long as it follows the [naming conventions](<02.12.03.02.03_Naming_rules_and_conventions.md>).

 |
 |

:dcSequence:

 |

Defines a sequence of DC events for use by the DC_EVENT_RANGE function (described in [Macros and functions in program files](<02.12.03.03.03.01.08_Macros_and_functions_in_program_files.md>)).

A sequence of DC events can be executed concurrently to normal MTL code, allowing you to shape the voltage levels during device accesses.

DC sequences are optional; they are needed only if you want to use the DC_RANGE_EVENT function.

See the "DC sequence keywords" table below for details.

 |
 |

:dcSet:

 |

<setName>: The name of a DC event set.

You can give the set any desired name, as long as it follows the [naming conventions](<02.12.03.02.03_Naming_rules_and_conventions.md>).

A DC event file can contain any number of DC sets, although only one of them can be active at any time. The desired set is specified by name in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>). (See the :name: keyword, below.)

 |
 |

:dcSetup:

 |

The action to be performed on the DC Scale card for the event.

<namespace>: The namespace indicates a set of DC events. It references a namespace defined in a test method or by the [DFTD](<../02.06_Command_Reference/02.06.02.02.68_DFTD__DFTD___DeFine_Test_Data.md>) firmware command.

Only one namespace can be referenced per pattern.

<dataID>: The ID of an event if the set specified by the namespace.

Note that the namespace and data ID are separated by a comma; there must be no space before or after the comma.

 |
 |

:dcTest:

 |

This keyword is required at the start of the file.

 |
 |

:name:

 |

<setName>: The name of a DC event set.

The active set for a given program is specified in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>) using the :dcTest: keyword.

You can give the set any desired name, as long as it follows the [naming conventions](<02.12.03.02.03_Naming_rules_and_conventions.md>).

 |
 |

:pinList:

 |

<pinName>: The name of a pin (as specified in the [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>)) affected by the event.

If multiple pins are to be affected, separate their names by commas. Do not add spaces after the commas or enclose the entire pin list in quotes. You cannot specify pin groups.

You can specify [Buses](<02.12.03.03.06.02_Buses.md>) defined in the [Pin mapping file](<02.12.03.03.06_Pin_mapping_file.md>).

For PMU events (see :type:, below), you can also specify ports.

 |
 |

:type:

 |

The pin type.

Two types of events are available:

- pmu: The event controls the PMUs of standard pins. Note that DC events of this type cannot be used in event sequences.
- DCScale: The event controls pins on DC Scale cards.
 |

## DC sequence keywords

These keywords let you specify sequences of DC events for use by the DC_EVENT_RANGE function (see :dcSequence:, above).

 |

Keyword

 |

Parameters and descriptions

 |
 |

:interface:

 |

<parameterName>: The name of a parameter for the sequence. These parameter names can be used to calculate the sequence's period and the offsets of the individual DC events in the sequence.

There can be any number of parameter names; they must be separated by spaces.

If no parameters are desired, leave the curly braces empty.

 |
 |

:name:

 |

<sequenceName>: The name of the DC event sequence by which it is called from the DC_EVENT_RANGE function.

See [Naming rules and conventions](<02.12.03.02.03_Naming_rules_and_conventions.md>) for naming restrictions.

 |
 |

:period:

 |

<periodLength>: An expression that provides the length of the DC event sequence in edges. The period allows you to create pauses between the last DC event of a sequence and the beginning of the next sequence iteration.

The expression can use parameters (from the :interface: keyword) to calculate the period. The period must be longer than the offset of any DC event in the sequence.

Note that the expression must be enclosed in quotes if it contains any spaces.

 |
 |

:table:

 |

The list of DC events and their offsets.

See the following table for details.

 |

The :table: element contains these keywords:

 |

Keyword

 |

Parameters and descriptions

 |
 |

:dcEvent:

 |

<dcEventName>: The name of a DC event to be used in the sequence. The event must be defined in the same DC set (see :dcset:, above.)

There can be any number of DC events in a sequence. An event can be used multiple times in a sequence.

DC events with the pmu type cannot be part of a DC sequence. (See :type:, above.)

 |
 |

:offset:

 |

<offsetValue>: An expression that provides the number of edges from the start of the sequence when the DC event is to be executed.

Note that the expression must be enclosed in quotes if it contains any spaces.

 |

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 2.4.0: Added :dcSequence: and subordinate keywords
- MTP 3.0.1: DC events now support also PMUs
- MTP 3.0.3: Buses can be specified in the :pinlist: column.
- MTP 3.0.3: (MTP on SOC 103.0.0) PMU type DC events are now available in both MTP on HSM and MTP on SOC
