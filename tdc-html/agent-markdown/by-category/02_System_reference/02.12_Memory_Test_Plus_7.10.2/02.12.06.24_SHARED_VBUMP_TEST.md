The SHARED_VBUMP_TEST class provides an API for changing the supply voltage levels during a functional test for the DUTs with [driver sharing](<02.12.02.05.06.07.01_Driver_sharing_concepts.md>).

When you use this API to create your own custom test method, you should add the following limit:

- "SharedVBump": Let's you define the test number for a functional test.

For how to add limits and their values to a test method, see [How to create a universal test method class](<../02.07_Test_Method_Reference/02.07.02.02.02_How_to_create_a_universal_test_method_class.md>).

You also need to include the driver sharing API library and header file to complete a test method code. For detail procedures, see [Setting up for using driver sharing APIs](<02.12.02.05.06.07.09.04_Setting_up_for_using_driver_sharing_APIs.md>).

If you Do not have special requirements, such as a customized testing algorithm or a special output format, you can use the [SharedVBump test method](<02.12.02.05.06.07.09.15_SharedVBump_test_method.md>), a ready-made test method by MTP, to do a quick test. For how to use this test method, see [SharedVBump syntax](<02.12.02.05.06.07.09.16_SharedVBump_syntax.md>).

Note The SHARED_VBUMP_TEST API is available only for MTP.

This API is defined in the header file /opt/93000mts/mts/solution_tools/common/include/SHARED_VBUMP_TEST.h.

## Class definition

### Public types

```
VBUMP_VDD = 1
VBUMP_VDDQ = 2
VBUMP_VDD_VDDQ = 4
enum VBUMP_SOURCE_TYPE
{ VBUMP_VDD = 1,
  VBUMP_VDDQ = 2,
  VBUMP_VDD_VDDQ = 4
}
```

- VBUMP_VDD: VDD as the VBump resource
- VBUMP_VDDQ: VDDQ as the VBump resource
- VBUMP_VDD_VDDQ: Both the VDD and VDDQ as the VBump resource

## Examples

### Note

The following examples demonstrate how to use this API within a test method. If you want to see a complete test method code via SHARED_VBUMP_TEST, find the example in /opt/93000mts/mts/solution_tools/common/sh_lib/DriverSharing.tar.gz.

### Example 1

Doing VBump test, the VBump resource is VDD.

```
#include "solution_tools.h"
#include "testmethod.hpp"
#include "mapi.hpp"

class CSharedVBump: public testmethod::TestMethod
{
protected:
    virtual void run()
    {
      ON_FIRST_INVOCATION_BEGIN();
      {
        // Always do initialization at the beginning of test
        mTest.init();

        // hand over the parameters to the test class
        mTest.sharingConfigFile("default.cfg")
             .bumpSource(SHARED_VBUMP_TEST::VBUMP_VDD)
             .highPower(MTP::OPTION_YES)
             .resultPin("@");

        // execute the test
        mTest.execute();
      }
      ON_FIRST_INVOCATION_END();

      // set result
      mTest.judgeAndLog();
      // Print out in the UI Report Window.
      mTest.print();
    }

private:
    SHARED_VBUMP_TEST mTest;
  };
```

### Example 2

Customizing output.

```
#include "solution_tools.h"
#include "testmethod.hpp"
#include "mapi.hpp"

class CSharedVBump: public testmethod::TestMethod
{
protected:
    virtual void run()
    {
      ON_FIRST_INVOCATION_BEGIN();
      {
        // Always do initialization at the beginning of test
        mTest.init();

        // hand over the parameters to the test class
        mTest.sharingConfigFile("default.cfg")
             .bumpSource(SHARED_VBUMP_TEST::VBUMP_VDD)
             .highPower(MTP::OPTION_YES)
             .resultPin("@");

        // execute the test
        mTest.execute();
      }
      ON_FIRST_INVOCATION_END();

      // set result
      mTest.judgeAndLog();
      // Print out in the UI Report Window.
      STRING_VECTOR pinNames =
        PinUtility.getDigitalPinNamesFromPinList("@", TM::ALL_DIGITAL, TRUE);

      cout << "Test result of site " << CURRENT_SITE_NUMBER() << ": " << mTest.getPassFail() << endl;

      for (STRING_VECTOR::const_iterator it = pinNames.begin();
           it != pinNames.end(); ++it)
      {
        cout << "PIN (" << *it << ")\t" << mTest.getPassFail(*it) << endl;
      }
    }

private:
    SHARED_VBUMP_TEST mTest;
};
```
