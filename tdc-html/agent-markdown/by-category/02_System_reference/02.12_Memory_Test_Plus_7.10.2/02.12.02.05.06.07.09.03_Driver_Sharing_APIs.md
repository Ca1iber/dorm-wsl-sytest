# Driver Sharing APIs

Using those ready-made driver sharing test methods provided with MTP is normally the quickest and easies way to test shared DUTs. However, if you have special requirements that those test methods cannot meet, you can also develop you own test methods using these APIs:

- To test pins (either shared, non-shared or cross-terminated pins) with same measurement conditions, use APIs:

  - [SHARED_CONTINUITY_TEST](<02.12.06.21_SHARED_CONTINUITY_TEST.md>) lets you check the continuity and find short circuits for the DUTs with driver sharing.
  - [SHARED_IDD_TEST](<02.12.06.22_SHARED_IDD_TEST.md>) lets you check the IDD and IDDQ for the DUTs with driver sharing.
  - [SHARED_LEAKAGE_PARALLEL_TEST](<02.12.06.23_SHARED_LEAKAGE_PARALLEL_TEST.md>) lets you do the parallel leakage test for the DUTs with driver sharing.
  - [SHARED_VBUMP_TEST](<02.12.06.24_SHARED_VBUMP_TEST.md>) lets you change the power supply voltages during a functional test for the DUTs with driver sharing.

All these APIs support logging their test results.

- To test any number of pins (either shared, non-shared or cross-terminated pins) with any types of measurement conditions within one test method, these classes, defines, and functions are supported:

## Functional changes

- Introduced in MTP 3.1.3
- MTP 3.1.5: Added new APIs for testing any numbers of pins with any measurement conditions within one test method.
- MTP 3.3.2: Pre-setups for using driver sharing APIs have been automatically done by the system.
