# Creating an FXDL file for a repaired fixture

The inherent shared-bus delay is introduced by the load board and is constant across all test.

## About this task

Measure the inherent shared-bus delay when you have repaired or otherwise modified the board.

## Before you begin

Make sure that SmarTest is running.

Insert the load board into the test head.

Create an FXDL file as described in [Measuring fixture delay](<02.12.02.05.06.07.07.05.01_Measuring_fixture_delay.md>).

## Procedure

-  Load the pin configuration file specified in the [Sharing configuration file](<02.12.02.05.06.07.07.02_Sharing_configuration_file.md>).
-  Open the Fixture Delay Tool.
-  Choose Edit > Select Configured.
-  Choose Edit > Set Default and enter 0 in the entry dialog.
-  Choose Edit > Deselect All.
-  Insert a short device into the first sites on all socket boards.
-  Select the first site by control-clicking the column title:  ![Fixture Delay Tool, selecting a site](<../../../../raw/126372.png>)
-  Choose Execute > Measure with Dual Transmission Lines to perform the measurement.
-  Save the measurements as the FXDL file for the first site (for example, by naming it site1.fxdl).
-  Repeat steps 3 through 9 for all other sites that have been repaired or modified.
-  Use the fd_merge tool's -a option to apply the same loading that the manufacturer used to the files generated in steps 3 through 10.

You can find out the loading by running fd_merge with the manufacturer data using the fd_merge tool's -v option in the process described in [Measuring fixture delay](<02.12.02.05.06.07.07.05.01_Measuring_fixture_delay.md>).

## Results

You have created a replacement FXDL file (<merged FXDL file>) for the repaired fixture that you can use in calibration procedures.

## Functional changes

- Introduced before SmarTest 6.3.2
