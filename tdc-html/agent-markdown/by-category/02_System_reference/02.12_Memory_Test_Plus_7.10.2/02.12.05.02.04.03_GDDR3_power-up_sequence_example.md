# GDDR3 power-up sequence example

GDDR3 SDRAMs must be powered up and initialized in a pre defined manner (see following figure). Operational procedures other than those specified may result in undefined operation.

  ![Power up and initialization diagram](<../../../../raw/80037.gif>)

An MTL example of an GDDR3 initialization sequence is shown in the figure below.

  ![GDDR3 initialization sequence MTL example](<../../../../raw/81539.png>)  Note The usage of the character a for address function names and d for data function names in the above example is not enforced by the [MTL compiler](<02.12.03.02.05_Using_the_MTL_compiler_from_the_command_line.md>). It is just recommended by Advantest due to readability of your memory test pattern.

In the GDDR3 initialization sequence MTL example shown in the figure above access to the different signals is split into:

- Address-based access

Identified by the character a at the beginning of the function name, for example `aWRITE(bank, column)`.

Signals in the address group are: CMD, ADDRESS, BANK, CLK, RESET, VREF

- Data-based access

Identified by the character d at the beginning of the functions name, for example `dWRITE(data)`.

Signals in the data group are: WDQS, DM, DQi, RDQS, DQo

 Note Every test system cycle can be split up into several device accesses. In the example above an device access for all data pins and a separate access for all other pins is used.

Each function call in above sequence implements four GDDR3 memory device cycles. Using x8 mode with 50% duty cycle matches perfectly to one test system device cycles (see following figure).

  ![Clock of WRITE to PRECHARGE](<../../../../raw/81547.png>)

For further information see

- [GDDR3 MTL examples](<02.12.05.02.04.04_GDDR3_MTL_examples.md>) for the function calls used in the initialization sequence and
