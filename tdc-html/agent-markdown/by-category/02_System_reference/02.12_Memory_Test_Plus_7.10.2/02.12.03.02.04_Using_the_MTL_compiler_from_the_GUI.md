# Using the MTL compiler from the GUI

#### Subtopics

- [MTL Compiler Control dialog](<02.12.03.02.04.01_MTL_Compiler_Control_dialog.md>)

You can run the MTL compiler using a graphical user interface (GUI), if desired. A command dialog offers full control of the execution options.

## About this task

The MTL compiler is used to convert a test program and a set of setup files into an executable memory test pattern. Its GUI is integrated into SmarTest and is the most common way to run the compiler. The GUI (as opposed to the command line) must be used if you want to automatically upload and run the compiled vectors.

## Before you begin

Make sure that you have prepared all required configuration files, as described in [Basic MTL workflow](<02.12.03.02.01_Basic_MTL_workflow.md>).

Note The MTL compiler requires a FLEXlm license provided by a FLEXlm license server. If the FLEXlm license server cannot provide a license, the MTL compiler will not start. For further details on FLEXlm licensing see Installing your FLEXlm license in the installation guide.

## Procedure

-  Start the [Memory Test Manager](<02.12.04.03.02_Memory_Test_Manager.md>).
-  To start the MTL compiler, click its button in the Memory Test Manager window:  ![Memory Test Manager (MTM)](<../../../../raw/79494.png>)

The MTL Compiler Control window opens.

Note that you can open multiple instances of the compiler control dialog (up to six) by clicking the button in the MTM more than once.

-  Choose the APG pattern files that you want to compile and set the execution options in the dialog.

This dialog is described in detail in [MTL Compiler Control dialog](<02.12.03.02.04.01_MTL_Compiler_Control_dialog.md>).

-  Click Run.

The compiler creates a vector pattern file from each of the specified files APG pattern files according to the options provided. It also creates a makefile to use in future compilations; if such a makefile exists, it only compiles those files that have changed or are depending on changed files.

Progress information on the compilation process is provided in the MTL Compiler Output tab, which is displayed in the dialog once you click Run.

While the compilation is in progress, you can click Abort to stop it.

## Results

The compiler has created these output files in the directories in which the specified pattern files (.apg file) are located:

- <apg pattern file name>.apg.vec: The binary file with the vector pattern as a per-pin subroutine. This pattern can be downloaded into the tester using SmarTest.
- <apg pattern file name>-EL7.apg.rec.so: An optional file containing binary reconstruction information for converting cycle-based data to address-based data. It is only generated when the Generate Reconstruction File option is checked.
- If you have checked the Automatic Waveform Generation option, the existing waveform file (the timing or waveform map file specified in the APG pattern file) is backed up by appending .BAK$$ to its name and a new timing file with the original name is created in its place.

If you have specified the appropriate copying, downloading, or execution options, the generated vector files are post-processed accordingly. That is, they are copied to a specified directory, downloaded into the tester, or executed.

Error messages of the MTL compiler

If error messages are displayed in the MTL Compiler Output tab during or after the compilation, the following topics contain possible solutions:

[Data Queue Empty error](<02.12.03.05.02.01_Data_Queue_Empty_error.md>)

## What to do next

If you did not specify that this happen automatically, you can now download the files to the tester and execute them to test the DUT.

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 2.4.2: New file name convention for binary files on Red Hat Linux 5
- MTP 3.0.1: A makefile is created and used during compilation
- MTP 3.0.1: Multiple instances of the compiler control dialog can be opened
- MTP 3.0.1: Compiler output is provided in a tab of the dialog
- MTP 3.0.1: Removed the -r0 option and support for non-binary reconstruction files (.apg.rec files)
