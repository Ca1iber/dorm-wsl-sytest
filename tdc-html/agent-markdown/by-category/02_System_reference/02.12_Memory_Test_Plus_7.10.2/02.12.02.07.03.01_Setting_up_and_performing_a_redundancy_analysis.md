To set up redundancy analysis, you specify the relevant details of the DUT, the execution options for the analysis, specific options for the algorithm, and the desired output format options.

## Before you begin

Gather all required information about the architecture of the DUT, its redundancy capabilities, and the guidelines used to assign spares to failed elements.

Set up the map converter library you plan to use and make sure that it contains the required functions. If it does not, add them and recompile the library as described in [Setting up address scrambling](<02.12.02.05.03_Setting_up_address_scrambling.md>). The required functions are:

- If the map converter type is RA_LAYOUT_BASED: [get_ra_layout](<02.12.02.07.03.01.03.05.01_get_ra_layout.md>) and [phys_to_layout](<02.12.02.07.03.01.03.05.02_phys_to_layout.md>).
- If the map converter type is TOPO_ADDR_BASED: get_map_size and phys_to_map.

Make sure that the folder structure for the redundancy analysis files is correctly set up, as described in [Folder structure for redundancy analysis files](<02.12.02.07.03.01.01_Folder_structure_for_redundancy_analysis_files.md>).

## Procedures

### Online analysis

- Decide on whether you want to use the Successive algorithm supplied by Advantest.

If you want to use your own algorithm, write it as explained in [Writing a custom redundancy analysis algorithm](<02.12.02.07.03.02.05_Writing_a_custom_redundancy_analysis_algorithm.md>).

- Describe the DUT in the DUT representation file as explained in [DUT representation file](<02.12.02.07.03.02.03_DUT_representation_file.md>).
- Compile the DUT representation file as described in [Compiling the DUT representation file](<02.12.02.07.03.02.03.01_Compiling_the_DUT_representation_file.md>).
- Set up the operation parameters for the redundancy analysis as described in [Redundancy analysis configuration file](<02.12.02.07.03.01.03.01_Redundancy_analysis_configuration_file.md>).
- Set up the operation parameters for the redundancy analysis algorithm as described in [Control file for the Successive algorithm](<02.12.02.07.03.02.02_Control_file_for_the_Successive_algorithm.md>).
- For using the redundancy analysis online (that is, as part of a test flow), insert the ExecutionEngine test method in a test flow. Configure it as described in [Parameters for the ExecutionEngine test method](<02.12.02.05.06.01.03.01_Parameters_for_the_ExecutionEngine_test_method.md>).
- Run the test flow.

### Offline analysis

- If the bit fail map you want to analyze does not already exist, run a test to create a bit fail map for the DUT.
- Perform steps 1 through 5 from the "Online analysis" procedure (above).

In step 4, make sure to specify the bit fail map in the faildata_file parameter of the [Redundancy analysis configuration file](<02.12.02.07.03.01.03.01_Redundancy_analysis_configuration_file.md>).

- Enter this command in a terminal window:

```
RaServer -o <ra_config_file>
```

Where <ra_config_file> is the [Redundancy analysis configuration file](<02.12.02.07.03.01.03.01_Redundancy_analysis_configuration_file.md>).

## Results

The algorithm log and solution output is available in the locations described in [Output of the Successive algorithm](<02.12.02.07.03.02.04_Output_of_the_redundancy_analysis_algorithm.md>).

The redundancy analysis logs are available in /var/opt/93000mts/mts/log:

- The redundancy analysis server log is named MTP_RAServer.log and is stored directly in that directory.
- Logs of the individual services are named  <ra_service_id>.log and are stored in the RA_logs subdirectory.

## What to do next

Implement the repair solution for the device.

## Functional changes

- Introduced in MTP 2.6.5
- MTP 3.0.3: (MTP on SOC 103.0.0) Redundancy analysis is now performed via the ExecutionEngine test method.
- MTP 3.2.1: MTP-on-SOC and MTP-on-HSM become one software. There are no differences between them. Features can be different if the used licenses are different.
- MTP 3.2.2: Removes the tool used for verifying the redundancy analysis.
