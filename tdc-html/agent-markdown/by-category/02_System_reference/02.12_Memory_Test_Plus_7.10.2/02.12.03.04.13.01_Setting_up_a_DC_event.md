# Setting up a DC event

#### Subtopics

- [Specifying DC event details](<02.12.03.04.13.01.01_Specifying_DC_event_details.md>)
- [Differences between DCScale type and PMU type events](<02.12.03.04.13.01.02_Differences_between_DCScale_type_and_PMU_type_events.md>)
- [Limitations of PMU type DC events](<02.12.03.04.13.01.03_Limitations_of_PMU_type_DC_events.md>)

DC events allow you to control initiate measurements as well as control voltage or current on DC Scale pins and PMUs on standard pins.

## Before you begin

In SmarTest, set up any DC events that you want to call from the DC event file.

## Procedures

### Setting up a DC event

- If there is no DC event file yet, create a new one or copy an existing one.

The structure of DC event files is described in [DC event file syntax](<02.12.03.03.08.01_DC_event_file_syntax.md>).

- If there is no DC set or you need an additional set, create a DC set in the DC event file.
- Specify the desired events in the DC set.

For details on doing so, see [Specifying DC event details](<02.12.03.04.13.01.01_Specifying_DC_event_details.md>).

- Save the DC event file in the appropriate device directory.
- Reference the DC event file and DC set from the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>) using the :dcTest: keyword.
- In the appropriate locations in the [program code](<02.12.03.03.03_APG_program_file.md>), insert the DC_EVENT function, providing the name of the event as its parameter.

When a DC event with a type of pmu is called by the DC_EVENT function, a pad() instruction must be inserted before it. This is required because a PMU DC event interrupts the pattern on all pins, which means that the pattern must be kept in an interruptible state until a tester cycle boundary is reached. The pad() instruction ensures that this happens.

 Note Strictly speaking, a pad() instruction is not necessary when you make sure that all PMU events in your program occur on tester cycle boundaries when all pins are in an interruptible state. (If this is not the case, a compiler error is created for PMU events without preceding pad() instructions.) However, since there is usually no benefit in leaving out pad() instructions, we recommend that you always put them before all DC events.

### Placement of DC events in code

There are certain limitations to observe when placing multiple DC events in code:

- DCScale type DC events must have a minimum distance of 32 vectors.
- After a measurement in a DCScale type DC event, a settling time of 2 碌s is required. If another measurement is initiated on the same board before this time is elapsed, the accuracy may be impaired.
- The maximum frequency of DCScale type measurements on a DPS board is in the region of 300,000 samples per second.
- The frequency for forcing voltages using DCScale type DC events must not exceed 3 kHz per DPS board.

For more information about the number of vectors, sampling, and settling time for DC events, see [Timing of DC events - DPS128 / DPS64](<../02.07_Test_Method_Reference/02.07.04.01.63.01.03_Timing_of_DC_events_-_DPS128___DPS64.md>).

## Results

The pins in the DC events are accessed as specified when the compiled program is executed.
