# Redundancy analysis configuration file

The redundancy analysis configuration file specifies settings for performing the analysis.

You specify the algorithm to be used, parameters for the algorithm, various settings files, and (for offline operation), the fail data to analyze.

## File types

The configuration settings can be specified either in an XML file or a plain text file. A utility is provided to convert text files to XML.

## XML files

XML settings files must have a .xml file name extension.

The root element of the XML file always is `<RA_Config></RA_Config>`.Within this element, individual settings are subelements.

For example, to specify librasucc.so as the algorithm library, you would add this element:

```
<algorithm_lib>/opt/93000mts/mts/rr/sh_lib/librasucc.so</algorithm_lib>
```

See the examples, below, for a more complete example of the XML syntax.

Note XML has very strict requirements for syntactical correctness. While XML files can be edited with any text editor, we recommend that you create XML settings files in an XML editor and check it for well-formedness before using it. A wide range of XML editors is available. For example, [XMLmind XML Editor](<http://www.xmlmind.com/xmleditor/>) is free and works on all major operating systems. (Note that this is provided just for informational purposes and constitutes neither a recommendation nor an endorsement.)

## Text files

Text settings files must have a .rcs file name extension.

Put settings in the text file at the beginning of new lines. Each setting is followed by a colon, the value, and a semicolon. Settings must be enclosed in quotation marks.

For example, to specify librasucc.so as the algorithm library, you would add this line to the text file:

```
algorithm_lib: "/opt/93000mts/mts/rr/sh_lib/librasucc.so";
```

See the examples, below, for a more complete example of the text syntax.

Note that paths in text files cannot exceed 250 characters in length. If you need to specify longer paths, use an XML file.

## Converting files

You can convert redundancy analysis configuration files in text format to the XML format using the rcsParser utility, which is located in /opt/93000mts/mts/rr/bin.

To convert a file, provide it as a parameter to the utility on the command line. For example:

```
rcsParser sampleFile.rcs
```

## Syntax

 |

Parameter

 |

Values and Description

 |
 |

algorithm_lib

 |

The path and file name of the library compiled from the analysis algorithm.

The value can be an absolute path or a relative path from the mts/ra/algorithm/sh_lib/ directory in the current device directory.

See the "Specifying library names" section below this table for details.

 |
 |

algorithm_parameter

 |

A string containing the parameters that are passed to the algorithm.

The number, type, and semantics of these parameters depend on the chosen algorithm. For the default Successive algorithm, they are described in [Parameters of the Successive algorithm](<02.12.02.07.03.02.01_Parameters_of_the_Successive_algorithm.md>).

 |
 |

environment_info

 |

A comma-separated list of environment information:

- Lot ID
- Cassette ID
- Wafer ID
- x-coordinate of the die
- y-coordinate of the die

You can omit individual items by specifying a space for them.

In XML, no quotes around the string are required, but in the .rcs file, it must be enclosed in quotes.

This parameter is optional.

 |
 |

result_root_path

 |

The path under which the result files of the redundancy analysis are stored. (Some files may be stored in subfolders of this directory.)

If this value is not specified, the default <device directory>/mts/ra/result is used.

This parameter is optional.

 |
 |

algorithm_control

 |

The path of the algorithm control file to be used.

This parameter is required only if the algorithm uses a control file. The control file for the default successive algorithm is described in [Control file for the Successive algorithm](<02.12.02.07.03.02.02_Control_file_for_the_Successive_algorithm.md>).

The value can be an absolute path or a relative path from the mts/ra/control_options/ directory in the current device directory.

 |
 |

DUT_rep

 |

The path of the DUT representation shared library to be used.

The DUT representation file for the default successive algorithm is described in [DUT representation file](<02.12.02.07.03.02.03_DUT_representation_file.md>). This file is required for the Successive algorithms and all other algorithms based on the RA algorithm template.

If you write your own algorithm, you may write it in such a way as not to use the DUT representation file, but we do not recommend or support this.

The value can be an absolute path or a relative path from the mts/ra/device_rep/sh_lib/ directory in the current device directory.

See the "Specifying library names" section below this table for details.

This parameter is optional for legacy algorithms.

 |
 |

map_converter

 |

The path of the map converter shared library to be used.

Note that the shared library must implement certain required functions: get_ra_layout and phys_to_layout if the map converter has the type RA_LAYOUT_BASED and get_map_size and phys_to_map if the type is TOPO_MAP_BASED. See [Setting up address scrambling](<02.12.02.05.03_Setting_up_address_scrambling.md>) for more information.

The value can be an absolute path or a relative path from the mts/ra/bitmap/converters/bin/ directory in the current device directory.

See the "Specifying library names" section below this table for details.

If you write your own algorithm, you may write it in such a way as not to use the DUT representation file, but we do not recommend or support this.

 |
 |

ra_counting_enabling

 |

When the failing cell counts generated during the tests are to be summed up by the redundancy analysis algorithm:

- Disable: No summing is performed.
- Enable_on_concurrent_mode: The failed cells are summed after each bit fail map.

This parameter is used only in offline mode, not in online mode.

The default value is Enable_on_concurrent_mode.

 |
 |

ra_algorithm_enabling

 |

When the redundancy analysis algorithm is to be executed:

- Disable: The algorithm is not executed.
- Enable_on_concurrent_mode: The algorithm is executed after each bit fail map.

This parameter is used only in offline mode, not in online mode.

The default value is Disable.

 |
 |

ra_counting_results_leverage

 |

Whether to use the counting results in the execution of the redundancy analysis algorithm:

- YES: The counting results are used. This requires that RA_counting is enabled, that RA_algorithm is enabled, and that the redundancy analysis algorithm supports using the counting results in its analysis.

Note that any combination of concurrent and delayed enabling for counting and algorithm is supported. However, when you specify delayed counting and concurrent execution of the algorithm, the algorithm cannot leverage the counting results.

- NO: The redundancy analysis algorithm does not use the counting results.

This parameter is optional.

The default value is YES.

 |
 |

mapconv_type

 |

The type of the specified map converter:

RA_LAYOUT_BASED: The map converter provides the algorithm that is based on RA layout information, that is, tuples of data bit group, segment, column, and row. The successive algorithm expects this kind of input.

TOPO_ADDR_BASED: The map converter provides the algorithm with input based on topological addresses.

 |
 |

device_path

 |

The path of the device directory of the device to be analyzed.

This parameter is evaluated only in offline mode.

 |
 |

test_name

 |

The name of the test.

In principal, you can use any string here, but we recommend using the name from the test that has been used to create the bitmap file being.

This parameter applies only to offline analysis.

 |
 |

algorithm_timeout

 |

The timeout of the redundancy analysis, in seconds. If the timeout is exceeded, the analysis is considered to have failed and no solution output is created.

A timeout value of -1 or 0 indicates that there is no timeout.

This parameter is optional for online redundancy analysis and required for offline analysis.

 |
 |

faildata_file

 |

The data file containing the fail data that are the input for the redundancy analysis in offline mode.

You can specify a bit fail map (.bfd), a [BFD list file](<02.12.02.07.03.01.05_Bit_fail_map_list_file.md>) (.bfdl), or a physical address-based bit list file (.pabl).

The value can be an absolute path or a relative path from the mts/bitmap/bitmap_data/ directory in the current device directory.

 |

## Specifying library names

Several parameters in the redundancy analysis file require you to specify a shared library:

/opt/93000mts/mtp64_<version>/rr/sh_lib/librasucc-EL7.x86_64.so

An error message is displayed if a library with the required name cannot be found.

## Example

This is a sample redundancy analysis configuration file in XML format:

```
<?xml version="1.0" encoding="UTF-8" standalone="no"?>
<RA_Config>
 <algorithm_lib>/opt/93000mts/mts/rr/sh_lib/librasucc</algorithm_lib>
 <algorithm_control>raControlFile.rac</algorithm_control>
 <algorithm_parameter>1:1:0:7:7:0,/tmp,STD2</algorithm_parameter>
 <environment_info>lot,cassette, waf, 0, 0</environment_info>
 <DUT_rep>libradutdef</DUT_rep>
 <map_converter>libra_failmap</map_converter>
 <mapconv_type>RA_LAYOUT_BASED</mapconv_type>
 <ra_counting_enabling> Enable_on_concurrent_mode </ra_counting_enabling>
 <ra_algorithm_enabling> Enable_on_concurrent_mode </ra_algorithm_enabling>
 <ra_counting_result_leverage>YES</ra_counting_result_leverage>
 <ra_counting_enabling> Enable_on_concurrent_mode </ra_counting_enabling>
 <ra_algorithm_enabling> Enable_on_concurrent_mode </ra_algorithm_enabling>
 <ra_counting_result_leverage>YES</ra_counting_result_leverage>
 <device_path> /home/demo/devices/eDram_demo </device_path>
 <test_name> mts_m7_b0_Yf_RA </test_name>
 <algorithm_timeout> -1 </algorithm_timeout>
 <faildata_file> mts_m7_b0_Yf_RA </faildata_file>
</RA_Config>
```

These are the same settings as a text file:

```
/* Ra Configuration Setup file */
algorithm_lib: "/opt/93000mts/mts/rr/sh_lib/librasucc";
algorithm_control: "raControlFile.rac";
algorithm_parameter: "1:1:0:7:7:0,/tmp,STD2";
environment_info: "lot,cassette, waf, 0, 0";
DUT_rep: "libradutdef";
map_converter: "libra_failmap";
mapconv_type: "RA_LAYOUT_BASED";
ra_counting_enabling: "Enable_on_concurrent_mode";
ra_algorithm_enabling: "Enable_on_concurrent_mode";
ra_counting_result_leverage: "YES";
ra_counting_enabling: "Enable_on_concurrent_mode";
ra_algorithm_enabling: "Enable_on_concurrent_mode";
ra_counting_result_leverage: "YES";
device_path: "/home/demo/devices/eDram_demo";
test_name: "mts_m7_b0_Yf_RA";
algorithm_timeout: -1;
```

## Functional changes

- Introduced in MTP 2.6.5
- MTP 3.0.3: (MTP on SOC 103.0.0) Added environment_info, result_root_path, ra_counting_enabling, ra_algorithm_enabling, and ra_counting_results_leverage parameters.
- MTP 3.0.3: (MTP on SOC 103.0.0) Both XML and text files can now be used for both online and offline analysis.
- MTP 3.2.1: MTP-on-SOC and MTP-on-HSM become one software. There are no differences between them. Features can be different if the used licenses are different.
- MTP 3.3.2: Obsoletes the Enable_on_delayed_mode option for both the ra_algorithm_enabling and ra_counting_enabling parameters.
