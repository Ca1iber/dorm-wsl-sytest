# Redundancy analysis on multiple test suites

Redundancy analysis can be performed on multiple test suites, either online or offline. Some specific considerations apply.

## About this task

Perform these steps in addition to those in [Setting up and performing a redundancy analysis](<02.12.02.07.03.01_Setting_up_and_performing_a_redundancy_analysis.md>) when you want to perform redundancy analysis on multiple test suites in one or more testflows.

## Before you begin

Set up redundancy analysis as described in [Setting up and performing a redundancy analysis](<02.12.02.07.03.01_Setting_up_and_performing_a_redundancy_analysis.md>).

## Procedure

-  Specify the desired modes - blocking or non-blocking and concurrent or delayed - in the first test suite (of the first testflow, if you perform the analysis on multiple testflows).

The settings in this test suite apply to the entire redundancy analysis.

-  By setting the RA_enabling parameter for the various test suites as required specify which test suites are to be included in the redundancy analysis.
-  If you perform the redundancy analysis over multiple testflows, make sure to set the RA_generate_overlaid_bitmap [parameter](<02.12.02.05.06.01.03.01_Parameters_for_the_ExecutionEngine_test_method.md>) in the ExecutionEngine test method to Yes.

## Results

The redundancy analysis is performed on the specified test suites.

When the analysis of the results of a particular test suite indicates that a device cannot be repaired, the redundancy analysis is stopped at that point.
