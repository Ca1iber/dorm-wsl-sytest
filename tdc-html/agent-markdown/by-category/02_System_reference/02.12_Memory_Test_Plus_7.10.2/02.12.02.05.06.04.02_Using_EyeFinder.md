# Using EyeFinder

TrainingAlgorithm

 |

SpecTraining or EmbeddedTraining

SpecTraining performs the search for the eye on the test controller workstation as a parallel spec search. It does not support multiport setups.

Controlling the amount of output messages in the report window is possible by setting the [test flow flags](<02.12.02.05.10.02_Testflow_flags.md>):

- Output on fail
- Output on pass

Reporting messages are controlled:

- If the two flags are both set to 'Off' the execution result of the EyeFinder test method is just Pass or Fail. No report will be generated. This improves the run time and should be used in HVM testing.

Setting the flag to:

- 'Output on fail' to 'On': detailed failure information only is printed to the report window
- 'Output on pass' to 'On': a summary report for both failing and passing pins is printed.

The following shows an output example for Output on fail set to On:

```
No 1st output transition on pin 0 site 1 found: RSSR 1,E,,,(@)
No 2nd output transition on pin 0 site 1 found: RSSR 2,E,,,(@)
No 1st input transition on pin 0 site 1 found: RSSR 3,E,,,(@)
No 2nd input transition on pin 0 site 1 found: RSSR 4,E,,,(@)
```

The following shows an output example for Output on pass set to On:

```
Site: 1
Max Pins: 16
Output Pin DQ0_o is failing
 Input Pin DQ0_i is failing
 Input Pin DQ1_i is passing
 Input Pin DQ2_i is passing
 Input Pin DQ3_i is passing
 Input Pin DQ4_i is passing
```

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 3.0.1: Added parameters TrainingAlgorithm, out_pins, out_spec_names, in_pins, in_N_pins, in_spec_names; removed parameter period
- MTP 3.0.1: The EyeFinder is now configured in a window instead of a dialog.
