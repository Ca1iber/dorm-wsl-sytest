# Defining memory test patterns using x-modes

#### Subtopics

- [Introducing x-modes](<02.12.02.04.02.01_Introducing_x-modes.md>)
- [Test system front-end involvement in using x-modes](<02.12.02.04.02.02_Test_system_front-end_involvement_in_using_x-modes.md>)
- [Setting up an x-mode](<02.12.02.04.02.03_Setting_up_an_x-mode.md>)

The V93000 timing system uses x-modes to support the execution of patterns at the highest frequency the test system is capable of. This section will introduce the general concepts for defining the timing and how memory test patterns are compiled for different x-modes.

The following is needed to support [x-modes](<02.12.02.04.02.01_Introducing_x-modes.md>):

- A test system with a front end able to drive or receive signals with a faster rate than the test system itself as described in [test system front end involvement in using x-mode](<02.12.02.04.02.02_Test_system_front-end_involvement_in_using_x-modes.md>).
- A physical waveform table containing the different possible combinations of ones and zeros the memory test pattern might need.
- A programming language to define the memory test pattern, a compiler to compile that memory test pattern for any x-mode and determine what physical waveform is required at execution time for that x-mode with a memory test pattern.
