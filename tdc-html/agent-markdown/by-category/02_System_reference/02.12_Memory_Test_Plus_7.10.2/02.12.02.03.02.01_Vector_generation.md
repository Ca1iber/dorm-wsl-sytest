# Vector generation

When generating a standard test, a set of vectors are generated and then loaded into the vector memory (SDRAM). These vectors are applied to the DUT. The sequencer program controls the execution sequence of all drive (and compare) data. It is loaded into the sequencer memory (SRAM)

This way of testing memory devices would be fine as long as the pattern required to test the device fits within the available vector memory. Since this is no longer the case, other ways of testing the device are necessary. One way of doing this is to essentially compress your drive data - for example, by using sequencer sub-routines - so that it fits within vector memory.

The per-pin APG works by generating the test pattern from sequencer sub-routines, on a per-pin basis. Each pin of your memory test has its own set of sequencer sub-routines, which in turn generate the appropriate repeat language commands. It is low level sequencer program for these sequencer sub-routines, that are loaded into the sequence memory (instead of the individual vectors loaded into the vector memory). As these routines require only a fraction of the space a set of vectors would (maybe 1/100 or 1/1000 of the size), much larger test patterns can be accommodated - without the need for segmentation.
