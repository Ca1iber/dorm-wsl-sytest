# Output of the redundancy analysis algorithm

Running the redundancy analysis creates several log and solution files as the output.

 Note The output and its contents depends on the algorithm used. The files described here are created when the Successive algorithm is used (some of the files are also generated by any other algorithm based on the RA algorithm template); when you are using a different algorithm, see its documentation for information on its output.

Running the Successive algorithm creates these output files:

- Algorithm log files

These files are located in the directory specified in the log file root path passed as a [parameter](<02.12.02.07.03.02.01_Parameters_of_the_Successive_algorithm.md>) to the algorithm; if no such parameter is provided, in the /mts/ra/results/ directory in the current device directory. There is a subdirectory ra_exec_log that contains all algorithm log files in the following directory structure: <lot ID>/<cassette ID>/<wafer ID>/. Each wafer directory contains log files named dieX<die x-position>Y<die y-position>_<test program>_<RA test name>_<temperature>_<site index>.exec.

- Solution files

These files are located in the directory specified in the log file root path passed as a [parameter](<02.12.02.07.03.02.01_Parameters_of_the_Successive_algorithm.md>) to the algorithm; if no such parameter is provided, in the /mts/ra/results/ directory in the current device directory. There is a subdirectory ra_solution_log that contains all solution files in the following directory structure: <lot ID>/<cassette ID>/<wafer ID>/. Each wafer directory contains solution files named dieX<die x-position>Y<die y-position>_<test program>_<RA test name>_<temperature>_<site index>.soln.

The <RA test name> element of the file names is the test name defined in the [Redundancy analysis configuration file](<02.12.02.07.03.01.03.01_Redundancy_analysis_configuration_file.md>) for offline execution and the name of the test suite for online execution. If online redundancy analysis is performed across multiple test suites, <RA test name> is the content of the RA_execution_name parameter.

Note In addition to these algorithm-specific files, an RA Server log (in /var/opt/93000mts/mts/log/) and RA service log files (in /var/opt/93000mts/mts/log/RA_logs/, each named with the service's ID) are generated. These files are independent of the redundancy analysis algorithm.

## Algorithm log file

The algorithm log file contains detailed information on the functions executed as part of the redundancy analysis, the data they operate on, and their results.

## Solution file

There are two formats for the solution file, both of which present the same information. The desired format is specified in the solution output selector parameter for the Successive algorithm (as explained in [Parameters of the Successive algorithm](<02.12.02.07.03.02.01_Parameters_of_the_Successive_algorithm.md>)).

Format 1 includes the die x- and y-coordinates and the information whether the device is reparable. It then notes the number of row replacements and specifies each replacement as a tuple containing the spare row and the original row it replaces. This is followed by the number of column replacements and a tuple for each column replacement.

For example:

```
Die X = 0, Y = 0
Repairable = YES
R=4 (8, 140) (9, 141) (10, 142) (11, 143)
C=12 (24, 830) (25, 831) (26, 846) (27, 847) (28, 862) (29, 863) (40, 830) (41, 831) (42, 846) (43, 847) (44, 862) (45, 863)
```

Format 2 includes the die x- and y-coordinates and the information whether the device is reparable. It then includes each replacement on a separate line.

For example (same information as above):

```
Die X = 0, Y = 0
Repairable = YES
SR=8:R=140:
SR=9:R=141:
SR=10:R=142:
SR=11:R=143:
SC=24:C=830:
SC=25:C=831:
SC=26:C=846:
SC=27:C=847:
SC=28:C=862:
SC=29:C=863:
SC=40:C=830:
SC=41:C=831:
SC=42:C=846:
SC=43:C=847:
SC=44:C=862:
SC=45:C=863:
```

The solution file also includes the output of the RA counting algorithm. This output is included at the beginning of the file, and it is stored in comment lines (beginning with #).

The amount of output data included depends on the setting of the Output_level parameter in the [Control file for the Successive algorithm](<02.12.02.07.03.02.02_Control_file_for_the_Successive_algorithm.md>):

- If the output level is 0, no RA counting algorithm output is included. (This leads to solution files like those shown above.)
- If the output is 1 or greater, the counting summary (fail bit counts per segment and for the entire DUT as well as rows and columns that must be repaired) and the result of the counting check are included.
- If the output level is 2 or greater, the list of non-repairable cells is shown for non-repairable devices.

Depending on the repairability and the result of the RA counting check, the repair solution is output differently:

- If the device can be repaired by MUST repair and passes the counting check:

  - If the RA algorithm is enabled, the repair solution is commented out because it is not final.
  - If the RA algorithm is not enabled, the repair solution is output normally.

- If the device cannot be repaired, the current repair steps are listed as comments.

Example solution file:

```
# Die X = 0, Y = 0
# ------ Begin of Fail Bit Count -----
# FBC_Of_Dut = 96
# FBC_of_Segment[1]=48
# FBC_of_Row_of_Segment[1][140]=12
# FBC_of_Row_of_Segment[1][141]=12
# FBC_of_Row_of_Segment[1][142]=12
# FBC_of_Row_of_Segment[1][143]=12
# FBC_of_Col_of_Segment[1][0]=4
# FBC_of_Col_of_Segment[1][1]=4
# FBC_of_Col_of_Segment[1][16]=4
# FBC_of_Col_of_Segment[1][17]=4
# FBC_of_Col_of_Segment[1][32]=4
# FBC_of_Col_of_Segment[1][33]=4
..........................................
# FBC_of_Col_of_Segment[5][62]=4
# FBC_of_Col_of_Segment[5][63]=4
# FBC_of_Col_of_Segment[5][78]=4
# FBC_of_Col_of_Segment[5][79]=4
# FBC_of_Col_of_Segment[5][94]=4
# FBC_of_Col_of_Segment[5][95]=4
# ------ End of Fail Bit Count -----
# ----- Begin of Ra counting check -----
# ++TEST: Ra counting check passed!
# ----- End of Ra counting check -----
# ----- Begin of Results of Must Repair -----
# Must Repair: row (0, 1, 140) is repaired by spare row 8
# Must Repair: row (0, 1, 141) is repaired by spare row 9
# Must Repair: row (0, 1, 142) is repaired by spare row 10
# Must Repair: row (0, 1, 143) is repaired by spare row 11
# ----- End of Results of Must Repair -----

#  SR=9: R=141:

```
