# Non-transparent x-modes

#### Subtopics

- [Introducing x-modes](<02.12.03.05.03.01_Introducing_x-modes.md>)
- [X2 mode example (for SRAM)](<02.12.03.05.03.02_X2_mode_example__for_SRAM.md>)
- [X4 and x8 mode example (for GDDR)](<02.12.03.05.03.03_X4_and_x8_mode_example__for_GDDR.md>)

Earlier releases of MTL supported x-modes in a different way than the current release, requiring users to create specific device accesses for each x-mode they wanted to use. This made x-mode programs both harder to use and maintain as well as more difficult to read.

While the MTL compiler still supports these non-transparent x-modes, we strongly suggest that you do not create new programs that use them. Use the much more convenient [transparent x-mode](<02.12.03.04.02_Transparent_x-modes.md>) instead.

Note that non-transparent x-modes are not compatible with [Counted match loops](<02.12.01.09.07.01_Counted_match_loops.md>).

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 2.6.6: Non-transparent x-modes are incompatible with match loops
