# Setting up dynamic bus inversion

Dynamic bus inversion (DBI) is used to invert the bus signals under specified conditions.

## About this task

Set up DBI if you require bus signals to be sometimes inverted, but not always.

## Before you begin

Make sure that the [pin configuration](<02.12.03.03.09.01_Pin_configuration_file.md>) and [pin mapping files](<02.12.03.03.06_Pin_mapping_file.md>) are properly set up.

## Procedure

-  Define the DBI settings in the [Device architecture file](<02.12.03.03.05_Device_architecture_file.md>).

  -  Add a :dbi: block and name it.
  -  Add a :configuration: block for each combination of a set of pins to apply inversion to and a condition governing when the inversion is applied.

The details of both blocks are described in [Device architecture file syntax](<02.12.03.03.05.01_Device_architecture_file_syntax.md>).

Repeat steps a and b for each additional group of DBI settings that you want to create.

-  Specify the desired DBI setting in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>) by adding the :dbi: keyword and the name of the desired DBI setting (from step 1a) to the file.
-  Apply the dbi macro in the :operation: column of every device access where you want to use it. More information on this is available in [Macros and functions in device accesses](<02.12.03.03.04.02_Macros_and_functions_in_device_accesses.md>).

Note that any device access containing the dbi macro cannot be used in padding routines.

Also note that any device access containing the dbi macro must always access all pins that belong to the bus defined in the DBI configuration used. The device access may not leave out some of the bits that have been specified as belonging to the DBI bus used in the access.

-  When compiling the pattern, specify binary reconstruction information:

  - When you use the GUI, check the Generate Reconstruction File option and set the slider to r1 or r2.
  - When you use the command line, specify the `-r1` or `-r2` command line option.

Dynamic bus inversion does not work with the `-r0` option.

## Results

Whenever the defined condition is reached, the signals on the specified bus are inverted before they reach the DUT.

## Example

In the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>):

```
...
:dbi:  GDDR5_dbi
...
```

In the [Device architecture file](<02.12.03.03.05_Device_architecture_file.md>):

```
...
:dbi:
{
  :name: GDDR5_dbi
  :configuration:
  {
    :name: writeDBI
    :condition: bitCount(e[],0)>bitControl
    :table:
    {
      :format:
      { :bus:       :flag: }
      { DQi[0..7]   dbi[0] }
      { DQi[8..15]  dbi[1] }
      { DQi[16..23] dbi[2] }
      { DQi[24..31] dbi[3] }
    }
  }
  :configuration:
  {
    :name: readDBI
    :condition: "bitCount(e[],0)> bitControl"
    :table:
    {
      :format:
      { :bus:       :flag: }
      { DQI[0..31]  dbi[0] }
    }
  }
}

...
```

In the [Device access file](<02.12.03.03.04_Device_access_file.md>):

```
...
:apgAccess:
{
  :name:  Write
  :table:
  {
    :format:
    {:pin:  :states:  :data:          :operation:    }
    { DQi   {0 1}     data(dw, x, y)  dbi(writeDBI)  }
    { dbi   {0 1}     0               dbi(writeDBI)  }
  }
}
...
```
