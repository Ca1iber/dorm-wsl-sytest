# Setting up indirect waveform mapping

Much like direct waveform mapping, indirect waveform mapping converts the waveforms created by the compiler to indexes into the timing file that are added to the vector file. Instead of using the timing file, however, it uses a separate waveform mapping file.

## About this task

Use indirect waveform mapping only if:

- If you are using the :devCyc: keyword in the [Device access file](<02.12.03.03.04_Device_access_file.md>) (which we recommend that you avoid doing).
- If you need to map multiple logical waveforms to one physical waveform, for example, to use a third level.

In all other cases we recommend that you use [Direct waveform mapping](<02.12.03.04.03.01_Setting_up_direct_waveform_mapping.md>). If you use [Transparent x-modes](<02.12.03.04.02_Transparent_x-modes.md>), you cannot use indirect waveform mapping.

## Before you begin

Make sure your timing file is properly set up.

## Procedure

-  Create a waveform mapping file.

You can create the file from scratch, but the easiest way is often to use a copy of the timing file as a start.

-  For each pin group, create a table with waveform index and state sequence columns (and optionally with a waveform description column as well) as described in [Waveform mapping file syntax](<02.12.03.03.07.01_Waveform_mapping_file_syntax.md>).
-  Save the file.
-  Enter the name of the waveform mapping file in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>), in the form :waveformMap:<waveformMappingFile>.

## Results

When the pattern is compiled, any logical waveforms created by the compiler are looked up in the appropriate PINS table of the waveform mapping file and replaced by the corresponding index (which is used at runtime to look up the corresponding vector from the wavetable), which is written to the vector file. At run time, this index is used to look up the correct waveform in the wavetable and send it to the device.
