# Macros and functions in program files

MTL includes some predefined macros and functions for use in the APG program file.

## Syntax

These functions and macros are available, listed in alphabetical order.

 |

Keyword

 |

Parameters and descriptions

 |
 |

DC_EVENT(<event>)

 .delay(<edges>)

 |

<event>: The name of the event that is to be executed. The event must be defined in the [DC event file](<02.12.03.03.08_DC_event_file.md>).

<edges>: The delay of the event, measured in waveform edges. The delay() function property is optional.

The delay is the time difference between the scheduled time of the event in the pattern and its actual execution. If the delay is negative, the event is executed before its scheduled time. The value is an expression; the expression may contain normal variables but not loop-dependent variables (that is, variables that change during a loop iteration).

The delay() property cannot be used with pmu type DC events.

The DC_EVENT function executes the specified DC event. It can be used in the [APG program file](<02.12.03.03.03_APG_program_file.md>).

 |
 |

DC_EVENT_RANGE(

 <sequence>,

 <parameters>)

 .maxRepeats(<num>)

 .initialDelay(<d>)

 {

 <instructions>

 }

 |

<sequence>: The name of the sequence that is to be executed. The event must be defined in the [DC event file](<02.12.03.03.08_DC_event_file.md>) using the :dcSequence: keyword.

<parameters>: The parameters that are passed to the sequence. Parameters are separated by commas.

<num>: The maximum number of times that the specified sequence is to be executed. The maxRepeats() function property is optional.

<d>: The amount by which the start of the sequence is delayed (relative to the beginning of the execution of the instructions in the macro body), measured in waveform edges. The initialDelay() function property is optional.

<instructions>: Standard MTL program statements. While these statements are being executed, the specified sequence is executed on the DC Scale card (subject to the limit set in maxRepeats(), if that property is used.

The DC_EVENT_RANGE function executes the specified sequence of DC events alongside the instructions in its body. It can be used in the [APG program file](<02.12.03.03.03_APG_program_file.md>).

 |
 |

pad(<paddingRoutine>) {}

 |

<paddingRoutine>: The name of the padding routine that is to be used. The routine must be specified as a subroutine in the [APG program file](<02.12.03.03.03_APG_program_file.md>) without any arguments.

The `pad() {}` macro applies padding in the location where it occurs, if such padding is needed. It can be used in the [APG program file](<02.12.03.03.03_APG_program_file.md>).

 |
 |

REFRESH_CTRL(<command>)

 |

Manually Enables or disables maintenance operations (refreshes) in the [program file](<02.12.03.03.03_APG_program_file.md>).

<command>: Either START, STOP or SWITCH.

See details in [Enabling and disabling maintenance operations](<02.12.03.04.12.02_Enabling_and_disabling_maintenance_operations_in_APG_program_file.md>).

 |

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 2.4.0: DC_EVENT_RANGE macro added
- MTP 2.6.6: Counted match loops cannot be used inside pad()
- MTP 3.0.1: delay() is not compatible with PMU type DC events
- MTP 3.0.1: REFRESH_CTRL function added
- MTP 3.1.6: (MTP on SOC 103.3.0) New commands in REFRESH_CTRL() are added for multiple refreshes maintenance operations.
