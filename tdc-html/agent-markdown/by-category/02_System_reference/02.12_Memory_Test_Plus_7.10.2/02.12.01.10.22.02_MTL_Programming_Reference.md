# MTL Programming Reference

- The specification for pins is refined by introducing a new command for subgroups.

This new command allows you to group pins with a finer granularity than before. This facilitates the programming for testing memory device with growing pin counts and increasing complexity and lowers the risk for programming errors.

- The user interface for the compiler is improved by a GUI, an additional icon in the Memory Test Manager GUI and the Compiler Control window. You can run the compiler now using the Memory Test Manager's GUI. In a Compiler Control window the compiler flags can be specified with point and click actions to ease the task of downloading vectors. An automatic vector download function is added.

The GUI allows you to easily set the compiler flags by checking boxes and to navigate to the APG files with standard dialog windows.

- Automatic Waveform Generation is introduced as an optional feature supporting the creation of new waveforms and wavetables or re-using existing ones.

If the user is using indirect waveform mapping and the specified file does not exist it will be created. For using direct waveform mapping, the timing file specified in the .apg file must exist and the compiler will create a new wavetable with the specified name and mode context. If the file does not exist the compiler will print an error message and exit.

- Memory Test Language allows to define per-pin programs that are different in length. MTL would report if there is an inconsistency over pins. If there is an inconsistency detected by the compiler a warning message is issued to indicate that a Inconsistent Cycle Count was detected.

A summary for all pins and their respective length is displayed. If there is an inconsistency reported which is not intended by the user he should check pattern and device accesses of his MTL pattern program.

- If device maintenance is activated and a refresh subroutine is defined in the MTL program the compiler reports the Number of Refresh Vectors that will be executed.

The user gets information on how many vectors will be executed during a device maintenance operation.

- Wildcard Patterns as an APG-Pattern-File argument are allowed to speed up the pattern executable generation.

This allows to generate multiple executables at once instead of running the compiler once for each pattern file.

- New options for the Generation of the Reconstruction File are introduced.

Depending on the complexity of the pattern file a compromise can be found to have short compile time with slower reconstruction speed or vice versa.

- Minimize Sequencer Memory Consumption: more flexibility is achieved splitting memory test patterns and device maintenance operations in separate per-pin subroutines.

Device maintenance operations become a resource which can be reused by many different memory test patterns and need to be defined and loaded only once.
