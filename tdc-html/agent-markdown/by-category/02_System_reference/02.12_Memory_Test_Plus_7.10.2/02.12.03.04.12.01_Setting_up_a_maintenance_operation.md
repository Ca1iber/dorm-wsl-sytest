# Setting up a maintenance operation

Setting up a device maintenance operation, such as a refresh, requires modifications to several of the configuration files in addition to writing the program from which the operation is compiled.

## About this task

You set up a maintenance operation when your device requires periodic support operations - most commonly refreshes - that have to occur too frequently to specify manually in the code.

## Before you begin

Set up timing and waveforms in SmarTest.

## Procedure

-  Specify the maintenance operation in the [Device architecture file](<02.12.03.03.05_Device_architecture_file.md>):

Add the :maintenanceOperation: keyword and the corresponding information to the file, as described in [Device architecture file syntax](<02.12.03.03.05.01_Device_architecture_file_syntax.md>).

For example:

```
:maintenanceOperation:
{
  :name: writeRefresh
  :table:
  {
    :format:
    {:operation:     :subroutine: :timerMode: :intervalMode:}
    {maintop_time_a  refreshWrite  static      accumulated   }
  }
}
```

Note that if this table specifies:

  - A single refresh maintenance operation, in this table there is only one row. And in the :operation: column, the keyword must be maintop_time_a.

Both the static and dynamic timer modes support the single refresh maintenance operations.

  - A multiple refreshes maintenance operation, there are multiple rows. One row stands for one refresh's setups.

In the :operation: column, the keyword for each row must be static_maintop_time_x (x can be any given letter), where x is different between rows.

Only the static timer mode supports the multiple refreshes maintenance operations.

You can specify multiple maintenance operations if desired; there must be a :name: block for each.

-  Reference the newly specified maintenance operation in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>):

Enter the name (the one specified with the :name: keyword) of the desired maintenance operation after the :maintenanceOperation: keyword.

For example:

```
:maintenanceOperation:  writeRefresh
```

-  If you have specified a static maintenance operation in step 1, add the required :timing: information in the [APG pattern file](<02.12.03.03.02_APG_pattern_file.md>) as described in [APG pattern file syntax](<02.12.03.03.02.01_APG_pattern_file_syntax.md>).

The static refresh maintenance operation supports both single-port and multiport operation. For multiport operation, you need specify the different timing sets for different ports in the :tims: parameter in :timing:. See the below examples:

Example 1, for single-port:

```
:timing:
  {
    :file:  "write.tim"
    :eqns:  "write_eqn_set"
    :tims:  "write_timing_set"
    :spec:  "write_spec_set"
  }
```

Example 2, for multiport:

```
:timing:
  {
    :file:  "write.tim"
    :eqns:  "write_eqn_set"
    :tims:  "timingset1@port1, timingset2@port2"
    :spec:  "write_spec_set"
  }
```

-  If you have specified a dynamic maintenance operation in step 1 and you want to run the refresh in sequencer mode, specify the SEQ value for the interruptCtrl pin attribute in the [pin mapping file](<02.12.03.03.06.01_Pin_mapping_file_syntax.md>).
-  Add a subroutine for the maintenance operation to the [APG program file](<02.12.03.03.03_APG_program_file.md>):

The subroutine must have the name specified in the device architecture file (in the :subroutine: column). It follows the same conventions as all other subroutines, except that no parameters can be passed to it. See [Subroutines](<02.12.03.03.03.01.07_Subroutines.md>) for details.

For example:

```
refreshWrite()
{
  for(rowAddr=0 ; rowAddr<1024; rowAddr+=1)
  {
    refreshRow( rowAddr );
  }
}
```

-  Specify the maintenance operation in the [Timing file](<02.12.03.03.09.02_Timing_file.md>):

Add the period and maintop_time_a or static_maintop_time_x (x can be any given letter) keywords at the beginning of a timing set (before the PINS definition) and define spec variables for both.

For a multiport operation supported by single or multiple static refreshes maintenance operations, add the above keywords at the beginning of each timing set (before the PINS definition) to be used for each port.

  - If a single refresh operation, use the maintop_time_a keyword as the refresh-period name.
  - If a multiple static refreshes operation, use the static_maintop_time_x (x can be any given letter) keywords as the different refresh-period names, where x must be different for each refresh.

For example, a single-port refresh maintenance operation:

```
SPECS
  cycleTime    [ns]
  refreshTime  [ns]
TIMINGSET 1 "writeRefresh"
  period = cycleTime
  maintop_time_a = refreshTime
  PINS
  ...
```

For example, a multiport refresh maintenance operation:

```
SPECS
  cycleTime    [ns]
  refreshTime  [ns]
TIMINGSET 20 "timingset1"
  period = cycleTime
  maintop_time_a = refreshTime
  PINS
  ...
TIMINGSET 30 "timingset2"
  period = cycleTime*2
  maintop_time_a = refreshTime*2
  PINS
  ...
```

Make sure to always specify a period; a failure to do so can lead to unexpected errors.

Maintenance operations can be specified only in equation-based timing sets.

-  In the [APG program file](<02.12.03.03.03_APG_program_file.md>), mark non-interruptible locations using either the [nis{}](<02.12.03.03.03.01.04_Other_control_structures.md>)[ or ](<02.12.03.03.03.01.04_Other_control_structures.md>)[is{}](<02.12.03.03.03.01.04_Other_control_structures.md>) instructions if needed.

If you do not use the nis{} or is{} instructions, the default is that the program can be interrupted at any location once the refreshes are set up as described in this procedure.

Note that nis{} instructions are not compatible with the sequencer refresh mode (see step 4).

-  If you have specified a multiple refreshes maintenance operation in step 1, you must insert the [refresh control instructions](<02.12.03.04.12.02_Enabling_and_disabling_maintenance_operations_in_APG_program_file.md>) in your [APG program file](<02.12.03.03.03_APG_program_file.md>) to enable and disable the refreshes.

Note that for multiple refreshes maintenance operations, all refreshes are disabled initially after setting up as described in this procedure.

-  If you have specified a single refresh maintenance operation in step 1, you can manually enable or disable the refresh in the pattern by inserting the [refresh control instructions](<02.12.03.04.12.02_Enabling_and_disabling_maintenance_operations_in_APG_program_file.md>) in your [APG program file](<02.12.03.03.03_APG_program_file.md>).

Note that for single refresh maintenance operations, refreshes are enabled initially after setting up as described in this procedure.

-  Save all modified files.

## Results

The maintenance operation is now set up, ready to be compiled and be used in compiled test patterns.

The compiler stores the specified type of interval mode (accumulated or compensated) in the vector (.vec) file to allow SmarTest to verify that the mode is compatible with the hardware when loading it.

## What to do next

Compile the pattern, execute it, and view the results (if desired).
