# Transparent x-modes

#### Subtopics

- [Using transparent x-modes](<02.12.03.04.02.01_Using_transparent_x-modes.md>)
- [Setting up padding](<02.12.03.04.02.02_Setting_up_padding.md>)

An x-mode is a way to send multiple edges to the DUT in one test system cycle. For example, x4 mode means that the test system can send four edges to the DUT in each cycle.

Transparent x-modes are a way to specify and use these x-modes in a away that minimizes the impact on other parts of the pattern setup and allows you to easily switch x-modes.

The V93000 HSM Series fully supports the x1, x2, x3, x4, x6 and x8 modes.

 Note Earlier releases of MTL implemented x-modes in a different, non-transparent way. While that x-mode implementation is still supported, we strongly recommend against using it in new programs. The old x-mode implementation is described in the [Non-transparent x-modes](<02.12.03.05.03_Non-transparent_x-modes.md>) appendix.

## X-modes and maintenance operations

Because x-modes create multiple vectors per test system cycle, maintenance operations may not always be scheduled to occur on test system cycles. There are two approaches to this issue:

- Static maintenance operations can occur at any point in the pattern, even if they do not fall on a test system cycle boundary. This is discussed in [Maintenance operations](<02.12.03.04.12_Maintenance_operations.md>).
- Dynamic maintenance operations can only occur on cycle boundaries. Patterns using dynamic maintenance operations require padding to fill the gap between the point when the maintenance operation is scheduled to occur and the next test system cycle boundary. This is discussed in [Setting up padding](<02.12.03.04.02.02_Setting_up_padding.md>).
