# Creating a testflow in SmarTest

SmarTest provides the facilities to collect a set of test methods into a testflow which you can run in one go or in portions.

Before creating a new testflow using the testflow editor you have to load a setup you created for your device as described in [Defining a memory test](<02.12.02.03.05.05_Defining_a_memory_test_setup.md>).

After you created a complete testflow you have a [Test Program](<../02.08_Setup_and_Result_Tools/02.08.04.31_Test_Program.md>) you can save or execute.

When you cerate a testflow, the following information may be helpful:

- [Multiple Sites Execution](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.04_Multiple_Sites_Execution.md>) for production test environment
- [Hierarchy within a testflow](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.03_Hierarchy_within_a_testflow.md>)
- [Bins](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.06_Bins.md>)
- [Test suites](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.01_Test_suites.md>)
- [Special test suites](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.01.02_Special_test_suites.md>)
- [Support for Burst Mode](<../02.08_Setup_and_Result_Tools/02.08.04.32.02.01.14_Identifying_fail_labels_in_a_burst.md>) for production test environment
- [Master File Format for Testflow](<../02.08_Setup_and_Result_Tools/02.08.04.32.03.06_Testflow_master_file.md>)

For details on how to work with a testflow see [Tasks](<../02.08_Setup_and_Result_Tools/02.08.04.32.02_Using_the_Testflow_Tool.md>).

Your testflow should differ in the amount of logging whether your run a DV or a HVM test.

Remember to set flags for use case debug.

Set System flag: Log_Events_enable = on

A typical testflow for a memory device should contain:

Eyefinder (XDR) or Source Sync (GDDR) Data Training + ExecutionEngine

in this sequence.

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 3.0.1: The ExecutionEngine test method replaces the Memtest test methods
