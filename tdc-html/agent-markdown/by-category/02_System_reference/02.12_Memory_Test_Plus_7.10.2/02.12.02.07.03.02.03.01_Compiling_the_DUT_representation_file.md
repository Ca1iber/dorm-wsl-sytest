# Compiling the DUT representation file

When you have created or edited a [DUT representation file](<02.12.02.07.03.02.03_DUT_representation_file.md>), you must compile it into a shared library to be able to use it for redundancy analysis.

## Before you begin

Note Shared libraries that have been compiled with version 2.x of MTP cannot be used with version 3.x (MTP for SOC 103.x) or later and need to be recompiled.

Create or edit the DUT representation file and save it.

## Procedure

 Compile the file by entering this command:

```
/opt/93000mts/mts/rr/bin/DutRepGenerator [-d](<drs_file>| -c <cpp_file>)
```

Where:

- -d is an optional parameter that preserves the intermediate .cpp file that the generator creates in the transformation process.
- <drs_file> is the name and path of the .drs file to be converted. You cannot specify a .drs file if you use the -c option (see below).
- -c is an optional parameter that lets you use a .cpp file instead of a .drs file as the input. You cannot use the -c option if you specify a .drs file.
- <cpp_file> is the .cpp input file you specify with the -c option.

## Results

The compiler compiles the DUT representation file, checking its consistency while doing so. any inconsistencies are reported.

A shared library is created that you can use in the redundancy analysis. Specify it in the DUT_rep parameter of the [Redundancy analysis configuration file](<02.12.02.07.03.01.03.01_Redundancy_analysis_configuration_file.md>).

Also a log file which includes the contents of the DUT representation file is generated in the same directory as the original .drs or .cpp file.

## Example

```
/opt/93000mts/mts/rr/bin//DutRepGenerator sampleRepresentation.drs
```

This command converts the file sampleRepresentation.drs from the current working directory into a shared library in the same directory. The intermediate .cpp file is discarded.
