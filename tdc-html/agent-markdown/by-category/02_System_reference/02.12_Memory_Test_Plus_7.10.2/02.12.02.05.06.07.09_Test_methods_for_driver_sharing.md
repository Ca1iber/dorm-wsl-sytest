To test under driver sharing, MTP offers both the [ready-made test methods](<02.12.02.05.06.07.09.02_Overview_of_the_ready-made_test_methods.md>) and [APIs](<02.12.02.05.06.07.09.03_Driver_Sharing_APIs.md>). When you Do not want to use the ready-made test methods, you can use the APIs to create your own custom test methods.

The MTP software package includes an RPM package (solution_tools) that contains the shared library libMTP_SolutionTools.so with the ready-made [test methods](<02.12.02.05.06.07.09.02_Overview_of_the_ready-made_test_methods.md>) that you can use in your test flow to test devices in a driver shared environment. The library also provides access to the DriverSharing classes, which contains the driver sharing APIs.

Advantest also provides fd_merge, a tool that helps you to handle fixture delay files. This is also contained in the solution_tools directory.

## Functional changes

- Introduced before SmarTest 6.3.2
- MTP 3.0.1: Registering test methods is no longer necessary
- MTP 3.1.3: Four APIs are introduced to create custom test methods for driver sharing in continuity test, IDD test, VBump test, and parallel leakage test.
