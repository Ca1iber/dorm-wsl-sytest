# Transparent X-Mode

There is no need to have the same number of edges/events per pin as the defined X-Mode.

Using transparent X-Mode leads to productivity improvements.

A special treatment with regard to refresh is needed which can only take place at the end of a tester cycle after a NIS function has terminated.

If transparent X-Mode access definitions are used the memory pattern could require "padding" at the end of a pattern if it does not match a complete tester cycle.

For more information refer to Transparent X-Mode, Transparent X-Mode and Refresh and [Padding Control](<02.12.03.04.02.02_Setting_up_padding.md>) in [Memory Test Language (MTL) Programming Reference](<02.12.03_Memory_Test_Language__MTL__Programming_Reference.md>).
