# Binning concept for driver sharing

During a test, the tested devices normally need to be sorted according to their test results. This is done by assigning the devices to different bins. For example, all devices that fail in a certain test suite will end up in one bin and not be tested any further.

Binning in a shared multi-site environment is different from binning in a non-shared environment. If a site fails and gets binned during test flow execution, it will undergo a disconnect sequence and no longer receive data or deliver results. The disconnect sequence performs the following operations:

- Sets sequencer to off state.
- Powers down the DPS.
- Disconnects all relays.

Due to the default disconnect sequence above, in a shared multi-site environment device to device interaction can happen, where the failing device influences the electronic characteristics of the neighboring good device.

When a failing device is powered down, the electronic characteristic of its input pins will change. Therefore, the testing condition is not the same as it is intended to be when defining the level setup:

- Input diodes will actively clamp the voltage in the domain.
- Reflections may occur that influence the signal integrity in the domain.

These effects can change the voltage levels for the non-failing devices such that they also fail.

Binning also influences the device power due to sharing the DPS that supplies the device power. If one device gets binned, the respective DPS gets disconnected. This causes a fail of the other eventually good devices in the next test suite that follow in the test flow.

Therefore, driver pin sharing requires to keep all devices powered on during the entire test flow execution. Only after the test flow has been executed, a standard disconnect sequence can follow. Master Binning happens at the end of the test flow.
