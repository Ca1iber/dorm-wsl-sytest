# Specifying DC event details

When you set up a DC event, you must define what is to happen when a particular named event (as specified in a :dcSet: in the DC event file) is called in the pattern.

## About this task

Depending on the type of DC event (DCScale or PMU), there are different options for specifying the event actions:

- For DCScale type events: Specify the namespace and ID of a [DFTD](<../02.06_Command_Reference/02.06.02.02.68_DFTD__DFTD___DeFine_Test_Data.md>) command.
- For PMU type events: Use the LBL command to specify the label of a subroutine.
- For PMU type events: Use the MEAS command to specify the ID of a measurement set.

These options are described in more detail below.

## Procedures

### Providing a DFTD data set

This procedure applies only to DCScale type DC events.

- Define the DC event in the [DC event file](<02.12.03.03.08.01_DC_event_file_syntax.md>) in a :dcSet: object.
- In the :dcSetup: column, specify the event as the namespace and ID of a DFTD test data object. For example:

```
{ :dcEvent:     :pinList:   :dcSetup:   :type:   }
{ sampleEvent1   Pin1        mySetup,1   dcscale }
```

- In the level file or the test method, create a call to [DFTD](<../02.06_Command_Reference/02.06.02.02.68_DFTD__DFTD___DeFine_Test_Data.md>) in which you specify the name of the DC setup as the test data name, that is, the first parameter. For example:

```
DFTD "mySetup",INSERT,(Pin1),#3237<?xml version="1.0"?>
<testdata> <td id=1> ... </td> </testdata>
```

Make sure that the name you give to the DFTD command is the same as the one specified in the DC event file (in this example, `mySetup`).

Also make sure that the index you use in the DC set's :dcSetup: column (1 in the example) references the correct <td> element in the test data set; it must match the element's id value.

- Save and close both files.

### Using LBL with a named procedure

This procedure applies only to PMU type DC events.

- Define the DC event in the [DC event file](<02.12.03.03.08.01_DC_event_file_syntax.md>) in a :dcSet: object.
- In the :dcSetup: column, specify the LBL function with the name of a subroutine as the parameter. For example:

```
{ :dcEvent:     :pinList:   :dcSetup:   :type:   }
{ sampleEvent2   Pin1       "LBL mySR"   pmu     }
```

- In SmarTest's Pattern Explorer, create a subroutine with the name you specified in the DC setup (in the above example, mySR). Make it an empty subroutine containing just a return statement.
- In the test method, create the necessary measurement sets using these APIs:

  - [PPMU_SETTING](<../02.07_Test_Method_Reference/02.07.04.01.160_PPMU_SETTING.md>)
  - [PPMU_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.158_PPMU_RELAY.md>)
  - [PPMU_CLAMP](<../02.07_Test_Method_Reference/02.07.04.01.154_PPMU_CLAMP.md>)
  - [PPMU_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.157_PPMU_MEASURE.md>)

- Call the set using the [PATTERN_CONTROLLER](<../02.07_Test_Method_Reference/02.07.04.01.142_PATTERN_CONTROLLER.md>) API; specify the name of the subroutine ("mySR" in the example above) as the first parameter of the label() member function and add the measurement sets specified in step 4.
- Save and close all files.

### Using the MEAS command

This procedure applies only to PMU type DC events.

Note We do not recommend that you use this method. You should use LBL instead (see above).

- Define the DC event in the [DC event file](<02.12.03.03.08.01_DC_event_file_syntax.md>) in a :dcSet: object.
- In the :dcSetup: column, specify the event by using the [MEAS](<../02.06_Command_Reference/02.06.02.02.160_MEAS_-__execute_a_MEASurement_set.md>) function with the ids of a DC set and a data object within that set as the parameters. For example:

```
{ :dcEvent:     :pinList:   :dcSetup:   :type:   }
{ sampleEvent3   Pin1       "MEAS 2,3"   pmu     }
```

- Set up the test method you are using so that it creates the referenced measurement set using the [MSET](<../02.06_Command_Reference/02.06.02.02.164_MSET__MSET__-__definition_of_Measurement_SET.md>) command.
- Save and close all files.

## Results

The DC event is ready to be executed when the test program is compiled and is being executed.

## What to do next

Compile the test program.
