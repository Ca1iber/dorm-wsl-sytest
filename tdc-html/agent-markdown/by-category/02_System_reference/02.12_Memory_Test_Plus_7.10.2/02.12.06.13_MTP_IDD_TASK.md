# MTP_IDD_TASK

#### Subtopics

- [MTP_IDD_PIN_TASK](<02.12.06.13.01_MTP_IDD_PIN_TASK.md>)

- [MTP_IDD_TASK.execute()](<02.12.06.13.05_MTP_IDD_TASK.execute.md>)
- [MTP_IDD_TASK.getPassFail()](<02.12.06.13.06_MTP_IDD_TASK.getPassFail.md>)
- [MTP_IDD_TASK.getValue()](<02.12.06.13.07_MTP_IDD_TASK.getValue.md>)

The MTP_IDD_TASK class provides an API for performing the IDD test for DUTs with driver sharing. It offers similar functionality with the [SharedIDD test method](<02.12.02.05.06.07.09.14_SharedIDD_syntax.md>) and the [SHARED_IDD_TEST](<02.12.06.22_SHARED_IDD_TEST.md>) API but can test different VDD or VDDQ pins which have different measurement conditions within one test method. All tested pins are measured in parallel.

The three methods each have advantages and disadvantages:

- SharedIDD test method: A ready-made test method included with MTP.

  - Advantage: Quickest and easiest way to develop a test program with support for logging results. See [SharedIDD syntax](<02.12.02.05.06.07.09.14_SharedIDD_syntax.md>).
  - Disadvantage: May not meet any special requirements such as testing more than one group of VDD or VDDQ pins, or a special output format.

- SHARED_IDD_TEST API:

  - Advantage: You can develop your own custom test method, from setting measurement conditions, executing measuring, and logging results.

Creating a test program is easy because no other APIs are needed to complete an IDD test.

  - Disadvantage: The test method based on this API cannot test more than one group of VDD or VDDQ pins.

- MTP_IDD_TASK API:

  - Advantage: This is the most flexible method. You can test any number of pins with any types of measurement conditions within one test method.
  - Disadvantage: Results logging is not supported but you can retrieve the results and manually log them.

Creating a test program is complex because other APIs are needed to complete an IDD test, such as [CONNECT](<../02.07_Test_Method_Reference/02.07.04.01.18_CONNECT.md>), [FOR_EACH_TEST_BEGIN](<02.12.06.04_FOR_EACH_TEST_BEGIN.md>), [FOR_EACH_TEST_BEGIN_WITH_RESET](<02.12.06.05_FOR_EACH_TEST_BEGIN_WITH_RESET.md>), [FOR_EACH_TEST_END](<02.12.06.06_FOR_EACH_TEST_END.md>), [FOR_EACH_SHARED_SITE_BEGIN](<02.12.06.02_FOR_EACH_SHARED_SITE_BEGIN.md>), [FOR_EACH_SHARED_SITE_END](<02.12.06.03_FOR_EACH_SHARED_SITE_END.md>), and [SHARING_CONFIGURATION](<02.12.06.25_SHARING_CONFIGURATION.md>).

Note The MTP_IDD_TASK API is available only for MTP.

This API is defined in the header file /opt/93000mts/mts/solution_tools/common/include/MTP_IDD_TASK.h.

## Example

This example tests the IDD for the VDD and VDDQ pins with different limits.

Assume the sharing configuration file (default.cfg) is as below:

```
domains: 8
4 3 2 1 ; 5 6 7 8
12 11 10 9 ; 13 14 15 16
utility_control:
idd;(y<1);(U3=0x222&0xfff);(DEVICE_SUPPLY=VDD)
idd;(y>=1);(U3=0x111&0xfff);(DEVICE_SUPPLY=VDD)
iddq;(y<1);(U3=0x777&0xfff);(DEVICE_SUPPLY=VDD)
iddq;(y>=1);(U3=0xbbb&0xfff);(DEVICE_SUPPLY=VDD)
oc_reset;(U2=0x000&0x400,U2=0x400&0x400,U3=0x000&0xfff,U2=0x000&0x401)
default;(U3=0x000&0xfff,U2=0x000&0x401)

```

The program is:

```
#include "solution_tools.h"
#include "testmethod.hpp"
#include "mapi.hpp"
class CSharedIDD: public testmethod::TestMethod
{
  virtual void run()
  {
    ON_FIRST_INVOCATION_BEGIN();
    {
      // get limits
      LIMIT limitVDD, limitVDDQ;

      // setup for IDD
      mTest.pin("VDD").limits(limitVDD);
      // setup for IDDQ
      mTest.pin("VDDQ").limits(limitVDDQ);
      mTest.waitTime(10);

      // connect
      CONNECT();

      FOR_EACH_TEST_BEGIN_WITH_RESET("default.cfg", "idd, iddq", "nRESET");
      {
        // It will test in 2 steps with sites (4, 3, 2, 1, 12, 11, 10, 9) and
        // (5, 6, 7, 8, 13, 14, 15, 16).
        // Without utility control setting, it will test all sites in one step.

        // set the utility line for the VDD measurement
        int index = GET_CURRENT_UTILITY_CONTROL("idd");
        SHARING_CONFIGURATION::getInstance().utilityActionExecute(index);
        // measurement of IDD of VDD
        mTest.execute();

        index = GET_CURRENT_UTILITY_CONTROL("iddq");
        SHARING_CONFIGURATION::getInstance().utilityActionExecute(index);
        // measurement of IDD of VDDQ
        mTest.execute();
      }
      FOR_EACH_TEST_END();
    }
    ON_FIRST_INVOCATION_END();
  }
private:
  SHARED_IDD_TEST mTest;
};
```
