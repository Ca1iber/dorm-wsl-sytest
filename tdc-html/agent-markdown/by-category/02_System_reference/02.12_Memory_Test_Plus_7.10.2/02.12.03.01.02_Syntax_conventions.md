# Syntax conventions

This section describes the notation used to describe configuration file syntax.

The MTL syntax itself is described in [MTL compiler syntax](<02.12.03.02.02_MTL_compiler_syntax.md>).

## Syntax

All elements that do not belong to the program code but describe it are set in italics. These elements can indicate:

- Optional elements
- Alternatives
- Placeholders
- Repetitions
- Omissions

See below for details.

## Optional elements

Elements in the program code that may or may not be included are enclosed in square brackets [ ].

For example: [ `:nullData:`<data_Value> ]

This indicates that the entire statement may be included in the code, but may also be left out.

## Alternatives

Sometimes, one element out of a limited selection can be used in a particular place. This is indicated by a vertical divider |.

## Placeholders

Placeholders indicate that an element described later in the text must appear at a location. Placeholders are enclosed in angle brackets < >.

For example: `:nullData: `<data_value>

This indicates that the null data parameter takes a value that is described under the name "<data_value>" following the syntax description.

## Repetitions

When a given element or set of elements can be repeated as often as desired, this is indicated by three dots ... . Repetitions indicated in this way are always optional.

For example:

```
{  :pin:       :state:       :data:      }
{  <pin_name><pin_states><pin_data>  }
{  .........         }
```

This example describes a syntax where you can add as many lines as desired with the same structure as the first one.

## Omissions

Three dots may also describe omissions, that is, information that needs to be there in the real file but is not shown in this manual because it is irrelevant in the context.

For example:

```
:apgAccess:
{
...
  :inMap:   sram.pmap
...
}
```

Here, the :apgAcess: keyword requires more information than just the pin map specification, but that other information is not shown here because it is not relevant at this point of the documentation.
