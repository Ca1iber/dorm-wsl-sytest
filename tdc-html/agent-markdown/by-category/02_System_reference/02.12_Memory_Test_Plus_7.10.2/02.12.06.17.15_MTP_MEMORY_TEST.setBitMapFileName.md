# MTP_MEMORY_TEST.setBitMapFileName()

Specifies names for the generated BFD files. The .bfd suffix will be automatically added.

If you do not specify a name with this function, each BFD file will get a default name:

- The name of each BFD file generated with an execution of a test is: ${time}-${label}-${pattern}-${port}-Site${site}.bfd., which does not show the wafer information.
- The name of each BFD file generated with RA when you have [enabled RA](<02.12.06.17.31_MTP_MEMORY_TEST.setRAEnablingMode.md>) and configured [setRAEndAction(MTP::RA_END_SAVE_BFD)](<02.12.06.17.32_MTP_MEMORY_TEST.setRAEndAction.md>) is ${time}._port${port}_${lot}_${cassette}_${wafer}_${die_x}_${die_y}.bfd. This BFD file is binary format even you have configured [setBitmapMode(MTP::ASCII_ENCODING)](<02.12.06.17.17_MTP_MEMORY_TEST.setBitmapMode.md>).

See the followings for the name description.

## Syntax

```
MTP_MEMORY_TEST& MTP_MEMORY_TEST::setBitMapFileName (const string& name) [inherited];
```

Parameter
 |

Parameter

 |

Description

 |
 |

name

 |

A string to name the generated BFD files. The name string can contain application model variables, testflow variables, and the reserved variables listed below to display more information in the file name, such as wafer, site, and port information. The syntax for using a variable in the name string is ${variable name}.

- ${time}: The file name will show the time at which the BFD file is generated.
- ${pattern}: The file name will show the name of the memory pattern (per pin subroutines generated by the MTL compiler) that the BFD file is generated from.
- ${label}: The file name will show the name of the start label where in the pattern to start generating the BFD file.
- ${port}: The file name will show the name of the port that the pattern belongs to.
- ${site}: The file name will show the site number.
- ${test}: The file name will show the name of the test suite.

If the name string contains a variable which is an application model variable and that is also a testflow variable, the file name will display the value of the application model variable.

If the name string does not contain a variable, all the BFD files will have the same name and the later one will overwrite the earlier one.

If the string does not contain the ${time} variable, the BFD file generated with the execution of a test and the BFD file generated with RA if you have [enabled RA](<02.12.06.17.31_MTP_MEMORY_TEST.setRAEnablingMode.md>) and configured [setRAEndAction(MTP::RA_END_SAVE_BFD)](<02.12.06.17.32_MTP_MEMORY_TEST.setRAEndAction.md>) will have the same name. The later one will overwrite the earlier one.

By default, all generated BFD files are saved to: device/mts/bitmap/bitmap_data. You can change the path of the BFD file generated with an execution of a test by using [MTP_MEMORY_TEST.setBitMapFilePath()](<02.12.06.17.16_MTP_MEMORY_TEST.setBitMapFilePath.md>). But you cannot change the path of the BFD file generated with RA.

Examples:

- "${time}-${label}-${pattern}-Port${port}-Site${site}"
- "Time${time}-Port${port}-$Lot{LOT_ID}-Cassette${CASSETTE_ID}-Wafer${WAFER_ID}-X${DIE_X}-Y${DIE_Y}"
 |

Return value

There is no return value.
