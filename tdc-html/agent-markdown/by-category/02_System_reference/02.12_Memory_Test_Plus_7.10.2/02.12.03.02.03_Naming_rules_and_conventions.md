# Naming rules and conventions

When creating names for variables, parameters, or functions in MTL, you must follow certain rules. There are also recommendations for names access from subroutines, although these are not mandatory.

## Naming rules

MTL supports names of arbitrary length for variables, parameters, or functions. There are, however, a few rules that must be observed:

- Names must begin with a letter (a to z, A to Z) or underscore character.
- The other characters in a name can be any combination of letters, underscores, periods, and digits (0 to 9).
- MTL distinguishes upper and lower case, that is, `sample`, `Sample`, and `SAMple` would be considered three different names.
- Certain elements may not have the same names:

  - All device accesses and subroutines must have unique names. That is, not only must no device access have the same name as any other, it neither must have the same name as a subroutine. (And vice versa.)
  - All variables, program parameters, device access parameters, and device access constants must have different names as well. As an exception, multiple elements of these types may have the same names as long as their scopes do not overlap.

## Naming conventions for device accesses and subroutines

In order to clearly distinguish device accesses from subroutines in the code, we recommend using different naming conventions for the two. Note that these conventions are not enforced by the compiler.
