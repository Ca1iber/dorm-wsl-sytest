## Ganging

Ganged XPS256 channels can be setup under user control or under software control:

- User controlled ganging:

Several channels are simply connected in parallel and similar settings are applied. This can lead to an undefined distribution of the current to the individual channels and may result in unstable output voltages and invalid current measurements. Modifying the settings may improve the behavior but needs more attention of the user.

- Software controlled ganging:

The parallel connected channels are defined as ganging group in the pin definitions of SmarTest. The ganging group is accessed as single pin. The on-board-ganging controller distributes the total output current equally between the ganged channels. This solution will show a stable output signal and provides reliable current measurements without applying special setups as required for ganging under user control.

We recommend therefore, always setting up software controlled ganging.

## Ganging characteristics

An XPS256 channel can be ganged together with any other XPS256 channel in any order under the following conditions:

- Ganging is supported for any number of channels within a card.
- Flexible ganging allows channels to be assigned to a ganging group, even if they are not consecutive.
- Flexible ganging across XPS256 cards is supported for up to 4096 channels.
- The number of ganging groups is

  - limited to 128 for ganging within an XPS256 card,[1)](<#fntarg_1>)
  - system-wide limited to 32 for ganging across XPS256 cards.

- For XPS256, ganging is supported in the 1 A range of the PMU exclusively, even if less current is required or available. The maximum current per channel is limited as follows:

  - 1.0 A for voltages up to 3.0 V
  - 0.6 A for voltages up to 7.0 V

For information regarding the maximum current of ganged XPS256 channels, refer to Maximum continuous voltage and current capability per card in [XPS256 voltage and current capability specifications](<../02.02_Specifications/02.02.05.03.04_XPS256_voltage_and_current_capability_specifications.md>).

Since the XPS256 channels are digitally regulated VI supplies and the on-board ganging controller uses internal data paths to balance the output current between the ganged channels, no external control connections are required between ganged XSP256 channels. This applies also for ganging across XPS256 cards.

## Defining ganging groups

- DPS operating mode:

Ganging groups for [XPS256 channels in DPS operating mode](<02.05.05.03.10.07_XPS256_programming_-_DPS_operating_mode.md>) are defined in the DPS Pins editor. You can specify the range of channels to be ganged by "-" (hyphen) or a list of channels with the channels separated by "," (comma). For more information refer to [DC Scale pin (DPS mode) setup](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.01.03.01_DC_Scale_pin__DPS_mode__setup.md>).

- PMU operating mode:

Ganging groups for [XPS256 channels in PMU operating mode](<02.05.05.03.10.15_XPS256_programming_-_PMU_operating_mode.md>) are defined in the Digital Pins editor. You can specify the range of channels to be ganged by "-" (hyphen) or each channel separated by "," (comma). For more information refer to [Digital Pins editor](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.01.02_Digital_Pins_editor.md>).

## Software overview

 No special APIs are required to control ganged XPS256 channels. The complete functionality is covered by

- APIs [SPMU_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234_SPMU_TASK.md>) and [SPMU_PIN_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234.01_SPMU_PIN_TASK.md>) for an [XPS256 pin in PMU operating mode](<02.05.05.03.10.15_XPS256_programming_-_PMU_operating_mode.md>) or by the
- [Equation based level setup](<../02.08_Setup_and_Result_Tools/02.08.04.14.02_Equation_based_level_setup.md>) and API [DPS_TASK](<../02.07_Test_Method_Reference/02.07.04.01.50_DPS_TASK.md>) for an [XPS256 pin in DPS operating mode](<02.05.05.03.10.07_XPS256_programming_-_DPS_operating_mode.md>).

Current measurements with temporarily unganged channels are supported by the following APIs and keywords:

- API [SPMU_PIN_TASK.mode("VFIM_UNGANGED")](<../02.07_Test_Method_Reference/02.07.04.01.234.01.24_SPMU_PIN_TASK.mode.md>)
- API [DPS_PIN_TASK.measurementMode(TM::MEASURE_CURRENT_UNGANGED)](<../02.07_Test_Method_Reference/02.07.04.01.50.01_DPS_PIN_TASK.md>)
- SmartRDI API [rdi.dc().ungang()](<../02.07_Test_Method_Reference/02.07.13.12.02.38_ungang.md>)

Current measurements with temporarily unganged channels are supported in the code‑based mode using the API as defined above. Current measurements with temporarily unganged channels are not supported in the pattern‑based mode.

## Checking the gang connections

SmarTest provides the functionality to check the connection of ganged channels. Since the return line is common for all channels of a card, the check is performed only for the force (P#) lines. It is expected that the connection of the individual sense lines PS# and GS# have already been checked performing a [sense connection test](<02.05.05.03.10.12_XPS256_programming_-_Kelvin_test___sense_connection_test.md>).

For more information, refer to [Checking the gang connections](<02.05.05.03.08_XPS256_ganged.md#_350922__s_Checking_the_gang_connections>) in [XPS256 ganged](<02.05.05.03.08_XPS256_ganged.md>).

 Setting up a gang connection check

APIs and hints and rules to consider when checking the ganging connections:

- The test is performed by the following functions of class [HW_STATE](<../02.07_Test_Method_Reference/02.07.04.01.117_HW_STATE.md>):

  - Function [HW_STATE.checkGangConnectionParallel()](<../02.07_Test_Method_Reference/02.07.04.01.117.05_HW_STATE.checkGangConnectionParallel.md>):The function initiates a gang connection test on all ganged channels of the defined pins to verify that all force lines (P#) of the slave channels are properly connected to the master channel on the DUT board or at the DUT pins. The test is performed in parallel for all active sites. The function returns a go/no-go result for each configured site in a single integer array.

    - The go/no-go result of the function is set to 0 (Gang connection test has failed) if any of the tested channels has returned a failing result for any of the performed measurements.
    - The go/no-go result of the function is set to 1 (Gang connection test passed) if all tested channels have successfully finished all measurements on all active sites.

  - Function [HW_STATE.checkGangConnection()](<../02.07_Test_Method_Reference/02.07.04.01.117.04_HW_STATE.checkGangConnection.md>):

The function initiates a gang connection test for the site in focus. The function returns a go/no-go result for each pin of the given pin list in an integer array.

- The test requires that 0.0 V are applied to the gang connection on the DUT or on the DUT board.

The DUT must therefore be powered down and disconnected for the gang connection test.

- The default value of the programmable threshold for the force connection test is 20 Ω.
- To improve the stability of the results, you can use the optional samples parameter of the APIs. The number of samples used internally for averaging the ADC values will be multiplied by the defined samples value.
- The gang connection test returns a single go/no‑go result for all channels of the ganging group. In online mode, failing channels are reported in the UI report window if the environment variable DEBUG_CHECKGANGCONNECTION is defined.
  Gang connection check in Hardware view

The gang connection test is supported by the [Hardware view](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.05.03_Hardware_view.md>) for the XPS256 pins in [DPS operating mode](<02.05.05.03.10.07_XPS256_programming_-_DPS_operating_mode.md#_354249__s_Hardware_view>) or in [PMU operating mode](<02.05.05.03.10.15_XPS256_programming_-_PMU_operating_mode.md#_354253__s_Hardware_view>).

## Application notes

  Surge tracker is silently disabled in temporarily unganged mode

Note that on DPS128/64 and XPS256 you cannot execute a current compare on a ganged group of channels in unganged mode. Already activated comparators are silently disabled in unganged mode. A user notification (Error or warning) is omitted in this case, to avoid any interrupt in the testflow. The previous state of the comparators is automatically restored after the ganged group has been restored.

  Dynamic behavior of the surge tracker in ganged mode The digital closed loop control leads always to a small delay of minimum one sample from the master channel of a ganging group to the slave channels: The slave channels react to the measured values of the master channel and adjust their outputs to drive the same current.

This may lead to a certain hypersensitivity for fast changes of the signal level.

The thresholds of the surge tracker must therefore be adjusted accordingly to compensate this behavior.

 Resolution of the force or clamp current All channels of a ganged group are programmed to the same values. The resolution of the programmed force or clamp current is the resolution of a single channel multiplied by the number of ganged channels.

## Example

### Check gang connection example

The following code shows a standard example for a gang connection test using the fast parallel test and the detailed test on the site in focus only.

```
SPMU_TASK   spmuTask;
HW_STATE    hwState;
ARRAY_I     goNogoResultArray;
ARRAY_I     perPinResultArray;

STRING      pinList = "XPS256_PMU_GANG,XPS256_DPS_GANG";
int         samples = 10;

ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Disconnect the tested pins
    //
    spmuTask.pin("XPS256_PMU_GANG").disconnect();

    spmuTask.execMode(TM::FORCE_OFF).execute();

    DISCONNECT();

    //
    // Perform the gang connection test in parallel on all active sites
    //
    hwState.checkGangConnectionParallel("XPS256_PMU_GANG,XPS256_DPS_GANG", samples, goNogoResultArray);

    //
    // Evaluate the go/no-go results, re-test failing sites
    //
    FOR_EACH_SITE_BEGIN_WITH_QUERY();
    {
        cout << "Parallel gang connection test, GoNogo result for site " << CURRENT_SITE_NUMBER() << ": ";

        if (goNogoResultArray[CURRENT_SITE_NUMBER() -1] == 1)
        {
            cout << "PASS" << endl;
        }
        else
        {
            cout << "FAIL" << endl;

            //
            // Serial test identifies failing pins
            //
            hwState.checkGangConnection("XPS256_PMU_GANG,XPS256_DPS_GANG", samples, perPinResultArray);

            for (int arrayIndex = 0; arrayIndex < perPinResultArray.size(); arrayIndex++)
            {
                cout << "\tDetailed result for site " << CURRENT_SITE_NUMBER()
                     << ", pin " << arrayIndex + 1 << ": " << perPinResultArray[arrayIndex] << endl;
            }
        }
    }
    FOR_EACH_SITE_END();
}
ON_FIRST_INVOCATION_END();
```
