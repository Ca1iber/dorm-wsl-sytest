## XPS256 licensing

For a complete list of available licenses, refer to [V93000 License Master Look-up Table](<../02.04_Model_File_and_Licensing/02.04.02.01_V93000_License_Master_Look-up_Table.md>) and set the filter of the Main product column to "XPS256".

License needs are almost all derived from the pin configuration of a device but upgrade license needs for the [High‑accuracy voltage mode](<02.05.05.03.10.01_XPS256_specific_setup_tasks.md#_350709__s_High_accuracy_mode_for_voltage>) must manually be enabled manually using the [DC Scale Extensions editor](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.05_DC_Scale_Extensions_editor.md>).

If only the Base Capability license is available, XPS256 supports only 16 pins on the lower 128 channels, each consisting of eight consecutive ganged channels and capable of driving up to 8 amperes.

The Base Capability Extension license offers 16 more pins on the upper 128 channels.

 In the [Pin setting editors](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.01_Pin_setting_editors.md>), these up to 32 pins are to be defined as follows:

- Each pin must be defined as a ganging group.
- Each pin must use eight consecutive channels or a multiple there.
- Multiple groups of eight channels can be assigned to a pin in any order to increase the maximum current to a multiple of 8 A.
The Fine Granular Capability is required for each channel where the group of eight consecutive channels is not fully defined per site. A Fine Granular Capability license covers 32 channels: 1 ... 32, 33 …nbsp;64, …nbsp;, 225 …nbsp;256.

## XPS256 in the device license file

For release to production, we recommend creating a [device license file](<../02.04_Model_File_and_Licensing/02.04.05.06_The_device_license_file.md>) using the [Testflow Analyzer Tool (TAT)](<../02.04_Model_File_and_Licensing/02.04.05.07_The_Testflow_Analyzer_Tool__TAT.md>).

The device license file holds the device specific license information including the XPS256 upgrade license for the [High‑accuracy voltage mode](<02.05.05.03.10.01_XPS256_specific_setup_tasks.md#_350709__s_High_accuracy_mode_for_voltage>) that has manually be enabled manually using the [DC Scale Extensions editor](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.05_DC_Scale_Extensions_editor.md>).

Example for configuring XPS256 upgrade licenses in the device license file:

## XPS256 card configuration in the tester.model file

Although SmarTest 7.10 and higher supports both the [legacy model file](<../02.04_Model_File_and_Licensing/02.04.01.03.02_Model_file_reference__model_legacy.md>) and the [tester.model file](<../02.04_Model_File_and_Licensing/02.04.01.03.01_Model_file_reference__tester.model.md>), the V93000 EXA Scale based XPS256 can be defined only in the tester.model file.

The combination of [DPS128 / DPS64 cards](<02.05.05.01_DC_Scale_DPS128_DPS64_cards.md>) and XPS256 in one tester.model is not supported. SmarTest will issue an error waring in this case and will ignore all XPS256 cards.

The XPS256 card and pogo blocks must be defined in the [CARD_CONFIGURATION](<../02.04_Model_File_and_Licensing/02.04.01.03.01.02_CARD_CONFIGURATION_section.md>) section of the [tester.model](<../02.04_Model_File_and_Licensing/02.04.01.03.01_Model_file_reference__tester.model.md>) file:

- Variants of the card

In the tester.model file, the variants are to be defined as follows:

 | Variant  | Part number  | tester.model file |
 | XPS256  | (EK751HC):  | ... HW = XPS256, ... |

Basic data of the XPS256 variants are available in section [Variants](<02.05.05.03.03_XPS256_functionality_and_features.md#_350909__s_Variants>) of [XPS256 functionality and features](<02.05.05.03.03_XPS256_functionality_and_features.md>).

- Pogo cable assemblies

For the available pogo cable assemblies, refer to [Pogo cable assemblies](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md#_350670__s_Pogo_cable_assemblies>) in [XPS256 pogo pin assignment](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md>).

In the tester.model file, the pogo cable assembly is to be defined as follows:

 | Product number  | Pogo block type  | # pogo blocks  | tester.model file |
 | [EK751HDA](<../02.03_DUT_board_design_reference/02.03.06.02.07.01_XPS256_pogo_cable_assembly_EK751HDA__16_HD_pogo_blocks__256_channels.md>) |

[High-density (HD)](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md#_350670__s_Pogo_pin_assignment_HD_pogo_block>)

   | 16  | ... type = REDIRECT, subtype = EK751HDA |
 | [EK751VHDA](<../02.03_DUT_board_design_reference/02.03.06.02.07.02_XPS256_pogo_cable_assembly_EK751VHDA__8_VHD_pogo_blocks__256_channels.md>)  | [Very-high-density (VHD)](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md#_350670__s_Pogo_pin_assignment_VHD_pogo_block>)  | 8  | ... type = REDIRECT, subtype = EK751VHDA |

Default value, if parameter type is not defined, is the [EK751HDA](<../02.03_DUT_board_design_reference/02.03.06.02.07.01_XPS256_pogo_cable_assembly_EK751HDA__16_HD_pogo_blocks__256_channels.md>) pogo cable assembly for XPS256 (EK751HC).

- Pogo blocks

  - [High-density (HD) pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md#_350670__s_Pogo_pin_assignment_HD_pogo_block>)For the pogo cable assemblies that use HD pogo blocks with 16 channels each, the 16 pogo blocks of the assembly are to be defined as simple list or as groups:

```
... pogoblocks = A B C D ... P
... pogoblocks = A-B ...
```

  - [Very-high-density (VHD) pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.02.07_XPS256_pogo_pin_assignment.md#_350670__s_Pogo_pin_assignment_VHD_pogo_block>)The channels on the VHD block are split into two groups:

    - For channels A1 …nbsp;A16[1)](<#_350709__fn_PA_PB>) on pogo block rows a, b, c, and d, the same mapping is used as for the HD pogo block. For these channels, the physical pogo block position is used in tester.model file.
    - The additional channels B1 …nbsp;B16[1)](<#_350709__fn_PA_PB>) on pogo block rows e, f, and g are mapped to virtual pogo blocks. The number of a virtual pogo block is defined by the physical pogo block position plus an offset of 400.
The following syntax is to be used to define the eight physical pogo blocks `A` …`H` of the pogo cable assembly:

```
... pogoblocks = A A+400 B B+400 C C+400 D D+400 ... H H+400, type = REDIRECT, subtype = EK751VHDA
```

The notation in the syntax definition above is as follows:

    - Physical pogo blocks `A` …`H` without an offset refer to the channels on pogo block rows a, b, c, d.
    - `A+400` …`H+400` refer to the channels on pogo block rows e, f, g and define eight virtual pogo blocks.

Note that in the tester.model file you have to define twice as many pogo blocks as the pogo cable assembly has pogo blocks: All physically available pogo blocks and the same number of virtual pogoblocks that cover the additional channels B1 …nbsp;B16.

Example for HD pogo cable assembly EK751HDA:

The following example code shows how to define an XPS256 (EK751HC) card with 256 channels that connects to the DUT interface via a 16 connection pogo cable assembly with HD pogo blocks. Since pogo cable assembly EK751HDA is the default, the definition of the type and subtype are optional.

```
CARD_CONFIGURATION
    slot = 107, HW = XPS256, pogoblocks = 417-432, type = REDIRECT, subtype = EK751HDA
```

Example for VHD pogo cable assembly EK751VHDA:

 The following example code shows how to define an XPS256 (EK751HC) card with 256 channels that connects to the DUT interface via an 8 connection pogo cable assembly with VHD pogo blocks:

- The physical block positions 417 …nbsp;424 are assigned to channels A1 …nbsp;A16 on pogo block rows a, b, c, and d.
- The virtual block positions 817 …nbsp;824 are assigned to the additional channels B1 …nbsp;B16 on pogo block rows e, f, and g.

```
CARD_CONFIGURATION
    slot = 107, HW = XPS256, pogoblocks = 417 817 418 818 419 819 420 820 421 821 422 822 423 823 424 824, type = REDIRECT, subtype = EK751VHDA
```

## High‑accuracy voltage mode

XPS256 features a licensed high‑accuracy voltage mode. In this mode, the 1.5 V voltage range is used to provide a higher accuracy for all voltage related settings and measurements.

The high‑accuracy voltage mode applies to forcing, clamping, and measuring voltages. For more information, see the [XPS256 voltage specifications](<../02.02_Specifications/02.02.05.03.02_XPS256_voltage_specifications.md>).

Since a license is required for the high‑accuracy voltage mode, the mode must be enabled per pin in the HAC column of the [DC Scale Extensions editor](<../02.08_Setup_and_Result_Tools/02.08.04.18.03.05_DC_Scale_Extensions_editor.md>):

## Pull‑down circuit at P#, PS# and GS#

  Each of the pins P#, PS# and GS# features a circuit that pulls the pin down to ground. The circuit keeps the voltage at disconnected pins at a defined level of about 0 V referenced to the GND pin.

- Pull‑down resistance: Typical 200 kΩ
At the end of the main testflow, the pull‑down circuit is activated for all three pins P#, PS# and GS#. For all other cases, the state of the pull down is shown in the following table:

 | Operating mode  | Connection state  | [Measurement mode](<../02.07_Test_Method_Reference/02.07.04.01.234.01.24_SPMU_PIN_TASK.mode.md>)  | Default state of the pull‑down circuit |
 | P#, PS#, and GS# |
 | DPS  | disconnected (hiz)  | n/a  | active |
 | disconnected (loz)  | n/a  | inactive |
 | connected  | n/a  | inactive |
 | PMU  | disconnected (hiz)  | n/a  | active |
 | disconnected (loz)  | n/a  | inactive |
 | connected  | All measurement modes  | inactive  |  The behavior of the pull‑down circuit in disconnected state of the pins can be modified by the following APIs:

 |   | SmartRDI:  | [rdi.dc().pulldown()](<../02.07_Test_Method_Reference/02.07.13.12.02.33_pulldown.md>) |
 |   | Test method API:  | [SPMU_PIN_TASK.pulldown()](<../02.07_Test_Method_Reference/02.07.04.01.234.01.27_SPMU_PIN_TASK.pulldown.md>) |

## Handling of disconnected channels

 For protection of the DUT, the DUT board and the tester hardware, channels that exceed a defined limit can cause that a status flag is set and are automatically disconnected if this functionality has been enabled. This applies to the following status flags:

- [Current limit disconnect](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Current_limit_disconnect>)
- [Overpower / Overcurrent / Power budget exceeded](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Overpower>)
- [Overtemperature](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Overtemperature>)
- [Overvoltage](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Overvoltage>)
- [Voltage drop force](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Voltage_drop_force>)
- [Voltage drop return](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Voltage_drop_return>)

In this context "disconnected" means that output relays are opened by the channel controller immediately and independently of the SmarTest software.

To continue normal operation, the related pin must additionally be disconnected and reconnected by SmarTest.

An active status flag for an XPS256 pin that has been disconnected by the channel controller is indicated the next time the pin is accessed. To display the actual state, the pin must also be disconnected and reconnected by SmarTest.
