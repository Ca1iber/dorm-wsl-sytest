# DPS128 and DPS64 pogo cabling and model file configuration

The various pogo cable assemblies (supported by the DPS128/DPS64 ensure DUT board compatibility with the DPS32 and the MS-DPS power supplies. Each of these pogo cable assemblies requires a specific entry in the [model file](<../02.04_Model_File_and_Licensing/02.04.01_The_model_file.md>).

## DPS128 and DPS64 card configuration in the model file

In the [POGOCABLING](<../02.04_Model_File_and_Licensing/02.04.01.03.02.02_POGOCABLING_section.md>) section of the [model file](<../02.04_Model_File_and_Licensing/02.04.01_The_model_file.md>) you must specify the installed pogo cable assembly as follows:

- [E8023PA pogo cable assembly: 8 HD pogo blocks (Standard)](<../02.03_DUT_board_design_reference/02.03.06.02.02.01_E8023PA_pogo_cable_assembly__8_HD_pogo_blocks__Standard.md>)

The E8023PA pogo cable assembly connects the DPS128/DPS64 via eight HD pogo blocks to the DUT board.

There are no special rules and no special checks in the software.

Example:

```
112: pogoblocks = "225, 425, 229, 429, 303, 304, 307, 308"
```

DPS64 channels are connected via the first four pogo blocks. These four pogo blocks must be defined in the POGOCABLING section. See also the E8023PH pogo assembly below.

Example:

```
112: pogoblocks = "225, 425, 229, 429"
```

- [E8023PB pogo cable assembly: 2 VHD pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.02.02.02_E8023PB_pogo_cable_assembly__2_VHD_pogo_blocks.md>)

The E8023PB pogo cable assembly connects the DPS64 or half of the DPS128 channels via two VHD pogo blocks to the DUT board.

Pogo cable assembly E8023PB is supported by SmarTest 7.5.4.4, 8.3.4.2, and higher.

  - For channels A1 鈥?nbsp;A16[1)](<#_140649__d203e61>) on pogo block rows a, b, c, and d, the same mapping is used as for the HD pogo block. For these channels, the physical pogo block position is used in the model file.
  - The additional channels B1 鈥?nbsp;B16[1)](<#_140649__d203e61>) on pogo block rows e, f, and g are mapped to virtual pogo blocks. The number of a virtual pogo block is defined by the physical pogo block position plus an offset of 400.

The pogo block sequence is defined as follows:

`"AB, AB+400, CD, CD+400"`

The notation in the sequence definition above is as follows:

  - Physical pogo blocks `AB` and `CD` without an offset refer to the channels on pogo block rows a, b, c, d.
  - `AB+400` and `CD+400` refer to the channels on pogo block rows e, f, g and define two virtual pogo blocks.

Example:

```
107: pogoblocks = "317, 717, 318, 718", type = REDIRECT,
                        subtype = E8023PB, config = "317=317,717; 318=318,718"
```

Note that in the model file you have to define twice as many pogo blocks as the pogo cable assembly has pogo blocks: All physically available pogo blocks and the same number of virtual pogo blocks that cover the additional channels B1 鈥?nbsp;B16.

- [E8023PC pogo cable assembly: 4 HD pogo blocks (DPS128-HC only)](<../02.03_DUT_board_design_reference/02.03.06.02.02.03_E8023PC_pogo_cable_assembly__4_HD_pogo_blocks__DPS128-HC_only.md>)

The E8023PC pogo cable assembly connects the DPS128 via four HD pogo blocks to the DUT board, ganging two DPS128 channels to one channel on the pogo block side. The pogo cable assembly combines 32 DPS128 channels per pogo block. Virtual pogo blocks, using an offset of 432 to the physical pogo block locations, must therefore be defined.

The pogo block sequence is defined as follows:

`"A, A+432, B, B+432, C, C+432, D, D+432"`

Example:

```
112: pogoblocks = "225, 657, 425, 857, 229, 661, 429, 861",
     type=REDIRECT, subtype=E8023PC,
     config="225=225,657; 425=425,857; 229=229,661; 429=429,861"
```

SmarTest checks that eight addresses are entered, that the offset for the virtual pogo blocks is 432 and that the mapping (config) is correctly set up.

- [E8023PD pogo cable assembly: 2 HD pogo blocks (DPS64 only)](<../02.03_DUT_board_design_reference/02.03.06.02.02.04_E8023PD_pogo_cable_assembly__2_HD_pogo_blocks__DPS64_only.md>)

The E8023PD pogo cable assembly connects the DPS64 card via two HD pogo blocks to the DUT board. It gangs two DPS64 channels to one channel on the pogo block side. Virtual pogo blocks, using an offset of 432 to the physical pogo block locations, are to be defined.

This cable is only used for the half-populated DPS card with 64 channels (equals 4 logical boards).

The pogo block sequence is defined as follows:

"`A, A+432, ,B ,B+432"`

Example:

```
112: pogoblocks = "225, 657, 425, 857",
     type=REDIRECT, subtype=E8023PD,
     config="225=225,657; 425=425,857"
```

SmarTest checks that four addresses are entered, that the offset for the virtual pogo blocks is 432 and that the mapping (config) is correctly set up.

- [E8023PE pogo cable assembly: 8 MS-DPS style pogo blocks (DPS128-HC only)](<../02.03_DUT_board_design_reference/02.03.06.02.02.05_E8023PE_pogo_cable_assembly__8_MS-DPS_style_pogo_blocks__DPS128-HC_only.md>)

The E8023PE pogo cable assembly connects the DPS128-HC via eight MS-DPS style pogo blocks to the DUT board. It gangs two DPS128 channels to one channel on the pogo block side.

All DPS128 channels are to be defined by virtual pogo blocks. Pogo blocks such as "341, 342" are virtual pogo blocks.

The physical MS-DPS pogo block locations are defined by the config statement. This statement assigns the virtual three-digit DPS128 pogo blocks to the physical one-digit MS-DPS pogo block locations.

Example:

```
112: pogoblocks = "341, 342, 343, 344, 345, 346, 347, 348",
     type=REDIRECT, subtype=E8023PE,
     config="1=341; 2=342; 3=343; 4=344; 5=345; 6=346; 7=347; 8=348"
```

SmarTest checks that eight addresses are entered and that the mapping (config) is correctly set up.

- [E8023PF pogo cable assembly: 2 MS-DPS style pogo blocks (DPS64 only)](<../02.03_DUT_board_design_reference/02.03.06.02.02.06_E8023PF_pogo_cable_assembly__2_MS-DPS_style_pogo_blocks__DPS64_only.md>)

The E8023PF pogo cable assembly connects the DPS64 card via two MS-DPS style pogo blocks to the DUT board. It gangs four DPS64 channels to one channel on the MS-DPS pogo block side.

All DPS64 channels are to be defined by virtual pogo blocks. Pogo blocks such as "341, 342" are virtual pogo blocks.

The physical MS-DPS pogo block locations are defined by the config statement. This statement assigns the virtual three-digit DPS128 pogo blocks to the physical one-digit MS-DPS pogo block locations.

Example:

  -

First cable:

```
112: pogoblocks = "341, 342, 343, 344", type=REDIRECT, subtype=E8023PF,
     config="1=341, 342; 2=343, 344"
```

  -

Second cable:

```
113: pogoblocks = "345, 346, 347, 348", type=REDIRECT, subtype=E8023PF,
     config="3=345, 346; 8=347, 348"
```

  -

Third cable:

```
114: pogoblocks = "457, 458, 459, 460", type=REDIRECT, subtype=E8023PF,
     config="4=457, 458; 5=459, 460"
```

  -

Fourth cable:

```
115: pogoblocks = "461, 462, 463, 464", type=REDIRECT, subtype=E8023PF,
     config="6=461, 462; 7=463, 464"
```

- [E8023PG pogo cable assembly: 4 MS-DPS style pogo blocks (DPS64 only)](<../02.03_DUT_board_design_reference/02.03.06.02.02.07_E8023PG_pogo_cable_assembly__4_MS-DPS_style_pogo_blocks__DPS64_only.md>)

The E8023PG pogo cable assembly connects the DPS64-HC via four MS-DPS style pogo blocks to the DUT board: It gangs two DPS128 channels to one channel on the MS-DPS pogo block side.

All DPS64 channels are to be defined by virtual pogo blocks. Pogo blocks such as "341, 342" are virtual pogo blocks.

The physical MS-DPS pogo block locations are defined by the config statement. This statement assigns the virtual three-digit DPS128 pogo blocks to the physical one-digit MS-DPS pogo block locations.

Example:

  -

First cable:

```
112: pogoblocks = "341, 342, 343, 344", type=REDIRECT, subtype=E8023PG,
     config="1=341; 2=342; 3=343; 4=344"
```

  -

Second cable:

```
113: pogoblocks = "345, 346, 347, 348", type=REDIRECT, subtype=E8023PG,
     config="5=345; 6=346; 7=347; 8=348"
```

SmarTest checks that four addresses are entered and that the mapping (config) is correctly set up.

- [E8023PH pogo cable assembly: 4 HD pogo blocks (DPS64 standard)](<../02.03_DUT_board_design_reference/02.03.06.02.02.08_E8023PH_pogo_cable_assembly__4_HD_pogo_blocks__DPS64_standard.md>)

The E8023PH pogo assembly connects the DPS64 card via four HD pogo blocks to the DUT board.

There are no special rules and no special checks in the software.

Example:

```

```

- [E8023PK pogo cable assembly: 4 VHD pogo blocks (DPS128)](<../02.03_DUT_board_design_reference/02.03.06.02.02.09_E8023PK_pogo_cable_assembly__4_VHD_pogo_blocks__DPS128.md>)

The E8023PK pogo cable assembly connects the DPS128 via four VHD pogo blocks to the DUT board.

Pogo cable assembly E8023PK is supported by SmarTest 7.5.4.4, 8.3.4.3, and higher.

  - For channels A1 鈥?nbsp;A16[1)](<#_140649__d203e61>) on pogo block rows a, b, c, and d, the same mapping is used as for the HD pogo block. For these channels, the physical pogo block position is used in the model file.
  - The additional channels B1 鈥?nbsp;B16[1)](<#_140649__d203e61>) on pogo block rows e, f, and g are mapped to virtual pogo blocks. The number of a virtual pogo block is defined by the physical pogo block position plus an offset of 400.

The pogo block sequence is defined as follows:

`"AB, AB+400, CD, CD+400, EF, EF+400, GH, GH+400"`

The notation in the sequence definition above is as follows:

  - Physical pogo blocks `AB` 鈥?`GH` without an offset refer to the channels on pogo block rows a, b, c, d.
  - `AB+400` 鈥?`GH+400` refer to the channels on pogo block rows e, f, g and define four virtual pogo blocks.

Example:

```
105: pogoblocks = "320, 720, 321, 721, 322, 722, 323, 723", type=REDIRECT,
                        subtype = E8023PK, config="320=320,720; 321=321,721;322=322,722; 323=323,723"
```

Note that in the model file you have to define twice as many pogo blocks as the pogo cable assembly has pogo blocks: All physically available pogo blocks and the same number of virtual pogo blocks that cover the additional channels B1 鈥?nbsp;B16.

## DPS128 power budget

The DPS128/DPS64 card features two power domains with a dedicated power budget. Each domain is able to deliver half of the overall power budget. The power domain to channel mapping must be observed for DPS128 cards when assigning the available channels to the DUT pins. For more information refer to [DPS128/DPS64 power budget](<02.05.05.01.05_DPS128____PS64_power_budget.md>).
