# Pin Scale 5000 embedded timing search

The per pin architecture enables fast timing searches as the data does not need to be uploaded to the workstation.

The main purpose of the embedded timing search is to adjust the tester timing to the actual behavior of the DUT.

To detect PASS/FAIL or FAIL/PASS transitions within a search range and to locate the transition points, the embedded timing search does an automatic alignment. To achieve the alignment, the embedded timing search goes through the following sequence:

- It broadcasts search parameters to test processors.
- It calculates the next timing settings per channel/test processor.
- It executes functional tests in parallel on all channels with the new timing settings per channel.
- It repeats the steps 2. and 3. until the search on all channels is done (local in TP).
- It retrieves the search result per channel when the search is finished for all channels.

When executing a timing search, a timing offset is calculated and set to the middle of the eye. Thereafter, the new timing offset will always be added to the timing information specified in the timing set.

 Note As the timing search is done locally in the test processor (TP), setup and result channel must belong to the same TP.  Note The timing search is not based on the equation system and, therefore, does not move or modify a spec variable during the search. The timing search only varies the timing offset delay.

Embedded timing search is programmed via test method APIs:

- [TIMING_OFFSET_SEARCH_TASK](<../02.07_Test_Method_Reference/02.07.04.01.248_TIMING_OFFSET_SEARCH_TASK.md>)
- [TIMING_OFFSET_SEARCH_PINS](<../02.07_Test_Method_Reference/02.07.04.01.248.01_TIMING_OFFSET_SEARCH_PINS.md>)
