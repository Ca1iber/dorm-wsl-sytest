# XPS256 programming - Measure currents

Each channel of an XPS256 card features six combined force, clamp, and measure current ranges.

## Current ranges

Each PMU features six combined force, clamp, and measure current ranges:

 | Variant  | Range  | Minimum and maximum current |
 | XPS256  | 1 A  | -1.0 A  | ...  | 1.0 A |
 | 100 mA  | -100.0 mA  | ...  | 100.0 mA |
 | 10 mA  | -10.0 mA  | ...  | 10.0 mA |
 | 1 mA  | -1.0 mA  | ...  | 1.0 mA |
 | 100 渭A  | -100.0 渭A  | ...  | 100.0 渭A |
 | 10 渭A  | -10.0 渭A  | ...  | 10.0 渭A |

The current ranges are common for forcing, clamping, and measuring currents. The force or clamp range is always the same as the measurement range. For specification data, refer to [XPS256 voltage specifications](<../02.02_Specifications/02.02.05.03.02_XPS256_voltage_specifications.md>).

## Measurement filters

XPS256 channels feature programmable anti-aliasing, low-pass measurement filters for all ADCs:

- Voltage measurement ADC of the PMU
- Current measurement ADC of the PMU
- Voltage drop measurements on the force line
- Voltage drop measurements on the return line

 | Measurement filter characteristics |
 | Minimum cutoff frequency:  | 10 Hz |
 | Maximum cutoff frequency:  | 500 kHz |
 | Default cutoff frequency:  | 30 kHz |

The dynamic behavior of the force output is independent of the measurement filters.

## Averaging

All channels of the card feature hardware based averaging of measurements. The average of multiple consecutive ADC samples is calculated and stored on board. Hardware based averaging can be utilized for code鈥慴ased and pattern鈥慴ased measurements.

 | Hardware-based averaging |
 | Programmable range of samples:  | 1 ... 262144 (any value supported) |
 | ADC sample frequency:  | 2 MHz[1)](<#_354458__d609e1117>) |

Some hints to consider:

- The sample time for averaged measurements must be taken into account.
- Pattern鈥慴ased measurements require a minimum number of vectors after the trigger has been initiated. For more information, refer to [Timing of DC events](<../02.07_Test_Method_Reference/02.07.04.01.63.01.01_Timing_of_DC_events.md>) and the related sub-topics.
- The effective maximum sample frequency is the ADC sample frequency of 2 MHz[1)](<#_354458__d609e1117>) divided by the number of averaged samples.
- The "measurement filter" may be used instead of averaging if a high effective sample frequency is required. This filter behaves like a simple RC filter. The settling time is to be considered but the filter setting has no effect on the effective maximum sample frequency.
- The dynamic behavior of the force output is independent of the settings for averaging.

## Automatic down鈥憆anging

 XPS256 channels feature automatic down鈥憆anging for current measurements:

- In [DPS operating mode](<02.05.05.03.10.07_XPS256_programming_-_DPS_operating_mode.md>), automatic down鈥憆anging is supported for both [code鈥慴ased](<../02.07_Test_Method_Reference/02.07.01.01.02_Code-based_and_pattern-based_programming.md#_355202__s_Code-based_programming>) and [pattern鈥慴ased](<../02.07_Test_Method_Reference/02.07.01.01.02_Code-based_and_pattern-based_programming.md#_355202__s_Pattern-based_programming>) programming using the [DPS_TASK](<../02.07_Test_Method_Reference/02.07.04.01.50_DPS_TASK.md>) API, the [DC events](<../02.07_Test_Method_Reference/02.07.04.01.63_EVENT_...__DC_events_API_reference.md>) or [SmartRDI](<../02.07_Test_Method_Reference/02.07.13.12.02_Setting_up_DC_Scale_pins_with_SmartRDI.md>).
- In [PMU operating mode](<02.05.05.03.10.15_XPS256_programming_-_PMU_operating_mode.md>), automatic down鈥憆anging is supported only for [pattern鈥慴ased](<../02.07_Test_Method_Reference/02.07.01.01.02_Code-based_and_pattern-based_programming.md#_355202__s_Pattern-based_programming>) programming using the [DC events](<../02.07_Test_Method_Reference/02.07.04.01.63_EVENT_...__DC_events_API_reference.md>) or [SmartRDI](<../02.07_Test_Method_Reference/02.07.13.12.02_Setting_up_DC_Scale_pins_with_SmartRDI.md>). Automatic down鈥憆anging is not supported for [code鈥慴ased](<../02.07_Test_Method_Reference/02.07.01.01.02_Code-based_and_pattern-based_programming.md#_355202__s_Code-based_programming>) programming, which means that settings done by APIs [SPMU_PIN_TASK.iMeasureRange()](<../02.07_Test_Method_Reference/02.07.04.01.234.01.16_SPMU_PIN_TASK.iMeasureRange.md>) and [rdi.dc().iMeasRange()](<../02.07_Test_Method_Reference/02.07.13.12.02.19_iMeasRange.md>) are silently ignored. For code鈥慴ased programming, we recommend therefore, always using the APIs [SPMU_PIN_TASK.iForceRange()](<../02.07_Test_Method_Reference/02.07.04.01.234.01.15_SPMU_PIN_TASK.iForceRange.md>) and [rdi.dc().iForceRange()](<../02.07_Test_Method_Reference/02.07.13.12.02.17_iForceRange.md>).

Automatic down-ranging means that the current range is automatically changed to the best fit range for the measurement and restored to the original range after the measurement.

 Two parameters define whether the automatic down-ranging is performed or not:

- The force current or clamp current range:

  - Can be set explicitly or (if not defined)
  - is automatically derived from the forced or clamped value.

- The current measurement range:

  - Can be set explicitly or (if not defined)
  - is automatically derived from the pass/fail thresholds.

Automatic down-ranging is performed only if the current measurement range is lower than the force / clamp current range regardless whether the ranges have been set explicitly or have been selected automatically. Restoring the XPS256 current range after down-ranging always restores the last applied force current range:

- For code-based programming in DPS operating mode, the current range is automatically restored.
- For pattern-based programming in DPS- or PMU operating mode, the current measure range is not automatically restored. We recommend adding an [EVENT_RANGE_RESTORE](<../02.07_Test_Method_Reference/02.07.04.01.63.15_EVENT_RANGE_RESTORE.md>) at the end of the pattern or using SmartRDI function [restoreRange()](<../02.07_Test_Method_Reference/02.07.13.12.02.35_restoreRange.md>) at least at the end of the [RDI block](<../02.07_Test_Method_Reference/02.07.13.05_Code_structure_with_SmartRDI.md#_142604__dle_RDI_block>).

## Application notes

  Flush vectors at the end of a pattern  Due to inter module communication it is required to keep the pattern running for a short time after the last ADC measurement related DC event. The actual required time or number of flush vectors depends on the setup. In case of insufficient number of vectors before pattern stop, a communication error might occur.

The number of required flush vectors depends on the average count and the pattern cycle time as follows:

Minimum number of vectors = 37 + ( average / (2 MHz * period) )

 |   | where:  | average  | = Programmed average count |
 |   |   | period  | = Cycle time of the pattern |

The calculated number is the minimum number of vectors that is required between the last measure event and the end of the pattern.
