# Pin Scale 5000 timing setup

The Pin Scale 5000 card can drive and receive single-ended or differential signals up to data rates of 5.0 Gbit/s. For this purpose, you to need to set up various termination configurations and, depending on the speed of data you wish to transfer, one of the two operating modes: "Standard" (std) or "Fast" (FAST). The timing (and level) setup with FAST pins must be equation based.

  Note FAST mode is a pre-release version on SmarTest 7.10.3 and has been enabled only for evaluation purposes.

## Timing setup

The timing setup of the Pin Scale 5000 provides the following features:

- Use of contexts (modecontext).
- Introduction of a FAST mode.
- 256 waveforms (std and FAST pins).
- 8 drive (all tri-state capable), 8 receive edges (std and FAST pins).
- Device cycle names up to 16 characters.
- X-mode definition per pin via period_div keyword. This applies to FAST pins only.
- Supported x-modes for FAST pins are: x1, x2, x3, x4, x6, x8 (see below).
- Special support for differential signals in wavetables and pattern debug tool.

## Defining timing edges in the equation

 You can define the timing edges in the following ways:Note For FAST mode, only the option 2 is possible.

- By defining every offset.

```
# Timing equation
...
Period = 10
PINS P1
  d1 = 0.0
  d2 = 2.5
  d3 = 5.0
  d4 = 7.5
```

- By specifying the [period divisor](<../02.08_Setup_and_Result_Tools/02.08.04.34.04.03.04.12_Period_divisor__period_div.md>) using the keyword period_div and together defining the d1 edge. This will result in four equidistant distributed edges. Note For FAST mode, only this option is possible.

```
# Timing equation
...
period = 10
PINS p1
  period_div = 4
  d1 = 0.0
```

- By specifying the period divisor using the keyword period_div and together defining the d1 and d5 edges. This will result in two sets of four equidistant distributed edges.

```
# Timing equation
...
period = 10
PINS p1
  period_div = 4
  d1 = 0.0
  d5 = 2.0
```

## Possible X-Modes in the FAST mode

In the FAST mode the, Pin Scale 5000 card uses a multiplexing architecture between the test processor and the front-end. This has the following impact:

- Possible programmable X-modes are: X1, X2, X3, X4, X6, X8.
- Because of this architecture, in principle only even x-modes are possible but the X1 and X3-modes are derived from an internally programmed X2 and X6-mode, respectively. As the maximum X-mode is X8, it is not possible to program X5 and X7-modes.

You use the keyword period_div (see [Period divisor (period_div)](<../02.08_Setup_and_Result_Tools/02.08.04.34.04.03.04.12_Period_divisor__period_div.md>)) to define the X-mode in the timing equation set. This is shown below for an X4 mode. Setting period_div is mandatory in FAST mode.

```
# Timing equation
...
PINS A0,A0-        # I-pins

   period_div=4   # Accepted values: 1,2,3,4,6,8
   d1=...
```

In the figure above, the differential pins have been defined as PINS A0, A0-.

To give the same result, you could also use the shorthand notation to specify just one of the differential pins (A0) as PINS A0@diff, see [Differential pins - @diff](<../02.08_Setup_and_Result_Tools/02.08.04.34.04.03.02.01_Differential_pins_-__diff.md>).

## Receive Edge Positioning

In the FAST mode, the receiver uses a re-timing technique. Due to the re-timing, only 1 receive edge can be programmed - others are equidistantly distributed over the test system period according to the specified X-mode.
