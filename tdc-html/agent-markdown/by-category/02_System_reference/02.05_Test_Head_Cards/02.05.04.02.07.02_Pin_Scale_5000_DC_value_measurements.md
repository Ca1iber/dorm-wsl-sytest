# Pin Scale 5000 DC value measurements

With the PS5000 pin PMU and the board ADC, you can perform pattern-synchronous DC value measurements. Your options are:

- Pattern-controlled true parallel DC value measurements with the pin PMU

  - Pin PMU value measurement using level comparator.
  - Resource per pin, full parallel capability. Single measurement typically takes more time than (2) and (3) but all pin PMU channels settle in parallel and all A/D conversions are done in parallel.

- Pattern-controlled DC value measurements with the pin PMU and board ADC

  - Pin PMU value measurement using board ADC.
  - Resource per pin. All pin PMU channels settle in parallel, A/D conversion serialized through AMUX on Board ADC.

- Pattern-controlled DC value measurements with the board ADC

  - High-impedance board ADC value measurement.
  - Resource shared by 16 channels. Single measurement is typically faster than (1) and (2), but one Board ADC is shared by 16 channels. Depending on load board design, this may require switching of DC relays which makes it overall slower than (1) and (2).

Note that both the speed and the accuracy of this measurement compared to (1) and (2) ultimately depends on the number of samples taken: A high number of samples (for example, 1024) provides the highest accuracy but will take typically longer than methods (1) or (2). Specifying fewer samples (for example, 16) results in faster performance but does not provide the maximum accuracy.

For further details and examples see the sections below. For specifications see [Pin Scale 5000 parametric measurement unit](<../02.02_Specifications/02.02.04.03.09_Pin_Scale_5000_parametric_measurement_unit.md>) and [Pin Scale 5000 precision voltage measure (board ADC)](<../02.02_Specifications/02.02.04.03.10_Pin_Scale_5000_precision_voltage_measure__board_ADC.md>) in the [PS5000 specifications](<../02.02_Specifications/02.02.04.03_PS5000_specifications.md>).

## Pattern-controlled true parallel DC value measurements with the pin PMU

This relies on the successive approximation technique using the level comparator of the pin PMU (PPMU).

The following figure gives an overview.

   ![PS5000 DC value measurements with the Pin PMU](<../../../../raw/354965.png>)   Note The AC relay shown in the Hardware view does not represent a real relay. SmarTest uses here a generalized schematic diagram.

To set this up, test methods are used to achieve parallel DC value measurements on all pins.

The implementation is similar to the Pin Scale 1600 card.

 The following test method APIs are used:

- [PPMU_SETTING](<../02.07_Test_Method_Reference/02.07.04.01.160_PPMU_SETTING.md>) , [PPMU_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.158_PPMU_RELAY.md>), [PPMU_CLAMP](<../02.07_Test_Method_Reference/02.07.04.01.154_PPMU_CLAMP.md>), [PPMU_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.157_PPMU_MEASURE.md>)
- [PPMU_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.157_PPMU_MEASURE.md>) measurement type TM::VMUM to perform fast value determination on all channels using Pin PMU comparators.
- [PATTERN_CONTROLLER](<../02.07_Test_Method_Reference/02.07.04.01.142_PATTERN_CONTROLLER.md>) to perform measurement.
- [DC_RESULT_ACCESSOR](<../02.07_Test_Method_Reference/02.07.04.01.28_DC_RESULT_ACCESSOR.md>) to retrieve results.

This method allows you to save time by performing the measurements in parallel (see figure below).

   ![PS1600 Measurement Times for DC Value Measurements with Pin PMU](<../../../../raw/126344.png>)

## Pattern-controlled DC value measurements with the pin PMU and board ADC

Here, you have a better accuracy but, although the settling time of the pin PMU is done in parallel for all pins, you measure serially.

The following figure gives an overview.

   ![PS5000 DC value measurements with Pin PMU and board ADC](<../../../../raw/354966.png>)

Pass/Fail results for these measurements are coming from Pin PMU comparators; values are measured with the Board ADC.

The AMUX for the BADC can be set either before the functional test is executed using the [FLEX_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.68_FLEX_RELAY.md>) or the [SPMU_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234_SPMU_TASK.md>) API, or the AMUX can be set during the functional test using the [PPMU_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.158_PPMU_RELAY.md>) API.

 The following test method APIs are used:

- Either [FLEX_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.68_FLEX_RELAY.md>) or [SPMU_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234_SPMU_TASK.md>) for the AMUX and relay control (before the functional test)
- [PPMU_SETTING](<../02.07_Test_Method_Reference/02.07.04.01.160_PPMU_SETTING.md>) to set up pins and limits
- [PPMU_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.158_PPMU_RELAY.md>) for the PPMU relay control (PPMU_ON) and the AMUX control (MUX_PPMU_BADC_ON)
- [PPMU_BADC_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.153_PPMU_BADC_MEASURE.md>) for DC-dynamic high accuracy board ADC measurements
- [BADC_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.08_BADC_MEASURE.md>) to set up Board ADC measurement samples
- [PATTERN_CONTROLLER](<../02.07_Test_Method_Reference/02.07.04.01.142_PATTERN_CONTROLLER.md>) to perform the measurement
- [DC_RESULT_ACCESSOR](<../02.07_Test_Method_Reference/02.07.04.01.28_DC_RESULT_ACCESSOR.md>) to retrieve results

See also the "Pattern controlled Pin PMU voltage measurement using Board ADC and FLEX_RELAY path control" example below.

 Note Selective capture and DC measurements: When using selective capture and DC measurements (or any other sequencer instruction that generates break vectors such as (BRKV, CTIM, CLEV, Matchloop, etc.) in a pattern, you have to observe certain preconditions with respect to the capture block sizes. In principle, the blocks where data is captured must always be a multiple of 8 cycles, otherwise unwanted samples will be recorded when entering the break cycle generating part of the pattern. This restriction does not apply to the [Pin Scale 5000 card](<02.05.04.02_Pin_Scale_5000_card.md>). Hence, the data captured by the PS5000 may not be the same as the data captured by the PS1600, if this condition is not followed.

## Pattern-controlled DC value measurements with the board ADC

The following figure shows this arrangement.

   ![PS5000 DC value measurements with the board ADC](<../../../../raw/354967.png>)   Note The AC relay shown in the Hardware view does not represent a real relay. SmarTest uses here a generalized schematic diagram. This method gives you the following features:

- High-impedance voltage measurement with the board ADC
- Accuracy of 卤500uV, for example, for DC trimming applications
- Resolution of 20bit to address low-end DAC test

Note, however, that the board ADC is shared between 16 pins, which may be necessary to consider in your DUT board design.

The DC relay and the BADC relay, including the AMUX are sequencer鈥慶ontrolled.

Pass/fail results are judged from values measured with the board ADC and the specified limits.

 The following test method APIs are used:

- Either [FLEX_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.68_FLEX_RELAY.md>) or [SPMU_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234_SPMU_TASK.md>) to switch the relays and control the measurement path statically before the functional test,

or [PPMU_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.158_PPMU_RELAY.md>) for the DC relay control and the BADC, including AMUX control (MUX_VM_HIZ_ON)

- [BADC_SETTING](<../02.07_Test_Method_Reference/02.07.04.01.09_BADC_SETTING.md>) to set up pins and limits
- [BADC_MEASURE](<../02.07_Test_Method_Reference/02.07.04.01.08_BADC_MEASURE.md>) to set up Board ADC measurement samples
- [PATTERN_CONTROLLER](<../02.07_Test_Method_Reference/02.07.04.01.142_PATTERN_CONTROLLER.md>) to perform the measurement
- [DC_RESULT_ACCESSOR](<../02.07_Test_Method_Reference/02.07.04.01.28_DC_RESULT_ACCESSOR.md>) to retrieve results

See also the "Pattern controlled high impedance voltage measurement with SPMU_TASK path control" example below.

## Special considerations for pattern-controlled DC value measurements with the board ADC

Turn the Site Match Mode flag OFF (site_match_mode=OFF) for proper serialization of the DC-dynamic high BADC measurements (measuring values dynamically by connecting the BADC serially to the PPMUs) using the PPMU_BADC_Measure class. Turning ON the Site Match Mode flag (site_match_mode=ON) may impact the proper serialization of measurements that use shared resource such as the BADC and thus it could cause incorrect readings.

## Examples

### Pattern controlled high impedance voltage measurement with FLEX_RELAY path control

This example forces a voltage with pin PMU on pin "pin_force". This pin is cross-connected with pin "pin_meas". The "pin_meas" pin uses the high impedance (HIZ) measurement path to measure the voltage of "pin_force". The measurement path is configured with the [FLEX_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.68_FLEX_RELAY.md>) API.

```
virtual void run()
{
    DC_RESULT_ACCESSOR result;
    static STRING_VECTOR pinList;
    static string measPins = "pin_meas";

    if(firstRun)
    {
        PATTERN_CONTROLLER pc;
        FLEX_RELAY badcConnect;
        PPMU_SETTING ppmuForce;
        PPMU_RELAY ppmuOn,ppmuOff;
        BADC_SETTING badcSetting;
        BADC_MEASURE badcMeasure;

        ON_FIRST_INVOCATION_BEGIN();

            badcConnect.pin(measPins).set("DC","PMU","MUX_VM_HIZ");
            badcConnect.execute();

            ppmuForce.pin("pin_force")
                    .vForce(forceVoltage.getValueAsTargetUnit("V"))
                    .iRange(1 uA).min(0 uA).max(2 uA);
            ppmuForce.wait(1 ms);

            ppmuOn.pin("pin_force").status("PPMU_ON");
            ppmuOn.wait(1 ms);

            ppmuOff.pin("pin_force").status("AC_ON");
            ppmuOff.wait(1 ms);

            badcSetting.pin(measPins).min(0 V).max(5 V);
            badcSetting.wait(1 ms);

            badcMeasure.pin(measPins).numberOfSamples(16);
            badcMeasure.wait(100 us);

            pc.label("MeasBADC","@").add(ppmuForce)
                    .add(ppmuOn)
                    .add(badcSetting)
                    .add(badcMeasure)
                    .add(ppmuOff);

            pc.setup();

        ON_FIRST_INVOCATION_END();

        firstRun=false;
    }

    ON_FIRST_INVOCATION_BEGIN();

        FUNCTIONAL_TEST();

        result.uploadResult(measPins ,TM::RESULT_INDEX);

        pinList = PinUtility.getDigitalPinNamesFromPinList(measPins,TM::ALL_DIGITAL);

    ON_FIRST_INVOCATION_END();

    //
    // Results
    //
    int numberPins = pinList.size();

    for(int i=0; i<numberPins; i++)
    {
        ARRAY_D values      = result.getValues(pinList[i]);
        int numberOfResults = values.size();

        for (int j = 0; j< numberOfResults; j++)
        {
            double value = values[j];

            cout << "PF: " << result.getPassFail() << endl;
            cout << "NumVal: " << result.getNumberOfAvailableResults(pinList[i]) << endl;
            cout << "FailInfo: " << result.getFailInfo() << endl;
            cout << "PPMU VMHIZ BADC Measurement result: " << value << endl;
        }
    }

    return;
}
```

### Pattern-controlled high impedance voltage measurement with voltage forced by pin PMU

This example shows a pattern-controlled high impedance voltage measurement. A voltage is forced with pin PMU on pin_force. This pin is cross-connected with pin_meas. The pin_meas uses the high impedance measurement path to measure the voltage of pin_force. The measurement path is configured with [SPMU_TASK](<../02.07_Test_Method_Reference/02.07.04.01.234_SPMU_TASK.md>).

```
virtual void run()
{
     DC_RESULT_ACCESSOR result;
     PATTERN_CONTROLLER pc;
     SPMU_TASK badcConnect;
     static STRING_VECTOR pinList;
     static STRING measPins = "pin_meas";

     ON_FIRST_INVOCATION_BEGIN();

        //
        // Connect BADC
        //
        badcConnect.pin(measPins).mode("VM_HIZ").relay("NT").connect();
        badcConnect.execute();

        //
        // Setup dynamic test, do it only one time
        // first_run is a protected variable "Boolean first_run;"
        // which is set to 'true' in initialize method
        //
        if (first_run)
        {
            PPMU_SETTING ppmuForce;
            PPMU_RELAY ppmuOn,ppmuOff;
            BADC_SETTING badcSetting;
            BADC_MEASURE badcMeasure;
            ppmuForce.pin("pin_force")
                 .vForce(forceVoltage.getValueAsTargetUnit("V"))
                 .iRange(1 uA).min(0 uA).max(2 uA);
            ppmuOn.pin("pin_force").status("PPMU_ON");
            ppmuOff.pin("pin_force").status("AC_ON");
            badcSetting.pin(measPins).min(0 V).max(5 V);
            badcSetting.wait(1 ms);
            badcMeasure.pin(measPins).numberOfSamples(16);
            badcMeasure.wait(100 us);

            pc.label("MeasBADC","@").add(ppmuForce)
                                .add(ppmuOn)
                                .add(badcSetting)
                                .add(badcMeasure)
                                .add(ppmuOff);
            pc.setup();

            first_run = false;
        }

        //
        // Execute test
        //
        FUNCTIONAL_TEST();

        result.uploadResult(measPins ,TM::RESULT_INDEX);

        pinList = PinUtility.getDigitalPinNamesFromPinList(measPins,TM::ALL_DIGITAL);

    ON_FIRST_INVOCATION_END();

    //
    // Results
    //
    int numberPins = pinList.size();
    for(int i=0; i<numberPins; i++)
    {
        ARRAY_D values = result.getValues(pinList[i]);
        int numberOfResults = values.size();
        for (int j = 0; j< numberOfResults; j++)
        {
            double value = values[j];
            cout << "PF: " << result.getPassFail() << endl;
            cout << "NumVal: " << result.getNumberOfAvailableResults(pinList[i]) << endl;
            cout << "FailInfo: " << result.getFailInfo() << endl;
            cout << "PPMU VMHIZ BADC Measurement result: " << value << endl;
        }
    }

    return;
}
```

### Pattern controlled Pin PMU voltage measurement using Board ADC and FLEX_RELAY path control

This example does two value measurements with the Board ADC, connected to the Pin PMU.

The measurements validate the voltage forced with Pin PMU on pin "pin_force". This pin is cross connected with pin "pin_meas". The measurement path is configured with the [FLEX_RELAY](<../02.07_Test_Method_Reference/02.07.04.01.68_FLEX_RELAY.md>) API.

```
virtual void run()
{
    DC_RESULT_ACCESSOR result;
    static STRING_VECTOR pinList;
    static string measPins = "pin_meas";

    if(firstRun)
    {
        PATTERN_CONTROLLER pc;
        FLEX_RELAY badcConnect;
        PPMU_SETTING ppmuSetMeasVolt, ppmuSetMeasVolt2;
        PPMU_RELAY ppmuOn,ppmuOff;
        BADC_MEASURE badcMeasure;

        ON_FIRST_INVOCATION_BEGIN();

            badcConnect.pin(measPins).set("PPMU","X","MUX_PPMU");
            badcConnect.execute();

            ppmuOn.pin("pin_force").status("PPMU_ON");
            ppmuOn.wait(1 ms);

            ppmuOff.pin("pin_force").status("AC_ON");
            ppmuOff.wait(1 ms);

            ppmuSetMeasVolt.pin("pin_force").vForce(3 V).iRange(10 uA).min(1 uA).max(2 uA);
            ppmuSetMeasVolt.pin(measPins).iForce(1 uA).iRange(10 uA).min(2 V).max(4 V);
            ppmuSetMeasVolt.wait(1 ms); // ppmu settling

            badcMeasure.pin(measPins).numberOfSamples(16);
            badcMeasure.wait(100 us);

            ppmuSetMeasVolt2.pin("pin_force").vForce(300 mV).iRange(1 mA).min(1 uA).max(2 uA);
            ppmuSetMeasVolt2.pin(measPins).iForce(1 uA).iRange(1 mA).min(250 mV).max(350 mV);

            ppmuSetMeasVolt2.wait(1 ms); //ppmu settling

            pc.label("MeasPPMU_ADC","@").add(ppmuOn)
                                .add(ppmuSetMeasVolt)
                                .add(badcMeasure)
                                .add(ppmuSetMeasVolt2)
                                .add(badcMeasure)
                                .add(ppmuOff);

           pc.setup();

        ON_FIRST_INVOCATION_END();

        firstRun=false;
    }

    ON_FIRST_INVOCATION_BEGIN();

        FUNCTIONAL_TEST();

        result.uploadResult(measPins ,TM::RESULT_INDEX);

        pinList = PinUtility.getDigitalPinNamesFromPinList(measPins,TM::ALL_DIGITAL);

    ON_FIRST_INVOCATION_END();

    //
    // Results
    //
    int numberPins = pinList.size();

    for(int i=0; i<numberPins; i++)
    {
        ARRAY_D values      = result.getValues(pinList[i]);
        int numberOfResults = values.size();

        for (int j = 0; j< numberOfResults; j++)
        {
            double value = values[j];

            cout << "PF: " << result.getPassFail() << endl;
            cout << "NumVal: " << result.getNumberOfAvailableResults(pinList[i]) << endl;
            cout << "FailInfo: " << result.getFailInfo() << endl;
            cout << "PPMU PPMU BADC Measurement result: " << value << endl;
        }
    }

    return;
}
```

### Static high voltage measurement with board ADC

This code snippet demonstrates how to measure high voltage (-6V ~ +13.4V) on HV-configured pins.

```
virtual void run()
{
    // HV DC Voltage BADC direct measurement
    HV_DC_TASK hvDcTask;

    ON_FIRST_INVOCATION_BEGIN();

        hvDcTask.pin("p1") .min(0 mV) .max(1 mV) .execMode("VM_HIZ") .samples(8) .settling(1.5 ms);
        hvDcTask.execute();

    ON_FIRST_INVOCATION_END();

    DOUBLE measuredValue = hvDcTask.getValue("p1");

    return;
}
```
