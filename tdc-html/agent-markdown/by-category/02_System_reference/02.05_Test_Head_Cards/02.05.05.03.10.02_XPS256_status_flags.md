## Status flags and warnings

Several flags indicate the state of the [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) or indicate the occurrence other warnings. For more information refer to [DPS status flags - get...() functions](<../02.07_Test_Method_Reference/02.07.04.01.43.07_DPS_status_flags_-_get...___functions.md>), [DPS power flags - get...() functions](<../02.07_Test_Method_Reference/02.07.04.01.43.06_DPS_power_flags_-_get...___functions.md>) or [DPS_AUX_TASK.getSurgeTrackerStatus()](<../02.07_Test_Method_Reference/02.07.04.01.43.05_DPS_AUX_TASK.getSurgeTrackerStatus.md>).

 | Flag  | Description |
 | Clamp distance too low  | Trigger: |

The programmed distance between the upper and lower clamp voltage or between the sourcing and sinking clamp current is too low.

The flag is set if the clamp distance is continuously too small for a period of more than 400 μs.

 |
 | Action: |

The applied clamp values are adapted to the minimum clamp distance that is defined be the programmed hardware.

A warning is shown in the UI report window.

Note: In most cases, the flag will be set only if the violation of the minimum clamp distance is caused by DC events in a pattern.

 |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getClampDistanceTooLow()](<../02.07_Test_Method_Reference/02.07.04.01.43.06.04_DPS_AUX_TASK.getClampDistanceTooLow.md>) |
 | High voltage or current of surge tracker exceeded  | Trigger: |

The [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) has detected a voltage or current above the user defined upper limit.

Since the XPS256 surge tracker can simultaneously monitor the voltage and the current, this flag is always set in combination with one or both of the flags [High voltage of surge tracker reached](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_HV_surge_tracker>) or [High current of surge tracker reached](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_HC_surge_tracker>).

 |
 | Action:  | The hardware settings are not changed. The flag represents the test result of the surge tracker. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getSurgeTrackerStatus()](<../02.07_Test_Method_Reference/02.07.04.01.43.05_DPS_AUX_TASK.getSurgeTrackerStatus.md>) |
 | High voltage of surge tracker reached  | Trigger: |

The [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) has detected a voltage above the user defined upper limit.

This flag is always set in combination with flag [High voltage or current of surge tracker exceeded](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_High_surge_tracker>).

 |
 | Action:  | The hardware settings are not changed. The flag represents the test result of the surge tracker. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getSurgeTrackerStatus()](<../02.07_Test_Method_Reference/02.07.04.01.43.05_DPS_AUX_TASK.getSurgeTrackerStatus.md>) |
 | High current of surge tracker reached  | Trigger: |

The [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) has detected a current above the user defined upper limit.

This flag is always set in combination with flag [High voltage or current of surge tracker exceeded](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_High_surge_tracker>).

 |
 | Action:  | The hardware settings are not changed. The flag represents the test result of the surge tracker. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getSurgeTrackerStatus()](<../02.07_Test_Method_Reference/02.07.04.01.43.05_DPS_AUX_TASK.getSurgeTrackerStatus.md>) |
 | Low voltage or current of surge tracker exceeded  | Trigger: |

The [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) has detected a voltage or current below the user defined lower limit.

Since the XPS256 surge tracker can simultaneously monitor the voltage and the current, this flag is always set in combination with one of both of the flags [Low voltage of surge tracker reached](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_LV_surge_tracker>) or [Low current of surge tracker reached](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_LC_surge_tracker>).

 |
 | Action:  | The hardware settings are not changed. The flag represents the test result of the surge tracker. |

 | Low voltage of surge tracker reached  | Trigger: |

The [XPS256 surge tracker](<02.05.05.03.03.07_XPS256_surge_tracker.md>) has detected a voltage below the user defined lower limit.

This flag is always set in combination with flag [Low voltage or current of surge tracker exceeded](<02.05.05.03.10.02_XPS256_status_flags.md#_354167__r_Low_surge_tracker>).

## Safety and self-protection

The safety of the user, the DUT and DUT board, and the self-protection of the card require that actions are performed automatically by the control logic of the card or channels. These actions cannot be blocked or disabled. Some flags indicate these unusual operating conditions. For more information refer to [DPS power flags - get...() functions](<../02.07_Test_Method_Reference/02.07.04.01.43.06_DPS_power_flags_-_get...___functions.md>).

 | Flag  | Description |
 | Current limit disconnect  | Trigger: |

The user defined time for constant current mode was reached.

For the DPS operating mode, [DPSPINS resources](<../02.08_Setup_and_Result_Tools/02.08.04.14.02.03.07.01_DPSPINS_resources.md>) parameter [ms_const_curr_time_to_alarm](<../02.08_Setup_and_Result_Tools/02.08.04.14.02.03.07.01_DPSPINS_resources.md#_16887__ms_const_curr_time_to_alarm>) defines the delay time for a pin that is in constant current mode without interruption before this flag is triggered. Parameter [ms_const_curr_disconnect](<../02.08_Setup_and_Result_Tools/02.08.04.14.02.03.07.01_DPSPINS_resources.md#_16887__ms_const_curr_disconnect>) defines the delay time until the channel is disconnected. The parameter ms_const_curr_disconnect must be defined in the level setup to enable the disconnection in case the current limit is exceeded. Parameter [disable_const_curr_check](<../02.08_Setup_and_Result_Tools/02.08.04.14.02.03.07.01_DPSPINS_resources.md#_16887__disable_const_curr_check>) can be used to disable this status flag.

For the PMU operating mode, see [SPMU_PIN_TASK.currentClampTimeToAlarm()](<../02.07_Test_Method_Reference/02.07.04.01.234.01.05_SPMU_PIN_TASK.currentClampTimeToAlarm.md>) and [SPMU_PIN_TASK.currentClampTimeToDisconnect()](<../02.07_Test_Method_Reference/02.07.04.01.234.01.06_SPMU_PIN_TASK.currentClampTimeToDisconnect.md>).

 |
 | Action:  | The related channel or the entire ganging group is disconnected. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getConstantCurrentLimitDisconnect()](<../02.07_Test_Method_Reference/02.07.04.01.43.06.06_DPS_AUX_TASK.getConstantCurrentLimitDisconnect.md>) |
 | DUT board disconnect  | Trigger:  | The channel has received [DUT board disconnect shutdown](<02.05.05.03.03.06_XPS256_safety_line_and_DUT_board_disconnect.md#_354940__s_DUT_board_disconnect_shutdown>) signal from an appropriately configured trigger source. |
 | Action:  | All XPS256 channels are disconnected. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getDutBoardDisconnect()](<../02.07_Test_Method_Reference/02.07.04.01.43.06.09_DPS_AUX_TASK.getDutBoardDisconnect.md>) |
 | Note:  | See also [XPS256 programming - Safety line and DUT board disconnect](<02.05.05.03.10.18_XPS256_programming_-_Safety_line_and_DUT_board_disconnect.md>). |
 | Overpower / Overcurrent / Power budget exceeded  | Trigger: |

An overpower or overcurrent condition has been detected.

The flag is triggered when the overcurrent condition has been detected for longer than 50 ms without interruption.

 |
 | Action:  | The related channel is disconnected. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getOvercurrent()](<../02.07_Test_Method_Reference/02.07.04.01.43.06.11_DPS_AUX_TASK.getOvercurrent.md>) |
 | Overtemperature  | Trigger:  | The temperature of the channel hardware is too high. |
 | Action:  | The related channel is disconnected. |
 | Availability:  | The flag is available per channel. |
 | API:  | [DPS_AUX_TASK.getOvertemperature()](<../02.07_Test_Method_Reference/02.07.04.01.43.06.12_DPS_AUX_TASK.getOvertemperature.md>) |

## Enabling a channel after it has been disconnected

The procedure described below should be followed for channels that have been disconnected by the channel controller for reasons of safety or for the self-protection of the card:

- Ensure that the reason for the disconnection has been eliminated.
- The following actions are required in case a channel has been disconnected in the testflow:

  - Check the state of the flags using the APIs described in [DPS power flags - get...() functions](<../02.07_Test_Method_Reference/02.07.04.01.43.06_DPS_power_flags_-_get...___functions.md>).
  - Disconnect the channel by SmarTest. The related error message will be shown in the report window and the status flags will be cleared.
  - Connect the channel.

- The following actions are required in case a channel has been disconnected when working with the hardware view:

  - For a channel in the PMU operating mode: Start a dummy measurement in the ADC sub-panel with the relay action set to NT.
  - For a channel in the DPS operating mode: Click onto the Disconnect button in the toolbar of the Eclipse Work Center.
  - Disconnecting the channel will cause that the related error message is shown in the report window and will clear the status flags.
  - Connect the channel.

## DC event status

The command [TSST? - (TeSt STatus)](<../02.06_Command_Reference/02.06.02.02.280_TSST__-__TeSt_STatus.md>) returns global information about the [DC event](<../02.07_Test_Method_Reference/02.07.04.01.63_EVENT_...__DC_events_API_reference.md#_345840__s_Event_classes_and_data_types>) related results of the last executed test, and also provides the accumulated status information about all recorded measurements. A test point pattern must have been executed for DC Scale pins. The accumulated information is cleared at the begin of a functional test. The accumulated flags remain then valid until the begin of the next functional test.

TSST? returns a twofold reply. One informs about the test results, the other about the test status:

- Test result flags:

The functionality of some test result related flags can be enabled or disabled for specific measurement events using member functions of the [DC events](<../02.07_Test_Method_Reference/02.07.04.01.63_EVENT_...__DC_events_API_reference.md#_345840__s_Event_classes_and_data_types>). Functions to enable or disabled the flags are for example

  - ...clampChecks()
  - ...outOfRangeCheck()

The flags are cleared with the start of the next functional test.

- Test status flags:

The test status related flags cannot be enabled or disabled. These flags are accumulated for the complete functional test. The flags are cleared with the start of the next functional test.

 |

 |
