# Memory pooling and memory sharing

The management of scan vector memory in combination with wide and narrow scan methodologies gets more and more complex. This combine with the trend towards multisite is adding to the challenge. In summary these are the trends

- More vector memory on selected pins
- Deeper vector memory on selected pins
- More system vector memory distributed on multisite setups

Enabling vector memory is expensive however. How can we provide very deep memory to our customers without the need to give up on our powerful per-pin value proposition?

benefits:

Flexible DFT method selection

 Today's device designs require flexible selection of the appropriate DFT methodology. Devices might be pin count or area limited. The different scan architectures to address these different devices need flexibility in the memory size assignment. The pooling and sharing configuration does support both scan approaches.

Maximizing the ROI

 The flexible distribution of memory across pins can help to better balance memory license usage, customized to the needs of the device. Especially the sharing approach allows to use memory from one pin to support multiple sites in a very flexible and easy-to-use fashion.

## Memory pooling

Just remove the comment and exchange text from ON to OFF and Memory Sharing is available for the whole test system. Memory Sharing on a part of the test system and Memory Pooling on the other part of the test system is not supported.

On the test processor we have eight cores integrated. The design of the processor does have a dedicated memory interface, being able to distribute memory data to the different cores in a flexible way. One test processor has one memory on board, and depending on the chosen memory usage, the addressing is done differently. The distribution to these 8 channels is done 'virtually' by using Pointers.

The pooling feature does help for deep memory requirements as multiple memory sections are assigned to one core and front end. For Patterns, the whole physically addressable size of this test processor's memory is used, and for all channels, the used pointers are pointing to the same memory address.

## Memory sharing

The opposite concept is the sharing of memory across pins. This is typically done for multisite setups, where the same deep scan data is shared across sites in order to save memory consumption. For Patterns, the whole physically addressable size of this test processor's memory is used, and for all channels, the used pointers are pointing to the same memory address. Sequencer Instructions and Result Memory are stored per channel - no sharing available.
