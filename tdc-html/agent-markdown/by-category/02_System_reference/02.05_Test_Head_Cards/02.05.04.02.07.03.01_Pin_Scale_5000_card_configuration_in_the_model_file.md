# Pin Scale 5000 card configuration in the model file

Although SmarTest 7.10 and higher supports both the [legacy model file](<../02.04_Model_File_and_Licensing/02.04.01.03.02_Model_file_reference__model_legacy.md>) and the [tester.model file](<../02.04_Model_File_and_Licensing/02.04.01.03.01_Model_file_reference__tester.model.md>), the V93000 EXA Scale based PS5000 can be defined only in the tester.model file.

The combination of [PS1600 card](<02.05.04.01_Pin_Scale_1600_digital_card__Smart_Scale.md>) and [PS5000 card](<02.05.04.02_Pin_Scale_5000_card.md>) in one tester.model is not supported. SmarTest will issue an error warning in this case and will ignore all PS5000 cards.

The PS5000 card and pogo blocks must be defined in the [CARD_CONFIGURATION](<../02.04_Model_File_and_Licensing/02.04.01.03.01.02_CARD_CONFIGURATION_section.md>) section of the [tester.model](<../02.04_Model_File_and_Licensing/02.04.01.03.01_Model_file_reference__tester.model.md>) file.

   Standard-density pogo blocks

Type SD is used for the [PS5000 pogo cable assembly EK601-61602: 16 SD pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.03.05.01_PS5000_pogo_cable_assembly_EK601-61602__16_SD_pogo_blocks.md>).

The default pogo block sequence and the sequence for type SD is defined as follows:

`A B C D E F G H I J K L M N O P`

The pin number consists of three digits according to the pattern [1-4][01-32].

The following examples show the allocation of sixteen standard-density pogo blocks:

```
CARD_CONFIGURATION

    slot 101, HW = PS5000, pogoblocks = 101-116
```

or

```
CARD_CONFIGURATION

    slot 101, HW = PS5000, pogoblocks = 101 102 103 104 105 106 107 108,
                                        109 110 111 112 113 114 115 116, type = SD
```

The sixteen pogo blocks A ... P are mapped to pogo block positions "101" …nbsp;"116". The code `type = SD` is optional for the standard-density pogo block.

  High-density (HD) pogo blocks

Type HD8x32 is used for the [PS5000 pogo cable assembly EK601-61603: 8 HD pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.03.05.02_PS5000_pogo_cable_assembly_EK601-61603__8_HD_pogo_blocks.md>).

For channels A1 …nbsp;A16, the same mapping is used as for the standard-density pogo block. The additional channels B1 …nbsp;B16 are mapped to virtual pogo blocks. The number of a virtual pogo block is defined by the position of the physical pogo block plus an offset of 400.

The pogo block sequence for type HD8x32 is defined as follows:

`A A+400 B B+400 C C+400 D D+400 E E+400 F F+400 G G+400 H H+400`

 |   | with |

A = Physical pogoblock "AB"

B = Physical pogoblock "CD"

C = Physical pogoblock "EF"

D = Physical pogoblock "GH"

 |

E = Physical pogoblock "IJ"

F = Physical pogoblock "KL"

G = Physical pogoblock "MN"

H = Physical pogoblock "OP"

 |

The following example shows the allocation of eight high-density pogo blocks:

```
CARD_CONFIGURATION

    slot 101, HW = PS5000, pogoblocks = 101 501 102 502 103 503 104 504
                                        105 505 106 506 107 507 108 508, type = HD8x32
```

Channels A1 …nbsp;A16 on block A …nbsp;H are assigned to physical pogo block positions "101" …nbsp;"108" while additional channels B1 鈥?nbsp;B16 of the same physical blocks are assigned to virtual pogo blocks "501" 鈥?nbsp;"508".

Note that although you use only eight physical high-density pogo blocks for the 256 pins, you need to define eight more virtual pogo blocks to cover the additional channels B1 鈥?nbsp;B16.

  Very-high-density (VHD) pogo blocks

Type VHD4x64 is used for the [PS5000 pogo cable assembly EK601-61604: 4 VHD pogo blocks](<../02.03_DUT_board_design_reference/02.03.06.03.05.03_PS5000_pogo_cable_assembly_EK601-61604__4_VHD_pogo_blocks.md>).

Each physical pogo block covers four logical boards and needs three additional virtual pogo blocks defined with an offset of 400, 32 and 432.

The pogo block sequence for type VHD4x64 is defined as follows:

`A A+400 A+32 A+432 B B+400 B+32 B+432 C C+400 C+32 C+432 D D+400 D+32 D+432`

 |   | with |

A = Physical pogoblock "ABCD"

B = Physical pogoblock "EFGH"

 |

C = Physical pogoblock "IJKL"

D = Physical pogoblock "MNOP"

 |

Example:

```
CARD_CONFIGURATION

    slot 101, HW = PS5000, pogoblocks = 101 501 133 533 102 502 134 534
                                        103 503 135 535 104 504 136 536, type = VHD4x64
```

Note that although you use only four physical very-high-density pogo blocks for the 256 pins, you need to define twelve more virtual pogo blocks to cover the additional channels B1 鈥?nbsp;B16, C1 鈥?nbsp;C16, and D1 鈥?nbsp;D16.
