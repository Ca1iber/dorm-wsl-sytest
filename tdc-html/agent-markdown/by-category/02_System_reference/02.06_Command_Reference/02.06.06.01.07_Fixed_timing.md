# Fixed timing

#### Subtopics

- [Data organization of fixed timing](<02.06.06.01.07.01_Data_organization_of_fixed_timing.md>)
- [Defining waveform shapes](<02.06.06.01.07.02_Defining_waveform_shapes.md>)
- [Defining the period](<02.06.06.01.07.03_Defining_the_period.md>)
- [Defining the Edge Delays](<02.06.06.01.07.04_Defining_the_Edge_Delays.md>)

The standard timing of SmarTest is equation based. Such a timing consists of three data collections, equation sets, wavetables and specifications. Every collection can contain several items of the respective type and is downloaded to the tester as one string argument of the EQSP or EQFS commands. There exists another type of timing, called fixed timing, where each single setup element, such as a waveform or the edge positions for one pin and timing set, is defined separately by calling a firmware command. In fixed timing, periods and edge delays must be specified as constants. Also, the organization of the data differs from that of equation based timing (for which see [Data organization of equation based timing](<02.06.06.01.02_Data_organization_of_equation_based_timing.md>)).
