# How to use Fast Sync

Fast Sync enables the local synchronization of the test processor.

## Before you begin

Make sure you are using SmarTest 7.4.0 or later versions.

Make sure the device pins, which belong to a mach loop, are located on the same test processor. For best throughput, minimize the number of independent match loops on a test processor.

## Procedure

-  According to the steps described in [Multiport operation](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.04.14_Multiport_operation.md>), define a port or ports for the Fast Sync pins and ports for other pins.
-  Define levels as usual.
-  Set up the a [multiport timing](<../02.08_Setup_and_Result_Tools/02.08.04.34.04.02_Multiport_timing_setup.md>).
-  Create a [multiport timing specification](<../02.08_Setup_and_Result_Tools/02.08.04.30.02.16_How_to_set_up_a_multiport_timing_specification.md>).
-  Define a clock group for the fast sync port as shown in [Example 1: Multiport timing](<02.06.07.01.08.04.03.03.01_How_to_use_Fast_Sync.md#_150838__ex_Multiport_timing>).
-  Refer to [Creating a multiport burst](<../02.08_Setup_and_Result_Tools/02.08.04.16.01.04_Creating_a_multiport_burst.md>) to set up the pattern.
-  In the Flow Data Editor, on the Flags tab, set the [site_match_mode](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_site_match_mode>) testflow flag to off.
-  On the Test Suites tab, choose each test suite, and in the opened Properties view, under the Site Control section, set the [Site Match](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_site_match>) flag to OFF.
-  Define the max number of match ports on a test processor using the commands [SQST, SQST? - (SeQuencer STate)](<02.06.02.02.241_SQST__SQST__-__SeQuencer_STate.md>) and [NIFE, NIFE? - (Number of Independent Fast Error)](<02.06.02.02.167_NIFE__NIFE__-__Number_of_Independent_Fast_Error.md>) in [disconnected](<../02.07_Test_Method_Reference/02.07.04.01.41_DISCONNECT.md>) mode. For a test method example, refer to [Example 2: Define the max number of match ports on a test processor](<02.06.07.01.08.04.03.03.01_How_to_use_Fast_Sync.md#_150838__ex_Define_match_ports_on_TP>) below.
-  In the test method, use the [STME FAST](<02.06.02.02.250_STME__STME__-__SiTe_Match_Enable.md>) firmware command to enable the Fast Sync feature.

## Results

The overhead for site scaling synchronization is significantly reduced.

### Example 2: Define the max number of match ports on a test processor

```
class SetNife: public testmethod::TestMethod
{
public:
    Boolean firstRun;

protected:
    int mErrorProb;

    virtual void initialize()
    {
        addParameter("errorProb", "int", &mErrorProb, testmethod::TM_PARAMETER_INPUT)
                   .setDefault("0");

        firstRun = true;
    }

    virtual void run()
    {
        if (firstRun)
        {
            ON_FIRST_INVOCATION_BEGIN();

                DISCONNECT();

                if ( mErrorProb < 1 || mErrorProb > 8 )
                {
                    cout << "NIFE not set!!!" << endl;
                }
                else
                {
                    char buf[1000];

                    sprintf (buf, "SQST OFF\nNIFE %i\n", mErrorProb);

                    FW_TASK(buf);
                }

            ON_FIRST_INVOCATION_END();

            firstRun = false;
        }

        return;

    } // virtual void run()
...
...
};
REGISTER_TESTMETHOD(...);
```

### Example 3: Use the Fast Sync feature for blocking functional test

```
class BlockingFuncTest: public testmethod::TestMethod
{
protected:

    int mFast;

    virtual void initialize()
    {
        addParameter("fast", "int", &mFast, testmethod::TM_PARAMETER_INPUT)
                   .setDefault("1");
    }

    virtual void run()
    {
        static STRING tsName;
        static STRING lblName;

        ON_FIRST_INVOCATION_BEGIN();

            GET_TESTSUITE_NAME(tsName);

            lblName = Primary.getLabel();

            CONNECT();

            mFast?FW_TASK("STME FAST,\n"):FW_TASK("STME ON,\n");

            FUNCTIONAL_TEST();

            FW_TASK("STME OFF,\n");

        ON_FIRST_INVOCATION_END();

        Boolean res = GET_FUNCTIONAL_RESULT();

        TEST(tsName, lblName, res?TM::Pass:TM::Fail,true);

        return;

    } // virtual void run()
...
...
};
REGISTER_TESTMETHOD(...);
```

### Example 5: Use the Fast Sync feature for Independent Sequencer Run on the Smart Scale cards

```
class IndependentSequencerRuns: public testmethod::TestMethod
{
protected:

    int mFast;

    virtual void initialize()
    {
            addParameter("fast", "int", &mFast, testmethod::TM_PARAMETER_INPUT)
                        .setDefault("1");
    }

    virtual void run()
    {
        static STRING tsName;
        static STRING lblName;

        ON_FIRST_INVOCATION_BEGIN();

            GET_TESTSUITE_NAME(tsName);

            lblName = Primary.getLabel();

            CONNECT();

            SEQUENCER_CONTEXT_ITEM s1("matchCt");
            SEQUENCER_CONTEXT_ITEM s2("otherCt");

            s1.setPorts("match");
            s2.setPorts("other");

            SEQUENCER_CONTEXT seqCon;

            seqCon.add(s1).add(s2).apply();

            mFast?FW_TASK("STME FAST,\n"):FW_TASK("STME ON,\n");

            START_TEST("matchCt");
            FUNCTIONAL_TEST("otherCt");
            WAIT_TEST_DONE(TM::WAIT_DIGITAL,"matchCt");

            FW_TASK("STME OFF,\n");

        ON_FIRST_INVOCATION_END();

        Boolean res = GET_FUNCTIONAL_RESULT("match");

        TEST(tsName, lblName, res?TM::Pass:TM::Fail,true);

        return;

    } // virtual void run()
...
...
};
REGISTER_TESTMETHOD(...);
```
