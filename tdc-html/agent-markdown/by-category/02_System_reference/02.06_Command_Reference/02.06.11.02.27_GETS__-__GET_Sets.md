# GETS? - (GET Sets)

The GETS? query maps test cycles to set data. It returns the timing and level sets for the given cycle range. The range can be positive or negative, depending on whether you enter a positive or negative start_cycle (see the syntax), regardless of the sequencer analysis mode (Start Analysis or Stop Analysis). GETS? queries a cycle range that the system requires, or that you enter.

If the query [VRCS? - (Valid ReConStruction)](<02.06.02.02.328_VRCS__-__Valid_ReConStruction.md>) reports a cycle range as being reconstructable, then the range can be queried with GETS?. If you query a cycle range that is not reconstructible, GETS? returns no answer.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
GETS? {start_cycle}, {no_of_cycles}, {(pinlist)}
```

returns:

```
GETS {start_cycle}, {no_of_cycles}, {timing_set}, {level_set}, {(pinlist)}
```

Parameters
 |

start_cycle

 |

The start cycle is an integer that defines the first cycle to be reported. The start cycle is in the range 0 to 248 when the sequencer runs in the Start Analysis mode, or -248 to -1 when the sequencer runs in the Stop Analysis mode. If a positive number is entered, cycles are counted from 0 upwards. If a negative value is entered, the cycles are counted from the end of the test at -1. The start cycle returned by the system may be different from the start cycle entered for the query.

 |
 |

no_of_cycles

 |

In the command, this parameter defines the number of cycles to be reported. The integer must be in the range 0 to 2147483648.

In the reply, the parameter specifies the number of cycles that are generated with the timing and levels sets specified by the timing_set and level_set parameters. 0 is returned if a CLEV and a CTIM instruction follow each other immediately.

 |
 |

pinlist

 |

Information is only returned for the pins specified in pinlist. If more than one pin is to be included, the names must be separated with a comma. You can type the character @ to return the sequencer instructions for all pins.

 |
 |

timing_set

 |

This parameter is an integer that represents the timing set used in the given cycle range.

 |
 |

level_set

 |

This parameter is an integer that represents the level set used in the given cycle range.

 |
 |

level_set_id

 |

Derived as follows:

`100000 *`equation_set_no `+ 1000 * `specset_no `+ `level_set_no

 |

## Application

Test results, see [Test Result Commands](<02.06.11_Test_Result_Commands.md>).

## Errors

An error is generated if:

- You enter an invalid cycle range.
- You send the query while the sequencer is running. There is then no result data available.

## Example

```
GETS? 0,2000,(Q0)
```

This example requests the timing and level set information for the first 2000 test cycles of pin `Q0`. The response may be as follows:

```
GETS 0,160,2,1,(Q0)
GETS 160,704,1,1,(Q0)
GETS 864,1136,2,1,(Q0)
```

The first 160 cycles were generated with timing set 2 and level set 1, the next 704 cycles with timing set 1 and level set 1, and the last 1136 cycles with timing set 2 and level set 1 again.
