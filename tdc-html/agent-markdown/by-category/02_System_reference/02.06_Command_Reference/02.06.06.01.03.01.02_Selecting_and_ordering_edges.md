# Selecting and ordering edges

#### Subtopics

- [Restrictions for drive edges](<02.06.06.01.03.01.02.01_Restrictions_for_drive_edges.md>)
- [Restrictions for receive edges](<02.06.06.01.03.01.02.02_Restrictions_for_receive_edges.md>)

Every action in a waveform shape definition must be associated with an edge, which is a point in time within a tester cycle. SmarTest knows two types of edges, drive edges, which can only be associated with a drive action, and receive edges, which can only be associated with a compare action.

On the Pin Scale 800/3600 boards, drive edges are denoted by dn, where 1 鈮?n 鈮?8. Receive edges are denoted by rn, where 1 鈮?n 鈮?8 for Pin Scale boards. Thus, there are 8 drive and 8 receive edges for a Pin Scale board.

On the Smart Scale boards, there are two kinds of drive edges, which are denoted by fn and sn, respectively. There are 8 edges for each of the two types. For details see [Defining waveforms for Smart Scale pins](<02.06.06.01.03.02_Defining_waveform_shapes_for_Smart_Scale_pins.md>).

Note that edge delays are defined on the pin level, not for individual waveforms. Thus, if you want to use the first two drive waveforms shown in [Waveform Shapes and Edge Delays](<02.06.06.01.01_Waveform_Shapes_and_Edge_Delays.md>) with the same timing set, you would have to define two shapes and use different edges, for instance d4 and d5, for the last two actions of the second definition. The resulting definitions could look as follows:

(PDW1) "d1:0 d2:1 d3:0"

(PDW2) "d1:0 d4:1 d5:0"

The required delays for d4 and d5 would have to be added to the timing set in question. This timing set could then look as follows:

(DE) d1=0

 d2=20

 d3=40

 d4=15

 d5=25

In addition, there are specific restrictions for drive edges and for receive edges, see [Restrictions for drive edges](<02.06.06.01.03.01.02.01_Restrictions_for_drive_edges.md>) and [Restrictions for receive edges](<02.06.06.01.03.01.02.02_Restrictions_for_receive_edges.md>).
