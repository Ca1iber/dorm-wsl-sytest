# SQGB, SQGB? - (SeQuencer GloBal)

The command serves two purposes simultaneously. On the one hand, it controls the termination of the sequencers. By default, the complete test is executed once, but the test can also be repeated in an endless loop or stopped before it is completed.

On the other hand, SQGB also configures the Error map by setting the recording mode and the cycle area to be recorded. There are two recording modes, the acquire failure mode, which only records failed cycles (with their surroundings), and the cycle oriented mode, which records all cycles within the selected area.

The SQGB? query returns the current settings.

SQGB should only be used to control the sequencers; the settings for the Error Map should be defined with the [DCGM](<02.06.02.02.44_DCGM__DCGM__-__Digital_Compare_Global_Mode.md>) and [DCRP](<02.06.02.02.47_DCRP__DCRP__-__Digital_Compare_Result_Positioning.md>) commands. These commands provide more flexibility. Note however that all SQGB modes that modify the behavior of the sequencers (EL, SE, SEEL, STSQ, STSV) require that the second and third parameter of [DCGM](<02.06.02.02.44_DCGM__DCGM__-__Digital_Compare_Global_Mode.md>) are set to NONE. This is enforced when SQGB is issued with one of these modes. But if you subsequently change one of these [DCGM](<02.06.02.02.44_DCGM__DCGM__-__Digital_Compare_Global_Mode.md>) parameters to another value, no functional test will be possible, and [FTST?](<02.06.02.02.127_FTST__-__Functional_TeST.md>) will issue an error message.

## SQGB

```
SQGB [mode], [analyze_delay][, (ref_port)]
```

## SQGB?

```
SQGB? [(portlist)]
```

returns:

```
SQGB {mode}, [analyze_delay][, (port)]
```

## Parameters

 |

mode

 |

Possible values are:

 |
 |

ACQF

 |

ACQuire Failure mode. Only failed cycles are recorded, starting after analyze_delay cycles. If analyze_delay is not a multiple of 8, recording starts after the nearest smaller multiple of 8. In this mode the Error Map is called the Acquire Failure Map.

As the test proceeds the Acquire Failure Map is filled with failure data until the test stops or the map becomes completely full, whichever occurs first. If the map stops recording before the test has finished, the sequencer, which is in standard mode, continues executing the test until the end.

This mode is only supported for compatibility reasons. Instead, you should use DCGM and DCRP to configure the Error Map. The effect of ACQF is reproduced by:

DCGM FAIL,STRT,NONE

DCRP EMAP,<error_map_pos>,<ref_port>

 |
 |

ACFF

 |

This mode is functionally identical to ACQF. It is obsolete and should not be used in new applications.

 |
 |

EL

 |

EndLess. The sequencer repeats the complete test, including primaries and multiport synchronization, in an endless loop and can only be stopped by Break.

The analyze_delay parameter is ignored. The Error Map is set to cycle oriented mode.

This mode is used for oscilloscope tests. The Error Map functions as a rolling buffer. After stopping the sequencer, the Error Map shows the last "buffer-full" of recorded cycles.

 |
 |

ELPT

 |

EndLess PaTtern. The sequencer repeats only the user program. This avoids critical holds during measurement.

In case of multiport testing, ports may run with different frequencies. Using the ELPT mode in this case, can lead to the situation, that for loop counts >1 the synchronization is no longer executed.

 |
 |

EMPS

 |

Error Map PoSitioning. The Error Map is in cycle oriented mode, the sequencer in default mode. The analyze_delay parameter specifies the end of the recorded area. If it is not a multiple of 8, the last cycle to be displayed is the largest multiple of 8 that is smaller than analyze_delay. The first cycle to be displayed is determined by the size of the Error Map (8k cycles).

This mode is only supported for compatibility reasons. Instead, you should use DCGM and DCRP to configure the Error Map. The effect of EMPS is reproduced by:

DCGM ALL,HALT,NONE

DCRP EMAP,<error_map_pos>,<ref_port>

 |
 |

SE

 |

Stop on Error. The sequencer runs from the beginning of the test and stops when an error is encountered. If no errors occur, the sequencer runs to the end of the test and stops. The Error Map is set to cycle oriented recording mode, but this can be changed with DCGM. The analyze_delay parameter is ignored.

 |
 |

SEEL

 |

Stop on Error and EndLess. The sequencer repeats the test in an endless loop, unless an error is encountered, whereupon it stops. The Error Map is set to cycle oriented recording mode. This mode is used to locate sporadic failures.

 |
 |

STSQ

 |

STop SeQuencer. Stops the sequencer after analyze_delay cycles. The Error Map is set to cycle oriented recording mode, but this can be changed with DCGM. See also the query [GETC? - (GET Cycles)](<02.06.02.02.131_GETC__-__GET_Cycles.md>) for the analyze_delay count.

 |
 |

STRD

 |

In the query reply, this mode is displayed if the current combination of recording mode, as set with DCGM, and interpretation of the Error Map position, as set with DCRP, is different from all the other SQGB modes. For example, the Error Map can be in cycle oriented recording mode, and analyze_delay be interpreted as a start value.

In the command, this option leaves it to SmarTest to select the appropriate recording mode (cycle oriented or acquire failure), unless the recording mode has been explicitly set with DCGM.

 |
 |

STSV

 |

STop Sequencer on Vector. Stops the sequencer at the logical vector number specified in the analyze_delay parameter before executing the vector. The Error Map is set to cycle oriented recording mode, but this can be changed with DCGM.

Note that the STSV option cannot be used if no start label has been defined with SQSL, or if the start label is a burst or multi-port burst label.

 |
 |

analyze_delay

 |

Sets the analyze delay. This parameter is mandatory for the STSQ and STSV modes. Its interpretation depends on the selected mode parameter. The number must be between 1 (0 for ACQF) and 281,474,976,710,655 = 2^48 - 1 (2^48 - 2 for ACQF).

If the mode parameter is set to STSV, three cases must be distinguished:

- If analyze_delay is an existing logical vector number of the actual start label, the sequencer will be stopped at this logical vector before executing the vector.
- If analyze_delay specifies the total number of logical vectors (= greatest logical vector number of the test + 1) the sequencer stops at the last valid vector.
- If analyze_delay is greater than the total number of logical vectors, an error message is issued.
 |
 |

ref_port

 |

This parameter accepts a single port. It must be specified in the following situation:

- The selected mode requires an analyze delay (but is different from STSV), and
- the start label is a multi-port burst.

It specifies the port which is used for counting the cycles specified with the analyze_delay parameter. When this reference port has completed the specified number of cycles, the sequencers will be stopped, or cycle recording started or stopped, for all ports. Note that the reference port must belong to the current start label (as defined by SQSL).

 |
 |

port_list

 |

If the current mode requires an analyze delay, you can specify a port list in the query. The reply will give the calculated analyze delays for those ports that are not used as the reference port. These delays are derived from the analyze delay of the reference port and the ratio between the period lengths of the reference port and the other port in the primary timing setup. If you specify @@, SQGB will return the settings for all ports of the current start label.

 |

## Application

Runtime command in Pattern Tool, and in the Error Map.

## Errors

An error is generated if the analyze_delay is out of range.

## Example

```
> PCLK? "mu_burst",1,(@@)
< PCLK "mu_burst",1,20,(P1)
< PCLK "mu_burst",1,10,(P2)
> SPRM "mu_burst",1,,
> SQSL "mu_burst"
> SQGB STSQ,30,(P2)
> SQGB? (@@)
< SQGB STSQ,15,(P1)
< SQGB STSQ,30,(P2)
```

This example configures the sequencers to stop when port P2 has completed 30 cycles. Port P1, whose period length is twice the period length of P2, will be stopped after 15 cycles. Note that P1 and P2 must belong to the same sequencing group.
