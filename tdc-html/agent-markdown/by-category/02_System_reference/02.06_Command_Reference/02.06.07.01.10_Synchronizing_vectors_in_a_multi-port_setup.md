# Synchronizing vectors in a multi-port setup

#### Subtopics

- [Synchronization within sequencing groups](<02.06.07.01.10.01_Synchronization_within_sequencing_groups.md>)
- [De-coupling ports by separate sequencing groups](<02.06.07.01.10.02_De-coupling_ports_by_separate_sequencing_groups.md>)
- [Phase synchronization across sequencing groups](<02.06.07.01.10.03_Phase_synchronization_across_sequencing_groups.md>)
- [Defining sequencing groups](<02.06.07.01.10.04_Defining_sequencing_groups.md>)

In a multi-port setup, the patterns of different ports can be run in parallel at different speed (with different period lengths). In this case corrective actions must be taken if the user vectors of these ports are to be (re)started simultaneously or at least coordinated in some way. SmarTest supplies two such correction methods of different strength.

Exact synchronicity is achieved by putting the ports into the same sequencing group. This has the effect that the user vectors of the ports in question start simultaneously after every CTIM instruction (including the internal CTIM at test start).

However, sequencing groups impose certain restrictions on the sequencer programs of the involved ports which may not be acceptable (for possible reasons see [De-coupling ports by separate sequencing groups](<02.06.07.01.10.02_De-coupling_ports_by_separate_sequencing_groups.md>)). Ports that do not belong to the same sequencing group always start their user vectors at different points in time, but they can at least be synchronized partially. This means that the port that starts its user vectors later starts them at least simultaneously with some user vector of the port that was started earlier. This partial synchronization is activated by setting the PHASE flag for these ports in the multi-port timing specification (see [Phase synchronization across sequencing groups](<02.06.07.01.10.03_Phase_synchronization_across_sequencing_groups.md>)).
