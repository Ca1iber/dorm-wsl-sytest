# How to set up and execute a PRBS test

The following describes how to set up, execute, and analyze a PRBS (Pseudo-Random Binary Sequence) test in which both the input and the expected output PRBS are generated by SmarTest, on the firmware level.

## About this task

Note This task describes how to set up and execute a PRBS test by firmware commands. We recommend using the test method APIs for this task. For a test method example, see [PRBS_PINS](<../02.07_Test_Method_Reference/02.07.04.01.166.01_PRBS_PINS.md>).

PRBS tests serve to create test patterns automatically. See [Generating and checking pseudo random bit sequences](<02.06.17.02_Generating_and_checking_pseudo_random_bit_sequences.md>) for more information.

## Procedure

-  Define the pin configuration: Note PRBS tests can only be executed for all pins of a port. Therefore, if you want to execute a PRBS test in parallel with a normal digital test, you must put the digital pins and the PRBS pins into different ports. This holds for both timing and vector ports.
-  Define a PRBS set:

  -  Create a PRBS set with PRDF.
  -  Define the PRBS test parameters for the appropriate pins with PRCF.

The parameters are

    - connection polynomial,
    - seed (for generating an input PRBS).

  -  Make the PRBS set the primary such set with PRPR.

If you do not define a primary PRBS set, a default set will be used.

-  Define the timing setup:

  - In the wavetable, specify PRBS_I and the required x-mode for the PRBS input pins, and PRBS_O with a (possibly different) x-mode for the output pins. SmarTest will then create the required waveforms automatically. For the input pins, you can also define a break waveform. For more information see [Defining the wavetable for a PRBS test](<02.06.06.01.03.02.02_Defining_the_wavetable_for_a_PRBS_test.md>).
  - The edges for a PRBS test must distributed equidistantly within the tester cycle. To achieve this, you only need to define the period divider (and possibly a start delay for the first edge) in the timing sets. The period divider must equal the x-mode that is specified in the wavetable. For more information see [Defining edge delays for a PRBS test](<02.06.06.01.04.02.03.02_Defining_edge_delays_for_a_PRBS_test.md>).

-  Define the vector setup:

Define a label that contains a PRBS instruction. If you want to delay the start of the PRBS test within this pattern, add break vectors with BRKV before PRBS. Note that BRKV and TMUA are the only instructions that this label is allowed to contain besides PRBS. For more information see [Instructions for PRBS and SmartLoop tests](<02.06.07.01.08.06_Instructions_for_PRBS_and_SmartLoop_tests.md>).

-  Make the label the start label with SQSL.
-  Execute the test with FTST?.

## Results

FTST? will return a global P/F result.

## What to do next

The Error map does not work for a PRBS test, but you can query the number of errors with ERCT?.
