# ETIM, ETIM? - (Edge TIMing)

This command is replaced by the command [ETDS](<02.06.02.02.117_ETDS__ETDS__-__Edge_Timing_Definition_String.md>)[, ](<02.06.02.02.117_ETDS__ETDS__-__Edge_Timing_Definition_String.md>)[ETDS?](<02.06.02.02.117_ETDS__ETDS__-__Edge_Timing_Definition_String.md>) from release 2.1 onwards when 14-edge setups are used.

The ETIM(Edge TIMing) command defines the edge timing for the specified waveform set, timing set and pins. The number of defined waveform and timing sets is not modified.

The edge delay parameters are optional. Missing delays are supplied by the system from a data base. Any not previously set delays default to 0.0 ns. No auto-corrections are performed, invalid values are rejected.

Make sure you include a comma for any omitted or unused timing parameter.

The ETIM? query returns delays for all events.

See also the following commands:

- [WFDF, WFDF? - (WaveForm DeFinition)](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>)
- [WAVE, WAVE? - (WAVEform)](<02.06.02.02.333_WAVE__WAVE__-__WAVEform.md>).

All four commands are required to generate DUT test signal timing.

With this command you configure setups of those sites that have the setup focus: For more information, see also: [PSFC, PSFC?](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Restrictions

Actions which use the same resource in one waveform (drive, tri-state or window formatter) must be ordered according to the specifications made in the [WFDF](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>)and [BWDF](<02.06.02.02.13_BWDF__BWDF__-__Break_Waveform_DeFinition.md>)commands.

All receive edges in a waveform used for a window compare must be physically ordered. For instance, the edge closing the window must come after the edge that opens it. See also [Selecting and ordering edges](<02.06.06.01.03.01.02_Selecting_and_ordering_edges.md>).

## Equation Based Testing

In Equation Based Testing, you must identify a wavetable instead of a waveform set. This is achieved by supplying a specset_id, calculated from equation set number and specset number as follows:

```
100 * equation_set_no + specset_no
```

The appropriate wavetable is determined by looking at which wavetable is referenced by equation_set_no and specset_no in the Timing Specification File.

Note The ETIM command sets bit 8 of the status bits to indicate that the equation based values have been overridden. Refer to the [SPST?](<02.06.02.02.229_SPST__-__SPecset_STatus.md>) query for a description of these.

The command will be disabled for pin and waveform sets containing more than 6 edges.

## ETIM

```
ETIM {waveform_set},{timing_set}, [t1], [t2], [t3], [t4], [t5], [t6], {(pinlist)}
```

## ETIM?

```
ETIM? {waveform_set}, {timing_set}, {(pinlist)}
```

returns:

```
ETIM {waveform_set},{timing_set}, [t1], [t2], [t3], [t4], [t5], [t6], {(pinlist)}
```

or:

```
ETIM? {specset_id}, {timing_set_no}, {(pinlist)}
```

returns:

```
ETIM {specset_id}, {timing_set_no}, [t1], [t2], [t3], [t4], [t5], [t6],{(pinlist)}
```

Parameters
 |

waveform_set

 |

Waveform Set Number. Enter PRM for the Primary Waveform Set, or an integer in the range 1 to the maximum number of allowed waveform sets. The maximum number is determined by [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>). For the query command you can also enter ALL for all waveform sets.

 |
 |

specset_id

 |

Derived as follows:

`100 *`equation_set_no `+ `specset_no

 |
 |

timing_set

 |

Timing Set Number. Enter PRM for the Primary Timing Set, ALL for all timing sets, or an integer in the range 1 to the maximum number of allowed timing sets. The maximum number is determined by TSUS.

 |
 |

t1..t6

 |

Edge delay in ns. Note that the positions of some edges may be affected by the use and position of previously defined edges as explained in "Restrictions" in [ETIM, ETIM? - (Edge TIMing)](<02.06.02.02.118_ETIM__ETIM__-__Edge_TIMing.md>).

 |
 |

pinlist

 |

The name of the pin or pins for which edge delays are to be set or read back. This parameter can also include groups previously created by the DFGP (DeFine GrouP) command. The symbol @ can be used to specify all configured pins. If more than one pin is to be included, the names must be separated with a comma.

 |

## Application

Timing setup, see [Timing Setup Commands](<02.06.06_Timing_Setup_Commands.md>).

## Errors

An error is generated if:

- waveform_set is greater than the range allowed by the [WSUS](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>)command.
- timing_set is greater than the range allowed by the [TSUS](<02.06.02.02.283_TSUS__TSUS__-__Timing_Sets_USed.md>)command.
- The selected primary timing set is not defined for the specified waveform set.
- The edge order is wrong; for instance a window open must come before a window close - a mismatch exists between edge delays of the selected timing set and the waveform definition - [WFDF, WFDF? - (WaveForm DeFinition)](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>), or the break waveform definition - [BWDF, BWDF? - (Break Waveform DeFinition)](<02.06.02.02.13_BWDF__BWDF__-__Break_Waveform_DeFinition.md>).
- Edge placement is outside the allowed range.
- All edges of the same direction in the specified timing set do not lie within one period.
- specset_id does not reference a defined wavetable.
- specset_id is invalid because equation_set_no, specset_no, or both are invalid.

## Example

```
ETIM 1,1,2,4,8,6,10,,(DATA)
```

This example sets the edge delays for the pin group DATA specified for waveform set 1 and timing set 1. Edges 1 to 5 are set to 2,4,8,6 and 10 ns respectively, edge 6 is unused. If no previous setting for edge 6 exists in waveform set 1 and timing set 1, then its delay remains at 0.0 ns.
