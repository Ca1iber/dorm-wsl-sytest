# MSCF, MSCF? - (Modulation Set ConFiguration)

This command serves to define and query the parameters of a modulation set. The specified modulation set must have been defined with MSDF. The modulation set must be referenced in a jitter set with the JSCF command. For more information see [Two ways of organizing jitter setup data](<02.06.16.01.01_Two_ways_of_organizing_jitter_setup_data.md>).

## MSCF

```
MSCF {"modulation_set_name"}, {"property"}, {"property_value"}
```

## MSCF?

```
MSCF? {"modulation_set_name"|ALL}, {"property"|ALL}
```

returns:

```
MSCF {"modulation_set_name"}, {"property"}, {"property_value"}
```

## Parameters

 |

modulation_set_name

 |

Specifies the name of a modulation set that must have been defined with MSDF.

 |
 |

property

 |

Specifies a property of the modulation set. For a list see the table below.

 |
 |

ALL

 |

This value can be specified in the query to retrieve the configuration data of all modulation sets.

 |
 |

property_value

 |

Specifies the value for the specified property. The values that are admitted for the individual properties are listed in the table below.

 |

## Properties and their values

 |

Property

 |

Explanation and values

 |
 |

SHAPE

 |

This parameter either

(a) defines a list of offsets (in picoseconds) from the edge delays specified in the currently active timing set, or

(b) selects a predefined waveform.

In case (a), the list items must be separated by a comma, and the maximum number of items is 3072. Note that case (a) is only supported for STDDIFF pins.

The list items of case (a) do not define the actual delays, but only their mutual proportions. The actual values are computed from the list and the required maximum value (AMPLITUDE property) by

list_item * ( max_value / max_item),

where max_item is the greatest item in the specified list. To give a simple example, if the specified list is

 0, 10, 20, 10, 0, -5, -10, -5, 0

and the required maximum value is 30ps, then the actual waveform is calculated by

 list_item * ( 30 / 20)

as

 0, 15, 30, 15, 0, -7.5, -15, -7.5, 0

picoseconds. If no amplitude is specified, the default of 100ps is assumed.

The predefined waveforms (case (b)) are:

 |
 |

 |

SINE

 |

Creates a sinusoidal waveform.

 |
 |

 |

RANDOM

 |

Generates random jitter within delay - amplitude and delay + amplitude,

where delay is the delay that is defined in the currently active timing set for the pins that are associated with the modulation set in the respective jitter set, and amplitude is the value of the AMPLITUDE property.

 |
 |

PHASE

 |

This property is intended to define a phase offset for the RESTART mode (the mode is defined with JSCF). This value must be specified as a degree. The maximum is 360°.

 |
 |

AMPLITUDE

 |

This property determines the amplitude (that is, half of the peak-to-peak value) of a predefined shape.

The maximum is 200 ps. The default is always 100 ps.

 |
 |

PERIOD

 |

This property defines the jitter period in picoseconds.

In general, the maximum period depends on the clock resolution as follows:

2 * clock_resolution * 1024 * 512

The clock resolution is calculated from the period resolution, but also takes other parameters into account. Therefore a different clock resolution may be calculated from the same period resolution in different circumstances.

If you want to have complete control over the clock resolution, you must specify a period resolution not greater than 2 * minimal_clock_resolution manually (with the period_res keyword). Then the clock resolution will equal the period resolution. See also [Period resolution, clock resolution, and master clock period](<02.06.06.01.04.01.02.03_Period_resolution__clock_resolution__and_master_clock_period.md>).

 |

## Application

Jitter injection.

## Errors

An error is generated if no modulation set with the specified name exists.

## Example

```
> MSCF? "mod1",ALL
< MSCF "mod1",SHAPE,SINE
< MSCF "mod1",PERIOD,250
< MSCF "mod1",PHASE,180
< MSCF "mod1",AMPLITUDE,305
```

## Functional changes

- Introduced in SmarTest 7.3.0
- SmarTest 7.3.1: User defined waveforms for FASTDIFF pins can now be defined with MSCF.
