# MVVA - (Modify Vector VAriable)

The MVVA (Modify Vector VAriable) command modifies vector variables within a vector label.

 The vector variables must have been defined with the [DVVA](<02.06.02.02.94_DVVA__DVVA__-__Define_Vector_VAriable.md>) command. In order to retrieve the modified definition, use the [DVVA?](<02.06.02.02.94_DVVA__DVVA__-__Define_Vector_VAriable.md>) query. On the function of vector variables and details of the extraction process which is referenced in the parameter descriptions, see [DVVA, DVVA? - (Define Vector VAriable)](<02.06.02.02.94_DVVA__DVVA__-__Define_Vector_VAriable.md>).Note If the specified variable does not exist, MVVA will create it.

With this command you configure setups of those sites that have the setup focus: For more information, see also: [PSFC, PSFC?](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
MVVA {"name"}, {type}, {"vector_label"}, {xfer_mode}, [device_cycle], [start_vector_nr], [capt_label], [init_discard], [nr_vec_per_frame], [nr_vec_per_sample], [nr_vector_interdisc], [nr_of_frames], [nr_frame_interdisc], {(pinlist)}
```

## Parameters

 | name |

Name of a vector variable.

 |
 | type |

Type of vector variable. Currently, only the type DIGCAPT is supported.

 |
 | vector_label |

Name of a vector label. Only main vector labels are supported.

 |
 | xfer_mode |

Mandatory parameter that determines the transfer mode. The options available are

-

PARA = Parallel. This is the default.

-

SERI = Serial

Note that you cannot select SERI if the vector variable is associated with more than one pin.

 |
 | device_cycle |

Optional parameter, currently not used.

 |
 | start_vector_nr |

Optional parameter, currently not used.

 |
 | capt_label |

This optional parameter describes a label reference to a capture block within a vector label which has been set aside for digital capture. If this parameter is specified, the vector variable is defined with respect to this capture area. If it is not specified, the capture label references the entire pattern.

 |
 | init_discard |

The optional parameter defines the offset relative to the start location of a capture block within the capture memory. The vectors before this offset will not be uploaded.

The default value is 0.

 |
 | nr_vec_per_frame |

The optional parameter defines the number of vectors that make up a frame.

 |
 | nr_vec_per_sample |

The optional number of vectors that are contained in one sample.

The suitable values for this parameter depend on the selected transfer mode ([xfer_mode](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_xfer_mode>) parameter).

- For transfer mode PARA, this parameter must be set to 1 (the default value).
- For SERI, it should be set to the number of code bits (see the code_width parameter of [DIDT?](<02.06.02.02.75_DIDT__DIDT__-__upload_DIgital_DaTa.md>)). The maximum value is 32.
 |
 | nr_vector_interdisc |

The optional parameter defines how many vectors are discarded between two extracted vectors in step 2 of the extraction process. If set to 2, for example, the first and then every third vector will be extracted.

The default value is 0, in which case no vector will be discarded in step 2.

 |
 | nr_frames |

The optional number of frames that are to be extracted, starting from the first frame.

The default value is 1.

 |
 | frame_interdisc |

The optional number of irrelevant vectors between frames. These will be discarded in step 3 of the extraction process.

The default value is 0.

 |
 | pinlist |

The mandatory List of pins for which the vector variable is defined. The pins specified here should be contained in the pin list that was associated with the referenced vector label (vector_label parameter) by the [SDGC](<02.06.02.02.219_SDGC__SDGC__-__Setup_DiGital_Capture.md>) command. Only then will the digital data of these pins be retrieved by [DIDT?](<02.06.02.02.75_DIDT__DIDT__-__upload_DIgital_DaTa.md>), if DIDT? is called with the actual vector variable.

If the list contains more than one element, the element names must be separated with a comma.

If you have set [xfer_mode](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_xfer_mode>) to SERI, specify only one pin.

The LSB of the uploaded vector variable data will be assigned to the last pin of the pin list.

 |

## Application

Digital capture applications.

## Errors

An error occurs if:

- The referenced vector label is not yet defined.
- The vector label does not reside in sequencer memory (SM).
- Variable [start_vector_nr](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_start_vector_nr>) is specified.
- Variable [init_discard](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_init_discard>) is specified for a variable of type DIGSRC.
- The vector variable exceeds the size of the vector label or the referenced capture label.
- The PARA mode has been selected for [xfer_mode](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_xfer_mode>), and [nr_vec_per_sample](<02.06.02.02.166_MVVA_-__Modify_Vector_VAriable.md#_99063__r_nr_vec_per_sample>) is not 1.
- The referenced pin names have not been defined with the [DFPN](<02.06.02.02.63_DFPN__DFPN__-__DeFine_Pin_Name.md>) command.

## Example

```
> DVVA "vec_var",DIGCAPT,"test_capt",PARA,,,,0,1,1,0,1,0,(OUT_1)
> MVVA "vec_var",DIGCAPT,"test_capt",SERI,,,,,,,,,,(OUT_1)
> DVVA? "test_capt"
< DVVA "vecvar",DIGCAPT,"test_capt",SERI,,,,0,1,1,0,1,0,(OUT_1)
```
