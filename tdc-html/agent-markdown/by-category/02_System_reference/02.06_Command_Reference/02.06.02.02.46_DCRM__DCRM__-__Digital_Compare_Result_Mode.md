# DCRM, DCRM? - (Digital Compare Result Mode)

The DCRM command serves to configure the Error Maps. The DCRM? query returns the current settings.

## Mode of operation

The overview Error Map can be configured in two modes: It either compresses a fixed number of cycles into one result bit, or it returns one result bit for every pattern of a (single- or multi-port) burst. In the fixed mode, you can also define the granularity of the compression.

The configuration parameters of the detailed Error Map are

- the maximum number of recorded results per cycle,
- how the receive edges of one cycle are to be combined into recorded results, and
- whether only a Pass/Fail code or more detailed error information is to be returned.

## Syntax

 DCRM

```
DCRM {map},{mode},[bits],["sub_cycles",] {(port_list)}
```

 DCRM?

```
DCRM? [answer_type,] {map},{(port_list)}
```

returns:

```
DCRM {map},{mode},[bits],[sub_cycles,] {(port)}
```

## Parameters

 | map  | Specifies which error map will be configured. Possible values are: |
 | EMAP  | Detailed Error Map |
 | OVEM  | Overview Error Map |
 | mode  | The meaning of this parameter depends on the map parameter.

- map is set to EMAP:

In this case mode specifies the maximum number of results that are recorded per cycle. The possible values are 1, 2, 4, 6, 8; 6 is only supported by Smart Scale cards. 1 is the default.

Note that not all these values are supported on all hardware types. Furthermore certain of these values are only available with one option of the bits parameter. The details can be found in [Possible combinations of CYRM, CYRP, and DCRM](<02.06.11.01.02.01.02.05_Possible_combinations_of_CYRM__CYRP__and_DCRM.md>).

The number of results can be reduced with the sub_cycles parameter, but not for mode values of 6 and 8.

- map is set to OVEM:

In this case the mode parameter controls the compression mode and the compression factor. The following values are allowed:

 | FCM  | A fixed number of cycles is combined into one result. The number can be defined by a second call of DCRM, where the number is specified as the mode parameter. |
 | LMAP  | All cycles of one pattern in a (single-port or multi-port) burst are combined into one result. Note that with this option, 8 …nbsp;15 break cycles are inserted between the patterns of the burst. In the error map, 0 .. 7 additional cycles are recorded.Note If you use the LMAP error map mode, [FLBL](<02.06.02.02.123_FLBL__-__Failing_LaBeLs.md>) ignores the RETC clearing flag for failures. |
 | BFLM  | All cycles of one pattern in a (single-port or multi-port) burst are combined into one result. With this option, which is only available for Smart Scale, no break cycles are inserted between the patterns of the burst. Note In BFLM mode, each pattern in the burst must generate 8 or more cycles. |
 | cycles |

The number of cycles to be compressed in FCM mode. It must be divisible by 16.

Note that this number is not affected by a switch to LMAP. If you switch back to FCM the compression factor will be the same as before the switch to LMAP.

The default is 4096.

 |
 |
 | bits  |  Only valid if map is set to EMAP. Specifies how detailed the recorded error code is to be in case of failure. Possible values are: |
 | PF  | Only a one bit Pass/Fail result will be returned. |
 | PFC  | In case of failure, a more detailed two bit code will be recorded. This is the default. |
 | The meaning of the 2 bit error codes depends on the expected result as follows:

 |   | Received |
 | Expected  | L  | I  | H  | U |
 | L  | 00  | 01  | 10  | 11 |
 | I  | 10  | 00  | 01  | 11 |
 | H  | 01  | 10  | 00  | 11 |
 | U  | 01  | 10  | 11  | 00 |

"I" stands for "Intermediate", and "U" stands for "Unstable". Note that you can reconstruct the received result from the expected result and the error code.

 |
 | Note that only one error code format is supported for some result granularities. See [Possible combinations of CYRM, CYRP, and DCRM](<02.06.11.01.02.01.02.05_Possible_combinations_of_CYRM__CYRP__and_DCRM.md>). |
 | sub_cycles |

This parameter, which is only valid if map is set to EMAP, defines the sub-cycles. The format is

c1: edge_list1 [c2: edge_list2 [c3: edge_list3 [c4: edge_list4]]]

where every edge list is a comma separated list of edge numbers.

The number of sub-cycles must not be larger than the number specified with the mode parameter. A sub-cycle can contain only one edge, numbering gaps are allowed, and the same edge may occur in more than one sub-cycle.

User defined sub-cycle definitions are not supported for all combinations of mode and bits, and some combinations are only supported for certain recording modes and certain hardware types. For details see [Possible combinations of CYRM, CYRP, and DCRM](<02.06.11.01.02.01.02.05_Possible_combinations_of_CYRM__CYRP__and_DCRM.md>).

The default with mode set to 2 is:

```
"c1:1,2,3,4 c2:5,6,7,8"
```

The default with mode set to 4 is:

```
"c1:1,2 c2:3,4 c3:5,6 c4:7,8"
```

 |
 | port_list  | Specifies the ports for which the recording mode is to be defined. If you specify @@, DCRM will set the recording mode, or return the current settings, for all ports. |
 | answer_type  | This query parameter specifies whether the current configuration or the configuration of the last executed test is to be returned. Possible values are: |
 | CONF  | The current configuration is returned. This is the default. |
 | EXEC  | The configuration of the last executed test is returned. |

## Application

Error Map (Overview Error Map and Detailed Error Map).

## Examples

### Example 1

```
DCRM EMAP,4,PF,"c1:1,3 c2:5,7 c3:2,4 c4:6,8",(P1,P2)
```

This example configures the detailed Error Map of port `P1` and `P2` to record 1 bit results for 4 sub-cycles, each of which combines two different edges.

### Example 2

```
DCRM EMAP,1,PFC,(P1,P2)
```

This example configures the Error Map to record one global detailed two bit result combining all edges of a cycle at every test execution.

### Example 3

```
DCRM OVEM,6000,,(@)
```

This example defines that 6000 cycles will be compressed into one Overview Error Map bit when the next test will be executed.
