# Assigning a pin name to a digital channel

Digital channels are assigned a pin name with the DFPN command.The pin name is the name by which the software identifies the channel. Note that you can use the DFPN command only if the sequencer state is OFF (compare the SQST command).

Digital channels are identified by a five digit number. The first three digits specify the pogo block number, and the last two digits specify the pin number in the pogo block. The first digit is 1 to 4 (or 1 to 2 for the P-/Ce-/C-models), the second and third digits is 01 to 32, and the final two digits is 01 to 16. For example, 10105 is the digital channel whose pogo pin number is 05 in the pogo block 101.

The DFPN? query returns the channel numbers of the specified pins.

DFPN can also be used to assign a pin name to a DC Scale channel in PMU mode, see [Assigning a pin name and operation mode to a DC Scale channel](<02.06.03.01.04_Assigning_a_pin_name_to_a_digital_or_DC_scale_channel.md>).

Assignments of pin names to digital channels are revoked with the UDEF command. In a setup based on waveform sets, this has the effect that the pin is only made invisible for the firmware or the Pin Configuration GUI, but that the operating mode and the level, timing and vector setup for the channel remain in memory. This can be used to assign a new pin name to a channel, but keep all its previous setup data, as follows.

- Remove the old name with the UDEF command.
- Assign the new name with the DFPN command.

The pin type will be set to OFF.

- Restore the former pin type with the CONF command (see [Configure pin type and operating mode for a context](<02.06.03.01.03_Configuring_pin_type_and_operating_mode_for_a_context.md>)).

All setup data will be restored.

This kind of renaming is not possible in an equation based setup.

 Note Using the UDEF command affects the following relay settings of the specified channel: AC relays connecting the pin electronics to the DUT pin are opened, and DC relays connecting the DC rail to the DUT pin are opened.You close the relays (and reconnect the DUT) by using RLYC, as described in [Relays and Control Commands](<02.06.08_Relays_and_Control_Commands.md>).
