# DMAS, DMAS? - (Define Memory Area Size)

The DMAS command defines or extends (depending on the setting of the [SAOF](<02.06.02.02.216_SAOF__SAOF__-__Set_Alternating_Operation_Features.md>) command) the logical memory area for the sequencer programs of the individual ports.

The DMAS? query serves two purposes:

- DMAS? can return how much memory is currently used for the different logical memory areas.
- DMAS? can return how much memory is still available for storing vectors (area options MFRE and MFRP) or result data (area option RSLT).

## Mode of operation

Normally, you should not issue this command. In some cases, however, you have to use it, for example, when you want to define a burst label at the firmware level. For more information see the [SQLB](<02.06.02.02.236_SQLB__SQLB__-__SeQuencer_LaBel_definition.md>) command.

During data download, the order of use of firmware commands for the sequencer area is:

- DMAS
- [SQLB](<02.06.02.02.236_SQLB__SQLB__-__SeQuencer_LaBel_definition.md>) (SeQuencer LaBel)
- [SQPG](<02.06.02.02.237_SQPG__SQPG__-__SeQuencer_ProGramming.md>) (SeQuencer ProGramming)

## DMAS

```
DMAS SQPG, [memory], {size}, {(port)}
```

## DMAS?

Area type PARA:

```
DMAS? PARA, [memory], PER_PORT, {(port_list)}
```

returns:

```
DMAS PARA, {memory}, {size}, {(port)}
```

Area type SQPG:

```
DMAS? SQPG, [SM], [PER_PORT,] {(port_list)}
```

returns:

```
DMAS SQPG, SM, {size}, {(port)}
```

Area type PPSQ:

```
DMAS? PPSQ, [SM], [PER_PORT,] {(@)}
```

returns:

```
DMAS PPSQ, SM, {size}, {(@)}
```

Area type RSLT, querying ports:

```
DMAS? RSLT, [SM], [PER_PORT,] {(port_list)}
```

returns:

```
DMAS RSLT, SM, {size}, {port}
```

Area type RSLT, querying pins:

```
DMAS? RSLT, [SM], {PER_PIN}, {(pin_list)}
```

returns:

```
DMAS RSLT, SM, {size}, {pin}
```

Area type SAVE:

```
DMAS? SAVE, ALL, [PER_PORT,] {(port_list)}
```

returns:

```
DMAS SAVE, {memory}, {size}, {(port)}
```

Area type ALL:

```
DMAS? ALL, [memory], [PER_PORT,] {(port_list)}
```

returns:

```
DMAS {area}, {memory}, {size}, {(port)}
```

Area type MFRE, querying ports:

```
DMAS? MFRE, [SM|SMEXT], [PER_PORT,] {(port_list)}
```

returns:

```
DMAS MFRE, {SM|SMEXT}, {size}, {port}
```

Area type MFRE, querying pins:

```
DMAS? MFRE, [SM|SMEXT], {PER_PIN}, {(pin_list)}
```

returns:

```
DMAS MFRE, {SM|SMEXT}, {size}, {pin}
```

Area type MFRE, querying channels:

```
DMAS? MFRE, [SM|SMEXT], {PER_CHANNEL}, {(channel_list)}
```

returns:

```
DMAS MFRE, {SM|SMEXT}, {size_1}, {size_2}, {size_3}, {(channel)}
```

Area type MFRP, querying channels:

```
DMAS? MFRP, [SM|SMEXT], {PER_CHANNEL}, {(port_list)}
```

returns:

```
DMAS MFRP, {SM|SMEXT}, {size_1}, {size_2}, {size_3}, {(channel)}
```

Area type MFRP, querying pools:

```
DMAS? MFRP, [SM|SMEXT], {PER_POOL}, {(port_list)}
```

returns:

```
DMAS MFRP, {SM|SMEXT}, {pool_size}, {(pool_channels)}
```

## Parameters

 |

area

 |

The area parameter specifies the type of data for which a memory area is to be set or read. It can be one of the following:

 |
 |

 |

PARA

 |

Only the DMAS? PARA (PARAllel vector area) query is supported. It returns the current end of the vector areas for the different memory types. Note that in case of a multiport setup, values are only returned if the PER_PORT option is explicitly set as the third parameter.

 |
 |

 |

PPSQ

 |

Only the DMAS? PPSQ (Per Pin SeQuencer subroutine) query is supported. It returns the space currently used for per pin sequencer subroutines. It can only be applied to the default port @.

 |
 |

 |

RSLT

 |

The DMAS? RSLT(ReSuLT area) query returns how much memory is available for result data (Error Map in the external memory or digital capture data).

 |
 |

 |

SAVE

 |

The DMAS? SAVE query returns the size of the currently used memory for the area types PARA, PPSQ, and SQPG.

Note that in case of a multiport setup, PARA values are only returned if the PER_PORT option is set explicitly as the third parameter.

 |
 |

 |

SQPG

 |

The SQPG (Sequencer ProGramming area) option allocates memory for a number of sequencer instructions. The allocated command lines are filled with NOP instructions.

The DMAS? SQPG query returns the current end of the sequencer areas for the specified ports.

 |
 |

 |

MFRE

 |

The MFRE (Memory Free RangE) option can only be used in the query. It reports the actual maximum number of vectors that can be added to each of the specified ports, pins or channels.

 |
 |

 |

MFRP

 |

The MFRP (Memory Free Range per Pool) option can only be used in the query. It reports the free memory space for the specified ports from the pool (test processor, channel group) perspective.

 |
 |

 |

ALL

 |

The ALL (ALL areas) option can only be used in a query. It returns the size of the currently used memory for the area types PARA, PPSQ, and SQPG, and in addition also the space that is free for result data (area type RSLT).

Note that in case of a multiport setup, PARA values are only returned if the PER_PORT option is set explicitly as the third parameter.

 |
 |

size

 |

In the command, the size parameter defines the number of sequencer instructions for which memory is to be allocated on the specified port (area type SQPG). One sequencer instruction requires the space of 8 vectors. Enter a number of instructions between 0 and MAX_FREE_MEM/ 8 vectors.

In the query replies, this parameter either specifies the used space (for example, with area type PARA) or the available free space (with area types RSLT, MFRE, and MFRP).

 |
 |

size_1

 |

This query reply parameter specifies the amount of free vector memory at the end of a specified channel for the PER_CHANNEL option of MFRE and MFRP.

 |
 |

size_2

 |

This query reply parameter specifies the largest block of free vector memory on a specified channel for the PER_CHANNEL option of MFRE and MFRP.

 |
 |

size_3

 |

This query reply parameter specifies the total amount of free vector memory on a specified channel for the PER_CHANNEL option of MFRE and MFRP.

 |
 |

pool_size

 |

This query reply parameter specifies the total amount of free vector memory on a pool (channel group, test processor) which shares a channel with a specified port for the PER_POOL option of MFRP.

 |
 |

memory

 |

Specifies the type of memory which is acted upon:

 |
 |

 |

SM

 |

Sequencer memory. This is the default.

 |
 |

 |

SHMEM

 |

A special kind of SM for memory sharing in multisite setups. For details see [Selecting the memory type](<02.06.07.01.04.01_Selecting_the_memory_type.md>).

 |
 |

 |

HSER

 |

A special kind of SM for patterns used in SmartLoop testing. For details see [Defining a compliance pattern for pattern‑based SmartLoop testing](<02.06.17.04.01_Defining_a_compliance_pattern_for_pattern__ased_SmartLoop_testing.md>).

 |
 |   | SMEXT  | A special kind of memory for vectors, used only when himem is enabled in the .technology file. See [Technology file for a device - himem](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_himem>) for details. This option can only be used in the query with MFRE or MFRP. |
 |

 |

ALL

 |

All types of memory. This option can only be used in the query.

 |
 |

PER_PORT

 |

This query option requires the answer to be given per port. This is the default.

Note however that this option must be specified for area type PARA; otherwise DMAS? will return no answer. This also applies to the PARA values for area types SAVE and ALL.

 |
 |

PER_PIN

 |

This query option is only supported by area types MFRE and RSLT, Its point is that the amount of free vector space or result space can be different for different pins of the same port.

 |
 |

PER_CHANNEL

 |

This option is only supported by the MFRE and the MFRP area types. With area type MFRE, it causes DMAS? to return three values for each specified channel in the following order:

- size_1: The amount of memory that is available at the end of the vector memory
- size_2: The size of the largest free vector memory block
- size_3: The sum of all free blocks

With area type MFRP, the same three values are returned, but for all channels of any pool that supplies channels to one of the specified ports.

 |
 |

PER_POOL

 |

This option is only supported by the MFRP area type. It causes DMAS? to return the total free space of all pools (channel groups, test processors) that supply channels for the specified ports.

 |
 |

port

 |

The port for which areas are to be defined or for which information is requested. The default port, to which all pins belong, is denoted by the @ character.

 |
 |

port_list

 |

The ports for which information is to be retrieved.

 |
 |

pin, pin_list

 |

The pins for which information is requested or returned.

 |
 |

channel, channel_list

 |

The channels for which information is requested or returned.

 |
 |

pool_channels

 |

The channels of the pool to which the channels of those ports belong that are specified in the query.

 |

## Application

Download and upload command in the test program explorer and the CAE Link.

## Example

The following example illustrates the various options of the MFRE and MFRP queries. First, the free memory range of the `port12` port is queried on the port level:

```
> DMAS? MFRE,,(port12)
< DMAS MFRE,SM,84288,(port12)
```

On the pin level, the corresponding query and reply look as follows:

```
> DMAS? MFRE,,PER_PIN,(port12)
< DMAS MFRE,SM,84288,(Pin1)
< DMAS MFRE,SM,88288,(Pin2)
```

Note that the query per port returns the smaller of the two values.

`Pin1` is mapped to channel 10101, `Pin2` to channel 10102. Thus the corresponding channel related query and its reply are

```
> DMAS? MFRE,,PER_CHANNEL,(10101,10102)
< DMAS MFRE,SM,84212,84312,84640,(10101)
< DMAS MFRE,SM,88312,88312,88640,(10102)
```

The figures are slightly different, because the query per channel only considers the hardware.

Finally, the two possible options for MFRP, applied to `port12`, produce

```
> DMAS? MFRP,,PER_CHANNEL,(port12)
< DMAS MFRP,SM,84212,84312,84640,(10101)
< DMAS MFRP,SM,88312,88312,88640,(10102)
< DMAS MFRP,SM,84212,84312,84640,(10103)
< DMAS MFRP,SM,90464,90464,90736,(10104)
```

 for the PS9G pool 10101 through 10104, and

```
> DMAS? MFRP,,PER_POOL,(port12)
< DMAS MFRP,SM,347400,(10101,10102,10103,10104)
```

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.0.1: The only area for which DMAS is still supported is SQPG.
- SmarTest 7.0.3: The MTST option no longer has any effect
- SmarTest 7.3.2: The MFRE area type now has a third option PER_CHANNEL, and a new area type MFRP was added.
