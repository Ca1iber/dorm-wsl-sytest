# Recording mode for detailed Error Map

The detailed Error Map can be operated in two different recording modes,

- the acquire failure mode, which records only failed cycles (with their surroundings), and
- the cycle oriented mode, which records all cycles, passed as well as failed.

The overview Error Map always records in cycle oriented mode, that is, it records both passed and failed blocks of n * 16 cycles.

The acquire failure mode has the obvious advantage that you can cover a greater area of the test. One advantage of the cycle oriented mode is that the response times of some reporting queries are better.

 Note The detailed Error Map records information in 32 bit words. Such a word can contain results of up to 16 cycles (2 bit result, cycle level). The minimum is 4 cycles (1 bit result for all 8 receive edges). In acquire failure mode, only those cycle blocks (between 4 and 16 cycles) are recorded that contain at least one failed cycle (edge). If the block immediately preceding such a failing block contained no failed cycle (edge), then the number of the first cycle in the failing block is also recorded. Since storing this address information uses up one 32 bit word, the number of errors that can be recorded in acquire failure mode depends on the distribution of the errors.

The recording mode also determines how the internal Error Maps react to an overflow:

- In acquire failure mode, recording will stop.
- In cycle oriented mode, recording will continue by wrapping around to the start (so that the first recorded data will be overwritten).

Accordingly, the overview Error Map will always wrap around unless a stop position is specified for it (see [Recording position](<02.06.11.01.02.01.02.02_Recording_position.md>)).

You can either define the recording mode yourself, or leave it to SmarTest to make the appropriate selection. SmarTest will use the acquire failure mode as the default, but will switch to the cycle oriented mode in certain situations.
