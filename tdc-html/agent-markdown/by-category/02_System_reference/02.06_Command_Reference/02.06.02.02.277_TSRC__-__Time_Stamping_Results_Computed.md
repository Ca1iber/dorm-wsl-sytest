# TSRC? - (Time Stamping Results Computed)

The TSRC? query computes the periods and their descriptive statistics from the raw results (time stamps) for one site or all sites. This is done on the test head card.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Operation

The TSRC? query computes the periods of the time stamps from the specified result area and the statistics for those periods (see [Storing the results of more than one measurement](<02.06.13.01.03_Storing_the_results_of_more_than_one_TMU_measurement.md>)). By default, it performs these steps to do so:

- It checks whether all required samples have been taken. If not, it issues a warning and continues with the next step.
- It assigns an ID to each sample. An ID contains information about the site, the pin, the shot, and the measurement block to which the sample belongs. IDs are used by the system to identify individual measurement blocks.
- It computes the periods and their statistics from the time stamps of all samples and stores the statistics in the embedded memory for later upload with TSRS?.

You can use the execution_control parameter to start the execution from the second or third step. This can save time if any of these steps has already been performed by TSRW? or TSRC?.

## Syntax

```
TSRC? [(sitesToBeDone),] [measurement_id], {result_type}, [first_sample], [no_of_samples], [(execution_control),] [(site_selector),] [(resultAreaName),] {(pinlist)}
```

returns:

```
TSRC [shotcount],{result_type}, {successinfo}, {(pin)}
```

## Parameters

 | sitesToBeDone |

An extra string parameter, defining the sites to be uploaded. i.e. "01110011".

This option needs parameter [site_selector](<02.06.02.02.277_TSRC__-__Time_Stamping_Results_Computed.md#_141847__r_site_selector>) to be set to ALL.

 |
 | measurement_id |

The optional number of the measurement block (identified by the ARM keyword within a waveform that is executed in the pattern) for which the computation is performed. If no measurement block is specified, all measurement blocks will be computed.

 |
 | result_type |

The mandatory result type. Currently, the only supported result type is PERIOD.

 |
 | first_sample |

NOT USED

 |
 | no_of_samples |

NOT USED

 |
 | execution_control |

With this extra parameter, you can modify the default action sequence of TSRC?. Possible values are:

 | NOT_FINISHED |

Default. All three steps described above will be executed. If not all required samples have been actually taken, the query will not stop, it issues warning and continues to analyze and compute the available samples.

 |
 | FINISHED |

Completeness check will be skipped. TSRC? assumes that all required samples have been taken. It will analyze and compute the available samples. It starts from step 2, above.

 |
 | ANALYZED |

Samples will not be analyzed. TSRC? assumes that all required samples were taken and analyzed in a previous step. It computes the available samples. It starts from step 3, above.

   | |
 | site_selector |

This extra query parameter allows you to compute the results for a specific site or all sites. Possible values are:

 | ONE |

Only the values of the site which has the query focus are processed (the default).

 |
 | ALL |

The values of all sites or the sites defined by parameter [sitesToBeDone](<02.06.02.02.277_TSRC__-__Time_Stamping_Results_Computed.md#_141847__r_sitesToBeDone>) are processed.

 |
 | <N> |

The results of the site with this number are processed.

   | |
 | resultAreaName |

The extra parameter defines the name of the result area from which the samples should be computed. If this parameter is omitted, the default result area is used.

 |
 | pinlist |

The mandatory list of pins for which the time stamps are to be computed.

 |
 | pin |

The pin to which the computed results belong.

 |
 | shotcount |

The parameter returns the number of shots that have been computed.

 |
 | successinfo |

The parameter indicates whether the computation succeeded.

Possible return values:

-

SUCCEEDED

-

FAILED.

 |

## Application

Per-pin TMU measurements.
