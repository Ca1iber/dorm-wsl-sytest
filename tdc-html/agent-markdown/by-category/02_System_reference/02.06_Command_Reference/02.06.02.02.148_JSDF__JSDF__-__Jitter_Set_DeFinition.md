# JSDF, JSDF? - (Jitter Set DeFinition)

JSDF creates a jitter set by defining a unique name for it. Up to 128 jitter sets can be stored in the hardware. If you exceed this number by selecting a jitter set that is not yet stored in the hardware, the new set will replace the set that was downloaded first.

A jitter set can be associated with a user defined mode context (see [Mode contexts](<02.06.03.01.03.01_Mode_contexts.md>)). The primary jitter set (as defined with JSPR) must be associated with the same context as the other primary sets.

JSDF? returns the names of the specified or all defined jitter sets.

## JDSF

```
JSDF {"js_set_name"} [, "mode_context"]
```

## JDSF?

```
JSDF? ["js_set_name"|ALL]
```

returns:

```
JSDF {"js_set_name"} [, "mode_context"]
```

## Parameters

 |

js_set_name

 |

In the command, this is the name of a new jitter set. In the query, it is a name of an existing jitter set. If you omit this parameter in the query, JSDF? will return the names of all user defined jitter sets.

 |
 |

mode_context

 |

The mode context with which the jitter set is associated. If this parameter is omitted, the DEFAULT context is assumed.

 |
 |

ALL

 |

With this parameter, the query returns all existing jitter sets.

 |

## Application

Jitter test.

## Errors

An error is generated if a jitter set with the specified name already exists.

## Example

```
> JSDF   "js_set1"
> JSDF   "js_set2"
> JSDF   "js_set3"

> JSDF?
< JSDF   "js_set1"
< JSDF   "js_set2"
< JSDF   "js_set3"

```

## Functional changes

- Introduced in SmarTest 7.0.1
- SmarTest 7.3.0: The jitter set can now be associated with a user defined mode context.
