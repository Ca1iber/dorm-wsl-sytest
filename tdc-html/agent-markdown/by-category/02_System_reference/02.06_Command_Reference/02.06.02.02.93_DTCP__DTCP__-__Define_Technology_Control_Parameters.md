# DTCP, DTCP? - (Define Technology Control Parameters)

This command serves to control certain system control parameters. It supplements the DSCP command. The values that are defined with DTCP must be activated with the [*RST](<02.06.02.02.345_RST_-__ReSeT.md>) command.

The DTCP? query returns the currently selected value of a specified parameter. Note that this is not the active value, if a new value has been defined, but not yet been activated with *RST.

## DTCP

```
DTCP {"key"}, {"value"}
```

## DTCP?

```
DTCP? {"key"}
```

returns:

```
DTCP {"key"}, {"value"}
```

## Parameters

 | key  | The string specifies the system control parameter.

Currently, the only supported control parameters are testpoints and extended_dram_factor.

For more information, refer to [testpoints](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_testpoints>) and [extended_dram_factor](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_extended_dram_factor>) in [Technology file for a device](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>).

 |
 | value   | The value to be set as string. |

## Examples

```
> DTCP? "testpoints"
< DTCP "testpoints", "0"
> DTCP "testpoints", "100"
> DTCP? "testpoints"
< DTCP "testpoints", "100"
> *RST
> DTCP? "testpoints"
< DTCP "testpoints", "100"
```

```
> DTCP "extended_dram_factor","90"
> *RST
> DTCP? "extended_dram_factor"
< DTCP "extended_dram_factor","90"
```
