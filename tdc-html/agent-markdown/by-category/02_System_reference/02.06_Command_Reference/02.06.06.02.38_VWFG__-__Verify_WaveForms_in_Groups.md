# VWFG? - (Verify WaveForms in Groups)

The VWFG? (Verify WaveForms in Groups) query checks whether all specified pins have the same device cycle and waveform definitions. The system responds with a 0 or a 1.

The VWFG? query has no influence on the number of defined waveform sets.

The items taken into account when checking for device cycle definitions are the device cycle name and the waveform sequence.

The items taken into account when checking for waveform definitions are the parameters to commands [WFDF, WFDF? - (WaveForm DeFinition)](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>), [WAVE, WAVE? - (WAVEform)](<02.06.02.02.333_WAVE__WAVE__-__WAVEform.md>) and [BWDF, BWDF? - (Break Waveform DeFinition)](<02.06.02.02.13_BWDF__BWDF__-__Break_Waveform_DeFinition.md>), such as waveform set number, edge actions, data parameters.

## Equation-based testing

In equation-based testing, you must identify a wavetable instead of a waveform set. This is achieved either by supplying wavetable_name directly, or by supplying specset_id, calculated from equation set number and spec set number as follows:

```
100 * equation_set_no + specset_no
```

The appropriate wavetable is determined by looking at which wavetable is referenced by equation_set_no and specset_no in the timing specification file.

## Syntax

There are three different ways to call VWFG?:

```
VWFG? {waveform_set}, ["dev_cyc_name"], {(pinlist)}
VWFG? {specset_id},["dev_cyc_name"],{(pinlist)}
VWFG? {wavetable_name}, ["dev_cyc_name"], {(pinlist)}
```

All three forms return:

```
VWFG {status}
```

## Parameters

 |

waveform_set

 |

Waveform Set Number. Enter PRM for the Primary Waveform Set, or an integer in the range 1 to the maximum number of allowed waveform sets. The maximum number is determined by [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>).

 |
 |

specset_id

 |

Derived as follows:

`100 * equation_set_no + specset_no`

 |
 |

wavetable_name

 |

The wavetable name. Enter a string of up to 40 alphanumeric characters (upper or lower case) enclosed in double quotes.

 |
 |

dev_cyc_name

 |

If you specify the name of a device cycle, only this device cycle will be checked. Enter ALL for all device cycle names in the device cycle table.

 |
 |

pinlist

 |

The name of the pin or pins whose definitions you want to check. This parameter can also include groups previously created by [DFGP, DFGP? - (DeFine GrouP)](<02.06.02.02.60_DFGP__DFGP__-__DeFine_GrouP.md>). If more than one pin is to be included, the names must be separated with a comma. The symbol @ can be used to check all configured pins.

 |
 |

status

 |

The system returns:

0: The definitions are not the same.

1: The definitions are the same.

 |

## Application

Timing setup, see [Timing Setup Commands](<02.06.06_Timing_Setup_Commands.md>).

## Errors

An error is generated if:

- waveform_set is greater than the range allowed by the [WSUS](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>) command.
- specset_id is invalid because equation_set_no, specset_no or both are invalid.
- specset_id does not reference a defined wavetable.
- wavetable_name does not reference a defined wavetable.
- multi-port spec does not reference a defined wavetable.

## Example

```
> VWFG? "spec_search_wtb","SBC",(ser_in)
< VWFG 1
> VWFG? "spec_search_wtb",,(ser_in)
< VWFG 0
```

According to this example, the waveform and device cycle definition for device cycle SBC are the same for the pins in the group ser_in within the wavetable spec_search_wtb, but this does not hold for all device cycles that are defined for the pins of this group.
