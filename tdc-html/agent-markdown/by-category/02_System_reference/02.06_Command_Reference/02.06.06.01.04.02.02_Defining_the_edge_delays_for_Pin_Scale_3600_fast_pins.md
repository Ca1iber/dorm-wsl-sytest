# Defining the edge delays for Pin Scale 3600 fast pins

Every equation set that contains edge delay definitions for fast pins must be associated with a mode context. This mode context is specified with the keyword MODECONTEXT immediately below the EQNSET statement. For more information on mode contexts see [Mode contexts](<02.06.03.01.03.01_Mode_contexts.md>).

By default, the edge delays for fast pins are calculated by SmarTest from

- the period length,
- the number of edges, and
- an initial delay which is specified by the user for the edge d1 or r1.

The number of edges is specified with the period_div statement; you can specify a different number for every pin within one timing set. However, this number must be the same for the same pin in every timing set of the same equation set (this is required for CTIM instructions where the timing set is changed, but the wavetable remains the same). The number of edges can be queried for individual pins with PDIV?.

When you connect an equation set with a wavetable in a specification, the period_div statement in the timing set must equal the length of the action sequences in the wavetable.

The edges are placed equidistantly at an interval which is calculated as the period length divided by the number of edges. A delay can be specified for the position of the first edge. All the other edges will then be delayed accordingly.

For drive edges other than d1 (not for receive edges) you can define an offset from the calculated position, which can also be negative. This is indicated by a + sign between the edge and the = sign.

## Related firmware commands

You can use the ETDS command to retrieve and change the delays. However, this is only a temporary change of the runtime values, which does not modify the values in the timing set.

## Example

Consider the following example:

EQNSET 4 "fast"

MODECONTEXT "F"

TIMINGSET 1 "eq 4 ts 1"

 period=20

PINS I1

 period_div=6

 d1=3

 d3+=-0.166

PINS O1

 period_div=4

 r1=16

If you query the edge positions resulting from this equation set fragment with

ETDS? 401,1,,(I1,O1)

the reply will be:

ETDS 401,1,,"pdiv:6 d1:3 d2:6.333 d3:9.5 d4:12.999 d5:16.332 d6:19.665",(I1)

ETDS 401,1,,"pdiv:4 r1:16 r2:21 r3:26 r4:31",(O1)

Note that due to the delay of 16 ns, r3 and r4 are placed outside the period (cycle boundary crossing).

Note also the format of the definition string, which contains the period divider at the start. You could change the runtime delays for all six edges of `I1` by issuing

ETDS 401,1,,"pdiv:6 d1:0",(I1),

which would result in

ETDS? 401,1,,(I1)

ETDS 401,1,,"pdiv:6 d1:0 d2:3.333 d3:6.667 d4:10 d5:13.333 d6:16.667",(I1)

Note that the offset for d3 is no longer valid.
