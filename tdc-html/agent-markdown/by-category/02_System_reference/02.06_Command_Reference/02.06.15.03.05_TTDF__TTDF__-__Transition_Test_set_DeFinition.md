# TTDF, TTDF? - (Transition Test set DeFinition)

TTDF creates a transition test set by defining a unique name for it. Transition test sets serve to configure a protocol engine test.

TTDF? returns the names of all defined transition test sets.

Every new transition test set is associated with the configuration parameters of the predefined transition test set DEFAULT. You can modify these parameters with the [TTCF](<02.06.02.02.286_TTCF__TTCF__-__Transition_Test_ConFiguration.md>) command.

The number of transition test sets that can be defined on the system controller is not restricted. However, the hardware can only store up to 16 transition test sets in parallel. If you exceed this number by selecting a primary transition test set that is not yet stored in the hardware, the new primary set will replace the set that was downloaded first.

A transition test set can be associated with a mode context. The primary transition test set (as defined with TTPR) must be associated with the same context as the other primary sets.

## TTDF

```
TTDF {"tt_set_name"} [, "mode_context"]
```

## TTDF?

```
TTDF? ["tt_set_name"]
```

returns:

```
TTDF {"tt_set_name"} [, "mode_context"]
```

Parameters
 |

tt_set_name

 |

In the command, this is the name of a new transition test set. In the query, it is a name of an existing transition test set. If you omit this parameter in the query, TTDF? will return the names of all user defined transition test sets.

 |
 |

mode_context

 |

The mode context with which the transition test set is associated. If this parameter is omitted, the DEFAULT context is assumed.

 |

## Application

Protocol engine test.

## Errors

An error is generated if:

- A transition test set with this name already exists,
- The existing sets already exhaust the maximum number of transition test sets.

## Example

```
> TTDF   "myTTTrckSet1"
> TTDF   "myTTPatTSet1"
> TTDF   "myTTRCTLSet1"

TTDF?
> TTDF   "myTTTrckSet1"
> TTDF   "myTTPatTSet1"
> TTDF   "myTTRCTLSet1"
```
