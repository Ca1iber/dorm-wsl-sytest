# APTS - (APpend TeSt)

The high-level (edit) command APTS (APpend TeSt) serves to simplify creation of a vector label (pattern) for a port.

## Mode of operation

APTS defines a label (name, type, command line segment, base wavetable, and port) and creates a rudimentary sequencer program for it at the end of the sequencer area for the specified port. It does not support all label types, but only MAIN, SVEC, DSRC.

The structure of the created sequencer program depends on the label type:

- For type MAIN, it consists of the STVA and STSA address instructions and of the STOP instruction.
- For type SVEC, it consists of the STVA and the RSUB instructions.
- For type DSRC, it consists of the SSRC and SRCV instructions.

See the [SQPG](<02.06.02.02.237_SQPG__SQPG__-__SeQuencer_ProGramming.md>) command for more information on these instructions.

APTS is similar to the low level command [SQLB](<02.06.02.02.236_SQLB__SQLB__-__SeQuencer_LaBel_definition.md>). Its advantages over SQLB are twofold:

- APTS expands the sequencer area automatically. In contrast, you can call [SQLB](<02.06.02.02.236_SQLB__SQLB__-__SeQuencer_LaBel_definition.md>) only after having done this manually with the [DMAS](<02.06.02.02.79_DMAS__DMAS__-__Define_Memory_Area_Size.md>) command.
- APTS adjusts the address of the STVA instruction to the end of the vector areas (if the pins of the port have vector areas of different size, the end of the largest area is taken). In contrast, [SQLB](<02.06.02.02.236_SQLB__SQLB__-__SeQuencer_LaBel_definition.md>) sets the address to 0, and you must adjust it manually afterwards with the [SQPG](<02.06.02.02.237_SQPG__SQPG__-__SeQuencer_ProGramming.md>) command.

## Postdependencies

After having created the label, you must insert vector generating instructions into the sequencer program. For example, to insert a GENV instruction:

- Activate the label for editing with the [TSTL](<02.06.02.02.281_TSTL__TSTL__-__TeST_Label.md>) command.
- Issue the [INGV](<02.06.02.02.143_INGV_-__INsert_Generate_Vectors.md>) command.

## Syntax

```
APTS {"label"}, {type}, {base_wf_set|"wavetable"|specset_id|"multiport_spec"} [,(port)]
```

## Parameters

 |

label

 |

Defines the name of the new label. Enter an alphanumeric string in double quotes containing 1 to 128 characters.

 |
 |

type

 |

The label type. It has the following options:

 |
 |

MAIN

 |

The MAIN program. You can make calls to both types of subroutine (SJMP and SVEC), execute commands and sequencer instructions, generate vectors and use SSRC and SRCV instructions.

 |
 |

SVEC

 |

Vector subroutine. A subroutine where you can execute commands and sequencer instructions and generate vectors. You can nest SVEC subroutines up to 7 levels deep.

 |
 |

DSRC

 |

The digital source label. A type of label used only by SSRC and SRCV (see [SQPG, SQPG? - (SeQuencer ProGramming)](<02.06.02.02.237_SQPG__SQPG__-__SeQuencer_ProGramming.md>)). A DSRC label is not executable. The contents of the DSRC label are determined by the DVCU command. See [DVCU, DVCU? - (Define Vector variable Configuration Usage)](<02.06.02.02.96_DVCU__DVCU__-__Define_Vector_variable_Configuration_Usage.md>)

 |
 |

base_wf_set

 |

Defines a base waveform set. Enter an integer in the range of 1 to the number of used waveform sets as defined by the command [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>).

 |
 |

wavetable

 |

The name of the base wavetable. Enter a string of up to 40 alphanumeric characters (upper or lower case) enclosed in double quotes.

 |
 |

specset_id

 |

Derived as follows:

`100 *` equation_set_no `+ ` specset_no

 |
 |

multiport_

spec

 |

In a multiport setup, you can also specify the name of a multiport specification.

 |
 |

port

 |

This parameter fulfills two functions. It primarily determines the port with which the label is to be associated. If you do not specify a port, the label is associated with the default port @.

If you have entered a multiport specification as the third parameter, the parameter also serves to identify uniquely the base wavetable for the label.

 |

## Application

Edit command in Pattern Tool.

## Errors

An error is generated if:

- There is insufficient channel memory.
- There is insufficient disk space (offline operation only).
- No label is defined.
- The specified label already exists.
- No more labels can be defined.
- You specify an invalid label.
- The specified waveform set number is out of range of used waveform sets.
- wavetable does not reference a defined wavetable.

## Examples

### Example 1

```
> APTS "test_2",MAIN,"gross_func_wtb"
> SQLB? ALL,ALL,(@)
< SQLB "test_1",MAIN,0,3,"gross_func_wtb"
< SQLB "test_2",MAIN,4,6,"gross_func_wtb"
> SQPG? ALL,(@)
< SQPG 0,STVA,504,,,(@)
< SQPG 1,STSA,,,,(@)
< SQPG 2,GENV,12,,,(@)
< SQPG 3,STOP,,,,(@)
< SQPG 4,STVA,520,,,(@)
< SQPG 5,STSA,,,,(@)
< SQPG 6,STOP,,,,(@)
```

This example appends a label to the sequencer area of the default port @. The label has the name `test_2`, is of type MAIN and is configured with the base wavetable `gross_func_wtb`. The following two queries display the result of the call. The STVA instruction of the new label points to the actual end of the vector areas.

### Example 2

```
APTS "NEW",MAIN,"spec_port_1_port_2",(port_1)
```

This example appends the label `NEW` to the sequencer area of port `port_1`. The base wavetable is identified uniquely by specifying the multi-port specification `spec_port_1_port_2` and the port `port_1`, which belongs to `spec_port_1_port_2`.
