# UTOT, UTOT? - (UTility line OuTputs)

The UTOT (UTility line OuTputs) command sets the state of the utility lines. All utility lines have read and write capabilities. The lines have open collector outputs. A programmed 0 sets the corresponding output to high (high impedance state), a programmed 1 sets the output to low, (the state of the output lines is the inverse of the programmed value).

For more information, see [Interface circuitry](<../02.03_DUT_board_design_reference/02.03.04.03_Utility_line_interface_circuitry.md>) in the DUT board design reference.

The UTOT? query returns the last programmed value.

Utility lines are organized in pogo blocks that provide 32 lines per block on the DUT interface. The blocks can be accessed independently of each other. Several test head configurations are available offering either 32, 64, 256 or 512 utility lines accessible on 1, 2, 8 or 16 utility blocks. For information on this and on the mapping of utility blocks see [Utility line assignments](<../02.03_DUT_board_design_reference/02.03.04.01_Utility_line_assignments.md>).

A utility line is referenced as URWxx, where xx represents the number of the line starting with 00. Utility lines have a range of 00 to 31.

## UTOT

```
UTOT {utility_group}, [mask], {value}
```

## UTOT?

```
UTOT? {utility_group}
```

returns:

```
UTOT {utility_group}, [mask], {word}
```

## Parameters

 | utility_group |

This parameter specifies the utility pogo block.

The pogo block is defined by a three‑digit number. For valid pogo blocks, refer to [DUT interface layout](<../02.03_DUT_board_design_reference/02.03.03.01_DUT_interface_layout.md>) and to [Utility pogo block mapping](<../02.03_DUT_board_design_reference/02.03.06.08.02_Utility_pogo_block_-_Utility_Card__V93000_EXA_Scale_systems.md#_347642__s_Utility_pogo_block_mapping>) in [Utility pogo block - Utility Card (V93000 EXA Scale systems)](<../02.03_DUT_board_design_reference/02.03.06.08.02_Utility_pogo_block_-_Utility_Card__V93000_EXA_Scale_systems.md>).

The legacy single‑digit format 1 ... 8 is also supported, but the query always returns the three ‑digit format.

For the UTOT? query, the parameter can be set to ALL to specify all utility blocks.

For more information, see [Utility line assignments](<../02.03_DUT_board_design_reference/02.03.04.01_Utility_line_assignments.md>) and [DUT interface layout](<../02.03_DUT_board_design_reference/02.03.03.01_DUT_interface_layout.md>).

 |
 | mask |

The optional parameter masks the utility lines in the block selected by the utility_group parameter.

Enter a decimal equivalent of a 32 bit binary number (0 ... 4鈥?94鈥?67鈥?95), to mask the required line.

The mask value is defined as follows:

- 1: A bit value of 1 causes the selected line to be programmed to the value specified in the parameter value.
- 0: A bit value of 0 masks the line, that is, the line remains unchanged.

If the mask parameter is not specified, then all the utility lines in the selected block are programmed.

 |
 | value |

This parameter can be entered either as string in the form of a hex word (0 ... FFFF FFFF), or in the form of an integer word (0 ... 4鈥?94鈥?67鈥?95).

Utility lines are basically low side switches. Therefore, the utility lines are set to the inverse of the binary equivalent of the specified value. For example, let us assume the value is 12. This equals to 1100 in binary, its inverse is 0011. Therefore, the first and the second utility line (URW00 and URW01) will be set to high, while all others on this block are set to low.

You can pulse the output utility lines by entering several hex words one after another (not decimal integers) enclosed in double quotes.

- Thus to produce a single pulse on the sixth line of the second utility pogo block, you would enter: `UTOT 166, "0040, 0000, 0040"`.
- You can use this facility for instance to produce a trigger pulse for a certain measurement.
- The specified hex data is sequentially written to the utility lines.Note Such pulses on the utility lines can in no way be synchronized to the execution of test vectors and are meant to enable you to switch slow devices such as relays. If you need to switch utility lines in synchronism with test vectors you must use the command [UTSC, UTSC? - (UTility line Serial Configuration)](<02.06.02.02.312_UTSC__UTSC__-__UTility_line_Serial_Configuration.md>) and set up serial control of utility lines as described in [Sequencer-controlled utility lines](<../../03_Use_cases_and_application_papers/03.09_How_to_set_up_sequencer__ontrolled_utility_lines/03.09.01_Sequencer-controlled_utility_lines.md>).
 |
 | word |

This is an integer value returned by the system, informing you of the setting of the utility output lines. For each utility block you enter, the system returns a reading.

The query returns the value the utility lines were set to by `UTOT`. Use the [UTIX?](<02.06.02.02.310_UTIX__-__UTility_line_Inputs_eXtended.md>) command to read back the actual state of the utility lines.

 |

## Application

Controlling the output utility lines.

## Errors

An error is generated if you enter a decimal value outside the valid range:

- for 4-row utility blocks: 0 ... 4鈥?94鈥?67鈥?95

## Warnings

A warning is generated if you enter a sequence of values outside the valid range:

- for 4-row utility blocks: 0 ... FFFF FFFF (or 4鈥?94鈥?67鈥?95).

The entry will be ignored by the system.

## Examples

### Example 1

```
UTOT 165,16383,12345
```

This code sets the first sixteen utility lines of the first block, except those used for the addressing of EEPROMs related to the DUT interface. These are URW14 and URW15. URW0 to URW13 are set to the inverse of 12345. 12345 in decimal equals 0011000000111001 in binary. Inverted, this is 53190 in decimal or 1100111111000110 in binary. Thus the lines will have these states:

 |

URW00 = low

 |

URW04 = low

 |

URW08 = high

 |

URW12 = low

 |
 |

URW01 = high

 |

URW05 = low

 |

URW09 = high

 |

URW13 = low

 |
 |

URW02 = high

 |

URW06 = high

 |

URW10 = high

 |

URW14 = high

 |
 |

URW03 = low

 |

URW07 = high

 |

URW11 = high

 |

URW15 = high

 |

For the utility lines required to address EEPROMs related to the DUT interface see [Utility lines and DUT board EEPROMs](<../02.03_DUT_board_design_reference/02.03.04.06_Utility_lines_and_DUT_board_EEPROMs.md>).

### Example 2

```
UTOT? 165
```

returns:

```
UTOT 165,,12345
```

The query returns the value that was written by UTOT. If you have previously executed Example 1, then the returned value will be the written value, but bits 14 and 15 may be different. This is because these lines retain the values that have been written previously.

Use the [UTIX?](<02.06.02.02.310_UTIX__-__UTility_line_Inputs_eXtended.md>) command to read back the actual state of the utility lines.

### Example 3

```
UTOT 166,65535,"5555,AAAA,0,FFFF"
```

writes the sequence AAAAh, 5555h, FFFFh, 0000h to the first sixteen utility lines of the second utility block.

### Example 4

```
UTOT? 166
```

returns the last written values. If you have just executed example 3, the result would be:

```
UTOT 166,,65535
```
