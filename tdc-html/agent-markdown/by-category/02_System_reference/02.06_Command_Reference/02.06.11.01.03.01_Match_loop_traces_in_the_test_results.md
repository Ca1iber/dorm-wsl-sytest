# Match loop traces in the test results

In principle, a successful match loop should leave no traces in the Error Map. But if the match loop starts or ends in the middle of an 8-cycle block, it will have an impact on the recorded results:

- If the match loop starts in the middle of a 8-cycle block, the whole block will be part of the match loop, and consequently the cycles of the surroundig test at the start of the block will not be recorded.
- If the match loop ends in the middle of a 8-cycle block, the whole block will be part of the surrounding test, and consequently the last match loop cycles at the start of the block will be recorded.

The GETV?, VCYC?, and CYCI? result queries inform the user explicitly or implicitly about this. For more information see [Adjusting the junctions between match loop and surrounding label](<02.06.07.01.08.04.03.01.01_Adjusting_the_junctions_between_match_loop_and_surrounding_label.md>).

## Example

The following example, which uses GETV?, illustrates both possibilities for a counted match loop. Consider the following sequencer program:

```
QPG 0,STVA,0,,,(@)
SQPG 1,STSA,,,,(@)
SQPG 2,GENV,13,,,(@)
SQPG 3,MACT,120,,,(@)
SQPG 4,GENV,10,,,(@)
SQPG 5,MRPT,8,,,(@)
SQPG 6,GENV,2,,,(@)
SQPG 7,STOP,,,,(@)
```

When you execute this program online, and a match is already obtained in the first pass of the match loop, GETV? will supply the following answer:

```
> GETV? 0,200,(CP)
< GETV 0,8,0,13,GENV,,,(CP)
< GETV 8,7,23,8,MTCH,,,(CP)
< GETV 15,2,31,2,GENV,,,(CP)
< GETV 17,7,-1,-1,BRK,,,(CP)
```

The first two parameters of the GETV? replies specify a cycle range, the second two the range of the active vectors from which these cycles have been created. The 5th parameter specifies the instruction with which the vectors are associated.

Note that by the first reply, only 8 cycles are recorded for the first GENV instruction. The remaining 5 belong to the block in which the match loop starts, and are therefore not recorded.

The 7 recorded cycles that are assigned to the match loop (by MTCH) in the second reply belong to the cycle block in which the match loop ends. They are created from the MRPT vectors. The 8th cycle of this block is the first cycle generated from the vectors of the following GENV instruction. Note that GETV? will report the impact of the MRPT vectors also if the last match loop cycle is also the last cycle of a block; in this case it will return 0 in the second parameter.
