# WAVE, WAVE? - (WAVEform)

The WAVE command defines a physical waveform in fixed timing by specifying values for the data parameters of a logical waveform and assigning a physical waveform index to these values. Only physical waveforms are downloaded to the hardware and executed by the sequencer. Therefore at least one WAVE command must be issued for every logical waveform, even those that do not contain any data parameter. The command can also be used to create new runtime definitions of physical waveforms in an equation based timing. The WAVE? query returns the physical waveform definitions for all logical waveforms of the specified or implied wavetable / waveform set.

## Prerequisites

The logical waveform for which physical waveforms are to be created must have been defined with [WFDS](<02.06.02.02.335_WFDS__WFDS__-__WaveForm_Definition_String.md>) or [WFDF](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>).

## Mode of operation

The definition of a logical waveform specifies drive and receive actions either by a fixed state or by a data parameter. The fixed state actions specify the physical state of the signal directly. The physical states for data parameters are supplied by a call of the WAVE command. The physical states for drive actions are specified with the WAVE parameters DD1 and DD2, the physical states for receive actions with the parameters ED1 and ED2.

The following table shows which fixed actions can be assigned to which forms of the drive data parameters.

 |

Data parameter

 |

Admitted fixed state actions

 |
 |

D11, D22, C11, C22

 |

F10, F1Z, F00, F0Z

 |
 |

D1N, D2N

 |

F0N, F1N

 |
 |

DN1, DN1

 |

FN0, FNZ

 |

The following table shows which fixed actions can be assigned to which forms of the receive data parameters.

 |

Data parameter

 |

Admitted fixed state actions

 |
 |

EE1, EE2

 |

F0, F1, FI, FU, FX, C, D

 |
 |

WE1, WE2

 |

F0, F1, FI, FU, FX

 |

If the logical waveform contains no data parameters, the WAVE parameters DD1 through ED2 must be left blank.

## WAVE

```
WAVE {wvf_set}, {wfIndex}, [DD1], [DD2], [ED1], [ED2], {pwfIndex}, {(pinlist)}
WAVE {specset_id|"multiport_spec"}, {wfIndex}, [DD1], [DD2], [ED1], [ED2], {pwfIndex}, {(pinlist)}, ALLOW_EQ
```

## WAVE?

```
WAVE? {wvf_set|"wavetable_name"|specset_id|"multi-port_spec"}, {(pinlist)}
```

returns:

```
WAVE {wvf_set|"wavetable_name"|specset_id|"multi-port_spec"}, {wfIndex}, [DD1], [DD2], [ED1], [ED2], {pwfIndex}, {(pinlist)}
```

## Parameters

 |

wvf_set

 |

Waveforms set number. Enter an integer in the range 1 to the maximum number of allowed waveform sets. The maximum number is determined by [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>). For the query command you can also enter ALL for all waveform sets.

 |
 |

specset_id

 |

Derived as follows:

`100 * equation_set_no + specset_no`

 |
 |

wavetable_name

 |

The wavetable name. Enter a string of up to 40 alphanumeric characters (upper or lower case) enclosed by double quotes.

 |
 |

multiport_spec

 |

To change or query a multiport specification, enter the name of the specification.

 |
 |

wfIndex

 |

Logical waveform index. This index identifies the logical waveform for which a physical waveform is to be created. The values specified for the DD1, DD2, ED1, and ED2 parameters must be in accordance with the format of this logical waveform.

 |
 |

DD1 and DD2

 |

First and second drive data parameter. These are optional parameters and contain values for both drive data and tri-state. The values you can define are:

 |
 |

F0N

 |

drive 0

 |
 |

F1N

 |

drive 1

 |
 |

FN0

 |

tri-state off

 |
 |

FNZ

 |

tri-state on

 |
 |

F00

 |

drive 0, tri-state off

 |
 |

F0Z

 |

drive 0, tri-state on

 |
 |

F10

 |

drive 1, tri-state off

 |
 |

F1Z

 |

drive 1, tri-state on

 |
 |

ED1 and ED2

 |

First and second receive data parameter. These are optional parameters. The values you can define are:

 |
 |

F0

 |

compare to 0

 |
 |

F1

 |

compare to 1

 |
 |

FI

 |

compare to intermediate

 |
 |

FX

 |

compare to mask

 |
 |

FU

 |

compare to unstable

 |
 |

C

 |

capture digital data

 |
 |

D

 |

do not capture digital data

 |
 |

The values C and D are used for selective digital capture. The following rules apply to these values:

- A waveform that is used for selective digital capture cannot contain more than one compare action. Therefore, if you specify C or D for one of ED1 or ED2, you cannot specify a value for the other Expected Data parameter.
- If you issue more than one instance of the WAVE command for the same logical waveform, the values you specify for the same Expected Data parameter in these different WAVE instances must be homogeneous; that is, either all or none of them must be C or D. You cannot, for instance, set ED1 to C in one of these WAVE instances, and set it to F1 in another.
 |
 |

pwfIndex

 |

Physical waveform index. Enter an integer between 0 and 31 (0 and 255 on the Pin Scale Digital systems) for each physical waveform . The index is stored in the vector area and references the physical waveform in the physical waveform table.

 |
 |

pinlist

 |

The name of the pin or pins for which physical waveform states are to be defined or read back. This parameter can also include groups previously created by [DFGP, DFGP? - (DeFine GrouP)](<02.06.02.02.60_DFGP__DFGP__-__DeFine_GrouP.md>). The symbol @ can be used to specify all configured pins. If more than one pin is to be included, the names must be separated by commas.

 |
 |

ALLOW_EQ

 |

This extra parameter allows you to define physical waveforms for an equation based timing. Note that only the runtime settings are affected; the definitions in the wavetable are not changed.

Note also the following:

- Every runtime change will affect all specifications that use the respective wavetable.
- Since the new waveform must be evaluated and downloaded for every specification that uses the respective wavetable, the change tends to be rather slow.
- The runtime definitions are not checked for consistency. It is up to the user to ensure this.
 |

## Application

Timing setup, see [Timing Setup Commands](<02.06.06_Timing_Setup_Commands.md>).

## Errors

An error is generated if:

- wvf_set is greater than the range allowed by the [WSUS](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>) command.
- The logical waveform index is outside the range of 0-31 (for P/C/Ce systems) or 0-255 (Pin Scale systems).
- The physical waveform index is outside the range of 0-31 (0-255 on the Pin Scale Digital Cards).
- You try to define a physical waveform for which no logical waveform exists. Define the waveform first with ([WFDS, WFDS? - (WaveForm Definition String)](<02.06.02.02.335_WFDS__WFDS__-__WaveForm_Definition_String.md>).
- There is a mismatch of action between the data parameter in the [WFDF](<02.06.02.02.334_WFDF__WFDF__-__WaveForm_DeFinition.md>) or [WFDS](<02.06.02.02.335_WFDS__WFDS__-__WaveForm_Definition_String.md>) definition and the corresponding fixed action as specified by WAVE.
- You try to redefine a physical waveform for a waveform. Delete the waveform and any associated physical waveforms first with [WFUD - (WaveForm UnDefine)](<02.06.02.02.338_WFUD_-__WaveForm_UnDefine.md>).
- specset_id is invalid because equation_set_no, specset_no, or both are invalid.
- specset_id does not reference a defined wavetable.
- wavetable_name does not reference a defined wavetable.

## Example

```
> WFDS 1,2,,"d1:D11 d3:0 d4:C11",(pin1,pin2,pin3,pin4)
> WAVE 1,2,F00,,,,4,(pin1,pin2,pin3,pin4)
> WAVE 1,2,F10,,,,5,(pin1,pin2,pin3,pin4)
```

This example first defines a logical waveform with the index 2 for waveform set 1. The waveform uses the data parameter D11, the fixed action 0, and the complement C11 of D11. Then two physical waveforms are defined for logical waveform 2, which are referenced by the physical waveform DC/DC power units 4 and 5. Waveform 4 drives to 0 at edge d1, to 0 at d3, and to 1 at d4. Waveform 5 drives to 1 at edge d1, to 0 at d3, and to 0 at d4.
