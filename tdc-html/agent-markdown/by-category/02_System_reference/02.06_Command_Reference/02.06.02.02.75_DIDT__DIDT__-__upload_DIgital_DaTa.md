# DIDT, DIDT? - (upload DIgital DaTa)

The DIDT command is defined for Digital Source Memory (DSM) applications. It serves to download digital data to a DSM vector variable (a vector area segment of a source label). For more information see [Overview of Digital Source Memory (DSM)](<../02.08_Setup_and_Result_Tools/02.08.01.03.01_Overview_of_Digital_Source_Memory__DSM.md>).

The DIDT? query is defined for both Digital Capture and Digital Source Memory applications. For Digital Source Memory, it serves to upload digital data from a DSM vector variable. For Digital Capture, the query serves to upload, filter, convert, and output captured digital data.

When uploading data for digital source memory, the vector variable passed to DIDT? must have been defined with the DVCU command. See [DVCU, DVCU? - (Define Vector variable Configuration Usage)](<02.06.02.02.96_DVCU__DVCU__-__Define_Vector_variable_Configuration_Usage.md>).

When uploading data for digital capture, the filtering conditions are specified in a vector variable which is passed to DIDT?. This vector variable must have been defined with the DVVA command. See [DVVA, DVVA? - (Define Vector VAriable)](<02.06.02.02.94_DVVA__DVVA__-__Define_Vector_VAriable.md>).

DIDT? returns data in 32-bit words that are called samples. The content of a sample depends on the transfer mode that was defined in the vector variable. For parallel transfer mode, one sample contains the parallel values of all the pins that are associated with the vector variable. For serial transfer mode, it can consist of up to 32 successive values of the one pin for which the vector variable is defined.

With this command you configure setups of those sites that have the setup focus: For more information, see also: [PSFC, PSFC?](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
DIDT {"var_name"}, [code_format], [code_input_mode], [byte_order], [code_width], [offset], [nr_vectors], [comment], {data}
DIDT? {"var_name"}, ["area-id",][code_format], [code_input_mode], [byte_order], [code_width], [offset], [nr_vectors]
```

returns:

```
DIDT {"var_name"}, [code_format], [code_input_mode], [byte_order], [code_width], [offset], [nr_vectors], [comment], {data}
```

To return only parameters and comments:

```
DIDT?ALL,,,,,0,0
```

Returns all vector variable parameters.

```
DIDT? "var_name",,,,,0,0
```

Returns only the parameters of the specific vector variable var_name:

```
DIDT {"var_name"}, [code_format], [code_input_mode], [byte_order], [code_width], [offset], [nr_vectors], ["comment"], #9000000000
```

Parameters
 |

var_name

 |

This is a unique name string for the vector variable that defines the filtering conditions.

 |
 |

area-id

 |

Selects a specific result retention area by ID to upload from. The corresponding result retention configuration must have been configured and valid results must have been recorded into the area by a previously executed digital capture test.

 |
 |

code_format

 |

Output format of the DUT, which is the input format for DIDT?. The possible values are:

- BIN
- COMP1
- COMP2
- MOD_COMP1
- GRAY
- BCD
- SYMM
- MOD_SYMM
- ALAW
- MOD_ALAW
- MSB

The default value is BIN. If you specify another DUT format, DIDT? takes an end segment of the sample with length code_width (see below) to be a code in that format and converts it into binary format before the sample is returned.

MSB causes the bit order of the sample segment to be reversed, that is, if the segment length is m, then the nth input bit will be the (m-n+1)th output bit. The maximum segment length is 32.

For example, 010011 will become 110010.

 |
 |

code_input_mode

 |

Defines the input mode of the data.

Code formats specified by the code_format and code_input_mode parameters determine how the data will be decoded for digital source memory downloads with the DIDT command or encoded during digital capture uploads with the DIDT? query.

The possible modes are:

- NORM (normal)
- COMP (complementary)

The default is NORM (assumed if not specified).

For details, see [Code Format Tables](<../02.07_Test_Method_Reference/02.07.04.04_Code_Format_Tables.md>) from the related VECTOR test method API [inputMode()](<../02.07_Test_Method_Reference/02.07.04.01.269_VECTOR.md#_29830__dle_inputMode>) and [getInputMode()](<../02.07_Test_Method_Reference/02.07.04.01.269_VECTOR.md#_29830__dle_getInputMode>).

 |
 |

byte_order

 |

Specifies the byte order of the device. Allowed values are:

- BIG_ENDIAN: The high-order byte is most significant.
- LITTLE_ENDIAN: The low-order byte is most significant.
 |
 |

code_width

 |

The width of that end segment of the sample that is considered as a code. It is this segment which is converted. The default width for Digital Capture variable type is determined as follows:

- If the xfer_mode parameter of the specified vector variable has been set to PARA, the default value of code_width is the number of pins that are associated with the vector variable.
- If xfer_mode is set to SERI, the default width is the value of the nr_vec_per_sample parameter of the vector variable.
 |
 |

offset

 |

This parameter can be used to further reduce the size of the data returned. This offset starts from the position specified by the init_discard parameter of the vector variable. The default is 0. This usage of offset is only supported for Digital Capture variables (defined with DVVA).

 |
 |

nr_vectors

 |

The number of vectors that are to be downloaded or uploaded, starting from offset. The Digital Capture variable type default is

nr_of_ frames 脳 nr_vec_per_frame

where nr_of_ frames and nr_vec_per_frame are parameters of the vector variable.

This parameter determines the number n of samples that are returned when uploading. n will be

nr_vectors / nr_vec_per_sample [+1],

where 1 is added if nr_vectors is not an integer multiple of the vector variable parameter nr_vec_per_sample.

 |
 |

comment

 |

String that can be used for equation algorithm of the downloaded arbitrary waveform. For example, sin(x)+sin(2x). This is not needed for Digital Capture upload.

 |
 |

data

 |

The waveform data described by using the binary data standard format. It consists of a standard header followed by the actual data (32 bit integer format). The format is:

#Nn1n2n...nNdata_stream

where the digit N defines the number of the digits ni that specify the length of data_stream in bytes.

 |

## Application

Digital Source Memory and Digital Capture applications.

## Errors

An error occurs if:

- There is no vector variable with the given name.
- The specified code format is either unknown or undefined for the number of bits given by code_width.
- The number of vectors in DIDT? is greater than the number of vectors defined in DVCU.
- offset + nr_vectors > nr_vec_per_frame 脳 nr_of_frames, where nr_vec_per_frame and nr_of_frames are parameters of the Digital Capture type vector variable.
- The pin list associated with the used vector variable does not match the pin list of the specified area or the area was not used for capturing.
- An invalid (that is, undefined) result area has been specified for uploading.
- The specified area does not contain valid results.

## Warnings

A warning is given if you specify a value for code_width that is smaller than the default value for this parameter.

## Examples

### Example 1 - Digital capture

```
> DVVA? ALL
< DVVA "par_var",DIGCAPT,"MYTEST",PARA,,,,0,3,1,1,2,2,(PAR3,PAR2,PAR1)
> DIDT? "par_var",,,,,,
< DIDT "par_var",BIN,NORM,BIG_ENDIAN,3,0,6,,#9000000024,,,,,,
```

or, alternatively:

```
> $DIDT? "par_var",,,,,,2
< DIDT "par_var",BIN,NORM,BIG_ENDIAN,3,0,2,,
       0000  0000  0000 0000  0000 0000  0000  0110
       0000  0000  0000 0000  0000 0000  0000  0101
```

In the preceding call of $DIDT? it was assumed that the output format of the DUT is BIN. Accordingly, no conversion was performed. If the output format is GRAY, call and reply will look like this:

```
> $DIDT? "par_var",GRAY,,,,,2
< DIDT "par_var",GRAY,NORM,BIG_ENDIAN,3,0,2,,
       0000 0000 0000 0000 0000 0000 0000 0100
       0000 0000 0000 0000 0000 0000 0000 0110
```

### Example 2 - Digital Source Memory

```
> DIDT? ALL,,,,,0,0
```

returns:

```
DIDT "LEFT",BCD,NORM,BIG_ENDIAN,16,0,10,"download comment LEFT",#9000000000
DIDT "L1",BIN,NORM,BIG_ENDIAN,32,0,0,"download sin wave",#9000000000
DIDT "L11",BIN,NORM,BIG_ENDIAN,32,0,0,"", #9000000000
DIDT "L2",BIN,NORM,BIG_ENDIAN,32,0,0,"",#9000000000
DIDT "LF",BIN,NORM,BIG_ENDIAN,16,0,20,"download comment Flat",#9000000000
```

Note To query the comments or download parameters of DIDT, you must specify that offset and nr_vectors be 0. Omitting nr_vectors means that you upload the number of frames defined in the vector variable configuration usage, using all the other default download parameters.
