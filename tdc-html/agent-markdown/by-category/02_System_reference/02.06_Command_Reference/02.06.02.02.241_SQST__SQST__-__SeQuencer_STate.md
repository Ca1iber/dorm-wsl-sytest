# SQST, SQST? - (SeQuencer STate)

The SQST command serves to control the state of a set of sequencers. This sequencer set is determined by an execution context which consists of a list of ports; it comprises the sequencers that belong to these ports. The ports of a user defined execution context must be a subset of the ports that are contained in the current start label. The port set of this label constitutes the global execution context. For more information on execution contexts see [Using execution contexts](<02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>).

Some sequencer states can be set only for the global execution context, and this implies that all user defined contexts will also be set into this state. But the RUN and (indirectly also) the BRK state can be assigned on the execution context level.

The SQST? query returns the maximum current state.

There are dependencies to the command [SQGB, SQGB? - (SeQuencer GloBal)](<02.06.02.02.232_SQGB__SQGB__-__SeQuencer_GloBal.md>), see below.

Note that the DPS128/DPS64, when starting the sequencer with `SQST RUN` or with the [SEQUENCER_STATUS run()](<../02.07_Test_Method_Reference/02.07.04.01.204_SEQUENCER_STATUS_-__Sequencer.md>) test method, cannot execute dynamic and static DC actions in parallel. Use [profiling](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.05.03.05_Profiling_of_DC_Scale_cards_with_Hardware_view.md>) for measurements in parallel to a dynamic pattern.

## SQST

SQST {seq_state} [,"exec_context"]

## SQST?

```
SQST? ["exec_context"]
```

returns:

```
SQST {seq_state}
```

## Parameters

 |

seq_state

 |

Gives the state of the sequencer:

 |
 |

OFF

 |

In the OFF state, both the sequencers and the clock are off. All pins go into the high-z state.

This option can only be applied to all execution contexts.

 |
 |

HALT

 |

In the HALT state, both the sequencer and the clock are off, and the drivers keep their last level or remain in high-z state if already in high-z state.

Note that you cannot pass directly from HALT to OFF or from OFF to HALT. You must first pass to BRK in both cases.

This option can only be applied to all execution contexts.

 |
 |

BRK

 |

In the BRK state, the clock is on and the break waveform is applied to the DUT.

This option can only be applied to all execution contexts.

 |
 |

ABRT

 |

This is not a sequencer state, but an instruction to change the state of an execution context from RUN to BRK. ABRT requires that an execution context is specified.

 |
 |

CBRK

 |

This is not a sequencer state, but a conditional instruction. If no context is in BRK or RUN state, the state of the global context will be changed to BRK. If any context is in BRK or RUN state, nothing will be done.

 |
 |

RUN

 |

In the RUN state, the clock is on and the sequencer applies vectors to the DUT. This option can be applied to a specified execution context.

 |
 |

Note that if the sequencer state changes from OFF or BRK to RUN, the sequencer runs with the global settings that have previously been defined with [SQGB, SQGB? - (SeQuencer GloBal)](<02.06.02.02.232_SQGB__SQGB__-__SeQuencer_GloBal.md>).

 |
 |

exec_context

 |

An execution context. In the command, this parameter can only be added to the sequencer state RUN and the instruction ABRT. It must be added if ABRT is specified. For more information on execution contexts see [Using execution contexts](<02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>) .

If the query is issued without a context, then RUN will be returned if there is at least one context that is in the RUN state.

 |

## Application

AC tests.

Connect or disconnect the test system, see [Relays Control Commands](<02.06.08_Relays_and_Control_Commands.md>).

## Example

```
SQST RUN
```

This example starts a global sequencer run.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.2.0: An execution context can now be specified for the RUN and the new ABRT option.
