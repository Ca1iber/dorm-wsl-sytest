# Burst labels

A burst label differs from a sequence of independent MAIN labels in two respects:

- If a MAIN label is called directly (with FTST?), a certain amount of time is required for handling the activation of the primary sets. By default, SmarTest does not activate the actual primary sets before actually starting the label if they are already active. But even then it must check if activation can actually be suppressed. Also, this optimization of primary activation can also be switched off, in which case the primary sets will be activated even if they have not changed since the last test. This activation triggers an even more time-consuming CTOF sequence.

In a burst label, the primary sets are activated only once, at the beginning of the burst. These primary sets are used for all MAIN labels of the burst. Therefore, no CTOF sequence is required at the start of the second and all following labels. Also, no check is performed between two labels of a burst.

- If a MAIN label is called directly, and the number of its user cycles is not a multiple of 8, it will be filled up with break cycles to the next multiple of 8.

In a burst label, the last user cycle of the predecessor label will be followed immediately by the first user cycle of the successor label.

Especially the first point can enhances the throughput considerably as compared to a sequence of independent MAIN labels with the same primary sets.

A failing burst label returns one global FAIL result. If you want to identify the failing MAIN labels of a failing burst, you have two options:

- You can run the burst label in the so called unburst mode. In this mode, every main label of the burst label is run separately, and data log data is generated for each of these labels.
- You can configure the overview error map in such a way that it returns one result for every label of a burst. For more information see [Compression factor for overview Error Map](<02.06.11.01.02.01.02.07_Compression_factor_for_overview_Error_Map.md>).

A burst label has no special start instruction. It consists of a sequence of CALL instructions for the individual MAIN labels of the burst, and is terminated by the BEND instruction.

## Example

The following listing shows a burst label:

```
SQPG 12,CALL,,"test_1",,(@)
SQPG 13,CALL,,"test_2",,(@)
SQPG 14,BEND,,,,(@)
```

This label calls the MAIN labels `test_1` and `test_2`. The definition of the burst label is as follows:

```
SQLB "burst",BRST,12,14,"table1"
```
