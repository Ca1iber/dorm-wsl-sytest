# ERCY? - (ERror CYcle)

The ERCY? query retrieves error cycles, as well as received and expected data, for every pin in the specified pin list.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
ERCY? {type}, {start_cyc_no}, [no_of_cycles], [no_of_errors], {(pinlist)}
```

returns:

```
ERCY {type}, {cycle_no}, [window_len], [expected_data], [received_data], [data_type], {(pinlist)}
```

Parameters
 |

type

 |

Selects the type of error data to be returned. The parameter can be:

 |
 |

CYC

 |

Only Error Cycles are returned.

 |
 |

EXP

 |

Error Cycles with expected data is returned.

 |
 |

REC

 |

Error Cycles with received data is returned.

 |
 |

ALL

 |

Error Cycles with expected and received data is returned.

 |
 |

start_cyc_no

 |

An integer that defines the cycle following which failures are to be returned.

 |
 |

no_of_cycles

 |

An integer that defines the cycle range in which failures are to be reported. This parameter must be entered if the no_of_errors parameter has not been included.

 |
 |

no_of_errors

 |

This parameter determines how many cycles containing errors are to be returned for every pin, starting from start_cycle. This parameter must be entered if the no_of_cycles parameter has not been included.

 |
 |

cycle_no

 |

Specifies the cycle where an error has occurred.

 |
 |

window_len

 |

Window length is an optional parameter returned only if you have specified the error type EXP, REC or ALL and the cycle containing an error occurred during a window compare. The parameter window_len delivers the length of the compare window. A length of one test system cycle returns a 0. A length of two cycles returns a -1, and so on. An error occurring during a window compare is reported in the cycle where the compare window closes. The number of cycles making up the window is therefore negative.

In cases where cycle-boundary crossing takes place, the window_len parameter is useful when re-constructing in which cycle the error actually occurred.

 |
 |

expected_data

 |

Expected Data optional parameter. Returned only if the selected data type is EXP or ALL. The values returned can be:

 |
 |

F0

 |

expected data is 0

 |
 |

F1

 |

expected data is 1

 |
 |

FI

 |

expected data is intermediate

 |
 |

FU

 |

expected data is unstable

 |
 |

FN

 |

No reconstruction possible due to multiple compare edges in a single cycle. This will usually be the case when testing in X mode.

 |
 |

received_data

 |

Received Data optional parameter. Returned only if the selected data type is REC or ALL. The values returned can be:

 |
 |

F0

 |

received data is 0

 |
 |

F1

 |

received data is 1

 |
 |

FI

 |

received data is intermediate

 |
 |

FU

 |

received data is unstable

 |
 |

FN

 |

No reconstruction possible due to multiple compare edges in a single cycle. This will usually be the case when testing in X mode.

 |
 |

data_type

 |

Data Type optional parameter. Returned only if the selected data type is EXP, REC or ALL. The values returned can be:

 |
 |

FIX

 |

The edge or window compare was made to a fixed state.

 |
 |

E1

 |

The edge or window compare was made to the E1 parameter.

 |
 |

E2

 |

The edge or window compare was made to the E2 parameter.

 |
 |

FE1

 |

Multiple compare. Contains at least one edge or window compare to a fixed state, and one edge or window compare to the E1 parameter.

 |
 |

FE2

 |

Multiple compare. Contains at least one edge or window compare to a fixed state, and one edge or window compare to the E2 parameter.

 |
 |

E1E2

 |

Multiple compare. Contains at least one edge or window compare to the E1 parameter and one edge or window compare to the E2 parameter.

 |
 |

FE1E2

 |

Multiple compare. Contains at least one edge or window compare to a fixed state, one edge or window compare to the E1 parameter and one edge or window compare to the E2 parameter.

 |
 |

See also the [WAVE](<02.06.02.02.333_WAVE__WAVE__-__WAVEform.md>) command for an explanation of the expected data parameters.

 |
 |

pinlist

 |

The pin name or names for which error cycles are to be retrieved. If more than one pin is required, the names must be separated with a comma. The @ character can be used to retrieve the data for all configured pins.

 |

## Application

Error Map.

## Errors

An error is generated if:

- You fail to specify either the no_of_cycles or the no_of_errors parameter. One of the two has to be specified.
- No failure data is available. Restart the test.

## Example

```
> ERCY? ALL,0,,2,(pin1,pin2)
< ERCY ALL,215,-2,F1,F0,E1,(pin1)
< ERCY ALL,240,,F0,FI,FIX,(pin1)
< ERCY ALL,17,,F0,F1,FIX,(pin2)
```

This example queries the system for the first two error cycles of pin1 and of pin2, starting from cycle 0. Expected and received data are also to be returned. The system returns the first two error cycles of pin1. For pin2 only one error cycle exists, therefore only one cycle can be returned.

There is an error on pin1 in cycle 215 which was a window compare 3 cycles long. The expected data was a 1, the receive data was a 0. The window compare was made to the E1 parameter.

There is an error on pin1 in cycle 240 which was an edge compare to a fixed state. The expected data was a 0, the received data was intermediate.

There is an error on pin2 in cycle 17 which was an edge compare to a fixed state. The expected data was 0, the received data was 1.
