# TSRS? - (TMU Set ReSults)

The TSRS? query is used to compute and upload either the mean of the periods of the time stamps or the individual periods and their descriptive statistics. It can query one site or all sites.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Operation

The TSRS? query computes and uploads the periods of the time stamps from the specified result area and the statistics of those periods (see [Storing the results of more than one measurement](<02.06.13.01.03_Storing_the_results_of_more_than_one_TMU_measurement.md>)). By default, it performs these steps to do so:

- It checks whether all required samples have been taken. If not, it issues a warning and continues with the next step.
- It assigns an ID to each sample. An ID contains information about the site, the pin, the shot, and the measurement block to which the sample belongs. IDs are used by the system to identify the measurement blocks from which the periods are processed.
- It computes the periods and their statistics from the time stamps on the test head card and stores them in the card's memory.
- It retrieves the periods and their statistics to the system controller.

  - If the measurement_id parameter is omitted, and the optional parameters first_sample and no_of_samples are omitted, the TSRS? returns the descriptive statistics for all measurement blocks. This has the advantage that you can upload only the statistical values for all measurement blocks of all sites very fast.
  - If measurement_id parameter is specified, and the optional parameters first_sample and no_of_samples are omitted, the TSRS? returns the descriptive statistics for the specified measurement block only.
  - If the first_sample and no_samples are specified, the TSRS? returns both the individual periods of the specified samples and the descriptive statistics of the measurement block. Depending on the value of measurement_id, this is done just for the specified block or for all blocks. This operation is slower since the upload of the individual periods to the system controller takes more time.

You can use the execution_control parameter to start the execution from the second, third, or fourth step. This can save time if any of these steps has already been performed by TSRW? or TSRC?.

## Syntax

```
TSRS? [(sitesToBeDone),] [measurement_id], {result_type}, [first_sample], [no_of_samples], [(execution_control),] [(site_selector),] [(resultAreaName),] [(mode),] {(pinlist)}
```

returns:

```
TSRS [measurement_id], [(sitenumber),] {result_type}, [sample_id|aggregation_type|first_sample], {result|no_of_samples}, {(pin)} [,#spec(binary_results)]
```

## Parameters

 | sitesToBeDone |

An extra string parameter, defining the sites to be uploaded. i.e. "01110011".

This option needs parameter [site_selector](<02.06.02.02.278_TSRS__-__TMU_Set_ReSults.md#_125500__r_site_selector>) to be set to ALL.

 |
 | measurement_id |

The optional number of the measurement block (identified by the ARM keyword within a waveform that is executed in the pattern) for which periods or statistics to be returned. If no measurement block is specified, the periods or statistics of all measurement blocks are returned.

 |
 | result_type |

The mandatory result type. Currently, the only supported result type is PERIOD.

 |
 | first_sample |

The optional parameter specifies the first sample in the query (TSRS?) for which the period is to be returned. In the return (TSRS) of the query it specifies the first sample that is returned if the mode is set to ON. Samples are counted from 0.

 |
 | no_of_samples |

The optional parameter defines in the query (TSRS?) the number of samples for which the periods are to be returned. In the return (TSRS) of the query it specifies the number of samples that are returned if the mode is set to ON.

Depending on the value of parameter first_sample, fewer samples than specified may be returned. For example, if there are 9 samples in total, first_sample is 7 and no_of_samples is 4, only two samples are returned (the last two), not four.

 |
 | execution_control |

With this extra parameter, you can modify the default action sequence of TSRS?. Possible values are:

 | NOT_FINISHED |

All four steps described above will be executed. If not all required samples have been actually taken, the query will not stop, it will continue to analyze,compute and upload the available samples.

This is the default value.

 |
 | FINISHED  | Completeness check will be skipped. TSRS? assumes that all required samples have been taken. It will analyze, compute, and upload the available samples. It starts from step 2. |
 | ANALYZED  | Samples will not be analyzed. TSRS? assumes that all required samples were taken and analyzed in a previous step. It computes the available samples. It starts from step 3. |
 | COMPUTED  | Samples will not be computed. TSRS? assumes that all required samples were taken, analyzed, and computed in a previous step. It retrieves the periods and their statistics to the system controller. It starts from step 4.  | |
 | site_selector |

This extra query parameter allows you to request the results for all sites or a specific site. Possible values:

 | ONE |

Only the values of the site which has the query focus are processed (the default).

 |
 | ALL |

The values of all sites or the sites defined by parameter [sitesToBeDone](<02.06.02.02.278_TSRS__-__TMU_Set_ReSults.md#_125500__r_sitesToBeDone>) are processed.

 |
 | <N> |

The results of the site with this number are processed.

   | |
 | resultAreaName |

The extra parameter defines the name of the result area from which the samples should be retrieved. If this parameter is omitted, the default result area is used.

 |
 | mode  | This extra parameter controls the format of the reply when a range is specified with parameters first_sample and no_of_samples:

- If mode is set to OFF, a separate line is returned for every period value within the range.
- If mode is set to ON, the values are returned in a binary format in one line.
OFF is the default value. |
 | pinlist  | The mandatory list of pins for which the time stamps are to be returned. |
 | sitenumber |

Extra reply parameter. The site the samples belong to if the site_selector parameter has been set to ALL.

 |
 | sample_id |

This reply parameter identifies the sample. It is only returned if a range was specified in the query and mode was set to OFF.

 |
 | aggregation_type |

This reply parameter specifies an aggregation type. If a range was specified in the query, TSRS? returns not only the individual period values but also a number of statistics. These are:

-

STDDEV (standard deviation)

-

MEAN

-

MAX

-

MIN

-

MEDIAN

-

PP (peak to peak), the PP is same as MINMAX in the TMU ORE firmware.

 |
 | result |

The reply parameter specifies the period related to sample n or a value of the descriptive statistics. The unit is seconds.

It is not returned if a range was specified in the query and mode was set to ON.

 |
 | pin |

The pin to which the returned results belong.

 |
 | #spec(raw_results) |

The binary data that are returned if a range is specified with parameters first_sample and no_of_samples, and parameter mode is set to ON. The general format is:

`n1n2...nNdata_stream`

Where the decimal digit N defines the number of the decimal digits ni (1 = i = N) that specify the length of data_stream in bytes.

The values are specified as seconds.

 |

## Application

Per-pin TMU measurements.

## Example

This example returns the descriptive statistics for the measurement blocks individually.

```
> TSRS? ,PERIOD, , , (pin_a)

    < TSRS  1,PERIOD , STDDEV ,1.36,(pin_a)
    < TSRS  1,PERIOD , MEAN 1.36,(pin_a)
    < TSRS  1,PERIOD , MAX, 1.36,(pin_a)
    < TSRS  1,PERIOD , MIN, 1.36,(pin_a)
    < TSRS  1,PERIOD , MEDIAN, 1.36,(pin_a)
    < TSRS  1,PERIOD , PP, 1.36,(pin_a)

    < TSRS  2,PERIOD , STDDEV ,1.36,(pin_a)
    < TSRS  2,PERIOD , MEAN 1.36,(pin_a)
    < TSRS  2,PERIOD , MAX, 1.36,(pin_a)
    < TSRS  2,PERIOD , MIN, 1.36,(pin_a)
    < TSRS  2,PERIOD , MEDIAN, 1.36,(pin_a)
    < TSRS  2,PERIOD , PP, 1.36,(pin_a)
```

This example returns the individual samples 100 through 119 in measurement block 2, and also the statistical values.

```
> TSRS? 2,PERIOD,100,20,(pin_a)

    < TSRS  2,PERIOD ,100,1.36,(pin_a)
    < TSRS  2,PERIOD ,101,1.37,(pin_a)
    ...
    < TSRS  2,PERIOD ,119,1.36,(pin_a)
    < TSRS  2,PERIOD , STDDEV ,1.36,(pin_a)
    < TSRS  2,PERIOD , MEAN 1.36,(pin_a)
    < TSRS  2,PERIOD , MAX, 1.36,(pin_a)
    < TSRS  2,PERIOD , MIN, 1.36,(pin_a)
    < TSRS  2,PERIOD , MEDIAN, 1.36,(pin_a)
    < TSRS  2,PERIOD , PP, 1.36,(pin_a)
```
