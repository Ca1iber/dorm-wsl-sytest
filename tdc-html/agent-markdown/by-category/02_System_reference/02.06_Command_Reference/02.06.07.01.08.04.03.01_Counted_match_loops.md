# Counted match loops

#### Subtopics

- [Adjusting the junctions between match loop and surrounding label](<02.06.07.01.08.04.03.01.01_Adjusting_the_junctions_between_match_loop_and_surrounding_label.md>)

Counted match loops differ from timed match loops in the following respects:

- You can specify the maximum number of unsuccessful repetitions. If this number is exceeded, the match loop is terminated, and the surrounding test fails, unless you explicitly specify the test to continue.
- For the evaluation of the error flag, you must specify the dummy vector(s) without compare actions explicitly:

  - Minimum one dummy vector must be specified.
  - You do not have to adjust the number of dummy vectors to the exact time required for setting the error flag; the system repeats the specified dummy vector(s) as often as required.
  - It will often suffice to specify one single dummy vector.
  - The number of repetitions depends on the number of defined dummy vectors, the pattern cycle time, the pin configuration and other parameters.
  - The total number of executed dummy vectors for the required delay time is typically in the range from some hundred to more than 1000 vectors.

The following figure shows the operation mode of the counted match loop:

  ![Counted match loop](<../../../../raw/10564.png>)

There are two loops, the main loop and the wait loop. The body of the main loop executes the compare vectors once, and then the wait loop.

A counted match loop is started with the MACT instruction. This instruction specifies the maximum number of unsuccessful repetitions for the main loop. The CONTINUE option specifies to carry on with the test even if all repetitions of the match loop failed. Then the compare vectors must be specified with a GENV or RPTV instruction (an exception is when using [Nested match loops](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.05.02.07_Nested_match_loops.md>), in which case you may insert the MACT or MRPT instruction here). These must be followed by the MRPT instruction, which defines the number of dummy vectors to be repeated in the wait loop. You can specify more than one dummy vector if the total number of cycles within the match loop must be a multiple of a number greater than 1.

There are two subsidiary queries that return information about the last executed match loop:

- CHFA? - This query returns the result of the last match loop cycle for selected pins.
- MCNT? - This query returns the number of match loop passes that were needed to satisfy the match condition.

If you want the number of dummy vectors in a counted match loop to be fixed and known, run the EPRC? query with a block size of 1. Then the number of repetitions returned is the number of dummy vectors that you must define for the wait loop. For more information see [Calculating the buffer vectors for JMPE and RETC (and match loops)](<02.06.07.01.08.05.02.01_Calculating_the_buffer_cycles_for_JMPE_and_RETC__and_match_loops.md>).

 Note If a pattern contains more than one match loop, a full reconstruction of the test results is only possible if the number of cycles created by the loops is always a multiple of 8. This is required for the cycles generated within the match loop body as well as for the cycles generated with MRPT. For MRPT this can be ensured by specifying 8 vectors for this instruction. For the [Pin Scale 5000 card](<../02.05_Test_Head_Cards/02.05.04.02_Pin_Scale_5000_card.md>), the pattern containing the match loop must meet the following criteria:

- The start position of the match loop must be a multiple of 8 cycles.
- The number of cycles within the match loop must be a multiple of 8.
- There must not be any instructions to generate break cycles within the match loop.
- There must not be a conditional branch instruction within the match loop.
You can execute patterns that do not meet these conditions by setting [check_exa_scale_seq_restrictions](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363___Toc73527999>) in the [.technology file](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>) to off. However, the result for each cycle after the match loop may not be acquired correctly.

Match loops are subject to certain restrictions in the following contexts:

- Multi-port setup: See [Sequencing groups and pattern structure](<02.06.07.01.10.01.01_Sequencing_groups_and_pattern_structure.md>).
- Multi-site setup: See [Controlling the site match function](<02.06.03.01.10.04_Controlling_the_site_match_function.md>).
- SmartLoop鈩?setup: See [Executing a pattern鈥慴ased SmartLoop test](<02.06.17.04_Executing_a_pattern__ased_SmartLoop_test.md>).

## Example

The following is a simple example of a counted match loop:

```
SQPG 3,MACT,256,CONTINUE,,(@)
SQPG 4,GENV,5,,,(@)
SQPG 5,MRPT,5,,,(@)
```

Note that only the GENV or RPTV instruction is allowed immediately before the MACT instruction. CONTINUE, which is optional, tells SmarTest to continue the surrounding test even if the match loop failed.
