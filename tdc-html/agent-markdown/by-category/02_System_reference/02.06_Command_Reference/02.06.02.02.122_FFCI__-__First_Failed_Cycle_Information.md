# FFCI? - (First Failed Cycle Information)

The FFCI? query retrieves information on the first n failed cycles for all configured O and IO pins in the current mode context. If a port is specified, SmarTest returns only the pins from that port. The port should correspond to one of the pattern ports used in the last functional test execution.

FFCI? is a speed-optimized command that delivers only the error cycles sorted in order, starting from the acquisition start cycle.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
FFCI? {(no_ffcyc)} [,(port)]
```

returns:

```
FFCI {(no_ffcyc)}, {no_pins}, {#spec(data)}
```

## Parameters

 | no_ffcyc  | Number of first failed cycles to be reported. |
 | port  | Specifies the port for the pins for which information is to be returned. If you omit this parameter information will be returned for the default port @ to which all configured pins belong. |
 | no_pins  | The number of O and IO pins. |
 | #spec(data) |

Prefix and pin error data in binary format:

- The prefix is defined as follows:

  - The number sign # marks the start of the data block.
  - One digit follows, indicating how many digits make up the following data length specifier.
  - A number of digits indicating the length (in bytes) of the data to follow.

- Binary data are available per reported cycle. The data for each cycle consists of two parts, the number of the failing cycle and the pin data, which indicates the failing pins of that cycle:

  - Cycle number:

The length of the cycle number is always 8 bytes.

  - Pin data:

The pin data consists of one byte per eight pins that belong to the specified port:

    - Each pin is represented by one bit.
    - An error on a particular pin is denoted by a 1, an error free pin by a 0.
    - Bits of the pin data are filled starting from the left (MSB) side.
    - If the number of configured channels of the specified port is not divisible by 8, the last byte of pin data contains unused bits on the right (LSB) side.

Mapping of the bits in the pin data block to the individual pins:

- The I / IO pins are sorted based on their pogo number defined for the first site.
- The sorted pins are mapped starting on the left (MSB) side of the first byte of the pin data block.
- The information how the pins are mapped can be read by command [FFPM? (First Failing cycle information Pin Mapping)](<02.06.11.02.24_FFPM___First_Failing_cycle_information_Pin_Mapping.md>).
 |

## Examples

### Example 1: Firmware view

```
$FFCI? 2
FFCI 2,7,#218
  00000000 00000000 00000000 00000000 00000000 00000000 00000000 00000011
  01100000 00000000 00000000 00000000 00000000 00000000 00000000 00000000
  00010000 00010000
```

This example for [Firmware view](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.08.08_Firmware_view.md>) queries the first two cycles where failures have occurred on an output pin of the default port, that is, on any configured output pin. Note: For the query, you must use the prefix $ so that the binary data are represented by ASCII 1 or 0.

The answer is to be interpreted as follows:

- `FFCI 2,7` means that 2 cycles are reported and 7 output pins are configured. Since this entails that one byte is sufficient for the pin data, the binary data needs only one byte for the pin data consists of 2 * 9 bytes.
- `#218` defines the size of the following binary data: 2 digits for the length specifier followed by the length specifier itself that indicates a length of 18 for the binary data.
- The Firmware view displays the cycle numbers and pin data as groups of eight bytes that must be evaluated as follows:

  - Failed cycle # 3:

    - The cycle number 3 is defined by the first eight address bytes `0000000` … `00000011`.
    - The 9th byte `01100000` shows failures on the 2nd and 3rd pin: Value 0 of the MSB on the left represents the passing 1st pin.

  - Failed cycle # 16:

    - The next eight bytes 10 …17 (`00000000` … `00010000`) define the cycle number 16.
    - The last byte 18 (`00010000`) shows that the fourth pin failed.

For the assignment from bits of the pin data bytes to the configured pins, refer to [#spec(data)](<02.06.02.02.122_FFCI__-__First_Failed_Cycle_Information.md#_98603__r_specData>), the [following example](<02.06.02.02.122_FFCI__-__First_Failed_Cycle_Information.md#_98603__d_Example_2>) and to firmware command [FFPM? (First Failing cycle information Pin Mapping)](<02.06.11.02.24_FFPM___First_Failing_cycle_information_Pin_Mapping.md>).

The FFCI? command can also be executed using API [FW_TASK](<../02.07_Test_Method_Reference/02.07.04.01.77_FW_TASK.md>). You must use the syntax `FWTASK_STATUS FW_TASK(const STRING& command, FW_ResultData & resultdata);` to retrieve the binary data.

### Example 2: Sort order of pins

The pogo numbers of the following example setup are assigned in descending order to emphasize that the order of the pogo numbers and not the order of the definition by [DFPN](<02.06.02.02.63_DFPN__DFPN__-__DeFine_Pin_Name.md>) matters.

```
DFPN 11105,"",(pinA)
DFPN 11104,"",(pinB)
DFPN 11103,"",(pinC)
DFPN 11102,"",(pinD)
DFPN 11101,"",(pinE)
CONF IO,F160,(pinA)
CONF I,F160,(pinB,pinC)
CONF O,F160,(pinD,pinE)
```

The FFCI? command will sort I / IO pins based on their pogo number defined for the first site resulting in the pin list pinE, pinD, pinA. The two pins pinB and pinC have no output capability and, therefore, will not be included in the FFCI? answer.

Assuming a test has been executed where pinA passes, but pinD and pinE fail for every cycle, the FFCI? answer for the first two failing cycles now would look like this:

```
FFCI? 2
FFCI 2,3,#218
  00000000 00000000 00000000 00000000 00000000 00000000 00000000 00000000
  11000000 00000000 00000000 00000000 00000000 00000000 00000000 00000000
  00000001 11000000
```

 The binary data of the answer is to be interpreted as follows:

- Byte 1 …8: Address of the first cycle (`00000000` … `00000000` = 0)
- Byte 9: Pin data `11000000`
- Byte 10 …17: Address of the second cycle (`00000000` … `00000001` = 1)
- Byte 18: Pin data `11000000`

Byte 9 and 18 show that the first two pins on the left side (MSB) are failing. According to the sorting scheme that is defined in the FFCI parameter description for [#spec(data)](<02.06.02.02.122_FFCI__-__First_Failed_Cycle_Information.md#_98603__r_specData>), the failed pins are pinE (Channel 11101 and pinD (Channel 11102).

The [FFPM?](<02.06.11.02.24_FFPM___First_Failing_cycle_information_Pin_Mapping.md>) firmware command will return `FFPM 3,(pinE,pinD,pinA)` as pinE, pinD and pinA are configured for the I / IO mode. The pin list is sorted by the pogo number defined for the first site.
