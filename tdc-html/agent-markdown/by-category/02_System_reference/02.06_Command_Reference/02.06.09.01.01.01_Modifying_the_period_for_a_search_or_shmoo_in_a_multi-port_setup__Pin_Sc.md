# Modifying the period for a search or shmoo in a multi-port setup (Pin Scale)

Both shmoo tests and parallel searches can be based on modification of spec variables. When this spec variable is used in the definition of the tester period, the period length should be modified in each step according to the step width of the search or shmoo plot definition. If, however, the test is performed on a Pin Scale system, and the port on which the search or measurement is to be performed is not the first port within the timing specification, this requirement will usually not be met in a standard multi-port setup.

The reason for this is that on a Pin Scale system, the periods of all ports must be an integer multiple of the period resolution, and that in a standard multi-port setup, the period resolution will be determined by the period of (timing set 1 of) the first port in the order of the specification. If the period lengths of the other ports are not directly divisible by this period resolution, they will be auto-corrected accordingly, and if this happens to the search/shmoo port, the search or shmoo measurement will be spoiled.

With a shmoo test, SmarTest avoids this problem by automatically deriving the period resolution from (timing set 1 of) the shmoo port while the shmoo test is running. With a parallel search, you can tell SmarTest to derive the period resolution from the search port. Note that in both cases, this will actually be done only if necessary, that is, if the spec variable used by the shmoo or search actually occurs in the definition of the tester period in timing set 1. If not, the period resolution will be derived from the standard port.

## Example

Suppose that there are two ports, P1 and P2. Let P1 be the first port within the specification, and P2 the port on which a parallel search is to be executed. Assume further that the period of P2 is set to the spec variable of the search. Finally suppose that the period length P1 is 15 ns, that of P2 as set with the spec variable is 10 ns, and that the step width of the search is 0.5 ns. Then the period resolution will be 5 ns. Now if the spec variable is incremented by 0.5 in the second search step, the period resolution will not change, and since 10.5 ns is not be an integer multiple of 5, the period of P2 will be auto-corrected to 10 ns. Thus, the search will be pointless.

If, however, the period resolution is derived from P2, it will be recalculated from 5 ns to 5.25 ns for the second search step, and the search will be executed with the requested period. When the search is finished, the period resolution will be reset to the value determined by the first port within the specification.
