# SPRM, SPRM? - (Set PRiMary sets)

The SPRM (Set PRiMary sets) command is used to define and change the primary sets in a test suite or a test that is defined in a user procedure. If, for example, your test involves repeating a functional test with varying parameters, you can use the SPRM command to define the primary sets for each test run. Unless otherwise specified, the functional test uses the parameters defined in the actual primary sets.

The primary sets include:

- A timing equation set and spec set (equation based testing)
- A multi-port specification (in a multiport setup)
- A waveform set (non-equation based testing)
- A timing set, or (in a multiport setup) a timing set list
- A level equation set, level spec set, and level set (equation based testing)
- A level set (non-equation based testing)
- A DPS set

This command does not activate primary sets in the hardware - see [APRM, APRM? - (Activate PRiMary sets)](<02.06.02.02.03_APRM_-__Activate_PRiMary_sets.md>).

The commands in the following list also depend on the SPRM command, however, they do not need the [APRM](<02.06.02.02.03_APRM_-__Activate_PRiMary_sets.md>) command in advance.

- [FTST? - (Functional TeST)](<02.06.02.02.127_FTST__-__Functional_TeST.md>)
- [RCLS? - (ReCeive Level Sensitivity)](<02.06.02.02.203_RCLS__-__ReCeive_Level_Sensitivity.md>)
- [SQST, SQST? - (SeQuencer STate)](<02.06.02.02.241_SQST__SQST__-__SeQuencer_STate.md>)
- [PSST, PSST? - (Power Supply STatus)](<02.06.02.02.198_PSST__PSST__-__Power_Supply_STatus.md>)Note If some of the specified sets do not exist, SPRM may issue an error message. But it will always store the values that were passed to it, even if it has detected that (some of) these values do not identify an existing set.

## Equation Based Testing:

In an equation based timing or level setup, you must identify a spec set ID, level set ID and DPS set ID instead of waveform set number, level set number and DPS set number.

The spec set is identified through specset_id, which is calculated from the timing equation set number and the timing spec set number as follows:

```
specset_id = 100 * equation_set_no + specset_no
```

The appropriate wavetable is determined by looking at which wavetable is referenced by equation_set_no and specset_no in the Timing Specification File.

Level set ID is calculated from the level equation set number, level spec set number and level set number as follows:

```
100000 * equation_set_no + 1000 * specset_no + level_set_no
```

DPS set ID is calculated from the level equation set number and level spec set number as follows:

```
100000 * equation_set_no + 1000 * specset_no + 1
```

## SPRM

```
SPRM [waveform_set_no], [timing_set_no], [level_set_no|level_set_id], [dps_set_no|dps_set_id]
```

or:

```
SPRM {timing_specset_id}, [timing_set_no], [level_set_no|level_set_id], [dps_set_no|dps_set_id]
```

or, for multiport specifications:

```
SPRM {"multi-port_spec"}, [timing_set_no|"timing_set_list"], [level_set_id|level_set_no],[dps_set_id|dps_set_no] [,(port)]
```

## SPRM?

```
SPRM?
```

returns:

```
SPRM {waveform_set_no}, {timing_set_no}, {level_set_no|level_set_id}, {dps_set_no|dps_set_id}
```

or:

```
SPRM {timing_specset_id}, {timing_set_no}, {level_set_id|level_set_no}, {dps_set_id|dps_set_no}
```

or, for multiport specifications:

```
SPRM? [(port)]
```

returns:

```
SPRM {"multi-port_spec"}, {timing_set_no|"timing_set_list"}, {level_set_id|level_set_no},{dps_set_id|dps_set_no} [,(port)]
```

## Parameters

 |

waveform_set_no

 |

The identification number of the waveform set. Enter an integer in the range 1 to the maximum number of allowed waveform sets. The maximum number is determined by [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>). The number you enter must also be less than or equal to the maximum number of waveform sets allowed - as defined by [CONF, CONF? - (CONFiguration)](<02.06.02.02.31_CONF__CONF__-__CONFiguration.md>).

 |
 |

timing_specset_id

 |

Derived as follows:

`100 * equation_set_no + specset_no`

Note that the spec set ID also identifies the primary wavetable in equation based testing.

 |
 |

multi-port_spec

 |

For a multi-port setup, specify a primary multi-port specification.

 |
 |

timing_set_no

 |

The identification number of the timing set. Enter an integer in the range 1 to the maximum number of allowed timing sets (of the selected waveform set or timing specification). The maximum number is determined by [TSUS, TSUS? - (Timing Sets USed)](<02.06.02.02.283_TSUS__TSUS__-__Timing_Sets_USed.md>). The number you enter must also be less than or equal to the maximum number of timing sets allowed (as defined by [DSCP](<02.06.02.02.90_DSCP__DSCP__-__Define_System_Control_Parameter.md>)).

In a multiport setup, the timing set number applies to all ports of the specification if you do not specify a port. If you do, the number applies to the specified port.

 |
 |

timing_set_list

 |

In a multi-port setup, you can specify primary timing sets for all ports of the specification by entering a list of numbers separated by commas. The order of the timing sets must correspond to the order of the ports in the multi-port timing specification.

In the query, the numbers of the primary timing sets are returned in a list for all ports of the primary specification unless the numbers are identical for all ports or a port has been specified in the query.

 |
 |

level_set_no

 |

The identification number of the level set. Enter an integer in the range 1 to the maximum number of allowed level sets. The maximum number is determined by [LSUS, LSUS? - (Level Sets USed)](<02.06.02.02.155_LSUS__LSUS__-__Level_Sets_USed.md>). The number you enter must also be less than or equal to the maximum number of level sets allowed (as defined by [DSCP](<02.06.02.02.90_DSCP__DSCP__-__Define_System_Control_Parameter.md>)).

 |
 |

dps_set_no

 |

The identification number of the DPS set. Enter an integer in the range 1 to the maximum number of allowed DPS sets. The maximum number is determined by [DSUS, DSUS? - (Dps Sets USed)](<02.06.02.02.91_DSUS__DSUS__-__Dps_Sets_USed.md>). The number you enter must be less than or equal to the maximum number of DPS sets allowed (as defined by [DSCP](<02.06.02.02.90_DSCP__DSCP__-__Define_System_Control_Parameter.md>)).

 |
 |

level_set_id

 |

Derived as follows:

`100000 * equation_set_no + 1000 * specset_no + level_set_no`

 |
 |

dps_set_id

 |

Derived as follows:

`100000 * equation_set_no + 1000 * specset_no + 1`

 |
 |

port

 |

In a multiport setup, you can specify a port of the specification that was entered as the first parameter. In this case, the timing set number specified as the second parameter will only be applied to the specified port. The port parameter is ignored if a timing set list is specified.

 |

## Application

Defines the primary sets for a test.

AC tests.

DC measurements, see [DC Measurement Commands](<02.06.10_DC_Measurement_Commands.md>).

## Errors

An error is generated if:

- The set number given is greater than the maximum number allowed by the [DSCP](<02.06.02.02.90_DSCP__DSCP__-__Define_System_Control_Parameter.md>) (Define System Control Parameter) command (the specified set is not configured), or the equivalent for equation based tests where a spec number is out of the allowed range.
- specset_id is invalid because equation_set_no, specset_no, or both are invalid.
- specset_id does not reference a defined wavetable.
- level_set_id does not describe a defined equation set, spec set or level set.
- dps_set_no is undefined or out of range.
- dps_set_id does not describe a defined equation set or spec set.

## Example

The following example shows how to define and query primary timing sets for the multi-port specification spec_ClockP_P1_P2, which contains three ports:

```
> SPRM "spec_ClockP_P1_P2","2,1,2",,
> SPRM?
< SPRM "spec_ClockP_P1_P2","2,1,2",101002,101003
> SPRM "spec_ClockP_P1_P2",2,,,(port_1.CP_1)
> SPRM?
< SPRM "spec_ClockP_P1_P2",2,101002,101003
> SPRM? (port_1.CP_1)
< SPRM "spec_ClockP_P1_P2",2,101002,101003,(port_1.CP_1)
```
