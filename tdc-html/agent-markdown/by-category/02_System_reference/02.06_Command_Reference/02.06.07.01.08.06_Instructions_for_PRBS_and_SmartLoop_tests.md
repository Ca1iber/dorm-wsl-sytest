# Instructions for PRBS and SmartLoop tests

On the PS9G and PS1600 cards, you can execute a PRBS (Pseudo Random Bit Sequence) or a SmartLoop™test (for background information see [Commands for PRBS and SmartLoop tests](<02.06.17_Commands_for_PRBS_per_pin_tests_and_loopback_tests.md>)). Each of these is triggered by a dedicated sequencer instruction. If a pattern (label) contains such an instruction the only other instructions that are allowed in it (except the obligatory STVA, STSA, and STOP instructions) are

- BRKV

This instruction can be used to program an initial delay before a PRBS test starts.

- TMUA

This instruction serves to arm the TMU per pin from within a pattern. This allows you to execute a TMU measurement in parallel with a SmartLoop™or PRBS test.

Note that TMUA arms the TMU per pin on the port level, namely for the port to which the pattern belongs. Therefore, a TMU configuration must be present for all port pins in this case.

- LBGN / LEND

This instruction can be used to repeat a block containing a TMUA instruction within a PRBS test (not a SmartLoop™test).

 Note The PRBS checker can only start and stop at a 32 cycle boundary. If the number of break vectors at the start of the pattern is not a multiple of 32, the PRBS test checker skips the received data up to the next multiple of 32.

The instruction for a PRBS test is PRBS. The number of cycles is specified with param_1. param_2 can also be specified. It will be multiplied with param_1. In this way, the maximum number of cycles you can request is considerably increased.

The instruction for a SmartLoop™test is LPBK. The number of cycles can be specified with param_1. param_2 can also be specified. It will be multiplied with param_1. If you omit both parameters, then the behavior of the SmartLoop™test depends on whether ports without loopback pins exist in the start label. If so, the SmartLoop™test will run until all ports without loopback pins have finished their test. If all pins are loopback pins, the test will start, but stop at once.

You can trigger a TMU measurement with TMUA more than once in a PRBS or SmartLoop™pattern. In this case, take care that LPBK is called without any parameters only as the last instruction before STOP, since any further instructions will be never be executed.

Since the waveforms for a PRBS test or a SmartLoop™ test are created internally, and the order in which they are applied is defined by the connection polynomial (PRBS) or the received data (SmartLoop™, such a test does not require a user defined sequence of waveform DC/DC power units. Therefore the vector area address specified with the STVA instruction is ignored in both PRBS and SmartLoop™tests.

## Examples

### Example 1

The following is the sequencer program of a PRBS test.

```
> SQPG? "prbs_test",(@)
< SQPG 0,STVA,0,,,(@)
< SQPG 1,STSA,,,,(@)
< SQPG 2,BRKV,200,0,,(@)
< SQPG 3,LBGN,100,,,(@)
< SQPG 4,TMUA,,,,(@)
< SQPG 5,PRBS,2147483647,4095,,(@)
< SQPG 6,LEND,,,,(@)
< SQPG 7,STOP,,,,(@)
```

This example combines a PRBS test with a TMU per pin measurement. Note that the TMUA instruction is included in a loop. Note also that the first parameter of PRBS is set to its maximum value 2^31 - 1, and that the number of cycles is increased above this maximum by multiplication with the second parameter, which is also set to its maximum value 2^12 - 1.

### Example 2

```
> SQPG? "loopback_tmu",(@)
< SQPG 0,STVA,0,,,(@)
< SQPG 1,STSA,,,,(@)
< SQPG 2,LPBK,1000,1,,(@)
< SQPG 3,TMUA,,,,(@)
< SQPG 4,LPBK,500,1,,(@)
< SQPG 5,STOP,,,,(@)
```

This example combines a SmartLoop™test with a TMU per pin measurement.

## Functional changes

- Introduced in SmarTest 7.0.1
- SmarTest 7.1.3: New sequencer instruction TMUA for arming the TMU from a SmartLoop or PRBS test.
