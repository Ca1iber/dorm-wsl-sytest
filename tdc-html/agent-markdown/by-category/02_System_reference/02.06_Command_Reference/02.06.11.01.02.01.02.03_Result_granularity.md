# Result granularity

The result granularity parameter defines how many results are to be recorded per cycle. The possible values depend on the hardware type and on the resolution of the error code.

The minimum is 1, which means that only one global result is recorded for every cycle (cycle granularity). The maximum is 8, in which case a separate result is returned for every available receive edge (edge granularity); edges that are not used by the waveform of the cycle are recorded as Passed.

If the result granularity is 2 or 4, each result combines a sub-cycle into one Passed or Failed value. A sub-cycle (or result combination) is a subset of the available receive edges. The sub-cycles can be defined by the user. Edges that are included in a sub-cycle, but are not used by the waveform of the cycle are again considered as Passed.

If the user does not specify any sub-cycles, and the result granularity is two, the first sub-cycle combines the first 4 edges and the second sub-cycle the last 4 edges. If the result granularity is 4, the 4 sub-cycles defined by the system combine each edges n and n+1, where n is odd.

User defined sub-cycles can contain only one edge, they may contain numbering gaps, and the same edge can be included in more than one sub-cycle of a user-defined result configuration. For example, if 2 results are required, you could let the first result be generated from edges 1, 4, 6, 8, and the second from 1, 2, 3, 5, 7.

Of course, increasing the number of results per cycle will reduce the number of cycles for which information can be stored. It will therefore often be advisable to put the detailed Error Map into the external memory if you want information on the edge level.

Note that you can retrieve edge information even if you record on the cycle level. This is achieved by instructing SmarTest to perform additional shots (that is, re-executions of the test where all compare actions except one are masked for each pin) for the individual compare actions when the test fails on the cycle level. This can be done on all hardware types. For more information see [Retrieving edge information by repeating the test](<02.06.11.01.02.02.01_Retrieving_edge_information_by_repeating_the_test.md>).
