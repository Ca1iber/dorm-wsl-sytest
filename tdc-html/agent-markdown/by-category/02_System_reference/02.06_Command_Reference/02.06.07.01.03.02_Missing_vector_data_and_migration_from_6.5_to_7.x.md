# Missing vector data and migration from 6.5 to 7.x

When the sequencer program of a pattern (label) contains vector generating instructions (GENV, RPTV), these instructions are carried out on all pins of the label port. The DC/DC power units of the waveforms that are to be applied successively to one of these pins are stored in a segment of its vector area. The waveform DC/DC power units are downloaded from the vector setup file with the VECD or VECC firmware commands.

SmarTest issues an error message if no complete vector data is present for a pattern on any pin of the pattern port. It also always issues a warning if the specified vector data is incomplete on some pin (even if complete vector data exists on all the remaining pins).

 Note SmarTest also issues a warning in the converse case, that is, if vector data exists for a pin that is not included in the pattern port. This can happen, for example, with the pattern files of a vector setup that is based on a pattern master file, because each of these pattern files contains only one pattern.

But if complete vector data is defined for a pattern on one or more pins of the pattern port, and no vector data at all for the remaining pins, SmarTest assumes that this omission is deliberate and accepts the setup. However, to make use of this behavior is not recommended for the following reasons:

If no vector data exists for a pattern on some pin, then the actual content of its label specific vector area segment will depend on the history of the current SmarTest session, that is, it will be basically undetermined. But the vector generating instructions will still assume that this segment contains the DC/DC power units of the waveforms that they are to generate, and act on this information. Therefore, the waveform sequence for this pin will also be undetermined.

In particular, the fact that you did not download vector data for a pin does not ensure that nothing will be done on it. The content of the vector area can be such that when interpreted as a sequence of waveform DC/DC power units, it actually points to waveforms that are defined in the primary wavetable. If this is the case, the test can easily be adulterated.

This problem is aggravated when you load a 6.5 setup with incomplete vector data into a 7.x release. As long as you use the 6.5 software to load such a setup, and the session history before the actual loading is always the same, the complication described above may be avoided, if only accidentally. But with release 7.0, the vector area layout has fundamentally changed (see [From global to port specific vector areas: Migration and compatibility](<02.06.07.01.03.01_From_global_to_port_specific_vector_areas__Migration_and_compatibility.md>)). Therefore the locations of the vector areas in the memory may be different in these two releases. But then the vector area content of a pin for which no vector data is downloaded may also differ on release 7.x as compared with release 6.5.

The appropriate way to exclude certain pins from the vector setup is to utilize SmarTest's multi-port feature as follows:

- Put the idle pins, for which no vector data is to be downloaded, into a separate port.
- Create a multiport timing specification that includes a timing setup for this port.
- Create a multiport burst that does not include this port.

When a test is executed with this timing specification and multiport burst, the sequencers of the idle pins will be started, but then will immediately pass into the BREAK state and feed the pins with break vectors until the end of the test. For more information see [Incomplete multi-port setups](<02.06.07.01.08.05.03.02.02_Incomplete_multi-port_setups.md>).
