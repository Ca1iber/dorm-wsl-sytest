# Using the Error Maps

#### Subtopics

- [Configuring the Error Map recording](<02.06.11.01.02.01_Configuring_the_Error_Map_recording.md>)
- [Reporting the results](<02.06.11.01.02.02_Reporting_the_results.md>)

The Error Map is used by SmarTest to record information about failing test cycles. This forms the basis for the analysis of the test results. In fact, SmarTest provides two Error Maps, a detailed and an overview Error Map. The detailed Error Map provides information on the cycle or even the edge level. The overview Error Map combines multiple cycles into one result, which is Failed if at least one of the cycles failed. It can be operated in two modes. You can specify a fixed number of cycles that are to be represented by one bit, or you can request one result for every main pattern of a (single-port or multi-port) burst; this latter option allows you to identify the failing patterns of a burst.

Both of these Error Maps are located within the test processor. But the detailed Error Map can also be located in the external memory. But by default, the internal Error Map is used.

The firmware commands for managing the Error Maps can be divided into two main groups. The commands of the first group define what is recorded. The commands of the second group define what is reported. Of course, everything that is reported must have been recorded, but the recorded data can be filtered and formatted in different ways for the reports.
