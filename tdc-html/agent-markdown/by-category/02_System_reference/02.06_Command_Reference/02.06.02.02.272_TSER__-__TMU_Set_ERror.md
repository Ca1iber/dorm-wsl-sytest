# TSER? - (TMU Set ERror)

The TSER? query returns possible errors that have occurred during the last TMU measurement.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
TSER? {(pinlist)}
```

returns:

```
TSER {VDL_OVERRUN|ARM_OVERRUN|OUT_OF_MEMORY|GLITCH_OVERRUN|NOT_FINISHED}, {(pinlist)}
```

## Parameters

 |

VDL_OVERRUN

 |

The sample rate of the TMU is exceeded.

 |
 |

ARM_OVERRUN

 |

The TMU is re-armed before all the requested samples have been taken in the preceding measurement execution.

 |
 |

OUT_OF_MEMORY

 |

The embedded processor has run out of memory.

 |
 |

GLITCH_OVERRUN

 |

An event that should appear in the prescaler output occurs before the positive pulse representing the previous such event is terminated. See [Dealing with very high frequencies](<02.06.13.01.05_Dealing_with_very_high_data_rates.md>).

 |
 |

NOT_FINISHED

 |

The measurement has not been finished.

 |
 |

pinlist

 |

The pins for which the state of the TMU measurement is to be returned.

 |

## Application

TMU per pin measurements.

## Example

```
> TSER? (Pin1)
< TSER ARM_OVERRUN,(Pin1)
```

## Functional changes

- Introduced in SmarTest 7.1.0
