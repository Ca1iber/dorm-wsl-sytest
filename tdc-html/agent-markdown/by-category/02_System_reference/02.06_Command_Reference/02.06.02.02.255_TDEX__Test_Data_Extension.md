# TDEX (Test Data Extension)

The TDEX command encapsulates context data for a test label. The encapsulated data has the form of an XML data set.

The TDEX command has no effect during the execution of a label. It is intended to provide useful information for tools reading or manipulating the vector label.

## Syntax

Italic text in the syntax descriptions below indicates meta-syntax, as described in [Syntax conventions](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.01.02_Syntax_conventions.md>).

## Firmware command

The TDEX firmware command has a few parameters in addition to the XML data:

```
TDEX "::pattern::mtl::hsm",<label>,#<length><?xml version="1.0" encoding="ISO8859-1" standalone="no" ?>
<contextData>
```

The individual parameters have this meaning:

- `"::pattern::mtl::hsm"`: This is a fixed string that describes the type of TDEX command.
- <label>: This is the name of the per-pin subroutine, enclosed in quotes.
- `#`: The crosshatch is a required charater that marks the start of the data section.
- <length>: This is the length of the data section. The first character gives the number of digits in the length specifier (a maximum of nine digits).

A data section of 512 characters could thus be specified by, for example, `3512` or `9000000512`. Note that the length specifier itself is not counted when the length of the data section is determined.

- `<?xml version="1.0" encoding="ISO8859-1" standalone="no" ?>`: This is a fixed string that must always be present in exactly this form.
- <contextData>: This is the context data in XML form, as described below.

Note that this data usually takes up multiple lines.

## Context data

```
<testDataExtension
                   xsi:noNamespaceSchemaLocation="TestDataExtension.xsd">
  <pinMap>
    <pin id=<pinID>[ name=<pinName>][ xmode=<pinXmode>][ system=<value>][ optional=<value>] >
[ <capabilities>
        <digital refInsertionCtrl=<refreshType> />
      </capabilities> ]
    </pin>
...
  </pinMap>
[ <mtlPattern>
    <sourceFiles>
      <apgFile name=<apgFilePath> />
    </sourceFiles>
[ <setupConfiguration>
[ <scramble name=<scrambleName> /> ]
[ <bitInversion name=<bitInversionName> /> ]
[ <bitOrdering name=<bitOrderingName> /> ]
[ <dbi name=<dbiName> /> ]
[ <crc name=<crcName> /> ]
    </setupConfiguration> ]
[ <deviceMaintenance>
[ <refresh>
        <timer id=<timerId>
               timerMode=<timerMode>
               intervalMode=<intervalMode>
               refreshCtrl=<refreshCtrl> />
...
      </refresh> ]
    </deviceMaintenance> ]
[ <consistencyCheck>
      <sequencerProgram checkSum=<checkSum> />
    </consistencyCheck> ]
[ <reconstruction>
      <pins>
        <pin id=<pinId> />
...
      </pins>
    </reconstruction> ]
[ <errorCorrection>
      <layer id=<layerId> type=<layerType> >
        <bus>
          <pins>
            <pin id=<pinId> />
...
          </pins>
          <flags>
            <pin id=<pinId> />
          </flags>
        </bus>
...
      </layer>
    </errorCorrection> ]
    <compilation>
      <options expansionSize=<expansionSize>
               limitVariableScope=<limitScope>
               reconstructionLevel=<reconstructionLevel>
               reusableMaintenance=<reuse>
               wavetableGeneration=<generateWavetable> />
    </compilation>
  </mtlPattern> ]

</testDataExtension>
```

## Parameters

The attributes used in the XML data, grouped by element (elements are in alphabetical order):

 |

apgFile

 |

name: <apgFilePath>, a string, is the path to the compiled [APG program file](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.03_APG_program_file.md>).

 |
 |

bitInversion

 |

name: <bitInversionName>, a string, is the name of the bit inversion setting used.

See the discussion of :bitInversion: in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

 |
 |

bitOrdering

 |

name: <bitOderingName>, a string, is the name of the bit oderingsetting used.

See the discussion of :bitOrdering: in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

 |
 |

crc

 |

name: <crcName>, a string, is the name of the cyclic redundancy check setting used.

See the discussion of :crc: in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

 |
 |

dbi

 |

name: <dbiName>, a string, is the name of the data bus inversion setting used.

See the discussion of :dbi: in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

 |
 |

digital

 |

refInsertionCtrl: <refreshType>, a string, is the type of refresh insertion control on the pin. Supported types include:

- SEQ
- SEQUENCER
- VEC
- VECTOR

For an explanation of the refresh insertion control types, see the discussion of using interrupCtrl in [Pin mapping file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.06.01_Pin_mapping_file_syntax.md>).

 |
 |

layer

 |

- id: <layerId>, an integer, is the unique ID of the layer being defined.
- type: <layerType>, a string, is the type of operation applied by the layer, crc (cyclic redundancy check) or dbi (data bus inversion).

See [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

The order of the layer elements within the errorCorrection element determines the order in which the error correction operations are applied.

 |
 |

options

 |

- expansionSize: <expansionSize>, an integer, is the expansion size setting used for the compilation.

See the description of the -e option in [apgc command syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.02.05.01_apgc_command_syntax.md>) for details.

- limitVariableScope: <limitScope>, a boolean, is the setting of the variable scope limitation:

  - "true": Limited variable scope was active for compilation.
  - "false": Extended variable scope was active for compilation.

See the description of the -evs and -lvs options in [apgc command syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.02.05.01_apgc_command_syntax.md>) for details.

- reconstructionLevel: <reconstructionLevel>, a string, is the reconstruction level with which the label was compiled.

See the description of the -r0, r1, and r2 options in [apgc command syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.02.05.01_apgc_command_syntax.md>) for details.

- reusableMaintenance: <reuse>, a boolean, is the setting whether the label has been compiled as a reusable maintenance operation.

See the description of the -m option in [apgc command syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.02.05.01_apgc_command_syntax.md>) for details.

- wavetableGeneration: <generateWavetable>, a boolean, is the setting whether new waveforms have been generated during the compilation.

See the description of the -w option in [apgc command syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.02.05.01_apgc_command_syntax.md>) for details.

 |
 |

pin

 |

- id: <pinId>, an integer, is the unique ID of the pin being defined or referenced. If this <pin> element is a reference, the value of the id attribute must match one of the pins defined in the <pinMap> element.
- name: <pinName>, a string, is the name of the pin being defined. This attribute is optional.
- xmode: <pinXmode>, a string, is the xmode of the pin being defined. This attribute is optional.

See the description of the xmode pin attribute in [Pin mapping file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.06.01_Pin_mapping_file_syntax.md>) for details.

- system: <value> can be true or false. The default value is false. If system = true, SmarTest will generate corresponding programs for those pins (system generated). No vector data will be generated for those pins by MTP.
- optional: <value> can be true or false. The default value is false. If optional = true, even this pin is not defined in the pin configuration file, SmarTest will skip this pin and run the relative MTL patterns without warning.
 |
 |

scramble

 |

name: <scrambleName>, a string, is the name of the scrambling setting used.

See the discussion of :scramble: in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details.

 |
 |

sequencerProgram

 |

checkSum: <checkSum>, an integer, contains the checksum of the label as calculated by the MTL compiler.

 |
 |

timer

 |

- id: <timerId>, an integer, is the unique ID of the maintenance settings being defined.
- timerMode: <timerMode>, a string, is the name of the pin being defined. This attribute is optional.

See the description of the :timerMode: keyword in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details

- intervalMode: <intervalMode>, a string, is the interval mode defined for this refresh operation setting.

See the description of the :intervalMode: keyword in [Device architecture file syntax](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.05.01_Device_architecture_file_syntax.md>) for details

- refreshCtrl: <refreshCtrl>, a string, reflects the refresh control settings with which the label has been compiled:

  - start: The REFRESH_CTRL(START) command has been used.
  - none: The REFRESH_CTRL(START) command has not been used, but refresh is enabled.

If refresh has been disabled and the REFRESH_CTRL(START) command has not been used, there is no refreshCtrl attribute at all.

The REFRESH_CTRL function is described in [Macros and functions in program files](<../02.12_Memory_Test_Plus_7.10.2/02.12.03.03.03.01.08_Macros_and_functions_in_program_files.md>).

 |

## Example

```
TDEX "::pattern::mtl::hsm","myLabel",#9000003254<?xml version="1.0" encoding="ISO8859-1" standalone="no" ?>
<testDataExtension
                   xsi:noNamespaceSchemaLocation="TestDataExtension.xsd">

  <pinMap>
    <pin id="0" name="pin0" xmode="2">
      <capabilities>
        <digital refInsertionCtrl="VEC"/>
      </capabilities>
    </pin>
    <pin id="1" name="pin1" xmode="4">
      <capabilities>
        <digital refInsertionCtrl="SEQ"/>
      </capabilities>
    </pin>
    <pin id="2" name="pin2" xmode="6">
      <capabilities>
        <digital refInsertionCtrl="SEQ"/>
      </capabilities>
    </pin>
    <pin id="3" name="pin3" xmode="8">
      <capabilities>
        <digital refInsertionCtrl="VEC"/>
      </capabilities>
    </pin>
    <pin id="4" name="pin4">
      <capabilities>
        <digital refInsertionCtrl="SEQ"/>
      </capabilities>
    </pin>
    <pin id="5" name="pin5" xmode="4">
      <capabilities>
        <digital refInsertionCtrl="SEQ"/>
      </capabilities>
    </pin>
  </pinMap>

  <mtlPattern>
    <sourceFiles>
      <apgFile name="/data/device/mts/pattern_defs/apg_file_name_create.apg"/>
    </sourceFiles>
    <setupConfiguration>
      <scramble name="scramble_1"/>
      <bitInversion name="bitInversion_1"/>
      <bitOrdering name="bitOrdering_1"/>
      <dbi name="dbi_1"/>
      <crc name="crc_1"/>
    </setupConfiguration>
    <deviceMaintenance>
      <refresh>
        <timer id="0" intervalMode="accumulated" refreshCtrl="none" timerMode="dynamic"/>
        <timer id="1" intervalMode="compensated" refreshCtrl="start" timerMode="static"/>
        <timer id="2" intervalMode="accumulated" refreshCtrl="none" timerMode="static"/>
        <timer id="3" intervalMode="unknown" refreshCtrl="start" timerMode="unknown"/>
      </refresh>
    </deviceMaintenance>
    <consistencyCheck>
      <sequencerProgram checkSum="21845"/>
    </consistencyCheck>
    <reconstruction>
      <pins>
        <pin id="0"/>
        <pin id="1"/>
        <pin id="2"/>
      </pins>
    </reconstruction>
    <errorCorrection>
      <layer id="0" type="dbi">
        <bus>
          <pins>
            <pin id="0"/>
            <pin id="1"/>
            <pin id="2"/>
          </pins>
          <flags>
            <pin id="3"/>
          </flags>
        </bus>
        <bus>
          <pins>
            <pin id="10"/>
            <pin id="11"/>
            <pin id="12"/>
          </pins>
          <flags>
            <pin id="13"/>
          </flags>
        </bus>
      </layer>
      <layer id="1" type="other">
        <bus>
          <pins>
            <pin id="100"/>
            <pin id="101"/>
          </pins>
          <flags>
            <pin id="103"/>
          </flags>
        </bus>
        <bus>
          <pins>
            <pin id="110"/>
            <pin id="111"/>
          </pins>
          <flags>
            <pin id="113"/>
          </flags>
        </bus>
      </layer>
    </errorCorrection>
    <compilation>
      <options expansionSize="100"
               limitVariableScope="false"
               reconstructionLevel="2"
               reusableMaintenance="true"
               wavetableGeneration="false"/>
    </compilation>
  </mtlPattern>

</testDataExtension>
```
