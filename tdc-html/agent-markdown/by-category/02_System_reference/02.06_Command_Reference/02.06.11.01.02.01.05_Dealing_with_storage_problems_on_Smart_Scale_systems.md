# Dealing with storage problems on Smart Scale systems

When you need result information on the edge level, it is usually advisable to put the detailed Error Map into the external memory, which provides much more space than the internal error map. This decision is made on the port level (with the DCRT command). But if

- all channels of an 8-channel group or 4-channel group ([Channel groups of Smart Scale cards](<../02.05_Test_Head_Cards/02.05.04.03.08_Channel_groups_of_Smart_Scale_cards.md>)) are associated with O or IO pins of such a port, and
- the tester cycle is very short,

then the amount of edge data to be written to the common channel group memory can become too large for the bandwidth of the memory. In this case, recording will be aborted, and consequently, not all requested results will be stored.

Two measures can be taken against such a recording abort:

- It is possible that all channels of a Smart Scale channel group belong to a port that has its error map in the external memory, but that you are only interested in the results of some of them. In this case you can mitigate the recording problem by directing the result data of the irrelevant pins to the internal error map. This is done with the DCEL command.

Note that the risk of an overflow of the internal Error Map is smaller on Smart Scale systems than on Pin Scale systems (see [PS1600 error map size](<../02.05_Test_Head_Cards/02.05.04.01.03.02_PS1600_error_map_size.md>)).

- If you require information on the edge level, but not for all edges, you can tell SmarTest (using the DCRM command) to record not all 8 edges, but only a subset that comprises all the edges you are interested in. This will reduce the amount of data that must be stored in the Error Map.

In particular, if you are only interested in less than 5 edges, you can tell SmarTest to record only 4 or 2 edges, since in this case, you can select the edges to be recorded with the sub_cycles parameter of DCRM. If you retrieve the result data with ERMP? or EMAP? using the resolution mode EDGE, the reply will not only return the recorded results, but will also display the edges in their correct position within the cycle (by returning a byte per cycle, where the first bit corresponds to r1, and the last to r8). For details see [EMAP? - (Error MAP)](<02.06.02.02.103_EMAP__-__Error_MAP.md>).

If recording is aborted despite these precautions, the functional test will nonetheless be completed. You can configure with the SQIB command what the system will do thereafter. There are three options:

- SmarTest issues an error message immediately after completion of the functional test. This message reports the channels, pins, and sites of all channel groups on which recording was aborted.
- SmarTest does not issue an error message immediately after completion of the test, but only if a channel which is involved in a recording abort is queried for result data. In this case again, the channels, pins, and sites of a all channel groups on which recording was aborted will be reported. This is the default.
- SmarTest does not issue any error message. If a channel of a group on which recording was aborted is queried for result data, all its cycles will be reported as failing.

This option can be used in a production environment if the result data is recorded in acquire failure mode, since if any data is recorded with this recording mode, the device must in fact have failed. Actually, recording will only be aborted in case of a massive fail on several pins belonging to the same channel group.

## Example

Suppose that the default port @ comprises 8 IO pins, `P1` through `P8`, and that all these pins are associated with a channel of the 8-channel group 10101 through 10108 on an PS1600 system. Assume further that you want edge information about r2, r4, r6, and r8 for pins `P1`, `P3`, `P5`, and `P7`. Then the following setup would minimize the risk that recording is aborted:

```
DCRT RAM,(@)
DCEL DCRT,TP,SET,(P2,P4,P6,P8)
DCRM EMAP,4,PF,"c1:2 c2:4 c3:6 c4:8",(@)
```

If you call EMAP? after completion of the test with resolution mode EDGE, you will get the values for the edges of interest in a format that also identifies their edge numbers. If, for example, all 4 edges have failed in a cycle, the result will be returned as

```
01010101
```
