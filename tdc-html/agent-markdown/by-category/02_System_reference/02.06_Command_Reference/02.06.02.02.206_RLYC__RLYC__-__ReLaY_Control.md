# RLYC, RLYC? - (ReLaY Control)

The RLYC (ReLaY Control) command controls the position of relays that connect a DUT pin to various test system resources. The RLYC? query returns the existing relay settings.

Common test system resources are addressed logically via the pin list. Thus the command always addresses the resources which are assigned to pins in your pin list.

  CAUTION When using this command in a multisite configuration, you must be careful as it can lead to incorrect binning and possible corruption of devices.

A [RLYC](<02.06.02.02.206_RLYC__RLYC__-__ReLaY_Control.md>) command that is issued after the testflow already binned one device does not only affect the still enabled device, but all devices.

At the end of the testflow, the still enabled device is disconnected and the relays are opened. But the already binned device is marked as disconnected in the shared memory already and is thus not disconnected again and the relays stay closed! This can lead to incorrect binning and possibly corruption of devices due to insertion with active levels as the relays are in a different state than expected.

Example

```
   site#1     site#2
     | |
   test1      test1
     | |
   test2      test2
   (PASS)     (FAIL) -> binned
     |        site#2 stops here
   test3      UI status is "disconnected"
   (PASS)
 |
   test4
   (PASS)
 |
   RLYC ON   <- this RLYC commands affect both site#1 and site#2(disabled site)
```

After execution of the RLYC command for site#2, the user interface still recognizes site#2 is disconnected because direct execution of the firmware does not update the user interface status. But the actual relay setting has changed to "connect" status. The relays of site#2 which are directly controlled by the firmware command are never disconnected by SmarTest at the end of the flow because the user interface status considers them to be disconnected.

Programming tip: Replace the FW_escape commands by a user procedure or test method doing a PSFC (see [PSFC, PSFC? - (Parallel Setup FoCus) (Jump Template)](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>) ) to the enabled sites only before doing RLYC and then switching back to PSFC ALL.

  Note If you use the RLYC command to open a relay while the test system is in the connected state, any tests executed subsequently do not call the Connect sequence because the connect flag is already set. This can lead to incorrect results.Note Similarly, if you use the RLYC command to close a relay while the test system is in the disconnected state, any Continuity test subsequently executed does not call the Disconnect sequence because the disconnect flag is already set. This can also lead to incorrect results.

With this command you configure setups of those sites that have the setup focus: For more information, see also: [PSFC, PSFC?](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

The command does not perform any additional consistency checks!

The Pin PMU (PPMU) is a per pin resource. The board ADC is provided once per logical channel board (16 channels) and is connected to a specific Pin PMU via a multiplexer to perform value measurements at the corresponding DUT pin. To perform such measurements, the PPMU relay is closed for the appropriate DC tests.

## RLYC

```
RLYC [pin_mode], [dc_target], [mux_setting,] {(pinlist)}
```

## RLYC?

```
RLYC? {(pinlist)}
```

returns:

```
RLYC [pin_mode], [dc_target], {(pinlist)}
```

 Note

In offline mode, the command cannot always return the correct settings of the hardware. This is especially true when hardware settings depend on pattern鈥慴ased conditional jumps and match loops.

 If SmarTest determines that the state of the hardware cannot be evaluated correctly, the message

```
WARNING: ... - reported last DC state ... may not reflect online state.
```

is issued in the ui_report window.

## Parameters

 | pin_mode |

This parameter controls per-pin relay resources. These are AC, DC and PPMU relays. pin_mode can take the following options:

 | IDLE  | Disconnects all relays |
 | AC  | Connects a DUT pin to its associated digital channel |
 | DC  | Closes the DC relay |
 | PPMU  | Closes the PPMU relay to connect the pin to the Pin-PMU |
 | ACDC  | Closes both the AC and DC relay |
 | BOTH  | Identical to ACDC |
 | ACPM |

Closes both the AC and the PPMU relay.

 |
 | DCPM  | Closes both the DC and PPMU relay |
 | ALL  | Closes all pin relays (AC, DC, PPMU) |
 | CNCT  | Special connect mode: for all I, O, IO pins AC relay closed, for all DC pins AC relay open |
 | X  | The settings of all relays remain unchanged  | |
 | dc_target |

The parameter lets you connect DC resources to the selected DUT pin. It controls the following relays:

- ISOL and GND relays on channel boards
- Pin PMU on channel boards

The dc_target parameter can be specified as an "enum" or a "string" value. The following keywords can be specified:

 | OFF  | Opens all channel board and clock board relays. |
 | PMU  | Closes the channel board PMU relay. This does not automatically connect the pin to the board ADC. |
 | EXT |

For digital DC pin:

Closes the external relays (EXT) on the clock board and ISOL and GND relays on the channel board.

For utility DC pin:

 Depends on the test system.

- Smart Scale test system: closes the EXT relay and the DUT relay on the clock board.
- EXA Scale test system: closes all relays on the utility-line card, card-cage, and test-head needed to establish a connection from the utility pogo to the external instrument.
 |
 | X  | The relays connecting the pins remain unchanged.  |   The keywords specify fixed combinations of relay settings, necessary to perform certain functions. As an alternative you can control the relays individually using the "string" entry. This has the format: "CCC", where each character "C" represents a relay on a channel board. Each character can take the value 0, 1, or X:

- 0: opens the relay
- 1: closes the relay
- X: leaves the relay unchanged

The functionality of the characters from the left to the right are as follows:

- ISOL relay on channel board
- GND relay on channel board
- PMU relay on channel board (BADC)
- EXT relay for utility lines (test system dependent)

This option, to control individual relays usin the "string" entry, is not supported for utility DC pins

 |
 | mux_setting |

This is an extra parameter that controls the input MUX of the board ADC (BADC). The following keywords can be specified:

 | MUX_VM_HIZ  | Switches the MUX to the high-impedance input of the BADC. |
 | MUX_PPMU  | Connects the BADC to the PPPMU in preparation for a dynamic pin PMU value measurement using the BADC.  | |
 | pin_list |

The pinlist parameter defines which pins are affected by the command. All pins must be configured as I, O, IO or DC pins. If more than one pin is to be included, the names must be separated by commas.

When some digital channels are configured for triggering analog modules that are shared by multiple sites in a multi-site test, you can use the special identifier @NONSHARED@ to disconnect just the resources that are not shared between configured sites. Also, you can use @SHARED@ to disconnect just the resources that are shared.

 |

## Application

Low-level relay switching.

## Errors

An error is generated if you enter an illegal parameter option.

## Example

### AC and DC examples

 |

```
RLYC IDLE,OFF,(pin)
```

   | Open all relays. |
 |

```
RLYC DC,OFF,MUX_VM_HIZ,(pin)
```

   | Close the DC relay, open all channel board relays, select the high impedance input of the board ADC. |
 |

```
RLYC ACPM,OFF,MUX_PPMU,(pin)
RLYC? (pin)
```

 |

Close both the AC and the PPMU relay, open all channel board relays, connect the board ADC to the PPMU and

 query the state of the relays. The returned state is

```
RLYC ACPM,OFF,(pin)
```

 |
 |

```
RLYC AC,,(pin)
RLYC? (pin)
```

 |

Close only the AC relay and

 query the state of the relays. The returned state is

```
RLYC AC,OFF,(pin)
```

 |
 |

```
RLYC DC,,(pin)
RLYC? (pin)
```

 |

Close only the DC relay and

 query the state of the relays. The returned state is

```
RLYC DC,OFF,(pin)
```

 |
 |

```
RLYC PPMU,,(pin)
RLYC? (pin)
```

 |

Close the PMU relay and

 query the state of the relays. The returned state is

```
RLYC PPMU,PMU,(pin)
```

 |
