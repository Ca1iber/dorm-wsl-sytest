# VRCS? - (Valid ReConStruction)

The VRCS? query determines the range of cycles that have been reconstructed.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
VRCS? {reconstr_type}, [reconstr_cond,] {(pinlist)}
```

returns:

```
VRCS [reconstr_cond,] {reconstr_state}, [reconstr_oper,] {start_cycle}, {no_of_cycles}, {(pinlist)}
```

Parameters
 |

reconstr_type

 |

The reconstruction type determines how test cycles are counted.

 |
 |

STRT

 |

Start analysis. Specifies that cycles are counted from the start of the test.

 |
 |

STOP

 |

Stop analysis. Specifies that cycles are counted from the end of the test.

 |
 |

reconstr_cond

 |

The reconstruction condition defines how VRCS? reacts to ambiguous sequencer instructions, that is, instructions that may generate a varying number of cycles from one test execution to the next. Examples for such instructions are JMPE or multiple counted match loops.

 |
 |

 |

STRD

 |

Reconstruction stops at the first ambiguous instruction. The result may be incomplete, but is reliable.

 |
 |

 |

FULL

 |

Reconstruction continues even if ambiguous instructions are present. The maximum possible number of cycles is assumed for the ambiguous instructions. The result may be complete, but possible not completely reliable.

 |
 |

pinlist

 |

Information is only returned for the pins specified in pinlist. If more than one pin is to be included, the names must be separated by a comma. pinlist can include pins configured as I, O and IO types.

 |
 |

reconstr_state

 |

This parameter returns the state of the reconstruction.

 |
 |

 |

INVL

 |

If INVL is returned, no valid cycles exist. This occurs if you have hit BREAK before any vectors are generated.

 |
 |

 |

PRED

 |

If PRED is returned, all returned values are predicted (a change to the setup has been made, but a test has not yet been executed).

 |
 |

 |

REAL

 |

If REAL is returned, all values given are values from the last executed test.

 |
 |

reconstr_oper

 |

OKAY

 |

The reconstruction was successful, no problems encountered.

 |
 |

 |

MMRV

 |

Multiple Matchloop Restriction Violation:

The reconstruction stopped at the first match loop because there are multiple match loops in the pattern, and the match loop execution counter, which is needed for the reconstruction, can only hold the count from the last match loop execution.

 |
 |

 |

JMPE

 |

The reconstruction stopped at a jump on error instruction because execution path of the sequencer is unknown (for example, whether the jump was taken or not).

 |
 |

 |

RETC

 |

The reconstruction stopped at a return conditional instruction because execution path of the sequencer is unknown (for example, whether the jump was taken or not).

 Note If you use the LMAP error map mode, [FLBL](<02.06.02.02.123_FLBL__-__Failing_LaBeLs.md>) ignores the RETC clearing flag for failures. |
 |

 |

ABRT

 |

The pattern was empty or there was an unspecified problem during the reconstruction.

 |
 |

start_cycle

 |

The start cycle is an integer which identifies the first cycle for which results exist.

 |
 |

no_of_cycles

 |

This parameter is an integer which defines the total number of valid cycles.

 |

## Application

Test results, see [Test Result Commands](<02.06.11_Test_Result_Commands.md>).

## Errors

An error is generated if:

- You send the query while the sequencer is running. There is then no result data available.
- You enter an invalid cycle range.

## Example

```
VRCS? STRT, (@)
```

returns:

```
VRCS? REAL, 0, 437621, (@)
```

This example queries the number of reconstructed cycles, counting the cycles from the start of the test. The system replies that 437,621 cycles, starting from zero have been reconstructed, based on the last performed test.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.3.1: reconsts_state can return REAL in offline mode
- SmarTest 7.3.1: New parameter reconstr_oper
