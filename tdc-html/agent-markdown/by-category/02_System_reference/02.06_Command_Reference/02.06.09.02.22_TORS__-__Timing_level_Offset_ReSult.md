# TORS? - (Timing/level Offset ReSult)

The TORS? query returns the offsets for one or more timing or level sets.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## For timing search results

```
TORS?{waveform_set|specset_id|"multiport_spec"|PRM|ALL}, {timing_set|PRM|ALL}, {edge_type|ALL}, {(pinlist)}
```

returns:

TORS {waveform_set|specset_id|"multiport_spec"|PRM}, {timing_set|PRM}, {edge_type}, {offset}, {(pin)}

## For level search results

```
TORS?{level_set_id|PRM|ALL}, , {level_type}, {(pinlist)}
```

Note The second parameter must be left empty.

returns:

```
TORS {level_set_id}, , {level_type}, {offset}, {(pinlist)}
```

Note The second parameter is left empty

## Parameters

 |

waveform_set

 |

Number of a waveform set. Enter PRM for the primary waveform set, or an integer in the range 1 to the maximum number of allowed waveform sets. The maximum number is determined by [WSUS, WSUS? - (Waveform Sets USed)](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>). For the query, you can also enter ALL for all waveform sets.

 |
 |

specset_id

 |

A specification ID (single port). It is derived as follows:

100 * equation_set_no + specset_no

 |
 |

multi-port_spec

 |

Name of a multiport specification.

Note that the multi-port specification uniquely determines an equation set for every pin of pinlist, because no pin can belong to more than one port within a multi-port specification.

 |
 |

level_set_id

 |

A level set ID. It can be:

- A fixed level set ID, which is an integer in the range of 1 to the maximum number of level sets defined with the [DSCP](<02.06.02.02.90_DSCP__DSCP__-__Define_System_Control_Parameter.md>) command.
- An equation based level set ID, which is derived as follows:

eqnset * 100000 + specset * 1000 + level_set_no

 |
 |

timing_set

 |

The timing set.

 |
 |

PRM

 |

This refers to the primary waveform set or specification, or to the primary timing set, both as defined with SPRM.

For level offset earch, This refers to primary level set.

 |
 |

ALL

 |

The offsets are returned for all fixed specifications, timing sets or level sets.

 |
 |

edge_type

 |

Possible values are:

- F: Fast drive edges
- S: Slow drive edges
- R: Receive edges
 |
 |

level_type

 |

Possible values are:

- VIH: High driver levels
- VIL: Low driver levels
- VISWING: Driver swings
- VOH: High receiver levels
- VOL: Low receiver levels
- VTH: Receiver thresholds
- VIOFFSET: Driver offsets (Both the driver high and low levels will be moved by the same values.)
- VOOFFSET: Receiver offsets (Both the receiver high and low levels will be moved by the same values.)
- VOSWING: Receiver swings
 |
 |

offset

 |

The offset for the respective type (edge type or level type) and pin. The offset is 0 if no search was executed or no value stored.

The units for voltage resources are [mV].

The units for timing resources are [ns].

 |
 |

pin

 |

A reply parameter. The pin for which the offsets are returned

 |
 |

pinlist

 |

A query parameter. The pins for which the offsets are to be retrieved.

 |

## Application

Embedded timing and level search.

## Example

```
> TORS? PRM,PRM,R,(p1)
< TORS 1,1,R,0,(p1)

> TORS? PRM,PRM,S,(p1)
< TORS 1,1,S,0,(p1)

> TORS? PRM,PRM,F,(p1)
< TORS 1,1,F,0,(p1)

> TORS? PRM,PRM,D,(p1)
< TORS 1,1,F,0,(p1)
< TORS 1,1,S,0,(p1)

> TORS? PRM,PRM,ALL,(p1)
< TORS 1,1,R,0,(p1)
< TORS 1,1,F,0,(p1)
< TORS 1,1,S,0,(p1)

> TORS? PRM,,VIL,(@)
<TORS 1,,VIL,750,(p1)
<TORS 1,,VIL,750,(p2)

> TORS? PRM,,VISWING,(@)
< TORS 1,,VIH,-450,(p1,p2)
< TORS 1,,VIL,450,(p1,p2)
```

## Functional changes

- Introduced in SmarTest 7.0.3
- SmarTest 7.2.1: Supports the query for level offsets.
