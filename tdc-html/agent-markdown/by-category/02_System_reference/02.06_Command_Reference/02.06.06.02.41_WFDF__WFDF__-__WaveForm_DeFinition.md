# WFDF, WFDF? - (WaveForm DeFinition)

The WFDF command defines a logical waveform with at most 6 edges within a waveform set (fixed timing). The WFDF? query returns the existing logical waveform definitions; note that it only retrieves the first 6 edges of the waveform.

## Mode of operation

If the specified waveform index is already in use, WFDF overwrites the previous definition. This causes all previously defined physical waveforms for this logical waveform to be undefined. You have to define all of them for the modified logical waveform again (with the [WAVE](<02.06.02.02.333_WAVE__WAVE__-__WAVEform.md>) command).

The command will not be accepted if the edge order restrictions are not fulfilled for the used edges. If the position of an unused edge does not meet the order requirements implied by the new definition string, it will be auto-corrected. Edges which are already used in other waveforms will not be moved. Edge restrictions are discussed in [Selecting and ordering edges](<02.06.06.01.03.01.02_Selecting_and_ordering_edges.md>).

## Postrequisites

After you have defined the logical waveform with WFDF, you must specify the physical waveforms that are based on it with the [WAVE](<02.06.02.02.333_WAVE__WAVE__-__WAVEform.md>) command. This is required even if the logical waveform contains no data parameters.

## WFDF

```
WFDF {wvf_set}, {wfIndex}, {a1}, {a2}, {a3}, {a4}, {a5}, {a6}, {(pinlist)}
```

## WFDF?

```
WFDF? {wvf_set|"wavetable"|specset_id|"multiport_spec"}, {wfIndex}, [mode], {(pinlist)}
```

returns:

```
WFDF {wvf_set|"wavetable"|specset_id|"multiport_spec"}, {wfIndex}, {a1}, {a2}, {a3}, {a4}, {a5}, {a6}, {(pinlist)}
```

On the expected data side the actions you can define are:

- N: No action
- E0: Edge compare to 0
- E1: Edge compare to 1
- EI: Edge compare to intermediate
- EX: Edge compare to mask
- EU: Edge compare to unstable
- C: Capture digital data (selective digital capture)
- D: Do not capture digital data (selective digital capture)

Note that waveforms that are to be used for selective digital capture must contain exactly one compare action.

- W0: Window open with compare to 0
- W1: Window open with compare to 1
- WI: Window open with compare to intermediate
- WX: Window open with compare to mask
- WU: Window open with compare to unstable

## Application

Timing setup, see [Timing Setup Commands](<02.06.06_Timing_Setup_Commands.md>).

## Errors

An error is generated if:

- wvf_set_no is greater than the range allowed by the [WSUS](<02.06.02.02.342_WSUS__WSUS__-__Waveform_Sets_USed.md>) command.
- wvf_set_no is smaller than one.
- The waveform index is outside the range of 0-31
- There is a mismatch between the edge actions and edge order in the specified waveform.
- You specify a drive action for an output pin.
- You specify a receive action for an input pin.
- There is a mismatch in edge direction between the waveform you have defined and existing waveforms.
- There is a missing window close action between two window open actions.
- There is a missing window open action between two window close actions.
- FN0 or FNZ are data parameters of edges 2 or 5, or if there is an implicit generation of a tri-state on edges 2 or 5 (tri-state error).
- specset_id is invalid because equation_set_no, specset_no, or both are invalid.
- specset_id does not reference a defined wavetable.
- multi-port_spec does not reference a defined multiport specification.

## Warnings

A warning is generated if edge delays are auto-corrected to fit in with the programmed waveform. The timing sets belonging to the affected waveform set are modified as necessary.

## Example

```
> WFDF 1,2,N,N,D11,N,N,N,(D0,D2,D2,D3)
```

This example defines a waveform referenced by waveform index 2. The waveform uses the drive data and tri-state parameter 1. Edge number 3 provides the timing for this waveform. The definitions are made for waveform set 1 and for pins D0 to D3.
