# SPST? - (SPecset STatus)

The SPST? query returns the current settings of the status bits. Most of these bits determine what kind of violation checks are performed with respect to edge order and periods when a test is executed; the check is performed when its associated bit is cleared, and omitted when it is set. The rest of the bits indicate if the timing has been modified by certain firmware commands.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Syntax

```
SPST? {spec_type}, {equation_set_no}, {specset_no}
```

returns:

```
SPST {spec_type}, {equation_set_no}, {specset_no}, {status}
```

or, for multiport specifications:

```
SPST? {spec_type}, , {"multi-port_spec"}
```

or

```
SPST? {spec_type}, PRM,
```

returns:

```
SPST {spec_type},, {"multi-port_spec"}, {status}
```

## Application

- Level setup
- Timing setup
- Testflow
- Spec tool

## Examples

### Example 1

```
> SPST? lev,all,all
< SPST LEV,1,1,0
```

### Example 2

```
> SPST? tim,all,all
<  SPST TIM,1,1,0
< SPST TIM,2,22,0
```

### Example 3

```
> SPST? TIM,,"mu_burst"
< SPST TIM,,"mu_burst",6
```

In this last example, a multi-port specification is queried. The answer says that bits 1 and 2 have been set. This has the effect that a drive or receive period 1 limit violation will be ignored, and only a period 2 limit violation will be recorded.

## Functional changes

- Introduced before SmarTest 6.3.2
