# Compression factor for overview Error Map

The overview Error Map compresses multiples of 16 cycles into one result. The compression factor is configurable. This allows you to get an overview of the whole test regardless of its size.

The overview Error Map can also be used to identify the failing main patterns of a (single-port or multi-port) burst. To this end, the compression factor of the overview Error Map must be set to BFLM (only for Smart Scale) or LMAP with the [DCRM](<02.06.02.02.46_DCRM__DCRM__-__Digital_Compare_Result_Mode.md>) command. This will have the effect that the overview Error Map returns one PASS/FAIL result for every pattern of a burst. Note that if the start pattern is not a burst, the test cannot be executed with this setting. The difference between LMAP and BFLM is that with LMAP, break vectors are inserted between the patterns, whereas this is not the case with BFLM.

 Note In LMAP mode, 8 …nbsp;15 break vectors are inserted to allow the subsequent pattern starting on a cycle position that is a multiple of 8. In BFLM mode, each pattern in the burst must generate 8 or more cycles. Note If you use the LMAP error map mode, [FLBL](<02.06.02.02.123_FLBL__-__Failing_LaBeLs.md>) ignores the RETC clearing flag for failures. Note You cannot use the LMAP error map mode for ports that contain both pins of Smart Scale generation cards and pins of EXA Scale generation cards.

The results of such a test execution can be retrieved with the following firmware queries:

- [VALD?](<02.06.02.02.316_VALD__-__VALid_Data.md>) returns the number of label calls in the burst for the specified pins.
- [ERMP?](<02.06.02.02.114_ERMP__-__ERror_MaP.md>) returns the PASS/FAIL results for a specified range of label calls.
- [GETL?](<02.06.02.02.132_GETL__-__GET_Label.md>) returns the label names for a specified range of calls.
- [FLBL?](<02.06.02.02.123_FLBL__-__Failing_LaBeLs.md>) returns the names of the failing labels for a specified cycle range.
