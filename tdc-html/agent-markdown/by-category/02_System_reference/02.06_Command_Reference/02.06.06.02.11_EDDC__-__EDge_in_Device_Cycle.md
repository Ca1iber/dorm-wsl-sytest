# EDDC? - (EDge in Device Cycle)

The EDDC? (EDge in Device Cycle) query mainly serves to determine the leading or trailing edge for a combination of a data parameter and logical device cycle. The concept of leading and trailing edge makes it possible, for example, to define a window close edge as the reference edge by specifying a data parameter.

 Note The EDDC? query is completely independent of the definitions made with [EDSP](<02.06.02.02.102_EDSP__EDSP__-__EDge_SPecification.md>), which determine the search (leading and trailing) edges for the timing searches.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

You can also use EDDC? to retrieve the logical device cycles that use a certain edge.

A response is given for each device cycle that uses the given edge number.

## Syntax

```
EDDC? [waveform_set], [timing_set], {edge_spec},
[dev_cyc_name], [dc_ref], [direction], {(pinlist)}
```

returns:

```
EDDC {edge_number}, {dev_cyc_name}, [reuse_flag], {(pinlist)}
```

## Equation Based Testing

```
EDDC? [specset_id|"multi-port_spec"],[timing_set], {edge_spec}, [dev_cyc_name], [dc_ref], [direction], {(pinlist)}
```

returns:

```
EDDC {edge_number}, {dev_cyc_name}, [reuse_flag], {(pinlist)}
```

Parameters
 |

waveform_set

 |

Specifies a waveform set number for a fixed timing setup.

 |
 |

specset_id

 |

Specifies a specset ID for an equation based setup. The specset ID is derived from an equation set number and a specset number as follows:

100 * equation_set_no + specset_no

 |
 |

multi-port_spec

 |

Specifies the name of a multi-port specification for a multi-port setup. PRM is the default value.

 |
 |

timing_set

 |

Specifies the number of the a timing set. PRM is the default value.

 |
 |

edge_spec

 |

The edge specifier can either be a physical edge (d1 through d8 or r1 through r8), or one of the data parameters D1, D2, C1, C2 (drive parameters) or E1, E2 (receive parameters).

If you specify a physical edge, the dev_cyc_name and the dc_ref parameters must be omitted.

 |
 |

edge_number

 |

In the query reply, this parameter contains the edge that is used as leading or trailing edge.

 |
 |

dev_cyc_name

 |

Specifies the name of a logical device cycle that uses the data parameter given as the edge_spec. It must be defined for all pins in pinlist. If you do not enter a name in this parameter, the first device cycle in the device cycle table is used.

 |
 |

dc_ref

 |

This parameter specifies whether the leading or the trailing edge that is associated with the specified dev_cyc_name and dc_ref parameters is to be returned. The two options are LE (for "leading edge") and TE (for "trailing edge").

The leading edge is always the first edge that is associated with the specified data parameter within the specified device cycle,

The trailing edge is determined differently for drive and receive parameters:

- Drive parameter: The trailing edge is the first drive edge after the leading edge that performs a data or tri-state action.
- Receive parameter: If the action of the leading edge is an edge compare, leading and trailing edge will be identical. If it is the start action of a window compare, then the associated window close edge is the trailing edge.
 |
 |

direction

 |

This parameter can be in or out. If in is selected to define an input edge, then the edge_spec parameter must be D1, D2, C1, or C2. If out is selected to define a receiver edge, then the edge_spec parameter must be E1 or E2. If either in or out is selected along with an edge_spec parameter of 1,2...6, then a check is performed to ensure that the edges of all pins are in the required direction. If no entry is made in this parameter, the measuring edges of the pin in pinlist can have any direction or be unused.

 |
 |

reuse_flag

 |

The reuse flag is returned by the system. A flag is returned only for the device cycle specified in the dev_cyc_name parameter of the EDDC? query, and only if D1, D2, C1, C2, E1, or E2 has been selected as the edge_spec. The reuse flag can be:

- R: The returned edge is used in another device cycle.
- N: The returned edge is not used in another device cycle.
 |
 |

pinlist

 |

The parameters of the EDDC? command are applied to all pins named in this parameter. If more than one pin is used, the names must be separated by a comma.

In a multi-port setup, all pins must belong to the same port of the specification that was entered as the first parameter.

 |

## Application

AC tests

## Errors

An error is generated if:

- The edge_spec parameter specifies a drive edge, but the direction parameter specifies a compare edge, or the other way round.
- Pins of different periods are included in the pin list.
- You select an unused edge.
- The edge direction of the selected edge is not the same for all pins in the pin list.

## Functional changes

- Introduced before SmarTest 6.3.2
