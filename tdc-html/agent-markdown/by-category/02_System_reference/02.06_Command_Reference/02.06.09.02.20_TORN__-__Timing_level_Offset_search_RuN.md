# TORN? - (Timing/level Offset search RuN)

The TORN? query executes an embedded timing or level search with the current primary timing and level according to the search conditions defined for this timing or level.

In a multi-site setup, the search will be executed for all active sites.

## Predependencies

- The timing or level search must have been configured with [TOCF](<02.06.02.02.260_TOCF__TOCF__-__Timing_Level_Offset_search_ConFiguration.md>).
- With a multi-site setup, ensure that all sites on which the search is to be executed are active (controlled with [PACT](<02.06.02.02.191_PSFC__PSFC__-__Parallel_Setup_FoCus.md>)).

## Syntax

```
TORN? {(pinlist)} [,"exec_context"]
```

Returns:

```
TORN {status}
```

## Parameters

 |

pinlist

 |

The pins for which the embedded search is to be executed. You can specify @ for all pins.

Note the difference between a list of pins and @ in a multi-site setup. In the former case, all channels that are associated with these pins must have the embedded timing/level search capability and must have been configured with TOCF. If this is not the case, TORN? will return the status FAILED. But if @ is specified, channels that do not fulfill both these conditions will simply be ignored.

 |
 |

exec_context

 |

An execution context. For more information on execution contexts see [Using execution contexts](<02.06.07.01.08.05.03.02.03_Using_execution_contexts.md>) .

 |
 |

status

 |

TORN? returns one of the following three status codes:

 |
 |

 |

SUCCEEDED

 |

The search was successfully finished for all active sites.

 |
 |

 |

FAILED

 |

The search failed for at least one channel.

 |
 |

 |

ABORTED

 |

The search was canceled by the user.

 |

## Application

Embedded timing and level search.

## Example

```
> TORN? (Pin1,Pin2)
< TORN SUCCEEDED
```
