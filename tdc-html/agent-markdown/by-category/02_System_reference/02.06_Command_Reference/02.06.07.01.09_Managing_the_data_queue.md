# Managing the data queue

#### Subtopics

- [Data transfer from the vector area to the data queue](<02.06.07.01.09.01_Data_transfer_from_the_vector_area_to_the_data_queue.md>)
- [Operation mode of the data queue](<02.06.07.01.09.02_Operation_mode_of_the_data_queue.md>)
- [How to prevent the data queue from running empty](<02.06.07.01.09.03_How_to_prevent_the_data_queue_from_running_empty.md>)

The sequencer of a pin (channel) cannot process instructions and apply a waveform to its pin at the same time. In order to supply a continuous stream of waveforms even when the sequencer is busy decoding sequencer instructions, a data queue is used. The sequencer does not apply the waveforms to the pin right away, but writes them into the data queue, and from this queue they are forwarded to the pin at the rate defined by the user period. In this way, the DUT can be fed with vectors from the queues of the individual pins while the sequencers are decoding instructions.

There are three main points that you must understand concerning the data queue, namely

- how the sequencer transfers the waveform DC/DC power units from the vector area to the data queue,
- how the data queue works, and
- how you can prevent that it runs empty.
