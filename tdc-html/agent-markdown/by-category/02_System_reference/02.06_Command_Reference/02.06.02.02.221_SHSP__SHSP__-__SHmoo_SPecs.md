# SHSP, SHSP? - (SHmoo SPecs)

The SHSP command is used to define the shmoo specifications needed for subsequent SHVL commands.

- If spec_type_<number> is omitted, spec_name_<number> and pinlist_<number> must also be omitted.
- If spec_name_<number> is omitted, @some_port, spec_type_<number> and pinlist_<number> must also be omitted.
- If all pins are required, the SHSP command is faster when pinlist_<number> is left blank instead of using @.
- You should unset the shmoo specs with SHSP,,,,, after using an [SHVL](<02.06.02.02.222_SHVL__SHVL__-__SHmoo_spec_VaLues.md>) command.

The SHSP? query returns the shmoo specifications used by [SHVL](<02.06.02.02.222_SHVL__SHVL__-__SHmoo_spec_VaLues.md>) commands.

## Temporarily setting the primary port

For detailed information on the primary port, see [Modifying the period for a search or shmoo in a multi-port setup](<02.06.09.01.01.01_Modifying_the_period_for_a_search_or_shmoo_in_a_multi-port_setup__Pin_Sc.md>).

Setting and resetting the primary port is included in the SHSP command, see description of the parameter port and the section Example below. SmarTest sets the primary port before starting the search, and resets the primary port after the search is complete.

## SHSP

```
SHSP [spec_type_1], ["spec_name_1[@port[@UNCHANGED]]"], [(pinlist_1)], [spec_type_2], ["spec_name_2[@port[@UNCHANGED]]"], [(pinlist_2)]
```

## SHSP?

```
SHSP?
```

returns:

```
SHSP [spec_type_1], ["spec_name_1"], [(pinlist_1)], [spec_type_2], ["spec_name_2"], [(pinlist_2)]
```

Parameters
 |

spec_type_<number>

 |

Which specification type to use. Use:

 |
 |

LEV

 |

to specify levels, or

 |
 |

TIM

 |

to specify timing.

 |
 |

spec_name_<number>

 |

A string of up to 16 alphanumeric characters (upper or lower case) enclosed in double quotes ("...").

If you use the option @port[@UNCHANGED] (see parameter port), you must enclose it in the double quotes.

 |
 |

port

 |

Define temporarily the port being shmooed as primary port.

This is only applicable if spec_name_<number> affects the period.

Add @UNCHANGED to apply legacy behavior: primary port is not switched to the port being shmooed

 |
 |

pinlist_<number>

 |

The name of the pin or pins to be applied. This parameter may also include groups previously created by the [DFGP](<02.06.02.02.60_DFGP__DFGP__-__DeFine_GrouP.md>)command. If more than one pin is to be included, the names must be separated with a comma. The @ character indicates all pins.

 |

## Application

- Shmoo

## Errors

An error is generated if the level or timing primary set is not an equation based spec set.

## Examples

### Example 1

```
> SHSP LEV, "aclk_vil",(aclkout), LEV, "adata_vil", (adata3)
> SHSP?
< SHSP LEV, "aclk_vil",(aclkout), LEV, "adata_vil", (adata3)
```

### Example 2

In the following Pin Scale example, both spec variables occur in the period definitions associated with the two ports:

```
> CLKR? "MP_spec",(Port1)
< CLKR "MP_spec",17,3.4,(Port1)
> PRPT? "MP_spec","shmsp@Port1";
< PRPT "MP_spec",(Port2)
> SHSP TIM, "shmsp@Port1",,TIM,"shmsp@Port2",
> SHVL 17,30
> PRPT? "MP_spec","shmsp@Port1"
< PRPT "MP_spec",(Port1)
> CLKR? "MP_spec",(Port1)
< CLKR "MP_spec",17,4.25,(Port1)
```

Since `shmsp` is used in the period definitions for both port `Port1` and `Port2`, the one that is specified first in the SHSP command will be used to derive the period resolution. Note that the primary port is only changed after issuing the SHVL command.
