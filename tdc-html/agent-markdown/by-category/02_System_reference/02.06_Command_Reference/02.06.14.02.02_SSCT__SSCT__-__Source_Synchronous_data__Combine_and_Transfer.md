# SSCT, SSCT? - (Source Synchronous data: Combine and Transfer)

The SSCT command combines source synchronous test result data of several source channels and transfers the result to a target channel. The source data is combined by AND, that is, the combined result is 1 if and only if the result of all source channels is 1. The source channels can be associated with the pins to be tested, but they can also be buffer channels which are used in source synchronous testing for accumulating global cycle results (see [Exploiting hardware resources for performance enhancement](<02.06.14.01.02_Exploiting_hardware_resources_for_performance_enhancement.md>)).

The meaning of the combined result depends on how 1 and 0 are mapped to PASS and FAIL. If 1 is PASS and 0 is FAIL, then a combined result of 1 says that all source channels contain PASS, and 0 says that at least one source channel contains FAIL. If 0 is PASS and 1 is FAIL, then a combined result of 1 says that all source channels contain FAIL, and 0 says that at least one source channel contains PASS.

In the hardware, 1 means PASS and 0 means FAIL. But in source synchronous testing, you want to return PASS already if a cycle has passed for all pins at least in one shot. To enable such a disjunctive evaluation of the source data, you can cause SSCT to invert 0 and 1 internally (the data in the source channel is not changed) before actually processing the data.

Suppose, for example, that you have three input channels, one of which contains 1=PASS, while the other two contain 0=FAIL. If you want to get a PASS result in such a case, let SSCT invert the data (so that 0 means PASS and 1 means FAIL) and then combine them by AND. The result will be 0, which now means that at least one source channel contains PASS.

The inversion option of SSCT is global. You can only invert all or no source channels. In order to invert only some of the source channels, use the SSAC command.

Note The inversion options of SSAC and SSCT are concatenated. If you have required inversion for one source channel with SSAC, this inversion will be canceled if you also require global inversion with SSCT.

The SSCT command can be executed immediately, but its execution can also be delayed. In the latter case the command will be triggered by the next [FTST?](<02.06.02.02.127_FTST__-__Functional_TeST.md>) call or the next SSCT command for which immediate execution is required. This serves to enhance the performance of source synchronous testing in two respects. Triggering execution of SSCT with FTST? has the advantage that the command will be processed in parallel with the next functional test, and if several source synchronous tests are executed in parallel, their accumulation steps can be executed in parallel under certain conditions. For details see [Hardware restrictions for result accumulation](<02.06.14.01.02.01_Hardware_restrictions_for_result_accumulation.md>).

The SSCT? query returns all SSCT instances not yet executed for one or more destination pins.

## SSCT

```
SSCT {exec_mode},[read_mode],[nr_of_results],{(dest_pin)}, {(source_pins)}
```

## SSCT?

```
SSCT? {(dest_pins)}
```

returns:

```
SSCT {exec_mode},{read_mode},{nr_of_results},{(dest_pin)}, {(source_pins)}
```

Parameters
 |

exec_mode

 |

Possible execution modes are:

 |
 |

IMM

 |

The command is executed immediately.

 |
 |

ACC

 |

Command execution is delayed to the next FTST? call or the next SSCT IMM call (whichever comes first).

 |
 |

DEL

 |

Deletes all SSCT instances that ar still pending for the specified destination pin and source pins. The other parameters are ignored.

 |
 |

read_mode

 |

Possible read modes are:

 |
 |

NORM

 |

Source data is processed as it is stored in the source channels. This is the default.

 |
 |

INV

 |

Source data is inverted internally before it is processed. The source data itself is not changed.

 |
 |

Note that the read modes of SSAC and SSCT are concatenated. If inversion has been set for a source channel with SSAC, and the read mode of SSCT is also set to INV then the data of the respective channel will be inverted twice, and therefore processed as it is stored.

 |
 |

no_of_results

 |

Specifies the number of results to be processed. The default is all results (as defined with SSAC). The maximum is the number of results that are configured by SSAC.

The number to be specified here must be calculated as `result_granularity * number_of_cycles`.

The result granularity is the number of results per cycle. It can be 1 (one global result), in which case you must specify the number of cycles, or 8 (one result for every edge), in which case you must specify `8 * number_of_cycles`.

The number of bytes required to store the specified number of results must be a multiple of 8. If this requirement is not satisfied, the number of results will be auto-corrected.

 |
 |

dest_pin

 |

The target buffer pin into which the combined results are transferred. This should be an input pin, in order to avoid conflicts within the result area between the buffer function and pin specific result data. This pin must have been defined as a buffer pin with SSAC.

Note that the Error Map for this pin must be located in RDRAM (DCRT command).

 |
 |

source_pins

 |

The pins whose results are to be combined. Note that the Error Map for these pins must be located in RDRAM (DCRT command).

 |

## Errors

An error is generated if:

- The hardware requirements for the transfer operation are not fulfilled, that is, source and target channels belong to different card cages, or different source channels belong to different logical (for Pin Scale 3600 cards) or physical (for Pin Scale 800 carrds) boards.
- The target channel has not been configured with SSAC.
- The requested number of results is greater than the size configured with SSAC.
- The number of configured sites is greater than the licenses allow.

## Warnings

A warning is generated if one of the source channels has been set to inverse read mode with [SSAC](<02.06.02.02.245_SSAC__SSAC__-__Source_Synchronous_testing__Add_Configuration.md>), and SSCT also operates with inverse read mode, in which case the two concatenated inversions will cancel each other

## Example

The following example shows a typical start sequence of a source synchronous test:

```
> DCGM ALL,STRT,NONE
> DCRT RAM,(@)
> SSRC (@)
> SSAC INV,128,,(SB)
> SSAC NORM,128,,(G1,G2)
> SVLR TIM,1,1,"sweep",2.4
> FTST?
> SSCT IMM,NORM,128,(SB),(D1,D2,D3,CL)
> SSCT ACC,NORM,128,(G1),(SB)
> SVLR TIM,1,1,"sweep",2.5
> FTST?
> SSCT IMM,NORM,128,(SB),(D1,D2,D3,CL)
> SSCT ACC,NORM,128,(G2),(SB,G1)
. . .
```

At first, the detailed Error Map is configured for the requirements of result buffering (error map located in RDRAM, recording mode ALL). After the first functional test the results of the data pins D1 through D3 and the output clock pin CL are immediately combined and transferred into the source buffer SB. The subsequent transfer into the first global buffer is delayed and will only be triggered by the next FTST? call. After the second functional test, the SSCT ACC call combines the results of the source buffer and the first global buffer into the second global buffer.
