# SQBV, SQBV? - (SeQuencer Break Vector insertion)

The SQBV command serves to synchronize the user vectors of ports that belong to different sequencing groups. It can insert break vectors at runtime at two places into all patterns of a specified port, namely:

- Immediately before the first user vector
- Immediately before the last primary set is activated.

The specified port will be called the insertion port. The break vectors before the first user vector are called pattern-align vectors. They are intended to synchronize a port that admits no activation of primary sets ([FTCG](<02.06.02.02.125_FTCG__FTCG__-__Functional_Test_ConfiGure.md>) SKPR,ON) with another port that must change its primary sets during the testflow. Their purpose is to compensate the delay which is caused by activating primary sets in the other port, and thus to synchronize the start of the user vectors. The break vectors before the last activation, which are called CTOF-align vectors, are to ensure that moving edges across cycle boundaries does not change the time interval between the last user vector of the respective test and the first user vector of its successor test.

You can define a different number of pattern-align vectors or CTOF-align vectors for different types of activation sequences. The possible types are:

- No activation of primary sets

This type is intended for adjustments that are required by the hardware.

- Only timing activation
- Timing and level activation
- Activation of all primary sets

The port with which the insertion port is to be synchronized is specified with the SQRP command. It is called the reference port. At runtime, whenever the reference port enters an activation sequence, [FTST?](<02.06.02.02.127_FTST__-__Functional_TeST.md>) determines the type of the sequence and inserts the number of pattern-align vectors defined for that type with SQBV before the user vectors of the insertion port. For the CTOF-align vectors, insertion port and reference port are typically identical.

Note The number of break vectors that are required for a certain activation sequence cannot be calculated beforehand. It must be determined empirically, based on the device setup, calibration data, and the hardware topology.

The SQBV? query returns the current numbers for the specified port and sequence type.

The SQBV command is not available on the P/Ce systems.

## SQBV

```
SQBV [CTOF_align],[pattern_align],[activ_type],{(port)}
```

## SQBV?

```
SQBV? {(port)}
```

returns:

```
SQBV {CTOF_align},{pattern_align},{activ_type},{(portlist)}
```

Parameters
 |

CTOF_align

 |

This parameter specifies the number of break vectors that are to be inserted before the last activation. If the specified number is not exactly divisible by 8, it will be autocorrected to the next multiple of 8. The default is 0. The maximum depends on the activ_type parameter.

Note that a value greate than 0 is not allowed for ports whose sequencing group does not admit any activation of primary sets ([FTCG](<02.06.02.02.125_FTCG__FTCG__-__Functional_Test_ConfiGure.md>) SKPR,ON).

 |
 |

pattern_align

 |

This parameter specifies the number of break vectors that are to be inserted before the first user vector. If the specified number is not exactly divisible by 8, it will be autocorrected to the next multiple of 8. The default is 0. The maximum depends on the activ_type parameter.

 |
 |

activ_type

 |

The type of activation sequence which is to be compensated by the break vectors. The possible values are:

 |
 |

 |

NONE

 |

No primary sets are activated. This option can be used to compensate hardware specific delays. The maximum number for this type is 2 * 262136.

 |
 |

 |

TIM

 |

Only the timing is activated. The maximum number for this type, which must not be smaller than that specified for NONE, is the number for NONE plus 262136.

 |
 |

 |

TIM_LEV

 |

Timing and levels are activated. The maximum number for this type, which must not be smaller than that specified for TIM, is the number for TIM plus 262136.

 |
 |

 |

ALL

 |

All primary sets are activated. This is the default. The maximum number for this type, which must not be smaller than that specified for TIM_LEV, is the number for TIM_LEV plus 2 * 262136.

 |
 |

port

 |

The port where the break vectors are to be inserted. Note that the vectors are inserted into all patterns of this port.

 |
 |

portlist

 |

The ports for which the settings are to be returned. Specify @@ to retrieve the settings of all ports.

 |

## Example

The following example synchronizes two ports RX and TX, each of which is the only port in its sequencing group. The RX port does not admit any changes of primary sets, the TX port must change its primary sets several times during the testflow. This is implemented by the [FTCG](<02.06.02.02.125_FTCG__FTCG__-__Functional_Test_ConfiGure.md>) command as follows:

```
> FTCG SKPR,OFF,(@@)
> FTCG SKPR,ON,(RX)
```

In order to synchronize both ports, the time span used up by the activation sequences in TX must be filled with break vectors in RX. If both ports operate with the same period length, and the PHASE flag is set for both of them in the multi-port timing specification, then the number of break vectors that compensates the different types of activation sequences will always be a multiple of 8. The exact number must be determined by empirical tests. The required numbers could then be passed to SQBV as follows:

```
> SQBV ,1504,TIM,(RX)
> SQBV ,22048,TIM_LEV,(RX)
> SQBV ,31784,ALL,(RX)
```

The reference port is TX. This is specified by

```
> SQRP (TX)
```

Finally, the timing changes in TX may include moving receive edges across cycle boundaries, and this in turn can (in rare cases) prolong the activation sequence for the next functional test. But this is not acceptable, because only one value can be passed to SQBV for every activation sequence type. In order to secure that the length of an activation sequence is not affected by the timing of the preceding test, break vectors can be inserted in TX before the last activation of the respective sequence type, so that the sequence as a whole has the extended length even if no cycle crossing takes place in the previous test.

The required number of break vectors must again be determined by measurements. The required number of vectors could then be defined as follows:

```
> SQBV 128,,TIM,(TX)
> SQBV 128,,TIM_LEV,(TX)
> SQBV 128,,ALL,(TX)
```

Note that in this case the insertion port is identical with the reference port.
