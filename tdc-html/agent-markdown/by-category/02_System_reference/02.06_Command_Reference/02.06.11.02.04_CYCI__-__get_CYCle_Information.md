# CYCI? - (get CYCle Information)

The CYCI? query returns the test data of the last executed test for every requested cycle and all pins. A separate answer is given for every cycle.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

## Mode of operation

CYCI? reads vector and error information and analyzes the sequencer program in the requested cycle range. The overall structure of the reply is as follows:

- A header containing global information on the cycle
- One block of binary data for every pin of the specified port, each block consisting of

  - 23 bytes of cycle specific information
  - a variable number of 3 byte units with edge information (so-called receive events), one for each used edge

The pins are ordered by ascending channel numbers. Item 2.b is only present if CYCI? requires information on the edge level (resolution_mode parameter set to CYRM), and the CYRM command has been set to EDGE. This restriction holds for all DCRM configurations where results are recorded on the edge level, not only for repetition of the test when DCRM is set to `1,PFC`.

In the case of HXA pins, only the multiplexed Pin Scale pin 0 is returned, the results of the others are integrated into the answer for pin 0. Thus if edge level information is returned, item 2.b can comprise up to 32 receive events.

## Syntax

CYCI? {start_cycle}, {no_of_cycles}, {resolution_mode} [,MUX] [,(port)]

returns:

CYCI {cycle}, [res_mode] [, (port)], {vector_number}, [label], [type], [seq_status], [comment], [no_of_waveforms] [,MUX], {#spec(data)}

## Parameters

 |

start_cycle

 |

The start cycle is an integer that defines the first cycle to be reported. The start cycle is in the range 0 to 2^48 when the sequencer runs in the Start Analysis mode, and -2^48 to -1 when the sequencer is in the Stop Analysis mode. If a positive number is entered, cycles are counted from 0 upwards. If a negative number is entered, the cycles are counted from the end of the test to -1. In both cases the reported start cycles are in Start Analysis mode.

 |

Defines the number of cycles to be reported. The integer must be in the range 0 to 256.

Returns the current sequencer status. The status is expressed on most occasions in the form of the sequencer instruction that was used to generate the vectors in the requested cycle range. Otherwise it is expressed in terms of the current sequencer activity. Note that seq_status is not the same as the sequencer state determined by [SQST, SQST? - (SeQuencer STate)](<02.06.02.02.241_SQST__SQST__-__SeQuencer_STate.md>). Sequencer instructions are parameters to [SQPG, SQPG? - (SeQuencer ProGramming)](<02.06.02.02.237_SQPG__SQPG__-__SeQuencer_ProGramming.md>). For additional information on sequencer programming see also see [Vector Setup Commands](<02.06.07_Vector_Setup_Commands.md>).

The seq_status parameter is required for the reconstruction of received data. Some of the values it returns signify that vectors are being generated, others inform of sequencer status changes, which cause some or no break vectors to be generated.

 |
 |

GENV

 |

This is returned if GENV is the sequencer instruction that generated the parallel vector for the reported cycle.

 |
 |

SRCV

 |

This is returned if SRCV is the sequencer instruction that generates vectors in the reported cycle range.

For "non-source pin" the reported cycle range is generated by the parallel vectors exactly the same way as RPTV. That means "no_of_vectors" parallel vectors are repeated for a repeating count (equal to no_of_cycles divided by no_of_vectors) to generate "no_of_cycles" cycles on the test system.

For "source pin" the reported cycle range is generated by the vectors stored in the source memory. It means "no_of_cycles" vectors are generated from the source memory to produce "no_of_cycles" cycle on the test system, and the information of "no_of_vectors" has no meaning to "source pin".

 |
 |

RPTV

 |

This is returned if RPTV is the sequencer instruction that generated the parallel vector for the reported cycle.

 |
 |

JPPS

 |

This keyword indicates that a per pin subroutine is executed that cannot be reconstructed because it is too complex. In this case, PP is returned for the drive data and expected data parameters in the result data (#spec(data) parameter).

 |
 |

CTIM

 |

This is returned if a change timing instruction has been issued in the queried cycle range. Each timing change generates break vectors.

The real number of break cycles depends on the test system period and will not be shown in the cycle reconstruction.

Between 0 to 7 break cycles will be recorded during a CTIM instruction, the exact number depends on the number of vectors loaded previously. For instance, if the previous number of cycles was a multiple of 8, then no break vectors are issued during the reload.

 |
 |

CLEV

 |

The CLEV (change levels) parameter indicates that unrecorded break cycles, due to a change of level set, exist in the specified cycle range.

 |
 |

BRK

 |

This is returned if break cycles are being generated during the reported cycle range - for example, if a timed match loop is in progress. Between 0 and 7 break cycles will be recorded.

## Application

Reconstruction command used for data logging.

## Errors

An error is generated if:

- the primary timing setup has changed since last test execution.
- you entered an invalid cycle range.

## Warnings

A warning is generated if more than 256 cycles are requested. In this case only 256 cycles are reported.

## Example

CYCI? 20,2,CYCL

returns:

CYCI 20,11,"TEST1",SVEC,RPTV,"comment",1,

#9000000046

 dvc_01\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x02\x00\x04\x99

 dvc_02\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x04\x0F\x0F\x00

CYCI 21,12,"TEST1",SVEC,GENV,,1,

#9000000046

 dvc_03\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x04\x04\x05\x0F\x6C

 dvc_04\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x00\x04\x04\x0F\x0F\x0D

This example returns result information (on the cycle level) for 2 cycles and 2 output pins of the label `TEST1`, which is of type SVEC. The first cycle was generated by a RPTV instruction from logical vector 11 and has an associated comment, the second cycle was generated by a GENV instruction for logical vector 12.

The binary data reports the device cycle names, which in this example are different for each pin and cycle. The waveform offsets are zero. The reported drive/expected/received data are:

no error

 |
 |

dvc_03:

 |

DD1 = N, DD2 = N, ED1 = FU, ED2 = N

error: high received on edge 5 (param E1)

 |
 |
