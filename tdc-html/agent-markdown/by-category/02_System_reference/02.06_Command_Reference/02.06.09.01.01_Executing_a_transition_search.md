# Executing a transition search

#### Subtopics

- [Modifying the period for a search or shmoo in a multi-port setup (Pin Scale)](<02.06.09.01.01.01_Modifying_the_period_for_a_search_or_shmoo_in_a_multi-port_setup__Pin_Sc.md>)

Transition searches repeat a functional test in a loop. With each test execution, one and the same parameter is systematically modified within a certain range. The goal of such a search is to identify that value of the parameter where the test result changes from PASS to FAIL or vice versa. The parameter that is modified can be a spec variable or a resource parameter. Currently, the resource must be a (drive or receive) edge.

The values of the spec variable (or resource) can be varied for all pins or a subset of the pins (the setup pins) within a certain range. You can also restrict the output pins whose results decide on the test result (the result pins) to a subset of the configured pins.

You can execute different searches in parallel. The granularity is per pin and site, that is, the search conditions can be different for different setup pins on the same site, and also for the same setup pin on different sites.

The search can be executed on the workstation or within the test processor. Each option has its own set of firmware commands.

On the workstation, these are DPSR, which defines the search conditions, EXSR, which executes the search, and RSSR?, which retrieves the results. These commands can vary both timing and level parameters, and modify both spec variables and hardware resources.

The processor based search is only available on a Smart Scale system, and only supports timing parameters. Furthermore, it only modifies source parameters (not spec variables). For the relevant firmware commands see [Using embedded timing search](<02.06.09.01.02_Using_embedded_timing_and_level_search_on_a_Smart_Scale_system.md>).
