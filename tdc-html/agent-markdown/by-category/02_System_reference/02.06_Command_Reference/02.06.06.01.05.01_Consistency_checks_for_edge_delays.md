# Consistency checks for edge delays

With the CHECK keyword, you can request that the edge positions resulting from the selected wavetable and the selected equation set are checked for consistency when the specification is downloaded. You can control if

- the interval between the first and the last edge of the same type (drive or receive) does not exceed one, two, or ten user periods (edge distance)
- the edges of the same type are ordered in all waveform definitions of the specified wavetable by increasing delay for all timing sets of the specified equation set (edge order).

You can activate all checks by specifying `CHECK all`, and suppress all checks by specifying CHECK NONE.

## Checking the edge distance

The keywords for the individual checks of the edge distance are:

1period, 2period, 10period,

1period_drv, 2period_drv, 10period_drv,

1period_rcv, 2period_rcv, 10period_rcv.

These keywords define the maximum distance between the first and the last edge of the specified type. The first edge delay from the start of the test system cycle is not counted.

Assume, for example, that the period length is 20 ns and that the first drive edge has a delay of 7 ns. Assume further that you have activated the check that the interval between the first and the last drive edge is not greater than one user period with 1period_drv. Then the maximum delay allowed for the last edge is 27 ns.

Note On the Smart Scale Digital boards, the maximum interval must not exceed 10 user periods. Specifications that violate this restriction or have switched off the distance check will not be executed.

## Checking the edge order

The individual checks for the edge order are switched on by specifying one of the following keywords:

edgeorder, edgeorder_drv, edgeorder_tri, edgeorder_win

The edgeorder keyword is equivalent to the combination of the other three keywords. What is checked is if the edges of the respective type are ordered in all waveform definitions of the specified wavetable by increasing delay for all timing sets of the specified equation set. This requirement would be violated, for example, if the wavetable for one drive pin contained the definition "d1:1 d2:0", and one of the timing sets specified a greater delay for d1 than for d2.

Note that drive actions and tri-state actions are treated as different types. Thus, the waveform definition string "d1:FN0 d2:F1N" is compatible with a delay of 4 for d1 and a delay of 2 for d2.

## Related firmware commands

With the SPST? query, you can determine which checks are active, and which are disabled.
