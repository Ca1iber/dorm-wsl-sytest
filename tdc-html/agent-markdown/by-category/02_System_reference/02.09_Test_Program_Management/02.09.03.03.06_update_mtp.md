# update_mtp

The update_mtp command for the SmarTest Program Manager MCM (STPM MCM) [control file](<02.09.03.03_STPM_MCM_control_file.md>) updates objects in an MTP (master test program) that have been imported from an STP (source test programs). You specify the source STP and the objects that are updated.

This command lets you selective update an MTP when an STP has changed, without having to completely rebuild the MTP with the [create_mtp](<02.09.03.03.05_create_mtp.md>) command.

Note that you can use update_mtp even if you have never previously used [create_mtp](<02.09.03.03.05_create_mtp.md>) for the device.

## Syntax

```
update_mtp(
  stp_name              = <name>,
  test_objects          = [ <test>, ...],
[ stp_missing_primaries = '<behavior>']
)
```

## Parameter

 |

stp_name

 |

The name of the STP.

<name> is the name under which the STP is listed in the MTPT's [STP table](<02.09.03.04.01_STP_table.md>).

 |
 |

test_objects

 |

The test suites or test groups that must be updated.

<test> is the name under which the test is listed in the MTPT's [Test mapping table](<02.09.03.04.04_Test_mapping_table.md>).

This is an optional parameter. If it is not specified, all test suites and test groups from the specified STP are updated in the MTP.

 |
 |

stp_missing_primaries

 |

What STPM MCM is to do when an STP uses missing primaries.

<behavior> can be any of these:

- 'error': An error is generated and the update of the MTP is stopped.
- 'warning': A warning is generated but the MTP is updated. The test suite from the STP is integrated without change; STPM MCM leaves the references to the missing primaries unchanged.
- 'bypass': STPM behaves differently depending on whether the test suite is bypassed:

If the test suite is bypassed, STPM behaves as for 'warning'.

If the test suite is not bypassed, STPM behaves as for 'error'.

STPM considers a test suite bypassed if the local bypass flag of the test suite is set, if the bypass flag is set for it in the MTPT flags table, or if it is part of a group for which the bypass flag has been set.

This is an optional parameter. If it is not specified, 'bypass' is used.

 |

(The information about the MTPT and device directory to use comes from the mtp_template_dir and mtp_device_testflow[settings](<02.09.03.03.01_STPM_MCM_parameter_settings.md>) in the control file.)

## Example

```
mtp_template_dir    = "/prj/MTPT"
mtp_device_testflow = "/prj/MTP/testflow/rel.tf"
update_mtp(stp_name = "CPU", test_objects = ["JTAG", "SCAN"], stp_missing_primaries = "bypass")
```
