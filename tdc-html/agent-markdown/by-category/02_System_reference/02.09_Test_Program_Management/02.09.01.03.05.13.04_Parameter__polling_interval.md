# Parameter: polling_interval

If the driver uses the polling method while waiting for parts, this parameter defines the time in [microseconds] between two polling operations.

Choosing a value larger than busy_wait_delay_threshold avoids high system load when waiting for parts. A value lower than busy_wait_delay_threshold should be chosen if fastest reaction time to test start signals is desired.

Driver default: 10000

Changeable at run-time: no

Applicable for: handlers and probers

Example: polling_interval: 10000
