# Parameter: test_start_relax_time

A small delay may be required between the driver sending the end-of-test signal and the driver looking for the next test start signal of the handler. This may be important for example for a "static" test_start_waveform since the start signal is not reset by the handler until it has received the end-of-test signal signal from the driver. The previous test start signal may therefore be wrongly interpreted as the next test start signal. The delay amount will take into account execution times of the SmarTest processes between the ph_device_done and ph_device_start calls and ensure at least the defined delay amount has occurred before continuing. The delay time is given in milliseconds.

Driver default: depends on plug-in

Changeable at run-time: yes

Applicable for: handlers and probers

Example: test_start_relax_time: 20
