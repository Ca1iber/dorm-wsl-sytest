# Eclipse handler configurations

#### Subtopics

- [GPIB communication flow for Delta Eclipse handlers](<02.09.01.03.06.01.08.02.01_GPIB_communication_flow_for_Delta_Eclipse_handlers.md>)
- [Auto-retest communication flow for Eclipse handlers](<02.09.01.03.06.01.08.02.02_Auto-retest_communication_flow_for_Eclipse_handlers.md>)

The Eclipse handler is a pick-and-place product from Delta Design.

## Barcode query

The Delta Eclipse handlers support the driver through GPIB interface.

 The following code statement can be used in the test program for retrieving barcode IDs of devices on Site 1:

```
SITE1_PHYSICAL_PART_MARKING = PROB_HND_CALL (ph_get_status DEVICEID 1);
```

- If DEVICEID 4 is used in the statement, the barcode IDs of devices on Site 4 will be returned.
- If a site number is specified, but the site number does not exist, the return value is an empty string.
- If no site number is specified, a string which contains all barcode IDs is returned. These barcode IDs are separated by colons ":", for example, `"site1_barcode:site2_barcode:site3_barcode:site4_barcode"`.

## Functional changes

- SmarTest 7.6.0: The Eclipse handler driver supports auto-retest.
