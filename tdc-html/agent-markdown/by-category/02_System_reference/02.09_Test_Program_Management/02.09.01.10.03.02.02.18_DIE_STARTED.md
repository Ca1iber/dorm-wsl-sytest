# DIE_STARTED

This asynchronous event indicates the test for a new die is started in the test program execution. It is only available for wafer sort.

## Dependency and constraints

- The test program is in execution.
- If the application model does not use the standard prober/handler driver function call (`ph_die_start`) or the equivalent, this event may not be generated.

The standard naming for the application model variable must be used (not case-sensitive).

For Lot ID: "`ph_LOT_ID`" | "`LOT_ID`"

For Cassette ID: "`ph_CASSETTE_ID`" | "`CASSETTE_ID`" | "`ph_CASS_ID`" | "`CASS_ID`"

For Wafer ID: "`ph_WAFER_ID`" | "`WAFER_ID`" | "`ph_WAF_ID`" | "`WAF_ID`"

Otherwise it will fail to response the values.
