# Workorder Manager and custom production test shells

#### Subtopics

- [Custom shell in operator mode](<02.09.01.15.01.01_Custom_shell_in_operator_mode.md>)
- [Custom shell in supervisor mode](<02.09.01.15.01.02_Custom_shell_in_supervisor_mode.md>)

A production test shell is a program that enables an operator to select a work order from a list, assign values to test parameters, and start the execution of a test. SmarTest provides the Workorder Manager for that purpose. However, if your environment requires special functions that the Workorder Manager does not include or if you need to integrate the work order selection with other tools, you may want to create a custom production shell.

There are two basic types of custom production shells which differ in the SmarTest mode they call:

- When SmarTest is called in operator mode, you can only select and execute work orders from the shell. In addition, the setups must be reloaded before every work order execution.
- If SmarTest is called in supervisor mode, you can take advantage of the SmarTest Test Programming Interface and Command Programming Interface (see [Overview of the SmarTest API](<02.09.01.15.04_Overview_of_the_SmarTest_API.md>)), which enable you to programmatically control the entire test process. Setups do not have to be reloaded in this case.

Therefore, it is usually better if the custom shell calls SmarTest in supervisor mode.
