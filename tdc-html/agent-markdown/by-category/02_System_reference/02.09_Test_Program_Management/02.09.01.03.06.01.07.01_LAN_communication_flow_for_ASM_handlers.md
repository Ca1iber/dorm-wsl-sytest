# LAN communication flow for ASM handlers

The following table lists the messages and actions between the tester and the handler in LAN communications.

See [Conventions for GPIB/LAN communication](<02.09.01.03.06.01.04_Conventions_for_GPIB_LAN_communication.md>) for the syntax description.

LAN communication flow for ASM handlers
 | Message from driver  | Message from handler  | Description |
 | Start test on a range of DUT sites: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `START RANGE` `x` `y`  | The handler replies with the START RANGE command, which indicates that the test starts from DUT sites x to y inclusively. The site number is zero-based.

For example, `START RANGE 0 7`. The handler sends the command to test DUT sites 0 to 7.

 |
 | `RESULT r0 r1 r2 ... rn-1`  |   | The tester replies the test result of devices from sites x to y.

For example, `RESULT 0 11 0 2 0 0 0 0`. The tester replies the result in the same site order. Sites 1 and 3 fail with categories 11 and 2.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | Start test on a list of DUT sites: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `START EXPLICIT` `x0` `x1` `x2` `...` `xn-1`  | The handler replies with the START EXPLICIT command, which indicates that the test starts for DUT sites xi.

For example, `START EXPLICIT 3 4 5 0 1 2`. The handler sends the command to test DUT sites 3, 4, 5, 0, 1, and 2 in order.

 |
 | `RESULT` `r0` `r1` `r2` `...` `rn-1`  |   | The tester replies the test result of devices from sites xi.

For example, `RESULT 0 1 2 0 0 3`. The tester sends back the result that sites 4, 5, and 2 fail with categories 1, 2, and 3 respectively.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | Restart test on a range of DUT sites: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `RESTART RANGE x y`  | The handler replies with the RESTART RANGE command to retest from DUT sites x to y.

For example, `START RANGE 0 7`.

 |
 | `RESULT` `r0` `r1` `r2` `...` `rn-1`  |   | The tester replies the test result of devices from sites x to y.

For example, `RESULT 0 11 0 2 0 0 0 0`. The tester replies the result in the same site order. Sites 1 and 3 fail with categories 11 and 2.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `RESTART RANGE x y`  | The handler starts retest from sites x to y.

For example, `RESTART RANGE 1 3`, which indicates retest on sites 1, 2, and 3.

 |
 | `RESULT` `r0` `r1` `r2` `...` `rn-1`  |   | The tester replies the retest result of devices from sites x to y.

For example,

 `RESULT 11 0 1`, which indicates that sites 1 and 3 fail with categories 11 and 1 respectively.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | Restart test on a list of DUT sites: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `RESTART RANGE x y`  | The handler replies with the RESTART EXPLICIT command to retest from DUT sites xi.

For example, `START RANGE 0 7`.

 |
 | `RESULT` `r0` `r1` `r2` `...` `rn-1`  |   | The tester replies the test result of devices from sites x to y.

For example, `RESULT 0 11 0 2 0 0 0 0`. The tester replies the result in the same site order. Sites 1 and 3 fail with categories 11 and 2.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `START EXPLICIT` `x0` `x1` `x2` `...` `xn-1`  | The handler starts retest from sites x to y.

For example, `RESTART RANGE 1 3`, which indicates retest on sites 1, 2, and 3.

 |
 | `RESULT` `r0` `r1` `r2` `...` `rn-1`  |   | The tester replies the retest result of devices from sites x to y.

For example,

 `RESULT 11 1`, which indicates that sites 1 and 3 fail with categories 11 and 1 respectively.

 |
 |   | `ACK`  | The handler replies to indicate the test result received. |
 | Nothing to test: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `ACK`  | The handler acknowledges. |
 | Strip ID (Option 1): |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `STRIP_ID <stripID>`  | The handler sends the ID of the strip that just enters the test platform. For example, `STRIP_ID 7C841410AT-643613163`. If no ID information, `stripID` is empty. |
 | Strip ID (Option 2): |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `START RANGE "2DID" coord1,coord2, ... `  | The handler sends the ID of the strip that just enters the test platform, followed by X-Y coordinates of the index testing.

For example, `START RANGE "NB22W4208763" AA0,AA1,AA2,AA3,AA4,AA5,AB0,AB1,AB2,AB3,AB4,AB5 ...`.

 |
 | `RESULT coord1,x,coord2,x, ...`  |   | The tester sends back result by X-Y coordinates followed by the bin result of each die.

For example, `RESULT AA0,1,AA1,1,AA2,1,AA3,3,AA4,1,AA5,3,AB0,1,AB1,3,AB2,1,AB3,1,AB4,1,AB5,1,`.

 |
 |   | `ACK`  | The handler acknowledges. |
 | Lot ID: |
 | `LOT_ID?`  |   | The tester requests for Lot ID. |
 |   | `LOT_ID <lot_id>`  | The handler sends the Lot ID. |
 | End of lot: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `END_OF_LOT`  | The handler sends End of Lot. |
 | Indexing number: |
 | `RUN`  |   | The tester looks for active sites or handler commands. |
 |   | `INDEX_NO <indexNumber>`  | The handler sends the current index of the strip. For example, `INDEX_NO 3`. |
 | Handler information: |
 | `INFO?`  |   | The tester requests for more handler information. |
 |   | `INFO <handler_name>`  | The handler sends the information to the tester. |
 | Ping: |
 | `PING`  |   | The tester pings the handler. |
 |   | `ACK`  | The handler acknowledges.  |
