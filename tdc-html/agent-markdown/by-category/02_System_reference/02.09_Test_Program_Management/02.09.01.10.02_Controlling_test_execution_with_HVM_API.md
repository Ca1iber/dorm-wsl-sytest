There are three ways to control the SmarTest run:

- control the SmarTest running with [Application model](<../02.08_Setup_and_Result_Tools/02.08.04.02_Application_model.md>)
- control the SmarTest running with [Batch/Lot Control](<02.09.01.11_Batch_Lot_Control.md>)
- control the SmarTest running with HVM API [ExecTestflow()](<02.09.01.10.03.02.02.22_ExecTestflow.md>).

Application model is the legacy production environment that is widely in use. BLC can implement the same functionality as application model in C++ with much more flexibility. The ExecTestFlow() API executes the testflow directly and is simple to use.

 Note Test method executor is not automatically terminated after testflow executions or application model runnings. This can avoid losing the information generated in the test method execution. To explicitly terminate the test method executor to release all resources and get a clean environment for next execution, you can execute the following command in a shell:

```
$/opt/hp93000/soc/testmethod/bin/tmm_console -e stopAll
```

Here we will only discuss how to control the test execution with HVM API. You can use the HVM API to

- start and terminate a SmarTest session
- get the existing SmarTest session information
- download and execute a test program or testflow
- Control the running of a BLC client
- notify the customer client status to SmarTest
- get the hardware information of test system and Linux controller
- query the test system calibration status
- monitor the production status
