# Explanation of the Syntax Structure

The following syntax listing conforms to the Backus Naur Format (BNF). Additional symbols used in the syntax description are as follows:

 |

 |

 |

indicates that a choice is available; read as or

 |
 |

:=

 |

read as comprises

 |
 |

<>

 |

whatever is within these brackets indicates a variable; the brackets themselves should not be used.

 |
 |

[]

 |

whatever is within these square brackets is optional

 |
 |

""

 |

whatever is enclosed by these inverted commas is an obligatory character in the whole construct

 |
 |

+

 |

indicates that there must be at least one or more of the preceding entity

 |
 |

*

 |

indicates that there can be zero or more of the preceding entity

 |
 |

"*"

 |

indicates that the parameter may be logged. For example, the line in the wafer_auto application model,

* Lot_id = DIALOG_INPUT / REGEXP(nnnn);

states that Lot_id will be logged. Compare this to the syntax for the <dialog_parameter>,

<dialog_parameter> := [["*"] [<parameter_type>] <name> "="

<access> [ "/" <format_spec> ]";" ]

 |
 |

[]x

 |

means that the entity within the brackets is to be repeated "x" times

 |
 |

--

 |

denotes a comment

 |

For those unfamiliar with BNF, the structure of the syntax may be easier to understand by looking at the first few lines of the wafer_auto application model file and seeing how the syntax relates to them.

```
START_DIALOG

{ lot:
SCREEN_DIALOG
* Lot_id =    DIALOG_INPUT     / REGEXP(nnnn);
```

The first line of the syntax states that an application model can comprise of the following:

- An optional expression START_DIALOG, and/or
- An optional expression OLD_GDF_FORMAT, and/or
- 1 or more <level_section>, and/or
- An <on_pause_section>

In the wafer_auto example, the model file begins with START_DIALOG and then the first <level_section>, called lot.

A <level_section> comprises,

- an obligatory enclosing set of braces ({ at the beginning of the level and } at the end),
- a name to the <level_section> , which can be one of the following,

a <level_name>, followed by :

the expression WAFER with an optional <header>, a

<level_name> followed by :

the expression DEVICE with an optional <header>,

a <level_name> followed by :

- optional permutations of <dialog>s, ACTIONS and LOG_SPECIFICATIONS, together with their parameters (see [The application model structure](<02.09.01.02.01.02_The_application_model_structure.md>) for details on the levels within the application model).

In the wafer_auto example, the <level_section> is of the first type, comprising the <level_name> lot and a <dialog> variable SCREEN_DIALOG.

The <dialog_parameter> can take many forms, but in the case of wafer_auto, the first form is appropriate, namely,

["*"] [<parameter_type>] <name> "=" <access> ["/"<format_spec>]";" ]

In wafer_auto, Lot_id is the <name>, DIALOG_INPUT the <access> method. The format of the data for Lot_id is of type REGEXP with its <regexp> argument comprising a <formatstring> - which itself comprises four numeric characters. The asterisk, *, indicates that the value for Lot_id will be logged.

```
<application_model> :=  [ "START_DIALOG" ]
                    ["OLD_GDF_FORMAT"]
                    [<level_section>]+
                    [<on_pause_section>]
<level_section> := "{"  <level_name> ":"
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ "LOG_SPECIFICATION"
                        [ <log_parameter> ]+ ]
                    <level_section>
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                "}"
 |
                "{" "WAFER" [<result-display-header>]<level_name> ":"
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ "LOG_SPECIFICATION"
                        [ <log_parameter> ]+ ]
                    <level_section>
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                "}"
 |
                "{" "DEVICE" [<result-display-header>]<level_name> ":"
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ "LOG_SPECIFICATION"
                        [ <log_parameter> ]+ ]
                    "{"
                        "DEVICE_TEST"
                    "}"
                    [ "REPROBE_ACTION" "=" <action> ]
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                    "}"
<on_pause_section> := "{" "ON_PAUSE" <level_name> ":"
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    [ <dialog_form>
                        [ <dialog_parameter> ]+ ]
                    [ "ACTIONS"
                        [ <action_parameter> ]+ ]
                    "}"
<dialog_form> := "SCREEN_DIALOG" |
                "LINE_DIALOG"
<dialog_parameter> := [ ["*"] ["SUBLEVEL_COUNT"] <name>
                    "=" <access> [ "/" <format_spec> ]";" ] |
                    [ ["*"] BUTTON <name>
                    "=" <action> [ "/" <format_spec> ]";" ] |
                [ "DISABLE_CHECKDEV_BUTTON" ";" ] |
                [ "DISABLE_D_RETEST_BUTTON" ";" ] |
                [ "DISABLE_W_RETEST_BUTTON" ";" ] |
                [ "DISABLE_REFERENCE_BUTTON" ";" ] |
                [ "DISABLE_SKIP_BUTTON" ";" ] |
                [ "DISABLE_QUIT_BUTTON" ";" ] |
                [ "DISABLE_SUMMARY_BUTTON" ";" ] |
                [ "DISABLE_TESTER_SW_BUTTON" ";" ]
<action_parameter> := ["*"] [ ["SUBLEVEL_COUNT"] <name> "=" ]
                        <action> [ "/" <format_spec> ]";"
<log_parameter> := "RESULT_LOG" "=" <on_or_off> ";" |
                [ "NEW_RESULT_FILE" "=" <file_name> ";"
                [ "POST_PROCESSING" "=" <action> ";" ] ]
-- post processing only makes sense on a given file

<action>    := "AUTOINCREMENT" |
            "CONST_INPUT" "(" <name> ")" |
            "GET_ENV" "(" <env_var_name> ")" |
            "FILE_INPUT" "(" <file_name> ")" |
            "MOVE_EVENT_STREAM" "(" <file_name> ")" |
            "ELEMENT_OF_PARAM_LIST" "(" <var_name> ")" |
            "EXEC_INP_CALL" "(" <cmd_with_args> ")" |
            "PROB_HND_CALL" "(" <cmd_with_args> ")" |
            "D_BRIDGE_CALL" "(" <cmd_with_args> ")" |
            "GET_TEST_INFO" "(" <keyword> ")" |
            "GET_WAFERLIST" "(" <waferlist_param> ")" |
            "SET_PACKAGE_ID" "(" <name_with_vars> ")" |
            "SET_TEMPERATURE" "(" <real> ")" |
            "SET_DIE_X_Y" "(" <x_y_id> ")" |
            "MONITOR_CALL" "(" <monitor_call_param>")" |
            "DOWNLOAD_INTERFACE_DATA""(" <name_with_vars> ")" |
            "DRIFT_CALIBRATION"
<access> := "DIALOG_INPUT" |
            "APPLIC_DATA_EDITOR_INPUT" |
            "WORKORDER_MANAGER_INPUT"
<format_spec> := "REGEXP" <regexp> |
            "CONST_FORMAT" <name_with_vars> |
            "APPLIC_DATA_EDITOR_FORMAT" |
            "WORKORDER_MANAGER_FORMAT"
<waferlist_param> := <wafer_per_list> ","
                <readscript> ","
                [ <list_id> ","
                <list_file> "," ]4
<wafer_per_list> := <int>
<read_script> := <name_with_vars>
<list_id> := <name_with_vars>
<list_file> := <name_with_vars>
<x_y_id> := <name_with_vars> "," <name_with_vars>
-- this expression is more useful in the form:
    <int> "," <int>
<monitor_call_param> := <check_activity> |
                    <setup_activity>
<keyword> := "test_desc" |
            "test_rev" |
            "dev_name" |
            "dev_rev" |
            "testprog" |
            "date_time" |
            "ooc_warning_rule" |
            "ooc_stop_rule"
<setup_activity> := "BrdTemp_limit" "," <brd_tmp_param_1>
                             "," <brd_tmp_param_2> |
                 "calAge_limit" "," <cal_age_param_1> |
                 "dpsCurrent_limit" "," <dps_cur_param_1>
<check_activity> := "calAge_check" |
                 "BrdTemp_check" |
                 "dpsCurrent_check" |
                 "diagnostic_check"
<brd_tmp_param_1> := <name_with_vars>
-- range is -2.5.. 0.0 (degrees C)
<brd_tmp_param_2> := <name_with_vars>
-- range is 0.0.. 2.5 (degrees C)
<cal_age_param_1> := <name_with_vars>
-- range is 1 .. 90 (days)
<dps_cur_param_1> := <name_with_vars>
-- range is 0.0.. 1.0 (percent of programmed range)
<regexp>      := [ "List: " ] "int" |
                [ "List: " ] "real" |
                [ "List: " ] "string" |
                [ "List: " ] <formatstring>
<formatstring> := "a"]["n"]["c"]["x"]["n"]["|"1:80
                a - alphabetic character
                c - alphanumeric character
                x - Do not care
                n - numeric character
                | - OR function
-- any combination of the above entities is possible;
-- for example, annna, caannxnn, ann|axn, etc.
<on_or_off>        := "ON" |
                "OFF"
<cmd_with_args> := <name_with_vars> [ " " <name_with_vars>]*
-- blank is separator; first <name_with_vars> is used as command;
-- subsequent <name_with_vars> are used as parameters
<result-display-header> := "[" "(" <name_with_vars> ")" ","
                       "(" <name_with_vars> ")" "]"
<env_var_name>    := <name_with_vars>
<file_name>        := <name_with_vars>
<level_name>        := <name_with_vars>
<name_with_vars>    := [<name>]+ |
                <name>]<var_name>[<name>+
<var_name>        := "{" <name> "}"
<name>            := [a-zA-Z0-9_./-+!$%^&*]+
<int>            := [0-9]+
<real>            := [-] [0-9]+ [.] [0-9]*
```
