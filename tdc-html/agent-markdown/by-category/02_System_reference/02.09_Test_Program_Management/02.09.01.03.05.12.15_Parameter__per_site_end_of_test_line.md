# Parameter: per_site_end_of_test_line

Most of the handlers use one or more end of test signals to read the binning information. In case of serial binning, usually different end of test lines are used for different sites. In case of parallel binning, often only one end of test line is used to clock in all binning information to the handler at once.

Some handlers which use an explicit binning do not need an additional end of test signal at all.

This parameter defines the GPIO output lines to be used as end of test signals lines per site.

If this parameter is set, it is assumed, that the handler needs to receive an end of test pulse for each site. Even if it is working in parallel mode, an entry for each site must be given, most likely with equal values for each site.

Valid values for the output lines are "DO0" to "DO15", "CTL0", and "CTL1"

If no settings for this parameter are made, it is assumed, that no explicit end of test pulses are necessary. In this case bin_coding must be set to "explicit" and bin_waveform must be "pulse".

Examples:

This defines a serial binning using output lines 1 to 15 of the GPIO interface to provide the bin category, using the CTL0 line for site A and the CTL1 line for site B.

handler_site_ids: [ "A" "B" ]

binning_mode: "serial"

per_site_bin_line_groups: [ [ "DO1" "DO15" ] [ "DO1" "DO15" ] ]

per_site_end_of_test_line: [ "CTL0" "CTL1" ]

This defines a parallel binning with two separated groups of bin information lines for both sites A and B. Both sites use the same end of test line CTL0.

Only one end of test pulse is generated!

handler_site_ids: [ "A" "B" ]

binning_mode: "parallel"

per_site_bin_line_groups: [ [ "DO0" "DO7" ] [ "DO8" "DO15" ] ]

per_site_end_of_test_line: [ "CTL0" "CTL0" ]

Driver default: depends on plug-in

Changeable at run-time: yes

Applicable for: handlers and probers

Example: per_site_end_of_test_line: ["CTL0"]
