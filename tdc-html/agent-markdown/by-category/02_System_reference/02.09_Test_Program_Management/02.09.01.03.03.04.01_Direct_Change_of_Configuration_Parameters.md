# Direct Change of Configuration Parameters

By calling the function ph_set_configuration from the application model, you can directly change the setting of any parameter which is defined in the attributes definition file of the plug-in (except for those which are not changeable at run-time per definition (see [Configuration Parameters](<02.09.01.03.05_Configuration_Parameters.md>)).

The function ph_set_configuration takes one or more pairs of arguments, each consisting of a parameter name and the new parameter setting.

## Example:

This example sets the parameter debug_level to 3, and trace_driver_calls to "yes".

PROB_HND_CALL (ph_set_configuration debug_level:3 trace_driver_calls:"yes")

There are several aspects to consider when using the ph_set_configuration function:

- The new setting of a parameter must comply with the definition of valid settings for that parameter in the attributes definition file.
- Some parameters cannot be changed individually, as other parameter settings must correspond to the settings of these parameters. Always change all related parameters to avoid inconsistencies.

For example, when changing the number of elements in the parameter handler_site_ids, the parameters handler_site_mask and smartest_site_to_handler_site_map must be changed correspondingly.

- The application model which calls the function ph_set_configuration becomes unusable for other plug-ins if the function changes a parameter which is not defined in the attributes definition of the other plug-ins, or if the attributes definitions of the other plug-ins define different valid parameter settings for this parameter. Note ph_set_configuration even allows you to change the settings of parameters which were disabled for changes at run-time with the function ph_interactive_configuration. (See [Editing a Driver Configuration File](<02.09.01.03.03.03.01_Editing_a_Driver_Configuration_File.md>) for information about how to disable/enable parameters for changes at run-time).
