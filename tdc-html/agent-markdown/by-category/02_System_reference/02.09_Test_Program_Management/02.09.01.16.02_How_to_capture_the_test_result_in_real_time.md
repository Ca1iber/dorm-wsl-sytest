In SmarTest, event data logging is provided to retrieve the test result data from the production environment. Event data logging is fully event based. Whenever an event occurs during the production test, an event record is immediately written to the data log stream. The data log stream thus holds the event records in the order of when the events occurred. Detail information of how events and attributes are organized is described in [Event Data Logging Format (EDF)](<../02.10_Data_Logging/02.10.01.06_Event_Data_Logging_Format__EDF.md>).

To capture the test result in real-time from the data log stream, you can use the Event Formatter or create your own data retrieval routine.

Event Formatter is provided in SmarTest to generate the test report from the data log stream. You can select what kind of information you want to log in the [Report Dialog window](<../02.10_Data_Logging/02.10.02.06_Report_Dialog_window.md>). The output of the report formatter always contains information on the test program, the application model level and the test flow. For details see [Event Formatter](<../02.10_Data_Logging/02.10.02_Event_Formatter.md>).

To create your own data retrieval routine, you can use the data retrieval library. The library is provided to access the data log stream and read event records. In the data retrieval routine, you can capture the test result from the data log stream, print the result in a file and display the result on the user interface. For example, you can create a routine to simply capture the test result data you want or you can even decide the following behavior of data retrieval routine according to the incoming event.

You can use the [DRLDump tool](<../02.10_Data_Logging/02.10.01.10_Appendix_B__The_DRLDump_Tool.md>) as a template to create your own data retrieval routines. The source file main.c and a make file for compilation are provided in the /opt/hp93000/soc/.service/DRLDump directory.

In the data retrieval library, the following functionalities are provided:

- read event records from the data log stream and extract data from the records
- store the extracted data in the variables of data types.

The data types provided by data retrieval library contain the following information:

- application model level information including level name and level type
- attribute record data including attribute type and attribute data
- bin and bin statistic information
- device setup information including

  - device directory, device ID, site ID
  - pin/level/timing/vector information, waveform information
  - test suite flag settings, test suite name and type, test number, test name, test suite list, test function type and parameters, scan instance description and list
  - test program name, lot type, work order

- environment information like host name, SmarTest version, user ID and timing stamp
- event information like event mask, event record data including event type and attribute records
- generic data record including type, length and data
- test result including pass/fail result, per pin pass/fail result, per pin result value range, result value, pass/fail result per port, pass range, detailed error map information, error overview, measured range and unit, data to be printed to data log, failing cycle number and pin list, ganged current of IDDQ measurement
- shmoo information including axis, result data of a cell, failed pins in a cycle, definition data of a shmoo test, result data of a shmoo
