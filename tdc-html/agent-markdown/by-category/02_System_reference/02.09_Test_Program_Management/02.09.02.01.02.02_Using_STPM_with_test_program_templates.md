# Using STPM with test program templates

STPM lets you convert an existing testflow into a [Test program template](<02.09.02.01.02.03_Test_program_template.md>) (TPT), which contains a testflow with a similar structure as the base workflow but placeholder test suites.

This template can be modified using SmarTest or external tools.

STPM can then convert the template into a device directory that is filled with test suites, creating fully functional testflows.

You can also create templates from scratch and convert them to device directories to be filled in STPM.

When all relevant information has been specified in the template, you convert it to a device directory and then assemble the complete test program.

## Working with an existing testflow

A TPT is most commonly created from an existing testflow that has been developed for a particular device.

To adapt the template, you load the CSV files of which it consists into the spreadsheet and specify the required information for the individual test suites. When you are done, you save the information as a set of CSV files again and use STPM to create a new device directory from them.

The test program described in the device directory can be populated with actual tests using [STPM](<02.09.02.01_Introduction_and_installation.md>). It can then be loaded into SmarTest as usual.

If required, you can edit the testflow file that is part of the template in SmarTest, for example to rearrange the placeholder test suites. The pin configuration and .technology files can also be modified if needed.

## Creating a test program template from scratch

You can also use STPM to create a test program template from scratch, without using an existing testflow. This creates the same files as described above, but without the device-specific files (testflow, pin configuration, .technology).

You proceed as above, editing the files as needed, and then use STPM to create a new device directory.
