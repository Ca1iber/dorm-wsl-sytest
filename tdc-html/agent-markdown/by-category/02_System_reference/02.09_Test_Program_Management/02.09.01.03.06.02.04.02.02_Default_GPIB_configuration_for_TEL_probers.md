# Default GPIB configuration for TEL probers

When a configuration file has been created, some certain aspects in the file must be defined. The table below lists these aspects and how they are to be defined.

   |  Note Due to different firmware versions in some probers of the 20S group, the prober may not function as it should for multi-site probing. Please note the following:

- The resulting string of the O command ("on wafer" command) may be either encoded or in ASCII. Set the parameter tel_o_command_style to ascii if necessary. The default uses encoded.
- If the binning results are incorrect, you may have to change the configuration parameter tel_reverse_binning. You can reverse the binning order by setting the parameter to yes.
  [1)](<#fnsrc_1>) Must be changed to a correct value based on the prober's configuration.[2)](<#fnsrc_2>) For the probers supporting multi-die probing and SmarTest-controlled stepping, the parameter dont_bin_dies is set to the default value yes so that the binning data is not to be overwritten with empty bins if dies are reprobed.[3)](<#fnsrc_3>) Recommendation: First start SmarTest's test program, then start lot at prober. Test program will loop endlessly. After a lot end is detected, the test program will wait for a new lot start signal from the prober. The test program can be stopped by setting the ABORT flag or pressing QUIT when it is in a SmarTest pause.
