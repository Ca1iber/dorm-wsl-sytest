# Clear Duplicated dialog

The Clear Duplicated dialog lets you set the parameters for removing duplicate primaries from the test program. Its options correspond to the parameters of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) control file command.

The command affects the entire test program (not just selected test groups).

If you want to use any of the "Keep ..." options, the test program must first be analyzed. This is done by clicking the Analyze button and is required only once per test program; the analysis also applies to the [Clear Unused dialog](<02.09.02.07.03_Clear_Unused_dialog.md>).

 ![STPM UI_Clear Duplicated dialog](<../../../../raw/142267.png>)

The dialog is opened by the Clear Duplicated command from the [STPM menu](<02.09.02.07.02_STPM_menu.md>). It contains these fields and options:

- Content error message: The message at the top of the dialog, just below the title, notifies you of any errors or warnings caused by your settings, for example, an empty testflow path:

  - ![STPM UI_error icon](<../../../../raw/142286.png>): This icon indicates an error. The error is noted in the message, and the offending field or option is marked with the same icon. The Run button is disabled until the problem is resolved.
  - ![STPM UI_warning icon](<../../../../raw/142287.png>): This icon indicates a warning. The problem is noted in the message, and the offending field or option is marked with the same icon. You can, however, still click Run to execute the command with this setting.

- Pin Configuration Cleanup: In this section, you specify how to handle duplicate pins:

  - Merge duplicated definitions for pins: If this option is checked, wavetable, timing set, level set, and DPS definitions for similar pins in the program are merged. This option is the same as the proc_merge_pins parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.

- Timing Cleanup: In this section, you specify how to handle duplicate timing settings:

  - Clear duplicated wavetables: If this option is checked, wavetable duplicates are removed from the test program. This option is the same as the proc_wavetables parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Keep wavetables: In this field, you can specify wavetables that will be ignored. That is, these wavetables will not be removed, even if they are duplicates of other wavetables.

You can specify the wavetables to keep by clicking Select and checking the desired wavetables, or you can enter them manually in the field. If you enter multiple items manually, separate them with commas.

This option corresponds to the skip_wavetables parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.

  - Clear duplicated timing EQNSETs: If this option is checked, timing equation set duplicates are removed from the test program. This option is the same as the proc_tim_eqnsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Clear duplicated timing SPECSETs: If this option is checked, timing set duplicates are removed from the test program. This option is the same as the proc_tim_specsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Keep timing EQNSETs: In this field, you can specify timing equation sets that will be ignored. It is similar to Keep wavetables, described above.

This option corresponds to the skip_tim_eqnsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.

  - Clear duplicated timing specifications: If this option is checked, timing specification duplicates are removed from the test program. This option is the same as the proc_specifications parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Keep specifications: In this field, you can specify specifications that will be ignored. It is similar to Keep wavetables, described above.

This option corresponds to the skip_specifications parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.

- Levels Cleanup: In this section, you specify how to handle duplicate level settings:

  - Clear duplicated level EQNSETs: If this option is checked, level equation set duplicates are removed from the test program. This option is the same as the proc_lev_eqnsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Clear duplicated level SPECSETs: If this option is checked, level set duplicates are removed from the test program. This option is the same as the proc_lev_specsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.
  - Keep level EQNSETs: In this field, you can specify level equation sets that will be ignored. It is similar to Keep wavetables, described above.

This option corresponds to the skip_lev_eqnsets parameter of the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command.

- User Scripts: In this area, you can specify scripts that are executed before or after the Clear Duplicates command:

  - Preprocessing script: You can specify any executable script to be executed when you click Run, before the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command itself is executed.

Clicking Browse lets you choose a script file from disk.

Clicking Args lets you specify which arguments to pass to the script. (The script is assumed to know how to handle these arguments.)

  - Postprocessing script: This is similar to Preprocessing script, except that the script is run after the [clear_duplicated](<02.09.02.03.26_clear_duplicated.md>) command has been executed.

- Analyze: Clicking this button analyzes the test program, compiling lists of duplicated and unused elements for display in the Select dialogs for specifying exceptions.
- Run: Clicking this button removes duplicate elements according to the specified settings.

The progress of the command is displayed in the STPM console view which is automatically opened.
