# tpt_generate_test_stages

The tpt_generate_test_stages command creates a data log profile from the [test stage table](<02.09.02.05.06_Test_stage_table_of_a_TPT.md>) of a test program template.

The command converts the information in the TPT specified in the [mtp_template_dir](<02.09.02.03.02_File_and_parameter_settings.md>) parameter into a data log profile for use in SmarTest. The profile is stored in the profiles/ subdirectory of the current device directory.

## Syntax

```
tpt_generate_test_stages(
[include_undefined_objects = <flag>,      ]
[pre_proc                  = <pre_proc>,  ]
[post_proc                 = <post_proc>]
)
```

## Parameters

The parameters in the order in which they are listed above:

 |

include_undefined_objects

 |

<flag> (0 or 1) specifies how STPM treats undefined objects in the [test stage table](<02.09.02.05.06_Test_stage_table_of_a_TPT.md>):

- 0: Undefined objects are not included in the data log profile.
- 1 (default): Undefined objects are treated as enabled.

An object is considered undefined for a test stage when the object's row contains neither Y nor N in the column for that test stage.

If this parameter is omitted, 1 is used. That is, undefined objects are considered to be enabled.

 |
 |

pre_proc

 |

<pre_proc> is a script that is executed before this command.

The syntax of the parameter value is described in [Preprocessing and postprocessing scripts](<02.09.02.03.03_Preprocessing_and_postprocessing_scripts.md>).

This is an optional parameter.

 |
 |

post_proc

 |

<post_proc> is a script that is executed after this command.

The syntax of the parameter value is described in [Preprocessing and postprocessing scripts](<02.09.02.03.03_Preprocessing_and_postprocessing_scripts.md>).

This is an optional parameter.

 |

## Functional changes

- Introduced in SmarTest 7.2.1
- SmarTest 7.2.2: Added the pre_proc and post_proc parameters.
