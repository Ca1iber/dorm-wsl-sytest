# Common Components of All Hook Functions

## Common Parameters:

All hook functions have the two parameters result and stReturn which allow them to pass a return value back to the driver, or to SmarTest, respectively.

The return value for SmarTest (stReturn) must be set if the return value for the driver (result) is PHEVENT_RES_ABORT. For the function phHookActionStart, also if result is PHEVENT_RES_HANDLED.

The parameter result determines how the driver will proceed after the hook function was executed. result can take one of the following values:

- PHEVENT_RES_VOID

The driver will continue with its normal operation as if the hook function had not been called. The hook function has done nothing.

- PHEVENT_RES_CONTINUE

The driver will continue with its normal operation as if the hook function had not been called. The hook function has done something (for example, prompted a message), but it is necessary that the driver continues normally.

- PHEVENT_RES_HANDLED

The driver will not continue with the operation which caused the calling of the hook function, but proceed as if this operation had been successfully finished. The hook function has replaced the normal driver operation and done everything that allows the driver to proceed accordingly.

- PHEVENT_RES_ABORT

The driver will not continue with the operation which caused the calling of the hook function. The current PROB_HND_CALL will be aborted and the next application model line will be executed. The hook function neither handled the situation (in case of a problem), nor replace the normal driver operation. The hook function must also return the SmarTest return value.

See [Appendix A Hook Function Execution Flow](<02.09.01.03.08.09_Appendix_A__Hook_Function_Execution_Flow.md>) for details about how the driver and hook function execution is determined by the result values.

The Parameter stReturn can take one of the values:

PHTCOM_CI_CALL_PASS, PHTCOM_CI_CALL_ERROR, or PHTCOM_CI_CALL_BREAKD

These values fully correspond to the normal command set return values CI_CALL_PASS, CI_CALL_ERROR, and CI_CALL_BREAKD, which are described in the manual Command Interface.

The driver maps the returned PHTCOM_CI_CALL_X value to the corresponding CI_CALL_X value, and then passes it to SmarTest.
