# Basic Driver and Hook Function Interaction

This section explains several general aspects of the interaction between the driver and hook functions.

- During its initialization, the driver checks which of the five hook functions are activated (see [Activating a Hook Function](<02.09.01.03.09.04.03_Activating_a_Hook_Function.md>)). Only activated hook functions will be called by the driver later on.
- After its execution, a hook function returns a result status to the driver which tells the driver if the hook function has done something, and how the driver must continue its operation. There are four different types of result status (see [Description of the Hook Function Templates](<02.09.01.03.09.04.02_Description_of_the_Hook_Function_Templates.md>) for details).

[Appendix A: Hook Function Execution Flow](<02.09.01.03.08.09_Appendix_A__Hook_Function_Execution_Flow.md>) contains a description of the execution flow of driver and hook function in pseudo C code.

- Hook functions typically interact with SmarTest using the CPI library, and read certain driver states.

However, hook functions also allow you to access and change many sensitive parts of the driver, for example internal driver settings. Be extremely careful when changing internal driver states, as this can easily cause driver malfunction. In general, driver state changes should be avoided unless the hook function completely substitutes a driver's command.
