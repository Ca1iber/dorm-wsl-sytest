# Parameter: end_of_test_delay_time

Some handlers require a minimum time between sending the test start signal and being able to receive an end of test signal.

If the device test is faster than this minimum time, the end of test signal may not be recognized by the handler.

This parameter delays the sending of the end of test signal by the driver.

The end of test signal will not be sent earlier than the time specified (in milliseconds), after the test start signal.

Driver default: depends on plug-in

Changeable at run-time: yes

Applicable for: handlers and probers

Example: end_of_test_delay_time: 0
