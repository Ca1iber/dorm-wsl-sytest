# Notes regarding the RFS configuration files

For safety reasons, the RFS handler cannot be remotely started by using GPIB commands. It is therefore recommended to configure the driver so that it does not stop and start the handler in case SmarTest is paused (default for delivered configuration files). If the driver is however so configured, a message will be written to the report window, informing the operator that manual start of the handler is required.

The testresults GPIB command and bin verification mode are currently not supported for the RFS handlers. The SW revision of RFS where they will be supported is not yet known. So, currently the driver cannot automatically check to find out whether bin verification and the faster testresults command can be used. In the current driver revision, the parameter verify_bin_data influences whether testresults is used or not.

In this case, the driver uses these features as described in the following cases:

- If verify_bin_data is not given in the configuration (default), s bin bin and s reprobe are used to bin or reprobe devices.
- If verify_bin_data is set to no in the configuration, bin verification will be disabled and testresults will be used to transfer the binning and reprobe information instead of s bin bin and s reprobe commands.
- If verify_bin_data is set to yes in the configuration, verification mode is activated by the driver. The driver will switch over to use the commands testresults, querybins, releaseparts and verifytest.
