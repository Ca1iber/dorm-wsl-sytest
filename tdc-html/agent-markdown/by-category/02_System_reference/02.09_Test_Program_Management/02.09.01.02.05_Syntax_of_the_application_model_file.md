# Syntax of the application model file

#### Subtopics

- [Explanation of the Syntax Structure](<02.09.01.02.05.01_Explanation_of_the_Syntax_Structure.md>)
- [Keyword Explanation](<02.09.01.02.05.02_Keyword_Explanation.md>)

This chapter gives the structure syntax of the application model file together with an explanation of the keywords in it. It is intended mainly as a reference section, where you can check if your syntax is correct.

If you prefer to see a few examples of how an application model file is structured, and how it can be modified, before getting in to the syntax, see [Example of modifying your application model](<02.09.01.02.03_Example_of_modifying_your_application_model.md>).

The first part of this chapter lists the Backus Naur Format (BNF) application model file. This listing shows you the overall structure of the application model file, and how each of the smaller sections within it are structured. In the BNF description of the application model, certain keyword expressions are used which are unique to i (WORKORDER_MANAGER_INPUT, GET_TEST_INFO, dpsCurrent_limit, for example); these keywords are individually explained in the second part of the chapter. For each of the keywords, associated syntax entities are given. These can be similar keyword expressions and/or related section entities in the BNF description (<access>, <action_parameter>, <keyword>, for example).

Note  The BNF keywords can use executables. These executables (for example, user procedures, shared libraries etc.) generated in a Unix 11.i environment cannot be used in a Unix 10.2 environment. The executables generated in a Unix 10.2 environment can be used in the Unix 11.i environment.
