# Status query

You can use GPIB commands to read the handler status. These commands can be sent by the function [ph_get_status()](<02.09.01.03.08.04.02_Function__ph_get_status.md>).

 |

Message from driver

 |

Message from handler

 |

Description

 |
 |

`ACMCONTACT?`

   | |

The driver asks for the total number of contactors.

 |
 |

 |

`CONTACT_dataA;data1,data2,... dataN`

 |

- dataA: Total contactor count
- data1: Contactor 1 count
- data2: Contactor 2 count
- ...
- dataN: Contactor n count

The value of N is the number of devices tested in parallel.

 |
 |

`ACMERROR?`

 |

 |

The driver asks for the total number of errors.

 |
 |

 |

`ERROR_dataA;data1,msg1;data2,msg2; ...,dataN,msgN;`

 |

- dataA: Error count
- data1,msg1: The first error count and message number.
- data2,msg2: The second error count and message number.
- ...
- dataN,msgN: The nth error count and message number.

The value of N is the number of the error conditions.

 |
 |

`ACMJAM?`

 |

 |

The driver asks for the total number of jams.

 |
 |

 |

`JAM_dataA;data1,msg1;data2,msg2;..., dataN,msgN;`

 |

- dataA: Jam count
- data1,msg1: The first jam count and message number.
- data2,msg2: The second jam count and message number.
- ...
- dataN,msgN: The nth jam count and message number.

The value of N is the number of the error conditions.

 |
 |

`ACMRETRY?`

 |

 |

The driver asks for the total number of retries.

 |
 |

 |

`RETRY_dataA;data1,data2,...,dataN`

 |

- dataA: Retry count
- data1: The first retry count
- data2: The second retry count
- ...
- dataN: The nth retry count

The value of N is the number of vacuum heads.

 |
 |

`ACMTIME?`

 |

 |

The driver asks for total elapsed time.

 |
 |

 |

`OPERATION_timeA;timeH;timeL;`

 |

- timeA: Normal operating time
- timeH: High alarm processing time
- timeL: Low alarm processing time
 |
 |

`ACMTOTAL?`

 |

 |

The driver asks for the statistics.

 |
 |

 |

`TOTAL_dataA;dataB;dataC;data0, data1,data2,...,data9,dataR, data10,...,dataN`

 |

- dataA: Number of loaded devices
- dataB: Reject count
- dataC: Number of sorted devices
- data0: Category 0
- data1: Category 1
- data2: Category 2
- ...
- data9: Category 9
- dataR: Retest category
- data10: Category 10
- ...
- dataN: Category N

The value of N is the maximum number of categories.

 |
 |

`CURRENTALM?`

 |

 |

The driver asks for the current code of the alarm message.

 |
 |

 |

`CURRENTALM_msg1,msg2,...,msgN;`

 |

- msg1: The first current alarm message
- msg2: The second current alarm message
- ...
- msgN: The nth current alarm message

The value of N is the number of current alarms.

 |
 |

`HANDLERNUM?`

 |

 |

The driver asks for the individual handler ID number.

 |
 |

 |

`HANDLERNUM dddddd`

 |

The individual handler ID number is a six-digit number.

 |
 |

`LOTERROR?`

 |

 |

The driver asks for the total number and the code of message.

 |
 |

 |

`ERROR_dataA;data1,msg1;data2,msg2; ...,dataN,msgN;`

 |

- dataA: Error count
- data1,msg1: The first error count and message number.
- data2,msg2: The second error count and message number.
- ...
- dataN,msgN: The nth error count and message number.

The value of N is the number of the error conditions.

 |
 |

`LOTJAM?`

 |

 |

The driver asks for the total number and the code of jam.

 |
 |

 |

`JAM_dataA;data1,msg1;data2,msg2;..., dataN,msgN;`

 |

- dataA: Jam count
- data1,msg1: The first jam count and message number.
- data2,msg2: The second jam count and message number.
- ...
- dataN,msgN: The nth jam count and message number.

The value of N is the number of the error conditions.

 |
 |

`LOTRETRY?`

 |

 |

The driver asks for retries.

 |
 |

 |

`RETRY_dataA;data1,data2,...,dataN`

 |

- dataA: Retry count
- data1: The first retry count
- data2: The second retry count
- ...
- dataN: The nth retry count

The value of N is the number of vacuum heads.

 |
 |

`LOTTIME?`

 |

 |

The driver asks for the elapsed time.

 |
 |

 |

`OPERATION_timeA;timeH;timeL;`

 |

- timeA: Normal operating time
- timeH: High alarm processing time
- timeL: Low alarm processing time
 |
 |

`LOTTOTAL?`

 |

 |

The driver asks for the summary of lot.

 |
 |

 |

`TOTAL_dataA;dataB;dataC;data0,data1, data2,... ,data9,dataR,data10,... ,dataN`

 |

- dataA: Number of loaded devices
- dataB: Reject count
- dataC: Number of sorted devices
- data0: Category 0
- data1: Category 1
- data2: Category 2
- ...
- data9: Category 9
- dataR: Retest category
- data10: Category 10
- ...
- dataN: Category N

The value of N is the maximum number of categories.

 |
 |

`MEASTEMP?`

 |

 |

The driver asks for the measured temperature of the handler.

 |
 |

 |

`Meastemp 卤ddd.d`

 |

The handler asks for the data from the Pt channel which is the closest to the contactor socket regardless of the temperature control of the handler.

 |
 |

`SETTEMP?`

 |

 |

The driver asks for the set temperature of the handler.

 |
 |

 |

`Settemp 卤ddd.d`

 |

The handler returns the [Set Temp.] parameter values regardless of the temperature control of the handler.

 |
 |

`LDPOCKET?`

 |

 |

For DLT driver enhancement.

The driver asks for the number of the loader tray (waffle pack) .

 |
 |

`LDTRAY?`

 |

 |

For DLT driver enhancement.

The driver asks for the number of the loader tray (waffle pack) pocket .

 |
 |

`DVID?`

 |

 |

For YUSHAN driver enhancement.

The driver asks for the ID of the device under test from the handler.

 |
 |

 |

`DVID ddd`

 |

The handler returns the ID of the tested device.

For example, `DVID 001`, in which 001 is the device ID of the tested device.

 |
 |

`TLOOP?`

 |

 |

For YUSHAN driver enhancement.

The driver asks for the number of temperature set points.

 |
 |

 |

`TLOOP ddd`

 |

The handler returns the number of temperature set points.

For example, `TLOOP 4`, in which 4 is the amount of temperature set points.

 |
 |

`TSSET?`

 |

 |

For YUSHAN driver enhancement.

The driver asks for the test sequence setting (temperature sequence and subloop).

 |
 |

 |

`TSSET n, 卤dd, c...`

 |

The handler returns the sequence setting.

Example:

The number in the TLOOP 3 message indicates that there are three sets of temperature in Celsius for cycle temperature testing.

`TSSET1,-40,3,2,110,5,3,25,4`

The first set is 1,40,3.

- 1 is the first order number, -40 is the temperature, and 3 is the subloop.

The second set is 2,110,5.

- 2 is the second order number, 110 is the temperature, and 5 is the subloop.

The third set is 3,25,4.

- 3 is the third order number, 25 is the temperature, and 4 is the subloop.
 |
 |

`DEVICEID [n]`

 |

 |

The driver gets a 2D barcode of a specified device ID. If no ID has been specified, the driver returns all 2D barcodes for all devices.

 |
 |

 |

Examples:

`1345678900000000 | 1,1234567800000000; 2,2345678900000000; ......; n,1245678000000000; | DATANG`

 |

The reply depends on the value of n:

- If n is specified as a valid device ID, a 16-digits 2D barcode is returned.
- If n is an invalid number, the DATANG is returned.
- If no n is specified, then the driver returns all barcodes for all devices.
 |
