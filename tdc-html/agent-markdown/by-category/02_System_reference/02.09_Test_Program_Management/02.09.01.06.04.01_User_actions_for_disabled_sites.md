# User actions for disabled sites

When multiple sites with many digital channels are tested, there are rare cases where a digital channel becomes defect. Depending on the failure's root cause, a particular user action is required.

Failure modes
 |

Error case

 |

Symptoms

 |

Root Cause

 |

User Action

 |
 |

1

 |

Diagnostics or calibration identifies a pin as defective.

 |

Front-end failure, but test processor is okay.

 |

Add defective channel to MCDIgnore file (see MCDIgnore file in Service_Guide Part 1). Restart SmarTest. Channel is marked as unavailable. Disable site on handler. Loading the pin configuration will automatically disable the site the channel of which is defect.

 |
 |

2

 |

Diagnostics, calibration and pin configuration report "channel unavailable".

 |

Test processor is defective.

 |

Disable site on handler. Load pin configuration.

 |
 |

3

 |

Software fails with sequencer timeout of a channel.

 |

Test processor fails during test.

 |

If the failing channel is known, add it to the MCDIgnore file (see MCDIgnore file in Service_Guide Part 1). Disable the site on the handler. Exit SmarTest and start it again. Loading the pin configuration disables sites with defective channels.

 |
 |

4

 |

All tests fail on one site.

 |

Front-end failure (including contact failures).

 |

Disable the site using the site control window. Disable the site on the handler. Continue testing.

 |
