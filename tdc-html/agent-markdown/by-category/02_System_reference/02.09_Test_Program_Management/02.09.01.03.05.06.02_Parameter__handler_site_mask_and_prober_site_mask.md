# Parameter: handler_site_mask and prober_site_mask

This mask tells the driver which of the equipment sites are active (=1) and which are (currently) deactivated (=0). The mask corresponds to the parameters handler_site_ids, or prober_site_ids, respectively.

Telling the driver about deactivated sites avoids unnecessary latency delays (see [Parameter: maximum_multi_site_latency](<02.09.01.03.05.12.09_Parameter__maximum_multi_site_latency.md>)).

Driver default: [ 1 1 1 ... ] (corresponding to handler/prober_site_ids)

Changeable at run-time: yes

Applicable for: handlers or probers, respectively

Example: handler_site_mask: [1 1 0 1]
