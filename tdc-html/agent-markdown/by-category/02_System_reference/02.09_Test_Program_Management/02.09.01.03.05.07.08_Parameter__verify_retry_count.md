# Parameter: verify_retry_count

If the parameter verify_bin_data is set to "yes", it is possible to define the maximum number of retries which will be applied in case the verified binning data is corrupt. Taken the binning data has been verified as corrupt within the first verification and if verify_retry_count is set to 1, the binning data will be sent once more and has to be verified as corrupt again, before the driver will issue a fatal error message and stop.

Driver default: 1

Changeable at run-time: yes

Applicable for: handlers and probers, plug-in dependent

Example: verify_retry_count: 3
