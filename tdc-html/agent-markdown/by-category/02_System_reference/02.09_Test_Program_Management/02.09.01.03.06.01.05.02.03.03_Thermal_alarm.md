# Thermal alarm

When a thermal alarm occurs during a test, the driver aborts the test program and disconnects all devices under test.

The actions are:

- `<log DTR>`
- `<exit test flow>`
- `<kill test method manager process>`
- `<kill ATE server process>`
- `<OVERTEMP>`
- `<current alarm message>`
- `<abort test program>`

 | Message from driver  | Message from handler  | Description |
 |   | `0x48 | 0x49` |

The handler sends the thermal alarm SRQ to the driver.

 |
 |

`log DTR:`

The driver records THERMAL ALARM into DTR. |
 |

`exit test flow:`

The driver sets a system flag to exit the testflow. |
 |

`kill test method manager process:`

The driver kills the test method manager process to ensure that the test can be aborted immediately.

 |
 |

`kill ATE server process:`

The driver kills the ATE server process to abort the test. |
 |

`OVERTEMP:`

The driver asks for which site has generated the thermal alarm.

 |
 | `OVERTEMP?`  |   | The driver asks for which site has generated the thermal alarm. |
 |   | `OVERTEMP n` |

The handler replies which site has generated the thermal alarm.

 |
 |

`Current alarm message:`

The driver asks for the current alarm message number. |
 | `CURRENTALM`?  |   | The driver asks for the current alarm message. |
 | |

`CURRENTALM_msg1,msg2,...,`

`msgN;`

 |

msg1: The first current alarm message.

msg2: The second current alarm message.

...

msgN: The nth current alarm message.

The value of n is the number of current alarms.

 |
 |

`abort test program:`

The driver aborts the test program; and the devices are binned to the "otherwise" bin.

   |  Note The thermal alarm feature is supported by Advantest GS1 handlers only.
