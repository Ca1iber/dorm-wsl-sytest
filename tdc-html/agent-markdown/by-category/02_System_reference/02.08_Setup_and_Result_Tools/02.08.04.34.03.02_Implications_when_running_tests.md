# Implications when running tests

After you complete your setups you can start running tests. You can change the position of the edges while a test is in progress by switching to a different timing set in the current waveform set. You do this with a sequencer instruction (CTIM) in the Pattern Tool. You must, however, take the possibility of reduced timing accuracy of the period in timing sets other than TS1 into consideration.

## Multiple Waveform Sets

Before you do anything else with timing, you have to define the number of waveform sets that you actually want to use. If you Do not, the system assumes you want to use just one waveform set. Enter the number into the WFset entry field in the Timing Setup window.

Applications for using multiple waveform sets are:

- switching edge usage for IO pins.
- using different timing for binning tests. You can change the vector rate (and edge positions) in the waveform sets.

Interface operations with waveform sets are described in [Working with Multiple Waveform and Timing Sets](<02.08.04.34.06.11_Working_with_Multiple_Waveform_and_Timing_Sets.md>).

## Multiple timing sets

The system lets you create up to 999 different timing sets. You will need multiple timing sets for applications that require you to vary the timing parameters during a test sequence.

At power-up, one timing set exists, containing the default values for the configured pins. This set is identified as Timing Set 1. Any new timing sets you create are numbered sequentially by the test system.

Applications for using multiple timing sets are:

- making quick timing changes while a test is in progress.
- obtaining high throughput.

Interface operations with timing sets are described later in the chapter under [Working with Multiple Waveform and Timing Sets](<02.08.04.34.06.11_Working_with_Multiple_Waveform_and_Timing_Sets.md>).

## Effects of multiple timing sets on the timing accuracy

Whenever you set the system period (see [Setting the period](<02.08.04.34.06.05_Setting_the_period.md>) and [Minimum period / maximum frequency of the sequencer](<02.08.04.34.06.05.01_Minimum_period___maximum_frequency_of_the_sequencer.md>)), the system defines the master clock period. This is derived from the period setting of Timing Set 1 of the current waveform set. The master clock period always remains in the range of 4 to 10 ns.

The resolution of the master clock is defined by Timing Set 1. You therefore always get the programmed vector rate in Timing Set 1.

All other timing sets you create for the same waveform set assume a period which takes the nearest multiple of the master clock period. The deviation of the test system period in timing sets other than 1 from the desired period can be up to ± 6ns.

## Changing the vector rate - the trade-offs

To change from one accurate period to another, you must switch to a different waveform set. This reprograms the VCO. You can switch waveform sets only between tests.

Should your requirement be changing the period "on-the-fly", you can do so by switching to a different timing set within the same waveform set. This changes the value in the timing system counters. You can switch timing sets while a test is running.

If you require different vector rates to run your tests, you may need to weigh up what is more important to you - an accurate period, or the ability to effect a quick change to a different period while your test is in progress.
