# Defining edge delays for a PRBS test

The edges for a PRBS test are distibuted equidistantly within the tester cycle. This holds for both input and output pins. But you can define a start delay for the first (drive or receive) edge. You must specify the number of edges per cycle with the period_div keyword. This number must equal the corresponding value of the PRBS_I or PRBS_O statement within the wavetable which is to be associated with the equation set in question (see [Defining the wavetable for a PRBS test](<../02.06_Command_Reference/02.06.06.01.03.02.02_Defining_the_wavetable_for_a_PRBS_test.md>)).

You can also combine a PRBS check with transition tracking. In this case, you must specify a TTMODE statement with the required x-mode in the timing set for the output pin. Furthermore, the PRBS input pin must also be set to this same x-mode. For details of the protocol engine test setup, see [Combining transition tracking with a PRBS or pattern‑based SmartLoop test](<../02.06_Command_Reference/02.06.15.02.01_Combining_transition_tracking_with_a_PRBS_or_pattern__ased_SmartLoop_tes.md>).

## Example

```
EQNSET 3 "prbs"
. . .
TIMINGSET 1 "eqs 3 ts 1"
PINS IN1
period_div = 6
d1 = 0.5
. . .
PINS OUT1
TTMODE X6
r1 = 1.0
. . .
```

This example can be combined with the example of [Defining the wavetable for a PRBS test](<../02.06_Command_Reference/02.06.06.01.03.02.02_Defining_the_wavetable_for_a_PRBS_test.md>) in one timing specification.
