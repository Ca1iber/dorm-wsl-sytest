# Transaction details

The transaction details are shown if you select a transaction in the protocol editor's overview area.

  ![Transaction details](<../../../../raw/126145.png>)

The transaction details are divided into different sections like parameters, symbols of parameter and functions.

The protocol describes different transactions to exchange information between the sender and receiver of an interface. Typical transaction names are read and write.

Mandatory transaction properties are the transaction name and length (in bits/state characters).

 Note The transaction length has to match the total length of all fields defined for that transaction!

## Parameters

Transaction parameters can be used within test methods to pass variables to a transaction. This way one can create dynamic transactions. Typical parameters of read/write transactions are register address, physical address and register data.

The order of the parameter definition has an impact to the corresponding transaction and the resulting state character sequence.

The state character sequence representing a decoded field will be mapped back to transaction parameters during parameter reconstruction in order to be readable from test methods.

For output parameters the decode function describes how the received bits/state character sequence (represented by the parameter value) is transferred back to fields.

Display mode

 |

Specifies the number format in which numerical parameter values are displayed in the TA column of the Pattern Debug Tool. Possible values are "BINARY", "DECIMAL", and "HEX". HEX is the default.

The property is ignored if the parameter value is specified as a state character sequence.

## Symbols of selected parameter

Symbolic names for special state character sequences may be specified here to improve readability and prevent duplication of SCS.

If defined, these symbols are used for encoding and decoding at transaction level.

## Functions

The encode/decode functions defined here at transaction level are considered global for that transaction.

This means, when encoding at transaction level any pin role specific encode functions are applied first.

When decoding at transaction level the state character sequence, representing the protocol, is cut into transaction subsequences based on the defined length. Here the transaction's global function is applied first.
