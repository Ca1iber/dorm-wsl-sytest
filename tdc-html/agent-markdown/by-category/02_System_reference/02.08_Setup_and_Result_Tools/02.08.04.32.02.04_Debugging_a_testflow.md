# Debugging a testflow

#### Subtopics

- [Single step testflow debugging](<02.08.04.32.02.04.01_Single_step_testflow_debugging.md>)

SmarTest automatically displays the Debug view when the Testflow tool is open.

Before starting a debug session, set the [Debug Mode flag](<02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_debug_mode>) to choose the level of debug information in the [Report window](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.13_Report_window.md>).

To step through the testflow, test suite for test suite, see [Single step testflow debugging](<02.08.04.32.02.04.01_Single_step_testflow_debugging.md>). For debugging individual test methods, see [How to debug a universal test method](<../02.07_Test_Method_Reference/02.07.02.02.04_How_to_debug_a_universal_test_method.md>).

When you debug a, potentially multi-site, testflow, the [Site Control Window](<02.08.04.27_Site_Control_Window.md>) lets you identify passing and failing sites and view the results of individual sites with the result tools.

When you perform multisite testing using analog modules shared among multiple sites, you can also view and change the test order of sites for every site in the testflow in the expanded window.

 Note Running a wide selection behaves different than running a narrow selection (see [Narrow selection and wide selection](<02.08.04.32.02.01.11.01_Narrow_selection_and_wide_selection.md>)). Running a wide selection will behave like a [full testflow execution](<02.08.04.32.02.03_Running_a_testflow.md>) without disconnecting on [Binning](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.01.03.01.01_Binning.md>).
