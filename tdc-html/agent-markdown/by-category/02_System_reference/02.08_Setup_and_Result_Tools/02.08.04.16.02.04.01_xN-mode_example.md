# xN-mode example

This topic explains the usage of the xN-mode on the basis of an example.

In the example below, the base tester rate is 1.2 MHz (tester cycle). The example generates clock pulses at three different data rates:

- for signal Pin1: 4.8 MHz,
- for signal Pin2: 7.2 MHz, and
- for signal Pin3: 9.6 MHz.

These data rates can be reached by using the following x-modes:

- for signal Pin1: x2-mode,
- for signal Pin2: x3-mode, and
- for signal Pin3: x4-mode.

This is the wavetable related to the example:

```

WAVETBL mytable

PINS Pin1 Pin2 Pin3
0 "{d1:1 d2:0} {d3:1 d4:0}" P-2
1 "{d1:1 d2:0} {d3:1 d4:0} {d5:1 d6:0}" P-3
2 "{d1:1 d2:0} {d3:1 d4:0} {d5:1 d6:0} {d7:1 d8:0}" P-4

STATEMAP
#physSeq  statechars  x-mode  selector
0         PP          x2
1         PPP         x3
2         PPPP        x4

```

The PINS section defines three waveforms for all pins. All edges related to one x-mode cycle are included in curly braces.

The STATEMAP section defines the x-modes used in the Pattern Editor. The columns have the following meaning:

- `#physSeq` refers to the waveforms defined in the PINS section.
- `statechars` defines the state characters displayed in the x-mode format in the Pattern Editor. For a description of the different formats, see [Configuring the layout of the Pattern Editor](<02.08.04.16.02.06.02_Configuring_the_layout_of_the_editor.md>).
- `x-mode` defines the x-mode used in the Pattern Editor.
- `selector` is not used in this example.

This is the timing equation set related to the example:

```

EQNSET 1 "timeqnset1"

SPECS
Frequency [MHZ]

EQUATIONS
Tcyc=1000/Frequency

TIMINGSET 1 "timset1"
period=Tcyc

PINS Pin1
d1=(0/4)*Tcyc
d2=(1/4)*Tcyc
d3=(2/4)*Tcyc
d4=(3/4)*Tcyc

PINS Pin2
d1=(0/6)*Tcyc
d2=(1/6)*Tcyc
d3=(2/6)*Tcyc
d4=(3/6)*Tcyc
d5=(4/6)*Tcyc
d6=(5/6)*Tcyc

PINS Pin3
d1=(0/8)*Tcyc
d2=(1/8)*Tcyc
d3=(2/8)*Tcyc
d4=(3/8)*Tcyc
d5=(4/8)*Tcyc
d6=(5/8)*Tcyc
d7=(6/8)*Tcyc
d8=(7/8)*Tcyc

```

In the pattern editor in the figure below, every signal appears in three different columns. Each column displays the signal in a different format:

- in the x-mode format (SC = state character),
- in the device cycle (DVC) names format, and
- in the physical waveform (PW) DC/DC power units format.
  ![Pattern Editor showing xN example pattern](<../../../../raw/100465.png>)

The device sees x-mode vectors (pulses P in this example) at different data rates. The logic is represented exactly as the device sees the data and it is possible to edit each x-mode vector individually.
