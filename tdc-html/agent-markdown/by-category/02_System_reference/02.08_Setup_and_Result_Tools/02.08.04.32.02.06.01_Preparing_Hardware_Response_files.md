Hardware response files are required when debug a testflow or test suite using the emulator.

## About this task

To debug a testflow or test suite using the emulator, first, prepare the [Hardware response files](<02.08.04.32.02.06.03_Hardware_response_files.md>) for all test suites and test method APIs for retrieving data used in the testflow or test suite.

To prepare the hardware response files, set up the emulator and run a testflow using the emulator in Store mode.

## Before you begin

Make sure the following prerequisites are met:

- Connected to a test system
- Required SmarTest version is activated
- SmarTest is running. For details, see [Starting SmarTest](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.01_Starting_SmarTest.md>).
- Required test flow is loaded and Load all Setups has been executed. For details, see [Loading a testflow and all setup components](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.02.01.05_Loading_a_testflow_and_all_setup_components.md>).
- Testflow opened in Flow Sequence Editor: Open with > Flow Sequence Editor. For details, see [Flow Sequence Editor](<02.08.04.32.03.02_Flow_Sequence_Editor.md>).
- All sites that must be available offline are active.

## Procedure

-   Right-click in the test flow window and choose Run > Open Run Dialog

The Run Configurations dialog box opens.

![Rn configuration window](<../../../../raw/351465.png>)

-  Right-click Testflow (Full) and create a new testflow, with the name Testflow (Full_HWRE).
-  From the tree list on the left, select the testflow Testflow (Full_HWRE), for which the hardware response files are required.
-  In the Response Emulator pane on the right, select the Enable check box and Store mode.
-  Click Apply followed by Run to run the testflow.
-  The Hardware Response Emulator window opens. In the Please Select HW Response Emulator Mode panel, you can see that the Emulator ON (Store) button is selected.    ![Hardware Response Emulator window](<../../../../raw/111621.png>)

  -  Set the Enable emulating testmethod based test suite results check box according to your requirements:

-  Set the hardware response directory:

  -  Accept the suggested path (default), or replace with an alternative if preferred in the Path field. If you enter a name in the HW Response Directory field, a new directory with that name is created.

When you use the Hardware Response Emulator in online import mode, if you specify a new directory or a directory that does not contain necessary hardware response data as hardware response directory, the emulator opens a dialog to show the current measurement result retrieved from hardware for supported API in your test method program and ask you to use it instead of the specified hardware response data, because the specified directory has no HW Response data. This is very useful for debugging your programs because it lets you view the current captured results such as captured waveforms, measurement values, and so on.

-  On the right pane of the Hardware Response Emulator window you find the HW Response Emulator Enable list, which shows all the test suites in the testflow file. By default, all test suites are selected.

From this list, select the target test suites for which the emulator is to create hardware response files (unselect the suites you do not want to be taken into generation of the HWRE files).

When the emulator is called for executing the test suite, it creates or imports the hardware response file for the test suite and the test method API called in the test suite.

The configuration is now complete.

-  Click OK to close the Hardware Response Emulator window.

 SmarTest automatically starts with the settings specified in the Run Configuration (as shown in the graphic above) and creates the hardware response files.

## Results

The hardware response files storing the hardware response data are generated in the specified hardware response directory.
