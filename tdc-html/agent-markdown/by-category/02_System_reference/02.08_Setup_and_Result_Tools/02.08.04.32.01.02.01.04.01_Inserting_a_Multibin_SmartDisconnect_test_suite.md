# Inserting a Multibin SmartDisconnect test suite

The Multibin SmartDisconnect test suite is a combination of a multibin node and a user defined test suite. It is inserted like a multibin node into the fail branch of a Run and Branch test suite.

## About this task

In a test program with several sites and test suites, the hardware for failing sites must be deactivated and disconnected after a failed test suite. This must meet the needs of the DUT and take into account the current hardware settings. This task describes how to define a universal test method class and insert it as Multibin SmartDisconnect test suite into the testflow.

An alternative method is to insert an existing floating test suite as Multibin SmartDisconnect test suite. For more information, refer to [Connecting a floating test suite to the testflow](<02.08.04.32.02.01.04.03.01_Connecting_a_floating_test_suite_to_the_testflow.md>).

## Before you begin

The Testflow Tool is open and the testflow has been loaded.

## Procedure

-  Create a universal test method class that handles the disconnection of the hardware.

For creating the test method class, refer to [How to create a universal test method class](<../02.07_Test_Method_Reference/02.07.02.02.02_How_to_create_a_universal_test_method_class.md>).

 The following rules are to be considered for the test method class:

  - The Multibin SmartDisconnect test suite is inserted into the fail branch of a Run and Branch test suite. The new test method class must therefore be based on the hardware settings of the Run and Branch test suite and must disable and disconnect the hardware related to the failing sites in a way that meets the needs of the DUT.
  - The site mask is already inverted by SmarTest when entering the run() function: Only sites are active for which the associated Run and Branch test suite has failed. The site mask is reset automatically to the still passing sites when leaving the Multibin SmartDisconnect test suite.
  - Use only test method APIs or [SmartRDI](<../02.07_Test_Method_Reference/02.07.13_SmartRDI.md>) based code. SmartRDI based code is recommended.
  - Since the created test method class can be reused as normal test suite, you can use the test method API [GET_DISCONNECT_CONTEXT()](<../02.07_Test_Method_Reference/02.07.04.01.84_GET_DISCONNECT_CONTEXT.md>) to determine whether the test method is running as a normal test method or as disconnect test method that is assigned to a Multibin SmartDisconnect test suite.

-  Insert a Multibin SmartDisconnect test suite.

  -  In the Flow Sequence Editor, select the fail branch insertion point of a Run and Branch test suite where you want to insert the Multibin SmartDisconnect test suite.
  -  Right-click and select Multibin Disconnect from the palette.    ![Inserting a Multibin SmartDisconnect test suite](<../../../../raw/353654.png>)

The New Multibin Disconnect Wizard opens.

  -  In the New Multibin Disconnect Wizard enter the required information for the node and click Finish.    ![New Multibin SmartDisconnect Wizard](<../../../../raw/353712.png>)

The previously created test method is to be selected. This test method may be reused for other Multibin SmartDisconnect test suites if it matches the hardware setup in the fail branch.

## Results

You have inserted a Multibin SmartDisconnect test suite into the fail branch of a Run and Branch test suite.

  ![Multibin SmartDisconnect flow 1st node](<../../../../raw/353999.png>)  The example flow shown above uses the "Disconnect_all" test suite at the end. You must always add a test suite to the end of the test flow to apply a disconnect sequence adapted to the needs of the passed sites. If you insert a Multibin SmartDisconnect test suite also into the fail branch of the previously performed "Test_3" test suite, you can reuse the assigned disconnect test method class for the final disconnect in test suite "Disconnect_all".
