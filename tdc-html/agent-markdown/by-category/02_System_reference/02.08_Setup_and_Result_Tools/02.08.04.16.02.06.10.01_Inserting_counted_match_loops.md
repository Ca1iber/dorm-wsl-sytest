# Inserting counted match loops

## About this task

Match loops are used to put a DUT without a reset pin into a state required for some test. The general principle is to specify a sequence of vectors that are executed in a loop and, if repeated often enough, put the DUT successively into each of its possible states. After each repetition, it is checked if the desired state has been reached. If so, the loop is terminated. If not, it is repeated.

A certain time is required for evaluating the compare result and to propagate it to the error flag that controls the repetition of the loop. To provide this time span, a number of dummy vectors without compare actions must be generated after the functional vectors before the end of the match loop.

The following figure shows the operation mode of the counted match loop:

 ![Counted match loop](<../../../../raw/10564.png>)

There are two loops, the main loop and the wait loop. The body of the main loop executes the compare vectors once, and then the wait loop.

A counted match loop is started with the MACT instruction. This instruction specifies the maximum number of unsuccessful repetitions for the main loop. The CONTINUE option specifies to carry on with the test even if all repetitions of the match loop failed. Then the compare vectors must be specified with a GENV or RPTV instruction (an exception is when using [Nested match loops](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.05.02.07_Nested_match_loops.md>), in which case you may insert the MACT or MRPT instruction here). These must be followed by the MRPT instruction, which defines the number of dummy vectors to be repeated in the wait loop. You can specify more than one dummy vector if the total number of cycles within the match loop must be a multiple of a number greater than 1.

Note Because switching into match loop mode can only be done at cycle boundaries of 8, and a match loop can start and end anywhere, the start and end cycles of a match loop block may belong to the surrounding pattern. This can have an effect on the recording in the Error Map and on the test result. Therefore the seven vectors prior to the MACT instruction and the dummy vectors must not contain any compare action. For details see [Adjusting the junctions between match loop and surrounding label](<../02.06_Command_Reference/02.06.07.01.08.04.03.01.01_Adjusting_the_junctions_between_match_loop_and_surrounding_label.md>).

## Before you begin

The Instruction column must be displayed and the pattern must be displayed in collapsed mode.

## Procedure

-  To insert the MACT instruction, right-click the Vector# or Instruction cell where you want to insert it, and select Insert Instruction.

Make sure that at least the last seven vectors before the MACT instruction contain no compare actions.

-  Double-click MACT and type the number of loops (the maximum number of unsuccessful repetitions, for example, 32.
-  Optionally select the CONTINUE option. It specifies to continue the test even if all loops (repetitions) failed.
-  Specify the compare vectors in the rows below.
-  For the last compare vector, specify the compare event (supported by DPS128 only). You can set the Compare Type to either High or Low (see also example below).
-  To insert the MRPT instruction, right-click where you want to insert it, and select Insert Instruction.
-  Double-click MRPT and type the number of vectors, i.e. the number of dummy vectors to be repeated in the wait loop, for example, 5. The REPEATEND instruction is inserted in the row after the number of specified vectors.
-  Make sure none of the receive pins of the dummy vectors is set to receive, but for example to X (Do not care).
