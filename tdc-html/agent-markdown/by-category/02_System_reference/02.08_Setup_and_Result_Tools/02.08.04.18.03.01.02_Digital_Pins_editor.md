# Digital Pins editor

Digital pins and DC Scale pins in PMU operating mode are configured in the Digital Pins editor.

The editor consists mainly of the tabular pin configuration area. The CONTEXT drop鈥慸own list at the top right allows you to select a [mode context](<../02.06_Command_Reference/02.06.03.01.03.01_Mode_contexts.md>).

   ![Digital Pins editor](<../../../../raw/355141.png>)

In the pin configuration area, the [Name](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Name>), [No](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_No>), and [Type](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Type>) parameters configure the DUT pins. The [Mode](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Mode>) and [Tester Channel](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Tester_Channel>) parameters give instructions to the software about how it must configure the test system channels. The [HW](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_HW>) parameter shows the tester channel hardware information. The [Connection Set](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Connection_Set>) parameter adds the ability to sequentially reuse DC Scale channels in other pin definitions.

The following table describes the function of these parameters.

 |

Name

 |

A descriptive and unique name for the DUT pin.

The pin name can have up to 64 alphanumeric characters. Spaces and the following characters are not allowed:

- # ; ( ' ' ) ? @ ,

It is also recommended not to use the following characters, as it will not be possible to save the Pattern Debug Tool configuration layout using these:

< >

Other SmarTest windows will always display the pin name when they refer to a pin of the DUT.

 |
 | No |

The optional parameter defines the pin number which is set according to the DUT packaging.

 |
 | Type |

The function of each pin on your DUT. The pin is configured to either to

-

drive a digital signal to the DUT and/or receive a signal from the DUT or to

-

connect a PMU channel to apply a DC signal or perform a DC measurement.

A list offers you the following choices for each pin:

- off: No pin type set.
- i: A digital input to your DUT.
- o: A digital output from your DUT.
- io: An input and output to and from your DUT. You can receive or drive a signal on this pin at any time during the test.
- dc:

  - A [DC Scale pin](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__s_DC_Scale_pin_setup>) in [PMU operating mode](<../02.05_Test_Head_Cards/02.05.05.05_PMU_operating_mode_of_DC_Scale_cards.md>) or
  - a utility DC pin

 |
 | Mode |

The operating mode of the pin.

A list offers you the following choices for each pin:

- std: Set the channel to standard mode for digital channels.
- fast: Set the channel to fast mode for Pin Scale 5000 channels.
- SIG: Set the channel to PMU operating mode for DC Scale pins.
- CMON: The pin is configured as current monitor output. This mode applies only to [XPS256 pins.](<../02.05_Test_Head_Cards/02.05.05.03_DC_Scale_XPS256_card.md>)

For more information, refer to [XPS256 current monitor](<../02.05_Test_Head_Cards/02.05.05.03.03.02_XPS256_current_monitor.md>).

 |
 | Scaling |

This column applies to the CMON option of the Mode column. The setting defines the scaling factor of the [XPS256 current monitor](<../02.05_Test_Head_Cards/02.05.05.03.03.02_XPS256_current_monitor.md>) output in volts per ampere (V/A).

 |
 | HW |

This column is not editable. After you enter the tester channel, it automatically shows the hardware information of this channel. In the Digital Pins editor, the following items may be displayed:

- PS1600: Pin Scale 1600 digital channel
- PS5000: Pin Scale 5000 digital channel
- DCS-DPS128HC, XPS256: DC Scale channel
- DMM: Utility DC pin
 |
 | Connection Set |

Optional string parameter.

This parameter is currently not supported.

 |
 | Comment  | Optional string parameter.

You can provide additional description of the pin in this column.

 |
 | Tester Channel |

The tester channels that have been wired to your DUT.

The software uniquely identifies each channel in the system using a five鈥慸igit channel鈥慖D.

The syntax for the channel specification of an IO channel is aaabb where:

- aaa: The physical pogo block number (range 101 ... 132, 201 ... 232, 301 ... 332 and 401 ... 432) or a virtual pogo block number. For more information, see [DUT interface layout](<../02.03_DUT_board_design_reference/02.03.03.01_DUT_interface_layout.md>).
- bb: The channel number (range 01 ... 16).

For example, 10301 refers to the channel 01 of the pogo block 103.

For Utility DC pins the channel id is UTIDC, followed by a three digit number, specifying the utility block of the card cage.

For DC Scale channels, there are the following additional rules:

  Ganging of DC Scale channels Unless otherwise defined below, the following rules are to be followed for defining ganging groups:

- With exception of XPS256, you can gang (parallel connect) only successive channels within a DC Scale card.
- The gang chain can start at any channel and have a minimum of 2 successive channels.
- You can specify the range of channels to be ganged by "-" (hyphen) or each channel separated by "," (comma).
- With exception of XPS256, to gang DC Scale channels, you must specify a consecutive number of channels, for example 10105-10106 (the test channel assigned for Vdd_ in the example below). The first channel in this sequence is automatically set as master channel, the others are set as slave channels.

Some other rules are to be followed for DC Scale cards:

- DPS128, DPS64:

Ganging is possible for any number of successive channels within a card, but not across cards.

DPS128/DPS64 channels must be of the same type (HC or HV).

- XPS256:

See section [Ganging characteristics](<../02.05_Test_Head_Cards/02.05.05.03.08_XPS256_ganged.md#_350922__s_Ganging_characteristics>) in [XPS256 ganged](<../02.05_Test_Head_Cards/02.05.05.03.08_XPS256_ganged.md>).

See also [Connecting DPS channels in parallel](<../02.03_DUT_board_design_reference/02.03.07.01.03_Connecting_DPS_channels_in_parallel.md>).

Note that on DPS128/64 and XPS256 you cannot execute a current compare on a ganged group of channels in unganged mode. Already activated comparators are silently disabled in unganged mode. A user notification (Error or warning) is omitted in this case, to avoid any interrupt in the testflow. The previous state of the comparators is automatically restored after the ganged group has been restored.

## DC Scale pin (PMU mode) setup

The DC Scale pin of PMU mode is set up in the Digital Pins editor. In [PMU operating mode](<../02.05_Test_Head_Cards/02.05.05.05_PMU_operating_mode_of_DC_Scale_cards.md>), you use the DC Scale card like a standard PMU to temporarily supply power in a single test suite or for a group of test suites.

The following table describes for DC Scale pins some more specific settings in the pin configuration area.

 | [Type](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Type>) |

The function of each pin on your DUT.

For a DC Scale pin in PMU operating mode, the parameter must be dc.

 |
 | [Mode](<02.08.04.18.03.01.02_Digital_Pins_editor.md#_105634__r_Mode>) |

The operating mode of the test system channel.

For a DC Scale pin in PMU operating mode, it must be SIG.

 |

- Introduced in SmarTest 6.5.0
- SmarTest 7.1.3: Changed the parameter Instrument to HW.
- SmarTest 7.1.3: Removed the parameter Ser.R[ohm].
- SmarTest 7.1.3: Added the HV mode option.
- SmarTest 7.2.0: Modified pin name length.
- SmarTest 7.3.1: New parameter "Connection Set".
- SmarTest 7.3.1: DC Scale PVI8 card added.
- SmarTest 7.4.0: DC Scale AVI64 card added.
- SmarTest 7.5.0: DC Scale FVI16 card added.
- SmarTest 7.10.0: PVI8 not supported, HV mode option not supported
- SmarTest 7.10.1: DC Scale XPS256 card added.
- SmarTest 7.10.2: XPS256 current monitor: New option "CMON" for "Mode" column and new "Scaling" column.
