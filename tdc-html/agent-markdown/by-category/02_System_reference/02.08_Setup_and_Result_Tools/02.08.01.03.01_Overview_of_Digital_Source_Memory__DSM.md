# Overview of Digital Source Memory (DSM)

#### Subtopics

- [Digital Source Memory Terminology](<02.08.01.03.01.01_Digital_Source_Memory_Terminology.md>)
- [Normal DSM setup](<02.08.01.03.01.02_Normal_DSM_setup.md>)
- [Flat DSM setup](<02.08.01.03.01.03_Flat_DSM_setup.md>)
- [Test System Speed](<02.08.01.03.01.04_Test_System_Speed.md>)

DSM is a software feature that enables the testing and the preconditioning of devices containing, amongst others, embedded ADCs and DACs. It can be used in any application, single site and multisite, where vectors must be dynamically modified from execution to execution in order to set up the test conditions required by the measurement. DSM is also suitable for multisite applications where each site must be set up differently by means of different vectors applied to each device in each site.

A typical use case requires running a pattern with variable vector data, which may or may not change at every execution based on some externally determined conditions, interleaved with non-variable vector data, like a reset sequence.

DSM can be set up in two ways. Normally, there are two labels, a main label that contains the static context, and a DSRC label that contains the variable vector data. The static context is included in a loop, so that it needs to be stored only once.

But you can also store both the static context and the variable data in the same main label. This kind of setup is called flat because in this case no loop can be defined, and thus the static context must be stored as often as the test must be executed.

The following sections give an overview of both setup types.
