# Technology file for a device

The .technology file defines the source directory for technology-related settings, some device specific system parameters and some maximum values for certain system parameters.

The maximum values for certain system parameters determine the amount of memory reserved for the respective data structures. The absolute maximum values are not automatically used so that memory usage can reflect the actual requirements of the device. Since the available memory is limited it is possible that one or more otherwise valid settings are reduced by the firmware in order to remain within the memory limits, see [The Testflow Analyzer Tool](<../02.04_Model_File_and_Licensing/02.04.05.07_The_Testflow_Analyzer_Tool__TAT.md>) and [Optimizing the technology file](<../02.04_Model_File_and_Licensing/02.04.05.07.02_Optimizing_the_technology_file.md>). See also [Result areas for error map data](<../02.07_Test_Method_Reference/02.07.04.01.190.09_Result_areas_for_error_map_data.md>).

## Changing the .technolog file

The .technology file is normally updated by making changes in the [Change Device dialog](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.10.03.03_Editing_technology_data.md>) (on the menu, select 93000 > Change Device). Changes made in this window are saved in the .technology file and communicated immediately to the firmware using the DSCP (Define System Control Parameter) and other firmware commands. These changes are permanent and apply each time the device is selected thereafter.

The parameters that are not present in the Change Device window can be changed permanently only by editing the .technology file directly. In this case, the DSCP command must be issued manually to define the new values to the firmware, or the device must be re-selected (which will reissue the DSCP command).

The concepts related to each of the parameters are documented in more detail in the Command Reference guide.

## Application note

  Memory reserved for testpoints  Some rules must be observed when defining high numbers of testpoints:

- Unlike other settings, the maximum memory required for the defined [testpoints](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_testpoints>) will be reserved at the very beginning of loading a device using commands [DTCP, DTCP? - (Define Technology Control Parameters)](<../02.06_Command_Reference/02.06.02.02.93_DTCP__DTCP__-__Define_Technology_Control_Parameters.md>) and [*RST - (ReSeT)](<../02.06_Command_Reference/02.06.02.02.345_RST_-__ReSeT.md>).
- The memory is reserved on all DC Scale cards that are available in the [model file](<../02.04_Model_File_and_Licensing/02.04.01_The_model_file.md>).
- The maximum memory that is required for all testpoints is reserved no matter if it is used later or not[3)](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__fn_DPS128_max_testpoints>).
- The amount of reserved memory depends on the value of [testpoints](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__row_testpoints>) and the card specific structure[2)](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md#_49363__fn_Bytes_per_testpoint>) of the testpoints.

  CAUTION Ignoring the rules above and defining too much test points may result in memory overflow for the subsequently defined and loaded setups or pattern.

If a memory overflow occurs, the error message "ERROR: Specified set size is too large for memory configuration" will be shown in the UI report window. SmarTest restores the previous setup or the default setup and newly defined settings and pattern are not available.
