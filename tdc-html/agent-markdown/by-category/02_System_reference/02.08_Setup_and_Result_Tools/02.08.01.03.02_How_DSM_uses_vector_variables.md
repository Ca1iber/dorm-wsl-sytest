# How DSM uses vector variables

#### Subtopics

- [Vector variable configuration](<02.08.01.03.02.01_Vector_variable_configuration.md>)
- [Vector variable configuration usage](<02.08.01.03.02.02_Vector_variable_configuration_usage.md>)

Vector variables are used by Digital Capture to selectively retrieve desired data from memory. After the capturing of data is complete, the captured data (samples) needs to be read from the vector memory and be analyzed as required.

Digital Source Memory (DSM) takes advantage of this feature by using the vector variable to download and upload vectors to selected positions in the source memory (vector area of the source label).

Normally, one vector variable describes the storage information of one specific waveform in the memory, so it is the only destination when other applications (vector setup and test methods) are used to download/upload the testing data.

In the [Overview of Digital Source Memory (DSM)](<02.08.01.03.01_Overview_of_Digital_Source_Memory__DSM.md>), the vector setup of the DSRC label has been described as one block of configuration settings, and this is also how it is represented by the GUI. On the firmware level, however, the DSRC label is set up in two steps:

- A vector variable configuration (VVC) defines the structure of a frame source block and the mapping from 0,1 to waveforms.It is independent of any label and defines only vector variable templates.
- For every VVC, at least one vector variable configuration usage (VVCU) must be defined. The VVCU associates the VVC with a label, creates the required number of frame source blocks in the source label, and creates genuine vector variables from the VVC variable templates.
