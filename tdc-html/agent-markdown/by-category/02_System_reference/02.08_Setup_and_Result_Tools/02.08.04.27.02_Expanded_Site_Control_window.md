# Expanded Site Control window

In the Expanded Site Control window, you can view and change the site test sequence settings of each test suites directly. This is shown in the figure below.

To open the expanded site control window, click Edit > Expand in the [Site Control Window](<02.08.04.27_Site_Control_Window.md>).

 ![Expanded Site Control Window](<../../../../raw/47564.png>)

 | Test suite name list  | Include all the test suites in the testflow. |
 | Site control execution mode  | The Site Control window allows selecting one of the three options Parallel, Serial or Semi-Parallel. In the [Test suite properties view](<02.08.04.32.03.04_Testflow_Properties_view.md#_99279__s_Test_suite_properties_view>), you can set the mode also to OTHER or UNDEF. For these modes, the label of the button shows no mode.

The flag [allow parallel](<02.08.04.27.02_Expanded_Site_Control_window.md#_100119__row_Allow_parallel>) must be set to yes before Parallel or Semi-Parallel can be selected.

Use Parallel or Serial to change the site test sequence from another mode to the parallel or serial execution mode. If you want to execute the test in parallel or serial, you do not have to set the [Site test sequence](<02.08.04.27.02_Expanded_Site_Control_window.md#_100119__row_Sequence>).

When Semi-Parallel is selected, the drop down lists Size and Cycle are activated. You need to set the two parameters as shown below.

 |
 | Size & Cycle  | Size and Cycle define the automatically set [ Site test sequence](<02.08.04.27.02_Expanded_Site_Control_window.md#_100119__row_Sequence>) for a semi-parallel test.

There are two modes to define the automatically set site test sequence for a semi-parallel test:

-

Cycle set to unbounded:

The value that is selected in drop down list Size, defines the number of parallel tested sites per semi-parallel group. The first group starts with site #1. The other sites are grouped in numerical order by the Size value.

-

Size and Cycle are set to a numerical value:

  -

Cycle specifies the number of sites that are assigned to a "virtual group". All sites are grouped in the "virtual groups" in numerical order by the Cycle value. The first "virtual group" starts with site #1.

  -

Size specifies the size of the "parallel groups" within the "virtual groups". All sites within a "virtual group" are grouped in numerical order by the Size value. The first "parallel group" starts with the first site of the related "virtual group".

  - The number of "parallel groups" within a "virtual group" is defined by the ratio of Cycle and Size.
 Order of execution:

  - All sites within the "parallel groups" are tested in parallel.
  - All "parallel groups" within a "virtual group" are tested serially.
  - All "virtual groups" are tested in parallel.

As a result of this structure, sites that are assigned to equally positioned "parallel groups" in different "virtual groups" are tested in parallel.

Note: If test sites are added afterward, additional sites will be tested according to Size and Cycle settings. You do not have to set up this again. |
 | Site test sequence  | The shown sequence is defined by Size and Cycle settings if the execution mode has been set to Semi-Parallel.

You can also enter the order numbers directly. Hence, you can set up a free site test sequence. In this case, if test sites are added afterward, additional sites will be tested in parallel after tests of the existing sites are completed.

Adding the order numbers directly will change the [execution mode](<02.08.04.27.02_Expanded_Site_Control_window.md#_100119__row_Execution_mode>) to an empty field. This mode corresponds to the OTHER setting in the [Testflow Properties view](<02.08.04.32.03.04_Testflow_Properties_view.md>).

 |
 | allow parallel  | Allow Parallel test suite flag

For more information, see [Setting Flags for Parallel Execution](<../../03_Use_cases_and_application_papers/03.02_How_to_do_Multi-Site_Testing/03.02.02.06.04_Setting_Flags_for_Parallel_Execution.md>) and [Allow Parallel](<02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_allow_parallel>).

  | Note If you want to execute the test in parallel or serial, you do not have to set the site test sequence on this page. This is because the test sequence is decided by the setting of the Allow Parallel test suite flag.

## Example

For example, to test sites 1 and 2 in parallel and then sites 3 and 4 in parallel for four-site semi-parallel testing, you can set up the test sequence by specifying Size = 2 and Cycle = Unbounded. Each parallel test in the semi-parallel test will be executed from the group including site 1 in numerical order.

If test sites are added afterward, additional sites will be tested according to the Size and Cycle settings. Therefore, you do not have to set up this again.

The figure below shows three examples of the site test sequence settings including the above typical example.

 ![Size and Cycle Parameters](<../../../../raw/47559.png>)

You can also enter the order numbers directly into the Site Test Sequence field. Hence, you can set up a free site test sequence. In this case, if test sites are added afterward, additional sites will be tested in parallel after tests of the existing sites are completed.

The Parallel and Serial buttons can be used to change the site test sequence from Semi-Parallel or free sequence to the Parallel or Serial sequence.

Note If you turn the [Allow Parallel](<02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_allow_parallel>) flag off, all sites will be tested serially. However, the sequence might be different from the sequence specified by clicking the Serial button. For example, if you click the Semi-Parallel button and run the test suite in the following sequence as sites 1 and 3 (in parallel), and site 2 and site 4 (in parallel), then after you turn off the Allow Parallel flag, the site test sequence is site 1, site 3, site 2, and site 4. However, for the serial test (the Allow Parallel flag is turned on and the Serial button is pressed), the site test sequence is site 1, site 2, site 3, and site 4.

TIP: You can also set up the site test sequence for all test suites in the Site Control window. If you want to set it up for many test suites once, it is better to use the Site Control window.
