# Error Reporting

Errors are normally output to the report window. However, some firmware commands described in the [Command Reference](<../02.06_Command_Reference/02.06_Command_Reference.md>) allow output to be directed to a file. These commands are:

- `CKST?`
- `EQFS`

Whenever level or timing resource violations are detected by `CKST?`, `SPST` and `SPST?`, an error is reported for each violation.

These resources are:

- DPS Level

  - `vout`
  - `ilimit`
  - `t_ms`
  - `offcurr`
  - `vbump`
  - vout_b

- I/O Level

  - `vih`, vil
  - `voh`, `vol`
  - `vch`, `vcl`
  - `ioh`, `iol`
  - `vt`

- Timing

  - `period_res`
  - `period`
  - `d1-d8`
  - `r1-r8`

In addition, if these violations are the result of evaluating an equation containing specs, the setup values of all specs are used first to evaluate the equation, then the minimum and then the maximum values, if specified.

For example, equation (2*a) + (b/3) - c is evaluated using:

- setup value of a, setup value of b, setup value of c.
- minimum value of a, setup value of b, setup value of c.
- maximum value of a, setup value of b, setup value of c.
- setup value of a, minimum value of b, setup value of c.
- setup value of a, maximum value of b, setup value of c.
- setup value of a, setup value of b, minimum value of c.
- setup value of a, setup value of b, maximum value of c.

An error is reported for each violation.

For each violation, the error message specifies:

- which specset
- which resource in that specset
- the evaluated value giving rise to the violation
- which minimum or maximum value of which spec that gave rise to the violation. This is only reported if the minimum or maximum is used. The minimum or maximum are only used if they are defined in the spec.
