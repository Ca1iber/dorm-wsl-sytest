# Cloning a pattern

When you clone a pattern, you can generate a new pattern related to all or part of the pins of the original pattern.

## About this task

This function allows you for example, to extract a subset of an existing pattern and extend it in a larger port containing more or other pins.

In the following description, the original pattern to be cloned is referred to as "source pattern"; the pattern generated by cloning the original pattern is referred to as "target pattern".

## Before you begin

You must have a source pattern.

## Procedure

-  In the Pattern Explorer, right-click the source pattern and select Clone.

The Clone pattern window opens.

  ![The Clone Pattern window](<../../../../raw/118852.png>)
-  In the top field, type the new pattern name.
-  Below, select the target port of the target pattern. Content assist (Ctrl-Spacebar) lists the available ports.
-  In the Folder field you may specify the location of the target pattern file. Default is ../vectors. The field is active only for pattern master file setups.
-  When you have entered all values, click OK.

## Results

The target pattern is generated by cloning the source pattern. The following applies:

- The target pattern is only related to the selected target port.
- The type of the target pattern is same as that of the source pattern (`Main`, `SJMP`, `SubRoutine`, `Burst`, or `DSRC`).
- The vector variable of the source pattern is also cloned to the target pattern, if the pins of the vector variable are all included in the port of the target pattern.
- All the instructions in the source pattern are also cloned to the target pattern.
- If the selected target port contains additional or other pins compared to the source port, the source data is used for matching pins. Additional or other pins are filled with reasonable data, for example the value of the physical waveform index.Note If an instruction (`CALL`, `JSUB`, `JPPS`, `SSRC`, and `JMPE`) uses the pattern parameter and the pattern's port is not a subset of the target pattern's port, the instruction is replaced by an `NOP` instruction (No Operation) in the target pattern. On the console tab a warning appears: "Some commands could not be copied and are transformed to NOP's. Manual intervention required." In this case you must manually modify the NOP instruction.

## Example

The following examples explain the transformation to NOP instructions in more detail.

- For the instruction `SSRC dsm_data_pattern`, if the port of the pattern `dsm_data_pattern` is also the port of the target pattern, the `SSRC` instruction is cloned to the target pattern without change.
- For the instruction `JSUB sub_pattern`, as the port of the pattern `sub_pattern` is not the same as that of the source pattern, in the target pattern, the `JSUB` instruction is replaced by an `NOP` instruction and a warning message is displayed on the console tab.

If an instruction is replaced by `NOP` in the target pattern (for example, the `JSUB sub_pattern` instruction), you must modify the instruction manually:

- Create a new subroutine pattern `sub_pattern_clone` by cloning the `sub_pattern` pattern with the port of the target pattern.
- Replace `NOP` with the `JSUB` instruction using the new pattern: `JSUB sub_pattern_clone.`
