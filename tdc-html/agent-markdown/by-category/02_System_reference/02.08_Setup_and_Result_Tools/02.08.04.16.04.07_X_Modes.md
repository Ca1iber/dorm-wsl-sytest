# X Modes

This term refers to set up processes which can be used to fit multiple device cycles into a single test system cycle. The "X" implies multiplication ("X4 mode" means that there are 4 device cycles per test system cycle). The purpose of X modes is to run tests faster and use memory more efficiently.

If the test system cycles occur at 8 ns intervals, the device cycles will occur at 2 ns intervals in X4 mode, and at 1 ns intervals in X8 mode. Usage of vector memory is similarly compressed (in X4 mode, 40 MV of the device fits into 10 MV of test system memory).

This multiplying effect is accomplished by using many drive/receive edges. For example, a device cycle containing one pulse (represented by a pair of drive edges) could occur 4 times within a test system cycle if 8 drive edges are used. The greater the "X" value, the more edges are needed per test system cycle.

The test system hardware provides 8 drive edges and 8 receive edges per test system cycle for each pin. Special hardware, for example for HSIO applications, does feature higher X Modes to enable higher data rates.

The recommended way of specifying the X mode for a given pattern is via the definition of a [STATEMAP](<02.08.04.16.02.04.03_STATEMAP_section_of_the_wavetable.md>), and AreaPatternAttachment, which is associated with a [VCAT](<../02.06_Command_Reference/02.06.02.02.318_VCAT__VCAT__-__VeCtor_ATtachment.md>) command for each pattern.
