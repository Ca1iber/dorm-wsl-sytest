# Period resolution for a multi-port setup (Smart Scale)

Every Smart Scale channel has its own PLL, and the period of this local PLL defines its clock resolution. Every Smart Scale channel can therefore have a different clock resolution, and consequently also a different period resolution.

The period resolution of Smart Scale ports is independent of all the other ports within the specification:

- If a Smart Scale port P is associated with an equation set containing a period_res statement, then this period resolution will be used, even if P is not the first port within the specification that supplies a period_res statement.
- If the associated equation set contains no period_res statement, the period resolution of a Smart Scale port will be calculated from the period in timing set 1 of this equation set, even if some other port within the specification supplies a period_res statement.

If the period resolution is calculated by the system, its upper limit is not 10 ns, as in the single-port case, but equals the maximum clock resolution of the respective system, that is ≤3.52 ns on a PS1600 system.

## Example

In the following example, the ports PortA and PortB are Smart Scale ports. The relevant parts of the timing setup are as follows:

```
EQNSET 1 "equation set 1"
DEFINES  PortA

period_res = 4

TIMINGSET 1 "eq 1 ts 1"
period = 10
. . .

EQNSET 2 "equation set 2"
DEFINES  PortB

TIMINGSET 1 "eq 2 ts 1"
period = 10
. . .

SPECIFICATION "mu_burst"
{

CHECK all

EQNSET 1 "equation set 1"
WAVETBL "wavetable 1"
PORT PortA
. . .

EQNSET 2 "equation set 2"
WAVETBL "wavetable 2"
PORT PortB
. . .
```

If you query the period resolution of the 4 ports, the result will be as follows:

```
> CLKR? "mu_burst",(@@)
< CLKR "mu_burst",20,4,(PortA)
< CLKR "mu_burst",10,1.25,(PortB)
```

The period resolution is returned in the third parameter.
