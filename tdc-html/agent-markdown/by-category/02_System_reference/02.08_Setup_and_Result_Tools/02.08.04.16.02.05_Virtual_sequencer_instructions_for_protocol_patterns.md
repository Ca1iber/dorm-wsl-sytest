# Virtual sequencer instructions for protocol patterns

The protocol patterns that are generated by the Protocol Aware ATE (see [Protocol Aware ATE](<../02.07_Test_Method_Reference/02.07.11_Protocol_Aware_ATE.md>)), can be viewed in the pattern editor. The editor does not simply display the generated vector stream, but adds sequencer instructions in the Instruction column which are virtual in the sense that they do not exist on the firmware level. Their purpose is to facilitate understanding the vector stream of the protocol pattern.

These virtual instructions are as follows:

## List of sequencer virtual Instructions:

 |

Instruction

 |

Explanation

 |
 |

GENA <nbr_of_vectors>

 |

Generates vectors for one transaction sequence. This instruction is only visible when the Pattern Debug Tool is in expanded mode.

 |
 |

IDLE <length_of_idle_sequence> <nbr_of_cycles> <time_to_wait>

 |

Waits for the specified number of tester cycles and in addition the specified time (in ns). The specified time is converted into the smallest number n of tester cycles so that n * tester_period ≥ specified_time

The total number of wait cycles can be checked when the Pattern Debug Tool is in expanded mode.

 |
 |

JPPS

 |

Jump to a per pin sequencer subroutine.

 |
 |

MACT <nbr_of_repetitions> <debug_mode>

 |

Indicates the start position of a counted match loop.

<nbr_of_repetitions> specifies the maximum number of unsuccessful repetitions. <debug_mode> specifies whether the match loop is in fact executed as a match loop (DebugOff) or rather as a standard counted loop (DebugOn). For more information see [TRANSACTION_SEQUENCE](<../02.07_Test_Method_Reference/02.07.04.01.256_TRANSACTION_SEQUENCE.md>).

 |
 |

MRPA <nbr_of_vectors>

 |

Indicates the end of the body of a counted match loop.

<nbr_of_vectors> specifies the number of the dummy vectors that are repeated to provide the necessary time for setting the error flag.

 |
 |

WTFM <length_of_idle_sequence> <name_of_synchronization_marker> <port>

 |

Waits until a synchronization point in the simulation port is reached. For more information see [SYNCHRONIZED_TEST](<../02.07_Test_Method_Reference/02.07.04.01.239_SYNCHRONIZED_TEST.md>) and [Vector based synchronization](<../02.07_Test_Method_Reference/02.07.11.01.10.01_Vector_based_synchronization.md>).

How often the sequence is repeated can be controlled when the Pattern Debug Tool is in expanded mode.

 |

## Functional changes

- Introduced in SmarTest 7.1.0
- SmarTest 7.2.0: Instructions for a PA match loop were added.
