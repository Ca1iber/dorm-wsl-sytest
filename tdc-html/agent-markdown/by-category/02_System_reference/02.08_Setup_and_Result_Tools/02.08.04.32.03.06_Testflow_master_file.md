# Testflow master file

#### Subtopics

- [Top-level control structures](<02.08.04.32.03.06.01_Top-level_control_structures.md>)

The testflow can be organized as one single file, or its parts can be be stored in separate files. In the latter case the parts that make up a complete testflow are pulled together by a master file which contains references to the individual files. This structure has the advantage that several users can work on the same testflow in parallel.

The first line of a testflow master file must be:

```
hp93000,testflow_master_file,0.1
```

The second line has the format:

```
testerfile: <tester_file_name>
```

This line specifies the tester setup file which is to be split or into which the subfiles are to be merged. If you manage the master file from the Test Program Explorer the name specified here is of no particular importance, but it must be present.

The following lines associate the individual testflow parts with subfiles.

The smallest parts of a testflow that can be stored in separate subfiles are:

- Test suite groups
- Information
- Flags
- Bins
- Setup
- Variables

Each of these parts is associated with a subfile by a line which specifies the type of the part, its name (except for general information such as flags and the setup files), and the associated subfile. Different parts can be associated with the same subfile. The group subfiles are merged in the order of the master file entries.

Note that individual test suites or bins cannot be stored in separate files. Therefore, all top level objects must be groups.

You can insert comments anywhere in the file. They are identified by the hash (#) character at the start of a line.

The paths for the subfiles can be relative or absolute. The reference directory for relative paths is the directory of the master file.

## Format of different parts

 |

`GROUP <group_name> [open|closed]: <file_name>`

 |

The optional parameter defines whether the group is displayed in full detail (`open` option) or as a single node (`closed` option) in the testflow editor.

 |
 |

`information: <file_name>`

`bins: <file_name>`

`flags: <file_name>`

`setup: <file_name>`

 |

Each of these global entries must occur only once in the master file.

 |
 |

`VAR <variable_name>: <file_name>`

`VAR_default: <file_name>`

 |

`VAR_default` collects all variables that are not specified explicitly by a `VAR` entry.

 |

## Format of automatically created file names

When the Setup Management Tool splits a testflow file and finds a group for which no entry exists in the master file, it must create not only a new subfile for this part, but also a name for it. These automatically created file names are constructed as follows:

```
group_<group_name>.tfl
```

You can add a user defined prefix to the names with the environment variable `VERIGY93000_MFH_PREFIX`.

In the shell in which you want to smart SmarTest, specify the desired prefix before starting SmarTest:

```
export VERIGY93000_MFH_PREFIX=<prefix>
```

## Example

```
hp93000,testflow_master_file,0.1

testerfile: testflow

information: files/general.tfl
flags: files/general.tfl
bins: files/general.tfl
setup: files/general.tfl
VAR_Default: files/vars.tfl

GROUP group1: files/group1.tfl
VAR myvar1: files/group1.tfl
VAR myvar2: files/group1.tfl

GROUP group2: files/group2.tfl
VAR myvar3: files/group2.tfl
```
