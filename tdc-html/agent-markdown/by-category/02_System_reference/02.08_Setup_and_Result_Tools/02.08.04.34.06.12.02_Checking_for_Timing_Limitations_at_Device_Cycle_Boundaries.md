# Checking for Timing Limitations at Device Cycle Boundaries

#### Subtopics

- [Checking for All Possible Combinations of Device Cycle Sequences](<02.08.04.34.06.12.02.01_Checking_for_All_Possible_Combinations_of_Device_Cycle_Sequences.md>)
- [Checking for the Combinations used in the Selected Test](<02.08.04.34.06.12.02.02_Checking_for_the_Combinations_used_in_the_Selected_Test.md>)

There is a minimum pulse width and a minimum window width limit, both of which have been set in the software to 500 ps. This is reflected in the Timing Setup. When you generate device cycles, the software will not let you create pulses or windows shorter than this limit.

The limit is applied within device cycles, when you are creating waveforms. It is also applied at device cycle boundaries, when you create a test, that is, when device cycles follow one another in the Pattern Tool.

The software lets you check whether violations of the minimum pulse/window width exist at device cycle boundaries. There are two checks you can make:

- check for all combinations of all device cycles following each other;
- check for the combinations that exist in the selected test.Note The minimum pulse width value programmable in the software is lower than the value specified for the system. Programming a value smaller than that stated in the specifications requires verification of actual signal performance.
