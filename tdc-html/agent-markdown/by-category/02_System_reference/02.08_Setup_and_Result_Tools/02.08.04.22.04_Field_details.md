# Field details

[Fields](<../02.07_Test_Method_Reference/02.07.11.01.09.03_Field.md>) describe the logical structure of a transaction.

Each transaction is build out of one or several fields matching the required sequence of the protocol.

Fields are associated with the pin roles defined for the transaction to generate a vector. Changing the order of fields leads to a different sequence sent to or read from the DUT.

The field details are shown if you select a field in the protocol editor's overview area.

The field details are divided into different sections like symbols and functions.

  ![Field details](<../../../../raw/126154.png>)

Mandatory field properties are the field name and length (in bits/state characters).

 Note The length of all fields of a transaction has to match the overall length of that transaction! Note If changing the field name here, the change will be applied in the current transaction only.

## Symbols

Symbolic names for special state character sequences may be specified here to improve readability and prevent duplication of SCS.

If symbols are defined,

- they are used for encoding and decoding at transaction level.
- a direction, either In or Out, has to be assigned manually.

If left Undefined, an error will be generated!

  ![Error if symbol's directions is left undefined.](<../../../../raw/129383.png>)  Note The chosen direction is valid for all symbols defined with that field.

## Functions

During encoding the field function is the first to be applied.

If no other encode functions are applied to the SCS, the exact vector sequence defined here will be applied to the DUT.

Note Symbols can also be used for encoding functions.
