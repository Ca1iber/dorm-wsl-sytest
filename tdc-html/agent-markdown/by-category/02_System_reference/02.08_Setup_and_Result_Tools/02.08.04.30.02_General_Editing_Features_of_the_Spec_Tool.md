## Editable sections

The Timing Set and Wavetable entities in the uppermost area of the window provide information, and are also user-editable. To edit any particular entity, click the appropriate edit field (it appears highlighted), enter a new value, and press return.

You can enter figures with up to 9 decimal places. Depending on the text you have typed, the closest matching entity will be displayed. For an alternative way of changing any of these parameters, see the topics listed in the "In this section" paragraph.

The timing and edge check information in the middle area of the window is changed by activating the appropriate radio button.

The variable information in the table at the bottom part of the window is also editable - apart from each variable name and its unit of measurement, as these will be retrieved automatically from the equation file. To edit any particular value (actual, min, max, etc.), double-click the appropriate edit field, double-click any existing value, enter a new value, and press return. See also [Changing Spec Values](<02.08.04.30.02.14_Changing_Spec_Values.md>).

Note You define the units in the equation based spec setup only. You cannot define units using the spec tool.

## Update between software and hardware

Unlike the [Level setup tool](<02.08.04.14.04_Opening_and_using_the_Level_Setup_Tool.md>), the Spec Tool does not automatically update the frontend of the hardware. The Spec Tool UI download changes levels or DPS sets inside the backend hardware, but not the frontend state. To apply the modifications to the frontend, the primaries need to be activated:

- Press the [download button of the Spec Tool](<02.08.04.30.01_The_Spec_Tool_window.md>) for downloading the changes to the backend of the hardware.
- Activate the primaries for applying the changes to the frontend:

  - Perform a global disconnect / connect sequence using the [Connect and disconnect buttons](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.10.02_Connect_and_disconnect_buttons.md>) in the short cut bar of the SmarTest Eclipse window
  - or perform a disconnect / connect sequence of the individual channel using the [Hardware view](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.05.03_Hardware_view.md>)
  - or invoke the FW command [APRM](<../02.06_Command_Reference/02.06.02.02.03_APRM_-__Activate_PRiMary_sets.md>) in the [Firmware view](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.08.08_Firmware_view.md>) tab.

## Unit conflict between EQNSET and SPECSET

If one or more of the loaded SPECSET contain units different to the units that are defined in the referenced EQNSET, SmarTest displays the following warning window. This may happen, for example, after importing setups converted by STIL reader with version 2.1 or earlier.

```
WARNING: Unit for spec variable "<variable>" in EQNSET <no>, SPECSET <no> is not consistent (EQNSET unit: [<unit>], SPECSET unit: [<unit>]).
Only EQNSET units will be used. To overwrite SPECSET units with EQNSET units, press "Download" and then save the setup.
To keep SPECSET units, edit EQNSETs and set the same units as in SPECSETs.
```

Follow the procedure given in the warning window (for details on the spec tool interface, refer to [The Spec Tool window](<02.08.04.30.01_The_Spec_Tool_window.md>)):

- Use units defined in the equation based setup:

  - On the Spec Tool click the Downloadbutton.
  - On the menu click File > Save.

- Use units defined in the SPECSET setup:

  - Edit the equation based setup file.
  - Refer to [Equation based timing setup](<../../01_Getting_started/01.07_Testing_a_Basic_Digital_Device/01.07.01.04.01_Equation_based_timing_setup.md>) and [Equation based level setup](<02.08.04.14.02_Equation_based_level_setup.md>).
