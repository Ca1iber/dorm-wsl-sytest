# Pattern editor properties view

For the pattern editor, the properties view shows the vector parameters, that is the properties of

- a vector in SC (state character), PW (physical waveform), and DVC (device cycle) format,
- a test point,
- a vector variable for digital capture,
- a DSM ( Digital Source Memory) setup.

The properties view also allows to change some of the displayed values. To change a value, highlight it and either select or type the new value.

## Examples

### Vector properties

The graphic below shows the properties of a vector in device cycle (DVC) format.

 ![Device cycle properties view](<../../../../raw/129366.png>)

On vector properties views you cannot edit any parameters. Do this in the pattern editor.

The vector properties view always shows the physical waveform. Drive edges and receive edges appear on two different lines. In collapsed mode the view is based on the [base wavetable](<02.08.04.16.04.05.01_Function_of_the_base_wavetable.md>), in expanded mode the properties are taken from the primary wavetable.

Any abbreviations you may use in your wavetables, are translated into the proper action code for [drive edges](<../02.06_Command_Reference/02.06.06.01.03.01.01.01_Drive_actions.md>) and [receive edges](<../02.06_Command_Reference/02.06.06.01.03.01.01.02_Receive_actions.md>).

### Vector variable properties

The properties view of a vector variable (see below) allows to edit for example, the assigned pins, the transfer mode, and other parameters. To display additional data upload formatting parameters (Upload Parameters) click the Show Advanced Properties icon. For a definition of the vector variable parameters see [Creating a Digital Capture setup](<02.08.01.02.07.02.05.01_Creating_a_Digital_Capture_setup.md>).

 ![Vector variable properties view](<../../../../raw/116397.png>) Note The Upload Parameters shown here are the last which were used by the system. If you stop a testflow at a particular test suite and then open the pattern editor, the vector variable data is shown exactly as it was last uploaded from any test method or any command line operation.
