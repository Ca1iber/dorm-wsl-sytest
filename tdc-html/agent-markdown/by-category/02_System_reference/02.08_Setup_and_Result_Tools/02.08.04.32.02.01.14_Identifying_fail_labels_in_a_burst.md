# Identifying fail labels in a burst

The burst mode option in the vector setup allows you to execute a sequence of test labels in one go. In a production environment this feature becomes very important (as a one-shot execution can be considerably quicker than individual test execution), especially if you have streams of vectors with lots of labels.

## About this task

However, it is also important to pinpoint which of a sequence of tests a device has failed. There are two solutions to locate where devices are failing in a burst mode test.

- Set the testflow flag unburst_mode for testflow execution.
- Use the for...loop testflow control node.

This task describes the second method.

## Before you begin

There must be a testflow using the burst mode. For details on setting bursts, see:

## Procedure

-  In the Flow Sequence Editor, select the insertion point on the F branch immediately after the test suite BurstTestusing the burst mode, and then click for loop on the Palette.  ![Setting up a loop for identifying the fail label in a burst](<../../../../raw/110990.png>)
-  The New For Loop Wizard window opens. Set up appropriate parameters of a loop that automatically tests each of the labels in the failing burst mode test suite.

Two [Built-in functions](<02.08.04.32.01.02.02.01_Built-in_functions.md>) `burstfirst(Burst_label)` and `burstnext(label),` enable you to find the first label and next label of a burst label.

In the above figure, a variable lbl is used. The expression `burstfirst("Burst")` returns the name of the first label of the burst label Burst.

-  On the T branch immediately after the for loop node, insert a test suite Unburst. The only difference between the Unburstand BurstTesttest suites is that BurstTest uses the label Burst and Unburst uses lbl.
-  Insert the bin and the Print node to output message in the report window, displaying which label makes the device fail.

## Results

When you run the testflow, the individual labels of the burst is executed separately, which allows you to pinpoint which of a sequence of tests a device has failed.
