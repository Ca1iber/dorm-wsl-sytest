# DUT oriented view - xN and x1/N mode

The pattern debug tool offers you large flexibility regarding DUT oriented periods:

## Multiple periods:

A pattern can contain different periods for different signals. This can be realized by using different xN or x1/N modes in different signals within the same pattern.

Example:

An audio application requires 12 MHz for master clock input, 3 MHz for data clock and 375 kHz for register setup. If the tester frequency is 12 MHz, these frequencies can be realized by x1, x1/4 and x1/32 modes. If the tester frequency is 1.5 MHz, these frequencies can be realized by x8, x2 and x1/4 modes. By using multiple periods you can avoid the more complex multiport setup.

## Change period on the fly (CPOF)

A pattern can contain signals, whose period changes on the fly. This can be realized by changing xN or x1/N mode in the same signal.

Example:

If presetting requires 100 kHz and testing requires 10 MHz, these frequencies can be realized by x1/100 and x1 modes when the tester period is 10 MHz.

## STATEMAP section of the wavetable

To define the xN and x1/N modes, the wavetable contains the STATEMAP section. This section enables the user to define a meaningful representation of x-mode waveforms for viewing and editing in the Pattern Debug Tool. Waveforms can be defined consistently for both xN and x1/N modes.

## xN-mode

Provides higher data rates by utilizing the edges of a single physical waveform to create multiple DUT waveforms in a single tester cycle. The eight drive and eight receive edges of a physical waveform can be used. For example, x2-mode can be set up by utilizing a maximum of four edges in each DUT waveform. Up to x8-mode is supported.

## x1/N-mode

Provides slower data rates by using N physical waveforms per single x-mode waveform. Up to x1/1024 is supported.
