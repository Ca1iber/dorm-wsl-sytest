# Defining a new Protocol: MDIO

## About this task

This task is about creating a MDIO protocol definition from scratch. The following picture illustrates the starting point and the target of the procedure.

 ![Timing of MDIO](<../../../../raw/142170.png>)

When done, your MDIO protocol in in smartest will be represented as follow:

 ![Timing of MDIO PA](<../../../../raw/142171.png>)

## Before you begin

Ensure you have the available license. The pins used in a protocol need to be defined in a dedicated port. Each port can just get one protocol assigned, but the same protocol can be used for several ports. Protocol Aware requires the use of STATEMAP in the wavetable. The state map section in the wavetable allows to uniquely map a transaction to a sequence of physical waveforms respectively interpreting a waveform sequence as transaction words.

## Procedure

-  Launch the Protocol Editor from the Test Program Explorer, enter the protocol name, define the Pin Roles for the Protocol, define the Properties for the Pin Roles. See also [Pin role details](<02.08.04.22.03_Pin_role_details.md>). For the MDIO protocol, the pin roles are MDC and MDIO. They will be mapped to the pins of the device. The definition and properties of the MDIO protocol are illustrated in the next picture. The picture shows the protocol name (MDIO), the pin roles (MDC and MDIO) and the properties like idleSequence.  ![MDIO Definition and Properties](<../../../../raw/142172.png>)
-  The lower part of the protocol definition contains tabs for Level, Timing and Wavetable. You will use those tabs to enter the timing for the protocol pins according to the protocol specification. Enter Timing, Wavetable and Level data for protocol pins (pin roles within the protocol). See also [Editing protocol specific levels](<02.08.04.22.10.07_Editing_protocol_specific_levels.md>).

Level (mdio level)

```
PINS MDC
vil - 0.0
voh = 3.0
PINS MDIO
vil =0.0
vih = 3.0
vol= 1.2
voh = 1.9
vt= 2.0
```

Timing (mdio timing). See also [Editing protocol specific wavetable and state map](<02.08.04.22.10.08_Editing_protocol_specific_wavetable_and_state_map.md>).

```
PINS MDC
d1 = 50
d2 = 250
PINS MDIO
d1 = 30
d2= 350
```

The corresponding wavetable definition is shown in the next picture

  ![PA MDIO Wavetable](<../../../../raw/142173.png>)  Note You may want to define different timing or level for the PA pin roles to take in account different device stages like nominal, stress, relaxed etc.
-  You need to link the timing and level definition of the device with the timing and level of the protocol. The timing definitions of the protocol will be integrated to the equation system using the statement:

```
USE_PROTOCOL "<protocolName>:<timingSegmentName>" [<portList>]
```

For this example:

```
USE_PROTOCOL "MDIO:mdio_timing" poMD
```

The level definitions of the protocol will be integrated to the equation system using the statement:

```
USE_PROTOCOL "<protocolName>:<levelSegmentName>" [<portList>]
```

For this example:

```
USE_PROTOCOL "MDIO:mdio_level" poMD
```

-  Setup the transactions needed for the MDIO protocol and define the frame structure. The MDIO protocol contains two transactions : Read and Write. For those transactions we will use the following variables phyaddr, regaddr, data. To create the transactions, select the protocol name in the Overview pane and the New Transaction shortcut menu as shown in the next picture. Several parameters are involved in the transactions definitions: In parameters, Out parameters capture received data by the ATE, Length: defines the size (number of bits) of the parameter. See also [Editing field details](<02.08.04.22.10.06_Editing_field_details.md>).  ![MDIO Transactions](<../../../../raw/142174.png>)
-  Proceed until you define all the transactions and fields needed in the protocol.
-  Validated the protocol definition according to [Validating a protocol definition](<02.08.04.22.10.10_Validating_a_protocol_definition.md>). Once validated, your protocol should reflect the protocol specification as shown in the next picture.You may have to go back and forth until you get the this picture right.  ![Validate the MDIO Protocol](<../../../../raw/142175.png>)
-  Once validated, you protocol is basically in place. Now you may want to go back to certain fields and add or change parameters or add encode functions until you finally match the protocol specification. This is illustrated in the next picture. Depending on the data flow direction the fields can be IN or OUT.   ![Encode function of a Protocol](<../../../../raw/142176.png>)
-  Create your protocol wrapper according to [Generating protocol wrappers](<02.08.04.22.10.11_Generating_protocol_wrappers.md>).
-  Copy the generated .cpp and .hpp files to you UTM project directory.
-  Add an include statement to your test method class #include <wrapperClass>.hpp

## Results

The result of the MDIO protocol is shown from the Test Program Explorer after selecting View In Protocol.

## What to do next

Use the Protocol in you testflow.
