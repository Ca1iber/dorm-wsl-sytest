# The Break Waveform

The break waveform is issued when the test system is in the break state. The waveform is always present when you set up a pin with a drive component, that is an I pin or an IO pin. The default is hold (holds the previous state of drive and tri-state).

You can change the default to a different shape, it must, however, be a fixed shape - that is, one which uses no data parameters. The break waveform does not require any entries in the physical waveform table Data Parameters.

Waveforms containing data use data parameters. These determine their physical states (high or low) at hardware level. The states translate to actual test signals.

Data parameters on the drive side are D1 and D2, on the receive side they are E1 and E2. They are independent of each other and take the values shown in the sections [Drive Edges and Actions](<02.08.04.34.01.01.01_Drive_Edges_and_Actions.md>) and [Receive Edges and Actions](<02.08.04.34.01.01.02_Receive_Edges_and_Actions.md>). You supply these values in Vector Setup, or obtain them from a CAE station as vector data.

Data parameters enable you to associate two different drive states and two different compare states with waveforms, giving a total of 256 different physical waveform states. Assigning values to data parameters is dealt with later in this chapter. The states are referenced in the hardware by means of the physical waveform index. The index entries are stored in the physical waveform table.

Thirty two physical waveform index entries are more than enough for most applications. Bear in mind, however, that it is possible to fill the table with just a single device cycle if for instance:

- You use both D1 an D2 data parameters and both E1 and E2 data parameters in a bidirectional pin. Or
- You use both D1 an D2 data parameters for drive actions and again for tri-state actions in a drive pin.

You cannot then create any more device cycles for that particular pin.

Break waveforms are not considered in the timing module during speed license checks. The timing module counts the drive actions of all "normal" waveforms, but not the break waveforms.
