# Selective Capture with Equation based timing

On a Smart Scale system, pure selective capture is possible with both the modified standard format and the native Smart Scale format; the HRPF mode is currently only supported for the modified standard format.

The maximum number of samples that can be taken in one tester cycle is restricted by the number of receive edges, which is 8.

You must also be aware that the digital capture supports specific X-modes. Namely: 1, 2, 4, or 8. If the requested number of samples is 3, or between 5 and 7, SmarTest will automatically use the next bigger X-mode that is multiple of 2. For example, if you requested 5 samples to be captured, SmarTest will automatically use the X-8 mode. This means, 3 zeros will be appended to every fifth sample in your digital capture. Thus, there will be some redundant samples returned by DIDT? at the end of each cycle, which must be filtered out by the vector variable (for which see [Setting up a Vector Variable](<02.08.01.02.07.02.05_Setting_up_a_Vector_Variable.md>)). Note that the same also applies for the result mode used in the Error Map.

## Standard selective capturing with standard pins

The following is an example of a wavetable for standard selective capturing with standard pins:

```
WAVETBL "sel_capt"

PINS pin1

0 "d1:0 d2:F0N r1:C"   00C
1 "d1:1 d2:F0N r1:C"   10C
2 "d1:0 d2:F0N r1:D"   00D
3 "d1:1 d2:F0N r1:D"   10D
...
```

Certain restrictions must be observed with respect to the digital capture actions:

- If a waveform contains digital capture actions, its receive actions must be used exclusively for digital capture, that is, the waveform must not contain any compare action.
- A waveform can contain more than one digital capture action, but C and D cannot be combined within one waveform.
- If any waveform contains more than one digital capture action, all capture waveform must contain the same number of actions and use the same edges. The first edge must be r1, and there must not be any numbering gaps.

The following examples illustrate the restrictions for standard selective capture:

```
0 "r1:L r2:C"   LC
```

This will be rejected because digital capture actions and standard compare actions are combined in one waveform.

```
0 "r1:D r2:C"   DC
```

This will be rejected because C and D are combined in one waveform.

```
0 "r1:C r3:C"   CC
1 "r1:D r3:D"   DD
```

This will be rejected because of the edge numbering gap.

```
0 "r2:C r3:C"   CC
1 "r2:D r3:D"   DD
```

This will be rejected because the first edge is not r1.

```
0 "r1:C"        C
1 "r1:D r2:D"   DD
```

This will be rejected because the two waveforms contain a different number of edges.

If, however, the capture waveforms contain only one action, the edges are allowed to be different:

```
0 "r1:C"   C
1 "r2:D"   D
```

This will be accepted.

## HRPF selective capturing with standard pins

Normally, digital capture is executed by comparing the received values to L. If the comparison passes, the captured value will be L; if it fails, the captured value will be H. These compare actions will impact the global P/F value of the test (which will be F if at least one H is received), but if you are only interested in the captured values, this is irrelevant.

However, there are situations where digital capture must be combined with a functional test, for example, when you want to execute a match loop before you start capturing. This can be achieved for selective digital capture by specifying the HRPF keyword in the primary wavetable for the combined functional and capture test.

The HRPF keyword causes SmarTest to capture the values by a different method, by which capture actions have no impact on the global P/F result, but normal compare actions (H/L) have, just as in a standard functional test. In this way the global P/F value will only reflect the result of the normal compare actions. It will be F when a match loop fails or any received value is different from the expected value.

But note that the individual compare results will not be written to the Error Map. Only capture actions will be recorded.

An example for a HRPF wavetable is

```
WAVETBL "SELECTIVE CAPTURE HRPF"

  PINS IO1
  HRPF 0  "d1:0 d2:0 r1:C" C1
       1  "d1:1 d2:0 r1:C" C2
       2  "d1:0 d2:0 r1:D" D1
       3  "d1:1 d2:0 r1:D" D2
       4  "d1:0 d2:0 r1:E0" E01
       5  "d1:1 d2:0 r1:E0" E02
       6  "d1:0 d2:0 r1:E1" E11
```

In HRPF mode, capture waveforms with more than one capture edge must observe certain pairing rules as follows:

r1 must be combined with r5

r2 must be combined with r6

r3 must be combined with r7

r4 must be combined with r8

On the other hand, you may use different pairs in different capture waveforms (which is not allowed with standard selective capture) as long as the total number of edges is the same. Note that the pairing rule apply only on the receive edges of the capture waveforms defined in your wavetable. The timing equations for these edges in your timing set specify the edges in ascending order, that is, r1, r2, r3, and so on. See the following example:

```
# WAVETABLE
WAVETBL "X8Capt"
...
PIN SEROUT
HRPF 0 "d1:0" 0
1 "d1:1" 1
2 "d1:Z r1:L"       L
3 "d1:Z r1:H"       H
4 "d1:Z r1:X"       X
// receive edges in the capture waveform are defined according to the pairing rule
5 "d1:Z r1:C r5:C r2:C r6:C r3:C r7:C r4:C r8:C"  CCCCCCCC
...
# Timing
EQNSET "X8CaptTim"
...
PIN SEROUT
d1=0d2=0.5*Tcyc
// receive edges for the digital capture are specified in ascending order
r1=0.100*Tcyc
r2=0.225*Tcyc
r3=0.350*Tcyc
r4=0.475*Tcyc
r5=0.600*Tcyc
r6=0.725*Tcyc
r7=0.850*Tcyc
r8=0.975*Tcyc
```
