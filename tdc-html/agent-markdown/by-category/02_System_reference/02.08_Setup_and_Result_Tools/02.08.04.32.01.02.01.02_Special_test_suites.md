# Special test suites

Special test suites are executed at a particular point in time, which can be either dependent or independent of the testflow. For example, downloading an initial set of values to the test system, or defining what will be executed if you abort the testflow.

 Special test suites do not appear as nodes in the Flow Sequence Editor, but in the [Flow Data Editor](<02.08.04.32.03.01_Flow_Data_Editor.md>), they are displayed at the end of the [Test Suites page](<02.08.04.32.03.01.01_Test_Suites_page.md>) when sorting by default.Note Do not throw any exceptions from inside special test suites, as the handling is not compatible with the testflow executor.

There are seven types of special test suites.

 | Init |

An optional test suite that gets an initial setting for the test system. It can be used to set testflow variables, external equipment to an initial state (by supporting the docking of a prober, for example), and etc.

The Init test suite is executed after the [Download](<02.08.04.32.01.02.01.02_Special_test_suites.md#_20281__r_Download>) test suite and before the testflow execution starts.

The following shows the position of the Init test suite in the testflow execution sequence:

- The test program is loaded.
- The testflow is loaded.
- The pin configuration is loaded.
- The [Download](<02.08.04.32.01.02.01.02_Special_test_suites.md#_20281__r_Download>) test suite is executed.
- The Init test suite is executed.
- The first run of the testflow begins.
- All setup files not yet loaded are downloaded.
- The first test suite is executed.
 |
 | bin_disconnect |

Executed when a device falls into a bin.

If you use the [DISCONNECT](<../02.07_Test_Method_Reference/02.07.04.01.41_DISCONNECT.md>) API in this test suite, then

- if you defined a disconnect sequence in the device, the disconnect sequence will be executed;
- if no disconnect sequence is defined, the standard disconnect sequence will be executed.

bin_disconnect is a legacy method of disconnecting failing devices. For new devices, we recommend using the [Multibin SmartDisconnect test suite](<02.08.04.32.01.02.01.04_Multibin_SmartDisconnect_test_suite.md>) that is a combination of a multibin node and a user defined test suite.

See also [Special test suite bin_disconnect](<../../03_Use_cases_and_application_papers/03.04_How_to_do_disconnect/03.04.01.04_Special_test_suite_bin_disconnect.md>).

 |
 | Abort |

Executed when the test system gets into the abort state.

This state is either chosen in the Operation Control Window (in any mode), or programmed; or occurs in cases of exception handling (test system, library or program errors). The abort state unloads the test program and disconnects the test system. It does not, however, reset the test system hardware.

 |
 | Reset |

Executed when the test system gets into the reset state.

This state is either chosen in the [Operation Control Window](<../02.09_Test_Program_Management/02.09.01.07_Controlling_a_Production_Run.md>), or programmed; or occurs in some cases of exception handling (test system, library or program errors). The reset state unloads the test program and puts the test system in an initialized (disconnected) state. The test system hardware is reset, so you must ensure you download the original settings again if you wish to restart.

 |
 | Pause |

Executed when the test system gets into the pause state.

This state is either chosen in the [Operation Control Window](<../02.09_Test_Program_Management/02.09.01.07_Controlling_a_Production_Run.md>), or programmed; or occurs in most cases of exception handling (test system, library or program errors). The pause suite is executed before the pause section in the application model.

 |
 | multi_bin_decision |

Executed whenever one or more sites reach a multi_bin node in the testflow.

While binning you can decide which bin to be used in the multi_bin by using the [SET_MULTIBIN](<../02.07_Test_Method_Reference/02.07.04.01.212_SET_MULTIBIN.md>) API in the test method.

 |
 | Exit |

Executed when the test system gets into the exit state.

This state is either chosen in the [Operation Control Window](<../02.09_Test_Program_Management/02.09.01.07_Controlling_a_Production_Run.md>), or programmed; or occurs in cases of exception handling (test system, library or program errors). The exit suite is relevant only when the testflow was started from within a testprogram. The exit suite is executed before the testprogram terminates.

 |
 | Download |

The Download test suite is executed after the testflow is loaded. You can use this test suite to load the pin configuration setup selected on the [Setups page](<02.08.04.32.03.01.07_Setups_page.md>) of the [Flow Data Editor](<02.08.04.32.03.01_Flow_Data_Editor.md>) or other setup files.

The following shows the position of the Download test suite in the testflow execution sequence:

1. The test program is loaded.

2. The testflow is loaded.

3. The pin configuration is loaded.

4. The Download test suite is executed.

5. The [Init](<02.08.04.32.01.02.01.02_Special_test_suites.md>) test suite is executed.

6. The first run of the testflow begins.

7. All setup files not yet loaded are downloaded.

8. The first test suite is executed.

 |

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 6.3.2: Special test suites are now displayed in the Tabular Testflow Editor.
- SmarTest 6.5.0: New special test suite bin_disconnect.
- SmarTest 6.5.2: New special test suite multi_bin_decision.
