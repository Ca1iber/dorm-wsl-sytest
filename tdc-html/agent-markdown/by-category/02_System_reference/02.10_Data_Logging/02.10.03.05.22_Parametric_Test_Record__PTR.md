# Parametric Test Record (PTR)

#### Subtopics

- [Logging user text to PTR records with test methods](<02.10.03.05.22.01_Logging_user_text_to_PTR_records_with_test_methods.md>)

Function:

The Parametric Test Record contains the result of a single execution of a parametric test in the test program. The first occurrence of this record also establishes the default values for all semi-static information about the test such as limits, units and scaling. The PTR is related to the TSR by test number, head number, and site number.

Location in the file:

The Parametric Test Record can appear anywhere in the data stream after the corresponding PIR, and before the corresponding PRR.

TEST_TXT

 |

- Test description text or label
 |

- Variable length character string
- First byte is unsigned count of bytes to follow
- Maximum 255 bytes
- Length byte = 0 if invalid or missing data
- For multi_port testing, contains the string <test suite name>@<pattern port name>.
- The test text contains: "Test suite name: test name#test comment" for MPR's and FTR's. Where '#' is the separator which can be configured in the config file. The comment is logged from the test method api and is optional.
- It contains "Test suite name: test name#pin name#test comment" for PTR's if there is a pin name associated with the PTR. Where '#' is the separator which can be configured in the config file. The comment is logged from the test method api and is optional.

## Functional changes

- Introduced before SmarTest 6.3.2
- SmarTest 7.1.1: The values of the C-RESFMT, C_LLMFMT, and C_HLMFMT fields are no longer hardcoded.
- SmarTest 7.2.2: Added HEAD_NUM and SITE_NUM conventions for tests on more than 255 sites.
- SmarTest 7.5.0: TEST_FLG bit 0 is no longer hard-coded
