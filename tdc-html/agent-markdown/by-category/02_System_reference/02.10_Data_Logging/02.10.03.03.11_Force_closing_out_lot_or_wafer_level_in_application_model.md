# Force closing out lot or wafer level in application model

In some test environments, it may be necessary to force the completion of the data formatter output file near the end of the wafer or lot application model level. For example, the data formatter will not close the file for the lot or wafer level until the level is complete. If there is some action (i.e. via an EXEC_INPUT_CALL) near the end of the application model level, which waits for the data formatter file to complete, it will not return. This new variable would be useful in forcing completion before the call that searches for the complete file, allowing the call to return and the level to complete.

If this situation becomes a problem in a particular environment, there is a way to signal to the data formatter that the level should be closed out and any pending STDF file should be generated. By assigning either the value LOT or WAFER to a variable named FORCE_MODEL_LEVEL_LOGGING_COMPLETE in the application model, the data formatter will recognize this as a signal to complete the designated level. This assignment should be placed just before the handler call that causes the blockage. It is important that this functionality be used only if necessary, and that an assignment to that variable name is only done in the post actions for the lot or wafer level. When in the lot level's post actions, the value assigned should be LOT; when in the wafer level's post actions, the value assigned should be WAFER.

## Example

The following example illustrates a common use of FORCE_MODEL_LEVEL_LOGGING_COMPLETE. It performs tests on all devices belonging to a lot and at the end copies the finished log into a quality database. (The details of the test are unimportant here and have been left out; the log is copied by using EXEC_INP_CALL to call an external function that is assumed to perform this task.)

To ensure that the log is properly closed before it is copied, FORCE_MODEL_LEVEL_LOGGING_COMPLETE is executed just before the copying begins. Because logs can be open simultaneously for the lot and the wafer, it is necessary to specify which one the data formatter is to close.

```
{ lot:
    ...
  { DEVICE device:
    ...
    { DEVICE_TEST }
    ...
  }
  ...
  ACTIONS
    FORCE_MODEL_LEVEL_LOGGING_COMPLETE = CONST_INPUT(LOT);
    EXEC_INP_CALL(push_stdf_to_database);
}
```
