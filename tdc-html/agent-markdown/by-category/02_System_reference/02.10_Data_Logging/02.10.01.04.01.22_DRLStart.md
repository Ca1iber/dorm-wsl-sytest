# DRLStart

int DRLStart (const char *path, int flags, DRLDataStream *stream)

This function initializes a new data retrieval process. If you implement the data retrieval as a stand-alone process, this function needs to be called before any other DRL function is used. For a report formatter, this function is called automatically. (See [How the Event Formatter works](<02.10.02.07_How_the_Event_Formatter_works.md>).)

If the parameter path is NULL, the data retrieval process attaches to the system shared memory and reads data from the data log stream. If the parameter path is not NULL, the saved data log file specified in path is opened and logged data will be read from that file. This allows for offline analysis of saved data log data.

As it is possible to start several data retrieval processes on more than one data log stream or file, the pointer stream is used to distinguish between the different data log streams or files. stream should be seen as an abstract variable representing the connection to the data log stream or file. stream is used in various DRL functions that access the data log stream or file.

See [DRLSave](<02.10.01.04.01.20_DRLSave.md>) for information on how to save the data log stream to a file.

The parameter flags is composed of the following flags by bitwise OR:

- DRL_SYNC_COUNTER: If set, the event counter used in the new data retrieval process is initialized with the value of the current event counter of the data log stream. Thus the function [DRLEventAvailable](<02.10.01.04.01.01_DRLEventAvailable.md>) only checks for new event records written to the data log stream. If this flag is not set all pending event records are considered.
- DRL_RESET_MASK: If set, the active event mask (see [DRLGetEventMask](<02.10.01.04.01.08_DRLGetEventMask.md>)) is reset so that all events are unmasked. If this flag is not set, the currently active event mask is used. Use this flag if no active event mask has been previously defined.
- DRL_TRUNCATE: If set, the data collection will be truncated immediately before attaching. From the formatter's perspective, the attachment will behave as if it were synchronized, since all past events are cleared.
- DRL_WAIT_FOR_EVENT: If set, calls to [DRLEventAvailable](<02.10.01.04.01.01_DRLEventAvailable.md>) and [DRLGetNetUnmaskedEvent](<02.10.01.04.01.09_DRLGetNextUnmaskedEvent.md>) are blocked until the next event arrives. This eliminates the need to poll for events and improves the performance of the formatter process. We recommend always setting this flag unless there is a specific reason not to set it.
- DRL_NO_EVENTS: If set, the formatter will not receive data events. This mode can be used to improve performance if only formatter control commands such as [DRLSave](<02.10.01.04.01.20_DRLSave.md>) and [DRLTruncate](<02.10.01.04.01.24_DRLTruncate.md>) are used.

## Return Value

The return value is zero if the function was successful; otherwise the error code ERR_ACCESS (see [Error Codes](<02.10.01.04.02.108_Error_Codes.md>)) is returned if the file specified in path could not be accessed.

## Example

```
void example (void)
{
 DRLDataStream stream;
 if (DRLStart (NULL,(DRL_SYNC_COUNTER | DRL_RESET_MASK,
    &stream))
    {
       /* error handler  */
     };
/* starts a data retrieval operating on the data log stream and checks */
/* only for new event records. The active event mask is reset.*/
}
```
