# Handling of test suite flags by the Event Formatter

In the Report Dialog window, you specify which report data are to be included in the output of the Event Formatter. The actual data contained in the data log stream, however, depends on the active test suite flag settings. For example, per-pin fail values will only be available if the Per pin on fail test suite flag is set.

Because this may lead to unexpected results, the Event Formatter can operate in two different modes: The filter mode does not change the current test suite flags, which means that data availability is determined by the flags' settings. The trigger mode changes the test suite flags when required to make sure the requested data is available. The active mode is determined by the auto_apply variable in the .formatterrc file: If the variable is set to 0, the filter mode is active: if it is set to 1, trigger mode is active. (See [Settings for the Event Formatter](<02.10.02.08_Settings_for_the_Event_Formatter.md>) for more information.)

## Filter mode

The Event Formatter does not make changes to the test suite flags. Only data that is available in the data log according to the current test suite flag settings can be reported. Thus, the Report Dialog settings only operate as filters for the available data.

Only when you click the Set Testsuite Flags button in the Report Dialog window are testflow flags modified by the Event Formatter in such way that the required data are generated when a test suite is executed. Everything explained below for the Trigger Mode applies then.

## Trigger mode

In trigger mode, all testflow flags are modified by the Event Formatter such that the required data - according to the settings in the Report Dialog window - is generated when a test suite is executed. The data will then be contained in the corresponding attributes, that is, mainly in the attributes coming with events of the type [TestEventType](<02.10.01.06.03.12_TestEventType.md>).

For example, if you enable Output as Result for Failed Pins in the Report Dialog, the Output on fail flag is set for all test suites.

The first time a checkbox in the Report Dialog window is altered, an automatic copy of the current state of the test suite flags is made. This is indicated by a message in the lower text window of the report window.

The saved flag states can be restored manually by using the Restore Flags command in the Datalog menu of the report window (see [Report window menus](<02.10.02.02_Report_window_menus.md>)), or will automatically be restored when another report formatter is activated. When the flags are restored, a corresponding message is written to the lower text window of the report window.

Note In trigger mode, whenever you change the state of a checkbox, the necessary changes to test suite flags are made immediately. These flag changes can be observed in the Test Suite Flags window, which you can open by using the Production Settings > Testsuite Flags command in the Operation Control window.Note As explained above, the changes to the test suite flags are only temporary, and you can restore the initial settings at any time. Yet, it is important to be aware of the fact that the test suite states, as set by the Report Dialog, will also be saved if the testflow is saved, and thus overwrite previously saved flag settings.
