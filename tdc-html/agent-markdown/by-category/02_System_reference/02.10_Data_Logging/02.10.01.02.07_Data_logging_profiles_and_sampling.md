# Data logging profiles and sampling

Sampling is the practice of logging data not from all tested devices but only a subset of them.

There are two basic sampling techniques:

- Fixed sampling, in which devices are logged in regular intervals - for example every third or every tenth device
- Adaptive sampling, in which the sampling rate is varied according to some factor

Both are explained in more detail below.

## Fixed sampling

In fixed sampling, data is logged for every nth device, for example, every other device or every fifth device. (However, data logging events are still created for every device - some are just not recorded.)

The [datalog_sample_size](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_datalog_sample_size>) system flag allows you to control the sampling rate for fixed sampling. (See [Data logging flags](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.03_Testflow_flags_for_data_logging.md>) for more information.)

Instead of simply logging some devices and not logging others, you can also apply two different profiles for fixed sampling. One of these profiles is used for every device that is set to be logged, and the other for every device that would, according to the setting of the [datalog_sample_size](<../02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_datalog_sample_size>) flag, not be logged.

The [setSamplingProfile](<../02.09_Test_Program_Management/02.09.01.08.05.04.19_Set_the_data_logging_profiles.md>) CPI function lets you specify which data logging profiles to use for either case.

Choosing, for the devices that you do not wish to log, a logging profile which creates no or very few data logging events may improve the test performance with fixed sampling active.

## Adaptive sampling

In adaptive sampling, the sampling rate (that is, the ratio of devices that are sampled to devices that are not sampled) is dynamically varied according to one or more user-selectable criteria, such as the yield or the number of failed devices.

Adaptive sampling is performed under program control using the [Data logging profile API](<02.10.01.02.08_Data_logging_profile_API.md>). A simple example is shown in [Data logging profile API examples](<../02.07_Test_Method_Reference/02.07.04.01.169.05_Data_logging_profile_API_examples.md>). (Note that the sampling performed in this example is equivalent to fixed sampling, but other criteria are easily specified in the program.)

If STDF output from adaptive sampling is required, you must take care that the stdf_output flag is switched on at the right times. This is explained in the example in [Data logging profile API examples](<../02.07_Test_Method_Reference/02.07.04.01.169.05_Data_logging_profile_API_examples.md>).
