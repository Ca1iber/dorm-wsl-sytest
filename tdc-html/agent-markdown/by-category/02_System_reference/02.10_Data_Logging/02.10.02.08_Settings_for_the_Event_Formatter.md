# Settings for the Event Formatter

Besides the settings you can make in the Report Dialog window, there are several further settings to customize the behavior of the Event Formatter.

You define these further settings directly in the configuration file (.formatterrc) for the Event Formatter, which is generated in your home directory the first time you use the Datalog > Save Current Formatter Settings menu command in the report window.

[Appendix B: Event Formatter Defaults](<02.10.02.13_Appendix_B__Event_Formatter_Defaults.md>) lists that file with all default settings and a full description of all settings.

Each time you activate the Event Formatter, this file is read and the formatter will work according to the settings it contains. The file can also be loaded with the Datalog > Save Current Formatter Settings menu command in the report window; this overwrites the current formatter settings with the settings saved in the file.

The .formatterrc file contains a number of configuration variables. To change these variables:

- Open .formatterrc with any text editor (for example, NEdit).
- Make the changes to the configuration variable settings according to your needs. A list of variables and their available settings is provided below.
- Save the changes by overwriting the old .formatterrc file with the new version.

Here is a list of all the configuration variables and how they let you determine the behavior of the Event Formatter. More details on these variables can be found in [Appendix B: Event Formatter Defaults](<02.10.02.13_Appendix_B__Event_Formatter_Defaults.md>).

- open_report_dialog_on_startup = (0, 1)

Determines whether the Report Dialog window needs is opened automatically whenever the Event Formatter is activated (1) or must be opened manually when desired using the Datalog > Open Report Dialog menu command.

- start_logging_on_startup_to = (NULL, <filename>)

Determines whether the Event Formatter automatically writes the output to a file (<filename>), or only writes to a file when the START Logging Formatter Output to File option in the Datalog menu of the report window is chosen (NULL, the default value).

- auto_apply = (0, 1)

Determines whether the Event Formatter automatically changes test suite flags (1), or only does this when the Set Testsuites Flags button is clicked (0, the default value). For full detail see [Handling of test suite flags by the Event Formatter](<02.10.02.09_Handling_of_test_suite_flags_by_the_Event_Formatter.md>).

- output_width = (0, <x>)

Limits the number of columns for the formatter output to <x>, or defines it as unlimited (0, the default value).

This helps you format the output for printing. Vector results with more pins than can be displayed in the given number of columns will automatically be broken up into individual blocks of pins that fit that column number.

- ffv_spaces_between_pins = <x>

Determines the number of spaces (<x>) to be included between pin columns in the vector result output in short mode. The default is 0 (no spaces).

- always_get_per_pin_pf = (0, 1)

Determines whether the Event Formatter automatically enables the Per pin on fail test suite flag for all test suites that perform functional tests (1), or does not touch these flags (0, the default value). Only with the flag enabled is the pass/fail information for individual pins available.

- save_and_clear = (0, 1)

Determines whether in the Datalog menu of the report window displays the Save Datalog Stream and Clear option (1, the default value), or the Save Datalog Stream option (0), which lets you save the current data log stream without automatically clearing it.

- shmoo_y_axis_direction = (0, 1)

Determines whether the y-axis of a shmoo plot is going up or down when output:

  - 0: (default) The y-axis goes down.
  - 1: The y-axis goes up.

- check_event_queue_period = <x>

number_events_per_chunk = <y>

These two variables let you control the execution of the Event Formatter. To keep the system load low, the event handler (see [Appendix A: Event Formatter Files](<02.10.02.12_Appendix_A__Event_Formatter_Files.md>)) works in a loop. It sleeps for <x> milliseconds (default is 200 ms) and then reads a maximum of <y> event records from the data log stream (default is 500). Then it sleeps again, and so on.

We recommend to use the default settings for <x> and <y>, as these provide a reasonable balance between the active and idle times of the Event Formatter. During the default sleep time of 200 ms, typically less than 500 event records are written to the data log stream.

 Note In order to apply changes you made to the .formatterrc file to the Report Formatter, you need to load the settings with the Load Formatter Settings options in the Datalog menu of the report window.
