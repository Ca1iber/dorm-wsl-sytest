# Important notes for user-written report formatters

If you want to write your own event-based report formatter, the source file main.c of the DRLDump tool (see [Appendix B: The DRLDump Tool](<02.10.01.10_Appendix_B__The_DRLDump_Tool.md>)) can be used as a template for all basic functions like event processing, attribute processing, and handling the data log stream. This file is located in `/opt/hp93000/soc/.service/DRLDump`.

The source files for the Event Formatter contain further information that helps you with the implementation. All Event Formatter source files are located in `/opt/hp93000/soc/formatter/EventFormatter`. The contents of the individual files are described in [Appendix A: Event Formatter Files](<02.10.02.12_Appendix_A__Event_Formatter_Files.md>).

Further notable implementation details for an event-based report formatter:

- An event-based report formatter does not contain explicit calls to the [DRLStart](<02.10.01.04.01.22_DRLStart.md>) and [DRLStop](<02.10.01.04.01.23_DRLStop.md>) functions. These functions are called automatically when the report formatter is activated by selecting it in the Report Formatter window or deactivated by selecting another formatter respectively.
- The active event mask for a report formatter is automatically set to that specified in the InitHandler function in the `handler.c` file, once the reported formatter is activated. InitHandler is called from the start function in the `filter.c` file.
- Output for the upper text panel of the report window must be written to the output_buffer string, and the number of characters in output_buffer must be assigned to the variable length. (When handed over to the user, length contains the maximum number of characters that are available for output_buffer. Exceeding this limit results in unpredictable behavior of the software.) The contents of output_buffer is automatically output to the report window.

For short messages to the lower text panel of the report window, you can use fprintf (stderr, ...), but as there is no reliable mechanism to inform the software about the length of the output, this is not recommended.
