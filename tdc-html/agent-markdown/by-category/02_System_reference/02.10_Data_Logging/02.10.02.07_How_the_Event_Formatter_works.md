# How the Event Formatter works

#### Subtopics

- [How the output is directed to the report window](<02.10.02.07.01_How_the_output_is_directed_to_the_report_window.md>)
- [Modifying report window menus](<02.10.02.07.02_Modifying_report_window_menus.md>)
- [Important notes for user-written report formatters](<02.10.02.07.03_Important_notes_for_user-written_report_formatters.md>)

This section contains low-level information about the Event Formatter which you may need if you want to make changes to the formatter, or which will help you if you want to write your own event-based report formatter. For normal use of the Event Formatter, this information is not needed.

Basically, the Event Formatter works in the same way as any data retrieval method based on event data logging. The Event Formatter utilizes the same functions and data types of the [Data Retrieval Library](<02.10.01.04_Data_Retrieval_Library.md>), and is implemented in a very similar way to that explained in [Recommended implementation structure](<../02.09_Test_Program_Management/02.09.01.16.02.01_Recommended_implementation_structure.md>). Detailed information on how to implement a data retrieval is given in [Developing a data retrieval function](<02.10.01.05_Developing_a_data_retrieval_function.md>). [Appendix A: Event Formatter Files](<02.10.02.12_Appendix_A__Event_Formatter_Files.md>) contains descriptions of all the files that build the Event Formatter.

According to the settings in the configuration file for the Event Formatter (see [Settings for the Event Formatter](<02.10.02.08_Settings_for_the_Event_Formatter.md>)), the software regularly runs the formatter by calling the `eventProcess` function. This function is the core of the Event Formatter. The formatter then reads a defined number of event records (if any are available) from the data log stream. The Event Formatter's event mask is set by the `InitHandler` function, which is called automatically when the Event Formatter is selected as the active report formatter (see [How to Activate the Event Formatter](<02.10.02.01_Activating_the_Event_Formatter.md>)). In that mask, no event is set to "masked".

After each event record has been read, the attributes are processed according to the event type and the settings of the Report Dialog. When the attributes for all read events have been processed, the Event Formatter terminates. It will be run again by the next call of `eventProcess`.
