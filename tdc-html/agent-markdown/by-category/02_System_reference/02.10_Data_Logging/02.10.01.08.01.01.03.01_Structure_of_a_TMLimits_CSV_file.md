# Structure of a TMLimits CSV file

A TMLimits CSV file is a standard CSV file with a specified column structure.

Data fields in a TMLimits CSV file are separated by commas; records are separated by newline characters.

A TMLimits CSV file contains two header rows plus one row for each test.

## Header rows

The first header row contains the names of the columns. Which columns you include is optional, but appropriate key columns are required (see Key columns, below).

The second row contains the test mode assigned to each column. If no test mode is specified in this row, the values in the column apply to all test modes. If a test mode is specified, the values are used only when the specified test mode is chosen.

Note To add a test mode row in the SmarTest GUI (if one is not present), add an empty row at the top and enter "Test mode" (without the quotes) in the first cell.

Key points about specifying test modes in TMLimits CSV files:

- You can specify any number of test modes.
- You can have multiple columns with the same header if you specify different test modes for them in the second row.

For example, you can have one column named "Lsl" with the test mode "QA" and a second column named "Lsl" with the test mode "DT".

- You must not specify a test mode for key columns. You cannot have multiple versions of a key column.

## Required and optional columns

The columns in a TMLimits CSV file are user-definable. Most are optional, but a minimum set is required for useful operation of TMLimits:

- Identifying columns. Normally, this means the Suite name and Test name columns, but other combinations are possible (see Key columns, below).
- Test number
- Lsl
- Usl
- Units

## Supported columns

These columns can occur in a TMLimits CSV file:

- Limit key

The name of the row. You can enter any string. Limit name may be used as the test key (see Key columns, below, for details).

- Suite name

The name of the test suite. By default, Suite name is the primary key (see Key columns, below, for details).

- Test name

The name of the test to which the limits apply. By default, Test name is the secondary key (see Key columns, below, for details).

- Pins

The pins to which the test applies. If it is present, it is used as an additional key, in combination with either Suite name and Test name or with Limit key (see Key columns, below, for details).

- Test number

The test number that has been assigned to this test. Test numbers can be assigned either manually or automatically, as described in [Generating Test Numbers](<02.10.01.08_Managing_Test_Numbers.md>).

If no test number is specified, -1 is assigned as the test number.

- Units

The units for the test results and spec limits.

There may be multiple Units columns for different test modes or stages. (Test modes are specified in the second header row. Common modes include Quality Assurance and Final Test; users can specify modes as desired.)

- Lsl

The lower spec limit. If you do not enter a lower spec limit, 1e23 is assumed and the test always fails.

As with Units, above, there may be multiple Lsl columns.

- Lsl_typ

The type of the lower limit:

  - GT: For a test to pass, the result must be greater than the lower spec limit (Lsl, above).
  - GE: For a test to pass, the result must be greater than or equal to the lower spec limit (Lsl, above).
  - NA: No lower spec limit has been specified.

If you do not specify this parameter, the default of GE is used.

As with Units, above, there may be multiple Lsl_typ columns.

- Usl_typ

The type of the upper limit:

  - LT: For a test to pass, the result must be less than the upper spec limit (Usl, below).
  - LE: For a test to pass, the result must be less than or equal to the upper spec limit (Usl, below).
  - NA: No upper spec limit has been specified.

If you do not specify this parameter, the default of LE is used.

As with Units, above, there may be multiple Usl_typ columns.

- Usl

The upper spec limit. If you do not enter an upper spec limit, -1e23 is assumed and the test always fails.

As with Units, above, there may be multiple Usl columns.

- Offset

A fixed value that is added to the test result before it is tested against the specified limits.

As with Units, above, there may be multiple Offset columns.

- Bin_s_num

The number of the software bin specified by Bin_s_name. This information is only evaluated if there is a multibin in the fail branch of the test.

The number can be between 0 and 32767. (SmarTest itself also supports other alphanumerical strings of five characters and less, but only integers from 0 to 32767 are compatible with the SmarTest Data Formatter.)

To use multibinning, you must specify both the software bin number and the hardware bin number.

- Bin_s_name

The name of the software bin specified by Bin_s_number. This information is not normally evaluated by the software; it is intended mainly for human readers.

- Bin_h_num

The number of the hardware bin for the device in case of a failed test. This information is only evaluated if there is a multibin in the fail branch of the test.

To use multibinning, you must specify both the software bin number and the hardware bin number.

If no number is specified, -1 is assumed.

- Bin_h_name

The name of the hardware bin specified by Bin_h_number. This information is not normally evaluated by the software; it is intended mainly for human readers.

- Bin_type

The type of the bin, good or bad. If this value is missing, the default is bad.

- Bin_reprobe

Whether the device is to be retested when this bin is reached.

Possible values are

  - yes and
  - no.
The default is no.
- Bin_overon

Whether the [overon behavior](<../02.08_Setup_and_Result_Tools/02.08.04.32.02.03.02_Using_the_Overon_feature_while_running_a_testflow.md>) applies to this bin (continuing testing even if a stop bin has reached).

Supported values are

  - yes and
  - no
The default is yes and invalid values are also considered as yes.
- Test_remarks

Any comments for explaining the test row. This column is not evaluated by the software; it is intended only for human readers.

- Exec

Whether this test is to be executed (Y) or not (N).

Additional user-defined columns are supported. The possible values and meanings of these values must also be specified by the user and can be freely chosen.

## Key columns

Each TMLimits file must contain a column or combination of columns that can act as a key, that is, that uniquely identify each of the tests (rows). There are different possibilities for this; a combination is evaluated only if none of the combinations listed above it is present:

- Suite name, Test name, Pins
- Suite name, Test name

This is the recommended combination. If you create a TMLimits CSV file in SmarTest, this combination is used to identify tests.

- Limit key, Pins
- Limit key

## Example

The example shown below is part of a bigger TMLimits CSV file. Only a few tests and just one test mode are shown:

```
"Suite name",  "Test name",       "Test number", "Units", "Lsl",   "Usl",   "Test_remarks"
"Test mode",   "",                "",            "QA",    "QA",    "QA",    ""
"Continuity2", "DC_CONT_P",       "555",         "UNIT",  "-0.1",  "0.1",   "WalkZP"
"Continuity2", "DC_CONT_N",       "565",         "UNIT",  "-0.1",  "0.1",   "WalkZP"
"DC_FreeVI",   "IDD_Shutdown",    "575",         "uA",    "-1",    "6.88",  "FreerunVI"
"DC_FreeVI",   "IDD_FREG_PWR_ON", "585",         "mA",    "1",     "10",    "FreerunVI"
"DC_FreeVI",   "FREG_OUT_PWR_ON", "595",         "V",     "1.6",   "2.1",   "FreerunVI"
"DC_FreeVI",   "VDD_ALDO_PWR_ON", "605",         "V",     "1.25",  "1.6",   "FreerunVI"
"DC_FreeVI",   "VDD_DREG_PWR_ON", "615",         "V",     "1.085", "1.315", "FreerunVI"
"ATECtrl",     "ATECtrl",         "625",         "",      "-0.1",  "0.1",   "ATEctrlEdl"
```

This is the same example with an added user-defined column "Status":

```

"Continuity2", "DC_CONT_P",       "555",         "UNIT",   "4",      "-0.1",  "0.1",   "WalkZP"
"Continuity2", "DC_CONT_N",       "565",         "UNIT",   "3",      "-0.1",  "0.1",   "WalkZP"
"DC_FreeVI",   "IDD_Shutdown",    "575",         "uA",     "3",      "-1",    "6.88",  "FreerunVI"
"DC_FreeVI",   "IDD_FREG_PWR_ON", "585",         "mA",     "0",      "1",     "10",    "FreerunVI"
"DC_FreeVI",   "FREG_OUT_PWR_ON", "595",         "V",      "1",      "1.6",   "2.1",   "FreerunVI"
```
