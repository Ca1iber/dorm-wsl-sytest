# Activating the Event Formatter

This section describes how to activate the Event Formatter.

To activate the Event Formatter, select EventFormatter in the Report Formatter window and click Select:

  ![Selecting the Event Formatter](<../../../../raw/93101.png>)

Selecting the Event Formatter automatically sets the log_events_enable system flag, that is, activates event logging (see [Activating event data logging](<02.10.01.01.04_Activating_event_data_logging.md>) for further information). Then the .formatterrc file is read to configure the Event Formatter:

- First, the .formatterrc file in your home directory is read. This file contains your individual settings for the Event Formatter. If the file exists, the message "Set parameters according to file '$HOME/.formatterrc' " is displayed in the report window.
- If there is no .formatterrc file in your home directory, the default .formatterrc.def settings file in the Event Formatter directory is read instead.

For more information on the settings file, see [Settings for the Event Formatter](<02.10.02.08_Settings_for_the_Event_Formatter.md>) and [Appendix B: Event Formatter Defaults](<02.10.02.13_Appendix_B__Event_Formatter_Defaults.md>).

 Note In SmarTest releases before 5.4.2 and in SmarTest 6.0, the .formatterrc file in the device directory is never read. Only the .formatterrc file in your home directory or the default .formatterrc.def settings file in the Event Formatter directory is used for configuring the Event Formatter in these releases.  Note All system flags beginning with "datalog_" apply to GDF data logging; they have no relation to event data logging. If you do not use GDF data logging, you should set all these flags to off to optimize system performance.

If you have written your own report formatter, you can select it in the same way as described above. Just specify the path and directory for that formatter in the Report Formatter window and click OK.

## Functional changes

- Introduced before SmarTest 6.3.2
