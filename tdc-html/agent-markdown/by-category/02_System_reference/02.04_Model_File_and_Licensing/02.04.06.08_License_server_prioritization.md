# License server prioritization

When licenses are required, a license request is sent from SmarTest to a license server. The order in which license servers receive requests is dictated by the order of the data in following stores:

- Order of appearance in LM_LICENSE_FILE.
- If the SOCBU_LICENSE_FILE environment variable is specified, SmarTest reads the license files at the specified path instead.
- By default SmarTest reads at startup all *.lic license files (in lexicographical order) in the /opt/flexlm/license directory.

SmarTest can connect to more than one license server to collect the licenses requested for one feature. Licenses are checked out from the first queried license server with available licenses. If insufficient licenses are available on the first server contacted, all available licenses from the first server are checked out and the remaining licenses are taken from following servers.

Node-locked licenses have priority over floating licenses. Licenses locked to the system controller requesting licenses are checked out first, maximizing the availability of floating licenses for subsequent requests.

SmarTest contacts the license servers based on the data in the license files. The license server is specified in the SERVER line of the license files.

## Deactivating node-locked license prioritization

For time-critical environments, setting the environment variable SOCBU_IGNORE_NODELOCKED deactivates the prioritization of node-locked licenses.

Note This setting is not recommended for typical environments with a mixture of node-locked and floating licenses because there is a high risk of checking out all floating licenses, leaving only free node-locked licenses free but not generally usable.

There are two situations where deactivating the prioritization of node-locked licenses could be used effectively:

- No node-locked licenses are available for all requested features. Be aware that this may change, for example, when installing demo licenses.
- Only node-locked licenses are available for all requested features.

## Best practices

- Specify servers and files by using LM_LICENSE_FILE instead of *.lic-files.
- Order sources first by utilization frequency, then by latency (ping time).
- Place backup servers at the end of the list.
- Avoid multiple files pointing to the same server.
