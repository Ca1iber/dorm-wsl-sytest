# GLOBAL section

In the GLOBAL section of the tester.model file you define what kind of system is used and what features are available system-wide.

## Syntax

```
GLOBAL
    [testhead](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_testhead>) = test_head_size
    [dut_interface](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_dut_interface>) = DUT_interface_type
    [hpib_interface](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_hpib_interface>) = GPIB_interface_type
    [utility_lines](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_utility_lines>) = number, type, pogo_size, redirectpogoblocks
    [legacy_udps](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_se_udps>) = 268 # Internal Utility Power Option of V93000 EXA Scale systems only
    [PS1600MemoryCompatibility](<02.04.01.03.01.01_GLOBAL_section.md#_255460__r_memory_compatibility>) = OFF | ON
```

Parameters
 |

testhead

 |

Specifies the size of the test head and the number of card cages in the test head:

- V93000 EXA Scale systems:

```
testhead = [ TH_9Slot | TH_18Slot | TH_27Slot ]
```

TH_27Slot: LX test head (3 card cages)

TH_18Slot: SX test head (2 card cages)

TH_9Slot: CX test head (1 card cage)

- V93000 Smart Scale systems:

```
testhead = [ TH_8CC | TH_4CC | TH_2CC | TH_1CC ]
```

TH_8CC: Large test head (8 card cages)

TH_4CC: Small test head (4 card cages)

TH_2CC: Compact test head (2 card cages)

TH_1CC: A test head (1 card cage)

 |
 |

diag_subsystem_interface

   |   Note

The diag_subsystem_interface entry is optional for Pin Scale and Smart Scale systems, and used for non-default configurations.

The diag_subsystem_interface entry is not applicable to EXA Scale.

Defines the serial device that is used for low-level diagnostics using RS-232 communication.

```
diag_subsystem_interface = <device>
```

  CAUTION If you also specify the export variable DI_RS-232 , it take precedence over the settings from the model file.

USB to RS-232 adapter

- Port 1: `diag_subsystem_interface = /dev/ttyUSB0`
- Port 2: `diag_subsystem_interface = /dev/ttyUSB1`
- Direct connection via Com1: `diag_subsystem_interface = /dev/ttyS0`

2-port and 4-port RS-232 MOXA cards

- Port 1: `diag_subsystem_interface = /dev/ttyMUE0`
- Port 2: `diag_subsystem_interface = /dev/ttyMUE1`
- Port 3 (4-port card only): `diag_subsystem_interface = /dev/ttyMUE2`
- Port 4 (4-port card only): `diag_subsystem_interface = /dev/ttyMUE3`

See also: Prerequisites for executing diagnostic on system controller Z4 G4.

 |
 |

dut_interface

 |

Specifies the DUT interface type.

```
dut_interface = [ SOC | SOC_8GROUP | SOC_4GROUP]
```

SOC: Default for Pin Scale, Smart Scale, and EXA Scale systems.

 Note The DUT interface size depends on the test head size:

TH_8CC test head: DUT interface = `SOC_8GROUP`

Smaller test heads: DUT interface = `SOC_4GROUP`

SOC_8GROUP: to interface the large DUT board

SOC_4GROUP: to interface the small DUT board

 |
 |

hpib_interface

 |

Specifies the GPIB interface type for the external calibration.

Standard Configuration for the LAN to GPIB Solution

Required statement for external calibration:

```
hpib_interface = vxi11/<LAN-GPIB gateway>/192.168.0.100/gpib0
```

The entry <LAN-GPIB gateway> depends on the connected LAN to GPIB gateway:

- E7032A LAN to GPIB gateway: e5810a (Agilent E5810A)
- E7032C LAN to GPIB gateway: e5810b (Agilent E5810B)
 |
 |

utility_lines

 |

Specifies the number of utility lines, the type of utility lines, the size of the pogo block, and the redirect utility pogo blocks if the dut_interface type is WSMM_I2C or WSMM.

- V93000 EXA Scale systems:

```
utility_lines = (32 | 64 | 256 | 512) ...
..., type = (static | sequencer_controlled) ...
..., pogo_size = 32 ..., redirectpogoblocks = (redirect utility pogo blocks)
```

  - First utility board: 4133 (165), 5209 (166), 6217 (167), 7225 (168), 4129 (169), 5205 (170), 6213 (171), 7221 (172)
  - Second utility board: 4333 (265), 5409 (266), 6417 (267), 7425 (268), 4329 (269), 5405 (270), 6413 (271), 7421 (272)
Note For V93000 EXA Scale systems, the definition of the utility lines in the global section is mandatory. The parameters of the keyword are all mandatory except redirectpogoblocks.Rules to follow when defining a Utility Card in the tester.model file:

  - The first Utility Card in the tester.model file must always use the pogo block range 165 ... 172.
  - Defining utility_lines = 256 always means that the first Utility Card is installed.
  - The second Utility Card for the pogo block range 265 ... 272 can be defined only if the first Utility Card has also been defined.
  - The pogo block ranges 165 ... 172 and 265 ... 272 must be defined in ascending order and without gaps.
  - All eight pogo blocks must be defined for each installed Utility Card.

For more information, refer to [Utility resources](<../02.05_Test_Head_Cards/02.05.08_Utility_resources.md>) and [UTILITY256 utility card configuration in the tester.model file](<../02.05_Test_Head_Cards/02.05.08.04.04_Utility_Card_specific_setup_tasks.md#_351252__s_Utility_card_in_the_tester_model_file>) in [Utility Card specific setup tasks](<../02.05_Test_Head_Cards/02.05.08.04.04_Utility_Card_specific_setup_tasks.md>).

redirectpogoblocks can be used to specify available redirect utility pogo blocks only if the dut_interface type is WSMM_I2C or WSMM. SmarTest will not start if redirectpogoblocks is specified for other DUT interface types. Supported redirect utility pogo blocks for a Smart Scale system are: 4133 (UTIL 1), 5209 (UTIL 2), 6217 (UTIL 3), 7225 (UTIL 4), 4129 (UTIL 5), 5205 (UTIL 6), 6213 (UTIL 7), 7221 (UTIL 8)

Dependent on the detected wiring board, the definitions are validated and a warning is given if there is a mismatch.

A utility_lines = 256 entry in the model file is required to enable all 32 utility lines per pogo block.

If no utility_lines entry is made, the system defaults to 16 utility lines. Entering 32 lines makes sense only if 4-row utility line pogo blocks are installed. If this is not observed SmarTest does not start.

Note No utility_lines entry causes the following system behavior on the small test head (STH) and on the large test head (LTH):

If dut_interface = SOC_8GROUP, the system provides 128 utility lines, not sequencer-controllable.

 |
 | legacy_udps |

Enables the [Internal Utility Power Option](<../02.05_Test_Head_Cards/02.05.08.03.02_Internal_utility_power_supplies.md#_351298__dle_Internal_Utility_Power_Option>) of V93000 EXA Scale systems:

```
legacy_udps = 268
```

  Note This parameter is supported only for V93000 EXA Scale systems. SmarTest will not start if the parameter is used for V93000 Smart Scale systems.

This internal utility power supply is to be defined in this section if the required pogo cable assembly is installed.

Pogo block 268 is the new designation for the legacy DPS 8 pogo block of V93000 EXA Scale systems. This pogo block is the recommended position as defined in the V93000 Standard Configuration Guidelines. For more information, refer to [DUT interface layout](<../02.03_DUT_board_design_reference/02.03.03.01_DUT_interface_layout.md>).

 Note This entry in the tester.model file prevents a second [Utility Card](<../02.05_Test_Head_Cards/02.05.08.04_Utility_Card.md>) from being installed: The second Utility Card occupies all eight former DPS-slot pogo blocks and therefore cannot be installed in combination with the Internal Utility Power Option. |
 | PS1600MemoryCompatibility  | Disables the PS1600 memory compatibility mode.

`PS1600MemoryCompatibility = OFF | ON`

The mode is enabled by default.

 |

## Example

```
GLOBAL
    testhead = TH_8CC
    dut_interface = SOC_8GROUP
    hpib_interface = vxi11/e5810a/192.168.0.100/gpib0
    utility_lines = 64, type=static, pogo_size=16
#   legacy_udps = 268 # V93000 EXA Scale systems only
```
