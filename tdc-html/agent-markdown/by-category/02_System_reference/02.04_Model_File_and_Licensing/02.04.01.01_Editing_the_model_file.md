# Editing the model file

#### Subtopics

- [Editing the model file to optimize license use](<02.04.01.01.01_Editing_the_model_file_to_optimize_license_use.md>)
- [Switching model files](<02.04.01.01.02_Switching_model_files.md>)

To customize entries of the model file you use a general ASCII text editor. Editing the model file can serve one of these purposes:

- To define the necessary configuration and capability of test system resources. See [Model file sections](<02.04.01.03_Model_file_sections.md>).
- To correct parser syntax, feature dependency, or hardware compatibility error that may occur by reentering parameters. See [Model file error messages](<02.04.05.09.01_Model_file_error_messages.md>).
- To free resources or SmarTest features for which you have license access. If you do not need them at full capacity for your addressed tests, they can then be activated by other users.Note The current IOCHANNEL settings remain active as long as the test system is up and running. Therefore, you can reuse or modify the model file settings to test additional devices using the current SmarTest licenses. To free the current licenses or to check out additional licenses you must close down and restart the software.

The following steps describe how to edit the GLOBAL or CARD_CONFIGURATION description of the model file for online or offline operation:

- Open a terminal window.
- Change directory to /etc/opt/hp93000/soc_common/
- Save a copy of the original model file as model.org or tester.model.org, see [Model file sections](<02.04.01.03_Model_file_sections.md>).
- Open the model file in an ASCII editor, locate the "`GLOBAL`"/"`CARD_CONFIGURATION`" section, and change the relevant system feature.
- Save the model file.
- Restart the SmarTest software for the specified test. Upon restarting, the new model file is compared to the test system configuration. If any problem occurs, an error message will either be displayed or appear in the report window.

In case of an error, go to [Model file error messages](<02.04.05.09.01_Model_file_error_messages.md>).
