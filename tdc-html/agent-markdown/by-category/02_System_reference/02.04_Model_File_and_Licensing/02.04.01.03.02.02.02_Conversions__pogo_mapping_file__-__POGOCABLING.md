# Conversions: pogo mapping file <-> POGOCABLING

The pogo mapping feature gives you additional flexibility as it allows different cabling rules for the same DUT board and test head size, but for varying test head content.

SmarTest 6.5.x releases support both the use of pogo mapping files and the POGOCABLING format in the model file. SmarTest 7.0 or later supports only the POGOCABLING format.

## Conversion from pogo mapping file to POGOCABLING

If you want to use pogo mapping on a SmarTest version 7.0 or later, you need to convert the information in the pogo mapping file to the `POGOCABLING` format in a model file.

- Start a SmarTest version 6.5.x (not 7.x). A log file PogoCabling.log will be created in the directory /opt/hp93000/soc/system/log. The log file contains the current pogo mapping information in the `POGOCABLING` format.
- Copy the content of the log file to the model file which will be used in the later version of SmarTest. Save the model file.
- Restart SmarTest with the model file using the `POGOCABLING` format.

## Conversion from POGOCABLING to pogo mapping file

If you want to use a model file using the `POGOCABLING` format on a SmarTest version lower than 6.5, you need to convert the pogo mapping information in the model file to a pogo mapping file.

- Run the script

/opt/hp93000/soc/system/config/xoc.hw.cor.pogocabling.ZSPogoCabling/pogocablingToPogomappingConverter.ksh.

Use your model file as the input argument and save the converted content in a file. For example, run the script as below:

`/opt/hp93000/soc/system/config/xoc.hw.cor.pogocabling.ZSPogoCabling/pogocablingToPogomappingConverter.ksh ~/model_new >/etc/opt/hp93000/soc/pogomap`

- Refer to the saved pogo mapping file in the model file and remove the `POGOCABLING` section. For example, add the following specification in the model file,

`pogo_cabling =/etc/opt/hp93000/soc/pogomap`

 Note SmarTest 6.5.x supports both the pogo mapping file and the `POGOCABLING` format. A conversion is not required.
