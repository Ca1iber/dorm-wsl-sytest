# How to generate and provide a device license file

The testflow analyzer tool (TAT) analyzes the testflow and generates a device license file (.licenses) in the current directory.

## Before you begin

Note that some of the optional parameters require a [line model encrypted database](<02.04.05.07.01_Installing_the_line_model_encrypted_database.md>) (smartest_aslmedb*).

## Procedures

### Default

- Start SmarTest in either offline or online mode. We recommend that you start SmarTest in the offline mode, and that you use a model file with full capabilities (full memory, top speed, all features).
- Load a testflow, including setups.
- Make sure to provide a [hardware definition file](<02.04.05.07.04_The_hardware_definition_file__HDF.md>) (HDF).
- Enter the following command:

/opt/hp93000/soc/prod_pws/bin/tat -f <filename>

-f is a must parameter; <filename> is either the hardware definition file (HDF) or a model file.

The generated device license file lists only the minimum needed capabilities for the given testflow.

You can rename the .license file to reflect different test scenarios, for example, finalTest.license or waferSort.license.

To provide the device license file for the test system, you must move or copy the file to your device license directory. In order to be read, the device license file must reside in the following directory:

<device-directory>/license

### Alternatives

- Alternatively, you can develop your device license files based on an example file or on a model file.
- The "example device license file" at /opt/hp93000/soc_<version>/pws/data/per-device-license.def documents the device license file syntax and serves as device license file example.
- You may also edit a model file to get a device license file:
- Copy the model file to the license directory of the device.
- Remove all SECTIONS including their section header that Do not include any license information.
- Remove all entries in the remaining sections which Do not have to be licensed (like test head, etc.)
- Modify the license requiring entries for your device according to your needs (speed, memory, timing_bundle, etc.)
- Add possible hardware alternatives.
