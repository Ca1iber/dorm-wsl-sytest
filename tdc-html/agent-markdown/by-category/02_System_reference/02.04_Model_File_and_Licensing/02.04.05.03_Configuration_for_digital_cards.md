# Configuration for digital cards

To access the full capabilities of a test system resource, for example, maximum speed or memory of a channel or memory card for your device test, you must specify them either in the model file or in the device license file.

The model file or the device license file enables the required test system resources and features. You must define the resources in the [model file](<02.04.01_The_model_file.md>) or the [device license file](<02.04.05.06_The_device_license_file.md>) to set the necessary configuration and features for your addressed tests.

 CAUTION If a device license file exists, its parameters will be evaluated and any licensing parameters in the model file will be ignored.

The device license file can only include license relevant entries, like speed, memory, etc. Non-license relevant entries like test head, etc. belong into the model file. If no device license file is provided, the relevant licensing parameters in the model file will be evaluated. See also [The device license file](<02.04.05.06_The_device_license_file.md>).

The following sequences for both online and offline mode vary for Licensing-per-device. When SmarTest is started, it proceeds as described below.

## Offline mode

In offline mode, SmarTest:

- Reads the model file.
- Checks for a device license file.

If a device license file is found, the licensing content in the model file is ignored and the device license file is used instead. Otherwise, the licensing parameters in the model file are used for licensing.

- Checks the model file for syntax errors, feature dependency errors, or hardware dependency errors.
- Sets the configuration of the test system from the model file contents.

The model file is used to simulate the test system configuration.

## Online mode

In online mode, SmarTest:

- Reads the model file.
- Checks for a device license file.

If a device license file is found, the licensing content in the model file is ignored and the device license file is used instead. Otherwise, the relevant licensing parameters in the model file are used for licensing.

- Checks if there is no syntax error or feature dependency error in the model file.
- Checks if there is no hardware conflict (for example, hardware is not installed, or hardware is not compatible) by comparing the actual installed resources in the test system.
- For the test system resources and features that are managed by the licenses, generates the license requests for the resources and features from the model file to the license server, then checks out the requested licenses from the server.
- Sets the configuration of the test system from the model file contents and given licenses.

Thus, for the resources managed by licenses, the model file is one possible basis for generating license requirements.

## License blocking

But avoid license-blocking. For example, if you define "too many" features in the configuration of your addressed device test in the model file, SmarTest will check out "too many" licenses from the server. This means, your system holds some surplus licenses. At this time, other users cannot use their licenses on other systems until the instance of SmarTest on your system is shut down (all given licenses will be released). As this is not useful, you should create a model file that fits with your test needs and thus avoids the blocking of licenses.

If your own licensing needs coincide with those of other users, we recommend to share the same licenses in different time slots. Otherwise you need to purchase enough licenses so that both users can use the same sort of licenses on their respective system.

For the flexibility of the license system, you could create a variety of the model files and switch them as needed. We do not recommend this approach. With release 5.3 you should apply [The device license file](<02.04.05.06_The_device_license_file.md>) concept instead.

If SmarTest detects an error, such as a syntax error in the model file, a hardware conflict, or no available license, an error message will be displayed in the report window or a pop-up error window.

For more information on the SmarTest's start-up process, see [How SmarTest sets the system configuration](<02.04.04.01.01_How_SmarTest_sets_the_system_configuration__for_SmarTest_7.md>).

Note If a channel card is installed but the model file does not have the channel card definition entry for that channel card, the system software evaluates no channel corresponding to the channel card in both the online and offline mode.Note When you change the device or create a new device in the SmarTest software, SmarTest skips the above process and keeps the currently-used configuration based on the model file that is read at SmarTest start-up. When SmarTest is shut down, it will release the given licenses. When SmarTest is restarted, a new model file will be enabled and the SmarTest software will check out licenses again.
