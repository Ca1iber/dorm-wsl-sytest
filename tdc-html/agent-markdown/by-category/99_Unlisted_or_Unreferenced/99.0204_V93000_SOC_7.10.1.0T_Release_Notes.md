 SmarTest is the V93000 system software required to operate the V93000 family of semiconductor test systems. SmarTest runs under the operation system (OS) Red Hat enterprise Linux (RHEL).

 Release notes inform you about the software support for new products, newly added features and functionalities as well as on provided defect fixes. Advantest provides support and maintenance over stated time periods for all SmarTest release streams. This life cycle allows customers and Advantest to effectively plan, deploy and support SmarTest software.

## What's new

Release stream 7.10 enables to use the new EXA Scale generation with SmarTest 7.

Release 7.10.1T is the second technology release in the SmarTest 7.10 stream.

Release stream 7.10 is a 64-bit application supported under RHEL7.4.

- EXA Scale platform support

### Test program compatibility

-  SmartRDI-7.4.4. is better integrated into SmarTest which requires that `${HP83000_ROOT}/segments/tml/include` is set in the project properties of the project for both Debug & Release build.

 After SMT 7.3.2, by DEFAULT, above include pathes are already set by Smartest, but they might be missing in older projects. In case you get a build issue with RDI 744, please check the include path and add the path.
- Since 7.1.3T we handle obsolete CMM more consequently. Any statement with "VM" in the pattern (e.g. DMAS, SQPG) will generate a download error (as the parser does no longer know VM). The 7.0 software already gives a warning that the used statements are no longer supported. Now, since 7.1.3, this will be an error.

 Solution: In case you still have VM statements in the pattern, simply invoke the conversion tool (conv_vector).

### Calibration Data Compatibility

Calibration intends to derive correction values, so that the hardware will always comply with the stated specifications. With newer software revisions there may be algorithm changes and syntax changes making the resulting calibration data incompatible with older revisions.

Starting with SmarTest 7.10 the system has to be recalibrated. Run a full calibration. For more details see service documentation, "Internal adjustment (auto calibration)" (77951) and "Calibration and adjustment" (87730).

Key Mapping

 |

- Due to the key mapping issue of the system window manager, we strongly recommend to turn off the lock keys ("Caps Lock", "Scroll Lock", and "Num Lock") when using key accelerators, for example to execute a selected test suite in the test flow editor.
 |

 |
 |

defining LD_LIBRARY_PATH

 |

- Do not put system library directories (especially /lib and /usr/lib) into the LD_LIBRARY_PATH environment variable!
 The software does not need a pre-set LD_LIBRARY_PATH environment variable to run. This variable is heavily used internally but the software takes care of that itself at startup. However, an LD_LIBRARY_PATH set and exported before the software is started, is not discarded! There are some debugging scenarios that require pre-setting it. But the system standard libraries, especially '/lib' and '/usr/lib' should NEVER be put into the LD_LIBRARY_PATH, except you really, really know what you are doing!
- Background: The SmarTest software contains at least one shared library with the same name as a system library (there are about 900 libraries in /lib and /usr/lib - this happens). The system library is not needed by our software so the name clash is not an issue. But when the '/usr/lib' directory is searched for libraries before the application library directories, the wrong library is found and loaded. As it does not contain what the application expects, of course, the software crashes with some 'symbol not found' error messages.
 |

 |
 |

Environment Permission Setup

 |

- If a SmarTest installation is used (= started) by more than one user-account, the following rule must be strictly applied:
 All users working with SmarTest must grant read and write permission to each other! A way to do this, is to put all those users in one group and set a umask value of 2. A user with a umask setting of 2 will create files with mode `-rw-rw-r--`. This allows all users in the same group to read from and to write into the created files. If more protection is needed, use a umask value of 6. This will create files with permission `-rw-rw----`, which allows only users in the same group to access the file.
 |

 |
 |

Network configuration

 |

- Definition of "localhost" in /etc/hosts
 In some network configurations SmarTest fails to start when the definition of "localhost" (127.0.0.1) is not the first one in the file "/etc/hosts". We recommend putting the definition for "localhost" always into the first line of "/etc/hosts".
 Symptoms for a problem with the /etc/hosts file are:

  - The SmarTest software fails to start and reports a "process timeout" error.
  - In the log file "CompleteSystem.slg" (usually under "/opt/hp93000/soc/system/log/" - if elsewhere the location is written to the report screen) is an error message containing:
 "Session Service Manager threw: URP_Bridge : disposed (tid=5) Unexpected connection closure"

- DHCP configuration
 If your network is configured with DHCP, make sure that your workstation has one of the following configurations:
 In the file /etc/sysconfig/network you must have one of the following entries:

  - no HOSTNAME entry
  - HOSTNAME = localhost.localdomain
  - HOSTNAME = < resolvable hostname >

>

Resolvable hostname means that the IP your DNS server returns for the hostname must be identical to the IP of your workstation.

Diagnostic Tests Fail in Case of Enhanced Embedded Result Array

 |

- A custom setting using a device with an enhanced embedded result array e.g. for DC-dynamic features, causes some diagnostic tests to fail, which are based on per-pin sequencer programs:

  - DQUE : data queue
  - MREF : memory refresh
  - ESIN : extended sequencer instruction

- In order to run the tests successfully, a device must be used that doesn't change the location, and where per-pin programs are stored. This can be easily achieved by creating and using a new dummy device.
 |
