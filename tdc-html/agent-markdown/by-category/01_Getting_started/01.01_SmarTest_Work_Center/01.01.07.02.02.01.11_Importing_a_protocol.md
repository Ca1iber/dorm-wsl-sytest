# Importing a protocol

## About this task

This task describes how to import a protocol definition to your device.

## Before you begin

With regards to resource pin and port setup, ensure your device pin setup is already prepared for the protocol to be imported.

## Procedure

-  Right-click the Protocols icon in the test program explorer and select Import...
-  Now you have two options. You can either import a predefined protocol, or import a user defined protocol from a shared repository or from the /protocols directory of a different device.

  - SmarTest provides a bundle of predefined protocols for memory emulation. This bundle must have been separately installed before the protocols it contains can be imported. If yes, "ME" can be selected for memory emulation. Select the bundle and click Next.
  - In the second case, activate Custom directory, browse to the location from where you want to import a protocol definition, and click Next. ![Import protocol](<../../../../raw/126349.png>)  Note The imported protocols will be loaded automatically after import unless you deselect this option.

-  Rename the to be imported protocol if needed, i.e. if the same protocol definition exist within your device already or if you would like to use a different name.  ![Rename protocol imported](<../../../../raw/126353.png>)  Note Protocols already existing in your device directory are marked. Note If you do not rename existing protocol definitions they will be overwritten!
-  Click Finish to import and load the selected protocol.

## Results

The selected protocol has been imported to your device directory and loaded into the test program explorer.

## What to do next

You can edit the protocol definition to match your current device as described in [Using the protocol editor](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.22.10_Using_the_protocol_editor.md>).

You have to adapt pin role and port assignments to match your current device as described in [Assigning pin roles and protocols](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.18.03.10.01_Assigning_pin_roles_and_protocols.md>).
