# Using the Setup Management Tool from the Test Program Explorer

The Setup Management Tool ships with SmarTest. It is intended to be used from the Test Program Explorer (although it can also be started from the command line, as described in [Using the Setup Management Tool from the Command Line](<01.01.07.02.02.04.03_Using_the_Setup_Management_Tool_from_the_Command_Line.md>)).

For a conceptional description of the Setup Management Tool see [Setup Management Tool](<01.01.07.02.02.04_Setup_Management_Tool.md>).

 Note If SmarTest is installed on a system controller for the first time, nothing else is required to activate the Setup Management tool. But if the system controller already contained an earlier version of SmarTest which does not include the Setup Management tool, then you will also have to copy the Test Program Explorer filter scripts from /opt/hp93000/soc/com/lbin to /etc/opt/hp93000/soc_common/lbin and rename them. See [Customizable Scripts](<01.01.07.02.02.02_Customizable_Scripts.md>) for details.

Activating the Setup Management Tool does not commit you to administrating your setups with the tool. In fact, the Test Program Explorer calls the Setup Management Tool only in the following two situations:

- The file which is to be loaded or into which the actual setup component is to be saved already exists, and its first line indicates that it is a master file.
- The file into which the actual setup component is to be saved does not yet exist, and its name has the extension *.mfh.

In all other cases, the file is considered to be a standard setup file, which can be loaded or saved as it is.

The setup component which is created from the subfiles specified in the master file and is downloaded to the tester is not visible in the Test Program Explorer. It is the name of the master file which is displayed below the icon of the respective setup component. In fact, you practically need not care about the setup file at all when you use the Setup Management Tool from the Test Program Explorer. This will become clear from the following overview of the user actions that trigger the Setup Management Tool.

## Converting a normal setup file to a new master file

Load a normal setup file and save it as <base_name>.mfh, where <base_name>.mfh does not yet exist. Then the Setup Management Tool will:

- Split up the currently loaded setup file as much as possible
- Create subfiles for the individual parts
- Create a master file with the name <base_name>.mfh which contains the appropriate entries for the created subfiles

You can rename the new master file after it has been created. The Test Program Explorer will recognize it as a master file by its first line.

## Converting a normal setup file to a predefined master file

Load a normal setup file and save it as <master_file_name>, where <master_file_name> already exists. If the first line of <master_file_name> indicates that <master_file_name> is, in fact, a master file, then the Setup Management Tool will:

- Split up the currently loaded setup file and create subfiles according to the entries in <master_file_name>
- If a part of the setup has been deleted, or a new part has been added, then it will also update the master file (and create a separate subfile for a new part).

This approach has the advantage that you have control over the splitting granularity (you can store several parts in one subfile) and the names of the subfiles. However, you must have created the master file beforehand in this case. To make sure that its format is correct, you can copy an existing master file or create an empty master file with the New option of the Test Program Explorer.

The master file must specify a tester setup file name, but you can name it as desired. If it is different from that of the currently loaded tester file, the Test Program Explorer will rename this tester file accordingly before it calls the Setup Management tTool.

## Loading a master file

Select a file whose first line identifies it as a master file from the file list and load it. The Setup Management Tool will merge the subfiles specified in the master file into one setup, and the Test Program Explorer will download this setup to the tester.

## Saving a master file

Save the currently loaded master file. The Setup Management Tool will split the setup file and create subfiles according to the entries in the master file. If a part of the setup has been deleted, or a new part has been added, then it will also update the master file (and create separate subfiles for new parts).

## Saving a master file as another master file

This case is similar to converting a normal setup file to a master file. The file that will be split is the setup file that was ceated from the source master file.
