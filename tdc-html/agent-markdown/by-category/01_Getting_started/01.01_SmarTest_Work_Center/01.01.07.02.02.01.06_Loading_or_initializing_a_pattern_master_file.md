# Loading or initializing a pattern master file

You can load a pattern master file either from the Testflow Editor or from the Test Program Explorer. This topic describes the latter.

## About this task

There are two ways to load a pattern master file from the Test Program Explorer. The result of these actions is not identical.

- Load: loads the pattern master file, sets up the internal structures, and loads all the pattern files specified.
- Initialize Pattern Master File: loads the pattern master file, sets up the internal structures, but does NOT load the patterns.

In the Pattern Explorer, the initialized but not loaded patterns are listed as grayed-out items.

## Before you begin

The pattern master file must exist. To create a pattern master file see [Creating a pattern master file](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.16.01.15.01_Creating_a_pattern_master_file.md>).

## Procedure

-  In the Test Program Explorer right-click the pattern item and select Load. This opens the file selection dialog.
-  Select a pattern master file (*.pmfl) to load and click OK. This loads the pattern master file and all referenced pattern files.
-  To initialize a pattern master file:
-  In the Test Program Explorer right-click the pattern item and select Initialize Pattern Master File. This opens the file selection dialog.
-  Select a pattern master file (*.pmfl) to initialize and click OK. This loads the pattern master file and initializes all referenced pattern files. In the Pattern Explorer they appear grayed-out, and in the State column they are marked with Not Loaded. The sequencer program will only be loaded into hardware during the actual test execution. Note When loading a pattern master file and viewing the status information in the report window, it may appear that patterns are loaded twice. The first time when patterns are read from disk, a dependency analysis is computed. This is usually a quick process. Then, depending on the patterns that are to be loaded, those patterns, and any that they call, are read from disk and loaded into hardware, in the correct order. This loading into hardware takes significantly more time. Therefore, the files are read from disk twice, but only loaded into hardware once.
