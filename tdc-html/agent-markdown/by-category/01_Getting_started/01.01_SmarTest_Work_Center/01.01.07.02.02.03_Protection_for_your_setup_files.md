# Protection for your setup files

#### Subtopics

- [Customized hp83_import for encrypted setup files](<01.01.07.02.02.03.01_Customized_hp83_import_for_encrypted_setup_files.md>)
- [How to crypt a file](<01.01.07.02.02.03.02_How_to_crypt_a_file.md>)
- [How to compile hp83_import](<01.01.07.02.02.03.03_How_to_compile_hp83_import.md>)

In a production environment, you may want to protect your setup files against any unauthorized modification. Modification from within SmarTest can be prevented by starting the software in the Protected mode (option -P). This mode gives no access to any debug or setup GUI's, and does also not allow switching into any other (for example, engineering) mode.

## File encryption

In order to exclude modification of the files from outside of SmarTest, you can encrypt them. For this, you can use the ccrypt tool which is preinstalled on every system controller that is shipped with the test system. The encrypted files must be protected against unauthorized decryption by an encryption password.

If you encrypt your setup files, you must decrypt them before they can be loaded into SmarTest. This must be done in such a way that the decrypted content is not stored anywhere in a file, since otherwise these files could be tampered with.

You can achieve this by creating a customized version of the hp83_import script (see [Pre-Load Operations for Setup Data: hp83_import](<01.01.07.02.02.02.01_Pre-Load_Operations_for_Setup_Data__hp83_import.md>)) which calls ccrypt to decrypt the files. The script must be compiled in order to hide the decryption pass word that it must pass to ccrypt. If you use conventional setup files (or a pattern master file for the vector setup), the decrypted content can be passed directly through stdout to the SmarTest software, so that it will never be stored in a file. For an example of such a modified import script, which also takes care of other security issues, see [Customized hp83_import for encrypted setup files](<01.01.07.02.02.03.01_Customized_hp83_import_for_encrypted_setup_files.md>).

## Using master files

Things are more complicated if you use master files for setup components other than the vector setup (see [Setup Management Tool](<01.01.07.02.02.04_Setup_Management_Tool.md>)). In this case hp83_import would have to decrypt not only the master file which is passed to it, but also the subfiles pointed at in the master file. Furthermore, the decrypted subfiles would have to be stored somewhere to be available to the Setup Management tool. Therefore some mechanism would have to be implemented which removes the decrypted subfiles after they have been merged and downloaded by the Setup Management tool. However, since the Setup Management tool is primarily intended for distributed development, there will be probably no reason to make use of it in a production environment. You can always transform a setup component that is controlled by a master file into a conventional setup file by loading it with the Setup Management tool and then saving it under a new name which has not the extension *.mfh.
