# Collision handling for the TMLimits master file

Collision between definitions in component files referenced in a test table master file are detected but not automatically resolved.

If several files referenced from one TMLimits master file contain tests (rows) with identical keys, these test definitions collide.

Such collisions are reported by SmarTest but not resolved automatically. The setup files are all loaded, and you can continue to use them. However, only the first loaded definition of several conflicting definitions for one test is actually available. This means that testflow executions that rely on the other conflicting definitions will not perform correctly.

If a conflict between test definitions in setup files is reported, you should always resolve the conflicts and reload the files.

## Example

File 1:

```
"Suite name", "Test name", "Test number", "Units", "Lsl",  "Usl", "Test_remarks"
...
"Continuity2", "DC_CONT_P", "555",        "UNIT",  "-0.1", "0.1", "WalkZP"
...
```

File 2:

```
"Test name",  "Suite name",  "Test number", "Rem"
...
"DC_CONT_P",  "Continuity2",  "125",         "optional"
...
```

Both files define the same test, which is identified by the combination of suite name and test name. (The order of the fields does not matter.)

Only the definition in file 1 is kept (assuming that file 1 is loaded before file 2); the definition in file 2 is discarded.
