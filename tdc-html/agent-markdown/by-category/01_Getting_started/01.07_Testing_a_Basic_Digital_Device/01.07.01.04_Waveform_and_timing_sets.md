# Waveform and timing sets

#### Subtopics

- [Equation based timing setup](<01.07.01.04.01_Equation_based_timing_setup.md>)
- [Setting up the wavetables](<01.07.01.04.02_Setting_up_the_wavetables.md>)
- [Defining the equation sets](<01.07.01.04.03_Defining_the_equation_sets.md>)
- [Defining the spec sets](<01.07.01.04.04_Defining_the_spec_sets.md>)

For each channel or a group of channels you can define a number of waveform and timing sets to run your tests with. A waveform set is a logical entity stored in system memory that holds:

- For all pins together:

  - System clock period
  - Default device cycle name

- Per pin:

  - [Device cycle](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.34.01.03_Device_Cycles.md>) definitions in a device cycle table
  - Physical waveform definitions in a [physical waveform table](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.16.04.05_Wavetables.md>)
  - One or more timing sets

To define a waveform, you need to provide (among other things) the timing information for the waveform. This is where timing sets come in. A timing set forms a part of a waveform set and stores:

- The test system period
- Edge placement delays for the configured pins
