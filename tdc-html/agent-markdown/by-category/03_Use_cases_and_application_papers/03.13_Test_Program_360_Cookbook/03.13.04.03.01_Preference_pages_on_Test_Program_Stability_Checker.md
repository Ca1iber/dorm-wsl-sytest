# Preference pages on Test Program Stability Checker

Lets you customize the checking process for the risks you want to check. Different risk items are associated with different preference pages.

Clicking the ![Step 1: Configure contents to be generated in release report (optional) (3)](<../../../../raw/143004.png>) icon for the risk to be checked opens its related preference page.

## HiZ risk Preference page

On its related preference page, you can configure the test suites to be checked and the pins, waveforms and level sets to be checked.

- Check HiZ (High Impedance voltage) risk in selected test suite types: all, functional
- Options related with "Pin driver without definitive drive status"

  - Check HiZ risk of missing level termination definition
  - Check if iol and ioh are both set to zero
  - Check HiZ risk of waveform with "no drive state, tri-state on(FNZ), no compare or compare X".

- Option related with no wavetable defined for vector

  - Check HiZ risk of using undefined waveform index(s) in vector

- Depth of vector cycles to check undefined waveform index(s) in vector: 100, 1000, 10000, all
- Option is related with standard HiZ behavior protection

  - Check HiZ risk of missing termination and clamp definition for level set 0 on PS400(Only SamrTest version 6.3.6 or above)

## DPS setup risk preference page

With its related preference page, you can find out the DPS pins whose current exceeds the limit value that you have specified there.

- Check ilimit value of DPS pins
- Report risk if ilimit value of a DPS pin is larger than

## Edge placement risk preference page

Check whether risky waveform index is used in related vectors

## Missing and redefined pin preference page

On its related preference page, you can select the setups so that missing pins or redefined pins will be checked.

- Check no trigger line definition for MCA,MCB,MCC
- Check missing pin(s) in level setup
- Check missing pins(s) in wavetable
- Check missing pins(s) in timing equation set and timing set
- Check missing pins(s) in vector
- Check redefined pin(s) in level setup
- Check redefined pin(s) in wavetable
- Check redefined pin(s) in timing equation set and timing set

## MSET resource usage preference page

- Check if new MSET is created in every test flow execution that will lead to MSET overflow risk
- Check if "m_sets" number defined in .technology file is too larger than needed which can lead to Xput issue with following criteria

## Hot-switching and clamp risk preference page.

On its related preference page, you can select and specify the criteria for reporting hot-switching risks.

Note The hot-switching risk check is based on the MCDLog and warning messages.

## Relay switching times preference page

On its related preference page, you can set up the criteria for reporting relay switching times risks.

- Check AC,DC and PPMU relay switching times is larger than limit
- Check utility line switching times is larger than limit

Specify the Pin relay switching times warning limit(Unit:times)
