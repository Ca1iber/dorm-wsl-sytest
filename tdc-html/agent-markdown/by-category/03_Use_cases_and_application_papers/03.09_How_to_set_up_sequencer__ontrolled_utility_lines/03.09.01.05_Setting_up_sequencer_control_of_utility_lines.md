# Setting up sequencer control of utility lines

## About this task

This task describes how to set up and use sequencer鈥慶ontrolled utility lines.

- V93000 EXA Scale systems running SmarTest 7:

Sequencer鈥慶ontrolled utility lines are provided by the [optional Utility Card](<../../02_System_reference/02.05_Test_Head_Cards/02.05.08.04_Utility_Card.md>) and controlled via the serial interface pins FRAMn, SCLK and SINP of the utility pogo blocks.

- V93000 EXA Scale systems running SmarTest 8:

Sequencer鈥慶ontrolled utility lines are provided by the [optional Utility Card](<../../02_System_reference/02.05_Test_Head_Cards/02.05.08.04_Utility_Card.md>) and controlled via an internal data path.

- V93000 Pin Scale and Smart Scale systems:Sequencer鈥慶ontrolled utility lines are provided by the active wiring boards implemented on the following test head / DUT interface combinations:

  - Large test head (LTH) with the large DUT interface
  - Small test head (STH) with the DUT Scale interface
  - Compact test head (CTH) with the DUT Scale interface
  - A-class test head (ATH) with the DUT Scale interface or with the small DUT interface
The utility lines are controlled via the serial interface pins FRAMn, SCLK and SINP of the utility pogo blocks.

## Procedure

-  For V93000 EXA Scale systems running SmarTest 8:

  - Configure the [GLOBAL section](<../../02_System_reference/02.04_Model_File_and_Licensing/02.04.01.03.01.01_GLOBAL_section.md>) of the SmarTest 8 tester.model file for the correct utility pogo block size.
  - No additional connections are required on the DUT board. Serial interface pins FRAMn, SCLK and SINP provide no functionality but connections to digital pins are tolerated.
  - The setup for the utility lines is similar to the setup defined in Controlling utility lines but the definition of the control lines by keyword utilityControl is not required. An already existing section utilityControl is accepted but has no effect.
  - Use "utility actions" of the Utility Card to control utility lines during a measurement within an operating sequence.Note The Utility Card cannot be used as single instrument in an operating sequence. It must always be accompanied by another test processor based instrument. Native V93000 EXA Scale instruments like PS5000 and XPS256 are preferred but legacy V93000 Smart Scale instruments are also accepted.

-  For V93000 Smart Scale systems running SmarTest 8:

  - Configure the [GLOBAL section](<../../02_System_reference/02.04_Model_File_and_Licensing/02.04.01.03.01.01_GLOBAL_section.md>) of the tester.model file for the correct utility pogo block size.
  - Route three digital pins on the DUT board to the appropriate serial interface pins FRAMn, SCLK and SINP.
  - Create a test setup for the serial pins: For more information, refer to Controlling utility lines.
  - Use "utility actions" of the Wiring board to control utility lines during a measurement within an operating sequence.

-  For V93000 Pin Scale, Smart Scale systems, or EXA Scale systems running SmarTest 7:

  -  Configure the [GLOBAL section](<../../02_System_reference/02.04_Model_File_and_Licensing/02.04.01.03.02.01_GLOBAL_section.md>) of the model file (Pin Scale and Smart Scale systems) or the [GLOBAL section](<../../02_System_reference/02.04_Model_File_and_Licensing/02.04.01.03.01.01_GLOBAL_section.md>) of the tester.model file (EXA Scale systems) for the correct utility pogo block size. Do the same for the [.technology file](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>).
  -  Route three (or four) digital pins on the DUT board to the serial interface pins of the required utility line pogo block. For pogo block locations see [Utility line assignments](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.01_Utility_line_assignments.md>).
  -  Use APIs [UTILITY_SEQ_MODE](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.265_UTILITY_SEQ_MODE.md>) and [UTILITY_SEQ_STATIC_MASK](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.266_UTILITY_SEQ_STATIC_MASK.md>) to configure and enable the serial interface.
  -  Set up the pin configuration according to your DUT board design using the [Pin configuration tool](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.18_Pin_configuration_tool.md>).
  -  Set up the levels for the serial interface pins using the [Level setup tool](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.14_Level_setup_tool.md>).
  -  Create a wavetable and set up the timing for the serial interface pins using the [Timing Setup Tool](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.34_Timing_Setup_Tool.md>).
  -  Create your pattern for the serial interface using the [Pattern Editor](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.16.02_Pattern_Editor.md>).
  -  Use API [UTILITY_SEQ_MODE](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.265_UTILITY_SEQ_MODE.md>) in your test methods to enable sequencer control. This is referred to as dynamic access to utility lines.
  -  Use API [UTILITY_SEQ_STATIC_MASK](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.266_UTILITY_SEQ_STATIC_MASK.md>) in your test methods to define static masks for sequencer鈥慶ontrolled utility lines.

## Examples

### Example 1: Setup for SmarTest 7

The following example sets up three digital pins named D1, D2 and D3 to act as serial inputs to the utility line controller on the active wiring board, refer also to the graphic in [Sequencer-controlled utility lines](<03.09.01_Sequencer-controlled_utility_lines.md>). The controller acts as the DUT in this case.

Pin D4 is a receive pin. It is also set up in the pin configuration but is not used in the rest of the example. The example programs utility lines 1, 3, and 15 on utility block 1 to turn on LEDs connected to these lines.Note This example uses 2-row pogo blocks.

Serial pins for sequencer control of utility lines
 | Digital pin  | Serial pin description  | Direction |
 | SCLK  | Serial clock  | Input |
 | FRAMn  | Serial frame enable  | Input |
 | SINP  | Serial data in  | Input |
 | SOUT  | Serial data out  | Output |

-  Make the following entry in the [GLOBAL section](<../../02_System_reference/02.04_Model_File_and_Licensing/02.04.01.03.02.01_GLOBAL_section.md>) of the SmarTest 7 model file:

utility_lines = 128, type = sequencer_controlled, pogo_size = 16

pogo_size specifies the number of utility lines per pogo block and utility_lines specifies the total number of utility lines (pogo_size multiplied by the number of utility blocks). Usual combinations are 64/16, 128/16 and 256/32.

Note If you were to use 4-row utility pogo blocks, the values for utility_lines and pogo_size would need to double. Combinations such as 128/32 or 256/16 are invalid. Note The default for the model file is 128 utility lines and 16 utility lines per pogo block. This applies if you omit the utility_lines entry.

Make the following entry in the [.technology file](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.07.02.01.02_Technology_file_for_a_device.md>):

utility_lines_per_pogo_block: 16

Alternatively you could edit the Utility Block Size entry in the Change Device dialog window, in this case refer to [Editing technology data](<../../01_Getting_started/01.01_SmarTest_Work_Center/01.01.10.03.03_Editing_technology_data.md>).

Refer also to [Configuration of 4-row or 2-row utility pogo blocks](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.07.02_Configuration_of_4-row_or_2-row_utility_pogo_blocks.md>).

Note If you were to use 4-row utility pogo blocks, the value for utility_lines_per_pogo_block would need to double.
- Set up the pins as shown:  ![Pin configuration for the serial interface](<../../../../raw/128789.png>)
- Use the following code to set up the levels.

```
EQNSET 1 "drive_receive"

SPECS

EQUATIONS

LEVELSET 1

    PINS SCLK FRAMn SINP
        vil = 0
        vih = 1.8

    PINS SOUT
        vol = 0.7
        voh = 1.1
```

- Use the following code to set up the timing.

```
EQNSET 1

    SPECS
        Frequency [MHz] # max 20 MHz

    TIMINGSET 1
        period = 1000/Frequency

    PINS SCLK FRAMn SINP
        d1 = 0

    PINS SOUT
        r1 = 1000/Frequency*0.5+100
```

- Use the following code to set up the wavetable

```
WAVETBL drive

    DCDT nop

    PINS SCLK FRAMn SINP
        0 "d1:0"
        1 "d1:1"
        2 "d1:Z"
        3 "d1:Z"
        4 "d1:Z"

    PINS SOUT
        2 "r1:L"
        3 "r1:H"
        4 "r1:X"
```

- Assign the clocking frequency for the serial control lines to your equation set and wavetable.Note The utility line controller on the wiring board is able to handle a maximum frequency of 10 MHz. The clock input to the controller is filtered and higher frequencies are ignored.  ![Assign the frequency of 10 MHz for the serial control lines](<../../../../raw/128790.png>)
- Enter the pattern shown below into the Pattern editor. It shifts 16 bits into the utility line shift register via SINP. Note that one bit is represented by two vectors in the pattern. Thus the waveform at SCLK (D1) requires a 0 and a 1 to generate a single cycle, see for example vectors 4 and 5.

The whole pattern is surrounded by high-Z vectors. The pattern section required to drive the 16 utility lines present on a single block starts with vector 4 and ends with vector 35. During this period the signal on FRAMn (D2) is driven to 0.

Bit 0 of SINP specifies utility line 1, bit 15 specifies utility line 16. Thus to turn on relays on lines 0, 12 and 14, the pattern on SINP (D3) must drive a 0 on vectors 34 & 35, 10 & 11 and 6 & 7. The rest of the vectors must remain at 1. Each relay coil must be connected between the UP5V line and the corresponding utility line as shown in example [Controlling user relay on a DUT board (V93000 systems)](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.03.03_Utility_line_example_circuits.md#_98018__s_Controlling_user_relay_on_a_DUT_board>) of [Utility line example circuits](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.03.03_Utility_line_example_circuits.md>). For additional details refer to [Utility line interface circuitry](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.03_Utility_line_interface_circuitry.md>).

For the mapping of utility lines on utility blocks refer to the links in [step 2](<03.09.01.05_Setting_up_sequencer_control_of_utility_lines.md#_124758__cmd_Routing_of_digital_pins>) of the procedure above. SOUT (D4) is not used and is therefore set to high-Z for all vectors in the sequence.

  ![Control pattern for a single utility line block](<../../../../raw/124940.png>)  Note If you were to use 4-row utility pogo blocks, the pattern would need to be extended to shift 32 bits into the utility line shift register instead of 16. Note Entering a pattern manually can be a tedious and error-prone method, but is the simplest way if controlling just one or two utility blocks. If you need many utility lines you may consider other methods such as [d2s](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09_d2s-framework.md>) or [Protocol Aware](<../../02_System_reference/02.07_Test_Method_Reference/02.07.11_Protocol_Aware_ATE.md>).
- Add the test method code to the test method class as shown below.

```
UTILITY_SEQ_MODE utiSeqModeReset;
UTILITY_SEQ_MODE utiSeqModeOn;
UTILITY_SEQ_MODE utiSeqModeOff;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Reset previous settings
    //
    utiSeqModeReset.pogoBlock().mode(TM::SEQ_POGO_MODE_OFF);
    utiSeqModeReset.execute();

    //
    // Enable utility block 1 for serial control
    //
    utiSeqModeOn.pogoBlock(1).mode(TM::SEQ_POGO_MODE_RW );
    utiSeqModeOn.execute();

    //
    // Perform the functional test
    //
    FUNCTIONAL_TEST();

    //
    // Disable the sequencer鈥慶ontrolled mode of all utility blocks
    //
    utiSeqModeOff.pogoBlock().mode(TM::SEQ_POGO_MODE_OFF);
    utiSeqModeOff.execute();

ON_FIRST_INVOCATION_END();
```

### Example 2: Ganging utility blocks in SmarTest 7

If you were to gang two 2-row utility line blocks together you would need to set up a pattern of twice the length as you would have to shift in 32 bits instead of just 16. Then, to enable for example utility line blocks 1 and 2 for serial control, you would need to implement the following API call into your test methods:

```
UTILITY_SEQ_MODE utiSeqModeOn;

utiSeqModeOn.pogoBlock(1,2).mode(TM::SEQ_POGO_MODE_RW );
utiSeqModeOn.execute();
```

Note If you were to gang two 4-row utility pogo blocks, the above API calls would shift 64 bits into the utility line shift register instead of 32.
