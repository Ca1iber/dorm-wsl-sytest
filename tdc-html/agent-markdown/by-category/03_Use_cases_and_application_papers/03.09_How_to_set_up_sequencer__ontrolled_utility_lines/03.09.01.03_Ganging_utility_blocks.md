# Ganging utility blocks

A serial interface for sequencer‑controlled utility lines can handle the data stream for more than one utility block. This cascading of serial interfaces of utility blocks is called "ganging" in the context of the sequencer‑controlled utility lines.

  Note This section applies to

- V93000 Pin Scale and Smart Scale systems running SmarTest 7,
- V93000 Pin Scale and Smart Scale systems running SmarTest 8,
- V93000 EXA Scale systems running SmarTest 7 and equipped with the [optional Utility Card](<../../02_System_reference/02.05_Test_Head_Cards/02.05.08.04_Utility_Card.md>).

On V93000 EXA Scale systems running SmarTest 8 and equipped with the optional Utility Card, the pattern sequencer controls utility lines via an internal data path.

## Rules and general behavior for ganged utility blocks

The following rules are to be considered for ganging utility blocks:

- The ganged utility blocks must be contiguous.
- Up to eight pogo blocks can be controlled by a single serial interface.
- The block with the lowest number becomes the master.
- Only the serial interface pins on the master must be connected to the digital pins that you will be using to supply the control signals.
- The interface pins of the slave utility blocks must be left floating. The required connections for ganging the slave blocks are routed internally.
- On V93000 EXA Scale systems running SmarTest 7 and equipped with more than one [optional Utility Card](<../../02_System_reference/02.05_Test_Head_Cards/02.05.08.04_Utility_Card.md>), ganging utility blocks across Utility cards is not supported.

The serially transferred data are internally stored in a hardware register and transferred in parallel to all utility lines of the controlled group of ganged blocks:

- Utility lines are not toggled while the data are transferred via the serial interface is in progress.
- All lines change the state in parallel as soon as the transfer via the serial interface has been finished.
- Because the time required for this hardware based dynamic switching is negligible, latency can be disregarded.

## Defining ganged utility blocks

 In your test program, ganged utility blocks are to be defined as follows:

- SmarTest 8:

The ganged utility blocks are to be defined by element utilityControl of the DUT board description file  with minimum two contiguous utility pogo blocks defined. For more information, refer to Controlling utility lines.

- SmarTest 7:

The ganged utility blocks are to be defined by the [UTILITY_SEQ_MODE.pogoBlock()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.265.02_UTILITY_SEQ_MODE.pogoBlock.md>) test method API. Refer also to the example on ganging utility blocks in [Setting up sequencer control of utility lines](<03.09.01.05_Setting_up_sequencer_control_of_utility_lines.md>).

## Multiple groups of ganged utility blocks

It is possible to configure more than one ganged group. For example, you can set up digital control of utility blocks 1,2,3 via a set of three digital channels and at the same time set up digital control of utility blocks 4,5,6,7 via another set of three digital channels. Sequencer control of the groups of utility blocks can be switched on and off independently.

## Data width of the serial interface

Ganging of utility blocks allows you to expand the data width beyond that of a single word (either 16 or 32 bits), where the number of ganged utility blocks multiplies the available word width.

For instance, by ganging three utility blocks of 16 bits each a data width of 48 bits is produced which can be controlled by a single burst of digital serial data. With word widths of 32 bits, available on 4‑row utility blocks, it is possible to control up to 256 utility lines (8 utility blocks with 32 utility lines each) by three (or four) digital pins. You determine the word width yourself by fitting either 2‑row or 4‑row utility pogo blocks to your DUT interface, refer to [Utility line assignments](<../../02_System_reference/02.03_DUT_board_design_reference/02.03.04.01_Utility_line_assignments.md>).
