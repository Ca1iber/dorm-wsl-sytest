# PRBS Jitter Measurement by TMU

Hideo Okawara, ADVANTEST

Paper-ID: 144892 November 2013

## Preface

The TMU (Time Measurement Unit) is an excellent resource integrated in the PS9G/1600 test head cards of the V93000 SoC Tester. It records timestamps the instant that a signal crosses over a designated threshold. This article describes about points to take a PRBS bit stream and how to figure out jitter values from the measured timestamps.

## TMU Setup

Figure 1 illustrates the TMU’s schematic from the programming point of view. There are three modes available for capturing events. "RISE" looks at rising edges. "FALL" takes falling edges. "RISE_FALL" captures rising and falling edges alternately. The input signal is up to 8 Gbps or 4 GHz for PS9G. The timestamp speed reaches maximum 50 Msps. So you may need to slow down a high-speed signal event that is faster than 50 Msps. Prescaler is a frequency divider up to 1/16, making the input events less than 250 Msps this is the maximum event speed. For instance, 4 GHz by 16 makes 250 MHz. The prescaled events are decimated in the next stage to less than 50 Msps.

 ![PRBS Jitter Measurement by TMU (1)](<../../../../raw/144893.png>)

For a fair analysis of jitter in PRBS signals, both rising and falling edges should be taken care of, so you should select the edge mode of RISE_FALL. Then, "Prescaler" is allowed from 2 to 16. Figure 2 illustrates the situation of Prescaler=2. Two pulses are skipped and the third pulse is captured. Thus it detects rising and falling edges alternately, marked as red and green. The prescaled events go into the next stage for decimation, which is programmed by "InterSampleDiscard." For example, while InterSampleDiscard is 0 or 2, both rising and falling events would be timestamped as array data T[n]. However, if InterSampleDiscard is 1, either rising events or falling events only would be captured as illustrated. This situation is not appropriate for fair jitter evaluation. Therefore, you should assign an even number to InterSampleDiscard.

## PRBS and Unique Patterns

PRBS (Pseudo Random Binary Sequence) is a typical test signal used for high-speed digital testing. An LFSR (Linear Feedback Shift Register) generates a specific bit stream. The 4-bit LFSR illustrated in Figure 3 continuously generates 24-1=15-bit pseudo random pattern. Looking at the waveform of the PRBS4 bit pattern, you can find 8 edges or 23 events in the stream.

 ![PRBS Jitter Measurement by TMU (2)](<../../../../raw/144894.png>)

Figure 4 illustrates how the TMU captures all rising and falling events of the PRBS4 and records the timestamps. This is a conceptual figure for comprehension so that Prescaler is omitted for simplicity. The red-marked edges are supposed to be timestamped. In the case of InterSampleDiscard=2 (left), two events are skipped between the rising and falling edges, and in InterSampleDiscard=4 (right), four events are skipped. In each case the final edge is the same as the starting edge. So, the TMU continuously captures the series of three iterations in the left case, and the series of five iterations in the right case.

 ![PRBS Jitter Measurement by TMU (3)](<../../../../raw/144895.png>)

While looking at the time intervals between the marked events in each case, there are eight time intervals found during the three and five iterations respectively. The point here is that the waveform of each interval pattern is individually unique in each case. An L-bit LFSR generates 2L-1 bits of PRBS stream, and there are 2L-1 unique patterns found in the time interval waveforms. Even if InterSampleDiscard is different, the number of unique patterns is constant. The averaged time interval is 5.625 UI (unit interval) and 9.375 UI respectively, which is supposed to be the virtual sampling period in the next discussion.

## Jitter Computation Procedure

TMU puts out timestamps which are monotonously increasing data. Figure 5 depicts how time error (jitter) can be derived from the timestamps. It describes the simplified case of PRBS4. The TMU would report timestamps at the red-marked edges of the waveform. You already know a set of eight unique patterns repeated in the timestamps. So you can recognize a set of eight time intervals as 8, 5, 6, 6, 4, 8, 5 and 3 UI. Then, you can estimate the reference timestamp values by accumulating the sizes of time intervals. Consequently, you can compute the time difference array TE[i] between the measured and the reference of the timestamps. The data TE[i] is the time error that is primitive jitter, which is supposed to be sampled at the rate of the average time interval, i.e. 5.625 UI in the case.

 ![PRBS Jitter Measurement by TMU (4)](<../../../../raw/144896.png>)

In the actual measurement, you do not need to know what kind of unique patterns are captured or how long each one of the unique patterns is. You already know the number of unique patterns as 2L-1 for a PRBS of L-bit LFSR. The measured time intervals contain the 2L-1 unique pattern set repeated. So you can compute the ideal timestamp locations based on the captured data itself.

Now that you have the gross time error sampled at the average time interval that is the virtual sampling rate, you can analyze the frequency spectrum of the jitter by applying the FFT (Fast Fourier Transform) as Figure 6 illustrates.

Firstly, you can compute the total jitter (TJ) from the gross jitter spectrum. Jitter is noise so that you should accumulate the total noise power, which is square-rooted to make it the amplitude of jitter. TJ is usually represented with the unit of peak-to-peak (pp) so that the amplitude is multiplied by 2. The equation to calculate TJ is included in the figure.

Generally speaking, TJ can be classified to random jitter (RJ) and deterministic jitter that can be separated to periodic jitter (PJ) and data dependent jitter (DDJ). So in this article, TJ is separated into PJ, RJ and DDJ eventually.

In the example of PRBS4, the number of unique patterns is 23=8. When you capture 1025 timestamps and calculate 1024 time intervals, you would find the 8-unique-pattern set 128 times repeated in the time interval data. So 1024-element jitter data can be aligned to an 8x128 array as Figure 7 illustrates. Each row shares each unique pattern so that the mean value of each row provides DDJ component based on the unique pattern. Then you can remove the DDJ component from each jitter elements as Figure 8 depicts. Consequently, PJ and RJ remain in the residual jitter.

 ![PRBS Jitter Measurement by TMU (5)](<../../../../raw/144897.png>)

The DDJ repetition has an impact on the gross jitter spectrum. It would appear as a specific spurs in the spectrum, which looks something like green lines in Figure 9. Subtracting the DDJ components from the gross jitter makes the spectrum quieter as Figure 10 shows. There is PJ and RJ remained in the residual jitter. Therefore, you can compute the DDJ as the power difference between the gross jitter and the residual jitter. PTJ is the original total noise power. PPJRJ is the residual noise power containing PJ and RJ. The power difference (PTJ-PPJRJ) becomes the DDJ power, so square-root of the power difference is the amplitude. DDJ is represented as peak-to-peak (pp) so that the amplitude should be multiplied by 2. The equation is included in Figure 10.

 ![PRBS Jitter Measurement by TMU (6)](<../../../../raw/144898.png>)

After computing the DDJ, the residual jitter spectrum should be separated into PJ and RJ. Figure 11 illustrates how to do it. You should draw an appropriate decision threshold by examining the spectrum appearance. There is no specific rule on how to draw the threshold. So you may need to do some preliminary experiments.

 ![PRBS Jitter Measurement by TMU (7)](<../../../../raw/144899.png>)

PJ components are strong, conspicuous and localized in the spectrum display. RJ has no frequency response so that it looks like white noise. Once you draw an appropriate threshold in the spectrum, the power of components above the threshold is counted as PJ power, and the power below the threshold is counted as RJ power. Figure 11 contains the equations to figure out PJ and RJ. PJ is usually represented as peak-to-peak (pp) so that the power of PJ is square-rooted and multiplied by 2. RJ is usually represented as root-mean-square (rms) so that the power of RJ is square-rooted and divided by square-root of 2.

## Program Example (V93000 SoC Tester)

The tested signal is 6.4 Gbps 127-bit PRBS7 so that there are 64 unique patterns found in the measured time intervals. The one UI period of the signal is 156.25 ps.

The TMU is programmed as follows;

- Prescaler 13
- InitialDiscard 0
- InterSampleDiscard 6
- Number of Samples 65537 Points (65536+1)

The program code listed below is an example coding of the measurement.

 ![PRBS Jitter Measurement by TMU (8)](<../../../../raw/144900.png>)

This part describes how the TMU is set up and measures. There are definition of task, measurement and data uploading coded. "CP" is the TMU pin name. In the digital vector pattern of "CP", there must be the keyword of "ARM" where TMU starts measurement. The measured timestamp data is uploaded and stored in the variable dTstamps[], which will be processed to calculate jitter.

The following lines are the data processing for jitter computation. Firstly, the timestamp data is normalized by the period of 1 UI at Line 50 and 51. Then, the time intervals between consecutive timestamps are computed by the resolution of UI from Line 53 to 56. The number of time intervals Nintervals is one less than the number of timestamps Nsamples.

 ![PRBS Jitter Measurement by TMU (9)](<../../../../raw/144901.png>)

Now that the timestamps are transformed to the time intervals, the time error or the primitive jitter data will be derived. Firstly, the number of unique patterns Nuniq is computed at Line 58 so that the number of iterations of the unique pattern set is settled at Line 59.

 ![PRBS Jitter Measurement by TMU (10)](<../../../../raw/144902.png>)

Each one of the iterations would contain exactly the same unique pattern sets; however, if the test signal contains significant, high-frequency jitter, the individual size of unique elements actually fluctuates iteration by iteration. So all unique pattern sets are averaged from Line 64 to 72. This averaging makes the measurement method applicable to larger amplitude of high-frequency jitter. The processing from Line 76 to 79 accumulates the averaged unique patterns to figure out the ideal timestamp values.

The difference between the measured timestamps and the ideal timestamps becomes the primitive time error data as Line 83 and 84, which is supposed to be sampled at the rate of averaged time intervals.

 ![PRBS Jitter Measurement by TMU (11)](<../../../../raw/144903.png>)

The derived time error trend may still remain a small slant and an offset. Therefore, the time error array is straightened by the regression analysis from Line 86 to 89. Finally, the primitive jitter data is derived as dTimeErrorUI[].

The gross jitter array is transformed to the jitter frequency spectrum by the FFT at Line 93, where the keyword of "PWR" is important.

 ![PRBS Jitter Measurement by TMU (12)](<../../../../raw/144904.png>)

Each one of the spectrum lines except DC is accumulated at Line 96. This is the TJ power. The square-root of power makes it the amplitude at Line 97, and the factor of 2.0 makes the amplitude as peak-to-peak value. The factor of dT1UI/(1.0 ps) means the conversion from [UI] to [picoseconds]. This is the way TJ is computed.

Line 99 to 112 is the DDJ calculation. The gross jitter array can be aligned as 2D array of Nuniq x Niterations.

 ![PRBS Jitter Measurement by TMU (13)](<../../../../raw/144905.png>)

There are Niterations of elements in each row, which shares the same unique pattern. So elements in each row are summed and the mean value is computed per row from Line 106 to 109. Each mean value is the DDJ of each unique pattern. Then, the gross jitter element is modified by subtracting each DDJ element at Line 113 and 114.

Now that PJ and RJ remain in the residual array, the power of residual jitter is computed from Line 118 to 120. The DDJ power is the difference of the TJ power and the PJ+RJ power. The TJ power is already computed at Line 96.

 ![PRBS Jitter Measurement by TMU (14)](<../../../../raw/144906.png>)

Finally, the square-root of the DDJ power is the DDJ amplitude. DDJ is expressed as peak-to-peak so that the factor of 2 is multiplied at the end. This is the way DDJ is calculated.

The residual jitter power is a mixture of PJ and RJ. Periodic jitter is a deterministic component so that its spectrum stays still at a certain bin. On the other hand, random jitter has no frequency response so that it looks like white noise in the band. Therefore, by introducing a decision threshold in the frequency spectrum, you can/are able to separate PJ and RJ.

 ![PRBS Jitter Measurement by TMU (15)](<../../../../raw/144907.png>)

The threshold is actually decided experimentally by examining the spectrum appearance. Once you decide it as Line 126, by collecting the power above the threshold, the PJ power is calculated at Line 131, and by collecting the power below the threshold, the RJ power is calculated at Line 132. PJ is expressed as peak-to-peak so that the factor of 2 is multiplied to the square-root of the PJ power. On the other hand, RJ is expressed as rms so that the square-root of the RJ power is divided by the square-root of 2.

 ![PRBS Jitter Measurement by TMU (17)](<../../../../raw/144909.png>)

## Experimental Results (2)

In this experiment, a 1 MHz 100 ps-pp sinusoidal jitter is intentionally injected in the same PRBS signal. The TMU measures it with the same condition.

Figure 18 depicts the measured time error and its amplitude histogram. Figure 19 shows the gross jitter spectrum, where you can find the strong spectrum component at 1 MHz. The TJ is calculated as 106.2 ps-pp.

 ![PRBS Jitter Measurement by TMU (20)](<../../../../raw/144912.png>)

The gross jitter is aligned as a 64x1024 array and the DDJ is analyzed. By subtracting the DDJ component from the gross jitter, Figure 20 shows the DDJ removed time error. The jitter amplitude is slightly reduced and the amplitude histogram looks more like sinusoidal distribution. Figure 19 shows the residual jitter spectrum. The power difference between Figure 19 and 21 provides the DDJ as 31.6 ps-pp. The PJ and RJ are calculated as 99.2 ps-pp and 7.5 ps-rms with the decision threshold of -40 dB. The injected jitter is 100 ps-pp so that the derived PJ seems to be reasonable.

 ![PRBS Jitter Measurement by TMU (21)](<../../../../raw/144913.png>)

The PJ/RJ separation threshold is experimentally decided by examining the spectrum appearance. So the threshold sensitivity to the separated PJ and RJ values is tested as Figure 22 illustrates. The graph shows the computed PJ and RJ trends according to the decision threshold from -80 to -30 dB on the X-axis. While the threshold is set around -60 dB to -40 dB, PJ is estimated approximately 100 ps-pp and RJ is around 5 to 7 ps-rms. These results are acceptable for this experiment. Therefore, the threshold is not so sensitive when separating PJ and RJ. Consequently, you need not worry about how to settle it accurately.

## Conclusion

The TMU provides timestamps of events, and is a good resource to measure jitter in a PRBS signal. The point of setup is as follows;

- Edge type: RISE_FALL
- InterSampleDiscard: Even Number
- Number of Samples: 2n+1 (n does not mean the LFSR size.)

The procedure of processing is as follows;

 ![PRBS Jitter Measurement by TMU (23)](<../../../../raw/144915.png>)

Jitter is a kind of timing noise so that the summation of power spectrum should be analyzed. The square-root of the power becomes the jitter amplitude. TJ, DDJ and PJ are usually represented with p-p so that the jitter amplitude is multiplied by 2. RJ is usually represented with rms so that the jitter amplitude is divided by square-root of 2.
