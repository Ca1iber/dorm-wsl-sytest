# Sequencer Start overhead

## Optimizing activation of primary sets at pattern start

At the start of a functional test, the sequencers must activate the actual primary sets, at least when they are not yet active. This is time consuming and should be reduced to the necessary minimum. In order to minimize the sequencer overhead at pattern start you have the following options:

## Group together testsuites that use the same primary sets

By default, activation of primary sets is suppressed if these sets are already active.

See [FTCG, FTCG? - (Functional Test ConfiGure)](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.125_FTCG__FTCG__-__Functional_Test_ConfiGure.md>).

## Combine tests with the same primary sets into a burst

Even if the primary sets for a functional tests are already active and therefore by default not reactivated, the software still has to check whether activation can in fact be suppressed. This delay can be avoided by combining several functional tests into a burst. All these tests must use the same primary sets.

See [Burst and Multi-Burst Labels](<../../02_System_reference/02.06_Command_Reference/02.06.07.01.08.05.03_Burst_labels_and_multi-port_burst_labels.md>), [Viewing and editing bursts](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.16.01.03_Viewing_and_editing_bursts_in_the_Pattern_Explorer.md>).

If the burst fails, you can determine with the FLBL? query which patterns failed. Note that this requires to configure the overview Error Map accordingly.

See [Compression factor for overview Error Map](<../../02_System_reference/02.06_Command_Reference/02.06.11.01.02.01.02.07_Compression_factor_for_overview_Error_Map.md>).

## Optimizing activation of timing and level sets within the pattern

If CTIM (timing set change) and CLEV (level set change) instructions are present within the sequencer program, the sequencers must activate the new sets. This also prolongs the test time considerably. These instructions cannot be optimized, but will always be executed, even if the respective set is already active. Therefore, remove any unnecessary CTIM or CLEV instructions from your sequencer program.

If these instructions are required, the following facts may be helpful for reducing the test time:

- A timing set change is faster than a level set change
- Changing from a slow to a fast period takes longer than changing from a fast to a slow period.

The Ascii Interface inserts a, usually redundant, CTIM instruction at the start of every sequencer program by default. This can be suppressed by adding the v2b option -T to the respective pattern in the global configuration file.

See [The Input Columns](<../../02_System_reference/02.11_Data_Conversion_and_Bridges/02.11.02.02.01.01.01_The_Input_Columns.md>).

## Reducing the execution time for activating primary sets

The time that is needed to activate a primary set depends on the specified tester period. If the required device period is long, you can minimize this time by making the tester period as small as possible and building the device waveforms (X-waveforms) from several tester waveforms (fractional x-mode). You can define the X-waveforms by using the STATEMAP section of the wavetable.

See [Representing a pattern in device orientation](<../../02_System_reference/02.06_Command_Reference/02.06.06.01.03.05_Representing_a_pattern_in_device_orientation.md>).

A drawback of this construction is that if one device waveform consists of n tester waveforms, you will need n times as much vector memory.
