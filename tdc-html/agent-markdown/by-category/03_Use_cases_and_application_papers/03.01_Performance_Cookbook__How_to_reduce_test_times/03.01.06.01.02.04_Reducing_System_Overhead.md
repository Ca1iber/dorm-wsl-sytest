# Reducing System Overhead

All delay factors that are caused by the local system configuration should be eliminated as far as possible. This also serves to make the measurements reproducible on another system. In particular observe the following:

- Save the data log to a local, not a remote file.

The output files of the SmarTest Data Formatter are defined in the /etc/opt/hp93000/soc_common/datalog/global.conf file. The relevant keywords are formatter.stdf.detailedFileLocation and formatter.stdf.summaryFileLocation.

If you want to transfer the event data log stream into a file without using STDF, you must add the MOVE_EVENT_STREAM command to the sublevel_dialog application model.

The GDF data log file is defined in the application model, the location of the GDF workorder status file depends on where the workorder directory is situated.

- Make sure that SmarTest is located on a local disc.

Before you execute the workorder, make sure that no other (especially server) processes than those actually needed are running on the workstation. You can view the active processes with the ps -ef shell command. In particular make sure that

- no SmarTest offline session
- no Java process (this includes the jstart process)
- no VNC server

is active on the workstation. The first two requirements can be forced by rebooting the workstation and then starting SmarTest in supervisor mode (using supervisor mode ensures that none of the java processes that are needed for engineering mode is started). In order to check if a VNC server is running, issue the shell command

ps -ef | grep vnc
