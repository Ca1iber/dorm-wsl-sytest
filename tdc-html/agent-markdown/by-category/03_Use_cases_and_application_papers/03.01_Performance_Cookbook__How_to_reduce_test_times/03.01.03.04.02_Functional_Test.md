# Functional Test

FUNCTIONAL_TEST() only activates digital primaries such as timing and levels and, therefore, typically has a fast execution time.

Use functional tests where ever possible for parametric tests.

When a functional test is executed from a test suite, the following procedures take place

- The following primary set parameters are programmed to the hardware if they are different to the previous parameters:

  - timing setup
  - level setup
  - vector label (patterns)
  - analog set (for mixed signal tests)

- The master clock frequency is programmed if different to the previous Primary set.
- The sequencer is triggered to run patterns.
- When completed, Global or Detailed pass/fail are checked.

All these steps contribute to the test time, so it is necessary to consider how to keep these steps to a minimum when testing your DUT.

Some general points to observe:

- Use the Optimizer flag to optimize test programs
- Do not run from test flow editor.
- Use averaging (min 25 runs) to get repeatable test numbers. NO single shot
- Minimize switches between primary setting (level,timing,analog sets, spec sets etc.) between test suites. Put the test suites in an appropriate order to minimize switching.
- Pay attention to test suite (data log) flags. Goal: Log only pass/fail.
