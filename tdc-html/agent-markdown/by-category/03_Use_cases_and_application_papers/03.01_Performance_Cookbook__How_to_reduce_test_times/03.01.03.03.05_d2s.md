# d2s

The d2s-framework provides the features needed to set up and test DUT's using protocols.

It has two [modes](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.03_d2s_modes.md>) which can be controlled by a global user variable:

- Learning mode - generates static pattern and adds them to one burst label.
- Production mode - executes the burst label generated by the learning mode.

## Steps to implement the d2s-framework

- Setup level, timing, vectors and pins of your device as described in [Setup and Result Tools](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08_Setup_and_Result_Tools.md>).
- Generate write, read and wait template labels for your protocol as outlined in [Prepare device setup](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.01_Prepare_device_setup.md>).Note The d2s-framework only supports x1 and 1/x (padding)-modes for serial protocols.
- Rename and modify the user template file d2sSerialProtocolTemplate.cpp to fit your protocol as described in [Configure the protocol](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.03_Configure_the_protocol.md>).

  - [Configure general parameters](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.03.01_Configuring_general_parameters.md>), such as protocol port name, address and data bits and the protocol name.
  - [Configure the write parameters](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.03.02_Configuring_write_parameters.md>) of your protocol.
  - [Configure the read parameters](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.03.03_Configuring_read_parameters.md>) of your protocol.Note Reading from an register always requires to strobe to 'L'.
  - [Configure the wait parameters](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.03.04_Configuring_wait_parameters.md>) of your protocol.

- [Include the renamed protocol template](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.02_Prepare_the_test_method_infrastructure.md>) (for example, `d2sJTAG.h`) and the `d2sFramework.h` to your test method.
- Write your test method and include the d2s protocol methods, such as read, write, etc, within a d2s_LABEL-block.Note Do not use any other API calls other than the d2s methods in the d2s_LABEL-block.

## Special options

The d2s-framework offers special options such as

- [Multiple transaction ports](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.04.01_Multiple_transaction_ports.md>), which enables concurrent protocol transactions on multiple ports.
- [Transaction ports without a protocol](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.04.02_Transaction_ports_without_a_protocol.md>), which allows you to add predefined patterns of ports that do not use a protocol to the burst label.
- [Global framework mode](<../../02_System_reference/02.07_Test_Method_Reference/02.07.09.04.04.03_Global_framework_mode.md>), which allows easy switching between learning and production mode by using a test method variable.
