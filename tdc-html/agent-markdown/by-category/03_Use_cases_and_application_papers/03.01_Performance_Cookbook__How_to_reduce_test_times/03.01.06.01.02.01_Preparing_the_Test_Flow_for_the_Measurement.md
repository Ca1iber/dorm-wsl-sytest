# Preparing the Test Flow for the Measurement

In the first step, you must prepare your testflow for the measurement. This includes:

- If you use event data logging, set all system flags referring to GDF to off.

Event data logging does not affect the test time significantly. The delay caused by logging the data log stream is small, and the data formatter, which converts the log stream into STDF format, is not called when a test is running.

- Enable test time measurement by setting the debug_mode testflow flag to 3.

With debug_ mode set to 3, SmarTest will write a detailed time analysis of the testflow as a whole and its individual components into the ui_ report window. These data are the basis for further investigations. For more details see [Understanding the Output of Debug Mode 3](<03.01.06.01.03_Understanding_the_Output_of_Debug_Mode_3.md>).

Note that the event data log also provides test time information. For some details see [Timestamps in the event data log](<03.01.06.01.04_Timestamps_in_the_event_data_log.md>).

- If you have a linear testflow (no branching), set the global_overon flag (which is set to off by default) and the Overon flags of all stop bins (which are by default set to on) to on.

This setting has the effect that the testflow is continued even if a device falls into a stop bin. This ensures that the sample size for the statistical analysis is the same for all testsuites.

 Note The model file (/etc/opt/hp93000/soc/model) can also prolong the test time unnecessarily if you have activated features in it that you do not need in your test. Therefore, as a rule of thumb, do not enable any feature in the model file that is not required for your purposes. For example, if differential receivers are enabled in the model file (diff entry in misc column of the IOCHANNEL section), then all timing sets must be downloaded in two versions, one for single-ended termination and one for differential mode, which can prolong the download time up to 40 %. Similarly, initialization of the wavetable takes longer for 256 waveforms than for 32.
