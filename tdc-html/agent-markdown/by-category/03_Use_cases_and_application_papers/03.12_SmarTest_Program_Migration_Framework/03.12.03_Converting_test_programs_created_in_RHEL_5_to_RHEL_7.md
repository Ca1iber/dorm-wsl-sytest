# Converting test programs created in RHEL 5 to RHEL 7

Compiling test program source code with SmarTest running on the Red Hat Enterprise Linux (RHEL) 7 operating system that were originally developed on Red Hat 5 might require some minor changes.

## Conflict between SI-units from MapiUnit.h and boost headers

Variables defined in test methods must not have the same name as these unit identifiers.

By including boost headers after MapiUnit.h variables and template parameter names that have been given the same names as these unit identifiers might become part of your code and the code will fail to compile.

To fix the problem make sure that MapiUnit.h is always included after all other #include statements.

  Note MapiUnit.h might be included indirectly by other header files - commonly mapi.hpp and testmethod.hpp and also your own header files.

Most common are conflicts for s(econds), A(mpere), S(iemens), and V(olt).

You can find examples for these with the following command:

grep -rl " [ASV]," /usr/include/boost/

Example:

boost/lexical_cast.hpp uses s as variable name.

In the MapiUnit.h API, s is also defined as a macro:

#define s

If the MapiUnit.h API is included before boost/lexical_cast.hpp, the result is a compiler error.

Change the order of includes to make sure that boost/lexical_cast.hpp is included before MapiUnit.h. Failing example

```
#include <mapi.hpp> // includes MapiUnit.h
#include <testmethod.hpp> // includes MapiUnit.h

#include <boost/lexical_cast.hpp> // defines from MapiUnit.h cause compilation errors
```

  Corrected example

```
#include <boost/lexical_cast.hpp>

#include <mapi.hpp> // includes MapiUnit.h
#include <testmethod.hpp> // includes MapiUnit.h
```

  Alternative Another option is to undefine (#undef) the conflicting units before including boost headers and defining them again afterwards.

```
#undef s
#include boost/lexical_cast.hpp
#define s
```

This might be necessary if the include statements are deeply nested and it is not possible to move MapiUnit.h after all include statements.
