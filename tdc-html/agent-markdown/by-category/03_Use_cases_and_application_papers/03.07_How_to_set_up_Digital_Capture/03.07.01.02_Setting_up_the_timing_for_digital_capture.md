# Setting up the timing for digital capture

To set up the timing for digital capturing, you must add a wavetable for the pins you want to capture on. The timing setup for digital capturing differs for the capture modes Sequential, standard Selective, and Selective in High-Resolution-Pass/Fail (HRPF) mode.

- For sequential capturing, the wavetable entries are regular compare actions on the capture pins.
- For selective capturing with standard resolution, the wavetable entries corresponding to capture actions are entered on the desired cycles.
- For selective standard capturing with a statemap defined resolution, you additionally must provide a STATEMAP section to the wavetable in the timing file.

For selective capturing in High-Resolution-Pass/Fail (HRPF) mode, the wavetable must contain the HRPF keyword.

## Timing for sequential capturing

For sequential capturing the timing setup is identical to the timing created for a regular o or io digital pin. In single mode only one compare strobe is set (note that only r1 can be used), and in double mode two compare strobes are set (r1 and r4 are the allocated strobes).

For details see also [Digital Capture Modes](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.01.02.07.01_Digital_Capture_Modes.md>).

Note Sequential capturing is not available for Pin Scale 3600 channels in FAST mode.

## Timing for selective standard capturing

For selective capturing the receive strobes are defined as capture (C) or Do not capture (D), for example, r1:C and r1:D. Selective capturing can be carried out on any or all of the eight receive edges. For further timing aspects see [Defining waveform shapes](<../../02_System_reference/02.06_Command_Reference/02.06.06.01.03_Defining_waveform_shapes.md>).

Note A capture pin for selective standard capturing must contain only C and D receive actions across the entire pattern.

## Timing for selective STATEMAP-based capturing in xN-mode

Digital capturing can also utilize the xN mode. For this you must add a STATEMAP section to the digital capture wavetable. The STATEMAP section defines the representation of x-mode waveforms in the pattern editor.

In this case, the STATEMAP section defines the resolution of the selective capturing, that is the number of samples per test system cycle.

## Rules for STD and FAST channel modes

Pin Scale 3600 channels can be configured in STD (standard) mode or in FAST mode. The number of capture samples taken per test system period depends on the channel mode:

- in STD (standard) mode: between 1 and 8
- in FAST mode: 1, 2, 3, 4, 6, 8

In STD mode, the following rules apply:

- C or D actions cannot be mixed with other receive actions within one waveform:

0 "r1:C r2:H" ch = ERROR

- The selective capture actions C and D cannot be mixed within one selective capture waveform:

0 "d1:1 r1:C r2:D" zcd = ERROR

## Example 1:

This example shows a simple wavetable for selective standard capturing.

```
WAVETBL "digital_capture"

  PINS dig_cap
       0    "d1:Z r1:L"      L
       1    "d1:Z r1:H"      H
       2    "d1:Z r1:X"      X
       3    "d1:Z r1:C"      C     # capture
       4    "d1:Z r1:D"      D     # Do not capture
```

## Example 2:

This example again starts with a wavetable for selective standard capturing, but adds a STATEMAP section to the wavetable. This allows to capture in xN-mode; in this example in x4 mode.

```
WAVETBL "digital_capture"

  PINS dig_cap
       0    "d1:Z r1:L"                  L
       1    "d1:Z r1:H"                  H
       2    "d1:Z r1:X"                  X
       3    "d1:Z r1:C r2:C r3:C r4:C"   CCCC   # capture
       4    "d1:Z r1:D r2:D r3:D r4:D"   DDDD   # Do not capture

   STATEMAP
       #wf_idx   statechars   x-mode   selector
       0         L            x1
       1         H            x1
       2         X            x1
       3         CCCC         x4
       4         DDDD         x4
```

## Timing for selective capturing in HRPF mode

To enable the High-Resolution-Pass/Fail (HRPF) mode, you must add the HRPF keyword in front of at least one waveform definition. This marks the whole wavetable as being "capture with pass/fail compare".

That is, you can capture and compare on the same pin in one pattern, but you cannot capture and compare within one waveform.

Note Different than capture pins for selective standard capturing, a capture pin for selective capturing in HRPF mode can contain C and D receive actions and compare actions.

## Examples

### Simple wavetable for selective capturing in HRPF mode

```
WAVETBL "digital_capture_hrpf"

  PINS dig_cap_hrpf
  HRPF  0    "d1:Z r1:L"      L
        1    "d1:Z r1:H"      H
        2    "d1:Z r1:X"      X
        3    "d1:Z r1:C"      C     # capture
        4    "d1:Z r1:D"      D     # Do not capture
```

### Restriction on "partner edges" in HRPF mode

A restriction applies to to the so-called partner edges on Pin Scale 800 and Pin Scale 3600 digital cards. In HRPF mode, for x2 and x4 modes, each edge must be matched to a corresponding partner edge:

r1 with r5

r2 with r6

r3 with r7

r4 with r8

For example, for the x2 mode you must partner as follows:

```
        3    "r1:C r5:C"      CC
```

You cannot use `r1:C r2:C,` as you can for selective standard capturing. Note that the pairing rule apply only on the receive edges of the capture waveforms defined in your wavetable. The timing equations for these edges in your timing set specify the edges in ascending order, that is, r1, r2, r3, and so on. See the following example:

```
# WAVETABLE
WAVETBL "X8Capt"
...
PIN SEROUT
HRPF 0 "d1:0" 0
1 "d1:1" 1
2 "d1:Z r1:L"       L
3 "d1:Z r1:H"       H
4 "d1:Z r1:X"       X
// receive edges in the capture waveform are defined according to the pairing rule
5 "d1:Z r1:C r5:C r2:C r6:C r3:C r7:C r4:C r8:C"  CCCCCCCC
...
# Timing
EQNSET "X8CaptTim"
...
PIN SEROUT
d1=0d2=0.5*Tcyc
// receive edges for the digital capture are specified in ascending order
r1=0.100*Tcyc
r2=0.225*Tcyc
r3=0.350*Tcyc
r4=0.475*Tcyc
r5=0.600*Tcyc
r6=0.725*Tcyc
r7=0.850*Tcyc
r8=0.975*Tcyc
```
