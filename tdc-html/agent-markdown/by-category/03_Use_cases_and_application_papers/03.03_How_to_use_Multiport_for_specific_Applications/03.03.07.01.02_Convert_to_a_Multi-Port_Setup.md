# Convert to a Multi-Port Setup

#### Subtopics

- [Multi-Port Port Definition and Pin Configuration](<03.03.07.01.02.01_Multi-Port_Port_Definition_and_Pin_Configuration.md>)
- [Multi-Port Vector Conversion](<03.03.07.01.02.02_Multi-Port_Vector_Conversion.md>)

As mentioned, in this example the DUT to be tested contains two independent cores:

- Digital Signal Processor (DSP)
- Audio A/D and D/A converter (CODEC)

For speed of testing, a concurrent test for testing both cores simultaneously is desired and this requires a multi-port setup.

However, your existing DSP digital test program (functional test) is set up for a single port application.

Note: For simplicity, in this example it is assumed that the CODEC program was already developed in multi-port and does not need conversion.

Your first step is to modify the digital test program from single port to multi-port and include any digital pins from the CODEC core into your modified digital test program (the analog pins are simply defined as analog pins).

If the DUT's cores, operate at different frequencies and utilize different sequencer data, each port will need to be set up to execute separate vectors and utilize different timing settings.

Each functional port can have a different clock period which would normally be an integer multiple of the assigned master clock on the V93000 test system.

When multiple ports are assigned to a master clock, the period resolution is normally optimized to match the test periods of all ports as accurately as possible. However, the ideal period may not be equal to the actual period.
