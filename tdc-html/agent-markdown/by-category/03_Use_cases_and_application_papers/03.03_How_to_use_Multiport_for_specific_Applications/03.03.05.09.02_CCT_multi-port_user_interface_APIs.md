# CCT multi-port user interface APIs

The CCT Multi-Port Sequencer Synchronizer API includes user interface APIs that you use to program digital multi-port burst and handle the synchronization across ports.

The available user interface APIs are the following:

- CCTMultiportSync

CCTMultiportSync is a data container to trace the activities (insertion of a label) at each port and control synchronization across ports.

- RegisterControlPort with PA

RegisterControlPort with PA is the interface to create a label with protocol (PA) and append that label to an assigned port.

Common functions for register access

The RegisterControlPort abstract base class defines and implements, some general forms of register access functions. Those functions invoke register operation functions that are implemented in the derived SYNCHRONIZED_TEST(for PA) user class that must implement the virtual function defining the register access functions able to create labels using the user defined method (PA wrapper API).

For details about the usage of the APIs, see [APIs defined for the Concurrent Test Framework](<../../02_System_reference/02.07_Test_Method_Reference/02.07.08.06_APIs_defined_for_the_Concurrent_Test_Framework.md>).

## Workflow

The following workflow lists the high-level tasks that you need to complete to program digital multi-port burst and handle the synchronization across ports.

- The wrapper (first level by PA tool and second level wrapper by CTF wrapper tool).

Example using PA :

  - Define protocol and generate PA wrapper APIs. Refer to Topic 126275 for PA wrapper.
  - Create a class derived from "RegisterControlPort".
  - The implementation of constructor.
  - The implementation of preStart()
  - The implementation of the "register access function". The implementation of the register access function finally will invoke those access function defined in the PA wrapper API.
  - 2nd Level Protocol Wrapper

- Register write and read
- Adding a flat pattern to a multi-port burst
- Adding a sequencer DC test to a multi-port burst
- Adding a dynamic DC test to a multi-port burst
- Adding digital capture test to a multiport burst
- Synchronization between any normal ports, PA ports
- Integration to CCF, create burst across test suites

## The wrapper (first level by PA tool and second level wrapper by CTF wrapper tool)

### Creating a class derived from "RegisterControlPort"

The following example illustrates how to create a class derived from RegisterControlPort:

```
#ifndef TMLEXT_PROTOCOL_REGISTERCONTROLPORT_H_
#define TMLEXT_PROTOCOL_REGISTERCONTROLPORT_H_

#include "common/Global.hpp"
#include "protocol/SynchronizedPort.hpp"
#include "protocol/ResultProxy.hpp"
#include "protocol/ResultVector.hpp"

#define TMLEXT_DECLEARE_PA_INSTANCE(PA) \
public:\
  static PA & getInstance(const STRING& _name);\
  static void releaseInstance(const STRING& _name);\
private:\
  static PA * mpInstance;\
  static map<STRING, PA *> mPAPtrMap;

#define TMLEXT_DEFINE_PA_INSTANCE(PA) \
PA * PA::mpInstance = NULL;\
map<STRING, PA *>  PA::mPAPtrMap;\
\
PA & PA::getInstance(const STRING& _name)\
{\
    map<STRING, PA *>::iterator it = mPAPtrMap.find(_name);\
    if (it !=  mPAPtrMap.end())\
    {\
      return *mPAPtrMap[_name];\
    }\
    else\
    {\
      mPAPtrMap[_name] = new PA();\
      return *mPAPtrMap[_name];\
    }\
}\
\
void PA::releaseInstance(const STRING& _name)\
{\
    map<STRING, PA *>::iterator it = mPAPtrMap.find(_name);\
    delete mPAPtrMap[_name];\
    mPAPtrMap.erase(it);\
}

namespace tmlext
{
  const UINT64 SIZE_RESULTPROXY = 1024;

  class RegisterControlPort : public SynchronizedPort
  {
  public:
    enum REGISTER_CONTROL_INTERFACE { REG_CTRL_UNKNOWN=0, REG_CTRL_PA=1 }; //RegisterControlPort support PA only now

    RegisterControlPort();
    virtual ~RegisterControlPort(){};

    void setInterface(REGISTER_CONTROL_INTERFACE _interfaceSel) {mInterfaceSel = _interfaceSel;}
    void setWaveTable(const STRING& _waveTable) {mWaveTable = _waveTable;};

    bool hasFailed();
    bool hasPattern();

    void resetResults() {mResults.clear();};

  protected:
    virtual void createProtocolImpInstance() = 0;

    virtual void addAccumWaitTimeToBurst() = 0;

    virtual void configureResources(){};
    virtual void preExecute();
    virtual bool flush(const STRING& _d2sBurstName = "");
    virtual void postExecute(INT _executePattern = 1){};
    virtual void cleanup(){};
    virtual void cleanup(const STRING& _executedId = "", INT _executePattern = 1, INT _keepLink = 0);

    virtual void registerProtocol();

    virtual PatternControlType getPatternControlType();
    virtual SYNCHRONIZED_TEST* getPAImpPtr() {return NULL;}
    virtual PROTOCOL_TEST_RESULT_VECTOR getPAImpResults() {CODE_TRACE_THROW_ERROR("getPAImpResults() not supported for " + getName());PROTOCOL_TEST_RESULT_VECTOR obj;return obj;}

    virtual vector<UINT64> getResults();
    virtual vector<STRING> getResultsString();

    /* Common functions for Register Access
     * Child classes need to implement them.
     */
    virtual void write(UINT64 _regAddr, UINT64 _data);

    virtual void read(UINT64 _regAddr);
    virtual void readExpect(UINT64 _regAddr, UINT64 _expectedData);

  private:
    void evaluateReads(INT _executePattern = 1);

    /* Convenience wrapper functions to take STRING arguments
     * Conversion to UINT64 done here. Child classes do NOT need to implement them.
     */
    void write(const STRING& _regAddr, const STRING& _data);
    void read(const STRING& _regAddr);
    void readExpect(const STRING& _regAddr, const STRING& _expectedData);

    static void replaceHexBits(UINT64& _inData, UINT64 _newData, UINT _startBit, UINT64 _len);
    static void replaceHexBitsStr(STRING& _inStr, UINT64 _newData, UINT _startBit, UINT64 _len);

  protected:
    REGISTER_CONTROL_INTERFACE mInterfaceSel;

    STRING  mWaveTable;

    PROTOCOL_TEST_RESULT_VECTOR  mResults;
    UINT64                       mCompRead;

  private:

    friend class MultiportSync;
  };

} // namespace tmlext
#endif

```

### Register write and read

User can use a class which is inherited from "RegisterControlPort" class to make normal register write and read operation; Here user doesn’t need to care if PA is used.

```

CCTMultiportSync Sync;

Sync.registerSyncPort(Lshift::getInstance(tsName));

Lshift::getINstance(tsName).write(0x18, 0x22);
Lshift::getINstance(tsName).write(0x18, 0x86);
Lshift::getINstance(tsName).read(0x18, "readID1");
Lshift::getINstance(tsName).readExpect(0x18, 0xFE);
Lshift::getINstance(tsName).getReadValue("readID1") //get the read value marked as "readID1"

FOR_EACH_SITE_BEGIN();

FOR_EACH_SITE_END();

```

### Adding a flat pattern to a multi-port burst

The following code describes the implementation of adding a flat pattern to a multi-port burst:

```

CCTMultiportSync Sync;

PatternPort::getInstance().setPort(Port);
PatternPort::getInstance().setWaitTemplatePatternName(WaitTemplate);
Sync.registerSyncPort(PatternPort::getInstance());

Sync.start();
PatternPort::getInstance().playPattern(FlatPatt);
Sync.sync();
Sync.flush();

```

### Adding a sequencer DC test to a multi-port burst

The following code describes the implementation of adding a sequencer DC test to a multi-port burst:

```

CCTMultiportSync Sync;

DCDynamicPort::getInstance().setPort("pPPMUDC");
Sync.registerSyncPort(DCDynamicPort::getInstance());

DCDynamicPort::getInstance().PPMU_Relay("DC_Pin1", "PPMU_ON", 20 ns);
DCDynamicPort::getInstance().PPMU_Setting_VForce("DC_Pin1", vin V, 10 mA, -12 uA, 12 mA, 10 ns);
DCDynamicPort::getInstance().PPMU_Relay(MeasPin, "PPMU_ON", 20 us);
DCDynamicPort::getInstance().PPMU_Setting_IForce(MeasPin, "CLAMP_ON", 0 uA, 100 uA, -1 uA, 1 uA, 0.002 ms);
DCDynamicPort::getInstance().PPMU_VClamp(MeasPin, "CLAMP_ON", 0, 4 V, 0.1 us);
DCDynamicPort::getInstance().PPMU_Meas(MeasPin, "VMUM", "PVAL", 2, 10 ns);
```

### Adding a digital capture test to a multi-port burst

The following code describes the implementation of adding a digital capture test to a multi-port burst:

```

CCTMultiportSync Sync;

// Setting digital capture port
DigitalCapturePort::getInstance().setPort("DigCap_Port");
DigitalCapturePort::getInstance().setIdentifer(tsName);
Sync.registerSyncPort(DigitalCapturePort::getInstance());

// Setting normal pattern port
PatternPort::getInstance().setPort("ADC_Control");
DigitalCapturePort::getInstance().setWaitTemplatePatternName("ADC_Control_waitTemplate");
Sync.registerSyncPort(PatternPort::getInstance());

Sync.start();
PatternPort::getInstance().playPattern("ADC_Control");
Sync.sync();

vectorVariable adcCap_lin(capture_variable);

DigitalCapturePort::getInstance().setDefaultPattern("D", 8);

// For serial data capture
adcCap_lin.pin("ADC_D0")
     .mode("SER");
     .initSkipBits(0)
     .sampleLengthInBits(capSampleNum)
     .sampleCount(1)
     .skipBits(0)
     .interSampleSkipBits(0)
     .bitPerWord(1);
DigitalCapturePort::getInstnce().capture(adcCap_lin), "ADC_D0", capSampleNum);

Sync.sync();
Sync.flush();
```

The following code describes the implementation of synchronization between any normal ports and PA ports:

```

CCTMultiportSync Sync;

// Set up normal port1
. . .

// Set up normal port2 (or PA port)
. . .

// To synchronize the 2 ports

```

### Integration to CCF, create burst across test suites

There is no difference in the CCTMultiportSync APIs used for serial or concurrent mode. The CTF will handle the cross test suites multiport burst.
