# Match Loops in the Data Port

In a continuous clock setup, the clock port and the data port are in different sequencing groups. So you can have a match loop in the data port pattern and no match loop on the clock pin, where match loops do not make sense.

However, if you use a single-port vector setup, the sequencer program is the same for both ports. So you also have a match loop on the clock pin if you want to execute a match loop on the data port.

Since the clock port does not include any output pins the match loop on the clock port will always match after the first loop and continue with the next parallel vector.

The match loop on the data port is executed in the same way as in a conventional single-port setup.

Note that this behavior requires that the clock port and the data port are in different sequencing groups. But this is the case in any continuous clock setup.

- All ports of a sequencing groups have to execute the same number of match loops. After a certain port has finished a match loop it waits until the other ports of its sequencing group have finished their match loop. When a port has finished its match loop and waits for the other ports to finish their match loops it receives break vectors.

Assume that ports of a sequencing group do not have the same number of match loops. For example, one port goes through one match loop, and the other ports do not have any match loop. The following would happen:

  - The port with the match loop would finish its match loop. Then it would go into break state and wait for the other ports to finish their match loop.
  - Since these ports do not have any match loops these ports would finish their user vectors and wait for the port with the match loop to finish its user vectors resulting in a SmarTest Work Center condition.

- Match loops of different ports in a sequencing group are executed asynchronously.
- There is no restriction with respect to match loops in ports of different sequencing groups. If there are match loops in one port and no match loops in other ports, they can be de-coupled by having their own and different sequencing groups. Ports in different sequencing groups do not wait for each other to finish their match loops. Note In general, CTOF commands in a multi-port setting have an insignificant effect on the test time. However, if one (or more) of the ports is slower than the others, the effect becomes quite significant.
