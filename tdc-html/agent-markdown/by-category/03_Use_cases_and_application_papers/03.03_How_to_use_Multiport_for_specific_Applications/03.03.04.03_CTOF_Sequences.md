# CTOF Sequences

#### Subtopics

- [Reload of Primary Sets](<03.03.04.03.01_Reload_of_Primary_Sets.md>)
- [Preventing Reload of Primary Sets for Clock Port](<03.03.04.03.02_Preventing_Reload_of_Primary_Sets_for_Clock_Port.md>)

When the timing or the levels have to be re-programmed, the driver is set to a static level for the time needed for reprogramming. During this time it does not send any user or break vectors to the device.

The following figures show the signals of two pins, a clock pin and a data pin in different setups.

[Reload of Primary Sets](<03.03.04.03.01_Reload_of_Primary_Sets.md>) shows the situation when the primary sets for both the clock and data pins are re-loaded.

[Preventing Reload of Primary Sets for Clock Port](<03.03.04.03.02_Preventing_Reload_of_Primary_Sets_for_Clock_Port.md>) shows the situation where the clock and data pins are in separate ports and the primary set for the data pins only are reloaded.

 Note In general, CTOF commands in a multi-port setting have an insignificant effect on the test time. However, if one (or more) of the ports is slower than the others, the effect becomes quite significant.
