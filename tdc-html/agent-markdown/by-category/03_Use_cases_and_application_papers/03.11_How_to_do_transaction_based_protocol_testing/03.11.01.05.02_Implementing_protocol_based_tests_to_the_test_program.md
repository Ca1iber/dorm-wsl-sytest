# Implementing protocol based tests to the test program

#### Subtopics

- [Example: Writing a protocol based UTM without using protocol wrapper](<03.11.01.05.02.01_Example__Writing_a_protocol_based_UTM_without_using_protocol_wrapper.md>)

This sections lists the requirements and steps necessary to implement protocol based tests to your test program.

The description is kept general by purpose as the corresponding [example](<03.11.01.05.02.01_Example__Writing_a_protocol_based_UTM_without_using_protocol_wrapper.md>) will be more detailed.

## Preparation

- Define device pins, that are not used with the protocol, in an individual or multiple ports.
- Create a vector sequence that will run on the non-protocol ports while the protocol's multiport bust is executed.
- Create a multiport burst pattern that includes the non-protocol port(s) and corresponding vectors sequence only.
- Use a UTM project, if not already done, create one following the description of [How to create a universal test method project](<../../02_System_reference/02.07_Test_Method_Reference/02.07.02.02.01_How_to_create_a_universal_test_method_project.md>).

## Adding a protocol based test to a testflow

- Create a UTM class as described in [How to create a universal test method class](<../../02_System_reference/02.07_Test_Method_Reference/02.07.02.02.02_How_to_create_a_universal_test_method_class.md>).
- Enter your protocol based test code.

  - Create one protocol based test object per protocol, passing the required parameter to the object: (protocol's) port name
  - Add optional parameter if required: multiport burst pattern of the non protocol ports, wavetable and a custom protocol's pattern label.

`SYNCHRONIZED_TEST <ProtocoltestObject>(<"protocol'sPort">, <"non-protocol multiport burst pattern">, <"wavetable">, <"ProtocolPatternLabel");`

  - Add a transaction to the object with the parameter values defined in the protocol definition.

`ProtocoltestObject.transaction(<"TransactionName">).set(<"parameter1">, <"Parameter1Value">).set(<"parameter2">, <"Parameter2Value">).set(<"parameter3">, <"Parameter3Value">);`

  - Complete protocol based test definition by using the .flush() function of your object.

`ProtocoltestObject.flush()`

  - Perform a functional test to start the digital seqencer.
  - Unlink the generated protocol bust label from the non-protocol multiport bust, to make it available to other transactions.

`SYNCHRONIZED_TEST::unlink("ProtocolPatternLabel", "non-protocol multiport bust pattern");`

- Build your project and debug it if necessary as outlined in [How to create a universal test method class](<../../02_System_reference/02.07_Test_Method_Reference/02.07.02.02.02_How_to_create_a_universal_test_method_class.md>).
- Add your protocol based test method to a test suite as described in [How to create and execute a universal-test-method-based testflow](<../../02_System_reference/02.07_Test_Method_Reference/02.07.02.02.03_How_to_create_and_execute_a_universal-test-method-based_testflow.md>).
