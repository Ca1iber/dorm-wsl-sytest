# Implementing protocol wrappers to the test program

#### Subtopics

- [Example: Writing a protocol based UTM using protocol wrapper](<03.11.01.05.03.01_Example__Writing_a_protocol_based_UTM_using_protocol_wrapper.md>)

Using protocol wrappers will simplify programming by making the code shorter and thus more readable.

[Generating protocol wrappers](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.22.10.11_Generating_protocol_wrappers.md>) describes how to generate custom protocol based test classes as well as result proxy and vector classes.

While the result proxy and vector classes Do not have to be regenerated upon any modification of the protocol definition the custom wrapper class has to.

It can be a good practice to make the protocol wrapper classes available across multiple projects, which aids maintaining the classes. However, this is not part of this topic.

The description is kept general by purpose as the corresponding [example](<03.11.01.05.03.01_Example__Writing_a_protocol_based_UTM_using_protocol_wrapper.md>) will be more detailed.

## Preparation

- Decide how to implement the wrapper classes, either as local copy in your UTM project, or as shared UTM project.
- Preparation with regards to device setup, etc. is identical to [Implementing protocol based tests to the test program](<03.11.01.05.02_Implementing_protocol_based_tests_to_the_test_program.md>).
- Create your custom protocol wrapper classes following the procedure [Generating protocol wrappers](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.22.10.11_Generating_protocol_wrappers.md>).

## Implementing custom wrapper APIs

Note The following only points out the differences to [Implementing protocol based tests to the test program](<03.11.01.05.02_Implementing_protocol_based_tests_to_the_test_program.md>).

- Create a UTM class and include your wrapper class by adding the line `#include <"CustomWrapperClass.hpp">` .
- Reuse your wrapper-less protocol based test code. Replace the system API `SYNCHRONIZED_TEST()` with your wrapper API `<CustomWrapperClass>_SYNC_TEST()` to create a protocol test object. The parameters passed to the object can be left unchanged:

`CustomWrapperClass_SYNC_TEST <ProtocoltestObject>(<"protocol'sPort">, <"non-protocol multiport burst pattern">, <"wavetable">, <"ProtocolPatternLabel");`

- Add a transaction to the protocol based test object passing the parameter values in the same order as defined in the corresponding protocol definition.

`ProtocoltestObject.write(<"Parameter1Value">, <"Parameter2Value">, Parameter3Value">);`

- Replace the `.flush()` and `FUNCTIONAL_TEST()` calls with the now available `.run()` function of your wrapper class: `ProtocoltestObject.run();`
- Replace the system's `SYNCHRONIZED_TEST::unlink()` call with the now available `.unlink()` function of your wrapper class: `ProtocoltestObject.run();`

## Result proxy and vector classes

Result proxy and vector classes are usually being generated together with the custom wrapper classes.
