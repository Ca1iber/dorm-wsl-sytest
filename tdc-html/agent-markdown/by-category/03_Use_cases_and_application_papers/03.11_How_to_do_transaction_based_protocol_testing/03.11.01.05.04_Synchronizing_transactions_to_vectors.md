# Synchronizing transactions to vectors

#### Subtopics

- [Adding synchronization markers](<03.11.01.05.04.01_Adding_synchronization_markers.md>)
- [Removing synchronization markers](<03.11.01.05.04.02_Removing_synchronization_markers.md>)
- [Example: Using sync markers within test methods](<03.11.01.05.04.03_Example__Using_sync_markers_within_test_methods.md>)

A synchronization marker ('sync marker') allows to control the execution of protocol transactions from the patterns running on non-protocol ports.

Once a vector -marked by a sync marker- is reached during test execution, the transactions at the protocol port are launched.

A sync marker is attached to a vector and a pin of a non-protocol port. Green arrows and green triangles show where sync markers are located in the pattern.

The same synchronization point can be used as a reference from different synchronized protocol tests. This way two synchronized protocol tests can be executed synchronous to each other.

Protocol tests without any synchronization point automatically will be synchronized to the first vector and run in the default timing synchronization group.

There is no similar mechanism the other way around, this means, there is no way to start execution of vectors after a 'marked' transaction is reached.

Executing a burst at a non-protocol port the marker might occur more than once.In this case synchronization will be done to the first occurrence of the marker at the non-protocol port.
