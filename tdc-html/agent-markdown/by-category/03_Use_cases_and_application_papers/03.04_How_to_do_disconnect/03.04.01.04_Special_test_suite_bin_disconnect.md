# Special test suite bin_disconnect

#### Subtopics

- [Implementing bin_disconnect to overcome the pass or fail site dependency issue](<03.04.01.04.01_Implementing_bin_disconnect_to_overcome_the_pass_or_fail_site_dependency.md>)

This section explains how to use the special test suite bin_disconnect to do a flexible disconnect after binning.

Using bin_disconnect is a solution for avoiding [the pass or fail site dependency](<03.04.02.01_Description_and_analysis_of_the_pass_or_fail_site_dependency.md>) and to deal with the different disconnects of the utility lines within a test flow.

The new recommended solution is the [Multibin SmartDisconnect test suite](<03.04.01.05_Multibin_SmartDisconnect_test_suite.md>).

## Use model

The test suite bin_disconnect (contained in [Special test suites](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.32.01.02.01.02_Special_test_suites.md>)) is executed when a device falls into a pass or fail bin.

This special test suite can only be used in combination with a test method that defines a [conditional disconnect sequence](<03.04.01.03.02_Implementing_a_conditional_final_disconnect_with_disconnect.user_def.md>). In a multi-site testing setup, the sites which are binned out will be activated before calling the test method assigned to the bin_disconnect test suite.

This means:

- After one device enters into the pass or fail bin, the standard or user-defined disconnect sequence is omitted, and the enabled site number is reduced by 1, then the bin_disconnect test suite is executed. For the last site to be binned, the total enabled site number is 0 before doing the final disconnect.
- If the bin_disconnect is not used, while binning SmarTest initially executes the standard or user-defined disconnect sequence, and then reduces the enabled site number. For the last site to be binned, the total enabled site number is 1 before doing a disconnect.

Hence, for carrying out a conditional disconnect with the bin_disconnect, you need the following assessment in your test method:

- If the current number of enabled sites is larger than 0, it means some sites are still connected. Their pins including potential shared (digital) pins should not be disconnected after binning.
- If the current number of enabled sites is equal to 0, then after the binning action, all the left connected pins should be disconnected including shared (digital) pins.
- An alternate solution is provided by the test method API [GET_DISCONNECT_CONTEXT()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.84_GET_DISCONNECT_CONTEXT.md>) which returns the run context of the bin_disconnect test suite.

The bin_disconnect feature allows you to accomplish the task of conditional final disconnect in an easier way than was available till now (no need to insert a test suite before every stop bin as explained in [Implementing a conditional final disconnect with disconnect.user_def](<03.04.01.03.02_Implementing_a_conditional_final_disconnect_with_disconnect.user_def.md>)).

Note If you use SmartCalc, refer to [Terminate SmartCalc threads after binning](<../../02_System_reference/02.07_Test_Method_Reference/02.07.10.04.12_Terminate_SmartCalc_threads_after_binning.md>).
