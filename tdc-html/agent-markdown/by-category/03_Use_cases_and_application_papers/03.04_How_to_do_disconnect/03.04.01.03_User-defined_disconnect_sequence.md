# User-defined disconnect sequence

#### Subtopics

- [Effects of user-defined disconnect sequence](<03.04.01.03.01_Effects_of_user-defined_disconnect_sequence.md>)
- [Implementing a conditional final disconnect with disconnect.user_def](<03.04.01.03.02_Implementing_a_conditional_final_disconnect_with_disconnect.user_def.md>)

The behavior of the [Standard disconnect sequence](<03.04.01.02_Standard_disconnect_sequence.md>) can be changed by providing a user-defined disconnect sequence.

For test situations where you want to define a particular disconnect sequence (see examples below), it can be done by creating a command file. This optional user-defined disconnect command file must be named disconnect.user_def, and placed in the folder testfunc of your device directory.

Use a user-defined disconnect sequence in the following cases:

- If there are shared power pins across multi-sites and you want to disconnect the site related power pins separately.
- If test suites within a test flow are not [self-contained](<../03.02_How_to_do_Multi-Site_Testing/03.02.02.06.05_Self-contained_Testsuites.md>), and some test suites require a continuously running clock or require the current state of a device control pin to be maintained.
 Note On startup SmarTest always performs a standard disconnect.Note Use only firmware commands that make use of the site focus. That means you have to set the site focus before you can execute the command. For a list of all possible firmware commands, see [Site dependent firmware commands](<../../02_System_reference/02.06_Command_Reference/02.06.01.05_Site_dependent_firmware_commands.md>).

## Examples

### Example 1

This is one example of how to use a user-defined disconnect sequence for switching power pins in a pin list:

```
[DLSO](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.77_DLSO__Driver_Level_Switch_Off.md>) (@NONSHARED@)
[CHRS](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.23_CHRS__CHRS__-__CHeck_Routing_Set_globally.md>) OFF
[FLSH](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.124_FLSH_-__FLuSH_buffered_commands.md>) MUX
[WSDN](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.341_WSDN_-__Wait_Setup_DoNe.md>)
[SQST](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.241_SQST__SQST__-__SeQuencer_STate.md>) OFF
[CNCT](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.29_CNCT_-_CoNneCT_disCoNneCT.md>) OFF,(@NONSHARED@)
[BCMD](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.07_BCMD__BCMD__-_Binding_CoMmanD.md>) "",ACTION,"Update",
[PSST](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.198_PSST__PSST__-__Power_Supply_STatus.md>) OFF,(pinlist for DPS2)
[PSST](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.198_PSST__PSST__-__Power_Supply_STatus.md>) OFF,(pinlist for DPS1)
[RLYC](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.206_RLYC__RLYC__-__ReLaY_Control.md>) IDLE,OFF,(@NONSHARED@)

```

### Example 2

This is the recommended user-defined disconnect sequence to avoid [the pass or fail site dependency behavior](<03.04.02.01_Description_and_analysis_of_the_pass_or_fail_site_dependency.md>) and keep the clock running:

```
[DLSO](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.77_DLSO__Driver_Level_Switch_Off.md>) (@NONSHARED@)
[RLYC](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.206_RLYC__RLYC__-__ReLaY_Control.md>) IDLE,OFF,(@NONSHARED@)
[CHRS](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.23_CHRS__CHRS__-__CHeck_Routing_Set_globally.md>) OFF
[FLSH](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.124_FLSH_-__FLuSH_buffered_commands.md>) MUX
[WSDN](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.341_WSDN_-__Wait_Setup_DoNe.md>)
[CNCT](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.29_CNCT_-_CoNneCT_disCoNneCT.md>) OFF,(@NONSHARED@)
[BCMD](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.07_BCMD__BCMD__-_Binding_CoMmanD.md>) "",ACTION,"Update",
[PSST](<../../02_System_reference/02.06_Command_Reference/02.06.02.02.198_PSST__PSST__-__Power_Supply_STatus.md>) OFF

```

Compared with the standard disconnect sequence, the above user-defined sequence has the following three major differences:

- Removal of "SQST OFF" from the standard disconnect sequence, so that the clock keeps running.
- Usage of "@NONSHARED@" pin group in the disconnect sequence, so that Smartest will disconnect site related pins correctly.
- Moving the "RLYC" command up to the second position after "DLSO", so that potential hot switching is avoided.
Note When the above user-defined disconnect sequence is used, SmarTest cannot automatically distinguish between shared and non-shared pins, but applies the same sequence throughout the entire test flow. This leaves [shared pins connected](<03.04.01.03.01_Effects_of_user-defined_disconnect_sequence.md>) which may impact on the DUT under certain circumstances.
