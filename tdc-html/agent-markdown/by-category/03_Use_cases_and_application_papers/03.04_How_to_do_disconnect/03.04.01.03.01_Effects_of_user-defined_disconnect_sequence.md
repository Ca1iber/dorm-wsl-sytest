# Effects of user-defined disconnect sequence

Replacing the standard disconnect sequence with a user-defined disconnect sequence needs systematic knowledge to avoid damage to your device or to the test system.

A user-defined disconnect sequence can be used to avoid [the pass or fail site dependency](<03.04.02.01_Description_and_analysis_of_the_pass_or_fail_site_dependency.md>).

 Note On startup SmarTest always performs a standard disconnect. Note Use only firmware commands that make use of the site focus. That means you have to set the site focus before you can execute the command. For a list of all possible firmware commands, see [Site dependent firmware commands](<../../02_System_reference/02.06_Command_Reference/02.06.01.05_Site_dependent_firmware_commands.md>).

According to the second example file shown in the section [User-defined disconnect sequence](<03.04.01.03_User-defined_disconnect_sequence.md>) (which effects the removal of SQST OFF and the other two steps), you can replace the standard disconnect sequence in disconnect.user_def with your user-defined disconnect sequence.

With the MCDLog (introduced in [Using the Trace Function](<../../02_System_reference/02.06_Command_Reference/02.06.01.03.05_Using_the_Trace_Function.md>)), you can observe the software behavior.

## Example

In a 2-site test flow, site 1 fails and site 2 passes. In the picture, site 1 is in focus.

The MCDLog file for disconnecting each site after binning is shown:

 ![Effects_UserDefined](<../../../../raw/116206.png>)

Effects of using the above user-defined disconnect sequence are:

- Shared pins among multi-site remain connected after test flow execution.
- Sequencers are not switched off for the purpose of keeping the clock alive.
- SmarTest will issue an error message at the next test flow execution due to running sequencers. This can be solved by executing conditional "final" disconnect, which means executing an additional "final" disconnect of all pins including "SQST OFF" via a [FW_TASK](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.77_FW_TASK.md>) API at every stop bin when binning of the very last site happens.
Note Making use of user-defined disconnect sequence to solve the site pass or fail dependency issue works only with SmarTest 6.1.5.1, 6.3.5, 6.5.2 and above, where the fixes for the DLSO command are included.
