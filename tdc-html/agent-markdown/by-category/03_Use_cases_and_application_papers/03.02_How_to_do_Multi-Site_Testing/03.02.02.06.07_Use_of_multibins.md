# Use of multibins

#### Subtopics

- [Use of TESTSET with multibin](<03.02.02.06.07.01_Use_of_TESTSET_with_multibin.md>)
- [Use of SMC_TEST() with multibin](<03.02.02.06.07.02_Use_of_SMC_TEST___with_multibin.md>)
- [Use of TESTSET and SMC_TEST() test suites with multibin](<03.02.02.06.07.03_Use_of_TESTSET_and_SMC_TEST___test_suites_with_multibin.md>)

Using the multibin you can create different hardware and software bins in a test suite, where each hardware and software bin pair is related to a [TESTSET](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.244_TESTSET.md>) object.

Use the multibin feature in the testflow to allow multiple or flexible bin and test number assignments. For more information on the usage of all kinds of bins, see [Use of bins with multisite tests](<03.02.02.06.08_Use_of_bins_with_multisite_tests.md>).

 Note Multibin is mandatory for all test suites in a CCF block so that the correct bins can be set for any of the failing tests, see [Special test suites](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.32.01.02.01.02_Special_test_suites.md>).

## Internal multibin variable

SmarTest differentiates between two multibin related processes:

- Setting an internal multibin variable.

SmarTest uses the internal multibin variable inside of test suites and for test suites without a bin or multibin. This variable can be overwritten according to the binning rules (see below).

- Logging its value to the multibin.

At a multibin node, SmarTest logs the internal multibin variable to the multibin.

Note

If a multibin was logged at a multibin node, it cannot be overwritten anymore, even not in another multibin node in the same testflow:

The first multibin node after a failing test suite logs the multibin value to the multibin. Failing tests of following test suites with multibin nodes will not log to the multibin, with one exception: You call [RESET_MULTIBIN](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.188_RESET_MULTIBIN.md>) after a multibin node and before a test suite followed by another multibin node.

## Overon testflow flag combined with multibins

The [Overon testflow flag](<../../02_System_reference/02.10_Data_Logging/02.10.03.03.05_Overon_flag.md>) allows you continuing the testflow after the stop bin. For information on how to use the flag, refer to [Using the Overon feature while running a testflow](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.32.02.03.02_Using_the_Overon_feature_while_running_a_testflow.md>).

 The following items should be noted when combining the Overon flag with Multibins:

- The [global_overon](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_global_overon>) must be set to on.
- [TMLimits](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.250_TMLimits.md>) allows you defining the [Bin_overon](<../../02_System_reference/02.10_Data_Logging/02.10.01.08.01.01.03.01_Structure_of_a_TMLimits_CSV_file.md#_112490__li_Bin_overon>) per SW bin.
- The test flow for a failing site will continue after binning if

  - the global_overon flag has been set to true and
  - all of the failing tests within the test suite have the Bin_overon flag set to yes.

- The test flow for a failing site will be stopped after special test suite [bin_disconnect](<../03.04_How_to_do_disconnect/03.04.01.04_Special_test_suite_bin_disconnect.md>) has been executed for the site if

  - the global_overon flag has been set to false or
  - any of the failing tests within the test suite have the Bin_overon flag set to no.

## Binning rules

- SmarTest logs the multibin per site, and writes it to the data log as BinReachedEvent (see [Overon flag](<../../02_System_reference/02.10_Data_Logging/02.10.03.03.05_Overon_flag.md>), [Software Bin Record (SBR)](<../../02_System_reference/02.10_Data_Logging/02.10.03.05.10_Software_Bin_Record__SBR.md>)).
- set_fail and set_pass flags do not influence the binning, with one exception for the set_pass flag: If the [multibin_mode](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.32.01.02.07.01_Alphabetical_list_of_flags.md#_342556__row_multibin_mode>) flag is set to suppress_on_set_pass, SmarTest does not set the internal multibin variable.
- Multiple calling the same non-temporary [TESTSET](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.244_TESTSET.md>) object, which can be the system-prepared class object `TestSet` or the same user object `TESTSET` <object name>:

If the same object is multiple called, the first call of the same object with a failing test sets the internal multibin variable. Failing tests of the same object at a later point of time do not change the internal multibin variable.

- If the temporary [TESTSET()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.244_TESTSET.md>) object is multiple called, the last called object with a failing test determines the internal multibin variable, and overwrites the internal multibin variable, which was set by a prior object with a failing test.

The same rule applies, if the [SET_MULTIBIN](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.212_SET_MULTIBIN.md>) API is multiple called: The last called [SET_MULTIBIN](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.212_SET_MULTIBIN.md>) object determines the bin, and overwrites the variable, which was set by prior [SET_MULTIBIN](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.212_SET_MULTIBIN.md>) objects with failing tests.

- Calling different [TESTSET](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.244_TESTSET.md>) objects, which can be the system-prepared class object TestSet, different user object `TESTSET` <object name> or a temporary object TESTSET():

If different objects are called, the last called object with a failing test determines the internal multibin variable, and overwrites the internal multibin variable, which was set by prior objects with failing tests.

For more details and examples, see [Use of TESTSET with multibin](<03.02.02.06.07.01_Use_of_TESTSET_with_multibin.md>).

- The binning information of all [SMC_TEST()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.45_SMC_TEST.md>) calls are validated in the [SMC_SYNCHRONIZE()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) test suite. Inside of the [SMC_SYNCHRONIZE()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) test suite all [SMC_TEST()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.45_SMC_TEST.md>) calls are validated like calling the same non-temporary TESTSET object in the same test suite: The first failing [SMC_TEST()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.45_SMC_TEST.md>) test suite sets the internal multibin variable for the [SMC_SYNCHRONIZE()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) test suite.

For more details and examples, see [Use of SMC_TEST() with multibin](<03.02.02.06.07.02_Use_of_SMC_TEST___with_multibin.md>).

Note

If you use TESTSET within the [SMC framework](<../../02_System_reference/02.07_Test_Method_Reference/02.07.10_SmartCalc_framework.md>) instead of [SMC_TEST](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.45_SMC_TEST.md>), binning happens in [SMC_SYCHRONIZE](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.43_SMC_SYNCHRONIZE.md>) according to the binning rules as for SMC_TEST. For details, see [Use of SMC_TEST() with multibin](<03.02.02.06.07.02_Use_of_SMC_TEST___with_multibin.md>).

If you use, within a testflow, the [SMC framework](<../../02_System_reference/02.07_Test_Method_Reference/02.07.10_SmartCalc_framework.md>) and TESTSET test suites independent of each other, binning happens according to the binning rules explained in [Use of TESTSET and SMC_TEST() test suites with multibin](<03.02.02.06.07.03_Use_of_TESTSET_and_SMC_TEST___test_suites_with_multibin.md>).

- Using test suites with and test suites without [SMC_TEST()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.45_SMC_TEST.md>):

If a test fails in a non-SMC test suite, which is called before [SMC_SYNCHRONIZE()](<../../02_System_reference/02.07_Test_Method_Reference/02.07.04.01.231.43_SMC_SYNCHRONIZE.md>), the failing non-SMC test suite determines the multibin value.

For more details and examples, see [Use of TESTSET and SMC_TEST() test suites with multibin](<03.02.02.06.07.03_Use_of_TESTSET_and_SMC_TEST___test_suites_with_multibin.md>).
