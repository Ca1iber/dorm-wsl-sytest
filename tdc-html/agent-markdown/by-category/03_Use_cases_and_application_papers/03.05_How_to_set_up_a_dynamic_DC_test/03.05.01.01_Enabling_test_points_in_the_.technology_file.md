# Enabling test points in the .technology file

As first step, make sure you have sufficient test points enabled in the .technology file. A test point connects a test event with a logical vector of a pattern.

## About this task

The default number of test points per pin is 0, the upper limit is 1048576. The value determines the amount of memory reserved for test points. Since the available memory is limited, set the number with care. If set to 0, the DC Scale pins (Signal) will not be shown in the [pattern editor](<../../02_System_reference/02.08_Setup_and_Result_Tools/02.08.04.16.02.03_Pattern_editor_properties_view.md>).

The overall number of usable test points for all patterns can be defined in the Change Device wizard or directly in the .technology file (testpoints keyword). This example procedure uses the Change Device wizard:

## Procedure

-  On the Smartest icon bar click Change Device. The Change Device wizard opens and shows your current device.

To change technology parameters, click Next. The Edit Device page of the wizard appears.

  ![Expand the extra options](<../../../../raw/111079.png>)
-  In the Testpoints field type 100.
-  Click Finish.

## Results

The changed values are written to the .technology file of the selected device.

## Example

The resulting .technology file in the device directory:

```
/dev_tech/cmos
device_cycles: 256
waveform_sets: 16
timing_sets: 256
level_sets: 32
dps_sets: 32
pdc_sets: 1
m_sets: 1024
routing_sets: 256
period_res_precision: 9
testpoints: 0
utility_lines_per_pogoblock: 16
tester_model: act
licensing_file:
digital_default_result_area_size: 2048
```
