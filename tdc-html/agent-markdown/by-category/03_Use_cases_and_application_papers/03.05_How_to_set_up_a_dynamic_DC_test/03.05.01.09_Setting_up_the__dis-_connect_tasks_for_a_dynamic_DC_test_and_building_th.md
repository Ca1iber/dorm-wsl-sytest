# Setting up the (dis-)connect tasks for a dynamic DC test and building the test methods

You will use test methods also to connect and disconnect the signal pins of a dynamic DC test.

The power pins are handled by the test flow, that is, they connect and disconnect automatically. Only the connect and disconnect of the signal pins (PMU) must be programmed in a test method.

Once this is done, you can build the test method project.

The test method example code below connects and disconnects the PMU signal pins, and also ensures they are disconnected in case of an error.

```
...
class DCDynDemoTests_connect: public testmethod::TestMethod
{
protected:
//Add your class member variable here.

protected:
/**
 *Initialize the parameter interface to the testflow.
 *This method is called just once after a testsuite is created.
 *
 *Note: TestMethod API should not be used in this method.
 */
virtual void initialize()
{
  //Add your intialization code here.
}

/**
 *This test is invoked per site.
 */
virtual void run()
{
  SPMU_TASK connectTask;

  ON_FIRST_INVOCATION_BEGIN();

    // Connect the power pins
    CONNECT();

    // Connect the PMU pins
    for (INT i = 0; i < numPMUPins; ++i) {
      SPMU_PIN_TASK& pinTask(connectTask.pin(pmuPins[i]));
      pinTask.relay("NT");
      pinTask.iForce(0.01);
      pinTask.mode("VM_HIZ");
      pinTask.clamp(1500 mA);
      pinTask.min(0 V);
      pinTask.max(7 V);
      pinTask.settling(0 ms);
    }
    // Ensure the PMU is disconnected in case of an error.
    connectTask.execMode(TM::FORCE_OFF);
    connectTask.execute();

    for (INT i = 0; i < numPMUPins; ++i) {
      SPMU_PIN_TASK& pinTask(connectTask.pin(pmuPins[i]));
      pinTask.settling(250 us);
    }
    connectTask.execMode(TM::FORCE_ON);
    connectTask.execute();

  ON_FIRST_INVOCATION_END();

  return;
}

/**
 *This function will be invoked once the specified parameter's value is changed.
 *@param parameterIdentifier
 *
 *Note: TestMethod API should not be used in this method.
 */
virtual void postParameterChange(const string& parameterIdentifier)
{
  //add your code
}

};
REGISTER_TESTMETHOD("DCDynDemoTests.connect",DCDynDemoTests_connect);

/**
 *Testmethod class.
 *
 *For each testsuite using this testmethod, one object of this
 *class is created.
 */
class DCDynDemoTests_disconnect: public testmethod::TestMethod
{
protected:
//Add your class member variable here.

protected:
/**
 *Initialize the parameter interface to the testflow.
 *This method is called just once after a testsuite is created.
 *
 *Note: TestMethod API should not be used in this method.
 */
virtual void initialize()
{
  //Add your intialization code here.
}

/**
 *This test is invoked per site.
 */
virtual void run()
{
  SPMU_TASK connectTask;

  ON_FIRST_INVOCATION_BEGIN();

    // Disconnect the PMU pins.
    for (INT i = 0; i < numPMUPins; ++i) {
      SPMU_PIN_TASK & pinTask(connectTask.pin(pmuPins[i]));
      pinTask.relay("NT");
      pinTask.iForce(0);
      pinTask.mode("VM_HIZ");
      pinTask.clamp(1500 mA);
      pinTask.min(0 V);
      pinTask.max(7 V);
      pinTask.settling(0 ms);
    }
    connectTask.execMode(TM::FORCE_OFF);
    connectTask.execute();

    // Disconnect the power pins.
    DISCONNECT();

  ON_FIRST_INVOCATION_END();

  return;
}

/**
 *This function will be invoked once the specified parameter's value is changed.
 *@param parameterIdentifier
 *
 *Note: TestMethod API should not be used in this method.
 */
virtual void postParameterChange(const string& parameterIdentifier)
{
  //add your code
}

};
REGISTER_TESTMETHOD("DCDynDemoTests.disconnect",DCDynDemoTests_disconnect);
```

Once the test methods are complete, you must build the test method project.

- Open the C/C++ perspective.
- In the Project Explorer right-click the test method project and Build Project.
- Check the console view that the test methods were correctly built.

Next you can define the test suites in the testflow editor and set the previously defined test methods and primaries.
