Topic 143373

FwGuard

This class provides user control to protect running non-blocking firmware from being interrupted by other firmware commands.

In some some rare special cases there might be the need for intentionally protecting running non-blocking firmware commands from being interrupted by other firmware calls. Such cases can occur if a graphical user interface (GUI) or an API calls a firmware command during debugging. Examples for GUI and API that may cause this problem in interaction with the running test method are:

  • Pattern Editor
  • hpt utility
  • Firmware view
  • SMC_EXECUTE_TEST()

In case such calls are initiated on a running non-blocking firmware command, they may cause the sequencer to be interrupted while the DUT is still connected to the power supplies.

CAUTION The above mentioned circumstances may damage the DUT.

SmarTest displays the following messages in the Report window and System console view:

  • An ERROR: No result data available while tester is running and
  • A WARNING: Current sequencer run will be interrupted

This class provides a ways to intentionally protect running non-blocking firmware calls.

The recommended way is to use the FwGuard constructor within a function or a for-, while- or if-block right after the API call that's to be protected. This way the FwGuard object will be destructed at the end the function or for-, while- or if-block. However, one can also use it outside of that narrow scope when utilizing its member functions .acquire() and .free() explicitly.

Note A non-blocking firmware command de facto turns into a blocking firmware command as long it is protected by this class.
Note You must not declare a FwGuard object to be global or static! Because this would block the whole SmarTest system!

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Extension.h.

Constructor

class FwGuard();

Member functions

void acquire();
void free();

List of parameters

There are no parameters.

Return value

There is no return value.

Example

The following example show the implicit locking.

// some variables
int i;

// execute the following test in a loop
for (i=1; i<10; i++) {
   // The firmware call of the following API will be locked
   SMC_EXECUTE_TEST(i*0.1, &timeout_s, &mis_trg_s);

   // instantiate the guard
   // it will be automatically destructed at the end of the for-loop!
   FwGuard implGuard;

   // do something, for example calculations, that does not
   // interfere with the firmware call above
   // Note: firmware calls put in here are blocked from being executed!
   }
// here you can used code that also issues firmware commands.
....

The following example show the explicit locking.

// some variables
int i;

// execute a non-blocking firmware command
SMC_EXECUTE_TEST(0.1 sec, &timeout_s, &mis_trg_s);

// initiate the guard that protects firmware command called above
FwGuard explGuard;

// do something, for example calculations, that does not
// interfere with the firmware call above
// Note: firmware calls put in here are blocked from being executed!
....
// release the lock
explGuard.free();

// here one can used code that also issues firmware commands.
....

// execute the following test in a loop
for (i=1; i<10; i++) {

   // The firmware call of the following API will be locked
   SMC_EXECUTE_TEST(i*0.1, &timeout_s, &mis_trg_s);

   // use the explGuard for locking the firmware command called by above API
   explGuard.acquire();

   // do something, for example calculations, that does not
   // interfere with the firmware call above
   // Note: firmware calls put in here are blocked from being executed!
   }
// here you can used code that also issues firmware commands.
....
