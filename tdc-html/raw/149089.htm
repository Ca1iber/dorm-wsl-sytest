GPIB communication flow for MCT handlers

The GPIB communication flow determines how the driver controls the handler and at the same time how the handler responses and acts by following the commands.

The table below shows the communication between the driver and the handler. The actions and messages are listed in sequential order.

See Conventions for GPIB/LAN communication for the description of the syntax.

waiting for strip start | waiting for device start (optional):

 

 

wait for devices: [<SRQ>]

 

The driver waits for a service request (SRQ).

SRQ:

0x43

The handler returns the test start SRQ.

Site population

 

 

wait for devices start | wait for strip done:

Set StartTest "panel_id_string" <device id>,<device id>,<device id>, <device id>...

| Set PanelComplete

The handler sends the Set StartTest command to tell which parts are to be tested. For example, Set StartTest "123456789" A1,B1,C1,D1,E1.

If one strip has been tested, the handler sends the Set PanelComplete command to tell the driver that one strip test has been done.

wait for 30 ms:

 

 

ibclr

 

The driver uses this basic GPIB command to clear the GPIB buffer.

testing devices:

 

 

bin devices:

 

 

Set Bin "panel_id_string" CR,#,CR,#,CR,#,CR,#...

 

The driver sends the bin information.

CR presents the Column and Row of the tested devices. # presents a bin value from 1 to 99999.
