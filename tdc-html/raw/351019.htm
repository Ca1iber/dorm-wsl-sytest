Topic 351019

Relationship between bits and device cycles

In the pattern generation through the smartVec() class, SmartRDI allows the bit values 0, 1, and 2 specified by some APIs to match with 0, 1, Z or L, H, X device cycles (DVC) defined in your wavetable.

Write APIs

For the "write" type of commands, such as writeBit(), bits 0, 1, and 2 in the specified value are converted to 0, 1, and Z for corresponding with DVCs. That means SmartRDI always deals with 0, 1, and 2 for "0", "1", and "Z".

The relationship between bits and DVCs for X1 and Xn modes are different:

  • X1 mode: bit 0 to DVC "0", 1 to "1", and 2 to "Z".
  • Xn mode: bits 0101 to DVC "0101" and bits 0112 to "011Z".
In the corresponding wavetable, waveform definitions must consecutive, ranging from "00...0" to "11...1". For example, a wavetable for x8-mode:
PhyIndex   Action      DevCyc

0          "d1...d8"   00000000
1          "d1...d8"   00000001
...        ...         ...
...        ...         ...
...        ...         ...
ff         "d1...d8"   11111111
If a waveform contains "Z" or "X", like "10Z1", it can have any physical index in the wavetable.
Write-related APIs in smartVec() class
defaultBit()
fillBit()
writeBit()
writeData()
xMode()

Compare APIs

For the "compare" type of commands, such as expectBit(), bits 0, 1, and 2 are converted to L, H, and X for corresponding with DVCs. That means for "compare" APIs, SmartRDI always deals with 0, 1, and 2 for "L", "H", and "X".

The relationship between bits and DVCs for X1 and Xn modes are different:

  • X1 mode: bit 0 to DVC "L", 1 to "H", and 2 to "X".
  • Xn mode: 0101 to "LHLH" and 0112 to "LHHX".
Compare-related APIs in smartVec() class
expectBit()
expectData()
xMode()
