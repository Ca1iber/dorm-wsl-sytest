Switching model files

You can provide a choice of model files for offline operation under a variety of test system configurations for your workstation. To switch the model file you have two options. One option requires super-user access (root), the other does not. The model file is located at /etc/opt/hp93000/soc_common/.

With root access

  1. Log in as root.
  2. Open a terminal window.
  3. Change directory to /etc/opt/hp93000/soc_common/
  4. Save a copy of the original model file as model.org.

    If the original model file is a symbolic link, use the rm command to remove the symbolic link.

  5. Create several model files with different names, for example, model.sysA, model.sysB, and so on.
  6. Use the ln command to create a symbolic link to one of them with the /etc/opt/hp93000/soc_common/modelfile.

    For example:

    ln -s model.sysA /etc/opt/hp93000/soc_common/model

To use another model file in offline mode proceed as follows:

  1. Shut down SmarTest
  2. Switch the model file. That is, change the symbolic link as described above.
  3. Restart SmarTest.

No root access

If you Do not have super-user access (root), you can alternatively reset the environment variable to use another model file. To set the environment variable enter the following:

export V93000_MODEL=<modelfile_path/modelfilename>

For example:

  1. Create several model files with different names, for example, model.sysA, model.sysB
  2. Shut down SmarTest.
  3. Switch the model file, for example:

    export V93000_MODEL=/home/<user_name>/my_modelfiles/model.sysA

  4. Restart SmarTest.

You may also provide a startup script for each model file. To do so, create an executable file, for example, run_sysA, containing the following lines:

#/bin/ksh
export V93000_MODEL=<path>/model.sysA
/opt/hp93000/soc/prod_env/bin/HPSmarTest -o &
Note Do not create model files from scratch. To avoid any model file errors, reuse the original model file, the model file template, or the model files of other test systems.
Note When changing device or creating a new device in SmarTest, the software keeps its current configuration as defined in the model file that was read at start-up.
