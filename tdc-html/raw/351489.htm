Register access execution mode

Bit field operations, also called Read-Modify-Write (RMW) operations, are used to change part of a register value while other parts of the value remain unchanged. These RMW operations can be executed in two modes: learning mode and production mode.

Learning mode

In the learning mode, the following actions will be done in sequence internally in the RA library for RMW operations :
  1. Read original values from all the registers on which RMW operations are to be performed.
  2. Save the values to Register Cache.
  3. Overwrite bit fields to be modified.
  4. Write all the registers.

The read operations, which are performed on all related RMW registers, read bit field values and save the values to a file as Register Cache (RC).

All the changes of register values are tracked in sequence according to write operations on registers.

In the learning mode, two burst patterns are generated for each RDI_BEGIN/RDI_END block.
  • Normal pattern, which contains all the actions defined in the block.
  • Auxiliary burst pattern, which is generated by the RA library to read values from RMW-related registers before write operations are performed.
Each burst that has RMW operations must have a corresponding auxiliary burst generated.

Production mode

The production mode does not have the reading step.

This mode has a Check action:

  1. Check: read values from all registers and compare the values to those saved in RC. This action is optional and can be skipped.

    By default, this action is disabled. Use RA_CFG.setDefaultCheckMode(RA::CHK_VAL) or RA_SET_CHECK_MODE(RA::CHK_VAL) to enable this action.

  2. Use specified bit field values to replace the corresponding part in the whole register value which is stored in RC.

In the Check operation, the tester reads the values of RMW registers and compares them to the corresponding values saved in RC.

In this mode, a normal burst pattern is generated for each RDI_BEGIN/RDI_END block. The main patterns for Check are generated and put at the beginning of the burst pattern of an RDI_BEGIN/RDI_END block.

The mode is set by RA_CFG.setDefaultMode(RA_MODE mode) in test suite or RA_SET_MODE(RA::MODE) before an RDI_BEGIN/RDI_END block. See Example 2.

Register Cache

Register Cache is only required by RMW operations.

RC is represented by a file for each burst. The RC file is automatically generated in the learning mode and it has an .rcf extension. The values of RMW registers are saved to the file and these values can be read back by operations in the production mode. If the Check action is enabled in the production mode, RC files are used to compare with the actual registers values read back from DUT.

The RC files must exist in the production mode. Otherwise an error message is displayed.

Be default, RC files are located in the test program folder. You can use RA_CFG.setRegisterCacheFilePath("./rcf"); to specify a location for your RC files.

Examples

Example 1

Register Cache file _Test_Port_bk1.rcf

Tag:_Test_Port_bk1
  Address: 47e1
    Name: PERIPHERAL0.REGISTER0
    Value: ab
    Mask: fe
    Port:pJTAG
    Protocol: MyJATG
  Address: 2085
    Name: PERIPHERAL1.REGISTER5
    Value: ab
    Mask: 3d
    Port:pSPI
    Protocol: MySPI
...

Example 2

Setting a mode in test method
RA_SET_MODE(RA::LEARNING);

ON_FIRST_INVOCATION_BEGIN();
RDI_BEGIN();
  // Entire Register Write
  reg.PERIPHERAL0().REGISTER0().setValue(0x55).write();
  // Bit Field Write, RMW
  reg.PERIPHERAL0().REGISTER1().setField_HiClm(1).write();
...
In the first test suite of your testflow
RA_CFG.setDefaultMode(RA::LEARNING);
