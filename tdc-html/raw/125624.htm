The TMU_TASK is a container class representing a time measurement unit (TMU) set. It can be used with TASK_LIST.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TMUTask.h.

Syntax

TMU_TASK(TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
TMU_TASK(const std::string& setName,TESTMETHOD_API::TMAPICTXT_TYPE ctxt = TESTMETHOD_API::TMAPI_CURR);
TMU_TASK(const std::string& setName,const std::string& ModeContext);

Creates an object with the specified TMU set name and the specified context. If the specified set does not exist, it will be created. If the specified set is existing but the specified context is different, the specified set will be created again.

Note The created TMU_TASK objects are persistent until the next testflow run. Assigning one object to other objects is not allowed. But one object can reference other objects.
Note Do not create static objects of the class in the test method and do not create test method member variables from this class.
Parameters

I

ctxt

The context for which the TMU set will be created. It can be:

  • TESTMETHOD_API::TMAPI_DEFAULT: The default context
  • TESTMETHOD_API::TMAPI_CURR: The context of the current primary sets (default)
  • TESTMETHOD_API::TMAPI_PRM: Synonymous with TMAPI_CURR

I

setName

The string to be appended to the test suite name to compose the TMU set name. If not specified, the default set name is the test suite name. A set name is needed when more than one TMU_TASK object is defined in a test suite.

I

ModeContext

The context name for which the TMU set will be created. If not specified, the context DEFAULT is used.

Examples

Example 1: TMU raw result

This example shows some best practice code for usage of the TMU, setting a wait time before ending the TMU data acquisition, and then uploading the raw results.

The correct timeout value depends on the number of samples, the signal frequency and the parameters preScaler and interSampleDiscard, as shown in the example code below. The calculated value is passed to waitTMUfinished().

For sequencer generated signals which ends with sequencer run, you can call waitTmuFinished() by passing 1 µs as the timeout value. But you must always call it before retrieving the TMU results.

TMU::EdgeType   edge                = TMU::...;
double          threshold           = ...;
int             numSamples          = ...;
int             freqSignal          = ...;
int             preScaler           = ...;
int             interSampleDiscard  = ...;
int             initDiscard         = ...;
STRING          pinList             = "...,...";
TMU_TASK        tmuTask;

ON_FIRST_INVOCATION_BEGIN();
{
    //
    // interSampleDiscard must be an even number for RISE_FALL mode
    //
    // preScaler must be 2..16 for RISE_FALL mode
    //
    double tmuTimeout = numSamples * (1/freqSignal) * preScaler
                       * interSampleDiscard + (1/freqSignal) * initDiscard;

    tmuTimeout = tmuTimeout * 1.1; // safety margin

    cout << "TMU Timeout = " << tmuTimeout * 1e3 << "ms" << endl;

    tmuTask.pin(pinList)
            .setEdgeSelect          (edge)
            .setAThreshold          (threshold)
            .setNumSamples          (numSamples)
            .setNumShots            (1)
            .setNumMeasurements     (1)
            .setInterSampleDiscard  (interSampleDiscard)
            .setPreScaler           (preScaler)
            .setInitialDiscard      (initDiscard);

    tmuTask.setAsPrimary();
    tmuTask.setup();

    FUNCTIONAL_TEST();

    bool taskFinished = false;

    tmuTask.waitTMUfinished(tmuTimeout, taskFinished);

    cout << "TMU finished = " << taskFinished << endl;

    //
    // If you will do other measurements without TMU disable TMU
    // otherwise it will be disabled when this run method returns
    // tmuTask.disableTMU();
    //
    DISCONNECT();
}
ON_FIRST_INVOCATION_END();

//
// Upload the results into the result cache
//
tmuTask.uploadRawResults();

//
// Get the reference to the resultCache
//
TMU_RESULTS&  tmuResults = tmuTask.getResultCache().pins(pinList).shot(1);

if ( !tmuResults.checkSiteAppTypeStored(TMU::APP_RAW))
{
    cout << "ERROR!! No results uploaded for TMU RAW measurement" << endl;

    return;
}

STRING_VECTOR pinVec = PinUtility.getDigitalPinNamesFromPinList(pinList, TM::IO_PIN, TRUE, TRUE);

//
// Iterate over pins
//
int numPins = tmuResults.getNumberOfMeasuredPins(pinVec, TMU::APP_RAW);

for (int i = 0; i < numPins; i++)
{
    STRING pin = pinVec[i];

    //
    // Iterate over armings
    //
    int numarmings = tmuResults.getNumberOfMeasurements(pin, TMU::APP_RAW);

    //
    // Arming starts with 1
    //
    for (int arming = 1; arming <= numarmings; arming++)
    {
        //
        // Retrieve the samples
        //
        ARRAY_D samples;

        tmuResults.getPinMeasuredResults(pin,samples,TMU::APP_RAW,arming);

        cout << "Site[" << CURRENT_SITE_NUMBER() << "] arming [" << arming
             << "] samples " << pin << " = " << samples.size() << endl;
    }

} // for (int i = 0; i < numPins; i++)

waitTMUFinished() will return after timeout and uploadRawResults() will return the taken samples, and only these, even if they may be incomplete. Pins that are not finished, can be identified by running TMU_RESULTS.getPinsNotFinished(). If timeout is shorter than the period, uploadRawResults() will not retrieve any sample.

If you want to check if anything was uploaded from a specific pin, use TMU_RESULTS.checkSiteAppTypeStored(). If this returns True, you can use TMU_RESULTS.getNumberOfMeasuredPins() to retrieve the measured pins, and then retrieve the samples using TMU_RESULTS.getLastMeasurementId(), TMU_RESULTS.getMeasurementIDs(), and iterate over those ids using TMU_RESULTS.getPinMeasuredResults() and APIs from the list in TMU_RESULTS.

As an alternative to the above, you can use .setDataRate as shown below.
// setDatarate will calculate the optimal settings for 
// Prescaler and InterSampleDiscard
// So set it to a value of the max expected signal datarate.
// The resulting InterSampleDiscard is the min value
// and can be set to a higher value if you want measure 
// frequency with only a few samples.
// The best way to use setDatarate is to call it at last.
// And reread the stings for later postprocessing if needed. 

TMU::DATARATE_DEPENDENT_VALUES_TYPE drsettings;

tmuTask.pin(pAll)
       .setEdgeSelect(edge)
       .setAThreshold(threshold V)
       .setNumSamples(numSamples)
       .setNumShots(1)
       .setNumMeasurements(1)
       .setInitialDiscard(initDiscard);
       .setDatarate(datarate,drsettings);

Example 2: TMU frequency measurement

In this example, the variable mInterSampleDiscard and mPrescaler represent the test method parameters that serve to pass the number of events to be discarded between samples and the prescaler value to the test method. To use the following code, you need to replace the placeholders by defining the corresponding test method parameters for these variables.

TMU_TASK    task("setA");

STRING      digitalPin          = "...";
int         mInterSampleDiscard = ...;
int         mPrescaler          = ...;

ON_FIRST_INVOCATION_BEGIN();
{
    task.pin(digitalPin)
            .setEdgeSelect(TMU::RISE)
            .setInterSampleDiscard(mInterSampleDiscard)
            .setNumSamples(2).setNumMeasurements(1)
            .setPreScaler(mPrescaler);

    CONNECT() ;

    task.setAsPrimary();
    task.setup();

    FUNCTIONAL_TEST() ;
}
ON_FIRST_INVOCATION_END();

TMU_RESULTS tmuResults;

task.pin(digitalPin).uploadRawResults(tmuResults);

ARRAY_D values;

tmuResults.getPinMeasuredResults(digitalPin, values, TMU::APP_RAW);

cerr << setprecision(10);
cerr << "FREQUENCY (via raw data upload) = "
        <<((mPrescaler*(mInterSampleDiscard+1)) / (values[1]-values[0]))*1e-6 << " MHz"
        << endl;

task.pin(digitalPin).uploadPeriodResults(tmuResults);

DOUBLE period = tmuResults.getPeriodMean(digitalPin);

cerr << setprecision(10);
cerr << "FREQUENCY (via HW processing) = " << 1e-6/period << " MHz" << endl;

For frequency measurement, to improve the accuracy you can take the elapsed time divided by the number of counted cycles as the average. The elapsed time is the difference of two stamps of the same slope (rising edges or falling edges). The number of cycles is equivalent to the number of events skipped in between which can be calculated by the number of inter-discard multiplied by the value of prescaler.

In the example, two approaches are used to retrieve data, uploading raw results and uploading the calculated period results directly. Both approaches use the same methodology described above. The major difference of these two uploading schemes is the number of samples needs to be uploaded. Uploading raw results is to upload all samples stamped and then perform the calculation on the system controller. Uploading calculated results is to perform the calculation first in the test processor and then upload only the statistical values.

Example 3: TMU jitter measurement

In this example, the variable mInterSampleDiscard, mNumberOfSamples, mPreScaler, mSignalType and mTarget_UI_ns represent the test method parameters that serve to pass the number of events to be discarded between samples, the number of samples, the prescaler value, the type of signal and the target unit to the test method. To use the following code, you need to replace the placeholders by defining the corresponding test method parameters for these variables.

TMU_TASK    task("setA");

STRING      digitalPin          = "...";
STRING      mSignalType         = "CLOCK";
int         mInterSampleDiscard = ...;
int         mNumberOfSamples    = ...;
int         mPreScaler          = ...;
double      mTarget_UI_ns       = ...;

ON_FIRST_INVOCATION_BEGIN();
{
    if (mSignalType == "CLOCK")
    {
        task.pin(digitalPin).setEdgeSelect(TMU::RISE);
    }
    else
    {
        task.pin(digitalPin).setEdgeSelect(TMU::RISE_FALL);
    }

    task.pin(digitalPin)
            .setInitialDiscard(1)
            .setInterSampleDiscard(mInterSampleDiscard)
            .setNumSamples(mNumberOfSamples)
            .setNumMeasurements(1)
            .setPreScaler(mPreScaler);

    CONNECT();

    task.setAsPrimary();
    task.setup();

    FUNCTIONAL_TEST() ;
}
ON_FIRST_INVOCATION_END();

TMU_RESULTS tmuResults;

task.pin(digitalPin).uploadRawResults(tmuResults);

ARRAY_D values;

tmuResults.getPinMeasuredResults(digitalPin, values, TMU::APP_RAW);

PUT_DEBUG(digitalPin, "raw data", values);

//
// Determine DUT data rate received
//
double unitInterval = mTarget_UI_ns * 1e3;

//
// Find error of each time stamp
//
vector<double> edgeError;

for (int i = 1 ; i<values.size() ; i++)
{
    double  edgediff    = (values[i]-values[0]) * 1e12; // [ps]
    int     N           = (int)floor((edgediff + 0.5 * unitInterval)/unitInterval);
    double  error       = edgediff - N * unitInterval;

    edgeError.push_back(error);
}

PUT_DEBUG(digitalPin, "Edge Error", ARRAY_D(&edgeError[0], edgeError.size()));

//
// Jitter calculation
//
double mean, sigma;

DSP_MEAN(&(edgeError[0]), &mean, &sigma, edgeError.size());

double  min, max;
int     min_index, max_index;

DSP_MINMAX(&(edgeError[0]), &min, &max, &min_index, &max_index, edgeError.size());

cerr << setprecision(13);
cerr << " data rate  = " << unitInterval/1e3 << " ns" << endl;
cerr << " rms jitter = " << sigma << " ps" << endl;
cerr << " p-p jitter = " << max-min << " ps" << endl;
int nBins = 512;
vector<int> histogram(nBins);

DSP_HISTOGRAM(&(edgeError[0]),&(histogram[0]),edgeError.size(),min,max,nBins);

PUT_DEBUG(digitalPin, "Data Jitter Histogram", ARRAY_I(&histogram[0], histogram.size()));

Jitter measurement in the example is done by analyzing the error of every stamp being away from the ideal position. It can be expressed in the formula below: 

Sk = nk*T + ek

where

  • Sk is the time elapsed from the reference point,
  • nk is the number of cycles in between,
  • T is the period (or the unit interval),
  • and ek is the error at index k.

In this example, Sk is derived by the difference of every time stamp to the first one. nk is derived via the calculation of the closest integer of the ratio of the elapsed time to the signal period. Then the error can be calculated via the formula above for every time stamps. In the general case, ek is supposed to have a normal distribution and rms jitter and peak-to-peak jitter can be calculated accordingly. The calculation of ek is based on the assumption that it is smaller than a half period (a half unit interval).

Example 4: TMU pin result flat uploading

TMU_TASK    task;
string      pinList_1           = "...,...";
string      pinList_2           = "...,...,...";
int         numshots            = ...;
int         mNumberOfSamples    = ...;

ON_FIRST_INVOCATION_BEGIN();
{
    task.pin(pinList_1).setDatarate(10E6).setNumSamples(mNumberOfSamples);
    task.pin(pinList_2).setDatarate(20E6).setNumSamples(mNumberOfSamples);
    ...
    ...
    task.setup();
    task.setAsPrimary();

    //
    // If multiple shots are taken, loop the execution
    //
    for(int i = 0; i < numshots; i++)
    {
        task.execute();
    }

    //
    // Upload results for all pins and shots
    //
    task.uploadRawResultsFlat();
}
ON_FIRST_INVOCATION_END();

//
//  Define TMU_RESULTS objects for the two pin lists
//
TMU_RESULTS& pin_pL1_result = task.getResultCache().pins(pinList_1);
TMU_RESULTS& pin_pL2_result = task.getResultCache().pins(pinList_2);

for(int shot = 1; shot <= numshots; shot++)
{
    //
    // Generate a pin vector from result and get pin result flat
    //
    STRING_VECTOR pin_pL1_vector;

    UINT32 num_pL1_pins = pin_pL1_result.shot(shot).getNumberOfMeasuredPins(pin_pL1_vector,TMU::APP_RAW_FLAT,0);

    //
    // Loop over the pinlist
    //
    for (UINT32 i = 0 ; i < num_pL1_pins; i++)
    {
        STRING  pin     = pin_pL1_vector[i];
        ARRAY_D values;

        pin_pL1_result.shot(shot).getPinResultsFlat(pin,values,TMU::APP_RAW_FLAT,TRUE,0);
        ...
        ...
    }

    //
    // and now the second pin list:
    //
    STRING_VECTOR pin_pL2_vector;

    UINT32 num_pL2_pins = pin_pL2_result.shot(shot).getNumberOfMeasuredPins(pin_pL2_vector,TMU::APP_RAW_FLAT,0);

    for (UINT32 i = 0 ; i < num_pL2_pins; i++)
    {
        STRING  pin     = pin_pL2_vector[i];
        ARRAY_D values;

        pin_pL2_result.shot(shot).getPinResultsFlat(pin,values,TMU::APP_RAW_FLAT,TRUE,0);
        ...
        ...
    }

} // for(int shot = 1; shot <= numshots; shot++)

Example 5: TMU objects need not to be passed through functions in a testsuite context.

void myTestMethodClass::run()
{
    TMU_TASK  task1("key1")
    TMU_TASK  task2("key2")
    ...
    ...
    doSomething();
}

If you need the task objects from the run() function inside the doSomething() function, declare the variables in the same way. The right internal objects will be referenced.

void  myTestMethodClass:: doSomething()
{
    TMU_TASK  task1("key1")
    TMU_TASK  task2("key2")
    ...
    ...
}
