MTP_MEMORY_TEST.setFailAddressListOrdering()

The setFailAddressListOrdering() member function of MTP_MEMORY_TEST lets you specify the order of failing address, either the physical address order or the cycle order.

Use this function before execute(). Otherwise, the desired order does not take effect.

Difference in ordering

Assume that the following test results were generated:

Cycle result  x  y  z  d
  1   fail    0  0  0  0
  2   pass    1  0  0  0
  3   pass    2  0  0  0
  4   fail    3  0  0  0
  5   pass    4  0  0  0
  ...
  (all pass)
  ...
101   pass    0  0  0  0
102   fail    1  0  0  0
103   pass    2  0  0  0
  ...
  (all pass)

If the failing addresses are ordered by failing address, the list is:

  0  0  0  0
  1  0  0  0
  3  0  0  0

If the failing addresses are ordered by cycle, the list is:

  0  0  0  0  // occurred in cycle 1
  3  0  0  0  // occurred in cycle 4
  1  0  0  0  // occurred in cycle 102

Syntax

MTP_MEMORY_TEST& setFailAddressListOrdering(MTP::ADDRESS_LIST_ORDERING order)

Parameter

Description

order

The order in which the failing addresses are output:

  • MTP::PHYSICAL_ADDRESS (default): The failing addresses are output in the physical address order.

    To retrieve the failing addresses, use MTP_MEMORY_PATTERN.getFailingAddressList().

  • MTP::ORDERING_CYCLE: The failing addresses are output in the cycle order.

    This option is the same as MTP::FAIL_CYCLE but uses less memory.

    To retrieve the failing addresses, use MTP_MEMORY_PATTERN.getFailingCycleAddresses().

  • MTP::FAIL_CYCLE: The same as MTP::ORDERING_CYCLE, but consumes more memory.

    To retrieve the failing addresses, use MTP_MEMORY_PATTERN.getFailingCycleAddressList().

Example

Setting the list of failing addresses to be ordered by cycles:

MTP_MEMORY_TEST memoryTest();
memoryTest.setFailAddressListOrdering(MTP::FAIL_CYCLE);
