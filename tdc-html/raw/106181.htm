Control file for the Successive algorithm

Some basic aspects of the Successive algorithm are configured in a control file.

File types

The control settings can be specified either in an XML file or a plain text file.

XML files

XML files must have a .xml file name extension. A utility for converting text files to XML is available.

The root element of the XML file always is <RA_algorithm_control></RA_algorithm_control>. Within this element, individual control settings are subelements.

For example, to specify COL as the repair mode, you would add this element:

<REPAIR_MODE>COL</REPAIR_MODE>

See the examples, below, for a more complete example of the XML syntax.

Note XML has very strict requirements for syntactical correctness. We recommend that you create XML settings files in an XML editor (as opposed to a general text editor) and check it for well-formedness before using it. A wide range of XML editors is available. For example, XMLmind XML Editor is free and works on all major operating systems. (Note that this is provided just for informational purposes and constitutes neither a recommendation nor an endorsement.)

Text files

Text file must have a .rac file name extension.

Put settings in the text file at the beginning of new lines. Each setting is followed by a colon, the value, and a semicolon. Settings are enclosed in quotation marks.

For example, to specify COL as the repair mode, you would add this line to the text file:

repair_mode: COL;

See the examples, below, for a more complete example of the text syntax.

Converting files

You can convert redundancy analysis control files in text format to the XML format using the racParser utility, which is located in /opt/93000mts/mts/rr/bin.

To convert a file, provide it as a parameter to the utility on the command line. For example:

racParser sampleFile.rac

Syntax

Parameter

Values and Description

repair_mode

COL: The repair algorithm will choose columns before rows to repair failed cells.

ROW: The repair algorithm will choose rows before columns to repair failed cells.

data_check

YES: The formal correctness of the DUT initialization is checked before the algorithm is executed.

NO: No verification of the correctness of the setup is performed.

debug

YES: Debug information is output during the execution of the algorithm.

NO: No debug information is output.

output_level

The detail level of the debug information for the redundancy analysis counting algorithm. This value is an integer:

  • 0: Basic output, for example, the repair solution
  • 1: Detailed result, for example, the counting summary, results of limit checks, results of the Must Repair checks
  • 2: Reserved
  • 3: All results, for example, lists of unrepaired cells
  • 4: Reserved
  • 5: Reserved

The default value is 0.

count_limit_per_segment

The maximum number of failing cells in a segment, an integer. If the number is 0 or lower, no limit check is performed.

must_repair_iteration_limit

The maximum number of times that the Must Repair algorithm is executed, an integer. If the number is 0 or lower, there is no limit to the number of times that the algorithm is executed.

(The Must Repair algorithm searches for columns and rows with so many failures that they definitely must be replaced with a spare. The results of an iteration of this algorithm can turn up additional columns or rows in subsequent iterations.)

Note that the parameter names may be all lowercase (for example, "debug") or all uppercase (for example, "DEBUG"), but not a mixture of both (for example, "Debug").

Example

This is a sample Successive algorithm control file in XML format:

<?xml version="1.0" encoding="UTF-8" standalone="no"?>
<RA_algorithm_control>
  <repair_mode>COL</repair_mode>
  <data_check>YES</data_check>
  <debug>NO</debug>
  <output_level>1</output_level>
  <count_limit_per_segment> -1 </count_limit_per_segment>
  <must_repair_iteration_number> -1 </must_repair_iteration_number>
</RA_algorithm_control>

These are the same settings as a text file:

/* Plain text format for Succcessive Algorithm Control setup file */
repair_mode: COL;
data_check: YES;
debug: NO;
output_level: 1;
count_limit_per_segment -1
must_repair_iteration_number -1
