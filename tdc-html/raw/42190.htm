Topic 42190

Parameter: handler_site_ids prober_site_ids

Specifies the number of sites of the equipment, and the ID of each site.

Each string element of the array is a site ID. The number of elements is the number of sites.

The order and naming of the site IDs should match the equipment documentation to avoid confusion. The left most entry refers to the first equipment site, the right most entry refers to the last equipment site.

When a GPIO interface is used, the site IDs are not transferred to the equipment. Still, the handler_site_ids or prober_site_ids array must be set up to tell the driver the number of sites supported by the equipment. In addition, the site IDs will be used by the driver during message and error logging.

Note When the device pin configuration file defines multi-sites and not all these sites are configured in the driver plug-in configuration file by the prober_site_ids and handler_site_ids parameters, only the sites specified by these two parameters can be recognized and controlled by the driver and have valid results. To deactivate some equipment sites, you need specify all the available sites defined in the pin configuration file for the prober_site_ids and handler_site_ids parameter and mask the unused sites with the prober_site_mask and prober_site_mask parameters.

Driver default: none; value must be defined in the driver configuration

Changeable at run-time: yes

Applicable for: handlers or probers, respectively

Example: handler_site_ids: ["site1" "site2" "site3" "site4"]
