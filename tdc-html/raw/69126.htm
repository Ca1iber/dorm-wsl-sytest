Retest Data Record (RDR)

The Retest Data Record signals that the data in this STDF file is for retested parts. This record tells post-processing tools that the entire data set in the STDF file is retest data.

Location in the file:

If this record is used, it must appear immediately after the MIR.

RDR field name

Field description

Value

93000 data source

NUM_BINS
  • Number of bins being retested
  • Two-byte unsigned integer
  • Calculated value from number of bin entries in RTST_BIN

RTST_BIN
  • Array of retest bin numbers
  • Two-byte unsigned integer (maximum 32767)
  • Array of short unsigned integers
  • Application model variable:

    RTST_BIN

  • Data source can also be a constant value in the configuration file or a system environment variable.
    Note NUM_BINS indicates the number of hardware bins being retested. This value is calculated by counting the number of entries in the RTST_BIN list. The RTST_BIN list should be a comma-separated list of bin numbers given in an application model variable, a constant value in the configuration file or a system environment variable. For example, if RTST_BIN contained a list of bin numbers 5, 10, 47, 103, 200 then the value shown in NUM_BINS would be 5.
    Note The LOT_ID, SUBLOT_ID, and TEST_COD of the current STDF file should match those of the STDF file that is being retested, so the data can be properly merged at a later time.

Functional changes

  1. Introduced before SmarTest 6.3.2
