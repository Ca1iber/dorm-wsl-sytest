Driver sharing concepts

Driver sharing is a means to increase throughput for testing devices using a limited number of tester resources. By using one drive pin to support multiple equivalent pins on multiple devices, you can test more devices in parallel with the same test system resources. This is particularly useful to increase throughput in HVM (high-volume manufacturing) applications,

To increase throughput of automatic testing a common approach is to increase the number of sites that are tested in parallel. This requires more and more test channels and device power supplies (DPS) which increases cost of test. The resource limitations of the test system also limits the number of sites that can be tested in parallel. One solution to increase throughput without increasing cost proportionally is to share drivers - output pins of channel cards or DPS card outputs - between several test sites containing the same device type.

Sharing drivers requires:

  • A DUT board that connects several test sites to one driving source.
  • A fixture delay measurement procedure to extract the correct fixture delays for the shared pins.
  • A methodology to set up the correct timings and levels for shared and unshared pins.
  • Test methods to create a test flow for your driver sharing application.

To support driver sharing Advantest supplies:

  • A library containing specialized test methods (from the DriverSharing class).
  • A tool to merge fixture delay files into one file.
  • A DUT board design reference that helps you in to design your DUT board for shared-driver applications.

The test methods from the DriverSharing class are contained in the shared library delivered with MTP software. The test methods are:

  • DC continuity for driver sharing
  • Binning
    • Binning handler
    • Binning executor
  • OnlineCompensation
  • Leakage
    • SharedLeakage
    • SharedLeakageParallel
  • SharedIDD
  • ResetOverCurrentProtection
  • SharedVBump

These test methods have inter-dependencies. Therefore, you are required to follow the recommendations on how to arrange them in your test flow. Refer to Test methods for driver sharing for details.
