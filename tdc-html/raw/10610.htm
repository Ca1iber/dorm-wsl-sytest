Topic 10610

Restrictions for receive edges

As long as no window compares occur in a waveform definition, the order of the receive edges in the waveform is completely arbitrary. However, if a waveform contains at least one window compare, the receive edges must be arranged in ascending temporal and numerical order. Consequently, receive edges with a higher number must be assigned greater delays in all timing sets that are to be used with such a waveform.

Note that by default, these restrictions are checked by SmarTest. The check is activated or disabled by the CHECK keyword in the timing specification, see Consistency checks for edge delays.

Example

If r1 has delay 5 and r2 delay 3, then the waveform definitions "r1:E0 r2:E1" and "r2:E0 r1:E1" are both correct. But "r1:W0 r2:WC" and "r2:W0 r1:WC" are always both incorrect for the given delays.

Functional changes

  1. Introduced before SmarTest 6.3.2
