Topic 346552

Printing tester status from test method

Using the Pin Property Monitor API in test method supports customizing tester status outputs.

About this task

Follow steps below to enable user flags which control the Pin Property Monitor API and implement codes in test method for tester status outputs.

The user flag enableTMApiHWStateLogging enables printing tester status. Always mandatory.

The user flag enableTestsuitesPreAndPostHWStateLogging controls outputs for tester status. Mandatory when printing tester status to ASCII files.

The user flag enableAccumulatedStateLogging enables printing accumulated status. Optionally.

Before you begin

Check that your SmarTest has a version no less than 7.5.2.

Make sure that your device works properly.

Procedure

  1. In the Test Program Explorer panel, right-click Test Program and load your test program.
  2. Right-click Testflow and select Load All Setups.
  3. Right-click Testflow and select Open With > Flow Data Editor.
  4. Select the Variables tab.
  5. Add the user flag enableTMApiHWStateLogging.
    1. In the Variables tab, right-click and select Add Variable....
    2. On the Add Variable window displayed, select USERFLAG for Type.
    3. Enter enableTMApiHWStateLogging for Name.
    4. Enter 1 for Value.

      You must set value to 1 in order to print tester status from test method by using the Pin Property API.

  6. Add the user flag enableTestsuitesPreAndPostHWStateLogging.
    1. In the Variables tab, right-click and select Add Variable....
    2. On the Add Variable window displayed, select USERFLAG for Type.
    3. Enter enableTestsuitesPreAndPostHWStateLogging for Name.
    4. Enter 1 for Value.

      You must set value to 1, otherwise tester status output is disabled. Tester status will be printed at two time points: before test method run and after test method run. Printed tester status are saved as ASCII files under the <your device root>/waste/TestsuitesPreAndPostHWStateLog folder. The file names contain testflow, test suite and site information by default. The pre string in the file names identifies tester status printed before test method run, while the post string identifies those printed after test method run.

  7. Optionally, add the enableAccumulatedStateLogging user flag.

    Add the enableAccumulatedStateLogging user flag only if you want to include the accumulated status in the automatically saved tester status outputs (ASCII files) when testflow execution completes. See Controlling printing accumulated status from testflow for details.

  8. Right-click Testflow and select Open With > Flow Sequence Editor.
  9. Right-click the testflow displayed in the flow sequence editor and select Open Test Method.

    Instead, press F3 from the keyboard.

  10. In the test method file (.cpp) opened, add code lines calling PinPropertyMonitor to customize outputs for tester status.
    1. Based on your needs, decide a constructor to retrieve outputs by site(s), pin(s), instrument(s) or properties.
    2. Choose to print the outputs to system console or to text files.
  11. Save changes to the test method and rebuild the class binary.
  12. Back to the testflow displayed in the flow sequence editor and select Run Testflow.

Results

Tester status are printed to system console or text files based on your code implementation in the test method.

Example

The following codes retrieve tester status at all sites, on all pins, for all instrument and properties. It then prints the results to system console.

PinPropertyMonitor ppm1("@");
stringstream ss;
ppm1.printStatus(ss);
cout<<ss.str()<<endl;
The following codes retrieve tester status at all active sites, on four pins (SWITCH_R/4, SWITCH_R/2, SWITCH_R and SWITCH_2R), for instrument PPMU and property slewI. It then prints the results to new files per site. The new files are named like a.site.1, a.site.2 and saved in the TestsuitesPreAndPostHWStateLog folder under <your device root>/waste.
ARRAY_I sites;
GET_ACTIVE_SITES(sites);
string pinList = "SWITCH_R/4,SWITCH_R/2,SWITCH_R,SWITCH_2R";
PinPropertyMonitor ppm1(sites, pinList, "PPMU", "slewI");
ppm1.printStatus2File("a", PinPropertyMonitor::NEW);
