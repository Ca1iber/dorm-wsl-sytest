TRANSACTION

The TRANSACTION class represents a protocol transaction. Its member functions define the execution mode (drive, compare, capture) of the transaction and the values of its parameters.

This class cannot be instantiated directly, but can only be accessed by the add() and transaction() member functions of the PROTOCOL_TEST class, and the syncTransaction() function of the SYNCHRONIZED_TEST class.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Transaction.h.

Member functions

set()

TRANSACTION& set(const STRING& name, UINT64 value);
TRANSACTION& set(const STRING& name, const STRING& value);

This function sets an input parameter of a transaction to a specified value. The value can be specified in various formats, but not as an arbitrary state character sequence.

Parameters

I/O

Parameter

Description

I

name

Name of an input parameter. It must be a parameter of the transaction from which the function is called.

I

value

The value to which the parameter is to be set. It can be specified in the following formats:

  • Integer constant (decimal, octal, or hexadecimal), which however cannot be larger than 64 bit
  • Hexadecimal string of arbitrary size prefixed by 0x
  • Binary string of arbitrary size prefixed by 0b
  • Symbol

    The symbol must have been defined for the fields that use the parameter. It can represent a decimal number, a binary or hexadecimal literal, and also an arbitrary state character sequence.

capture()

TRANSACTION& capture(const STRING& name, const STRING& resultName);

This function configures an output parameter to receive the results of a sequence of capture actions. In order to preserve the results when the same output parameter is used for several capture sequences within the same test method, the captured sequences are stored independently of the parameter at a location that is identified by a name. This name must also be specified. The result areas can be accessed under this name with the getResult() function.

Parameters

I/O

Parameter

Description

I

name

Name of an output parameter. It must be a parameter of the transaction from which the function is called.

I

resultName

The name of the result area in which the captured values are to be stored.

expect()

TRANSACTION& expect(const STRING& name, UINT64 value);
TRANSACTION& expect(const STRING& name, UINT64 value, UINT64 mask);
TRANSACTION& expect(const STRING& name, const STRING& value);
TRANSACTION& expect(const STRING& name, const STRING& value, const STRING &mask);

This function sets an output parameter to the expected values of a compare action sequence.

Optionally, you can specify a mask by which certain bits of the expected values are skipped when determining the overall PASS/FAIL result. The effect of the mask is that the value bits corresponding to a set bit of the mask will be converted to the state character X. For example, if the value is 0xA700, and the mask is 0xFF, then the resulting state character sequence will be HLHL LHHH XXXX XXXX.

Parameters

I/O

Parameter

Description

I

name

Name of an output parameter. It must be a parameter of the transaction from which the function is called.

I

value

The value to which the parameter is to be set. It can be specified in the following formats:

  • Integer constant (decimal, octal, or hexadecimal), which however cannot be larger than 64 bit
  • Hexadecimal string of arbitrary size prefixed by 0x
  • Binary string of arbitrary size prefixed by 0b
  • Symbol

I

mask

The value to which the mask is to be set. It can be specified in the following formats:

  • Integer constant (decimal, octal, or hexadecimal), which however cannot be larger than 64 bit
  • Hexadecimal string of arbitrary size prefixed by 0x
  • Binary string of arbitrary size prefixed by 0b

The mask must always be specified in the same format as the value.

expectStateChar()

TRANSACTION& expectStateChar(const STRING& name, const STRING& value);
TRANSACTION& expectStateChar(const STRING& name, const STRING& value, const STRING &mask);

This function sets an output parameter to a state character sequence which defines expected values for a sequence of compare actions.

Optionally, you can specify a mask by which certain characters of the expected state character sequence are skipped when determining the overall PASS/FAIL result. The mask must be specified as a binary string. It causes the state characters of the value parameter that correspond to a set bit of the mask to be replaced by the state character X. For example, if the expected character sequence is HHLLHL, and the mask is 101, then the result will be HHLXHX.

I/O

name

Name of an output parameter. It must be a parameter of the transaction from which the function is called.

I

value

The state character sequence to which the parameter is to be set. It can be of arbitrary length.

I

mask

A binary string that defines which characters of the value parameter are to be replaced by X .

setComment()

TRANSACTION& setComment(const STRING& comment);

This function adds a comment to a transaction. The comment will be displayed in the Comment column of the Pattern Debug Tool at the start of the transaction within the protocol pattern.

You can define different comments for different sites. The Pattern Debug Tool will display the comment that was defined for the site that currently has the query focus.

hasProtocolError()

Boolean hasProtocolError();
Parameter

I/O

Parameter

Description

O

boolean

TRUE is returned if a protocol violation occurred.

FALSE is returned if the transaction has not been executed.

Returns TRUE if the latest execution of this transaction has encountered a protocol violation. The function will return FALSE if the transaction was not yet executed.

Note Protocol violations are bits received from the DUT that do not match the specified fixed fields in a protocol frame.

hasFailed()

Boolean hasFailed();
Parameter

I/O

Parameter

Description

O

boolean

TRUE is returned if a protocol protocol error occurred or if the data read from the DUT does not match the expected data.

FALSE is returned if all received data matched the expected data, but also if the transaction was not executed or if it did not execute a compare action.

Returns TRUE if any transaction of the latest execution of this protocol test failed. The function will return FALSE if the transaction was not yet executed.

A transaction is considered failing if any of its received fields did not match the expected parameter value or if a protocol error occurred.

getFailInfo()

const STRING& getFailInfo();
Parameter

I/O

Parameter

Description

O

string

String containing:

'E' for each failing state character

'F' for each failing bit

'P' for for all other bits and state characters respectively

Returns a string that shows where protocol errors or fails occurred in the transaction.

The string will contain character 'E' for each bit respectively state character where a protocol error was found (constant compare failed). Character 'F' will be displayed for each bit where the read date did not match an expected parameter and character 'P' in all other bits.

getResult()

UINT64 getResult(const STRING& resultName);
STRING getResult(const STRING& name, TM::FORMAT format);
Parameter

I/O

Parameter

Description

I

resultName

Name of a result area that has been used in a capture action (capture() function of the TRANSACTION class).

I

format

Specifies the format of the returned sting.

Possible formats are:

TM::HEX hexadecimal literal prefixed with 0x

TM::BIN binary literal prefixed with 0b

TM::SCS the captured bits without any prefix

TM::SYMBOL symbolic value, if the parameter was set up with symbolic values

O

UINT64

Result access with a max length of 64 bit.

O

string

Result access with a length more than 32 bit.

This function returns the result data of the specified result area. If the enableBulkUploadMode() member function of the PROTOCOL_TEST class is set to TRUE (which is the default), the capture results are uploaded for all sites in parallel into a cache on the work station by the first call of getResult(); all later calls within the same test method access this cache. This is independent of whether or not the first call is placed within the ON_FIRST_INVOCATION block. If enableBulkUploadMode() is set to FALSE, getResult() only returns the result of the site that has the query focus; in this case, getResult() must be placed outside the ON_FIRST_INVOCATION block.

The UINT64 version allows at most 64 bit values to be reconstructed. If larger parameter values should be read then the alternative syntax must be used.

The string version should be used if expecting more than 32 bit length of result data. In this case the format of the returned string has to be specified! If the format is set to SYMBOL and the captured value does not match any symbolic value the operation will return an empty string.

Exceptions will occur if:

  • called for an empty transaction object, respectively if no valid results are available, i.e. no test executed yet or results already invalidated again
  • the parameter identified by name was not set up to be captured.

setTransactionIdString()

void setTransactionIdString(const STRING& transactionIdString);

This member function assigns an ID to a transaction. This ID can be used to retrieve transaction results, but only if the transaction has only one output parameter. In the case of a SERIAL_LINK_TEST object, where transactions can be associated with a timeout parameter, it can also be used to query the remaining time for the respective transaction.

Parameter

I/O

Parameter

Description

I

transactionIdString

The name that is to be associated with the transaction. It must be unique within the transaction sequence, but you can use the same name for a transaction in another transaction sequence, in which case the transaction ID alone is not sufficient to identify the transaction within the test. A similar situation arises when the same persistent pattern (precompiled transaction sequence) is used more than once in a test.

Whenever you want to retrieve the result of a transaction with such an ambiguous ID, you must identify it by the compound string

persistent_pattern_name:occurrence_no:transactionIdString,

where

  • __MAPI_GENERATED_TS__ must be specified for persistent_pattern_name if an transaction ID is used more than once in the test method code, and
  • occurrence_no counts either
    • the instances of the persistent pattern, or
    • the MAPI generated transaction sequences containing the specified transaction ID

      within the test, starting from 0.

getTransactionIdString()

STRING getTransactionIdString();

This member function retrieves the transaction ID of the transaction from which the function is called. Note that it only returns the string defined with setTransactionIdString(), not the compound string required to identify a transaction with a non-unique ID. The function has no parameters.

Important information

If a protocol violation was encountered each transaction is in error state.

If any expected value did not match the device output each transaction is in error state.

If no protocol violation nor expect value mismatch was encountered the transactions will be in pass state.
