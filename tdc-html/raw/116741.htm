Topic 116741

TTST? - (Transition Test STatus information)

This query retrieves status information about the most recently completed test.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Syntax

TTST? {status_type}, {filter}, {(pinlist)}

returns:

TTST {status_type}, {property}, {state}, {(pinlist)}

Parameters

status_type

Specifies the status type. Possible values are:

ERR_STATUS

Returns information about possible errors per pin. These are exactly the properties that can be activated as errors with TTCF, and whose names start with "ERR_".

Note that each of the states contained in this status type is reported when it is observed, regardless of whether it is actually activated with TTCF. TTCF only controls whether the specific error condition contributes to the pass/fail result of a pin.

The possible errors are:

ERR_BADTRAN

An illegal sequence of transitions occurred.

ERR_CNTADJOVR

An adjustment overflow occurred. This means that the observation window was adjusted more than 1 UI in one direction within 24 UI. Note that adjustments in opposite direction cancel each other out. Thus if '+' indicates an adjustment to the right, and '-' an adjustment to the left,

- + - + - + - +

is acceptable, but

+ + + + + - + +

creates an overflow.

ERR_CNTLMT

The maximum drift of 7.75 UI for the entire pattern was exceeded.

ERR_COMPARE

Compare errors were detected.

ERR_FTO

The number of bits that were skipped for synchronization at test start exceeds the maximum defined with FIRST_INITIAL_SYNC_LIMIT.

ERR_JMP2

An unrecoverable BC transition (jump by 2) was detected.

ERR_PULSE

A bit was sampled only once. If pulse stretching was enabled this error refers to the stretched pulse. See Stretching the pulse.

ERR_STO

The number of consecutive skipped bits after initial synchronization exceeds the maximum defined with SUBSEQUENT_INITIAL_SYNC_LIMIT.

This can happen in two cases:

  • at synchronization of an IO pin that has been switched from drive to receive mode, or
  • when too many consecutive idle tokens have been skipped, that is, if

    no_of_tokens * token_size >

    SUBSEQUENT_INITIAL_SYNC_LIMIT.

ERR_STOP

The sequencer stopped too early, that is, before all compare actions have been completed. This error can be avoided by adding an appropriate number of break vectors (at least 400) at the end of the test.

ERR_TE0

No reference transition occurred, that is, the observation window could not be adjusted successfully.

ERR_TE2

A BC transition occurred in a block of three UI, for example

LLLL LLHH HHHH

ERR_TE3

Two different transitions occurred within a UI (not between two UI) in a block of three UI, for example

LLLL LHHH LLLH

Here the second UI contains an AB transition, and the third UI contains a CD transition.

ERR_TE4

Three transitions occurred within a UI (not between two UI) in a block of three UI, for example

HHLL LHHH LLLH

Here the first UI contains a BC transition, the second contains an AB transition, and the third a CD transition.

ERR_TRK

The maximum drift for the entire pattern as defined with TRACKING_LIMIT was exceeded.

ERR_TRMCNT

The removed idle bits were not a multiple of the token size.

ERR_XMAX

The length of the received data exceeds the length of the expected data by more than the value defined with DEVIATION_LIMIT_DUT_BEFORE_ED.

This only applies when X-token removal is activated with the REMOVE_XTOKEN_MODE property.

ERR_XMIN

The length of the expected data exceeds the length of the received data by more than the value defined with DEVIATION_LIMIT_ED_BEFORE_DUT.

This only applies when X-token removal is activated with the REMOVE_XTOKEN_MODE property.

ERR_STATUS_COMBINED

Returns combined information about possible errors for all specified pins.

Note that each of the states contained in this status type is reported when it is observed, regardless of whether it is actually activated as an error with TTCF.

INTR_STATUS

Returns information per pin about interrupts during the last sequencer run.

INTR_STATUS_COMBINED

Returns combined information about interrupts for all specified pins.

ALL

All status types are returned.

filter

Specifies which subset of the available information is to be returned. The possible values depend on the selected status type.

Possible values for ERR_STATUS and ERR_STATUS_COMBINED are:

ALL

The state of all possible errors is returned.

ALL_HEX

The state of all possible errors is returned as a hexadecimal number.

OFF

Only the possible errors that were not observed are returned.

ON

Only the possible errors that were observed are returned.

property

The reply is whether the possible error identified by this property was observed. For the meaning of the properties see the TTCF command.

The values ALL, ALL_HEX, OFF, and ON can also be specified for INTR_STATUS and INTR_STATUS_COMBINED.

The individual properties for these two types are:

ADJUSTMENT_ERROR

This is a hardware error.

DRIVE_BIT_IN_COMPARE_DATA

This can only happen when APG mode is enabled and a drive bit was found in the received data.

DUT_FIFO_OVERFLOW

This can happen when X-token removal is enabled and the number of removed X-tokens exceeds the number of skipped idle tokens.

EXPECTED_FIFO_DUT_OVERFLOW

This is a hardware error.

state

Specifies the state of a selected property. Possible values are:

OFF

The state was not observed.

ON

The state was observed.

pinlist

Specifies the pins for which status information is to be retrieved.

Application

Protocol engine tests.

Errors

An error is generated if no transition test set with the specified name exists.

Example

> TTST? ALL,ALL,(p1)

< TTST INTR_STATUS,DRIVE_BIT_IN_COMPARE_DATA,OFF,(p1)
< TTST INTR_STATUS,ADJUSTMENT_ERROR,OFF,(p1)
< TTST INTR_STATUS,DUT_FIFO_OVERFLOW,OFF,(p1)
< TTST INTR_STATUS,EXPECTED_FIFO_OVERFLOW,OFF,(p1)
< TTST ERR_STATUS,ERR_XMAX,OFF,(p1)
< TTST ERR_STATUS,ERR_XMIN,OFF,(p1)
< TTST ERR_STATUS,ERR_FTO,OFF,(p1)
< TTST ERR_STATUS,ERR_STO,OFF,(p1)
< TTST ERR_STATUS,ERR_TRMCNT,OFF,(p1)
< TTST ERR_STATUS,ERR_COMPARE,ON,(p1)
< TTST ERR_STATUS,ERR_TE4,OFF,(p1)
< TTST ERR_STATUS,ERR_TE3,OFF,(p1)
< TTST ERR_STATUS,ERR_TE2,ON,(p1)
< TTST ERR_STATUS,ERR_TE0,OFF,(p1)
< TTST ERR_STATUS,ERR_JMP2,ON,(p1)
< TTST ERR_STATUS,ERR_TRK,OFF,(p1)
< TTST ERR_STATUS,ERR_PULSE,OFF,(p1)
< TTST ERR_STATUS,ERR_BADTRAN,OFF,(p1)
< TTST ERR_STATUS,ERR_CNTADJOVR,OFF,(p1)
< TTST ERR_STATUS,ERR_CNTLMT,OFF,(p1)
< TTST ERR_STATUS,ERR_STOP,OFF,(p1)
< TTST ERR_STATUS,ERR_WRCMP,OFF,(p1)

This example returns all properties of the ERR_STATUS type. ON indicates that the respective state was observed, OFF indicates that it was not observed. Note that ON does not imply that the test failed. For this, the respective property must also be activated as an error with TTCF. In this example compare errors (ERR_COMPARE) and a jump by 2 (ERR_TE2, ERR_JMP2) were observed.

Functional changes

  1. Introduced in SmarTest 7.0.1
