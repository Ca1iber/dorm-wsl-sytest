ERRE? - (Expected and Received Results of Events)

The ERRE? query returns measurement values that were generated from a pattern of the previously performed test. The query returns one answer per pin.

The measurements must have been executed for DC Scale pins from a test point pattern, by a DC event or, for digital pins, by a MEAS instruction within a DC pattern (for DC patterns, see Executing PPMU tests from a pattern). Events (or MEAS instructions) that do not generate a result (for example, setMeasureRange) are not reported. For DC Scale pins, ERRE? is the counterpart to EMAP?. For such pins, ERRE? can also return expected data.

Note that ERRE? can return the values produced by a DC pattern only on Pin Scale 9G cards. Observe also that ERRE? cannot return Pass/Fail results of a DC pattern (as required with measurement mode PMUM, see the MSET command).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Predependencies

If result data are requested, a test point pattern must have been executed for DC Scale pins, or a DC pattern for digital pins.

Syntax

ERRE? {type}, {resultIndex}, {numResults}, {data_format}, {rep_mode}, [byte_max] [,gang_index], {(pinlist)}

returns:

ERRE {type}, {resultIndex}, {numResults}, {data_format}, {rep_mode}, [error_status] [, gang_index], {(pin)}, {#spec(data)}
Parameters

type

The supported types are:

  • RCV

    Requests received data only.

    Can only be requested if a test point pattern has been executed for DC Scale pins, or a DC pattern was executed for digital pins.

  • EXP

    Requests expected data of only those test point events that generate a result.

    This type is only allowed for test point patterns, not for DC patterns.

  • ALL

    Requests both expected and received data.

    This type is only allowed for test points patterns, not for DC patterns.

resultIndex

The index of the first result to be read. Only test point operations (MEAS instructions) that provide a result are counted, starting from 0.

numResults

The number of results to be retrieved.

data_format

Specifies the binary data format of #spec(data). The DC Scale cards DPS32, VI32, and UHC4 / UHC4T, as well as DC patterns, support both formats.

  • 0

    This format contains PASS/FAIL and status information for every measurement. It can be used for status analysis where expected data and measurement values are not required. This format is only available for type RCV.

  • 1

    For test point events, this format can return both received and expected data. Expected data are not available for DC patterns.

    The received data of format 1 not only contains PASS/FAIL and status information for every measurement, but also the measurement type and value.

    The expected data contains all the setup information of an event (td element) that contains a Measure operation.

    Format 1 is available for all three types.

rep_mode

Specifies the reporting mode. Possible values are:

  • ALL:Reports all results within the selected area.
  • EOLY: Reports only failed results including measurement errors (that is, too small a distance between two measurements, or type mismatch between measurement and range). This mode is not available for type EXP.

byte_max

In the query, this parameter specifies the maximum number of bytes that may be returned. This option can be used for the reporting mode EOLY, where the size of the data that will be returned cannot be calculated beforehand.

In the reply, this parameter is used to indicate the reason in case that not all the requested results can be returned:

  • EOB

    The number of requested results exceeds the maximum buffer length specified with byte_max.

  • EOF

    The result range of the query exceeds the length of the test.

  • EOM

    This code is returned if the size of the answer exceeds the available storage capacity.

gang_index

The index within the ganged channels for which data will be

answered. If this parameter is used, the connect_state (set with PSLR) must be hdig or norm_hdig.

This only applies to test point measurements.

pinlist

DC Scale pins for which no test point pattern has been executed and digital pins for which no DC pattern has been executed will be ignored.

#spec(data)

The binary data that are returned. The general format is:

#Nn1n2n...nNdata_stream

The N digit defines the number of the digits ni (1 ≤ i ≤ N) that specify the length of data_stream in bytes.

The data stream itself consists of a stream header and one or more answers (only one answer for data formats 0 and 1), where every answer contains the same number of data blocks.

The stream header defines

  • the number of answers (4 long bytes, big-endian encoded)
  • the number of data blocks per answer (4 long bytes, big-endian encoded).

Every data block consists of a block header and one or more data units each of which contains the result of one test point measurement or MEAS instruction (DC pattern).

The block header defines

  • the index of the first result (4 long bytes, big-endian encoded)
  • the number of successive results (4 long bytes, big-endian encoded).

If rep_mode is set to ALL, there will be only one block; if it is set to EOLY, there can be more than one.

The length of the data units depends on the selected format and on the selected type. If type is set to ALL, each data unit consists of the expected data and the received data in this order.

Binary data formats

There are currently two data formats, 0 and 1.

Data format 0

This format, which is only available for type RCV, only contains the received data, one byte for each measurement. The individual bits must be decoded as follows:

Content

Bits

Description

Compare result

0 (LSB)

Upper limit. The meaning of this flag is different for test point results and DC pattern results. For test points, it is set to 1 if all of the following conditions are satisfied:

  • An upper limit is specified (limitHigh attribute of measure operation).
  • The check of the upper limit is active (failAboveHighLimit attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false with DFTD).
  • The measured value is greater than the upper limit.

For DC patterns, the flag is set to 1 if one of the following conditions is met:

  • The compare mode for the measurement is set to H by the measurement mode action of the measurement set (MSET command), and the measured value is smaller than the higher limit.
  • The compare mode for the measurement is set to I by the measurement mode action of the measurement set (MSET command), and the measured value is greater than the higher limit.

 

1

Lower limit. The meaning of this flag is different for test point results and DC pattern results. For test points, it set to 1 if all of the following conditions are satisfied:

  • A lower limit is specified (limitLow attribute of measure operation).
  • The check of the lower limit is active (failBelowLowLimit attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false with DFTD).
  • The measured value is smaller than the low limit.

For DC patterns, the flag is set to 1 if one of the following conditions is met:

  • The compare mode for the measurement is set to L by the measurement mode action of the measurement set (MSET command), and the measured value is greater than the lower limit.
  • The compare mode for the measurement is set to I by the measurement mode action of the measurement set (MSET command), and the measured value is smaller than the lower limit.

 

2

Status information. This flag is set to 1 if at least one of the following conditions is satisfied:

  • One of the bits 3 through 5 is set to 1 and active, and the measurement result is not masked.
  • Bit 6 is set to 1
  • Bit 7 is set to 1

Status information

3

Low clamp violation. This flag is set to 1 if there is a low clamp violation.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of low clamp violation is active (failOnLowClamp attribute of measure operation set to true with DFTD)
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

This flag is not set for DC patterns.

 

4

High clamp violation. This flag is set to 1 if there is a high clamp violation.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of high clamp violation is active (failOnHighClamp attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

This flag is not set for DC patterns.

 

5

Measurement range exceeded. This flag is set to 1 if the measurement range is exceeded.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of the measurement range is active (failOnOutOfRange attribute of measure operation set to true).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

 

6

Distance too small. This flag is set to 1 if the distance between two consecutive measurements is too small. It is always evaluated for the status information (bit 2), even if the measurement result is masked.

This flag is not set for DC patterns.

 

7 (MSB)

Type mismatch. This flag is set to 1 if the measurement type does not match the measurement range. It is always evaluated for the status information (bit 2), even if the measurement result is masked.

Application

DC Dynamic, DC patterns

Example

# Get the number of available results
> VALR? (dpsPin)
< VALR CONS,10,(dpsPin)

# upload the first 5 received results in format 0
> ERRE? RCV,0,5,0,ALL,,,(dpsPin)
< ERRE RCV,0,5,0,ALL,(dpsPin),#9000000021
  \x00\x00\x00\x01\x00\x00\x00\x01
  \x00\x00\x00\x00\x00\x00\x00\x05
  \x00\x02\x00\x00\x0C

The data stream has been broken up to make it more readable. The first test point measurement failed because of a low limit violation, the fourth because of a low clamp violation.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 6.5.0: New parameter: gang_index
  3. SmarTest 7.0.1: ERRE? now also returns results of DC patterns (multiple measurement values)
  4. SmarTest 7.3.1: New Force type values 010 to 100. Force value extended to 16 bytes for force type 100.
