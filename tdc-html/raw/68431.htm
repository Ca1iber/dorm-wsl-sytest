Using the MTL compiler from the command line

Subtopics

  1. apgc command syntax

You can run the MTL compiler from the command line, if desired. Numerous command switches let you control the processing and post-processing options.

About this task

The MTL compiler is used to convert a test program and a set of setup files into an executable memory test pattern. Reasons to use the command line (as opposed to the GUI) include:

  • Personal preference.
  • Reusing existing command line commands: If a command already exists that executes the compiler with the desired options, reusing it is usually quicker than setting the specifications in the GUI.
  • Including the compiler execution in a shell script.

Note that using the compiler from the command line does not provide options for automatically uploading and executing the compiled pattern or copying the vector file, as the GUI does.

Before you begin

Make sure that you have prepared all required configuration files, as described in Basic MTL workflow.

Note The MTL compiler requires a FLEXlm license provided by a FLEXlm license server. If the FLEXlm license server cannot provide a license, the MTL compiler will not start. For further details on FLEXlm licensing see Installing your FLEXlm license in the CTH Installation Guide.

Procedures

To run the MTL compiler from the command line:

  1. In any terminal window, enter apgc.
  2. Add the desired command line options, as explained in apgc command syntax.
  3. Add the name of the APG pattern file.

    You can add either the name and path of a pattern file verbatim to compile just that file.

    Or you can specify a name pattern with wildcard characters to compile all matching pattern files in one go. Using wildcard characters is described in "Specifying pattern files with wildcard characters", below.

  4. Press the Enter key.

    The compiler creates a vector pattern file from the specified file according to the options provided.

Specifying pattern files with wildcard characters

The MTL compiler supports the ? and * wildcard characters:

  • ? signifies any single character. For example, a?e matches "ale", "are", or "ate", but not "anne" or "ae".
  • * signifies any run of zero or more characters. For example, a*e matches "ae", "ale", "anne", "are", or "ate", but not "art" or "file".

Some commonly used wildcard arguments and the pattern files that they match:

  • *.apg: all pattern files in the active directory
  • x*.apg: all pattern files in the active directory the names of which begin with x
  • */*.apg: all pattern files in all subdirectories of the active directory (but not the active directory itself)
  • *march6n.apg: all pattern files in the active directory the names of which end with "march6n"
  • ???.apg: all pattern files in the active directory with names consisting of exactly three characters.
    Note If the wildcard pattern matches a file that cannot be compiled, the compiler generates an error message and continues with the next matching file.

Results

The compiler has created these output files in the directory in which the specified pattern file (.apg file) is located:

  • <apg pattern file name>.apg.vec: The binary file with the vector pattern as a per-pin subroutine. This pattern can be downloaded into the tester using SmarTest.

    This file is created when the compiler is called with the -pps option or without both the -pps and -para options.

  • <apg pattern file name>.para.vec: The binary file with the vector pattern as a per-pin subroutine. This pattern can be modified manually or converted to Verilog format.

    This file is created when the compiler is called with the -para option.

  • <apg pattern file name>-EL7.apg.rec.so: An optional file containing binary reconstruction information for converting cycle-based data to address-based data.
  • If you have specified the -w command option, the existing waveform file (the timing or waveform map file specified in the APG pattern file) is backed up by appending .BAK$$ to its name and a new timing file with the original name is created in its place.
  • If you have specified the -o command option, a file containing the stderr and stdout output is created with the name and location you specified.

Error messages of the MTL compiler

If error messages are displayed in the result window during or after the compilation, Data Queue Empty error may contain possible solutions.

Example

apgc mypattern.apg -o ../diagout.txt: The system compiles the program and configuration files specified in the file mypattern.apg in the active directory. It saves the compiled vector file as mypattern.apg.vec in the active directory and all stderr and stdout output as diagout.txt in the directory containing the active directory.
