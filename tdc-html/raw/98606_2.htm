FTCG, FTCG? - (Functional Test ConfiGure)

The FTCG command serves to change the system behavior with respect to the activation of primary sets.

The system activates the primary sets (timing, levels, waveforms) at two occasions:

  • When a connect sequence is executed (as, for example, at the start of every test flow)
  • At the start of a functional test (initiated, for example, by FTST?, STRS?)

The activation is carried out on the sequencing group level. Primary sets are not activated for individual ports, but always for all ports of the same sequencing group, as defined in the primary timing specification (with SPRM) or start label (with SQSL).

Set activation is time consuming, and is therefore by default executed at test start only if necessary, that is, only if the test setup specifies a currently inactive primary set for at least one port of the sequencing group.

There is one exception to this principle: If a sequencing group contains more than one port, one set is always activated, even if it is already active (this is required to synchronize the user vectors of the ports, see Synchronization within sequencing groups).

With the FTCG command, you can change this standard behavior in both directions.

On the one hand (option ON), you can use it to suppress activation completely, even in the case of a sequencing group containing several ports, and even if the respective sequencing group contains a port whose primary sets are currently inactive. This option is intended for keeping a PLL alive across functional tests; for the activation interrupts vector generation by executing a CTOF sequence, which is associated with static states of the drivers for a certain period in time. Note that activation within a connect sequence is not suppressed.

On the other hand (option NEVER) the command serves to enforce the activation even if the specified primary sets are already active for all ports of the sequencing group.

In both cases the new behavior is defined for a port, but this port is treated as a representative of its sequencing group.The settings defined with FTCG remain valid until they are modified by another application of FTCG, or *RST is executed explicitly or implicitly.

You can restore the standard behavior with the OFF option.

Note that the command has no impact on the user defined CTIM (Change TIMing) or CLEV (Change LEVel) sequencer instructions within the functional test. These instructions and their associated CTOF sequences will always be executed.

Note also that suppressing the activation has the following effects:

  • If the period lengths of the ports belonging to such a sequencing group are different, the user vectors of these ports are no longer started synchronously.
  • If activation of the primary sets is suppressed for a port that contains a receive pin (io or o), the Timing Diagram will not be able to make scope or high resolution measurements for the sequencing group to which this port belongs.
Note If keep alive ports are set via FTCG and FLUSH(TM::APRM) (Command FLSH) is executed, the following message will be issued in case of updating the clock:
FTCG ON was specified for at least one port which cannot be retained unchanged now.
The command "Flush" forces a clock off, resulting in a stop of all channels.
For more information, refer to Suppressing Reactivation of Primary Sets with FTCG.

Syntax

FTCG
FTCG {parameter}, {mode}, {(portlist)}
FTCG?
FTCG? {parameter}, {(@@)}

returns: 

FTCG {parameter}, {mode}, {(portlist)}
Parameters

parameter

The parameter to be used is SKPR (SKip PRimaries).

mode

Specifies different activation conditions. This option can take the following values:

ON

Suppresses activation of all primary sets at the start of a functional test for the sequencing groups of the ports specified by the portlist parameter. This option serves to keep a PLL alive across functional tests.

OFF

Allows activation for the ports specified by the portlist parameter. This is the default.

 

NEVER

By this option, the primary sets will always be loaded at the start of a test for all ports of the sequencing groups to which the ports specified by the portlist parameter belong.

portlist

In the command, specify a list of ports, separated by commas. Note that the ports are treated as representatives of their sequencing groups. Activation will be suppressed, allowed, or enforced not only for the specified ports, but for all member ports of the sequencing groups to which the specified ports belong in the current setup.

In the query, specify @@, which stands for all ports.

Application

Continuous clock setups.

Example

The following example illustrates the dependence of the FTCG command on the current sequencing group definitions.

> SQLB "MP_burst1",MPBU,28,31,"SG1",(clock)
> SQLB "MP_burst1",MPBU,28,29,"SG2",(data1)
> SQLB "MP_burst1",MPBU,31,32,"SG2",(data2)
> SQLB "MP_burst2",MPBU,32,33,"SG1",(clock)
> SQLB "MP_burst2",MPBU,30,31,"SG1",(data1)
> SQLB "MP_burst2",MPBU,33,34,"SG2",(data2)
> FTCG SKPR,ON,(clock)
> FTCG SKPR,NEVER,(data2)
> SPRM "cont_clock",,,
> SQSL "MP_burst1"
> SQGB ACQF,0
> FTST?
...
> SQSL "MP_burst2"
> FTST?
...

In the first functional test, sequencing group SG1 only contains the port clock, and therefore activation of primary sets is suppressed at the start of MP_burst1 only for clock, whereas it is enforced for ports data1 and data2. In the second test, SG1 contains both clock and data1, and therefore activation is suppressed for both these ports at the start of MP_burst2, and enforced only for data2.
