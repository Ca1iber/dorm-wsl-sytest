TOCF, TOCF? - (Timing/Level Offset search ConFiguration)

TOCF and TOCF? define and query the configuration of an embedded timing or level search for the specified pins. The search is executed with the TORN? query.

The search serves to correct the positions of all edges or levels of the same type, as defined in the current primary timing or level setup. It changes the positions according to a certain algorithm (basically first a linear, then a binary search) within a search range. After each change, a functional test is executed. The result of the search is an area of maximal length within the search range where the test passes. The start, middle or end of this area can then be stored as an offset that is to be added to the edge or level delays of the current primary timing or level.

For more information on embedded timing search see Using embedded timing search.

TOCF respects the multi-site setup focus as defined with PSFC. TOCF? returns the configuration of the site that has the query focus (defined by PQFC).

With this command you configure setups of those sites that have the setup focus: For more information, see also: PSFC, PSFC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

TOCF

TOCF [search_type], {resource_type}, {start}, {number_of_steps}, {step_width}, {resolution}, [min_pass_count], [min_stable_error_count,] [histogram_step_width,] [transition_detection], [error_count_limit], [restore_flag], {(setup_pinlist)}

TOCF?

TOCF? {(pinlist)}

returns:

TOCF {search_type} {resource_type}, {start}, {number_of_steps}, {step_width}, {resolution}, {min_pass_count}, {min_stable_error_count}, {histogram_step_width}, {transition_detection}, {error_count_limit}, {restore_flag}, {(setup_pinlist)}

Parameters

search_type

This parameter defines which value of the search result is to be stored as an offset to the edge positions of the current primary timing. Possible values are:

 

EYE

The middle of the pass area is stored as the offset. This is the default.

 

LB

The left boundary of the pass area is stored as the offset.

 

RB

The right boundary of the pass area is stored as the offset.

resource_type

This parameter selects the timing or level resource. Possible values are:

Timing resources

R

Receive edges are moved.

F

Fast drive edges are moved.

S

Slow drive edges are moved.

D

Both kinds of drive edges are moved.

Level resources

VIH

High driver levels are moved

VIL

Low driver levels are moved

VISWING

Driver swings are moved.

VOH

High receiver levels are moved.

VOL

Low receiver levels are moved.

VIOFFSET

Driver offsets. Both the driver high and low levels will be moved by the same values.

VOOFFSET

Receiver offsets. Both the receiver high and low levels will be moved by the same values.

VTH

Receiver thresholds are moved.

VOSWING

Receiver swings are moved.

start

This parameter defines the start of the search range relative to the edge or level positions as defined in the current primary timing or level. Negative values are allowed.

Units for timing and level searches are ns and mV.

number_of_steps

This parameter defines the number of steps for the linear search.

step_width

This parameter defines the step width for the linear search. The search range is number_of_steps * step_width.

step_width can be negative. Therefore, a negative search is possible.

Units for timing and level searches are ns and mV.

resolution

This parameter defines the resolution of the binary search. The binary search is stopped when the distance between the last two binary search steps is ≤ resolution.

Units for timing and level searches are ns and mV.

min_pass_count

The PASS area determined by the binary search may still contain isolated FAIL results at its start or end. This parameter activates an additional check that is intended to exclude this. It specifies how many consecutive PASS results must be present at the start (before the end) of the putative PASS region. If this requirement is not satisfied, the left boundary of the area is moved to the right (the right boundary moved to the left) until the required number of consecutive PASS results is found.

The default for min_pass_count is 1.

min_stable_error_count

This and the histogram_step_width parameter define a histogram based search, which is performed after the binary search. It moves the left boundary of the PASS area to the left (the right boundary to the right) until the number of errors is the same for the number of search steps specified with min_stable_error_count.

histogram_step_width

This parameter defines the step width of the histogram search.

transition_detection

This parameter controls the criterion for a test to be considered as PASSED. Possible values are:

 

PF

The test is considered to have passed only if no errors occurred at all. This is the default

 

ECL

The test is considered to have passed if the number of errors is smaller than error_count_limit.

 

PF_FASTSTOP

Like PF but, using the FASTSTOP mode, stops the linear search after the first PASS area is detected (see Linear search modes).

 

ECL_FASTSTOP

Like ECL but, using the FASTSTOP mode, stops the linear search after the first PASS area is detected (see Linear search modes).

error_count_limit

This parameter defines the minimum number of errors that are not tolerated if transition_detection is set to ECL.

restore_flag

The restore_flag parameter enables or disables the restore process after a search was executed: It allows you to suppress storing of the search result.

 

YES

Restores the timing / level offsets to the values it had before the offset search was executed.

 

NO

The new measured offset values are used in the edge position calculation.

This is the default configuration.

setup_pinlist

This parameter defines the pins the edge positions of which are to be changed. If an input pin is specified, the O or IO pins on which the outcome of a search step is to depend must be defined with TOCR.

Note also that the edge type specified with the edge_type parameter must be in line with the pin type.

Application

Embedded timing and level search.

Example

TOCF EYE,R,1,100,1,0.1,5,PF,,NO,(Pin1)

This example appends a check for 5 consecutive pass results to the result of the binary search.

TOCF EYE,R,1,100,1,0.1,1,10,0.1,ECL,7,NO,(Pin1)

This example appends a histogram based search to the binary search. The histogram based search is terminated if the error count is stable for 10 consecutive search steps. A test is considered passed if the number of errors is smaller than 7.
