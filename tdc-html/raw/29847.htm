WAIT_TEST_DONE

This API waits for the test completion. This API also detects whether digitizers and samplers have received one or more trigger input or not from when the test is started by the START_TEST API until the execution of this API ends. For details of this functionality, see Error Handling on Missing Trigger Input.

The test time is compared to a timeout value. This value can be defined with the timeout parameter. If this parameter is omitted, the default or the value that was last set is used. If the timeout_info parameter is omitted and the test exceeds the timeout value, the test will be aborted and the testsuite will be judged as FAILED. If the timeout_info parameter is set, WAIT_TEST_DONE() will return timeout information, and the test will continue with the next statement.

In a multi-site test, the reply of the timeout_info parameter depends on whether it is used in combination with the trigger_info parameter. If it is used alone, it will return global timeout information, that is, it will return 1 if a timeout occurred on any site, and 0 otherwise. If both parameters are specified, it will return site specific timeout information.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/Execute.h.

Parameters

I/O

Parameter

Description / Range

I

timeout

Timeout time of the measurement (test) in sec.

This cannot detect a timeout for the AWGs. Operations when timeout occurs depend on whether the timeout_info parameter is set or omitted. See Important Points.

O

timeout_info

This parameter returns timeout information. It can only be used in combination with the timeout parameter.

The reply of timeout_info depends on whether it is used with or without the trigger_info parameter.

If trigger_info is not specified, timeout_info returns global timeout information. Possible return values are:

0: No timeout occurred on any site.

1: A timeout occurred on one site at least.

If trigger_info is also specified, timeout_info returns site specific timeout information.

In this case, the returned integer must be converted into binary format. Every bit returns the timeout status of one site. Site 1 is represented by the LSB.

For example, if 13 is returned to this parameter, this corresponds to binary number 1101. This indicates that a timeout occurred on the sites 1, 3, and 4.

O

trigger_info

This parameter returns site specific information on the trigger status of the digitizers. It can only be used in combination with the timeout_info parameter.

The reply refers to the following digitizers: MCA-ADGT/VDGT, MCB LF/VHF-DGT, and MCC. The state of the module (or MCA/MCB/MCC unit) is checked if a pin is defined and connected to the core.

The parameter informs about which of these digitizers have not been triggered from when the test is started by the START_TEST API until the end of this API. For more details of this functionality, see Error Handling on Missing Trigger Input.

The returned integer must be converted into binary format. Every bit returns the trigger status of one site. Site 1 is represented by the LSB. The bit states have the following meaning:

0: All the digitizer/sampler modules (and all the MCA/MCB/MCC measure units) on the site have been triggered at least once.

1: At least one digitizer/sampler module (or one MCA/MCB/MCC measure unit) on the site has never been triggered (missed a trigger).

In offline mode, this flag indicates whether the trigger signal input is enabled for all the modules (and all the MCA/MCB/MCC units) (0) or not (1).

I

wait_action

This parameter allows you to select which sequencer's completion the API waits for, from the following hardware categories that are represented by the constant variables. It is also valid for combination of them by using "|" (use bitwise OR to select multiple ones). For example, if you make this API waited until AWGs and digitizers/samplers complete the current sequencer programs, specify TM::WAIT_AWG|TM::WAIT_DGT to this parameter.

Default: TM::WAIT_DIGITAL| TM::WAIT_DGT| TM::WAIT_TIA

  • TM::WAIT_ALL

    waits until all used digital channels, AWGs, digitizers/samplers, and TIAs complete their tasks.

  • TM::WAIT_DIGITAL

    waits until all used digital channels complete the current sequencer program.

  • TM::WAIT_AWG

    waits until all used AWGs complete the current sequencer programs.

  • TM::WAIT_DGT

    waits until all used digitizers and samplers complete the current sequencer programs.

  • TM::WAIT_TIA

    waits until all used TIAs complete the current measurements.

  • TM::WAIT_TMU

    waits until all running TMUs have finished their measurements.

I

context

Name of an execution context. The ports of the context must be included in the current start label (which must be a multiport burst). For more information on execution contexts see Using execution contexts .

The context must have been defined on the firmware level (with the SQEC command), or as a SEQUENCER_CONTEXT_ITEM object. In the latter case this object must have been included in a SEQUENCER_CONTEXT object, and must also have been activated on the firmware level with the apply() function of this SEQUENCER_CONTEXT object. If the context has been defined as a SEQUENCER_CONTEXT_ITEM object, you must use the name specified for its name parameter.

I

pins

If WAIT_TMU is included in the wait_action parameter, WAIT_TEST_DONE will by default wait until the TMU measurement has been completed on all pins of the active TMU set. With the pins parameter, this behavior can be restricted to the specified pins.

I

wait_abort_cond

This parameter allows you to wait and abort the test execution, when a digital compare failure has happened. With the following options, users can

  • TM::ABORT_NONE

    don´t abort the test execution.

  • TM::ABORT_ON_FAIL_ALL_PINS

    abort when the failure detected on all the pins.

  • TM::ABORT_ON_FAIL_ANY_PIN

    abort when the failure detected on any of the listed pins.

Important points

  • The WAIT_TEST_DONE API has to be used in conjunction with the START_TEST API. You can perform another job (for example, data calculation in parallel) between the START_TEST and WAIT_TEST_DONE APIs while the tester hardware is running.
  • If the timeout parameter is specified, the timeout time is compared to the time from when the test started. If the test exceeds the timeout value, the next action depends on whether the timeout_info parameter is set or not. If it is set, the test will stop and issue timeout information, then the next statement will be executed. If the timeout_info parameter is not set, the test will be aborted and the testsuite will be judged as FAILED.
  • For the syntax without the parameter wait_action, the API does not wait until the AWG finishes the output. If an infinite loop sequence, LOOPI or RPTI, is used for AWG, you can use the ABORT_TEST API to stop the infinitely loop of the AWG.
  • If the WAIT_TEST_DONE API is used with the START_TEST API, it starts to count the timeout from the beginning of the execution of the START_TEST API. The WAIT_TEST_DONE API can also be used with the DIGITAL_CAPTURE_TEST, FUNCTIONAL_TEST, SEQUENCER_STATUS and SPEC_SEARCH APIs. In this case, it starts to count the timeout from the end of the execution of these APIs.
  • If the stop on error mode (activated with WAIT_TEST_DONE) is set and any tools (in particular the Pattern Explorer) are open, the following warning may be displayed:
    WARNING: Current digital sequencer run will be interrupted. To avoid this warning,
please wait for sequencer run completion or abort test prior to issuing setup commands.
To identify the source of the setup error, use 'DIAG 108' to change this warning into an error.

    To run a pattern you have to close all tools.

Examples

Example 1

This example executes two test executions; the first is by the EXECUTE_TEST API and the second is by the START_TEST API. During the second test execution, the DSP_SND API calculates the SND in parallel from the first test's result between the START_TEST and WAIT_TEST_DONE APIs.

  INT timeout_flag;
  ARRAY_D AnaWave1, AnaWave2;
  double snr_result, spower, n_power;
    :
 //Execute a test with primary analog set
  EXECUTE_TEST(0.1 sec);

  //Retrieve first measurement result
  AnaWave1 = Analog.DGT("Aout").getWaveform();

  //Change primary analog set to #2
  Analog.primary(2);

  //Execute a test with primary analog set #2
  START_TEST();

  //Calculate SND from first
  //measurement result
  DSP_SND(AnaWave1, &snr_result, &spower, &n_power, 
          1, 0.0, 0);

  //Wait to complete a test and calculation
  WAIT_TEST_DONE(0.1 sec, &timeout_flag);

  //Retrieve second measurement result
  AnaWave2 = Analog.DGT("Aout").getWaveform();

Example 2

Wait and abort the test execution when a digital compare failure has been detected on either pinA or pinB.

WAIT_TEST_DONE(TM::ABORT_ON_FAIL_ANY_PIN, "pinA, pinB");

Example 3

Wait and abort the test execution when digital compare failures have been detected on both pinA and pinB.

WAIT_TEST_DONE(TM::ABORT_ON_FAIL_ALL_PINS, "pinA, pinB");
