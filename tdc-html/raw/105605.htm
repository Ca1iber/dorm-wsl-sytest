GPIB communication flow for Synax handlers

This section describes the communication between the driver and the handler. The actions and messages are listed in the sequential order in the table below.

See Conventions for GPIB communication for descriptions of the syntax.

GPIB communication flow for Synax handlers

Message from driver

Message from prober

Comment

init: <running query>

 

 

Running query: FR?

n

Query whether handler is running. Handler returns 0 or 1.

wait for devices: [<SRQ>] <poll>

 

Based on the configuration parameter waiting_for_parts_method, the driver will either wait for an SRQ or poll for the current site population.

SRQ

SRQ(0x43)

Handler sends test start SRQ.

Poll:

FULLSITES?

 

FULLSITES n

Handler returns bit coded site population.

bin devices:

BINON:n

ECHO:n

Bin the devices. n represents the bin code string for all the sites, like "xxxxxxxx,xxxxxxxx,xxxxxxxx,xxxxxxxx". The first character is the Site 32's bin code, and the last character is the Site 1's bin code.
