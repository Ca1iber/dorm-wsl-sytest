DpsConnectivity

This test method checks that the DPS force and sense wires are correctly connected to the DUT board. The two two-wire connections are also known as "Kelvin connection". The performed test is known as "sense connection test" or as "Kelvin test".

The force voltage is set to 0 V and then a test current of 5 µA is forced on the sense line. The force and sense voltages are then measured:

  • if a connection exists at the DUT between the force and sense lines, then the voltage difference between the two lines will be almost 0 V and a PASS result is returned
  • if no connection exists, then the 5 µA test current can only flow through the internal force to sense resistance (see the figure below) and will cause a higher voltage difference between the two lines. A FAIL result will be returned.

    Note Other test head cards will utilize other test methods and hardware to check the Kelvin connections but the structure of the test is always the same as shown above: A test current is forced via the Kelvin connection. The voltage difference between the two tested lines is measured and the result is used to judge the Kelvin connection.

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

Parameters

dpsPins

PinString

DPS pins or DCScale pins in DPS mode to be measured, separate by comma.

testName

string

The test names to be used as limit. You can:

  • Use the test names defined in the test table or testflow limits. Type in the test names manually. Make sure these test names are in the Test name column of the test table (Refer to Structure of a TMLimits CSV file) or in Test Name column of Tests page of Flow Data Editor.
  • Define new test names. After that you need to add the defined test names (limits) to the test suite. (Refer to Adding a limit in the Properties view and Adding a limit on the Tests page.)

To specify different settings for different pins or pin groups, separate them with commas.

output

string

Controls how to output the per pin test result. It can be:

  • None: Do not output the per pin result.
  • ReportUI: Output all the per pin result to the report window.

ShowFailOnly: Only outputs the failed pin result to the report window.

samples

int

Controls how many samples are used to perform the measurement.

The default value is 1. The valid value range is (1,128).

Limits

If you define new test names in the parameter testName, you need to add limits to the test suite with the same test name. For more information refer to Adding a limit in the Properties view and Adding a limit on the Tests page.

Implementation pseudo code

IF connected THEN
  disconnect DUT
ENDIF
do force/sense check with FW PDMM
datalog test results
