Vector variable configuration usage

The VVC defines one or more frame source templates and mappings from 0,1 to waveform DC/DC power units. It is not tied to any label, and also says nothing about the number of frame source blocks to be created. Furthermore, the variables used in the VVC are a kind of template, which must be instantiated by genuine vector variables. Therefore every VVC must be supplemented by a vector variable configuration usage (VVCU).

The VVCU

  • connects the VVC to a label,
  • determines how many frame source blocks this label is to contain, and
  • converts the abstract variables of the VVC into real vector variables.

If the source label is a separate DSRC label, the VVCU allocates the space for the required number of vectors. If the source label is the main label (flat setup), this space must already have been defined. Conversely, if the VVCU is deleted and the label is a DSRC label, then the vector area for this label will be reduced to 0.

Multiple VVCUs can be defined for the same combination of VVC and label. Each VVCU creates different vector variables for the abstract VVC variables The source data blocks of the second usage will be appended to those of the first VVCU. The order is determined by a further VVCU parameter called Offset. This parameter specifies the logical vector of the source label at which the first frame source block of the respective VVCU begins. The first VVCU starts at offset 0, the second at vector m*n, where m is the length of the frame source template, and n the number of frame source blocks created by the first VVCU. The benefit of this is that you can manipulate the source data of the second VVCU independently of those belonging to the first VVCU, because they define different vector variables.

The same effect can be obtained by using several VVCs for the same label and associate each of these with only one VVCU. The order of the VVCUs will again be determined by their Offset parameter. Note that in this case the source data templates of the different VVCs must contain the same number of sections, and that corresponding sections must have the same size. For an example of this construction see Making use of the Offset parameter.

Note The GUI only admits the second option. It does not support the definition of several VVCUs for the same VVC.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 6.5.2: For each VVC, only one VVC usage can be defined in the GUI. You needn't define the mapping between VVC variables and the vector variables in the VVC usage.
