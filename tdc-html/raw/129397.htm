Topic 129397

BfdGenerator()

The constructor of the BfdGenerator class lets you create new BfdGenerator objects.

In setting up a new BfdGenerator object, you supply it with a name and comment, the dimensions of the tested device, and encoding specifications.

Creating the object automatically creates the bit fail map file at the specified location. If additional bit fail maps are later added using the addFailmap() function, the file is updated.

Syntax

BfdGenerator(const string& filename, const string& file_comments, long xBits, long yBits, long zBits, long dBits, const char encoding_sequence, enum encoding_mode, long toc_reserve);

Parameter

Description

file_name

The name under which the bit fail map file generated by the BfdGenerator object member function is to be stored.

file_comments

Comments regarding the bit fail map (for example, a description of the testing conditions).

The comments will be stored in the comments section of the bit mail map file.

xBits

The size of the tested device in the x-dimension, in bits.

yBits

The size of the tested device in the y-dimension, in bits.

zBits

The size of the tested device in the z-dimension, in bits.

dBits

The number of data bits (pins) of the device.

encoding_sequence

A four-character string describing the order in which the device dimensions are serialized.

For example, "dzyx" means that the data is presented in x-data chunks. These chunks are listed in the file first by the d-values, then their z-values, and then their y-values.

The default value is "dzyx".

encoding_mode

How the data is encoded in the file:

  • BINARY_ENCODING
  • ASCII_ENCODING

The default value is BINARY_ENCODING.

toc_reserve

The number of bytes to reserve for the table of contents (TOC) in the file header.

This is an optional parameter; the default value is 4096 (0x1000).

We recommend that you do not change this default value.

See the examples in BfdGenerator.
