Delay Binning I: Overon Enable

If you activate the Overon flag in the relevant bin, any failing devices are assigned bin details (bin code, bad part, bin number, and so on) but are not switched off (that is, no SQST OFF command is given) until a failing device enters a bin that does not have the Overon flag activated, later in the flow.

Points to Note

  • The failing part continues to be tested for the remaining tests, unless it lands in another bin and is de-activated. However, even though it may fail further tests, it is still assigned the bin that it first landed in.
  • Ensure that the use of the Overon flag does not conflict with its use as a debug tool.
  • Using the Overon flag complicates the testflow. You must, therefore, be careful to maintain consistency and be able to predict what effect using it will have.
  • The failing site will continue to be tested, possibly even to the end of the flow. This could have a negative effect on the test time if:
    • there are serially executed tests in the flow
    • there are match loops that might fail to match if the part fails the test where Overon was set
    • the testflow has branches, as the failing part might take off down a branch that would not otherwise have been taken by any of the other parts

In such cases as those outlined above, Solution II - Assign Variables to Failing Parts may provide an alternative.
