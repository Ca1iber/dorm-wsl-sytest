Implementing protocol based tests to the test program

Subtopics

  1. Example: Writing a protocol based UTM without using protocol wrapper

This sections lists the requirements and steps necessary to implement protocol based tests to your test program.

The description is kept general by purpose as the corresponding example will be more detailed.

Preparation

  • Define device pins, that are not used with the protocol, in an individual or multiple ports.
  • Create a vector sequence that will run on the non-protocol ports while the protocol's multiport bust is executed.
  • Create a multiport burst pattern that includes the non-protocol port(s) and corresponding vectors sequence only.
  • Use a UTM project, if not already done, create one following the description of How to create a universal test method project.

Adding a protocol based test to a testflow

  1. Create a UTM class as described in How to create a universal test method class.
  2. Enter your protocol based test code.
    1. Create one protocol based test object per protocol, passing the required parameter to the object: (protocol's) port name
    2. Add optional parameter if required: multiport burst pattern of the non protocol ports, wavetable and a custom protocol's pattern label.

      SYNCHRONIZED_TEST <ProtocoltestObject>(<"protocol'sPort">, <"non-protocol multiport burst pattern">, <"wavetable">, <"ProtocolPatternLabel");

    3. Add a transaction to the object with the parameter values defined in the protocol definition.

      ProtocoltestObject.transaction(<"TransactionName">).set(<"parameter1">, <"Parameter1Value">).set(<"parameter2">, <"Parameter2Value">).set(<"parameter3">, <"Parameter3Value">);

    4. Complete protocol based test definition by using the .flush() function of your object.

      ProtocoltestObject.flush()

    5. Perform a functional test to start the digital seqencer.
    6. Unlink the generated protocol bust label from the non-protocol multiport bust, to make it available to other transactions.

      SYNCHRONIZED_TEST::unlink("ProtocolPatternLabel", "non-protocol multiport bust pattern");

  3. Build your project and debug it if necessary as outlined in How to create a universal test method class.
  4. Add your protocol based test method to a test suite as described in How to create and execute a universal-test-method-based testflow.
