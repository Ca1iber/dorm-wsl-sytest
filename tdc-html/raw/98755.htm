SSAC, SSAC? - (Source Synchronous testing: Add Configuration)

The SSAC command defines the pins whose associated channels are to be used as buffers for source synchronous testing. It mainly specifies the read mode and the number of results that are to be stored in the channel.

Note Rapid source sync is not supported on the EXA Scale test systems. SmarTest will give the following error: "ERROR: SSAC - RSS is not supported on EXA Scale machine type." and the execution of SSAC is blocked if used while running on this system.

The read mode defines whether the data of the channel is inverted by the SSCT command before it is processed. This is necessary, for example, for the source buffer channel in order to get an accumulated PASS result with SSCT if only one of the source channels contains PASS. For details see Exploiting hardware resources for performance enhancement.

The number of results can be specified explicitly or by defining a reference pin. The intended application of the latter option is to run a preliminary functional test for the pins to be tested in order to determine the required memory size. In a second step, the buffer channels are then configured by reference to one of these pins. This is the recommended way to define the buffer size.

Note that certain restrictions exist with respect to the location of the channels that are used as buffer channels. For details see Hardware restrictions for result accumulation.

The SSAC? query returns the configuration of the specified buffer pins.

SSAC

SSAC [read_mode],[nr_of_results],[(ref_pin}],{(pinlist)}

SSAC?

SSAC?

returns:

SSAC {read_mode},[nr_of_results],[(ref_pin}],{(pinlist)}

Parameters

read_mode

Possible read modes are:

NORM

Channel data is processed as it is stored in the source channels. This is the default.

INV

Channel data is inverted internally before it is processed. The channel data itself is not changed.

nr_of_results

Specifies the size of the area to be used for buffering cycle/edge data for source synchronous testing. If this parameter is omitted you must specify a reference pin.

The number to be specified here must be calculated as

result_granularity * number_of_cycles.

The result granularity is the number of results per cycle. It can be 1 (one global result), in which case you must specify the number of cycles, or 8 (one result for every edge), in which case you must specify 8 * number_of_cycles.

The number of bytes required to store the specified number of results must be a multiple of 8. If this requirement is not satisfied, the number of results will be auto-corrected.

ref_pin

The pin that defines the size of the buffer area. If this parameter is omitted, you must specify the number of results. If a reference pin is defined, the nr_of_results parameter is ignored.

pinlist

The pins that are to be configured as buffer pins.

Errors

An error is generated if the requested number of results exceeds the available result area size.

Rapid source sync is not supported on the EXA Scale test systems. SmarTest will give the following error: "ERROR: SSAC - RSS is not supported on EXA Scale machine type." and the execution of SSAC is blocked if used while running on this system.

Example

The following example shows how the buffer channels are configured by using a reference pin: 

> DCGM ALL,STRT,NONE
> DCRT RAM,(@)
> SSRC (@)
> SVLR TIM,1,1,"sweep",2.4
> FTST?
> SSAC INV,,(D1),(SB)
> SSAC NORM,,(D1),(G1,G2)
> SSCT IMM,NORM,,(SB),(D1,D2,D3,CL)
> SSCT ACC,NORM,,(G1),(SB)
> SVLR TIM,1,1,"sweep",2.5
> FTST?
. . .

First the detailed Error Map is configured for source synchronous testing (recording mode ALL, location in RDRAM). Next the existing buffer configurations are removed. Then the sweep variable is set, and the first functional test executed. Subsequently the buffer channels are configured using D1 as the reference pin. Then the results of the first functional test are processed. Finally, the sweep variable is incremented and the next functional test executed.
