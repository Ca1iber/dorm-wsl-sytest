Topic 81300

DpsStatus

This test method allows you to check the status of the DPS channels after executing a functional test.

It checks for various DPS states, and returns a pass/fail result. You can choose which states will cause a failure from the following list:

  • Constant Current
  • Unregulated
  • Overvoltage
  • Overtemperature
  • Overpower

This test method supports test table. But you need to enter the test names manually in the parameter. You can use both test table and testflow limits in a testflow. The test table has higher priority than testflow limits. If a test name used in the test flow is defined in both test table and testflow limits, the value defined in the test table will be used.

Dependencies

  • Some states force the DPS channels to High-Z. To return to normal DPS operation, disconnect and then connect the DUT.
  • In the overvoltage state, the DPS channels are disconnected and not initialized. Before continuing, you must disconnect and then connect the DUT.
  • If a Power-On, a programming, or an overtemperature error occurs, you must disconnect and then connect the DPSs before continuing.
  • If the DPS status becomes unregulated, any testflow currently being executed stops
Parameters

Parameter

Type

Description

dpsPins

PinString

pins to be tested. This can be @ for all applicable pins, or any number of applicable single pins.Valid pin types include DPS pins.

constantCurrent

string

Checks whether DPS is in the constant current state. It can be:

ON - check

OFF - Do not check

unregulated

string

Checks whether DPS is in the unregulated state. It can be:

ON - check

OFF - Do not check

overVoltage

string

Checks whether DPS is in the overvoltage state. It can be:

ON - check

OFF - Do not check

overPowerTemp

string

Checks whether DPS is in the overpower/overtemperature state. It can be:

ON - check

OFF - Do not check

protect

string

UHC4T only!

Checks whether UHC4T is in the protect state. It can be:

ON - check

OFF - Do not check

testName

string

The test names to be used as limits. Default is DPS_Status.

If you want to use the test names defined in the test table or testflow limits, type in the test names manually. Make sure the test names are in the Test name column of the test table (Refer to Structure of a TMLimits CSV file) or in the Test Name column of Tests page of Flow Data Editor.

output

string

Controls how to output the per pin test result. It can be:

  • None: Do not output the per pin result.
  • ReportUI: Output all the per pin result to the report window.

ShowFailOnly: Only outputs the failed pin result to the report window.

Limits

DPS_Status

It is only used to enter the test number.

Implementation pseudo code

IF not already connected THEN
 connect DUT
ENDIF
check DPS status with specified requirement
datalog test results

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 6.5.0: Change parameter type of dpsPins to PinString for UTM library.
  3. SmarTest 7.0.3: Classic test method library is removed.
  4. SmarTest 7.1.1: Test table is supported in TML 2.1.1.
  5. SmarTest 7.1.1: Mixed usage of test table and testflow limits in one testflow is supported in TML 2.1.1.
  6. SmarTest 7.1.1: New parameter testName is added in TML 2.1.1.
  7. SmarTest 7.2.1: New option ShowFailOnly for the parameter output in TML 2.2.0.
  8. SmarTest 7.3.2: New parameter: protect for UHC4T
