GPIB communication flow for Rasco handlers

This section describes the GPIB communication between the driver and the handler. The actions and messages are listed in the sequential order in the table below.

See Conventions for GPIB communication for descriptions of the syntax.

GPIB communication flow for Rasco handlers

Message from driver

Message from handler

Comment

init: <id request> <configuration>

 

 

ID request:

ID?

"string"

Driver asks for handler ID.

Handler returns ID.

configuration: <temperature setup>

 

Send at startup and after each driver reconfiguration at runtime.

temperature setup:

:TEMP:SETPOINT OFF

:TEMP:SETPOINT <value>

 

One of the following communication flows applies according to the setting of the configuration parameter temp_control:

"manual": no commands are send to the handler.

"ambient": disable temperature controls.

"active": the command is sent to the handler to set the setpoint in specified zone to the given value in Celsius.

wait for devices: [<SRQ>] [<poll>]

 

 

 

Based on the configuration parameter waiting_for_parts_method, the driver will either wait for an SRQ or poll for the current site. If an SRQ is received, polling is still done afterwards in cases where:

not all active sites that are active based on the configuration parameter handler_site_mask seem to be populated;

or there are no SRQs received during the time frame defined by parameter flag_check_interval.

Waiting for devices repeats, until there is a device to test.

site_mapping

temperature_setpoint

temperature_soaktime
