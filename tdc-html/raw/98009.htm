Data logging profile rule syntax

A data logging profile consists of a number of rules with the following format:

<Test suite>.<Test method>.<Test identifier>.<Property> = <Value>

The expressions in angle brackets have the following meaning:

 

Options

Examples

Test suite

ts:<test suite name>

g:<group name>

ts:*DC_TEST*

g:Functional

Test method

<test method name>

Run_Func*

PLL_freq

Test identifier

name:<test name>

 

num:<test number pattern>

bin:<bin name>

name:LeakageH

name:PUT_DATALOG

num:[1-100,200,600-700]

bin:bad*

Property

<flag name>

<property name>

<user defined property name>

log_events_enable

datalog_level

myErrorThreshold

Value

<property value>

1

3

30
  • Every expression can be a shell wildcard pattern, for example, te?t; te*; te[a-z]t.
  • The sequence of the rules in a data logging profile is relevant: SmarTest evaluates the rules from the first to the last, stopping whenever it finds a matching rule. (That is, rules coming after a matching rule are ignored.)
  • If you use name:<test name> or num: <test number pattern>, you must use the TEST_SET API in your test method to calculate the values for the test name or test number.
  • If you use bin:<bin name>, you must use the SET_MULTIBIN API in your test method to calculate the values.
Example data logging profile

Rule

Explanation

*.*.*.log_events_enable = 1

Sets the log_events_enable system flag to on.

*.*.*.datalog_level = 3

datalog_level is a convenience property; see the System properties table, below, for details.

*.*.*.datalog_detail = 2

datalog_detail is a convenience property; see the System properties table, below, for details.

ts:gross_func_p2.*.*.ffc_enable = 1

Sets the ffc_enable flag of the gross_func_p2 test suite to on.

*.*.num:900-910.myErrorThreshold = 1024

Sets the user defined property my.ErrorThreshold to 1024 for tests with test numbers between 900 and 910.

ts:TestSuiteA.*.name:PUT_DATALOG.output_on_pass=1

Ensures that in TestSuiteA all PUT_DATALOG messages are output when the test passes.

System properties

These are the properties you can choose in the Properties list box of the Profile Editor:

Properties

Explanation

log_events_enable

Sets the system flag log_events_enable, value: 0=off, 1=on

datalog_level

Convenience property that sets the following test suite flags:

  • output_on_fail
  • output_on_pass

Values:

  • 0 = no output
  • 1 = output on fail only
  • 2 = output on pass only
  • 3 = output on fail and pass

Use this property together with datalog_detail.

datalog_detail

Convenience property that sets the following test suite flags:

  • fail value
  • pass value
  • per_pin_on_fail
  • per_pin_on_pass
  • ffc_enable
  • frg_single_shot
  • H/L/I/U (multiple execution)
  • ffv_enable

Values:

  • 0 = log pass/fail
  • 1 = log per-pin pass/fail
  • 2 = log per-pin with values
  • 3 = log per-pin with first failing cycle (FFC) info
  • 4 = log per-pin with fine result granularity (FRG) info
  • 5 = log per-pin with first failing vector (FFV) info

Use this property together with datalog_level.

Note that the settings 4 and 5 are not compatible with test suites that execute protocol-aware tests.

output_on_pass

Sets the test suite flag output_on_pass, value: 0=off, 1=on

output_on_fail

Sets the test suite flag output_on_fail, value: 0=off, 1=on

ffc_enable

Sets the test suite flag ffc_enable, value: 0=off, 1=on

ffv_enable

Sets the test suite flag ffv_enable, value: 0=off, 1=on

frg_enable

Sets the test suite flag frg_enable, value: 0=off, 1=on

Note that the this flag must be set to 0 for test suites that execute protocol-aware tests.

frg_single_shot

Sets the test suite flag frg_single_shot, value: 0=off, 1=on

Note that the this flag must be set to 0 for test suites that execute protocol-aware tests.

log_mx_waveforms

Sets the test suite flag log_MX_waveforms (Log mixed signal waveforms), value: 0=off, 1=on

User defined properties

You can define your own properties, which can be used in test methods by the Property class. Thus you can, for example, control the flow of a test suite.

For a description of the Property class and its member functions, see Property class.
