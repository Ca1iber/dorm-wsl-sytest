Topic 105694

Redundancy analysis

Subtopics

  1. Setting up and performing a redundancy analysis
  2. Redundancy analysis algorithm

Redundancy analysis evaluates memory test results to see if failed DUTs can be repaired by substituting built-in spare cells for failed cells. If there are repair possibilities, one of them is suggested.

Performing the redundancy analysis

Redundancy analysis can be performed as part of a test flow (using the ExecutionEngine test method) or separately (using the RaServer utility).

The analysis is configured using a setup file and, if the test method is used, also using the test method parameters. It also requires a DUT representation file to describe and set up the device. You can choose the algorithm used in the analysis (see below).

The redundancy analysis results include information on whether the DUT can be repaired and a proposal for reassigning resources to repair it.

Redundancy analysis algorithm

A standard algorithm - the Successive algorithm - for analyzing the test results is supplied with MTP; users can substitute their own algorithms if they so desire.

The Successive algorithm is site-independent and can be used to analyze multiple sites simultaneously by creating an algorithm object for each site.

The algorithm is configured through various parameter files so that no recompilation is necessary if settings are changed. The algorithm also is independent of address conversion routines for mapping physical addresses to topological addresses.

The redundancy analysis framework also supports certain legacy algorithms (those implementing the repair_start, test_start, test_log, test_end, and repair_end functions). The shared libraries compiled from such algorithms can be specified as the redundancy analysis algorithm.

If such legacy algorithms are used, site-independence, independence of address conversions, and reconfiguration without recompilation are not available.

Note Legacy algorithms (written for MTP versions older than MTP on SOC 103.0.0) can be used in multiple test suites within the same test flow as long as they use static global variables. A script for recompiling legacy algorithms is provided at /opt/93000mts/mts/rr/lbin/cc_ra.sh.s.

Functional changes
