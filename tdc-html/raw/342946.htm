Troubleshooting third-party plug-ins

Checking the configuration in the custom file

Make sure that the configuration in the custom file is as illustrated below:

  1. Open the custom file from the following location:

    /opt/hp93000/soc/segments/eclipse/eclipseRE/links/custom

    or enter the following command to view its contents:

    $less /opt/hp93000/soc/segments/eclipse/eclipseRE/links/custom

    The following configuration should be present:

    path=/opt/hp93000/soc/segments/eclipse/custom
optional=true
  2. If the current configuration is not as illustrated, make the appropriate changes and save the file.

Checking the link to the SmarTest path

  1. Check that the link in the /opt/hp93000/soc/segments/eclipse/custom/eclipse/plugins file is pointing to the correct SmarTest installation path.
  2. Check that the appropriate permissions to read the specified file path are available.

Clearing the Eclipse configuration cache

To erase the Eclipse configuration cache, execute the following command:

rm -rf ~/.eclipse/com.verigy.itee.ui.ewcProduct_*

Force check for new plug-ins

Eclipse checks for new plug-ins during the first startup after deleting the .eclipse/com.verigy.itee.ui.ewcProduct_* directory. If it appears that the check is not being made, force it by exporting the following environment variable before starting SmarTest:

export XOC_EWC_TESTSET=-clean

Note Exporting the XOC_EWC_TESTSET environment variable this is not generally recommended, as each subsequent SmarTest start is slowed due to Eclipse re-reading the configuration data and re-checking the installation.
