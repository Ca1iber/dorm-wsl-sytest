Defining waveform shapes

Subtopics

  1. Defining waveform shapes for Pin Scale standard pins
  2. Defining waveform shapes for Smart Scale pins
  3. Defining the break waveform
  4. Handling waveform definitions at the firmware level
  5. Representing a pattern in device orientation

A waveform shape is an ordered sequence of actions each of which is associated with an edge. The edges are divided into drive edges and receive edges. Drive actions are associated with drive edges, receive actions with receive edges.

Every waveform shape is associated with a numerical index. It is this index, not the waveform itself, which is stored with the pattern (label) in the vector areas. The waveform shapes are stored only once in a physical waveform table which is located in the Sequencer Memory. When the test is executed the physical waveform DC/DC power units are resolved into waveforms by looking up the physical waveform table.

Within a wavetable, there are basically two different formats for defining a waveform shape.

Standard format

In this format, a waveform shape is defined by a sequence of edge-action pairs. You can also add a name for the shape. For details on the definition of Pin Scale pins see Defining waveform shapes for Pin Scale standard pins.

Smart Scale pins provide two different kinds of drive edges. For details see Defining waveforms for Smart Scale pins.

Format without edge specifications

In this format the shape consists of a sequence of actions. The edges with which these actions are associated are selected by SmarTest. In most cases, the number of the edge that is associated with an action is determined by the position of the action within the sequence.

Defining waveform shapes for differential pins

The waveform shapes for differential pairs can either be defined separately for the two legs, or you can add the diff@ operator to the PINS section for the positive pin, in which case the definitions for the negative pin will be generated automatically by inverting the waveform shapes for the positive pin.

Note that with differential receive pins, the definitions for the negative pin are ignored on all systems. This holds for both coding formats.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 6.5.2: Logical waveforms are no longer supported.
