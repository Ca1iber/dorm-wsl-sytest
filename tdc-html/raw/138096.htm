Factory preset recipe file

Factory preset recipe file is used to store the common data log variables and consolidate the paths of the data log files and the lot summary files. As shown in the example section, it contains the following elements:

  • (optional) validate: specifies how to validate the code before loading the testflow. This is used to prevent loading a wrong recipe file or a wrong testflow file. The following three types of validation are supported:

    none: no validation is done.

    user_compare: specifes the value to be entered before loading the testflow.

    popup_script: specifies the script to be executed before loading the testflow. The script is used to generate the validation code.

    If user_compare or popup_script is used, a dialog will pop up asking you to enter the validation code when you load a testflow or recipe file. If you enter the same value as defined in the recipe file or generated by the script, the testflow or the recipe file will be loaded. Otherwise, an error message will be shown in the dialog. The testflow or the recipe file will not be loaded until you enter the correct value.

    Note The validate setting in the user-defined recipe file has higher priority than the validate setting in the factory preset recipe file.
  • datalog: specifies the data log related settings.
    • lot_variable: specifies the values for the common data log variables.
    • file: specifies the path and the name for the STDF data log file, text data log file and lot summary file to be generated by the Test Cell Control Tool (TCCT).

      The following variables can be used to specify the name and the path of the output data log file and the lot summary file. In the real name of the files, they will be replaced by the value of the variables at that moment.

      The variables related to lot information, including PART_TYP, TST_TEMP, TEST_COD, LOT_ID and OPER_NAM

      The system variables, including HOSTNAME, USER and LOGNAME

      Others: DEVICE_PATH, DEVICE_NAME, TESTFLOW_NAME and TIMESTAMP

      Note DEVICE_PATH can be used to specify the path but not the name of the file. To avoid the confliction among the name of files, a TIMESTAMP will be automatically added in the file name if it is not used.

The location of the file is /etc/opt/hp93000/tcct/factory_preset_recipe.xml. You can use the root user authority to modify the content of the file. Changes to this file will take effect when you restart TCC.

Example

<?xml version="1.0" encoding="UTF-8"?>
<recipe>
  <validate type= "popup_script" value="/home/demo/tcct/recipe/md5checker#{testflow}"/>
  <datalog>
    <lot_variables>
      <variable name="TST_TEMP" value="25C" />
      <variable name="TEST_COD" value="FT" />
    </lot_variables>
    <file path="/tmp/datalog/" name="datalog_{HOSTNAME}_{LOGNAME}_{LOT_ID}_{TIMESTAMP}">
      <stdf enable="true" ext="stdf" />
      <text enable="true" ext="txt" screen="true" />
      <summary enable="true" ext="sum" whichtest="all_test" persite="true" screen="true" />
    </file>
  </datalog> 
</recipe>

Functional changes

  1. Introduced in SmarTest 7.2.0
  2. SmarTest 7.2.0: in patch 2, supports validate tag in TCCT 1.2.
