Topic 116890

JSCF, JSCF? - (Jitter Set ConFiguration)

This command serves to define and query the jitter injection for the specified pins. The specified jitter set must have been defined with JSDF. For more information see Principles of jitter injection.

Note that there are certain incompatibilities between the properties that can be defined with JSCF. The MODULATION_SETS property excludes all the other properties except MODE. For more information see Two ways of organizing jitter setup data.

With this command you configure setups of those sites that have the setup focus: For more information, see also: PSFC, PSFC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

JSCF

JSCF {"jitter_set_name"}, {"property"}, {"property_value"}, {(pinlist)}

JSCF?

JSCF? {"jitter_set_name"|ALL|PRM}, {"property"|ALL}, {(pinlist)}

returns:

JSCF {"jitter_set_name"}, {"property"}, {"property_value"}, {(pinlist)}

Parameters

jitter_set_name

Specifies the name of a jitter set that must have been defined with JSDF.

property

Specifies a property of the jitter set. For a list see the table below.

ALL

This value can be specified in the query to retrieve the configuration data of all jitter sets.

PRM

This value can be specified in the query to retrieve the configuration of the current primary jitter set.

property_value

Specifies the value for the specified property. The values that are admitted for the individual properties are listed in the table below.

pinlist

Specifies the pins to which this configuration is to be applied.

Properties and their values

Property

Explanation and values

MODE

This parameter defines the operation mode of the jitter injection. The possible values are:

OFF

No jitter injection takes place. This is the default.

CONT

Jitter injection is started with the first functional test and then keeps running until it is explicitly terminated.

RESTART

Jitter injection is stopped after every functional test and restarted with the next functional test.

MODULATION_SETS

By this parameter, you can associate one or two modulation sets with the jitter set. If two modulation sets are specified, they must be separated by a comma. In this case the name list, not the individual names, must be included by quotes.

Note also that when you specify this property, you cannot specify any of the other properties except MODE.

WAVEFORM

This parameter either (a) defines a list of offsets from the edge delays specified in the currently active timing set, or (b) selects a predefined waveform. In case (a), the list items must be separated by a comma, and the maximum number of items is 512.

 

The list items of case (a) specify the actual delays in picoseconds.

The following restrictions apply:

  • The maximum offset from the delay defined in the timing set is 200 ps in either direction.
  • If the successor in the list is smaller than its predecessor, the maximum difference max_diff between the two items depends on the clock resolution as follows:

    max_diff = clock_resolution/2 - 410 ps

The list can be used to approximate a jitter modulation waveform.

There are three predefined such waveforms (case (b)) which can be selected by the following keywords:

SINUSOIDAL

Creates a sinusoidal waveform.

RECTANGLE

Creates a rectangular waveform.

TRIANGLE

Creates a triangular waveform.

PERIODFACTOR

An integer n that defines the distance between two items of the list defined by WAVEFORM. It only applies to user defined waveforms and specifies a multiple of 2 * clock_resolution. The default for n is 1, the maximum is 1024.

The clock resolution is calculated from the period resolution, but also takes other parameters into account. Therefore a different clock resolution may be calculated from the same period resolution in different circumstances.

If you want to have complete control over the clock resolution, you must specify a period resolution not greater than 2 * minimal_clock_resolution manually (with the period_res keyword). Then the clock resolution will equal the period resolution. See also Period resolution, clock resolution, and master clock period.

PHASE

This property, which only applies to predefined waveforms, is intended to define a phase offset for the RESTART mode. This value must be specified as a degree. The maximum is 360°.

AMPLITUDE

This property determines the amplitude (that is, half of the peak-to-peak value) of a predefined waveform.

It is not applicable to user defined waveforms for Smart Scale STDDIFF pins.

The maximum is 200 ps. The default is always 100 ps.

PERIOD

This property defines the period of a predefined waveform in ps.

It is not applicable to user defined waveforms for Smart Scale STDDIFF pins.

The maximum period depends on the clock resolution as follows:

2 * clock_resolution * 1024 * 512

For clock_resolution, see the PERIODFACTOR property.

DUTYCYCLE

This property defines the ratio between the positive half wave and the full wave. It is only applicable to the TRIANGLE and RECTANGLE waveforms. The default is 50%.

NOISE

Setting this property will add random noise to every waveform. The value given with this property is interpreted as the amplitude of the random noise to be added.

The maximum amplitude is 400 ps. The default is 0.

ALLOWED_NOISE

This parameter defines the maximum step width that is allowed between two sampling points in a predefined waveform for a STD or STDDIFF pin. If this value is exceeded, an error message will be issued.

Application

Jitter injection.

Errors

An error is generated if no jitter set with the specified name exists.

Example

> JSCF? "my_J_SET",ALL,(Pin1)
< JSCF "my_J_SET",MODE,CONT,(Pin1)
< JSCF "my_J_SET",WAVEFORM,"-100,-50,0,50,100,50,0,-50",(Pin1)
< JSCF "my_J_SET",PERIODFACTOR,25,(Pin1)

This example defines a simple sawtooth waveform with a peak-to-peak value of 200ps for a STDDIFF or STD pin.

Functional changes

  1. Introduced in SmarTest 7.0.1
  2. SmarTest 7.1.1: WAVEFORM parameter SINUS changed to SINUSOIDAL
  3. SmarTest 7.3.0: The MODULATION_SETS property was added.
  4. SmarTest 7.3.1: User defined jitter waveforms are now supported for FASTDIFF pins.
