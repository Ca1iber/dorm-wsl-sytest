Topic 29695

UTI_PURPOSE_I

The member function of the UTI_PURPOSE_I class applies the utility purpose specified by the uti_purpose member function of the ROUTING_STATUS API because the UTI_PURPOSE_I class is always called as the subsidiary data container of the ROUTING_STATUS API. Therefore, the UTI_PURPOSE_I class does not have a constructor. For related topics, see ROUTING_STATUS - (Routing).

If you described multiple Routing.uti_purpose statements, the settings of the Routing.uti_purpose statements are sequentially stored in the Message Concentrator and Distributor (MCD) once temporarily, then all the settings are downloaded to the hardware in parallel when the next Execution API or FLUSH API is executed. At this time, the Execution API or FLUSH API waits the longest settling time of all the utility purposes specified in the pin configuration after controlling the utility lines. For the MCD, see the manual Command Reference.

This class is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/UtiPurposeI.h.

Class definition

Member Function:

 void set();

Member Function

set()

void set();

This member function applies the specified utility purpose.

Important Points

  • Do not use this API between the FOR_EACH_SITE_BEGIN and FOR_EACH_SITE_END.
  • See also the "Important Points" of the UTIL_I.

Example

Routing.uti_purpose("ALL_ON").set();

The member function applies the settings of the utility lines in the utility purpose "ALL_ON" defined in the Pin Configuration.

Functional changes

  1. Introduced before SmarTest 6.3.2
