Hidden upload

SmartCalc automatically determines the package size of data to be uploaded to the test system controller. It performs an optimized upload behind a currently running test (sequencer execution).

Uploading the packages are done by SmartCalc APIs, which know start and end times of sequencer executions. These are required in order to upload data during the currently running test. This technique is called hidden upload, as the upload is hidden behind the sequencer execution of the next test.

For this, the upload task has to be part of the SmartCalc (SMC) section of a test method. SMC then manages the uploads automatically whenever it does not effect the throughput of the main test flow.

The size of a package depends on the estimated sequencer run time of the next test. It is calculated with the goal to use 100% of the sequencer run time. Therefore SMC can bundle smaller or split bigger packages automatically.

While executing a test flow, SmartCalc automatically measures and caches the sequencer execution time for each test execution. The cached value is dynamically compensated for one subsequent execution of the same sequencer run. The optimal upload package size depends on the predicted sequencer execution time. After the upload is completed, the system returns to the default packet size or to the user package size, if specified.

The SMC predicted sequencer execution time can be overwritten by SMC_SET_TEST_EXECUTION_TIME(). It allows to set the sequencer execution time of the next test to a user defined value and to control whether the upload should continue after the predicted execution time has elapsed, but the sequencer is still running. This function can be used if the automatic algorithm cannot calculate the execution time precise enough, for instance if Match Loops are used.

Note For FPGA compatibility refer to service note E8001-140611A when using hidden upload with MBAV8+
Note

Hidden uploads, controlled and started by SMC_ARM() must be finished before a Mode context is changed.

For changes of the Mode context within a test suite, we recommend calling the API SMC_SYNCHRONIZE_WITHOUT_BINNING() before the Mode context is changed.

For changes of the Mode context over several test suites, we recommend inserting a new test suite with no level-, timing-, or pattern-information defined and assigning the system-prepared test method smartCalc.SMC__SYNCHRONIZE.

Functional changes

  1. Introduced in SmarTest 6.5.3
  2. SmarTest 7.2.0: Default behavior of SMC changed to automatically determined optimized package sizes.
  3. SmarTest 7.2.1: FPGA compatibility needs to be ensured.
