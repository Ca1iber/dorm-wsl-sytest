Topic 345251

rdi.alarm().check().execute()

Adds an alarm checking event in any position inside an RDI_BEGIN-RDI_END block.

Syntax

rdi.alarm().check().execute();
rdi.alarm("ID").check().execute();

When you use this command to add an alarm checking event, its position must be inside an RDI_BEGIN-RDI_END block. This command will automatically insert an alarm checking event in the burst after the previous measurement.

This command requires the usage of port for multiport bursts, for example:
rdi.port("portA").alarm().check().execute();
Note This command can be impacted by the alarm-checking-enabled or -disabled status. In the alarm-checking-disabled status, this command will do nothing.

When the alarm() specified with an ID, if there is no other measurement in the RDI_BEGIN/RDI_END block, this ID can be used to retrieve the alarm pass or fail result on a pin or the general alarm pass or fail result on all pins.

Example

Alarm check per result ID

RDI_BEGIN();
  rdi.dc().pin("A").vforce(1)...
  rdi.alarm("id1").check().execute();
  rdi.dc().pin("B").vforce(2)...
RDI_END();

rdi.id("id1").getAlarmPassFail();    // result from all pins
rdi.id("id1").getAlarmPassFail("A"); // result from pin A

See also the example in Alarm handling commands.

Functional changes

  1. Introduced in SmartRDI 7.5.0
  2. SmartRDI 7.6.0: Alarm check per result ID.
