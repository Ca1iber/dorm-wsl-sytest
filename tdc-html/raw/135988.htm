Topic 135988

Recipe file

Subtopics

  1. System library for recipe

The recipe file includes the following elements. The format of the recipe file is shown in the example section below.

  • recipe: This is the root element of a recipe file.
    The auto_start_lot attribute can be used in the recipe element to enable the automatic startup of lot testing. For example, 
    <recipe popup_newlot_dialog="false" auto_start_lot="true">
   ...
</recipe>

    When the current lot test is automatically done, the next lot will be automatically started. If the current lot test is manually ended, the next lot needs to be started manually.

  • smartest: specifies the settings to start SmarTest. If a SmarTest session has already been started, this element will shut down the session and start a new session with the specified settings. The settings to start SmarTest in the Production configuration file will be ignored if the settings are also specified in the loaded recipe file.
    • version: specifies the SmarTest version to use.
    • tml_version: specifies the version of test method library to use.
    • mtp_version: specifies the MTP version to use.
    • startup_mode: specifies the start-up mode. It can be offline or online.
    • user_mode: specifies the user mode. It can be supervisor, engineer or operator.
    • model_file: specifies the model file to use. You can also use the environment variable V93000_MODEL to specify the model file.
    • env: specifies the variables used to start SmarTest, for example, V93000_MODEL to specify the model file.
    • rdi_version specifies a SmartRDI version to be used in the recipe file.

    The smartest element has the force_restart attribute: If it is set to true, SmarTest is always restarted before the recipe is executed. If it is false, SmarTest is restarted only if a version other than the one specified in version is running.

  • (optional) validate: specifies how to validate the code before loading the testflow. This is used to prevent loading a wrong recipe file. The following three types of validation are supported:
    • none: no validation is done.
    • user_compare: specifies the value to be entered before loading the testflow.
    • popup_script: specifies the script to be executed before loading the testflow. The script is used to generate the validation code.

      If user_compare or popup_script is used, a dialog will pop up asking you to enter the validation code when you load the recipe file. If you enter the same value as defined in the recipe file or generated by the script, the recipe file will be loaded. Otherwise, an error message will be shown in the dialog. The recipe file will not be loaded until you enter the correct value.

Note The validate setting in the user-defined recipe file has higher priority than the validate setting in the Factory preset recipe file.
  • testflow: specifies the path of the testflow file to be loaded. It can be a full path or a relative path to the recipe file. Using the return value of a script as the testflow name is also supported. The script can be a full path or a relative path to the recipe file. You can pass arguments to the script in the linux way when calling it. See the example below for the usage of the script.
    You can also use license inside the testflow element to specify a license file. For example, 
    <recipe>
   <smartest>
      ...
      <V93000_LICENSING>../license1</V93000_LICENSING>
   </smartest>
   
   <testflow name="testflow_name" license="your_license2"/>
   ...
</recipe>
  • equipment: specifies the test type, the equipment vendor, the equipment model. The test type can be HAND, HANDLER or PROBER. For HAND test, do not specify the equipment vendor and the equipment model. Otherwise, you will get an error message when loading the recipe file.
  • datalog: contains the data log settings for the Datalog Setup dialog.
    • profile: specifies the name of the profile to use. If you do not want to use any profile, delete this element.
    • lot_variables: specifies values for lot variables and wafer variables to be logged in the data log file. It can also assign the return value of a script to a variable. The script can be a full path or a relative path to the recipe file. You can pass arguments to the script in the linux way when calling it. See the example below for the usage of the script.
      Note TCCT will convert the names of all the variables into uppercase letters.
    • file: specifies the full path and the name for the EDL file, STDF data log file, text data log file, custom data log file, and lot summary file to be generated.

      For the text datalog, you can also specify the test name width and whether to show the pin name column.

      For the PROBER test, specify whether to generate the data log file and the lot summary file per wafer.

      For the custom data log file, specify the library of the custom data log formatter. If not specified, the library /opt/hp93000/soc/formatter/EventFormatter/libfilter.so will be used.

      For the lot summary file, you can specify which tests are included, whether to organize the summary according to the site number and whether to output the summary in a pop-up window.

      In the naming of the data log file and lot summary file, the following variables in a pair of braces can be used to specify the name and the path of the output data log file and the lot summary file. In the real names of the files, they will be replaced by the current value of the variables.

      The variables related to lot information, including PART_TYP, TST_TEMP, TEST_COD, LOT_ID, and OPER_NAM.

      The system variables, including HOSTNAME, USER, and LOGNAME.

      Others: DEVICE_PATH, DEVICE_NAME, TESTFLOW_NAME, and TIMESTAMP.

      Note DEVICE_PATH can be used to specify the path but not the name of the file. To avoid the conflict among the names of files, a TIMESTAMP will automatically be added in the file name if no TIMESTAMP is included in the file name.
  • states: defines the following insertion points to execute some scripts.

    You can execute the scripts around the following states:

    • PROGRAM_LOAD: You can specify a script to be executed before and after loading a testflow.
    • LOT_CREATE: You can specify a script to be executed before creating a new lot. A new lot is created when you click the New Lot button, enter the lot variables, and click OK in the pop-up Lot Information dialog.
    • LOT_REMOVE: You can specify a script to be executed after a lot is removed. A lot is removed when you click the End Lot button and click OK in the pop-up End Lot dialog.
    • TESTFLOW_EXECUTE: You can specify a script to be executed before or after a testflow is executed.
    • WAFER_CREATE: You can specify a script to be executed before or after a wafer is loaded.
    • WAFER_REMOVE: You can specify a script to be executed before or after a wafer is unloaded.
  • instruction: specifies the instruction to be displayed in the Instruction Console and in a pop-up window. You need to click OK in the pop-up window to continue your actions.
  • ooc_rules: specifies the out-of-control rule. The rules apply per site.

    bins: specifies the out-of-control rules related to the software bin and hardware bin. The element of the rules include hardbin, softbin, consecutivecount or overallcount. When the devices tested on a site fall in the specified software bin or hardware bin consecutively for the specified consecutivecount times or fall in the specified software bin or hardware bin overall for the specified overallcount times, a dialog box will be displayed asking whether to end the lot or ignore it.

In the recipe file, you can use variables in the following ways:

  • Use a script file to assign a value for a variable. In this way, other variables will be passed as input parameters.
    <variable name="LOT_ID" value="script:xxx.sh ${MyVariable} />
  • Define a data log path.
    <file perwafer="false" path="/tmp/datalog/${MyVariable}" name="advantest_2233">
  <stdf enable="true" ext="std" />
  <text enable="true" ext="txt" screen="true" showpincolumn="true" testnamewidth="60" />
  <summary enable="true" ext="sum" whichtest="All Tests" persite="true" screen="true" />
</file>
  • Define an insertion point in the exec node.
    <state name="LOT_CREATE">
  <before>
    <exec program="beforelotstarted.sh ${MyVariable}" />
  </before>
  <after>
    <exec program="afterlotstarted.sh ${MyVariable}" />
  </after>
</state>

Example

<?xml version="1.0" encoding="UTF-8"?>
<recipe>
  <smartest force_restart="true">
    <version>soc64_7.2.3.0</version>
    <tml_version>tml64_7.2.3.0_2.2.0</tml_version>
    <mtp_version></mtp_version>
    <startup_mode>offline</startup_mode>
    <user_mode>engineer</user_mode>
    <env>
     <V93000_MODEL>/home/linlin/devices/DemoTcct/demo74299/model.mrt.ps1600</V93000_MODEL>
      <!-- here can specify the env variables for smartest using, for example -->
      <!-- <LD_LIBRARY_PATH>/path/or/paths/to/3rd_party_libs</LD_LIBRARY_PATH> -->
    </env>
  </smartest>
  <validate type="user_compare" value="123456"/>
  <testflow name="/tmp/devices/DemoTcct/demo74299/testflow/demoflow_4sites" />
  <equipment testtype="HANDLER" vendor="Multitest" model="MT9918" />
  <datalog>
    <profile name="datalog_ON.prf" />
    <lot_variables>
      <variable name="LOT_ID" value="12345" />
      <variable name="OPER_NAM" value="Jean" />
      <variable name="PRODUCT_ID" value="script:/home/demo/my_recipes/script.sh x y z"/> 
    </lot_variables>
    <file perwafer="false" path="/tmp/datalog/"
      name="datalog_{HOSTNAME}_{LOGNAME}_{LOT_ID}_{TIMESTAMP}">
      <stdf enable="true" ext="stdf" />
      <text enable="true" ext="txt" screen="true" />
      <summary enable="true" ext="sum" whichtest="All Tests"
       persite="true" screen="true" />
      <edl enable="true" ext="edl" name="edlfile" perwafer="false" /> 
      <customdatalog enable="true" ext="txt" name="customfile"
       librarypath="/home/demo/formatter/libfilter.so" perwafer="false" />
    </file>
  </datalog>
  <states>
    <state name="PROGRAM_LOAD">
      <before>
        <exec program="/projects/scripts/beforeDownloadTestflow.sh"/>
      </before>
      <after>
        <exec testSuite="bbb" sites="all"/>
      </after>
    </state>
  </states>
  <ooc_rules>
    <bins softbin="1" hardbin="1" consecutivecount="12" overallcount="15"></bins>
    <bins softbin="31" hardbin="3" consecutivecount="3" overallcount="5"></bins>
  </ooc_rules>
  <instruction>
    Please send the Lot summary file to datalog@abc.com after the lot test is done.
  </instruction>
</recipe>

In this example, user_compare is used for the validation. To use the type popup_script, you can change it as follows:

<validate type= "popup_script" value="/home/demo/tcct/recipe/md5checker#{testflow}"/>

For more examples, go to the directory /opt/hp93000/tcct/examples/. The example files are named as recipe_example_*.xml.

Functional changes

  1. Introduced in SmarTest 7.2.0
  2. SmarTest 7.2.0: in patch 2, supports the validate tag in TCCT 1.1
  3. SmarTest 7.2.0: in patch 2, supports per wafer lot summary file in TCCT 1.1
  4. SmarTest 7.2.0: in patch 2, supports popup_script type for validate tag in TCCT 1.2
  5. SmarTest 7.2.0: in patch 2, supports executing a script around PROGRAM_LOAD, before LOT_CREATE and after LOT_REMOVE in TCCT 1.2.
  6. SmarTest 7.2.0: in patch 2, supports adding content in the Instruction Console in TCCT 1.2.
  7. SmarTest 7.2.1: Added a pop-up window to show the instruction content in TCCT 1.3.
  8. SmarTest 7.2.2: Supports EDL data log file in TCCT 1.4.
  9. SmarTest 7.2.2: Supports the custom data log formatter and file in TCCT 1.4.
  10. SmarTest 7.2.2: Supports assigning the value to a variable with script in TCCT 1.4.
  11. SmarTest 7.2.3: Supports passing arguments to the script in TCCT 1.5.
  12. SmarTest 7.2.3: Supports relative file path for testflow in TCCT 1.5
  13. SmarTest 7.2.3: Supports executing a test suite after testflow loaded in a specific state in TCCT 1.5
  14. SmarTest 7.2.3: Supports starting SmarTest in TCCT 1.5
  15. SmarTest 7.3.3: Added force_execute attribute for the smartest element.
  16. SmarTest 7.3.4: Added the rdi_version child element for the smartest element.
  17. SmarTest 7.3.4: Add the auto_start_lot attribute for the recipe element.
