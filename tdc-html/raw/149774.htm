SMC_ARM_OTHER_TS()

Arms the SMC_backgroundProcessing() method and passes the name of another test suite and data to it. This API enables you to log the data of the specified test suite in the background.

Important points to consider

Passing data to the background process
Data can be passed to the background process
  • as member variable of the test method class,
  • by up to eight optional parameters as value,
  • by up to eight optional parameters as reference.
Passing data as member variable
The recommended way of passing data to the background process is using class member variables.

Member variables of the test method class that are used in a background process must not be changed while the background process is running.

This restriction also applies to test method parameters defined in the initialize() function of a test method class and assigned to member variables of the class: SmarTest initializes these parameters for each execution of the run() function to ensure that the conditions are the same for all sites.
CAUTION Parallel access to member variables of a test method class through the run() function and a background process may result in invalid data or in a crash of the test method and is therefore not allowed.
Passing data by optional parameter as value
All data that are passed to the background process using the eight optional parameters are copied by the SmartCalc framework. The background process gets only a copy of the data.

Be careful with passing large data containers to the background process even though the parameters are only references to the data containers: These data containers are also copied by the framework. This might impact the performance of the test method.

Passing data by optional parameter as reference

Alternatively you can pass data by the optional parameters as follows, so that only references are used:

  • use boost::cref() - for constant references
  • use boost::ref() - for non-constant references

For this kind of passing data to the background process, you have to be aware of

  • memory leaks if the variable is not freed properly,
  • issues of the lifetime of the variable, as the background process will last longer than the run() function where it has been armed, and
  • issues regarding thread safety as two or more threads could access the content of the variable at the same time.
Binning of sites while hidden uploads are running

The SmartCalc framework automatically synchronizes background threads before sites are binned. For optimized usage of hidden uploads, only background threads that process the sites to be binned should be synchronized.

  • For the thread per site, the processed site is automatically defined by the site that was in focus when the background process has been armed by this API.
  • For the common thread, the SmartCalc frame work will automatically assume that all active sites are processed in the background process. In case a background process utilizes a modified list of sites to process, you must use APIs SMC_ARM_FOR_SITES() or SMC_ARM_OTHER_TS_FOR_SITES() to make the modified list of sites accessible for the SmartCalc framework.
Hidden upload and Mode_contexts

Hidden uploads, controlled and started by SMC_ARM() must be finished before a Mode context is changed.

For changes of the Mode context within a test suite, we recommend calling the API SMC_SYNCHRONIZE_WITHOUT_BINNING() before the Mode context is changed.

For changes of the Mode context over several test suites, we recommend inserting a new test suite with no level-, timing-, or pattern-information defined and assigning the system-prepared test method smartCalc.SMC__SYNCHRONIZE.

Syntax

void SMC_ARM_OTHER_TS(STRING& testsuite, value1, value2, value3, ..., value8);
This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.
Note With C++98 there is a compiler warning when using the compile option -Wpedantic in the header.
Parameters
Parameter Description/Range
testsuite The name of the test suite to use in the SMC background process.
value1 ... value8

Up to eight optional parameters of any type to transfer data to SMC_backgroundProcessing().

The parameters value1 ... value8 of SMC_ARM_OTHER_TS() and your SMC_backgroundProcessing() method have to be equal in both the number of parameters and the type of the parameter.
Return value
There is no return value.

SMC_backgroundProcessing()

void SMC_backgroundProcessing (type value1, type value2, ..., type value8);
This method must be defined as public method of your test method class. The call of this function is armed by SMC_ARM_OTHER_TS() in the run() function of the same test method class and controlled by the SmartCalc framework.

In case different SMC_backgroundProcessing() methods become necessary in your test method class, they need a different number of parameters to be distinguishable (different types is insufficient).

The name that has been defined by parameter testsuite of SMC_ARM_OTHER_TS() is not available as input parameter of SMC_backgroundProcessing() but can be read by API SMC_GET_TESTSUITE_NAME().
Parameters
Parameter Description/Range
type value1 ... type value8

Up to eight optional parameters of any type that are passed from SMC_ARM().

The parameters value1 ... value8 of SMC_ARM_OTHER_TS() and your SMC_backgroundProcessing() method have to be equal in both the number of parameters and the type of the parameter.
Return value
There is no return value.

Examples

Example 1: Passing data by member variables

The following code shows the recommended way of passing data to SMC_ARM_OTHER_TS() and the background process.

Class myTestMethod
{
protected:

    ARRAY_D data;

    virtual void run()
    {
        ON_FIRST_INVOCATION_BEGIN();

            //
            // Store the data in the member variable of the class
            //
            data = ...

            FOR_EACH_SITE_BEGIN();

                SMC_ARM_OTHER_TS("otherTestSuite");
                ...

            FOR_EACH_SITE_END();

        ON_FIRST_INVOCATION_END();
        ...
    }

public:

    //
    // Your SMC_backgroundProcessing() method.
    //
    void SMC_backgroundProcessing()
    {
        //
        // Do some processing in the background
        //
        cout << data[0] << endl;
    }

} // Class myTestMethod
Note

The example above contains a call of cout in function SMC_backgroundProcessing(). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to Thread safety.

Example 2: Passing data by reference

The following code shows how to pass data by reference to SMC_ARM_OTHER_TS() and the background process.

Class myTestMethod
{
protected:

    virtual void run()
    {
        ...
        static ARRAY_D data;
        ...
        //
        // Pass the data to SMC_ARM_OTHER_TS() by reference
        // Note: no data will be copied due to boost::cref()
        //
        SMC_ARM_OTHER_TS("otherTestSuite", boost::cref(data));
        ...
    }

public:

    void SMC_backgroundProcessing(const ARRAY_D& data)
    {
        //
        // Do some processing in the background
        ...
    }

} // Class myTestMethod
