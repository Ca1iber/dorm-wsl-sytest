Using SmartCalc (SMC) with SmartRDI

Subtopics

  1. Using hidden upload with SmartRDI
  2. SmartRDI functions controlling SmartCalc (SMC)
  3. SmartRDI examples for SmartCalc (SMC)

SmartRDI can be used in combination with the SmartCalc (SMC) framework. This allows you to move time consuming calculations and uploads of test results to separate background threads and executing them in parallel.

For concepts and detailed information refer to SmartCalc framework.

For a list of all SMC related test method APIs, refer to SMC_... (SmartCalc API reference).

Basic structure

A test suite, based on SmartRDI, utilizes the same structure as a test method that uses test method APIs only:

  • Background processes are armed by the SMC_ARM() function or the variants of this function. Each SMC_ARM() call creates a new thread. For more information, refer to SMC_... (SmartCalc API reference).
  • The background process itself is defined as public SMC_backgroundProcessing() function within the test method class of the test suite.
  • The SmartRDI functions used for the setup and used to retrieve the data are the same for tests utilizing hidden upload and tests without hidden upload: Just the functions to retrieve the results are to be moved from the run() function to the SMC_backgroundProcessing() function.
  • SmartRDI uses rdi.hiddenUpload() to enable the hidden upload feature, which allows SmartRDI to perform the upload of data in the SMC_backgroundProcessing() function of the test suite.
  • Ensure that SMC gets enough time to access the hardware in the background threads. For more information, refer to Hide analog and digital data upload in SmartCalc recommendations.

For general information on how to implement an SMC test, refer to Four-step SmartCalc implementation in the SmartCalc framework documentation.

Thread per site and common thread

Each function call and each thread takes some time overhead for preparation and cleanup. This overhead in test time depends also on the ratio of function calls and threads and the number of available CPU cores. For high-site-count applications, the overhead my exceed the benefit of using background threads or hidden uploads respectively.

The SmartCalc framework supports therefore two implementations of background processes:

Thread per site
The "Thread per site" is armed by SMC_ARM() or the variants of this function outside of the ON_FIRST_INVOCATION block. The "Thread per site" is recommended for low site-count applications.
Common thread
The "Common thread" (also know as "Single thread") is armed by SMC_ARM() or the variants of this function inside of the ON_FIRST_INVOCATION block. The "Common thread" is recommended for high site-count applications.

For more information, refer to SmartCalc "Thread per site" and "Common thread".

CAUTION

Within a test suite, SmartRDI supports either the implementation "Thread per site" or "Common thread" with one thread for all active sites.

Mixing the two solutions by assigning multiple active sites to more than one thread (multisite per thread) is not supported and can lead to invalid logging of results. For example: A solution with 16 sites and 4 threads is not supported.
