Topic 113256

User-defined disconnect sequence

Subtopics

  1. Effects of user-defined disconnect sequence
  2. Implementing a conditional final disconnect with disconnect.user_def

The behavior of the Standard disconnect sequence can be changed by providing a user-defined disconnect sequence.

For test situations where you want to define a particular disconnect sequence (see examples below), it can be done by creating a command file. This optional user-defined disconnect command file must be named disconnect.user_def, and placed in the folder testfunc of your device directory.

Use a user-defined disconnect sequence in the following cases:

  • If there are shared power pins across multi-sites and you want to disconnect the site related power pins separately.
  • If test suites within a test flow are not self-contained, and some test suites require a continuously running clock or require the current state of a device control pin to be maintained.
Note On startup SmarTest always performs a standard disconnect.
Note Use only firmware commands that make use of the site focus. That means you have to set the site focus before you can execute the command. For a list of all possible firmware commands, see Site dependent firmware commands.

Examples

Example 1

This is one example of how to use a user-defined disconnect sequence for switching power pins in a pin list:

DLSO (@NONSHARED@)
CHRS OFF
FLSH MUX
WSDN
SQST OFF
CNCT OFF,(@NONSHARED@)
BCMD "",ACTION,"Update",
PSST OFF,(pinlist for DPS2)
PSST OFF,(pinlist for DPS1)
RLYC IDLE,OFF,(@NONSHARED@)

Example 2

This is the recommended user-defined disconnect sequence to avoid the pass or fail site dependency behavior and keep the clock running:

DLSO (@NONSHARED@)
RLYC IDLE,OFF,(@NONSHARED@)
CHRS OFF
FLSH MUX
WSDN
CNCT OFF,(@NONSHARED@)
BCMD "",ACTION,"Update",
PSST OFF

Compared with the standard disconnect sequence, the above user-defined sequence has the following three major differences:

  • Removal of "SQST OFF" from the standard disconnect sequence, so that the clock keeps running.
  • Usage of "@NONSHARED@" pin group in the disconnect sequence, so that Smartest will disconnect site related pins correctly.
  • Moving the "RLYC" command up to the second position after "DLSO", so that potential hot switching is avoided.
Note When the above user-defined disconnect sequence is used, SmarTest cannot automatically distinguish between shared and non-shared pins, but applies the same sequence throughout the entire test flow. This leaves shared pins connected which may impact on the DUT under certain circumstances.
