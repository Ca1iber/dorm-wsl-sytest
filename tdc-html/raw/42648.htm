Topic 42648

Important Points on Multisite Programming

This section summarizes the important points on programming for multisite testing.

  • Do not access any variable values assigned in the first-invocation block outside the block. This is because the values assigned in the first-invocation block are never stored for subsequent executions. Hence, unknown values are assigned to the variables at later executions. If necessary, declare the variable outside the function scope (global scope), or declare it as static.

    The following shows an example of an incorrect program. The compiler will show the error message "'clockFrequency' was not declared in this scope ..." for this code:

    ON_FIRST_INVOCATION_BEGIN();

    DOUBLE clockFrequency = 10 MHz;

ON_FIRST_INVOCATION_END();

DOUBLE clockPeriod = 1 / clockFrequency;    // This will result in a compile error
                                            // at subsequent invocations

    The correct code is shown in the next example.

  • On the other hand, the variable values assigned before the first-invocation block (outside of the block) can be referred from the block.
    DOUBLE clockFrequency;

ON_FIRST_INVOCATION_BEGIN();

    clockFrequency = 10 MHz;

ON_FIRST_INVOCATION_END();

DOUBLE clockPeriod = 1 / clockFrequency;
  • If you want to use the values assigned before the first-invocation block as site-specific setup data, you should refer them in the each site loop block:
    ARRAY_I configuredSites;
ARRAY_D vOffsetPerSite(GET_CONFIGURED_SITES(configuredSites));

vOffsetPerSite.init();
...
...
//
// Fill the array with site specific offset voltages
//
// Note:    Array elements that are not set in this section
//          remain on the initialization value of 0.0.
//
vOffsetPerSite[0] = 0.25 V; // DC offset for site # 1
vOffsetPerSite[1] = 0.28 V; // DC offset for site # 2
...
...
ON_FIRST_INVOCATION_BEGIN();

    //
    // Apply the site specific offset
    //
    FOR_EACH_SITE_BEGIN();

        AWG("Ain").vOffset(vOffsetPerSite[CURRENT_SITE_NUMBER() - 1]);

    FOR_EACH_SITE_END();

    FLUSH();
    ...
    ...
ON_FIRST_INVOCATION_END();
  • As described previously, the Result APIs store the measurement data of all sites into the cache when the APIs are executed at the first execution. Therefore, do not call the Result APIs conditionally in the test method program. If a certain Result API is not executed from the result of a conditional branch at the first execution, the cache does not have any corresponding measurement data of all sites. If the Result API is executed at subsequent executions, the Result API gets unknown data.
    ARRAY_D wave1, wave2;

wave1 = ANALOG(1).DGT("Aout").getWaveform();

if (...)
{
    wave2 = ANALOG(2).DGT("Aout").getWaveform();    // Subsequent execution = unknown waveform
}
  • You can describe the FW_TASK API enclosed by the BEGIN_EXTENSION API with the site parameter and END_EXTENSION API in the first-invocation block for multisite testing. Note that you should define the site parameter for an explicit definition of the sites in setup focus. for more information refer to the examples in BEGIN_EXTENSION. BEGIN_EXTENSION and END_EXTENSION should be used as a pair.
  • When debugging your multisite test method program, you have to execute the following APIs written in your program at the first execution.
    • ON_FIRST_INVOCATION_BEGIN - ON_FIRST_INVOCATION_END
    • FOR_EACH_SITE_BEGIN - FOR_EACH_SITE_END or
    • FOR_EACH_SITE_BEGIN_WITH_QUERY - FOR_EACH_SITE_END
    • All Execution APIs
    • All Result APIs corresponding to Execution APIs

      At subsequent executions, you have to execute the following APIs.

    • FOR_EACH_SITE_BEGIN - FOR_EACH_SITE_END or
    • FOR_EACH_SITE_BEGIN_WITH_QUERY - FOR_EACH_SITE_END

      If you skip any of them, you may encounter problems (for example, the Result API returns incorrect data).
