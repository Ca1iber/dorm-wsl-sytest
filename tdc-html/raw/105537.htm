TPSP, TPSP? - (TestPoint SuPpression)

The TPSP command serves to suppress operations of a certain type that are executed by testpoints in patterns for selected pins. The TPSP? query returns the current settings.

Note that the command only changes the runtime settings. No setup file will be changed.

With this command you configure setups of those sites that have the setup focus: For more information, see also: PSFC, PSFC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Note The TPSP command does not work reliably when SmarTest is running in offline mode.

DC events are executed (or emulated) despite suppression being active.

TPSP

TPSP {suppression_type}, {(pin_list)}

TSPS?

TPSP? {(pin_list)}

returns:

TPSP {suppression_type}, {(pin_list)}

Parameters

suppression_type

Defines which types of test point operations are suppressed. Possible values are:
OFF No operations are suppressed. This is the default.
I Operations that change the DUT input signal are suppressed.
O Operations that record DUT output signals are suppressed.
IO Both operation types are suppressed.

pin_list

The pin or pins to which this command is applied. To specify multiple pins, separate the names with a comma, or use @ to specify all pins. Pin groups can also be specified. Only pins that are associated with DCScale channels are taken into account.

Example

TPSP I,(dps1)
FTST?
TPSP OFF,(dps1)

In this example, input operations for dps1 are suppressed for the following functional test. After completion of the test, the suppression is canceled.

Functional changes

  1. Introduced in SmarTest 6.5.0
