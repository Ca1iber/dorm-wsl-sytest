Buses

Buses are collections of pins that can be used in device accesses. You can use buses wherever MTL pin groups can be used (that is, pin groups defined in the pin mapping file).

Buses are a more efficient implementation of the group and subgroup concept (see the :group: and :subgroup: keywords in the Device access file) and supersede them. When the configure bus keyword is used in the Pin mapping file, :group: and :subgroup: in the device access file are ignored.

Syntax

A bus is defined in the Pin mapping file using the configure bus keyword:

configure bus <busName> (<pinList>)

<busName> is the name of the bus, which you can choose as desired.

<pinList> is the list of member pins. Its elements must be separated by commas. The most significant bit of the bus is listed first, the least significant bit is listed last.

The pin list can contain:

  • MTL pin names, as defined in the pin mapping file.

    You can include undefined pins; they are simply ignored.

  • Other buses defined in the pin mapping file.

    If you include a bus in a pin list, all the pins from that bus are added in their defined order. For example:

    configure bus myBus (pin7, pin8)
configure bus myOtherBus (myBus, pin3, pin4)

    In this case, myOtherBus contains the pins pin7, pin8, pin3, pin4.

  • A bus can also be empty:
    configure bus myBus ()

    This can be useful, for example, to support multiple device densities without having to redefine the device access file.

Accessing bus pins

You can access bus pins by adding a three-digit suffix to the bus name: <busname>.<nnn> is the pin number nnn from the bus definition.

For example:

configure bus myBus (pin2, pin4, pin6, pin8)

In this case, myBus.000 would be pin2.

Ambiguities

When naming buses and pins, take care not to create ambiguities.

For example, if you define a bus named data and also define a pin named data.000, any reference to data.000 could either refer to the individual pin you defined or the first pin in your bus.

There is an exception to this when both references are actually the same pin. For example, if there is an individual pin data.000 and you define a bus called data as (data.000, data.001, data.002, data.003), data.000 always refers to the same pin, since the individual pin data.000 is the first pin of the bus data.

Example

This example shows how to replace a group with subgroups with a bus.

Groups are specified in the device access file:

:groups:
{
  :format:
  { :name:        :size:  }
  {  DQo            8     }
}

:subGroups:
{
  :format:
  { :baseGroup:  :context:   :name:      :bits:      }
  {   DQo         ALL         ALL        [7..0]       }
  {   DQo         C1          C1S1       [7..4]       }
  {   DQo         C1          C1S2       [3..0]       }
  {   DQo         C2          C2S1       [7,5,3,1]    }
  {   DQo         C2          C2S2       [6,4,2,0]    }
}

This definition in the pin mapping file is equivalent and replaces the above group and subgroups:

/* original group */
configure bus DQo (DQo.000,DQo.001,DQo.002,DQo.003,DQo.004,DQo.005,DQo.006,DQo.007)
                                                                  /* MSB <-> LSB */

/* original subgroup */
configure bus DQo.ALL.ALL (DQo.007,DQo.006,DQo.005,DQo.004,DQo.003,DQo.002,DQo.001,DQo.000)
                                                                          /* MSB <-> LSB */
configure bus DQo.C1.C1S1 (DQo.007,DQo.006,DQo.005,DQo.004)   /* MSB <-> LSB */
configure bus DQo.C1.C1S2 (DQo.003,DQo.002,DQo.001,DQo.000)   /* MSB <-> LSB */
configure bus DQo.C2.C2S1 (DQo.007,DQo.005,DQo.003,DQo.001)   /* MSB <-> LSB */
configure bus DQo.C2.C2S2 (DQo.006,DQo.004,DQo.002,DQo.000)   /* MSB <-> LSB */
