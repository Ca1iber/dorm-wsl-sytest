Topic 353370

Building and executing the client

The SmartProd client program needs to be built before you use it to monitor switch_version operations. For building the client, you need to create a Makefile which holds relevant setups. See the Example.

About this task

Create a Makefile and build the SmartProd client.

Before you begin

  • Make sure that you have a root account or your account has been configured to use the sudo command.
  • Make sure that a SmartProd client program has been created. See SmartProd client program for the example.

Procedure

  1. Run the command cd to go to the directory where your SmartProd client program is located.
  2. Create a Makefile which is used to build your client program. The Makefile must specify the path of the header file: /opt/hp93000/smartprod/include/ and the library file: /opt/hp93000/smartprod/lib/libSmartMonitorApi.so.
  3. Run make clean and make in the shell to build the program.
  4. Run ./clientTest to execute the SmartProd client.

Results

The SmartProd client is running in the shell to timely monitor switch_version operations.

Example

A Makefile example

CPP = /usr/bin/g++ -m64 -g -std=c++11
LD = /usr/bin/g++ -m64 -g -std=c++11
 
SMARTPROD_PATH = /opt/hp93000/smartprod/
  
INCLUDES =  -I $(SMARTPROD_PATH)/include -I /opt/hp93000rt/el7/x86_64/log4cxx_0.9.7/include
LIB_PATHS = -L $(SMARTPROD_PATH)/lib -L /opt/hp93000rt/el7/x86_64/log4cxx_0.9.7/lib
 
CPPFLAGS = $(INCLUDES)
LDFLAGS = $(LIB_PATHS) -lSmartMonitorApi -llog4cxx -Wl,-rpath=${SMARTPROD_PATH}/lib:/opt/hp93000rt/el7/x86_64/log4cxx_0.9.7/lib
 
 
SRCS = $(shell ls *.cpp)
OBJS = $(SRCS:.cpp=.o)
 
all: clientTest 
clean: ; @rm -f $(OBJS); rm -f core*; rm -f clientTest 
clientTest: $(OBJS)
      ${LD} $(OBJS) $(LDFLAGS) -o $@
.cpp.o:
      ${CPP} $(CPPFLAGS)  -c $<

See also /opt/hp93000/smartprod/examples/monitor/testclient/ for the Makefile example.

What to do next

Check the notification in the shell when a switch_version operation is done. For example, the SmartProd client outputs notifications as follows:

Receive Event:

EVENT TYPE : VERSION SWITCH

STATUS:START

ORIGINAL_VERSION: 8.4.2.0

TARGET_VERSION:7.6.1.0

...

Based on the SmartProd client, in online mode, when the SmarTest system is ready for testing, SmartProd will also output the tester hardware configuration information, including tester, boards, utility line number, ignored cards and channels that the current SmarTest version does not support, and others. For example, the information starts as follows:

Receive Event:

EVENT TYPE : TESTERSTATUS

TESTER_STATUS : {"TesterInfo":{"SerialNumber":"YO19100015","WorkstationInfo":"HP Z4 G4 Workstation, P61 v02.56, 4DA93923PD, 1 phys. CPU, 8 Cores, HT on with Linux 3.10.0-862.3.2.el7.x86_64 (63985 MB)" ,"TestHeadType":"SX"},"Board":[{"HwSpecifier":"..",......}

You can copy all your tester hardware configuration output, from the first curly bracket '{' to the last one '}', to a JSON editor. You can clearly see tester and boards status data in the tree mode of the editor.

Functional changes

  1. Introduced in SmarTest 7.10.0
  2. SmartProd 0.1.0-14: SmartProd outputs installed SmarTest versions and tester hardware configuration.
