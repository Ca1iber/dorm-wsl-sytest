The API Reference provides details to universal test methods (UTM). It describes API, class and member functions used for writing test programs for the V93000 test system.

Definitions of terms

Within this reference the term API is used for all functions provided by the SmarTest MAPI, that can be used without the need of being instantiated. In order to ease identification at title level, they follow the syntax ApiName(). For instance, SMC_DISABLE().

UTM also offers classes with various purposes. Those classes usually have to be instantiated to create an object to work with. Class descriptions within the API reference have a simple syntax: ClassName to identify them at title level. For instance, SPMU_TASK.

Member functions are operators and functions that are declared as members of a class and can only be used in the context of objects. Each member function is listed as separate topic underneath its class with this title syntax: ClassName.CMemberFunction(). For instance, SPMU_TASK.execMode().

Structure of UTM reference topics

All UTM reference topics, regardless whether of API, class or member function type will have the following structure.

  • Each topic starts with the description of what the API, class or member function is, its intended use/behavior followed by additional essential details.
  • The syntax section provides an overview of all interfaces of the API or member function, including details about class constructors. An interface reflects the variations of how the API/member function can be called.
  • It is followed by a list of parameters and, if applicable, a list of options per parameter. The list of parameters provides a complete overview and description of all parameters to all listed interfaces.
  • The return values, if applicable, completes the formal description of the API, class or member functions.
  • More or less complex code snippets, depending on the context of the topic, are provided to the user within the example section.
  • Links listed in the related information section will lead to underlying concepts, tasks ore closely related functions.
  • The functional changes section of a class only reflects changes to the class it self, like new or obsoleted member functions. However, all other changes are tracked in the individual functional changes section of each API and member function topic.
