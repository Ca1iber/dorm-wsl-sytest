rdi.site()

In high-site-count applications, the SMC_ARM() API should be used within the FIRST_INVOCATION block to create a common thread for all active sites and to minimize the overhead in test time for calling functions and handling of threads. A common thread receives a list of all active sites and the site() API is to be used in the SMC_BackgroundProcessing() function to set a site to be processed from this list.

Note Function site() can be used only in a only in a Common thread. The function cannot be used in a "Thread per site" implementation.1)

Syntax

The API is applicable for DC, SmartVec, Digital Capture and Error Map APIs.

rdi.site(int site).id(...).getValue(); // ...getVector(), ...getVectorBit(), ...
List of parameters

Parameter

Description

site

The number of the site to be processed.

Example

virtual void run()
{
    RDI_INIT();

    ON_FIRST_INVOCATION_BEGIN();

        rdi.hiddenUpload(TA::ALL);

        RDI_BEGIN();

            rdi.dc("a").pin("A").vForce(1).iMeas().execute();
            rdi.digCap("b").pin("B").samples(1000).execute();

        RDI_END();

        ARRAY_I activeSite;

        GET_ACTIVE_SITES(activeSite);

        SMC_ARM(activeSite);

    ON_FIRST_INVOCATION_END();

    return;
}

public:

void SMC_backgroundProcessing(ARRAY_I activeSite)
{
    double  result;
    ARRAY_I vec;

    //
    // Retrieve result for each active site
    //
    for (int I = 0; I < activeSite.size(); i++)
    {
        result = rdi.site(activeSite[i]).id("a").getValue();
        vec    = rdi.site(activeSite[i]).id("b").getVectorBit();
    }
}

Functional changes

  1. Introduced in SmartRDI 2.3.1
  2. SmartRDI 2.4.5: rdi.site().id().getXXX() can be called anywhere inside a test method's run() function; the error map result supports common thread SMC.
1) Before SmartRDI 2.4.5, rdi.site() has to be called only inside the SMC_BackgroundProcessing() function. In SmartRDI 2.4.5 and newer versions, rdi.site() can be called anywhere inside the test method's run() function. This enhancement supports the usage of the same post-processing code structure for background and foreground processing.
