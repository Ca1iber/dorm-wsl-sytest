Topic 73014

Data Queue Empty error

Data Queue Empty is a situation where the per-pin processor runs out of vectors in the queue. If the queue for the processor cannot be filled in a timely manner, the Data Queue Empty execution erroroccurs. The higher the base rate, the greater the risk of Data Queue Empty errors.

Details on the Data Queue Empty error condition are available in:

  • Managing the data queue in Vector Setup Commands

Data Queue Empty errors can usually be eliminated by increasing the expansion size. There are two ways of doing so:

  • Use the -e compiler setting (see Starting the MTL compiler from the command line) or check the Expansion Size option when using the graphical user interface (see Compiler control dialog). This is appropriate in situations where the error is occurring on many pins.
  • Use the exps pin attribute (see Pin mapping syntax for details). This is appropriate when the error occurs on only one or a few pins.
    Note You can find out on which pins the errors occur by noting the affected channels in SmarTest's report window and looking up the corresponding pins in the Pin configuration file.

The expansion size controls the maximum length of loop bodies. Larger sizes causes the MTL compiler to unroll the loops, creating more instructions in the loop body while decreasing the number of loop iterations.

Larger expansion sizes decrease the risk of Data Queue Empty errors at the expense of requiring more vector memory. The expansion size value is proportional to the loop lengths and can range from 60 to 1,000,000. We recommend trying the values from this series in turn until you have found a setting that does not produce an error: 100, 250, 500, 1,000, 10,000, 50,000, 100,000, 500,000, 1,000,000.

Recompile your memory pattern after each change of the expansion size setting.
