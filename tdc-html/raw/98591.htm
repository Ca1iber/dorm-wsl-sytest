EPRC? - (Error Propagation Repetition Count)

The EPRC? query serves to calculate how often a block of buffer vectors must be repeated before execution of a conditional jump (JMPE instruction). These buffer vectors are required to ensure that the internal error flag on which the jump depends is set correctly (see Calculating the buffer vectors for JMPE and RETC (and match loops)).The calculation is based on the current primary sets. In particular, the currently active timing set (as defined by SPRM) is used to determine the tester period.

EPRC? can also be used if you want the number of dummy vectors in a new style counted match loop (MACT and MRPT sequencer instructions) to be fixed and known (see Adjusting the junctions between match loop and surrounding label). Run EPRC? with a block size of 1. Then the number of repetitions returned is the number of dummy vectors that you must define for the match loop.

Syntax

EPRC? {no_of_vectors}, {(port_list)}

returns:

EPRC {no_of_vectors}, {no_of_repetitions}, {(port)}

Parameters

no_of_vectors

Specifies the size of the vector block that is to be repeated.

no_of_repetitions

This reply parameter specifies how many times no_of_vectors must be repeated to ensure that the error flag has been set correctly. The calculation is based on the current primaries, including the currently active timing set

port_list

In the query, you can specify a port list. If you specify @@, EPRC? will return the settings for all ports of the current specification.

port

In the reply, a separate answer is given for every port.

Example

The following examples queries the required number of repetitions for the three ports of the timing specification MP_SPEC2.

> SPRM "MP_SPEC2",1,1,1
> EPRC? 2,(@@)
< EPRC 2,228233,(Port1)
< EPRC 2,342193,(Port2)
< EPRC 2,171253,(Port3)
