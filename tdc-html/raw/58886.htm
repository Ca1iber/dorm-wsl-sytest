The TESTSET class accesses a data container holding information that defines numbering procedures for results in a given test suite.

The testname() and testnumber() functions are used with TESTSET to assign user defined names and numbers to specific tests. The testnumber member functions are used with the TESTSET API to define test numbering procedures, such as defining default numbering procedures.

Test numbers are affected by other factors in addition to those described in TESTSET, TESTNUMBER, and GET_TESTNUMBER API topics. For example, you can enter loop iterations and global increment numbering parameters by using the Testflow Editor and the Parameter Dialog. This will result in modifying the test numbers that would be derived by using these APIs. For a detailed explanation of how you can modify numbering values using these features, see Generating Test Numbers. In order for test numbering to proceed, the test_number_enable testflow flag in the Testflow Editor must be enabled, see Generating Test Numbers for instructions on the use of these flags.

Use the following APIs for judging and logging test results:
  • judgeAndLog_FunctionalTest()
  • judgeAndLog_ParametricTest()
  • judgeAndLog_PmuIfvm()
  • judgeAndLog_PmuVfim()
  • judgeAndLog_DpsVfim()
  • judgeAndLog_Dps();
  • judgeAndLog_Spmu();
  • judgeAndLog_PpmuMeasure()
  • judgeAndLog_SpecSearch()
  • judgeAndLog_PptiaTask()
  • judgeAndLog_DcResultAccessor()
  • judgeAndLog_ScanTest()
  • doLog_ShmooTest()

The purpose of these APIs is to easily find the judge and log API for the specific test. The TEST() APIs are currently used for judging and logging test results. However, they require greater effort to choose the proper API to use for the specific test because they share the same name but differ in the parameter numbers and/or types.

The naming convention for these APIs is divided into two parts:

  • The first part, "judgeAndLog", indicates that this API will judge the whole test suite P/F according to the test result and will log the test result.

  • The second part identifies the type of test where this API should be used. For example: FunctionalTest, ParametricTest, PpmuMeasure, etc.

Note The judgeAndLog_ParametricTest(), judgeAndLog_FunctionalTest(), and judgeAndLog_ScanTest() functions can be used within the SMC framework, for details refer to their descriptions.
Note

If you use TESTSET within the SMC framework instead of SMC_TEST, binning happens in SMC_SYCHRONIZE according to the binning rules as for SMC_TEST. For details, see Use of SMC_TEST() with multibin.

If you use, within a testflow, the SMC framework and TESTSET test suites independent of each other, binning happens according to the binning rules explained in Use of TESTSET and SMC_TEST() test suites with multibin.

Note The test_number_enable testflow flag must be set in the Testflow Editor for test numbering to be enabled. See the Generating Test Numbers section of the event data logging documentation for an explanation of enabling both default and user-selected numbering parameters.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TestSet_r.h.

You can use the system-prepared class object "TestSet" when using member functions. You can also create a new class object. If a function sets up a parameter, the parameter setting is kept until you reset it or return it to a default setting.

System-prepared class object
TestSet
Note The system-prepared object cannot be used within the SMC framework.
Constructor
TESTSET();
This constructor creates the class object that contains the settings of the member functions that define numbering procedures for results in a given test suite, and is used for specifying all options that relate to the TEST API and test methods.
TESTSET(bool withContext, INT site);

This constructor creates the class object as defined above and additionally defines the site to be processed. The parameter withContext is to be set to false. For more information refer to Example 5: Using TESTSET() in SMC background processing.

Note

TESTSET class objects must not be shared across multiple threads.

If used in SMC background processing, TESTSET class objects should be created and used only within the SMC_backgroundProcessing() method.

Syntax descriptions

Placeholders used

In the syntax descriptions below, placeholders are used for certain functions:

  • member_func()

    Where member_func() is noted, you can use any of these member functions, individually or in combination:

    • cont()
    • port()
    • reliabilty()
    • testname()
    • testname_default()
    • testnumber()
    • testnumber_default()
    • testnumber_none()

      Because these member functions are optional, you can also omit them. For example, when the syntax specifies TestSet.member_func().judgeAndLog_...(), you can use TestSet.judgeAndLog_...().

  • judgeAndLog_...()

    Where judgeAndLog_...() is specified, you can use any of the functions whose names begin with "judgeAndLog".

Syntax descriptions

The syntax of the TESTSET API depends on the effect you want to achieve:

  • To use a temporary object:
    TESTSET().member_func().judgeAndLog_xxx(parameters);
  • To use a temporary object and define the site to be processed:
    TESTSET(false, site).member_func().judgeAndLog_xxx(parameters);
  • To use the system-prepared object:
    TestSet.member_func().judgeAndLog_xxx(parameters);
    Note The system-prepared object cannot be used within the SMC framework.
  • To use a user object:
    TESTSET obj;
obj.member_func().judgeAndLog_xxx(parameters);
  • To judge and log a functional test result:
    TESTSET().cont(true).judgeAndLog_FunctionalTest();
  • To judge and log the functional test result of a specific port:
    TESTSET().port("port").judgeAndLog_FunctionalTest();
  • To retrieve information about binning, test numbers and test names from tmLimits (see parametric tests), and log the test name:
    TESTSET().judgeAndLog_FunctionalTest("[test name]", tmLimits);
  • To suppress the adding of numbers to test names to make them unique when they conflict with another name:
    TESTSET().suppressTestnameLoopCount(true);
  • To judge and log the general parametric test results or to judge and log the values with a defined limit, use:
    bool TESTSET::judgeAndLog_ParametricTest(const STRING &pin, const STRING &testname, DOUBLE value);
bool TESTSET::judgeAndLog_ParametricTest(const STRING &pin, const STRING &testname, const LIMIT& limit, DOUBLE value);
bool judgeAndLog_ParametricTest(const STRING_VECTOR &pins, const STRING &testname, const LIMIT & limit, ARRAY_D& values);
bool judgeAndLog_ParametricTest(const STRING_VECTOR &pins, const STRING &testname, V93kLimits::TMLimits& tmLimit, ARRAY_D& values);
bool judgeAndLog_ParametricTest(const STRING &pinList, const STRING &testname, const LIMIT & limit, ARRAY_D& values);
bool judgeAndLog_ParametricTest(const STRING &pinList, const STRING &testname, V93kLimits::TMLimits& tmLimit, ARRAY_D& values);
bool judgeAndLog_ParametricTest(const STRING_VECTOR& pins, const STRING& testname, ARRAY_D& values);
  • To judge and log the DC test results, use:
    bool TESTSET::judgeAndLog_PmuIfvm(const PMU_IFVM &pmuIfvm);

Examples

Example 1: Using the same condition for multiple tests

If you wish to use the same condition for multiple TEST member functions, you can program the condition for the class object of the TESTSET. In this example, the conditions are set in the first line and effective for all the following three tests.

double dIdd1, dIdd2, dIdd3;

TESTNUMBER sdc6 = GET_TESTNUMBER("SDC_6");

TestSet.cont(true).testnumber(sdc6);

TestSet.TEST("Vcc","test1",dIdd1); 
TestSet.TEST("Vcc","test2",dIdd2); 
TestSet.TEST("Vcc","test3",dIdd3);

Example 2: Generating test numbers

The TESTSET class can be used as a programmable interface for generating test numbers for each test in a test suite by assigning offset and increment values that iterate based on the number of calls. The examples below use the offset and increment values as shown in the table below.

Note The following TESTSET examples use the term "subtest Test Number". A "subtest Test Number" refers to the number that is stored in the EDL. The numbers assigned to a test result can be modified and are affected by default and user-selectable numbering parameters. In this sense these test numbers are temporary.
TESTSET adc_1, dac_1;

adc_1.testnumber("ADC_1").TEST(...); // subtest Test Number = 777(777 + 3 * 0)

adc_1.TEST(...);    //subtest Test Number = 780 (777 + 3 * 1)
adc_1.TEST(...);    //subtest Test Number = 783 (777 + 3 * 2) 

dac_1.testnumber("DAC_1")

dac_1.TEST();       //subtest Test Number = 723 (723 + 0 * 0)
dac_1.TEST();       //subtest Test Number = 723 (723 + 0 * 1)
dac_1.TEST();       //subtest Test Number = 723 (723 + 0 * 2)

In this example the adc_1 test suite is assigned an offset of 777 and an increment of 3, which results in assigning every subtest result a distinct subtest Test Number. The dac _1 test suite is assigned only an offset value, with no increment, which results in all subtest iterations having a subtest Test Number value of 723.

Example 4: Judge and Log Examples

ON_FIRST_INVOCATION_BEGIN();

    FUNCTIONAL_TEST();

ON_FIRST_INVOCATION_END();

TESTSET().judgeAndLog_FunctionalTest();

The first three lines perform a functional test for multi-site parallel, and the last line performs the judging and logging for each site respectively.

double thd_result, snr_result;

TESTSET().cont(true).judgeAndLog_ParametricTest("dgtz_pin", "THD", thd_result);
TESTSET().judgeAndLog_ParametricTest("dgtz_pin", "SNR", snr_result);

The first judgeAndLog_ParametricTest() judges the thd_result data as pass or fail. Then, the second one judges the snr_result data as pass or fail because the TESTSET().cont(true) is called in advance. When the result of the first judgeAndLog_ParametricTest() is pass, the test will continue even if you do not call the cont(true) member function.

double low_limit, high_limit, thd_result;

TESTSET().judgeAndLog_ParametricTest("Aout", THD",LIMIT(TM::GT, low_limit, TM::LT, high_limit), thd_result);

The judgeAndLog_ParametricTest() compares the thd_result data with the limit range specified by the LIMIT API, then judges as pass or fail.

TESTSET().judgeAndLog_ParametricTest("I/O0","ft_test",tmLimits,VMeas);

In this example, Vmeas is the variable containing the measured value. The judgeAndLog_ParametricTest() compares the value of VMeas with the limit range of the test name ft_test in the loaded test table. To use tmLimits, add the following two lines to the test method:

#include "TMLimits.h"
using V93kLimits::tmLimits;

The following example illustrates the binning rule of tmLimits, which bins on the first fail.

TESTSET().cont(true).judgeAndLog_ParametricTest(pin,"param1",tmLimits,value1);
TESTSET().cont(true).judgeAndLog_ParametricTest(pin,"param2",tmLimits,value2);

Example 5: Using TESTSET() in SMC background processing

The example shows how to implement TESTSET() for SMC background processing. The example contains the code for two versions of the background process:
  • SMC background process per site
  • Common SMC background process for all active sites

The example requires that the test limits are defined by a CSV file. For more information refer to TMLimits and Working with TMLimits.

The following definition of test method member variables is required in the protected section of the test method class:
protected:
    string      mSMCMode;
    string      mPinList;
    string      mTestSuite;
    string      mTestName;
    int         mMeasurements;
    int         mOffline;
    ARRAY_I     mActiveSites;
A DC value test is defined in the run() method of the test class. Result processing is performed in an SMC background process per site or in a common SMC background process for all active sites.
virtual void run()
{
    PATTERN_CONTROLLER patternCtrl;

    ON_FIRST_INVOCATION_BEGIN();
    {
        //
        // Prepare
        //
        mSMCMode        = "COMMON_THREAD"; // "THREAD_PER_SITE" or "COMMON_THREAD"
        mPinList        = "PS1600_1,PS1600_2";
        mTestName       = "Test 1";
        mMeasurements   = 1;

        GET_SYSTEM_FLAG("offline",&mOffline);
        GET_TESTSUITE_NAME(mTestSuite);

        RESULT_AREA_CONFIG_SET resultArea(mTestSuite);

        resultArea.pin(mPinList).setDcValueResultAreaSize(mMeasurements);

        //
        // Create setup for DC value measurement
        //
        ...
        ...

        //
        // Execute
        //
        resultArea.setAsPrimary();

        CONNECT();

        SMC_FUNCTIONAL_TEST();

        resultArea.deselectGlobally();

        //
        // Result processing
        //
        if (mSMCMode == "THREAD_PER_SITE")
        {
            //--------------------------------------------------------------
            // SMC background thread per site
            //--------------------------------------------------------------
            FOR_EACH_SITE_BEGIN();
            {
                SMC_ARM();
            }
            FOR_EACH_SITE_END();
        }
        else if (mSMCMode == "COMMON_THREAD")
        {
            //--------------------------------------------------------------
            // Common SMC background thread for all active sites
            //
            // Note:    The array of currently active sites must be stored
            //          in the member variable mActiveSites.
            //--------------------------------------------------------------
            GET_ACTIVE_SITES(mActiveSites);

            SMC_ARM();
        }
        else
        {
            cout << "Invalid SMC mode \"" << mSMCMode << "\"." << endl;
        }
    }
    ON_FIRST_INVOCATION_END();

    return;
}
The SMC background processing method of the test class is to be defined in the public section:
//
// The SMC background processing method; armed by SMC_ARM() in the run() method above
//
virtual void SMC_backgroundProcessing()
{
    DC_RESULT_ACCESSOR  resultAccess(mTestSuite);
    STRING_VECTOR       pinVector;

    //
    // Prepare
    //
    pinVector = PinUtility.getDigitalPinNamesFromPinList(mPinList,TM::ALL_DIGITAL);

    cout << "SMC_backgroundProcessing for SMC mode \""
         << mSMCMode << "." << endl << flush;

    if (mSMCMode == "THREAD_PER_SITE")
    {
        //------------------------------------------------------------------
        // Thread per site
        //------------------------------------------------------------------
        TESTSET testSet;

        if (!mOffline)
        {
            resultAccess.uploadResult(mPinList, TM::RESULT_INDEX);
        }

        for (uint pinIndex = 0; pinIndex < pinVector.size(); pinIndex++)
        {
            ARRAY_D results = resultAccess.getValues(pinVector[pinIndex]);

            for (int resultIndex = 0; resultIndex < mMeasurements; resultIndex++)
            {
                cout << "\t\tProcessing data for site " << SMC_SITE_NUMBER()
                        << ", pin " << pinVector[pinIndex]
                        << ", result " << resultIndex + 1 << endl << flush;

                testSet.cont(true).judgeAndLog_ParametricTest(pinVector[pinIndex],
                        mTestName, V93kLimits::tmLimits,
                        (mOffline) ? 1 : results[resultIndex]);

            } // for (int resultIndex ...

        } // for (uint pinIndex ...
    }
    else if (mSMCMode == "COMMON_THREAD")
    {
        //------------------------------------------------------------------
        // Common thread for all active sites
        //
        // Note:    The common thread requires that the array mActiveSites
        //          has been filled in the calling run() method.
        //------------------------------------------------------------------
        for (int siteIndex = 0; siteIndex < mActiveSites.size(); siteIndex++)
        {
            if(!mOffline)
            {
                resultAccess.uploadResult(mActiveSites[siteIndex],
                        mPinList,TM::RESULT_INDEX,
                        TM::RESULT_RANGE(TM::RESULT_INDEX,0,mMeasurements));
            }

            //
            // Create new TESTSET using the current site as parameter
            //
            TESTSET testSet (false, mActiveSites[siteIndex]);

            for (uint pinIndex = 0; pinIndex < pinVector.size(); pinIndex++)
            {
                ARRAY_D results = resultAccess.getValues(mActiveSites[siteIndex],
                                                         pinVector[pinIndex]);

                for(int resultIndex = 0; resultIndex < mMeasurements; resultIndex++)
                {
                    cout << "\t\tProcessing data for site " << mActiveSites[siteIndex]
                            << ", pin " << pinVector[pinIndex]
                            << ", result " << resultIndex + 1 << endl << flush;

                    testSet.cont(true).judgeAndLog_ParametricTest(pinVector[pinIndex],
                            mTestName, V93kLimits::tmLimits,
                            (mOffline) ? 1 : results[resultIndex]);

                } // for (int resultIndex ...

            } // for (uint pinIndex ...

        } // for (int siteIndex ...
    }
    else
    {
        cout << "Invalid SMC mode \"" << mSMCMode << "\"." << endl;
    }

} // virtual void SMC_backgroundProcessing()
Note

The example above contains several calls of cout in function SMC_backgroundProcessing(). cout is not thread safe. In production test cout must never be used in a background process.

When using cout in a background process, you have to expect a mix up of the output in the ui_report window and possibly other unwanted behavior. For more information, refer to Thread safety.
