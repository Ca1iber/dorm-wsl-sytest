INDEPENDENT_TEST

The INDEPENDENT_TEST class supplies protocol tests that are executed independently of the simulation ports. It is derived from the PROTOCOL_TEST class. Like a synchronized protocol test, an independent test consists of one or more transaction sequences each of which contains one or more transactions.

Since the simulation ports and the protocol port are to run asynchronously, they must be started from different execution contexts. The protocol context is started by the INDEPENDENT_TEST object. The simulation context can be started, for instance, with the START_TEST (which must be used if the two contexts are to run in parallel) or FUNCTIONAL_TEST APIs. For more information on execution contexts see Using execution contexts.

INDEPENDENT_TEST provides two member functions for starting an execution context. One of them blocks the interface until the test result is returned, the other allows you to start another context while the first is still running, thus enabling overlapping execution of the protocol port with the simulation ports.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/IndependentTest.h.

Member functions

run()

virtual Boolean run();
virtual Boolean run(const STRING &seqCtxtItemName);
virtual Boolean run(const SEQUENCER_CONTEXT_ITEM &item);

This member function runs an execution context in such a way that the firmware interface is blocked (using the FTST? firmware query). A new context can only be run after the current context has returned its global PASS/FAIL result. If the context contains the protocol port, its protocol is first converted into a pattern.

Parameters

I/O

Parameter

Description

I

seqCtxtItemName

(Optional) The name of the context to be run. The context must have been defined either as an SEQUENCER_CONTEXT_ITEM object or on the firmware level.

In the former case, this must be the name specified as the name parameter of the SEQUENCER_CONTEXT_ITEM object. Furthermore, the context item must have been integrated into a SEQUENCER_CONTEXT object.

I

item

(Optional) The name of an SEQUENCER_CONTEXT_ITEM object. This object must have been integrated into a SEQUENCER_CONTEXT object.

If run() is called without a parameter, the name of the execution context is assumed to be identical with the port name.

start()

virtual Boolean start();
virtual Boolean start(const STRING &seqCtxtItemName);
virtual Boolean start(const SEQUENCER_CONTEXT_ITEM &item);

This member function starts an execution context containing the protocol port in such a way that the firmware interface is not blocked (using the SQST RUN firmware command). A new context can be started while the current context is still running. If the context contains the protocol port, its protocol is first converted into a pattern.

Parameters

I/O

Parameter

Description

I

seqCtxtItemName

(Optional) The name of the context to be started. The context must have been defined either with the SEQUENCER_CONTEXT_ITEM API or on the firmware level.

In the former case, this must be the name specified as the name parameter of the SEQUENCER_CONTEXT_ITEM object. Furthermore, the context item must have been integrated into a SEQUENCER_CONTEXT object and been activated on the firmwar level with the apply() function of this SEQUENCER_CONTEXT object.

I

item

(Optional) The name of an SEQUENCER_CONTEXT_ITEM object. This object must have been integrated into a SEQUENCER_CONTEXT object and been activated on the firmware level with the apply() function of this SEQUENCER_CONTEXT object.

If start() is called without a parameter, the name of the execution context is assumed to be identical with the port name.

waitDone()

VOID waitDone(DOUBLE timeout=360000);

This member function waits for the contexts started from the independent test object to be finished. If the timeout is exceeded, and some context is still running, the function sets its state to BRK. This can be used to ensure that a test that was started with start() (not run()) has actually been completed before result queries are issued.

The function expects that at least one context has been started with start() before it is called. If this is not the case, it will issue an error message.

getStatus()

INT getStatus (INT siteNumber = -1);
Boolean getStatus (ARRAY_I &siteStatus);

This member function returns the status of the independent test. You can either request the status of one site or the status of all active sites. The returned integer value(s) must be interpreted according to the mapping defined in independentTest.h. The possible states are:

SITE_NOT_ACTIVE
NOT_EXECUTED
TRANSLATION_ERROR
EXECUTED
TIMEOUT
Parameters

I/O

Parameter

Description/Range

I

siteNumber

(optional) The site the status of which is to be returned. If no site number is specified the function will return the status of the site that currently has the query focus.

O

siteStatus

(Optional) A predefined integer array into which the function will write the status of all active sites.

With this parameter type, the function will return TRUE if all active sites have passed.

get Result()

static UINT64 getResult(const STRING& test, const STRING& resultName);
static STRING getResult(const STRING& test, const STRING& resultName, TM::FORMAT format);

This member function returns the capture results of a specified independent test that are associated with the specified result identifier for the site that has the query focus. It is a static version of the getResult() function of PROTOCOL_TEST, and allows you to retrieve the read results of an independent test even if the test object does not exist anymore.

Parameters

I/O

Parameter

Description

I

test

The name of an independent test.

I

resultName

Identifier of read results, as specied for a capture transaction.

I

format

Specifies the format of the returned string.

Possible formats are:

TM::HEX Hexadecimal literal prefixed with 0x

TM::BIN Binary literal prefixed with 0b

TM::SCS The captured bits without any prefix

TM::SYMBOL Symbolic value, if the parameter was set up with symbolic values

O

UINT64

Result access with a max length of 64 bit.

O

string

Result access with a length of more than 32 bit.
Note If return values are required larger than 64 bit, use the static STRING getResult() method.

clear()

INDEPENDENT_TEST& clear();

This member function clears the transaction sequence buffer of the independent test object. However, results will still be available until next run. The function has no parameters.

empty()

Boolean empty();

This member function returns TRUE is the transaction sequence buffer of the independent test object is empty. The function has no parameters.
