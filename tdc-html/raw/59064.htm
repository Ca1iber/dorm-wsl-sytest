Topic 59064

Creating a label with low level commands

About this task

The creation of a label with low level commands consists of three main steps,

  1. expanding the sequencer area and defining the label,
  2. adapting the sequencer program, and
  3. downloading the waveform DC/DC power units.

Procedure

  1. Expand the sequencer area and define the label.

    You must expand the sequencer area for the new sequencer program before you can define the label. The size of the sequencer area is defined with the DMAS command. The new size must be the old size plus the number of lines for the new program. Thus, you must first determine the current size, then define the new size, and only then define the label, as follows:

    1. DMAS? SQPG,SM,(@)

      The system replies:

      DMAS SQPG,SM,9,(@)

    2. DMAS SQPG,SM,13,(@)

      The new size must be 13 because the new sequencer program consists of four lines. The 4 new lines are filled by SmarTest with the dummy instruction NOP.

    3. SQLB "test_2",MAIN,9,12,"table1",(@)

      Define the label for the default port @. The label is associated with the newly created lines 9 to 12 of the sequencer area. table1 is the base wavetable of the label.

      SQLB overwrites the NOP instructions in lines 9, 10, and 12 with the STVA, STSA, and STOP instructions, respectively.

      When SQLB is issued, the attributes of the new label are also set to their default values. One label attribute is the memory type for the vectors. On a Pin Scale system, the default for the memory type depends on the memory mode. In compatibility mode, it is VM. Therefore in this case, you must change the memory type by calling SQLA as follows:

    4. SQLA LBL,"test_2","PARA_MEM=SM"
  2. Adapt the sequencer program.

    The STVA instruction created by SQLB points to absolute vector area address 0. In order to redirect it to the actual end of the vector areas, where the waveform DC/DC power units for the new label are to be appended, determine the current end of the vector areas, and correct the address accordingly, with the following two commands:

    1. DMAS? PARA,SM,(@)

      The system replies:

      DMAS PARA,SM,432,(@)

    2. SQPG 9,STVA,432,,,(@)

      The program now looks as in the figure in Addressing the vector areas except for command line 11, which still contains the dummy instruction NOP. Overwrite command line 11 with the GENV instruction as follows:

    3. SQPG 11,GENV,12,,,(@)
  3. Download the waveform DC/DC power units into the vector areas of the pins with VECD. In contrast to the sequencer area, you need not expand the parallel vector areas manually before you issue this command. VECD extends the vector area of IN1 automatically as required.

    There are two ways to call VECD with hpt:

    • From the fw-hpt prompt (see Executing commands in a shell window using the hpt utility), you can use the variant $VECD of the VECD command (see Storing and Retrieving Binary Data). When you use $VECD, you must specify every bit of your input data by an ASCII 1 or 0. For the pin IN1, whose vector area segment is displayed in the figure in Addressing the vector areas, you would have to issue:

      $VECD PARA,SM,432,16,(IN1),

      00001011 00001011 00001011 00001011 00001011 00000000 00000010 00000100

      00000101 00000110 00000101 00001000 00000000 00000000 00000000 00000000

      You can enter the blanks between the individual bytes in order to structure your input.

    • When you use VECD, every input character represents one byte. You cannot enter values below 32 for VECD directly from the hpt prompt. However, you can create a command file with an editor like emacs, and pass this file to fw-hpt (see Executing Firmware Commands from a Command File). emacs would display the VECD command for pin IN1 as follows:

      VECD PARA,VM,432,16,(IN1),#216^K^K^K^K^K^@^B^D^E^F^E^H^@^@^@^@

      Here, #216 specifies the length of the binary data. The first digit defines the length of the following number, which, in its turn, specifies the length of the following data.

      Both variants of the command download 16 binary values at the absolute address 432; only the first 12 values are active vectors, but you must specify a complete memory word. This step must be carried out for all pins.
