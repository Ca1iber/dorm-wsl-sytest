Starting a TMU measurement

Normally, TMU measurements are started by executing special arming waveforms in a pattern. An arming waveform must specify the ARM action for a receive edge. An example is given by the following wavetable fragment:

PINS pin1
. . . 
02 "f1:0  f2:1  r7:ARM"  arm

The delay of the arming edge r7 is defined in the active timing set of the primary equation set, for example:

PINS pin1
. . . 
r7=6

By this example, executing waveform 02 will arm (activate) the TMU of pin pin1 6 ns after the start of the cycle.

Note that the wavetable for a pin can contain only one arming action. That is, there cannot be more than one waveform that executes the arming action, and this waveform cannot execute it more than once.

A wavetable that contains the ARM keyword can also be used for functional tests without TMU measurements, but since the window formatter is used to arm the TMU, the following restrictions must be observed:

  • Only r1 through r7 can be used for arming the TMU.
  • If the wavetable for a pin contains an arming waveform, then no waveform of this wavetable must contain a window compare action.
  • Neither the receive edge that is used for arming nor its upper neighbor can be used for any compare actions in the wavetable.
  • The wavetable cannot be used for protocol engine tests (since these need the window formatter for other tasks).

Combining a TMU measurement with a PRBS or SmartLoop™ test

It is possible to execute a TMU per pin measurement in parallel with a PRBS or SmartLoop™ test. In this case, the TMU must be armed by the sequencer instruction TMUA (not a special waveform, as with normal functional tests) within the PRBS or SmartLoop™ pattern. For details see Instructions for PRBS and SmartLoop tests.
