Topic 29618

PPMU_SETTING

Subtopics

  1. PPMU_PIN_SETTING

The PPMU_SETTING class is a data container holding the contents of the task for setting up measurement conditions of pin PMUs. This class can be used to call the PPMU_PIN_SETTING class that is a subsidiary data container to set up per pin measurement conditions for pin PPMU.

For releases up to 6.5.3 and of the 7.0 stream, to execute tasks defined with this class, you had to use the execute member function of the TASK_LIST class. With the releases 6.5.4, 7.1.0 and later, tasks defined with this class can also be executed directly.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PpmuSetting.h.
Constructor
PPMU_SETTING();

This constructor defines a task that is a set of measurement conditions for the V-force, I-measure or I-force-V-measure test with the pin PMU.

Note Do not create static objects of the class in the test method and do not create test method member variables from this class.
Member functions
  • pin()
  • execute()
  • fastTransferMode()
  • wait()
  • syncWait()
Usage of the class

For creating an object:

PPMU_SETTING <object>;

For setting up per pin measurement conditions:

<object>.pin("pinlist").<member_func>;

For setting a wait time from when the execution of the task defined with the PPMU_SETTING is started:

<object>.wait(time);

<object>

Object name to be defined

pinlist

Target pin name or pin group name of this class. You can specify multiple pins and pin groups by separating with a comma or using "@" which means the all PPMU pins. "@" includes the digital pins that is wired to an analog module on the DUT board for a trigger source.

<member_func>

Member functions of the PPMU_PIN_SETTING class

time

Waiting time

The next task execution will be started after the wait time.

Member functions

pin()
PPMU_PIN_SETTING & pin(const STRING& pinlist);

This function returns the reference to the PPMU_PIN_SETTING class object that represents the measurement parameters for the specified pin. To add an action to the task, use the member functions of the PPMU_PIN_SETTING class.

Parameter
pinlist Target pin name or pin group name of this class. You can specify multiple pins and pin groups by separating with a comma or using "@" which means the all PPMU pins. "@" includes the digital pins that is wired to an analog module on the DUT board for a trigger source.
execute()
virtual void execute (FwStream * stream = NULL);

This function downloads the settings defined with PPMU_SETTING directly without adding it to TASK_LIST.

Parameter
stream

Optional reference to a FwStream object.
fastTransferMode()
void fastTransferMode (bool enableFastTransfer);

Enables or disables the fast transfer mode for site specific voltage levels.

This will only apply if different levels for different sites are to be applied. The fast transfer mode will have no effect if the same level is to be programmed for all sites.

Parameter
enableFastTransfer
Bool value enables or disables the fast transfer mode:
  • FALSE: Fast transfer mode is disabled. This is the default mode.
  • TRUE: Fast transfer mode is enabled.

When using the fast transfer mode, there are some rules to consider:

  • This member function can be used only with SmartScale test head cards.

  • This member function requires that a minimum fast transfer buffer size of 131072 bytes is specified in the Technology file for a device. Otherwise the following error message is issued:

    ERROR: MTRA - ... a minimum fast transfer buffer size of 131072 bytes ...
  • The fast transfer mode is not supported for resources shared between sites. The following error message is issued if shared resources are used1):
    ERROR: MTRA - mismatch between number of sites selected and number of values given
  • The fast transfer mode is supported only for site specific voltage levels that can be set by member function vForce() of the PPMU_PIN_SETTING class.
  • You can use the fast transfer mode only within a FOR_EACH_SITE block.
  • With fast transfer mode enabled for the FOR_EACH_SITE block, only the forced voltage can be changed. Changing other parameters like the current range results in the following error message:
    Error: PPMU_PIN_SETTING::iRange
E12500: Changing this setting is not allowed after fastTransferMode is set to true.
  • Before the FOR_EACH_SITE block, the PPMU_SETTING must be defined using the common settings and downloaded to the hardware. The fast transfer mode must remain disabled for this initial download.
  • The fast transfer mode is to be enabled before the FOR_EACH_SITE block and after the common settings have already been downloaded.
  • The fast transfer mode is intended to be used for high-site-count applications. This mode can increase the test time for low-site-count applications:
    • The minimum number of sites to take advantage of the fast transfer mode is >= 4 sites.
    • The break-even point can be higher depending on the configuration of your application.

For more information, refer to Example 4: Fast transfer mode.

Examples

Example 1: PPMU IFVM and VFIM measurement

PPMU_SETTING   ppmuSetting;
PPMU_RELAY     ppmuRelay_on, ppmuRelay_off;
PPMU_MEASURE   ppmuMeasure;
PPMU_CLAMP     ppmuClamp_on, ppmuClamp_off;
TASK_LIST      taskList_1;

ON_FIRST_INVOCATION_BEGIN();

    //
    // Setups for PPMU
    //
    ppmuSetting.pin("S0").iRange(1 mA).min(0 V).max(4.3 V).iForce(10 uA);
    ppmuSetting.pin("S1").iRange(10 mA).min(-10 uA).max(30 uA).vForce(3.3 V);

    //
    // Relay setups
    //
    ppmuRelay_on.pin("S0,S1").status("PPMU_ON");
    ppmuRelay_on.wait(1.3 ms);
    ppmuRelay_off.pin("S0,S1").status("AC_ON");

    //
    // Measurement setups
    //
    ppmuMeasure.pin("S0,S1").execMode(TM::PVAL);

    //
    // Hardware specific programming to avoid hot switching on the current force setup
    //
    ppmuClamp_on.pin("S0").status("CLAMP_ON").low(2.6 V).high(2.9 V);
    ppmuClamp_off.pin("S0").status("CLAMP_OFF");

    //
    // Build and execute the task list
    //
    taskList_1.add(ppmuSetting)
              .add(ppmuClamp_on)
              .add(ppmuRelay_on)
              .add(ppmuClamp_off)
              .add(ppmuMeasure)
              .add(ppmuRelay_off);

    taskList_1.execute();

ON_FIRST_INVOCATION_END();

//
// Result upload and Datalog
//
double VMeas, IMeas;

VMeas = ppmuMeasure.getValue("S0");
IMeas = ppmuMeasure.getValue("S1");

TEST("DC_Test",ppmuMeasure, true);

In this example, a PPMU IFVM test on the pin S0 and a PPMU VFIM test on the pin S1 are performed in parallel. The current range, force current/voltage range and result pass/fail limit are set with PPMU_SETTING.

Example 2: PPMU measurement with different settings for different sites

PPMU_MEASURE    ppmuMeasure1, ppmuMeasure2;
PPMU_SETTING    ppmuSetting1, ppmuSetting2;
PPMU_CLAMP      ppmuClamp_on, ppmuClamp_off;
PPMU_RELAY      ppmuRelayOn,  ppmuAcRelayOn;
TASK_LIST       taskList_multiDeltaFlexDc1, taskList_multiDeltaFlexDc2;

ON_FIRST_INVOCATION_BEGIN();
{
    //
    // Setups for PPMU
    //
    ppmuSetting1.pin("I/O1").vForce(1.8 V).iRange(1 uA).max(1 uA) .min(-1 uA);
    ppmuSetting2.pin("I/O1").iForce(20 uA).iRange(1 mA).max(0.5 V).min(-0.5 V);
    ppmuSetting2.wait(1 ms);

    //
    // Relay setups
    //
    ppmuRelayOn.pin("I/O1").status("PPMU_ON");
    ppmuRelayOn.wait(1.3 ms);

    ppmuAcRelayOn.pin("I/O1").status("AC_ON");

    //
    // Measurement setups
    //
    ppmuMeasure1.pin("I/O1").execMode(TM::PVAL);
    ppmuMeasure2.pin("I/O1").execMode(TM::PVAL);

    //
    // Task list
    //
    taskList_multiDeltaFlexDc1.add(ppmuSetting1)
                              .add(ppmuRelayOn)
                              .add(ppmuMeasure1);

    //
    // The setups to this task will change. The function setup() must be used
    //
    ppmuClamp_on .pin("I/O1").status("CLAMP_ON").low(2.6 V).high(2.9 V);
    ppmuClamp_off.pin("I/O1").status("CLAMP_OFF");

    taskList_multiDeltaFlexDc2.add(ppmuSetting2)
                              .add(ppmuClamp_on)
                              .add(ppmuRelayOn)
                              .add(ppmuClamp_off)
                              .add(ppmuMeasure2)
                               add(ppmuAcRelayOn);

    taskList_multiDeltaFlexDc2.setup();

    //
    // Execute first measurement
    //
    taskList_multiDeltaFlexDc1.execute();

    //
    // Setup second measurement
    //
    FOR_EACH_SITE_BEGIN();
    {
        ppmuSetting2.pin("I/O1")
                .iForce(ppmuMeasure1.getValue("I/O1"))
                .iRange(ppmuMeasure1.getValue("I/O1"))
                .min(-0.5 V)
                .max(0.5 V);
    }
    FOR_EACH_SITE_END();

    //
    // Execute second measurement
    //
    taskList_multiDeltaFlexDc2.execute();
}
ON_FIRST_INVOCATION_END();

//
// Result upload and datalog
//
double VMeas;

VMeas = ppmuMeasure1.getValue("I/O1");

TEST ("DC_TEST2",ppmuMeasure2, true);

In this example, a PPMU VFIM per-pin value measurement is performed on the pin I/O1. Then the measured current value is retrieved for each site and used as the force current and range of the IFVM per-pin value measurement on the pin I/O1. A PPMU IFVM test is performed on the pin I/O1. The current range, force current/voltage range and result pass/fail limit are set with PPMU_SETTING.

Example 3: Direct execution without TASK_LIST

PPMU_SETTING ppmuSetting;

ON_FIRST_INVOCATION_BEGIN();

    ppmuSetting.pin("Q0").vForce(3.0 V).iRange(1 mA).min(-1 mA).max(1 mA);
    ppmuSetting.execute();

ON_FIRST_INVOCATION_END();

This sets the voltage on pin Q0 permanently to 3.0 volt. The setting is defined and directly executed, without using a TASK_LIST.

Example 4: Fast transfer mode

The fast transfer mode should be enabled if different voltage levels for a large number of sites are to be applied.
ON_FIRST_INVOCATION_BEGIN();
{
    PPMU_SETTING ppmuSetting;

    //
    // Basic setup for all sites
    //
    ppmuSetting.pin("PS1600_1")
            .vForce(3.0 V)
            .iRange(1.0 mA)
            .min   (-100.0 uA)
            .max   ( 100.0 uA);

    ppmuSetting.wait(4.0 us);

    //
    // Download setup and enable fast transfer mode
    //
    // Setup for all sites must be applied before the
    // fast transfer mode is enabled.
    //
    ppmuSetting.execute();

    ppmuSetting.fastTransferMode(true);

    //
    // Define a different level for each site
    //
    FOR_EACH_SITE_BEGIN();
    {
        ppmuSetting.pin("PS1600_1").vForce(3.0 V + 0.1 V * CURRENT_SITE_NUMBER());
    }
    FOR_EACH_SITE_END();

    //
    // Download the site-specific values using the fast transfer mode
    //
    ppmuSetting.execute();
}
ON_FIRST_INVOCATION_END();

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.0.1: New member function syncWait()
  3. SmarTest 6.5.4: PPMU_SETTING tasks can be executed directly without TASK_LIST. Also supported in 7.1.0 and later, not supported in 7.0.n releases.
  4. SmarTest 7.5.3: New member function fastTransferMode().
1) The firmware command MTRA shows the error message only, if resources are shared between active sites. For example, in a 4-site configuration where one resource is shared by sites 1 and 3 and another resource is shared by sites 2 and 4, no error message is issued if only sites 1 and 2 are active. To verify that your configuration is supported, you must activate all configured sites.
