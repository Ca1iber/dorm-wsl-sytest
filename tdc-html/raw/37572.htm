X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding

Subtopics

  1. Processing a Repeat Factor > 1
  2. X-Mode ASCII Vector Padding

The term x-mode refers to the possibility to execute more than one DUT cycle (as defined in an ASCII device cycle) in one test system cycle (as defined in a timing set); for more details see Using X-Modes: the xfact Column. The x-mode factor specifies how many DUT cycles are to be executed in one test system cycle. The x-mode factor can also be fractional, which means that m DUT cycles are executed in n test system cycles, and n is not divisible by m.

Normally, the vector translation is informed of the x-mode factor through the timing map file (see Calculating the Lengths of the State Character and the Index Sequences). If the x-mode factor m of a pattern is > 1 (and the x-mode is not fractional), it will convert blocks of m ASCII vectors to one row of the index array. Two points require more detailed explanations, namely:

  • How is a repeat factor > 1 processed when the x-mode factor is > 1?
  • What happens when the total number of the ASCII vectors (taking also account of the repeat factors) is not a multiple of the x-mode factor?
