MTP_MEMORY_TEST.setRABeginAction()

Defines actions before performing redundancy analysis. You can either generate a new fail map or load a saved fail bit map file (.bfd) for the redundancy analysis.

This function is available only after you have set setRAEnablingMode() to MTP::RA_ENABLE_BEGIN.

Syntax

MTP_MEMORY_TEST& setRABeginAction (const MTP::RA_BEGIN_MODE & mode);
Parameter

Parameter

Description

mode

The default mode is MTP::RA_BEGIN_START.

See the available modes in the following table.
Available options of parameter: <mode>

Option

Description

MTP::RA_BEGIN_START (default)

Executes the current test suite and generates a fail map to be used for redundancy analysis.

The corresponding RA end action is MTP::RA_END_EXECUTE.

MTP::RA_BEGIN_USE_BFD

Use this mode only when a redundancy analysis contains multiple testflows (the first testflow must have been set to MTP::RA_ENABLE_BEGIN by setRAEnablingMode()).

This mode loads a fail bit map file (.bfd) that has a matching RA service ID (RA execution name, DUT information, and port name), and executes the current test suite:

  • If the previous redundancy analysis indicates that the device is reparable, an overlay fail map is generated, which will be used for redundancy analysis.
  • If the previous redundancy analysis indicates that the device is not reparable, this test suite is skipped.

When using this mode, you also need to set setRAGenerateOverlaidBfd() to true.

The corresponding RA end action is MTP::RA_END_SAVE_BFD.
Note When RA is executed on multiple test suites, the results (including RA results) are generated on the last test suite (RA_end test suite) and DUT has to be available during execution of the last test suite. Do not specify any BIN before the RA_end test suite to ensure that both the execution is not interrupted and the results are generated correctly. For example, do not specify BIN for the false case of the RA_begin or RA_continue test suite. If you do, the RA result as well as the DUT test result cannot be generated correctly and error messages could occur.

For multisite cases, do not create RA_continue test suites in subflow branches based on pass or fail result of the previous RA test suite such as RA_begin or RA_continue.

Return value

There is no return value.
