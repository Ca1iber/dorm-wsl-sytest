EARD? - (Edge Action Result Data)

The EARD? query returns drive and (both expected and received) compare data for all used edges in the requested cycle range. It is used for cycle reconstruction by the Timing Diagram.

The overall structure of the reply is:

  1. 1 header byte for HXA multiplexing information
  2. 1 byte set to 1
  3. 2 bytes specifying the number of edge action blocks to follow
  4. A sequence of edge action blocks, each of which comprises 3 bytes and describes one edge.

The header byte is returned only once. The following three bytes are returned at the start of every cycle. Every cycle contains one or more action blocks.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Syntax

EARD? {start_cycle}, {no_of_cycles}, {type}, [MUX,] {(pinlist)}

returns:

EARD {start_cycle}, {no_of_cycles}, {type}, [err_type], {(pinlist)}, [MUX,] {#spec(data)}

Parameters

start_cycle

This is an integer that defines the first cycle for which information is to be returned. You can enter a value between 0 and 248.

no_of_cycles

This is an integer that defines the number of cycles for which information is to be returned. The range for this parameter is 0 to 248.

If a 0 is returned, no data is available for the given range.

type

This parameter specifies which actions will be reported. Possible values are:

 

RCV

Only receive edges are reported

 

DRV

Only drive edge actions are reported.

 

BOTH

Both drive and receive edge actions are reported. This is the default.

err_type

This parameter is used in the reply to inform about the recording mode, or if the specified cycle range is not included in the error map. Possible values are:

 

NOER

Indicates that the part of the requested cycle range specified in the reply is outside the recorded error map.

 

PF

Indicates that the requested cycle range is included in the recorded error map, and that 1 bit results have been recorded.

 

PFC

Indicates that the requested cycle range is included in the recorded error map, and that 2 bit results have been recorded.

MUX

If this flag is set, and one of the specified (Pin Scale) pins is multiplexed to an HXA pin, then the reply for this pin will combine the results of all Pin Scale pins that are multiplexed to the respective HXA pin.

pinlist

Information is only returned for the pins specified in pinlist. If more than one pin is to be included, the names must be separated with a comma. You can use the @ character to read the error data for all pins.

For an HXA pin, specify one of the Pin Scale pins to which it is mapped.

#spec(data)

Edge action data in binary format. This parameter reports the length of data (in bytes) being transferred, followed by the reconstructed data. The data is returned for each pin separately. The format of the reconstructed data supports expanded device cycles with up to 10 waveforms and 16 edges per waveform. Edges without action are not reported.

 

The data is to be decoded as follows:

 

Byte 0:

Contains multiplexing information for HXA pins. This byte is returned only once in the reply.

 

 

bits 7-4: Pin multiplexing factor. Specifies the number of Pin Scale pins that are mapped to one HXA pin or differential pin. 1 stands for differential pins or 2-multiplexed HXA pins, 3 for 4-multiplexed HXA pins.

The parameter is set to 0 for normal pins.

 

 

bits 3-0: Channel selector. If the pin multiplexing factor is > 0, this field specifies the logical position of the pin in the multiplexing order.

 

 

Information relating to HXA multiplexing is only returned if the MUX flag is set.

 

Byte 1:

Always 1. This byte is returned for every cycle.

 

Byte 2,3:

The number of actions to follow. The maximum, for an HXA pin mapped to 4 Pin Scale pins, is 640. This byte is returned for every cycle.

 

Every edge action is described in 3 bytes.

 

Byte A:

Normal action or OOB action. Possible values are:

0: Normal action

1: OOB action

 

Byte B:

Edge index (0-7 for normal pins, up to 31 for HXA pins).

 

Byte C:

Action data

 

 

bit 7: Action type. The following values can occur:

0: Drive action

1: Receive action

 

 

bit 6-4: Received value, 0 for drive actions. For receive actions, the following codes can occur:

000: No error (expected = received)

001: Intermediate

010: 0

011: 1

101: Unstable

110: Reconstruction not possible

 

 

bit 3-0: Expected compare/drive action.

The following values can occur for drive actions:

1010: Drive to 0, tri-state off

1011: Drive to 1, tri-state off

1110: Drive to 0, tri-state on

1111: Drive to 1, tri-state on

 

The following values can occur for receive actions:

0001: Edge compare to intermediate

0010: Edge compare to 0

0011: Edge compare to 1

0100: Edge compare to mask

0101: Edge compare to unstable

0110: Edge compare, reconstruction not possible

1001: Window compare to intermediate

1010: Window compare to 0

1011: Window compare to 1

1100: Window compare to mask

1101: Window compare to unstable

1110: Window compare, reconstruction not possible

1111: Window close

 

 

The codes for "reconstruction not possible" are only returned if the edge failed in single-ended standard mode with one bit results.

Examples

Example 1

> EARD? 2,1,BOTH,(TX1_d0)
< EARD 2,1,BOTH,PF,MUX,(TX1_d0),#9000000052
      \x10\x01\x00\x10
      \x00\x00\x82\x00\x01\x82\x00\x02\x82\x00\x03\x82\x00\x04\x82\x00\x05\x82\x00\x06\x82\x00\x07\x82
 \x00\x08\x82\x00\x09\x82\x00\x0a\x82\x00\x0b\x82\x00\x0c\x82\x00\x0d\x82\x00\x0e\x82\x00\x0f\x82

This example shows the results for a Pin Scale pin TX1_d0, which is multiplexed together with one other Pin Scale pin to an HXA pin. Since the MUX flag is set, the combined results of both these pins are returned in the reply.

Byte 0 indicates that TX1_d0 is one of two multiplexed Pin Scale pins, and that it has the logical position 0 in the multiplexing order. Byte 2 and 3 contain the information that the cycle contains 16 edges.

Byte A is the same for all edges and says that the edge is associated with a fixed value (not a data parameter), and that the waveform to which it belongs occupies position 0 in the device cycle. The edges of the two Pin Scale pins are interleaved according to the logical position in the multiplexing order. The edges of TX1_d0, which has position 0, are those with an even edge index (byte B), starting from 0. The edges of the other multiplexed Pin Scale pin (position 1) have an odd index. The actions (byte C) are also the same for all edges, namely an edge compare to 0 where expected = received value (that is, no error).

Example 2

The EARD? answer will be split if the requested cycle range is greater than the available error map information, as shown below:

> EARD? 0,15000, (pin1)
< EARD 0, 100, BOTH, NOER, (pin1), BinData        (a)
< EARD 100, 9900, BOTH, PF, (pin1), BinData       (b)
< EARD 10000, 5000, 1, NOER, (pin1), BinData      (c)
