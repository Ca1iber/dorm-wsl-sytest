PPMU_PIN_MEASURE

The PPMU_PIN_MEASURE class is the data container holding the object reflecting the pin PMU's measurement modes and compare modes.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PpmuPinMeasure.h.

Constructor
This class has no constructor. Instances of this class are created by using the pin() of the PPMU_MEASURE class.
Member functions

Member functions

execMode()
PPMU_PIN_MEASURE & execMode(TM::DCTEST_MODE mode);
PPMU_PIN_MEASURE & execMode(const STRING& mode);

This function selects the measurement mode from the following specifiers:

Parameter
mode The measurement mode. The following types are available:

TM::GPF

"GPF"

 This mode executes a global pass/fail measurement. The test will pass if all of the measurements pass. The test result can be retrieved with the getPassFail() member function.

TM::PPF

"PPF"

 This mode executes a per-pin pass/fail measurement. The pass/fail result for each measured pin can be retrieved with the getPassFail(const STRING & pinlist) member function. In this mode, you can also retrieve the global pass/fail result with the getPassFail() member function.

TM::PVAL

"PVAL"

 This mode executes a per-pin value measurement. The result value for each measured pin can be retrieved with the getValue(const STRING & pin) member function. In this mode, you can also retrieve the Global Pass/Fail result and the Per-pin Pass/Fail result by using the getPassFail() and getPassFail(const STRING & pinlist) member function, respectively.

TM::OVAL

"OVAL"

This mode executes a "only-value" measurement directly from the ADC (without triggering the sequencer). This measurement mode delivers only a measurement value, but no pass/fail information.

The result can be retrieved by the getValue() member function.

This measurement mode is faster than the measurement in the TM::PVAL mode. Use it when throughput is important.

Note that this mode can only be applied in a PPMU_MEASURE object if no other exec modes are specified. If mixed with other exec modes, it will be mapped to TM::PVAL.

TM::DCTEST_AUTO

"DCTEST_AUTO"

This mode executes the DC test according to the test suite flags.

If the flag Pass value or Fail value is on, the DC test will executes in the same way as the mode TM::PVAL.

If the flag Pass value and Fail value are off, the flag Per pin on pass or Per pin on fail is on, the DC test will executes in the same way as the mode TM::PPF.

If the flag Pass value and Fail value are off, the flag Per pin on pass and Per pin on fail are off, the DC test will executes in the same way as the mode TM::GPF.
numberOfSamples()
PPMU_PIN_MEASURE & numberOfSamples(const INT numberOfSamples);

This function defines the number of samples for value measurement.

In static measurements, a minimum number of samples is automatically applied. This member function can be used to increase the number of samples. The specified samples will be multiplied to the built-in required hardware samples to maintain the same measurement accuracy among different hardware modules which have different implementations of PPMU.

In dynamic measurements on the PS1600, the default number of samples is 1. This allows to capture the waveform in low-cost analog tests. To achieve the specified accuracy you need to specify the number of samples according to the table below.

Parameter

numberOfSamples

The number of samples to be taken for a value measurement: The default is 1; the maximum is 4096.

The required number to fulfill the specification depends on the measurement type and on the current range.

You may specify fewer samples for a higher speed but less accuracy, or more samples for a higher accuracy but lower speed.
measurementType()
PPMU_PIN_MEASURE & measurementType(const STRING& measurementType="PMUM");

This function selects the measurement type for a value or delta value measurement. Note that PMUM will automatically be set as default value.

measurementType The optional type of PPMU measurement . It can be:

"PMUM"

or

TM::PMUM

Defines PPMU pass/fail measurements per pin and per measurement point:

  • In conjunction with execMode("PVAL") it additionally does a value measurement using the BADC.
  • In conjunction with execMode("OVAL") it does only a value measurement using the BADC, but omits the pass/fail judgment on the PPMU.

This is the default value.

"VMUM"

or

TM::VMUM

Defines a value measurement.

It does not use the BADC. Instead it does a true parallel value measurement using a successive-approximation technique on the PPMU level comparator.

You need to specify the waiting time as 300us for dynamic VMUM measurements with PS1600, PS1600-ME, PS9G. No additional waiting time required for static VMUM measurements.

Note For VMUM measurements numberOfSamples is always one (1).

"DVM1"

or

TM::DVM1

 Defines a value measurement for point 1 of the delta value measurement.

"DVM2"

or

TM::DVM2

 Defines a value measurement for point 2 of the delta value measurement.
Depending on the measurement type, the PPMU compare mode used to judge the measurement value is implicit set to the values below:
PMUM Comp=I
VMUM Comp=I
DVM1

Comp=X

By default the reference measurement will not be judged against limits.
DVM2 DVM2

Examples

Example 1: Defining a PPMU value measurement

...
PPMU_MEASURE meas1;
meas1.pin("p1, p2").execMode(TM::PVAL).numberOfSamples(25);
...

This example defines a task to set the "p1" and "p2" pin to per pin value measurement mode and to take 25 samples for this measurement.

Example 2: Executing a PPMU value measurement from a pattern

PPMU_SETTING setting;
PPMU_RELAY relay;
PPMU_MEASURE measure; // define measurement
PATTERN_CONTROLLER p_c;
setting.pin("p1").iForce(-5 uA).min( -100 mV).max( 1000 mV).iRange(100 uA);
relay.pin("p1").status("PPMU_ON");
measure.pin("p1").measurementType("VMUM"); // define value measurement
p_c.label("pattern1").add(setting).add(relay).add(measure);
p_c.execute(); // execute the measurement
p_c.getPassFail(); //get the pass fail result

Example 3: Executing a PPMU delta value measurement from a pattern

PPMU_SETTING setting1;
PPMU_SETTING setting2;
PPMU_RELAY relay1,relay2;

setting1.pin("p1,p2").iForce(5 uA).min(50 mV).max(100 mV).iRange(10 uA);
setting2.pin("p1,p2").iForce(10 uA).min(80 mV).max(120 mV).iRange(10 uA);
setting2.wait(100 ms);
relay1.pin("p1,p2").status("PPMU_ON");
PPMU_MEASURE measure1; //defines measurement at point 1
PPMU_MEASURE measure2; //defines measurement at point 2
measure1.pin("p1,p2").measurementType("DVM1");
measure2.pin("p1,p2").measurementType("DVM2");
relay2.pin("p1,p2").status("PPMU_OFF");
PATTERN_CONTROLLER p_c;
p_c.label("pattern1","@@")
   .add(setting1)
   .add(relay1).add(measure1)
   .add(setting2).add(measure2)
   .add(relay2);
p_c.execute(); //execute a functional test
//  .. result access see Result retrieval API
...
