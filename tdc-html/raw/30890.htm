Topic 30890

Explanation of the Syntax

The syntax of the application model file as listed in Syntax Listing is explained in this topic. The numbers in brackets refer to the line numbers indicated in Syntax Listing.

The first level (init) specifies a dialog with the operator. They are prompted for their ID and the cassette size (3-8). This section can be changed accordingly to reflect the needs on your test floor - prompting the operator for a system identifier or a machine name, for example. The test temperature must be entered by the engineer when they develop the test; it must be either ambient temperature, or one of the numbers in the list of three(6). This value is used to initialize the prober (19). The variable, Cassette_size (8), determines the size of a cassette and is used in the GET_WAFERLIST expression (20) to limit the number of wafers that can be entered for each cassette.

The prober call, ph_init (19), downloads the prober setup and the step pattern from the wafer description file. If necessary it sets the hotchuck to the specified temperature. Using the GET_WAFERLIST (20) expression, the operator must enter the wafer numbers manually. Alternatively, a procedure can be written that reads the wafer numbers from an OCR-reader or from a file. The next lowest level is executed 4 times (21), allowing up to 4 cassettes per lot to be accommodated.

The cassette number is automatically incremented (24) when all wafers in a cassette have been tested. The cassette number is used to get the wafer identifiers from the correct file (25).

On the wafer level the software reads the wafer_id (30) from the file /tmp/waf_list<n> (25).

The call ph_get_wafer (31) unloads the current wafer (if there is one), loads, aligns and profiles the next one, and positions the first die underneath the needles. Probing then begins.

On the device level, the procedure ph_get_die_location (36) gets the actual die location and uses it for data logging purposes. The die is then tested. The call ph_bin_die (44) sends the pass/fail result to the prober. If an inker is installed and enabled, it inks all bad dies. The bin command also causes the chuck to move to the next die. When all dies have been tested, the prober responds with a message indicating that the whole wafer has been tested. If a die falls into the reprobe bin, the procedure ph_reprobe (42) lowers and raises the chuck.

Back on the wafer level, the procedure ph_check_reference_wafer (47) checks if the REFERENCE button was pressed while in the PAUSE state. If it was, the operator is requested to manually unload the last wafer and load the reference wafer. After testing the reference wafer, the operator is asked to unload it and to install the previous one. This part of the code will undoubtedly be subject to customization; for example, if only a few dies on the reference wafer should be tested. Depending on the wafer prober type, it is also possible to reduce the operator interaction when testing a reference wafer.

On the cassette level, the software checks if the output cassette is full (51). This should only be used for probers with a separate output cassette. If the output cassette is full, or there is no output cassette, the operator must load a new one.

Returning to the lot level, the procedure ph_exit (55) aborts, then closes the session.
