Introduction to the GIO library API

The GIO library API allows for the connection of external instruments in SmarTest to the system controller. The GIO library API offers the major part of the functionality that has been provided by SICL up to SmarTest 7.4.

Scope

The GIO library API offers an interface for the user application that shields low-level communication handling towards external instruments from the user. The user application invoking GIO library API functions can be a SmarTest test program release 7.5 and higher running on RHEL7.4, but also any other application outside SmarTest. To this end, the GIO library API is provided as a Dynamically Linked Library (DLL) of shared objects according to the Executable and Linkable Format (ELF).

Basically, the GIO library API offers functions

  • to set up and tear down connections to external instruments,
  • to communicate with external instruments,
  • to monitor and to control the connections to external instruments (handling of service requests, interrupts, errors, SmarTest Work Centers, triggers, etc.).

The functions provided by the GIO library API are of similar nature as the ones of the former SICL. For the relationship to SICL in detail, refer to Porting SICL applications to GIO.

Protocols supported

The following communication protocols are supported by the GIO library API:

  • VXI-11
  • VXI-11 to connect GPIB instruments via LAN-to-GPIB gateway (Keysight E5810)
  • serial interface RS-232.
Note The GIO library API does not provide support for the General Purpose Input/Output (GPIO) protocol and thus no interface to external handlers and probers based on GPIO.

The connectivity to external handlers and probers via GPIO is described in General handler drivers and General prober drivers.

Note The GIO library API does not provide connectivity of the LAN protocol formerly supported by the SICL LIBRARY (SICL-LAN), Instead, VXI-11 is to be used.

The GIO shared library (gio.h) offers access methods that abstract the invocation of low-level driver functions from the user application.

GIO functions

In order to uniquely identify the external instrument or an interface that may connect multiple external instruments, the GIO library API uses an Interface or Device Identifier (IDID). The IDID is returned upon opening a connection to an external instrument or device with the gio_open() function. The IDID replaces the external device or interface identity id of the type INST that formerly had to be declared as INST id in SICL.

The typical appearance of a GIO library API function is

GIO_ERROR functionName(IDID cid, <additionalArguments>)

with

  • GIO_ERROR

    as the error code returned by functionName; a return value GIO_ERR_NO_ERROR indicates the successful completion of the call to the function,

  • cid

    as the connection identifier of type IDID of the subject connection,

  • <additionalArguments>

    as additional arguments, dependent on the definition of functionName, for instance a GPIB command as a string.

Security advice

CAUTION Dependent on your corporate network, it might be necessary to take additional action to prevent exploits caused by the connections to external instruments.

The following hints on security shall help to avoid unnecessary risks.

  • If hosts are protected by a password, make sure to change the factory setting, typical examples "0000" or "12345", to a user-defined one that provides a sufficient level of security.
  • Disable connectivity that is not needed ("hardening"). For instance, if the RS-232 interface is not used, deactivate it.
  • If connectivity over dispersed sites is provided via the corporate network or even the public Internet, use secure protocols such as IPsec.
  • It is recommended to use a separate physical network (second LAN interface) of the system controller to connect external instruments with Ethernet.

Special care is necessary in securing commonplace protocols such as Ethernet, Internet Protocol (IP) family, and Universal Serial Bus (USB).
