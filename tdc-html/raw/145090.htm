Topic 145090

Use of TESTSET and SMC_TEST() test suites with multibin

The topic describes the binning rule and the main use cases using test suites with TESTSET and test suites with SMC_TEST() and its influence on the multibin.

Note

If you use TESTSET within the SMC framework instead of SMC_TEST, binning happens in SMC_SYCHRONIZE according to the binning rules as for SMC_TEST. For details, see Use of SMC_TEST() with multibin.

If you use, within a testflow, the SMC framework and TESTSET test suites independent of each other, binning happens according to the binning rules explained in the examples below.

In general, the first failing test defines the logged multibin. But for SMC_TEST() calls the test suite with the SMC_SYNCHRONIIZE() call defines the point of time in the testflow when SMC_TEST() tests are validated. In this respect, the SMC_TEST() calls do not influence the binning rule, but the test suite with the SMC_SYNCHRONIZE does.

Note The following examples use simplified setups with only one TESTSET object per "TESTSET_<number>" test suite. For more information when using more than one TESTSET object, see Use of TESTSET with multibin.

Examples

Example 1: Failing non-SMC test followed by failing SMC test

In a testflow a test of the non-SMC test suite TESTSET_6 fails before a test of SMC_TEST_4 fails and before SMC_SYNCHRONIZE is called.

Test suite Type State Bin
TESTSET_6 non-SMC Fail Logged
SMC_TEST_4 SMC Fail
SMC_TEST_5 SMC Fail
SMC_SYNCHRONIZE SMC n.a.

The failing test of non-SMC test suite TESTSET_6 is logged to the multibin.

Example 2: Failing SMC test followed by failing non-SMC test

In a testflow a test of the non-SMC test suite TESTSET_6 fails after a test of SMC_TEST_4 fails but before SMC_SYNCHRONIZE is called.

Test suite Type State Bin
SMC_TEST_4 SMC Fail
TESTSET_6 non-SMC Fail Logged
SMC_TEST_5 SMC Fail
SMC_SYNCHRONIZE SMC n.a.

Example 3: Failing SMC test followed by multiple failing non-SMC test using temporary TESTSET() objects

In a testflow a test of both the non-SMC test suites TESTSET_6 and TESTSET_7 fails after a test of SMC_TEST_4 fails but before SMC_SYNCHRONIZE is called. Both non-SMC testsuites are using temporary TESTSET() objects. All tests fail before SMC_SYNCHRONIZE is called.

Additional to the rule explained above, the rule for multiple test suites with temporary TESTSET objects applies (see Multiple usage of the temporary object in Use of TESTSET with multibin).

The failing test of TESTSET_7 is logged to the multibin.

Test suite Type State Bin
SMC_TEST_4 SMC Fail
TESTSET_6 non-SMC Fail
TESTSET_7 non-SMC Fail Logged
SMC_TEST_5 SMC Fail
SMC_SYNCHRONIZE SMC n.a.

Example 4: System prepared TestSet object in combination with temporary TESTSET object

In a testflow all tests of the test suite TestSet (using the system-prepared TestSet object) and test suite TESTSET_temporary (using a temporary TESTSET() object) fail after a test of SMC_TEST_4 fails but before SMC_SYNCHRONIZE is called.

Additional to the rule explained above, the rule for multiple test suites using temporary TESTSET() objects applies (see Multiple test suites section in Use of TESTSET with multibin).

The failing test of TESTSET_temporary is logged to the multibin.

Test suite Type State Bin
SMC_TEST_4 SMC Fail
TestSet non-SMC Fail
TESTSET_temporary non-SMC Fail Logged
SMC_TEST_5 SMC Fail
SMC_SYNCHRONIZE SMC n.a.
