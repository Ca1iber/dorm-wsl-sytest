FOR_EACH_TEST_BEGIN_WITH_RESET

FOR_EACH_TEST_BEGIN_WITH_RESET() works together with FOR_EACH_TEST_END() as a pair to declare a block for testing shared sites. It has a similar function as FOR_EACH_TEST_BEGIN(). The only difference is that FOR_EACH_TEST_BEGIN_WITH_RESET() can prevent the sites which are not under test from drawing current by setting the reset pin.

In this block:

  • The shared sites under test are divided into several groups according to the utility control settings of the Sharing configuration file.
  • These groups will be tested sequentially but the sites of a group are tested in parallel.
  • The utility settings will be restored at the end of tests.
  • You can use GET_SITES_UNDER_TEST() to get the currently tested sites.

This API is defined in the header file /opt/93000mts/mts/solution_tools/common/include/SHARED_UTIL.h.

Syntax

FOR_EACH_TEST_BEGIN_WITH_RESET(configFile,testName,resetPin)

Parameter

Description

configFile

The name of the sharing configuration file you want to use.

This file must be be in the <device directory>/configuration/ directory. FOR_EACH_TEST_BEGIN_WITH_RESET will automatically use the SHARING_CONFIGURATION API to load the file for you.

testName

The name of a utility control line in the utility_control section of Sharing configuration file. Multiple names are separated by commas.

The name represents all settings of a utility control line.

If there is one name, the FOR_EACH_TEST_BEGIN_WITH_RESET and FOR_EACH_TEST_END block will automatically execute the represented utility control settings.

If there are more than one names, you must execute each represented utility control settings manually by using GET_CURRENT_UTILITY_CONTROL() and SHARING_CONFIGURATION.utilityActionExecute().

resetPin

Name of the reset pin.

If there is no pin specified for resetPin, the FOR_EACH_TEST__BEGIN_WITH_RESET marco works the same as FOR_EACH_TEST_BEGIN.

Examples

Example1: Execute IDD tests for each shared sites

Assume the default.cfg sharing configuration file is used, which contains these settings:

domains: 8
4 3 2 1 ; 5 6 7 8
12 11 10 9 ; 13 14 15 16
utility_control:
idd;(y<1);(U3=0x222&0xfff);(DEVICE_SUPPLY=VDD)
idd;(y>=1);(U3=0x111&0xfff);(DEVICE_SUPPLY=VDD)
iddq;(y<1);(U3=0x777&0xfff);(DEVICE_SUPPLY=VDD)
iddq;(y>=1);(U3=0xbbb&0xfff);(DEVICE_SUPPLY=VDD)
oc_reset;(U2=0x000&0x400,U2=0x400&0x400,U3=0x000&0xfff,U2=0x000&0x401)
default;(U3=0x000&0xfff,U2=0x000&0x401)

This IDD test program fragment tests all sites:

FOR_EACH_TEST_BEGIN_WITH_RESET("default.cfg", "idd", "nRESET");
{
  // As the utility control setting, it will test the shared sites in two steps:
  //(4, 3, 2, 1, 12, 11, 10, 9) and (5, 6, 7, 8, 13, 14, 15, 16).
  // Without utility control setting, it will test all the sites in one step.

  // measurement of IDD of the VDD pins
}
FOR_EACH_TEST_END();

Example2: Execute IDD and IDDQ tests for each shared sites

Assume the same sharing configuration file as in the example 1 is used.

This test program fragment performs IDD and IDDQ tests on all sites:

FOR_EACH_TEST_BEGIN_WITH_RESET("default.cfg", "idd, iddq", "nRESET");
{
  //As the utility control setting, it will test the shared sites in two steps:
  //(4, 3, 2, 1, 12, 11, 10, 9) and (5, 6, 7, 8, 13, 14, 15, 16).

  //Since there are two testNames in FOR_EACH_TEST_BEGIN_WITH_RESET(),
  //you have to execute the respective utilities by yourself.

  int index = GET_CURRENT_UTILITY_CONTROL("idd");
  SHARING_CONFIGURATION::getInstance().utilityActionExecute(index);
  // measurement of IDD of VDD pins

  index = GET_CURRENT_UTILITY_CONTROL("iddq");
  SHARING_CONFIGURATION::getInstance().utilityActionExecute(index);
  // measurement of IDDQ of VDDQ pins
}
FOR_EACH_TEST_END();
