Setting up a DC resource as a digitizer is like setting up a real digitizer.

About this task

The DC resources that can be used as digitizers include DC Scale, PPMU, and board ADC. The result waveform can be retrieved with the function getWaveform().

Procedure

  1. Specify the port to set up with port().

    It is optional for DC Scale pins and it is a must setup for PPMU and board ADC with the trigger mode.

  2. Create a test with the class dc().
  3. Specify pins to do the capture with pin().
  4. (optional) Specify a force action with iForce() or vForce().
  5. Use vMeas() to capture the voltage waveform and use iMeas() to capture the current wavefrom. By default, vMeas() is used.
  6. Specify the number of samples to capture with samples().
  7. Specify a sampling frequency with FS(), sampleCycle() or samplePeriod().
  8. (For PPMU and board ADC) Specify a capture mode with capMode(). It can be either trigger mode or vector mode.
  9. (For PPMU) Specify an instrument to get the value with valueMode(). When it is used together with samples(), the default mode is TA::BADC.
  10. Execute the setup with the function execute().

Results

The DC resource is set up as a digitizer.

Note When PPMU is used as AWG, its default relay action is the same as a normal PPMU measurement:
Parameter Description
rly_before The relay actions before a PPMU measurement. The default value is TA::ppmuRly_onPPMU_offACDC.
rly_after The relay actions after a PPMU measurement. The default value is TA::ppmuRly_NO. If not specified, the relay will not be changed after the measurement.
You can use relay() to change the relay actions. See relay().
Note About the sampling by samples() on DC Scale, PPMU, and BADC:

The samples() … execute() command can have two different execution behaviors: blocking execution and non-blocking execution.

For example, 
RDI_BEGIN();
   rdi.dc().pin(A).....samples().FS().execute();// Command 1
   rdi.func().label().....execute(); // Command 2
RDI_END();

In this example,

  • If Command 1 runs in the non-blocking execution, pin(A) will keep sampling while Command 2 is running the pattern till the block end.
  • If Command 1 runs in the blocking execution, Command 2 will run the pattern after the pin(A) sampling has been done.
Points to remember:
  • For DC Scale, all the sampling executions with samples() are blocking execution. The pattern will be run after the sampling is done.
  • For PPMU and BADC, the sampling mode depends on the parameter specified by capMode():
    • For capMode(TA::VEC), the sampling is blocking execution.
    • For capMode(TA:TRIG), the sampling is non-blocking execution. The operations of pattern and sampling are running in parallel till the end of the code block.
Example for samples() with capMode(TA::VEC): 
RDI_BEGIN( ); 
   rdi.port("pt").dc().pin("pin").samples(1024).capMode(TA::VEC)...execute(); 
   rdi.port("pt").func().label(B).execute(); // Pattern running after sampling.
RDI_END();
Example for samples() with capMode(TA::TRIG):
RDI_BEGIN( ); 
   rdi.port("pt").dc().pin("pin").samples(1024).capMode(TA::TRIG)...execute();
   rdi.port("pt").label(A).execute();  // Pattern running while sampling.
   rdi.port("pt").wait(TA::WAIT_DCDGT);
   rdi.port("pt").func().label(B).execute(); // Pattern running after sampling.
RDI_END();

Example

rdi.dc().pin("DPS128_1")
        .iForce(2 mA).vMeas().samples(1024).FS(10 KHz).execute();

rdi.dc().pin("DATA1")
        .vForce(1 V).iMeas().samples(1024).capMode(TA::VEC)
        .valueMode(TA::BADC).FS(10 KHz).execute();

rdi.dc().pin("DATA1")
        .vMeas().samples(1024).capMode(TA::VEC)
        .valueMode(TA::SA).FS(1 KHz).execute();

rdi.port("ptPin1").dc().pin("DATA1")
        .samples(1024).capMode(TA::TRIG)
        .valueMode(TA::BADC).FS(10 KHz).execute();

rdi.port("ptPin1").dc().pin("DATA1",TA::BADC)
        .samples(1024).capMode(TA::TRIG).FS(10KHz).execute();
