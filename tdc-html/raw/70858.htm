PIN_UTILITY

When creating a device test, all pins to be tested are defined using the Pin Configuration tool. Some of the pins in this pin list are often defined in pin groups. When a test is created using Test Methods, the test is specified for that pin list, and the measurement results are retrieved on a per-pin basis. The measurement results are associated with the pin names, so you must know the pin names of all the pins in the pin list, including the names of the pins in the pin groups, to retrieve the measurement results for all of the pins in the pin list.

The PIN_UTILITY API is used to expand pin names from a pin list, including the names of the pins in a pin group, and expands a STRING containing pin names that are separated by a comma, for example, "pin1, pin2, pin3,....".

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PinUtility.h.

Class definition

Constructor
This class has no public constructor.

To use the PIN_UTILITY API, you must always use the system-prepared class object PinUtility. You cannot create any object of this class.

expandDigitalPinNamesFromPinList()
const STRING_VECTOR expandDigitalPinNamesFromPinList(const STRING& pinList,
            const TM::PIN_TYPE pinType,
            const BOOLEAN ignoreMissingPinNames)

This member function converts the pin names of the specified pin type contained in the pin list into a string vector. Pin group names will be resolved to pin names. The names in the pin list must be separated by commas.

Since this member function will return a std::vector, you can use all available methods provided in the Standard Template Library (STL) for std::vector, such as loop over all the elements or adding two separate lists.

This member function is only supported for downward compatibility. For new applications, getDigitalPinNamesFromPinList() should be used instead.

Parameter

Description

pinList

The name of the pin list (contains pin names, but also can contain pin group names)

pinType

Type of pin definition. It can be:

TM::I_PIN

TM::O_PIN

TM::IO_PIN

TM::DC_PIN

TM::ALL_DIGITAL

For example, TM::O_PIN|TM::DC_PIN will return all output and dc pins.

ignoreMissingPins

Flag to indicate whether or not to ignore pins that are not defined.

TRUE = no error if the pin is not defined

FALSE = error if pin is not defined
getDigitalPinNamesFromPinList()
const STRING_VECTOR getDigitalPinNamesFromPinList(const STRING& pinList,
            const TM::PIN_TYPE expectedPinTypes,
            const BOOLEAN throwErrorOnMissingPinNames,
            const BOOLEAN throwErrorOnMismatchedPinTypes,
            const SORT_ORDER sortOrder);

This member function, which is similar to expandDigitalPinNamesFromPinList(), converts the pin names of the specified pin type contained in the pin list into a string vector. Pin group names will be resolved to pin names. For pins defined in pin groups, the pins are listed in alphabetical order or pin group definition order. The names in the pin list must be separated by commas. You can cause the function to throw an error if the list contains undefined pins or pins that do not have the requested type.

Since this member function will return a std::vector, you can use all available methods provided in the Standard Template Library (STL) for std::vector, such as loop over all the elements or adding two separate lists.

Parameter

Description

pinList

The name of the pin list (contains pin names, but also can contain pin group names)

pinType

Type of pin definition. It can be:

TM::I_PIN

TM::O_PIN

TM::IO_PIN

TM::DC_PIN

TM::ALL_DIGITAL

For example, TM::O_PIN|TM::DC_PIN will return all "o" and "dc" pins.

throwErrorOnMissingPinNames

Flag to indicate whether or not to ignore pins that are not defined.

TRUE

An error is thrown if any pin in the list is not defined.

FALSE (default)

Undefined pins are not transferred into the vector. No error is thrown.

throwErrorOnMismatchedPinTypes

Flag to indicate whether or not to ignore pin types that are not specified by pinType .

TRUE

An error is thrown if the pin list contains any pin that has not one of the types specified with pinType.

FALSE (default)

Only pins that have one of the requested types are transferred into the vector. No error is thrown.

sortOrder

It controls the order of the returned pins. It can be PIN_UTILITY::ALPHABETICAL for the alphabetical order or PIN_UTILITY::DEFINITION_ORDER for the group definition order.

Since this member function will return a std::vector, you can use all available methods provided in the Standard Template Library (STL) for std::vector, such as loop over all the elements or adding two separate lists.

Parameter

Description

throwErrorOnMissingPinNames

TRUE

FALSE (default)

createPinListFromPinNames()
const STRING& createPinListFromPinNames (const STRING_VECTOR& pinName)

This member function is used to convert a vector of pin names to one pin list string, where the names will be separated by a comma. For example, if the STRING_VECTOR contains three elements pin1, pin2, and pin3, the return will be "pin1,pin2,pin3".

Parameter

Description

pinName

Name of pin name vector

See Example 1, below.

Important points

STRING_VECTOR objects are std::vector objects. Therefore, you can make use of all the methods provided in the Standard Template Library (STL) for std::vector.

You can use the operators +, -, and * to create the union, difference, and intersection of two STRING_VECTOR objects, respectively.

The + operator returns a STRING_VECTOR object that contains all the elements of the two argument vectors without duplicates.

The - operator returns a STRING_VECTOR object that contains all the elements that occur in the first argument vector, but not in the second.

The * operator returns a STRING_VECTOR object that contains all the elements that occur in both argument vectors.

If you use the extended operators +=, -=, or *=, the result will be stored in the first argument vector.

When using the normal operators, which return the const type, you can continue to operate on the result as a normal const variable but not modify them. If you need to perform other changes, you can store the result into your own variable (or instance) first.

See Example 2 below.

Examples

Example 1

STRING pinList  = "pin1,pin2,pin3";
STRING_VECTOR pinNameList;
pinNameList = PinUtility.getDigitalPinNamesFromPinList(pinList, TM::IO_PIN, TRUE,TRUE);
for (uint index = 0; index < pinNameList.size(); index++)
{
     cout << pinNameList [index] << endl;
      // pin1
      // pin2
      // pin3
}

Example 2

STRING pinList1 = "pin1,pin2,pin3";
STRING pinList2 = "pin4,pin5,pin6";
STRING_VECTOR sum, sv1, sv2;
sv1 = PinUtility.getDigitalPinNamesFromPinList (pinList1, TM::IO_PIN, TRUE,TRUE);
sv2 = PinUtility.getDigitalPinNamesFromPinList (pinList2, TM::IO_PIN, TRUE,TRUE);
sum = sv1 + sv2;
sv1*=sv2;

Example 4

This is a complete example that shows how to use PIN_UTILITY together with getDigitalPinNamesFromPinList to extract single pin results. dForceLow, dForceHigh1 and dForceHigh2 are parameters defined in the test method.

/**********************************
 *This test is invoked per site.
 **********************************/
 virtual void run()
 {
 PPMU_SETTING setLeakLow , setLeakHigh ;
 PPMU_MEASURE measLeakHigh , measLeakLow ;
 PPMU_RELAY relClose , relOpen ;
 TASK_LIST tskLeak ;
 /*************************************************************
 * Execution Section:
 * This section will executed only once.
 * ***********************************************************/
 ON_FIRST_INVOCATION_BEGIN();
 setLeakLow.pin ( "leak_pins1,leak_pins2" ).vForce (dForceLow V )
 .iRange ( 100 uA).min( 1.2 uA ).max ( 20 uA ) ;
 // One PPMU_SETTING can hold different values for different pins.
 setLeakHigh.pin ( "leak_pins1" ).vForce (dForceHigh1 V ).iRange ( 100 uA).min( 1.2 uA ).max ( 20 uA ) ;
 setLeakHigh.pin ( "leak_pins2" ).vForce (dForceHigh2 V ).iRange ( 100 uA).min( 1.2 uA ).max ( 20 uA ) ;
 // value only test test OVAL is faster than PVAL
 measLeakHigh.pin ( "leak_pins1, leak_pins2" ).execMode( TM::OVAL );
 measLeakLow.pin ( "leak_pins1, leak_pins2" ).execMode( TM::OVAL );
 relClose.pin ( "leak_pins1, leak_pins2" ).status ( "PPMU_ON" );
 relClose.wait ( 1 ms );
 relOpen.pin ( "leak_pins1, leak_pins2" ).status ( "AC_ON" );
 //Multiple measurements and settings are combined into one measurement.
 //The results of all sites are cashed in the measrement objects.
 //There is not .setup() API needed because the values will NOT change during
 //the testprogram run.
 tskLeak.add(setLeakLow).add(relClose).add(measLeakLow)
 .add(setLeakHigh).add(measLeakHigh).add(relOpen);
 //Execute the Leakage Pattern and the taskList
 CONNECT();
 FUNCTIONAL_TEST();
 tskLeak.execute();
 ON_FIRST_INVOCATION_END();
 /*************************************************************
 * Result upload, calculation and datalog
 * This section will be executed for each site.
 * ***********************************************************/
 STRING_VECTOR pinNameList;
 int SizeOfNameList;
 //Get Results and Datalog from Group leak_pins1
 pinNameList = PinUtility.getDigitalPinNamesFromPinList("leak_pins1", TM::IO_PIN, TRUE,TRUE);
 SizeOfNameList = pinNameList.size();
 for (int index = 0; index < SizeOfNameList; index++)
 {
 TEST(pinNameList[index],"Leakage_Low" ,tmLimits, measLeakLow .getValue(pinNameList[index]), TRUE);
 TEST(pinNameList[index],"Leakage_High",tmLimits, measLeakHigh.getValue(pinNameList[index]), TRUE);
 }
 //Get Results and Datalog from Group leak_pins1
 pinNameList = PinUtility.getDigitalPinNamesFromPinList("leak_pins2", TM::IO_PIN, TRUE,TRUE);
 SizeOfNameList = pinNameList.size();
 for (int index = 0; index < SizeOfNameList; index++)
 {
 TEST(pinNameList[index],"Leakage_Low" ,tmLimits, measLeakLow .getValue(pinNameList[index]), TRUE);
 TEST(pinNameList[index],"Leakage_High",tmLimits, measLeakHigh.getValue(pinNameList[index]), TRUE);
 }
 return;
 }
