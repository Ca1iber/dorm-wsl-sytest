Topic 118933

Terminate SmartCalc threads after binning

If hidden calculation is used, it may happen that one of the tests is failing, while SMC threads are still running. In this case SMC may not be terminated correctly and may cause errors during the next test program execution.

To ensure correct execution, it is required to implement the special test suite bin_disconnect. This test suite is always executed after the binning - instead of the default tester disconnect sequence. With that you have two options to terminate SmartCalc threads.

  • SMC_CLEANUP()

    Execute it inside the special test suite bin_disconnect. It operates on the active site only, so it has to be called outside the ON_FIRST_INVOCATION block. It will terminate the upload thread, but not the calculation running in the background process.

  • SMC_SYNCHRONIZE()

    It can be used similar to SMC_CLEANUP(). However, it will cause SmartCalc to wait for upload and calculation to be finished.

Example

The following example code was created by following the description of Using the special test suite bin_disconnect and has been adapted for SmartCalc. It is valid for both thread per site and common thread (see SmartCalc "Thread per site" and "Common thread").

virtual void run()
{
 ...// example of a customized disconnect
    ARRAY_I enabledSites;
    INT numEnabledSites;
    INT hwBinNumber, goodBin, reprobe, overon, otherwiseBin;
    STRING hwBinDescription, swBinDesciption, swBinNumber;

    const string nonshareddisconnect="ACMD \"CNCT\",\"OFF\",(@NONSHARED@); \
    FLSH MUX;WSDN;DLSO(@NONSHARED@); \
    CNCT OFF,(@NONSHARED@);CHRS OFF; \
    BCMD \"\",ACTION,\"Update\",; \
    PSST OFF;RLYC IDLE,OFF,(@NONSHARED@);";
    const string finaldisconnect ="ACMD \"CNCT\",\"OFF\",(@);FLSH MUX;WSDN; \
    SQST OFF;CNCT OFF,(@);CHRS OFF; \
    BCMD \"\",ACTION,\"Update\",; \
    PSST OFF;RLYC IDLE,OFF,(@);";

    numEnabledSites = GET_ENABLED_SITES(enabledSites);

    SMC_CLEANUP(false); // kills running thread only

    if (numEnabledSites == 0)
    {
        FW_TASK(finaldisconnect); //last enabled site to be disconnected 
    }
    else
    {
        //not the last site to be disconnected
        //only disconnect current site and keep shared resources connected
        FW_TASK(nonshareddisconnect);
    }

    return;
}

This example works regardless of the used pin Mode contexts.
