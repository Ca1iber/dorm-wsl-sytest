Topic 98956

How to create a universal test method class

Subtopics

  1. Working with Content Assist
  2. Working with Test Method Panel

This topic shows how to create a test method class step by step in SmarTest.

About this task

To create a test method class, use the Create a new TestMethod class wizard.

Before you begin

Make sure you are using SmarTest 6.3 or later, and a test method project has been created.

Procedure

  1. In the C/C++ perspective, right-click the test method project and select New > Test Method Class. The Create a new Test Method class wizard will pop up.
    Note You can separate the header file and source file by checking the box before Separate Header File and Source file.
  2. In Templates filed, select:
    • Normal test method class for normal test method
    • Concurrent test method class for CTF-based test method
    • Customized shmoo test method class for customized shmoo test method

      To easily manage the test methods, it is not recommended to put normal test methods and concurrent test methods in one project.

  3. In the Class Name field type the class name. It must start with an upper case character. Otherwise an error message is displayed as in the graphic above.
    Note Avoid using the same class name for different UTM projects. If you need to use the same class name, put the class source files in project sub-folders to differentiate their relative paths to the projects.
  4. To add input parameters to the test method click Add on the right side of the Parameters area. The "Add a new parameter" window appears.
  5. In the window enter the following parameter data and click OK.
    • Identifier: The parameter name to be shown in the testflow editor.
    • Type: The parameter type.

      The type can be int, double, string, PinString, SpecVariable, SpecValue, ContextPins, OptionList or FileString.

      PinString is used for pins, pin lists or pin groups.

      SpecVariable is used for spec variables defined in the timing or level files.

      SpecValue has the format "value[unit]".

      ContextPins is used to define the parameter CCF_FocusedPins in the concurrent test framework.

      OptionList provides the possibility to enter multiple options as the value of a parameter in this type.

      FileString is used to enter file names as the value of a test method parameter.

    • Variable: The variable name used in the run() function of the test method. It is automatically set as "m" plus parameter name. It can also be changed.
    • Default: (Optional) The default value of the parameter.
    • Options: (Optional) The value candidates of the parameter. The separator between the candidates is a colon (:). These values are displayed when you try to change the parameter value in the test suite view.
    • Comment: (Optional) A string set as the parameter comment.
      Note Parameter hierarchies are supported. You can use "." to create a parameter hierarchy. For example, if you define the parameter x.start, x.stop, x.step and x.scale, they will be displayed in the Properties view as below.
  6. To add output parameters to the test method, select from result0, result1, result2, and result3.
    Note If you need to add or remove the parameters later, you can modify the test method source file directly.
  7. To add limits to the test method, click Add on the right side of the Limits area. Type the limit name and Click OK. Only limit names can be specified here. The limit values are set and modified in the tabular testflow editor. (See Limits tab or Properties View).
  8. In the "Create a new TestMethod class" wizard click Finish. You will see the class source file template in SmarTest.

    For Concurrent test method class, you can also click Next to select the path to store the imported ccf_tml.

    If one ccf_tml is already imported in the project, its version information will be checked. If the version is the same with the version provided with the current SmarTest, it will not be imported again. Otherwise, a warning dialog box will be displayed asking you whether to replace the original version.

  9. For normal test method, enter your source code in the run() function.

    For concurrent test method, implement your test method as described in How to implement a concurrent test method.

  10. To build the project, right-click the test method project in the C/C++ perspective and select Build Project. A dialog box will be displayed to remind you that building or cleaning the project does not make its library effective for the current device. You can also build the test method project by building the device projects that refer to it. (See How to create a universal-test-method-based testflow)
    Note After you add or remove the parameters and rebuild the test method project, open the Properties view for the test suite using this test method, you will see that this view is grayed because the parameters displayed in this view are not consistent with those in the test method code. To activate the Properties view, click the Inconsistency Check button on the top right to update the parameter settings in the view according to the test method code.
  11. If any error occurred during the project building, correct the source file and re-build the project.

    You can check the building information in the C-Build console of the Console view. If multiple projects have been built, you can check the building information for each project in the C-Build console by highlighting the project in the Project Explorer.

Results

You will find the test method library in the Debug sub-directory of the test method project directory. The test method library is located in the directory /home/demo/devices/act299_tml/Debug/.

What to do next
