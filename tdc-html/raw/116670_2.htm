Topic 116670

TTCF, TTCF? - (Transition Test ConFiguration)

TTCF and TTCF? serve to define and query the configuration of a protocol engine test for the specified pins. This configuration is stored in a transition test set, which must have been defined with TTDF. For more information on protocol engine tests see Overview of the protocol engine per pin.

With this command you configure setups of those sites that have the setup focus: For more information, see also: PSFC, PSFC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

TTCF

TTCF {"tt_name"}, {property}, {property_value}, {(pinlist)}

TTCF?

TTCF? {"tt_name"|ALL|PRM|DEFAULT}, {property|ALL}, {(pinlist)}

returns:

TTCF {"tt_name"}, {property}, {property_value}, {(pinlist)}

Parameters

tt_name

Specifies the name of a transition test set that must have been defined with TTDF.

property

Specifies a property of the transition test set. For a list, see the Properties and their values table below.

ALL

This value can be specified in the query to retrieve the configuration data of all transition test sets.

PRM

This value can be specified to modify or retrieve the configuration of the current primary transition test set.

DEFAULT

This value can be specified in the query to retrieve the configuration of the predefined transition test set DEFAULT. Note that the DEFAULT set cannot be changed, it can only be queried.

property_value

Specifies the value for the specified property. The values that are admitted for the individual properties are listed in the table below.

pinlist

Specifies the pins to which this configuration is to be applied.
Properties and their values

Property

Explanation and values

ALL_PATTERN_ERR

This is a collective switch for all pattern matching errors. The possible values are ON and OFF. There is no default.

ALL_TRACKING_ERR

This is a collective switch for all tracking errors. The possible values are ON and OFF. There is no default.

DEVIATION_LIMIT_DUT_BEFORE_ED

This property only applies if X-tokens are removed (REMOVE_XTOKEN_MODE set to ON) and the token size is > 0. It defines the maximum number of UI by which the received data are allowed to exceed the expected data under these circumstances. The received data exceeds the expected data in length if the number of idle tokens in the received data is greater than the number of X-tokens in the expected data. See Skipping idle tokens.

The default is 0. The specified value must be ≤ 256.

DEVIATION_LIMIT_ED_BEFORE_DUT

This property only applies if X-tokens are removed (REMOVE_XTOKEN_MODE set to ON) and the token size is > 0. It defines the maximum number of UI by which the expected data are allowed to exceed the received data under these circumstances. The expected data exceeds the received data in length if the number of X-tokens in the expected data is greater than the number of idle tokens in the received data. See Skipping idle tokens.

The default is 0. The specified value must be ≤ 256.

DISPARITY_MODE

This property determines whether disparity is taken into account when comparing expected tokens with received tokens. This only applies to token size 10.

The possible values are ON and OFF. OFF is the default.

ERR_BADTRAN

This property defines whether the test fails if an illegal sequence of transitions occurred.

The possible values are ON and OFF. ON is the default.

ERR_CNTADJOVR

This property defines whether the test fails if an adjustment overflow occurs. This means that the observation window was adjusted more than 1 UI in one direction within 24 UI. Note that adjustments in opposite direction cancel each other out. Thus if '+' indicates an adjustment to the right, and '-' an adjustment to the left,

- + - + - + - +

is acceptable, but

+ + + + + - + +

creates an overflow.

The possible values are ON and OFF. ON is the default.

ERR_CNTLMT

This property defines whether the test fails if the maximum drift of 7.75 UI for the entire pattern is exceeded.

The possible values are ON and OFF. ON is the default.

ERR_COMPARE

This property defines whether the test fails if compare errors are detected.

The possible values are ON and OFF. ON is the default.

ERR_FTO

This property defines whether the test fails if the number of UI that are skipped for synchronization at test start exceeds the maximum defined with FIRST_INITIAL_SYNC_LIMIT.

The possible values are ON and OFF. ON is the default.

ERR_JMP2

This property defines whether the test fails if an unrecoverable BC transition (jump by 2) is detected.

The possible values are ON and OFF. ON is the default.

ERR_PULSE

This property defines whether the test fails if a bit was sampled only once. If pulse stretching is enabled, the error will refer to the stretched pulse (see Stretching the pulse).

The possible values are ON and OFF. ON is the default.

ERR_STO

This property defines whether the test fails when the number of consecutive skipped bits after initial synchronization exceeds the maximum defined with SUBSEQUENT_INITIAL_SYNC_LIMIT.

This can happen in two cases:

  • at synchronization of an IO pin that has been switched from drive to receive mode, or
  • when too many consecutive idle tokens have been skipped, that is, if

    no_of_tokens * token_size > SUBSEQUENT_INITIAL_SYNC_LIMIT.

The possible values are ON and OFF. ON is the default.

ERR_STOP

This property defines whether the test fails if the sequencer stops too early, that is, before all compare actions have been completed. This error can be avoided by adding an appropriate number of break vectors (at least 400) at the end of the test.

The possible values are ON and OFF. OFF is the default.

ERR_TE0

This property defines whether the test fails if no reference transition occurs, that is, the observation window could not be adjusted successfully.

The possible values are ON and OFF. OFF is the default.

ERR_TE2

This property defines whether the test fails if a BC transition occurs in a block of three UI, for example

LLLL LLHH HHHH

The possible values are ON and OFF. OFF is the default.

ERR_TE3

This property defines whether the test fails if two different transitions occur within a UI (not between two UI) in a block of three UI, for example

LLLL LHHH LLLH

Here the second UI contains an AB transition, and the third UI contains a CD transition.

The possible values are ON and OFF. OFF is the default.

ERR_TE4

This property defines whether the test fails if three transitions occur within a UI (not between two UI) in a block of three UI, for example

HHLL LHHH LLLH

Here the first UI contains a BC transition, the second contains an AB transition, and the third a CD transition.

The possible values are ON and OFF. OFF is the default.

ERR_TRK

This property defines whether the test fails if the maximum drift for the entire pattern as defined with TRACKING_LIMIT is exceeded.

The possible values are ON and OFF. ON is the default.

ERR_TRMCNT

This property defines whether the test fails if the skipped idle bits are not a multiple of the token size.

ERR_XMAX

This property defines whether the test fails if the length of the received data exceeds the length of the expected data by more than the value defined with DEVIATION_LIMIT_DUT_BEFORE_ED.

The possible values are ON and OFF. ON is the default.

ERR_XMIN

This property defines whether the test fails if the length of the expected data exceeds the length of the received data by more than the value defined with DEVIATION_LIMIT_ED_BEFORE_DUT.

The possible values are ON and OFF. ON is the default.

FIRST_INITIAL_SYNC_LIMIT

This property defines how many bits are allowed to be skipped by initial synchronization at test start. The maximum value is 232. This is also the default.

FIRST_INITIAL_SYNC_MODE

This property activates or deactivates initial synchronization at test start.

The possible values are ON and OFF. ON is the default.

IDLE_TOKEN_i

With this property, you can specify idle tokens whose occurrences in the received data are to be counted. i can be 1 through 6. This property only applies to token sizes > 0 and < 18.

PULSE_STRETCHING_MODE_1BIT

 

This property defines if and how much pulses that are sampled only once are to be stretched. For more information see Stretching the pulse.

Possible values are:

NONE

No stretching takes place.

STRETCH_1TO3

1 sample bits are stretched to 3 samples.

STRETCH_1TO4

1 sample bits are stretched to 4 samples.

PULSE_STRETCHING_MODE_2BIT

 

This property defines if and how much pulses that are sampled only twice are to be stretched. For more information see Stretching the pulse.

Possible values are:

NONE

No stretching takes place.

STRETCH_2TO3

2 sample bits are stretched to 3 samples.

STRETCH_2TO4

2 sample bits are stretched to 4 samples.

REMOVE_XTOKEN_MODE

This property activates or deactivates removal of tokens consisting entirely of X from the expected data. The possible values are ON and OFF. For more information see Skipping idle tokens.

This property only takes effect if the token size is > 0.

SUBSEQUENT_INITIAL_SYNC_LIMIT

This property defines how many bits are allowed to be skipped by subsequent initial synchronization. The maximum value is 232. This is also the default.

This property also limits the maximum number of consecutive idle tokens that can be skipped after synchronization, by the following inequality:

number_of_skipped_tokens * token_size ≤ SUBSEQUENT_INITIAL_SYNC_LIMIT

SUBSEQUENT_INITIAL_SYNC_MODE

This property activates or deactivates subsequent initial synchronization, for example after the switch of an IO pin from drive to receive mode. The possible values are ON and OFF. ON is the default. This property only takes effect if FIRST_INITIAL_SYNC_MODE is set to ON.

For more information see Startup latency and initial synchronization.

TOKEN_SIZE

This property defines the token size for the pattern matching block. The allowed values are:

0, 8, 9, 10, 12, 16, 18, 20, 24, 28, 32, 34, 36, 40, 44, 48, 52, 56, 60, 64, 66.

0 is the default. For more information see Pattern matching.

TRACKING_LIMIT

This property defines how much the device is to be allowed to drift during the whole pattern. The maximum value that still allows a reliable tracking is 7.75 UI. This is also the default.

The step width for this parameter is 1/4 UI.

TRACKING_MODE

 

This property defines the operation mode of the transition tracker. For more information see Controlling the tracking behavior.

The possible values are:

ACTIVE

If necessary, the observation window is adjusted after every 3 UI.

FREEZE_AFTER_SYNC

If necessary, the observation window is adjusted once at test start and once after every switch of a IO pin from drive to receive mode.

FREEZE_ALWAYS

The observation window is never adjusted.

Application

Protocol engine tests.

Errors

An error is generated if no transition test set with the specified name exists.

Example

> TTCF? "my_TT_SET",ALL,(PIN1)

< TTCF "my_TT_SET",DEVIATION_LIMIT_DUT_BEFORE_ED,100,(Pin1)
< TTCF "my_TT_SET",DEVIATION_LIMIT_ED_BEFORE_DUT,100,(Pin1)
< TTCF "my_TT_SET",DISPARITY_MODE,OFF,(Pin1)
< TTCF "my_TT_SET",ERR_BADTRAN,ON,(Pin1)
< TTCF "my_TT_SET",ERR_CNTADJOVR,ON,(Pin1)
< TTCF "my_TT_SET",ERR_CNTLMT,ON,(Pin1)
< TTCF "my_TT_SET",ERR_COMPARE,ON,(Pin1)
< TTCF "my_TT_SET",ERR_FTO,ON,(Pin1)
< TTCF "my_TT_SET",ERR_JMP2,ON,(Pin1)
< TTCF "my_TT_SET",ERR_PULSE,ON,(Pin1)
< TTCF "my_TT_SET",ERR_STO,ON,(Pin1)
< TTCF "my_TT_SET",ERR_STOP,OFF,(Pin1)
< TTCF "my_TT_SET",ERR_TE0,ON,(Pin1)
< TTCF "my_TT_SET",ERR_TE2,ON,(Pin1)
< TTCF "my_TT_SET",ERR_TE3,ON,(Pin1)
< TTCF "my_TT_SET",ERR_TE4,ON,(Pin1)
< TTCF "my_TT_SET",ERR_TRK,ON,(Pin1)
< TTCF "my_TT_SET",ERR_TRMCNT,ON,(Pin1)
< TTCF "my_TT_SET",ERR_WRCMP,ON,(Pin1)
< TTCF "my_TT_SET",ERR_XMAX,ON,(PIN1)
< TTCF "my_TT_SET",ERR_XMIN,ON,(Pin1)
< TTCF "my_TT_SET",FIRST_INITIAL_SYNC_LIMIT,10,(Pin1)
< TTCF "my_TT_SET",FIRST_INITIAL_SYNC_MODE,ON,(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_1,"LLLLLHHHHH",(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_2,"",(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_3,"",(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_4,"",(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_5,"",(Pin1)
< TTCF "my_TT_SET",IDLE_TOKEN_6,"",(Pin1)
< TTCF "my_TT_SET",PULSE_STRETCHING_MODE_1BIT,STRETCH_2TO4,(Pin1)
< TTCF "my_TT_SET",PULSE_STRETCHING_MODE_2BIT,STRETCH_1TO3,(Pin1)
< TTCF "my_TT_SET",REMOVE_XTOKEN_MODE,OFF,(Pin1)
< TTCF "my_TT_SET",SUBSEQUENT_INITIAL_SYNC_LIMIT,10,(Pin1)
< TTCF "my_TT_SET",SUBSEQUENT_INITIAL_SYNC_MODE,ON,(Pin1)
< TTCF "my_TT_SET",TOKEN_SIZE,10,(Pin1)
< TTCF "my_TT_SET",TRACKING_LIMIT,4,(Pin1)
< TTCF "my_TT_SET",TRACKING_MODE,ACTIVE,(Pin1)
