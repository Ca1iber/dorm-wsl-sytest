Topic 81319

Reprobe data

Reprobe test results are generated when a device is binned into a reprobe bin, and then the device is retested. Reprobe test records are handled as follows:

SBR and HBR records

The counts in these bin records reflect only the result of the last testflow execution.

Examples

Description

Software bin 11 is marked as a reprobe bin. If a device is tested and binned into software bin 11 (and hardware bin 1), the device will be immediately retested. If the device is retested and binned into software bin 10 and hardware bin 0, the SBR and HBR records will show the device binned into software bin 10 and hardware bin 0; the initial binning into software bin 11 and hardware bin 1 is not reflected in the SBR and HBR records.

TSR records

The TSR records reflect all tests that have been executed. If a device is tested and then retested, the tests from both testflow executions will be reflected in the TSR records.

PRR records

The PART_FLG will correctly reflect the status of the testflow execution. If a device is tested and then retested, the first PRR.PART_FLG record field will have a 0 in bit 0 and bit 1 indicating that this is the first set of test results for the device. The second PRR (that is associated with the retest results) will have a 1 in bit 0 if it is a package test or a 1 in bit 1 if it is a wafer test, indicating that these are retest results.

PCR records

The PART_CNT field will reflect the number of devices tested (not the number of testflow executions). The RTST_CNT field will reflect the number of devices that have had one or more reprobes executed. The GOOD_CNT field will reflect the number of devices that were binned into a good bin on the last testflow execution.
