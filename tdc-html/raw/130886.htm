PS1600 protocol engine per pin

The protocol engine per pin addresses several kinds of non-deterministic behavior of devices like initial latency, drift, and idle tokens. A prerequisite is that all data transitions at the output pins are expected to occur at multiples of a unit interval, defined by period_length/x_mode.

  • Initial latency (or startup latency) refers to varying time spans between the first stimulus to an input pin and the resulting effect at the output pin. This time span can vary between devices of the same kind and even between tests of the same device.
  • Drift is a long-term deviation of the transitions between H and L phases from their expected position. In many situations such a deviation can be tolerated within a certain range. A typical case is source synchronous testing where a common drift of the device clock and the data signal is acceptable as long as the relative timing of both is maintained.
  • Idle tokens: Tokens (or packets) are bit sequences of fixed length. They come in two kinds: Payload tokens contain the user data; idle tokens are inserted between the payload tokens to bridge wait times and must be skipped for the evaluation. It is not predictable when and how many of these idle tokens will be inserted between the payload tokens.

The protocol engine per pin hardware consist of two main parts,

  • a transition tracking block (drift/phase tracking) and
  • a pattern matching block (serial protocol capabilities).

The transition tracking block serves to detect a drift. It takes 4 samples per unit interval and moves an observation window along these oversampled data. When a drift is detected, the window is adjusted accordingly. From the samples, the transition tracker generates a stream of data bits, which is passed on to the pattern matching block.

The pattern matching block compares this data stream with the expected data. It is able to recognize idle tokens, which will then be skipped.

Note Tests using the protocol engine per pin can only be executed in x4 mode or x6 mode.

For further details see Overview of the protocol engine per pin.

Clock Forwarding

If the output clock and the output data exhibit the same moderate common drift, the device should pass a transition test if no other errors occur.

The drift of a clock signal is usually easier to track than the drift of a data signal, whose state may be steady for an extended period of time. The clock forwarding feature allows you to adjust the observation window of the data signals in parallel with the window for the clock pin. Thus you can track even data signals with few transitions reliably.

Clock forwarding is configured in a clock forwarding set. You define the clock forwarding sets in a test method.

For further details see Forwarding the clock.

Note For the PS1600, clock forwarding is restricted to the logical board. In other words, to pins of the same pogo block. See also Implementation details of clock forwarding.
