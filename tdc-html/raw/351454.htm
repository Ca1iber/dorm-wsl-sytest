Topic 351454

SPI predefined transactions

The Register Access library provides many predefined transactions for SPI. These transactions are listed and described in the table below.

Overview of predefined transactions for SPI
Transaction Description
changeSpeed(double freq)

Change the SPI clock speed. The SPI speed can be changed between transactions calls when a register read/write sequence is defined.

The speed is adapted to the resolution of the tester period.

freq: The frequency of clock to be changed to.
clockIdle(int cycles)

Send cycles to leave the clock in the idle state.

The Idle state is defined by the configuration of CPOL.
comment(const string& comments)

Add comments to the generated pattern where the flowing transaction is located.

For debugging the generated pattern, comments can be issued together with the subsequent transaction, for example: spi.comment("AAA").setState(".", ".", ".", ".");.

comments: The user comments in string.
compareData( RA::ULONG64 sendData, int bitLength, RA::ULONG64 expectedData, RA::ULONG64 mask = 0, const std::string& sendParamName = "")
Receive data from DUT and compare against the expected data.
  • sendData: The data to be sent to DUT.
  • bitLength: The bit length of data to be received. The length of the received data is equivalent to the length of the sent data.
  • expectedData: The expected data to be compared with.
  • mask: The mask setting applied on the expected data. Bit 1 stands for mask; 0 stands for no mask. By default, no mask is applied.
  • sendParamName: A tagged string name in reference to the received data.
loopBegin(int numberOfLoops)

Issue the instruction command of loop begin.

A sequencer instruction command loopBegin will be inserted in the generated pattern. It must be used in pair with loopEnd().

numberOfLoops: The number of loops.

For example, 
spi.loopBegin(10);
spi.sendData(0xFF, 8);
spi.loopEnd();
loopEnd()

Issue the instruction command of loop end.

It must be used in pair with loopBegin().
matchLoopBegin(int numberOfLoops, bool continueOnFail = false)

Start a counted match loop. It must be used in pair with matchLoopEnd().

Parameters:
  • numberOfLoops: The number of loops.
  • continueOnFail: Whether the digital sequence continues when the maximum loop number is exceeded and no match is reached.
matchLoopEnd(const string& repeatStateCharacterList = "")

End a block of match loops. It must be used in pair with matchLoopBegin().

repeatStateCharacterList: The state character string of pins when matching is evaluated. Format is: 
pinList1@Pattern1:PinList2@Pattern2:........PinListN@PatternN
  • PinLists are separated by comma.
  • Pattern is DVC name (1 character length) string streams, for example, 1000L1H.
  • Groups of Pinlists and patterns are separated by colon.

By default, it holds the last state of pattern.
receiveData( RA::ULONG64 sendData, int bitLength, const std::string& recParamName, const string& sendParamName = "")

Receive data from DUT.

Data bits are shifted out by following the configurations of CPOL and CPHA.

SPI is full deplux so the sent data on MOSI must be defined.

Parameters:
  • sendData: The data to be sent to DUT.
  • bitLength: The bit length of data to be received. The bit length is equivalent to the length of the sent data.
  • recParamName: A tagged string name in reference to the received data.
  • sendParamName: A tagged string name in reference to the received data.
restoreSpeed()

Restore the speed to its specification.
sendData( RA::ULONG64 data, int bitLength, const std::string& name = "" )

Send data to DUT.

Data bits are shifted out by following the configurations of CPOL and CPHA. For example, when CPOL = CLK_IDLE_LOW and CPHA = LATCH_AT_LEADING_EDGE, the data is latched with the rising edge of clock. SPI is full duplex, so the data received through MISO from DUT is ignored.

Parameters:
  • data: The data to be sent from the tester to DUT. Bit order is decided by getBitOrder() or getBitOrderSend().
  • bitLength: The bit length of data. Those MSBs that exceed the length are cut.
  • name: A tagged string name in reference to the data to be sent. The name can be referred in composeRegisterWriteData().
setState(const string& sclkState, const string& mosiState, const string& misoState, const string& ssState)

Set the state character list of SPI pins.

The lengths of state characters on pins must be the same.

  • sclkState: The state character of SCLK.
  • mosiState: The state character of MOSI.
  • misoState: The state character of MOSI.
  • ssState: The state character of SS.
ssHigh()

Set the SS pin to drive high.
ssLow()

Set the SS pin to drive low.

The SPI protocol typically is enabled by driving SS pin to low.
wait(double waitTime)

Set a hold time.

waitTime: The hold time in seconds.

Example

Transaction definitions for write operations:

virtual void defineWriteRegister(SPI& spi, ULONG64 address, ULONG64 data) {
  spi.ssLow();
  spi.sendData(0,1);
  spi.sendData(address,7);
  spi.sendData(data,8,"data_in");
  spi.sendData(data,8,"data_in2");
  spi.sendData(0,5);
  spi.sendData(getCRC(1,address,data,0),3,"crc_in");
  spi.ssHigh();
...
}
