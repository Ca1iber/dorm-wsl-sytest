Specifying the Test Program for the Measurement

The second step is to prepare a suitable test program. If you are only interested in the testflow time, this is easiest done as follows:

  1. Load your testflow under

    Test Program > Device Information > Testflow.

  2. If necessary, load the shared library containing the user procedures that are called in the testflow.
  3. Select the sublevel_dialog application model under

    Test Program > Testfloor Information > Application Data.

    This application model is shipped with the SmarTest software. It prompts the user to define how often the test program is to be executed, but contains no prober/handler calls and thus loops over one and the same device.

    Furthermore, sublevel_dialog as shipped does not support GDF data logging. You can use event data logging, which is independent from the application model. But even in this case you would have to customize the application model if you want to store the data log stream in a file (MOVE_EVENT_STREAM command).

  4. Save the test program under an appropriate name.

In principle, you can also use an existing test program which contains prober/handler calls. The output of debug mode 3 differentiates between the total test time and the execution time of the testflow (without prober/handler calls) and provides both values. For more details see Understanding the Output of Debug Mode 3

Functional changes
