B2A Errors and Warnings

Errors, warnings, and messages generated by b2a tool can be useful for debugging the conversion process. Summaries of errors and warnings are displayed on the output screen. b2a also generates a log file that contains details about any errors and warnings that occur. By default, the log file will be created with the same name specified as the output (-o option) file name but with the extension .b2alog. If you Do not want to use the default file name, you can specify a log file name by using the -l option. If desired, you can create multiple log files. For example, you could create a separate log file for each debug level.

The errors and warnings that are generated by b2a are assigned unique numbers and are generated in a format such that pattern/label-specific and pin-specific information can be retrieved easily. The messages that are specific to a label/pattern will have the label name in the message. Messages that do not apply to a specific label will not have a label name in the message. For example, a message that is generated while parsing a timing setup file will not have a label name in the message. The following example shows the format of an error/warning message

[ERROR|WARNING] : ERR-NUMBER : [Label/Pattern-name] : Error/Warning message

You can retrieve the following types of information from the log file:

  • All errors/warnings pertaining to a certain label. For example, type the following command to retrieve errors pertaining to label "func_test":

    $grep "func_test" <-o or -l option filename>.b2alog

  • All errors/warnings pertaining to certain pins. For example, type the following command to retrieve errors pertaining to pin "DCLK":

    $grep "DCLK" <-o or -l option filename>.b2alog

  • The first error of every unique error generated. For example, type the following command to retrieve the first error of type "no mapping information for waveindex 1":

    $grep "no mapping information for waveindex 1" <-o or -l option filename>.b2alog | head -1

Errors that do not stop the conversion

If an error does not affect the conversion process, the error is reported and the conversion continues. For example, if a particular label or pattern cannot be converted, the tool skips the conversion of that label or pattern and continues with the conversion of the next label or pattern.

Errors that stop the conversion

If the conversion of a particular label or pattern depends on an earlier pattern or label for which the conversion process failed, the error is treated as a fatal error and the conversion process stops (the B2A tool exits). An example of this type of error is one in which a failure occurs during the generation of a timing file (.tmf file). Since the vector conversion cannot occur without timing map information, the conversion process will stop.
