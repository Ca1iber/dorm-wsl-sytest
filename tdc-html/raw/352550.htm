Result areas and vector memory consumption

Test head cards for the V93000 Smart Scale systems use the vector memory not only for storing the digital pattern but also for storing the error map, digital capture data, scan results, and DC results.

Types of memory

  • Test processor memory

    The test processor has a small embedded memory that is used only as error map memory for recording errors. If there is a large number of errors to be recorded, the error map memory can be redirected to the vector memory.

  • Vector memory
    The larger external vector memory is used for various applications:
    • Digital pattern data or vector data respectively
    • Sequencer instructions
    • Detailed error map
    • Result areas
      • Retention areas / nonvolatile / persistent areas used for digital capture, scan tests, and DC measurements
      • Non-permanent / volatile /areas

Memory management by SmarTest

After loading the patterns there is a rebalance step, which tries to compact the memory layout.

Possible challenges

Dynamic generation of patterns and allocation of result areas within the testflow can lead to the available memory being divided into many small blocks. As a result, larger result areas may then possibly not be allocated.

Result areas handled by SmartRDI:
  • If rdi.hiddenUpload() is used, SmartRDI automatically handles the result area for the result upload. This means that it is not required to define a result area configuration manually but if the required result area is very large it is possible that the pin runs into the insufficient channel memory error in the following test suite executions.

Hints for optimizing the memory usage

We recommend the following procedure to minimize memory consumption and optimize memory usage:
  • Store the pattern generated by SmartRDI in the pattern file and load them in one piece together with other setups.
  • Reserve a common result area at the begin of the testflow after all pattern have been loaded. Use this result area for all following tests that do not use Hidden upload.
  • Pre-allocate also other result areas directly after all pattern have been loaded at the begin of the testflow.
  • For SmartRDI, if test conditions results in different pattern, use user variables to ensure that all branches of the test suites are executed and therefore all required pattern are generated and saved.
  • Use runtime values of SmartRDI to minimize the number of generated pattern.

  • Result areas, automatically created by SmartRDI (see Result areas handled by SmartRDI above), can be deleted using the RESULT_AREA_CONFIG_SET() test method API. This API provides access to some functions, which allows the user to handle result area configurations.
