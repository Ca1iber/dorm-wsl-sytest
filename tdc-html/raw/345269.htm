TESTSET().addAlarm()

This member function of TESTSET adds an alarm to the TESTSET instance. Alarms are accumulated by the instance and included in the data log when the instance is written to the log.

This member function lets you add alarms with custom IDs to the TESTSET instance, and you can also specify that the alarm causes the test result to be fail.

Alarms are logged in alarm attributes.

All alarms added to TESTSET instance are concatenated in the data log when a judgeAndLog...() function is called.

For example:

TESTSET().cont(true).addAlarm("alarm1").addAlarm("alarm2, alarm3").judgeAndLog_FunctionalTest();

If the length of the resulting alarmId string exceeds 255 characters, it is truncated to the first 252 characters plus three dots (...).

For example,
  • "alarm1, alarm2, alarm3, alarm4, alarm5, alarm6, alarm7, alarm8, alarm9, alarm10, alarm11, alarm12, alarm13, alarm14, alarm15, alarm16, alarm17, alarm18, alarm19, alarm20, alarm21, alarm22, alarm23, alarm24, alarm25, alarm26, alarm27, alarm28, alarm29, alarm30, alarm31"
  • becomes
  • "alarm1, alarm2, alarm3, alarm4, alarm5, alarm6, alarm7, alarm8, alarm9, alarm10, alarm11, alarm12, alarm13, alarm14, alarm15, alarm16, alarm17, alarm18, alarm19, alarm20, alarm21, alarm22, alarm23, alarm24, alarm25, alarm26, alarm27, alarm28, alarm29, ...".

Syntax

TESTSET & addAlarm(const STRING &alarmId);
TESTSET & addAlarm(const STRING &alarmId, const bool setToFail);

Parameter

Description

alarmId

The alarm ID that is stored in the EDL as an AlarmAttribute for a test result.

setToFail

If this parameter is true, the test result is forced to fail.

If the parameter is false, the test result is not changed by this alarm.

This parameter is optional. The default is true.

Example

TESTSET().cont(true).addAlarm("myAlarmCondition").judgeAndLog_FunctionalTest();

Functional changes

  1. Introduced in SmarTest 7.5.0
