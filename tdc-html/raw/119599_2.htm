JSWF? - (Jitter Set WaveForm)

The JSWF? query returns the offset sequence of the jitter waveforms for the specified pins in dependence of a specified clock resolution. The clock resolution enters into the calculation of the offset sequence in two ways:

  • The distance between two items of the offset list must be an integer multiple of 4 * clock_resolution.
  • If the second of two consecutive items is smaller than the first, the maximum allowed difference max_diff between the two depends on the clock resolution as follows

    max_diff = clock_resolution/2 - 410 ps.

    If this restriction is not observed in a user defined waveform, JSWF? will correct the list.

With this command you configure setups of those sites that have the setup focus: For more information, see also: PSFC, PSFC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Predependencies

A jitter waveform must have been defined with JSCF. In the case of a predefined waveform, amplitude and period must also have been defined.

Syntax

JSWF? {"jitter_set_name"}, {clock_resolution}, {(pinlist)}

returns:

JSWF {"jitter_set_name"}, {"offset_sequence"}, {(pinlist)}

Parameters

jitter_set_name

Specifies the name of a jitter set that must have been defined with JSDF.

clock_resolution

Specifies the clock resolution on which the calculation will be based. The admitted range is between 880 and 1750 ps.

You can retrieve the clock resolution for a specification with the CLKR? EXACT query.

Note that the unit is pico seconds, not nano seconds.

offset_sequence

The list of the calculated offsets that is returned.

pinlist

Specifies the pins for which the offset sequence is calculated.

Application

Jitter injection.

Examples

Example 1

> jscf? "test",,(IO0)
< JSCF "test",WAVEFORM,SINUS,(IO0)
< JSCF "test",PERIOD,20,(IO0)
< JSCF "test",AMPLITUDE,100,(IO0)
> CLKR? EXACT,101,(@)
< CLKR 101,2.4,1.2,(@)
> jswf? "test",1200,(IO0)
< JSWF "test","0,29,47,47,29,0,-30,-48,-48,-30,-1,29,47,47,29,0,
  . . .
  -1,-30,-48,-48,-30,0,29,47,47,29,0,-30,-48,-48,-30",(IO0)

This example first queries the jitter waveform for pin IO0, and also the clock resolution for timing specification 101. It then calculates the offset sequence for this waveform and clock resolution. Note that CLKR? returns the clock resolution as nano seconds, but that JSWF? expects it to be specified as pico seconds. The reply is displayed in abbreviated form. The total length of the sequence is about 500 items.

Example 2

> JSCF? "test",WAVEFORM,(IO1)
< JSCF "test",WAVEFORM,"150,110,80,70,0"
> JSWF? "test",880,(IO1)
< JSWF "test","150,120,90,70,40",(IO1)

This example shows how JSWF? corrects the offset list if the second of two consecutive items is smaller than the first, and the maximum difference is exceeded.

Functional changes

  1. Introduced in SmarTest 7.0.1
