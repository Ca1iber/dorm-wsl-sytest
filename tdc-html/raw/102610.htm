Loops

The APG program file syntax supports for loops and Counted match loops. You can use these loops for repeating any set of instructions. for loops are specially useful for iterating the same instructions over columns, rows, and banks of memory devices. Match loops are functionally equivalent to repeat...until loops with an upper limit of how often they can be repeated.

Note MTL does not support other types of loops, such as while or repeat loops.

for loops

MTL for loops follow C conventions, with some limitations:

  • Loop variables (that is, the variables that are automatically incremented in each loop iteration) cannot be assigned values in the loop body. For example, this code is not supported:
    for (x = 0; x < 8; x += 1) {x += 1}  # Incorrect
  • The selection of operators that can be used in the loop increment statement is limited to +=, -=, ++, and --.
  • While nested loops are supported, dependent nested loops are not. That is, you cannot program nested loops where the inner loop is initialized with, compared with, or incremented by the current value of the outer loop's loop variable. (See the "Correct nested loop" and incorrect nested loop" examples below.) Neither can inner loops depend on other variables that change in subsequent iterations of outer loops.
  • By default, the values of variables (other than the loop variables themselves) are handled differently in loop iterations by MTL than by C. This is discussed in "Variable handling in loop iterations", below.

Variable handling in loop iterations

There are two ways in which the values of variables are updated in loop iteration by MTP, one of which varies significantly from the standard way C handles variables:

  • By default, the values of variables are not preserved from one iteration to the next. Instead, the variables are reset at the beginning of each iteration to the values they had during the first iteration.

    This behavior can be forced by choosing the Limit Variable Scope option in the compiler control dialog or using the -lvs compiler switch.

  • Optionally, variables can behave like in standard C, preserving their values from one loop iteration to the next.

    To get this behavior, choose the Extend Variable Scope option in the compiler control dialog or use the -evs compiler switch.

To see the effect of the two different behaviors, consider this code snippet:

myVar = 0
for(x=0; x<10; x += 1)
{
  myVar += 1;
}

With the default (limited scope) behavior, myVar has the value 1 in each of the ten loop iterations.

With the standard C behavior (extended scope), the value of myVar changes in each iteration: 1, 2, 3, 4, ...

Counted match loops

For more information about counted match loops, see Counted match loops.

For the usage of counted match loops in the program file, see the Example below.

Note Do not use loop dependent variables in the count expression for counted match loops in the program file.

Syntax

For loops and counted match loops in MTL use the standard C syntax.

Examples

for loops

for (i = 0; i < maxTest; i += 2)
{
...  # any code here
}

Correct nested loop:

for (i = 0; i < 100; i += 1)
{
  for (j = 0; j < 10; j += 1)
  {
...
  }
}

Incorrect nested loop:

for (i = 0; i < 100; i += 1)
{
  for (j = 0; j < i; j += 1) # Incorrect code: the inner
  {                          # loop variable is compared
    ...                      # with the outer loop variable
  }
}

Counted match loops

countedMatch (10) // countedMatchWithBreak(n) for counted match loops with a break. 
{
  MATCH_WRITE_DQ (xAddr, yAddr, DW);
}
Note Do not use counted match loops in the APG program file and device access file at the same time.
