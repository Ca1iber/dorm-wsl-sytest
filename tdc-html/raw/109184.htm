Test method for ADC test

After all the digital setup and analog setup are finished, you need develop a test method to control the ADC test process.

Shown as the above figure, the typical testing flow in a test method program consists of the following five steps.

Changing existing setup data (or setting up new setup data)

You can create new setup data .

You can also change the existing setup data in case that multiple measurements are performed with different conditions in a test method program. APIs for setting up the measurement conditions, which are called Setup APIs.

Executing test

After conditioning the setup data, you can start test execution by using one of Execution APIs, which correspond to the types of tests.

For ADC test which contains digital capture, DIGITAL_CAPTURE_TEST API is used.

Retrieving raw measurement data

After measurement, you can retrieve the raw measurement data (for example, analog waveform data, single value, and so on). APIs for retrieving measurement data are called Result APIs.

For ADC test, the member function getVectors of VECTOR API is used.

Computing data

You can compute the measurement data to obtain the desired parameters. All calculations are performed on the workstation. APIs for computing data are called Computation APIs. They support dozens of computation functions.

For ADC linearity test, DSP_HISTOGRAM, DSP_ADC_HISTOGRAM and DSP_LINEAR APIs can be used to calculate DNL and INL.

For ADC distortion test, DSP_THD API can be used to compute SNR and THD.

Judging result to pass or fail

Comparing the result values against the specified limits, you can judge whether the obtained result has passed or failed in order to determine the pass/fail of the test suite.

APIs for judging the result are called Judgment APIs, such as TEST. In addition to judgment, these APIs can be used for data logging.

Example

The following is an example of test method for ADC linearity which includes the above five steps. Notice that in this example, the integer array "miss_code" has size 1024 because a 10 bit ADC is assumed.

    INT       GlobalOverOn = 1;
    INT       Offline_flag = 0;
    INT       i, num_pts;
    ARRAY_D   dgtz_waveform;
    ARRAY_I   dgtz_waveformI;
    ARRAY_I   histogram;

    LINEARtype    linear_result;
    ARRAY_D     dle, ile;
    INT         miss_number;
    INT miss_code[1024];
    DOUBLE      min_code_size = 0;

/* Step 1: Change existing setup data */
  ON_FIRST_INVOCATION_BEGIN();
    CONNECT();

    GET_TESTFLOW_FLAG("global_overon", &GlobalOverOn);
    GET_SYSTEM_FLAG("offline", &Offline_flag);
       
    Routing.pin(AWG_pin_name).connect(TM::SINGLE);
    FLUSH();
    AWG(AWG_pin_name).enable();

  
/* Step 2: execute test */
  
    DIGITAL_CAPTURE_TEST();
   
    AWG(AWG_pin_name).disable();
    Routing.pin(AWG_pin_name).disconnect();
    FLUSH();
  ON_FIRST_INVOCATION_END();  
 
/* Step 3: Retrieve raw measurement data */

    dgtz_waveformI = VECTOR(cap_label).getVectors();

     //  Adjust for Offset

    num_pts=lin_smpl_pts;
    if(!Offline_flag) {
       dgtz_waveform.resize(lin_smpl_pts);
       for(i=0;i<num_pts;i++) {
          dgtz_waveform[i]=(double)dgtz_waveformI[i+lin_offset_pts];
          }
         }
   
    PUT_DEBUG(adc_pin, "Source", dgtz_waveform);
   

/* Step 4: compute data */
 
    DSP_HISTOGRAM ( dgtz_waveform, histogram, 1, 255, 256);   
    PUT_DEBUG(adc_pin, "Histogram", histogram);
    DSP_ADC_HISTOGRAM ( histogram, &linear_result, dle, ile,
     &miss_number, miss_code, END_PT, min_code_size );
   
    PUT_DEBUG(adc_pin, "ILE", ile);
    PUT_DEBUG(adc_pin, "DLE", dle);

 
/* Step 5: judge result to pass or fail and log result */
   
    TEST( adc_pin, "INL", linear_result.iamax, GlobalOverOn );
    TEST( adc_pin, "DNL", linear_result.damax, GlobalOverOn );
