MTL compiler syntax

Two different kinds of syntaxes are used in MTL files: syntax for configuration files and syntax for the program files

The configuration file syntax is described below; the syntax for program files is described in APG program file syntax. An overview of naming rules and conventions is available in Naming rules and conventions.

Note Files that are created in SmarTest - that is, the timing and pin configuration files - follow a different syntax that is also used for the waveform mapping file and the pin mapping file. Please see the SmarTest documentation for details of this syntax.

Syntax

The MTL configuration file syntax revolves around the concept of keywords and associated values. Both of these as well as additional elements, like comments and whitespace, are described below.

Keywords

Information in the MTL configuration files is structured by keywords, which label the various types of information contained in each file.

Keywords are indicated by surrounding colons: :<keyword>:. For example, some keywords from the APG pattern file are :deviceAccess:, :pinMap:, or :programParam:.

Note Bit size specifications for numbers are enclosed in colons as well, as described in "Values", below.

Keywords are followed by values (see below), which come as simple or complex values:

  • Simple values are strings or numbers and are separated from the keyword by whitespace.
  • Complex values contain additional keywords and usually are similar to tables or records. They are enclosed in curly braces { }.

Most keywords can only occur in one or a few types of configuration files.

The order of the keywords is always irrelevant within a set of curly braces. That is, you can put the keywords and their associated parameters in any order you desire.

Values

Values are data that are associated with keywords. There are four different types of values:

  • Strings. Strings are combinations of alphanumeric characters. If they contain whitespace characters, they must be enclosed in double quotation marks (" "); otherwise, the quotation marks are optional. (If you need to put a quotation marks inside a quoted string, you can escape it with a backslash, for example: "This is a quotation mark \".")
  • Numbers. Numbers can be specified as decimal numbers (with no special formatting) or hexadecimal numbers (which are preceded by 0x). For example, the decimal number 17 would be expressed as 0x0011 in hexadecimal. Unless a number is preceded by a bit size indicator (see below), it is considered a 64-bit number.
  • Large and small numbers. When needed, MTL supports numbers with more or less than 64 bits. These numbers are indicated by a prefix that consists of the number of bits enclosed in colons, for example, :128: -1 or :32: 0xff.
  • Complex values. Complex values consist of keywords and associated values (which can be of any type, including complex). They are always enclosed in curly braces { }. Special conventions exist for making lists easier to read, as described below.

Conventions for lists

In order to make lists (which follow a :format: keyword and are enclosed in curly braces) easier to read, you can use either a tilde or two double quotes to indicate "repeat from the line above". For example:

:format:
{  :pin:  :states:  :data:  }
{  CFM    {0 1}     0       }
{  ""     {0 1}     1       }

The order of the columns is irrelevant, although you must provide the keywords in the first row in the same order as the associated values in the subsequent rows. (For example, if you put the :pin: column last, all pin values must come last in their respective rows.)

Comments

Anything following a number sign (#) is considered a comment and is ignored by the compiler, with the exception of the preprocessor statements (#define, #ifdef, and so on) described in Preprocessor statements. The comment can include the entire line (when the number sign is the first character) or just the end of the line, starting with the # character. For example:

# The following line contains a statement and a comment.
var =+ 2  # Skip odd values

Whitespace

MTL considers spaces, tabs, and carriage returns whitespace and lets you use them interchangeably.

Example

For examples of the MTL configuration file syntax, see the example configuration files in MTL Configuration Files.
