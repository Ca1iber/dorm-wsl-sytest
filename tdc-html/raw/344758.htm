Topic 344758

GPIB communication flow for Delta Eclipse handlers

The table below describes the GPIB commands and queries supported by the Eclipse handlers.

See Conventions for GPIB communication for descriptions of the syntax.
GPIB commands and queries for Eclipse handlers
Message from driver Message from handler Description
Query for handler status:
FR? The driver asks for the status.
FRn

The handler returns FR0 or FR1.

FR0: No devices at the contactor.

FR1: Parts at the contactor are ready for testing.

The tester then queries FULLSITES? to the handler if parts are at the contactor for testing.
Site population:
FULLSITES? The driver asks the handler whether any device is ready for testing at the contactor or not.
Fullsites xxxxxxxx

The handler returns a string that represents devices at the test site.

For example, a string Fullsites xxxxxxxx, where each x character represents four test sites. Each x character is a hexadecimal number that uses four bits to indicate if devices are present. Therefore, if four devices are present, the x value will be F which is 1111 in binary. The devices at test sites 1, 3, and 4 are 1011 in binary or B in hexadecimal.

The response must contain all eight x characters representing the 32 existing test sites.

If four devices are present in a four test site configuration, the handler responses Fullsites 00000000F.
Bin devices:
BINON:xxxxxxxx,xxxxxxxx,xxxxxxxx,xxxxxxxx; (bins 0 to 15)

The driver sends the test results to the handler. The command requires the handler to echo back the result string with the ECHO command for verification.

All 32 characters are required in the command string. Each x character represents the bin assignment for a single test site.

The valid bin characters are 0 to F hexadecimal numbers which are bins 0 to 15. 0 indicates no device on the socket.
ECHO:xxxxxxxx,xxxxxxxx,xxxxxxxx,xxxxxxxx; (bins 0 to 15) The handler returns an ECHO result string to the tester for validation. The results will not bin out at this time until an ECHOOK is received from the tester.
BINON:xyxyxyxyxyxyxyxy,xyxyxyxyxyxyxyxy, xyxyxyxyxyxyxyxy, xyxyxyxyxyxyxyxy; (bins 0 to 255)

The driver sends the test results to the handler. The command requires the handler to echo back the results string with the ECHO command for verification.

32 test sites are represented by the two character xy in the command syntax string. All 64 characters are required in the command string.

The characters are grouped into eight sets that are separated by a comma. Each pair of xy characters represents the bin assignment for a single test site. The valid bin characters are 0 to FF hexadecimal numbers which represents bins 0 to 255. 0 indicates that the socket has no device.

For example, bin 01 = bin 1, bin FF = bin 255, bin AE = bin 174.
ECHO:xyxyxyxyxyxyxyxy,xyxyxyxyxyxyxyxy, xyxyxyxyxyxyxyxy, xyxyxyxyxyxyxyxy; (bins 0 to 255) The handler returns an ECHO result string to the tester for validation. The results will not bin out at this time until an ECHOOK is received from the tester.
ECHOOK The driver confirms that the bin information is correct. That means the BINON and ECHO strings are matched.
ECHONG

The echoed bin data is not correct.

The handler resends a BINON command and waits for an ECHO.
