Example: Writing a protocol based UTM without using protocol wrapper

This example shows how to implement protocol based tests to UTM without using a protocol wrapper.

Initial details

Device & Protocol details

It is presumed that the setup has been done as detailed in Example: Defining a MDIO protocol.

UTM details

An UTM project MDIO_DEV_tml has been created as described in How to create a universal test method project.

An UTM Class MDIO_SingleWrite has been created as described in How to create a universal test method class, without entering parameters or limits in the wizard.

Entering protocol based code to the UTM template

Note This procedure will only point out individual steps allowing you to write a protocol based test definition following the description of Implementing protocol based tests to the test program.
  1. Open the UTM class MDIO_SingleWrite for editing.
  2. Create a protocol based test object MDIOSingleWriteTest.

    Pass the following parameters to the object:

    MDIOSingleWriteTest

    Parameter

    Description

    poMD

    Mandatory. Protocol's port name.

    MPB_NonProtPort

    Multiport bust label that deals with all non protocol ports/pins.

    Optional. If omitted the current sequencer start label is used.

    wt1

    Wavetable to be used for protocol pattern generation.

    Optional. If omitted the current primary setting is used.

    SingleWriteTransactionLabel

    Identifier of the synchronized protocol test label.

    Optional. If not provided, it will be assembled using the name of the current test suite, the multiport burst label and the protocol's port name.

    This is the corresponding code line:

    SYNCHRONIZED_TEST MDIOSingleWriteTest("poMD", "MPB_NonProtPort", "wt1", "SingleWriteTransactionLabel");

  3. Add the write transaction to the MDIOSingleWriteTest object.

    Use the parameters of the protocol's definition and pass in fixed values.

    Add write transaction to MDIOSingleWriteTest

    Parameter

    Value

    phyaddr

    hex 17

    data

    hex 3FFF

    regaddr

    bin 11

    This is the corresponding code line:

    MDIOSingleWriteTest.transaction("write").set("phyaddr", "0x17").set("data", "0x3FFF").set("regaddr", "0b11");

    Note The order of the parameters can differ from the order in the protocol definition, because the .set() function explicitly sets the value of the corresponding parameter.
  4. Complete the protocol based test definition using MDIOSingleWriteTest.flush() .

    At the execution of .flush() SmarTest will determine if the protocol label exists already. If it does not, a new label will be created.

    In this case the label Prot:MDIO:SingleWriteTransactionLabel will be generated (respectively reused) when the test suite is executed. For details on viewing protocol labels, see Protocol pattern specifics of the Pattern Editor.

    In both cases .flush() also links the protocol with the multiport bust label.

  5. Perform a functional test to start the digital sequencer.
  6. Unlink the labels using SYNCHRONIZED_TEST::unlink("SingleWriteTransactionPattern", "MPB_NonProtPort");.

    Unlinking the labels allows the multiport bust label to be used with other transactions. This prevents port conflicts with existing transactions if adding additional.

Excursus - adding a read transaction

Note For offline usage you need to set up a complementary protocol port to simulate the response of the device. However, this is not part of this excursus!

Adding a read transaction to the UTM code basically follows the sequence outlined above. Only the differences are mentioned in this section.

The parameters of the read transaction are usually the same as those of the write transaction.

However, parameters of read transaction can also be bidirectional as shown above. Here phyaddr and regaddr are used as inputs to read the corresponding data from the DUT.

A read transaction can be added to protocol based test object (MDIOReadTest) like this:

MDIOReadTest.transaction("read").set("phyaddr", 17).set("regaddr", 3).capture("data", "DataReadFromPhy17Reg3");

Note The order of the parameters is only important, if pyhaddr and regaddr first have to tell the device which data to output.
Parameters of the read transaction

Parameter

Value

phyaddr

0x17

regaddr

0x3

data

DataReadFromPhy17Reg3

The .set() function works the same way as with a write transaction.

However, the .capture() function will not execute a test and thus not retrieve any data. It just tells the transaction that the parameter data will receive data when executed. The DataReadFromPhy17Reg3 value is a user defined result name that used as reference when retrieving the data.

For retrieving data one has to use the .getResult() function after a functional test has been executed.

The corresponding code line could look like this:

string ReadResult = MDIOReadTest.getResult("DataReadFromPhy17Reg3")

These are the main differences between write and read transactions from a UTM perspective.

From here on you may handle the results similar to other results received from the DUT.

Example

Description

This class, together with the example device setup detailed in Example: Defining a MDIO protocol, can be copied to your UTM class and used as a reference to the previous description.

#include "testmethod.hpp"
#include "mapi.hpp"
using namespace std;

class MDIO_SingleWrite: public testmethod::TestMethod {

protected:
  virtual void initialize()
  {
    //Add your initialization code here
  }

  virtual void run()
  {
    ON_FIRST_INVOCATION_BEGIN();
      cout << "======= MDIO_Single_Write ================" << endl;
      cout << " This test does a single write transction " << endl;
      cout << " Verify the created protocol pattern" << endl;
      cout << " Pattern label is Prot:MDIO:SingleWriteTransactionLabel"  << endl;
      cout << " Check vectors 36-40 for phyadd  17 in hex" << endl;
      cout << " Check vectors 41-45 for regadd  11 in bin"  << endl;
      cout << " Check vectors 48-63 for data    3FFF in hex"  << endl;
      cout << " Compare with MDIO write transaction in Protocol setup "  << endl;
      cout << endl;

      Primary.label("MPB_NonProtPort");

      SYNCHRONIZED_TEST MDIOSingleWriteTest("poMD", "MPB_NonProtPort", "wt1", "SingleWriteTransactionLabel");

      MDIOSingleWriteTest.transaction("write").set("phyaddr", "0x17").set("regaddr", "0b11").set("data", "0x3FFF");

      if (!MDIOSingleWriteTest.flush()) {
        cerr << "flush error \n";
        ERROR_EXIT(TM::ABORT_FLOW);
      }

      FUNCTIONAL_TEST();

      SYNCHRONIZED_TEST::unlink("SingleWriteTransactionPattern", "MPB_NonProtPort");

    ON_FIRST_INVOCATION_END();
    return;
  }

  virtual void postParameterChange(const string& parameterIdentifier)
  {
    //Add your code
    return;
  }

  virtual const string getComment() const 
  {
    string comment = " please add your comment for this method.";
    return comment;
  }
};
REGISTER_TESTMETHOD("MDIO_SingleWrite", MDIO_SingleWrite);
