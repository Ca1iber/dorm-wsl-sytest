Topic 106483

Usage of the fract() function

Not every instance of fract() is evaluated as described in Avoiding rounding problems with the fract() function. Sometimes the function is trivially interpreted as

(<numerator>/<denominator>)*<global_var>.

This is always the case when it is used in a timing set n with n > 1.

Since every Smart Scale port can have a different ECLK value, the fract() statement is evaluated in its primary sense, for timing set 1 of every Smart Scale port, even if it is not the first port within the specification.

Note If fract() is to be used, the period definitions that use the respective global variable must be defined with fract() in timing set 1 of all ports that determine a period (clock) resolution, even if the value of the global variable need not be fractioned.
