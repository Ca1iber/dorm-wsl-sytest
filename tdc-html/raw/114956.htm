TRANSITION_TEST_PINS

The TRANSITION_TEST_PINS class is a container holding an object to represent the transition test features for some pin(s). It provides the methods to modify and query transition test properties. It is a sub-class of TRANSITION_TEST_SET. You cannot directly create an object of it.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/TransitionTestPins.h.

Member functions

trackingMode()

TRANSITION_TEST_PINS& trackingMode(TRANSITION_TEST::TRACKINGMODE mode);

This function sets the tracking mode for the transition test. This property defines the operation mode of the transition tracker. For more information see Controlling the tracking behavior.

Parameter

mode

The transition tracking mode. It can be:

  • TRANSITION_TEST::FREEZE_ALWAYS: the transition test tracking is disabled.
  • TRANSITION_TEST::FREEZE_AFTER_SYNC: the transition test tracking is disabled after synchronization.
  • TRANSITION_TEST::ACTIVE: the transition test tracking is enabled.

trackingLimit()

TRANSITION_TEST_PINS& trackingLimit(DOUBLE limit);

This function sets the tracking limit for the transition test. This property defines how much the device is to be allowed to drift during the whole pattern. For more information, see Drift and transition tracking.

Parameter

limit

The tracking limit of the transition test. The maximum value that still allows a reliable tracking is 7.75 UI. This is also the default. The step width for this parameter is 1/4 UI.

firstInitialSyncMode()

TRANSITION_TEST_PINS& firstInitialSyncMode(Boolean status);

This function sets the first initial synchronization mode. This property activates or deactivates initial synchronization at test start. For more information, see Startup latency and initial synchronization.

Parameter

status

The first initial sync mode. It can be:

  • true means the first initial sync is enabled;
  • false means the first initial sync is disabled.

subsequentInitialSyncMode()

TRANSITION_TEST_PINS& subsequentInitialSyncMode(Boolean status);

This function sets the sub-sequent initial synchronization mode. This property activates or deactivates subsequent initial synchronization, for example after the switch of an IO pin from drive to receive mode. This property only takes effect if the first initial synchronization is activated. For more information, see Startup latency and initial synchronization.

Parameter

status

The sub-sequent initial sync mode. It can be:

  • true means the sub-sequent initial sync is enabled;
  • false means the sub-sequent initial sync is disabled.

deviationLimitEdBeforeDut()

TRANSITION_TEST_PINS& deviationLimitEdBeforeDut(INT limit);

This function sets the deviation limit for expected data before DUT. This property only applies if X-tokens are removed and the token size is > 0. It defines the maximum number of UI by which the expected data are allowed to exceed the received data under these circumstances. The expected data exceeds the received data in length if the number of X-tokens in the expected data is greater than the number of idle tokens in the received data. See Skipping idle tokens.

Parameter

limit

The deviation limit of expected data before DUT. The default value is 0. The specified value must be ≤ 256.

deviationLimitDutBeforeEd()

TRANSITION_TEST_PINS& deviationLimitDutBeforeEd(INT limit);

This function sets the deviation limit for DUT before expected data. It is only valid if remove X token mode is on and the token size is > 0. It defines the maximum number of UI by which the received data are allowed to exceed the expected data under these circumstances. The received data exceeds the expected data in length if the number of idle tokens in the received data is greater than the number of X-tokens in the expected data. See Skipping idle tokens.

Parameter

limit

The deviation limit of DUT before ED. The default is 0. The specified value must be ≤ 256.

tokenSize()

TRANSITION_TEST_PINS& tokenSize(INT size);

This function sets the token size for the transition test patterns. This property defines the token size for the pattern matching block. For more information see Pattern matching.

Parameter

size

The token size. 0 is the default. The allowed values are:

0, 8, 9, 10, 12, 16, 18, 20, 24, 28, 32, 34, 36, 40, 44, 48, 52, 56, 60, 64, 66.

removeXTokenMode()

TRANSITION_TEST_PINS& removeXTokenMode(Boolean status);

This function sets the remove X token mode. This property activates or deactivates removal of tokens consisting entirely of X from the expected data. This property only takes effect if the token size is > 0. See Skipping idle tokens.

Parameter

status

Whether to remove X token mode. It can be:

  • 1: remove X token mode is on.
  • 0: remove X token mode is off.

pulseStretchingMode1Bit()

TRANSITION_TEST_PINS& pulseStretchingMode1Bit(TRANSITION_TEST::PULSESTRETCHINGMODE status);

This function sets the mode of pulse stretching on one bit. This property defines if and how much pulses that are sampled only once are to be stretched. For more information see Stretching the pulse.

Parameter

status

The mode to control pulse stretching on one bit. It can be:

  • "NONE": no streching
  • "STRETCH_1TO3": stretch 1 bit to 3 bits

pulseStretchingMode2Bit()

TRANSITION_TEST_PINS& pulseStretchingMode2Bit(TRANSITION_TEST::PULSESTRETCHINGMODE status);

This function sets the mode for pulse stretching on two bits. This property defines if and how much pulses that are sampled only twice are to be stretched. For more information see Stretching the pulse.

Parameter

status

The mode to control pulse stretching on two bits. It can be:

  • "NONE": no stretching
  • "STRETCH_2TO3": stretch 2 sample bits to 3 sample bits
  • "STRETCH_2TO4": stretch 2 sample bits to 4 sample bits.

idleToken()

TRANSITION_TEST_PINS& idleToken(INT tokenNumber, const STRING& tokenString);

This function defines an idle token as a sequence of bit states.Up to six tokens can be defined. It can be shorter than the token size, in which case the missing states are set to low. See Skipping idle tokens.

Parameters

tokenNumber

The number of the token.

tokenString

The token string.

disparityMode()

TRANSITION_TEST_PINS& disparityMode(Boolean status);

This function sets the disparity mode. It is only available when token size is 10. This property determines whether disparity is taken into account when comparing expected tokens with received tokens.

Parameter

status

The disparity mode. It can be:

  • 1: enable the disparity mode.
  • 0: disable the disparity mode.

firstInitialSyncLimit()

TRANSITION_TEST_PINS& firstInitialSyncLimit(INT limit);

This function sets the limit for the first initial sync. This property defines how many UI are allowed to be skipped by initial synchronization at test start.

Parameter

limit

The maximum number of consecutive UIs skipped before the first compare. The maximum value is 232. This is also the default.

subSequenceInitialSyncLimit()

TRANSITION_TEST_PINS& subSequenceInitialSyncLimit(INT limit);

This function sets the limit for the subsequent initial synchronization.

This property defines how many UI are allowed to be skipped by subsequent initial synchronization.

This property also limits the maximum number of idle tokens that can be removed, by the following inequality:

number_of_removed_tokens * token_size ≤ limit,

where limit is the value set by subSequenceInitialSyncLimit().

Parameter

limit

The maximum number of consecutive UIs that may be skipped after the first compare. The maximum value is 232. This is also the default.

errorControl()

TRANSITION_TEST_PINS& errorControl(TRANSITION_TEST::ERRCTRL_BIT bit, Boolean bitVal);

This function sets the error control bit. It can be one of the options defined in TRANSITION_TEST::ERRCTRL_BIT. For details of each option, see Properties in TTCF, TTCF? - (Transition Test ConFiguration)

Parameters

bit

The error control flag. It can be one of the options defined in TRANSITION_TEST::ERRCTRL_BIT.

enum TRANSITION_TEST::ERRCTRL_BIT

{

ERR_TE3=0,

ERR_TE2,

ERR_TE0,

ERR_TE4,

ERR_JMP2,

ERR_PULSE,

ERR_BADTRAN,

ERR_CNTADJ_OVR,

ERR_CNT_LMT,

ERR_STOP,

ERR_FTO,

ERR_STO,

ERR_COMPARE,

ERR_WRCMP,

ERR_TRMCNT,

ERR_X_MAX,

ERR_X_MIN,

ERR_X_CNT,

ERR_TRK

};

bitVal

The value for a bit. It can be:

  • true: the corresponding transition test error will make the test fail.
  • false: the corresponding transition test error will be disregarded and the test may still pass, if no other errors occur.
