Topic 105045

SetReprobeAction()

This API sets a CI function for "reprobe". The CI function will be called by the FTEST process when some devices fall into the reprobe bins.

Before calling this API, make sure that the corresponding CI library has been loaded. If the reprobe action is a prober/handler driver call and the prober/handler driver is linked to the BLC program directly, this API does not work.

SUCCESS will be returned if no error occurs. Otherwise an error object will be returned indicating the error code, description and severity.

Code

Typical Description

Severity

PARAMETER_EXCEPTION
  • The value of the parameter "FUNCTION_NAME" is empty.
  • The value of the parameter "FUNCTION_TYPE" is empty.
  • The value of the parameter "FUNCTION_TYPE" can only be "EXEC_INPUT", "PROB_HND" or "DB_CALL".

RECOVERABLE

ILLEGAL_OPERATION
  • The designated session ID "XXX" does not exist.
  • The local session does not exist.
  • The corresponding library is not loaded.
  • The function "XXX" doesn' exist in the loaded library.

RECOVERABLE

Parameters

I/O

Parameter

Description

I

FUNCTION_NAME

The name of the BLC reprobe function.

I

FUNCTION_TYPE

The type of the CI function. It can an execute-input call, a prober/handler driver call or a data-bridge call. The parameter value can be EXEC_INPUT, PROB_HND or DB_CALL.

I

PARAMETER

(optional) The parameter of the reprobe function.

Prototype

ParamList inputParams;
Status syncCommand("SetReprobeAction", inputParams);

Example

ParamList inputParams; 
inputParams["FUNCTION_NAME"] = "ph_reprobe";
inputParams["FUNCTION_TYPE"] = "PROB_HND";

Status retVal = syncCommand("SetReprobeAction", inputParams);
if ( retVal.isError() ) 
{
cout<<"error code= " << retVal.code() << " description="
    << retVal.text() << endl;
}

Functional changes
