RESULT_FAIL_INFO

The RESULT_FAIL_INFO class represents the status information of one result.

The class contains getter methods to access each bit of the status byte extracted from the results for one particular pin at one defined result point. One RESULT_FAIL_INFO object corresponds to one status byte of one result obtained from the DC_RESULT_ACCESSOR API.

Member functions

The high/low limit bit contributes to the pass/fail result, the rest of the status bits depends on whether you specified them for a status check. They represent in any case the HW status, but they will only contribute to the pass/fail result if you specified a status check.

The methods that access status bits that contribute to the pass/fail result, end with ..._Failed(); other methods end with ..._Violation().

hasHighLimitFailed()
BOOLEAN hasHighLimitFailed() const;

This function returns TRUE if corresponding value is above upper limit.

hasLowLimitFailed()
BOOLEAN hasLowLimitFailed() const;

This function returns TRUE if corresponding value is below lower limit.

hasUserStatusCheckFailed()
BOOLEAN hasUserStatusCheckFailed() const;

This function returns TRUE if the user defined status check is failed. Which condition failed can be retrieved using the has...Violation() methods.

hasFailed()
BOOLEAN hasFailed()const;

This function returns TRUE if either high limit, low limit, or the user status check fails.

hasHighClampViolation()
BOOLEAN hasHighClampViolation() const;

This function returns TRUE if the corresponding value was clamped by the high clamp.

hasLowClampViolation()
BOOLEAN hasLowClampViolation() const;

This function returns TRUE if the corresponding value was clamped by the low clamp.

hasMeasurementRangeViolation()
BOOLEAN hasMeasurementRangeViolation() const;

This function returns TRUE if the corresponding value has exceeded the measurement range.

hasMeasurementPlacementViolation()
BOOLEAN hasMeasurementPlacementViolation() const;

Returns TRUE if an error occurs in placing the measurement edges.

hasMeasurementTypeViolation()
BOOLEAN hasMeasurementTypeViolation() const;

This function returns TRUE is if the expected and received measurement types do not match (for example, voltage measurement expected but current measurement received).

hasMeasurementViolation()
BOOLEAN hasMeasurementViolation() const;

This function returns TRUE if any of above violations are TRUE. You can use it to obtain first overall status information. Note that this function does not return the status of the high/low limit and that it is independent of the user specified status checks.

Example

virtual void run()
{
    // ...
    // Perform DC Dynamic measurement ....
    ON_FIRST_INVOCATION_BEGIN();

        // settings and relay switching ...
        FUNCTIONAL_TEST();

    ON_FIRST_INVOCATION_END();

    // ...

    STRING pin("dps1");

    // upload the results
    //
    // Define a result accessor object
    DC_RESULT_ACCESSOR allResults;

    // Upload all available results for the pin in RESULT_INDEX addressing scheme.
    // The variable "range" will contain the start index and the length of the uploaded
    // result range. For uploadResult() the length is equal to the number of uploaded
    // results but for uploadFailedResults() it is usually larger than the number of
    // failed results.
    // Before the result data can be accessed, they always first need to be uploaded from
    // hardware/firmware. Each uploadResult() will overwrite the last uploaded results.
    // (independent of the particular DC_RESULT_ACCESSOR object!).

    const TM::RESULT_RANGE range(allResults.uploadResult(pin, TM::RESULT_INDEX));
    if (range.length > 0)
    {
        // Use result accessor member functions getFirstResultPoint() and
        // getLastResultPoint() to obtain iterators (RESULT_POINT objects) to the
        // first and last uploaded results.

        const RESULT_POINT first(allResults.getFirstResultPoint(pin));
        const RESULT_POINT end  (allResults.getLastResultPoint(pin));

        // process the results

        // Loop over the uploaded results using the first and end iterators (RESULT_POINTs)
        // and the increment ("++") operator on an iterator (decrement is not supported).
        for ( RESULT_POINT p = first; p <= end; ++p )
        {
            const bool testPassed         = allResults.getPassFail(p);
            const TM::PHYSICAL_VALUE type = allResults.getMeasurementType(p);

            std::cout << "Test " << (testPassed ? " PASSED " : " FAILED ");
            std::cout << ", Measured value " << allResults.getValue(p);
            std::cout << ((type == TM::VOLTAGE) ? " V " : " A ");
            std::cout << " at point " << p.getIndex();
            std::cout << " at site "  << CURRENT_SITE_NUMBER() << endl;

            if (! testPassed)
            {
                // test has failed at this point
                // obtain the status info to examine the fail reason...
                const RESULT_FAIL_INFO failInfo = allResults.getFailInfo(p);

                // print out the status bits ...
                std::cout << " HighLimitFailed : " << failInfo.hasHighLimitFailed();

                // ...
            }
        }
    }

    // set the test result and send data to datalog ...
    TEST(allResults, TRUE);
}
