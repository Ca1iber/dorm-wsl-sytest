Topic 44850

Script Dependencies

When you program a Command Set script, consider the following dependencies:

  • Max CI_MAX_COMMENT_LEN bytes are written to stdout. This constant is set at 45000 bytes. This value is fixed and cannot be changed.

    Failure to observe this dependency results in a comment truncation warning and possibly causes a script failure with the message ERROR: CI: child died: Write on Pipe. This means that the interface has read the maximum number of bytes allowed and has closed the input medium.

  • The script exit() status is assigned one of the following constants:

    CI_CALL_PASS = 0

    CI_TEST_PASS = 0

    CI_TEST_FAIL = 1

    CI_CALL_ERROR = 2

    CI_CALL_BREAKD = 3

    Failure to observe this dependency results in an undefined return status being returned to the production software. This means that zero bytes of comment are transferred to the application model file variable. The undefined state is treated as an error and an error message is generated. Manual intervention is required and a RETRY and an ABORT button are made available.

  • Any SmarTest Work Center requirements must be satisfied by the user (SIGALRM available).

    Failure to observe this dependency codes an endless loop into the function and results in a production software hang-up, except when the NOWAIT option is used. In this case you are responsible for hanging background processes.

  • Error Messages are your responsibility, and must be written to stderr. This is the medium for passing messages to the report window.
  • If a script forks another process then that process inherits the comment and report passing communication mediums. All sub-processes of the command script must terminate before script termination is accepted.

    Failure to observe this dependency hangs the interface until all child processes exit. Command execution is complete only when it and all child processes have terminated.
