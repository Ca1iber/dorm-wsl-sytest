The MULTI_PORT_BURST Statement

The MULTI_PORT_BURST statement is intended for a setup where the timing ports and the vector ports are identical. It is organized as a table. Every column contains the information for one port; every row contains information of a certain type. The information type is determined for most rows by a row header; rows without a header contain pattern names. The pattern rows must follow the rows with headers. The order of the latter is arbitrary.

The general format of the MULTI_PORT_BURST statement is:

MULTI_PORT_BURST <burst_name> {

PORTS <port_1> <port_2> ... <port_n>

CTIM (CT|NCT) (CT|NCT) ... (CT|NCT)

SEQ_GRPS <group_1> <group_2> ... <group_n>

PHASE (ON|OFF) (ON|OFF) ... (ON|OFF)

<pat_1_1>|"" <pat_2_1>|"" ... <pat_n_1>|""

<pat_1_2>|"" <pat_2_2>|"" ... <pat_n_2>|""

<pat_1_m>|"" <pat_2_m>|"" ... <pat_n_m>|""

...

};

The function of the individual rows is as follows:

  • MULTI_PORT_BURST<burst_name> (mandatory): This line defines the group type within the GROUPS section and the name of the multi-port burst, which is also used as the name of the multi-port specification. This line is copied into the vector configuration file.
  • PORTS<port_i> (mandatory): This line defines the ports for every column. It is copied to the vector configuration file. Note that the timing translation creates a separate wavetable (and therefore also a separate timing map file) and a separate equation set for each of these ports.

    Note also that the ports of the MULTI_PORT_BURST statement must contain every configured pin. This is a restriction that is only required by the ASCII interface; SmarTest also accepts port sets that do not contain all pins.

  • CTIM (CT|NCT) (mandatory): This row specifies for every port whether timing set changes are allowed "between" (that is, before the first vector of) the patterns of this port within the multi-port burst. This line is not copied into the vector configuration file; but the information it contains is integrated into the pattern configuration (*.vbc) files for the individual patterns of the burst.

    If the port is set to NCT, only one timing set is created for all patterns of the port; if the group elements have different ASCII periods, the common test system cycle length will be calculated as described under ctim in The Input Columns. Every pattern of the port must have been set to NCT in the PATTERNS section. Automatic insertion of a CTIM instruction at the start of the first group element is also suppressed.

    If the port is set to CT, different timing sets may be created for different patterns of the port. In this case the automatic insertion of CTIM instructions between vectors of one pattern of the port is controlled by the ctim column of the PATTERNS section (see ctim in The Input Columns). CTIM instructions are always inserted before the first vector of every group element even if the respective group element is associated with the same timing set as the previous element; this can be suppressed by specifying the option -T for the respective pattern in the v2b_options column.

  • SEQ_GRPS<group_i> (mandatory): This line specifies for every port the sequencing group to which it belongs. It is copied to the vector configuration file and then incorporated by the vector translation into the SQLB command that defines the multi-port burst component for the respective port.
  • PHASE (ON|OFF) (mandatory): This line specifies for every port whether or not phase synchronization is to be activated. It is not copied to the vector configuration file.
  • <pat_i_j>|"" (mandatory): This statement specifies for every port the patterns to be included in the multi-port burst. In principle, the patterns must have been defined in the PATTERNS section (port column) for the port of column i. If, however, shots have been defined for a pattern (see Using Shots: the shots Column), you can also specify one of these shots in the format

    <pattern_name>.<shot_no>,

    where <shot_no> must not exceed the number specified in the shots column of the PATTERNS section.

    If the number of patterns is not the same for all the ports, the place holder "" must be used to inform ait which patterns belong to which column. The pattern lines are copied to the vector configuration file.

    All patterns in the same column must share the same equation set. This implies that any EQUATIONS and SPECS blocks that are associated with them in the equations and specs columns (see The Input Columns) of the PATTERNS section must be compatible.
