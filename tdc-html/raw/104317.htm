Topic 104317

Synchronizing vectors in a multi-port setup

Subtopics

  1. Synchronization within sequencing groups
  2. De-coupling ports by separate sequencing groups
  3. Phase synchronization across sequencing groups
  4. Defining sequencing groups

In a multi-port setup, the patterns of different ports can be run in parallel at different speed (with different period lengths). In this case corrective actions must be taken if the user vectors of these ports are to be (re)started simultaneously or at least coordinated in some way. SmarTest supplies two such correction methods of different strength.

Exact synchronicity is achieved by putting the ports into the same sequencing group. This has the effect that the user vectors of the ports in question start simultaneously after every CTIM instruction (including the internal CTIM at test start).

However, sequencing groups impose certain restrictions on the sequencer programs of the involved ports which may not be acceptable (for possible reasons see De-coupling ports by separate sequencing groups). Ports that do not belong to the same sequencing group always start their user vectors at different points in time, but they can at least be synchronized partially. This means that the port that starts its user vectors later starts them at least simultaneously with some user vector of the port that was started earlier. This partial synchronization is activated by setting the PHASE flag for these ports in the multi-port timing specification (see Phase synchronization across sequencing groups).

Functional changes

  1. Introduced before SmarTest 6.3.2
