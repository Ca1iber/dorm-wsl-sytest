Topic 152836

SmartRDI 2.4.5

This section summarizes the changes and new features in SmartRDI 2.4.5.

Changes and new features

Category

Description

General

General features:

  • Non-blocking execution

    See the new parameter TA::NON_BLOCKING in RDI_END().

  • Default Emap location set in the RDI_Configure file

    See the new keyword DEFAULT_EMAP_LOCATION in RDI_Configure file.

  • Support dumping RDI executed code information

    See Level 3 in RDI_INFO_LEVEL.

  • Put RDI_INFO_LEVEL message to a log file

    See the new keyword ENABLE_RDI_INFO_LOG_FILE in RDI_Configure file.

General Improvements:

  • SmartVec upload speed improvement
    • Before SmartRDI 2.4.5, the DIGCAP read mode uploads data at a speed of 1 bit per word; SmartRDI 2.4.5 improves this speed to 32 bit per word.
    • In SmartRDI 2.4.5, the Emap read mode's upload speed is accelerated by changing the default error map location. This improvement takes effect only if the Emap location is set to RAM (default).
  • TMU upload speed improvement

    In SmartRDI 2.4.5, the result upload of TMU pins with the same setup is combined. Because data upload for multiple TMU pins with the same parameters in one RDI_BEGIN()/RDI_END() block is combined, the upload speed is improved.

  • 1st run speed improvement for non-MD5 bursts (SmarTest 7.4.2)

    See BURST_NAME_MD5 in RDI_Configure file.

  • Label content checking with customized label name (SmarTest 7.4.2)

    See the new keyword USER_NAMED_LABEL_CONTENT_CHECK in RDI_Configure file.

SMC

 

 
  • Common thread SMC for error map result

    Since SmartRDI 2.4.5, the error map result supports common thread SMC. See Using SmartCalc (SMC) with SmartRDI and rdi.site().

  • Non-SMC execution for short bursts

    See the new keyword DISABLE_SMC_EXEC_SHORT_BURST in RDI_Configure file.

  • Flexible control of the SMC execution (global ON/OFF)

    By default all RDI_BEGIN()/RDI_END() blocks run in the "SMC execution" mode, which can trigger result hidden upload of the previous tests, and take a longer time (extra 50-100 us) to complete compared to the normal execution. SmartRDI 2.4.5 provides two options to disable the default "SMC execution" mode.

    • A RDI_Configure option as a global setting of the mode. See the new keyword DISABLE_SMC_EXEC_GLOBAL in RDI_Configure file.
    • A pair of commands to set the execution mode for the following RDI_BEGIN()/RDI_END() blocks in code. See the new topics rdi.disableSmcExec() and rdi.enableSmcExec().
  • Improved code structure for SMC
    • In SmartRDI 2.4.5, rdi.site().id().getXXX() can be called anywhere inside a test method's run() function. See rdi.site().
    • In SmartRDI 2.4.5, SMC_DISABLE(true) can be combined with rdi.hiddenUpload(TA::ALL). See rdi.hiddenUpload().

SmartVec
  • Auto burst upload for SmartVec digital capture

    See the new keyword SMV_DIGCAP_AUTO_BURSTUPLOAD in RDI_Configure file.

  • burstLabel() with ports including portSync()

    See "Example 5" in burstLabel().

  • labelName() with MD5 postfix

    See the new parameter TA::MD5_OPTION in labelName().

DC
  • Pattern‑based loadCap() change for AVI64

    Minimum load capacity allowed changes from 1 uF to 1 nF, to fix the "Load Capacity value out of range" issue (CR-110587). See loadCap().

Emap
  • Xmode support

    See the new topic xMode().

UTIL
  • Utility mask for sequencer‑controlled utility lines

    See the new keywords UTIL_DYN_MASK_UNSPECIFIED_PIN and UTIL_DYN_MASK_INACTIVE_SITE in RDI_Configure file.

    See also the new topic Sequencer Controlled Utility Mask with SmartRDI.

portSync
  • portSync with the CTIM (Chang TIMing) instruction

    See the new parameter TA::MD5_CTIM in portSync().

TMU
  • Timeout behavior improvement

    Before SmartRDI 2.4.5, the TMU time out is set to 50 ms, which means that if the digital TMU does not get all results, it will wait for 50 ms after the pattern is finished. In SmartRDI 2.4.5, the timeout of the digital TMU is set to 0 ms, which means that the TMU stops working after the pattern is finished. To keep the same timeout behavior as SmarTest 2.4.4, a flag is implemented in the RDI_Configure file.

    See the new keyword TMU_TIMEOUT_50ms in RDI_Configure file.

Support
  • Return the RDI revision that TM code is built with

    See the new topics rdi.getActiveRdiRev() and rdi.getCompileRdiRev().
