Group mapping table

The group mapping table of the MTPT (STPM MCM mapping tables) describes how the ports, pin groups, and utility purposes from the STPs (source test programs) are named in the MTP (master test program).

The table is stored in a file named groupmap.csv in the MTPT directory. It is created by the generate_template command. The names of the STP ports, pin groups, and utility purposes - called "entities" below - are automatically entered in the STP columns (see <STP name>, below) and the MTP Group column is prefilled with defaults, but you may need to edit these columns according to the type of mapping:

  • STP entity is mapped to an MTP entity: Enter the name of the MTP entity in the MTP Group column.

    You can use this option to rename STP entities (for example, because MTP names including prefixes might otherwise be too long).

  • STP entity is not mapped (does not exist in the MTP): Enter __NC__ in the MTP Group column.

The file is best edited by importing it into the OpenOffice spreadsheet located in the MTPT folder. Editing is also possible in text editors, but this requires you to make sure yourself that all formatting is correct.

Syntax

Each row in the group mapping table describes the mapping of a specific STP entity (port, pin group, or utility purpose). The table contains these columns:

  • STP:<STP name>: Beginning at the left of the table, there is one column for each STP, with the STP name as the column title. The columns list the entity names from the STPs.
  • MTP Group: The name of the entity in the MTP.

    The default name STPM MCM enters in this column is the STP name with the prefix defined in the STP table. (If the "apply prefix on pin config" setting is 0, STPM MCM enters just the STP pin name without the prefix.)

    If an STP entity is not connected to any MTP entity, this is indicated by __NC__.

  • Notes: This column allows both you and STPM MCM to add remarks about the port, pin group, or utility purpose. These notes are just for human consumption and are never processed automatically by STPM MCM. They may be overwritten when the tables are updated, so they are not a suitable place for storing important information.

    STPM MCM initially fills this column with the name of the STP from which an entity is imported and the firmware command that is triggered by the mapping (DFGP for pin groups, DFPT for ports, or DFUP for utility purposes).
