ProfileMgr class

This class is the entry point to the profile subsystem. It allows you to scan the profiles of the current device, access profiles, or activate profiles. The method instance() returns a reference to the single instance of class ProfileMgr.

This class is defined in the header file /opt/hp93000/soc/prod_com/include/ProfileMgr.hpp.

createDefaultProfiles

bool ProfileMgr::createDefaultProfiles()

Creates the default datalog_OFF.prf and datalog_ON.prf profiles by creating a new profiles/ sub-directory under the device directory and placing the two default profiles within it.

This function assumes that the current working directory is "waste", meaning the appropriate target device for this action has already been selected.

If the profiles/ sub-directory already exists, no action is taken, as it is assumed that the user removed or renamed the default profiles for a good reason.

Return code: true upon success; false if the default profiles could not be created.

Parameters: none

createProfile

Profile * ProfileMgr::createProfile(char * filename)

Creates a new profile (assuming the profile associated with the named file does not yet exist), registers the profile in the profile list, and returns a pointer to the newly created profile.

If a profile object associated with this file name already exists, the object is re-used by first reloading the profile from disk (to ensure it is up-to-date) and then returning the pointer to the caller.

Return code: A pointer to the instance upon success; 0 if memory could not be allocated.

Parameter

filename

The name of the file to load and use for creation.

If this is just a file name, the file is created in the profile directory of the current device directory.

If it is a path, it must be an absolute path.

isActiveProfileDirty

bool ProfileMgr::isActiveProfileDirty()

Returns whether the active profile is "dirty" or not, that is, whether the profile settings in memory are different than those on disk. The status us determined by checking the UpToDate"flag in the dm_data shared memory structure.

Return code: true if active profile is dirty; false otherwise.

Parameters: none

readProfileDirs

bool ProfileMgr::readProfileDirs(int & count,char **& fileList)

Returns (by reference) a list of files found in all profile directories, which is essentially a list of strings, where each entry is an absolute path and profile name.

The list is determined by examining which profiles are contained in the device's profiles/ subdirectory.

The information returned by reference is owned by the ProfileMgr; the caller does not need to worry about freeing the memory.

Return code: true if a list could be compiled, false otherwise.

Parameter

count

The number of items in fileList

fileList

The list of available files

reloadProfile

bool ProfileMgr::reloadProfile(Profile * profile)

Reloads a single profile from disk, if possible. This is accomplished by first testing the reload on a clone, as the load could possibly fail and corrupt the existing data. The profile in memory itself is only over-written by the reload if the content of the profile on disk is valid.

Return code: true if the profile could be re-loaded; false if the profile content on disk was invalid.

Parameter

profile

The profile to reload

reloadProfiles

syntax void ProfileMgr::reloadProfiles()

Return code: void

Parameters: none
