Topic 69137

Parametric Test Record (PTR)

Subtopics

  1. Logging user text to PTR records with test methods

Function:

The Parametric Test Record contains the result of a single execution of a parametric test in the test program. The first occurrence of this record also establishes the default values for all semi-static information about the test such as limits, units and scaling. The PTR is related to the TSR by test number, head number, and site number.

Location in the file:

The Parametric Test Record can appear anywhere in the data stream after the corresponding PIR, and before the corresponding PRR.

TEST_NUM
  • Test number
  • Four-byte unsigned integer
  • In multi-port testing, a single pattern port or a specified combination of pattern ports in a test suite is treated as a test.
  • Valid test number is required for reliable analysis.
  • EDL Event:

    TestSuiteStartEventType

    Test

  • EDL Attribute:

    TestIdAttrType

HEAD_NUM
  • Test head number
  • One-byte unsigned integer
  • Value = 1

    If the ATR and GDR indicate that there are more than 255 sites in the test, HEAD_NUM is the number of the site divided by 256. For example, in a record for site 384, HEAD_NUM would be 2.
  • For tests with up to 255 sites: hard-coded value

    For tests with more than 255 sites: derived from SiteID

SITE_NUM
  • Test site number
  • One-byte unsigned integer

    If the ATR and GDR indicate that there are more than 255 sites in the test, SITE_NUM is the number of the site modulo 256. For example, in a record for site 600, SITE_NUM would be 88.
  • EDL Event:

    TestFlowStartEventType

  • EDL Attribute:

    SiteIdAttrType

RESULT
  • Test result
  • Four-byte floating point number
  • The RESULT field is considered valid only if TEST_FLG bits 0, 1, 2, 3, 4 and 5 and PARM_FLG bits 0, 1, and 2 are all set to 0.
  • If any of these bits are set to 1, then the RESULT field is invalid.
  • EDL Event:

    TestEventType

  • EDL Attribute:

    TestValueResult -> Value

    MeasuredRange -> MinValue

TEST_TXT
  • Test description text or label
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum 255 bytes
  • Length byte = 0 if invalid or missing data
  • For multi_port testing, contains the string <test suite name>@<pattern port name>.
  • The test text contains: "Test suite name: test name#test comment" for MPR's and FTR's. Where '#' is the separator which can be configured in the config file. The comment is logged from the test method api and is optional.
  • It contains "Test suite name: test name#pin name#test comment" for PTR's if there is a pin name associated with the PTR. Where '#' is the separator which can be configured in the config file. The comment is logged from the test method api and is optional.
  • EDL Event:

    TestSuiteEndEventType

    TestEventType

    User Procedure

  • EDL Attribute:

    TestSuiteNameAttrType

    TestSuiteNameAttrType + port

ALARM_ID
  • Name of alarm
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum 255 bytes
  • Length byte = 0 if invalid or missing data
  • If the alarm flag (bit 0 of TEST_FLG) is set, this field can contain the name or ID of the alarms that were triggered.
  • Alarm names are tester-dependent.
  • Hard-coded value

OPT_FLAG
  • Optional data flag
  • Variable length bit-encoded field

 

 
  • The OPT_FLAG field may be omitted if it is the last field in the record

  • EDL Attribute:

HLM_SCAL

  • EDL Attribute:

    PassRangeAttrType

LO_LIMIT
  • Low test limit value
  • Four-byte floating point number

  • EDL Event:

    TestEventType

  • EDL Attribute:

HI_LIMIT
  • High test limit value

UNITS
  • Test units
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum of 255 bytes
  • Length byte = 0 if missing or invalid data
  • V, A, etc (not mV or µA)
  • EDL Event:

    TestEventType

  • EDL Attribute:

    ValueResultAttrType -> Units

    MeasuredRangeAttr -> Units

C_RESFMT
  • ANSI C result format string
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum of 255 bytes
  • Length byte = 0 if missing or invalid data
  • Hard-coded value of '%7.9f'
  • Set by the TESTSET().resFmt function.

C_LLMFMT
  • ANSI C low limit format string
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum of 255 bytes
  • Length byte = 0 if missing or invalid data
  • Hard-coded value of '%7.9f'
  • Set by the TESTSET().llmFmt function.

C_HLMFMT
  • ANSI C high limit format string
  • Variable length character string
  • First byte is unsigned count of bytes to follow
  • Maximum of 255 bytes
  • Length byte = 0 if missing or invalid data
  • Hard-coded value of '%7.9f'
  • Set by the TESTSET().hlmFmt function.

LO_SPEC
  • Low specification limit value
  • OPT_FLAG bit 2 = 1
  • Hard-coded value

HI_SPEC
  • High specification limit value
  • OPT_FLAG bit 3 = 1
  • Hard-coded value

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.1.1: The values of the C-RESFMT, C_LLMFMT, and C_HLMFMT fields are no longer hardcoded.
  3. SmarTest 7.2.2: Added HEAD_NUM and SITE_NUM conventions for tests on more than 255 sites.
  4. SmarTest 7.5.0: TEST_FLG bit 0 is no longer hard-coded
