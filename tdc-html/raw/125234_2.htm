TORT? - (Timing/Level Offset search Result Transitions)

The TORT? query retrieves the offsets for the left and right boundaries of the pass area for the latest search.

  • If the latest search is a timing search, TORT? retrieves the offsets for timing boundaries.
  • If the latest search is a level search, TORT? retrieves the offsets for level boundaries.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Syntax

TORT? {(pinlist)}

returns:

TORT {left_boundary|NOT_FOUND}, {right_boundary|NOT_FOUND}, {(pinlist)}
Note The returned transition value is the latest passing value near to the transition.
Parameters

left_boundary

The offet of the left boundary or lower level of the pass area found by the last timing or level search, where the fail-pass transition was found.

Units for timing searches are [ns].

Units for voltage searches are [mV].

right_boundary

The offset of the right boundary or upper level of the pass area found by the last timing or level search, where the pass-fail transition was found.

Units for timing searches are [ns].

Units for voltage searches are [mV].

NOT_FOUND

This is returned if no search was executed, the search results were reset, or the search was aborted.

pinlist

The pins for which the offsets are to be returned.

Application

Embedded timing and level search.

Example

TORT? (@)
TORT NOT_FOUND,NOT_FOUND, (p1,p2)

Functional changes

  1. Introduced in SmarTest 7.0.3
  2. SmarTest 7.2.1: Supports the query for the boundary of level offset search results.
