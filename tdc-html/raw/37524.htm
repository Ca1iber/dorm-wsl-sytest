Topic 37524

Keeping the Clock Alive

Subtopics

  1. Setting Up a Continuous Clock with the KEEP_PLL_ALIVE Feature
  2. Using the KEEP_PLL_ALIVE Feature with a Multi-Port Vector Setup

SmarTest always activates the actual primary timing and level sets when a connect sequence is executed (as, for example, at the start of every test flow). By default, it also activates them before the start of a functional test whenever necessary. Finally, new timing or level sets are activated within a functional test when CTIM or CLEV sequencer instructions occur in the sequencer program of the test.

Whenever a primary set is activated, the driver is put into a static state for a short time; during this time no signals are sent to the DUT. But in certain cases, for example when testing a PLL device, the PLL clock must be running continuously (must be kept alive) during the whole testflow. This can be achieved by combining two features of SmarTest:

  • the multi-port capability, which allows you to run different sequencer programs with different timings for different pins simultaneously, and
  • the firmware command FTCG, which serves to completely suppress loading of timing and level sets at the start of a functional test (not within a connect sequence).

The multi-port capability is used to put the PLL clock pins and the data pins into separate ports, which must also belong to different sequencing groups. You can then use FTCG to suppress activation of timing and level sets at the start of functional tests for the sequencing group of the PLL port. The multi-port capability also allows you to keep the sequencer program of the PLL port free of any CTIM or CLEV instructions that are required for the data pins.

In addition, you must define the break waveform for the clock pins so that it also generates the clock signal, that is, it must be identical with the normal waveform for these pins. This serves to perpetuate the clock signal between functional tests when the sequencer is in the BREAK state.

As long as no CTIM or CLEV instructions are required for the data pins it suffices to distribute clock pins and data pins between different timing ports, and let them share the same vector port. But if one of these instructions is necessary for the data pins, the two groups of pins must also have different sequencer programs, and therefore belong to different vector ports (as illustrated by the figure in General Overview of Multi-Port Testing), in order to avoid a signal interruption for the clock pins.
