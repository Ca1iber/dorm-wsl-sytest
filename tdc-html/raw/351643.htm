Register structure

Register structure is based on a CMSIS-SVD XML hierarchy. A CMSIS-SVD XML file normally contains the structure description of a single device. The file must be converted to a C++ structure before the register structure can be used in test methods.

According to CMSIS-SVD , an SVD file usually describes the structure of a device. A device is formed of a processor and at least one peripheral. Each peripheral has at least one register. A register can have one or more fields. The range of values for a field can be further described with enumerated values.

Peripheral level, register level, and field level are the main levels handled in register operations. They are described by CMSIS-SVD as follows.
Peripheral level
A peripheral is a named collection of registers. A peripheral is mapped to a defined base address within the device's address space. A peripheral allocates one or more exclusive address blocks relative to its base address, such that all described registers fit into the allocated address blocks. Allocated addresses without an associated register description are automatically considered reserved. The peripheral can be assigned to a group of peripherals and may be associated with one or more interrupts.
Register level
A register is a named, programmable resource that belongs to a peripheral. Registers are mapped to a defined address in the address space of the device. An address is specified relative to the peripheral base address. The description of a register documents the purpose and function of the resource. A debugger requires information about the permitted access to a resource as well as side effects triggered by read and write accesses respectively.
Field level
Registers may be partitioned into chunks of bits of distinct functionality. A chunk is referred to as field. The field names within a single register must be unique. Only architecturally defined fields shall be described. Any bits not being explicitly described are treated as reserved. They are not displayed in the System Viewer and are padded in the bit fields of the device header file. The case-insensitive field named "reserved" is treated as a keyword and each field with this name is ignored.

For more detailed information about the CMSIS-SVD XML Hierarchy, refer to SVD Description (*.svd) Format on the CMSIS-SVD website.

An SVD file example

<?xml version="1.0" encoding="UTF-8" standalone="no"?>
<device xmlns:xs="http://www.w3.org/2001/XMLSchema-instance" schemaVersion="1.1" xs:noNamespaceSchemaLocation="CMSIS-SVD.xsd">
  <name>RegisterAccessExample</name>           <!-- name of part-->
  <addressUnitBits>8</addressUnitBits>         <!-- byte addressable memory -->
  <width>16</width><access>read-write</access> <!-- bus width is 16 bits -->
  <size>16</size>                              <!-- the default size (number of bits) of all peripherals and register that do not define "size" themselves -->
  
  <resetValue>0x00000000</resetValue>          <!-- by default all bits of the registers are initialized to 0 on reset -->
  <resetMask>0xFFFFFFFF</resetMask>            <!-- by default all 32 bits of the registers are used -->
  <peripherals>
    <peripheral>
      <name>RegisterGroup1</name>
      <baseAddress>0x0000</baseAddress>
      <size>16</size>
      <access>read-write</access>
      <registers>
        <register>
          <name>Register1</name>
          <addressOffset>0x0</addressOffset>
          <size>16</size>
          <resetValue>0x4800</resetValue>
          <fields>
