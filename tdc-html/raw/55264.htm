Multiport wavetable setup

The wavetable syntax used to define waveform shapes remains the same as for a single-port setup.

In a multiport setting, every wavetable defines the waveform shapes for the pins of one or more ports:

  • Define the waveforms of a number of pins in one wavetable. The pins can belong to different ports.
  • Insert a line
    DEFINES <port1> ... <port2>

    The keyword DEFINES followed by a list of port names is the only new keyword introduced in the wavetable syntax to support multi-port. The purpose of this keyword is for the software to check if the wavetable defines waveforms for all pins of the ports included in the port list of the DEFINES statement.

    Note The wavetable can also include pins of other ports so that you can use the wavetable for these pins as well, even when their ports are not included in the DEFINES statement. The reason may be that the ports these pins belong to may be overlapping with the ports listed in the DEFINES statement. The advantage provided by this setting is a reduction on the number of ports required for all possible settings in timing and vector settings.

The multiport wavetable is defined in the same manner as non-multi-port wavetables using the Timing Setup editor. See Verifying a multiport timing setup.

Syntax

WAVETABLE  "<WavetableName>" 
DEFINES <Port1_Name> <Port2_Name> ... <PortN_Name> 

DISPLAY multi 
DCDT <DefaultDeviceCycleName>  

PINS <Pin1_Name>|<PinGroup1_Name|Port1_Name> ... 
	<PinN_Name>|<PinGroupN_Name|PortN_Name> 

        0    "<Edge>:<Action> <Edge>:<Action> ..." <DVC_Name>                                   . . .

Example

The following example illustrates the general syntax description above:

WAVETBL spec_search_wtb
    DEFINES port_1 port_2
    DISPLAY multi
    DCDT 0 

    PINS CP_1 CP_2
      0 "d1:0  d2:0"
      1 "d1:1  d2:0"
    brk ""
         . . .

The new keyword DEFINES is the only difference to the syntax from a single-port wavetable.

Functional changes

  1. Introduced before SmarTest 6.3.2
