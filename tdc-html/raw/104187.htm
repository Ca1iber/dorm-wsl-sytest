Timing equation set reference

Equation sets are identified by a header in the following format:

EQNSET <equation_set_number> [["]<equation_set_description>["]]

<equation_set_number> is a number > 0 that identifies the equation set within the timing setup file. You can define up to 256 timing equation sets in one setup file. <equation_set_description> is an optional description for the equation set. It can contain up to 60 characters. If it contains spaces, it must be enclosed by double quotes. Note that semicolons are not allowed in the description.

A timing equation set contains, in this order:

  1. Optional: A definition of the mode context on which the equation set is based, in the format

    MODECONTEXT "<mode_context>"

    If no mode context is defined, the default mode context, in which all pins are configured as standard pins, is assumed. For more information see Mode contexts.

  2. Optional: A definition of the ports for which this equation set is intended, in the format

    DEFINES <port_1> [<port_2> ... <port_n>]

    This entry is used by SmarTest to check if the equation set supplies the required information for all pins of the specified ports.

  3. Optional: A list of base variables (also called spec variables).

    This part of the equation set is identified by the keyword SPECS. The variables, which are also called briefly specs, are only declared in the equation set, they are not assigned a value here; the values are assigned in the timing specification (see Defining the timing specification). The general format is

    SPECS

    var_name_1 [[unit_1]]

    . . .

    var_name_n [[unit_n]]

    For example:

    SPECS

    f [MHz]

    D [ns]

    The units in brackets are optional and only used for the display in the spec tool; they have no further function.

    Variable names are case sensitive, that is, f and F are different variables.

    Note that the variable names must not begin with a keyword of the level or timing setup file. These keywords are:

    ADJUST

    LEVELSET

    period_res

    CHECK

    master_clock1)

    SPECIFICATION

    CLKSET

    MODECONTEXT

    SPECS

    clockSrc

    MODULATION

    SPECSET

    DEFINES

    PDC2)

    SYNC

    DPSPINS

    PHYDVCTBL2)

    TIMINGSET

    EQNSET

    PINS

    v3_delay_register_value2)

    EQUATIONS

    PORT

    WAVETBL

    fract

    period_div

     

    Not all of these keywords belong to the timing equation set. Those that Do not (and do not belong to obsoleted functions) are either used in the timing specification (see Defining the timing specification and its subtopics) or in the level setup (see mainly DPSPINS and DPSPINS resources).

  4. Optional: Definitions of derived variables (also called equation variables).

    This part of the equation set is identified by the keyword EQUATIONS. The derived variables are defined by expressions that can contain base variables and derived variables already defined. The header keyword is due to the fact that the definitions have the form

    var_name = expression.

    The following example definition uses the base variable f of the previous example:

    EQUATIONS

    p= 1/f*1000

    The maximum total number of variables, both base and derived variables, is 4096.

  5. Optional: Definitions of the master clock period (only for Smart Scale, see also Period resolution, clock resolution, and master clock period), tester period resolution and the clock source.
    • The master clock period is fixed in SmarTest 7.10. For multiple clock domains, use different period_res.
    • The period resolution is defined with the period_res keyword. You can specify the period resolution by a constant or an expression. For example

      period_res = 4

      For more information see Determining the period resolution.

    • The clock source is defined with the clocksrc keyword. Possible values are INT (internal clock), which is the default, and AMC (alternate master clock).
  6. Mandatory: One or more timing sets.

    Timing sets are identified by a number that counts all the timing sets of a given equation set. They define edge delays and periods by assigning expressions, which can contain base variables and derived variables, to keywords identifying edges.

    You can specify a description for your timing sets after the number. This description can contain up to 60 characters. If it contains spaces, it must be enclosed by double quotes. Note that semicolons are not allowed in the description.

    A timing set has the following general format:

    TIMINGSET <timing_set_number> [["]<timing_set_description>["]]

    period = <expression>|fract(<spec_var1>,<spec_var2>,<spec_var3>)

    PINS<pin list> [-( <exclude pin list> )]

    [period_div = <number_1>]

    (d|r)<edge_no_1_1> = <expression_1_1>

    . . .

    (d|r)<edge_no_1_k> = <expression_1_k>

    . . .

    PINS <pin_list_m>

    [period_div = <number_m>]

    (d|r)<edge_no_m_1> = <expression_m_1>

    . . .

    (d|r)<edge_no_m_l> = <expression_m_l>

    The meaning of the individual statements is as follows:

    • TIMINGSET <timing_set_number> [["]<timing_set_description>["]]

      This statement indicates the start of a timing set within an equation set. <timing_set_number> is the number that identifies the timing set within the equation set. With the optional <timing_set_description> parameter, you can provide a description of the timing set. The description can contain up to 60 characters. If it contains spaces, it must be enclosed by double quotes. Note that semicolons are not allowed in the description.

    • period = <expression>|fract(<spec_var1>,<spec_var2>,<spec_var3>)

      This statement specifies the period, that is, the tester cycle length. <expression> is built up from numerical constants, base variables, and derived variables by arithmetical operators. For the fract() function, see Avoiding rounding problems with the fract() function.

    • PINS <pin_list> [-( <exclude pin list> )]

      This statement defines the pins to which the following block of edge delays is to be applied. Pin groups can also be specified in the list. The optional exclude list allows you to restrict the definition to a proper subset of a pin group (see Pin exclusion).

    • period_div = <number>

      This statement defines the number of edges for Pin Scale fast pins (see Defining the edge delays for Pin Scale 3600 fast pins) and Smart Scale pins (see Defining edge delays for Smart Scale pins). For more information on period_div, see Period divisor (period_div).

    • (f|s|d|r)<edge_no_i_j> = <expression_i_j>

      These statements define a delay for a drive or receive edge:

      d specifies a drive edge on a Pin Scale card (see Defining waveform shapes for Pin Scale standard pins),

      f and s define a drive edge on a Pin Scale 9G card (see Defining waveform shapes for Smart Scale pins),

      r defines a receive edge on both card types.

      <edge_no_i_j> specifies the number of the edge. Edges are counted starting from 1. The maximum number is 8 for both drive and receive edges. <expression_i_j> is built up from numerical constants, base variables, and derived variables by arithmetical operators.

      The following timing set fragment uses the example definitions for the SPECS and the EQUATIONS sections:

      TIMINGSET 1 "example"

      period= p

      PINS mode -( S0 )

      d1= 0

      d2= p/3

      d3= p/2 + D

      This timing set fragment defines edge delays for the pin group mode, with the exception of S0.

      The maximum total number of all timing sets in all equation sets and all waveform sets is defined with the DSCP command.
