Topic 93366

Measuring fixture delay

About this task

This task explains the procedure to measure the loading effect delays (for one sharing group) or to re-measure the manufacturing fixture delay data for all sharing groups.

Note that you should perform an additional procedure for fixtures that have been repaired or otherwise are no longer in factory condition, as described in Fixture delay compensation process.

Before you begin

All groups of sharing test sites (on one socket board) on a fixture are measured in parallel. Therefore, you must remove or place DUTs or shorts on all the corresponding sites of all groups before you start the delay measurement described below.The procedure to measure the fixture delays in a shared driver environment is given below. A times two sharing DUT1 and DUT2 is taken as an example.

Prepare the Sharing configuration file by referencing in the fixture_delay_files section the FXDL files received from the fixture manufacturer. If you have repaired or otherwise modified the fixture, instead reference the repaired fixture FXDL files.

Procedure

  1. Export the environment variable PS3600_FXDL_DRV_HI_MV=1000 to avoid device clamping that could falsify the loading result.
  2. Start SmarTest and load the pin configuration file specified in the Sharing configuration file.
  3. Call the standard fixture delay tool.

    The fixture delay tool screen is shown in the figure below. In this example, site 2 has been selected. The fields for shared channels have a white background, while the non-shared channels are laid out with a gray background.

  4. Load the pin configuration file specified in the Sharing configuration file.
  5. Choose Edit > Select Configured.
  6. Choose Edit > Set Default and enter 0 in the entry dialog.
  7. Choose Edit > Deselect All.
  8. Insert a short device into the last site of the reference socket board. Put golden devices into all other sites.
  9. Select the reference site by control-clicking its column title.

    This selects all sites' shared channels as well.

  10. Choose Execute > Measure with Dual Transmission Lines to perform the measurement.
  11. Save the measurements as the loaded FXDL file (for example, by naming it loaded.fxdl).
  12. Repeat steps 5 through 11 for the same site, with the following differences:
    • Instead of putting golden devices into all but the last socket, leave these sockets empty. (Leave the short device in the last socket.)
    • When saving the file, mark it as the file for the unloaded case (for example, by naming it unloaded.fxdl).
  13. Run the fd_merge tool, as described in Running the fd_merge tool to merge fixture delay files, to merge the files generated in steps 11 and 12.

Results

An FXDL file has been created that can be used to compensate fixture delays for SmarTest measurements.

Example

For a two sites sharing the following files are generated and stored in the default directory, <device>/ch_attributes/.

You may collect the files in a directory of your choice. In that directory you should run the fd_merge tool.

If you have measured all sharing groups on your fixture having a sharing factor of two, you will get two files. The naming of the files is arbitrary, whatever you specified while saving the file.

Fixture delay file 1: fixture_delay_site1

Fixture delay file 2: fixture_delay_site2

When you re-measure one sharing group without loading, then you may specify this name:

No loading effect file: no_effect_delay_site2_nld

For the delay file measured with loading you may specify this name:

Loading effect file: fixture_delay_site2_ld

What to do next

The last step is to merge the two fixture files into one using the fixture delay merge tool. This tool generates the fixture delay file (fd_MERGED) that will be used during device testing.
