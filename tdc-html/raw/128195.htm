Topic 128195

Understanding the terms of protocol based testing

Protocol based testing on the V93000 uses general protocol related terms, such as field and transaction, but also SmarTest specific terms like pin role and pin assignment.

This topic provides an overview of the terms used for defining or modifying a protocol.

Terms of protocol based testing on the V93000

 

Description

Protocol

A Protocoldescribes the signaling in respect of timing, level and message format which is required to exchange information between the sender and receiver of an interface.

It is defined in the protocol editor.

Transaction

The protocol describes different transactions to exchange information between the sender and receiver of the interface. Typical transactions are read and write.

Transactions usually have parameters, which are used within UTM for passing values to or receiving values from the DUT.

One transaction can utilize one or multiple pin roles which reflect the (device independent) interface to the DUT.

Transactions sometimes also referred to as frame.

They are defined in the protocol editor.

Field

Each transaction is build out of one or several fields which describe the logical structure of the transaction.

Fields are associated with pin roles used in the transaction.

They are defined in the protocol editor.

 

 

Pin role

A Pin role is the abstract (device independent) definition of an interface pin of a protocol. For instance, MDC and MDIO are typical pin names (roles) of the MDIO protocol.

It is associated with a physical device pin in the protocol assignment.

Pin roles are defined in the protocol editor.

Protocol assignment

Protocol assignment is the central point where device independent definitions (the protocol and its pin roles) are mapped (assigned) to the resources of the tester (physical pins via ports).

The protocol assignment can be opened from via the Test Program Explorer.

 

 

Encoding

Encoding defines how to convert a transaction into state characters, respectively vectors.

Encoding at field level is mandatory to convert and execute transactions during test.

Encode definitions are entered in the protocol editor.

Decoding

Decoding defines how to extract transaction's parameter values from vectors, respectively state characters.

Decoding is optional. When omitted, vectors cannot be translated back to parameter values of transactions. Thus a transaction may not display its parameters in the pattern editor properly.

Decode definitions are entered in the protocol editor.

 

 

Specific protocol definition tabs

The protocol editor provides separate tabs for entering protocol specific timing, level, wavetable/state map details. These details will be saved with the protocol definition.

This way they can be imported with the protocol definition to another device.

timing

The syntax of protocol specific timing is equivalent to the device timing definition.

For implementing a protocol's timing segment to the device timing equation, manually add the line:

USE_PROTOCOL"<protocolName>:<timingSegmentName>" [<PortList>]

levels

The syntax of protocol specific levels is equivalent to the device level definition.

For implementing a protocol's level segment to the device level equation manually add the line:

USE_PROTOCOL"<protocolName>:<levelSegmentName>" [<PortList>]

wavetable & state map

The syntax of the wavetable/state map is equivalent to the device wavetable.

Note Where multiple timing/level segments can be used per protocol, only one unique wavetable/state map is allowed!

For implementing the protocol's wavetable/state map to the device wavetable file manually add the line:

USE_PROTOCOL"<protocolName>" [<PortList>]
