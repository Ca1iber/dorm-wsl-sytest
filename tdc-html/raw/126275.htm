Protocol wrapper

Subtopics

  1. 2nd level protocol wrapper tool

Beside the protocol editor which allows to create or view custom host interface protocol definitions, SmarTest provides a protocol wrapper wizard to generate C++ classes from the protocol definition.

In general, generic test method API could be used to create protocol tests containing sequences of transactions and synchronization information. Due to the generic nature of the interface in combination with customizable transaction and parameter names, the use of generic APIs is somewhat cumbersome. In order to overcome these restriction the protocol editor provides the possibility to generate a C++ wrapper source code which can be used for test method programming. The source code contains methods for each of the protocol's transactions. The generated source code is partly protocol specific, can be modified by the user and included in his projects.

The advantage of the wrapper are:

  • Transactions of the protocol directly translate to methods of the wrapper and accept parameters according to the transaction definition.
  • For output parameters in transactions multiple versions for expected and captured parameters are generated automatically.
  • Sequencer labels may be passed as a parameter to functions flush() or run() directly.
  • Result access is abstracted so that it is no more necessary to remember additional result ID strings for accessing the data.
  • Users can customize the name of the protocol test which will automatically be generated and is better to memorize.

The generated wrapper consists of three different classes:

  • The actual wrapper class is protocol specific and thus the user is required to generate a class per protocol.
  • In addition two helper classes organize delayed and simple result access for multisite applications. The helper classes are not protocol specific and thus Do not need to be regenerated for each protocol.

Protocol wrapper class

The protocol wrapper class is generated from the name given by the user and derives from API class SYNCHRONIZED_TEST.

It creates methods based on the protocol's transactions that can be used in the test methods.

All public methods of the SYNCHRONIZED_TEST API are still accessible through the generated wrapper. However, the user generated wrapper class also offers additional public methods.

The two protocol wrapper files generated follow this convention: <your location>\<your class name>.cpp and <your location>\<your class name>.hpp

Note The customized wrapper has to be re-generated any time the protocol definition had been modified.

Result proxy class

The TRANSACTION_RESULT_PROXY class is only needed for capture transactions. It is independent from the specific protocol definition and provides access to the results of a single transaction.

In case a transaction has only a single result, the proxy can directly be converted to INT or STRING result after the protocol test has been executed.

If multiple parameters have been captured in the transaction, the proxy class provides access by index (in the same order as the parameters are declared in the protocol definition) or by parameter name.

The two result proxy class files generated follow this convention: <your location>\ResultProxy.cpp and <your location>\ResultProxy.hpp

Result vector class

The PROTOCOL_TEST_RESULT_VECTOR class is also independent from the specific protocol definition and provides access to all result proxies of transactions capturing results.

The two result proxy class files generated follow this convention: <your location>\ResultVector.cpp and <your location>\ResultVector.hpp
