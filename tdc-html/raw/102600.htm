Special considerations

When you are working with values of sizes other than 64 bits, you should be aware of certain behaviors, particularly when values of different sizes are combined in arithmetic expressions.

Behaviors

Floating-point values

Expressions with more than 64 bits cannot be combined with floating-point values in one expression.

Mismatch of value and size

If a number with fewer bits is expressed as a value with more bits, the value is padded with zeroes. For example:

a = :96:0xffffffffffffffff;      /* a == 0x00000000ffffffffffffffff */

If a number with more bits is expressed as a value with fewer bits, the number is truncated. For example:

a = :64:0xeeeeffffffffffffffffffffffff;      /*a == 0xffffffffffffff */

Missing size specification

If a value (including a variable) in an arithmetic expression has no size specifier, it is assumed to be a 64-bit value. This can lead to unintuitive results. For example:

a = :48: -1:
b = a >> 1;  /*b == 0x7fffffffffff */

Compare:

a = :48: -1:
b = :48: a >> 1;  /*b == 0x7fffffffffff */

Multiplication, division, addition, and subtraction

In calculations with values of different sizes, the value with fewer bits is padded with zeroes. The result always has the same number of bits as the larger value. For example:

a = :96:0xffffffffffffffffffffffff;    /* a = -1 */
b = :64:0x0000000000000009;            /* b = 9  */
c = a + b;     /* c = 0x000000000000000000000008 (8) */

Bitwise operations

As with addition, described above, the smaller value is padded and the result has the size of the larger value:

a = :64:-1;    /* a =         0xffffffffffffffff */
b = :96:-1;    /* b = 0xffffffffffffffffffffffff */
c = a & b;     /* c = 0x00000000ffffffffffffffff */

Bit shift operations

Left bit shifts (<<) are unsigned; the sign bit is not extended. For example:

c = :96:-1;     /* c = 0xffffffffffffffffffffffff (-1) */
e = c >> 2;     /* e = 0x3fffffffffffffffffffffff      */
