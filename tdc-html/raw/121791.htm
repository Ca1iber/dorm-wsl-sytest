Topic 121791

Time Stamps

SmarTest includes support for test methods to add time stamps to data logs, both to mark the beginning or the end of an interval and to mark an individual event. Time stamps are included in the standard data log, making them available to any post-processing tools without additional effort.

While all events in the data log include time stamps, functions are provided that let you add timestamps under test method control:

  • START_TIMER
  • STOP_TIMER
  • LOG_TIMER

The syntax is described below.

START_TIMER

START_TIMER(const char* id, const char* msg)

Creates an action event entry in the data log. The action event entry contains a tag attribute with the id parameter and a time stamp. If a msg parameter is specified, it is included in a second tag attribute.

Parameters

id

The name of the timer as a string.

The name lets you identify other events belonging to the same timer.

The parameter is stored in the action event as the value of a tag attribute with the name "start_timer".

msg

An optional string containing additional information.

The parameter is stored in the action event as the value of a tag attribute with the name "timer_annotation".

STOP_TIMER

STOP_TIMER(const char* id, const char* msg)

Creates an action event entry in the data log. The action event entry contains the id parameter in a tag and a time stamp. If a msg parameter is specified, it is included in a tag as well.

Parameters

id

The name of the timer as a string.

The name lets you identify other events belonging to the same timer.

The parameter is stored in the action event as the value of a tag attribute with the name "stop_timer".

msg

An optional string containing additional information.

The parameter is stored in the action event as the value of a tag attribute with the name "timer_annotation".

LOG_TIMER

LOG_TIMER(const char* id, const char* msg)

Creates an action event entry in the data log. The action event entry contains the id parameter in a tag and a time stamp. If a msg parameter is specified, it is included in a tag as well.

Parameters

id

The name of the timer as a string.

The name lets you identify other events belonging to the same timer.

The parameter is stored in the action event as the value of a tag attribute with the name "time_stamp".

msg

An optional string containing additional information.

The parameter is stored in the action event as the value of a tag attribute with the name "timer_annotation".

Example

This example illustrates the general use of the functions:

MYTestMethod(...)
{
  START_TIMER("A");
  ... code ...
  STOP_TIMER("A");
  START_TIMER("B");
  ... code ... 
  LOG_TIMER("B","Intermediate result available");
  ... code ... 
  STOP_TIMER("B"); 
}

This is an actual code snippet taken from a test method:

# ... other test method code ...
FOR_EACH_SITE_BEGIN();
  int site=CURRENT_SITE_NUMBER()-1;
  START_TIMER("timer1","data upload starts");
  adc_wave[site] = VECTOR ( capture_label ).getvectors ();
  STOP_TIMER("timer1";"data upload ends");
  # ... other site-specific code ...
FOR_EACH_SITE_END();
# ... other test method code ...
