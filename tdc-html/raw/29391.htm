GET_EXCEPTION_HANDLER

This API retrieves the error handler settings that have been set by the SET_EXCEPTION_HANDLER.

You can create a class object that represents the current error handler setting by using the constructor function of this API. The object is used as a parameter of the SET_EXCEPTION_HANDLER API for setting up the previously-retrieved error handler setting.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/ExceptionHandler.h.

Class definition

Constructor

GET_EXCEPTION_HANDLER(TM::EXIT_CASE case);

Member Functions

GET_EXCEPTION_HANDLER& update(TM::EXIT_CASE case);

Syntax

For creating a class object and retrieving the current error handler setting for the specified API category

GET_EXCEPTION_HANDLER obj(TM::EXIT_CASE case);

For switching the API category and retrieving the current error handler setting for the specified API category

obj.update(TM::EXIT_CASE case);

Constructor

GET_EXCEPTION_HANDLER()

GET_EXCEPTION_HANDLER(TM::EXIT_CASE case);

This constructor creates a class object, and then retrieves the error handler setting for the API category specified by the parameter. Hence, this constructor creates the class object that contains the error handler setting for the specified API category.

Parameter

case

An API category for which you want to retrieve an error handler. This must be one in TM::EXIT_CASE. See SET_EXCEPTION_HANDLER API.

Member functions

update()

GET_EXCEPTION_HANDLER& update(TM::EXIT_CASE case);

This member function switches the API category that is addressed by the constructor GET_EXCEPTION_HANDLER( ). Then, this retrieves the error handler setting for the API category newly specified by the parameter. Hence, this member function overwrites the contents of the class object.

Parameter

case

An API category for which you want to retrieve an error handler. This must be one in TM::EXIT_CASE. See SET_EXCEPTION_HANDLER API.

Example

SET_EXCEPTION_HANDLER(TM::ALL, TM::ABORT_FLOW);
SET_EXCEPTION_HANDLER(TM::COMPUTATION, TM::THROUGH);
// First Test
Routing.primary(1);
Analog.DGT("Aout").enable();
START_TEST();
WAIT_TEST_DONE(0.1 sec);

Analog.DGT("Aout").disable();
FLUSH();
// Code for retrieving/calculation/judgment
GET_EXCEPTION_HANDLER err_setup(TM::SETUP);
SET_EXCEPTION_HANDLER(TM::SETUP, TM::INTERACTIVE);

// Second Test
Routing.primary(2);
Analog.DGT("Aout").enable();
START_TEST();
WAIT_TEST_DONE(0.1 sec);
Analog.DGT("Aout").disable();
FLUSH();

// Code for retrieving/calculation/judgment
SET_EXCEPTION_HANDLER(err_setup);

The top two SET_EXCEPTION_HANDLER APIs set the following error handlers:

  • TM::THROUGH for the computation API category
  • TM::ABORT_FLOW for other API categories

These handlers are used for the first test in the program.

The GET_EXCEPTION_HANDLER API retrieves the current error handler setting for the setup API category, and it is stored as the class object err_setup.

The next SET_EXCEPTION_HANDLER API sets the new error handler TM::INTERACTIVE for the setup API category only. All error handlers at this point are as follows:

  • TM::INTERACTIVE for the setup API category
  • TM::THROUGH for the computation API category
  • TM::ABORT_FLOW for other API categories

There handlers are used for the second test in this program.

The last SET_EXCEPTION_HANDLER API restores the error handler for the setup API category using the object err_setup of the GET_EXCEPTION_HANDLER class.
