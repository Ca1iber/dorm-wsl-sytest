Topic 105158

Merging Programs and Modifying them

Subtopics

  1. Example of Merging Two Separate Test Programs Into One

By using a multi-port setup you can merge individual test programs together for convenience and speed of testing by setting up a concurrent test (CCT), which allows you to test several cores simultaneously.

Consider, for example, a case where you have a DUT containing separate digital and analog cores.

If the test program for the digital core already exists, you can modify it to a multi-port setup and merge it into the required final digital test. The analog core can be tested by defining analog pins for it.

You can then set up a concurrent test to test the cores simultaneously (see the section Concurrent Tests (CCT)).

You can also apply this method of test program reuse to DUTs, where the same core (die) is packaged with different pin configurations by defining ports to contain the appropriate pins and then perform a parallel test on all pins using a CCT setup.

The general procedure to modify a test program from a single-port setup to a multi-port setup for concurrent testing is as follows:

  1. Develop a concurrent test plan, based on test time, targeted tester capabilities, yield information, device operation, estimated time to production and desired results (see Making a CCT Plan).
  2. Convert a single-port pin configuration to a multi-port configuration by defining ports and pins.
  3. Convert single-port timing to multi-port timing and select different port periods where necessary.
  4. Convert vectors and port vector settings. Combine them per the CCT plan in a multi-port burst label.
  5. Convert Test Functions to Test Methods. Modifying existing Test Methods to include port specific requirements for test, evaluation, binning, etc.
  6. Set up the test flow based on the CCT plan and items above, to execute the parallel test.

The following sections describe this in more detail on the basis of an example for a DUT containing separate digital and analog cores.
