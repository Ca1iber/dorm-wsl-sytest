How the Event Formatter works

Subtopics

  1. How the output is directed to the report window
  2. Modifying report window menus
  3. Important notes for user-written report formatters

This section contains low-level information about the Event Formatter which you may need if you want to make changes to the formatter, or which will help you if you want to write your own event-based report formatter. For normal use of the Event Formatter, this information is not needed.

Basically, the Event Formatter works in the same way as any data retrieval method based on event data logging. The Event Formatter utilizes the same functions and data types of the Data Retrieval Library, and is implemented in a very similar way to that explained in Recommended implementation structure. Detailed information on how to implement a data retrieval is given in Developing a data retrieval function. Appendix A: Event Formatter Files contains descriptions of all the files that build the Event Formatter.

According to the settings in the configuration file for the Event Formatter (see Settings for the Event Formatter), the software regularly runs the formatter by calling the eventProcess function. This function is the core of the Event Formatter. The formatter then reads a defined number of event records (if any are available) from the data log stream. The Event Formatter's event mask is set by the InitHandler function, which is called automatically when the Event Formatter is selected as the active report formatter (see How to Activate the Event Formatter). In that mask, no event is set to "masked".

After each event record has been read, the attributes are processed according to the event type and the settings of the Report Dialog. When the attributes for all read events have been processed, the Event Formatter terminates. It will be run again by the next call of eventProcess.
