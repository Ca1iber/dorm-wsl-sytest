Topic 144753

Changing the parameter value at runtime with SmartRDI

Subtopics

  1. runTimeVal()
  2. PPMU fast transfer mode of SmartRDI

When some parameter values can be determined only at runtime, for example, from a previous measurement result, you can specify the parameter with runTimeVal() and use the parameter as an input in tests.

About this task

Runtime values can be defined and applied as
  • common value that is applied to all active sites or as
  • array of site-specific values.
This task covers both the common runtime value and site-specific runtime values. Both solutions support the code‑based mode and pattern‑based mode.

For setting site-specific PPMU voltage levels as runtime values, SmartRDI features a fast transfer mode that shortens the test time in high-site-count applications. For more information, refer to PPMU fast transfer mode of SmartRDI.

Procedure

  1. Define a variable that holds the runtime value(s):
    • Common value: Create a variable for a runtime value that applies to all active sites.
    • Site-specific values: Create an array for the site-specific runtime values.
      • Resize the array so that it matches to the number of all configured sites.
      • Initialize the entire array to a reasonable value.

    Supported types of runtime values are defined in the syntax section of runTimeVal().

  2. Set the runtime value(s):
    • Common value: Set the created variable to the value that should be applied to all active sites.
    • Site-specific values: Within a FOR_EACH_SITE loop, fill the created array for all active sites with the site-specific values.
  3. Pass the created individual value or array to function runTimeVal() using a unique name string as identifier.
  4. Use the unique name string as input parameter for a function that supports runtime values.

    The following table lists the functions that support runtime values.

    Class Function
    dc class PPMU: vForce(), iForce(), and waveform()
    SPMU: vForce(), Setting up SPMU
    DC Scale: vForce(), iForce(), iClamp(), and waveform()
    protocol class write()
    hwRelay class setOnRunTime() and setOffRunTime()
    smartVec class expectBit(), expectData(), writeBit(), writeData(), writeParData(), writeParDataBurst(), and writeVec()
    func class rdi.func().burstRunTime() and rdi.func().labelRunTime()

Results

The specified parameter value can be changed at runtime.

Note For a specific test action with runtime variables, the data type of the runtime variables cannot be changed during any test execution loop.

Examples

Example 1: DC test - Using different values for different sites

ARRAY_D rtv_arr(4); // Define a variable for quad-site tests
rtv_arr.init(0.0);

ON_FIRST_INVOCATION_BEGIN();

    rtv_arr[0]=1.0; rtv_arr[1]=1.1; rtv_arr[2]=1.2; rtv_arr[3]=1.3;

    rdi.runTimeVal("rtv",rtv_arr);

    rdi.dc().pin("A").vForce("rtv").execute();  // Both code‑based or pattern‑based modes are supported.

ON_FIRST_INVOCATION_END();

Example 2: RF stimulus - Using the different values for different sites 

ARRAY_D power(4); // Define a variable for quad-site tests
power.init(0.0);

power[0]=-10;power[1]=-11;power[2]=-12;power[3]=-13;

ON_FIRST_INVOCATION_BEGIN();

    rdi.runTimeVal("ppp",power);

    RDI_BEGIN();

        rdi.rfs().pin("A").signal(TA::CW).power("ppp").freq(1e9).execute();

    RDI_END();

ON_FIRST_INVOCATION_END();

Example 3: Protocol test - Changing the write data at runtime

ARRAY_I write_data(2); // Define a variable for dual-site test
write_data.init(0);

write_data[0]=0x1;
write_data[1]=0x2;

rdi.runTimeVal("data",write_data); // Site data array

RDI_BEGIN(); 

    rdi. protocol().pname("i2c").write(0x4,"data").execute();

RDI_END();
