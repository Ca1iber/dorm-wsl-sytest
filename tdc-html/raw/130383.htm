RESULT_CONFIGURATION

This API serves to define the result configuration. For more information see Result Configuration and Configuring the Error Map recording.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/ResultConfiguration.h.

Constructor
RESULT_CONFIGURATION();
RESULT_CONFIGURATION( const STRING& portName,
                      const NumberOfResultsPerCycle& numberOfResultsPerCycle,
                      const ResultWidth& resultWidth,
                      const ResultStorageLocation& resultStorageLocation,
                      const STRING& edgeToResultMapping,
                      const ResultGranularity& resultGranularity,
                      const STRING& resultStorageLocationExceptionPinList,
                      const ResultStorageIncompleteBehavior& resultStorageIncompleteBehavior,
                      const bool& multipleExecutions );
Parameters
portName The port for which the result configuration is to be defined.

numberOfResultsPerCycle

The number of results per cycle for the specified port. Possible values are:

RESULT_CONFIGURATION::RPCi,

where i is 1, 2, 4, 6, or 8 for 1, 2, 4, 6, or 8 results. The default is RPC1.

resultWidth

The result width for the specified port. Possible values are:

RESULT_CONFIGURATION::_1Bit One bit code

RESULT_CONFIGURATION::_2Bit Two bit code. This is the default.

resultStorageLocation

Defines whether the results of the specified port are stored in the internal Error Map or in the external memory (RAM). Possible values are:

  • RESULT_CONFIGURATION::TP

    Results are stored in the internal Error Map. The internal Error Map is located inside the test processor.

  • RESULT_CONFIGURATION::RAM

    Results are stored in the external memory. External memory means the vector memory.

If you select RAM, you can define an exception list. The results of the pins in this list will be stored in the internal Error Map.

edgeToResultMapping

If setNumberOfResultsPerCycle() is set to RPC2 or RPC4, you can specify a string that defines which edges are to be combined in the 2 or 4 results. The format of the string is

"c1: edge_list1 [c2: edge_list2 [c3: edge_list3 [c4: edge_list4]]]"

The default for RPC2 is:

"c1:1,2,3,4 c2:5,6,7,8"

The default for RPC4 is:

"c1:1,2 c2:3,4 c3:5,6 c4:7,8"

resultGranularity

This parameter defines the system behavior for two aspects of gathering information on the edge level. The possible values are:

  • RESULT_CONFIGURATION::edge :

    This option activates the following settings:

    • You activate gathering result information for all 8 edges by repetition of a failing test if numberOfResultsPerCycle is set to RPC1 and resultWidth is set to _2Bit.
    • You require the result combinations defined with edgeToResultMapping to satisfy the conditions for edge retrieval. For details see Possible combinations of CYRM, CYRP, and DCRM.

  • RESULT_CONFIGURATION::cycle :

    With this option, a failing test is not repeated, and any formally correct definition of the result combinations will be accepted. This is the default.

resultStorageLocationExceptionPinList

A comma separated pin list containing pins whose results are to be stored in the internal Error Map even if they belong to a port whose results are to be stored in the external memory. If you want to remove all exceptions, specify an empty list.

resultStorageIncompleteBehavior

This parameter defines the behavior of the system when the result storage location is set to RAM, and result recording was aborted. Possible values are:

  • RESULT_CONFIGURATION::ErrorImmediate :

    SmarTest issues an error message immediately after completion of the functional test. This message reports the channels, pins, and sites of all channel groups on which recording was aborted.

  • RESULT_CONFIGURATION::ErrorOnRequest :

    SmarTest does not issue an error message immediately after completion of the test, but only if a channel which is involved in a recording abort is queried for result data. In this case again, the channels, pins, and sites of a all channel groups on which recording was aborted will be reported. This is the default.

  • RESULT_CONFIGURATION::failOnRequest :

    SmarTest does not issue any error message. If a channel of a group on which recording was aborted is queried for result data, all its cycles will be reported as failing.

    This option can be used in a production environment if the result data is recorded in acquire failure mode, since if any data is recorded with this recording mode, the device must in fact have failed. Actually, recording will only be aborted in case of a massive fail on several pins belonging to the same channel group.

Member functions

enable()
void enable();

This member function activates the settings of the RESULT_CONFIGURATION object in the firmware. Only one configuration can be active at a time. The activated settings will be valid until enable() is executed again. This function has no parameters.

getEdgeToResultMapping()
const STRING & getEdgeToResultMapping( const STRING& portName = "@@" );

This member function retrieves the sub-cycle definition for the specified ports.

Parameter

portName

The port for which the sub-cycle definitions are to be retrieved. The default is @@, which stands for all ports.
getMultipleExecutions()
const bool& getMultipleExecutions() const;

This member function retrieves if multiple executions of a failing test are allowed at all. It has no parameters.

const ResultGranularity & getResultGranularity( const STRING& portName = "@@" );

This member function retrieves the behavior of the system for the specified ports if a test fails and one two bit result is requested per cycle for the respective port.

Parameter

portName

The port for which the result granularity (in case of two bit codes for one result per cycle) is to be retrieved. The default is @@, which stands for all ports.

Example

// Declare a new result configuration object: 
RESULT_CONFIGURATION config1; 
STRING exceptionPins("pin1,pin2");

// Use member functions to specify the needed settings for port "port1":
config1.setNumberOfResultsPerCycle( RESULT_CONFIGURATION::RPC8, "port1" ); 
config1.setResultWidth( RESULT_CONFIGURATION::_2Bit, "port1" ); 
config1.setResultStorageLocation( RESULT_CONFIGURATION::TP, "port1" ); 
config1.setResultGranularity( RESULT_CONFIGURATION::cycle, "port1" );

// Pins excepted from the above  storage locations settings: 
config1.setResultStorageLocationExceptionPinList( exceptionPins );

// Global settings:
config1.setResultStorageIncompleteBehavior( RESULT_CONFIGURATION::ErrorImmediate ); 
config1.setMultipleExecutions( true );

// Enable the configuration specified in the object "config1":
config1.enable();


// Use convenience constructor to specify a new result configuration 
// for a single port and the global settings:
STRING exceptionPins("pin1,pin2");
RESULT_CONFIGURATION config2( "port2",
                              RESULT_CONFIGURATION::RPC1,
                              RESULT_CONFIGURATION::_1Bit,
                              RESULT_CONFIGURATION::TP,
                              "",
                              RESULT_CONFIGURATION::edge,
                              "",
                              RESULT_CONFIGURATION::ErrorOnRequest,
                              false );

// Make some adjustments:
config2.setResultStorageLocationExceptionPinList( exceptionPins );

// Specify some additional settings for another port: 
config2.setResultGranularity( RESULT_CONFIGURATION::cycle, "port1" );

// Enable the configuration specified in the object "config2":
config2.enable();


// A newly created configuration contains the default settings.
// This can be used to reset the result configuration:
RESULT_CONFIGURATION  defaultConfig;
defaultConfig.enable();
