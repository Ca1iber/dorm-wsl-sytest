RDI_Configure file

Subtopics

  1. Example of keyword setups in the RDI_Configure file
  2. getRdiConfig()

The RDI_Configure file is used to configure some default settings to be used when programming with SmartRDI. The RDI_Configure file is in folder testmethod of the loaded device. An RDI_Configure.Template file will be generated in the first run, which has all options with comments.

These settings include setting the default pin status and configuring the sequencer‑controlled utility.

Testflow variable RDI_CONFIGURE_FILE

This testflow variable allows you to select a customized RDI_Configure file for a testflow. Therefore, you can have different setups in different RDI_Configure files for different testflows.

Use this variable to specify a RDI_Configure file for a testflow each time. You can specify as many RDI_Configure files to testflows as required. You can put your customized RDI_Configure files to an absolute path or paths.

Keyword groups in the RDI_Configure file

  • Alarm handling for DCVI
  • Default pin status
  • For debugging
  • For production
  • Offline Result Emulation (ORE) setup
  • Pass or fail per label
  • PPMU setup
  • Result upload
  • Routing setup
  • Setup naming
  • smartVec setup
  • SMC execution
  • Utility line setup
  • Others

Definition of keywords in the RDI_Configure file

The following tables list all of the applicable keywords and their definitions.

Alarm handling for DCVI
Keyword Description
ALARM_FAIL_WARNING Disable alarm warnings when alarm fails.

If you set ALARM_FAIL_WARNING = TRUE, SmartRDI throws an warning message when the alarm fails, for example, Test Suite:: SuiteName, Burst Label:: BurstName, Alarm Pin ("PinName") failed!.

If you set ALARM_FAIL_WARNING = FALSE, SmartRDI throws NOTHING. You can use rdi.id().getAlarmPassFail() to retrieve the alarm result.

The default value is TRUE.
ALARM_HANDLING_DCVI_ENABLE Enable the alarm handling for DCVI. The option is TRUE or FALSE.

The default value is FALSE.
ALARM_HANDLING_DCVI_SETUP_FILE Specify a path that directs to an alarm setup file which contains the limit setups for handling alarms for DCVI.

A file path relative to the root path of the loaded device is to be specified.

You can use different alarm handling setups for different testflows since you can use RDI_CONFIGURE_FILE to specify a RDI_Configure file for each testflow. See Testflow variable RDI_CONFIGURE_FILE above.

For more information on Alarm handling, see SmartRDI: Alarm handling for DCVI.

Default pin status
Keyword Description
DEFAULT_STATUS_INDEX Specify the default physical index for the pins, separated by commas.
DEFAULT_STATUS_PIN Specify the pins to set the default status, separated by commas.

For more information about default pin status, see Changing the default pin status with SmartRDI.

For debugging
Keyword Description
ENABLE_RDI_INFO_LOG_FILE Specify TRUE or FALSE to enable or disable saving the RDI_INFO_LEVEL report (shown in the UI report window) to a log file. When enabled, the RDI_INFO_LEVEL_x.log file is generated in the device/testmethod folder.

The default value is FALSE.
REPORT_RESULT_IN_SINGLE_MODE Specify TRUE or FALSE to enable or disable the measurement result in the SINGLE mode to be shown in the UI report window. When it is enabled, if the command is with a result ID, the results for DC and functional tests will show in the window once the commands are being executed one by one.

If not specified, FALSE is used by default.
For production
Keyword Description
SETUP_UPTODATE Specify this option to TRUE to have NO * (asterisk) in the setup tool; or to FALSE to have * in the setup tool.

The default value is FALSE.

SETUP_UPTODATE = TRUE # Have NO * in the setup tool.

SETUP_UPTODATE = FALSE # Have * in the setup tool as before.

Only setups programmed in SmartRDI code are handled.
Offline Result Emulation (ORE) setup
Keyword Description
ENABLE_ORE Specify TRUE or FALSE to enable or disable Offline Result Emulation.

The default value is FALSE.

In online mode, to automatically disable ORE, you can set this keyword as ENABLE_ORE = TRUE_OFFLINE. With this setting, ORE works only for offline.

If the ORE feature is enabled for online, SmartRDI delivers an error message for reminder.
Settings of ENABLE_ORE
RDI_Configure option Offline mode Online mode

ENABLE_ORE = TRUE

Enable ORE

 Enable ORE
ENABLE_ORE = FALSE Disable ORE

Disable ORE
ENABLE_ORE = TRUE_OFFLINE Enable ORE Disable ORE
ORE_FILE Specify a path to which the ORE file is saved. The ORE file path can be specified as an absolute path or a relative path. A relative path is based on the current test device's root directory. For example, ./myORE.xml is current_device_folder/myORE.xml.
ORE_FOLDER

Specify a path for the rdi_ore_template_by_user_code.xml and ARRAY data files.

If it is not set, the rdi_ore_template_by_user_code.xml and ARRAY result data files will be created in the device path.

The path can be an absolute path or a relative path. A relative path is based on the current test device directory. It can be ./ORE which directs to the current_device_folder/ORE/ folder.

You can also use it inside any XML file as the keyword to represent the result file path that has been specified in the RDI_Configure file.
ORE_TEMPLATE_BY_USER_CODE

Enable the generation of a specific ORE template file based on user code.

The default value is FALSE.

If it is set to TRUE, a template file named rdi_ore_template_by_user_code.xml will be generated during the first run of the test program and the file is stored in the current device path.
ORE_TEMPLATE_DATA_FILE_SIZE_THRESHOLD Set a threshold for the result size of your ORE template.

If the generated result size is less than the threshold value, the result will be inserted to the .xml file.

If the generated result size is greater than or equal to the threshold value, the result will be inserted to a .txt file which is located in the same folder as the rdi_ore_template_by_user_code.xml file is; the .txt file path information will be inserted to the .xml file.

For more information about ORE setup, see Using Offline Result Emulation in SmartRDI.

Pass or fail per label
Keyword Description
PER_LABEL_FUNC_RESULT_MODE Define how to return the pass/fail results per label in functional tests: ERMP or FLBL.

If not specified, ERMP is used by default.
PER_LABEL_FUNC_RESULT_NO_BREAK_VEC Specify TRUE or FALSE to enable or disable the SmartScale cards (PS1600, PS9GPSSL) feature of retrieving per label Pass/Fail results without inserting break vectors (BFLM mode).

If not specified, FALSE is used by default.

When this option is set to TRUE, no break vectors are inserted between labels of a burst.

Note This mode requires a pattern length not less than eight cycles for patterns inside a RDI_BEGIN()/RDI_END() block, because in BFLM mode, each pattern in the burst must generate eight or more cycles (see Compression factor for overview Error Map). So when this mode is enabled, a specified pattern length less than eight cycles is ignored and all patterns generated by SmartRDI have at least eight cycles. There are exceptions, for example vecLength() of the smartVec() class, where SmartRDI reports an error for a user setting with insufficient pattern length, rather than ignoring the setting. User labels less than eight cycles cause an error as well.

For more information about pass/fail per label, see Pass/Fail per label without break vectors.

PPMU setup
Keyword Description
PPMU_DEFAULT_RELAY Specify PPMU_ON or NO to set the default relay action.

If not specified, PPMU_ON is used by default.
PPMU_DEFAULT_VALUE_MODE Specify SA or BADC to set the default voltage or current measurement mode.

If not specified, BADC is used by default.
FAST_PPMU_LEVEL_TRANSFER

Specify TRUE or FALSE to enable DC fast download. This reduces the time required for Changing the parameter value at runtime with SmartRDI in high-site-count applications.

If not specified, FALSE is used by default.

For more information, refer to PPMU fast transfer mode of SmartRDI.

For more information about PPMU setup, see DC test with digital channels.

Result upload
Keyword Description
DC_BURST_SITE_UPLOAD Specify TRUE or FALSE to allow or disallow uploading DC results over sites in one burst (a SmarTest 7.4.3 new feature).

In the Technology File, a setting is required to use this capability:

"Fast Transfer Buffer" > 128K

If not specified, FALSE is used by default.

Note Burst site upload does not support hidden upload.
DIGCAP_ADAPTIVE_RESULT_SIZE

Specify the result size to be retrieved when the number of samples actually captured is less than the expected number.

The default value is FALSE.

When this flag is set to TRUE, the result array contains the values of actually-captured samples. For example, if the expected sample number is 32 and the sample number actually captured is 20, the result is an array with 20 values.

When this flag is set to FALSE, the result array contains the values of actually-captured samples plus some "-999" to match the length of the expected number. For example, if the expected sample number is 32 and the actually-captured sample number is 20, the result is an array with 20 values plus 12 of "-999".
DIGCAP_BURST_SITE_UPLOAD Specify TRUE or FALSE to allow or disallow uploading digital capture results over sites in one burst (a SmarTest 7.4.2.1 new feature).

This configuration is set to FALSE by default.

With this feature enabled, the SmartRDI classes digCap() and smartVec() with readMode(TA::DIGCAP) upload the digital capture results over sites in one firmware query.

For DIGCAP_BURST_SITE_UPLOAD = TRUE, the maximum sample number is 8192.

This global setting can be overwritten by a local setting specified with digCapBurstSiteUpload().

Note Burst site upload does not support hidden upload.

For more information about upload setup, see Controlling burst site upload.

Routing setup
Keyword Description
ROUTING_ACK_CHECK

Specify TRUE or FALSE to enable or disable a check if the route state is applied successfully to PMUX01 cards. The Acknowledge bit of the I2C bus is checked when a new state is applied by rdi.route().applyState() or when a switch is changed by rdi.route().pin() if the value of this set to TRUE.

If not specified, FALSE is used by default.
ROUTING_SETUP_FILE Specify the setup file created by the Routing Tools editors and to be loaded by the Routing tools API. An absolute file path or a file path relative to root path of the loaded device is to be specified. See the examples in Example of keyword setups in the RDI_Configure file.

For more information about Routing setup, see SmartRDI: DUT board connections control by Routing Tools.

Setup naming
Keyword Description
ANALOG_SET_NAME_MD5 Specify this option to be TRUE to append an MD5 checksum at the end of all analog set names. The MD5 checksum briefly shows the content in the burst. If the same analog set has already existed, the analog set will not be generated again.

If not specified, FALSE is used by default.

See Setting and retrieving the setup name with SmartRDI.
BURST_NAME_MD5 Specify this option to be TRUE to append an MD5 checksum at the end of all the burst names. The MD5 checksum briefly shows the content in the burst. If the same burst name has already existed, the burst will not be generated again.

Before SmartRDI 2.4.5, when BURST_NAME_MD5 is set to FALSE, the burst pattern does not contain MD5 information and SmartRDI always deletes and regenerates the burst pattern during the first run.

In SmartRDI 2.4.5, when BURST_NAME_MD5 is set to FALSE, SmartRDI saves the MD5 checksum into the burst pattern (by leveraging the new LBUD firmware command in SmarTest 7.4.2) and judges whether the burst pattern needs to be regenerated during the first run.

If not specified, FALSE is used by default.

See Postfix in burst pattern names.
smartVec setup
Keyword Description
DEFAULT_EMAP_LOCATION Provide a global option to set an error map location:
  • TP indicates an error map location in the test processor memory of the channel.
  • RAM indicates that the error map is located in the vector memory of the channel.

If not specified, the default error map location is RAM, which is the vector memory, because this location provides a higher upload speed.

In case the vector memory is insufficient for the test, the location switches to TP, which is the test processor memory.

Note that the RAM location is related to the "result area" configuration in the technology file of SmarTest.

For information about the error map size, refer to Pin Scale 1600 error map size.

See also emapLocation().
Note TP is the default value before SmartRDI 2.4.5. RAM is the default value since SmartRDI 2.4.5.
DEFAULT_SMV_READ_MODE Specify a central selection of SmartVec read mode for the whole test program: EMAP or DIGCAP.

If not specified, the default read mode is DIGCAP.
SMV_DIGCAP_AUTO_BURSTUPLOAD Specify TRUE or FALSE to enable or disable automatic burst of upload.

The default value is TRUE.

Using burstUpload for data read by SmartVec in the digital capture mode can significantly decrease test time. By default, all SmartVec's digital capture data on a certain pin in one RDI_BEGIN()/RDI_END() block are uploaded as one burst, and the burstUpload() function set in the code is ignored.

The only exception is a combination of digCap() and smartVec() readings in the same RDI_BEGIN()/RDI_END() block on the same pin. As the digCap class supports different capture modes (par, ser, bitPerWord), the smartVec burstUpload will be split into segments between the digCap commands.
SMV_VEC_MEM_TYPE Specify the memory location to put generated smartVec patterns: SHMEM or SM.

If not specified, SM is used by default.
USER_NAMED_LABEL_CONTENT_CHECK Specify TRUE or FALSE to enable or disable whether to check label content when you set a label name.

The default value is TRUE.

Based on the new LBUD firmware command in SmarTest 7.4.2, this option provides a capability of performing a content check on labels set by one of the following commands or command combinations:

  • A labelName() function in the smartVec() class
  • A burstLabel(TA::MD5_OFF) function in the smartVec() class
  • A label().copyLabel(false) function combination in the dc(), digCap(), tmu(), or smartVec() class

    With this feature enabled, the SmartRDI verifies whether the label content corresponds to the code in the RDI_BEGIN()/RDI_END() block and reports an error when a difference is detected.

VEC_EDIT_MODE Specify this option to select one of vector edit modes: VECD or VEC_TRANSFER_TASK.

If not specified, VECD is used by default.
SMV_IGNORE_COMMENT Globally enable or disable the suppression of smartVec comments generated in pattern.

By default, SMV_IGNORE_COMMENT = FALSE. If you set SMV_IGNORE_COMMENT = TRUE, all smartVec comments inserted by comment() will be ignored in pattern generation.

For more information about vector setup, see SmartRDI: Vector and protocol programming.

SMC execution
Keyword Description
DISABLE_SMC_EXEC_GLOBAL Specify TRUE or FALSE to globally allow or disallow SMC execution.

This configuration is set to FALSE by default.
DISABLE_SMC_EXEC_SHORT_BURST Specify TRUE or FALSE to enable or disable the SMC execution mode for short bursts (<1 ms) automatically.

This configuration is set to FALSE by default.

For more information about SMC execution, see SmartRDI functions controlling SmartCalc (SMC).

Utility line setup
Keyword Description
UTIL_BLOCK Specify the utility block to be controlled by the pattern. Use commas to separate groups; do not use commas to define ganged groups. Use the "-" character to link the ganged block numbers.

For example,

UTIL_BLOCK = 123, 4, 5, 6 // blocks 1, 2, and 3 are ganged

UTIL_BLOCK = 1-2-3, 4, 5, 6 // blocks 1, 2, and 3 are ganged

UTIL_BLOCK = 165-166-167, 168, 169, 170 // blocks 165, 166, and 167 are ganged

Ganged utility blocks cannot be on two utility cards, for example, 172-265.
UTIL_CTRL_MAX_SPEED Specify the target utility control maximum speed in case a lower speed is required such as 2e6 or 3e6. The valid value range is from 1e6 to 10e6.

If not specified, 10e6 is used by default.
UTIL_DYN_MASK_INACTIVE_SITE Specify TRUE or FALSE to keep or not keep the states (mask) of the utility bits of inactive sites. FALSE indicates that utility pins at inactive sites will STILL be changed by pattern; TRUE indicates that utility pins at inactive sites will NOT be changed by pattern.

The default value is FALSE.

This configuration option is implemented based on the utility mask capability in SmarTest 7.4.2 for the sequencer‑controlled utility lines.
UTIL_DYN_MASK_UNSPECIFIED_PIN Specify TRUE or FALSE to keep or not keep the states (mask) of unspecified utility bins in a command. FALSE indicates that unspecified utility pins in the same control pattern will be set to OFF; TRUE indicates that unspecified utility pins in the same control pattern will KEEP their states.

If not specified, the default value is TRUE.

This configuration option is implemented based on the utility mask capability in SmarTest 7.4.2 for the sequencer‑controlled utility lines. To keep the compatibility with old test programs, use FALSE for this keyword.
UTIL_FRAM Specify the serial frame enable pins for the sequencer‑controlled utility lines.
UTIL_PADDING_RPTV_FLAT Define a threshold which decides to use a flat pattern or RPTV pattern for padding.

The default value is 16.

If the padding value is less than and equal to the threshold, a flat pattern is used and repeated to append to the burst. If the padding value is greater than this threshold, RPTV is used to insert vectors.
UTIL_SCLK Specify the serial clock pins for the sequencer‑controlled utility lines.
UTIL_SINP Specify the serial data in pins for the sequencer‑controlled utility lines.
UTIL_SOUT Specify the serial data out pins for the sequencer‑controlled utility lines.

For more information about utility line setup, see SmartRDI: Utility lines control.

Others
Keyword Description
ALLOW_SAME_RESULT_ID_ACROSS_RDI_BLOCK Specify TRUE or FALSE to allow or disallow using the same result ID in different RDI_BEGIN()/RDI_END() blocks inside the same test suite. It only supports a serial execution of a shmoo test suite when the value is set to TRUE.

The default value is FALSE.
INACTIVE_SITE_AUTO_MASK If this option is set to TRUE, all inactive sites will execute a dummy label and remain in a hold state; other sites will still execute their normal labels.

The default state is FALSE.
PURE_GENERATION_MODE Specify TRUE or FALSE to enable or disable pure generation mode.

When this option is set to TRUE, SmartRDI generates setups (pattern, burst, dc event, analog set and so on) only and skips pattern execution and results upload.

Note All rdi...getXXX() calls such as getVector(), getReadBit(), getWaveform() return dummy results. The size of result arrays = 0.

Enabling this option reduces the execution time of a "clean" 1st run by omitting the Viasco bind. It also allows to generate setups (pattern or analog set) and save them for later use or reuse in another program.

If not specified, FALSE is used by default.
VEC_MODE_SAMPLING_WAIT Specify MSET or PATTERN to set up a wait time for PPMU or BADC digital sampling in the VEC mode. The default choice is PATTERN which uses the wait time being defined in the measurement set as the sampling period. Use the PATTERN mode for inserting some waiting time in the pattern to set up a deterministic sampling rate.
Note The RDI_Configure file and the settings that can be set in the file are all optional. You can omit any settings in the file or even omit the complete file if no settings are required.
