Topic 136815

SEQUENCER_CONTEXT

The SEQUENCER_CONTEXT class supplies objects that serve to manage one or more SEQUENCER_CONTEXT_ITEM objects (execution contexts). In particular, it must be used to download these context items to the firmware.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SequencerContext.h.

Note

Changing the SEQUENCER_CONTEXT will invalidate the results that are read by API GET_FUNCTIONAL_RESULT(). The original sequencer start label must be restored by API Primary.label() followed by a FLUSH() before the results are read by GET_FUNCTIONAL_RESULT().

For an example, refer to Example 3 below.

Syntax

Constructor

SEQUENCER_CONTEXT();
~SEQUENCER_CONTEXT();

Member functions

SEQUENCER_CONTEXT& add(const SEQUENCER_CONTEXT_ITEM& item);
SEQUENCER_CONTEXT& erase(const SEQUENCER_CONTEXT_ITEM& item);
SEQUENCER_CONTEXT& apply(void);
SEQUENCER_CONTEXT& reset(void);
SEQUENCER_CONTEXT_ITERATOR getList(void);

Constructor

SEQUENCER_CONTEXT();
~SEQUENCER_CONTEXT();

The destructor will delete not only the test method structures, but also the context definitions in the firmware.

Member functions

add()

SEQUENCER_CONTEXT& add(const SEQUENCER_CONTEXT_ITEM& item);

This member function adds a SEQUENCER_CONTEXT_ITEM object to the context.

Parameter

I/O

Parameter

Description

I

item

The name of an SEQUENCER_CONTEXT_ITEM object.

erase()

SEQUENCER_CONTEXT& erase(const SEQUENCER_CONTEXT_ITEM& item);

This member function removes a SEQUENCER_CONTEXT_ITEM object from the context. It does not remove the context definition in the firmware. To do this, the apply() member function must be called subsequently.

Parameter

I/O

Parameter

Description

I

item

The name of an SEQUENCER_CONTEXT_ITEM object.

apply()

SEQUENCER_CONTEXT& apply(void);

This member function downloads the SEQUENCER_CONTEXT_ITEM objects (execution contexts) of the SEQUENCER_CONTEXT object to the firmware.

The function has no parameters.

reset()

SEQUENCER_CONTEXT& reset(void);

This member function deletes all SEQUENCER_CONTEXT_ITEM objects of the sequencer context on both, the test method and the firmware level, except the default context. This is, for example, to clean up an ISR setup.

The function has no parameters.

getList()

SEQUENCER_CONTEXT_ITERATOR getList(void);

This member function returns a SEQUENCER_CONTEXT_ITERATOR object. Sequencer context iterators are used to simplify looping over all SEQUENCER_CONTEXT_ITEM objects.

The function has no parameters.

Examples

Example 1: Defining three sequencer context items and combining them into one sequencer context

The following example defines three sequencer context items and combines them into one sequencer context. Then a multiport burst, which contains the ports of context item DE, is made the start label, and DE is started in non-blocking mode with START_TEST().

After a wait period the start label is switched to another multiport burst containing the ports of BC, and BC is started. If DE is still running when BC is started, both contexts will now run in parallel, because DE was started in non-breaking mode.

SEQUENCER_CONTEXT_ITEM sci1 ("A");
sci1.setPorts("PortA");
SEQUENCER_CONTEXT_ITEM sci2 ("DE");
sci2.setPorts("PortD, PortE"); // MPB2_DE
SEQUENCER_CONTEXT_ITEM sci3 ("BC");
sci3.setPorts("PortB, PortC"); // MPB3_BC, MPB4_B 
...
SEQUENCER_CONTEXT context1;
context1.add(sci1).add(sci2).add(sci3); // add all three sequencer context items to context1
...
context1.apply();
Primary.label("MPB2_DE"); FLUSH(); START_TEST("DE");
WAIT_TIME(wait_some_time); // Optional wait
Primary.label("MPB3_BC"); FLUSH(); START_TEST("BC");

Example 2: Retrieving a functional result of a test executed on a special sequencer context

The following example illustrates how to retrieve a functional result of a test executed using GET_FUNCTIONAL_RESULT() on a special sequencer context.

STRING sContext = "global";

ON_FIRST_INVOCATION_BEGIN();

    SEQUENCER_CONTEXT_ITEM context1(sContext);

    context1.setPorts("port1");

    SEQUENCER_CONTEXT context;

    context.add(context1).apply();

    CONNECT();

    FW_TASK("DCRM OVEM,LMAP,,(@@)");

    START_TEST(sContext);

    int a, b;

    WAIT_TEST_DONE(36000, &a, &b ,sContext);

    FW_TASK("DCRM OVEM,FCM,,(@@)");

ON_FIRST_INVOCATION_END();

std::vector<FUNC_TEST_BURST_RESULT> result;

GET_FUNCTIONAL_RESULT("port1", sContext, result);

cout << endl << "*** Current Site number: " << CURRENT_SITE_NUMBER() << " ***" << endl;

for ( uint i = 0; i < result.size(); i++ )
{
    FUNC_TEST_BURST_RESULT funcTestRes = result[i];

    cout << "Result for label " << funcTestRes.labelname << ": "
         << (funcTestRes.result==true ? "TRUE" : "FALSE" ) << endl;

    cout << "startCycle: " << funcTestRes.startCyc << endl << "numberOfCycles: "
         << funcTestRes.numberOfCycles << endl << "----------------------------------------------------" << endl;
}

DISCONNECT();

Example 3: Retrieving a functional result after the sequencer context has been changed

The following example illustrates how to retrieve a functional result after the sequencer context has been changed: Changing the sequencer context will invalidate the results that are read by the API GET_FUNCTIONAL_RESULT(). The original sequencer start label must be restored before the results are read.

ON_FIRST_INVOCATION_BEGIN();
{
    SEQUENCER_CONTEXT_ITEM context1("Context_port_1");
    context1.setPorts("port_1");

    SEQUENCER_CONTEXT_ITEM context2("Context_port_2");
    context2.setPorts("port_2");

    SEQUENCER_CONTEXT context;

    context.add(context1).add(context2);
    context.apply();

    ...
    ...

    //
    // 1st sequencer context
    //
    Primary.label("label_context_1");
    START_TEST("Context_port_1");

    //
    // 2nd sequencer context
    //
    Primary.label("label_context_2");
    FUNCTIONAL_TEST("Context_port_2");

    WAIT_TEST_DONE();

    //
    // Restore the start label
    //
    Primary.label("label_context_1");

    FLUSH();
}
ON_FIRST_INVOCATION_END();

//
// Read the result
//
GET_FUNCTIONAL_RESULT("","Context_port_1");
