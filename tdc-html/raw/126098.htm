Topic 126098

Wavetable tab

Protocol definition requires the use of STATEMAP. The STATEMAP section in the wavetable is of significant importance for protocol interpretation and generation respectively.

It provides the link for uniquely mapping a transaction to a physical waveform, respectively interpreting a waveform sequence as transaction fields. Consequently the frame sequence for a transaction needs to be specified in state characters.

Important information

  • Each protocol timing setup must contain exactly one wavetable definition, defining waveforms for all pin roles of the protocol.
  • All state map entries in a wavetable definition must have the same x-mode (across all pin roles).
  • The state characters must be selected accordingly to the encode/decode rules defining a state character sequence.
  • Do not use edge action 'C' within protocol wavetables
  • Do not use state character 'C' with protocol state map entries.
  • You have to define the state character 'R' for read parameters that needs to be fixed mapped to a single 'L' edge action. However, this state character 'R' is reserved to ensure correct and efficient reconstruction of results, respectively out-parameters .
  • One might use either x-modes or x/n-modes, but it still needs to be ensured that 'R' is mapped to a single "L" edge action.
  • Edges have to be configured monotonously increasing within the wavetable, starting at 1 (d1, d2, ..d8 and r1, r2, ...r8).
  • Remapping edges to result x-modes is not supported.
  • It needs to be ensured that edge delay specifications keep the order of edge indexes and cycle indexes, i.e. constructions like edge delay(r1) > edge-delay(r2) or edge-delay(r1) + tester-cycle-time < edge-delay(r2) are not supported.
