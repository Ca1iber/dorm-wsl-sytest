Implementing protocol wrappers to the test program

Subtopics

  1. Example: Writing a protocol based UTM using protocol wrapper

Using protocol wrappers will simplify programming by making the code shorter and thus more readable.

Generating protocol wrappers describes how to generate custom protocol based test classes as well as result proxy and vector classes.

While the result proxy and vector classes Do not have to be regenerated upon any modification of the protocol definition the custom wrapper class has to.

It can be a good practice to make the protocol wrapper classes available across multiple projects, which aids maintaining the classes. However, this is not part of this topic.

The description is kept general by purpose as the corresponding example will be more detailed.

Preparation

  • Decide how to implement the wrapper classes, either as local copy in your UTM project, or as shared UTM project.
  • Preparation with regards to device setup, etc. is identical to Implementing protocol based tests to the test program.
  • Create your custom protocol wrapper classes following the procedure Generating protocol wrappers.

Implementing custom wrapper APIs

Note The following only points out the differences to Implementing protocol based tests to the test program.
  1. Create a UTM class and include your wrapper class by adding the line #include <"CustomWrapperClass.hpp"> .
  2. Reuse your wrapper-less protocol based test code. Replace the system API SYNCHRONIZED_TEST() with your wrapper API <CustomWrapperClass>_SYNC_TEST() to create a protocol test object. The parameters passed to the object can be left unchanged:

    CustomWrapperClass_SYNC_TEST <ProtocoltestObject>(<"protocol'sPort">, <"non-protocol multiport burst pattern">, <"wavetable">, <"ProtocolPatternLabel");

  3. Add a transaction to the protocol based test object passing the parameter values in the same order as defined in the corresponding protocol definition.

    ProtocoltestObject.write(<"Parameter1Value">, <"Parameter2Value">, Parameter3Value">);

  4. Replace the .flush() and FUNCTIONAL_TEST() calls with the now available .run() function of your wrapper class: ProtocoltestObject.run();
  5. Replace the system's SYNCHRONIZED_TEST::unlink() call with the now available .unlink() function of your wrapper class: ProtocoltestObject.run();

Result proxy and vector classes

Result proxy and vector classes are usually being generated together with the custom wrapper classes.
