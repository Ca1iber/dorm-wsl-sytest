Topic 42572

Testflow Execution

Subtopics

  1. Binning
  2. Variables

Although the idea of multisite testing is to test all sites in parallel, sometimes this is not possible with all types of test suites.

  • Tests with pass/fail results can be run in parallel if they have been optimized for maximum throughput.
  • Tests with value results that utilize shared resources like the Board ADC cannot be optimized. If a test suite within a multisite test uses a data set like this, all sites are tested one after the other.
  • User Procedures/Test Method Programs are also called for each site one after the other. You can, however, program them to run parallel.

If there are branches within a testflow the following rules apply:

  • In pass/fail branches, failing branches are taken before passing branches.
  • In if/then branches, FALSE statements are taken before TRUE statements.

Waiting sites receive the same data as the sites currently tested. This may change their initial status. If following tests require certain conditions, the sites may need to be re-initialized.
