The ASCII Vector Row

A (parallel) ASCII vector has the following format:

R<rep> <ASCII_dvc> (<st_ch_1>|(D|R)(<st_ch_1>|<x_1>)|<list_of_st_ch_1>) ...(<st_ch_n>|(D|R)(<st_ch_n>|<x_n>)|<list_of_st_ch_n>) [[%]<comments>];

The meaning of the individual components is as follows:

  • R<rep>: This statement, which is called the repeat factor of the ASCII vector, defines the number of repetitions for the vector, that is, how often its binary equivalent is to be sent to the DUT.

    If <rep> is > 1, there are two possibilities to convert the vector. Either, it is translated into an RPTV instruction with a repeat value of <rep>, in which case only one row of waveform DC/DC power units is created for the ASCII vector, or it is flattened, that is, the row is written <rep> times into the index array. This can be controlled by the -r parameter ofv2b. The default is that an RPTV instruction is only created for a repeat factor > 32. (The situation is more complex if the x-mode factor is > 1; see Processing a Repeat Factor > 1.)

  • <ASCII_dvc>: This statement specifies the name of the ASCII device cycle according to which the state characters of the vector are to be interpreted.
  • <st_ch_i>: Specifies a state character which is defined for <ASCII_dvc>. You can use any character as a state character except "D", "R", ";", "#", and blanks.
  • (D|R)(<st_ch_i>|<x_i>): This statement specifies state characters for the pins of a pin group as specified in the format line. You can either assign the same state character <st_ch_i> to every pin of the group, or code a separate state character for each of these pins by a single hexadecimal number <x_i>. The second case is assumed if the first character after the R or D is a hexadecimal digit (0-9, A-F or a-f), the first for all other characters.

    The hexadecimal number is processed as follows: If the pin group comprises n pins, the last n bits of the binary number corresponding to <x_i> are associated with the pins of the pin group from left to right. If the length of the binary number is m (m ≥ n), then the leftmost pin within the pin group definition is associated with bit m - n + 1, counting from the left. The rightmost pin will be associated with bit m.

    The initial character specifies how the bits are to be translated into state characters. With D, a binary 0 is translated into the character 0, and a binary 1 into 1. With R, a binary 0 is translated into the character L, and a binary 1 into H. Note that this implies that 0, 1 or L, H must be defined for the pins of the pin group in the ASCII device cycle <ASCII_dvc>.

    For example, suppose that a pin group comprises the five output pins o1 through o5 in that order, and that R1e has been specified for that group in an ASCII vector. Since the binary number corresponding to 1e is 00011110, the vector translation will assume the state character H for o1, and L for o5, and will expect to find an entry foro1 and H in <ASCII_dvc> within the timing map file, and and also an entry for o5 andH.

    See Example 2.

  • <list_of_st_ch_i>: This format also specifies state characters for the pins of a pin group as specified in the format line, but by specifying one state character for every pin of the group. This format must be used if some of the state characters are different from 0, 1 (for input pins) or L, H (for output pins).
  • [%]<comments>: Specifies an optional comment on the ASCII vector which is transferred to the binary vector file. By default, initial white spaces are suppressed. But if the comment is preceded by the % character, the white spaces are preserved. You can suppress the translation of these comments with the v2b option -U.

    Note that the name of the ASCII device cycle and the number of the ASCII vector are by default also added as comments to the binary vector file. To suppress these, use the v2b options -A and -L, respectively.

    The vector translation uses the BCMT firmware command to pass the comments to SmarTest. This command restricts the length of a comment to 250 bytes. If the comment is longer, it will be truncated. This must be taken into account especially with an x-mode n > 1, since in this case the vector translation will create the comment on the resulting binary vector by concatenating the comments on the n ASCII vectors.

    If the x-mode is > 1, you must also make sure to associate the comments on the resulting binary vectors with the appropriate ASCII vectors. With a X4-mode, for example, the comment on the first binary vector must be placed on the first ASCII vector, the comment on the second binary vector on the 5th ASCII vector and so on.
