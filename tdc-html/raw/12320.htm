Topic 12320

Accessing Utility Lines

The purpose of firmware commands for accessing utility lines is twofold:

  • to set and read the output state of the line (which defines the desired state of the external device), and
  • to read the input state of the line (which reflects the current actual state of the external device).

There are low level and high level commands for accessing utility lines. The low level commands can only address a complete utility line block which they identify by its block number. The values must be specified (and are returned by the query) as a decimal number whose binary representation determines the desired states for all lines of the block. The high level commands use symbolic names which can refer to a single line or an arbitrary subset of more than one block. Such a subset is called a utility purpose. The values are specified by a (string of) "1" or "0" character(s).

The desired state can be set with the low level UTOT command and the high level UTST and UPST commands. The corresponding queries return the current desired state of the device.

The low level command UTOT downloads the specified settings immediately to the hardware.

The high level commands UTST and UPST refer to a single line (UTST) or a utility purpose. The name used by UTST must have been defined with the DFUT command, and the name for UPST with DFUP. In contrast to UTOT, UTST and UPST do not download their settings directly to the hardware. They only define the data to be downloaded. The actual activation must be done with the FLSH command. FLSH downloads the settings of all utility lines for which an output state has been defined with UTST or UPST in parallel.

DFUP also assigns standard output states to the lines of the utility purpose it defines. These settings must also be selected for activation with UPST (which is done by specifying no setting in the command) and then downloaded with FLSH.

After execution of FLSH, you can cause the system to wait for a certain time with the WSDN command. The wait time is determined by the settling times of the utility lines and purposes for which a UTST or UPST command has been issued. The settling time for a utility line is defined with UTTI, that for a utility purpose with UPTI. WSDN will use the longest settling time that is defined for any of the affected utility lines or purposes.

The input state can be retrieved with the low level UTIX? and UTIN? queries, and with the high level UTST? query. UTST? can thus return both the output and the input state of a single line.

In a multi-site setup, you can use the UPAS command to associate different standard settings with the same utility purpose for sites > 1 (the standard setting for site 1 is defined with DFUP). To activate these site specific settings, you must restrict the setup focus to the site in question with the PSFC command, and then issue UPST and FLSH in order to download the settings. Note that you can use the same utility purpose for different sites only if the sites are executed serially.
