Defining sequencing groups

Sequencing groups are identified by sequencing group names. They can be defined in the timing specification as timing sequencing groups, or in the vector setup (with the Multiport Burst setup tool or the SQLB command) as synchronization groups.

Sequencing groups must be definable in both the timing and vector setup because it is possible to combine a multi-port timing with a single port vector setup (in which case no synchronization groups can be defined), and also a multi-port burst with a single-port timing (in which case no sequencing groups can be defined). A continuous clock setup is an example for the first case.

Special care must be taken if a timing setup containing sequencing group definitions is combined with a vector setup that contains synchronization group definitions. In this case the sequencing groups and the synchronization groups must be compatible in the following sense:

If the timing ports to which two pins pin1 and pin2 belong are members of the same sequencing group, then the vector ports of pin1 and pin2 must be members of the same synchronization group, and vice versa.

Note Do not use the name "Default" when you define a new synchronization group or change the name of an existing one. The "Default" synchronization group corresponds to the sequencing group with the empty name within the timing specification. If you use it for a user defined synchronization group, inconsistencies may arise, in which case the test will no longer be executable.
Note Where an explicit sequencing group is not needed, use the default sequencing group. Assigning all ports to your own "default" group adds about 600μs per sequencer run.

Example

For sequencing group definitions within a multi-port specification, see the example in Multi-port timing specifications. The same grouping could be defined in the vector setup with the SQLB command as follows:

> SQLB "MP_B",MPBU,28,31,"gr1",(port1)
> SQLB "MP_B",MPBU,28,29,"gr2",(port2)
> SQLB "MP_B",MPBU,31,32,"gr2",(port3)
