GPIB communication flow for TEL probers

This section describes the GPIB communication between the driver and the prober.

Ignored SRQs

The following table lists service requests (SRQs) from the prober that are ignored by the driver.

TEL prober SRQs that are ignored by the driver

Ignored prober SRQs

Description

0x4e

Assistance needed

0x68

Manual test

0x50

Prober error

0xff

Parameter error

These SRQs require direct operator operations at the prober. The driver waits until the operation is cleared.

The table below shows the communication between the driver and the prober. The actions and messages are listed in sequential order.

See Conventions for GPIB communication for descriptions of the syntax.

bin dies

Cibbb...*ibbb...

 

Send bin data string, where i represents the pass/fail information and bbb... represents the binning information.

For 20S probers, the characters 0, 1, 2, 4, and 8 are used.

For 78S and P8 probers, the characters @, A, B, D, and H are used.

For P12 and P8 probers, when the binary binning method is enabled, the driver supports up to 1,000,000 (0 to 999,999) bins. For example, C@O@GB@@@@ represents passing the die bin to 9999; OCBDO@@@ represents passing the die bin to 999999.

query chuck_temp:

f1

"string"

Query the temperature of the hot chuck with PROB_HND_CALL(ph_get_status chuck_temp).

The format of the returned string is current temperature:<aaaabbbb>. aaaa presents the current temperature and bbbb presents the setting temperature.
