Debugging the dynamic DC test setup

When the testflow fails on the first attempts, you may need to debug the setup of your dynamic DC test.

About this task

The pattern editor allows the viewing of failed patterns in detail.

To force the failure examples shown below, the low voltage limit in the meaLimV_0.0_0.2 event was changed to 150 mV.

Before you begin

You must have executed the test at least once. You should also make sure that the failure is not caused by the device.

Procedure

  1. The graphic shows a failed testflow for a dynamic DC test.
  2. While the "connect" test suite passed, the "ramp" test suite failed. Therefore the first test suite (connect) is green, the second (ramp) is highlighted in red.
  3. Failing tests are marked in the annotation ruler on the right of the pattern editor. A failing test point is highlighted in red.
  4. To go directly to a failed test point you can either click an annotation marker, or you use the navigation buttons in the pattern editor toolbar.
  5. The Properties view shows the result details per test point, in this case a violation of the low voltage limit.
  6. Because the dump routines in the test method project are programmed accordingly, the same information appears also in the Console view:

What to do next

Once your test setup is complete and runs without any failing tests, you can apply it in a real test environment.

Refer to the tables for each card in section EVENT_BASE, to determine the minimum number of vectors between DC events or at the end of a pattern.
