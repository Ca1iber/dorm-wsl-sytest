Activity Trace Event Record (ATER)

ATER (Activity Trace Event Record) records describe activity trace events that have been created using custom test method code. They are a variant of GDR records.

ATER records are converted from EDL data log entries that have been created through activity-tracing test methods. They record activity trace events that you want to add to the data log to help with later analysis.

Activity trace event entries in the EDL data log - from which ATER records in the STDF data log are converted - are not created implicitly by SmarTest, for example, when test results are evaluated. Instead, all such records must be expressly added to the data log in a test method.

If the amount of activity data logged exceeds the space available in a single ATER record, multiple records are automatically created.

ATER records are a proprietary STDF extension. They are based on the GDR records in the STDF standard.

ATER record structure

An ATER result record consists of two blocks:
  • The header is the same as for any other STDF record; it describes the size and type of the record.
  • The result section describes the a traced activity.

The data type abbreviations used in the tables are the standard STDF types.

Header section
Field Data type Description
REC_LEN Two-byte unsigned integer Bytes of data in the record, excluding the header.
REC_TYP One-byte unsigned integer Record type. This is always 137 for ATER records.
REC_SUB One-byte unsigned integer Record subtype. This is always 10 for ATER records.
Result section
Field Data type Description
REC_CUSTM Variable-length ASCII character string. The first byte is the string length in bytes. The type of the record. This is always ACTIVITY_TRACE_LOG.
EVT_SRC Variable-length ASCII character string. The first byte is the string length in bytes. The source of the event in the record. This is the information that was specified with the setTestCaseSource​() method.
HEAD_NUM One-byte unsigned integer The number of the site group. See HEAD_NUM and SITE_NUM fields, below, for details.
SITE_NUM One-byte unsigned integer The site number. See HEAD_NUM and SITE_NUM fields, below, for details.
ACTIVITY Variable-length ASCII character string. The first byte is the string length in bytes. The logged activities. This is the data that was logged with the setActivities() or setBinaryActivities​() method.

HEAD_NUM and SITE_NUM fields

The true site number is encoded in the HEAD_NUM and SITE_NUM fields for tests with more than 255 site

HEAD_NUM contains the number of the group of 256 sites in which a site is located: 0 for the first group, 1 for the second, and so on. SITE_NUM contains the number of the site within this group. In other words: HEAD_NUM is the quotient of dividing the true site number by 256, and SITE_NUM is the remainder (modulo).

To calculate the true site number, multiply HEAD_NUM by 256 and add SITE_NUM. For example, if HEAD_NUM is 5 and SITE_NUM is 23, the true site number is 5 * 256 + 23 = 1303.

GDR Record
  REC_CUSTM:       ACTIVITY_TRACE_LOG
  EVT_SRC:         Demo2
  HEAD_NUM:        0x0
  SITE_NUM:        0x1
