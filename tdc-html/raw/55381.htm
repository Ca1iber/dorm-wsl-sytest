Suppressing Reactivation of Primary Sets with FTCG

By default, the primary sets are activated at the start of each functional test. This activation requires a CTOF (Change Timing On the Fly) sequence during which the tester sequencer is inactive. But when testing a PLL device, the clock must be running continuously during the whole test flow. The FTCG (Functional Test ConfiGure) command allows you to suppress the (re)activation of the primary sets for the clock pins of such a device. For general information on FTCG, see the Command Reference manual.

FTCG suppresses (with the option ON) and allows (with the option OFF) activation of the primary sets for ports, but these ports are treated as representatives of the sequencing groups to which they belong in the current timing specification (defined by SPRM) or start label (defined with SQSL). This means that SmarTest will suppress activation for all ports of the respective sequencing group. You insert the FTCG command in the testflow with the FW-Escape testmethod.

The settings defined with FTCG remain valid until they are modified by another application of FTCG, or the system is reset, or the device is changed.

As an example, suppose that you have two ports port_1 and port_2 that are contained in two different sequencing groups. Then issue

FTCG SKPR,ON,(port_1)

at the start of the testflow before the first functional test. This will have the effect that activation of the primary sets is suppressed at the start of every following functional test for all ports of the sequencing group to which port_1 belongs. Note that the sequencing groups to which port_1 belongs may change from one test to another if the specification or the multi-port burst is changed.

FTCG can be used to suppress the CTOF sequences while the tester sequencer is inactive. CTOF sequences executed during vector label execution are controlled by the sequencing groups defined in the multi-port burst label.

In order to suppress CTOF sequences altogether for the clock ports of a continuous clock setup, the following conditions must be satisfied:

  • The clock ports must have their own sequencing group.
  • The port bursts of the clock ports must not contain any CTIM or CLEV instructions.
  • The settings for the clock ports must not be changed.

    This implies that. if the period resolution is calculated by SmarTest, the period must not be changed in the settings for any port (for example, by changing the value of a spec variable with SVLR). This holds even for those ports that do not belong to the sequencing group in question. For any such change would lead to a recalculation of the period resolution.

    To avoid recalculation, the period resolution can be explicitly defined in the timing port's equation set.

  • Activation of the primary sets at test start must be suppressed for the sequencing group by setting FTCG to ON for at least one port of the group.
