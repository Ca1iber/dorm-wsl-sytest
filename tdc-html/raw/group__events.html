Detailed Description

Typedef Documentation

typedef void(* gio_SRQ_handler_t) ( IDID id)

Type of SRQ handler functions.

An SRQ handler is called when an external instrument signals a request for service. The only argument is the IDID of the session for which the client application registered an SRQ handler.

Note that a single SRQ may cause more than one handler to be called, because interface hardware may not be able to identify the source of the SRQ; the handler then needs to check (for GPIB, e.g., using a serial poll via gio_read_status_byte()) if it must handle the request.

Attention
Concurrent SRQs on GPIB interfaces cannot be handled safely inside the GIO layer; the GPIB SRQ line is level triggered. A client application which needs to handle multiple simultaneous SRQs must use additional effort to avoid "losing" service requests.

GIO_ERROR gio_resume_events ( void  )

Globally resume asynchronous events.

This function re-enables all interrupts and SRQs after a prior call to gio_suspend_events(). Events which occur between suspension and resumption will not be lost, but delivered in the correct order after resumption.

When gio_suspend_events() was called more than once, events are re-enabled only after a corresponding number of calls to gio_resume_events(). It is an error to call gio_resume_events() while events are enabled.

GIO_ERROR gio_suspend_events ( void  )

Globally suspend all asynchronous events.

This function disables all interrupts and SRQs, until either

  • a call to gio_resume_events(), or
  • a call to gio_wait_event().

If asynchronous events arrive during the period in which events are disabled, they will be delivered after they are enabled again, and in the correct order.

Calls to gio_suspend_events() can be nested; events are re-enabled only after a corresponding number of calls to gio_resume_events().

GIO_ERROR gio_wait_event ( uint32_t  milliSeconds)

Wait for an asynchronous event to occur (and to be handled).

gio_wait_event() waits for at least one asynchronous event to arrive and be handled, temporarily enabling events if they are currently disabled. If no event occurs before the given timeout has elapsed, gio_wait_event() returns GIO_ERR_IO_TIMEOUT.

If milliSeconds is zero, the timeout is infinite.

Attention
There is no guarantee that the operation will time out after exactly milliSeconds milliseconds. Scheduling delays and timer granularities (which depend on the operating system and/or the system configuration) affect the timeout calculation. It is however guaranteed that the timeout will occur after at least the given interval.
