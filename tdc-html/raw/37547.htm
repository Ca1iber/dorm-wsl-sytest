d2w parameters

  • -A (optional): This flag causes d2w to specify the actions in the full, unabbreviated format within the wavetable. If it is omitted, the abbreviated format will be used.

  • -a <temp_dir> (optional): Specifies the name of an alternative directory for temporary files. By default, this directory is /tmp. If two d2w calls are executed in parallel, they should use different directories for their temporary files.

  • -b <test_system_cycle_length> (mandatory): This parameter specifies the length of the test system cycle. It is written into the timing set generated by d2w. It also determines for any given ASCII device cycle the mapping of state characters to waveform DC/DC power units in the timing map file. To this end, d2w first calculates the least common multiple lcm of the test system cycle length m and the period length n specified for the respective ASCII device cycle. Then it maps sequences of lcm/n state characters to sequences of lcm/m waveform DC/DC power units for this ASCII device cycle. In the special case where lcm = m, lcm/n is simply the x-mode factor as it would be specified in the global configuration file for ait.

    For example, if m = 15 and n = 9, then lcm = 45; therefore sequences of lcm/n = 5 state characters will be mapped to sequences of lcm/m = 3 waveform DC/DC power units in the timing map file. If, on the other hand m = 15 and n = 5, then lcm = 15, and sequences of 3 state characters will be mapped to a single waveform index.

    If a continuous clock setup is to be created, it is the test system cycle length of the data port that must be specified by this parameter.

  • -C (optional): If the wavetable specified with the -w parameter already exists, then by default, d2w expands this wavetable. If you specify the -C flag, however, the old wavetable is deleted.

  • -c (optional): If the timing set specified with the -t parameter already exists, then by default, d2w expands this timing set. If you specify the -c flag, however, the old timing set is deleted.

  • -D <dvc_output_file> (optional): This parameter specifies the name of an output ASCII timing file. This file is normalized and incorporates the effects of eventual OPTIONS statements in the input version of the ASCII timing file (see Merging State Character Definitions: The OPTIONS Statement). You can also use it to translate a timing setup file back to an ASCII timing file. To do so, do not specify an input ASCII timing file, but only an output version.

  • -d <dvc_input_file> (optional): This parameter specifies the name of an input ASCII timing file. It is the main input for the timing setup file to be created the name of which is specified with the -f parameter.

  • -E <equ_set_descr> [<pll_equ_set_descr>] (optional): This parameter specifies a description of the equation set to be created. Additionally, it can specify the description of the equation set for the clock port of a continuous clock setup; in this case, the first description applies to the equation set for the data port. If the descriptions contain whites spaces, they must be enclosed by double quotes.

  • -e <eq_set_no> [<pll_eq_set_no>] (mandatory): This parameter specifies the number of the equation set to be created or modified. Additionally, it can specify the number of the equation set for the clock port of a continuous clock setup; in this case, the first number specifies the number of the equation set for the data port. If a second equation set is specified, you must also specify a second timing set number for the -t parameter.

  • -f <timing_setup_file> (mandatory): This parameter specifies the name of a timing setup file. If an ASCII timing file is specified with the -d parameter as an input file, this is the file where the translated data is written. If the -d parameter is omitted and an ASCII timing file is specified with the -D parameter as an output file, then the data of this timing setup file will be translated back into the specified ASCII timing file.

  • -g (optional): This flag causes the timing translation to resolve pin groups. In the output files, the individual pins will be specified instead of the group.

  • -h (optional): This flag causes d2w to display a help file about itself.

  • -J <port> [<pll_clock_port>] (optional): This parameter specifies the ports for which the timing is created.

  • -K (optional): If the x-mode factor of a pattern is > 1, this flag causes the timing translation to create waveforms also for state character sequences from different ASCII device cycles. It is only effective if no x-mode control file is specified (for the x-mode control file, see The X-Mode Control File (*.cmb)).

    By default, that is, if no x-mode control file is specified and the -K flag is not set, the timing translation only considers sequences of state characters belonging to the same ASCII device cycle. If the -K flag is set and effective, a waveform is created for a state character sequence if the ASCII device cycle combination of the sequence fulfills the following conditions.

    • All its ASCII device cycles are associated with the pattern.
    • All its ASCII device cycles are connected to the same timing set.
    • Its total length (calculated by adding the ASCII periods of all its elements) equals (a multiple of) the test system cycle length specified in this timing set.
    • None of its initial segments fulfills condition c.
    • The number of its elements is not greater than 10.

      The ASCII device cycle combinations that can be selected in the x-mode control file are also characterized by these conditions. For an example, see Figure in Creating Sequences from Several ASCII Device Cycles.

  • -k <x_mode_file> (optional): Specifies the name (without extension) of an x-mode control file.

  • -L (optional): If combined with the -M flag, the -L flag causes the timing translation to merge data records with the same state character across timing records within one ASCII device cycle. The merge mode can also be specified in the ASCII timing file with the OPTIONS statement (see Merging State Character Definitions: The OPTIONS Statement). The statement in the file takes priority.

  • -M (optional): This flag causes the timing translation to merge timing records, that is, to create waveforms for any state character in any timing record within one ASCII device cycle. The merge mode can also be specified in the ASCII timing file with the OPTIONS statement (see Merging State Character Definitions: The OPTIONS Statement). The statement in the file takes priority.

  • -m <timing_map_file> (mandatory): This parameter specifies the name of the timing map file to be created, or (if it already exists) to be expanded.

  • -n <context_name> (optional): This parameter specifies the name of a context. Contexts define whether pins are used as differential or as single-ended pins. If the parameter is omitted, the default context DEFAULT, which defines all pins as single-ended, is assumed.

  • -O <equation_block> (optional): Specifies the name of an equation block (EQUATIONS keyword) from the ASCII timing file. This parameter can be specified more than once. It serves to restrict the equation blocks that are used in the timing. If it is omitted, all equation blocks will be processed.

  • -o <specs_block> <specset_no> [<specs_descr>] (optional): Specifies the name of a specs block from the ASCII timing file (SPECS keyword), a specset number, and optionally a specset description. This parameter can be specified more than once. It serves to restrict the specs blocks that are used in the timing. If it is omitted, all specs blocks will be processed.

  • -P (optional): This flag causes the timing translation to create the wavetables in the pure physical waveform format. If it is omitted, the logical waveform format is used.

  • -p <pin_config_name> (mandatory): Specifies the name of a pin configuration file.

  • -R (optional): The waveform index f (which is used as a s default value by RDI) will be skipped in the generated wavetable.

    If -R is specified, d2w generates a wavetable with the waveforms indexes 0 to e and then continues with the index 10.

  • -r <period_res> (optional): Specifies the period resolution (in ns).

  • -s <ASCII_dvc_list> (optional): Specifies the name of a file containing the names of those ASCII device cycles within the ASCII timing file from which the timing is to generated. If this parameter is omitted, all ASCII device cycles of the ASCII timing file are processed.

  • -T <timing_set_descr> [<pll_timing_set_descr>] (optional): This parameter specifies a description of the timing set to be created. Additionally, it can specify the description of the timing set for the clock port of a continuous clock setup; in this case, the first description applies to the timing set for the data port. If the descriptions contain whites spaces, they must be enclosed by double quotes.

  • -t <timing_set_no> [<pll_timing_set_no>] (mandatory): This parameter specifies the number of the timing set to be created or modified. Additionally, it can specify the number of the timing set for the clock port of a continuous clock setup; in this case, the first number specifies the number of the timing set for the data port. If a second timing set is specified, you must also specify a second equation set number for the -e parameter.

  • -U (optional): This flag activates waveform optimization. The generated waveforms are optimized by removing redundant actions, namely, by contracting two consecutive occurrences of the same action into one, and by suppressing masked comparisons (action code X).

    This option is primarily intended to be used with x-mode factors > 1. It serves to reduce the number of required edges (the maximum for the V93000 is 8 drive edges, and 6 receive edges on the P/Ce systems, 8 on the Pin Scale systems), and also the total number of generated waveforms per pin (for the V93000, the maximum is 32 for the P/Ce systems, and 256 for the Pin Scale systems), since different waveforms can become identical by removal of actions.

    Normally, it will be best to specify neither U nor its opposite u, in which case d2w will optimize the waveforms if the x-mode factor is > 1, and perform no optimization if it is 1.

  • -u (optional): This flag inactivates waveform optimization. Optimization is usually unnecessary for patterns with an x-mode factor 1.

    Normally, it will be best to specify neither u nor its opposite U, in which case d2w will optimize the waveforms if the x-mode factor is > 1, and perform no optimization if it is 1.

  • -V (optional): This flag causes d2w to issue the version of the tool.

  • -v (optional): This flag causes d2w to issue detailed (verbose) information about its processing.

  • -w <wavetable_name> (mandatory): Specifies the name of the wavetable to be created or expanded. The name can consist of up to 40 characters.

  • -X <mux_file> (optional): Specifies the name of a pin multiplexing file.

  • -x (optional): This flag causes d2w to create the device cycle names within the wavetable from the state character (for x modes > 1: character sequence) on which the waveform is based. If several state character sequences result in the same waveform, the first such state character sequence is used as the name.

  • -Y (optional): This flag causes the timing translation to create a timing setup for the 83000. This can be combined with the z flag in order to make the setup compatible with the V93000.

    If neither Y nor Z is specified, Z is assumed.

  • -y (optional): This flag causes the timing translation to make a setup for the V93000 compatible with the 83000. Thus, for example, only six edges will be used.

  • -Z (optional): This flag causes the timing translation to create a timing setup for the V93000. This can be combined with the y flag in order to make the setup compatible with the 83000.

    If neither Y nor Z is specified, Z is assumed.

  • -z (optional): This flag causes the timing translation to make a setup for the 83000 which is compatible with the V93000. Thus, for example, tristate actions will be confined to edges 1, 3, 4, and 6.
