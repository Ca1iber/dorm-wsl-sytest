Defining the wavetable for a pattern‑based SmartLoop test

The wavetable for a pattern‑based SmartLoop™ test is generated automatically by SmarTest. You only need to tell the system that a pattern‑based SmartLoop™ test is to be executed. This is done with the LOOP_O keyword for the output pins whose received data is to be used as the drive data for certain input pins, and with the LOOP_I keyword for the input pins which are to be driven by these received data. All x-modes (x1 through x8) are allowed. The edges are distributed equidistantly within the tester cycle. It is also possible to use transition tracking in a pattern‑based SmartLoop™ test (for details of setting up the transition tracking, see Combining transition tracking with a PRBS or pattern‑based SmartLoop test).

Thus, the format of a LOOP_I statement is

LOOP_I [Xi],

where 1 ≤ i ≤ 8.

If no x-mode is specified, x8-mode is assumed.

The format of a LOOP_O statement is

LOOP_O [Xi|TTXj].

where 1 ≤ i ≤ 8, and j is 4 or 6. TTXj must be specified if the pattern‑based SmartLoop™ is to be combined with transition tracking on the output pins. If no x-mode is specified, x8-mode is assumed.

For the input pins, you can also define a break waveform with the usual keyword BRK. The format is

BRK (CLK|HOLD|F10|F1Z|F00|F0Z).

The function of the individual options is as follows:

CLK

A transition from 0 to 1 or from 1 to 0 occurs at every edge. The start value is 0.

HOLD

Nothing is done.

F10, F1Z, F00, F0Z

The pin is kept in the specified state throughout the cycle.

F10_IDLE,

F1Z_IDLE,

F00_IDLE,

F0Z_IDLE

The pin is kept in the specified state throughout the cycle. The difference between the simple and the qualified options is that, for example, F10 is inverted to F00 for the negative connection of a pair of differential pins, whereas with F10_IDLE, no inversion takes place.

Combining pattern‑based SmartLoop™ with transition tracking

When you combine pattern‑based SmartLoop™ with transition tracking and specify TTX6 on the output pin, you must set the input pin to LOOP_I X6, as expected. With TTX4, however, the input pin must be set to LOOP_I X8, not x4. In order to compensate for the different x-modes, you must put input and output pin into different ports and run the input pin with twice as long a period as the output pin (see Defining edge delays for a pattern‑based SmartLoop test).

Intermediate loopback for PS1600

On a PS1600 system you can also pass an intermediate value back to the device. This is done with the keywords

LOOP_I_IDLE [Xi],

where 1 ≤ i ≤ 4 (not 8), and

LOOP_O_IDLE [Xi],

where again 1 ≤ i ≤ 4 (not 8). If no x-mode is specified, x4 is used.

Examples

Example 1

WAVETBL "LPBK"
PINS IN1
LOOP_I X6
BRK CLK

PINS OUT1
LOOP_O TTX6

In this example, the pattern‑based SmartLoop™ test is combined with transition tracking in x6-mode. This example can be combined with the first example of Defining edge delays for a pattern‑based SmartLoop test in one timing specification.

Example 2

WAVETBL "LPBK1"

DEFINES in

PINS IN1
LOOP_I X8
BRK CLK

. . .

WAVETBL "LPBK2"

DEFINES out

PINS OUT1
LOOP_O TTX4

In this example, the pattern‑based SmartLoop™ test is combined with transition tracking in x4-mode. Note that the drive pin is set to x8. Note also that input and output pin are put into different ports, IN1 into in, and OUT1 into out. This is done in order that input and output pin can be run with different periods. This example can be combined with the second example of Defining edge delays for a pattern‑based SmartLoop test in one timing specification.

Functional changes

  1. Introduced in SmarTest 7.0.1
  2. SmarTest 7.1.2: All x-modes are now supported. Pattern‑based SmartLoop can now also be combined with transition tracking in x6-mode.
