Scan Testing in a Multi-Port Setup

For a scan test, it is usual for the few scan pins to have long vector data, while the many parallel pins (all the non-scan pins) just repeat a sequence of vectors.

In this scenario, the advantage of scan testing in a multi-port setup, is that you can save on vector memory by setting up one port to hold the fast parallel vectors and a second port to hold all the slower scan vectors.

This works well where the device cores are isolated and scan tests do not affect other core tests.

The ASCII Interface will translate the scan vectors to a normal functional pattern for the scan port and the parallel repeat vectors will be translated to a very short port pattern on the parallel port with the vectors repeated hence saving vector memory.

Both port patterns are added to a multi-port burst pattern.

This technique requires synchronization and it may not apply to all scan tests. The implementation for this setting varies based on the number of available clock domains on the system and it may not always be practical with regards to alternatives.
