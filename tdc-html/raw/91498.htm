Master file format for timing setup

The first line of a timing master file must be

hp93000,timing_master_file,0.1

The second line has the format

testerfile: <tester_file_name>

It specifies the tester setup file which is to be split or into which the subfiles are to be merged.

The subsequent lines in the timing master file associate the parts of the timing setup with a subfile.

The smallest parts of a timing setup that can be stored in a separate subfile are

  • wavetables
  • equation sets (together with their associated single-port timing specifications)
  • multi-port timing specifications
  • common blocks (each enclosed by #begin<block_description> and #end) that are placed at the top of the wavetable or equation set section.

    Common blocks can be placed everywhere within the timing setup file. But only those at the top of a section are recognized by the Setup Management tool.

Each of these parts is associated with a subfile by a line which specifies the type of the part (wavetable, equation set, multi-port specification), its name or number, and the associated subfile. Different parts can be associated with the same subfile.

The paths for the subfiles can be relative or absolute. The reference directory for relative paths is the directory of the master file.

You can insert comments everywhere in the file. They are identified by the hash (#) character at the start of a line.

Format of entries

The formats for the different part types are as follows:

WAVETABLE <wavetable_name> [PIN_ALIAS_SET <pin_alias_set_name>]: <file_name>
EQNSET <equationset_number> [PIN_ALIAS_SET <pin_alias_set_name>]: <file_name>
MULTIPORT_SPEC <"specification_name">: <file_name>

DEFINES: <file_name>

The DEFINES entry points to the subfile that contains the common blocks.

The PIN_ALIAS_SET keyword identifies the alias set used in the wavetable or equation set of the assembled timing setup file.

When the assembled timing setup file is split with the Setup Management Tool, the alias set is removed from the generated sub-file and package pin names are used.

Format of automatically generated file names

When the Setup Management Tool splits the timing setup file and finds a part for which no entry exists in the master file, it must create not only a new subfile for this part, but also a name for it. These automatically created file names are put together as follows:

eqnset_<equation_set_number>.tim
wvt_<wavetable_name>.tim
mport_<multiport_specification_name>.tim
defines.tim

You can add a user defined prefix to the names with the environment variable VERIGY93000_MFH_PREFIX. Specify

export VERIGY93000_MFH_PREFIX=<prefix>

in the shell where you start SmarTest.

For more information on working with specifications, see also the section on the Spec Tool.

Example

The following is an example of a timing master file:

hp93000,timing_master_file,0.1
# this is a comment
testerfile: demo.tim

EQNSET 1: files/part1.tim
EQNSET 2 [PIN_ALIAS_SET usb_set]: files/eqnset02.tim

WAVETABLE wtbl_1: files/part1.tim
WAVETABLE wtbl_2: files/wtbl_2.tim

MULTIPORT_SPEC "spec_1":files/part1.tim
MULTIPORT_SPEC "spec_2":files/spec_2.tim
DEFINES: files/defines.tim

In the assembled level setup file demo.tim, the alias set usb_set is used in the equation set 2. When demo.tim is splitted, the alias set usb_set is removed from the generated sub-file eqnset02.tim and package pin names are used.
