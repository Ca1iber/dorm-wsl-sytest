Specifying the Device Path

The Workorder Manager can work with two file structures based on either the DUT_PATH or the INSTALLED_DUT_PATH, which-in each case- represents the root of the device path and is user-definable (see "Org File" below).

  • DUT_PATH. This is the standard (see the figure below).

    With this structure you can have several test programs for each device. And each test program can have common files-vectors, timing etc.

  • INSTALLED_DUT_PATH. This is a structure similar to the standard structure but with an additional directory level before the device directory level (see the figure below).

With the structure shown above, there is an extra level before each of the device directories. It is entirely up to you how you make use of this extra level; you might have different versions of SmarTest on these levels, or different testflows. This structure gives more flexibility to support revision control (see Executing a Workorder From the Command Line).

Org File

On any given tester, the SmarTest software parses the org file to extract a pointer to the root of the user-definable device path, namely the DUT_PATH or the INSTALLED_DUT_PATH.

The org file is located in the directory:

/etc/opt/hp93000/soc/

The org file consists of a single line specifying either the DUT_PATH or INSTALLED_DUT_PATH, so its contents could be, for example:

DUT_PATH /users/mike/ReleasedTestProgs
