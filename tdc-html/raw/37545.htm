ait command line parameters

The parameters marked with an asterisk ('*') are simply passed on to d2wfor every pattern in the global configuration file.

  • -a <temp_dir>(optional)*: Specifies the name of an alternative directory for temporary files created by d2w. By default, this directory is /tmp. If two ait calls are executed in parallel, they should use different directories for their temporary files.
  • -b <base_name>: Specifies the name (without extension) for all input and output files for which no override has been defined with one of the more specific file parameters. The parameter is mandatory for most of these files.
  • -c <in_config_name>: Specifies the name of an input version of the global configuration file. -c overrides -b and -i. The parameter is mandatory if neither -b nor -i is specified.
  • -C <out_config_name>: Specifies the name of an output version of the global configuration file. -C overrides -b and -o. The parameter is mandatory if neither -b nor -o is specified.
  • -d <ASCII_timing_file>: Specifies the name of an ASCII timing file. -d overrides -b and -i. The parameter is mandatory if neither -b nor -i is specified.
  • -F[<flags_1>]A[<flags_2>] (optional)*: This flag causes the timing translation to specify the actions in the full, unabbreviated format within the wavetable. If it is omitted, the abbreviated format will be used.
  • -F[<flags_1>]c[<flags_2>] (optional)*: This flag causes the timing translation to continue after creation of a timing set has failed.
  • -F[<flags_1>]d[<flags_2>] (optional)*: This flag causes the timing translation to issue additional messages for debugging.
  • -F[<flags_1>]G[<flags_2>] (optional)*: This flag completely suppresses removal of duplicate waveforms. This can be useful if the original ASCII timing is to be recovered from the timing setup file with the b2a tool; see Binary to ASCII Conversion Tool (B2A).
  • -F[<flags_1>]g[<flags_2>] (optional)*: This flag causes the timing translation to resolve pin groups. In the output files, the individual pins will be specified instead of the group.
  • -F[<flags_1>]K[<flags_2>] (optional)*: If the x-mode factor of a pattern is > 1, this flag causes the timing translation to create waveforms also for state character sequences from different ASCII device cycles. It is only effective if no x-mode control file is specified (for the x-mode control file, see The X-Mode Control File (*.cmb)).

    By default, that is, if no x-mode control file is specified and the K flag is not set, the timing translation only considers sequences of state characters belonging to the same ASCII device cycle. If the K flag is set and effective, a waveform is created for a state character sequence if the ASCII device cycle combination of the sequence fulfills the following conditions.

    • All its ASCII device cycles are associated with one and the same pattern.
    • All its ASCII device cycles are connected to the same timing set.
    • Its total length (calculated by adding the ASCII periods of all its elements) equals (a multiple of) the test system cycle length specified in this timing set.
    • None of its initial segments has a length that equals (a multiple of) the test system cycle length specified in this timing set.
    • The number of its elements is not greater than 10.

      The ASCII device cycle combinations that can be selected in the x-mode control file are also characterized by these conditions. For an example, see Figure in Creating Sequences from Several ASCII Device Cycles.

  • -F[<flags_1>]m[<flags_2>] (optional): This flag causes the timing translation to create a STATEMAP section if the wavetable is in the pure physical waveform format. The STATEMAP section serves to display the x-modes within the Pattern Debug tool. The ASCII device cycle name is used as the selector of the STATEMAP section. Note that fractional x-modes are not supported for this option. Note also that the STATEMAP section does not support special characters, so if the dvc file contain any such the conversion is stopped giving the error (example using '_'):

    '_' is not a valid state char, with -Fm (statemap) option. [0..9][a..z][A..Z] allowed.

    For more information on the STATEMAP section, see Representing a pattern in device orientation.
  • -F[<flags_1>]P[<flags_2>] (optional)*: This flag causes the timing translation to create the wavetables in the pure physical waveform format. If it is omitted, the logical waveform format is used.
  • -F[<flags_1>]q[<flags_2>] (optional)*: This flag causes the timing translation to check whether a given state character sequence matches more than one x-mode control file entry. If so, a message is issued. The flag is only effective if the -d flag is also set.
  • -F[<flags_1>]r[<flags_2>] (optional)*: This flag, which is only available for Pin Scale Digital Cards (options -z PS3600 or -z PS800), causes the timing translation to define the physical device cycle names in such a way that fractional x-modes are made visible in the pattern tool. To this purpose, every tester cycle is divided into n segments of equal size, where n is the numerator of the fractional x-mode. The device cycle name also has length n. In this name, every segment that contains the first action of a state character (as defined in the ASCII timing file) will be represented by the respective state character. All other segments will be represented by a dot.

    Suppose, for example, that the only data record for the pin CP in a certain ASCII device cycle is P F10:3 F00:9, and that the ASCII period is 12 ns. If you utilize this ASCII device cycle for a pattern with an x-mode factor of 2/3, the tester cycle length will be 8 ns, and three waveforms will be needed to create the equivalent of the only possible state character sequence PP. If the -r flag is set, then the corresponding 3 waveforms will be represented in the pattern tool as

    P. .P ..

  • -F[<flags_1>]s[<flags_2>] (optional)*: This flag causes the timing translation to use the splitting algorithm instead of the default incremental algorithm.
  • -F[<flags_1>]U[<flags_2>] (optional)*: This flag activates waveform optimization. The generated waveforms are optimized by removing redundant actions, namely, by contracting two consecutive occurrences of the same action into one, and by suppressing masked comparisons (action code X) as well as NOP actions.

    This option is primarily intended to be used with x-mode factors > 1. It serves to reduce the number of required edges (the maximum for the V93000 is 8 drive edges, and 6 receive edges on the P/Ce systems, 8 on the Pin Scale systems), and also the total number of generated waveforms per pin (for the V93000, the maximum is 32 for the P/Ce systems, and 256 for the Pin Scale systems), since different waveforms can become identical by removal of actions.

    Since this flag is passed on to d2w and will be used in all calls of d2w, it will normally be best to specify neither U nor its opposite u, in which case d2w will optimize the waveforms if the x-mode factor is > 1, and perform no optimization if it is 1.

  • -F[<flags_1>]u[<flags_2>] (optional)*: This flag inactivates waveform optimization. Optimization is usually unnecessary for patterns with an x-mode factor 1.

    Since this flag is passed on to d2w and will be used in all calls of d2w, it will normally be best to specify neither u nor its opposite U, in which case d2w will optimize the waveforms if the x-mode factor is > 1, and perform no optimization if it is 1.

  • -F[<flags_1>]v[<flags_2>] (optional)* This flag activates waveform optimization. It is similar to the -FU option, but does not suppress masked comparisons or NOP actions.
  • -F[<flags_1>]x[<flags_2>] (optional)*: This flag causes ait to create the device cycle names within the wavetable from the state character (for x-modes > 1: character sequence) on which the waveform is based. If several state character sequences result in the same waveform, the first such state character sequence is used as the name.
  • -F[<flags_1>]Y[<flags_2>] (optional)*: This flag causes the timing translation to create a timing setup for the HP83000. This can be combined with the z flag in order to make the setup compatible with the V93000.

    If neither Y nor Z is specified, Z is assumed.

  • -F[<flags_1>]y[<flags_2>] (optional)*: This flag causes the timing translation to make a setup for the V93000 compatible with the HP83000. Thus, for example, only six edges will be used.
  • -F[<flags_1>]Z[<flags_2>] (optional)*: This flag causes the timing translation to create a timing setup for the V93000. This can be combined with the y flag in order to make the setup compatible with the HP83000.

    If neither Y nor Z is specified, Z is assumed.

  • -F[<flags_1>]z[<flags_2>] (optional)*: This flag causes the timing translation to make a setup for the HP83000 which is compatible with the V93000. Thus, for example, tri-state actions will be confined to edges 2 and 5.
  • -h (optional): This flag causes aitto display a help file about itself.
  • -i <input_name> (optional): Specifies the name (without extension) for all input files for which no override has been defined with one of the more specific file parameters.-i overrides -b. The parameter is mandatory for most of these files if -b has not been specified. If a timing map file <input_name>.tmf exists, ait will try to expand this file. However, for standard pins this is only possible if no ASCII dvc with the same name and the same period length occurs both in the existing timing map file and in one of the new patterns.
  • -k <x_mode_name> (optional): Specifies the name of an x-mode control file. -k overrides -b and -i.

    Note that omitting this parameter does not ensure that no x-mode control file is applied. If the -b or -i parameter is specified, and an x-mode control file with this name and the extension *.cmb is present in the input directory, this file will be processed.

  • -M [w|e|t|x|m|s|S|U|o|F] (optional): This parameter defines the granularity of the generated timing, that is, how many wavetables, equation sets, and timing sets the timing translation will create. You can specify one or more of the listed characters.

    By default (if the parameter is omitted), it will try to use only one wavetable, one equation set, and one timing set.

    The possible values of this parameter have the following effects:

    • w: If this value is specified, a separate wavetable, a separate equation set, and therefore also a separate timing set will be created for every ASCII device cycle combination and x-mode factor that is used by a pattern or a pattern group in the global configuration file. -M without any value is equivalent to -Mw.
    • e: If this value is specified, a separate equation set, and therefore also a separate timing set, will be created for every ASCII device cycle combination and x-mode factor that is used by a pattern or a pattern group in the global configuration file.
    • t: If this value is specified, a separate timing set will be created for every ASCII device cycle combination and x-mode factor that is used by a pattern or a pattern group in the global configuration file.

      If timing set changes are allowed for a pattern in the global configuration file (ctim column of the PATTERNS section set to CT), and if more than one ASCII device cycle is associated with it, then setting this value will also cause the creation of different timing sets for each of these ASCII device cycles (that is, even within one pattern).

    • x: If this value is specified, separate wavetables, equation sets, and timing sets will be created for patterns or pattern groups with different x-mode factors.
    • m: This option activates the output columns of the global configuration file as input columns. This allows you to control the set numbers and wavetable names of the created timing setup. For more information see Controlling Set Numbers and Wavetable Names.
    • s: This option suppresses the merging of spec sets.
    • S: By default, the timing translation creates a separate wavetable for every port of a multi-port timing specification. But if S is specified, a single wavetable is generated for all ports of the specification. This can be used, for example, when a multi-port timing is combined with a single-port vector setup, to create a base wavetable for the single-port patterns.
    • U: This option serves to streamline multiport setups with an incomplete multiport burst in the following situation:

      - The global configuration file contains a MULTI_PORT_TIMING and a MULTI_PORT_BURST statement such that the ports of the MULTI_PORT_BURST statement are a subset of the ports in the MULTI_PORT_TIMING statement, and

      - The common ports are defined in the same way in both statements with respect to the CTIM, SEQ_GRPS, and PHASE rows.

      Then the timing translation will assume that MULTI_PORT_BURST is meant to be an incomplete vector setup for the timing setup of the MULTI_PORT_TIMING statement, and will not create a timing specification for the MULTI_PORT_BURST statement.

    • o: This option suppresses certain internal optimization routines related to wavetables. Use it only when turning on the -MU option in connection with multiport timing or bursts results in out-of-wavetable errors or missing specifications.
    • F: If this option is specified, ait creates a master file that links to all generated timing files.

      The first four values of this parameter are partially ordered by strength: w implies e, t, and x; and e implies t. Note, however, that SmarTest as such allows different wavetables to be associated with the same equation set in different specifications (which are distinguished by different spec set numbers). It is a peculiarity of the ASCII interface that it always creates different equation sets for different wavetables.

      Note Under certain conditions ait will create different timing sets for different patterns even if -M is omitted. This is the case if ASCII device cycles with different period lengths are assigned to different patterns, or if the ASCII device cycles that are specified in the PATTERNS section of the *.aic file collectively contain more than 8 different delays of the same kind (drive or receive) for the same pin (6 receive delays for P/C/Ce systems).
  • -o <output_name> (optional): Specifies the name (without extension) for all output files for which no override has been defined with one of the more specific file parameters. -o overrides -b. The parameter is mandatory for all these files if -b has not been specified.
  • -p <pin_config_name> (optional): Specifies a name for the pin configuration file. -p overrides -b and -i, and is itself overriden by the pinconfig_file parameter of theAI_DIR_FILE section of the global configuration file (see The AI_DIR_FILE Section ). The parameter is mandatory if neither -b nor -i is specified, and no pin configuration file is specified in the AI_DIR_FILE section.
  • -T <out_timing_name>: Specifies the name of an output timing setup file. -T overrides -b and -o. The parameter is mandatory if neither -b nor -o is specified.
  • -t <in_timing_name> (optional): Specifies the name of a timing setup file to be expanded. -t overrides -b and -i.

    Note that the timing map files that belong to this timing setup file are not expanded. Rather, one of two things will happen: If a name is specified with the -i parameter, and a timing map file with this name exists, then this file will be expanded. If -i is omitted or no timing map file with this name exists, a new timing map file will be created for the expansion.

  • -V (optional): Causes ait to create only the auxiliary files for the vector translation (vector configuration file, timing map files, pattern configuration files), no timing setup.
  • -X <mux_file> (optional)*: Specifies the name of a pin multiplexing file. -X overrides-b and -i.
  • -x <x_mode_map_file> (optional): Specifies the name of an x-mode mapping file. The ASCII interface will create this file under the specified name. This parameter is only intended for SmarTestPG, not for general usage.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.3.3: Added the s and F options for the -M switch.
  3. SmarTest 7.4.2: Added the PSSL and oe options for the -z switch.
