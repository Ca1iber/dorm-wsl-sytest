GETC? - (GET Cycles)

Note The GETC? query is no longer maintained. Advantest recommends using the GETX? - (GET eXtended vector information) query instead. It provides more parameters and makes the GETC? query redundant.

The GETC? query allows you to determine the cycle number within the Error Map for a logical vector number of the current start label (as set by SQSL).

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Mode of operation

The label must be a main label. If test results are available, the cycle number is calculated from the received data, otherwise from the expected data.

The cycle number can be larger or smaller than the vector number. It can be larger if some of the previous vectors have been executed in a loop (RPTV or RPTJ instruction). It can be smaller if a match loop occurs before the vector, because match loop cycles are not recorded in the Error Map.

Syntax

GETC? {(vector_no)}

returns: 

GETC {(cycle_no)}
Parameters

vector_no

The vector number for which you want to obtain the matching cycle number. vector_no must be a positive integer that does not exceed the maximum vector address allowed by the system.

cycle_no

The number of the cycle that results when the vector at vector_no is executed. The cycle numbers do not always linearly follow the vector numbers. The relationship between the two depends on the sequencer program. The system returns a cycle_no in the range of 0 to 248.

Application

DC tests of "IDDQ" and "Output DC".

Note The GETC? query is no longer maintained. Advantest recommends to use the GETX? - (GET eXtended vector information) query instead. It provides more parameters and makes the GETC? query redundant.

Errors

An error is generated if:

  • No valid test is enabled.
  • The cycle_no is negative.

Example

> SQPG? ALL,(@)
< SQPG 0,STVA,0,,,(@)
< SQPG 1,STSA,,,,(@)
< SQPG 2,GENV,103,,,(@)
< SQPG 3,GENV,7,,,(@)
< SQPG 4,MACT,256,,,(@)
< SQPG 5,GENV,1,,,(@)
< SQPG 6,MRPT,1,,,(@)
< SQPG 7,RPTV,1544,100,,(@)
< SQPG 8,GENV,1,,,(@)
< SQPG 9,STOP,,,,(@)
> GETC? 112
< GETC 104 
> GETC? 1656
< GETC 154504

In this example, the cycle numbers are calculated from the expected values. Vector 112 is the first vector after the match loop. The last 6 vectors before the match loop are not recorded in the Error Map, because the sequencers consider them to be part of the match loop (see Counted match loops). The two match loop vectors proper are also not recorded in the Error Map. Since no other loop has occurred before vector 112, the cycle number corresponding to vector 112 is calculated as 112 - 8 = 104.

The cycle number of vector 1656, the last vector of the label, is calculated as 104 + 100 * 1544 = 154504.

The calculation is more complicated if it is based on the received data, because the last match loop cycles may be recorded in the Error Map (see again Counted match loops).
