Guidelines of using concurrent test framework

When using concurrent test framework, the following points need to be considered.

  • Set up digital pins with multi-ports. Digital pins that belong to a certain IP block of the device are usually defined in one port dedicated to the IP block. This also applies for digital trigger pins of analog and RF instruments.
  • Set up the primary label of a test suite in a CCF block as multi-port burst label even if only one label is needed for this test suite.
  • All port burst in the multi-port burst label of a test suite must have the same length in time. This is important when other test suites of the same CCF block use the same ports.
  • Do not program the analog set name and RF definition name as hard-coded in the test method. Retrieve the value through the API CCTgetAnalogRFSetName.
  • Looped test executions within test method are not supported on the synchronous sequencer because this means multiple start and stop of sequencers.
  • Implement the test with smartCalc whenever possible. You need to enable smartCalc manually because it is not enabled by default.
  • To run the concurrent test in production mode, you need to run it in development mode first to generate the multi-port burst label. To use the generated multi-port burst label for future execution in production mode, you need to save it explicitly.
  • Use a FLUSH() at the end of the Analog setup to write the setup from cache to hardware.
  • The master clock of the Analog and RF setup blocks must match. You can set the clock mode to MCLK_FIXED for the analog setup to avoid unintended clock reprogramming which could lead to an unexpected sample rate.
  • Only one digital capture for each port can be used for the concurrent test framework execution. It must be the first label in the multiport burst label.

Functional changes

  1. Introduced in SmarTest 6.5.4
  2. SmarTest 7.1.4: Supports analog sets defined in the analog setup file in TML 2.1.6
