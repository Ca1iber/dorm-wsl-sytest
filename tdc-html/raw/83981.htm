Logging GDRs from the application model

You can log information to STDF from the application model, by using the EXEC_INP_CALL FormatToGDE. FormatToGDE logs a Generic Data Event to the SmarTest data collection file, which is then recognized by the data formatter and logged as a GDR to the STDF file.

FormatToGDE can log string, integer, or double data types to a GDR. The syntax for FormatToGDE is:

FormatToGDE <data type identifier><data character separator><data>

Where <data type identifier> can be s (string), i (integer), d (double) or f (float). The <data character separator> is a user-specified character that separates different data types. A data character separator can be any non-alphabetic character that is not used in the data. The characters # & | and * are examples of recommended character separators.

As an example, if you wish to log string and integer data that are separated by a "|" to a GDR, the EXEC_INP_CALL in the application model looks like this:

EXEC_INP_CALL(FormatToGDE s|i String to log to GDR|9876);

In this example, "s|i" specifies that the first data parameter is a string type, and a | separates the string type from the second data type which is an integer. "String to log to GDR" is the string data and 9876 is the integer data.

Note The EXEC_INP_CALL must be made in the ACTIONS section of an application model level.

Each instance of FormatToGDE from the application model will log one GDR to the STDF file. If multiple data types are included as parameters of a single FormatToGDE call, as shown in the example above, the GDR will contain multiple data fields.

The resultant GDR record from the example EXEC_INP_CALL above will be:

GDR Record
   FLD_CNT:    5
   Field # 1:  U1:  0xF0
   Field # 2:  U1:  0x0
   Field # 3:  Cn:  String to log to GDR
   Field # 4:  PAD Field
   Field # 5:  I4:  9876
Note See the GDR record description for more information on the PAD field.

If the application model EXEC_INP_CALL to log the GDR occurs before an STDF file has been opened, the GDR will be written after the initial STDF record sequence. Otherwise, the GDR will be written to the STDF file in the order that the EXEC_INP_CALL was made in the application model.

To use the FormatToGDE call from a test program's application model, you must do the following:

  1. Copy the /opt/hp93000/soc/formatter/dataformatter/app_model_data_lib/gde_exec_input.c file to the exec_input directory of the test program for which you wish to use this.
  2. Recompile the exec_input directory by typing make.

Functional changes

  1. Introduced before SmarTest 6.3.2
