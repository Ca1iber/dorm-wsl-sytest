Technology file for a device

The .technology file defines the source directory for technology-related settings, some device specific system parameters and some maximum values for certain system parameters.

The maximum values for certain system parameters determine the amount of memory reserved for the respective data structures. The absolute maximum values are not automatically used so that memory usage can reflect the actual requirements of the device. Since the available memory is limited it is possible that one or more otherwise valid settings are reduced by the firmware in order to remain within the memory limits, see The Testflow Analyzer Tool and Optimizing the technology file. See also Result areas for error map data.

Each device directory contains a .technology file. A sample file follows:

/dev_tech/cmos
device_cycles: 256
waveform_sets: 16
timing_sets: 256
level_sets: 32
dps_sets: 32
pdc_sets: 1
m_sets: 1024
period_res_precision: 9
testpoints: 10000
utility_lines_per_pogoblock: 16
tester_model: act
licensing_file: 
init_vectors_with_value: 50
fast_transfer_buffer_size: 131072

Changing the .technolog file

The .technology file is normally updated by making changes in the Change Device dialog (on the menu, select 93000 > Change Device). Changes made in this window are saved in the .technology file and communicated immediately to the firmware using the DSCP (Define System Control Parameter) and other firmware commands. These changes are permanent and apply each time the device is selected thereafter.

The parameters that are not present in the Change Device window can be changed permanently only by editing the .technology file directly. In this case, the DSCP command must be issued manually to define the new values to the firmware, or the device must be re-selected (which will reissue the DSCP command).

The concepts related to each of the parameters are documented in more detail in the Command Reference guide.

Parameters of the .technology file

The table below describes the parameters in detail. The following values are defined:

  • Short description: Short description of the parameter
  • Values: List or range of supported values, default value
  • Change Device wizard: The corresponding field of the Edit Device page.
  • DSCP command: The corresponding parameter of command DSCP in the Command Reference manual
  • Note: A more detailed description of the parameter, rules and hints

/dev_tech/cmos or /dev_tech/ecl
Short description: Technology directory
Values: n/a
Change Device wizard: Device technology
DSCP command: n/a
Note:

Defines the technology of the device by pointing to the corresponding directory structure (cmos or ecl) within the test system software data files.

The specific technology is given in the New device dialog. The technology-related level and other data for the device are stored in the subdirectories within the device directory. This subdirectory structure is initialized from the corresponding dev_tech directory when the device is created.

Default levels are defined by the selected device technology. These default levels can be customized to meet the needs of your device. For more information, refer to Default levels file for a device.

digital_default_result_area_size
Short description: Size of the result area
Values: Default: 0
Maximum: 134217728
Change Device wizard: Result Area Size
DSCP command: n/a
Note:

User defined size of the error map if the error map is located in the external (vector) memory. The unit is bytes. The space is reserved at load time. This can prevent the problem that not enough memory is available at run time. See also Result areas for error map data.

If, for example, you want to reserve 16 MB, you can set the digital_default_result_area_size to 16 [MB] x 1048576 [bytes / MB] = 16777216 [bytes]. You can use the DMAS? MFRE query to determine the available memory.

Some more hints to consider:

  • The area is reserved on every digital pin (but not on DPS pins or DC Scale pins configured for the PMU or DPS operating mode).
  • The area is not used for Hidden upload.
  • Recording stops in case recorded data exceeds the size of the reserved area. Uploading cycles beyond the end of the recorded data will result in an error.
  • The reserved area counts against the license limit.
  • Conversion from bytes to vectors: One byte is one vector.

enforce_smart_scale_dc_sync_compatibility
Short description: Function to generate FW commands for DC measurements compatible with the EXA Scale digital cards on Smart Scale digital cards.
Supported values: on | off (default)
Change Device wizard: SmartScale enforce DC sync compatibility
DSCP command: n/a
Note:

This is an option to generate EXA Scale digital cards compatible FW commands for DC measurement on Smart Scale digital cards, for example the PS1600.

When ON, the SYNC action is generated just after the ACTI, PMUM, VMUM, DVM1, or DVM2 action for each measurement set. This allows simulation of an EXA Scale digital card DC set memory consumption, and simplifies the alignment of DC measurements on all the supported digital cards for, for example, running test programs with pattern-controlled, and synchronized, DC measurements on different systems with PS1600 or PS5000.

When OFF, the SYNC action is not generated.

For more information on SYNC, please refer to MSET, MSET? - (definition of Measurement SET).

fast_transfer_buffer_size
Short description:

Defines the buffer for modification of

  • vector data with the VEC_TRANSFER_TASK API,
  • level specs with the LEV_TRANSFER_TASK API, and
  • PPMU settings with the PPMU_SETTING API.
Note The VEC_TRANSFER_TASK and LEV_TRANSFER_TASK APIs can be used only with SmartScale test head cards.
Values:

Default value: 0

Other values are restricted to the range of 131072 ... 16777216 bytes.

Note

  • For SmarTest ≥ 7.4.3.0:

    fast_transfer_buffer_size ≥ blockSize * (number of digital pins specified in VEC_TRANSFER_TASK() * number of configured sites)

    The value of the fast_transfer_buffer_size must greater than the largest used VTT (transfer) size multiplied by the number of configured (DPS and digital) channels.

    For example, if the largest vector update operation is 128 bytes, and a device is configured with 100 digital and DPS channels for each of 16 sites (a total of 1600 channels), the fast_transfer_buffer_size must be at least 128 x 1600 = 204800 bytes.

    To avoid problems when increasing the site count (for example, going from single or dual site to octal or higher production testing), it is recommended to calculate the buffer size assuming a minimum of 2000 channels (If the actual channel count is higher, the actual higher count should be used as a minimum).

  • For SmarTest < 7.4.3.0:

    fast_transfer_buffer_size ≥ blockSize * (number of configured digital and DPS/DC channels across all sites)

  • For SmarTest ≤ 7.4.1.0:

    The specified fast_transfer_buffer_size must be a multiple of 8192 bytes for SmarTest 7.4.1.0 and older versions.

An error message will be issued if the rule that is defined above is violated. You can then either increase the block size or split the vector data transfer into smaller blocks.
Change Device wizard: Fast Transfer Buffer Size
DSCP command: n/a
Note: This buffer will contain the new data for all pins. It will be created on every channel that is associated with one of these pins. The individual channels will then extract their segment of the data from the buffer.

Application note

Memory reserved for testpoints
Some rules must be observed when defining high numbers of testpoints:
  • Unlike other settings, the maximum memory required for the defined testpoints will be reserved at the very beginning of loading a device using commands DTCP, DTCP? - (Define Technology Control Parameters) and *RST - (ReSeT).
  • The memory is reserved on all DC Scale cards that are available in the model file.
  • The maximum memory that is required for all testpoints is reserved no matter if it is used later or not3).
  • The amount of reserved memory depends on the value of testpoints and the card specific structure2) of the testpoints.

CAUTION Ignoring the rules above and defining too much test points may result in memory overflow for the subsequently defined and loaded setups or pattern.

If a memory overflow occurs, the error message "ERROR: Specified set size is too large for memory configuration" will be shown in the UI report window. SmarTest restores the previous setup or the default setup and newly defined settings and pattern are not available.
