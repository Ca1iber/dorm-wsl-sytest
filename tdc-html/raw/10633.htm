Mode contexts

A mode context specifies, for every defined pin, the type (input or output or both) and operating mode. Every test is associated with a mode context, and every execution of the CONF command applies to exactly one mode context.

DEFAULT mode context

The system supplies the mode context DEFAULT. The DEFAULT context is assumed when no user defined mode context is specified. With user defined contexts, all operation modes that are supported on the respective system can be combined within the same context.

User defined mode contexts

User defined mode contexts are created in the pin configuration with the CTXT command. The new context is a copy of the DEFAULT context, which then can be modified with the CONF command. You can define more than one context for the same pin configuration.

Selection of mode context in levels, timing and vector setup

Which of these contexts is to be used in a test, must be specified separately for the level, the timing and the vector setup. The selected context must be the same for all setup components. It is up to the user to ensure that this condition is met. You can retrieve the mode context of all setup components or a selected setup component with the GCTX? query.

The mode context for the timing must be specified in both the wavetable and the equation set, and must of course be identical in both. The mode context of a label (pattern) is defined with the PARA_MCTX attribute of the SQLA command.
