Waiting for device and binning device

The driver waits for a special SRQ (service request) to manage the lot.

The actions are:

  • <lot start> | <lot restart>
  • <wait for device>
  • <lot end> | <final lot end>

Message from driver

Message from handler

Description

Lot start | <lot restart> :

The only difference between lot start and lot restart in the communication flow is the SRQ value.

If you want to use the lot management sequence, call ph_lot_start() and ph_lot_done() in the application model file.

 

0xC0

The handler sends the special SRQ.

SRQKIND?

 

The driver asks for the SRQ kind.

 

SRQKIND 02 | SRQKINGD 04

The handler returns a lot start or lot restart signal.

LOTORDER 0

 

The driver replies to the lot start request from the handler.

FULLSITES?

 

The driver asks for device set conditions of the contactor.

 

FULLSITES n

The handler returns device set conditions of the contactor.

Wait for device:

This action repeats until there is a device to test.

If the application model file only calls ph_device_start(), this sequence replaces the lot start | lotrestart, and the lot end | final lot end sequence will not be executed.

 

0x41

The handler sends test start.

FULLSITES?

 

The driver asks for device set conditions of the contactor.

 

FULLSITES n

The handler returns device set conditions of the contactor.

Lot end:

 

 

 

0xC0

The handler sends the special SRQ.

SRQKIND?

 

The driver asks for the SRQ type.

 

SRQKIND 08

The handler returns a lot end signal.

LOTRETESTCLEAR?

 

The driver clears all operation data (lot data).

 

LOTRETESTCLEAR | SETTINGNG

When the data has been correctly cleared, the handler sends LOTCLEARED.

When the data has not been cleared, the handler sends SETTINGNG.

LOTORDER 2

 

The driver replies to the lot end request sent from the handler.

Final lot end:

If there are no devices to retest, the driver will send the final lot end instead of the lot end signal to the handler.

 

0xC0

The handler sends the special SRQ.

SRQKIND?

 

The driver asks for the SRQ type.

 

SRQKIND 10

The handler returns the final lot end signal.

LOTORDER 2

 

The driver replies to the final lot end request from the handler.

Bin device

The driver sends the result of the device test of each contactor to the handler. The driver requests the handler to echo back the result.

The binning command format is defined by the driver configuration. The handler expects different GPIB command formats for 16-bin or 32-bin configurations.

Message from driver

Message from handler

Description

BINON: n

 

 

If the value n is a 16-bin format, it represents 'xxxxxxxx,xxxxxxxx,xxxxxxxx,xxxxxxxx'.

If the value n is a 32-bin format. it represents 'x,x,x,x,x,x,x,x'.

For both values:

  • The bits, from the least significant bit, correspond to contactor No.1, 2, 3...
  • The number of n is the number of devices tested in parallel.

For 16-bin values:

  • The n shows the test result. (n = 0 to 9 and A to H)

For 32-bin values:

  • The n shows the test result. (n = 0 to 21 hexadecimal number)

 

ECHO: n

ECHO shows the contents of BINON data received by the handler from the tester. The data format is the same as that of BINON.

ECHOOK | ECHONG

 

When the bin information is the same as the tester has sent, the driver replies ECHOOK, otherwise it replies ECHONG.
