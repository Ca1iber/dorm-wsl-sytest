How to generate and provide a device license file

The testflow analyzer tool (TAT) analyzes the testflow and generates a device license file (.licenses) in the current directory.

Before you begin

Note that some of the optional parameters require a line model encrypted database (smartest_aslmedb*).

Procedures

Default

  1. Start SmarTest in either offline or online mode. We recommend that you start SmarTest in the offline mode, and that you use a model file with full capabilities (full memory, top speed, all features).
  2. Load a testflow, including setups.
  3. Make sure to provide a hardware definition file (HDF).
  4. Enter the following command:

    /opt/hp93000/soc/prod_pws/bin/tat -f <filename>

    -f is a must parameter; <filename> is either the hardware definition file (HDF) or a model file.

    The table below lists all command parameter options:

    -h

    --help

    Lists all parameters with a short description.

    -i

    --info

    Lists a detailed description of all parameters.

    -v

    --version

    Gives version information

    -b

    --verbose

    Switches to verbose mode for trouble shooting

    -f

    --file

    Must-parameter. Specify the file name of either the hardware definition file (HDF), or a model file, or a device license file.

    -o

    --output-directory

    Allows specifying an output directory. Default is the current directory. The target directory must exist, otherwise an error occurs.

    -p

    --pins

    Adds the pin names to the device license file. Pin names help to map the generated licenses to the pins.

    -c

    --commercial-license

    Allows using commercial instead of technical license steps.

    -t

    -ppTia

    Allows specifying pin, port, or group names of pins that require the ppTIA feature.

    -a

    --flow-analyzer-abort

    Aborts the TAT if it cannot connect to a SmarTest session (for example, due to an empty DISPLAY variable).

    -s

    --session

    Allows specifying a SmarTest session to connect to, if multiple sessions exist.

    -d

    --dsl-tag

    Requires a line model encrypted database (smartest_aslmedb*).

    Allows specifying a DSL-tag to be added to the license file.

    This also creates a tagged copy of the pin configuration file in the specified output directory (see -o / --output-directory).

    -e

    --dsl-alternative-tag

    Requires a line model encrypted database (smartest_aslmedb*).

    Allows specifying an alternative DSL-tag to be added to the license file.

    -w

    --protocol-aware

    Activates the protocol-aware license and adds "protocol_aware = on" automatically in the GLOBAL section of the device license file.
    Note The option -t will be ignored for digital cards of Smart Scale family (Pin Scale1600, Pin Scale 9G).

    The generated device license file lists only the minimum needed capabilities for the given testflow.

    You can rename the .license file to reflect different test scenarios, for example, finalTest.license or waferSort.license.

    To provide the device license file for the test system, you must move or copy the file to your device license directory. In order to be read, the device license file must reside in the following directory:

    <device-directory>/license

Alternatives

  1. Alternatively, you can develop your device license files based on an example file or on a model file.
  2. The "example device license file" at /opt/hp93000/soc_<version>/pws/data/per-device-license.def documents the device license file syntax and serves as device license file example.
  3. You may also edit a model file to get a device license file:
  4. Copy the model file to the license directory of the device.
  5. Remove all SECTIONS including their section header that Do not include any license information.
  6. Remove all entries in the remaining sections which Do not have to be licensed (like test head, etc.)
  7. Modify the license requiring entries for your device according to your needs (speed, memory, timing_bundle, etc.)
  8. Add possible hardware alternatives.
