Hidden data logging

Hidden data logging is a feature of the SMC framework that enables event-based data logging in the background.

Results of tests that are executed in the SMC_backgroundProcessing() function of the test method class are usually logged by calling SMC_SYNCHRONIZE(). Typically, SMC_SYNCHRONIZE() is called in one of the last test suites causing delays at the end of the testflow's execution.

In order to optimize event-based data logging with SmartCalc, the TestEventType event type includes two attributes which let you assign a test event to the correct context (test suite and site). This way, the event stream server is able to reconstruct the order of events according to the order of the testflow.

SmarTest handles hidden data logging automatically, once it is enabled by the hidden_datalog_mode testflow flag.

Hidden_datalog_mode options

Value

Description

0

Default.

Turns hidden data logging off.

1

Turns hidden data logging in compatibility mode on.

In this mode, the limits are used that are defined in the SMC_SYNCHRONIZE() test suite.

2

Turns full hidden data logging on, including LIMIT support.

In this mode, the limits are used that are defined by the calling test suite.

This is the recommended mode.
Note Activating the hidden mode (value 1 or 2) may cause missing or unexpected data log entries when you interactively execute test suites based on the SMC framework. We do not recommend to activate hidden data logging for interactive execution.

Difference between mode 1 and 2

Note This differentiation is important only if you use test suite limits.

Mode 1 allows you to stay compatible using test suite limits defined in the SMC_SYNCHRONIZE() test suite.

This is because limits (opposed to TMLimits) are fetched from the test suite. Any SMC_TEST() that refers to test suite limits will be executed within SMC_SYNCHRONIZE(), retrieving its respective limit from that test suite. Thus running mode 1 with test suite limits will not hide data logging.

However, SMC_TEST() calls referencing a LIMIT object or using TMLimits are executed immediately ('hidden'), since they Do not rely on test suite limits.

Mode 2 immediately executes SMC_TEST() calls including those using test suite limits. However, this requires those limits to be defined within the test suite where they are called!

Note If you use tests with test suite limits in mode 1 and have other tests with TMLimits or LIMIT in the same test suite performing multisite tests, the appearance of the data log is not predictable. Therefore it is recommended to use mode 2.

TMLimits within the SMC framework

If you use TMLimits within the SMC framework together with background processing (as described in Four-step SmartCalc implementation), the following rules must be observed:

  • The functions getLimit(), getLimitRef(), and getLimitObj() for retrieving data from the TMLimits table are threadsafe.
  • Ensure that the TMLimits table is loaded into the memory before calling SMC_ARM(), for example:
    tmLimits.load("tmuVerify_limits.csv");
SMC_ARM(XXX);
  • Ensure that all required settings are done before an SMC background process is armed.
CAUTION You must not change or reload a TMLimits table while an SMC background process is armed or running. Violating this rule may result in invalid data or the crash of the test method.

Restrictions with hidden data logging enabled

If you enable the testflow flag hidden_datalog_mode, you cannot use the following APIs

  • SMC_SET_TESTSUITE_NAME()
    Note If you need to use the functionality of the following APIs with hidden data logging, use the corresponding functions of TESTSET.
  • SMC_TEST_TEXT(), use TESTSET.testtext() instead.
  • SMC_SET_HLM_FORMAT(), use TESTSET().hlmFmt() instead.
  • SMC_SET_LLM_FORMAT(), use TESTSET().llmFmt() instead.
  • SMC_SET_RES_FORMAT(), use TESTSET().resFmt() instead.

As noted above, Advantest recommends not to execute SMC-based test suites interactively.

Restrictions with hidden data logging disabled

If hidden data logging is disabled (hidden_datalog_mode=0), some member functions of the TESTSET API are not supported:

  • TESTSET().combineMultiPortTests()
  • TESTSET().hlmFmt()
  • TESTSET().llmFmt()
  • TESTSET().port()
  • TESTSET().resFmt()
  • TESTSET().suppressTestNameLoopCount()
  • TESTSET().testname()
  • TESTSET().testname_default()
  • TESTSET().testtype()
  • TESTSET().testtype_default()
