V93000 Concept of HW Programming

Optimization

Testflows can be optimized. The purpose of optimization is to increase the throughput of a testflow in a production environment where many devices of the same kind are tested

  • successively by repeating a testflow in a loop, or
  • within one testflow execution (multi-site testing),

or both. The main idea for optimizing a testflow loop is to define and download setup data only once, and to reuse them for the following loop repetitions. Multi-site testing is optimized by enabling parallel processing of the different sites and parallel retrieval of global PASS/FAIL results. Production tests should always be optimized.

DC set and measurement set management

Every DC test stores its measurement parameters in a DC set, which is identified by a number. All those DC tests that (can) define a PPMU test use a common pool of DC sets, which are stored in the Sequencer Memory: if the firmware commands they issue specify the same DC set number, they refer to the same object.

SmarTest supplies a mechanism by which the measurement parameters of a DC test are stored only once in the hardware and reused when the testflow is executed in a loop. This mechanism exists in two variants. With the more elementary variant, every DC test in a testflow is associated with a dedicated DC set that contains its measurement parameters.

For more information see DC set management.

Some test method API's provide a more sophisticated approach, by which different DC tests can share information contained in one and the same DC set. This is achieved by implementing the concept of a measurement set. A measurement set corresponds to a task within a DC test. One DC set can contain several measurement sets. Every specific task is stored only once, and this single copy is used by all DC tests that execute this specific task.

For more information see Using DC Sets Economically: DC Sets and Measurement Sets.

Parallel search

Parallel search allows you to execute different searches in parallel. The granularity is per pin and site, that is, the search conditions can be different for different setup pins on the same site, and also for the same setup pin on different sites.

Parallel search stores its search conditions in a search set. The management of search sets is similar to the DC set management.

For more information see Parallel Search and Search Set Management.
