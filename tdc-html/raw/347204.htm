Topic 347204

SmartCalc "Thread per site" and "Common thread"

Subtopics

  1. SmartCalc thread per site example
  2. SmartCalc common thread example

SmartCalc (SMC) uses multi thread capabilities of the system controller for minimizing the test time. Setting up multi threading is supported as separate thread per site or as common thread for all sites that is also known as single thread.

Each call of function SMC_ARM() and the similar functions SMC_ARM_OTHER_TS(), SMC_ARM_FOR_SITES() and SMC_ARM_OTHER_TS_FOR_SITES() creates a new thread. The performed actions of this thread is to be defined by function SMC_backgroundProcessing() of the related test method.

Multi-core CPUs are able to perform several of these threads in parallel. This feature will minimize the test time as long as the overhead for calling functions and the handling of threads does not exceed the time gained by the parallel execution: Each function call and each thread creates some time overhead for preparation and cleanup. The overhead depends also on the ratio of function calls and threads and the number of available CPU cores. The overhead will significantly increase for a thread per site configuration on high-site-count applications with low number of available CPU cores.

The SmartCalc framwork allows therefore defining the background processes in two different ways:

  • The "Thread per site" is armed outside of the ON_FIRST_INVOCATION block.
  • The "Common thread" (or "single thread") is armed inside of the ON_FIRST_INVOCATION block.

Sites assigned by the SmartCalc framework: Site in focus The sites that are assigned depend on the used API:

  • SMC_ARM() and SMC_ARM_OTHER_TS():

    All active sites.

  • SMC_ARM_FOR_SITES() and SMC_ARM_OTHER_TS_FOR_SITES():

    The processed sites are to be defined by mandatory parameter sites.1)
Reading the current site in thread:

The site can be read by SMC_SITE_NUMBER().

SMC_SITE_NUMBER() cannot be used in the common thread.

The transferred list of sites to be processed must therefore be used for site handling.
Site loop in thread: One thread is started per site. No loop over sites is required. A loop over all sites to be processed is to be implemented using a transferred list of sites.
