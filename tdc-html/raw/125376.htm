Transaction level function

At transaction level the DUT results first will be cut into individual transaction sequences before any decoding is applied. Therefore the length of a transaction has to be defined in the transaction specification.

In contrast to the transaction level encoding function here the global function is applied first -if specified. The pin role specific decode function then uses the results of the global decode function.

The transaction level functions have specific access to the state character sequence representing a single transaction and are specific for the transaction type.

Additional allowed parameters are:

  • The transaction specific subsequence of the DUT result (@@)
  • Protocol constants (<constant>)
  • Parameter symbols within the transaction (<parameterName>.<symbolName>)

The following errors may occur due to transaction encoding:

  • The resulting state character sequence does not fit the expected size (sum of all fields' sizes).

Example

The following example will first perform a bitwise AND with all fields of the transaction and the given SCS before that result will be reversed bitwise.

~(@@& "0000000000000001111111111111")

If no decode function is specified the default parameter is applied.
