Topic 118570

Enabling and disabling maintenance operations in APG program file

Maintenance operations (refreshes) can be manually enabled and disabled under program control in the APG program file. This is optional for single refresh maintenance operations but mandatory for multiple refreshes maintenance operations.

For single refresh maintenance operations

Once a single refresh maintenance operation is defined as described in Setting up a maintenance operation, the refresh is automatically enabled when a pattern begins to execute, and disabled when a pattern ends the execution.

To manually disable and enable the refresh during the course of a pattern, insert the following refresh control instructions to your APG program file:

  • REFRESH_CTRL(STOP): Disables the refresh during the course of a pattern.

    When this instruction is executed, single refresh operations are disabled in the test processor until they are re-enabled by a REFRESH_CTRL(START) instruction.

  • REFRESH_CTRL(START): Enables the refresh which is disabled by REFRESH_CTRL(STOP) during the course of a pattern.
    Note The two refresh control instructions above are ignored if there is no singe refresh maintenance operation defined as described in Setting up a maintenance operation.

For multiple refreshes maintenance operations

After a multiple refreshes maintenance operation is defined, as described in Setting up a maintenance operation, all refreshes are disabled initially. To enable and disable any one of the defined refreshes, you must insert the following instructions to your program:

  • REFRESH_CTRL(START, maint_op_ID): Enables the multiple refreshes maintenance operation by enabling the first refresh used in a pattern.

    Use this instruction only when all refreshes are disabled. Otherwise, you will achieve errors when compiling.

    maint_op_ID: The ID of the first refresh used in a pattern. Refresh IDs are listed in the :operation: column of the maintenance operation table in the Device architecture file.

  • REFRESH_CTRL(SWITCH, maint_op_ID, guard_expr): Disables the current refresh and enables another refresh. Once this function is executed, the value of refreshCount() is reset to 0 in order to count the insertions of the new refresh. refreshCount() is described below.

    Do not use this instruction when no refresh is enabled. Otherwise, you will achieve errors when compiling.

    maint_op_ID: The ID of the refresh which you want to enable when you disable the current refresh. Refresh IDs are listed in the :operation: column in the Device architecture file.

    guard_expr: An optional compare expression supports only ==, !=, <=, >=, <, > compare expressions, which is used to set the execution condition and cannot include loop dependent variables.

    • If no guard expression is used in this instruction, the switch action is executed immediately.
    • If a guard expression is present and the expression does not include refreshCount(), the switch action is either executed immediately or ignored depending on whether the result of the expression is true or false.
    • If a guard expression is present and the expression includes refreshCount(), the switch action is executed immediately if the result of the expression is true.

      If the result of the expression is false, the switch action becomes a pending switch action which is delayed to be executed until the result of the expression comes true.

      If any pending switch action exists after a pattern ends, warning messages will be displayed after compiling.

  • REFRESH_CTRL(STOP, guard_expr): Disables the multiple refreshes maintenance operation. Once the multiple refreshes maintenance operation is disabled, the value of refreshCount() is reset to 0.

    guard_expr: An optional compare expression supports only ==, !=, <=, >=, <, > compare expressions, which is used to set the execution condition and cannot include loop dependent variables.

    • If no guard expression is used in this instruction, the multiple refreshes operation is disabled immediately.
    • If a guard expression is present and the expression does not include refreshCount(), the disabling action is either executed immediately or ignored depending on whether the result of the expression is true or false.
    • If a guard expression is present and the expression includes refreshCount(), the multiple refreshes maintenance operation is disabled immediately if the result of the expression is true.

      If the result of the expression is false, the disabling action becomes a pending action which is delayed to disable the multiple refreshes maintenance operation until the result of the expression comes true.

      If any pending disabling action exits after a pattern ends, errors occur when compiling.

  • refreshCount(): Counts how many times a refresh is inserted between the locations of enabling the refresh and using refreshCount() in a pattern.

    refreshCount() is used only by guard_expr in REFRESH_CTRL(SWTCH, maint_op_ID, guard_expr) and REFRESH_CTRL(STOP, guard_expr) to make actions pending . For details, see the description of guard_expr.

    If there are more than one pending action like a number of pending switch actions and pending disabling actions waiting during the course of pattern:

    • Which pending action to be executed first depends on whose guard expression comes true first.
    • If more than one pending action becomes executable simultaneously since their guard expressions all come true at the same time,

      -If these actions switch to the same refresh, or all disable this multiple refreshes operation, MTL executes one action and remove all these pending actions.

      -Otherwise, errors occur when compiling.

      This function:

    • No parameters
    • The value of refreshcount() is 0 when the multiple refreshes maintenance option is disabled.
    • The value of refreshCount() will be reset to 0 as soon as REFRESH_CTRL(SWTCH, maint_op_ID, guard_expr) or REFRESH_CTRL(STOP, guard_expr) is executed.
      Note If there is no multiple refreshes maintenance operation defined as described in Setting up a maintenance operation, all the refresh control instructions above are ignored.

Examples

Example 1

Set up a single dynamic refresh maintenance operation. It is requested to enable and disable the refresh manually in the program.

In the Device architecture file:

:maintenanceOperation:
{
 :name: dynamic_compensated_refresh
 :table:
 {
 :format:
 { :operation: :subroutine: :timerMode: :intervalMode: }
 { maintop_time_a dynamic_refresh dynamic compensated }
 }
}

In the APG pattern file:

...
:maintenanceOperation: dynamic_compensated_refresh
...

In the Timing file:

SPECS
 cycleTime [ns]
 refreshTime [ns]
TIMINGSET 1 "withRefresh
 period = cycleTime
 maintop_time_a = refreshTime
PINS
 ...

In the program file: 

dynamic_refresh()
{
 ...
}
main() 
{
 REFRESH_CTRL(STOP);
 for(i=0;i<loopSize;i++)
 {
 WriteBackground();
 }
 REFRESH_CTRL(START);
 ...
 ...
}

Example 2

Set up a multiple static refreshes maintenance operation.

In the Device architecture file:

:maintenanceOperation:
{
 :name: static_multiple_refreshes
 :table:
 {
 :format:
 { :operation: :subroutine: :timerMode: :intervalMode: }
 { static_maintop_time_a static_routine_a static accumulated }
 { static_maintop_time_b static_routine_b static accumulated }
 }
}

In the APG pattern file:

...
:maintenanceOperation: static_multiple_refreshes
...
...
...
:timing:
{
 :file: "../../../timing/staticRefTest_x6.tim"
 :eqns: "functional-refresh"
 :tims: "standard"
 :spec: "1333-999_32ms"
}
...

In the Timing file:

SPECS
 cycleTime [ns]
 refreshTime_a [ns]
 refreshTime_b [ns]
TIMINGSET 1 "standard"
 period = cycleTime
 static_maintop_time_a = refreshTime_a
 static_maintop_time_b = refreshTime_b
PINS
 ...

In the program file: 

static_routine_a()
{
 ...
}
static_routine_b()
{
 ...
}
main{)
{
 REFRESH_CTRL(START, static_maintop_time_a); //Enable maintenance operation by enabling the static_a refresh
 writeBackground();

 readBackground();

 REFRESH_CTRL(SWITCH, static_maintop_time_b); //Disable static_a and enable static_b, reset refreshCount() to 0.

 readBackgroundB();

 REFRESH_CTRL(SWITCH, static_maintop_time_a, refreshCount()%4 == 0);
 //If the refresh insertion count of static_b is multiple of 4, disable static_b and enable static_a,
 //and reset refreshCount() to 0.
 //If the refresh insertion count of static_b is not multiple of 4, this switch action becomes pending.

 readBackgroundB();
 //If the above switch action has been pending, the static_b refresh is still enabled.
 //Once the static_b refresh insertion count recorded by refreshCount() reaches multiple of 4,
 //this pending switch action will be executed, which disables static_b and enables static_a,
 //and resets refreshCount() to 0.

 REFRESH_CTRL(STOP, refreshCount()%4 == 0);
 //If the refresh insertion count of static_a is multiple of 4, disable maintenance operation immediately.
 //If the refresh insertion count of static_a is not multiple of 4, MTL throws an error here because
 //a pending disabling action exits after a pattern ends.

 // MTL compiler will show a warning if the condition is never met before the pattern ends.

}
