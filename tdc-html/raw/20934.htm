Topic 20934

How to handle the API fatal errors

Subtopics

  1. How to handle the fatal errors with SET_EXCEPTION_HANDLER
  2. How to handle the fatal errors on demand

Basically, the Test Method API is designed so that the internal errors do not occur during runtime. However, they still might occur owing to unforeseen problems. Therefore, even if you design and develop a test method program carefully, you could encounter a warning or error problem during runtime.

There are two error levels for the API-internal runtime error. The following shows the behavior of the program execution and the displayed message types in the report window depending on the error level.

Problem

Program Execution

Report window

Warning

Go to next statement

Warning Message

Error

Aborts the current test method program execution immediately

Error Message

For example, if you request to get a result for unused tester hardware by an API, a "Warning" occurs; the program execution ignores it and goes to the next statement. On the other hand, if you download setting data to malfunctioning tester hardware by an API, an "Error" occurs and program execution is aborted.

This section explains error handling for the "Error" that aborts the program execution, called the fatal error.

There are the following two approaches to error handling:

  • handling the fatal errors with SET_EXECEPTION_HANDLER

    Error handling of the used APIs is prepared before you try to run the program. You can develop test programs with higher reliability by taking all possible prim measures for error handling. However, more program development time might be required with this approach.

  • handling the fatal errors on demand

    Action is taken for the occurred fatal error after you try to run the program. You can respond quickly according to the error, rather than the above approach.
