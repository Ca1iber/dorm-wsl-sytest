Consistency Rules for Set Numbers and Wavetable Names

If you select the wavetable names and the numbers for equation sets, timing sets, and specsets manually, you must take care yourself that your selections are consistent. Inconsistencies can arise within one pattern, but also between two different patterns. Consistency is secured in both cases if you adhere to the following rules.

Rules for wavetables

  • Patterns with different contexts (context column) must be associated with different wavetables.

Rules for equation set numbers

  • If two patterns are associated with different wavetables, then their equation sets must also be different.

    This is a restriction which is peculiar to the ASCII interface. SmarTest does not object to associating different wavetables with the same equation set in different specifications (which are distinguished by different specset numbers).

  • If two patterns are associated with different EQUATIONS sections then their equation set numbers must also be different.

Rules for timing set numbers

The setting of the ctim column imposes the following restrictions on the timing set numbers within one pattern:

  • If the ctim column is omitted or set to NCT for the respective pattern, then all ASCII device cycles of the pattern must be assigned the same timing set number.
  • If the ctim column is set to CT for the respective pattern, then all ASCII device cycles of the pattern must be assigned different timing set numbers.

The following rules hold for two different patterns:

  • If two patterns use the same equation set but different ASCII device cycles, then these ASCII device cycles must be assigned different timing set numbers.
  • If two patterns are associated with the same equation set, but different x-mode factors (xfact column), then they must not assign the same timing set number to the same ASCII device cycle.

Both rules together imply that patterns with the same equation set but different x-mode factors must not have any timing set number in common.

Rules for specset numbers

  • The hp_sps column is coupled to the specs column. You cannot specify a specset number without a SPECS section.
  • If you specify more than one group of SPECS sections for one pattern, each of these groups must be assigned a different specset number.

Relationships between timing set numbers and specset numbers

There are no formal dependencies between timing set numbers and specset numbers. But since the specsets supply the values for the variables that are used in the timing sets, you must take care that the specsets you create fit the timing sets. For example, if you merge two SPECS sections into one specset and the same variable is defined in both sections, then the resulting specset will only contain the second definition. Therefore you cannot use this specset, if you want to apply the values of the first SPECS section to a timing set.

Rules for multi-port specifications

  • Patterns belonging to different ports can be assigned the same wavetable only if the S option of -M is also activated.

    You have two options for the wavetable names of patterns belonging to different ports. If you do not specify S, then you can define wavetable names of your choice for these patterns, but the names must be different for different ports. If you specify S, then the wavetable name you select must be the same for all ports.
