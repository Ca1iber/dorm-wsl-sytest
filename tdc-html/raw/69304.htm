Topic 69304

GPIB communication flow for Delta Design Flex handlers

This section describes the GPIB communication between the driver and the handler.

The table below shows the communication between the driver and the handler. The actions and messages are listed in sequential order.

See Conventions for GPIB communication for descriptions of the syntax.

GPIB communication flow for Delta Design Flex handlers

Message from driver

Message from handler

Comments

init: <id request> <initialization> <configuration>

id request:

identify?

 

Asks for handler ID.

 

"string"

Handler returns ID, for example

Delta Design Flex Handler 6 Wed Dec 01 1999 14:31.

which?

 

Asks for handler name.

 

"string"

Handler returns name and SW version, for example 2904 15.0H 15.0H.

initialization:

sitespacing?

 

Asks handler how many sites it has and how they are spaced.

 

n

Handler returns site spacing code for all known sites.

skillchuck?

 

Asks handler for disabled sites.

 

n

Handler returns 0 (disabled) or 1 (enabled).

verifytest?

 

Asks handler if it is set up in bin verification mode.

 

n

Handler returns 0 (no) or 1 (yes).

categorysource tester

 

Activates tester binning mode.

errorclear!

 

Clears pending GPIB errors.

srqmask 63

 

Sets SRQ mask to report populated sites, jams and GPIB errors.

start!

 

Starts the handler, if not yet started.

configuration: <temperature setup> <verification setup>

These commands are sent at startup and after each driver reconfiguration at runtime.

temperature setup:

Depending on the configuration parameter temp_control, one of the following communication flows applies:

Communication flow when temp_control is set to manual

No commands are sent

Communication flow when temp_control is set to ambient

testtemp atambient

 

Sets handler to ambient mode.

Communication flow when temp_control is set to active

The following commands are sent to the handler for each chamber, where chamber can be either storage, testsite or tcu (temperature unit according to temp_equipment_unit):

chambersetpointn

 

Sets setpoint to given temperature.

chamber lowerguardn

 

Sets lower guardband temperature.

chamberhighguardn

 

Sets upper guardband temperature.

chamberheatn

 

Enables (1) or disables (0) heater.

chambercooln

 

Enables (1) or disables (0) cooler.

 

 

The following commands are sent to the handler once:

soaktime n

 

Sets soaktime in seconds.

testtemp atsetpoint

 

Tests devices at setpoint.

tempcontrol enable

 

Activates temperature control.

verification setup:

verifytestn

 

Activates bin verification (1), if configured with verify_bin_data (set to yes).

Deactivates bin verification (0), if configured with verify_bin_data (set to no).

Note: This command is not sent if verify_bin_data is not configured.

wait for devices: [<SRQ>][<poll>][<status request>]

The driver will either wait for an SRQ or poll for the current site population. If an SRQ was received, polling is still done afterwards in cases where:

Testing is done on more than 4 sites, or

not all sites that are active, based on configuration parameter handler_site_mask, seem to be populated.

This command is repeated until there is a device to test. The driver queries the status regularly if no devices are detected.

SRQ:

 

SRQ

Handler sends test start SRQ.

poll (1-4 sites):

srqbyte?

 

Driver asks for current SRQ status.

 

n

Handler returns SRQ status.

poll (more than 4 sites):

testpartsready?

 

Driver requests current site population.

 

n

Handler returns bit-coded site population.

bin or reprobe devices:

 

 

For all sites:

sbinbin |

 

Driver sends bin information, or

sreprobe

 

Driver sends reprobe request.

querybins?

 

Only if verification mode is active:

Driver asks handler for received bin and reprobe information^^.

 

bin,bin,...

Handler sends bin data back to driver.

releaseparts

 

Driver acknowledges correct binning data (if correct), or starts sending test results from the beginning (max. repeat count: verify_retry_count).

stop handler:

 

 

status?

 

Asks handler for current status.

 

n

Handler returns bit-coded status information.

stop!

 

Stops handler, only if received status was started.

status?

 

Asks handler for status again.

 

n

Handler returns bit-coded status information (should now be stopped).

start handler:

 

 

status?

 

Asks handler for current status.

 

n

Handler returns bit-coded status information.

start!

 

Starts handler, only if received status was stopped.

status?

 

Asks handler for status again.

 

n

Handler returns bit-coded status information (should now be started).

status request:

 

 

status?

 

Asks handler for current status.

 

n

 

Handler returns bit-coded status information.

Query the handler status by PH call ph_get_status. The input parameters used in the ph_get_status are:

"site_mapping"

"temperature_airtemp xxx"

"temperature_cool xxx"

"temperature_desoaktime xxx"

"temperature_heat xxx"

"temperature_lowerguardband xxx"

"temperature_masstemp xxx"

"temperature_setpoint xxx"

"temperature_soaktime xxx"

"temperature_tempcontrol"

"temperature_temperature"

"temperature_tempstatus xxx"

"temperature_testtemp xxx"

"temperature_upperguardband xxx"

 

query site_mapping:

sm?

"string"

Query the site mapping with

ph_site_map=PROB_HND_CALL(ph_get_status site_map).

Query temperature_airtemp:

[storage, testsite, tcu] airtemp?

"string"

Query the air temperature of the specified chamber with

val1=PROB_HND_CALL(ph_get_status temperature_airtemp xxx).

Query temperature_cool:

[sotrage, testsite, tcu] cool?

"string"

Query whether the handler's cooler is On or Off for the specified chamber with

val1=PROB_HND_CALL(ph_get_status temperature_cool xxx).

The return value "1" = On, "0"=Off.

Query temperature_desoaktime:

desoaktime?

"string"

Query the desoak time for the specified chamber with

t_desoaktime=PROB_HND_CALL(ph_egt_status temperature_desoaktime).

Query temperature_heat:

[storage, testsite, tcu] heat?

"string"

Query whether the handler's heater is On or Off, for the specified chamber.

val1=PROB_HND_CALL(ph_get_status temperature_heat xxx).

Query temperature_lowerguardband:

[storage, testsite, tcu] lowerguardband?

"string"

Query the lower guard band for the specified chamber with val1=PROB_HND_CALL(ph_get_status temperature_lowerguardband xxx).

Query temperature_masstemp:

[storage, testsite, tcu] masstemp?

"string"

Query the mass temperature of the specified chamber with val1=PROB_HND_CALL(ph_get_status temperature_lowerguardband xxx).

Query temperature_setpoint:

[storage, testsite, tcu] setpoint?

"string"

Query the temperature setpoint of the specified chamber with val1=PROB_HND_CALL(ph_get_status temperature_setpoint xxx).

Query temperature_soaktime:

[storage, testsite, tcu] soaktime?

"string"

Query the soak time for the specified chamber with val1=PROB_HND_CALL(ph_get_status temperature_soaktime xxx).

Query temperature_tempcontrol:

tempcontrol?

"string"

Query whether the temperature control system is On or Off with val1=PROB_HND_CALL(ph_get_status temperature_tempcontrol).

Query temperature_temperature:

temperature?

"string"

Query the current air and mass temperature for all the enabled chambers with temp=PROB_HND_CALL(ph_get_status temperature_temperature).

Query temperature_tempstatus:

tempstatus?

"string"

Query the 32-bit temperature status word with tempstatus=PROB_HND_CALL(ph_get_status temperature_tempstatus).

Query temperature_testtemp:

testtemp?

"string"

Query the test-at-ambient or test-at-setpoint enable flag with val1=PROB_HND_CALL(ph_get_status temperature_testtemp).

0=at ambient

1=at setpoint

Query temperature_upperguardband:

[storage, testsite, tcu] upperguardband?

"string"

Query the upper guard band for the specified chamber with val1=PROB_HND_CALL(ph_get_status temperature_upperguardband xxx).
