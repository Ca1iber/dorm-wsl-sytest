Four-step SmartCalc implementation

There are four key steps to implement SmartCalc to your test program.

  1. Structure your test program for parallel execution.
    //
// UTM class/test method code for RF Power Measurement
//
virtual void run()
{
    ON_FIRST_INVOCATION_BEGIN();
    {
        //
        // Parallel device setup and test execution
        //
        FOR_EACH_SITE_BEGIN();
        {
            //
            // Get "measParams", digitizer pin name and result handle.
            // Calculation will happen in your SMC_backgroundProcessing() method
            //
            SMC_ARM(measParams, mDgtPin, resultHandle);
        }
        FOR_EACH_SITE_END();
    }
    ON_FIRST_INVOCATION_END();
}
  2. Encapsulate upload, calculation and test statement into your SMC_backgroundProcessing() method.

    You have to write your own public method, that must match exactly the name SMC_backgroundProcessing() for SmartCalc to recognize it. The signature must be identical to the signature of the corresponding SMC_ARM().

    In case different SMC_backgroundProcessing() methods become necessary, they need different signatures.

    public:

void SMC_backgroundProcessing(ARRAY_D& measParams, sting mDgtPin, string resultHandle)
{
    DOUBLE resPower;
    INT    site = SMC_SITE_NUMBER();

    //
    // Hidden upload
    //
    const ARRAY_COMPLEX& cData = SMC_GET_COMPLEX_WAVEFORM(mDgtPin, resultHandle, 1);

    DSP_RF_MOD_POWER(cData,measParams,DBM,site,&resPower);

    SMC_TEST("port","testName",tmLimits,resPower,true);
}
    Note Use multibin to allow SMC_TEST() to bin each thread correctly.
  3. Synchronizing calculations, performing binning and data logging.
    virtual void run()
{
    //
    // Automatically synchronize all the calculation tasks,
    // print data log and do binning
    //
    SMC_SYNCHRONIZE();
}

    To properly synchronize a test flow with the "thread per site" or the "common thread" implementation and also a mixture of both, refer to Synchronize a test flow with any use model in SmartCalc recommendations.

  4. Using SmartCalc APIs for hidden uploads

    Hidden uploads are implicitly triggered by SMC APIs listed in the section Wrapper APIs to control hidden upload in threads of SmartCalc API overview.

    However, hidden uploads can also be triggered explicitly by using SMC_BACKGROUND_ENABLE() and SMC_BACKGROUND_DISABLE().

    These SMC APIs will make sure that uploads are carried out whenever they do not effect the throughput of the test program.

    Note Result areas for the digital capture memory have to be set up when using hidden upload.
