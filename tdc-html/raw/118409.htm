How to set up and execute a PRBS test

The following describes how to set up, execute, and analyze a PRBS (Pseudo-Random Binary Sequence) test in which both the input and the expected output PRBS are generated by SmarTest, on the firmware level.

About this task

Note This task describes how to set up and execute a PRBS test by firmware commands. We recommend using the test method APIs for this task. For a test method example, see PRBS_PINS.

PRBS tests serve to create test patterns automatically. See Generating and checking pseudo random bit sequences for more information.

Procedure

  1. Define the pin configuration:
    Note PRBS tests can only be executed for all pins of a port. Therefore, if you want to execute a PRBS test in parallel with a normal digital test, you must put the digital pins and the PRBS pins into different ports. This holds for both timing and vector ports.
  2. Define a PRBS set:
    1. Create a PRBS set with PRDF.
    2. Define the PRBS test parameters for the appropriate pins with PRCF.

      The parameters are

      • connection polynomial,
      • seed (for generating an input PRBS).
    3. Make the PRBS set the primary such set with PRPR.

      If you do not define a primary PRBS set, a default set will be used.

  3. Define the timing setup:
    • In the wavetable, specify PRBS_I and the required x-mode for the PRBS input pins, and PRBS_O with a (possibly different) x-mode for the output pins. SmarTest will then create the required waveforms automatically. For the input pins, you can also define a break waveform. For more information see Defining the wavetable for a PRBS test.
    • The edges for a PRBS test must distributed equidistantly within the tester cycle. To achieve this, you only need to define the period divider (and possibly a start delay for the first edge) in the timing sets. The period divider must equal the x-mode that is specified in the wavetable. For more information see Defining edge delays for a PRBS test.
  4. Define the vector setup:

    Define a label that contains a PRBS instruction. If you want to delay the start of the PRBS test within this pattern, add break vectors with BRKV before PRBS. Note that BRKV and TMUA are the only instructions that this label is allowed to contain besides PRBS. For more information see Instructions for PRBS and SmartLoop tests.

  5. Make the label the start label with SQSL.
  6. Execute the test with FTST?.

Results

FTST? will return a global P/F result.

What to do next

The Error map does not work for a PRBS test, but you can query the number of errors with ERCT?.
