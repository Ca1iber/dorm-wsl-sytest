PDMM? - (PDps Miscellaneous Measurement)

The PDMM? (PDps Miscellaneous Measurement) query checks that the force line and the sense lines are correctly connected together at the DUT or on the DUT board.

To check if the DPS force and sense wires are correctly connected, the forced voltage is set to 0 V and a small test current is forced on the sense line. The voltage difference between the force line and the sense line is then measured:

  • The measured voltage difference will be about 0 V and a pass result is returned if a connection exists between the force and sense line.
  • If no connection exists, then the test current will cause a higher voltage difference and a fail result is returned.

The query generates a return value for the positive power lines and for the negative power lines. Each return includes a result for the master and each slave DPS.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

The extra parameter PRLT must be specified to get the pass/fail result for all active sites using a PRLT? query.

Syntax

PDMM? [PRLT,] {spec},[averages,] {(pinlist)}

returns: 

PDMM {spec},, [ident], {result}, {(pinlist)}
Parameters
PRLT The extra parameter controls how the measurement is performed.

The value of the parameter can be: PRLT
PRLT specified:
The specified test is performed for all active sites and for all pins that are defined in the pinlist. The command returns individual results only for the site in focus.

The command additionally stores a global pass/fail result for all active sites. The global pass/fail result can be retrieved by a following PRLT? query.
PRLT not specified:
If not specified, the measurement results are returned only for the site in result focus. The command returns individual results for the measurements defined by parameter spec and for the pins defined by pinlist. A following PRLT? query will return an error message.
spec The mandatory parameter defines the test specification that can be:
Fo_Se to check that the force/sense lines are correctly wired on your DUT board. This measurement must be made in disconnected state.
Ma_S1 to check the force connections on the ganging line. The force of master and all forces of slaves must be connected within a resistant of 20 Ω. PASS is returned if pin is not in ganging mode.

Only supported with the DC Scale XPS256 card.
averages

The extra parameter defines the number of averaged measurements to be performed.

The valid range of the integer parameter is 1 … 128.

The default value is 1.
pinlist pinlist must contain the names of DPS previously defined by the DFPS command (and used in DPS operating mode) or the names of DPS previously defined by the DFPN command (and used in PMU operating mode).

See DFPS, DFPS? - (DeFine Power Supply) and DFPN, DFPN? - (DeFine Pin Name) for more information.

If more than one pin is specified, the names must be separated by a comma. The character @ can be used to specify all DPS pins.
ident The identifier is:
POS for positive power lines
NEG for negative power lines
result The result is P (pass), or F (fail) for a Fo_Se specification.

Application

See DC Measurement Commands.

Errors

An error is generated if:

  • A communication error with the DPS occurs.
  • You attempt to use a DPS channel number that does not exist in the system.

For a Fo_Se measurement, an error is generated if the test system is in the connected state, or if the measured values are not in the expected range.

Examples

Example 1: Test of the site in query focus

PDMM? Fo_Se, (@)

returns:

PDMM Fo_Se,,POS,P,(Vee)
PDMM Fo_Se,,NEG,P,(Vee)

This example checks that the force/sense connections on the DUT board are correctly wired for positive and negative lines. For the pin Vee the master channel and the slave channel show a pass for both lines.

Example 2: Test of all active sites

PDMM? PRLT, Fo_Se, (Vcc,Vee)
PRLT? ALL

returns:

PDMM Fo_Se,,POS,P,(Vcc)
PDMM Fo_Se,,NEG,P,(Vcc)
PDMM Fo_Se,,POS,P,(Vee)
PDMM Fo_Se,,NEG,P,(Vee)

PRLT ALL,"PF0P"

The returned pass/fail result of PRLT? presumes that four sites are defined and sites 1, 2, and 4 are active. Sites 1 and 4 have passed the test. Site 2 shows the result for an open force to sense connection.

Example 3: Averaging

PDMM? Fo_Se, 10, (@)

returns:

PDMM Fo_Se,,POS,P,(Vee)
PDMM Fo_Se,,NEG,P,(Vee)

The returned go/no-go results are built from the average of ten measurements to improve the stability of the measurement in noisy environments.

Example 4: Ganging 

PDMM? Ma_Sl,32,(@)
returns:
PDMM Ma_Sl,,POS,P,(Vee1)
PDMM Ma_Sl,,POS,P,(Vee2)

This example checks the master and slave connections for ganged pins with an average of 32 measurements to improve the stability of the measurements in noisy environments.
