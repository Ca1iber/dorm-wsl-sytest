FLEX_UTILITY_PURPOSE_RELAY

This class is a data container holding the settings of utility lines specified with the utility purposes.

In one task of FLEX_RELAY, if you make different settings for a utility line by using the member function of FLEX_UTILITY_PURPOSE multiple times, only the latest setting is downloaded to the hardware when the task is executed.

When you control utility lines, note that the settling time specified in the Pin Configuration window (for the defined utility line names and utility purposes) are not used in the FLEX_RELAY API when the task is executed. Specify a necessary wait time by using the wait() member function of FLEX_RELAY.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/FlexUtilPurposeRelay.h.

Constructor
This class is always called as the subsidiary data container of the FLEX_RELAY, API. Therefore, the FLEX_UTILITY_PURPOSE_RELAY class does not have a public constructor.
Member functions
In this class, the following public member functions are defined:
  • set()

Member function

set()
FLEX_UTILITY_PURPOSE_RELAY& set();

This member function specifies the utility line settings with the utility purposes.

List of parameters
There are no parameters.
Return value
A reference to the FLEX_UTILITY_PURPOSE_RELAY class object.

Behavior when different settings are specified for a utility line by using both utility line name and utility purpose in FLEX_RELAY

In one task of the FLEX_RELAY API, if you make different settings for a utility line by using both the util() and the util_purpose() member functions, the setting specified by util() is selected and is downloaded to the hardware when the task is executed.

This order of priority is same as when both of Routing.util() and Routing.util_purpose() APIs are used.

If you describe the util() statements in conjunction with the util_purpose() statements, the setting of whole utility lines is decided by the following order.

  1. Settings specified with utility purposes (util_purpose()) are sequentially interpreted by the FLEX_RELAY class object.
  2. Then, settings specified with the utility line names (util()) are sequentially interpreted by the FLEX_RELAY class object.
  3. If different settings are specified for a utility line by multiple statements in step 1 and step 2, the setting of the utility line is overwritten by the later setting.
  4. Finally, the whole settings of the utility lines are downloaded to the hardware.

The following example assumes the utility line "UTI101" is controlled by both the lines "B" and "C". 

FLEX_RELAY relay;
relay.util_purpose("group1").set(); // (A) UTI103:OFF, UTI104:OFF
relay.util("relay1").off();         // (B) UTI101:OFF
relay.util_purpose("group2").set(); // (C) UTI101:ON,  UTI102:ON
relay.util("relay2").on();          // (D) UTI105:ON
relay.execute();                    // Download to the hardware

The settings of the statements in the above example are interpreted by FLEX_RELAY class object in the following order:

  1. A (utility purpose "group1"). UTI103:OFF, UTI104:OFF
  2. C (utility purpose "group2"). UTI101:ON, UTI102:ON
  3. B (utility name "relay1"). UTI101:OFF
  4. D (utility name "relay2"). UTI105:ON

In this case, the utility purpose setting data of line "C" for "UTI101" is overwritten by the utility line setting data of line "B". Therefore, the following settings are downloaded to the hardware.

UTI101:OFF    UTI102:ON    UTI103:OFF    UTI104:OFF    UTI105:ON
