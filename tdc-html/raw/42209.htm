Topic 42209

Parameter: temp_chambers

Depending on the equipment type, more or less temperature dependent aspects as for example setpoints, guardbands or soaktimes may be defined.

The number depends on the path of material flow (as for example different device locations, heating and cooling devices). To be most flexible, the parameter temp_chambers defines a list of equipment specific, temperature controlled areas (chambers). For a wafer prober the only possible area where you can control the temperature could for example be the "chuck". In case of handlers you can have for example temperature chambers "testsite" or "storage" which are configured for some package handlers. The valid list of the area names depends on the current equipment type (the plug-in). Only the listed areas will be configured by the equipment driver. The number of the areas entered here defines the valid number of entries of all lists of the following temperature control parameters. The position inside the lists are matched to each other. If one of the following temperature parameters is set to a single value (not a list), this value will be applied to all chambers, if applicable. If an equipment type supports more temperature chambers than listed, these additional chambers are not configured by the driver.

Driver default: empty list

Changeable at run-time: yes

Applicable for: handlers and probers, plug-in dependent

Example for probers: temp_chambers: ["chuck"]

Example for handlers: temp_chambers: [ "testsite" "storage"]
