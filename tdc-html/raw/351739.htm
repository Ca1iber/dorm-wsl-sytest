Auto-retest communication flow for Eclipse handlers

The table below describes the GPIB auto-retest commands and queries supported by Eclipse handlers.

See Conventions for GPIB communication for descriptions of the syntax.

See GPIB communication flow for Delta Eclipse handlers for more related communication flow for Eclipse handlers.

Auto-retest communication flow for Eclipse handlers
Message from driver Message from handler Description
Start of a normal lot (first pass):
VERSION? The tester sends the query to the handler.
xxxx x.x.x The handler replies, for example, "Eclipse 0.2.4.10."
FR? The tester asks if the handler is running.
FR n The handler replies, for example, "FR 0."
DL 0 The tester sends the DL 0 command.
SRQMASK FF The tester sends the SRQMASK FF command to mask the status byte.
LOTCLEAR? The tester sends the query to clear the handler lot data.
LOTCLEARED The handler replies the query to indicate that the lot data has be cleared.
INPUTQTY xxxx The test sets a lot quantity to the handler.
SETTINGOK The handler returns that the setting is OK.

The tester polling
SRQKIND? The tester sends the query to obtain the request bit for the special operation for the status byte (serial polling).
SRQKIND 2 The handler replies the query with SRQKIND 2 to indicate bit 1 is set. The bit is the Normal Lot Start Request bit.
LOTORDER 0 The tester replies the SRQKIND 2 with LOTORDER 0 to tell the handler that operations are allowed to start.
FULLSITES? The tester sends the site population query.
Fullsites 00000000 The handler replies the query with Fullsites 00000000.

The tester polling
FULLSITES? The tester sends the site population query.
Fullsites 000007FF The handler replies the query with Fullsites 000007FF.
End of the Normal Lot and Before the Start of Retest Lot (second pass). When Auto Retest Mode is Full:
SRQKIND? The tester sends the query to obtain the request bit for the special operation for the status byte (serial polling).
SRQKIND 8 The handler replies the query with SRQKIND 8 to indicate the Lot End Request.
LOTRETESTCLEAR The tester sends the query to clear lot data on the handler.
LOTRETESTCLEARED The handler replies the query to indicate that all data is cleared.
LOTORDER 2 The tester replies that the lot end has been detected.

The tester polling
SRQKIND? The tester sends the query for running status.
SRQKIND 4 The handler replies the query with SRQKIND 4 to request for the Retest Lot Start.
LOTORDER 0 The tester replies with LOTORDER 0 to tell the handler operations are allowed to start.
FULLSITES? The tester sends the query.
Fullsites 00000000 The handler replies the query with Fullsites 00000000.
The tester polling
FULLSITES? The tester sends the query.
Fullsites 000003bf The handler replies the query Fullsites 000003bf.
End of the Normal Lot and Before the Start of Retest Lot (second pass). When Auto-retest mode is half:
SRQKIND? The tester sends the query to ask for the status.
SRQKIND 8 The handler replies the query with SRQKIND 8 for the Lot End Request.
LOTRETESTCLEAR The tester sends the query to clear the lot data.
LOTRETESTCLEARED The handler replies the query to indicate the lot data has been cleared.
LOTORDER 2 The tester replies with LOTORDER 2 that the lot end has been detected. The handler is in a stop state.
SRQKIND? The tester sends the query to ask for the status.
SRQKIND 4 The handler replies the query to indicate the Retest Lot Start Request.
LOTORDER 0 The tester replies with LOTORDER 0 to tell the handler that operations can start.
FULLSITES? The tester sends the query to ask the site population.
Fullsites 00000000 The handler replies the query.
FULLSITES? The tester sends the query.
Fullsites 000003bf The handler replies the query.
End of Retest Lot:
SRQKIND? The driver sends the query to ask for the status.
SRQKIND 10 The handler replies SRQKIND 10 to indicate the Retest Lot End Request or Final Lot End Request.
LOTORDER 2 The tester replies LOTORDER 2 to tell the handler that the Retest Lot End or Final Lot End Request has been received.

For how to set the auto-retest feature in your application model file, see the Example 2: Auto-retest in Examples: 2D barcode and auto-retest.
