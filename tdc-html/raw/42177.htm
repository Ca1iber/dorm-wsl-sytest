Parameter: waiting_for_lot_timeout

The time in seconds which the driver will wait for the prober to report that a new lot is ready to be tested.

Some probers send out a special signal in this situation. Other probers do not. To synchronize the start of SmarTest and the start of the prober it is necessary for the driver to know, whether the signal has already been sent (and will not occur again) before the test program in SmarTest was started, or whether the driver still has to wait for the lot start signal. In case of a timeout, a message will be generated by the driver, and the action defined by the parameter waiting_for_lot_timeout_action will be taken (see above). If the action is "operator-help", the operator can tell the driver to proceed as if the signal had been received.

The exact implementation of this function is plug-in specific.

Driver default: 120

Changeable at run-time: yes

Applicable for: probers and handlers

Example: waiting_for_lot_timeout: 90
