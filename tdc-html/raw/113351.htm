Topic 113351

Special test suite bin_disconnect

Subtopics

  1. Implementing bin_disconnect to overcome the pass or fail site dependency issue

This section explains how to use the special test suite bin_disconnect to do a flexible disconnect after binning.

Using bin_disconnect is a solution for avoiding the pass or fail site dependency and to deal with the different disconnects of the utility lines within a test flow.

The new recommended solution is the Multibin SmartDisconnect test suite.

Use model

The test suite bin_disconnect (contained in Special test suites) is executed when a device falls into a pass or fail bin.

This special test suite can only be used in combination with a test method that defines a conditional disconnect sequence. In a multi-site testing setup, the sites which are binned out will be activated before calling the test method assigned to the bin_disconnect test suite.

This means:

  • After one device enters into the pass or fail bin, the standard or user-defined disconnect sequence is omitted, and the enabled site number is reduced by 1, then the bin_disconnect test suite is executed. For the last site to be binned, the total enabled site number is 0 before doing the final disconnect.
  • If the bin_disconnect is not used, while binning SmarTest initially executes the standard or user-defined disconnect sequence, and then reduces the enabled site number. For the last site to be binned, the total enabled site number is 1 before doing a disconnect.

Hence, for carrying out a conditional disconnect with the bin_disconnect, you need the following assessment in your test method:

  • If the current number of enabled sites is larger than 0, it means some sites are still connected. Their pins including potential shared (digital) pins should not be disconnected after binning.
  • If the current number of enabled sites is equal to 0, then after the binning action, all the left connected pins should be disconnected including shared (digital) pins.
  • An alternate solution is provided by the test method API GET_DISCONNECT_CONTEXT() which returns the run context of the bin_disconnect test suite.

The bin_disconnect feature allows you to accomplish the task of conditional final disconnect in an easier way than was available till now (no need to insert a test suite before every stop bin as explained in Implementing a conditional final disconnect with disconnect.user_def).

Note If you use SmartCalc, refer to Terminate SmartCalc threads after binning.
