Timing and levels

The STIL timing block and the DCLevels block selected by the active PatternExec block are used to generate V93000 timing and levels, respectively.

Multiple WaveformTables blocks are merged into one V93000 wavetable, but they must share the same period. Each STIL waveform is translated into a V93000 waveform using the physical waveform syntax. Waveform numbering and edge allocation are performed automatically.

Processing multibit waveforms

Multibit waveforms in STIL are fully expanded in the V93000 timing. For each multibit waveform, all possible combinations are generated.

For example, consider this multibit waveform: 

tT { '0ns' L/H[0]; '2.5ns' L/H[1]; }

It is expanded to: 

tt    {'0ns' L; '2.5ns' L; }
tT    {'0ns' L; '2.5ns' H; }
Tt    {'0ns' H; '2.5ns' L; }
TT    {'0ns' H; '2.5ns' H; }

Each new waveform is accessible through a new ID, that is, the tT V93000 waveform matches {'0ns' L; '2.5ns' H; }.

These new IDs are assigned to V93000 physical waveform indexes according to their order of appearance, that is: 

tt:   0
tT:   1
Tt:   2
TT:   3

V93000 wavetable naming algorithm

For non-multiport setups, each wavetable is named based on all STIL waveform tables that are merged into this wavetable. For multiport setups, a wavetable is created for each port and named as above with the addition of the port name. All wavetable names are trimmed to fit SmarTest's maximum wavetable name limit (see also Naming of blocks and elements).

Device cycle naming algorithm

Resource tags serve to define device cycle names for the V93000 wavetable. They can be inserted into the STIL timing If resource tags exist and are enabled (see the ignore_stil_rtags setting in Translation-related STIL Reader setup options). The following example demonstrates the use of resource tags in STIL:

Timing {
   WaveformTable t1 {
     Period '100ns';
     Waveforms {
       clk {
         <T> P { '0ns' D; '25ns' U; '75ns' D; }
       }
       data {
         <0> D { '50ns' D; }
         <1> U { '50ns' U; }
       }
     }
   }
}

When translated to V93000, the wavetable will look as follows:

PINS clk
0 "d1:0 d2:F1N d3:F0N" T

PINS data
0 "d1:0" 0
1 "d1:1" 1

When no resource tags exist, device cycles are named based on STIL waveform characters (WFC).

When multiple waveform tables in the STIL file have the same WFC for a given signal in a single pattern, an index is added to the WFC to arrive at a unique V93000 device cycle name.

Note that you can define V93000 device cycle names also with the dcdf_remapping and the dcdf_signal_remapping settings in Test-processing STIL Reader setup options.
