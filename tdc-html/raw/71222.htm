Topic 71222

Preparing Hardware Response files

Subtopics

  1. ARRAY_X type
  2. DOUBLE type
  3. SpecSearch type
  4. DC API type
  5. FW_TASK type
  6. Pass/Fail type and ERROR_MAP type

Hardware response files are required when debug a testflow or test suite using the emulator.

About this task

To debug a testflow or test suite using the emulator, first, prepare the Hardware response files for all test suites and test method APIs for retrieving data used in the testflow or test suite.

To prepare the hardware response files, set up the emulator and run a testflow using the emulator in Store mode.

Before you begin

Make sure the following prerequisites are met:

  • Connected to a test system
  • Required SmarTest version is activated
  • SmarTest is running. For details, see Starting SmarTest.
  • Required test flow is loaded and Load all Setups has been executed. For details, see Loading a testflow and all setup components.
  • Testflow opened in Flow Sequence Editor: Open with > Flow Sequence Editor. For details, see Flow Sequence Editor.
  • All sites that must be available offline are active.

Procedure

  1. Right-click in the test flow window and choose Run > Open Run Dialog

    The Run Configurations dialog box opens.

  2. Right-click Testflow (Full) and create a new testflow, with the name Testflow (Full_HWRE).
  3. From the tree list on the left, select the testflow Testflow (Full_HWRE), for which the hardware response files are required.
  4. In the Response Emulator pane on the right, select the Enable check box and Store mode.
  5. Click Apply followed by Run to run the testflow.
  6. The Hardware Response Emulator window opens. In the Please Select HW Response Emulator Mode panel, you can see that the Emulator ON (Store) button is selected.
    1. Set the Enable emulating testmethod based test suite results check box according to your requirements:

      ON

      The emulator stores and imports the test suite result data normally. This is the default. In the import mode, the emulator uses previously stored results of test suites based on test methods.

      OFF

      The Emulator does not store and import the test suite result data. That is, when executing in the import mode, the results of the test method-based test suites depend on the details of your programs. For example, if you want to debug your test method programs, you should turn this option off because you need to obtain change of the test suite result by changing your code such as calculation algorithm.

    2. By default, the emulator window also opens when a testflow or test suite is executed with the emulator. This behavior is for confirming or changing the emulator settings before starting tests. If you want to disable this behavior, clear the Display this dialog whenever executing test with emulator checkbox.
  7. Set the hardware response directory:
    1. Accept the suggested path (default), or replace with an alternative if preferred in the Path field. If you enter a name in the HW Response Directory field, a new directory with that name is created.
    2. To add a time stamp to the directory name, check Add Time Stamp. Specify the desired format of the time stamp by entering a format string in the Time Stamp Format field. You can use these placeholders:

      Specifier

      Description

      %Y

      Year (four-digit)

      %y

      Year (last two-digit 00-99)

      %m

      Month (01-12)

      %b

      Month name (abbreviation)

      %B

      Month name (full name)

      %d

      Day (01-31)

      %H

      Hour (00-23)

      %I

      Hour (01-12)

      %p

      AM or PM

      %M

      Minute (00-59)

      %S

      Second (00-59)

      %a

      Day of the week (abbreviation)

      %A

      Day of the week (full name)

      When you use the Hardware Response Emulator in online import mode, if you specify a new directory or a directory that does not contain necessary hardware response data as hardware response directory, the emulator opens a dialog to show the current measurement result retrieved from hardware for supported API in your test method program and ask you to use it instead of the specified hardware response data, because the specified directory has no HW Response data. This is very useful for debugging your programs because it lets you view the current captured results such as captured waveforms, measurement values, and so on.

  8. On the right pane of the Hardware Response Emulator window you find the HW Response Emulator Enable list, which shows all the test suites in the testflow file. By default, all test suites are selected.

    From this list, select the target test suites for which the emulator is to create hardware response files (unselect the suites you do not want to be taken into generation of the HWRE files).

    When the emulator is called for executing the test suite, it creates or imports the hardware response file for the test suite and the test method API called in the test suite.

    The configuration is now complete.

  9. Click OK to close the Hardware Response Emulator window.

    SmarTest automatically starts with the settings specified in the Run Configuration (as shown in the graphic above) and creates the hardware response files.

Results

The hardware response files storing the hardware response data are generated in the specified hardware response directory.
