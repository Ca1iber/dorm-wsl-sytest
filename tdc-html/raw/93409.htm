Debugging a Function

Note that a list of all error messages associated with the Function Command Set is provided in Function Command Set Error Messages.

To debug a function perform the following steps:

  1. Type make debug at the command line in the directory containing the Function Command Set. This creates a debug version of the shared library.
  2. Execute a test program containing a call of the function from the Test Program Explorer. A ddd window will appear. You will see two error messages when the ddd window is opened, which say that ci_function.c and xdb_stop.c do not exist. You can ignore these messages.
    Note When a test program is executed from the Test Program Explorer, all setup data is loaded, including any shared library, so that the ddd window will be opened automatically. If the shared library is loaded manually before execution of the test program, SmarTest will try to load it again when the test program is executed, which will result in an error in the case of a debug version.
  3. Open the source code of the function. This can be done by
    • the menu option File > Open Source, or
    • by typing the function name into the (): field and click the Lookup button, or
    • by entering

      bre <function_name>

      in the debugger console.

  4. Insert a breakpoint at the start of or within the function that you want to debug.
  5. Continue execution of the test program by entering c in the debugger console or clicking Cont in the ddd command tool.

    In both cases program execution will be stopped at the breakpoint you have set.

  6. Debug the function. For details on the ddd debugger see the ddd manual.
  7. After you have finished debugging the function clear all breakpoints and complete the program by entering c in the debugger console.
    Note If the function belongs to a user procedure and you have to kill it, the testflow may hang itself up. In this case, you must also kill the testflow process ftest.
  8. Leave ddd.
  9. Correct your source code.
  10. Repeat steps 1 through 9.
  11. When all errors have been removed, recompile the shared library with make clean all to create a normal version of it.

If the function belongs to a user procedure, you can also debug the function from the testflow or testsuite level, as follows:

  1. Type make debug at the command line in the directory containing the shared library. This creates a debug version of the shared library.
  2. Load the user procedure. A ddd window will appear.
  3. Open the source code of the function with File > Open Source, or type the function name into the (): field and click the Lookup button.
  4. Insert a breakpoint at the start of or within the function that you want to debug.
  5. Execute a testflow which contains a testsuite calling this function, or open the respective testsuite window and execute the testsuite.
    Note When a testflow is executed from the Test Program Explorer or from within the testflow editor, the setup data is not loaded. Therefore the user procedure must be loaded, and the breakpoint set, before execution of the testflow or testsuite.
  6. Continue execution of the testflow or testsuite by entering c in the debugger console or clicking Cont in the ddd command tool.

    Program execution will be stopped at the breakpoint you have set.

  7. Debug the function. For details on the ddd debugger see the ddd manual.
  8. After you have finished debugging the function clear all breakpoints and complete the program by entering c in the debugger console.
    Note If the function belongs to a user procedure and you have to kill it, the testflow editor may hang itself up. In this case, you must also kill the process sf.
  9. Leave ddd.
  10. Correct your source code.
  11. Repeat steps 1 through 10.
  12. When all errors have been removed, recompile the shared library with make clean all to create a normal version of it.
