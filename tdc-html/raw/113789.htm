Concurrent Test Implementation

Concurrent test is highly successful if there is a project plan that test engineering can use for the test development.

The plan should consist of the goal (that is, test time reduction, tester utilization, etc.) and a schedule. It should also specify the cores that will be tested in parallel and the ports required.

Proper implementation is based on effective communication and setting up of the individual test program segments until final integration is possible.

The procedure for successful implementation is:

  • Define the cores needed and set the ports required.
  • Create a pin configuration file consisting of all ports needed.
  • Divide the work into digital, analog, and any other segments required.
  • Build the multi-port programs of the different segments using the common pin configuration file.
  • Test and debug the individual cores as stand alone units.
  • Combine the timing, levels, test methods, and test flow into one program.
  • Verify that all stand alone tests work using multi-port timing that covers all ports. The labels used are of a single port, specific to each core.
  • Combine ports by adding one at a time to a multi-port burst. Know when synchronization is needed. The default for CCT applications is no synchronization settings.
  • Merge test methods by adding code for digital results and data logging into analog test methods.
  • When needed, use the failing path of a multi-port test suite to re-test, for debugging purposes, or sort binning for the individual cores.
