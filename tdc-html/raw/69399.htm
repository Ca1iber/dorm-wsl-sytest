GPIB communication flow for Multitest handlers

This section describes the GPIB communication between the driver and the handler.

The table below shows the communication between the driver and the handler. The actions and messages are listed in sequential order.

See Conventions for GPIB communication for descriptions of the syntax.

APPLIES TO MT93xx HANDLERS ONLY: depending on the configuration parameter temp_control, one of the following communication flows applies:

 

 

temp_control set to "manual": no commands are send to the handler

TEMP OFF

 

temp_control set to "ambient": disable temperature controls

temp_control set to "active": the following command is sent to the handler set setpoint in specified zone to given value in celsius

wait for devices: [<SRQ>] [<poll>]

 

Based on the configuration parameter waiting_for_parts_method, the driver will either wait for an SRQ or poll for the current site population. If an SRQ is received, polling is still done afterwards in cases where:

testing is done on more than 4 sites, or

not all sites that are active based on the configuration parameter handler_site_mask seem to be populated.
