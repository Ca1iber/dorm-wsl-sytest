PMU_VFIM

The PMU_VFIM API accesses a data container for executing a V-force I-measure DC test with the Pin PMU (PPMU).

Note For the PMU of digital cards, it is strongly recommended to use FlexDC APIs for best throughput. This API does not support PS1600.

This API can perform the following:

  • Create a set of measurement conditions for a DC test, as a DC set.
  • Execute the DC test using the measurement conditions.
  • Retrieve the result of the DC test.
    Note This use is not recommended.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PmuVFIM.h.

Constructor

PMU_VFIM()

PMU_VFIM(STRING pinlist, TM::PMU_TYPE type = TM::PPMU);

This constructor defines a DC set which is a set of measurement conditions for V-force I-measure test.

You cannot explicitly create any class object with a user-defined name.

Note The constructor for this API cannot be called inside a FOR_EACH_SITE block.
Parameters

pinlist

Digital pin name or pin group name to be used for the measurement. The valid pin types are i, o and io for the using the PPMU, and i, o, io.

You can specify multiple pins and pin groups by separating with a comma.

"@" specifies all the defined digital channel pins.

type

PMU type to be used in the DC test.

TM::PPMU - (Default) Pin-PMU for digital channel pins.

Member functions

preAction()

PMU_VFIM& preAction(STRING preAct = "NONE");

This member function sets the action to be performed prior to the DC measurement.

Parameters

preAct

Action type to be performed prior to the DC measurement. The following types are available.

"NONE"

(Default) This option defines no pre-action. However, this option activates digital primaries specified on the Testsuite dialog prior to the DC measurement. To activate the primaries specified with the PRIMARY_STATUS API or primary analog set, put the FLUSH API prior to this statement.

"FTST"

Performs a functional test prior to the DC measurement with activating the digital primaries specified in the Testsuite dialog. This option is used to perform a DC measurement with applying a break vector defined in the primary set. To activate the primaries specified with the PRIMARY_STATUS API or primary analog set, put the FLUSH API prior to this statement.

You can retrieve the result of the functional test with the GET_FUNCTIONAL_RESULT() API or TEST API.

"NPRM"

This option defines no pre-action. Also, the primaries are not activated before the DC test.

min_current()

PMU_VFIM& min_current(DOUBLE min);

This member function sets the lower limit current for pass/fail judgment.

The limit value for pass/fail judgment must be set by using this member function or the limits member function. If you use the min_current member function, you must also set an upper limit by using the max_current member function, unless you have executed the limits member function.

Parameter

Lower limit current in [A]

The limit value for pass/fail judgment must be set by using this member function or the limits member function. If you use the max_current member function, you must also set a lower limit by using the min_current member function, unless you have executed the limits member function.

Parameter

Upper limit current in [A]

limits()

PMU_VFIM& limits(STRING testname);
PMU_VFIM& limits(LIMIT limit);

This member function sets the lower and upper limit currents using a test name or LIMIT API's class object.

The limit value for pass/fail judgment must be set by using this member function or the min_current and max_current member functions.

For using the PPMU and/or MCx-PMU, if you use this member function, you may omit either lower or upper limit value (see compare() for details).

Class object name of the LIMIT API.

The available limit current is as follows:

PPMU: -0.04 to 0.04 [A]

mode()

PMU_VFIM& mode(STRING mode = "NR");

This member function specifies the relay control pattern and how to measure multiple pins (serial or parallel measurement).

Generally, you must execute this member function. Otherwise, the measurement will be performed without connecting the PMU to the pogo pin ("NR" mode is set as default).

Parameter

mode

Relay control mode. The following modes are available. For each mode, see Member Functions ("SP" and "BP" modes are not available in this API).

  • "NP" (Non-terminated and parallel measurement)
  • "NS" (Non-terminated and serial measurement)
  • "TP" (Terminated and parallel measurement)
  • "TS" (Terminated and serial measurement)
  • "NR" (Performs measurement without relay control)

settling()

PMU_VFIM& settling(DOUBLE time = 0);

This member function sets the settling time which specifies the time interval between the PMU being programmed and the measurement being performed. The range is 0 to 2 [sec] and is additional to the system internal settling time. If you do not specify settling time, "0" will be used as a default value.

Parameter

time

Settling time in [sec].

preCharge()

PMU_VFIM& preCharge(DOUBLE prec);

This member function sets the pre-charge voltage before the PMU is connected to the DUT pin. After connecting the PMU to the DUT pin, the PPMU immediately forces the specified force voltage at the DUT pin.

This parameter is optional.

The pre-charge voltage parameter prevents sudden current flowing through the DUT when connecting the PMU to the DUT.

Parameter

prec

Pre-charge voltage in [V].

execute()

void execute(TM::DCTEST_MODE mode = GPF);

This member function downloads the DC set to the hardware and executes the DC test. At the end of the test, the PMU is disconnected from the DUT pin (unless the mode() member function sets "NR" mode for the PPMU).

Parameter

mode

Test mode to be selected from the following items.

TM::GPF - Executes a Global Pass/Fail test which records a global pass/fail result of all the pins. The result can be retrieved with the getPassFail() member function.

Without executing the getPassFail() member function, you may execute the TEST API (TEST(PMU_IFVM("pins")) to make the pass/fail result of the DC test as the pass/fail result of the test suite.

TM::PPF - Executes a Per pin Pass/Fail test which records the pass/fail result per pin. The results can be retrieved with the getPassFail(pin) member function. The getPassFail() member function is also executable.

TM::PVAL - Executes a Per pin Value test which records the measured value per pin. The results can be retrieved with the getValue(pin) member function. The getPassFail() or getPassFail(pin) member function is also executable.

For the PPMU, when TM::PVAL is set, the board ADC is used to obtain the measurement value. For the PPMU, the getPassFail() or getPassFail(pin) member function or the TEST API (TEST(PMU_IFVM("pins")) always retrieves the result of the PPMU comparison hardware, and the getValue(pin) member function retrieves the measurement value of the board ADC.

TM::DCTEST_AUTO - Executes the DC test according to the test suite flags.

If the flag Pass value or Fail value is on, the DC test will executes in the same way as the mode TM::PVAL.

If the flag Pass value and Fail value are off, the flag Per pin on pass or Per pin on fail is on, the DC test will executes in the same way as the mode TM::PPF.

If the flag Pass value and Fail value are off, the flag Per pin on pass and Per pin on fail are off, the DC test will executes in the same way as the mode TM::GPF.

For using the MCx-PMU, before a DC test is executed by this member function, the four pins of the unit whose MCx-PMU is used in the DC test must be disconnected. If any of the four pins is connected to the core, an error occurs. To disconnect the pins, use the ROUTING_STATUS API.

Example

  1. For PPMU and GPF judgment:
    :
PMU_VFIM pmuVfim("PIN1,PIN2");
pmuVfim.vForce(100 mV).mode("NP").settling(5 ms);
//use limits() function to set the min/max current 
//by taking the value from the limits defined in the test suite
pmuVfim.limits("limit1").execute();
TEST(pmuVfim); 
 :

    The PMU_VFIM API defines PIN1 and PIN2 to be used for measurement with the PPMU (and/or MCx-PMU), and the member functions set the force voltage, relay control mode and settling time. Then the limits member function specifies limits by using the class object name of the LIMIT API, and the execute member function starts the measurement. Then the TEST API judges a pass/fail result of the testsuite from the global pass/fail result of this measurement.

  2. For PPMU and PVAL retrieval:
    :
DOUBLE rslt1, rslt2;
PMU_VFIM("PIN1, PIN2").vForce(100 mV). settling(5.0 ms);
//use limits() function to set the min/max current 
//by taking the value from the limits defined in the test suite
PMU_VFIM("PIN1, PIN2").limits("limit1").mode("NP"). execute(TM::PVAL);
rslt1 = PMU_VFIM("PIN1, PIN2").getValue("PIN1");
rslt2 = PMU_VFIM("PIN1, PIN2").getValue("PIN2");
 :

    The PMU_VFIM API defines PIN1 and PIN2 to be used for measurement with the PPMU, and the member functions set the force current and settling time. Then the limits member function specifies limits by using the class object name of the LIMIT API, and the mode member function specifies the relay control mode, and the execute member function starts the measurement on per pin value test mode. Then the getValue member function gets the per pin measurement value for pin1 and pin2.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.1.0: The HRTP mode of the measureMode() member function is obsolete.
