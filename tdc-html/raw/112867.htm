Limitations of PMU type DC events

The special nature of DC events with the pmu type results in some limitations regarding their use.

The limitations stem from the fact that every PMU event interrupts the pattern. In addition, a PMU event can take a fairly long time - up to 1.3 ms. Together, these peculiarities result in certain limitations:

  • PMU DC events cannot be part of a DC event sequence.
  • PMU DC events cannot run at the same time as maintenance operations (refreshes). Because they can take a long time, this means that PMU events may delay refreshes for longer than permissible according to the DUT specs.
  • PMU DC events affect all pins of the specified port.
  • When the pins specified for a PMU DC event have different speeds (that is, different x-modes or base rates), PMU events take different amounts of time to execute. There are two ways to handle this:
    • You compensate for the difference in speed by adding break vectors for the faster pins.
    • You stop the test after the DC event or reset the DUT.

      If neither of these solutions is feasible, PMU DC events cannot be used on pins with different speeds.

  • The delay() property of the DC_EVENT function (see Macros and functions in program files) cannot be used with PMU DC events.
  • PMU DC Events can start only on tester cycle boundaries. Padding should be inserted before the event to ensure this.

    Note that the event must start on a tester cycle boundary on all affected pins.
