overwrite_label_wvt

The overwrite_label_wvt flag of the STPM merge rules file lets you specify what happens when STPM can rename the wavetable attribute of a pattern that it adds to the master test program (MTP) to allow reuse of an existing pattern.

Normally, STPM will try to reuse existing wavetables. If it adds a pattern which could reuse another wavetable that already exists in the MTP (instead of the wavetable it uses in the STP), STPM by default overwrites the wavetable attribute in the pattern with the name of the existing wavetable.

This is sometimes not desired; instead, the pattern in the STP and MTP should be completely identical (not just functionally identical, as in the case described above). Setting the overwrite_lable_wvt parameter to ignore results in such fully identical patterns (unless modifications other than the associated wavetable are required).

Syntax

The overwrite_label_wvt flag can be set to allow (default) or ignore:

  • allow

    STPM replaces the wavetable name in the pattern it imports from the STP with the name of a suitable wavetable that already present in the MTP (if such a wavetable exists). A wavetable is considered suitable if the pattern does not need to be modified (except for the replacement of the wavetable name attribute).

  • ignore

    STPM always leaves the name of the wavetable in the imported pattern as is and imports the wavetable.

There is no warning irrespective of the setting of this option. This setting has no effect when additional modifications to the pattern are needed during the import.

Example

This setting makes sure that the wavetable information in imported patterns is not modified:

overwrite_statemap = 'ignore'
