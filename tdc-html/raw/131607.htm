The MTP_LEAKAGE_TASK class provides an API for performing the leakage test for the DUTs with driver sharing. It provides the similar function with the SharedLeakageParallel test method and the SHARED_LEAKAGE_PARALLEL_TEST API but can test different shared, non-shared, and cross-terminated pins which have different measurement conditions within one test method. All tested pins are measured in parallel.

The three methods each have advantages and disadvantages:

  • SharedLeakageParallel test method: A ready-made test method included with MTP.
    • Advantage: Quickest and easiest way to develop a test program with support for logging results. See SharedLeakageParallel syntax.
    • Disadvantage: May not meet any special requirements such as testing more than one group of shared, non-shared, or cross-terminated pins, or a special output format.
  • SHARED_LEAKAGE_PARALLEL_TEST API:
    • Advantage: You can develop your own custom test method, from setting measurement conditions, executing measuring, and logging results.

      Creating a test program is easy because no other APIs are needed to complete a shared leakage test.

    • Disadvantage: The test method based on this API cannot test more than one group of shared, non-shared, or cross-terminated pins.
  • MTP_LEAKAGE_TASK API:
    • Advantage: This is the most flexible method. You can test any number of pins with any types of measurement conditions within one test method.
    • Disadvantage: Results logging is not supported but you can retrieve the results and manually log them.

      Creating a test program is complex because other APIs are needed to complete a shared leakage test, such as CONNECT, FOR_EACH_TEST_BEGIN, FOR_EACH_TEST_BEGIN_WITH_RESET, FOR_EACH_TEST_END, FOR_EACH_SHARED_SITE_BEGIN, FOR_EACH_SHARED_SITE_END, and SHARING_CONFIGURATION.

Note The MTP_LEAKAGE_TASK API is available only for MTP

This API is defined in the header file /opt/93000mts/mts/solution_tools/common/include/MTP_LEAKAGE_TASK.h.

Example

This example tests the leakage for the shared, non-shared, and cross-terminated pins.

Assuming the sharing configuration file (default.cfg) looks like this:

domains: 8
4 3 2 1 ; 5 6 7 8
12 11 10 9 ; 13 14 15 16
utility_control:
leakage;(U2=0x001&0x001)
oc_reset;(U2=0x000&0x400,U2=0x400&0x400,U3=0x000&0xfff,U2=0x000&0x401)
default;(U3=0x000&0xfff,U2=0x000&0x401)

This program performs leakage test:

#include "solution_tools.h"
#include "testmethod.hpp"
#include "mapi.hpp"

class CSharedLeakage: public testmethod::TestMethod
{
protected:
  virtual void run()
  {
    ON_FIRST_INVOCATION_BEGIN();
    {
      // get limits
      LIMIT limit, limit1, limit2;

      // set up for non-shared pins
      mTest.pin("DQ_Bus,DQS_DiffBus")
           .vForce(1.2)
           .limits(limit1);
      // set up for non-shared pin DM
      mTest.pin("DM")
           .vForce(1.2)
           .limits(limit2);
      // set up for cross-terminated pins
       mTest.pin("Clock_Bus")
            .vForce(1.2)
            .limits(limit);
      // set up for shared pins
      mTest.pin("Addr_Bus,Command_Bus")
            .vForce(1.2)
            .limits(limit)
            .prechargeVoltage(1.2)
            .prechargeTime(10);
      mTest.settlingTime(10);

      // connect
      CONNECT();

      FOR_EACH_TEST_BEGIN("default.cfg", "leakage");
      {
        // measurement of leakage
        // It will test in one step.
        // Without utility control setting, it will still test
        // in one step but without utility setting change.
        mTest.execute();
      }
      FOR_EACH_TEST_END();

      // at the end of leakage test, do post execution
      mTest.postExecute();
    }
    ON_FIRST_INVOCATION_END();
  }
private:
  MTP_LEAKAGE_TASK mTest;
};
