Topic 141715

Offline result emulation for TMUs

The parametric ORE (offline result emulation) can also emulate TMU upload tasks and possible errors.

Certain conditions apply when setting up the offline emulation:

  • The name attribute of the measurement tag must be set to the name of a result area that is introduced in the test method code. If the code does not define a result area, the attribute must be set to ''TDC Default Section''.
  • The TMU ORE can emulate uploads of the raw results and calculations of the periods from the raw results. But if you want to emulate the statistical summary of the periods, then you must define the desired statistical values in the code independently from the measurement text file. For more information refer to the TMU measurement offline emulation example below.

The special shot element is used to specify the number of the desired shot. The TMU-related values for the attributes of the value XML element are shown in the table below.

Attribute

Attribute value

Description

id

<arming number>

The id attribute value used to identify arming.

type

MAX

Maximum value of measurement results.

 

MIN

Minimum value of measurement results.

 

MEAN

Average of measurement results.

 

MEDIAN

Median of measurement results.

 

MINMAX

The difference between the minimum and maximum result values.

The MINMAX is same as PP (peak to peak) in TMU firmware.

 

STDEV

Standard deviation of measurement results.

 

ERROR

A code for errors that occurred. See the list of possible errors, below, for details.

The parametric TMU ORE enables you to emulate possible errors of TMU measurements offline. TMU errors have the value ERROR in the type attributes of the value elements. The error value is a sum of two or more enums of the TMU::ERROR _TYPE enums.

Examples

TMU measurement offline emulation example

This example shows a configuration for emulating the upload of the raw results, their periods and their descriptive statistics.

<offlineResultEmulation>
   <pattern name="ORE_testfirst">
     <testSuite name="ORE_test">
       <site number="1">
         <pin name="std_i">
         </pin>
       </site>
     </testSuite>
   </pattern>
   <measurement name="TDC Default Section">
     <testSuite name="ORE_test">
       <site number="1">
        <shot number="2"> 
         <pin name="std_i">
           <value id="1" type="MAX" val="2.345939e-7"/>
           <value id="1" type="MIN" val="2.344164e-7"/>            
           <value id="1" type="MEAN" val="2.3449988e-7"/>
           <value id="1" type="MEDIAN" val="2.34498e-7"/>
           <value id="1" type="MINMAX" val="1.775e-10"/>
           <value id="1" type="STDEV" val="4.2569466e-11"/>
           <waveform id="1" file="/home/hsternbe/devices/offline/ore/sample_values.txt"/>
         </pin>
        </shot>
       </site>
     </testSuite>
   </measurement>
</offlineResultEmulation>

TMU error emulation example

To specify the errors you want to emulate, calculate the sum of the individual error values (in this case, 16+65536= 65552) and provide it as the value of the val attribute.

<offlineResultEmulation>
   <pattern name="ORE_testfirst">
     <testSuite name="ORE_test">
       <site number="1">
         <pin name="std_i">
         </pin>
       </site>
     </testSuite>
   </pattern>
   <measurement name="TDC Default Section">
     <testSuite name="ORE_test">
       <site number="1">
         <pin name="std_i">
           <value id="1" type="ERROR" val="65552"/>
           <waveform id="1" file="/home/hsternbe/devices/offline/ore/testvalues100.txt"/>
         </pin>
        <shot number="2"> 
         <pin name="std_i">
           <waveform id="1" file="/home/hsternbe/devices/offline/ore/testvalues100_shot2.txt"/>
         </pin>
        </shot>
       </site>
     </testSuite>
   </measurement>
</offlineResultEmulation>
