Result areas for error map data

The required space for a result area created to hold error map data (pass/fail cycles) depends on the following parameters:
  • acquire mode (cycle oriented versus failure oriented),
  • range of cycles to record for cycle oriented mode, or the minimum number of fail cycles that must be recorded in acquire fail mode,
  • result mode (x-modes x1, x2, x4, x6 or x8), and results resolution (bits per result).

The following table explains the parameters used in the calculations.

Parameters
128 The 128 bytes are for safety, to avoid alignment issues and to ensure the minimum result area size requirement is reached.

ResultsPerTesterCycle

Given by the x-mode.

BitsPerResult

The resolution of the error code (1 or 2 bits per result)

RecordedTesterCycles

 The range of cycles to record

Cycle oriented mode

In cycle oriented mode, results for all cycles are recorded regardless of whether the compare result is pass or fail.

The number of required bites is given by the following formula.

ResultAreaSizeInBytes = 128 + (ResultsPerTesterCycle * BitsPerResult * RecordedTesterCycles + 7) / 8

If the cycles to be recorded are not at the beginning of the pattern, then additionally the start analyze delay must be programmed, so that error map recording is delayed until the first cycle of interest (see DCRP, DCRP? - (Digital Compare Result Positioning)).

Acquire fail mode - x1, x2, x4, and x8 mode

For this mode the exact area needed cannot be calculated before hand (as we do not know the number of fail cycles), so the upper bound must be used. Since not all cycles are recorded, it is necessary to record the cycle number (tag) of each recording.

There are two relevant upper bounds to consider, depending on whether you expect the failure rate to be high or low.

If fail cycles are rare, then 10.67 bytes are recorded per cycle. (This includes bytes for the cycle tag. The 2/3 are the results of padding bytes.)

ResultAreaSizeInBytes = 128 + RecordedFailCycles * 10.67

However for short patterns with a high failure rate, where effectively the whole pattern is recorded, it is not necessary to record the cycle tag for each failure cycle, and so we can use the calculation from the cycle oriented mode, but with a correction of 5.34/4 (due to extension and padding bytes):

ResultAreaSizeInBytes = 128 + (ResultsPerTesterCycle * BitsPerResult * RecordedTesterCycles + 7) / 8 * (5.34 / 4)

If you know the minimum number of fail cycle you want to record, you can determine the maximum result area needed by calculating both upper bounds described above, and choose the minimum of the two (see example below).

Acquire fail mode - x6 mode

For acquire fail mode, the x6 mode is a special case that requires more memory.

For sparse fail cycles, 16 bytes are recorded per fail cycle:

ResultAreaSizeInBytes = 128 + RecordedFailCycles * 16

If the failure rate is so high that you can neglect the cycle tag recordings however, you need an area of size given by:

ResultAreaSizeInBytes = 128 + (ResultsPerTesterCycle * BitsPerResult * RecordedTesterCycles + 7) / 8 * (5.34 / 4.5)

Examples

Cycle oriented mode example 1

An error map for 40000 cycles is to be recorded, using the x8-1bit result mode:

ResultAreaSizeInBytes = 128 + (8 * 1 * 40000 + 7) / 8 = 40128

Cycle oriented mode example 2

An error map for 40000 cycles is to be recorded, using the x1-1bit result mode:

ResultAreaSizeInBytes = 128 + (1 * 1 * 40000 + 7) / 8 = 5128

Acquire fail mode example - x8 mode

You have a pattern of 100 cycles, and are using the x8-1bit mode.

If you need to ensure you can record at least 100 fail cycles in acquire fail mode, then your two upper bounds are:

ResultAreaSizeInBytes = 128 + 100 * 10.67 = 1195 bytes

and

ResultAreaSizeInBytes = 128 + (8 * 1 * 100 + 7) / 8 * (5.34 / 4) = 262 bytes

So in this case, you need 262 bytes to ensure you record at least the wanted 100 fail cycles.

If however your pattern is instead 40000 cycles, then the second equation reads

ResultAreaSizeInBytes = 128 + (8 * 1 * 40000 + 7) / 8 * (5.34 / 4) = 53529 bytes,

and so you should instead take the other upper bound, and set the result area to 1195 bytes.

Acquire fail mode example - x6 mode

You have a pattern of 100 cycles, and are using the x6-1bit mode.

If you need to ensure you can record at least 100 fail cycles in acquire fail mode, then your two upper bounds are:

ResultAreaSizeInBytes = 128 + 100 * 16 = 1728 bytes

and

ResultAreaSizeInBytes = 128 + (6 * 1 * 100 + 7) / 8 * (5.34 / 4.5) = 218 bytes

So in this case, you need 218 bytes to ensure you record at least the wanted 100 fail cycles.

If however your pattern is instead 40000 cycles, then the second equation reads

ResultAreaSizeInBytes = 128 + (6 * 1 * 40000 + 7) / 8 * (5.34 / 4.5) = 35729 bytes,

and so you should instead take the other upper bound, and set the result area to 1728 bytes.
