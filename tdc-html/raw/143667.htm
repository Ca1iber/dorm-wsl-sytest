Two ways of organizing jitter setup data

The main component of a jitter setup is the jitter waveform. You can either specify these waveforms for a set of pins directly within the jitter set (with the JSCF command), or you can define them in separate modulation sets, which are independent of any pin.

Note that the two waveform definition formats exclude each other within the same jitter set. Since a modulation set defines the same waveform properties as a jitter set, jitter sets that contain a reference to a modulation set cannot contain references to any other waveform property that can be defined with JSCF, so that MODE is the only property that can be directly defined with JSCF in this case.

Thus if the first JSCF command for a jitter set specifies a modulation set, no other property can be defined with the JSCF command for this set except MODE, and if the first JSCF command defines a waveform related property, then the jitter set cannot contain a reference to a modulation set.

Timing modulation sets are defined on the firmware level with the MSDF and MSCF commands.

On the test method level, use the MODULATION_SET_TIMING API. For an example that overlays two modulation waveforms see the description of MODULATION_SET_TIMING.

Example

The following example illustrates the difference between the two setup formats:

> MSCF? "mset1",ALL
< MSCF "mset1",SHAPE,SINE
< MSCF "mset1",PERIOD,200
< MSCF "mset1",PHASE,180
< MSCF "mset1",AMPLITUDE,200
> JSCF? "jset1",ALL,(IN+)
< JSCF "jset1",MODULATION_SETS,"mset1", (IN+)
> JSCF? "jset2",ALL,(IN+)
< JSCF "jset2",WAVEFORM,SINUSOIDAL,(IN+)
< JSCF "jset2",PHASE,200,(IN+)
< JSCF "jset2",PERIOD,200,(IN+)
< JSCF "jset2",AMPLITUDE,200,(IN+)

Jitter set jset1 refers to a modulation set, jset2 defines the same jitter waveform directly.

Functional changes

  1. Introduced in SmarTest 7.3.0
  2. SmarTest 7.3.1: User defined jitter waveforms are now supported for FASTDIFF pins.
