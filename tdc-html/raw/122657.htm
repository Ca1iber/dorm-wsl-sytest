d2s modes

The d2s-framework is an efficient way to do register transactions, like read and write. The d2s-framework provides a learning mode for generating and bursting static patterns and a production mode for executing those burst pattern.

Learning mode

Working with dynamic pattern in learning mode shortens time to market (TTM) neglecting longer execution times.

In leaning mode the register transactions get executed and saved to individual labels on the disk while the burst label gets generated.

The framework generates the static patterns and the burst label in learning mode. The static pattern are created using this naming convention:

d2s_[protocol_class]_[protocol_port_name]_[write|dynamic_write|read|expect_value|wait]_[address]_[data]_[mask]

Note You have to go through all the if-branches of your test program at least once to generate the static patterns and the burst label, while in learning mode.

Production mode

Working with static pattern in production mode shortens execution times, thus it improves time to volume (TTV).

In production mode the predefined static pattern, which are generated automatically in learning mode, are executed as bust. In addition the error map is evaluated and the read values (per site) are cached at d2s_LABEL_END().

Default mode

This mode is automatically set by the d2s-framework for code outside the d2s_LABEL-block.

Note If you use this mode in your code, it will lead to an error. Only use learning and production mode in your d2s_LABEL-block.

Using testflow variables

Setting the modes can be done either manually, by changing the code, or more conveniently by defining a userflag within testflow variables. Each mode is represented by a predefined userflag value:

  • Learning mode is represented by the integer value 1.
  • Production mode is represented by the interger value 2.

However, when using testflow variables, you have to ensure that your testflow (incl. test methods) walks through all if-branches to generate all patterns at least once. If you modify your protocol template, you again have to walk through all if-branches again, which might be hard to remember after some time.
