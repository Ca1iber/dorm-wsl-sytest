Topic 149127

Default GPIB configuration

Some variables are used in the configuration file for Advantest handlers. When the configuration file is created, you must define them in the file. See Creating a New Driver Configuration for more information about how to create a new driver configuration.

The following table lists the variables used in the configuration file. You must define these variables as described.

Aspect

Used settings

handler_family

Advantest, the name of the handler family. It must be defined.

model

The name of a specific handler model within the handler family.

  • R7.2.3 only supports M45 and M48 handler families, including M4871.
  • R7.3.2 starts to support DLT handlers.
  • R7.3.3 starts to support Yushan handlers.

driver_message_log

The location of the driver message log file. The default value is "".

debug_level

The debug level of the driver, -1 to 4, or 9. The default value is 1.

stop_handler_on_smartest_pause

Stop the handler or not when SmarTest is paused, the default value is no.

interface_type

gpib, the handler interface type. It must be defined and has no default value.

symbolic_interface_name

hpib, the name of the interface device. It must be defined and has no default value.

gpib_port

22, the GPIB port number of the prober or handler.

handler_site_ids

The names of the handler sites, which must be defined and has no default value.

handler_site_mask

Mask of active handler sites, entries can be 0 or 1, and the default value is [ 1 1 1 ... ].

smartest_site_to_handler_site_map

Mapping of SmarTest sites to handler sites, entries are >= 1, the default value is [ 1 2 3 ... ].

bin_mapping

Method of SmarTest to handler bin mapping. Supported values are default, mapped-hardbins, or mapped-softbins.

  • default

    This is the easiest way to specify the device binning. SmarTest's hardbin numbers are used to map SmarTest bins to handler bins in a straight one-to-one mode.

    The SmarTest bin with hardbin number 0 is mapped to the first handler bin, the SmarTest bin with hardbin number 1 is mapped to the second handler bin, and so on. There are no further parameters to be set.

  • mapped-hardbins

    This setting allows you to assign SmarTest bins to handler bins, either individually or in group. The hardbin numbers of the SmarTest bins are used for bin identification.

    To use this feature, the parameters handler_bin_ids and hardbin_to_handler_bin_map must be defined.

  • mapped-softbins

    This setting allows you to assign SmarTest bins to handler bins, either individually or in group. The softbin codes of the SmarTest bins are used for bin identification.

    To use this feature, the parameters handler_bin_ids and softbin_to_handler_bin_map must be defined.

    See Configuration Parameters for Binning Management for more bin management information.

advantest_binning_command_format

For the Advantest handlers, it defines the binning command format to be used by the driver.

The Advantest handlers support different GPIB command formats for 16-bin and 32-bin configurations.

For the default bin_mapping, the value must be either 16-bin or 32-bin.

For mapped-hardbins and mapped-softbins, the value must match the bin number defined by the handler_bin_ids.

waiting_for_parts_method

How to wait for test-start signals on the GPIB port, polling or interrupt. The default value is interrupt.

srq_mask

The mask bits of the status byte. The default value is FF.

thermal_alarm_srq_list

The thermal alarm SRQ list, It must be defined and has no default value.
