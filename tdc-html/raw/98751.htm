SQSL, SQSL? - (SeQuencer Start Label)

The SQSL (SeQuencer Start Label) command activates an existing label for execution with the FTST? query. A label exists if it has been defined by the SQLB command. If no start label is defined, FTST? issues an error message. The SQSL? query returns the existing start label settings.

Only labels of the types MAIN, BRST (burst), and MPBU (multiport burst) can be activated with SQSL. For labels with type MAIN this is only possible if the label is associated with the default port @, which contains all pins.

Site specific start labels

Under certain conditions, different sites can be associated with different start labels, that is, the start labels for the different sites are independent of each other ("label per site"). These conditions are:

  • The same port set must be used for all sites, and these ports must be grouped by the same sequencing groups in the same way on all sites.
  • If all sites are to be started synchronously, the different labels must contain the same number of CTIM or CLEV instructions.

    The synchronous or asynchronous start of different sites for the same pin is controlled with the site match function. For details see the STME command.

  • Digital capture is not allowed.
  • Protocol-aware tests cannot be executed.
    Note If two or more sites connect the same pin to the same channel (have a "shared pin"), and these sites are not all associated with the same start label, the different labels cannot be carried out simultaneously on the shared pin. In this case, the default behavior of SmarTest is to execute on this pin the label that is associated with the highest numbered active site. You can change this default with the assignPinToCurrentSite() member function of the PRIMARY_STATUS TM API.

Note also that only the start label can be site specific. Different primary sets (defined with SPRM) or different result configurations for different sites are not supported by SmarTest.

The SQSL command disregards the setup focus (which is defined with PSFC): If you call it without the site parameter, then the specified label will be made the start label for all sites, regardless of any restrictions imposed with PSFC.

In contrast to the command, the query does take the query focus (defined with PSFC) into account. If you do not explicitly request the start labels for all sites, SQSL? will return the start label of the site that currently has the query focus.

SQSL

SQSL  {"label"} [, site|"site_string"]

SQSL?

SQSL?

returns:

SQSL {"label"}

With the TYPE option:

SQSL?TYPE

returns:

SQSL {"label"}, {type}, {(portlist)}

With the ALL option:

SQSL?ALL

returns: 

SQSL {"label"}, {"site_string"}, {type}, {(portlist)}
Parameters

label

The name of a sequencer start label. In the command, you can enter an empty string ("") to deactivate the current start label.

site|"site_string"

In the command, you can either specify a number to identify a single site, or a string of 1's and 0's. The length of the string must correspond to the number of the configured sites. The nth character of this string stands for site n.

"1" means that the specified label is to be assigned as the new start label to the respective site, "0" means that the current start label is not changed.

If you omit this parameter, the specified label will be made the start label of all sites.

When ALL was specified in the query, a site string is returned.

TYPE

If you issue SQSL? without any parameter, the query will return the name of the current start label for the site that has the query focus. If you add TYPE, not only the name, but also the type and the associated ports of this label will be returned.

ALL

If you specify this keyword in the query, SQSL? will return the start labels of all sites, including their type and associated ports.

type

The type of the label. For an explanation of the possible types, see the SQLB command.

portlist

This can be the default port @ which comprises all configured pins, or, in the case of a multi-port burst, the ports with which the label is associated.

Application

Runtime command.

Errors

An error is generated if:

  • The specified label has not previously been defined
  • A channel is shared between several sites.

Examples

Example 1

> SQSL "test_1"
> SQSL? TYPE
< SQSL "test_1",MAIN,(@)

Example 2

> PSFC 2
> SQSL "test_1"
> SQSL? ALL
< SQSL "test_1","11",MAIN,(@)
> SQSL "test_2", "10"
> SQSL "test_3", 2
> SQSL? ALL
< SQSL "test_2","10",MAIN,(@)
< SQSL "test_3","01",MAIN,(@)
> SQSL?
< SQSL "test_2"
> PQFC 2
> SQSL?
< SQSL "test_3"

This example illustrates the definition of different start labels for different sites. Note that the restriction of the setup focus has no influence on the command, but that the setting of the query focus does affect SQSL?.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 6.5.0: Site specific start labels are now supported under certain conditions.
