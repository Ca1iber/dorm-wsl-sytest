Parameter: bin_mapping

This parameter selects one of the different ways the driver can map SmarTest bins to equipment bins:

  • "default"
  • "mapped-hardbins"
  • "mapped-softbins"

Whenever a device is binned to a specific SmarTest bin, the equipment will receive the mapped bin code for this device.

Depending on the mapping selected, more or less additional parameters must be set, as described below.

"default" is a straightforward way to specify the device binning. SmarTest's hardware bin numbers are used for a mapping of SmarTest bins to equipment bins in a straight one to one fashion: The SmarTest bin with hardware bin number 0 is mapped to the first equipment bin, the SmarTest bin with harbin number 1 is mapped to the second equipment bin, and so on.

There are no further parameters to be set.

Note The "default" bin mapping is different from the default bin mapping of the earlier provided Universal TTL Driver, which maps SmarTest bin 1 to the first equipment bin, and so on. If desired, you can define your own bin map, as described below, which does the bin mapping according to your requirements.

"mapped-hardbins" provides a method to assign (groups of) SmarTest bins to (groups of) equipment bins. The hardware bin numbers of the SmarTest bins are used for bin identification.

To use this feature, the parameters handler_bin_ids (prober_bin_ids) and hardbin_to_handler_bin_map ( hardbin_to_prober_bin_map) must be defined, as explained below.

"mapped-softbins" provides a method to assign (groups of) SmarTest bins to (groups of) equipment bins. The software bin codes of the SmarTest bins are used for bin identification.

To use this feature, the parameters handler_bin_ids (prober_bin_ids) and softbin_to_handler_bin_map (softbin_to_prober_bin_map) must be defined, as explained below.

Driver default: none; value must be defined in the driver configuration

Changeable at run-time: yes

Applicable for: handlers and probers

Example: bin_mapping: "mapped-hardbins"
