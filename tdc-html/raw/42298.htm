Application model for package test

This example demonstrates the usage of general handler driver functions.

It is recommended to use this example application model as a template for your own application models for package testing. You find this example application model file, named package_generic_handler, in the directory /opt/hp93000/soc/applic_models/ .

hp93000,applicmodel,0.1

-----------------------------------------------------------------------
--  FILE NAME:  package_generic_handler
--
--  Example application model file for an automatically performed
--  PACKAGE test, using the new generic handler driver
-----------------------------------------------------------------------

--      DESCRIPTION: 
--
--      First, the operator must enter the DIALOG_INPUT items:
--
--      Lot_id .........: string
--      Operator_id ....: string
--
--      Press the START button once a packaged device has been connected
--      and all equipment is prepared for the test.
--
--      Package_id's are generated automatically by the system.
--
--      If the pause button is pressed the test pauses at device level
--      where a PAUSE dialog menu is displayed and the operator is asked to
--      enter the reason for the interruption. 
--      The operator may change the handler driver's configuration or change 
--      the driver's mode of operation during PAUSE.

--      ---------------------------------------------------------------------

START_DIALOG

{ lot:

    SCREEN_DIALOG
        Lot_id        = DIALOG_INPUT    / REGEXP(string);
        Operator_id   = DIALOG_INPUT    / REGEXP(string);

    ACTIONS
        Test_description = GET_TEST_INFO (test_desc);
        Test_version     = GET_TEST_INFO (test_rev);
        Device_name      = GET_TEST_INFO (dev_name);
        Device_revision  = GET_TEST_INFO (dev_rev);
        Test_program     = GET_TEST_INFO (testprog);
        Start_time       = GET_TEST_INFO (date_time);

    -- A call to ph_driver_start is mandatory

        PROB_HND_CALL (ph_driver_start);

        -- Optionally the handler driver may be reconfigured 

        -- PROB_HND_CALL (ph_set_configuration debug_level: 1);
        PROB_HND_CALL (ph_set_configuration trace_driver_calls: "no");
        PROB_HND_CALL (ph_set_configuration driver_message_log: "/tmp/{Lot_id}.driver_messages" driver_error_log:   "/tmp/{Lot_id}.driver_errors");

        -- Optional calls to retrieve information from handler driver

    PH_driver_id        = PROB_HND_CALL (ph_get_id driver);
    PH_plugin_id        = PROB_HND_CALL (ph_get_id plugin);
    PH_equipment_id     = PROB_HND_CALL (ph_get_id equipment);

    PH_family     = PROB_HND_CALL (ph_get_configuration handler_family);
    PH_model      = PROB_HND_CALL (ph_get_configuration model);
    PH_plugin     = PROB_HND_CALL (ph_get_configuration driver_plugin);
    PH_config     = PROB_HND_CALL (ph_get_configuration configuration);

        { DEVICE [(package test),({package_id})] device:
            ACTIONS
                package_id = AUTOINCREMENT;
                SET_PACKAGE_ID({package_id});

                -- Get a device from the handler

                -- You may measure the handling performance by removing the 
                -- comment signs of the ph_timer_start and ph_timer_stop calls
                -- and of the NEW_RESULT_FILE specification below. 
                -- ph_timer_start and ph_timer_stop may be nested.

                -- PROB_HND_CALL (ph_timer_start);
                PROB_HND_CALL (ph_device_start);
                -- PH_get_device_time = PROB_HND_CALL (ph_timer_stop);

                {
                  DEVICE_TEST
                }

            -- Reprobe may always be defined, 
            -- even if the used handler does not provide reprobing

            REPROBE_ACTION = PROB_HND_CALL(ph_reprobe);

            ACTIONS
                -- Bin devices

                -- You may measure the handling performance by removing the 
                -- comment signs of the ph_timer_start and ph_timer_stop calls.

                -- PROB_HND_CALL (ph_timer_start);
                PROB_HND_CALL (ph_device_done);
                -- PH_bin_device_time = PROB_HND_CALL (ph_timer_stop);
        }

    ACTIONS
        -- close the handler driver
        PROB_HND_CALL (ph_driver_done);
}

{ ON_PAUSE pause:

    ACTIONS
        -- The handler driver MUST be notified about the pause start !
        PROB_HND_CALL (ph_pause_start);
        
    LINE_DIALOG

    -- Here is a list of typical handler driver actions during pause.
    -- Add comment signs at the beginning of the lines you want to disable.

    BUTTON hand_on = PROB_HND_CALL (ph_handtest_start);
    BUTTON hand_off = PROB_HND_CALL (ph_handtest_stop);
    BUTTON reprobe = PROB_HND_CALL (ph_reprobe);
    BUTTON configure = PROB_HND_CALL (ph_interactive_configuration);
    BUTTON step_on = PROB_HND_CALL (ph_stepmode_start);
    BUTTON step_off = PROB_HND_CALL (ph_stepmode_stop);

    reason = DIALOG_INPUT;

    ACTIONS
        -- The handler driver MUST be notified about the end of pause !
        PROB_HND_CALL (ph_pause_done);
}

Functional changes

  2. SmarTest 7.1.0: GDF logging in application model is obsolete.
