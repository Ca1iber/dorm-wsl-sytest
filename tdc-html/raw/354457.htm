XPS256 programming - DGT

An FVI16 pin can be used as a digitizer (DGT), supporting sampling both of voltage and current waveforms. The DGT functionality is controlled by pattern sequencer DC events.

Refer to XPS256 digitizer (DGT) for a detailed description of the digitizer.

Note This topic of the XPS256 programming overview covers only the DGT specific settings. For common settings, refer to XPS256 programming - Measure currents and XPS256 programming - Measure voltages.

Maximum sample frequency

For XPS256, the maximum frequency of the pattern sequencer is 50 MHz and 32 vectors are required per sample. This results in a maximum sample frequency of 1.5625 MHz. See also Minimum period / maximum frequency of the sequencer.

SmartRDI overview

The basic functionality of an XPS256 pin that is used as DGT can be controlled by the dc() API and the id() API of SmartRDI. The basic DGT setup is supported in the code‑based mode and the DGT core functionality is supported only in the pattern‑based mode. For more information refer to Setting up DC Scale pins with SmartRDI and the related member functions of the dc() API.

SmartRDI supports also setting up DC resources like a real digitizer. For more information refer to Using DC resources as digitizer with SmartRDI.

API overview

The basic setup of the DGT must be programmed by standard APIs for an XPS256 pin in PMU operating mode or by the Equation based level setup or API DPS_TASK for an XPS256 pin in DPS operating mode.

The DGT core functionality is provided by measurement events in a pattern. For more information refer to DC events.

Sampled data can be uploaded to the test method using member functions of API DC_RESULT_ACCESSOR.

Application note

Flush vectors at the end of a pattern
Due to inter module communication it is required to keep the pattern running for a short time after the last ADC measurement related DC event. The actual required time or number of flush vectors depends on the setup. In case of insufficient number of vectors before pattern stop, a communication error might occur.

The number of required flush vectors depends on the average count and the pattern cycle time as follows:

Minimum number of vectors = 37 + ( average / (2 MHz * period) )

where: average = Programmed average count
period = Cycle time of the pattern

The calculated number is the minimum number of vectors that is required between the last measure event and the end of the pattern.
