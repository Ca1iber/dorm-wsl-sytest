Topic 37568

Inserting Sequencer Instructions

Subtopics

  1. The PADDING Instruction

If the ASCII vector file only consists of n ASCII vectors, the body of the resulting sequencer program will only contain one instruction, which sends the n corresponding binary vectors to the DUT once. If, for example, you want to send a sequence of vectors repeatedly, or change the level setup within the pattern, you must insert the respective instructions into the ASCII vector files at the appropriate places.

The general format of the sequencer instructions within the ASCII vector file is a simplification of the SQPG firmware command and looks as follows:

SQPG <instruction> [<para_1>[ <para_2>]];

Note In contrast to the SmarTest syntax, the second parameter must be separated from the first by a blank, not a comma.

The following table contains all the sequencer instructions that can be inserted:

Instruction

Explanation

CLEV <level_set_number>

Causes a change to the specified level set.

CTIM <timing_set_number>

Causes a change to the specified timing set. It is recommended to let this instruction be inserted automatically by the mechanism described in Controlling the Automatic Insertion of CTIM Instructions.

FLQU

Fills the data queue with break vectors.

GENV <number_of_vectors>

Generates the specified number of vectors. This instruction is created automatically by the vector translation, so that there will usually be no need to insert it manually. But if there is, the number of vectors that belong to the instruction must be indicated to the vector translation with the PADDING instruction. See The PADDING Instruction.

JPPS <name_of_per_pin_subroutine>

Calls a per-pin subroutine.

JSUB [<major_inst_offset>] <name_of_subpattern>

Calls a subpattern (type SVEC). The first parameter specifies the major instance offset for calls of scan subroutines (see Creating a Scan Subroutine). It must be omitted for all other types of subroutines.

LBGN [<number_of_repetitions>]

Starts an endless or counted loop.

LEND

Terminates a counted or endless loop.

MACT <maximum_number_of_failing_repetitions>

Starts a match loop (new style) and specifies the number of unsuccessful repetitions after which the test will fail. A match loop (new style) is terminated with the MRPT instruction.

MACT has a second optional parameter:

  • CONTINUE: This option keeps the test going on even if the loop fails.

  • TIL_FAIL_STOP: The loop is to be repeated until an iteration fails. When the maximum loop count is reached, the test program stops.

  • TIL_FAIL_CONT: The loop is to be repeated until an iteration fails. When the maximum loop count is reached, the test program continues after the loop has been completely executed. This behavior is a combination of both TIL_FAIL_STOP and CONTINUE.

Note The two values TIL_FAIL_STOP and TIL_FAIL_CONT are valid for Smart Scale cards only.

MRPT <number_of_vectors>

Terminates the body of a match loop (new style). Must be followed by one or more dummy vectors that are repeated while the result of the match loop is being evaluated. Note the following points:

  • A PADDING instruction must be inserted after the dummy vectors to indicate how many of the following ASCII vectors belong to MRPT. See The PADDING Instruction.
  • The repeat factor of the ASCII vectors belonging to an MRPT instruction must not be greater than the value specified for the v2b parameter -r (the default is 32).

PADDING

Informs the vector translation how many ASCII vectors are to be associated with an MTST, MRPT, or RPTV instruction. See The PADDING Instruction.

RPTJ <number_of_repetitions>

Repeats a subroutine a specified number of times. The subroutine must be specified in the next row with the JSUB instruction.

RPTV <number_of_vectors> <number_of_repetitions>

Sends a certain number of vectors to the DUT for a certain number of times. Note the following points:

  • The vector translation must be informed with the PADDING instruction how many ASCII vectors belong to RPTV. See The PADDING Instruction.
  • The repeat factor of the ASCII vectors belonging to an RPTV instruction must not be greater than the value specified for the v2b parameter -r (the default is 32).

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.0.3: Removed MTST instruction
  3. SmarTest 7.4.4: MACT supports CONTINUE as a parameter option.
  4. SmarTest 7.5.0: MACT supports TIL_FAIL_STOP and TIL_FAIL_CONT as parameter options.
