Topic 56406

GLOBAL section

In the GLOBAL section of the model file you define what kind of system is used and what features are available system-wide.

The following definitions are available:

apg_speed device_maintenance diag_subsystem_interface
dut_interface hpib_interface memory_pooling
memorytest protocol_aware memory_compatibility
rapid_source_synch s&s_value_package testhead
timing_bundle triage utility_lines
vectorCache xpressdata
Note The following features, for example, are licensed. Thus they could be overwritten by the device license file: apg_speed, device_maintenance, memorytest, timing_bundle, xpressdata
Parameters

apg_speed

Specifies the maximum speed (data rate) with which MTP memory patterns can be executed. The default is 0 Mbps.

On SOC systems:

apg_speed = 400Mbps | 800Mbps | 1800Mbps

The APG speed license applies to the entire test system. The execution speed of a pattern is the lower value of the APG speed license and the applicable channel speed license (see IOCHANNEL section).

An APG speed license is required to download MTP memory test patterns.

This license is required in addition to the channel speed license.

device_maintenance

Specifies the device maintenance or "refresh" feature.

device_maintenance = ON

If not specified, the feature is disabled by default. No warning or error message. Device maintenance requires a FLEXlm license.

Memory device cells leak charge over time and must be refreshed in a specified time (16-32 ms typical). For a refresh, the cell state is read into a buffer and then written back. For details see Maintenance operations.

diag_subsystem_interface

Defines the serial device that is used for low-level diagnostics using RS-232 communication.

diag_subsystem_interface = <device>

CAUTION If you also specify the export variable DI_RS-232 , it takes precedence over the settings from the model file.

RHEL 7 (SmarTest ≥ 7.5):

  • Port 1: diag_subsystem_interface = /dev/ttyUSB0
  • Port 2: diag_subsystem_interface = /dev/ttyUSB1
  • Direct connection via Com1: diag_subsystem_interface = /dev/ttyS0

2-port and 4-port RS-232 MOXA cards (SmarTest ≥ 7.3):

  • Port 1: diag_subsystem_interface = /dev/ttyMUE0
  • Port 2: diag_subsystem_interface = /dev/ttyMUE1
  • Port 3 (4-port card only): diag_subsystem_interface = /dev/ttyMUE2
  • Port 4 (4-port card only): diag_subsystem_interface = /dev/ttyMUE3

See also: Prerequisites for executing diagnostic on system controller Z4 G4.

dut_interface

Specifies the DUT interface type.

dut_interface = SOC | HSM | SOC_8GROUP | SOC_4GROUP

SOC: standard for Pin Scale systems

SOC_8GROUP: to interface the large DUT board

SOC_4GROUP: to interface the small DUT board

hpib_interface

Specifies the GPIB interface type for the NIST traceable calibration.

Standard Configuration for the LAN to GPIB Solution

Required statement for traceable calibration:

hpib_interface = vxi11/<LAN-GPIB gateway>/192.168.0.100/gpib0

The entry <LAN-GPIB gateway> depends on the connected LAN to GPIB gateway:

E7032A LAN to GPIB gateway: e5810a (E5810A)

memory_pooling

Specifies the memory pooling feature which allows combining the licenses of multiple pins to be used at one pin.

memory_pooling = OFF

The memory pooling feature is enabled by default. To disable it, you must specify it as OFF.

memorytest

Specifies the pattern generation feature of the memory-test software.

memorytest = ON

If not specified, the pattern generation feature is disabled by default. It requires a license.

Note: DO NOT use this parameter for SmarTest versions 7.0.1 and later. It has been obsoleted since 7.0.1.

protocol_aware

Enables the protocol-aware feature needed for executing transaction based protocol tests:

protocol_aware = ON

This license will enable the full feature set of protocol-aware.
PS1600MemoryCompatibility Disables the PS1600 memory compatibility mode.

PS1600MemoryCompatibility = OFF | ON

The mode is enabled by default.

rapid_source_synch

Specifies the number of enabled sites, the default is 0.

rapid_source_synch = <number_of_sites>

Rapid Source Synch (RSS) serves to enhance the performance of source synchronous testing by accumulating result data in the hardware, and processing the results in parallel. For details see Exploiting hardware resources for performance enhancement. RSS requires no license.

s&s_value_package

Enables the correction data converter:

s&s_value_package = ON

This license is only available with an active service contract.

For further details please contact your Advantest support representative.

testhead

Specifies the size of the test head and the number of card cages in the test head.

testhead = TH_8CC | TH_4CC | TH_2CC| TH_1CC

TH_8CC: Large test head (8 card cages)

TH_4CC: Small test head (4 card cages)

TH_2CC: Compact test head (2 card cages)

TH_1CC: A test head (1 card cage)

timing_bundle

A "system" resource.

Specifies the number of waveforms, drive edges, and receive edges to be bundled together for all channels.

timing_bundle = w32-d8-r6 | w256-d8-r8

Channels running at a speed of 1800 Mbps, 2700 Mbps or 3200 Mbps must be configured with 256 waveforms, 8 drive edges and 8 receive edges (timing_bundle = w256-d8-r8), or 32 waveforms, 8 drive edges and 6 receive edges (timing_bundle = w32-d8-r6).

triage

Specifies the algorithms of the Yield Learning Solution. If not specified, the feature is disabled by default.

triage = ON

Enables all algorithms.

triage = BCA | END_POINT_LOG | HOLD_TIME_FAULT | SPEED_SCAN

Enables the individual algorithms.

Triage requires a license.

For online use the utility lines are defined in the .technology file (device viewpoint) as well as in the model file (system viewpoint). Dependent on the detected wiring board the definitions are validated and a warning is given if there is a mismatch.

A utility_lines = 256 entry in the model file is required to enable all 32 utility lines per pogo block. If no utility_lines entry is made at all the system defaults to 16 utility lines. Entering 32 lines makes sense only if 4-row utility line pogo blocks are installed. If this is not observed SmarTest does not start.

No utility_lines entry in the model file nor in the .technology file causes the following system behavior on the small test head:

  • If dut_interface = SOC_8GROUP, the system provides 128 utility lines, not sequencer-controllable
Note No utility_lines entry in the model file nor in the .technology file causes the following system behavior on the large test head:

If dut_interface = SOC_8GROUP, the system provides 128 utility lines, not sequencer-controllable..

vectorCache

Enables or disables the vector cache of the test processor. If not specified, the vector cache is enabled by default.

vectorCache = OFF # default ON

The vector cache must remain enabled for all currently allowed cases.

xpressdata

Specifies the Xpress Data Mode.

xpressdata = ON

The Xpress Data Mode is disabled by default. If not specified, you cannot use the mode. To operate Smart Scale cards you must enable the Xpress Data Mode. It requires a license.

Example

...
GLOBAL
    testhead = TH_8CC
    dut_interface = SOC
    device_maintenance = ON
    timing_bundle = w256-d8-r8
    diag_subsystem_interface = /dev/usb/ttyUSB0
    ...
