Topic 129105

Device property file

The device property file specifies the geometry of your device to allow the Automatic Map Converter to create a mapping library for it.

You need to provide the following data:

  • Location of the APG pattern file
  • The order in which the DQ, bank, column, and row coordinates specify the memory cells.

    Depending on the device, DQs might be ordered by bank first and then by row and column; or by DQ block, then bank, then rows and columns; etc. This order must be specified.

  • The dimensions of the DQ matrix - how many rows and columns of DQs a device has
  • The numbering scheme of the DQ matrix.

    The map converter numbers DQs from left to right and from top to bottom. If desired, a different numbering scheme can be specified by associating DQs with new ID values.

  • The x/y orientation for each DQ area - how x and y are mapped to up/down and left/right, respectively.

    This allows mirrored DQ areas to be described in the property file. Orientations defined in nested address dimensions are superimposed to arrive at the final orientation of the row and column addresses of the memory cells (see cell, below, for details.)

  • The dimensions of the bank matrix - how many rows and columns of banks a device contains
  • The numbering scheme of the bank matrix.

    The map converter numbers banks from left to right and from top to bottom. If desired, a different numbering scheme can be specified by associating banks with new ID values.

  • The x/y orientation for each bank - how x and y are mapped to up/down and left/right, respectively.

    This allows mirrored banks to be described in the property file. Orientations defined in nested address dimensions are superimposed to arrive at the final orientation of the row and column addresses of the memory cells (see cell, below, for details.)

Syntax

<mapConverterProperties
    xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" 
    xsi:noNamespaceSchemaLocation="<schema_file>">
  <deviceSetup patternFile="<apg_file_path>" /> 
  <coordinateDependency>
    <geomAddr rowCol="<row_col_order>" /> 
    <level coordinate="<coordinate>">
      <level coordinate="<coordinate>">
        <level coordinate="<coordinate>" /> 
      </level>
    </level>
  </coordinateDependency>
  <matrix type="<matrix_type>">
    <dimensions cols="<number>" rows="<number>" /> 
    <layout>
      <cell col="<number>" row="<number>" id="<id>" xOrient="<x_orientation>" yOrient="<y_orientation>" />
      ...
    </layout>
  </matrix>
  ...
  <redundancyAnalysis>
    <COLS_IN_BLPAIR value="<cols>" />
    <ROWS_IN_WLSET value="<rows>" />
    <BLPAIRS_PER_SEGM value="<blpairs_per_segm>" />
    <WLSETS_PER_SEGM value="<wlsets_per_segm>" />
    <matrix type="segment">
      <dimensions cols="<number>" rows="<number>" /> 
      <layout>
        <cell col="<number>" row="<number>" id="<id>" />
        ...
      </layout>
    </matrix>
  </redundancyAnalysis>
</mapConverterProperties>
Elements and attributes

Name

Description

mapConverterProperties

The top-level element. It has two attributes:

  • xmlns:xsi: This must always be "http://www.w3.org/2001/XMLSchema-instance"
  • xsi:NoNameSpaceSchemaLocation: is the location of the schema file for the device configuration file. By default, the file is named propertyFileAPI.xsd and is located in the same directory as the Automatic map Converter binary.

Technically, these attributes could be omitted, but this would prevent any validation of the file. We recommend including these attributes and using an XML editor to edit the file to ensure syntactical correctness.

deviceSetup

The path to the MTL pattern file (.apg). The path can be absolute or relative to the device directory and is stored in the patternFile attribute.

coordinateDependency

This element contains the specification of the addressing scheme of the device.

It has no attributes.

geomAddr

The geomAddr element describes how the geometric x- and y-coordinates map to rows and columns of the device.

  • rowCol: This attribute can contain either "xy" or "yx".

    "xy" specifies that x-coordinates correspond to rows and y-coordinates to columns.

    "yx" specifies that x-coordinates correspond to columns and y-coordinates to rows.

level

The level elements specify the order of significance of the address dimensions: The outermost level element specifies the most significant dimension, the next level element, the next significant dimension, and the innermost element the least significant dimension.

There is one attribute:

  • coordinate: This attribute specifies the address dimension.

    Supported values are: "DQ", "bank", and "row/col".

The coordinate value for the outermost level element must always be either "DQ" or "Bank".

matrix

matrix elements specify the numbering and orientation properties of banks, DQs and segments.

At the top level of the mapConverterProperties element, there must be one matrix element for banks and one for DQs; in other words, there must be exactly two matrix elements.

In the redundancyAnalysis element, there must be exactly one matrix element, which describes the arrangement of segments.

A matrix element has one attribute:

  • type: This attribute specifies the address dimension being described.

    If the matrix element is at the top level of the mapConverterProperties element, type can have the values "DQ" or"bank".

    If the matrix element is located within a redundancyAnalysis element, type must have the value "segment".

dimensions

The number of rows and columns into which these banks or DQ areas are organized:

  • rows: The number of rows
  • cols: The number of columns

layout

The layout element contains the numbering and orientation for each bank or DQ area.

It has no properties of its own but contains one cell element for each row/column combination.

cell

A cell element describes the numbering and orientation for one bank or DQ area.

It has these attributes:

  • col: The column value of the bank or DQ area being described
  • row: The row value of the bank or DQ area being described
  • id: The number by which this bank or DQ area is referred to.
  • xOrient: The direction in which the row addresses in this bank or DQ area grow. Possible values are "down" (larger x-values indicate addresses further down) or "up" (larger x-values indicate addresses further up).

    The xOrient attribute is omitted when the cell element is located within a redundancyAnalysis element.

  • yOrient: The direction in which the column addresses in this bank or DQ area grow. Possible values are "right" (larger y-values indicate addresses further right) or "left" (larger y-values indicate addresses further left).

    The yOrient attribute is omitted when the cell element is located within a redundancyAnalysis element.

Note that the orientation specified for one address dimension also affects all less significant address dimensions. If the orientation is redefined for a less significant dimension, the effective orientation for the cells is a superimposition of both definitions.

For example, if memory cells are specified first by bank and then by DQ and the xOrient value for both dimensions is "up", the resulting orientation for the cells is "down".

redundancyAnalysis

The redundancyAnalysis element contains information that the Automatic Map Converter needs to create the get_ra_layout and phys_to_layout function, which are required for redundancy analysis.

This element is optional. If it is missing, the two functions are not generated.

COLS_IN_BLPAIR

This element describes the number of columns in a bit line pair of the device.

The number is contained in the value attribute.

ROWS_IN_WLSET

This element describes the number of rows in a word line set of the device.

The number is contained in the value attribute.

BLPAIRS_PER_SEGM

This element describes the number of bit line pairs per segment of the device.

The number is contained in the value attribute.

WLSETS_PER_SEGM

This element describes the number of word line sets per segment of the device.

The number is contained in the value attribute.

Example

<?xml version="1.0" encoding="UTF-8"?>

<mapConverterProperties xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
  xsi:noNamespaceSchemaLocation="amc_config_properties.xsd">

  <!-- Fully qualified path to the APG file: -->
  <deviceSetup patternFile="/home/hsmdevices/sampleDevice/mts/pattern_defs/sample.apg"/>

  <coordinateDependency>
    <!-- Specify whether the rows and columns of geometric addresses are
         referred to by x/y or y/x: -->
    <geomAddr rowCol="yx"/>

    <!-- Specify the address components ordered by significance. Only DQ or bank are
         allowed as the most significant address component. -->
    <level coordinate="DQ">
      <level coordinate="bank">
        <level coordinate="row/col">
        </level>
      </level>
    </level>
  </coordinateDependency>

  <!-- The properties of the DQ matrix. In this case there are eight DQs in
       a row, which are numbered in ascending order from left to right. -->
  <matrix type="DQ">
    <dimensions cols="8" rows="1"/>
    <layout>
      <cell col="0" row="0" id="0" xOrient="down" yOrient="right"/>
      <cell col="1" row="0" id="1" xOrient="down" yOrient="right"/>
      <cell col="2" row="0" id="2" xOrient="down" yOrient="right"/>
      <cell col="3" row="0" id="3" xOrient="down" yOrient="right"/>
      <cell col="4" row="0" id="4" xOrient="down" yOrient="right"/>
      <cell col="5" row="0" id="5" xOrient="down" yOrient="right"/>
      <cell col="6" row="0" id="6" xOrient="down" yOrient="right"/>
      <cell col="7" row="0" id="7" xOrient="down" yOrient="right"/>
    </layout>
  </matrix>

  <!-- The properties of the bank matrix. In this case there are two rows
       of four banks each, which are numbered from top to bottom and
       from left to right. The x-addresses in the second row have the
       opposite direction as in the first row. -->
  <matrix type="bank">
    <dimensions cols="4" rows="2"/>
    <layout>
      <cell col="0" row="0" id="0" xOrient="down" yOrient="right"/>
      <cell col="0" row="1" id="1" xOrient="up"   yOrient="right"/>
      <cell col="1" row="0" id="2" xOrient="down" yOrient="right"/>
      <cell col="1" row="1" id="3" xOrient="up"   yOrient="right"/>
      <cell col="2" row="0" id="4" xOrient="down" yOrient="right"/>
      <cell col="2" row="1" id="5" xOrient="up"   yOrient="right"/>
      <cell col="3" row="0" id="6" xOrient="down" yOrient="right"/>
      <cell col="3" row="1" id="7" xOrient="up"   yOrient="right"/>
    </layout>
  </matrix>
</mapConverterProperties>
