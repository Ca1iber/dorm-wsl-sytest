Using the Trace Function

The hpt utility provides a trace function that records the firmware commands issued by the user interface of SmarTest as well as the replies to these commands.

The trace file is named MCDLog and is located in the /var/opt/hp93000/soc directory.

MCDLog

The MCD-Log can get very long and can therefore be hard to read.

You can structure the test method code by setting markers using the firmware command NOOP:

FW_TASK("NOOP \"<your marker>\",,,");

To enable logging to the MCDLog file, set the environment variable before starting SmarTest (see SmarTest environment variables):

  • Before starting SmarTest, open a terminal window and type

    export HP83000_ANNOTATE_MCDLog=1

  • Include the line in your start script or profile file

    export HP83000_ANNOTATE_MCDLog=1

For each marker SmarTest writes a line to the MCDLog as follows:

>NOOP "<your marker>",,,

Additionally, SmarTest logs every test suite:

>NOOP <integer>, "TESTSUITE", "Leakage"

With <integer> = process id of ftest (testflow executor)

Note that the process id varies with each start of the testflow.

Note You can activate logging of test suites when SmarTest is already running. Set the debug_mode to "1 (Display actions)".

Starting the trace function

At the hpt prompt, type diag 2

Switching off the trace function

At the hpt prompt, type diag -2

Note The Pattern Explorer and the Pattern tool do not issue firmware commands. Accordingly, their activities are not recorded in the MCDLog file. This also holds for some Test Method API's.
