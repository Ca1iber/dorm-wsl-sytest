Unpredictable events in the application model

In The Structure of the Levels, you can see three additional events that cause the software to do something other than that defined in the current level, namely, Abort, Pause and Reset. These events correspond to button clicks of the last three buttons on the main Operation Control window; as such, these events are totally asynchronous, as you cannot predict when they will occur.

Abort, Pause and Reset are not the only unpredictable, or asynchronous, events that can occur in your test program; nor do these events always have to be triggered by a button input - they can also be triggered by flags (indeed, pressing a button from within the production environment sets the appropriate flag in the application model file). For example, you could write a routine that automatically sets the abort flag when a certain condition arises in the prober (for information about writing your own routines that incorporate these flags, see the manual Command Interface).

The various buttons and flags used for unpredictable events - or as is oft termed "exception handling" - are,

abort

if set, it will produce a predefined sequence of events, whereby the post-actions of successively higher levels are executed, one after the other, until the last level is exited.

pause

a special condition that has its own defined section in the application model file (the ON_PAUSE section). If the pause flag/button is set, the actions and dialogs that are defined in the ON_PAUSE section are executed. You then have the choice of quitting or continuing.

reset

is identical to abort, but in addition the tester hardware is reset.

skip

if set, the pre- and post-actions on the level where the skip occurs are executed; all lower levels are skipped.

retest_d

(retest die) can only be set at the device level; it causes the last die tested to be tested once more, and the results to be logged.

check_dev

(check device) can only be set at the device level; it causes the device to be tested without logging of the results (but a summary does appear in the report window)

retest_w

(retest wafer) can be set in the wafer level and the ON_PAUSE section. It results in the last tested wafer being tested once more, and the results being logged.

reference

can be set in the wafer level and in the ON_PAUSE section. If set, the reference wafer will be loaded and tested. However, your own prober driver must be able to support the reference event; this means it must be able to,

1. stop testing of the current wafer

2. remove the current wafer

3. load the reference wafer

4. test the reference wafer

5. remove the reference wafer

6. reload the wafer you had been testing

7. test this wafer again

quit

can be set in all levels. If set, the software moves back up through the levels, executing all post-actions, until it reaches the next dialog - which is then executed.

Readers wishing to have more detail on what exactly happens during exception handling should read the relevant sections in the V93000 Series User Training.
