Topic 91402

Creating a testflow in SmarTest

SmarTest provides the facilities to collect a set of test methods into a testflow which you can run in one go or in portions.

Before creating a new testflow using the testflow editor you have to load a setup you created for your device as described in Defining a memory test.

After you created a complete testflow you have a Test Program you can save or execute.

When you cerate a testflow, the following information may be helpful:

  • Multiple Sites Execution for production test environment
  • Hierarchy within a testflow
  • Bins
  • Test suites
  • Special test suites
  • Support for Burst Mode for production test environment
  • Master File Format for Testflow

For details on how to work with a testflow see Tasks.

Your testflow should differ in the amount of logging whether your run a DV or a HVM test.

Remember to set flags for use case debug.

Set System flag: Log_Events_enable = on

A typical testflow for a memory device should contain:

Eyefinder (XDR) or Source Sync (GDDR) Data Training + ExecutionEngine

in this sequence.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. MTP 3.0.1: The ExecutionEngine test method replaces the Memtest test methods
