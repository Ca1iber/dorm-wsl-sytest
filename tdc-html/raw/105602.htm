Topic 105602

GPIB communication flow for Mirae handlers

This section describes the communication between the driver and the handler. The actions and messages are listed in the sequential order in the table below.

See Conventions for GPIB communication for descriptions of the syntax.

GPIB communication flow for Mirae handlers

Message from driver

Message from prober

Comment

Init:<configuration>

 

 

Configuration: <temperature setup> <testset setup> <sitemap setup> <siteselection setup> <bincategory setup>

 

At startup, these setups will be made and the relevant GPIB commands will be sent to the handler.

temperature setup:

SETTEMP <value>

SETBAND <value>

SETSOAK <value>

"SettingOK"

Different temperature setups are made according to the value of configuration parameter temp_control:

off or manual: no temperature setting will be sent to the handler.

ambient: disable the temperature controls.

active, hot or cca: the left temperature setup GPIB commands will be sent to handler.

testset setup: (for MR5800)

TESTSET <value>,<value>,<value>

"SettingOK"

The three values are Para, Step and Row, representing the configuration of test tray.

Para=32/64/128 (test in parallel),

Step=1/2/4(number of test step),

Row should be set to F (1 1 1 1). Para*Step must be equal to 128.

sitemap setup:(for MR5800)

SITEMAP <value>

"SettingOK"

 

siteselection setup:(for MR5800)

SITESEL <value>

"SettingOK"

The value is determined by the configuration parameter handler_site_mask.

bincategory setup:(for MR5800)

SETBIN <value>

"SettingOK"

The value is determined by the configuration parameter handler_bin_categories.

Lot start:

SRQ(0x46)

Wait for the Lot Start SRQ 0x46

Lot end:

SRQ(0x48)

 

wait for devices: <SRQ><poll>

 

Based on the configuration parameter waiting_for_parts_method, the driver will either wait for an SRQ or poll for the current site number.

SRQ

SRQ(0X47)

Handler sends test start SRQ.

Poll: FULLSITES?

 

FULLSITES n

Handler returns bit coded site number.

 

 

 

bin devices:

BINON:n (for M330)

BINON n (for M660, MR5800)

ECHO n

Bin the devices. "n" represents the bin code string for all the sites, like "xxxxxxxx,xxxxxxxx,xxxxxxxx,xxxxxxxx". The first character is the Site 32's (16's for MR660) bin code, and the last character is the Site 1's bin code.

jam

SRQ(0x3d)

The handler is jam.

"version"

"status"

"jam"

"trayid"

"lottotal"

"accerrcode"

"accdata"

"alarmrecord"

query version:

VERSION?

"string"

Query the handler software version

with PROB_HND_CALL(ph_get_status version).

query testset:

TESTSET?

"string"

Query of the configuration of test tray.

query meastemp:

MEASTEMP 1

MEASTEMP 2

MEASTEMP 3

MEASTEMP 4

"string"

Query the measurement temperature in the specified test site with PROB_HND_CALL(ph_get_status meastemp n). n is the site number.

query status:

STATUS?(for MR5800,M330)

HDLSTATUS?(for MR660)

"string"

Query the current handler status, like started or stopped.

query settemp:

SETTEMP?

"string"

Query the set temperature of the handler.

query jam:

JAM?

"string"

Query whether the jam occurred or not. The returned result 1 means jam occurred, 0 means no jam.

query jamcode:

JAMCODE?

"string"

Query the jam code.

query jamcount:

JAMCOUNT?

 

"string"

The number of jams.

query jamque:

JAMQUE?

"string"

Dump the jam queue, which keeps up to 20 messages. Return 0 if there is no jam message.

query setlamp:

SETLAMP?

"string"

Get the status of tower lamps.

query tempmode: (only for MR660)

TEMPMODE?

 

 

 

"string"

Get the current temperature setting; the response:

TEMPMODE 0: no control (off)

TEMPMODE 1: hot mode

TEMPMODE 2: ambient

TEMPMODE 3: code mode

query trayid: (only for MR660)

TRAY_ID?

"string"

Get the ID of test tray in the test site

query loterrcode: (only for MR660)

LOTERRCODE?

"string"

Get the lot error code.

 

query lotalmcode: (only for MR660)

LOTALMCODE?

"string"

Get the lot alarm code.

query lotdata: (only for MR660)

LOTDATA?

"string"

Get the lot data, including the operation times, HiAlarm count, LowAlarm count.

query lottotal: (only for MR660)

LOTTOTAL2?

"string"

Get the current lot module information, like good, reject, rested, P/F, bin number, etc.

query accsortdvc: (only for MR660)

ACCSORTDVC?

"string"

Get the accumulated lot module information.

query accjamcode: (only for MR660)

ACCJAMCODE?

"string"

Get the accumulated JAM code.

query accerrcode: (only for MR660)

ACCERRCODE?

"string"

Get the accumulated error code.

query accdata: (only for MR660)

ACCDATA?

"string"

Get the accumulated lot data, including the operation times, HiAlarm count, LowAlarm count.

query alarmrecord: (only for MR660)

ALMRECORD?

"string"

Get the record of alarm messages.

set status:

<set name>

<set loader>

<set start>

<set stop>

<set plunger>

<set runmode>

<set lotclear>

<set accclear>

<set contactsel>

 

Set the handler's status by the PH call ph_set_status. The input parameters used in the "ph_set_status" are:

"name xxx" (xxx is the new name)

"loader"

"start"

"stop"

"plunger n"

"runmode n"

"lotclear"

"accclear"

"contactsel xxxx" (xxx is the bit-coded site selection value)

set name:

SETNAME xxx

 

 

"done"

Set the handler name to "xxx". Usage:

PROB_HND_CALL(ph_set_status name testing_123)

set loader:

LOADER

"done"

Prepare new lot or additional devices with PROB_HND_CALL(ph_set_status loader).

set start:

START

"done"

Start the handler.

Set stop:

STOP

"done"

Stop the handler.

set plunger:

PLUNGER 0

PLUNGER 1

"done"

Set the contractor to ON or OFF with

PROB_HND_CALL(ph_set_status plunger n). n is 0 or 1.

set runmode:

RUNMODE 0

RUNMODE 1

"done"

Set the running mode.

0=Normal mode,

1=Flush mode.

set lotclear: (only for MR660)

LOTCLEAR

"done"

Clear the lot counters.

set accclear:(only for MR660)

ACCCLEAR

"done"

Clear the accumulated counters.

set contactsel:(only for MR660)

CONTACTSEL xxxx

"done"

Set the contact (site) selection with

PROB_HND_CALL(ph_set_status contactsel xxxx).
