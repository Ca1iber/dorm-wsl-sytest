Topic 114219

Overview of various disconnect methods

Subtopics

  1. Comparing the disconnect methods
  2. Standard disconnect sequence
  3. User-defined disconnect sequence
  4. Special test suite bin_disconnect
  5. Multibin SmartDisconnect test suite

SmarTest provides you with the flexibility to modify the behavior of the disconnect sequence. According to your needs, you can choose the standard disconnect sequence, the user-defined disconnect sequence, the Multibin SmartDisconnect test suite, or the special test suite bin_disconnect.

The following methods for disconnecting are provided in SmarTest:

  • Standard disconnect sequence

    The standard disconnect sequence is the built-in solution of SmarTest. If not replaced by a user-defined sequence, it is performed at each stop bin to disconnect the failing sites or the remaining passing sites.

    For a stop bin, the standard disconnect sequence is applied only for the non-shared pins if not all sites have been binned. For the final disconnect with all sites binned, the standard disconnect sequence is applied for all pins and all remaining passing sites.

    Note On startup SmarTest always performs a standard disconnect.
  • User-defined disconnect sequence

    The user-defined disconnect sequence allows you modifying the built-in standard disconnect sequence for stop bins. This disconnect sequence is defined by firmware commands in a file that must be named disconnect.user_def and placed in the folder testfunc of your device directory.

    In contrast to the standard disconnect sequence, the user-defined disconnect sequence does not distinguish between shared and non-shared pins and uses only the pin identifier that is defined in the file. To avoid the pass or fail site dependency, it may be necessary to define the user-defined disconnect sequence only for non-shared pins and manually apply a disconnect sequence for the shared pins only at the end of the test flow.

  • Special test suite bin_disconnect

    The special test suite bin_disconnect is a solution to deal with different hardware setups of a test flow within one test method class. This special test suite can only be used in combination with a test method that defines a conditional disconnect sequence. The assigned test method is programmed using test method APIs.

  • Multibin SmartDisconnect test suite

    The Multibin SmartDisconnect test suite is a combination of a multibin node and a user defined test suite. Like a multibin node, the Multibin SmartDisconnect test suite is inserted into the fail branch of a Run and Branch test suite. A custom disconnect sequence adapted to the needs of the failed test suite can be implemented using test method APIs or SmartRDI-based code.

    Multiple different Multibin SmartDisconnect test suite can be integrated to handle different hardware setups of the test flow.

    The Multibin SmartDisconnect test suite is the recommended solution for new device test programs.

The common behavior of the disconnect sequences is that in the fail branch of a run and branch test suite they are executed only for the failing site. In the pass branch they are executed for the remaining sites.
