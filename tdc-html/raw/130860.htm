Structure of an STPM control file

The STPM control file contains commands and setting for SmarTest Program manager (STPM) to use in a conversion. It's structure follows the conventions of the Python programming language.

The STPM control file can contain these settings and commands:

  • Setting specifying files:
    • mtp_device_testflow
    • mtp_template_dir
    • merge_rules
  • Settings defining the environment:
    • ate_model
    • ate_target
    • ate_version
  • Other settings:
    • enable_backup
  • Commands for writing master test programs (MTPs):
    • write_tp
  • Integration commands:
    • add_test
    • add_burst
    • add_test_to_burst
    • add_empty_test_group
    • remove_test
    • replace_test
    • remove_label
  • Commands for creating and modifying test program templates (TPTs):
    • tpt_generate_template
    • tpt_import_from_device
    • tpt_generate_device_dir
    • tpt_merge
  • Commands for working with MTPs using TPTs:
    • tpt_add_test
    • tpt_replace_test
    • tpt_generate_tp
    • tpt_compare_tp
    • tpt_generate_test_stages
  • Collaboration support commands
    • extract_subflow
    • merge_subflow
    • remove_subflow
  • Clean-up commands
    • clear_duplicated
    • clear_unused
      Note STPM control files are Python files and as such support all standard conventions of the Python programming language. You can therefore use the usual programming constructs like conditional statements or loops. Describing these constructs is beyond the scope of this manual. If you require information about them, please see appropriate Python documentation.

Order of statements

The order of the integration and MTP write commands in the file determines in which order STPM works on the test suites to integrate or remove them and what states get written to disk.

Bins and test types must be defined before they can be used.

The order of the settings is not important.

Comments

You can add comments to the control file by beginning a line with #.

Example

Sample control file with support for test methods and binning:

############################## 
# Input: Device Test Program Location  
##  

##############################  
# Configuration  
##  

# Master Test Program (MTP) device path
mtp_device_testflow = '/home/user/93K_Device/project.tf'

# Merge Rules file.  
merge_rules = '/home/user/setup/merge_rules.py'  

##############################  
# Integration Commands  
##  

add_test(  
    test_flow_file = './home/user/new1_93k/testflow/test.tf', # Link to new test flow file  
    test = 'test_n1' # test name  
    )  
add_test(  
    test_flow_file = './home/user/new2_93k/testflow/test.tf', # Link to new test flow file  
    test = 'test_n2', # target test name  
    position = 'first',  
    lev_reuse = 'auto'
    )
  
##############################  
# Output: Device Test Program Location  
##  

# Write Master Test Program (MTP). 
write_tp = '/home/user/93K_Device/project.tf'

Functional changes

  1. Introduced in SmarTest 7.0.4
  2. SmarTest 7.2.1: Added the add_burst, add_empty_test_group, remove_label, tpt_generate_template, tpt_import_from_device, tpt_generate_device_dir, tpt_merge, tpt_add_test, tpt_replace_test, tpt_generate_tp, tpt_update_tp, tpt_compare_tp, tpt_generate_test_stages, extract_subflow, merge_subflow, and remove_subflow commands.
  3. SmarTest 7.2.1: Removed read_tp, define_test_type, and define_bin_type commands.
  4. SmarTest 7.2.1: Added mtp_device_testflow and mtp_template_dir settings.
  5. SmarTest 7.2.1: Removed tpt_master_file setting.
