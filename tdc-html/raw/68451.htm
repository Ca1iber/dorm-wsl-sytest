Variables

MTL variables are basically like C variables but with some key differences and limitations.

The differences and limitations are the following:

  • Variables do not need declarations before usages. Once they are first assigned Values, they achieve data types the same as the values'. After the initialization, only the value of the same data type or the compatible data type can be assigned to the variable.
  • Data types of the MTL variables:
    • In the .prog file, variables can be integers (normally signed 64 bits, to specify other bit length, see Expressions with more than 64 bits), Boolean values, or strings.
    • In all the other files, variables can only be integers (normally signed 64 bits, to specify other bit length, see Expressions with more than 64 bits) or floating-point numbers existing in the APG pattern file (and files that are imported into the pattern file using #include). See "Floating-point values", below, for details.
  • For rules on naming variables, see Naming rules and conventions.
  • For the usage and scope of global variables, see "Global variables", below.

Floating-point values

While variables normally contain only integer numbers, they can contain floating-point values in the APG pattern file. To specify a floating-point value, enter a number with a decimal point, for example:

:programParam:
{
  :format:
  { :name:  :value: }
  { tCK     3.75    }
}

When variables containing floating-point values are passed to the APG program file or other files, they are truncated. For example, if a variable is assigned the value 3.75 in the APG pattern file, it has the value 3 in the APG program file. A value of -3.75 becomes -3.

The truncation is performed automatically and does not generate any notification.

Floating-point variables cannot be combined in one expression with values greater than 64 bits. Shift, Boolean, and increment operations as well as the index operator are not available for floating-point numbers.

Global variables

Variables that are defined outside of any program routine (main() or subroutine) are global variables. Some special considerations apply:

  • Global variables are in scope for all subroutines.
  • Changes to the values of global variables are also global in scope, that is, changing the value inside a subroutine changes it outside of that routine as well.
  • Global variables cannot be used before they are defined.
  • Global variables can be defined in files that are imported with #include (for example, header files).
  • Global variables cannot be assigned new values outside of routines, that is, there must not be two definitions of the same global variable. New values can be assigned to global variables normally inside routines.
  • Subroutine parameters having the same name as a global variable override the global variable inside their subroutines. That is, all references to that name are considered to refer to the parameter, not the variable.

    In effect, a global variable is unknown in any subroutine having a parameter of the same name.

  • Global variables cannot be used in padding routines or maintenance operations.
  • Global variables are always updated in the standard way of C variables when they are used within loops (that is, they retain any changes in value for the next iteration, as opposed to being reset to the value they received in the first iteration). In other words, global variables always behave as if the Extend Variable Scope option (or -evs command line option) was set, even if the Limit Variable Scope option (or -lvs command line option) is used.
