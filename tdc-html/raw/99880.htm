Sequencer instructions

The vector sequencer has its own set of instructions which you use to control the execution of your test. The default instruction is GENV (GENerateVectors) for every vector, but the system does not display it and you do not have to enter it.

List of sequencer Instructions

Instruction

Explanation

BRKV <nbr_of_vectors> <wait_time>

Generates break vectors.

  • <nbr_of_vectors> specifies the number of break vectors. If not divisible by 8, it will be rounded up to the next multiple of 8. Range from 1 to 32760.
  • <wait_time> specifies the wait time in nanoseconds. SmarTest generates the appropriate number of break vectors to fill the interval. The parameter determines the lower bound; the actual wait time may be longer. The range of the <wait_time> is from 0 to 5592402.

CALL <pattern_name>

Calls a main pattern. Can only be used in bursts or multiport bursts.

CLEV <level_set_number>

Changes the level set.

Parameter <level_set_number> specifies the new level set number. You can also use PRM, which specifies the primary level set.

COGO (<pattern1> | <none>) <pattern2>

The "conditional go to" instruction is similar to the JMPE instruction. There are two differences:

  • COGO can only be used in SVEC subroutines.
  • When a subroutine is called with COGO, the called subroutine will not return to the calling subroutine, but to the lowest label in the call hierarchy that did not use COGO for its subroutine call.

If, for example, the MAIN label pat1 calls the subroutine sub1 with JSUB, and sub1 calls sub2 with JMPE, then sub2 will return to sub1. But if sub2 is called with COGO from sub1, then sub2 will return to pat1.

The reason for this is that the return address for a COGO call is not pushed onto the call stack. Note that this can be exploited to create an infinite loop by letting sub1 call sub2 with COGO, and letting sub2 in turn call sub1 also with COGO. By contrast, such a mutual call will lead to a stack overflow when JMPE is used for the calls.

The parameters are defined as follows:

  • <pattern1> will be executed if the error flag is set1).
  • <pattern2> will be executed if the error flag is not set 1).

CTIM <tming_set_number>

Changes the timing set.

Parameter <timing_set_number> specifies the new timing set number. You can also use PRM, which specifies the primary timing set.

FLQU

Inserts fill break vectors into the data queue.

JMPE <pattern1> <pattern2>

Executes a conditional jump to a vector type subroutine depending on an error flag. If both parameters are specified:

  • <pattern1> will be executed if the error flag is set 1).
  • <pattern2> will be executed if the error flag is not set 1).

Both parameters are optional, but the first cannot be simply omitted. You must specify the placeholder <none> in this case.

The error flag will be set if at least one cycle failed. It will be reset after the instruction has been executed.

JPPS <pattern_name>

Jumps to a pin specific subroutine.

JSUB <pattern_name>

Jumps to a vector type subroutine or a scan subroutine.

Not allowed in scan subroutines.

JTIN

Starts or stops the jitter injection. Parameters are START or STOP.

LOOP <repetitions>

Specifies the start position of a loop (counted or endless).

The loop is endless, if <repetitions> is set to 0 or omitted.

The size of the loop is determined by the current selection.

Use RPTV instead of a counted loop whenever possible. Counted loops are considerably slower than RPTV.

LOOPEND

Specifies the end of a loop. The instruction is inserted automatically.

LPBK <nbr_of_vectors> <factor>

Starts a loopback. Can only be executed if no user vectors are executed before this instruction.

Two optional parameters are available: <nbr_of_vectors> and <factor>:

  • <nbr_of_vectors>defines the number of generated vectors; the maximum is 232-1.
  • <factor> is an optional multiplier for the first parameter; the maximum is 212-1.

If both parameters are omitted the loopback will run until manually stopped.

MACT <repetitions>

Specifies the start position of a counted match loop.

Parameter <repetitions> specifies the maximum number of unsuccessful repetitions. If this number is exceeded, the match loop is terminated, and the surrounding test fails.

MACT has a second optional parameter:

  • CONTINUE: This option keeps the test going on even if the loop fails.

  • TIL_FAIL_STOP: The loop is to be repeated until an iteration fails. When the maximum loop count is reached, the test program stops.

  • TIL_FAIL_CONT: The loop is to be repeated until an iteration fails. When the maximum loop count is reached, the test program continues after the loop has been completely executed. This behavior is a combination of both TIL_FAIL_STOP and CONTINUE.

Note The two values TIL_FAIL_STOP and TIL_FAIL_CONT are valid for Smart Scale cards only.

MEAS <ppmu_set> <measure_set> N

Executes a PPMU measurement set. The measurement set must have been downloaded with command MSET, MSET? - (definition of Measurement SET).

MRPT <nbr_of_vectors>

Marks the end of a counted match loop.

Parameter <nbr_of_vectors> specifies the number of the dummy vectors that are repeated to provide the necessary time for setting the error flag.

NOP

Performs no operation on the DUT and increases the instruction density for the data queue.

PRBS  <nbr_of_cycles> <factor>

Starts a PRBS test.

  • <nbr_of_cycles> defines the number of cycles; maximum is 231-1.
  • <factor> is a multiplier of the first parameter; maximum is 212-1.

A pattern that contains a PRBS instruction must not contain any other instruction except BRKV, LOOP, LOOPEND, and TMUA.

RETC  <dependency> <reset>

Returns from a vector type subroutine to a higher level subroutine or the main program, or from a scan subroutine to the main program depending on an internal error flag. The error flag will be set if at least one cycle failed.

See also the parameter description in SQPG, SQPG?.

  • <dependency> = 0: The return will be executed, if no error occurred.

    <dependency> = 1: The return will be executed, if an error occurred.

  • <reset> = 0: The error flag will be reset.

    <reset> = 1: The error flag will remain in its current state.

Note If you use the LMAP error map mode, FLBL ignores the RETC clearing flag for failures.

RETURN

Returns from a vector type subroutine to a higher level subroutine or the main program, or from a scan subroutine to the main program.

RPTJ <repetitions>

Repeats the next JSUB instruction <repetitions> times. The JSUB instruction must follow the RPTJ instruction immediately.

Not allowed in scan subroutines.

RPTV <nbr_of_vectors> <repetitions>

Repeats a block of vectors.

  • Parameter <nbr_of_vectors> specifies the number of vectors to be repeated. The maximum is 221  * 8 - 1 for the sequencer memory [SM] or 221 * 7 - 1 for the legacy vector memory [VM].
  • Parameter <repetitions> specifies the number of repetitions. The maximum value depends on whether the number of vectors, which is defined by the first parameter, exceeds the word length of the respective memory type (8 for SM, 7 for VM):
    • The maximum <repetitions> is 224  - 1 if <nbr_of_vectors> does not exceed the word length.
    • The maximum <repetitions> is 218 if <nbr_of_vectors> exceeds the word length.

Valid range of <repetitions> for memory type SM:

<nbr_of_vectors> = 1 ... 8: 1 ... 16 777 215
<nbr_of_vectors> = 9 ... 16 777 215: 1 ... 262 144

RPTV #  <repetitions>

Repeats a sequence of vectors. The first parameter #, which defines the number of vectors, is predefined by the current selection.

SRCV  <block_size> <repeats>

Instructs to perform different actions on source pins and non-source pins.

SSRC  <pattern_name>

Sets the source memory pointer to the specified DSRC pattern.

Not allowed in subroutines.

STOP

Stops the pattern. Must be present in each main pattern.

TMUA

Arms the TMU per pin for all pins of the pattern port.

WAIT <nanoseconds>

Causes the sequencer to create a number of break vectors, which approximates the specified number of nanoseconds. The range is from 0 to 5592402.

Note The WAIT instruction cannot be used on DC Scale cards.

XACT <waveform_name>

Executes a DC waveform.
Note When the Fast Sync feature is configured on the Smart Scale cards, smaller number of vectors are needed for error propagation. EPRC? - (Error Propagation Repetition Count) can be used to determine the impact. Sequencer programs using COGO, JMPE, RETC, MACT and MRPT can profit from it.

Functional changes

  1. SmarTest 6.5.2: Additional sequencer instructions: RPTV 1, SSRC, SRCV.
  2. SmarTest 6.5.2: Removed sequencer instructions: MATCH, MATCHEND.
  3. SmarTest 7.0.3: Removed MTST instruction
  4. SmarTest 7.2.0: Removed Match loop (old style) instructions (eg. WTER,MBGN,MJPE). Additional sequencer instructions: XACT, TMUA, PRBS.
  5. SmarTest 7.4.0: New feature Fast Sync enables COGO, JMPE, RETC, MACT and MRPT to run faster.
  6. SmarTest 7.4.4: MACT supports CONTINUE as a parameter option.
  7. SmarTest 7.5.0: MACT supports TIL_FAIL_STOP and TIL_FAIL_CONT as parameter options.
1) The sequence of the two parameters is different for the SQPG command and the Sequencer instructions of the pattern editor: command SQPG utilizes the sequence "param_1 = label if error flag is not set" and "param_2 = label if error flag is set" for the two instructions COGO and JMPE; the reversed sequence "<pattern1> = error flag is set" and "<pattern2> = error flag is not set" is used for the two sequencer instructions COGO and JMPE of the pattern editor.
