TRANSACTION_RESULT_PROXY

Objects of the TRANSACTION_RESULT_PROXY class serve to hold the results of capture transactions within a protocol wrapper test (for which see Protocol wrapper and Protocol wrapper API). If you want to utilize result proxies with a protocol wrapper class, you must inform SmarTest accordingly when you create the wrapper class. SmarTest will then define the signature of the capture actions in such a way that they can (and actually must) be connected to a result proxy for result processing. The connection is established by means of a copy constructor or an overloaded assignment operator of the TRANSACTION_RESULT_PROXY class.

If a transaction has only a single result parameter, the proxy can directly be converted to an INT or STRING result. If multiple parameters have been captured in the transaction, the proxy provides access to the results either by an index corresponding to the order of the parameter declarations in the protocol definition, or by the parameter name.

Multisite handling

If the enableBulkUploadMode() member function of the PROTOCOL_TEST class is set to TRUE (which is the default), the capture results are uploaded for all sites in parallel into a cache on the workstation by the first call of the proxy; all later calls within the same test method access this cache. This is independent of whether or not the first call is placed within the ON_FIRST_INVOCATION block. If enableBulkUploadMode() is set to FALSE, the proxy only returns the result of the site that has the query focus; in this case, the first call must be placed outside the ON_FIRST_INVOCATION block.

Constructor

TRANSACTION_RESULT_PROXY();

Creates an empty result proxy object that is not associated to a protocol test when instantiated. Only when assigned from the return value of a transaction or from a result vector, the object can be used to access result data.

TRANSACTION_RESULT_PROXY(const TRANSACTION_RESULT_PROXY&);

This is a copy constructor which creates a new result proxy object and initializes it by reference to an existing proxy object. In particular, if the capture transactions of a wrapper class have been prepared for result proxies, this existing object can be the return value of such a capture transaction.

Overloaded operators

TRANSACTION_RESULT_PROXY& operator=(const TRANSACTION_RESULT_PROXY&);

This overloaded assignment operator assigns the data of a result proxy to an existing result proxy. In particular, if the capture transactions of a wrapper class have been prepared for result proxies, the source object can be the return value of such a capture transaction. In this case the results of the transaction can be accessed from the target proxy after execution of the test.

operator UINT64() const;
operator STRING() const;

These overloaded conversion operators return the data of a result proxy either as an integer (UINT64()) or as a hexadecimal string (STRING()). These functions can only be used for the first captured parameter of a transaction or if the transaction returns only one result parameter. In this case the returned result proxy can directly be converted.

If the associated test was not executed or the result is not accessible for other reasons, an exception will be thrown.

const TRANSACTION_RESULT_PROXY& operator[](int index) const;
const TRANSACTION_RESULT_PROXY& operator[](const STRING& paraName) const;
Parameters

I/O

Parameter

Description/Range

I

index

Index of parameters captured.

Valid DC/DC power units will be 0 through size()-1.

I

paraName

Name of capture parameter.

Navigates to the data of a specific captured parameter (usually only needed if more than one parameter are captured).

The first signature expects an index corresponding to a capture parameter in the order of the parameter declarations in the protocol definition. The second signature navigates by parameter name (paraName), which is more convenient but slower than the index.

The result of these operations can then be converted to a integer or string value representing the actual result value.

Parameter

format

Specifies the format of the returned string.

Possible formats are:

TM::HEX hexadecimal literal prefixed with 0x

TM::BIN binary literal prefixed with 0b

TM::SCS the captured bits without any prefix

TM::SYMBOL symbolic value, if the parameter was set up with symbolic values

Returns the actual result that this proxy represents as a string value in given format.

If the associated test was not executed or the result is not accessible for other reasons, the method will throw an exception.

Example

This example illustrates how to use the name of an output parameter (data) that has been used for capturing to retrieve the result data and display it at the system console.

Protected:
TRANSACTION_RESULT_PROXY ID1;
TRANSACTION_RESULT_PROXY ID2; 
. . .

CustomMDIOWrapper_SYNC_TEST mdioReadParameter("poMD", "", "", "SingleCaptureWrapper");

ON_FIRST_INVOCATION_BEGIN();
   ID1 = mdioReadParameter.read(17, 3);
   mdioReadParameter.write(17, 11, 0xAA11);
   mdioReadParameter.write(17, 11, 0xD431);
   ID2 = mdioReadParameter.read(17, 3);
   mdioReadParameter.run();
ON_FIRST_INVOCATION_END();

cout << "CURRENT SITE " << CURRENT_SITE_NUMBER() << endl;

// specify the parameter name
STRING parameterName("data");

// scan for the parameter name given above
// and print it to the system's console
cout << "-> MDIO_Capture Read ID1 of 'data': " << hex << ID1[parameterName] << endl;
cout << "-> MDIO_Capture Read ID2 of 'data': " << hex << ID2[parameterName] << endl;
