Topic 16757

Merging the testflows

Subtopics

  1. Source and target testflows

About this task

Purpose of merging testflows

Setting up a complete testflow is a major part of the whole test program development process. Reusing testflow elements can significantly shorten the time to develop a new testflow as well the time needed to modify an existing one.

Merging testflows takes elements from one or more existing testflows and reuses them in another testflow. By merging testflows, you can speed up testflow development and decrease your overall test program development time considerably.

This is particularly true when you have to set up a testflow for a new device of a device family. Devices of a family typically share large parts of the testflow. Once set up, these parts can be reused for new members of the device family.

Tools

SmarTest offers the following tools for merging testflows.

Flow Sequence Editor

With the Flow Sequence Editor, you can:

  • Merge all types of testflow elements.
  • Merge testflow elements at any position in the target testflow.
  • Use the full range of Testflow Editor functions for the target testflow. For example, the target testflow, or any of its test suites, can be executed at any time to check the merged results. Modifications can be made instantaneously, if required.

ASCII Interface

Can handle a large amount of data.

It provides full control of the merging process, optimizes the use of timings and waveforms, and can merge vectors.

This topic describes merging the testflows with the Flow Sequence Editor.

Before you begin

Make sure that a testflow has been loaded. This testflow is the target testflow.

Procedure

  1. In the Test Program Explorer view, right-click the testflow item and select Open testflow to merge.
  2. A window opens. In this window, select the testflow you want to merge and then click OK. This testflow is the source testflow.

    Another Flow Sequence Editor for the source testflow opens. This editor only shows the testflow sequence and does not contain a palette.

    You can open a number of source testflows by repeating this step.

  3. Select one or more testflow elements in the source testflow. Copy them and paste them into the target testflow. All settings of the nodes are copied along with them.

    If a copied testflow element uses a variable which does not exist in the target testflow, SmarTest opens the Add New Variables window.

    In the window SmarTest shows the missing variables and their values, which SmarTest would create in the target testflow.

    • Do not ask me again, add those variables automatically: Select this option if you want that SmarTest does not show this window anymore, and it shall copy the testflows and create the missing variables without further notice. You can configure this behavior on the Testflow Tool preferences page.
    • OK.: SmarTest copies the testflow element and creates the variables, taking their default value from the source testflow as initial value in the target testflow. If the values of the new created variables are not valid, you can correct them manually in the next step.
    • Cancel: SmarTest does not copy the testflow element and does not create the variables in the target testflow.
  4. If the values of the new created variables are not valid, correct them manually.
  5. If the primary settings of the merged test suite are invalid in the target testflow, you need to correct them manually.

    For example, the merged test suite DC_test uses the timing spec "12 f=20MHz". In the timing setup file, which is used for the target testflow, is no spec numbered 12. So the timing spec is invalid and its entry in the Test suites page highlighted in yellow. You need to select an existing timing spec for this test suite.

  6. Save the target testflow.

Results

The elements of source testflow have been merged to the target testflow.

What to do next

You can modify the target testflow as you desire.
