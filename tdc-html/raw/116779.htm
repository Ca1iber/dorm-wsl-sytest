Topic 116779

Pattern matching

Subtopics

  1. Startup latency and initial synchronization
  2. Skipping idle tokens

The result of the transition tracking is a stream of data bits. This stream is passed on to the pattern matching block of the protocol engine. The pattern matching block compares the received bit stream with the expected data in order to

  1. detect the start of meaningful data in the received bit stream, and then
  2. check if the meaningful received data match the expected data.

For the first, preparatory, task, it tries to find a match for a start segment of the expected data in the received data. The step width of this search is 1 data bit, that is, when the segment has length n, and the first n received bits do not match, then the n received bits starting with bit 2 will be compared, and so on until a match is found or a timeout occurs.

The operation mode for the second task depends on the token size. Tokens are bit sequences of fixed length. The token length can be defined by the user (for more information see Skipping idle tokens).

If the token size is 0, then expected and received data will be compared bit by bit, as in a standard digital test. If the token size is > 0, then then the expected tokens will be successively compared with the received tokens. In this case the step width is one token, that is, if the token length is n, and the first received token does not match the first expected token, then the complete received token will be skipped, and the first expected token will next be compared to the second received token. This is repeated until a match is found or a timeout occurs. If a match is found the same process will be applied to the second expected token, and so on.

Functional changes

  1. Introduced in SmarTest 7.0.1
