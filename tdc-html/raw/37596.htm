The State Mapping Tables for the Scan Tool

The scan tool of SmarTest displays the scan vectors in terms of state characters, and when you want to change a scan vector, you must modify these state characters. The scan tool therefore needs a table by which it can translate the physical waveform DC/DC power units for the scan pins into state characters and vice versa. The function of this mapping table is comparable to that of the base wavetable for the pattern tool.

Another purpose of the mapping table is to inform SmarTest of the x-mode factor for the scan vectors. This must be communicated in some way because the SCAN instructions of the sequencer program specify the length of the scan instances through the scan templates, and the template length is always defined in terms of state characters, not waveform DC/DC power units. If the x-mode factor for the scan vectors is 2, then the entries of the state mapping table associate 2 state characters with one waveform index. For a template length of 10, SmarTest can thus infer from the mapping table that an instance of this template must consist of 10/2 = 5 waveforms.

Different templates can be associated with different mapping tables. The tables are defined with the firmware commands SMDE and SMDU, and are then connected to a template by specifying the table name in the DFST command.

The ASCII interface creates these commands from the ASCII device cycles that are associated with the templates in the scan instances of the ASCII vector file. It assumes that every template is associated with only one ASCII device cycle, and accordingly takes the mapping information from the timing map file entries for the ASCII device cycle that is associated with the first instance of the respective scan template. The table name is derived from the name of the ASCII device cycle.

Note Previously, it was not possible to associate different state mapping tables with different templates. Rather, all templates used the same state mapping table. This is still the default of the ASCII interface. If you want to activate the new flexible functionality, you must call aiv with the option -d, and v2b with the option -is.
