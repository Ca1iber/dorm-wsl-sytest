CSAS? - (Channel Slot Accumulated Status)

The CSAS? query reads and clears the internal status flags of the DPS128/64 or XPS256 pins. The flags are not cleared by a connect or disconnect sequence.

The query returns either a hex value or a pass/fail (P|F) result. The hex value must be translated into binary form to interpret the status. The result will show any bits that have been set on tests performed since the previous execution of the query. It is not reset by a connect or disconnect sequence.

Note The CSAS? (Channel Slot Accumulated Status) query is supported by DPS128/64 and XPS256 DC Scale channels in DPS operating mode, in PMU operating mode, or (if supported by the card) in Digital I/O operating mode.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Note

Pass/fail results that are retrieved by command PRLT are invalidated by commands CSAS and PSAS.

We recommend therefore using the command PRLT directly after the related functional test and before command CSAS or PSAS are performed.

This behavior applies not only to the commands but also to the related APIs: Function GET_FUNCTIONAL_RESULT() must be performed before any of the DPS_AUX_PIN_TASK.check...() functions is called or the results of GET_FUNCTIONAL_RESULT() are invalid.

Any read status bits are cleared after the CSAS? query. If the mask parameter is specified, only the flags selected by the mask parameter are cleared. The status is then accumulated again, until the next CSAS? query. The flags are not cleared by a connect or disconnect sequence.

Syntax

CSAS? [msMode,] {mask}, {(pinlist)}

returns:

CSAS {status}, {(pinlist)}

Parameters

msMode The extra parameter controls how the return value is created.

The value of the parameter can be PQFC:

  • PQFC specified: The current query focus is respected and allows status query per site without affecting status bits of other sites.
  • PQFC not specified: The command reads (and clears) status bits of all enabled and active sites at a glance, ignoring the actual query focus.
The parameter applies only to use of parameter mask as integer value.

mask

 Integer bit mask or ALL.

  • Integer bit mask: Integer value is used to mask out individual status bits. Each bit of mask is logically AND-ed with the corresponding bit of the DPS status. If one of the resulting bits is set, then F (Fail) is returned, otherwise P (Pass).

    It is used to check for an error condition. All bit positions of the status flags that should be checked, must be set to 1 in mask. If one of the selected status bits is set, then CSAS? returns F.

  • ALL: Hex value (hexadecimal representation of all status bits) is returned.
For setting the integer bit mask or interpreting a returned hex value, refer to the status parameter below.

pinlist

Comma separated list of DPS128/64 or XPS256 pins. The @ character can be used to read the status for all DPS pins.

status

 If mask is ALL, you need to translate the hex value (hexadecimal representation of the status bits) to its binary form as follows:
Bit 0: High voltage or current of surge tracker exceeded
Bit 1: Low voltage or current of surge tracker exceeded
Bit 2: 0
Bit 3: Measurement range change failed
Bit 4: Clamp current correction failed
Bit 5: Battery full
Bit 6: Power budget 1
Bit 7: Power budget 2
Bit 8: Power budget 3
Bit 9: High voltage of surge tracker reached
Bit 10: Low voltage of surge tracker reached
Bit 11: High current of surge tracker reached
Bit 12: Low current of surge tracker reached

If mask is specified as an integer bit-mask:

  • Pass: P
  • Fail: F

DPS flag implementation

The implementation of the flags differs for the various DPS cards, that is, various cards do not support every flag.

Bit Flag DPS128/64 XPS256
0 High voltage or current of surge tracker exceeded + +
1 Low voltage or current of surge tracker exceeded + +
3 Measurement range change failed + +
4 Clamp current correction failed + -
5 Battery full - -
6 Power budget 1 - -
7 Power budget 2 - -
8 Power budget 3 - -
9 High voltage of surge tracker reached - +

12 Low current of surge tracker reached - +

Examples

Example 1: 

CSAS? 3,(VCC)

returns either

CSAS P,(VCC)

or

CSAS F,(VCC)

The example uses the integer bitmask and checks whether a spike on the VCC pin exceeded the low or high limit.

  • P = Pass

    No spike occurred since the last CSAS? query.

  • F = Fail

    Either the low or high limit or both were exceeded.

Example 2: 

CSAS? ALL,(Vaux)

returns

CSAS #H10,(Vaux)

The example uses the ALL specifier and checks for an error condition on the Vaux pin.

  • Bit 3 = 0

    No "Measurement range change failed" error. All set current measurement range requests were successful.

  • Bit 4 = 1

    The "Clamp current correction failed". A high-accuracy clamp current correction for a DCVH setup with execution mode SER_HAC or PAR_HAC was not successful.
