Using concurrent (multiport) testing

CCT, or concurrent test, is the V93000 test system's capability to test in parallel different groups of pins, called ports. This multiport feature makes test programming easier and more DUT oriented. Using multiport testing, it is possible to program each port separately, just like the DUT ports may operate independently of each other.

STIL Reader supports the multiport capability as follows:

  • Using NameMaps definitions in the STIL file:

    <signal_name> "port=<port_name>, sync_group=<sync_group>, master_clock=<clock_domain>, xfact=<x_factor>, type=<port_type>, specs_scope= <specs_scope>, keep_spec_variables=<keep_spec_variables>, phase_sync=<phase_sync>, scan_repeat_compression=<scan_repeat_compression>, pattern_comments=<pattern_comments>, extra_pattern_comment=<extra_comment>, card=<card>"

    The individual options have the following meanings:

    • port: The port name.
    • sync_group: The synchronization group.
    • master_clock: The clock domain. This is relevant only if the generate_clksets setup parameter is set to 1.

      For SmarTest 7.10x, the master clock is fixed.

    • xfact: The x-mode to use. This parameter overrides the xmode_factor setup parameter.
    • type: The high-speed channel handling. This parameter can be left empty, set to hx, or set to fast.
    • specs_scope: Can be set to global or to local, to create global (for all ports) or local (per-port) specs tables, respectively.
    • keep_spec_variables: Can be set to 0 or 1. If the parameter is set to 1, unused spec variables will be kept; if it is set to 0, they will be dropped. This parameter overrides the keep_spec_variables setup parameter.
    • phase_sync: Can be set to on or off to (respectively) enable or disable phase synchronization. The default is on.
    • scan_repeat_compression: Can be set to 0 or 1 to (respectively) enable or disable the compression of certain vectors. See the description of the repeat_compression parameter for details. The default is 0.
    • pattern_comments: Can be set to on or off to (respectively) enable or disable the preservation of any comments contained in the STIL pattern. The default is on.
    • extra_pattern_comment: An optional text that is a comment just for this port. The text is appended as a comment to the first vector for the port.

      The default is no comment.

    • card: The specific test system for which this translation is intended. Currently, the only supported option is PS1600.

      Example signal specification:

    Sig1 "port=Clock,sync_group=SyncGroup1,master_clock=1,xfact=1,specs_scope=global,keep_spec_variables=1,phase_sync=off";
  • Using the ParallelPatList STIL construct in a pattern burst. When ParallelPatList is used in a pattern burst, the STIL Reader creates a multiport setup.

Position-based syntax

Instead of specifying the desired options with named settings, as described above, you can also use a position-based syntax. In this case, you simply specify the desired parameters in the order given above, separated by commas, but omit the keywords. If you want to omit a setting, you simply leave the space between the two commas empty (but must include the commas).

In this syntax, the example given above would be: 

Sig1 "Clock,SyncGroup1,1,1,,global,1,off,,,,";

Because this syntax is more difficult to read and error-prone, we recommend that you use the named parameters described above.

Port names

When you are define the ports using NameMaps, you are defining the port name explicitly.

When you are using ParallelPatList, port names are created automatically using the pattern port1, port2, and so on, based on the order of patterns defined in the ParallelPatList object.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.2.1: Added port type fast.
  3. SmarTest 7.2.1: Added phase-sync parameter.
  4. SmarTest 7.2.2: Added scan_repeat_compression, pattern_comments, and card parameters.
  5. SmarTest 7.2.3: Added extra_pattern_comment parameter.
