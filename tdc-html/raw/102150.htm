APG pattern file syntax

The syntax of the APG pattern file, in general, follows the conventions of the MTL compiler syntax.

Specifically, an APG pattern file looks like this:

:apgPattern:
{
[ :version:            <patternVersion>]
[ :defines:
    {
        :format: 
        { :name:         :value:        }
        { <macroName><macroValue>   }
...
    } ]
[ :options: <cmdLineOption> ]
    :deviceAccess:       <deviceAccessFile>
    :apgProgram:         <programFileFile>
    :deviceArchitecture: <architectureFile>
[ :dcTest:             <DC_eventFile>:<dcSetName>]
    :pinMap:             <pinMapPath>
    :waveformMap:        <waveformMapFile>|<timingFile>:<wavetableName>
[ :pinConfig:          <pinConfigFile>]
[ :modeContext:        <modeContextName>]
    :nullData:           <nullDataValue>
[ :scramble:           <addressScramblingTableName>]
[ :bitInversion:       <bitInversionTableName>]
[ :bitOrdering:        <bitOrderingTableName>]
[ :crc:                <crcSetting>]
[ :dbi:                <dbiSetting>]
[ :maintenanceOperation: <maintenanceOperationName>]
[ :countedMatchPad:    <matchLoopPaddingName>]
[ :timing:
    {
        :file:           <timingFile>
        :eqns:           <equationSet>
        :tims:           <timingSet>
        :spec:           <specSet>
    } ]
[ :testLabel:          <testLabelName>[ (<ppinLabelList>) ]]
[ :programParam:
    {
        :format: 
        { :name:         :value:        }
        { <paramName><paramValue>   }
...
    } ]
}

The order of keywords shown above is typical, but not required; you can rearrange the keywords within a set of curly braces as desired.

Italic text indicates meta-syntax, as described in Syntax conventions.

Keywords and parameters

These are the keywords and their parameters in alphabetical order:

Keyword

Parameters and descriptions

:apgPattern:

This keyword is required at the start of the file.

:apgProgram:

<programFile>: The path (relative to the active directory) and name of the APG program file.

:bitInversion:

<bitInversionTableName>: The name of the bit inversion table to be used, as it is specified in the Device architecture file.

If no bit inversion is to be used, enter a tilde (~).

This keyword is optional; it is required only if bit inversion is to be applied.

:bitOrdering:

<bitOrderingTableName>: The name of the bit ordering table to be used, as it is specified in the Device architecture file.

If no bit ordering is to be used, enter a tilde (~).

This keyword is optional; it is required only if a bit ordering table is to be applied.

:crc:

<crcSetting>: A named CRC setting from the Device architecture file that is to be used whenever the crc macro is called.

To disable CRC calculation (causing the crc macro to always return its default value), enter ~ as the <crcSetting> parameter.

This keyword is optional; it is required only if CRC values are to be calculated.

:dbi:

<dbiSetting>: A named dynamic bus inversion setting from the Device architecture file that is to be used whenever the dbi macro is called.

To disable dynamic bus inversion, enter ~ as the <dbiSetting> parameter.

This keyword is optional; it is required only if dynamic bus inversion is desired.

:dcTest:

<DC_eventFile>: The path (relative to the active directory) and name of the DC event file.

<dcSetName>: The DC event set from the specified DC event file that is to be used.

This keyword is optional; it is required only if DC events are to be used.

:defines:

Text macros that can be used in the APG pattern file and other MTL configuration files (but not SmarTest configuration files).

The value of this keyword is a :format: table in which the actual macros and their values are specified. The keywords available in this table are described in Preprocessor statements.

Note that the values of these macros can be overwritten from the command line using the -D option of the apgc command or the Overwrite an Existing MTL Define option in the MTL compiler control dialog.

:deviceAccess:

<deviceAccessFile>: The path (relative to the active directory) and name of the Device access file.

:deviceArchitecture:

<architectureFile>: The path (relative to the active directory) and name of the Device architecture file.

:maintenanceOperation:

<maintenanceOperationName>: The name of the device maintenance (refresh) operation to be used. An operation with that name must have been defined in the Device architecture file.

This keyword is optional; it is required only if a device maintenance operation is to be used.

:modeContext:

This keyword should no longer be used; it is supported only for backwards compatibility. We recommend that you use the using modecontext statement in the Pin mapping file instead.

<modeContextName>: The name of the context in which the test is to be executed.

The named context must be specified in the SmarTest timing equation set and wavetable.

This keyword is optional; it is required only if Automatic waveform generation is desired.

:nullData:

<nullDataValue>: The null data value, specified as a decimal number or, prefixed with 0x, a hexadecimal number.

To use the default null data value (a logical zero), enter a tilde (~).

:options:

<cmdLineOption>: The command line options with which this file is to be compiled.

Enter the command line options exactly as you would for the apgc command and enclose them in quotes. For example:

:options: "-m -e 256"

You can use any command line option except -D.

If you specify options in the APG pattern file using the :options: keyword, they override any options that are specified for the compilation of the file using the apgc command as well as any option-equivalent settings in the compiler control dialog. That is, if options in two locations conflict, the one specified in :options: is used.

For details about the available command line options, see apgc command syntax.

:pinConfig:

This keyword should no longer be used; it is supported only for backwards compatibility. We recommend that you use the using pinconfig statement in the Pin mapping file instead.

<pinConfigFile>: The path (relative to the active directory) and name of the Pin configuration file.

This keyword is optional; it is required only if Automatic waveform generation or Multiport operation is to be used.

:pinMap:

<pinMapFile>: The path (relative to the active directory) and name of the Pin mapping file.

:programParam:

Parameters that can be used in the program and device access files.

The value of this keyword is a :format: table in which the actual parameters and their values are specified. The keywords available in this table are described in "Program parameter keywords", below.

:scramble:

<addressScramblingTableName>: The name of the address scrambling table to be used.

The table must have been defined in the Device architecture file.

If you do not want to use address scrambling, enter a tilde (~).

This keyword is optional; it is required only if address scrambling is to be applied.

:testLabel:

<testLabelName>: The test label that is to be used.

The label must either be defined in SmarTest or it must be created manually using SmarTest's pattern debug tool.

<ppinLabelList>: An optional list with precompiled patterns separated by commas. The patterns in the list are executed sequentially from left to right whenever the test label is called. If the list is not specified, the current pattern compiled from the APG program file will be executed when the test label is called.

The formats for listing patterns in <ppinLabelList> can be:

  • <pattern label>: List a pattern's label if the pattern is a per-pin sequencer subroutine.

    This is same as PPS(<pattern label>), as described below.

  • *: The current pattern (the one being compiled from the APG program file).

    The type of this pattern is parallel vector if it was compiled with the -paraapgc option and per-pin sequencer subroutine otherwise.

  • PPS(<pattern label>): Use this format if the pattern is a per-pin sequencer subroutine.

    This is the same as directly using the pattern's label, as described above.

  • PARA(<pattern label>): Use this format if this pattern is a parallel vector subroutine.

Example, the following two syntaxes are the same:

  • :testLabel: myLabel(initial,*,PPS(refresh),PARA(active1,active2))
  • :testLabel: myLabel(initial,*,refresh,PARA(active1),PARA(active2))

:timing:

Timing settings for static refreshes.

The actual settings are enclosed in curly braces and labeled by four keywords, as described in "Timing keywords", below.

This keyword is optional: it is required only if the Device architecture file specifies static timing (:timerMode: static).

:version:

<patternVersion>: Any string describing the version of the pattern file.

This keyword is optional.

:waveformMap:

The waveform mapping specification. You can specify either a waveform mapping file for indirect waveform mapping or a timing file and a wavetable name for direct waveform mapping.

(Note that you can also specify a waveform mapping file for use in direct waveform mapping. The file must contain a WAVETBL keyword in this case and is used like a timing file, as described below.)

<waveformMapFile>: The name of the Waveform mapping file to be used. Use this parameter for Indirect waveform mapping.

<timingFile>: The name of the SmarTest Timing file to be used. Use this parameter for Direct waveform mapping.

<wavetableName>: The name of the wavetable from the timing file that is to be used. This parameter is required for direct waveform mapping.

Each of the optional keywords can have a tilde character (~) as a placeholder in the APG pattern file.

Program parameter keywords

These keywords let you specify parameters for use in the program and device access files (see :programParameter:, above):

Keyword

Parameters and descriptions

:name:

<paramName>: The name of the parameter.

:value:

<paramValue>: The value of theB parameter.

To specify a hexadecimal number, prefix it with 0x. For values larger than 64 bits, see Expressions with more than 64 bits.

You can specify floating-point numbers as the value; such values are truncated when they are passed to other files.

You can also specify the value as an expression. This expression can include other parameters and all operators (see Operators), except assignment and increment operators.

Device parameters can be used in program parameter definitions.

Timing keywords

These keywords let you specify timing settings (see :timing:, above):

Keyword

Parameters and descriptions

:file:

<timingFilePath>: The name of the SmarTest Timing file to be used.

:eqns:

<equationSet>: The equation set in the specified timing file that is to be used. You can specify the equation set using its number or its name.

If multiple timing sets are specified for multiport operation, the entry for the equation set is ignored.

:tims:

<timingSet>: The timing set in the specified timing file that is to be used. You can specify the timing set using its number or its name.

There are special conventions for multiport operation, as described in Multiport timing conventions.

:spec:

<specSet>: The spec set in the specified timing file that is to be used. You can specify the spec set using its number or its name.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. MTP 2.4.0: Floating-point values supported for :programParam:
  3. MTP 2.4.0: Added :crc: keyword
  4. MTP 2.4.0: Added :dbi: keyword
  5. MTP 2.6.6: :countedMatchPadding: keyword added
  6. MTP 3.0.1: String macro values can be overwritten from the command line
  7. MTP 3.0.1: Added :options: keyword
  8. MTP 3.0.3: (MTP on SOC 103.0.0) :countedMatchPadding: keyword changed to :countedMatchPad:
  9. MTP 3.0.3: (MTP on SOC 103.0.0) :crc: and :dbi: keywords are now available in both MTP on HSM and MTP on SOC
  10. MTP 3.1.5: Parallel vectors can be called within the :testLabel: keyword.
