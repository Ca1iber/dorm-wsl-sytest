Parallel Tester Setup

Tests for multiple sites can be set up and executed in parallel. Retrieval and post-processing of the resulting measurement values, however, is only possible serially.

Setting the flags

A prerequisite for parallel setup and execution is that parallel processing is allowed for the respective test suites and the testflow. This is controlled by the test suite flag allow parallel and the testflow flog parallel_mode.

For more information see Setting Flags for Parallel Execution.

Test method API's

Parallel processing must be programmed within a first-invocation block, which is opened with the

ON_FIRST_INVOCATION_BEGIN()

API, and closed with the 

ON_FIRST_INVOCATION_END()

API. Everything in this block is executed only at the first invocation of the test method; all setup and actions in it are performed for all sites in parallel. The following invocations of the test method only serve to retrieve and evaluate the measurement results of sites > 1.

For more information see Parallel Execution.

If you want to set up different sites differently, but execute the measurement for all sites in parallel, put an each site loop block into the first-invocation block before execution of the test. An each site loop block is enclosed by 

FOR_EACH_SITE_BEGIN()
FOR_EACH_SITE_END()

API's. It successively sets up every site with specific data, which will usually be determined by a previous measurement.

For more information see Controlling the Setup/Query-Focus Automatically.
