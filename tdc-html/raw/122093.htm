Test Time Measurement

Subtopics

  1. TTT tool
  2. Measuring the test time manually
  3. Understanding the Output of Debug Mode 3
  4. Timestamps in the event data log

In production, test times must be as short as possible. To achieve this, test times must be measured and compared. The test time values must be reproducible across multiple testers.

For these reasons a certain standardization of test time gathering is required. It comprises the following parts:

  • All time delay factors that can be easily eliminated without affecting the purpose of the test must be eliminated before the measurement.

    This concerns mainly SmarTest specific parameters. For example,

    • Starting the testflow from the testflow editor, and not from a work order adds unnecessary test time.
    • Using an unoptimized testflow, or having unused features activated in the model file (/etc/opt/hp93000/soc/model) also adds test time.
  • The test time must be measured with the tools that are provided by SmarTest, and the result must be statistically significant.

The test time can be measured manually. How this is done, is explained in Measuring the test time manually. But standardization is easier to obtain if you use the TTT tool to execute the measurement. This tool is described in TTT tool.
