Site States and Test Method Programs

SmarTest controls which sites are addressed by Setup, Execution, and Result APIs, for achieving multisite testing with maximum performance.

The following describes the definition of the site states:

  • Configured sites:

    sites that are configured in the Pin Configuration. They may be called all sites simply.

  • Enabled sites:

    sites that are intended for multisite testing. For the enabled sites only, you can connect or disconnect the devices to the test system resources such as the drivers, analog modules, and so on in a test flow. Especially, the sites where the devices are connected to the test system resources are called connected sites.

    You can also specify which sites are enabled in the Site Control window.

    Binned sites in a test flow are disabled (not enabled-sites).

  • Active sites:

    sites that are intended for the execution of the test method program currently.

    For parallel execution, active sites are generally the same as the enabled sites.

    Outside the first-invocation block in the test method program (see MS Test Method Programming Overview and Parallel Execution), only the site that calls the test method program is an active site.

    For serial execution, only the site that calls the test method program is an active site. Hence, one site in the enabled sites is activated by repetition.

    In other words, assuming you have a 4-site setup and all the sites are enabled and activated.

    If site 1 calls the program, then:

    Sites 2, 3 and 4 are deactivated and the test is run on site 1.

    If site 2 calls the program, then:

    Sites 1, 3 and 4 are deactivated and the test is run on site 2.

    If site 3 calls the program, then:

    Sites 1, 2 and 4 are deactivated and the test is run on site 3.

    And so on.

    In the above example, the enabled sites are activated one by one.

    Deactivated sites can be called masked sites.

    Note: You can also specify which sites are activated in the Site Control window (see The states of the sites).

  • Setup-focused sites:

    sites that are addressed by Setup APIs.

    All configured sites are setup-focused generally. In the each site loop block, one site in the active sites is setup-focused by repetition. You can also setup-focus some sites by the SET_TEST_FOCUS API. You can be aware of this state for the site-specific setup only.

  • Query-focused site:

    single site that are addressed by Result APIs.

    This site is switched depending on the execution position in the test method program. In the each site loop block only, one site in the active sites is query-focused by repetition. On the other position, it is the site that calls the program.

    You can also specify which site is query-focused in the Site Control window (see The states of the sites). This may called focused site.

To determine which site is calling the test method program, you can use the API "CURRENT_SITE_NUMBER()

Note that for "enabled" but not "active" sites, the test method is not performed, however, the digital patterns for the devices in the "enabled" sites are, visible, because the relays are still closed.

The following describes the summary of the behavior related to the site states in the test method program in the multisite testing.

  • ON_FIRST_INVOCATION_BEGIN - ON_FIRST_INVOCATION_END

    In the first-invocation block,

    • Setup APIs except the CONNECT, DISCONNECT, and routing setup APIs are executed for all configured sites. Note that they are valid even for binned sites (disconnected sites after binned).
    • CONNECT, DISCONNECT, and routing setup APIs are executed for the all enabled sites.
    • Execution APIs are executed for the all connected sites.
    • Result APIs are executed for the site with lowest site number (first tested site) in the active sites.

      This is the query-focused site.

  • FOR_EACH_SITE_BEGIN - FOR_EACH_SITE_END

    In the each site loop block,

    • Setup (except the CONNECT, DISCONNECT, and routing setup APIs) and Result APIs are executed serially for each site in all active sites by repetition.

      One site in the active sites is setup-focused and query-focused by repetition.

    • CONNECT, DISCONNECT, and routing setup APIs are executed for the all enabled sites.
    • Execution APIs are executed for the all connected sites.
  • On the outside of the first-invocation block,
    • Setup APIs except the CONNECT, DISCONNECT, and routing setup APIs are executed for all configured sites. (They are executed every time the program is called for each site.)
    • CONNECT, DISCONNECT, and routing setup APIs are executed for the all enabled sites. (They are executed every time the program is called for each site.)
    • Execution APIs are executed for the all connected sites. (They are executed every time the program is called for each site.)
    • Result APIs are executed for the site that calls the program currently. This is the query-focused site.

These APIs change the state of sites automatically, as described above.
