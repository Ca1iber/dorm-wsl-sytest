Topic 44843

Program Dependencies

When you create a program Command Set, consider the following dependencies:

  • Max CI_MAX_COMMENT_LEN bytes are written to stdout.

    Failure to observe this dependency results in a comment truncation warning and possibly causes a program failure with the message ERROR: CI: child died: Write on Pipe. This means that the interface has read the maximum number of bytes allowed and has closed the input medium.

  • The program exit() status is assigned one of the following constants:

    CI_CALL_PASS = 0

    CI_TEST_PASS = 0

    CI_TEST_FAIL = 1

    CI_CALL_ERROR = 2

    CI_CALL_BREAKD = 3

    Failure to observe this dependency results in an undefined return status being returned to the production software. This means that zero bytes of comment are transferred to the application model file variable. The undefined state is treated as an error and an error message is generated. Manual intervention is required and a RETRY and an ABORT button are made available.

  • Any SmarTest Work Center requirements must be satisfied by the user (SIGALRM available).

    Failure to observe this dependency codes an endless loop into the function and results in a production software hang-up, except when the NOWAIT option is used. In this case you are responsible for hanging background processes.

  • The Makefile provided by the software is used for compilation of the program.

    Failure to observe this dependency results in compilation complications due to undefined external references on the CPI functions. This cannot happen if the Makefile provided by the software is used for the compilation. The Makefile program produces an executable program from each .c file in the directory. The Makefile also contains special commands to switch between debug/non-debug modes of operation.

  • Unless you modify the Makefile (see Writing a Program with more than one Sourcefile), only one source file is allowed per program.

    Failure to observe this dependency results in compilation complications, because the Makefile has been adapted for the single source per program type of Command Set.

  • Error Messages are your responsibility, and must be written to stderr. This is the medium for passing messages to the report window.
  • The actions for all SIGNALS remain undisturbed for the duration of the function execution. The exceptions are SIGALRM, SIGINT, SIGUSR1 and SIGUSR2).

    Failure to observe this dependency critically jeopardizes system robustness.

  • If a program forks another process then that process inherits the comment and report passing communication mediums. All sub-processes of the command program must terminate before program termination is accepted.

    Failure to observe this dependency hangs the interface until all child processes exit. Command execution is complete only when it and all child processes have terminated.
