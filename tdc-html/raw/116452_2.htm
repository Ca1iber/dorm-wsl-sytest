Topic 116452

Defining edge delays for Smart Scale pins

Subtopics

  1. Defining edge delays and period length for a protocol engine test
  2. Defining edge delays for a PRBS test
  3. Defining edge delays for a pattern‑based SmartLoop test

Timing equation sets for a Smart Scale pin differ from earlier versions in that different delays can now be defined for the f-edges and s-edges in the timing set. The di syntax is still supported and is taken to mean that si and fi are to be set to the same delay. However, you cannot mix the native Smart Scale syntax with the earlier syntax within the same PINS block. Special requirements for protocol engine test pins are described in Defining edge delays for a protocol engine test.

In order to reduce the coding effort, you can distribute edges equidistantly within the tester cycle with the period_div keyword. For the syntax of period_div see Defining the edge delays for fast pins. If you want to modify one of the edge positions determined with period_div, you can overwrite the predefined value for the respective edge; this is in contrast to the jitter notation for fast pins (see again Defining the edge delays for fast pins).

Related firmware commands

You can use the ETDS command to retrieve and change the delays. However, this is only a temporary change of the runtime values, which does not modify the values in the timing set.

Example

The following fragment contains a timing set for the wavetable of Defining waveforms for Smart Scale pins:

TIMINGSET 1 "eq 1 ts 1"
period=150

PINS  DS0
f1=1 
s1=4

PINS  DS1
d1=0 

PINS  Q0
r1=45
r2=95
r3=145

PINS  IO1
TTMODE X4
r1=22.5

If you issue ETDS? to query the edge positions resulting from this equation set fragment, the reply will be:

> ETDS? 101,1,,(@)
< ETDS 101,1,,"f1:0 s1:0",(DS1)
< ETDS 101,1,,"f1:1 f2:0 f3:0 s1:4",(DS0)
< ETDS 101,1,,"f1:0 f2:37.5 f3:75 f4:112.5 s1:0 s2:37.5 s3:75 s4:112.5 r1:22.5 r2:60 r3:97.5 r4:135",(IO1)
< ETDS 101,1,,"r1:45 r2:95 r3:145",(IO1)
