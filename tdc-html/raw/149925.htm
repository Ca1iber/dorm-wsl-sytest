Topic 149925

Check test method

Lets you check test method related risks.

These risks include:

  • Memory leakage risks
  • Thread safe related risks

Memory leakage risks

Memory leakage means that every device execution uses some memory and does not free that memory after execution. This happens when the user allocates memory in test method codes with "malloc" or "new", and then exits without using "free" or "delete".

You may observe some unexpected behavior when memory leakage happens, such as:

  • SmarTest crashes with fatal error message. Normally this will happen only after running device execution for many times, and could be recovered by restarting SmarTest again.
  • Test time slowly increases. Also note that this is needed to test the device more than 30 times before a trend emerges.

This function calls the valgrind tool to analyze test method execution and identify memory leakage codes.

Thread safe related risks

The implementation of multithreading is very common in the test methods of V93000 test programs. Thread safe means that the test method must satisfy the need for multiple threads to access the shared data, and a piece of shared data can be accessed by one thread only at a time. A subroutine is thread safe if:

  • It uses variables from the stack only
  • The execution depends only on the arguments passed in
  • Further subroutines have the same properties mentioned above

This function calls the Helgrind tool to analyze the test method execution and identify possible thread safe codes.
