Protocol

A protocol is a a set of formal rules to describe how to transmit data between sender(s) and receiver(s).

Protocols can be specified on different layers thus reaching from a pure definition of electrical interfaces and a basic command set for transferring data packages to rather comprehensive definitions for data package sequencing, handshaking, etc.

Protocols can be specified and used as

  • standard, i.e. agreed on by an international committee (for instance, IEEE)
  • de facto standard, established by a single company (rather true for simple protocols, for instance, SPI)
  • proprietary, i.e. company-internally defined and used

Protocol Specification

Protocol specification is the logical description of a device independent protocol description.

It contains at least a list of supported transactions and supplementary information to format and scale the data properly, for instance

  • a specifying byte order
  • signal amplitude,
  • frequency, etc.

On the V93000 it is implemented via the set of the following test data entities (TDE):

  • Protocol
  • Protocol Timing
  • Protocol Wavetable
  • Protocol Level

Together the above describe the signals in respect to timing, level and message format required to exchange information between a sender and a receiver of an interface.

Within SmarTest the term protocol reflects both:

  • The test data entity (TDE), which is holding pin role and frame definition(s) of the device independent protocol description.
  • The user's name of the protocol specification. This name is chosen, to make it explicit that the protocol specification does only reflect the device independent part of a protocol. To really work with a protocol, the protocol needs to be instantiated via a protocol-to-port assignment and an explicit pin-to-pin role mapping.

Example

Commonly known protocols and their abbreviations:
