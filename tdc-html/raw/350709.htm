XPS256 licensing

For a complete list of available licenses, refer to V93000 License Master Look-up Table and set the filter of the Main product column to "XPS256".

License needs are almost all derived from the pin configuration of a device but upgrade license needs for the High‑accuracy voltage mode must manually be enabled manually using the DC Scale Extensions editor.

If only the Base Capability license is available, XPS256 supports only 16 pins on the lower 128 channels, each consisting of eight consecutive ganged channels and capable of driving up to 8 amperes.

The Base Capability Extension license offers 16 more pins on the upper 128 channels.

In the Pin setting editors, these up to 32 pins are to be defined as follows:
  • Each pin must be defined as a ganging group.
  • Each pin must use eight consecutive channels or a multiple there.
  • Multiple groups of eight channels can be assigned to a pin in any order to increase the maximum current to a multiple of 8 A.
The Fine Granular Capability is required for each channel where the group of eight consecutive channels is not fully defined per site. A Fine Granular Capability license covers 32 channels: 1 ... 32, 33 … 64, … , 225 … 256.

XPS256 in the device license file

For release to production, we recommend creating a device license file using the Testflow Analyzer Tool (TAT).

The device license file holds the device specific license information including the XPS256 upgrade license for the High‑accuracy voltage mode that has manually be enabled manually using the DC Scale Extensions editor.

XPS256 card configuration in the tester.model file

Although SmarTest 7.10 and higher supports both the legacy model file and the tester.model file, the V93000 EXA Scale based XPS256 can be defined only in the tester.model file.

The combination of DPS128 / DPS64 cards and XPS256 in one tester.model is not supported. SmarTest will issue an error waring in this case and will ignore all XPS256 cards.

The XPS256 card and pogo blocks must be defined in the CARD_CONFIGURATION section of the tester.model file:

  • Variants of the card

    In the tester.model file, the variants are to be defined as follows:

    Variant Part number tester.model file
    XPS256 (EK751HC): ... HW = XPS256, ...

    Basic data of the XPS256 variants are available in section Variants of XPS256 functionality and features.

  • Pogo cable assemblies

    For the available pogo cable assemblies, refer to Pogo cable assemblies in XPS256 pogo pin assignment.

    In the tester.model file, the pogo cable assembly is to be defined as follows:

    Product number Pogo block type # pogo blocks tester.model file
    EK751HDA

    High-density (HD)

    		 16 ... type = REDIRECT, subtype = EK751HDA
    EK751VHDA Very-high-density (VHD) 8 ... type = REDIRECT, subtype = EK751VHDA

    Default value, if parameter type is not defined, is the EK751HDA pogo cable assembly for XPS256 (EK751HC).

  • Pogo blocks
    • High-density (HD) pogo blocks
      For the pogo cable assemblies that use HD pogo blocks with 16 channels each, the 16 pogo blocks of the assembly are to be defined as simple list or as groups:
      ... pogoblocks = A B C D ... P
... pogoblocks = A-B ...
    • Very-high-density (VHD) pogo blocks
      The channels on the VHD block are split into two groups:
      • For channels A1 … A161) on pogo block rows a, b, c, and d, the same mapping is used as for the HD pogo block. For these channels, the physical pogo block position is used in tester.model file.
      • The additional channels B1 … B161) on pogo block rows e, f, and g are mapped to virtual pogo blocks. The number of a virtual pogo block is defined by the physical pogo block position plus an offset of 400.
      The following syntax is to be used to define the eight physical pogo blocks A … H of the pogo cable assembly:
      ... pogoblocks = A A+400 B B+400 C C+400 D D+400 ... H H+400, type = REDIRECT, subtype = EK751VHDA
      The notation in the syntax definition above is as follows:
      • Physical pogo blocks A … H without an offset refer to the channels on pogo block rows a, b, c, d.
      • A+400 … H+400 refer to the channels on pogo block rows e, f, g and define eight virtual pogo blocks.

      Note that in the tester.model file you have to define twice as many pogo blocks as the pogo cable assembly has pogo blocks: All physically available pogo blocks and the same number of virtual pogoblocks that cover the additional channels B1 … B16.

Example for HD pogo cable assembly EK751HDA:

High‑accuracy voltage mode

XPS256 features a licensed high‑accuracy voltage mode. In this mode, the 1.5 V voltage range is used to provide a higher accuracy for all voltage related settings and measurements.

The high‑accuracy voltage mode applies to forcing, clamping, and measuring voltages. For more information, see the XPS256 voltage specifications.

Since a license is required for the high‑accuracy voltage mode, the mode must be enabled per pin in the HAC column of the DC Scale Extensions editor:
Note Data that are defined by the DC Scale Extensions Editor are stored in the Pin configuration file using the firmware command DFDM.

The high‑accuracy voltage mode is activated by the following APIs:

SmartRDI: rdi.dc().hiAccuracy()
Test‑method‑API: SPMU_PIN_TASK.highAccuracy()
Level‑setup:

vout and vout_frc_rng parameters of the DPSPINS resources must be ≤ 1.5 V.

The high‑accuracy is then automatically activated if the HAC option has been enabled in the DC Scale Extensions editor.

This activation applies only to the current RDI command, SPMU_TASK, or level setup.

Pull‑down circuit at P#, PS# and GS#

Each of the pins P#, PS# and GS# features a circuit that pulls the pin down to ground. The circuit keeps the voltage at disconnected pins at a defined level of about 0 V referenced to the GND pin.
  • Pull‑down resistance: Typical 200 kΩ
At the end of the main testflow, the pull‑down circuit is activated for all three pins P#, PS# and GS#. For all other cases, the state of the pull down is shown in the following table:
Operating mode Connection state Measurement mode Default state of the pull‑down circuit
P#, PS#, and GS#
DPS disconnected (hiz) n/a active
disconnected (loz) n/a inactive
connected n/a inactive
PMU disconnected (hiz) n/a active
disconnected (loz) n/a inactive
connected All measurement modes inactive
The behavior of the pull‑down circuit in disconnected state of the pins can be modified by the following APIs:
SmartRDI: rdi.dc().pulldown()
Test method API: SPMU_PIN_TASK.pulldown()
Level setup: pulldown parameter in DPSPINS resources

Handling of disconnected channels

For protection of the DUT, the DUT board and the tester hardware, channels that exceed a defined limit can cause that a status flag is set and are automatically disconnected if this functionality has been enabled. This applies to the following status flags:
  • Current limit disconnect
  • Overpower / Overcurrent / Power budget exceeded
  • Overtemperature
  • Overvoltage
  • Voltage drop force
  • Voltage drop return

In this context "disconnected" means that output relays are opened by the channel controller immediately and independently of the SmarTest software.

To continue normal operation, the related pin must additionally be disconnected and reconnected by SmarTest.

An active status flag for an XPS256 pin that has been disconnected by the channel controller is indicated the next time the pin is accessed. To display the actual state, the pin must also be disconnected and reconnected by SmarTest.

Functional changes

  1. Introduced in SmarTest 7.10.1
1) A1 … A16 means pogo pins "PA#", "PSA#", "GSA#" and B1 …  B16 means pogo pins "PB#", "PSB#", "GSB#" of the VHD block. The number sign "#" must be replaced with channel number 1 … 16.

For more information, refer to Very-high-density (VHD) pogo blocks.
