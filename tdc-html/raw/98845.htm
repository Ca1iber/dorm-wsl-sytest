VCYC? - (Valid CYCle)

The VCYC? query returns the physical waveform DC/DC power units for the requested cycle range.

You must make the label you are interested in the current start label with the command SQSL, SQSL? - (SeQuencer Start Label) prior to using this query; otherwise the system returns nothing. If different sites are associated with different start labels, you must also set the query focus to the requested site with PQFC.

Note If the current start label is a burst, and the overview Error Map is set to LMAP (DCRM command), then break vectors are generated between the individual labels of the burst (this is in contrast to the default settings of the overview Error Map). These break vectors are not displayed by VCYC?.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Syntax

VCYC? {start_cycle}, {no_of_cycles}, {(pinlist)}

returns: 

VCYC {start_cycle}, {no_of_cycles}, {seq_status}, {pin_oper_mode}, {(pinlist)}, {#spec(data)}

Parameters

start_cycle

This is an integer that defines the first cycle for which information is to be returned. The scanning method and the range of values this parameter can take depend on the analysis mode:

  • In the Start Analysis mode enter a positive value between 0 and 248. The system responds by counting cycles forwards from the first cycle of the label and returns a positive number. The Start Analysis mode is the default setting.
  • In the Stop Analysis enter a negative number between -248 and -1. The system responds by counting cycles backwards relative to the end of the label at -1 cycle and returns a negative number. This mode is used by the system for Stop-on-Error tests.

no_of_cycles

This is an integer that defines the number of cycles for which information is to be returned. It is the cycle length from the specified start_cycle to the last cycle resulting from the seq_status specified by a sequencer instruction. The range for this parameter is 0 to 2,147,483,648 (231).

seq_status

Returns the sequencer status that was current when the cycle range was generated. The status is expressed on most occasions in the form of the sequencer instruction that was used to generate the vectors in the requested cycle range. Otherwise it is expressed in terms of a sequencer activity. Note that seq_status is not the same as the sequencer state determined by the command SQST, SQST? - (SeQuencer STate). Sequencer instructions are parameters to SQPG, SQPG? - (SeQuencer ProGramming). For additional information on sequencer programming see Vector Setup Commands.

The seq_status parameter is required for the reconstruction of received data. Some of the values it returns signify that vectors are being generated, others inform of sequencer status changes, which can cause some break vectors to be generated.

 

GENV

This is returned if GENV is the sequencer instruction that generated the parallel vectors in the reported cycle range.

 

SRCV

This is returned if SRCV is the sequencer instruction that generates vectors in the reported cycle range.

For non-source pins the reported cycle range is generated by the parallel vectors exactly the same way as from RPTV. This means that no_of_vectors parallel vectors are repeated for a repeating count (equal to no_of_cycles divided by no_of_vectors) to generate no_of_cycles cycles on the test system.

For source pins the reported cycle range is generated by the vectors stored in the source memory. This means that no_of_cycles vectors are generated from the source memory to produce no_of_cycles cycles on the test system, and the information of no_of_vectors has no meaning to source pins.

 

RPTV

 

This is returned if RPTV is the sequencer instruction that generated the parallel vectors in the reported cycle range.

You can stop a repeat loop by hitting BREAK in the user interface. The seq_status may then still be RPTV because the BREAK occurs asynchronously to the execution of the loop.

 

 

 

 

 

JPPS

This is returned if the parallel vectors for the reported cycles were generated by a per-pin subroutine.

 

CTIM

This is returned if a change timing instruction has been issued in the queried cycle range. Each timing change generates break vectors.

The real number of break cycles depends on the test system period and will not be shown in the cycle reconstruction.

Between 0 to 7 break cycles will be recorded during a CTIM instruction, the exact number depends on the number of vectors loaded.

 

CLEV

The CLEV (change levels) parameter indicates that unrecorded break cycles, due to a change of level set, exist in the specified cycle range.

 

BRK

This is returned if break cycles are being generated during the reported cycle range - for example, if a timed match loop is in progress. Between 0 and 7 break cycles will be recorded.

MTCH

This is returned if

  • the test contains a counted match loop,
  • the test has been executed online, and
  • the last cycle of the match loop is not the last cycle of a 8-cycle block.

In this case the last match loop cycles belonging to this block (up to 7) are recorded in the Error Map and reported by VCYC?. For details see Adjusting the junctions between match loop and surrounding label.

pinlist

Information is only returned for the pins specified in pinlist. If more than one pin is to be included in the query, the names must be separated with a comma. You can type the character @ to obtain data for all pins.

The response is provided for each pin separately.

pin_oper_mode

Reports the operating mode of each pin in the pin list. This can be:

F160

Specifies Standard operating mode.

F330

Not valid.

#spec(data)

Vector data in binary format. The parameter reports the length of data (in bytes) being transferred, followed by the binary data. The data is returned for each pin separately, on a sequencer construct basis (see Addressing the vector areas). The system returns one byte for each cycle and pin. If the requested cycles are break cycles, then no data is returned.

Application

Test results, see Test Result Commands. Used by the Pattern Tool.

Errors

An error is generated if:

  • You send the query while the sequencer is running. There is then no result data available.
  • You enter an invalid cycle range.

Example

VCYC? 0, 5, (pin1)

returns: 

VCYC 0,5,GENV,F160,(pin1),#9000000005\x0E\x0E\x0E\x0F\x0D\x0A

This example returns the physical waveform DC/DC power units in hex notation in the range of 0 to 5 cycles.
