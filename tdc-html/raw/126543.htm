Memory pooling within channel groups

Channels that belong to the same 4-channel group or 8-channel group (Channel groups of Smart Scale cards) use the same physical memory. This is exploited by the so-called memory pooling. Memory pooling allows you to distribute the vector memory of the same type (SM, HSER) within a channel group flexibly among the channels of the group.

The total size of the vector memory per group is defined in the IOCHANNEL section of the model file:

  • For memory type SM, the size equals the sum of the smem entries for the group channels.
  • For memory type HSER, the size is n * 32 K, where n is the number of the group channels that are licensed for SmartLoop™.

Note that the pooling mechanism is independent of the assignment of channels to pins.

Memory pooling is by default active. In order to inactivate it, you must specify the following in the GLOBAL section of the model file:

memory_pooling = OFF

License dependent restrictions

With HSER, only channels that are licensed for SmartLoop™ can take part in the memory pooling. With SM, the rule is that the vector memory of a channel X can be expanded at the cost of a channel Y within the same 4-channel group (or 8-channel group) if the SM size of Y, as defined in the model file, is not larger than that of X. But conversely, if X has a smaller SM memory license than Y in the model file, then Y cannot donate any memory to X.
