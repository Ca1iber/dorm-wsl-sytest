Topic 42198

Parameter: softbin_to_handler_bin_map and softbin_to_prober_bin_map

Maps (groups of) SmarTest bins to (groups of) equipment bins. The software bin codes of the SmarTest bins are used for bin identification.

Each of the inner (groups of) software bin codes refers to one equipment bin, which was defined in handler_bin_ids (prober_bin_ids).

If a SmarTest bin is mapped to more than one equipment bin, the driver will equally distribute the devices assigned to that SmarTest bin to these equipment bins.

If a binning scheme other than ‘mapped_softbins' is used, this parameter is not functional, and should not be set in the driver configuration. However, if the parameter is set, it will be ignored by the driver.

Detailed example:

handler_retest_bins: [ 4 ]

handler_bin_ids: [ "A" "B" "C" "D" "E" ]

softbin_to_handler_bin_map: [ ["g1"] ["g2"] ["b1" "b2"] ["b1" "b2"] ["db"] ]

Handler bin "A" will receive devices binned to SmarTest software bin "g1".

Handler bin "B" will receive devices binned to SmarTest software bin "g2".

Handler bins "C" and "D" will both receive devices binned to SmarTest software bin "b1" or "b2".

Handler bin "E" will receive devices binned to SmarTest software bin "db" (usually this is the SmarTest 'otherwise' bin) and also devices that were not tested or have no bins assigned for some other reasons (defined through the handler_retest_bins definition).

Driver default: no mapping

Changeable at run-time: yes

Applicable for: handlers or probers, respectively

Example: softbin_to_handler_bin_map: [["1"] ["2"] ["b3" "b4"]]
