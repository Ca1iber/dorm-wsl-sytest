Topic 13860

Analyzing Data in Cycle Oriented or Failure Oriented Mode

Subtopics

  1. Force Cycle Oriented Mode
  2. Force Failure Oriented Mode

You can record your test results in either cycle oriented mode or in failure oriented mode. The test execution for each mode is identical. The only difference between the modes is how the results are acquired in the detailed Error Map.

These modes can be set in your test suite or in the Error Map Tool.

Cycle Oriented Mode

Failure Oriented Mode:
  • Logs data for each (passed or failed) test cycle.
  • One test run provides acquired data for up to 8K cycles in the internal error map, depending on the result granularity (see Result Mode).
  • To acquire data for a different cycle block, you need to run the test again after re-focusing the detailed Error Map on the desired block in the overview Error Map.
  • The upload of data is faster than with failure oriented mode.
  • Logs only failed test cycles.
  • Can possibly acquire data for a complete test in one run.
  • The number of errors which can be acquired is dependent on how the errors are distributed.
  • The upload of data is slower than with cycle oriented mode.

You can record more results than 8K cycles by placing the error map in the external memory. See Location of the detailed error map in Result Mode.

Functional changes

  1. Introduced before SmarTest 6.3.2
