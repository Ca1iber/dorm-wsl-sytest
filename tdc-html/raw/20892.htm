Comparing AC Test Results with Limit Values

To judge the test result, the TEST API requires the lower and upper limit values. There are two ways of providing these limit values. One is to specify in the Properties view, and another is to specify in the test method program. This section describes how to use the test method APIs for each case.

Applying Limit Values specified in Properties view

The following example shows the basic usage of the TEST API.

DOUBLE thd_result;
 :
TEST("Aout", "THD", thd_result);

This example compares a test result stored in the thd_result variable with the limit values defined for the THD test name, which are specified in the Properties view. Where, Aout is a pin name. If the value of the thd_result variable is within the limit range, the TEST API judges this test as PASS. Then, the program execution proceeds to the next statement. For the out-of limit range, the TEST API judges this test as FAIL. Then, the test execution will return to the Testflow after completing the TEST API execution. The judgment result of the TEST API will be a pass/fail result of the test suite.

You can compute multiple test parameters in a test method program. In this case, you can use multiple TEST APIs by adding a parameter as follows:

DOUBLE thd_result, snr_result;
  :
TEST("Aout", "THD", thd_result, TRUE);
  :
TEST("Aout", "SNR", snr_result);

The first TEST API has "TRUE" as an additional Boolean type parameter (called continue parameter). This continues executing the test program after the TEST API, even if the test result is judged as fail. Even if you omit TRUE, when the first test result is pass, program execution will continue. The second TEST API does not have this parameter. Hence, if the test is judged as fail, the test-method program is terminated after completing the second TEST API execution, and the test execution will return to the Testflow.

In the above example, the test method program returns a result of the logical AND operation over all judgment results of the TEST APIs to the Testflow, as a pass/fail result of the test suite. If one of the results of a TEST API is FAIL, the test suite fails.

The TEST API can also return the judgment result into a variable. In the following example, the judgment result is stored into the variable thd_pass (TRUE if within the limit range. Otherwise, FALSE).

Boolean thd_pass;
DOUBLE thd_result;
  :
thd_pass = TEST("Aout", "THD", thd_result, TRUE);

Using Limit Values Specified in Program

Instead of setting the limit values in the Properties view, you can set the limit values in the test method program. You can change the limit values temporarily for debugging. To set up the limit values in a test method program, use the LIMIT API.

You can write a TEST API statement using the class object of the LIMIT API:

DOUBLE thd_result;
  :
TEST("Aout","THD", LIMIT(TM::GE,-99.0 dB,
TM::LE,-45.0 dB), thd_result);

In this example, the class object of the LIMIT API defines the limit values. The defined limit range is as follows:

-99.0 dB <= thd_result <= -45.0 dB

The TM::GE and TM::LE are enumerators supported by the system. The following lists all enumerators for this parameter:

  • TM::LT: Less than a limit value
  • TM::LE: Less than or equal to a limit value
  • TM::GT: Greater than a limit value
  • TM::GE: Greater than or equal to a limit value
  • TM::NA: Not compare with a limit value

Where, TM::XXX means that the enumerators are defined as the TM object. Therefore, even if you use a variable LT in the program, the variable LT and TM::LT do not conflict.

You can also create the class object of the LIMIT API before the TEST API. In the following example, the object thd_limits specifies the limit range for the thd_result variable.

DOUBLE thd_result;
  :
LIMIT thd_limits(TM::GE, -99.0 dB, TM::LE, -45.0 dB);
TEST("Aout", "THD", thd_limits, thd_result);

During debugging, you may need the test result to be always judged as pass or fail, regardless of the result. The system supports system-prepared class objects of the LIMIT API: TM::Pass and TM::Fail. To handle the test as always pass, use the TM::Pass object as follows:

TEST("Aout", "THD", TM::Pass, thd_result);
