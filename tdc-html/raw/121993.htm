Combining selective digital capture with a functional test

Normally, digital capture is executed by comparing the received values to L. If the comparison passes, the captured value will be L; if it fails, the captured value will be H. These compare actions will impact the global P/F value of the test (which will be F if at least one H is received), but if you are only interested in the captured values, this is irrelevant.

However, there are situations where digital capture must be combined with a functional test, for example, when you want to execute a match loop before you start capturing. This can be achieved for selective digital capture by specifying the HRPF keyword in the primary wavetable for the combined functional and capture test.

The HRPF keyword causes SmarTest to capture the values by a different method, by which capture actions have no impact on the global P/F result, but normal compare actions (H/L) have, just as in a standard functional test. In this way the global P/F value will only reflect the result of the normal compare actions. It will be F when a match loop fails or any received value is different from the expected value.

But note that the individual compare results will not be written to the Error Map. Only capture actions will be recorded.

If a waveform is to contain more than one capture edge in HRPF mode, the edges must be paired according to certain rules. For details see Restrictions for selective digital capture.

Example

WAVETBL "SELECTIVE CAPTURE HRPF"

  PINS IO1
  HRPF 0  "d1:0 d2:0 r1:C" C1
       1  "d1:1 d2:0 r1:C" C2
       2  "d1:0 d2:0 r1:D" D1
       3  "d1:1 d2:0 r1:D" D2
       4  "d1:0 d2:0 r1:E0" E01
       5  "d1:1 d2:0 r1:E0" E02
       6  "d1:0 d2:0 r1:E1" E11
