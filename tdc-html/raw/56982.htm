Topic 56982

Defining the timing specification

Subtopics

  1. Consistency checks for edge delays
  2. Changing the runtime values of base variables
  3. Multiport timing specifications

In equation based timing, waveform shapes, as defined in a wavetable, are combined with a period length and edge delays, as defined in an equation set, in a timing specification which provides a complete timing for a test. This specification also contains a spec set where values are assigned to the base variables of the equation set, and specifies which checks are to be performed on the edge delays.

The timing specification file can be found here: <device_folder>/timing. The file can have any name that is suitable, for example, timingSpec1.

Usually, the specification is defined with the spec tool. However, if you want to download a specification with the EQFS or the EQSP command, you must specify it as it is coded in the timing setup file.

Related firmware commands

You can query the current values of base and derived (spec and equation) variables with the SVLR? query. You can also change the runtime values (not the definitions in the spec set) of base variables for a specified timing specification with the SVLR command; in this case the whole timing equation system will be recalculated.

Example

The following is a simple example of a single-port timing specification:

EQNSET 1 "default"

WAVETBL "table1"
CHECK all

SPECSET 1 "sp1"

# SPECNAME *****ACTUAL***** *****MINIMUM**** *****MAXIMUM**** UNITS COMMENT
f          100                                                [MHz]

This specification uses spec set 1 for equation set 1. It will be identified to the firmware commands by 101. The base variable f is set to 100. The CHECK all statement activates all consistency checks (see Consistency checks for edge delays).
