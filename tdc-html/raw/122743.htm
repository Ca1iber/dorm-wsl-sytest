Tester model and Configuration

The model file lets you configure your test system hardware. This also applies to any scalable features the system offers. The standard model file always includes the maximum possible configuration the system provides. Such a configuration is in many cases unnecessary to test your device and results in increased test times.

Note This topic is based on the legacy model file syntax.

This topic outlines the effects the model file has on the performance of the test system and therefore on throughput. It gives rough guidelines on steps you can take towards test time reduction (TTR) by making appropriate selections in the model file.

Examples

Generic example

The example below is based on the model file template issued with R. 6.5.4. The example is not complete, it shows just the sections containing selections that have an impact on throughput. These are located in the sections GLOBAL and IOCHANNEL. Refer to Model file sections for a full description of the various sections a model file consists of.

# Example for a model file, see detailed syntax description below:

GLOBAL

testhead = TH_8CC # TH_2CC | TH_4CC | TH_8CC

dut_interface = SOC_8GROUP # SOC_4GROUP | SOC_8GROUP | HSM

# hpib_interface = sicl/hpib

GLOBAL section

The GLOBAL section contains the following parameters that have a direct impact on testflow execution:

  • testhead = TH_8CC | TH_4CC | TH_2CC

    If your device requires less resources than installed in the test head, you can disable the unnecessary resources, thereby reducing the overall test time. As an example, this would be the case if you had an 8CC test head but needed only 4 CCs to test your device. You would reflect this with the entry testhead = TH_4CC in your model file.

    The test head size parameter affects the system clock and things like match loop overhead and pass/fail detection and reporting.

  • timing_bundle = w32-d8-r6 | w256-d8-r8

    The test system provides either

    • 32 waveforms, 8 drive edges and 6 receive edges or
    • 256 waveforms, 8 drive edges and 8 receive edges.

      The default value for Pinscale systems is timing_bundle = w256-d8-r8.

      Use only the resources you need. Consider using just 32 waveforms, but only if practical and only if you're doing a lot of primary switching that involves wavetable changes.

      Additionally, the number of physical waveforms has an influence on the number of break waveforms issued during primary set activation. The number of break waveforms is (32 or 256)*8, where 32 or 256 is the number of waveforms defined in the model file.

      Obviously, this is not always a practical method of TTR and using the 32-waveform bundle presents some challenges in terms of unused waveforms.

IOCHANNEL section

The IOCHANNEL section contains the following parameter which have a direct impact on testflow execution:

  • diff

    The diff parameter enables the differential receiver feature for the specified channels. It has an effect on the number of level sets created.

    For example, if you define 5 level sets and 8 spec sets for a given equation set, you finish up with 40 level sets, in hardware terms. If you have diff enabled in the model file, another set of "shadow" sets are created to support different termination modes, leading to 80 level sets. This has an influence on run-time spec changes causing an additional overhead and increasing the overall test time.

    If you do not need the differential receiver capability on certain channels, leave the diff parameter out for these channels.

Full-feature/Emergency/Demo Licenses

The interactions and dependencies between the model file and the device license file are explained in Model file and device license file.

For the purpose of TTR it is important to know that the full-feature licenses enable all features, even if they are not defined in the model file/device license file. This can have an impact on throughput. The following environment variable restricts the licenses to only what is specified in the model file/device license file:

export REQUESTED_CAPABILITY_MODE=1

For details refer to the section Environment Variables in the application paper Maximizing Advantest's V93000 Per Pin Tester Optimal FLEXlm License Server Setup
