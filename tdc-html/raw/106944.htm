Topic 106944

POGOCABLING section

Subtopics

  1. Pogocabling entries for various card types
  2. Conversions: pogo mapping file <-> POGOCABLING

In the POGOCABLING section of the model file you define the mapping between card slots (the physical position of the channel cards within the card cage respective the control segment) and pogo blocks on the DUT interface. This feature allows flexible routing between card cage slots and pogo blocks on the DUT interface.

For the process and tools to switch between the previously used pogo mapping file and the POGOCABLING section of the model file, refer to Converting between pogo mapping file and POGOCABLING.

Syntax

<physical_location>: pogoblocks = "<pogoblock_list>", type = SD | HD1x256 | HD2x32 | HD4x32 | VHD1x128 | VHD4x32 | REDIRECT, subtype
Parameters
<physical_location> Specifies the physical channel card position within the test head and the respective control segment. For more information regarding the control segments refer to pogo mapping.

The format of the number is CSS:

  • C represents the control segment (1 to 4).
  • SS represents the control segment slot number (01 to 18).

Refer to table Card cage allocation based on test head type below for the assignment of the control segment and the control segment slot number.

SS=09 and SS=18 address the two slots reserved for the legacy DPS cards, such as the MS-DPS.
pogoblocks Specifies the pogo pin blocks. <pogoblock_list> is a double quoted string defining the ordered list of pogo blocks or pogo block ranges. Use commas (,) to specify a list, like "101, 103". Use hyphens (-) to specify a pogo block range, like "101-104". You can also mix pogo blocks and pogo ranges, like "101, 210-212".

The total pogo block range is N MM, with N=1 to 8, MM=01 to 64. See also topic DUT interface layout.

The physically addressable pogo block range depends on the selected pogo cable.

Note The order of list must correspond to the structure of the pogo cable assembly. The first pogo block of the list defines always pogo block A of the cable. The last pogo block of the list defines always the last pogo block of the cable.
type Specifies the pogo cable type.
  • SD is used for the standard pogo cable with 16 channels per pogo block. Depending on the channel card, one SD pogo cable ends in 1-8 pogo blocks with 16 channels each.
  • HD2x32 is presently not used by any channel card.
  • HD4x32 describes a pogo cable with 32 channels per pogo block. One HD4x32 pogo cable ends in 4 pogo blocks with 32 channels each.
  • VHD1x128 describes a PS1600 pogo cable with two VHD pogo blocks and 64 channels per pogo block that is to be used for special configurations only.
  • VHD4x32 is not yet used. It describes a DPS128 pogo cable with four pogo blocks and 32 channels per pogo block.
  • REDIRECT, subtype is used for special DPS pogo cables which shall work also on older software revisions.

    If the software detects a "redirect" statement, the software will start, even if the information following redirect is unknown to this software revision.

The type parameter is optional. If not specified, the system defaults to SD.

Error messages

SmarTest startup will terminate with explicit error messages in the following cases:

  • an invalid pogo block number is used.
  • both pogo mapping file and POGOCABLING format are used in one model file.
  • in online mode, the provided pogo blocks in the model file do not match the density of the installed card variant.
  • in offline mode, the density of the used hardware variant in the model file does not match the provided pogo blocks in the model file.
  • an S2 pogo block is used to specify the pogo cabling of a UHC4T card.
  • an S1 pogo block is mapped to a UHC4T card, but the corresponding S2 pogo block is occupied by another card.
  • a pogo cable type is specified, which is not supported for the installed channel card.

Example

The following example illustrates the pogocabling entry of a double density digital card. 32 channels (2 logical boards) are routed via two pogo blocks of 16 channels each.

101: pogoblocks= "101,102"
