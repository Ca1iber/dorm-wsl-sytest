Topic 118011

CI_SITE_DISABLING_AUTOMATE

This system flag is used in the following two scenarios.

  • In a multisite environment, a digital channel is usually dedicated to a specific test site. When this channel becomes unavailable, the whole site becomes unavailable for testing. When a testflow containing unavailable sites is executed, the Check back window appears to allow you decide whether to continue executing the test flow or stop it.
  • Running a multisite testflow, if a hardware sequencer timeout occurs, which usually is caused by defective hardware, all sites are put to "otherwise_bin" and the current testflow execution stops. The sites whose channels cause HW sequencer timeout are disabled. A Site disabled warning window opens allows you to decide whether to continue the next testflow execution without disabled sites.

The CI_SITE_DISABLING_AUTOMATE system flag lets you enable or disable the Check back window and the Site disabled warning window.

This flag cannot be set in the SmarTest user interface. It is used in the handler driver.

The possible values of this flag are:

  • 0 (default)

    The Check back window opens if sites are unavailable during textflow execution.

    The Site disabled warning window opens if a hardware sequencer timeout occurs during thestflow execution.

  • 1

    The Check back window is never displayed; execution continues if unavailable sites are encountered.

    The Site disabled warning window is not displayed. The testflow execution continues without the disabled sites.
