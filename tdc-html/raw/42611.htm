Topic 42611

CI Calls for Multisite Testing

The CI provides access to user variables, to test suite flags, and to system flags.

For site-specific data there are additional commands, providing site-specific access.

The names of the calls are the same as for the global functions, followed by the suffix "OfSite". Examples are:

  • GetUserFlag() - GetUserFlagOfSite()
  • SetTestSuiteFlag() - SetTestsuiteFlagOfSite()

The following lists the CI calls relevant to multisite.

The following text contains all constants, global types, vars and function declarations for the CommandSet Programming Interface (CPI)

  1. long GetTestsuiteFlag(char tsname, char flag, long value)

    long GetTestsuiteFlagOfSite(char tsname, char flag, long site, long value)

    Retrieves the current value of the flag named flag in testsuite tsname and deposits it in the long pointed to by value. Flags are actually declared as int's, but are typecast to long's within this function for compatibility with VEE.

    GetTestsuiteFlagOfSite lets you specify which site should be used (1,2, etc.), while the first one assumes the site currently in focus (for example during sequential User Procedure execution).

    Entities in italics may be assigned one of the following constants:

    CI_BYPASS ....................: R/W

    CI_SET_PASS ..................: R/W

    CI_SET_FAIL ..................: R/W

    CI_HOLD ......................: R/W

    CI_HOLD_ON_FAIL ..............: R/W

    CI_OUTPUT_ON_PASS ............: R/W

    CI_OUTPUT_ON_FAIL ............: R/W

    CI_VALUE_ON_PASS .............: R/W

    CI_VALUE_ON_FAIL .............: R/W

    CI_PER_PIN_ON_PASS ...........: R/W

    CI_PER_PIN_ON_FAIL ...........: R/W

    CI_WDB_BREAK_POINT ...........: R/W

    CI_FORCE_SERIAL ..............: R

    CI_EXECUTED ..................: R

    CI_PASSED ....................: R

    CI_FFC_ON_FAIL ...............: R/W

    CI_FFC_ENABLE ................: R/W

    CI_FFV_ENABLE ................: R/W

    CI_LOG_MX_WAVEFORMS ..........: R/W

    Alternatively, use a string matching the flag name as required. A string is used to specify the TestSuite name (tsname).

    RETURN: 0 = ok, 1 = error on a name, -1 = internal error

  3. long GetUserFlag(char flag, long value)

    long GetUserFlagOfSite(char flag, long site, long value)

    Retrieves the current value of the user defined flag named flag and deposits it in the long pointed to by value. The flag must have been declared as a userflag (= int).

    RETURN: 0 = ok, 1 = error on name/type, -1 = internal error

  4. long GetUserDouble(char name, double value)

    long GetUserDoubleOfSite(char name, long site, double value)

    Retrieves the current value of the user defined variable named name and deposits it in the double pointed to by value. The variable must have been declared as a double.

    RETURN: 0 = ok, 1 = error on name/type, -1 = internal error

  5. long GetUserString(char name, char value)

    long GetUserStringOfSite(char name, long site, char value)

    Retrieves the current value of the user defined variable named name and copies it to the string pointed to by value. The variable must have been declared as a string.

    This function writes a maximum CI_CPI_MAX_USER_STRING_LEN + 1 bytes to the pointer value.

    Use a string constant to identify the variable required.

    RETURN: 0 = ok, 1 = error on name/type, -1 = internal error

    Note CI_CPI_MAX_USER_STRING_LEN is a constant defined in libcicpi.h (see /hp93000/soc/prod_com/include/libcicpi.h).
  6. long SetTestsuiteFlag(char tsname, char flag, long value)

    long SetTestsuiteFlagOfSite(char tsname, char flag, long site, long value)

    Sets the value of the flag named flag in testsuite tsname with the parameter value. Flags are actually declared as int's, but are defined as long's within this function for compatibility with VEE.

    RETURN: 0 = ok, 1 = error on tsname/name/value, -1 = internal error

    RETURN: 0 = ok, 1 = error on name/value

  10. long SetUserString(char name, char value)

  11. long GetDiePosXY(long x, long y)

    long GetDiePosXYOfSite(long site, long x, long y)

    Retrieves the currently set x and y die coordinates of the die about to be tested, or which has just been tested (depending on whether the call is made before or after a device test). The parameters x and y are defined as longs for compatibility with VEE, but actually return values that can fit into an int.

    RETURN: 0 = ok

  12. long SetDiePosXY(long x, long y)

    long SetDiePosXYOfSite(long site, long x, long y)

    Sets the x and y die coordinates of the die about to be tested when used before a device test takes place. The parameters x and y are defined as longs for compatibility with VEE, but are internally typecast to an int.

    RETURN: 0 = ok

  13. long GetPackageId(char id)

    long GetPackageIdOfSite(long site, char id)

    Retrieves the string currently set as the Package ID and copies it to the string pointer id.

    This function writes a maximum CI_CPI_MAX_PACKAGE_LEN + 1 bytes to the pointer id.

    RETURN: 0 = ok

    Note CI_CPI_MAX_PACKAGE_LEN is a constant defined in libcicpi.h (see /hp93000/soc/prod_com/include/libcicpi.h).
  14. long SetPackageId(char id)

    long SetPackageIdOfSite(long site, char id)

    Sets the string which is recorded as the device test package ID to the value pointed to by string pointer id.

    RETURN: 0 = ok, -1 = illegal ID (string too long)

  15. long IsFirstInvokation(long is_first)

    In order to write user procedures that operate in parallel on all sites, such a user procedure must be able to find out if the current execution of the user procedure was the first one in the context of a testsuite execution. It could, for example, then do all operation on the first call and return only values when called afterwards.

    IsFirstInvokation returns 1 if its execution was the first one in the context of a particular testsuite. Every subsequent call of IsFirstInvokation (in the context of this testsuite) returns 0.

    RETURN: 0 = ok, 1 = error occurred

  16. long GetSitesToBeTested(long sites_to_be_done)

    A user procedure that should operate on multiple sites must be able to find out which sites it should deal with. GetSitesToBeTested fills a caller-provided list of integers with the site numbers the user procedure should operate on. Valid site numbers are greater than 0. A 0 entry marks the end of the list.

    Note that the list must have a minimum size of CI_CPI_MAX_SITES+1.

    An example of this call might be:

    int to_do[CI_CPI_MAX_SITES+1], i;

    ....

    if (GetSitesToBeTested(to_do) == 1) ERROR();

    for (i=0; to_do[i] > 0; i++)

    do_something_with_site(to_do[i]); -- to_do[i] is a site number

    RETURN: 0 = ok, 1 = error occurred

    Note CI_CPI_MAX_SITES is a constant defined in libcicpi.h (see /hp93000/soc/prod_com/include/libcicpi.h).
