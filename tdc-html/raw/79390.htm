Topic 79390

Using EyeFinder

Parameter

Notes

TrainingAlgorithm

SpecTraining or EmbeddedTraining

SpecTraining performs the search for the eye on the test controller workstation as a parallel spec search. It does not support multiport setups.

EmbeddedTraining performs the search in the test processor on the test head card. It supports multiport setups.

out_pins

The output pins of the DUT.

out_spec_names

The spec variables for the output pins.

out_start

The start of the linear search range for the DUT output offset, in ps.

out_stop

The end of the linear search range for the DUT output offset, in ps.

out_step

The step size for linear the search range for the DUT output offset, in ps.

in_pins

The positive input pins of the DUT.

in_N_pins

The negative input pins of the DUT.

in_spec_names

The spec variables for the input pins.

in_start

The start of the linear search range for the DUT input offset, in ps.

in_stop

The end of the linear search range for the DUT input offset, in ps.

in_step

The step size for the linear search range for the DUT input offset, in ps.

Resolution

The resolution for the binary search, in ps.

Pattern

The name of the pattern to be used for the input-side calibration.

redo_out_search

If Y is selected, the output-side calibration is repeated at the end, this time using the pattern named above rather than the standard WDSL pattern. This is usually unnecessary (it is included for the sake of compatibility with some older applications); most users will want to select N.

Controlling the amount of output messages in the report window is possible by setting the test flow flags:

  • Output on fail
  • Output on pass

Reporting messages are controlled:

  • If the two flags are both set to 'Off' the execution result of the EyeFinder test method is just Pass or Fail. No report will be generated. This improves the run time and should be used in HVM testing.

Setting the flag to:

  • 'Output on fail' to 'On': detailed failure information only is printed to the report window
  • 'Output on pass' to 'On': a summary report for both failing and passing pins is printed.

The following shows an output example for Output on fail set to On:

No 1st output transition on pin 0 site 1 found: RSSR 1,E,,,(@) 
No 2nd output transition on pin 0 site 1 found: RSSR 2,E,,,(@) 
No 1st input transition on pin 0 site 1 found: RSSR 3,E,,,(@) 
No 2nd input transition on pin 0 site 1 found: RSSR 4,E,,,(@)

The following shows an output example for Output on pass set to On:

Site: 1
Max Pins: 16
Output Pin DQ0_o is failing
 Input Pin DQ0_i is failing
 Input Pin DQ1_i is passing
 Input Pin DQ2_i is passing
 Input Pin DQ3_i is passing
 Input Pin DQ4_i is passing
