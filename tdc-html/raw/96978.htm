Topic 96978

Fd_merge tool

Subtopics

  1. Running the fd_merge tool to merge fixture delay files

The fixture delay merge tool (fd_merge tool) helps you to generate a common fixture delay file that is finally used for compensation in a shared driver test setup.

The fixture delay fd_merge tool requires several fixture delay files and a sharing configuration file as input files, independent of the total number of sites on your fixture.

You must provide:

  • One FXDL file per shared site
  • One sharing configuration file

The merge tool generates a new fixture delay file that is used for testing the devices on a test fixture. This new merged delay file must be stored in the ch_attributes directory within your device path.

The input delay files contain:

  • Nominal delays measured at manufacturing or measured again in the field.
  • Delays measured for one socket board with golden devices as load.
  • Delays measured for one socket board without devices. This measurement repeats the measurements of the nominal delay and corrects the delays from the nominal delay files if necessary.

These fixture delay files are usually stored in the <device>/ch_attributes/ directory.

You may store them in a directory of your choice. The final merged delay file must be copied or moved to the ch_attributes directory for use by the compensation function of SmarTest.

The sharing configuration file can be customized to your needs. It is stored in the <device>/configuration/ directory. See Sharing configuration file for more information.

Multisite testing

Calculating the fixture delay for every site of a multisite setup, especially if there are a large number of sites, can be time-consuming. Fd_merge therefore lets you specify that the calculated delay values for one domain are applied to other sites as well, without any new calculations for these domains.

The advantage of this technique is that the tool runs much faster. The disadvantage is that delays are not calculated individually for each domain and so the applied delays may vary from the actual delays on the board. Use this technique only if you are confident that the differences between the delays for the various domains are negligible.

To apply the delays calculated for one domain to other domains, use the -C option, as described below. Optionally, you can add the -s and -d options to modify how the fd_merge tool copies the delay results.

Syntax

fd_merge.pl <options>

The following table shows the valid parameters for the compiler command:

fd_merge options

Options

Example

Description

-c <sharing_config_file>

config

Mandatory. Specify the name of the sharing configuration file that you prepared.

-o <output_file>

fd_output

Mandatory. Specify the name for your output file.

-l <device_loading_ file>

x2_site2_fd

Specify the name of the delay file that was measured with loaded devices.

-f <loading_reference_file>

x2_site2_nfd

Specify the name of the delay file that was measured without loaded devices. This file is needed if the fixture delay files as specified in the sharing configuration file are measured by manufacturer.

You can specify this parameter only if -l was also specified.

-i <user_fixture_delay_file>

my_fd

Specify a fixture delay file for comparison purposes.

The file is not used in the calculation but is displayed in a separate column in the Fixture Delay File Analysis section of the HTML report the fd_merge tool generates. You can use this column for comparison and debugging purposes.

-a <add_offset>

0.001

Specify an additional offset that is added to all delays in the output file. Must be always positive. The unit is nanoseconds.

-e <algorithm>

mean_pin

Specifies a compensation algorithm to use:

  • mean_pin: per-pin intrinsic and mean segment propagation delay
  • median_pin: per-pin intrinsic and median segment propagation delay
  • mean_grp: mean group intrinsic and segment propagation delay
  • median_grp: median group intrinsic and segment propagation delay

If you do not specify this option, mean_pin is used.

-C

--copy

 

If this option is specified, the calculated delay values for the first domain are used for all other domains as well. No individual values are calculated for the other domains.

This behavior can be modified with the -s and -d options (see below).

This is an optional parameter.

-s <site_number>

--site <site_number>

5

This parameter lets you specify that the delay values from a domain other than domain 1 are copied to the other domains.

For example, specifying -s 5 makes fd_merge calculate the delays for the domain to which site 5 belongs and copy them to all other domains.

This parameter requires -C (see above)

-d <site_number>

--destination <site_number>

9

9,17

9-12

If you use this option, the calculated delays are not copied to all domains but only to the domains containing the specified sites.

You can use this parameter multiple times.

For example, -d 5 -d 17 copies the values from the domain that contains site 1 to the domains with sites 5 and 17, but not to any other domains.

Instead of using -d multiple times, you can specify a comma-separated list or a range.

For example, -d 5,17 has the same effect as the example above.

Specifying -d 9-16 copies the delays from site 1 to the domains containing sites 9, 10, 11, 12, 13, 14, 15, and 16.

This parameter requires -C (see above)

-v

 

If specified, verbose output is generated in the report window.

-h

 

Outputs a help message.

-H

 

Outputs a sample sharing configuration file.

Running the tool displays progress information in the report window and creates an HTML report with the .report.html suffix.
