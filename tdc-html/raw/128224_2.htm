List of transaction based protocol test APIs

This topic lists APIs used with protocol based tests.

Note This is only a brief overview of the protocol based APIs. Detailed API description can be found in API Reference.
Protocol dependent APIs

API

Description

DRAM_ADDRESS_MAPPER

Defines address mapping for a MEMORY_EMULATION object.

INDEPENDENT_TEST

Creates a protocol pattern that runs asynchronously to (but possibly in parallel with) the simulation ports.

MEMORY_IMAGE

Provides content blocks that are downloaded to the XRAM of memory emulation as required.

MEMORY_EMULATION

Provides objects that control setup, execution, and result processing of a memory emulation test.

PROTOCOL_TEST

Common transaction based protocol test API, provides capabilities for future enhancements along with generic functions not implemented in the SYNCHRONIZED_TEST API, for example, cache related functions.

SEQUENCER_CONTEXT

Provides a container for managing a set of SEQUENCER_CONTEXT_ITEM objects.

SEQUENCER_CONTEXT_ITEM

Supplies a single sequencer context item (execution context).

SEQUENCER_CONTEXT_ITERATOR

Provides objects that simplify looping over the sequencer context items of a sequencer context.

SYNCHRONIZED_TEST

Is used for deterministic protocols providing synchronization features.It uses the subsidiary TRANSACTION and TRANSACTION_SEQUENCE APIs to build a functional test.

TRANSACTION

Provides functions to configure parameters of transactions.

TRANSACTION_SEQUENCE

Allows to set up a sequence of consecutive transactions.

TRANSACTION_ITERATOR

Returns objects to walk through consecutive transactions.
Protocol wrapper APIs

API

Description

Protocol wrapper API

Is a customized protocol dependent wrapper API enhancing the generic SYNCHRONIZED_TEST API. It allows to use more customer friendly API calls. It has to be re-generated anytime the protocol definition has been changed.

TRANSACTION_RESULT_PROXY

Is a protocol independent API providing access to the results of a transaction.1)

The return values are accessed based on their variable type.

PROTOCOL_TEST_RESULT_VECTOR

Is a protocol independent API similar to result proxy, that provides access to the result proxies.1)

The values are returned as a vector and accessed based on standard C++ vector access mechanisms.
