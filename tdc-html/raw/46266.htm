Implementation

X-modes for a factor x > 1 are realized by the ASCII interface as follows:

  • The waveforms for the ASCII device cycles of the pattern will be created from state character sequences of length x, and will thus contain all the actions associated with any state character occurrence of the sequence.

    By default, the timing translation creates waveforms for all sequences of length x that can be generated from the state characters of one ASCII device cycle and one pin. If there are y such state characters, then waveforms will be created for yx sequences. Even though different state character sequences can result in an identical waveform through waveform optimization (see the -FU parameter of ait in ait command line parameters, the 32 waveforms per pin that are available for the P/Ce systems will probably already be exceeded for y = 4 and x = 3. On the Pin Scale systems, where up to 256 waveforms can be defined per pin, y = 4 and x = 5 will exceed the available resources. In order to restrict the number of state character sequences to be considered by the timing translation, you can specify an x-mode control file to ait. See The X-Mode Control File (*.cmb).

  • The test system cycle length, as specified in a timing set, will be x times the ASCII device cycle period specified in the ASCII timing file.
  • The timing map file will contain mappings from state character sequences of length x to one physical waveform index. For more information on the timing map file see The Timing Map File.
  • The vector translation, using these mappings, will convert x ASCII vectors to one binary vector, thereby reducing the total number of vectors from n to n/x (or (n/x)+1).

This description assumes that either all ASCII device cycles associated with the pattern have the same period length, or that timing set changes are allowed within the pattern. If neither of these conditions is fulfilled, then the following modifications arise:

  • The test system cycle length will be the greatest common divisor of the ASCII periods, as described for the ctim column in The Input Columns, multiplied with the x-mode factor.
  • The mapping from state characters to waveform DC/DC power units in the timing map file will be m:n with m and n both greater than 1 for some ASCII device cycles; this is called fractional x-mode.
  • The total number of binary vectors can be greater than that of the ASCII vectors in this case.

As an example for this constellation, suppose that the pattern of Timing Translation is set to an x-mode factor of 2. Then the test system cycle length would be calculated as 8. In the timing map file, state character sequences of length 2 would be mapped to index sequences of length 3 for ASCII device cycle dvc2.

You can also specify a fractional x-mode factor in the xfact column of the global configuration file. The format is <m>/<n>. Then m state characters will be mapped to n test system cycles (waveform DC/DC power units).
