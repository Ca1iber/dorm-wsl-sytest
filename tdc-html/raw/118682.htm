ERCE? - (Expected and Received Cycle data of Events)

The ERCE? query returns test point related cycle data in a variety of formats. The query returns one answer per pin. In contrast to ERRE?, operations that do not generate a result can also be reported.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Predependencies

If result data are requested, a test point pattern must have been executed for DC Scale pins.

Syntax

ERCE? {type},{start_cycle},{no_of_cycles},{data_format},{rep_mode}, [byte_max], {(pinlist)}

returns:

ERCE  {type}, {start_cycle}, {no_of_cycles}, {data_format}, {rep_mode}, [error_status], {(pin)}, {#spec(data)}

Parameters

type

The supported types are:

RCV

Requests received data only.

Can only be requested if a test point pattern has been executed for DC Scale pins.
EXP Requests expected or setup data of all test point events, not only those that generate a result.
ALL

Requests both expected and received data of events that generate a result.

This option can only be requested if a test point pattern has been executed for DC Scale pins.
start_cycle The start cycle of the area from which event data is to be reported. Cycles are counted from 0.
no_of_cycles The length of the cycle area from which event data is to be reported.
data_format Specifies the binary data format of #spec(data). The DC Scale cards DPS32, VI32, and UHC4 / UHC4T support both formats.
0 This format contains PASS/FAIL and status information for every cycle. It can be used for status analysis where expected data and measurement values are not required. This format is only available for type RCV.
1

This format can return both received and expected data.

The received data of format 1 not only contains PASS/FAIL and status information for every measurement, but also the measurement type and value.

The expected data contains all the setup information of the respective event.

Format 1 is available for all three types RCV, EXP, and ALL).
rep_mode Specifies the reporting mode. Possible values are:
ALL Reports all results within the selected area.
EOLY Reports only failed results including measurement errors (that is, too small a distance between two measurements, or type mismatch between measurement and range). This mode is not available for type EXP.
byte_max

In the query, this parameter specifies the maximum number of bytes that may be returned. This option can be used for the reporting mode EOLY, where the size of the data that will be returned cannot be calculated beforehand.

In the reply, this parameter is used to indicate the reason in case that not all the requested results can be returned:
EOB The number of requested results exceeds the maximum buffer length specified with byte_max.
EOF The result range of the query exceeds the length of the test.
EOM This code is returned if the size of the answer exceeds the available storage capacity.
pinlist Only DC Scale pins are considered.
#spec(data)

The binary data that are returned. The general format is:

#Nn1n2n...nNdata_stream

The N digit defines the number of the digits ni (1 ≤ i ≤ N) that specify the length of data_stream in bytes.

The data stream itself consists of a stream header and one or more answers (only one answer for data formats 0 and 1), where every answer contains the same number of data blocks.

The stream header defines

  • the number of answers (4 long bytes, big-endian encoded)
  • the number of data blocks per answer (4 long bytes, big-endian encoded).

Every data block consists of a block header and one data unit which contains the data of one event (td element).

The block header specifies the cycle number of the event anchor (defined with TPSE) (8 long bytes, big-endian encoded). The cycle number can be different from the event anchor, which is a vector number.

The length of the data units depends on the selected format and on the selected type. If type is set to ALL, each data unit consists of the expected data and the received data in this order.

Binary data formats

There are currently two data formats, 0 and 1.

Data format 0

This format only contains the received data, one byte for each measurement event. The individual bits must be decoded as follows:

Content

Bits

Description

Compare result

0 (LSB)

Upper limit. This flag is set to 1 if all of the following conditions are satisfied:

  • An upper limit is specified (limitHigh attribute of measure operation).
  • The check of the upper limit is active (failAboveHighLimit attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false with DFTD).
  • The measured value is greater than the upper limit.

1

Lower limit. This flag is set to 1 if all of the following conditions are satisfied:

  • A lower limit is specified (limitLow attribute of measure operation).
  • The check of the lower limit is active (failBelowLowLimit attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false with DFTD).
  • The measured value is smaller than the low limit.

2

Status information. This flag is set to 1 if at least one of the following conditions is satisfied:

  • One of the bits 3 through 5 is set to 1 and active, and the measurement result is not masked.
  • Bit 6 is set to 1
  • Bit 7 is set to 1

Status information

3

Low clamp violation. This flag is set to 1 if there is a low clamp violation.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of low clamp violation is active (failOnLowClamp attribute of measure operation set to true with DFTD)
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

4

High clamp violation. This flag is set to 1 if there is a high clamp violation.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of high clamp violation is active (failOnHighClamp attribute of measure operation set to true with DFTD).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

5

Measurement range exceeded. This flag is set to 1 if the measurement range is exceeded.

But note that it is evaluated for the status information (bit 2) only if the following additional conditions are satisfied:

  • The check of the measurement range is active (failOnOutOfRange attribute of measure operation set to true).
  • The measurement result is not masked (maskPassFail attribute of the measure operation set to false).

6

Distance too small. This flag is set to 1 if the distance between two consecutive measurements is too small. It is always evaluated for the status information (bit 2), even if the measurement result is masked.

7 (MSB)

Type mismatch. This flag is set to 1 if the measurement type does not match the measurement range. It is always evaluated for the status information (bit 2), even if the measurement result is masked.

This format can also accommodate the expected data. One expected data block covers one event (td element). The block format is as follows:

Example

The following example shows a query for expected data only in the cycle range from 0 through 60000. 

> ERCE? EXP,0,60000,1,ALL,,(dpsPinMea)
< ERCE EXP,0,60000,1,ALL,,(dpsPinMea),#9000000405
    /x00/x00/x00/x01/x00/x00/x00/x0F
    /x00/x00/x00/x00/x00/x00/x00/x46
    /x00/x1D
    /x00/x00/x00/x00/x00/x00/x00/x00
    /x40/x10/x00/x00/x00/x00/x00/x00
    /x00
    /x00/x00/x00/x00/x00/x00/x00/x00
    . . .

The data stream has been broken up to make it more readable. The answer contains 15 (/x0F) data blocks, of which only the first is displayed in the example. Its cycle number is 70 (/x46). The event is a voltage range definition (x1D) which is defined by DFTD as follows

DFTD "myNamespace",INSERT,(dpsPinMea),#2473<?xml version="1.0"?>
<testdata>
  <td id="setMeasVoltRange" type="dcset">
    <setMeasureRange type="voltage" minValue="0" maxValue="4"/>
 . . .

Since this is not a measurement event, the result check byte is set to 0. Note that the cycle number and the two range limits are big endian coded. The event contains no setForceValue operation.

Functional changes
