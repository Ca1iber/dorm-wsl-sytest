The Parameters of v2b

  • -2 (optional): This flag causes v2b to use only two bits for scan vectors in the extended scan memory. With this restriction, the greatest possible physical waveform index is 3. This flag only applies to the HP83000.
  • -A (optional): By default, v2b adds the names of the ASCII device cycles as comments to the binary vectors. The flag -A causes v2b to suppress these comments.
  • -a<temp_dir> (optional): This parameter specifies the directory where the temporary files are to be stored. By default, they are stored in the current directory. If two v2b calls are executed in parallel, they should use different directories for their temporary files.
  • -B <unit> (optional): This parameter defines the unit for automatic detection of scan vectors. Every scan template generated will be a multiple of this unit. For details, see Detecting Scan Vectors Automatically.
  • -b (optional): This flag causes v2b to create only the vector download commands, and no sequencer program.
  • -C (optional): There are two download commands for the vectors (physical waveform DC/DC power units), VECC and VECD. They differ in that the waveform DC/DC power units are passed to VECC in compressed form, which usually reduces the size of the data to be downloaded. The -C flag causes v2b to use VECC whenever this is the case. aiv automatically sets this parameter when it calls v2b.
  • -c <pattern_config_file> (optional): This parameter specifies a pattern configuration file. If it is omitted, v2b assumes that all ASCII device cycles in the ASCII vector file are associated with timing set 1. If your timing is equation based, and you omit this parameter, you must specify the base wavetable for the pattern with the -w parameter.
  • -cmb <x-mode_control_file> (optional): This parameter puts v2b in a special mode, where it does not create a binary vector file, but checks a given x-mode control file against the ASCII vector file that was passed to it. It expands the x-mode control file by all those state character combinations that occur in the ASCII vector file, but are missing in the x-mode control file. Note that you cannot activate this option only for selected patterns in the vector configuration file (*.aiv). It must be specified globally in the AI_V2B_OPTIONS section. For more information see Adapting the X-Mode Control file to the ASCII Vector Files.
  • -D (optional): This flag causes v2b to write a normalized, pin oriented version of the timing map file into the file v2b.ddc.
  • -d<timing_map_file> (mandatory): This parameter specifies the timing map file for the vector translation.
  • -dvcat (optional): This switch prevents the VCAT command being inserted to the binary vector file in all cases that no matter what else v2b parameters are used.
  • -E (optional): This flag causes v2b to delete temporary files after usage.
  • -e <output_command> (optional): This parameter redirects the binary output to the specified command.
  • -f<frame_base_name> (optional): This parameter defines a base name for automatically generated scan frames.
  • -G (optional): This flag causes v2b to create a file <label>.toc, where <label> is the name specified for the -l parameter. This file provides for every ASCII device cycle and pin a list of the state characters that actually occur in the ASCII vector file, and their frequency.
  • -g <context> (optional): This parameter specifies the context for the pattern. The context defines which pins are used as differential or fast pins.
  • -H (optional): This flag causes v2b to suppress the header in the binary vector file. If you insert the SAOF APP firmware command at the top of the file instead, you can append the file to another binary vector file.
  • -h (optional): This flag causes v2b to display a help file about itself.
  • -I (optional): This flag must be used in combination with the -S flag, which tells v2b to translate the ASCII vector file as a scan subroutine. -I causes v2b to translate only the SCAN_DATA sections of a scan subroutine. For details, see Defining Scan Subroutines in the ASCII Interface.
  • -imc (optional): This flag causes v2b to suppress the comments it inserts by default when converting an ASCII scan setup into a binary multi-port setup. The conversion is activated with the -imp flag. For details see Converting an ASCII Scan Setup Into a Binary Multi-Port Setup.
  • -imp (optional): This flag causes v2b to convert an ASCII scan setup into a binary multi-port setup. For details see Converting an ASCII Scan Setup Into a Binary Multi-Port Setup.
  • -impv (optional): This flag causes v2b to convert an ASCII scan setup into a binary multi-port setup and also to insert an instance of the VCAT command for every scan instance in the pattern. For details see Converting an ASCII Scan Setup Into a Binary Multi-Port Setup.
  • -is (optional): This flag causes v2b to create different state mapping tables for different scan templates. If it is omitted, only one state mapping table will be created for all scan templates. See The State Mapping Tables for the Scan Tool.
  • -J<port_name> (optional): This parameter specifies to which port the pattern belongs. The port can also be specified in the ASCII vector file (see Specifying the Port in the ASCII Vector File). The -J parameter has priority. If no port is specified at all, the default port @, to which all pins belong, will be assumed.
  • -j (optional): This flag causes v2b to create a jump label (type SJMP) instead of a MAIN pattern.
  • -k (optional): By default, the vector download commands (VECD, VECC) created by v2b store the physical waveform DC/DC power units in the Vector Memory. The flag -k causes v2b to specify the Sequencer Memory as the location for the waveform DC/DC power units in the vector download commands. This is required, for example, for digital capture.
  • -K <multiplexing_file> (optional): This parameter tells v2b to replace the HXA pins in the ASCII vector file by Pin Scale pins according to the entries in the specified multiplexing file. For details, see Vector Translation for HXA Multiplexing.
  • -L (optional): By default, v2b adds the number of the ASCII vector as a comment to the corresponding binary vector. The flag -L causes v2b to suppress this number.
  • -l <label> (mandatory): This parameter defines the label of the pattern (first parameter of the SQLB firmware command). It can consist of up to 128 alpha-numeric characters. This parameter does not support the definition of a path like -l <path/label>. To specify the path of the ASCII vector file, use the -v <ASCII_vector_file> parameter.
  • -M <length> (optional): Specifies the maximum length of an ASCII vector section that will be converted into a scan instance and for which a template will be defined by automatic scan detection. For details, see Detecting Scan Vectors Automatically.
  • -m <length> (optional): Specifies the minimal length of an ASCII vector section that will be converted into a scan instance and for which a template will be defined by automatic scan detection. For details, see Detecting Scan Vectors Automatically.
  • -N (m|o)<file_name> (optional): This parameter either activates discarding of oversampled vector data and specifies the oversampling map file (option m), or it defines a port specific target file for converted data (option o). For details, see Discarding Oversampled Vector Data.
  • -O (optional): This flag causes v2b to create vectors to compare on odd cycles for high frequency pins. By default, the even cycles will be created.
  • -o<binary_vector_file> (optional): This parameter defines the name of the binary vector file that is created by v2b. If it is omitted, the name is derived from the label (-l parameter). If you specify the minus sign (-) instead of a name, v2b will write the output to stdout. This can be used to pipe the output to another tool.
  • -P (optional): This flag causes v2b to write the internally used pin database to the file v2b.pdb. This can be used for debugging purposes.
  • -p <pin_config_name> (mandatory): Specifies the name of the pin configuration file.
  • -Q (optional): This flag causes v2b to suppress scan template and scan frame definitions that occur in the ASCII vector file in the binary vector file.
  • -q [<buffer_lines>] (optional): This parameter activates the use of temporary files containing the ASCII vector data for one pin (preparing the creation of the pin specific download commands); using these files considerably improves the performance of the vector translation. The additional optional value specifies the size of the buffer from which the temporary files number are created and expanded. The default is 512.

    If you call v2b directly, you should activate the use of these files. The default size of the buffer is usually sufficient. aiv automatically sets this parameter when it calls v2b.

  • -R (optional): This flag causes v2b to create a file <label>.rep, where <label> is the value of the -l parameter, which specifies the ASCII vectors of the ASCII vector file where the ASCII device cycle changes or the state character for a pin changes.
  • -r <number_of_repetitions> (optional): This parameter determines the greatest repeat factor (first component of an ASCII vector) which is still flattened and not converted into an RPTV sequencer instruction. The default is 16. For more information, see Processing a Repeat Factor > 1.
  • -S (optional): This flag causes v2b to translate an ASCII vector file as a scan subroutine. The ASCII vector file must have a special format, where the scan data is not specified in the ASCII vector table, but in separate SCAN_DATA sections.

    Normally, v2b then creates a binary vector file that contains not only the scan subroutine, but also a MAIN pattern that calls the subroutine as many times as is implied by the SCAN_DATA sections. But the output can be modified by specifying the -I flag or the -u parameter in addition to the -S flag. For details, see Defining Scan Subroutines in the ASCII Interface.

  • -s (optional): This flag causes v2b to create a subpattern (type SVEC) instead of a MAIN pattern.
  • -T (optional): This flag causes v2b to suppress insertion of a CTIM sequencer instruction (which forces a change of the timing set) before the first vector.
  • -t (optional): This flag causes v2b to insert a CTIM sequencer instruction (which forces a change of the timing set) after each subpattern call (JSUB sequencer instruction). Note that this is done even if the ASCII device cycle of the last vector in the subpattern and that of the first vector in the calling pattern after the call are associated with the same timing set.
  • -U (optional): This flag causes v2b to suppress comments to ASCII vectors (see The ASCII Vector Row) in the binary vector file.
  • -u<step_width> (optional): This parameter must be used in combination with the -S flag, which tells v2b to translate the ASCII vector file as a scan subroutine. It causes v2b to generate only the sequencer program of the (without a MAIN pattern or instance data). <step_width> specifies the step width of the minor instance offsets for instances of the same template within the subroutine. This value should be equal to the maximum repeat factor (RPTJ instruction) for any call of the subroutine. For details, see Defining Scan Subroutines in the ASCII Interface.
  • -V (optional): This flag causes v2b to issue the version of the tool.
  • -v<ASCII_vector_file> (optional): This parameter specifies the name of the ASCII vector file for the vector translation. If it is omitted, the name must have the format<label>.avc, where <label> is the name specified for the -l parameter. If you specify the minus sign (-) instead of a name, v2b will read the input from stdin. This can be used to pipe the output of another tool to v2b.
  • -W<waveform_set_no> (optional): With this parameter you can specify the base waveform set for the pattern.
  • -w<wavetable> (optional): With this parameter you can specify the base wavetable for the pattern. The wavetable can also be specified in the pattern configuration file (see Structure of the Pattern Configuration File). The entry in the pattern configuration file has priority.
  • -xa (optional): With this parameter you can specify that the <number_of_vectors> parameter of a RPTV or MRPT instruction is corrected according to the number of ASCII vectors defined by the PADDING instruction, if these two specifications do not agree. For details, see The PADDING Instruction. This option can be combined with the -xpi option.
  • -xpe [<n1>,<n2>, ...,<nm>][<padding_translation_file>] (optional): With this parameter you can specify one or more integers and/or a padding translation file for x-mode ASCII vector padding at the end of the ASCII vector file. Note that the padding as such is always enabled at the end of the file. For details on x-mode ASCII vector padding, see X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding.

    The additional integers influence the number of padding vectors created by v2b. If one or more of them are present, then the number of padding vectors will be such that the total number of ASCII vectors in the padded block is directly divisible by this integer (and not only by the x-mode factor of the respective pattern). This can be used to synchronize the restart of the main pattern after a subroutine call in patterns that belong to different ports and run with different x-mode factors. For more information, see Synchronizing Subroutine Calls in Different Ports.

    The padding translation file defines the padding state characters (see The Padding Translation File). If you omit the file name, the default padding will be used.

  • -xph [<padding_translation_file>] (optional): With this parameter you can enable x-mode ASCII vector padding before automatically inserted CTIM or RPTV instructions, and additionally specify a padding translation file (see The Padding Translation File). If you omit the file name, the default padding will be used. For details on x-mode ASCII vector padding, see X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding.
  • -xpi [<n1>,<n2>, ...,<nm>] [<padding_translation_file>] (optional): With this parameter you can enable x-mode ASCII vector padding before sequencer instructions that are coded in the ASCII vector file. In addition, you can specify one or more integers, and/or a padding translation file. For details on x-mode ASCII vector padding, see X-Modes, Processing of the Repeat Factor, and ASCII Vector Padding.

    The additional integers influence the number of padding vectors created by v2b. If one or more of them are present, then the number of padding vectors will be such that the total number of ASCII vectors in the padded block is directly divisible by this integer (and not only by the x-mode factor of the respective pattern). This can be used to synchronize corresponding blocks in patterns that belong to different ports and run with different x-mode factors. For more information, see Synchronizing Scan and Parallel Ports with Different X-Mode Factors and Synchronizing Subroutine Calls in Different Ports.

    The padding translation file defines the padding state characters (see The Padding Translation File). If you omit the file name, the default padding will be used.

  • -Y <max_no_of_scan_pins>x<max_template_length> (optional): With this parameter, you can define the maximum number of scan pins and the maximum length of scan templates. The default value for <max_no_of_scan_pins> is 8, and the default value for <max_template_length> is 262144, which is also the absolute maximum template length. This parameter determines how much memory is allocated for the scan instances. You can use it to reduce the size of the allocated memory if the length of your templates is smaller than 262144.
  • -z[<test_system_type>] (optional): This parameter defines the test system type for which the binary vector file is created. Possible values are:
    • PS800: enables use of @diff qualifier.
    • PS3600: enables use of @diff qualifier.
  • -xf (optional): Used to automatically flatten SQPG RPTV loops.
