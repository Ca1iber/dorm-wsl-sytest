Multiport equation setup

In a multiport setup an equation set is associated with ports. One or more ports may be included in the same equation set and as in a non-multiport setting and multiple timing sets can be assigned to every equation. It is recommended that multiple timing sets per equation settings are not utilized. In cases where synchronization among ports is required, the definition of multiple timing sets may become a problem on the calculation of the synchronization interval and/or increase the test time.

Every equation set defines the edge delays and periods for the pins of one or more port. For the setup of an equation set:

  • Define the edge delays and the period of a number of pins in one equation set. The pins can belong to different ports.
  • Insert a line
    DEFINES <port1> ... <port2>

    The keyword DEFINES followed by a list of port names is the only new keyword introduced in the equation set syntax to support multi-port. The purpose of this keyword is to check if the equation set defines edge delays and periods for all pins of the ports included in the port list of the DEFINES statement.

The equation set can also include pins of other ports so that you can use the equation set for these ports as well. The application use is associated with a reduction on the number of ports defined in the pin configuration and it allows a different set of vector ports to be executed with a given set of timing ports and/or pins to be set in a continuous clocking or static state without utilizing vector data.

As in a single-port setup, an equation set is defined utilizing the Timing Setup Editor. See Verifying a multiport timing setup.

Syntax

EQNSET <EqnSetNumber> "<EqnSetDescription>" 
DEFINES <Port1_Name> <Port2_Name> ... <PortN_Name>

    SPECS
      <SpecName1>
      <SpecName2>
      <SpecName3>
        . . .
      <SpecNameN>

    EQUATIONS
      <EquationVariable1> = <Expression1>
      <EquationVariable2> = <Expression2>
      <EquationVariable3> = <Expression3>
                  . . .
      <EquationVariableM> = <ExpressionM>

    TIMINGSET 1 "<TimingSet1Description>"
      period = <PeriodExpression>
      PINS  <Pin1_Name>|<PinGroup1_Name> ... <PinN_Name>|<PinGroupN_Name>
                      . . .

Example

The following example illustrates the general syntax description above:

EQNSET 2 "specs_search_eqn"
DEFINES port_1 port_2

SPECS
    f            [MHz]
    ts_Sx_CP     [ns]
    th_CP_Sx     [ns]
        . . .

The new keyword DEFINES is the only difference to the syntax you know from a single-port equation set. This means that

  • spec declarations (keyword SPECS),
  • definition of equations (keyword EQUATIONS),
  • definition of timing sets (keyword TIMINGSET),

remain unchanged from a single-port setup with the added capability of defining port specific sets.
