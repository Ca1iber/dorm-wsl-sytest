Access Routines

The Command Set Programming Interface provides a variety of functions to get and set the Flags and Variables as previously described. In the Production set routines, the value passed on by the user is validated to ensure that the range of the flag is not exceeded. For user flags, the non-validated value is passed on to the flag.

The routines are grouped into get/set functions for test suite, test flow, system, user, and application model file flags/variables. Where a flag is set, the parameter description is named flag. For a variable, the parameter description is name. When Tsname occurs in the function get/set TestSuiteFlag, it is a reference to the testsuite where the flag is located.

Although all flags are internally defined as an int, the routines declare a long. This is simply for compatibility reasons with VEE which does not have an int type. The interface is robust because you cannot exceed flag limits on set, and the get routines internally typecast the int to a long. Because the underscore character is also illegal within VEE function declarations, they have been omitted within function and parameter names.

Some get, and set functions are specific to multi-site testing. Unless the function contains a parameter that allows you to specify the site number (for example GetSystemFlagOfSite), always assume that the function refers to the site that is currently in focus. When you specify a site in one of these functions, the site number must be in the range, 1..CI_CPI_MAX_SITES.

All functions are type dependent, so it is not possible to misuse the function SetUserFlag (for example) to set a SystemFlag and vice versa. Each routine has a clearly defined purpose in the CPI set.
