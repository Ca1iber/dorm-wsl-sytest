Topic 74892

FLEX_RELAY

Subtopics

  1. FLEX_PIN_RELAY
  2. FLEX_UTILITY_RELAY
  3. FLEX_UTILITY_PURPOSE_RELAY
  4. FLEX_UTILITY_CHANNEL_RES

The FLEX_RELAY class is a data container holding the contents of the task for setting up relay connections. You can control the relays for the digital channel pins and the user relays that are controlled by the utility lines.

This API has the following features.

  • Controls various types of relays with unified programming interface:
    • Relays in digital channels (relays on channel boards and clock boards).

      For example, you can set digital pins to Hi-Z by disconnecting the relays.

    • User relays (controlled by the utility lines).
  • Supports multi-site testing
  • Enables you to activate utility line settings by executing the task. You can activate them without using the FLUSH API, which activates various parameters specified with other APIs at a time.
  • In a test method program, you can use both of the FLEX_RELAY API and the Routing.util()/Routing.util_purpose() API whose settings are activated by the FLUSH API. However, controlling the utility lines by using either one in each test method program would be a good practice: for example, control the utility lines with FLEX_RELAY in digital/DC tests, and control them with Routing.util()/Routing.util_purpose() in mixed signal tests where the routing sets and analog module relay settings and so on are activated by the FLUSH API.
This class has four subsidiary data containers, which are for digital pins, utility lines, and utility purposes, respectively.
  • FLEX_PIN_RELAY:

    Holds the relay settings for the specified digital channels.

  • FLEX_UTILITY_RELAY:

    Holds the utility line (user relay) settings specified with the utility line names.

  • FLEX_UTILITY_PURPOSE_RELAY:

    Holds the utility line (user relay) settings specified with the utility purposes.

  • FLEX_UTILITY_CHANNEL_RES:

    Holds the settings of utility line channel resources.

These four class objects are stored in the FLEX_RELAY class object. When the task is executed, the settings defined with these four subsidiary containers are downloaded to the hardware.

To execute the task, use the execute() member function of the class, or the TASK_LIST API.

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/FlexRelay.h.

FLEX_RELAY();

This constructor creates an object of the FLEX_RELAY class.

List of parameters
The constructor has no parameters.
Return value
The constructor has no return value.

Using the class

For creating an object, which holds the settings of a task:

FLEX_RELAY object;

For setting up relays for the digital channels:

object.pin("pinlist").member_func;

member_func is a member function of the FLEX_PIN_RELAY class.

For setting up utility lines (user relays) with utility line names:

object.util("utilitylist").member_func;

member_func is a member function of the FLEX_UTILITY_RELAY class.

For setting up utility lines (user relays) with utility purposes:

object.util_purpose("uti_purposelist").member_func;

member_func is a member function of the FLEX_UTILITY_PURPOSE_RELAY class.

For setting up utility lines (user relays) with utility channel resources:

object.util_channelRes("channel_list").member_func;

member_func is a member function of the FLEX_UTILITY_CHANNEL_RES class.

For setting a wait time after controlling the relays specified in the task when the task is executed:

object.wait(time);

For executing the task defined with the FLEX_RELAY API:

object.execute();

Member functions

pin()
FLEX_PIN_RELAY& pin(const STRING& pinlist);

This member function specifies digital pins, and returns the reference to the FLEX_PIN_RELAY class object that represents the setup data for relays associated with the specified digital pins. To make a setting, use the member function of the FLEX_PIN_RELAY API.

Parameter
Parameter Description
pinlist

A target pin name or pin group name of the digital channel pins. You can specify multiple pins and pin groups by separating with a comma.

"@" specifies all the defined digital channel pins, including the digital pins that are used as the trigger source of the analog modules.

All pins must be configured as i, o, io, or dc pin in the Pin Configuration window.
Return value
A reference to the FLEX_PIN_RELAY class object.
util()
FLEX_UTILITY_RELAY& util(const STRING& utilitylist);

This member function specifies utility lines, and returns the reference to the FLEX_UTILITY_RELAY class object that represents the setup data for relays associated with the specified utility lines. To make a setting, use the member function of the FLEX_UTILITY_RELAY API.

Parameter
Parameter Description
utilitylist A utility line name or a list of utility line names separated with a comma. You can use the name defined in the Utility Pins editor.
Return value
A reference to the FLEX_UTILITY_RELAY class object.
util_channelRes()
FLEX_UTILITY_CHANNEL_RES& util_channelRes (const STRING& channellist);

This member function specifies a list of utility line channel resources and returns the reference to the FLEX_UTILITY_CHANNEL_RES class object. To set the channel resources, use the member functions of FLEX_UTILITY_CHANNEL_RES API.

Parameter
Parameter Description
channellist A utility line channel resource or a list of utility line channel resources separated with commas. It can be "@", that means all the utility line resources.
Return value
A reference to the FLEX_UTILITY_CHANNEL_RES class object.
util_purpose()
FLEX_UTILITY_PURPOSE_RELAY& util_purpose(const STRING&utility_purposes);

This member function specifies utility purposes, and returns the reference to the FLEX_UTILITY_PURPOSE_RELAY class object that represents the setup data for relays associated with the specified utility lines. To make a setting, use the member function of the FLEX_UTILITY_PURPOSE_RELAY API.

Parameter
Parameter Description
utility_purposes A utility purpose name or a list of utility purpose names separated with a comma. You can use the names defined in the Utility Purpose Editor.
Return value
A reference to the FLEX_UTILITY_PURPOSE_RELAY class object.
wait()
void wait (const DOUBLE& time);

This member function defines a wait time after controlling all relays in the task when the task is executed.

Parameter
Parameter Description
time

Wait time for the task in seconds (s).

Specify a positive value or zero.
Return value
There is no return value.
execute()
void execute();

This member function executes the task defined with FLEX_RELAY.

This member function checks whether the settings in the task are validated or not. If any error message is generated, this member function performs no action, that is, any setting is not downloaded to the hardware.

The sequence of the task execution is as follows:

  1. Download the settings of relays related to digital pins to the hardware if defined.
  2. Download the settings of utility lines specified with util_purpose()/util() to the hardware if defined.
  3. Wait for the specified time.
List of parameters
There are no parameters.
Return value
There is no return value.

Examples

Single site testing

//
// Construct TASK_LIST class object "tasklist1"
// and FLEX_RELAY class object "frelay".
//
TASK_LIST tasklist1; 
FLEX_RELAY frelay;

//
// Set "PIN1" to Hi-Z by setting the AC, DC, PPMU relays to off.
//
frelay.pin("PIN1").set("IDLE","X");

// Use utility purposes "group1" and "group2":
//
// - "group1" definition: 16501:ON, 16502:ON, 16503:OFF.
// - "group2" definition: 16503:ON, 16504:OFF, 16505:ON.
//
// "16503" is included in both the groups. The setting of
// "16503" in "group1" is overwritten by the setting in "group2".
// Thus, "16503" is set to ON by the following statement.
//
frelay.util_purpose("group1,group2").set();

//
// Modify the previous utility line settings:
//
// Change 16501 to OFF.
// Change 16504 and 16506 to ON.
//
frelay.util("UTL101").off();
frelay.util("UTL104, UTL106").on();

//
// Add "frelay" of FLEX_RELAY to the task list.
//
tasklist1.add(frelay);

//
// Execute the tasklist1, that is, "frelay" task.
//
tasklist1.execute();

In the last statement, frelay.execute() is called from the TASK_LIST class object tasklist1 internally, and the task frelay is executed. All the relay settings are download to the hardware after checking whether the settings are validated or not. If an error is found, this statement does nothing except displaying the error message.

You can also execute the frelay task by executing the frelay.execute() statement.

Multi-site testing

STRING utilgrp = "UTL1, UTL2, UTL3, UTL4, UTL5";

//
// "UTL1" to "UTL5" are the following utility lines
//
// For Site1: 16501, 16502, 16503, 16504, 16505
// For Site2: 16506, 16507, 16508, 16509, 16510
//
STRING setting_1 = "1,1,1,0,0";
STRING setting_2 = "0,1,1,0,1";

FLEX_RELAY frelay;

ON_FIRST_INVOCATION_BEGIN();

    //
    // common setting in all sites;
    //
    frelay.pin("PIN1").set("IDLE");

    //
    // site-specific settings
    //
    FOR_EACH_SITE_BEGIN();

        INT site = CURRENT_SITE_NUMBER();

        if(site == 1)
        {
            frelay.util(utilgrp).set(setting_1);
        }
        else if(site == 2)
        {
            frelay.util(utilgrp).set(setting_2);
        }

    FOR_EACH_SITE_END();

    //
    // Download the relay settings to the hardware
    //
    frelay.execute();

    //
    // Execute a test here
    //
    ...
    ...

ON_FIRST_INVOCATION_END();
