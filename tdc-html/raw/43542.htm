Topic 43542

Executing a work order from the command line

A workorder may also be specified on starting SmarTest. The workorder can be either a file name or the absolute path of the workorder or workorder status file. Please note that SmarTest will be terminated after completion of the workorder that is started from the command line.

About this task

For the workorder to be specified as a file in the command line, it should reside in the $HOME/workorder directory of the Operator starting the workorder. For example, an Operator starting SmarTest in online mode would use the command:

HPSmarTest -O wo_file

The workorder can also be specified as an absolute path, if the workorder does not reside in a user's $HOME/workorder directory. The command for an Operator starting SmarTest in online mode, in this case, would be:

HPSmarTest -O /wo_dir/wo_file

SmarTest may also be started with the workorder status file (see Viewing Results After Workorder Execution for details on the workorder status file.) as an additional command line parameter allowing you to specify the workorder status file name and an absolute directory path for it (if different from that of the workorder). If the workorder status file already exists, a unique identifier is added to the file name.

An Operator starting SmarTest in online mode would use the command:

  • HPSmarTest -O wo_file wo_status_file or
  • HPSmarTest -O wo_file /wo_dir/wo_status/wo_status_file.

Procedure

  1. Execute the workorder from the command line using one of the methods described above.

    The start dialog box will appear.

  2. If everything is ready, click start.

    A dialog box similar to that shown below then appears.

  3. Fill in the lot - data parameters, then click Continue.

    What happens after this point, whether you are running the workorder from the command line or the workorder manager, depends entirely on your application model file. If it is package_auto for example (one of the standard application model files), testing of the packages begins, and the Test Display shows the results from each test. However, as explained at the beginning of this section, we will take the wafer_auto application model file.

    • In the line dialog that follows (see the figure below), key in the number of wafers in your test, and then press return or click the Continue button.
    • In the subsequent screen, key in the cassette ID and then press return or click the Continue button.

      The wafer selection screen then appears, where you define the list of wafers you want to test. A full explanation of the wafer selection screen is given inUsing the Wafer Selection Screen.

    • Next, create or read a list of wafers you wish to test (see Creating a List of Wafers and Reading a List of Wafers).
    • Once you have finished creating your list, click Select to begin testing.

      While the tests are running, the wafermap graphically displays an overall passed/failed for each device (see Viewing Results During Workorder Execution). Depending on how the system flags have been set, individual pass/fail results can also be seen on a per-test-suite basis on the report window.
