Standard output of the Event Formatter

Regardless of the settings you make in the Report Dialog window (see Report Dialog window), the output of the report formatter always contains information on the test program, the application model levels, and the testflow.

Test program

The following lines show how data on the test program is presented in the report:

########## Started Testprogram MyTestPrg #########################
Test program MyTestPrg of device /tmp_mnt/home/joergm/joergm/demo_edl 
started on 02/18/98 at 15:04:47 on bidm01 by joergm

Test program terminated after 7 seconds on 02/18/98 at 15:04:54
########## Ended Testprogram MyTestPrg ###########################

The first three lines appear at the beginning of the report, the last two lines at the end. All other report data is included between these lines.

Note When you execute a testflow only, the test program name in the Report Formatter output is set to "Testflow".

Application model level

When an application model level is entered or left, lines as shown below for the application model level ‘lot' is included in the report:

Level lot started on 02/18/98 at 15:04:47
Level ended after 15 seconds on 02/18/98 at 15:05:02
Note The testflow execution happens at the lowest level of the application model, called the device level. When you execute a testflow only, the execution of the level device will be reported in the Event Formatter output.

Testflow

The start and end of a testflow is indicated like this:

Testflow started on 02/18/98 at 15:04:47
Site 1: P1
Flow ended after 4 seconds on 02/18/98 at 15:04:51

As you see in the example, the report contains the site ID (1, in the example above), the device ID (here: P1), and the start and end time of the testflow.

Variable assignments

Any assignment of a value to a variable is reported by a line like:

Assign testvariable = 2.432000

or, if the assignment was site specific, by a line like:

Assign Site 1: testvariable = 2.432000

Binning

Any binning of a device is reported by a line like:

Site 1 has PASSED. Binned to bin 1(1)

The pass/fail information is taken from the specification of the bin the device is binned to. A good bin will generate a PASSED result, while a bad bin will generate a FAILED result for that site.

Functional changes

  1. Introduced before SmarTest 6.3.2
