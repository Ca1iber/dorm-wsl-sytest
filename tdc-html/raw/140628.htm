Topic 140628

Special conversion issues

In some cases that may not be obvious, SmarTest Program Manager MCM (STPM MCM) has to modify data imported from a source test program (STP) into a master test program (MTP) or it may be unable to import the STP.

Some of these cases are described below.

Converting dc_tml.Leakage and multi_group_dc_tml.Leakage tests for a multiport environment

The dc_tml.Leakage test method does not work in multiport environments; the multi_group_dc_tml.Leakage may require modifications to work.

STPM MCM tries to substitute the test function of modify the parameters automatically. If it can do so, it continues with the conversion and notes the modification in the Notes column of the MTPT Test suite table. If no automatic modification is possible, it inserts an error in the Notes column and stops the conversion.

STPM MCM tries to modify tests using these test methods automatically when they are imported from an STP into the MTP. If it can do so, it continues with the conversion and notes the modification in the Notes column of the MTPT Test suite table. If no automatic modification is possible, it inserts an error in the Notes column and stops the conversion.

There are three principal cases:

  • If the dc_tml.Leakage test method is used, STPM MCM will replace it with multi_group_dc_tml.Leakage and maps the parameters to the new method.

    A note about the conversion is inserted in the Notes column of the MTPT Test suite table.

  • If the multi_group_dc_tml.Leakage test method is used (either because it was specified in the STP or because dc_tml.Leakage was specified and automatically converted, as described above), how STPM MCM handles the conversion depends on the setting of the preFunction parameter:
    • If preFunction is set to ToStopVec, the test method cannot run in a multiport environment and STPM MCM cannot automatically correct the issue. It inserts an error message in the Notes column of the MTPT Test suite table; no functional MTP is created before the error is resolved.

      In this case, you must change ToStopVec to ToStopCyc and convert all vector-based parameter values to cycle based ones.

      You can make this conversion in the MTP (so that the STP does not need to be modified), by inserting the required parameter and value in the Parameters column of the MTPT Test suite table.

      To determine the required cycle numbers, you can run the test suite in offline mode in SmarTest and open the resulting BINL file in the Pattern Editor in expanded mode (where both vector and cycle numbers are shown).

    • If preFunction is set to ToStopCyc, STPM MCM automatically appends the port name to the values of the stopCycVecLow and stopCycVecLow parameters.

      For example, if the STP contains stopCycVecLow = "2", this is converted to stopCycVecLow = "2@stp1_port".
