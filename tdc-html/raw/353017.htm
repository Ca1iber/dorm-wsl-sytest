Topic 353017

Model file sections

Subtopics

  1. Model file reference (tester.model)
  2. Model file reference (model/legacy)

The model file is organized in several sections. In each of these sections you can define specific test system aspects. The model file sections depend on the tester system.

When writing your model file, you have two options for which style to use:
  1. Option 1 is the 'tester.model' style, which was introduced with SmarTest 7.10, and can be used with both the Smart Scale and the EXA Scale tester systems.
  2. Option 2 is the 'model' (legacy) style, used in SmarTest versions < 7.10, which is used only with Smart Scale tester systems, but can be easily converted to Option 1 using the ModelFileConverter, see Converting legacy model files.
Note Some sections are common for the two options, while others are unique, and must not be mixed.
Note When both the tester.model and the legacy model file exist, the tester.model has priority over the model file.
Note In addition to the model file you may use one or more device license files for licensing-per-device. The concept of licensing-per-device is based on a licensing file for each device, the device license file. This concept allows you to better utilize your licenses by requesting only those licenses from the license server that are really required for a device.

Licensing-per-device does not break the model file concept and mechanisms. It is rather an add-on and enhancement of that concept. Therefore the device license file must contain only license relevant entries. To ensure compatibility the device license file uses the same syntax as the model file.

Important: If a device license file exists, its parameters will be evaluated and any licensing parameters in the model file will be ignored. To develop a device license file we recommend to use the Testflow Analyzer Tool (TAT).

Functional changes

  1. Introduced in SmarTest 7.10.0
