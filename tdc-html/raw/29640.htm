PRIMARY_STATUS - (Primary)

The PRIMARY_STATUS API accesses the data container holding the current definitions of digital primaries (timing-related primaries, level-related primaries, and start label). These definitions can be changed using the member functions.

This API can also be used to call the subsidiary data containers: The TIMING_SPEC and LEVEL_SPEC. API's class objects. Call these objects to change the definitions of the primary timing equation/spec sets and primary level equation/spec sets, and to change the definitions of the spec values. For multi-port testing, another subsidiary data container, the SPECIFICATION API's class object is available.

The changes of the definitions specified by this API are actually reflected to the hardware when any of the following APIs is executed.

  • EXECUTE_TEST
  • START_TEST
  • DIGITAL_CAPTURE_TEST
  • NB_DIGITAL_CAPTURE_START
  • FUNCTIONAL_TEST
  • FLUSH then SPEC_SEARCH.execute() member function
  • FLUSH then SEQUENCER_STATUS.run() member function
  • FLUSH then PMU_IFVM.execute() member function
  • FLUSH then PMU_VFIM.execute() member function
  • FLUSH then TASK_LIST.execute() member function
  • FLUSH then DPS_VFIM.execute() member function

The changes of the definitions specified by this API can be also reflected to the MCD when the FLUSH API is executed. This is an option to reflect the changes on the user interface such as the Test Program Explorer and the Spec Tool.

For retrieving the definitions, the current activated definitions are returned. Note that even if the timing set (or level set) is changed from the primary one to another one by the CTIM (or CLEV) sequencer instruction during the vector generation of the start label, the CTIM (or CLEV) sequencer instruction does not change the definition of primary timing set (or primary level set).

Class definition

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/PrimaryStat.h.

Constructor

There is no constructor available for this class.

To use the PRIMARY_STATUS API, you must always use the system-prepared class object Primary which represents the current definitions of the digital primaries or represents the digital primaries to be defined. You cannot create any object of this API.

Syntax for common tasks

  • For changing definitions of digital primaries:

    Primary.memberFunction();

    memberFunction

    Member functions of the PRIMARY_STATUS API.

  • For retrieving current definition of primary timing/waveform set number, primary level/DPS set number, or start label:

    return_value = Primary.memberFunction;

    memberFunction

    A member function of the PRIMARY_STATUS API. For retrieving data, only one member function is available.

  • For retrieving current definition of primary equation/spec set number (or specification name of multi-port testing):

    return_value = Primary.member_f.s_member_f;

    member_f

    A member function (getTimingSpec or getLevelSpec) of the PRIMARY_STATUS API. This member function calls a subsidiary data container (class object of the TIMING_SPEC or LEVEL_SPEC API). Only one member function is available.

    For multi-port testing, the getSpecification member function is available to call the subsidiary data container, SPECIFICATION API.

    s_member_f

    A member function of the subsidiary data container. Only one member function is available.

  • For changing a spec value in the spec set (or specification of multi-port testing) that is currently defined as the primary:

    Primary.member_f.s_member_f;

    For member_f and s_member_f, see the table above.

Member functions

timing()
PRIMARY_STATUS& timing(INT tset);
PRIMARY_STATUS& timing(const TIMING_SPEC& specset);
PRIMARY_STATUS& timing(INT tset, const STRING& port);
PRIMARY_STATUS& timing(const SPECIFICATION& specif);

The timing member function specifies the timing-related primaries (except the waveform set). Which primary you specify is determined by the data type of the specified parameter.

Parameters

tset

Integer timing set number to be defined as the primary. If you specify 0, the current definition is unchanged. Even if the setup is equation-based, use this parameter to define the primary timing set number.

specset

Name of a previously defined TIMING_SPEC object or

TIMING_SPEC(equation_set_no, specset_no).
For multi-port testing, the following parameters are also available:

port

Port name as string for which tset will be defined as the primary. If you omit this parameter, tset will be defined for all ports. To use this parameter, a specification of the timing setup must be currently defined as the primary or must be specified as the primary by the execution of the timing(specif) member function.

specif

Name of a previously defined SPECIFICATION object or

SPECIFICATION("specification_name").
waveform()
PRIMARY_STATUS& waveform(INT wfset);

This member function specifies the waveform set to be defined as the primary.

Parameter

wfset

Waveform set number to be defined as the primary. If you specify 0, the current definition is unchanged.

level()
PRIMARY_STATUS& level(INT lset);
PRIMARY_STATUS& level(const LEVEL_SPEC& specset);

This member function specifies the level-related primaries (except DPS set). Which primary you specify is determined by the data type of the specified parameter.

Parameter

lset

Integer level set number to be defined as the primary. If you specify 0, the current definition is unchanged. Even if the setup is the equation-based, use this parameter to define the primary level set number.

specset

LEVEL_SPEC level equation and spec set numbers to be defined as the primaries.
dps()
PRIMARY_STATUS& dps(INT dpsset);

This member function specifies the DPS set to be defined as the primary.

Parameter

dpsset

DPS set number to be defined as the primary. If you specify 0, the current definition is unchanged.
label()
PRIMARY_STATUS& label(const STRING& label);

This member function specifies the (digital) sequencer start label name to be activated.

Parameter

label

Start label name to be activated.

For multi-port testing, you can specify a multi-port burst label name as the start label.
getTiming()
INT getTiming();
INT getTiming(STRING& port);

This member function returns the currently defined primary timing set number. (Note that the CTIM sequencer instruction changes the timing set, but does not change the definition of the primary).

For multi-port testing, this member function returns the currently defined primary timing set number of the specified port:

Parameter

port

(For multi-port testing only.) Port name whose primary timing set number will be retrieved. To specify this parameter, a specification of the timing setup must be currently defined as the primary. If the currently defined primary timing set number is the same in all ports, you may omit this parameter even for multi-port testing.
getTimingSpec()
TIMING_SPEC& getTimingSpec();

This member function returns the TIMING_SPEC API's class object that represents the currently defined primary timing equation and spec set numbers and the spec values. For more information, see TIMING_SPEC. To use this member function, a timing spec set of the timing setup must be currently defined as the primary.

There are no parameters in this member function.

getWaveform()
INT getWaveform();

This member function returns the currently defined primary waveform set number. To use this member function, a waveform set of the timing setup must be currently defined as the primary.

There are no parameters in this member function.

getSpecification()
SPECIFICATION& getSpecification();

For multi-port testing only. This member function returns the SPECIFICATION API's class object that represents the currently defined primary specification name (of the timing setup) and the spec values (including per-port spec values). For more information, see SPECIFICATION. To use this member function, a specification of the timing setup must be currently defined as the primary.

There are no parameters in this member function.

getLevel()
INT getLevel();

This member function returns the currently defined primary level set number. (note that the CLEV sequencer instruction changes the level set, but does not change the definition of the primary).

There are no parameters in this member function.

getLevelSpec()
LEVEL_SPEC& getLevelSpec();

This member function returns the LEVEL_SPEC API's class object that represents the currently defined primary level equation and spec set numbers and the spec values. For more information, see LEVEL_SPEC. To use this member function, a level spec set of the level setup must be currently defined as the primary.

There are no parameters in this member function.

getDps()
INT getDps();

This member function returns the currently defined primary DPS set number. To use this member function, a DPS set of the level setup must be currently defined as the primary.

There are no parameters in this member function.

getLabel()
const STRING& getLabel();

This member function returns the currently activated (digital) sequencer start label.

For multi-port testing, this member function can return the multi-port burst label.

There are no parameters in this member function.

isTimingPortBased()
Boolean isTimingPortBased();

For multi-port testing (however, executable even for non-multi-port). This member function returns TRUE if any specification of the timing setup is currently defined as the primary (that is, TRUE if the current timing setup is port-based). Otherwise (that is, a non-multi-port spec set or waveform set is used), this member function returns FALSE.

Note Do not mix the usage of the firmware command with the test method API to query or change the hardware status. The test method API uses an internal cache which is not known and not accessible to the firmware command. The hardware status change made with the firmware command is not recorded in the cache and the subsequent hardware status querying with the test method API may return an incorrect result. To query the hardware status with the test method API, you need to change the hardware status with the test method API. To query the hardware status with the firmware command, you need to change the hardware status with the firmware command.
isLabelPortBased()
Boolean isLabelPortBased();

For multi-port testing (however, executable even for non-multi-port). This member function returns TRUE if any multi-port burst label is currently activated as the start label (that is, TRUE if the current vector setup is port-based). Otherwise, this member function returns FALSE.

There are no parameters in this member function.

assignLabelToCurrentSite()
PRIMARY_STATUS & assignLabelToCurrentSite(const STRING & label);

This member function assigns a site specific start label to the current site. It can only be used within a FOR_EACH_SITE block. Note that this function requires the parallel enable flag of the respective testsuite to be set. See also How to execute separate patterns per site.

Parameter

label

The label that is to be defined as the start label of the current site.
getAssignedLabelForCurrentSite()
const STRING & getAssignedLabelForCurrentSite();

This member function returns the start label for the current site. It can only be used within a FOR_EACH_SITE block. The function has no parameters.

assignPinToCurrentSite()
PRIMARY_STATUS & assignPinToCurrentSite(const STRING & pin = "");

This member function controls which label is to be executed on a channel that is shared for a pin by sites with different start labels. The operation mode of this function depends on whether it is used within or outside a FOR_EACH_SITE block. In the first case, it must be called with a pin which is associated on the current site with a channel also used by other sites. This call will have the effect that the start label of the current site will be executed on this channel. If the function is used outside a FOR_EACH_SITE block, it must be called with an empty parameter. This has the effect that all previously defined associations of channel sharing pins with a specific site are revoked. Note that this function requires the parallel enable flag of the respective testsuite to be set. See also How to execute separate patterns per site.

Parameter

pin

Name of a pin that is mapped to the same channel on several sites.
getAssignedPinForCurrentSite()
const STRING & getAssignedPinForCurrentSite();

This member function returns the channel sharing pins whose channel is associated with the current site. It can only be used within a FOR_EACH_SITE block. The function has no parameters.

getModeContextName()
bool getModeContextName(STRING& sModeContextName);
This member function returns the name of the currently active mode context.
Parameter

sModeContextName

Reference to an already defined string variable that is filled with the name of the active mode context.
Return value
The member function returns always true.

Important points

  • To use the PRIMARY_STATUS API, you must always use the system-prepared class object Primary, which is the single object of the PRIMARY_STATUS API. The constructor function is not available in the PRIMARY_STATUS API (you cannot create or destroy any object of this API).
  • When a test is started by any of the FUNCTIONAL_TEST(), START_TEST(), EXECUTE_TEST, DIGITAL_CAPTURE_TEST, or NB_DIGITAL_CAPTURE_START API, the digital primaries (the timing/level-related primaries and start label) that are specified by this API are automatically defined as the new settings (in the MCD) and are activated into the hardware. Therefore, you do not have to execute the FLUSH API if one of these APIs is used. However, FUNCTIONAL_TEST does nothing for the analog set and routing set (execute FLUSH before FUNCTIONAL_TEST if you execute a functional test that involves an analog module).

    If you need to generate vectors in a DC test API (PMU_VFIM, PMU_IFVM, or DPS_VFIM) after you specify the change of digital primaries using the PRIMARY_STATUS API, execute the FLUSH API beforehand to reflect the changes.

  • When one of the following member functions is executed, the changes of the primary timing set number and spec values that are specified in the PRIMARY_STATUS, TIMING_SPEC, and SPECIFICATION APIs are cleared if the FLUSH API has not been executed for them yet.

      timing(const SPECIFICATION& specif)

Examples

Change the primary timing set

Primary.timing(3);

FUNCTIONAL_TEST();

The timing member function specifies timing set 3 as the primary timing set to be defined, and FUNCTIONAL_TEST reflects it to the hardware then executes a functional test.

Retrieve the primary DPS set

INT dps_setNum;
...
dps_setNum = Primary.getDps();

The getDps member function returns the DPS set number that is currently defined as the primary into the variable dps_setNum.
