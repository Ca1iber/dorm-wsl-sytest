An Unprecedented Solution on DDR3

My-Way Wang, Verigy

Paper-ID: 120438 April 2010

Abstract

This paper addresses the fundamental operations of DDR3 and how the V93000 HSM series test system benefits customers that use DDR3. Because different data sequences output by DDR3 are organized under a different starting column address and burst types (see Table-1), current ATE test systems have yet to successfully achieve the goal of unifying all possible DDR3 conditions within one universal pattern. However, this goal has now been achieved by the V93000 HSM series, thanks in part to its unique software architecture.

This paper also explains in detail the method and algorithm used to achieve this goal, which involves complicated C-Language programming skills. In addition, this paper demonstrates the advantage of the V93000 SW APG architecture, as well how customers will benefit from developing test programs on the V93000 HSM.

Introduction

DDR3 SDRAM (double-data-rate three synchronous dynamic random access memory) is the successor of DDR2 SDRAM. Though the prototypes of DDR3 were manufactured in early 2005, it did not become a mainstream commodity SDRAM until this year. The two predominant reasons why DDR3 took so long to become mainstream was the over-supply of DDR2 and the global financial crisis. These two factors combined to cause a DDR3 price crash. Now that the economy is gradually recovering, several DRAM IDMs are beginning to slowly ramp mass production volume. Factor this with Windows 7 driving PC turnover, most semiconductor analysts forecast that the era of DDR3 is coming.

The major feature of DDR3 is a doubling of the transfer data rate over DDR2, achieved by using 8-bit wide prefetch buffer. In addition, DDR3 consumes less power, has a bigger chip capacity (up to 8 gigabits), and maintains better signal integrity.

Due to the unique structure of SDRAM and the limitations of current ATE memory, the challenge that has long bothered testing engineers has been the lack of an efficient testing program that covers all possible conditions. This paper addresses that challenge and offers a new testing solution using the V93000 HSM series.

DDR3 test challenge

Challenge description

This testing challenge came from the era of SDR (single-data-rate), and it becomes more complicated on DDR3. In Table-1 (extracted from JESD79-3D), it describes the relationship between #1.Burst-length, #2.Burst-type, and#3.Starting Column address for READ/WRITE operations respectively. For example, whenever a memory controller (chipset) wants to communicate with DDR3 (SDRAM), the controller chip first sends an (E)MRS command to set up the operating mode of memory, which includes Burst-length and Burst-type. Secondly, the controller sends a "READ/WRITE" command to memory after "ACTIVE" command follows some predefined timing delay. Starting Column address will simultaneously be interpreted by Column decoder of DDR3. There is a brief example to explain this concept in more detail.

Assuming DDR3 (SDRAM) configures x8 IOs, the data stream inside Column 0 through Column 7 of DDR3 (shown in Table-2), operates on Burst-Length=8, Burst-type=Sequential. Once the controller sends Column 0 as starting column address combined with "READ" command, DDR3 will output a data stream in the sequence shown in Table-2 (39,1A,84,05,FE,BC,65,72) after the predefined latencies. Further, if the controller sends Column 2 as the starting column address with other conditions remaining the same, DDR3 drives its output in another sequence (84,05,39,1A,65,72,FE,BC). If you are shrewd enough, you'll find what seems like a boundary between low nibble and high nibble. As mentioned in above example, Data stream starts at column 2, followed by column 3, then wraps to the beginning point (column 0) rather than crossing the boundary (column 4). From a testing viewpoint, this weird data stream sequence is a nightmare for testing engineers. Using current ATE test systems, test engineers do not have the ability to generate a universal pattern to satisfy these 32 (2 Burst-length x 2 Burst-type x 8 Starting address) testing conditions because the architecture of current mainstream memory ATE is designed on HW APG (Auto-test Pattern Generator) and uses low level language to develop test patterns. Not only is it impossible to provide 8 sets of different random data, but there's also no way to determine the next 1-7 following address from the starting column address. Let's take "MARCH" [2], a typical test pattern for SRAM & DRAM, as an example. Due to the restrictions described above, testing engineers need to create 32 different patterns for one "MARCH" as shown in Table-3.

Verigy HSM Solutions

In the high speed industry, the V93000 is well known as a cutting-edge SOC. HSM (High Speed Memory) overcomes the two drawbacks presented in the last example by leveraging the proven per-pin timing architecture and technology of 93000 platform. HSM is designed on per-pin SW APG, so there is no HW APG limitations (usually comes from data/address registers, general counters) to support any kind of address topologic memory. Another great innovation is supporting C-language on pattern development. There is a template coding shown below.

//..
Main()
{
//..
    Initialize();
    Region_Write();
    Region_Read();
//..
}

Initialize()
{
//..
    MRS(Bank0, code0);
    A1_A0=code&0x3;
    A3=code&0x8;
    if(A1_A0==2)
    {
        BL=4;
    }
    else
    {
        BL=8;
    }
//..
}

Region_Read()
{
//..
for (Col = Col_init; Col<Col_end; Col+=shift)
{
Active (Bank, Row);
Delay(tRCD);
Read(Bank, Col, DQ_SA, DQ_N1, DQ_N2, DQ_N3, DQ_N4, DQ_N5, DQ_N6, DQ_N7);
Delay(tRTP);
Precharge(Bank);
Delay(tRP);
Refresh();
}
//..
}

Read(_Bank, _Col, _DQ_SA, _DQ_N1, _DQ_N2, _DQ_N3, _DQ_N4, _DQ_N5, _DQ_N6, _DQ_N7)
{
//..
    if(A3)
    {
    DQ_BUS_rearrange_Intlv ();
    }
    else
    {
    DQ_BUS_rearrange_Seq ();
    }
//..
}

DQ_BUS_rearrange_Intlv()
{
//..
Y_warp=_Col&0x3;
Y_2=_Col&0x4;
Y_others=_Col&(Col_MAX-BL);
SA=Y_others|Y_2|(Y_wrap^0)&0x3;
N1=Y_others|Y_2|(Y_wrap^1)&0x3;
N2=Y_others|Y_2|(Y_wrap^2)&0x3;
N3=Y_others|Y_2|(Y_wrap^3)&0x3;
N4=Y_others|(~Y_2)&0x4|(Y_wrap^0)&0x3;
N5=Y_others|(~Y_2)&0x4|(Y_wrap^1)&0x3;
N6=Y_others|(~Y_2)&0x4|(Y_wrap^2)&0x3;
N7=Y_others|(~Y_2)&0x4|(Y_wrap^3)&0x3;
//..
}

DQ_BUS_rearrange_Seq()
{
//..
Y_warp=_Col&0x3;
Y_2=_Col&0x4;
Y_others=_Col&(Col_MAX-BL);
SA=Y_others|Y_2|(Y_wrap+0)&0x3;
N1=Y_others|Y_2|(Y_wrap+1)&0x3;
N2=Y_others|Y_2|(Y_wrap+2)&0x3;
N3=Y_others|Y_2|(Y_wrap+3)&0x3;
N4=Y_others|(~Y_2)&0x4|(Y_wrap+0)&0x3;
N5=Y_others|(~Y_2)&0x4|(Y_wrap+1)&0x3;
N6=Y_others|(~Y_2)&0x4|(Y_wrap+2)&0x3;
N7=Y_others|(~Y_2)&0x4|(Y_wrap+3)&0x3;
//..
}

Conclusion

The above C-language template consists of main, sub-function, for-loop, if-else condition, parameters assignment and ALU. The most sophisticated part resides in DQ_BUS_rearrange_X, although the details are not shown. The versatility of a C-language base allows you to do almost anything you would like to, such as mathematic equations, bit operations, global/local variables and arrays.

One other thing to note about the benefit of a C-language base is that it is simple to make a universal pattern that satisfies the 32 conditions of Table-1 & Table-3. If you want to add more testing conditions for example, tRCD, RL, CWL), it can still be done easily, as illustrated in Table-4.What this means for the test engineer is a future where only one universal pattern plus one excel sheet can handle all testing conditions. Consider that if your current HW-APG ATE cannot satisfy tomorrow's memory devices, regardless of improved functionality or speed, can you afford to continue waiting? Verigy's HSM series has already achieved what test engineers have long clamored for, while also providing an upgradable per-pin test processor for higher data rate performance, and a flexible per-pin compiler-based APG scheme for future enhanced functionalities. With Verigy's HSM series, the future is now.
