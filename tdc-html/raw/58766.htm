Topic 58766

Global and local scope of base variables

Base variables for the individual ports of a multi-port timing specification can have the same name. This is the case, for example, if the same equation set is associated with more than one port. When you want to change the value of such a variable for one port (for example, with the SVLR command), you may want to restrict the change to that port. In this case the scope of the requested change can be said to be local. In certain situations, however, it can be desirable to propagate the change to some or all of the other ports where the variable occurs. If this is done, the scope of the change is (more or less) global.

SmarTest allows you to control the propagation of a value change by associating a scope attribute with every variable for every port. This attribute is coded implicitly by the position of the value assignment to the variable within the specification. If a value change is to be propagated to at least one other port, the assignment must be placed at the start of the specification before the first port block (global assignment). If any value change is to be restricted to the port in question, the value assignment must be placed at the end of the block of that port (local assignment).

The same variable can be assigned a value both globally and locally. In this case the local assignment overrides the global one for the respective port. The global assignment thus applies to all those ports the equation set of which contains the variable, but for which no local assignment exists in the specification.

Example

The following example specification illustrates the principle:

SPECIFICATION "mu_timing" {

CHECK all

var 1.3

EQNSET 1 "equation set 1"

WAVETBL "wavetable 1"

PORT Port1

var 1.1

EQNSET 1 "equation set 1"

WAVETBL "wavetable 2"

PORT Port2

EQNSET 1 "equation set 1"

WAVETBL "wavetable 3"

PORT Port3

}

In this example, which combines the same equation set with different wavetables for the three ports, the global assignment 1.3 for the variable var is valid for Port2 and Port3, but not for Port1, which has the local assignment 1.1.

You can change the runtime value (not the value in the specification) of the base variables with the SVLR command. If you specify a port in the command, it will modify the (create a) local assignment for that port. If you do not specify a port, a global assignment will be created, or the existing global assignment modified.

Note that when a local assignment is created with SVLR, the global assignment will no longer be valid for the respective port. Thus if the above specification is the primary specification, issuing the command

SVLR TIM,PRM,,"var@Port2",2.1

will create an (internal) local assignment of 2.1 for var in Port2. If you subsequently change the global assignment with

SVLR TIM,PRM,,"var",1.9

this will have no effect on Port2 (or Port1). Also, as before, this change of the scope will not affect the specification, but only the runtime settings.
