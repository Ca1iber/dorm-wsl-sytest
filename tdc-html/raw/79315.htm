Continuous Clock Setup

The multi-port setup allows you to de-couple ports (pins), so that you can, for example, reload primary sets (CTOF sequence) to selectively change the timing of data, of control pins belonging to a particular port (or ports), while allowing the continuous execution of clocking signals in a different port and sequencing group.

The following section gives you a short summary of how to set this procedure up.

Note The continuous clock setup described here works with any number of ports for other pins. The important thing is that the clock pin has its own port. For simplicity, however, the following assumes that there is one clock port for the clock pin and only one other port containing all other pins.
  1. Define the pins for a multi-port configuration, in which the clock pin belongs to one port and the other pins to another port.
  2. Set up equations, timing sets and wavetables for the ports.
  3. Define the ports in the wavetables and define the waveforms for the clock (Tx_refclk) such that the "USER VECTOR" and "BREAK WAVEFORMS" are identical as shown below. This is important because a change of timing would cause the CTIM command to be issued and the clock signal would be interrupted.

    PINS Tx_refclk

    0 "d1:1 d2:0"

    1 "d1:1 d2:0"

    brk "d1:1 d2:0"

  4. Define two timing and equation sets. One for the clock pin and the other for the other pins.
  5. Create a new spec set to include the two ports defined above and assign the appropriate equation set to each port Specification.
  6. Select the Phase Flag, and define a Sequencing group name to each port.
    Note If the data port contains a CTIM or CLEV command, you have to create a multi-port burst which includes the clock port and the data port (see, Multiport Burst Setup Tool). Alternatively, a simpler solution would be to define an incomplete multi-port burst only for the data port. In this case, the pins of the clock port will be fed with break vectors during the test, but the break waveform for the clock pins must be identical with the standard clock pulse.
    Note By default, the primary sets are activated at the start of each functional test. This activation requires a CTOF sequence during which the tester sequencer is inactive. But when testing a PLL device, the clock must be running continuously during the whole testflow. The FTCG (Functional Test ConfiGure) command allows you to suppress the (re)activation of the primary sets for the clock pin(s) of such a device. For more information on this refer to the section Suppressing Reactivation of Primary Sets with FTCG.
