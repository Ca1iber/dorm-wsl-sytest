Elements of the Test Cell Control Tool

Subtopics

  2. Factory preset recipe file
  3. Equipment configuration file

  5. Production configuration file
  6. TCCT UI configuration file

The following figure shows the user interface of the Test Cell Control Tool (TCCT). If you changed the layout of the user interface by drag-and-drop, you can click Window > Reset Perspective to get back to the default layout.

The elements of TCCT user interface are introduced below the figure.

Test Cell Status
Tester Status
This can be: IDLE, LOADING, IDLE_WITH_TP_LOADED, TESTING, ALARM, UNKNOWN
Equipment Status

This can be:

(for PROBER or HANDLER test) CONNECTED, DISCONNECTED, ALARM, UNKNOWN

(for HAND test) NONE

Lot Status

This can be:

(for HAND test) LOT_CREATED, LOADING_LOT, TESTING, PAUSED, UNLOADING_LOT, LOT_ABNORMAL, LOT_REMOVED

(for HANDLER test) LOT_CREATED, LOADING_LOT, LOADING_DEVICE, TESTING, PAUSED, BINNING_DEVICE, UNLOADING_LOT, LOT_ABNORMAL, LOT_REMOVED

(for PROBER test) LOT_CREATED, LOADING_LOT, LOADING_WAFER, LOADING_DEVICE, TESTING, PAUSED, BINNING_DEVICE, UNLOADING_WAFER, UNLOADING_LOT, LOT_ABNORMAL, LOT_REMOVED

Load Testflow

Selects and loads the testflow to execute. The setup files used by the testflow will also be loaded. So loading a testflow here equals loading the testflow and loading all its setup files in the SmarTest Work Center. If you already loaded the testflow and the setups in the work center, you still need to click the Load Testflow button in the TCCT. TCCT will check whether the testflow has been loaded. If yes, the testflow information will be updated in TCCT and no reloading will be done.

Load Recipe
Selects and loads the recipe file. Loading the recipe file can load the testflow and all its setup files and set up the equipment and the data log information. The real action of loading a recipe file depends on the content included in the recipe file.
Equipment setting

Selects the test type and the equipment to use. The test type can be HAND, PROBER or HANDLER. If you select PROBER or HANDLER, then you must select the configuration for the equipment.

The available configuration files are listed in the equipment configuration. You can edit that file and add the configuration files you want to use.

Lot Summary

Shows the setup information, including the loaded testflow and the recipe file, the equipment type, the lot ID, the operator name and the wafer ID.

Shows the number of passed and failed devices and the yield of the tested devices. If you modified the part IDs manually and made duplicate part IDs with previous executions, they will be counted as different devices.

Console
Three consoles are available:
  • Text Console: Shows the text data log if the option Output text format to datalog console in the Datalog Setup dialog is checked.
  • System Console: Shows the warning and error message issued when working with TCCT.
  • Instruction Console: Shows the instruction specified in the recipe file.
Binning

Controls the sites to be tested in TCCT and shows the binning information for the previously executed devices and the part IDs for next round of execution. For final test, the part ID of each site is displayed. For wafer test, the device position of each site is displayed.

The part IDs will automatically increase after a testflow execution except of doing retest. The part IDs are continuous if you do not change them manually.

Binning Statistics
Shows the number and the percentage of the devices that fall into each hardware bin and software bin.
New Lot

When the testflow is loaded, the New Lot button is enabled. Clicking the button opens the Lot Information dialog. In the dialog, enter the values for the variables to start the data logging for the results of the following executions.

End Lot
Ends the testing of the current lot. Clicking the button can generate the STDF file and the lot summary file for the executed lot. This button will become available after you click the New Lot button.
Start Test

When a lot is started, this button will be enabled. Clicking this button will execute the loaded testflow. In the HAND test, it will only execute the testflow once. In the PROBER and the HANDLER test, it will test all the devices in this lot if you Do not pause the test.

If you specify the data log files to log, the log_events_enable flag will be checked. If it is turned off, an error message is displayed asking you to turn on the flag. The log_events_enable flag will automatically be turned on after the testflow execution.

Pause Test

Pauses the test of the current lot. This button will be available after you click Start Test in PROBER or HANDLER test. Clicking the button pauses the test of the lot when the execution of the current device is finished. If you click Pause Test when the equipment is loading new devices, you may need to wait for the devices to be loaded and tested before the test is really paused. If the new devices are not available for some time, the wait time to pause the test can be longer.

Resume
Resumes the test of the lot that was paused. The button will be enabled after you click Pause Test in the PROBER or the HANDLER test.
ReTest

When the loaded testflow has been executed and the device has not been binned out, this button will be enabled. In the PROBER and the HANDLER test, you need to pause the test before doing retest. Clicking the button will execute the loaded testflow on the device one more time. The test results in the Binning area will be updated. But the pass/fail counts and the yield will no be updated according to the result of the retest. The result of the retest will be included in the data log file.

Contact Check

When the testflow is loaded, the Contact Check button will be enabled. Clicking the button will execute the loaded testflow. The binning information will be displayed in TCCT. But the test results will not be included in the data log file.

Loop

When the testflow is loaded, equipment settings are done and the testflow has been executed, the Loop button will be enabled. (For hand test, it is enabled after you create a new lot.) Clicking the button will bring up the Loop Setting dialog. Enter the loop times and the delay time in the dialog and click OK. The testflow will be executed for the specified times. The system will wait for the delay time between two adjacent executions of the testflow. You can also choose whether to increase the part IDs automatically during the loop testing with the option Auto Increase Part Id.

The results of loop test will be counted in the pass/fail numbers and yield displayed in TCCT.

Partial Summary

Generates the partial lot summary for the tested devices until now if the summary has not been cleared yet. If the lot summary has been cleared before, the lot summary will only include the results of the tested devices since the last clearance.

It has the same functionality as the Get Partial Summary button in the Datalog Setup dialog.

Datalog Setup

Clicking this button opens the Datalog Setup dialog. For details, refer to Setting up the data log information.

More Variables

Clicking this button opens the Datalog Variables Setting window.

For final tests, you can enter the lot information you want to log in the data log files.

For wafer tests, click the Wafer Information tab and enter the wafer information to be logged. The variable name comes from the STDF specification including WADR_SIZ, DI_HT, WID_HT, WF_UNITS, WF_FLAT, CENTER_x, CENTER_y, POS_x, POS_y, WAFER_ID, FABWF_ID, MASK_ID and USR_DESC. You cannot define your own wafer information variables.

Cont On Fail

Controls whether to continue the execution of the testflow when a test suite fails. It has the same functionality as the global overon testflow flag.

Attached status

In the lowest part of the TCCT window, the attachment status is shown. If TCCT is successfully attached to a SmarTest session, "SmarTest XXX Attached" is shown. Otherwise, "SmarTest Session Detached" is shown.

Timing information

In the lower right corner of TCCT, the timing information is displayed.

Last Run shows the last execution time of the testflow.

Current Run increases instantaneously and shows the elapsed time of the testflow being executed. It will return to zero when an execution of the testflow is finished.

Functional changes

  1. Introduced in SmarTest 7.2.0
  2. SmarTest 7.2.0: in patch 2, adds More variables and Cont on Fail in TCCT 1.1
  3. SmarTest 7.2.0: in patch 2, adds Instruction Console to show the instruction in a recipe file in TCCT 1.2.
  4. SmarTest 7.2.1: For hand test, loop test is enabled after a new lot is created in TCCT 1.3.
  5. SmarTest 7.2.1: For hand test, part IDs are continuous when some sites are masked in TCCT 1.3.
  6. SmarTest 7.2.1: Check the value of log_events_enable and stdf_generation when clicking Start Test in TCCT 1.3.
  7. SmarTest 7.4.5: Removed stdf_generation flag
