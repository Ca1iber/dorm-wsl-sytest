Setting up Workorder Directories

Another preparatory task the Supervisor may need to do is to set up workorder directories-directories where all available workorders can be loaded, saved and executed from.

By default, workorders are set up in a directory named workorder within each operator's home file system, /users/jane, or

/users/tom, for example. Thus, when user Jane or user Tom log in, they have access to the workorders prepared for them to execute. If, for example, user Jane logs in and executes SmarTest, then she can execute all workorders that reside in the /users/jane/workorder directory by selecting them from the Valid Workorders list in the workorder select screen (see Starting SmarTest with operator mode).

As an alternative, you might want to "pool" workorders. If you do not know who should execute a particular workorder, or you may not even care, set up all workorders to be executed in one common pool, from which operator Jane or operator Tom could pick from.

For this, you can set up a workorder directory anywhere and use the workorders stored there instead of the defaults. If this is more what you require, you must create this directory, place the desired workorders in it, then give its absolute path when launching SmarTest; for example:

HPSmarTest -O /smartest/workorders/workorder_file.

Details of how to start the SmarTest software with the absolute path of a workorder are given in Executing a work order from the command line.
