Topic 118728

Translation-related STIL Reader setup options

The translation-related options in a STIL Reader setup file let you control the output of the translation process, in particular to accommodate variations between the input and the resulting output.

Syntax

The translation-related options in alphabetical order:
align_xmode_patterns=boolean

Whether the execution times of patterns are aligned to that they end at exactly the same times.

This is an optional parameter. The default value is 0.

allow_combinations_file_update=boolean

Whether STIL reader may modify the combinations file.

Available settings are:
  • 0: STIL Reader may not update the combinations file.
  • 1: STIL Reader may update the combinations file.

This parameter is optional. The default value is 1.

allow_ctim=boolean

Whether STIL reader may insert CTIM instructions. (CTIM instructions can only be used in X1 mode and are not compatible with multiport setups.)

Available settings are:
  • 0: STIL Reader may not insert CTIM instructions.
  • 1: STIL Reader may insert CTIM instructions.

This parameter is optional. The default value is 0.

allow_nonaligned_match_loops=boolean

This setting controls how STIL Reader deals with match loops that do not contain the number of vectors required by the x-mode. (For example, in x6 mode, the sum of the matched and dummy vectors in a loop must be a multiple of six.)

Available settings are:
  • 0: No special handling is performed. If the sum of the matched vectors and dummy vectors in a loop is not a multiple of the x-mode, an error will be generated and the translation fails.
  • 1: The vectors in a match loop are repeated to match the chosen x-mode. No error is generated.

This parameter is optional. The default value is 0.

allow_wavetbl_merge=boolean

Whether STIL Reader may merge the wavetables for different signal groups to save resources.

This is an optional parameter. The default value is 0.

allow_unify_periods=boolean

Whether wavetables in the STIL source can be split to achieve a unified period.

This concerns cases where the STIL files contain wavetables with multiple periods, for example, 40 ns and 60 ns.
0

No period unification is performed and the translation is stopped.

1

The wavetable is split to allow a unified period. The period is set to the largest common divisor of the periods from the STIl file. (For example, when the STIL periods are 40 ns and 60 ns, the translated files have a period of 20 ns.)

This is an optional parameter. The default value is 0.

auto_create_signal_groups=boolean
Whether STIL Reader during the translation automatically creates the two signal groups all_inputs and all_outputs, which can be useful for debugging purposes:
  • 0: The groups are not created.
  • 1: The groups are created.

This parameter is optional. The default value is 1.

bflm_match_repeat_count=boolean
Whether STIL Reader should prevent an issue that can occur when the BFLM is used together with match loops in SmarTest 7.3.2 to 7.3.4.15 and SmarTest 7.4.0 to 7.4.4.x, where some cycles are not correctly considered for error counts and are missing from the detailed error map:
  • 0: STIL Reader does not try to prevent the issue.
  • 1: STIL Reader prevents the issue.

This parameter is optional. The default value is 0.

bflm_mode=boolean
Whether STIL Reader should prevent an issue that can lead to the BFLM displaying incorrect pass/fail results for individual labels in SmarTest 7.3.2 to 7.3.4.15 and SmarTest 7.4.0 to 7.4.4.x:
  • 0: STIL Reader does not try to prevent the issue.
  • 1: STIL Reader prevents the issue.

This parameter is optional. The default value is 0.

combinations_allow_new_break_waveforms=boolean

Whether new break waveforms can be created for the combination file (see combinations_file, below).

This is an optional parameter. The default value is 1.

Note that this option is ignored if combinations_allow_new_waveforms is 0 or if allow_combinations_file_update is 0.

combinations_allow_new_waveforms=boolean

Whether new waveforms can be created for the combination file (see combinations_file, below).

This is an optional parameter. The default value is 1.

Note that this option is ignored if allow_combinations_file_update is 0.

combinations_file=combination_file_path

The path to an x-mode waveform combination file.

Specifying this file enables the waveform incremental mode that allows STIL Reader to generate consistent timing that is compatible with multiple STIL files.

The x-mode waveform combination file is automatically created and maintained by STIL Reader. It contains x-mode combinations and their mappings to physical waveform indexes.

There are some limitations:
  • The values of AC variables in equations are assumed to be identical; they are not checked.
  • Incremental timing generation is possible only if there are no conflicting waveform definitions. This means that, for each signal, a particular combination of waveform table and waveform character must result in the same waveform.
  • X-mode factors cannot be changed (for example, from x2 to x4).

Using this file and mode ensures consistent timing and minimizes the number of contexts required when using x-modes.

The type of the file is usually .txt, for example combinations_file = /usr/me/tmp/stil/combofile.txt.

This is an optional parameter. There is no default value. If this parameter is not specified, no combinations file is created.

combinations_ignore_spec_values=combination_file_path
Whether differences between AC specification values in the combinations file and in the translated pattern generate an error:
  • 0: An error is reported when an AC specification value in the combinations file differs from the value in the translated pattern.

  • 1: The AC specification values are not compared, and no error is reported if they differ.

This parameter is optional. The default value is 0.

create_default_break_waveforms=boolean

Whether STIL Reader should automatically add default break waveforms ("") to all signals:

Available settings are:
  • 0: STIL Reader does not add default break waveforms.
  • 1: STIL Reader adds "" as the default break waveform to all signals.

This parameter is optional. The default value is 0.

create_min_max_typ_tests=boolean
Whether STIL Reader splits the AC and DC specs into three separate spec sets, respectively for minimum, maximum, and typical values:
  • 0: The spec sets are not split.
  • 1: The spec sets are split.

This parameter is optional. The default value is 0.

cycle_end=index

The index of the cycle in the pattern where the translation is to stop. (The index is 1-based; that is, the first cycle in the pattern has the index 1, not 0.)

The parts of the pattern after the specified cycle are ignored in the translation. (The specified cycle itself is still translated.)

This is an optional parameter. The default value is -1, which indicates the last cycle in the pattern.

cycle_start=index

The index of the cycle in the pattern where the translation is to start. (The index is 1-based; that is, the first cycle in the pattern has the index 1, not 0.)

The parts of the pattern before the specified cycle are ignored in the translation.

This is an optional parameter. The default value is 1.

dcap_vector_variable_rename={'auto_var_name':'new_var_name', ... }.

Changes automatically generated names of digital capture vector variables to names you specify. (STIL Reader automatically creates vector variables for each pattern label and filter specified in a DCapFilter object.)

Each change is specified as a pair of strings separated by a colon:
  • auto_var_name is the original name generated by STIL Reader.
  • new_var_name is the name that you want to give this variable.

You can include as many renaming pairs as desired, separated by commas.

For example, to rename the variables vector_variable_with_a_long_name_1 to v_var_1 and vector_variable_with_a_long_name_2 to v_var_2, use dcap_vector_variable_rename={'vector_variable_with_a_long_name_1':'v_var_1', 'vector_variable_with_a_long_name_2"':'v_var_2'}.

This parameter is optional. If it is not specified, all vector variables keep their automatically generated names.

default_definitions=['stil_source_1'[,...,'stil source_n']]

This parameter is deprecated and may not fully work with STIL Reader 3.3.5 and up. We strongly recommend not to use it with those versions.

Specifies external STIL files to be used as defaults, when translated STIL does not have all the blocks defined. For example, if DC levels are missing, they are taken from the files specified in default_definitions.

Files can be specified using absolute or relative paths. If a STIL object is defined in multiple specified files, the definition from the first file in which it is found is used.

This parameter is optional. If it is not specified, no external STIL source files are used.

See the examples, below, for a sample file containing virtual signals that can be specified with default_definitions.

default_port='port_name'

port_name is the port to which STIL Reader assigns all pins. A string.

If a default port is specified, STIL Reader assigns all pins to that port and creates multiport timing and patterns.

If the parameter is "@", there is no default port.

This parameter is optional. The default value is "@".

digital_capture_mode='mode'

Specifies how received waveforms are handled in digital capture applications.

mode can be:
  • 'std_selective': All receive edges except C and D are masked because no comparisons can be performed.
  • 'HRPF': No received waveforms are remapped or masked. "HRPF" is prepended to the first waveform of the first signal.

This parameter is optional. If it is not specified, 'std_selective' is used.

equation_based_timing=boolean
Whether to create equations for values without specification definitions:
  • 0: No equations are generated for values without specification definitions.

  • 1: Equation-based timing is generated if the original timing only uses absolute values without any AC specification variables.

    For example, if the waveform table period is 100 ns and a value is specified as being 10 ns, it will be converted to 0.1 * per_100, where per_100 is a new specification variable.

This parameter is optional. The default value is 1.

error_on_2_state_ambiguity=boolean
What STIL Reader does when the STIL source file does not contain a WFCMap object for resolving two-state assignments:
  • 0: STIL Reader issues a warning and continues the translation.
  • 1: STIL Reader issues an error and aborts the translation.

This parameter is optional. The default value is 0.

exclude_signals=['signal-name ',...]

If this parameter is used, the specified signals are excluded from the generated vector files. (All signals are included in the timing and pin configuration files.)

signal-name is the name of a signal to exclude from the vector files. The wildcard characters * and ? can be used for pattern matching. Any number of signals can be specified; they must be separated by commas.

If exclude_signals is used, include_signals and pattern_signals (see below) cannot be used.

This parameter is optional. There is no default value.

external_data_files=['stil_source', ...]

This parameter is deprecated and may not fully work with STIL Reader 3.3.5 and up. We strongly recommend not to use it with those versions.

This parameter can be used to import additional STIL source files into the file being translated. (It is much like an import command in a programming language.) This allows for a modular setup of STIL files for conversion.

stil_source is the name and path of a file to be imported. The path can be either relative to the current working directory or absolute.

If more than one of these files specify the same setting, the specification from a file that comes later in the list overwrites the one from an earlier file.

This parameter is optional. There is no default value.

fix_failing_signals='failure_log'

The location of the failure log for fixing failing signals. If failing signals are fixed, all expected values for these signals are replaced with the actual measured values so that all comparisons pass.

failure_log is the absolute or relative path of the failure log file to use for the fixing. It must contain the cycle number, signal name, expected data, and actual data for each signal to mask, separated by tabs.

This parameter is optional. There is no default value.

fixed_as_breakpoint=boolean
Whether STIL Reader treats Fixed statements in the STIL source file the same as BreakPoint statements (that is, translates them to break waveforms):
  • 0: Fixed statements are translated normally.
  • 1: Fixed statements are treated as BreakPoint statements and are translated to break waveforms.

This is an optional parameter. The default value is 1.

force_edge_strobe=boolean
Whether to replace window strobes with edge strobes during the translation:
  • 0: Window strobes are not replaced.
  • 1: Window strobes are replaced with edge strobes.

This parameter is optional. The default value is 0.

frequency_based_timing=boolean
Whether to create timing equations based on periods or frequencies:
  • 0: Timing equations are created based on periods.

  • 1: Timing equations are created based on frequencies.

This parameter is optional. The default value is 0.

This parameter is ignored if equation_based_timing is 0.

generate_complementary_waveforms=boolean

Whether to create waveforms with complementary actions for certain waveforms.

For single-drive waveforms, any missing force-up and force-down waveforms are generated.

For single-compare waveforms, any missing compare-high, compare-low, compare-off and, compare unknown waveforms are generated.

  • 0: No complementary waveforms are generated.
  • 1: Complementary waveforms are generated.

This parameter is optional. The default is 0.

generate_mux_signals=[' signal-name',...]

A list of the names of signals that STIL Reader is to split into components. For example, a signal with two pulses is split into two signals with one pulse each that are set up on the tester in multiplex (mux) mode.

The name of the second signal is generated by adding the multiplex signal suffix (see mux_signal_suffix, below) to the original signal name.

This feature is primarily intended for use with systems that do not support x6 and x8 higher x-modes when those higher modes are needed.

signal-name is the name of a STIL signal that is to be split. The list can contain any number of signals; individual signals must be separated by commas. The ? and * wildcard characters can be used in signal names.

This parameter is optional. There is no default value.

high_voltage_signals=['signal-name ',...]

A list of the names of signals that are high-voltage signals; that is, signals using the vhh DC resource specified in the STIL file.

signal-name is the name of a STIL signal. The list can contain any number of signals; individual signals must be separated by commas. (Wildcard characters cannot be used in signal names.)

Note that signals that are not included in the high_voltage_signalsparameter is assigned the vt DC resource specified in the STIL file. More information on this is available in Using high-voltage pins.

This parameter applies only to Smart Scale platforms (target =93000SS). It is optional; there is no default value.

hvm_cycle_info=boolean

Whether cycle information is added to VCAT firmware instructions generated by STIL Reader.

These values are available:
  • 0: No cycle information is added. (This is the default.)

  • 1: Cycle information is added to each VCAT instruction in this form:

    scan-test-name c:cycle-number v:vector-number

This parameter is optional. The default value is 0.

hvm_shift_out_patterns=boolean

Whether STIL Reader should generate diagnostics information based on HVM shift-out patterns.

These values are available:
  • 0: No diagnostics are generated from the shift-out patterns.

  • 1: Diagnostics are generated.

This parameter is optional. The default value is 0.

ignore_free_running_clocks_in_patterns=boolean

Whether to ignore patterns that are specified for signals that are defined as free running clocks.

If this is set to true, no pattern data will be applied to any signal that has been specified as a free running clock using the FreeRunning user keyword. That signal will be driven as a clock.

ignore_scan_structures=boolean
Whether to disregard ScanStructure elements from STIIL files when converting the files:
  • 0: The ScanStructure elements are used.
  • 1: The ScanStructure elements are ignored.

This parameter is optional. The default is 1.

ignore_stil_rtags=boolean
Whether to filter out <rtag> information from STIIL files before processing them:
  • 0: The <rtag> information is used for naming device cycles.
  • 1: The <rtag> information is ignored.

This parameter is optional. The default is 0.

include_signals=['signal-name ',...]

Only the specified signals from the STIL file are passed to the target test program.

If include_signals is used, exclude_signals and pattern_signals (see above and below, respectively) cannot be used.

This parameter is optional. There is no default value.

infinite_loop_count_substitute=count

The loop count to specify for loops that are specified as infinite loops (using the InfiniteLoops user keyword) in the STIL file.

count is an integer. For example, infinite_loop_count_substitute=3 means that all loops that are marked as infinite in the STIL file are translated so that the loop body is executed three times.

This parameter is optional. The default value is 1.

keep_stil_files=boolean
Whether intermediate STIL files are to be kept or deleted:
  • 0: The files are deleted.
  • 1: The files are kept.

Intermediate STIL files are generated when WGL or TDL files are converted, or when certain preprocessing options are used, such as unify_periods.

This parameter is optional. The default value is 0.

levels_group_exclude_pins=['pin ',...]

A list of pins that are not included in a single definition for DC level resources.

This parameter is optional. There is no default value.

mask_failing_signals=' failure_log'

The location of the failure log for masking failing signals. If failing signals are masked, all compare operations for these signals are replaced with X (compare Do not care).

failure_log is the absolute or relative path of the failure log file to use for the masking. It must contain the cycle number, signal name, expected data, and actual data for each signal to mask, separated by tabs.

This parameter is optional. There is no default value.

mask_scan_cells=[' masked-cell',...]

A list of scan cells that are masked.

This parameter is optional. There is no default value.

mask_scan_chains=[' masked-chain',...]

A list of scan chains that are masked.

This parameter is optional. There is no default value.

mask_scan_signals=[' masked-signal',...]

A list of scan signals that are masked.

This parameter is optional. There is no default value.

mux_signal_name='signal-name-modifier'

The suffix added to the names of signals that are split for muxing (see generate_mux_signals, above).

overwrite_timing=file_path

The path to a STIL file with timing definitions. These definitions are used to overwrite similar definitions from the input STIL file.

For example overwrite_timing = /usr/me/stil/stdtim.stil.

This is an optional parameter. There is no default value. If this parameter is not specified, the timing information from the input STIL file is not overwritten.

pad_xmode_vectors=boolean
How STIL Reader pads patterns to ensure that all x-mode cycles are filled:
  • 0: Cycles are padded with vectors that perform no actions.
  • 1: Cycles are padded by repeating the last vector of the pattern (with masked compares, that is, only the drive actions are repeated).

This padding is only performed if the last vector contains only drive actions. If it contains any compare actions, STIL Reader behaves as if pad_xmode_vectors=0 has been specified.

For example, if the x-mode is 4 and a STIL pattern contains 18 vectors, two padding vectors are added at the end (to reach 20, the next higher multiple of 4). If pad_xmode_vectors is 0, these vectors contain no actions at all. If the parameter is 1, the vectors contain the drive actions from the last vector of the pattern.

This parameter is optional. The default value is 0.

pattern_signals=[' signal-name',...]

If this parameter is used, only the specified signals are included in the generated pattern files. (All signals are included in the timing and DUT board description files.)

signal-name is the name of a signal to include in the pattern files. The wildcard characters * and ? can be used for pattern matching. Any number of signals can be specified; they must be separated by commas.

This parameter is optional. There is no default value.

process_user_keywords=['keyword',...]

If this parameter is used, the specified nonstandard keywords for STIL blocks are recognized and translated by STIL Reader. Keywords not specified in this parameter are ignored.

These keywords are supported:
ShiftIncrement
This keyword has the same effect as the standard Shift keyword, except that if the block contains multiple vectors, data is shifted after each vector instead of just once for the entire block.
InfiniteLoop
When this keyword is enabled, STIL Reader does not fully support it but recognizes it as syntactically correct. Whenever STIL Reader encounters the InfiniteLoop keyword, it issues a warning and converts the loop so that the vectors in the loop block are executed once. (In effect, enabling InfiniteLoop causes STIL Reader to interpret it as meaning Loop 1.)
FreeRunning
This keyword defines an synchronous free-running clock.
DifferentialInvOf
This keyword specifies the name of the positive differential pin.
BitAlignment

This keyword specifies a pattern that is used for aligning the compare strobe timing of output pins to the bit centers of the signals in the pattern's signal group.

Such alignment is performed in high-speed scan tests as specified in IEEE 1149.10.

LatencyAlignment

This keyword is similar to BitAlignment (above), but specifies a pattern that is used to adjust the compare strobe timing to the functionally correct bit positions.

MatchAttrs
This keyword specifies customer match-loop attributes.

All keywords that are to be supported must be specified as quoted strings in a list. For example: ['ShiftIncrement', 'InfiniteLoop']

This parameter is optional. There is no default value.

rename_signals={'STIL-signal-name ':'93k-pin-name',...}

This parameter causes STIL Reader to replace the names of specified STIL signals with specified V93000 pin names.

STIL-signal-name is the name of the STIL signal that is to be replaced and 93k-pin-name following the colon is the pin name with which it is replaced. The list can contain any number of these pairs; they must be separated by commas.

This parameter is optional. There is no default value, meaning that by default all STIL signal names are used unaltered as V93000 pin names.

rename_wfts={' simulation-wft-name':'smartest-wft-name',...}

A mapping of waveform table names from the simulation to waveform table names for SmarTest.

For each pair of names, any waveform table from the simulation that has the name before the colon is converted into a waveform table with the name after the colon in the output file.

For example: {"simWFT1':'SmarTestWFT1',"simWFT2':'SmarTestWFT2'}.

This parameter is optional. There is no default value.

same_line_comment=boolean
This parameter controls the vector to which comments that start on the same vector as the STIL vector are attached:
  • 0: Comments are attached to the next vector.
  • 1: Comments are attached to the previous vector.

This parameter is optional. The default value is 0.

scan_multiport=boolean

Whether STIL reader creates separate ports for scan signals and non-scan signals.

Available settings are:
  • 0: No separate ports are generated.
  • 1: Separate ports are generated.

This parameter is optional. The default value is 0.

scan_pattern_start =' label-name'

If this parameter is used, only part of the scan pattern will be translated, beginning with the label label-name.

This parameter is optional. There is no default value.

scan_pattern_stop=' label-name'

If this parameter is used, only part of the scan pattern will be translated, ending with the label label-name.

This parameter is optional. There is no default value.

sequence_map={' signal_name_1':'state':'state',' state':'state',...}

The mapping of pattern states for the specified signal. state is a pattern specification that can contain these state characters: 0 1 L H T X

For example, these are valid patterns: 010111LHLLXL.

This parameter is optional. There is no default value.

shift_increment_disable_padding=boolean
Whether data padding caused by Shift statements is disabled:
  • 0: Data is padded normally according to the processing rules for the STIL Shift command.
  • 1: Data padding caused by Shift commands is not permitted and will result in an error.

This parameter is optional. The default value is 0.

signal_timing_map={' STIL-signal-name':{'original-action':' mapped-action',...},...}

This parameter lets you specify a custom timing mapping for individual STIL signals. It works much like timing_map (see below), but consists of a list of pairs of signal names and timing maps.

STIL-signal-name, the first element of each pair, is the name of the STIL signal to which the timing map applies. The timing map itself is the second element of the pair. It has the same format as the values of the timing_map parameter. The same wildcard characters for actions are supported.

This parameter is optional. There is no default value.

single_port_timing=boolean

Whether STIL Reader should create single-port timing even for a multiport setup.

Available settings are:
  • 0: Single-mode timing is created for single-port setups, multiport timing for multiport setups.
  • 1: Single-mode timing is created for both single-port and multiport setups.

This parameter is optional. The default value is 0.

skip_non_indexed_events=boolean
Whether only indexed events are to be used when creating waveform character sequences in multibit waveforms:
  • 0: Use both indexed and non-indexed events.
  • 1: Use only indexed events.

For example, the waveform eE '0ns' D/U[0]; '2.5ns' Z; is referred to in the pattern as e or E when the parameter is set to 1 and as ee or Ee if the parameter is set to 0.

This parameter is optional. The default value is 1.

skip_unused_signal_groups=boolean
Whether to translate signal groups that are not used in any timing or level definitions:
  • 0: Translate signal groups even if they are unused.
  • 1: Translate signal groups only when they are used.

This parameter is optional. The default value is 0.

stable_multiport=boolean

Whether STIL reader creates separate ports for stable signals and unstable signals.

Available settings are:
  • 0: No separate ports are generated.
  • 1: Separate ports are generated.

This parameter is optional. The default value is 0.

statemap_selector='selector'

The selector to apply to the statemap table.

This parameter is optional. The default value is the value of the project_name parameter.

stil_action_map={' original-action':'mapped-action',...}

If this parameter is used, every time original-action is encountered in the STIL file, mapped-action is inserted instead in the generated files. There can be any number of such pairs. This parameter is optional. The default value is {'N':'D'}.

stil_file_name_as_wft_prefix=boolean
Whether the STIL filename is to be added as a prefix to the names of STIL WaveformTable objects:
  • 0: The names of WaveformTable objects are not altered.
  • 1: The STIL filename is added as a prefix to the name of each WaveformTable object.

Adding the filename as a prefix is useful when multiple files with identical standard names but differing content are processed.

This parameter is optional. The default value is 0.

stil_ignore_pseudo_signals=boolean
Whether to ignore signals of type Pseudo in the STIL input file:
  • 0: Pseudo signals are processed like other signals.
  • 1: Pseudo signals are ignored.

This parameter is optional. The default is 1.

stil_pad_scanin='waveform-character'

The padding value for ScanIn signals, which overrides the standard padding value specified by the STIL standard. Padding is used when some scan chains are shorter than others.

This parameter is optional. There is no default value.

stil_pad_scanout='waveform-character'

The padding value for ScanOut signals, which overrides the standard padding value specified by the STIL standard. Padding is used when some scan chains are shorter than others.

This parameter is optional. The default value is 'X'.

stil_starc=boolean
Whether STARC features are supported:

  • 0: No STARC features are supported.

  • 1: These STARC features are supported:
    • IddqTestPoints statements can have Direction attributes.
    • Pattern names can be identical to PatternBurst names. However, nested bursts are not supported.

This parameter is optional. The default is 0.

stil_wfc_map={' conflicting-wfc conflicting-wfc':' resolution-wfc',...}
A waveform character map for the resolution of data assignment conflicts that is used when the native STIL WFCMap fails to resolve the conflict.
  • conflicting-wfc is one of a pair of conflicting waveform characters.
  • resolution-wfc is the character that is to be assigned whenever these two characters conflict.

For example, stil_wfc_map={'1Z':'1'} tells STIL Reader to assign a 1 whenever there is an unresolvable two-way conflict between 1 and Z.

This parameter is optional. There is no default value.

stop_on_uninitialized_signals=boolean
Whether STIL Reader stops the translation when it encounters signals that are not initialized in the first vector of the translated pattern or in a procedure:
  • 0: Translation continues when an uninitialized signal is encountered.
  • 1: Translation stops.

This parameter is optional. The default value is 0.

tetramax_scan_diagnostics=boolean

Whether STIL Reader should include support for TetraMAX scan diagnostics.

These values are available:
  • 0: No diagnostics support is included.

  • 1: Diagnostics support is included.

This parameter is optional. The default value is 0.

tim_group_exclude_pins=['pin',...]

A list of pins that are not included in a single WVT or TIMINGSET definition.

This parameter is optional. There is no default value.

timing_map={'original-action ':'mapped-action',...}

If this parameter is used, every time original-action is encountered in the STIL file, mapped-action is inserted instead in the generated files. There can be any number of such action pairs.

Input actions with undefined values are by default mapped to 0.

In addition to specific action characters, wildcards can be used:
  • I for any input event (D, U, P, A, or B)
  • O for any output event (H, L, X, x, T, V, l, h, t, v)
  • . (period) for any action

In addition to this global timing map, custom timing mappings can be specified for individual STIL signals using the signal_timing_map parameter (see above). The settings of timing_map do not apply to signals for which a setting has been specified in signal_timing_map (see above).

This parameter is optional. The default value is {'N':'D'}.

unify_periods=boolean
Whether all waveform tables are to be modified to use an identical period:
  • 0: The waveform tables are not modified.
  • 1: The waveform tables are modified to create a unified period.

For additional information, see the description of the -unify_periods command line option in STIL Reader command line options.

This parameter is optional. The default value is '0'.

We recommend not to use this setting.

unify_periods_boundary_edge_placement='location'
If unify_periods is on (see above), where to place edges that fall exactly on an edge boundary. location can be:
  • 'next_vector': The edge is placed at position 0 of the next vector.
  • 'curr_vector': The edge is placed at the end of the current vector.

This parameter is optional. The default value is 'next_vector'.

unify_periods_signal_boundary_edge_placement={' signal':'location',...}

If unify_periods is on (see above), where to place edges for specific signals that fall exactly on an edge boundary.

The parameter value consists of any number of signal/location pairs:
  • signal: The name of the signal for which the edge placement is specified.
  • location: The location where to put the edges, as described in unify_periods_boundary_edge_placement, above.

This parameter is optional. The default value is ''.

vector_comment_source=[' source',...]
A list that contains all types of STIL comments that STIL Reader is to convert to V93000 comments. The list can contain multiple values, separated by commas. source can have these values:
  • Annotation: All STIL Ann{* *} blocks are converted to V93000 comments.
  • C: All C-style comments /* */ are converted to V93000 comments.
  • C++: All lines beginning with // are converted to V93000 comments.

  • Label: Vector labels preceding a vector are converted to V93000 vector comments.

    These comments are prefixed with "L:".

  • Macro: A V93000 comment is created from each call to a STIL macro. The comment contains the name of the macro.

    These comments are prefixed with "MS:" (at the start of the macro) and "ME:" (at the end of the macro), respectively.

  • Procedure: A V93000 comment is created from each call to a STIL procedure. The comment contains the name of the procedure.

    These comments are prefixed with "PS:" (at the start of the procedure) and "PE:" (at the end of the procedure), respectively.

  • Scan Instance: The scan instance (that is, the number of times that the Shift statement has been called in the context of a Pattern block) is converted to a V93000 comment.

This parameter is optional. The default value is ['Annotation'].

virtual_signals=[{'name':'signal-name ',['type':'signal-type ',]'opcode':'opcode ','args':arglist}, ...]
This parameter causes STIL Reader to add signals to the created V93000 files as if they were present in the STIL files:
  • signal-name is the name of the added signal.

  • signal-type is the type of signal. It can be In, Out, or InOut.

    This parameter is optional. If you do not specify it, STIL Reader assigns the type based on the operator you specify (see below). (If you do specify a type but it conflicts with the operator or the parameters, an error is generated.)

  • opcode is the operator specifying how the signal is generated. It can be 'Fixed', 'Copy', or 'Not':
    • 'Fixed' generates a steady (unchanging) signal. It requires two arguments, the state of the signal (one of DUZLHXT) and the length of time for which it is to be generated.
    • 'Copy' makes the signal the copy of another signal. It requires one argument, the name of the signal to be copied.
    • 'Not' makes the signal the inverse of another signal. It requires one argument, the name of the signal to be inverted.
  • arglist is the list of arguments. Each argument must be a string enclosed in quotes and separated by commas (if two arguments are needed); the entire list is enclosed in square brackets. Which arguments must be specified depends on the chosen operator. See above for details.
wavetbl_remapping={'wavetable':' wavetable-name' [, 'wavetable':' wavetable-name', ...]}
A custom name for a waveform table. Waveform tables are automatically named by STIL Reader, and you can use this setting to give tables custom names of your choosing.

  • wavetable: The waveform table name as automatically created by STIL reader, for example, 'T1_T2'.

    In a multiport setup, add an underscore and the port, for example, 'T1_T2_Port1'.

  • wavetable-name: The name which you want to use for the specified waveform table.

You can remap as many waveform table names as desired in one wavetbl_remapping statement. Separate individual remappings with commas.

This parameter is optional. There is no default value.

Example

This example shows a STIL file that defines virtual signals. The file needs to be referenced with the default_definitions parameter.

STIL 1.0; // Standard STIL 1450.0 header

// Declaration of virtual signals with their direction
Signals {
 FX Out;
 CLK In;
}

// Signal groups, must be declared, even if empty
SignalGroups {
}

// Timing for virtual signals. Allows you to define an arbitrary waveform for a virtual signal that will be repeated 
// in every vector of the test. The period must be specified, but it is not taken into account.
// You can define multiple waveforms for each signal, they all will appear in tester timing.
Timing {
 WaveformTable t1 {
 Period '100ns';
 Waveforms {
 FX { X { '0ns' X; } }
 CLK { P { '0ns' D; '50ns' U;} }
 }
 }
} 

// The following definition selects a waveform to be repeated in the pattern. Even if only one waveform is defined for
// a signal, the definition is required.
MacroDefs {
 DefaultInit {
 C { FX = X; CLK = P;}
 }
}

See also the example in STIL Reader setup file.
