Using SmarTest Docker containers

There are two common ways SmarTest can be run in a docker container. You can either directly display the SmarTest user interface on the host workstation’s X Display or in headless mode, where a VNC Server runs inside the container, accessed using a VNC client.

About this task

There are two common ways to start SmarTest in a docker container:

  • Start the container in headless mode, which starts a VNC server inside the container, to which you can connect from your computer.
  • Start the container using the X Display of the host workstation you are already running and directly displays SmarTest windows on the host's X Server.

Before you begin

Before you can use the Docker image, make sure that you have completed the following steps and actions:

  • You are familiar with Docker and using docker images. The following points include some pointers to the Docker steps that you must have completed before running a Docker image.
  • The workstation operating system is Red Hat Enterprise Linux 7.2 or higher, or the required operating system version for the SmarTest versions to be installed, whichever is higher. Older operating systems are not supported.
  • Docker engine is installed:
    Note If you have the Platform Delta Bundle (PDB) version 422 or higher installed, Docker is pre-installed but not enabled. If this is the case, skip the following installation step.

    sudo yum install docker-ce docker-ce-cli containerd.io

  • docker daemon is set to automatically start on restart:

    sudo systemctl enable docker

  • docker daemon is started:

    sudo systemctl start docker

  • Check whether the docker daemon is running:

    sudo systemctl status docker

  • Optional: Add users to Docker group using:

    sudo usermod -a -G docker user name

  • The Docker image is installed. For details, see Installing SmarTest Docker images.

For more information about docker run, also refer to: https://docs.docker.com/engine/reference/run/

Procedure

  1. Start the Docker container by entering the docker run -it command in a terminal.

    • To start a container using the X Display of your workstation, enter:

      docker run -it --shm-size="host_max_memoryg" \ 
           -v host_license_pointer:container_license_pointer\
           -v host_project_folder:container_project_folder \ 
           -v host_model_file_folder/model_file:container_model_file_folder/model_file \
           -v /tmp/.X11-unix:/tmp/.X11-unix \
           -v host_log_file_directory:container_log_file_directory \
           repository/image mode

    • To start a container using its internal VNC server, enter:

      Enter the following command with appropriate modifications for your environment and chosen package:

      docker run -it --shm-size="host_max_memoryg" \ 
           -v host_license_pointer:container_license_pointer\
           -v host_project_folder:container_project_folder \ 
           -v container_model_file_folder/model_file:local_model_file_folder/model_file \
           -p external_port:container_port \ 
           repository/image mode
    The docker run command requires the following parameters:
    host-license-mapping pointer:container-license-pointer
    The mapping of your licensing file so that it is available in the container. These are fixed strings, depending on the licensing system used:
    FNE
    /etc/fne/client.conf:/etc/fne/client.conf
    FNP
    /opt/flexlm/license:/opt/flexlm/license
    container_project_folder

    The absolute path at the project folder is made available in the container. You can specify any convenient path.

    host_project_folder

    The absolute path of the project folder on your workstation.

    external_port

    The external port through which a VNC client on the host system communicates with the Docker container.

    As explained in the Network section, this is a number in the range from 5902 to 5999 that is usually referred to by the shorthand 2 to 99 and specified when you start up the VNC client.

    To connect using a remote VNC client,specify my_hostname:port_minus_5900. For example: myhostname:88 (if the specified external port is 5988).

    If the VNC client and the Docker container are running on the same host workstation, the hostname can be replaced with localhost:port_minus_5900. For example: localhost:88 (if the specified external port is 5988).

    container_port

    The port through which the VNC server running in the docker container communicates. For Advantest Docker containers, this port is set to 5901.

    host_max_memory
    As explained in the Memory and CPU section, SmarTest makes intensive use of shared memory. Specify the full amount of RAM that installed on your workstation as shared memory. For example: --shm-size=64g (if the workstation is equipped with 64GB of RAM).
    repository

    The location where your docker images are stored. This can be a local folder or a shared repository such as Docker Hub, which is a service for hosting Docker repositories.

    image

    The file name of the docker container that you are wanting to run.

    mode
    There are two different modes in which to use a SmarTest container:
    smartest
    The SmarTest Work Center is started and the graphical user interface expects that the X Server of the host is accessible.
    headless

    SmarTest is started with an internal VNC server which will be used by the graphical user interface.

  2. For VNC environments, access the session by opening a VNC client and connect to host workstation using the command:

    vncviewer docker_hostname:port_minus_5900

    For example, if the specified external port is 5988:

    my_hostname:88

    If the VNC client and the Docker container are hosted on the same host workstation, the IP address can be replaced with localhost.

    For example, if the specified external port is 5988:

    localhost:88

Results

You have started SmarTest in a Docker container.

Example

Starting a container using the host workstation’s X Display:

docker run -it --shm-size="64g" \ 
           -v /etc/fne/client.conf:/etc/fne/client.conf \ 
           -v /etc/opt/hp93000/soc_common/tester.model:/etc/opt/hp93000/soc_common/tester.model \
           -v /data/my-device:/data/my-device \ 
           -v /tmp/.X11-unix:/tmp/.X11-unix  \ 
           advantest/smartest-suite:8.4.2.0 headless

Starting a container with an internal VNC server:

docker run -it --shm-size="64g" \ 
           -v /etc/fne/client.conf:/etc/fne/client.conf \ 
           -v /etc/opt/hp93000/soc_common/tester.model:/etc/opt/hp93000/soc_common/tester.model \
           -v /data/my-project:/data/my-project \ 
           -p 5988:5901 \ 
           advantest/smartest-suite:8.4.2.0 smartest
