apgc command syntax

The apgc command executes the MTL compiler. It has several command options.

Syntax overview

/opt/93000mts/mts/mtl/bin/apgc <options><APG pattern file>
  • <options> can be none or any combination of these command line options:
    • -D <define>=<value>
    • -dp0 or dp1
    • -e <number>
    • -evs or -fevs or -lvs
    • --genidFilter <string regular expression>
    • -iic (--ignoreInterruptCheck)
    • -m
    • -M
    • -o <filename>
    • -O0 or -O1 or -O2
    • -para
    • -pps
    • -r , -r1, -r2 or -r3
    • -t <directory>
    • -v
    • -vw
    • -w

    • Note that options separated by "or" are mutually exclusive; you cannot use more than one of them in the same command. (For example, you cannot specify both -r1 and -r2.)

      All options are explained in the table below; the table also includes verbose equivalents.

  • <APG pattern file> is the name of the .apg pattern file that is to be compiled.

    The specified name may contain wildcard characters, as described in Specifying pattern files with wildcard characters in Using the MTL compiler from the command line.

    Note You can also put the file name or wildcard pattern before the command options.

If the specified APG pattern file contains compilation options specified with the :options: keyword, this overrides the command line options you specify. For example, if the :options: keyword contains the -evs option and you specify -lvs on the command line, the file is compiled ith the -evs option.

Command line options

All commands options have an abbreviated and a descriptive form. (For example, -e or --exps.) This table shows both forms:

Parameter

Description

-D <define>=<value>

This option overwrites the <define> string macro (defined with the :defines: keyword in the APG pattern file) with <value>.

In other words, the value in the :value: column of the macro definition in the APG pattern file is disregarded and the value specified in this command line option is used instead.

Note that the -D parameter is ignored in the :options: keyword of the APG pattern file.

[-dp0 | --disable-padding0]

Compiling with this option disables padding directly before and at the end of for loops.

[-dp1 | --disable-padding1]

Compiling with this option disables padding:

  • Directly before and at the end of for loops
  • Directly before and after is{} and nis{} instructions

[-e | --exps] <number>

The expansion size of the memory test pattern. The valid range for the expansion size is any value between 60 and 1,000,000.

The expansion size controls the degree to which for loops are unrolled during compilation.

Higher expansion sizes reduce the probability of a data queue empty error during the memory test pattern execution but lead to patterns that consume more memory.

If the -e option is not specified, the expansion size is set to 60.

If data queue empty errors occur when the memory pattern is executed, increase the expansion size using the following sequence of values, which experience has shown to be helpful:

100 - 250 - 500 - 1,000 - 10,000 - 50,000 - 100,000 - 500,000 - 1,000,000.

Make sure that the sequencer memory consumption does not exceed the limits of your sequencer memory. Compile the pattern with the -v option to see the memory consumption.

Example: apgc -e 500 apgfile.apg

Note that you can set the expansion size for individual pins in the Pin mapping file. Any such settings override this compiler switch for the pins in question.

[-evs | --extend-variable-scope]

Forces standard C behavior for non-loop variables in loops.

If this switch is used, variables in loops behave as in C, keeping their values from one iteration to the next.

[-fevs | --fast-extend-variable-scope]

The same as -evs but with faster speed and smaller memory consumption in early phase compilation.

Use -fevs only when -evs costs too long time and MTL (using -v option) prints out the message "Start creating per-pin programs".
-iic or --ignoreInterruptCheck Ignores the interrupt access check.

[-lvs | --limit-variable-scope]

Forces pre-2.3 behavior for non-loop variables in loops.

If this switch is used, the values of non-loop variables (that is, any variable used in the loop except those declared in the loop statement itself) are reset at the beginning of each loop iteration.

This is the default behavior, that is, if neither -evs nor -lvs is used, the compiler behaves as if -lvs was specified.

This switch is intended mainly for backwards compatibility with existing program relying on the historic behavior. We suggest that you write new programs using the extended variable scope and compile them using the -evs switch.

The -lvs setting never applies to global variables; they are always treated as if the -evs setting was in effect.

[-m | --mReuse]

Creates a reusable device maintenance operation.

A reusable maintenance operation is an operation that is stored in memory separate from the patterns that call it and so reduces memory use.

Using the -m switch requires either a program file without a main() function that contains just the maintenance operation, or a program file containing both the main() function and the maintenance operation at the top level. In the latter case, the name of the maintenance operation must match the name specified in the Device architecture file.

[-M | --Makefile-rule]

Suppresses compilation and instead creates a text file with dependency rules for a makefile.

If this switch is specified, the compiler does not create a vector file. Instead, it creates the file makefile.dependencies in the current directory.

  • makefile.dependencies contains all file dependencies for the compiled APG pattern file .
  • In the content of the makefile.dependencies file, the target vector directory is the same as the .apg file. When combined with -t command, the target vector directory is the directory specified with the -t command. (See the -t command.)

[-t | --target-dir] <directory>

The vector file (.vec) file will be generated in the specified directory.

  • When the combination of the -r/-r1/r2 command, both the vector file (.vec) and the reconstruction file (.rec.so) will be generated in the specified directory.
  • When the combination of the -M command, no vector file (.vec) will be generated. However, the makefile.dependencies file will be created. And in the content of the makefile.dependencies file, the target vector directory is the directory specified with the -t command.

[-o | --out] <output file name>

Used to save debugging information.

The MTL compiler redirects stdout and stderr messages to the file specified by <output file name>.

[-O0]

The compiled patterns are not compressed.

This is the default if none of the -On options are specified. We recommend using this option for small patterns.

[-O1]

The compiled patterns are compressed with a faster method.

This usually results in patterns that require less memory on the test systems than uncompressed patterns but more than patterns compiled with -O2.

Note that trying to compress small patterns can actually increase their sizes and is not recommended.

[-O2]

The compiled patterns are compressed with a slower method.

This usually results in patterns that require less memory on the test systems than uncompressed patterns or patterns compiled with -O1.

Note that trying to compress small patterns can actually increase their sizes and is not recommended.

Note, too, that in rare cases, -O1 results in stronger compression than -O2. When you need the greatest possible compression, you may therefore want to try both options to see which one works best on the specific pattern.

[-para]

If this option is specified, the compiler generates a parallel vector program as the output.

A parallel vector program can be helpful when conversion to Verilog format is desired or when the output will be manually edited.

Output generated with the -para option does not support a range of MTP features:

  • Dynamic refresh
  • Setting the pin ratio within a port using the cycleratio pin attribute
  • DC events
  • Multiplexed pins

[-pps]

If this option is specified, the compiler generates a per-pin sequencer program as the output.

This option is the default; it does not normally need to be specified. However, if the -para option (see above) is specified and you want to have both parallel vector and per-pin sequencer output, you also need to specify -pps.

[-r]

A binary reconstruction file is created.

[-r1 | --reconstruct1]

A binary reconstruction file is created.

Using the -r1 option results in fair compile times and high reconstruction speeds. See Reconstruction information for further information.

This is the default option if no reconstruction setting is specified.
[-r2 | --reconstruct2]

A binary reconstruction file is created.

Using the -r2 option results in the fastest reconstruction speed, though compile times may be high. See Reconstruction information for further information.

-r3 | --reconstruct3

 A binary reconstruction file is created.

Using the -r3 option results in slower reconstruction and less memory consumption for compilation.

[-v | --verbose]

Switches on verbose mode to display status information of each stage of the APG compile operation.

This parameter has to be set if you want to display:

  • Inconsistent pin count information
  • The number of refresh vectors for device maintenance in the output window

[-vw | --verbose-wavetable]

A detailed report is produced about the waveform usage.

[-w | --wvtgen]

The compiler creates new waveforms (plus new wavetables if not existing).

See Automatic waveform generation for details.

Environment variables

The MTL compiler supports the APGCOPTS environment variable that can contain preferred compiler switches.

For example, putting -evs -v in the variable would cause MTL to always compile with expanded variable scope and in verbose mode.

Any actual command line options that you provide override conflicting options in the APGCOPTS environment variable.

For example, if APGCOPTS contains -v -evs and you run apgc -lvs, MTL compiles a program with limited variable scope.

Example

apgc -m -w sramft.apg: Compiles the program and setup files that are referenced in the pattern file sramft.apg. During compilation, a reusable device maintenance operation and waveforms are generated.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. MTP 3.0.1: New compiler switches to partially disable padding, to create create a makefile rule, to compress compiled patterns, and to overwrite program variables
  3. MTP 3.0.1: Command line options are ignored when the APG pattern file contains the :options: keyword
  4. MTP 3.0.1: Removed the -r0 option
  5. MTP 3.1.3: Added -pps and -para options
  6. MTP 3.1.5: :Output generated with the -para option now supports the :testlabel: keyword
  7. MTP 3.2.1: Adds a new option, -t.
  8. MTP 3.2.2: Adds a new option, -fevs.
  9. MTP 3.3.1: Adds a new option --genidFilter.
  10. MTP 7.5.2: Adds a new option, -r3.
  11. MTP 7.6.0: Adds a new option -iic (--ignoreInterruptCheck).
