Index operator

The index operator [] lets you specify a single bit from the result of an expression, very much like an array index. It is not available for expressions with a floating-point value.

Bits are counted beginning with zero, starting with the least significant bit from the right.

For example, 0xB1[0] would be 1; 0xB[6] would be 0. 0xFF[4] XOR 1 would be 0; (0xFF XOR 1)[4] would be 1.

Index operators cannot be used on the left side of assignment operations. For example, this code would result in a compilation error: myVar[2] = 0.

The index operator is very similar to, but slightly different from, the Select operator. There are four main differences:

  • The select operator can appear only in device access files; the index operator can also appear in APG program files.
  • The select operator can only appear at the end of a full expression; the index operator can also appear at the end of a subexpression.
  • The select operator supports ranges of bits (for example, myVar[1..4] selects the first four bits of myVar); the index operator supports only selecting one single bit.
  • The select operator supports only constants within the square brackets; the index operator also allows variables and expressions for specifying the desired bit (for example, myVar[2*myIndex]).

If square brackets are found after a crc, data, dbi, pad, xaddr, yaddr, or zaddr expression in a device access file, they are considered a select operator by the MTL compiler. If they are found anywhere else (that is, in the APG program file or at the end of a different type of expression), they are considered an index operator.

Example

myVar = 0x55[2]   # myVar is assigned the value 1
