SMC_EXECUTE_TEST()

Executes a test by starting the digital sequencer from the specified start label and waits until the digital and analog sequencers have stopped or the specified timeout is reached. It allows hidden upload of data controlled by SmartCalc.

It is able to detect whether digitizers and samplers have received multiple trigger inputs during the execution. For further details, refer to Error Handling on Missing Trigger Input. This API cannot detect AWG timeouts.

The test time is compared to a timeout value. This value can be defined with the timeout parameter. If this parameter is omitted, the default or the value that was last set is used. If the timeout_info parameter is omitted and the test exceeds the timeout value, the test will be aborted and the test suite will be judged as FAILED. If the timeout_info parameter is set, SMC_EXECUTE_TEST() will return timeout information, and the test will continue with the next statement.

In a multi-site test, the reply of the timeout_info parameter depends on whether it is used in combination with the trigger_info parameter. If it is used alone, it will return global timeout information, that is, it will return 1 if a timeout occurred on any site, and 0 otherwise. If both parameters are specified, it will return site specific timeout information.

This API internally executes FLUSH() to reflect all changes of the hardware setup data that might be altered.

Use SMC_DIGITAL_CAPTURE_TEST() if your test contains digital capture.

This API is defined in the header file /opt/hp93000/soc/prod_com/include/MAPI/SMART_CALC2.h.

Parameters

I/O

Parameter

Description / Range

I

timeout

Timeout time of the measurement (test) in sec.The default timeout is 360000 s.

This cannot detect a timeout for the AWGs. Operations when timeout occurs depend on whether the timeout_info parameter is set or omitted.

O

timeout_info

This parameter returns timeout information. It can only be used in combination with the timeout parameter.

The reply of timeout_info depends on whether it is used with or without the trigger_info parameter.

If trigger_info is not specified, timeout_info returns global timeout information. Possible return values are:

0: No timeout occurred on any site.

1: A timeout occurred on one site at least.

If trigger_info is also specified, timeout_info returns site specific timeout information.

The returned integer must be converted into binary format. Every bit returns the timeout status of one site. Site 1 is represented by the LSB.

For example, if 13 is returned to this parameter, this corresponds to binary number 1101. This indicates that a timeout occurred on the site 1, site 3 and site 4.

O

trigger_info

This parameter returns site specific information on the trigger status of the digitizers. It can only be used in combination with the timeout_info parameter.

The reply refers to the following digitizers: MCA-ADGT/VDGT, MCB LF/VHF-DGT, and MCC. The state of the module (or MCA/MCB/MCC unit) is checked if a pin is defined and connected to the core.

The parameter informs about which of these digitizers have not been triggered during execution of this API. For more details of this functionality, see Error Handling on Missing Trigger Input.

The returned integer must be converted into binary format. Every bit returns the trigger status of one site. Site 1 is represented by the LSB. The bit states have the following meaning:

0: All the digitizer/sampler modules (and all the MCA/MCB/MCC measure units) on the site have been triggered at least once.

1: At least one digitizer/sampler module (or one MCA/MCB/MCC measure unit) on the site has never been triggered (missed a trigger).

In offline mode, this flag indicates whether the trigger signal input is enabled for all the modules (and all the MCA/MCB/MCC units) (0) or not (1)..

I

wait_action

Selects the sequencer the API shall wait for completion. Options can be combined by using '|' (bitwise OR).

Default: TM::WAIT_DIGITAL | TM::WAIT_DGT | TM::WAIT_TIA

Refer to the list of available options of the wait_action parameter below.

I

context

Name of an execution context. The ports of the context must be included in the current start label (which must be a multiport burst). For more information on execution contexts see Using execution contexts .

The context must have been defined on the firmware level (with the SQEC command), or as a SEQUENCER_CONTEXT_ITEM object. In the latter case this object must have been included in a SEQUENCER_CONTEXT object, and must also have been activated on the firmware level with the apply() function of this SEQUENCER_CONTEXT object. If the context has been defined as a SEQUENCER_CONTEXT_ITEM object, you must use the name specified for its name parameter.
List of available options of parameter: wait_action

Option

Description

TM::WAIT_ALL

Wait until all HW used with the test completed their current sequencer program.

TM::WAIT_DIGITAL

Wait until all used digital channels complete the current sequencer program.

TM::WAIT_AWG

Wait until all used AWGs complete the current sequencer programs.

TM::WAIT_DGT

Wait until all used digitizers and samplers complete the current sequencer programs.

TM::WAIT_TIA

Wait until all used TIAs complete the current measurements.

TM::WAIT_TMU

Wait until all all running TMUs have finished their measurements.

Return value

There is no return value.

Example

  • Retrieving failing sites in a multi-site test by converting the timeout_info parameter to binary:

    The integer number 13 was passed to timeout_info. This corresponds to binary 1101, which indicates that timeouts occurred on site 1, site 3 and site 4 (left to right).

  • The SMC_EXECUTE_TEST() API starts test execution. Here, the system default timeout is set because the timeout parameter is omitted:
    SMC_EXECUTE_TEST();
  • The timeout parameter is set to0.1sec. The timeout is compared to the start time of the test. If the test time exceeds the timeout , the test stops.Then the next statement is performed.
    SMC_EXECUTE_TEST(0.1 sec);
  • The timeout parameter is set to0.1sec.The timeout is compared to the start time of the test. timeout_s receives states whether the test time exceeds the timeout for each site. mis_trg_s receives states whether all connected digitizers (except WDA) received a trigger at each site. Further examples of using using the trigger_info parameter of this API can be found in Error Handling on Missing Trigger Input.
    int timeout_s,mis_trg_s;
SMC_EXECUTE_TEST(0.1 sec, &timeout_s, &mis_trg_s);
