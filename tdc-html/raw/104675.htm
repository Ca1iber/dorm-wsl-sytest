Sequencing groups and pattern structure

If two ports are to be members of the same sequencing group, the pattern sequences that are associated with them in a multi-port burst must fulfill certain requirements.

Number of level and timing set changes

The pattern sequences must contain the same total number of timing and level set changes (of course, this requirement is always satisfied if you use a single-port setup for the vectors). This also holds for the default sequencing group.

Therefore, if the port bursts for any two ports of a multi-port burst contain a different total number of timing and level set changes (this might be the case if you want to keep a PLL clock running across testsuites, see Continuous Clock Setup), then you must put them into different sequencing groups. This also implies that such ports cannot be synchronized exactly; only phase synchronization is possible, see Phase synchronization across sequencing groups.

It is not required that the timing or level changes start at the same point in time, but only that their number is the same for all ports. The SCLK edge at which the new timing becomes valid (for all ports of the sequencing group) is determined by the port that was the last to start the change.

Match loops in sequencing groups with multiple ports

If a port P within a sequencing group executes a match loop in one of its burst labels, the judgment on whether a match has been obtained will be based on the compare results for all pins of the sequencing group, not only the pins of port P. Therefore, if the sequencing group contains more than one port, a loop can fail even if all the received values of port P do match. For this reason it is recommended that any port that executes a match loop should have its own sequencing group, which contains no other member.

Match loops and CTIM / CLEV instruction in sequencing groups with multiple ports

Match loops in combination with the CLEV or CTIM instructions in multi-port pattern may result in an infinitely running sequencer if the match loop fails and the ports are assigned to the same sequencing group. This applies not only to user-defined sequencing groups but also if the ports are assigned to the Default sequencing group.

The failing match loop causes the sequencers from the pins of the related port to stop if the optimal parameter CONTINUE of a counted match loop is not set. All other ports of the same sequencing group continue executing their pattern until they reach the next CLEV or CTIM instruction where they will infinitely wait for the port with the failed match loop that already has been stopped.
