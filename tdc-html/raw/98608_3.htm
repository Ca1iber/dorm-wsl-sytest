FTST? - (Functional TeST)

The FTST? (Functional TeST) query executes a functional test and returns either a pass or a fail result. The test that is executed must have previously been defined by the SQLB, SQLB? - (SeQuencer LaBel definition) command and activated for execution by the SQSL, SQSL? - (SeQuencer Start Label) command.

Syntax

FTST? ["exec_context"]

returns: 

FTST {result_flag}

Parameters

exec_context An execution context. For more information on execution contexts see Using execution contexts.
result_flag This is returned by the system when the functional test has finished. It can be:
P is returned if the functional test passes.
F is returned if the functional test fails.

Application

AC tests

Errors

An error is generated if:

  • No sequencer start label has been set, see SQSL, SQSL? - (SeQuencer Start Label). A functional test cannot be executed.
  • The Primary Level Set number is greater than the range allowed by LSUS, LSUS? - (Level Sets USed).
  • The Primary Timing Set number is greater than the range allowed by TSUS, TSUS? - (Timing Sets USed).
  • The Primary Waveform Set number is greater than the range allowed by WSUS, WSUS? - (Waveform Sets USed).
  • The specified Primary DPS Set is not selected.
  • The specified Timing Set number is greater than the range allowed by TSUS, TSUS? - (Timing Sets USed).
  • The data queue empties, causing the test to stop. The system tells you at which vector the test aborted and also which sequencer instruction was currently valid via the command number. See also the command SQPG, as well as Managing the data queue.
  • Any of the primary sets has any test system resource range violations, a functional test cannot be executed.
  • If there is insuffcient channel memory to store error map / digital capture result in the extended error map (RAM).

Example

FTST?

returns: 

FTST P

This example returns a pass result for the functional test.

Functional changes

  1. Introduced before SmarTest 6.3.2
