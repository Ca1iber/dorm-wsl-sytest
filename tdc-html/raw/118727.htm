Topic 118727

Test-processing STIL Reader setup options

The test-processing options in a STIL Reader setup file let you configure the output of the translation process.

Syntax

The test-processing options in alphabetical order:
absolute_paths=boolean
Whether references to other files in the created files use absolute paths or relative paths:
  • 0: Relative paths
  • 1: Absolute paths

The pattern master file (.pmfl) always uses absolute paths.

This parameter is optional. The default is 0.

allow_default_levels=boolean
Whether to create values for undefined DC levels:
  • 0: No levels are generated for DC variables. If required DC variables are not defined in the STIL file, the conversion is aborted with an error message.
  • 1: If there are undefined DC variables, default levels are generated for them.

See also the default_levels_summary parameter, below.

This parameter is optional. The default is 1.

comment_max_size=integer

The maximum data size for the BCMT vector comment command.

This parameter is intended for use with old versions of SmarTest that had limitations regarding the size of the BCMT data. It is not needed for newer version but is observed if present.

This parameter is optional. The default value is 640000.

create_statemapping=boolean
Whether to create state mapping information in the generated timing files, which is required for displaying x-mode vector information in the vector editor:
  • 0: No state mapping information is generated.
  • 1: State mapping information is generated. See also the xmode_based_statemapping parameter, below.

This parameter is optional. The default is 0.

cycle_numbering=boolean
Whether cycle numbers are added to the comments of translated vectors:
0

No cycle numbers are added to the comments.

1
To each vector comment, the following information is added, divided by bars (|):
tp:time
time is the interval between the start of the execution of the pattern and the execution of the vector. It includes a unit.
cyc:cycle
cycle is the index of the cycle in the pattern execution. The index is one-based. (That is, the first cycle in the execution has the index 1.)
vec:vector
vector is the index of the vector in the pattern. The index is one-based. (That is, the first vector in the pattern has the index 1.)

For example, this could be a string that is added to a comment: tp:2000ns|cyc:3|vec:3

This is an optional parameter. The default value is 0.

dcdf_remapping={'wft _wfc':'custom-decvice-cycle-name ',...}

A list of mappings of standard waveform characters to custom device cycle names.

The list consists of pairs of waveform characters and device cycle names. The components of each pair are separated by colons; the pairs are separated by commas. Each pair has these components:
  • wft: The name of the wavetable
  • wfc: The name of the waveform character
  • custom-decvice-cycle-name: The device cycle name to which the character is to be mapped.

For example, to map the character "L" from the wavetable "default" to the cycle name "Low", you would use dcdf_remapping='default_L':'Low'.

This parameter is optional. The default is no remapping.

dcdf_signal_remapping={'signal_1 ':{'wft_wfc ':'custom-device-cycle-name',[...] },[{signal_2: ...}]}

This is similar to dcdf_remapping (above), but specific to one or more signals. That is, using this parameter, you can configure the DCDF remapping separately for each signal.

Specify for each signal a pair of waveform characters and device cycle names, as for dcdf_remapping, and prefix it with the signal name and a colon. To remap multiple signals, separate the mapping for the individual signals with commas.

default_levels_summary=boolean
Whether to output information on default levels that have been assigned to DC variables:
  • 0: No information on default levels is output.
  • 1: Information on default levels assigned to DC variables is output.

This parameter is optional. The default is 0.

digital_capture_res='resolution'
The resolution for the digital capture. Possible values for resolution are:
  • std: The digital capture is done in the hardware's standard mode. (See SDGC, SDGC? for more information.)
  • double: The digital capture is done in the hardware's double-resolution mode.

This parameter is optional. The default is std.

error_on_long_comments=boolean
How STIL Reader handles comments that are longer than the V93000 allows:
  • 0: Truncate the comment and issue a warning.
  • 1: Output an error message.

This parameter is optional. The default is 0.

expand_loops=boolean
How STIL Reader handles loops in the STIL patterns:
  • 0: The loops are converted to V93000 as they are.
  • 1: The loops are expanded before being converted to V93000.

This parameter is optional. The default is 0.

generate_ascii_pattern=boolean
Whether to generate ASCII pattern and timing map files that can be processed with the ASCII Interface:
  • 0: No ASCII pattern and timing map files are generated.
  • 1: ASCII pattern and timing map files are generated.

This parameter is optional. The default is 0.

generate_ascii_tmf=boolean
Whether to generate ASCII timing map files that can be processed with the ASCII Interface:
  • 0: No ASCII timing map files are generated.
  • 1: ASCII timing map files are generated.

This parameter is optional. The default is 0.

Note that this parameter is ignored if generate_ascii_pattern=boolean is set to 1.

generate_clksets=boolean
Whether to enable support for multiclock domain setups:
  • 0: Multiclock setups are not supported.
  • 1: Multiclock setups are supported; CLKSET statements are added to generated timing files.

This parameter is optional. The default is 0.

generate_hvm=boolean
Whether to add VCAT calls to the generated BINL files to support high-volume manufacturing:
  • 0: No VCAT calls are inserted.
  • 1: VCAT calls are inserted.

Note that complete VCAT calls are usually generated only when labels (in STIL) or comments (in WGL) have been generated by the TetraMax, FastScan, or Encounter Test ATPG tools.

Labels or comment generated by TetraMax or FastScan also must contain "pattern" in their names. Labels or comments generated by Encounter Test must consist of a sequence of integers separated by periods, such as 4.15.3.78.3. If these conditions are not met, the scan_test_name field remains blank.

For example, if a STIL label generated by TetraMax is named "myPat", no complete VCAT call is generated (regardless of the setting of the generate_hvm option), but when the same label is named "pattern 12", the call is generated properly when generate_hvm is set to true.

This parameter is optional. The default is 0.

generate_vmap=boolean
Whether to create a log file with scan and instance information (with a .vmap suffix) in the same directory as the V93000 vector file:
  • 0: No log file is generated.
  • 1: A log file is generated.

This parameter is optional. The default is 0.

gzip_patterns=boolean
Whether to compress generated patterns (BINL files) using GZIP:
  • 0: Do not compress generated patterns using GZIP.
  • 1: Compress generated patterns using GZIP.

GZIP compression is in addition to any standard compression applied to patterns on a per-pin basis, which is not influenced by this parameter but by the use_vecc parameter (see below).

Using GZIP compression may improve performance with comparatively slow disk configurations, but may worsen performance with very fast disk configurations.

This parameter is optional. The default is 0.

keep_all_specsets=boolean
Whether to delete spec sets from the translated files if they are not actually used:
  • 0: Unused spec sets are deleted.
  • 1: No specsets are deleted.

This parameter is optional. The default is 0.

keep_spec_variables=boolean
Whether to include unused AC and DC variables from the STIL files in the translated files:
  • 0: Unused variables are not included.
  • 1: All variables are included in the translated files, even if they are not used.

This parameter is optional. The default is 0.

keep_wfc_order=boolean
Whether to keep the waveform characters in the order they have in the STIL file or to reorder them to enhance readability for humans:
  • 0: Reorder the characters for better readability.
  • 1: Keep the characters in the order they have in the STIL file.

This parameter is optional. The default is 0.

label_suffix=suffix

A text that is added as a suffix to all generated pattern and burst labels.

This parameter is optional. The default is no suffix.

max_vector_buffer

This setting is reserved for future expansion. Do not use it.

optimize_drive_edges=boolean
Whether to optimize the allocation of drive edges:
  • 0: Do not optimize drive edge allocation.

  • 1: Optimize drive edge allocation.

    See the Table 2 table in Event mapping for details.

This parameter is optional. The default is 1.

optimize_receive_edges=boolean
Whether to optimize the allocation of receive edges:
  • 0: Do not optimize drive edge allocation.
  • 1: Optimize drive edge allocation.

See the Table 2 table in Event mapping for details.

This parameter is optional. The default is 1.

pattern_comment=comment

Add the text comment as a comment to the comments section of the pattern file.

This parameter is optional. There is no default.

overwrite_groups={'signal_group':['signal1','signal2',...],...}
The signals to assign to signal groups:
signal_group

The name of the signal group to redefine. The definition of this signal group from the STIL file is overwritten with the definition you specify in this overwrite_group statement.

To specify multiple signal groups, separate them with commas.

signal1, signal2
The names of the signals to assign to the group. You can specify any number of signals, separated by commas.

If you specify overwrite_groups={}, all signals groups from the STIL file are deleted. (The signals defined in the STIL file are not affected.)

This is an optional parameter. There is no default value; by default, all signals groups are translated as specified in the STIL file.

pattern_memory_type=memory_type
Which memory mode to use for the converted files:
  • VM: The compatibility mode is used, in which the RDRAM on the Pin Scale cards is divided into fixed vector memory and sequencer memory sections, which is similar to the memory setup of P and C series channel boards.
  • SM: The unified memory mode is used, in which the entire available RDRAM can be dynamically used for storing both vector and sequencer data.
  • SHMEM: The shared memory mode is used, which is similar to SM but in which the vectors for the same pin in different sites share the same memory area.
  • auto: The memory mode is automatically set based on the specified target version of SmarTest: For versions before 7.0 VM is used, and for 7.0 and up SM is used.

This parameter is optional. The default is SM.

pin_based_tim=boolean
Whether to use signal or signal group names in created timing files:
  • 0: When several signals share the same timing, a list of signals is specified in the timing file, not a group name.
  • 1: When several signals share the same timing, a group name is specified in the timing file when a suitable group exists.

This parameter is optional. The default is 0. This parameter is ignored if use_tim_groups (see below) is set to 0.

repeat_break=break-value
This parameter can be set to "none" or to an integer value. It controls the configuration of sequencer-based vector repetition:
  • Integer: The WFC repeat count that must be reached to use sequencer-based repeating of vectors.
  • None: Automatic optimization is used.

This parameter is optional. The default value is 32.

repeat_compression=boolean
Whether to compress adjacent identical vectors into one single loop:
  • 0: Do not compress adjacent identical vectors into a loop.

  • 1: Compress adjacent identical vectors into a loop.

    Scan vectors are by default skipped (that is, they are not compressed), even with this setting. They are only included in the compression if they are defined with named arguments in the SignalGroups definition, not with location-based information (indexes or channel numbers).

    For example, vectors relating to this signal group are compressed:

    SignalGroups {"CLOCKS_1" "port=port1, sync_group=SG1,master_clock=1,xfact=4,scan_repeat_compression=1";}

    Vectors relating to this signal group are not compressed:

    SignalGroups { "clock_2" = '"clk[1]" + "clk[2]"';}

This parameter is optional. The default is 0.

repeat_compression_ignore_comments=boolean

Whether to consider comments when compressing adjacent identical vectors into one single loop. This parameter is only evaluated when repeat_compression (see above) is 1.

  • 0: Adjacent vectors are only considered identical if their comments are also identical.
  • 1: Adjacent vectors are considered identical even if their comments are different (as long as they are otherwise the same).

This parameter is optional. The default is 1.

single_test_suite=boolean

Whether to combine multiple inputs into a single test suite.

  • 0: STIL Reader creates a separate test suite for each input.
  • 1: STIL Reader creates a single test suite from all inputs.

This parameter is optional. The default is 0.

skip_unused_signal_groups=boolean
Whether to translate signal groups that are not used in any timing or level definitions:
  • 0: Translate signal groups even if they are unused.
  • 1: Translate signal groups only when they are used.

This parameter is optional. The default value is 0.

smartest_version='version-of-SmarTest-that-is-targeted'

The SmarTest version that will run the converted files. Provide the version with three digits, for example, '6.5.0'.

This parameter is optional. The default is '6.3.5'.

stil_reader_mode='mode'
Specifies the STIL Reader operation mode with regard to input files that do not conform to the STIL standard:
one-pass
In one-pass mode, STIL Reader expects fully STIL-compatible source files.
two-pass
In two-pass mode, STIL Reader can ignore certain deviations from the STIL standard, such as multiple signal blocks or timing blocks located after pattern blocks. In this mode, operation is slower.

This parameter is optional. By default, one-pass mode is used.

strict_mode=boolean
Whether to apply the strict mode for the translation:
  • 0: Strict mode is off. The generated code may not be loadable.
  • 1: Strict mode is on. The generated code is loadable.

This parameter is optional. The default is 0.

tester_model='model'

The specific test system for which this translation is intended. STIL Reader displays warnings and error messages depending on this setting to inform you when the test system's capabilities are being exceeded.

The available values for model depend on the target platform (see the description of the target parameter). For the 93000SD platform, you can specify:
  • 'P1000'
  • 'P800'
  • 'P600'
  • 'C400e'
  • 'C200e'
For the 93000DD platform, you can specify:
  • 'PS400'
  • 'PS800'
  • 'PS3200'
  • 'PS3600'
  • 'PS6800'
For the 93000SS platform, you can specify:
  • 'PS1600'
  • 'PS9G'

This parameter is optional. The default for 93000SD target systems is 'P800', for 93000DD targets 'PS800', and for 93000SS targets 'PS1600'.

testmethod_class='class'

The class of the test method specified in the testflow. A string.

This information is used when testmethod_mode (see below) is 'utm' or 'classic'.

This parameter is optional. The default is 'ac_tml.AcTest.FunctionalTest', which is only suitable for UTM test methods. For classic test methods, replace this with 'functional'.

testmethod_limits='limits'

The limits that apply to the measurement, in standard SmarTest syntax. A string.

This information is used when testmethod_mode (see below) is 'utm' or 'classic'.

This parameter is optional. There is no default.

testmethod_mode='mode'

The kind of test method that is added to the testflow. A string.

  • 'classic': A classic test method.
  • 'utm': A UTM test method.
  • 'functions': No test method.

This parameter is optional. The default is 'utm'.

testmethod_name='name'

The name for the test method that is added to the testflow. A string.

This information is used when testmethod_mode (see above) is 'classic'.

This parameter is optional. There is no default.

testmethod_params='parameters'

The parameters that apply to the measurement, in standard SmarTest syntax. A string.

This information is used when testmethod_mode (see above) is 'utm' or 'classic'.

This parameter is optional. There is no default.

tim_comments=boolean
Whether verbose comments are added to the converted timing files:
  • 0: No verbose comments are added.
  • 1: Verbose comments are added.

This parameter is optional. The default is 1.

tim_header_comments=boolean
Whether the tool version and generation date are added to the converted timing files:
  • 0: The information is not added.
  • 1: The information is added.

This parameter is optional. The default is 1.

use_channel_mapping='namemaps-93k-channel-name'

When a STIL file contains multiple channel mapping definitions, this parameter specifies which one to use.

A channel mapping is specified in the NameMaps statement. For example, NameMaps "93kChannel:wafer" {...} specifies a channel named "wafer". To select this channel, use use_channel_mapping='wafer'.

This parameter is optional. The default is none.

use_eqfs=boolean
Whether to use a single timing file and a single level file or split them into several equation (.eqn) and specification (.spec) files that are loaded through references using the EQFS command:
  • 0: Use single files
  • 1: Use multiple referenced files

This parameter is optional. The default is 0.

use_lvl_groups=boolean
Whether to group signals with identical levels in the generated level files:
  • 0: Specify levels separately for each individual signal.
  • 1: Group signals with identical levels.

This parameter is optional. The default is 1.

use_mhz_specs=boolean
Whether to specify frequencies in AC specs in MHz:
  • 0: GHz is used as the unit for frequencies in the AC specs.
  • 1: MHz is used as the unit for frequencies in the AC specs.

This parameter is optional. The default is 0.

use_model_file='path-to-model-file'

A path to a SmarTest model file.

If this path is specified, the channel numbers will be checked against the model file or assigned from it:
  • If a NameMaps object named 93kChannel is present, the channel numbers specified in it will be checked against the model file.

  • If that NameMaps object is not present, the channel numbers will be automatically assigned based on the model file.

    In addition, STIL Reader checks for violations of vector memory and sequencer memory.

This parameter is optional. The default is none.

use_tim_groups=boolean
Whether to group signals with identical timing in the generated timing files:
  • 0: Specify timing separately for each individual signal.
  • 1: Group signals with identical timing. In this case, the exact nature of the grouping is determined by the setting of the pin_based_tim parameter (see above).

This parameter is optional. The default is 1.

use_vecc=boolean
Whether to compress vectors on a per-pin basis:
  • 0: Use the VECD command, that is, do not compress vectors.
  • 1: Use the VECC command, that is, compress vectors. Compressing vectors can significantly improve loading times.

This parameter is optional. The default is 1.

user_keywords=[' keyword',...]

A list of custom user keywords. This parameter is equivalent to the UserKeywords statement in STIL.

For example: ['myKeyword1','myKeyword2']

This parameter is optional. There is no default value.

vector_memory_summary=boolean
Whether to output a summary of the vector usage for each binary pattern:
  • 0: STIL Reader does not output a vector usage summary.
  • 1: STIL Reader outputs a vector usage summary.

This parameter is optional. The default is 0.

xmode_all_cmb=boolean
Whether to use all possible combinations of STIL waveforms for V93000 timing:
  • 0: Only actual combinations of STIL waveforms are used for V93000 timing.
  • 1: All possible combinations of STIL waveforms are used for V93000 timing.

This parameter is optional. The default is 0.

xmode_aware_comments=boolean
This setting determines how comments for sub-x-mode vectors are handled:

  • 0: If all comments for sub-x-mode vectors are identical, only a single comment is generated.

    For example: The x-mode is 2 and the STIL code is: 
    V // my comment 1
V // my comment 1

    Then the V93000 comment is "my comment 1".

  • 1: Each sub-x-mode comment is delimited by a vertical line (|).

This parameter is optional. The default is 0.

xmode_based_statemapping=boolean
Whether to base the state mapping on the selected x-mode:
  • 0: The state mapping is created without taking the selected x-mode into account.
  • 1: The waveforms are grouped according to the selected x-mode during state mapping.

This parameter is ignored if create_statemapping is not 1.

This parameter is optional. The default is 1.

xmode_factor=x-mode-factor
The global x-mode setting to be used in the translation. x-mode-factor can be:
  • An integer that specifies the mode, for example, 6 for the x6 mode.
  • 'auto'. In this case, STIL Reader automatically determines the optimal x-mode based on the patterns to be converted and the capability of the target hardware.

In multiport translations, this parameter is by default applied to all ports, unless individual x-modes are specified per port as described below. (For example, if ParallelPatList is used in the STIL file, a multiport translation is performed.)

X-modes can be set on a per-port basis in multiport translations by specifying them in the NameMaps block in the form "port name, sync group, clock domain, xmode factor, port type, specs scope, keep spec variables, phase sync". Note that port type, specs scope, keep spec variables, and phase sync are optional. (See Configuring x-modes using STIL Reader for more information on these options.)

For example, you could specify x-modes in this way (setting the "Clocks" signal group to x2 and the "data" signal group to x3): 
Environment {
  NameMaps "93kPorts" {
    SignalGroups {
    "Clocks" "Clock,SyncGroupA,1,2";
    "data" "Data,SyncGroupB,3,3";
    }
  }
}

This parameter is optional. The default is 1.

yield_learning=boolean
This parameter determines whether scan structure information is translated into a V93000-compatible form:
  • 0: Scan structure information is not translated.
  • 1: Scan structure information is translated.

This parameter is optional. The default is 0.

yield_learning_scan_structures=scan-structure

When a STIL file contains multiple scan structure definitions, this parameter specifies which one to use.

A scan structure is specified using the ScanStructures statement. For example, ScanStructures scan1 {...} specifies a structure named "scan1". To select this channel, use yield_learning_scan_structures='scan1'.

This parameter is optional. The default is none.

yield_learning_scan_domain=scan-domain

scan-domain is the name of the scan structure that is used in the generated files for LTDF and ATPF commands as well as for naming the scan structure protocol file. This parameter overrides the scan structure name from the STIL file.

This parameter is optional. The default is none, meaning that the scan structure name from the STIL file is used.

yield_learning_skip_flops=boolean
Whether the names of flops (cells) are left out of the protocol template:
  • 0: Flop names are included in the protocol template.
  • 1: Flop names are not written to the protocol template.

This parameter is optional. The default is 0.

Example

See the example in STIL Reader setup file.

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.1.4: Changed behavior of repeat_compression: scan vectors are now skipped by default.
  3. SmarTest 7.2.1: Added new options to xmode_factor setting.
  4. SmarTest 7.2.1: Removed full_incremental_log setting.
  5. SmarTest 7.2.2: Removed use_unified_memory setting.
  6. SmarTest 7.2.2: Added "auto" option to xmode_factor setting.
  7. SmarTest 7.2.2: Added pattern_memory_type and repeat_compression_ignore_comments settings.
  8. SmarTest 7.2.2: Changed the default for repeat_break to 32.
  9. SmarTest 7.4.2: Removed max_vector_buffer option.
  10. SmarTest 7.5.3: Added the generate_ascii_pattern and generate_ascii_tmf settings.
  11. SmarTest 7.6.0: Added the cycle_numbering, keep_all_specsets, single_test_suite, stil-reader_mode, testmethod_class, testmethod_limits, testmethod_mode, testmethod_name, testmethod_params, use_lvl_groups, and user_keywords options.
  12. SmarTest 7.10.1: Added the overwrite_groups parameter. Removed the use_restags parameter.
