Code-based and pattern-based programming

Even if almost everything in a test method is programmed using the test method APIs, there are two fundamental differences in programming. With code‑based programming, the hardware is controlled directly from the workstation. With pattern‑based programming, the hardware is controlled by the pattern‑sequencer, which leads to stable timing.

Code‑based programming

Code‑based programming means that the programmed hardware is directly controlled by the workstation. This also applies if a test‑processor is available.

Code‑based programming is also known as static programming.

See also Code-based mode in SmartRDI.

Pattern‑based programming

Pattern‑based programming means that the programmed hardware is controlled by a pattern‑sequencer.

Pattern‑based programming is also known as sequencer‑controlled programming or dynamic programming.

For DC Scale cards, the used commands are named "DC event". DC events allow you to initiate measurements as well as controlling voltages or currents on DC Scale pins. DC events can be defined by the EVENT... test method APIs and inserted into an existing pattern using the PATTERN_CONTROLLER test method API or the Pattern Editor.

Not that not all functions that can be controlled by code‑based programming are also available for pattern‑based programming.

See also Pattern-based mode in SmartRDI.
