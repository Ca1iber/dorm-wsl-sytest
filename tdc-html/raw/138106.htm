Topic 138106

generate_template

The generate_template command for the SmarTest Program Manager MCM (STPM MCM) control file creates an MTPT (mapping template) from the STPs (source test programs) and parameters with which you supply it.

The command is intended to be executed once during the initial setup of an STPM MCM conversion process.

Executing the command generates all the tables that make up an MTPT as well as an OpenOffice spreadsheet for comfortably editing them. Note that the mtp_template_dir parameter must be specified in the control file for the command to work.

After the tables have been created, you will often want to modify them to adapt them to special requirements. After you have edited them to your satisfaction, you can use the create_mtp command to combine the STPs into an MTP.

Note that you must once create a device directory using generate_device_dir before you run create_mtp for the first time.

Syntax

generate_template(
  stp_names                       = [ <stp>, ... ],
  stp_flow_paths                  = [ <flow_path>, ...],
[ stp_prefixes                    = [ <prefix>, ...],             ]
[ stp_bin_offsets                 = [ <bin_offset>, ...],         ]
[ stp_testnum_offsets             = [ <testnum_offset>, ...],     ]
[ stp_tim_offsets                 = [ <timing_offset>, ...],      ]
[ stp_lev_offsets                 = [ <level_offset>, ...],       ]
[ stp_test_modes                  = [ <mode>, ...],               ]
[ stp_apply_prefix_on_pin_configs = [ <apply_prefix_flag>, ...],  ]
[ stp_keep_unused_data            = [ <keep_data_flag>, ...],     ]
[ stp_keep_channels               = [ <keep_channel_flag>, ...],  ]
  sites                           = <num>
)

Parameters

The parameters in the order in which they are listed above:

stp_names

A list of names of STPs that will be integrated into one MTP

<stp> (string) is the name of the STP. You can specify multiple STPs; they must be separated by commas.

stp_flow_paths

A list of paths of STP testflow files

<flow_path> (string) is the path of the testflow file of this STP. You must specify one path for each STP listed in stp_names (see above); the paths must be listed in the same order as the STPs. They must be separated by commas.

stp_prefixes

A list of prefixes for objects from the individual STPs

<prefix> (string) is the prefix that is added to objects that are imported from this STP into the MTP to avoid duplicate names. You must specify one prefix for each STP listed in stp_names (see above); the prefixes must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, no prefix is used for any of the STPs.

stp_bin_offsets

A list of offset values for bins from the STPs

<bin_offset> (integer) is a number that is added to the numbers of bins from this STP to avoid numbering conflicts in the MTP. You must specify one offset for each STP listed in stp_names (see above); the offsets must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, 0 is used as the offset for each STP.

stp_testnum_offsets

A list of offset values for test numbers from the STPs

<testnum_offset> (integer) is a number that is added to the test numbers from this STP to avoid numbering conflicts in the MTP. You must specify one offset for each STP listed in stp_names (see above); the offsets must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, 0 is used as the offset for each STP.

stp_tim_offsets

A list of offset values for timing equation sets from the STPs

<timing_offset> (integer) is a number that is added to the numbers of timing equation sets from this STP to avoid numbering conflicts in the MTP. You must specify one offset for each STP listed in stp_names (see above); the offsets must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, 0 is used as the offset for each STP.

stp_lev_offsets

A list of offset values for level equation sets from the STPs

<level_offset> (integer) is a number that is added to the numbers of level equation sets from this STP to avoid numbering conflicts in the MTP. You must specify one offset for each STP listed in stp_names (see above); the offsets must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, 0 is used as the offset for each STP.

stp_test_modes

A list of test modes for tests from the STPs

<mode> (string) is the name of the test mode for the tests from this STP. You must specify one mode for each STP listed in stp_names (see above); the modes must be listed in the same order as the STPs. They must be separated by commas.

To specify no test mode for a particular STP, use an empty string ("").

This is an optional parameter. If it is omitted, no test mode ("") is specified for all STPs.

stp_apply_prefix_on_pin_configs

A list of flags for the STPs specifying whether to apply the prefix for this STP

<apply_prefix_flag> (0 or 1) specifies whether the prefixes from stp_prefixes are used for this STP:

  • 0: The prefix is not applied to the names of pin configuration objects from this STP
  • 1: The prefix is applied to the names of pin configuration objects from this STP

Pin configuration objects include names of pins, pin groups, power supplies, port, and utility lines.

You must specify one flag for each STP listed in stp_names (see above); the flags must be listed in the same order as the STPs. They must be separated by commas..

This is an optional parameter. If it is omitted, all prefixes are applied.

stp_keep_unused_data

A list of flags for the STPs specifying whether to copy unused data from this STP to the MTP

<keep_data_flag> (0 or 1) specifies whether all timing, level, and pattern data from this STP is copied to the MTP:

  • 0: Only timing, level, and pattern data that is used is copied to the MTP
  • 1: All timing, level, and pattern data in the STP is copied to the MTP

You must specify one flag for each STP listed in stp_names (see above); the flags must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, all data from the STP is copied (as if 1 was specified for each STP).

stp_keep_channels

A list of flags for the STPs specifying whether to copy channel numbers from this STP to the MTP

<keep_channel_flag> (0 or 1) specifies whether the channel numbers from this STP are copied to the MTP:

  • 0: Channel numbers are not copied to the MTP
  • 1: Channel numbers are copied to the MTP

Channel numbers for sites that are specified in the STP but not the MTP are never copied. Channel numbers for sites that are specified in the MTP but not the STP are initially empty in the template and must be filled in by you.

You must specify one flag for each STP listed in stp_names (see above); the flags must be listed in the same order as the STPs. They must be separated by commas.

This is an optional parameter. If it is omitted, no channel numbers are copied.

sites

<num> (integer) is the number of sits that the MTP will test.

This is an optional parameter. If it is omitted, an MTP for one site will be generated.

With the exception of sites, all parameters are lists of values. Each list must have the same number of elements, and the elements must be in the same order in all lists.

For example, if there are four STPs, each list must have four elements. The first element must always be the value for the first STP, the second element the one for the second STP, and so on.

Example

generate_template(
  stp_names                       = [ "CPU", "DSP" ],
  stp_flow_paths                  = [ "/prj/CPU/testflow/rel.tf", "/prj/DSP/testflow/rel.tf" ],
  stp_prefixes                    = [ "C", "D" ],
  stp_bin_offsets                 = [ 0 , 20 ],
  stp_testnum_offsets             = [ 0, 1000 ],
  stp_tim_offsets                 = [ 0, 50, ],
  stp_lev_offsets                 = [ 0, 50, ],
  stp_test_modes                  = [ "mode1", "mode2" ],
  stp_apply_prefix_on_pin_configs = [ 1, 0 ],
  stp_keep_unused_data            = [ 0, 0 ],
  stp_keep_channels               = [ 0, 0 ],
  sites                           = 2

)
