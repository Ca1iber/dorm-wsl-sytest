Enabling Workorders for Command Line Use

If a workorder does not reside in a user's $HOME/workorder directory, the user cannot execute the workorder from within the running SmarTest software.

However, a workorder can also be executed from the command line. To make this working, you must always specify a full device path in the workorder file, for example:

hp93000,workorder,0.1

device: /devices/74ACT299 (full device path)

test_prog_rev:

test_prog: wafer_auto

Tester_id=12

Prober_id=12

DUT_board_id=12

Supervisor_id=DSt

Date=12.12.94

Remark=ok

Note If the test_prog_rev is set and INSTALLED_DUT_PATH is set in the org file, the path of the device will be /INSTALLED_DUT_PATH/device/test_prog_rev.
Note If a full device path is specified as shown in this example, then the entries for DUT_PATH and INSTALLED_DUT_PATH in the file /etc/opt/hp93000/soc/org (see "Org File" in Specifying the Device Path) must still exist as paths, but the device needs not to be in one of these paths.

A workorder with a full device path must be executed with the SmarTest start up command.

The workorder manager does not support workorders with a full device path.

The commands for calling a workorder from the command line are given in Executing a Workorder From the Command Line. This section also tells you what to do next, when starting a workorder in this way.
