Topic 141276

RDI_BEGIN()

RDI_BEGIN() and RDI_END() define and enclose an RDI block. The RDI block marks a section in a test method to set up and execute tests in the pattern‑based mode of SmartRDI.

RDI_BEGIN() and RDI_END() are intended to be used in the ON_FIRST_INVOCATION block and must always be implemented together.

For the first run, SmartRDI creates corresponding pattern from the code within the RDI block. Depending on the value of parameter mode, the single patterns or a pattern burst that contains all generated patterns for the RDI block are executed for the first and all subsequent runs.

  • The code inside RDI_BEGIN()/RDI_END() is only executed in the first run after build. This is required for generating pattern content.

  • In the following runs, the code inside RDI_BEGIN()/RDI_END() is skipped! This is because the pattern content is already available.

  • DO NOT put any code that you would like to run in EACH execution into RDI_BEGIN()/RDI_END().

  • For debugging a project: At the line where RDI_END() is located, the pattern which has been created in the first run is executed.

Syntax

RDI_BEGIN();
RDI_BEGIN(mode);
Parameter

Parameter

Description

mode

The optional execution mode. It can be:

  • TA::BURST: Pattern-based execution mode. This is the default mode.

  • TA::SINGLE: Single step execution mode for debugging.

  • TA::PROD: Production mode. No new setups will be generated. The saved setups from the pattern‑based mode will be used.

Execution modes in RDI_BEGIN()

Burst Mode (TA::BURST)

This is the target mode for developing tests. This mode is the default mode if parameter mode is not specified.

  • First run after build:

    • One or more patterns are generated for all RDI commands of the RDI block.Note:

      RDI commands are enclosed by rdi.class() and execute().

    • A pattern burst, containing all generated patterns for the RDI block, is generated.
  • First run after build and all subsequent runs:
    • The pattern burst runs at the end of the RDI block when RDI_END() is executed.
Single Mode (TA::SINGLE)

This mode should be used only for debugging.

The Single Mode works similar to the Burst Mode but utilizes more pattern bursts:
  • In Burst Mode, one pattern burst is executed per RDI block.
  • In Single Mode, one pattern burst is executed per RDI command that is enclosed by rdi.class() and execute().
The Single Mode allows you therefore, using the debugger to execute the RDI commands within an RDI block step by step.
Production Mode (TA::PROD)

The non-generation mode for production.

  • Works similarly as TA::BURST, but WITHOUT setup generation.
  • SmartRDI just follows the naming rules to run the needed setups.
  • User still needs to keep alignment between the code and the setup. Result retrieval information is still based on the code.

SmartRDI does not create any pattern or setup in Production Mode. You must therefore ensure, that the following requirements are met:

  • Pattern in RDI block:
    • A pattern setup file must be available.
    • Required pattern of the RDI blocks are to be generated by SmartRDI with parameter mode of the RDI blocks set to TA::BURST.
    • The pattern setup file must be saved after it has been modified by SmartRDI: The modified file is marked by an asterisk "*" in the Test Program Explorer.
    • The pattern setup file must be added to the Setups page of the Flow Data Editor.
  • Analog setups:
    Setups for analog cards (AWG and DGT) are automatically generated by SmartRDI. Minimum an analog control file must be available. AWG setups also require an analog waveform file.1)
    1. Add both the analog control file and (for AWG tests) the analog waveform file in the Setups page of the Flow Data Editor.
    2. Ensure that parameter SETUP_UPTODATE in file RDI_Configure file is set to FALSE.
    3. Reload all setups.
    4. Ensure that all required files are loaded: Analog control file and (for AWG tests) the analog waveform file.
    5. Start the full flow with parameter mode of the RDI blocks set to TA::BURST to allow SmartRDI generating the setup and the waveform.
    6. Verify that both the analog control file and (for AWG tests) the analog waveform file are marked by an asterisk "*".
    7. Save both the analog control file and (for AWG tests) the analog waveform file.

The following error messages a shown in the ui_report window if a setup file is missing in production mode:

  • Pattern file missing: ERROR:[1] label(...) on port(...) not found in PROD mode!
  • Analog setup missing: ERROR:[1] Analog set(...) is NOT found in Production mode!
  • Analog waveform missing: ERROR: FLSH - Waveform label ... not yet filled with waveform data, but accessed in sequencer program ... for ... in analog set ....

Examples

Example 1: Minimum code

The following example shows the minimum code for a RDI block. The ellipses ("...") are to be replaced with your code.

RDI_BEGIN();
    ...
    ...
RDI_END();

Example 2: Optional curly brackets

The example utilizes an optional pair of curly brackets "{" and "}". These optional curly brackets are used for simplifying the correct indentation with assistance of the related Eclipse tool.

RDI_BEGIN();
{
    ...
    ...
}
RDI_END();
Note The two use options (with or without curly brackets) should not be mixed in one test method class.
