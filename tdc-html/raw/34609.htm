Files explanations

The Event Formatter is built from these files:

  • config.c: Contains all procedures that manage the utilization of the .formatterrc file (see below).
  • config.h: Exports the headers of the procedures of config.c and the struct CONFIG, which holds the Event Formatter settings that cannot be made in the Report Dialog window.
  • file_dialog.c: Contains the browser that is called when the report window menu items START Logging Formatter Output to File or Save Datalog Stream and Clear are chosen. Thus, this file mainly contains Motif commands and callback routines.
  • file_dialog.h: Exports the headers of the procedures of file_dialog.c, which can be run by external calls.
  • filter.c: Contains all procedures that form the interface to the report window process, except for the eventProcess procedure (see handler.c). The start procedure is called when the Event Formatter is activated. end is called when the Event Formatter is deactivated (by selecting another report formatter).
  • formatter.c: Contains the procedures that process and output the header and value parts (STDHeader, STDValue) of a test function event. Any additional functions for special processing of test functions should be included in this file.
  • formatter.h: Exports the headers of the procedures of formatter.c, so that these procedures can be called from tf_event.c.
  • handler.c: Determines how each type of event is dealt with. This is done by the eventProcess procedure, which receives one event each time it is called from the report window process. handler.c itself processes all types of events except for the test function event, which is passed to the HandleTFEvent procedure in tf_event.c (see below). When such a test function event is passed to HandleTFEvent, all attributes are stored in a dedicated struct, TFEventType.
  • handler.h: Exports the header of the eventProcess procedure and of the procedures which are used for the log-to-file functionality of the Event Formatter. Further, this file contains several defines, most of them needed in handler.c.
  • report_dialog.c: Implements the Report Dialog window. The functions of the checkboxes are realized by callbacks that set the test suite flags of the appropriate test suites.
  • report_dialog.h: Exports the headers of the procedures of report_dialog.c and the report_state struct variable, which holds the states of the checkboxes.
  • tf_def.h: Exports the struct TFLimits and also the array tf[ ], which is part of that struct. For each test function, tf contains the cpi index, the TFunctional or TParametric classification, the parameter DC/DC power units for the limits and, for some test functions, function pointers to the header/value procedure.
  • tf_event.c: Receives test function events from handler.c by means of the HandleTFEvent procedure and creates the formatted output for these test functions. Further, tf_event supports procedures in formatter.c, for example, PrintPinResult or PrintSeparator.
  • tf_event.h: Exports the headers of the procedures of tf_event.c; also declares structs like TFEventType which contains all data extracted from a test function event. Further, tf_event.h declares ToDoType, which determines which results/data re contained in the report (depending on the settings of the checkboxes in the Report Dialog window).
  • tf_event_ffv.c: Receives test function events from handler.c by means of the HandleTFEvent procedure and creates the formatted output of FFV (first failing vector) information for these test functions. Further, tf_event_ffv.c supports procedures in formatter.c, for example, PrintVectorResultsShort or PrintVectorResultVerbose.
  • tf_event_shmoo.c: Receives test function events from handler.c by means of the HandleTFEvent procedure and creates the formatted output of sweep test results for these test functions.
  • .formatterrc.def: Contains the default settings for the Event Formatter. See Appendix B: Event Formatter Defaults.

Functional changes
