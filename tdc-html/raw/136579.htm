DGCS, DGCC? (DiGital Capture aSynchronous)

The DGCS defines the next SQST run as asynchronous digital capture test.

It is part of a sequence that requires the commands DGCS, SQST, and DGCC? as described in the Syntax section below. This sequence is the respective command for asynchronous digital capture test to the DGCT? command.

Syntax

DGCS
SQST RUN
DGCC?

returns:

DGCC {result_flag}
Parameters

result_flag

The result returned by DGCC?.

P (for Pass) is returned if received and expected data match.

F (for Fail) is returned if received and expected data do not match.

F (for Fail) is returned if In a standard digital capture test a high is received, which means it does not match the functional test result (refer to Combining selective digital capture with a functional test to learn about using the HRPF keyword).

Note that the result flag refers to the functional test, and does not say anything about the success of the digital capture. Rather, when the functional test returns P, this may imply that something went wrong with digital capture. Thus, if the received values are compared against 0, which is recommended, P can indicate that no data was captured.

Examples

Generic example

> DGCS
> SQST RUN
> DGCC?
< DGCC F

Application

This command performs hardware activation and clean-up on pins configured for digital capture.
