This section describes all driver configuration parameters you can set to determine the behavior of the equipment driver.

As described in Driver Configuration, the attributes definition of a plug-in determines which of the configuration parameters can be set for the plug-in, and what the possible valid settings are.

Therefore, this chapter does not contain information about the valid range of settings for configuration parameters.

For some of the parameters, the driver uses default values, if no values are assigned to these parameters in the driver configuration.

These default values are listed as 'driver default' in the description of the parameters in this chapter.

Parameters which have no driver default and are defined in the attributes definition of the plug-in must be set up in the driver configuration.

Configuration parameters can be applicable for either handlers or wafer probers, or for both. This is stated with each parameter.

Normally, parameters which control general driver behavior (for example, debug_level, or driver_message_log) will be set as required for a user- specific application, while parameters which are communication interface and equipment specific (for example bin_data_setup_time or bin_coding) would normally always be used as set in the default configuration provided with a plug-in.

Note The example parameter settings given here only show typical settings. A particular attributes definition may likely require different settings.
Note In this chapter, "device" is used as a general term for a chip to be tested. That is, a "device" can be a packaged chip or a die on a wafer.
