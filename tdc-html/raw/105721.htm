Topic 105721

Setting up and performing a redundancy analysis

Subtopics

  1. Folder structure for redundancy analysis files
  2. Redundancy analysis on multiple test suites
  3. Setting up RA configuration and file generation tool
  4. Using RaServer for offline analysis
  5. Bit fail map list file
  6. Physical address-based list file

To set up redundancy analysis, you specify the relevant details of the DUT, the execution options for the analysis, specific options for the algorithm, and the desired output format options.

Before you begin

Gather all required information about the architecture of the DUT, its redundancy capabilities, and the guidelines used to assign spares to failed elements.

Set up the map converter library you plan to use and make sure that it contains the required functions. If it does not, add them and recompile the library as described in Setting up address scrambling. The required functions are:

  • If the map converter type is RA_LAYOUT_BASED: get_ra_layout and phys_to_layout.
  • If the map converter type is TOPO_ADDR_BASED: get_map_size and phys_to_map.

Make sure that the folder structure for the redundancy analysis files is correctly set up, as described in Folder structure for redundancy analysis files.

Procedures

Online analysis

  1. Decide on whether you want to use the Successive algorithm supplied by Advantest.

    If you want to use your own algorithm, write it as explained in Writing a custom redundancy analysis algorithm.

  2. Describe the DUT in the DUT representation file as explained in DUT representation file.
  3. Compile the DUT representation file as described in Compiling the DUT representation file.
  4. Set up the operation parameters for the redundancy analysis as described in Redundancy analysis configuration file.
  5. Set up the operation parameters for the redundancy analysis algorithm as described in Control file for the Successive algorithm.
  6. For using the redundancy analysis online (that is, as part of a test flow), insert the ExecutionEngine test method in a test flow. Configure it as described in Parameters for the ExecutionEngine test method.
  7. Run the test flow.

Offline analysis

  1. If the bit fail map you want to analyze does not already exist, run a test to create a bit fail map for the DUT.
  2. Perform steps 1 through 5 from the "Online analysis" procedure (above).

    In step 4, make sure to specify the bit fail map in the faildata_file parameter of the Redundancy analysis configuration file.

  3. Enter this command in a terminal window:
    RaServer -o <ra_config_file>

    Where <ra_config_file> is the Redundancy analysis configuration file.

Results

The algorithm log and solution output is available in the locations described in Output of the Successive algorithm.

The redundancy analysis logs are available in /var/opt/93000mts/mts/log:

  • The redundancy analysis server log is named MTP_RAServer.log and is stored directly in that directory.
  • Logs of the individual services are named <ra_service_id>.log and are stored in the RA_logs subdirectory.

What to do next

Implement the repair solution for the device.

Functional changes

  1. Introduced in MTP 2.6.5
  2. MTP 3.0.3: (MTP on SOC 103.0.0) Redundancy analysis is now performed via the ExecutionEngine test method.
  3. MTP 3.2.1: MTP-on-SOC and MTP-on-HSM become one software. There are no differences between them. Features can be different if the used licenses are different.
  4. MTP 3.2.2: Removes the tool used for verifying the redundancy analysis.
