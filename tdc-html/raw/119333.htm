How to use callgrind with UTM

The script restart_utm_with_callgrind.ksh is provided to analyze the cache utilization in your test method. The script is located in the directory /opt/hp93000/soc/testmethod/lbin/.

About this task

This script mainly uses the script /opt/hp93000/soc/system/sbin/amendProcessCmd.py. The amendProcessCmd.py is used to manipulate the run-time process configuration of SmarTest component processes. For more information about it, type amendProcessCmd.py -h in the command line.

Callgrind is a cache profiler. It identifies the number of cache misses, memory references and instructions executed for each line of source code, with per-function, per-module, whole-program summaries plus extra information about callgraphs. It was folded into the main Valgrind distribution in version 3.2.0. It can be used with programs written in any language.

Before you begin

Make sure you are using SmarTest 6.5.3 or later versions.

Procedure

  1. In a shell, change to the directory where you want to save the callgrind log files and start SmarTest from command line.
  2. In the command line, execute the following command: 
    $ /opt/hp93000/soc/system/bin/run -S
$ /opt/hp93000/soc/testmethod/lbin/restart_utm_with_callgrind.ksh
  3. After the above two scripts are finished, execute your test method.
  4. To dump the callgrind log, run the command: 
    $ callgrind_control -d

    A callgrind log file is created with the name callgrind.out.pid. Pid is the real process id of your current running UTM process, which can be showed by running /opt/hp93000/soc/testmethod/bin/tmm_console -e pid. A full callgrind log file callgrind.out.pid.1 is dumped. (For more usage of callgrind_control, run callgrind_control -h.)

  5. Display the log file by executing kcachegrind callgrind.out.pid. Switch to "Cycle estimation" in the menu marked with red in the image below.
  6. Review the results and fix the issue in the test method code.

What to do next

To continue running SmarTest without callgrind, exit SmarTest, and then exit the shell (from where you used the run -S option). Now restart SmarTest from another shell or the task bar.

Functional changes

  1. Introduced in SmarTest 6.5.3
