Testflow Tool preference page

You can change the following preferences on the Advantest V93000 > Testflow Tool preference page.

Option

Description

Resolve name conflicts by adding suffix automatically

This option determines how to resolve name conflicts when you copy and paste nodes into a testflow.

  • If you enable this option, the name of the pasted node is the original name with "_1" added at the end.
  • If you disable this option, pasting a node opens the Name Conflict window prompting you to enter a new name for the pasted node.

Synchronize selection between Flow Data Editor and Flow Sequence Editor
  • If you enable this option, the display of the test component is synchronized between the two editors. For example, if you click a test suite in the Flow Sequence Editor, the test suite is also in focus in the Flow Data Editor.
  • If you disable this option, the display of the test component is not synchronized between the two editors.

Synchronize selection between Debug view and Testflow editors
  • If you enable this option, when you execute the test suites one by one in the Debug view, the last executed test suite will be highlighted in the testflow tool.
  • If you disable this option, the highlighted test suite in the testflow tool will not be changed with the execution in the Debug view.

Execute selected UTM Test Method as separate process (to avoid blocking)

As the UTM CDT debugger is always attached to the default executor, the invocation of new Test Method is blocked if one Test Method is already suspended by the debugger.

By enabling this option, SmarTest always executes selected UTM Test Method on another executor as separate process. Its execution is no longer blocked.

Beware that those executions do not share the same process space. Value of global variable, for example, is different in each executor.

Check UTM test method library version when opening testflow editor
  • If you enable this option, when you open a testflow, the testflow tool will check whether the test method library is built on the version of SmarTest you are currently using. If not, a warning message will be displayed.
  • If you disable this option, no checking of the test method library will be done when you open a testflow.

When running shmoo tests, warn that no shmoo plot will be generated

This option determines how SmarTest behaves when you run a shmoo testflow using the Run Selected command.

  • If you enable this option, SmarTest opens a window asking you whether you want to transfer the test suite or not.
  • If you disable this option, SmarTest transfers the test suite without further notice.

Ask before copying testflow variables that do not exist in the target test flow.

This option determines how SmarTest behaves when you merge testflows and at least one element of the source testflow contains a variable that does not exist in the target testflow:

  • If you enable this option, SmarTest opens a window in which you decide whether SmarTest creates the variables with their default value in the target testflow or SmarTest does not copy those elements to and does not create the variables in the target testflow.
  • If you disable this option, SmarTest copies the testflow elements and creates the variables with their default values automatically.

Startup options

Specify whether the last opened editor (the Flow Data Editor or the Flow Sequence Editor) or both editors will be opened next time when you double-click the testflow item in the Test Program Explorer view.

  5. SmarTest 7.3.2: New option Pop up dialog window to configure whether or not to copy those testflow variables existing only in the source testflow to the target testflow.
