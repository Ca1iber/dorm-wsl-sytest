Topic 89070

SourceSync fast mode

The tables describe the parameters for the SourceSync fast mode test method.

Note Besides using this provided test method, you can use the SOURCESYNC_TEST API to create your own source-sync test.
Note To shmoo over a source-sync test, besides using the shmoo parameters described in this table, you can use the shmoo tool. For detailed procedures and comparisons between these two methods, see Shmooing over a source-sync test with Shmoo Tool.
Fast Mode Source Synchronous test method parameters

Name

Comment

Sharing Config File

The name of the sharing configuration file.

It should be located in <device directory>/configuration/. If the file is located elsewhere, specify its position as an absolute path or a relative path based on <device directory>/configuration/.

This is an optional parameter. It is required only if you want to specify different buffer pins for different sites. If you want to specify the same buffer pins for all sites, you can use this parameter and specify the buffer pins in the Sharing configuration file or use the BufferPins parameter described below.

SourceSyncPinGroups

Pin group. List of source synchronous pin groups (clock domains), separated by a semicolon. Each group must contain one clock output pin and at least one data output pin.

Examples:

Four groups: RDQS0o, DQ0o, DQ1o; RDQS1o, DQ15o; RDQS2o, DQ_Bus2;ssgroup3

In case of RSS (Rapid Source Sync) with 4 buffer method:

<pins of SS_0 at board 1>#<pins of SS_0 at board 2>;...; etc. Pins for same source sync pin group are located at two logical boards.

Note Rapid source sync is not supported on the EXA Scale test systems.

StartCycle

Cycle number. Specify the tester cycle number where source synchronous testing range starts.

You can define a start value for more than one cycle range, separated by a semicolon.

When you are using x-modes, this number should be different from the DUT data bit.

Example: 1;129

For RSS: Only one range and at least eight cycles to be selected.

Start test system cycle number starting from 0, in multiples of eight only.

Example: 0;128 or 8;128, ...

StopCycle

Cycle number. Specify the tester cycle number where the source synchronous testing range shall end. The smallest value is 1 (-1 is not allowed). You can define more than one cycle range separated by semicolon.

When you are using x-modes, this number should be different from the DUT data bit.

Example: 10;138

RSS: Only one range and at least eight cycles to be selected. The stop cycle number must be greater than the start cycle number by a multiple of eight.

Example: If the start cycle is 0, the stop cycle must be 7.

RepeatEdge

 

Interval

Number. Specify the bit sample interval. Output filter interval for error map counted in edges.

If greater than 0, for example N, in every N continuous edges, only one edge is displayed and used for calculating the histogram.

If set to 0, every edge is displayed and used for calculation and the RepeatEdgeOffset parameter is ignored.

Offset

Number. Output offset in every interval, counted in edges. The value must not be negative or greater than the value of RepeatEdgeInterval. In each cycle range for source synchronous testing, the first edge's offset is 0. The pass/fail result is not changed by these two parameters, even if the fail cycle is filtered out.

Example:

  • RepeatEdgeInterval = 16
  • RepeatEdgeOffset = 14
  • XMode = 8

Error map:

  • Cycle 7 (edge 0): FFFFFF.........FFF <-- cycle range starts here, nOffset=0
  • Cycle 7 (edge 1): FFFFF.........FFFF
  • ...
  • Cycle 8 (edge 6): FFFF........FFFFFF <-- output this line (nOffset=8+6=14)
  • Cycle 8 (edge 7): FFFFF.........FFFF
  • Cycle 9 (edge 0): FFFFFF.........FFF <--nOffset=0
  • ...
  • Cycle 10 (edge 6): FFFF........FFFFFF <--output this line (nOffset=8+6=14)
  • Cycle 24 (edge 7): FFFFF.........FFFF
  • ...

Length

Number. Specify the bit sample length.

UsePredefinedTimingFile

No or Yes. If Yes, the timing specification is changed during the sweep.

If No, sweeps by changing the timing specification variable content.

SweepingSpecVars

Variable name. Specify the timing specification variable for each of the source synchronous pin groups, separated by a semicolon. Used for multishot sweeping. The name can be identical for different source synchronous pin groups. The number of source synchronous pin groups and the number of timing specification variables need to be the same, otherwise the Test Method aborts with an error.

Example: TSweep0;TSweep1;TSweep2 for three source sync groups

Multiport: A port can be configured to have multiple, but exclusive, SS-groups (see second example ).

Examples (assuming the source sync groups sweep_a;sweep_b;sweep_c):

  • sweep_a@port_a;sweep_b@port_b;sweep_c@port_c
  • sweep_a@port_a;sweep_b@port_b;sweep_c@port_b

SSspecMin

On or Off. Enables or disables the tDQSQmin time testing. If you use two test suites, one for tDQSQmin testing and another one for tDQSQmax testing, only one of the two enabling parameters should be on in each of the test suite. If you want to test both the tDQSQmin time and tDQSQmax time in the same test suite, you need to change the vector label between two runs of the same test suite.

SpecVar

Name. Specify the name of the timing specification variable for tDQSQmin time offset on output pins in the timing equation. When tDQSQmin time testing is done, this variable is set to SSspecmin_DeviceSpec value. For testing the tDQSQmax time, this variable is set to zero.

DeviceSpec

Number. The tDQSQmin time specification from the data sheet in nanoseconds (ns).

This parameter can be considered as a test limitation.

VectorLabel

Name. The vector label used for tDQSQmin time testing. This vector must contain a toggle pattern for clock and data pins (of the source sync pins tested)

SweepStart

Number. In tDQSQmin time testing, the multishot sweeping starts from value in the SweepingSpecVar variable plus the value specified here.

If UsePredefinedTimeinFile set to No: the unit is in ns.

If UsePredefinedTimeinFile set to Yes: the number is an integer.

Example:

  • SweepingSpecVar("TSweep") = 3.0
  • SSspecmin_SweepStart = 4.0

This means the sweep starts by: 

SweepingSpecVar("TSweep") = 3.0 + 4.0 = 7.0 ns

RSS: In non debug mode there is no restriction for maximum number. Debug mode means: result output selected, one of the parameters OutputErrorMap, OutputMargin, OutputHistogram, OutputFailCycleEdge is set to Yes.

Multi port:

If UsePredefinedTimeinFile set to Yes: multi-port spec list (can be continued in Stop parameter).

Example: MP1_0ns, MP1_0ns75 continued in next parameter

SweepStop

Number. In tDQSQmin time testing, the multishot sweeping ends at the value of the SweepingSpecVar parameter at the beginning of the sweep plus the SSspecmin_SweepStop value specified here.

If UsePredefinedTimeinFile set to No: the unit is in ns.

If UsePredefinedTimeinFile set to Yes: the number is an integer.

Example:

  • SweepingSpecVar("TCmp") = 3.0
  • SSspecmin_SweepStop = 7.0

    This means the sweep stops at

    SweepingSpecVar("TCmp") = 3.0 + 7.0 = 10.0 ns

    Maximum number 256

RSS: In non debug mode there is no restriction for maximum number. Debug mode means: result output selected, one of the parameters OutputErrorMap, OutputMargin, OutputHistogram, OutputFailCycleEdge is set to Yes.

Multi port:If UsePredefinedTimeinFile set to Yes: multi-port spec list, (can be left blank or continued from Start parameter).

Example: MP1_0ns150, MP1_0ns225, continued from previous parameter

StepSize

Number. In tDQSQmin time testing, the multishot sweeping is executed by advancing the timing by the value specified here. The unit is nanoseconds.

If UsePredefinedTimeinFile set to No: You must specify a value for StepSize.

If UsePredefinedTimeinFile set to Yes:

  • If margin results are enabled and StepSize is specified, margin results are displayed as time. The time unit is nanosecond.
  • If margin results are enabled and StepSize is not specified, margin results are displayed as numbered steps.

Example:

  • SweepingSpecVar("TCmp") = 3.0
  • SSspecmin_SweepStart = 4.0
  • SSspecmin_SweepStop = 9.0
  • SSspecmin_StepSize = 2.0

This means the SweepingSpecVar("TCmp") is set to (7.0, 9.0, 11.0) step by step.

Example:

  • SweepingSpecVar("TCmp") = 3.0
  • SSspecmin_SweepStart = 4.0

This means the sweep starts by

SweepingSpecVar("TCmp") = 3.0 + 4.0 = 7.0 ns
Maximum number 256

RSS: In non debug mode there is no restriction for maximum number. Debug mode means: result output selected, one of the parameters OutputErrorMap, OutputMargin, OutputHistogram, OutputFailCycleEdge is set to Yes.

SSspecMax

On or Off. Enables or disables the testing of tDQSQmax.

SpecVar

Name. Timing specification variable to set the tDQSQmax time offset. In tDQSQmin time testing set to zero. In tDQSQmax time testing set to SSspecMax_DeviceSpec.

DeviceSpec

Number. The tDQSQmax time specification in the data sheet in ns.

VectorLabel

Name. The vector label name for tDQSQmax time testing.

SweepStart

Number. In tDQSQmax time testing, the multishot sweeping starts from SweepingSpecVar to SSspecMax_SweepStart plus its original value in nanoseconds.

SweepStop

Number. In tDQSQmax time testing, the multishot sweeping does not exceed SweepingSpecVar to SSspecMax_SweepStop plus its original value in nanoseconds.

StepSize

Number. In tDQSQmax time testing, the multishot sweeping is executed by increasing SSspecMax_StepSize for each step in nanoseconds.

If UsePredefinedTimeinFile set to No: You must specify a value for StepSize.

If UsePredefinedTimeinFile set to Yes:

  • If margin results are enabled and StepSize is specified, margin results are displayed as time. The time unit is nanosecond.
  • If margin results are enabled and StepSize is not specified, margin results are displayed as numbered steps.

Repeat

 

WholeSweep

Number. Repeats the whole multishot sweeping procedure for n-times.

The default value is 1.

SameTiming

Number. In the multishot sweeping, each shot is executed for RepeatWholeSweep times. The default value is 1.

Output

The settings in this section are available only if either both Shmoo.X_Axis and Shmoo.Y_Axis (see below) are set to Disable or Shmoo (see below) is set to Disable.

FailCycleEdge

Yes or No. Enables or disables to output the first fail cycle and edge number.

This parameter is available only if either Shmoo is Disable or both Shmoo.X_Axis and Shmoo.Y_Axis are Disable.

ErrorMap

Yes or No. Enables or disables the output of error maps.

This parameter is available only if either Shmoo is Disable or both Shmoo.X_Axis and Shmoo.Y_Axis are Disable.

See the output of error map in Error map output.

Edges

The compare edges on an Error Map. Default: 1,2,3,4,5,6,7,8

It can be:

  • A list of edge numbers separated with commas.

    Example: 1,2,3,4,5,6,7,8

  • Sub cycles. For the explanations, see the sub_cycles parameter in DCRM, DCRM?.

    Example: (1,5),(2,6),(3,7),(4,8)

    In this example, there will be four compare edges on the output error map, which are edge 1, 2, 3 and 4. The result of each edge is the AND result of the edges in the corresponding '()'.

Histogram

Yes or No. Enables or disables to output histogram.

This parameter is available only if either Shmoo is Disable or both Shmoo.X_Axis and Shmoo.Y_Axis are Disable.

Margin

TOTAL_MARGIN or Distribution or Off. Enables or disables the output of the tDQSQmin/tDQSQmax margin.

This parameter is available only if either Shmoo is Disable or both Shmoo.X_Axis and Shmoo.Y_Axis are Disable.

RapidSourceSync

Yes or No. Specify if you want to use Rapid Source Sync mode. Default: NO. If NO is chosen, omit the following two parameters

BufferPins

Pin names. Specify the buffer pins required for Rapid Source Sync separated by a comma. All buffer pins must be located on the same logical board. You must specify three or four pins.

Syntax:

<buffer1_SS0,buffer2_SS0,buffer3_SS0,<buffer4_SSO>; etc.

Example:

MUX2: digit_pin_0,digit_pin_1 or MUX4:digit_pin_0,digit_pin_1, digit_pin_3,digit_pin_4

Or mix, for example, MUX4, three buffers: rhx_plus_0, hrx_plus_1, (lrx2_1, lrx2_2, lrx2_3, lrx2_4)

CopyingMethod

Parallel or Sequential. Default: Parallel.

Parallel

  • For copying from pins to temp buffer: sum up SSCT command with ACC option and just for last source sync clock domain IMM option
  • For copying to accumulating buffers: sum up SSCT commands with ACC option. Execution is done parallel to next FTST.

Shmoo

Enable or Disable.

The other parameters in this section are available only if Shmoo is set to Enable.

Shmoo.X_Axis

Level or Timing or Disable. This defines the x-area and the ticks on the axis for the graphical output.

The default is Timing.

Shmoo.X_Axis.SpecVar

The name of the specification variable for the x-axis.

Shmoo.X_Axis.SpecUnit

The unit of the specification variable for the x-axis.

Shmoo.X_Axis.SweepStart

Number. The start value for the specification variable sweep.

Shmoo.X_Axis.SweepStop

Number. The end value for the specification variable sweep.

Shmoo.X_Axis.SweepStep

Number. The step size for incrementing the x-axis specification variable.

Shmoo.Y_Axis

Level or Timing or Disable. This defines the y-area and the ticks on the axis for the graphical output.

The default is Disable.

Shmoo.Y_Axis.SpecVar

The name of the specification variable for the y-axis.

Shmoo.Y_Axis.SpecUnit

The unit of the specification variable for the y-axis.

Shmoo.Y_Axis.SweepStart

Number. The start value for the specification variable sweep.

Shmoo.Y_Axis.SweepStop

Number. The end value for the specification variable sweep.

Shmoo.Y_Axis.SweepStep

Number. The step size for incrementing the y-axis specification variable.

Shmoo.Margin

Min or Max or Mean or Sigma. The kind of margin that the test captures from the source sync.

For example, if Min is specified, the test captures the minimum value of the margin as the source sync result.

The default value is Min.

Shmoo.2dMode

Compact or P/F or Value. The 2D print mode for the shmoo.

testName

The test names to be used as limit. You can:

  • Use the test names defined in the test table or testflow limits. Type in the test names manually. Make sure these test names are in the Test name column of the test table (Refer to Structure of a TMLimits CSV file) or in Test Name column of Tests page of Flow Data Editor.
  • Define new test names. After that you need to add the defined test names (limits) to the test suite. (Refer to Adding a limit in the Properties view and Adding a limit on the Tests page.)

To specify different settings for different pins or pin groups, separate them with commas.

The default value is "Min Value, Max Value, Mean Value, Sigma Value, Domain Result, MarginLimit, DQ Offset Min, DQ Offset Max"
Source-synchronous test method fast mode result parameters

Name

Comment

Min Value

The limits for the minimum value of the margin for tDQSQmin and/or tDQSQmax.

Max Value

The limits for the maximum value of the margin for tDQSQmin and/or tDQSQmax.

Mean Value

The limits for the mean value of the margin for tDQSQmin and/or tDQSQmax.

Sigma Value

The limits for the sigma value of the margin for tDQSQmin and/or tDQSQmax.

Domain Result

The limits for the domain pass/fail result for tDQSQmin and/or tDQSQmax.

MarginLimit

Margin limits for tDQSQmin and/or tDQSQmax.

If the more detailed limits Min Value, Max Value, Mean Value, Sigma Value, and Domain Result (see below) are set, MarginLimit is ignored.

DQ Offset Min

The largest absolute value of a shmoo spec (either Shmoo.X_Axis.SpecVar or Shmoo.Y_Axis.SpecVar) that passes.

This limit is used only in 1d timing shmoos.

DQ Offset Max

The sum of the absolute values of DQ Offset Min, DeviceSpec, and Max Value:

DQ Offset Max = |DQ Offset Min| + |DeviceSpec| + |Max Value|

This limit is used only in 1d timing shmoos.

Suppression of unreasonable output values is provided. The test method returns a fail if the output is unreasonable

Example 3: Error map

If the ErrorMap parameter (explained in the above table) is Yes, and the testflow flag debug_mode is set to 2, an error map similar to the one below is displayed in the Report window:

E R R O R M A P:
================
Cycle Range: 0 - 63
 0123456789012345678901234567890123456789012345678901234567890123456789012345678901234567
0:1 ###########################################..............############################### . 0.420
0:2 ##########################################...................########################### . 0.570
0:3 ################################.......#########..........############################## - 0
0:4 ##########################################.................############################# . 0.510
1:1 ######################################################################################## FAIL 0

In the error map:

  • In the fourth row, the numbers repeated from 0 to 9 represent different shorts.
  • From the fifth row, the pass/fail results and margins are displayed.
    • The two numbers at the beginning of each row: For example, "0:1", 0 is the cycle 0, 1 is the first compare edge.
    • "." or "#" corresponding to a shot in a row: Represents pass or fail for this shot: "." is pass and "#" is fail.
    • The value at the end of each row: Indicates the margin.
    • The symbol (".", "-", "FAIL") before the margin value and after the result of last shot in a row: Tells whether there will be a margin through analyzing the results of all shots.

      .: There is a margin and the margin value is displayed at the end of a row.

      -: It is an invalid multishot test for this compare edge and sets the margin value to 0.

      FAIL: Represents all fails for all shorts and sets the margin value to 0.
