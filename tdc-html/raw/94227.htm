Topic 94227

Using transparent x-modes

Using x-modes requires very little changes to the setup files. You do need to observe some guidelines, however.

About this task

This task describes what you need to do when you want to activate x-modes, deactivate them, or switch between them.

Before you begin

The MTL Configuration Files should be set up correctly. Indirect waveform mapping must not be used.

Procedures

Activating transparent x-modes

  1. Add the using defaultxmode statement to the Pin mapping file.
  2. If there are pins that need to run at a different x-mode, add xmode attributes to their definitions in the pin mapping file.

    Note that all pins grouped in one PINS section of the Pin configuration file must share the same x-mode.

  3. Set up a wavetable for the desired x-mode in the Timing file and reference it in the APG pattern file using the :waveformMap: keyword.

    To do so, either fill the wavetable yourself by defining all combinations of logical states or let the compiler do it by using the -wcompiler switch. (In the MTL Compiler Control dialog, this is the Automatic Waveform Generation option.)

Deactivating transparent x-modes

  1. Remove any using defaultxmode statements and xmode attributes from the Pin mapping file.
  2. In the APG pattern file, use the :waveformMap: keyword to specify a wavetable from the timing file that is set up for no x-mode. (See step 3 in "Activating x-modes", above.)

Switching transparent x-modes

  1. Change the parameters of the using defaultxmode and xmode= statements in the Pin mapping file as required.
  2. In the APG pattern file, use the :waveformMap: keyword to specify a wavetable from the timing file that is set up for the new x-mode. (See step 3 in "Activating transparent x-modes", above.)

Results

The transparent x-mode is set up as required.

What to do next

Setting up padding, as described in Setting up padding.
