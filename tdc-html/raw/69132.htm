Part Count Record (PCR)

The Part Count Record contains the part count totals for one or all test sites.

The Part Count Record can appear anywhere in the data stream after the initial sequence, and before the MRR. When data is being recorded in real time, this record will usually appear near the end of the data stream.

PCR field name

Field description

Value

93000 data source

HEAD_NUM
  • Test head number

     
  • One-byte unsigned integer
  • Value = 255

    If the ATR and GDR indicate that there are more than 255 sites in the test, HEAD_NUM is the number of the site divided by 256. For example, in a record for site 384, HEAD_NUM would be 2.
  • For tests with up to 255 sites: hard-coded value

    For tests with more than 255 sites: derived from SiteID

SITE_NUM
  • Test site number
  • One-byte unsigned integer

    If the ATR and GDR indicate that there are more than 255 sites in the test, SITE_NUM is the number of the site modulo 256. For example, in a record for site 600, SITE_NUM would be 88.
  • EDL Event:

    BinReachedEventType

  • EDL Attribute:

    SiteID

PART_CNT
  • Number of parts tested
  • Four-byte unsigned integer
  • EDL Event:

    BinReachedEventType

RTST_CNT
  • Number of parts retested
  • Four-byte unsigned integer
  • 4,294,967,295 = missing or invalid data
  • EDL Event:

    BinReachedEventType

ABRT_CNT
  • Number of aborts during testing
  • Four-byte unsigned integer
  • 4,294,967,295
  • Hard-coded value

GOOD_CNT
  • Number of good (passed) parts tested
  • Four-byte unsigned integer
  • 4,294,967,295 = missing or invalid data
  • EDL Event:

    BinReachedEventType

  • EDL Attribute:

    IsGoodBin

FUNC_CNT
  • Number of functional parts tested
  • Four-byte unsigned integer
  • 4,294,967,295 = missing or invalid data
  • Hard-coded value

Functional changes

  1. Introduced before SmarTest 6.3.2
  2. SmarTest 7.2.2: Added HEAD_NUM and SITE_NUM conventions for tests on more than 255 sites.
