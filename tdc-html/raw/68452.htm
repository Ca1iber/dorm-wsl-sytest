Subroutines

Subroutines let you group related instructions and name and reuse these groups. Using subroutines can make your programs easier to write and maintain as well as easier to read. It also can improve compilation times.

MTL subroutines are defined and accessed like they are in C.

There are a few rules and limitations:

  • No results: MTL subroutines cannot return results.
  • Unlimited subroutines: An APG program can contain any number of subroutines.
  • Limited nesting level: The nesting level may not exceed 64. (The nesting level is the depth of the subroutine calling stack. That is, if a subroutine calls another one before it is done, the nesting level increases by one.)
  • Naming: A subroutine may not have the same name as another subroutine or a device access. (See Naming rules and conventions for information on naming subroutines.) No subroutine may be called main() or REFRESH_CTRL().
  • No empty subroutines: Subroutines with empty bodies are not supported.
  • Arguments: A subroutine can have zero to 64 arguments. The number of arguments is fixed; overloading is not possible (that is, there cannot be subroutines with the same names but different numbers of arguments). A subroutine name can be declared only once.
  • Location and order of declaration: Subroutines can be declared anywhere within the APG program code block. The order of declaration and calling is not important, so a subroutine can be called in the code before it is declared.
  • Recursion: Recursion is not supported; a subroutine cannot call itself, nor can it call - directly or indirectly - a subroutine from which it has been called.
