Topic 124658

Macros and functions in device accesses

MTL includes some predefined functions and macros that you can use in the :data: and :operation: columns in device access files.

Syntax

These macros are available, listed in alphabetical order.

Keyword

Parameters and descriptions

bitCount(<elements>, <bitState>)

<elements>: The pins of the bus in question that are to be monitored. The pseudo-variable e can be used to avoid having to specify concrete pins. For example, e[2] refers to the second pin of the bus in the current configuration. e[] refers to all pins of the bus.

<bitState>: The bit state that is to be counted; either 0 or 1.

The bitCount function returns the number of bits among the specified elements that have the logical bit state given.

The function can be used for specifying the conditions of dbi macros.

crc(<configuration>, <crcBit>)

<configuration>: The CRC configuration that the crc macro is to use to returns the current CRC result.

<crcBit>: The bit (from the bit list specified in the CRC configuration) from which the CRC result is to be calculated.

If the pin list of the bit sequence specified in the chosen configuration includes multiple pins in each row, the result of the crc macro has multiple bits. You can access individual bits of the result using the Select operator.

For example: crc(myConfig,0), crc(myConfig,0)[3], crc(myConfig,0)[5,2] (These examples assume that there is a configuration named "myConfig" in the :crc: block that is currently specified in the APG pattern file.)

The crc macro can be used in the :operation: columns of device accesses. If it is used in a device access and CRC is globally enabled, the :data: column is ignored in that access.

data(<d>,<x>,<y>,<z>)

<d>: The unscrambled data word.

<x>: The unscrambled x address.

<y>: The unscrambled y address.

<z>: The unscrambled z address.

The data macro scrambles data words by applying the current bit inversion and bit ordering tables specified in the APG pattern file.

If fewer than four parameters are specified, the missing ones are considered to be zero. For example, data(0xff,1) would be the same as data(0xff,1,0,0). You must specify at least two parameters.

Note that all parameters are masked with the respective device parameter from the Device architecture file, that is, dBits, xBits, yBits, and zBits. For example, when xBits is 8 and the value provided as the unscrambled x address is 258, masking would convert it to 2.

The Select operator can be applied to data macro expressions to extract one or more individual bits.

The data macro must be used on all pins for which you require Reconstruction information.

The data macro can be used in the :data: columns of device accesses.

dbi(<configuration>)

<configuration>: The DBI configuration that the dbi macro is to use.

The dbi macro inverts the signals on a bus if a specified condition is met, as described in Dynamic bus inversion. The signal is inverted for all pins in each row in the specified DBI configuration that is completely part of the pins listed in the device access row in which the dbi macro is used. (See the DBI examples in the Examples section, below.)

Inversion is applied after scrambling; it is applied before or after cyclic redundancy checks, depending on the order in which the operations are listed with the :operationOrder: keyword.

The dbi macro can be used in the :operation: columns of device accesses. However, any device access containing the dbi macro cannot be used in padding routines.

xaddr(<x>,<y>,<z>)

<x>: The unscrambled x address.

<y>: The unscrambled y address.

<z>: The unscrambled z address.

The xaddr macro provides the scrambled x address by applying the current scrambling table specified in the APG pattern file.

If fewer than three parameters are specified, the missing ones are considered to be zero. For example, xaddr(1,1) would be the same as xaddr(1,1,0).

If no scrambling is specified, the macro returns the unscrambled x address.

The xaddr macro can be used in the :data: column of the device access file. The Select operator can be applied to address macro expressions to extract one or more individual bits.

yaddr(<x>,<y>,<z>)

The yaddr macro returns the scrambled y address. It is similar to xaddr, described above.

Missing parameters are handled as follows:

  • If there is only one parameter, that parameter is considered to be the unscrambled y address. For example: yaddr(1) is the same as yaddr(0,1,0).
  • If there are two parameters, they are considered to be the unscrambled x and y addresses. For example: yaddr(1,2) is the same as yaddr(1,2,0).

zaddr(<x>,<y>,<z>)

The zaddr macro returns the scrambled z address. It is similar to xaddr, described above.

Missing parameters are handled as follows:

  • If there is only one parameter, that parameter is considered to be the unscrambled z address. For example: zaddr(1) is the same as zaddr(0,0,1).
  • If there are two parameters, they are considered to be the unscrambled x and z addresses. For example: zaddr(1,2) is the same as zaddr(1,0,2).

Example

DBI examples

For all examples, the active DBI setup in the device architecture file is assumed to be:

:dbi:
{
  :name: sample_dbi
  :configuration:
  {
    :name:  writeDBI
    :condition: bitCount(e[], 0) >= 4 
    :table:
    {
      :format:
      { :bus:        :flag:    }
      { DQi[0..7]    RDQSi[0]  }
      { DQi[8..15]   RDQSi[1]  }
      { DQi[16..23]  RDQSi[2]  }
      { DQi[24..31]  RDQSi[3]  }
    }
  }
}

There are assumed to be two subgroups of the DQi pin group, one called DQi.subgroup.0_15 (containing pins 0 through 15), one called DQi.subgroup.4_11 (containing pins 4 through 11).

In the following example, all DQi pins would be inverted if the condition was met, because all would be listed in active DBI setup and in the row of the device access in which the dbi macro is called:

:apgAccess:
{
  :name:  Write
  :table:
  {
    :format:
    {:pin:  :states:  :data:          :operation:   }
    { DQi    {0 1}    data(dw,x,y)  dbi(writeDBI)   }
  }
}

In the next example, only pins DQi.000 through DQi.015 would be inverted upon fulfillment of the condition, because only they are included in the device access' :pin: column:

:apgAccess:
{
  :name:  Write
  :table:
  {
    :format:
    {:pin:              :states: :data:          :operation:   }
    { DQi.subgroup.0_15 {0 1}    data(dw,x,y)  dbi(writeDBI)   }
  }
}

In this example, no pins would be inverted, because the pins included in the :pins: column do not completely cover any of the four rows in the :bus: column of the DBI definition:

:apgAccess:
{
  :name:  Write
  :table:
  {
    :format:
    {:pin:              :states: :data:          :operation:   }
    { DQi.subgroup.4_11 {0 1}    data(dw,x,y)  dbi(writeDBI)   }
  }
}
