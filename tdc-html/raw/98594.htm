ERCC? - (ERror in Cycle range Count)

The ERCC? query returns the number of errors in a specified cycle range.

With this command you can retrieve site specific information (only one site can be in focus at a time). For the site in focus, SmarTest displays results in the Testflow Editor and in the result tools. Also, any firmware queries report setup and results for the site currently in focus only.

Syntax

ERCC? {type}, {start_cycle}, {no_of_cycles}, [MUX,] {(pinlist)}

returns:

ERCC {type}, {start_cycle}, {no_of_cycles} [, granularity], {valid_code}, {no_of_errors}, [map_mode], [MUX,] {(pin)}

Parameters

type

The type parameter can be:

ERCP

Error count per pin. Each pin returns a separate answer.

ERCG

Error count global, which requests the sum of all error counts reported by ERCP. Only one answer is generated.

start_cycle

An integer that defines the cycle following which failures are to be counted. If the queried range starts before the analyze delay (see SQGB command) then the returned value will be corrected to a later cycle number.

no_of_cycles

An integer that defines the cycle range in which failures are to be counted. If the queried start_cycle has to be corrected or the amount of failures causes an overflow of the error map then the returned value will be corrected to a smaller number of cycles.

granularity

 

 

This parameter specifies how errors are condensed. Possible values are:

CYCL

 The number of failing cycles is returned.

EDGE

 The number of failing edges is returned.

valid_code

This parameter tells you if the error count that the system returns is valid. The system may return:

VALD

The error count is valid. This reply is always returned in offline mode.

OVFL

This signifies an Error Map overflow. no_of_errors contains the number of errors that occurred until this happened.

LESS

Either the start of the cycle range was before the error map error acquisition started or the end was after the test has ended or both. If an overflow condition and the less condition are both true, LESS is reported.

MUX

If this flag is set, and one of the specified (Pin Scale) pins is multiplexed to an HXA pin, then the errors from all Pin Scale pins multiplexed to this HXA pin will be used to calculate the total number of errors.

pinlist

The pin name or names for which errors are to be counted. If more than one pin is required, the names must be separated with a comma. The @ character can be used to retrieve the data for all configured pins.

no_of_errors

An integer that contains the number of errors found in the queried range of cycles. If the reported range of cycles is smaller than the queried range then this value represents only the number of errors in the reported range and not in the requested range. It should be regarded as the minimum number of errors in the requested range, and could be higher.

map_mode

The system returns the current Error Map mode. This is:

F160

The pin operating mode is Standard mode

Application

Test results.

Example

> ERCC? ERCP, 1000, 200, (pin1,pin2)
< ERCC ERCP, 1000, 200, VALD, 5, F160, (pin1)
< ERCC ERCP, 1000, 200, VALD, 1, F160, (pin2)

Functional changes

  1. Introduced before SmarTest 6.3.2
