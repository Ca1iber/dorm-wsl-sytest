Storing the results of more than one TMU measurement

By default, only the results of the last TMU measurement execution are stored. You can, however, store the results of more than one measurement by defining a dedicated storage area for a measurement. This is done by defining (or activating) a handle for the respective measurement with the TSRH? query. Different handles point to different storage locations.

The general mechanism is as follows:

One handle is always active. The storage area referenced by the active handle is used by FTST? to store the measurement. The active handle can be the default handle (which is always present), or it can be a user defined handle.

If you want to change the result area for the next measurement execution, you must specify the requested result area by its handle with TSRH? before the test is executed. You can either define a new handle for this purpose with TSRH? REQUEST (which will then be activated automatically), or activate an existing handle with TSRH? SELECT.

After the test has finished you can retrieve the data of the active result area with TSRS? or TSRW?. If you want to upload the results of an earlier measurement, change the active result area accordingly.

Example

> TSPR "TMU_set1"
> TSRH? REQUEST,"area1"
< TSRH REQUEST,"area1",SUCCEED
> FTST?
> FTST P
> TSPR "TMU_set2"
> TSRH? REQUEST,"area2"
< TSRH REQUEST,"area2",SUCCEED
> FTST?
< FTST P
> TSRS? ,PERIOD,,,(pin_a)
< TSRS ,PERIOD,,1.36,(pin_a)
> TSRH? SELECT,"area1"
< TSRH SELECT,"area1",SUCCEED
> TSRS? ,PERIOD,,,(pin_a)
< TSRS ,PERIOD,,1.38,(pin_a)

This example makes successively TMU_set1 and TMU_set2 the primary TMU set, and executes a test with each of these primary TMU sets. The results of the first measurement are stored in area1, those of the second in area2. Afterwards, the global means of both measurements are retrieved with TSRS?.

Functional changes

  1. Introduced in SmarTest 7.1.0
