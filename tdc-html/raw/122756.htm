d2s

The d2s-framework provides the features needed to set up and test DUT's using protocols.

It has two modes which can be controlled by a global user variable:

  • Learning mode - generates static pattern and adds them to one burst label.
  • Production mode - executes the burst label generated by the learning mode.

Steps to implement the d2s-framework

  1. Setup level, timing, vectors and pins of your device as described in Setup and Result Tools.
  2. Generate write, read and wait template labels for your protocol as outlined in Prepare device setup.
    Note The d2s-framework only supports x1 and 1/x (padding)-modes for serial protocols.
  3. Rename and modify the user template file d2sSerialProtocolTemplate.cpp to fit your protocol as described in Configure the protocol.
    1. Configure general parameters, such as protocol port name, address and data bits and the protocol name.
    2. Configure the write parameters of your protocol.
    3. Configure the read parameters of your protocol.
      Note Reading from an register always requires to strobe to 'L'.
    4. Configure the wait parameters of your protocol.
  4. Include the renamed protocol template (for example, d2sJTAG.h) and the d2sFramework.h to your test method.
  5. Write your test method and include the d2s protocol methods, such as read, write, etc, within a d2s_LABEL-block.
    Note Do not use any other API calls other than the d2s methods in the d2s_LABEL-block.

Special options

The d2s-framework offers special options such as

  • Multiple transaction ports, which enables concurrent protocol transactions on multiple ports.
  • Transaction ports without a protocol, which allows you to add predefined patterns of ports that do not use a protocol to the burst label.
  • Global framework mode, which allows easy switching between learning and production mode by using a test method variable.
