Topic 10609

Restrictions for drive edges

The edges need not be ordered numerically within a waveform definition. But a general restriction is that if two drive edges within one waveform definition are associated with the same action type (both with a drive action, or both with a tri-state action) then this waveform cannot be used with a timing set that assigns to the subsequent edge a smaller delay than to the preceding edge. Thus, if d1 is associated with a delay of 4 ns and d3 with a delay of 2 ns in the same timing set, this timing set can be combined with the following two waveforms:

"d3:F10 d1:F00"
"d1:FN0 d3:F1N"

In the first definition, the delays conform to the edge order, in the second, the two edges are not associated with the same action type. But the following waveform is incompatible with these edge delays:

"d1:F10 d3:F00"

Note that checking of these restrictions can be activated or disabled by the CHECK keyword in the timing specification, see Consistency checks for edge delays. All checks are active by default.

In contrast to Pin Scale pins, drive edges for Smart Scale pins are not subject to any edge ordering restrictions.

CAUTION If the edge order restrictions for drive pins were not observed in a Pin Scale setup, the resulting waveforms will be different when the setup is loaded into a Smart Scale system.

Consider the definition

"d1:0 d2:1 d3:0" with the delays d1 = 0, d2 = 5, and d3 = 2.

The delays do not conform to the edge order and the same action type is used for all edges. The expected waveform will be

  • 0 - 0 - 0 - 0 - 0 - 1 for a Smart Scale system and
  • 0 - 0 - 1 - 1 - 1 - 0 for a Pin Scale system.
